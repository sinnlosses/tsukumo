# 無料の削り方とトレードオフ・cost-optimize 由来の取捨

SKILL.md の4章「何を候補にするか」で、提案ごとの「失うもの」を書くときに開く参照。

## 無料の削り方とトレードオフ

提案ごとに**失うもの**を書く（SKILL.md 3章の「失うもの」）。種類ごとの目安:

| `kind`                                            | 失うもの                                                                               |
| ------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `unused-mcp`                                      | 期間中に呼ばれていないなら、なし（無料）。まれに使うツールなら、使うときに足し直す手間 |
| `memory-file`                                     | 削った指示。守られなくなる決まりが出る                                                 |
| `skill-definition`                                | 外したスキルが自動で呼ばれなくなる                                                     |
| `tool-result`                                     | 絞った結果の情報。読み直しで歩が増えると逆効果                                         |
| `session-length`                                  | 区切った時点までの会話の文脈                                                           |
| `subagent-share` / `cache-reuse` / `model-choice` | 何を変えるか次第（提案の中で書く）                                                     |

## cost-optimize 由来の分析の取捨（2026-09-25）

`/claude-api cost-optimize`（API のアプリ向けの費用削減）が出した分析のうち、トークンの物差しで意味を持つものだけを取り入れた:

- **種類別の内訳 — 取り入れた（表の1章「種類の内訳」、`totals.overall.typeSharePct`）。** ただし重みなしのトークンの比で、ドルで割った比ではない。どの種類が数を占めるか（いまはキャッシュ読みがほぼ全部）を見て、どの提案が効くか（文脈を小さくする・歩を減らす）の見当に使う
- **モデルと effort — 取り入れない。** モデルの単価の違い（Opus 5 → 5.5 でキャッシュ読みが安い等）はトークンの数を変えないので、この物差しでは効きが消える。effort は出力と思考の量を変えうるが、記録に effort が無く、出力（思考を含む）は消費量の1%に満たないので効きを測れない
- **歩数 — 一部だけ取り入れた（表の2章「1歩あたり」、`scopes.rows.*.readPerStep`）。** 1歩ごとに文脈を丸ごと読み直すのはトークンでもそのまま効く。ただし `speak` だけの歩の数は記録に無い（`speak` は `tools[]` に残らない）ので、減らせる歩の数を置くと推測になる。見積もりは出さず、1歩の重さを測った数として根拠に使うまでにする
- **無料とトレードオフの区別と見送りの一覧 — 取り入れた（上の表と SKILL.md 3章）。** トークンでも「失うものなしで減る」か「何かと引き換えか」は利用者の判断に要る。画面の提案の型は変えず、失うものは `basis` の文面に書く（SKILL.md 7.2）。見送りの一覧は本文のレポートで返すとき（3章）だけ添え、ツールで返すときは渡す欄が無いので省く

# 見積もりの節（`estimates`）の形

SKILL.md の3章「提案の書き方」で、`--json` の `estimates` を読むときに開く参照。

`--json` の `estimates` は**固定の形**で、tsukumo の画面やツールに渡す提案へそのまま写せるようにしてある。形を変えたら `version` を上げる（読む側はこの数で形の変わり目に気づく。いまは `2`。`1` は費用を分母にし、各件に `estimatedCostUsd`、節に `unitPrices` を持っていた）。

| キー                 | 中身                                                                                                                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `version`            | 形の版（整数）                                                                                                                                                                |
| `measured`           | いつも `false`（測った数ではない印）                                                                                                                                          |
| `status`             | `ok` か `unavailable`。`unavailable` のときは `items` が空で、`reasons` に理由                                                                                                |
| `reasons`            | 出せなかった理由・一部の種類を出せなかった理由（文字列の配列）                                                                                                                |
| `caveats`            | 見積もり全体の断り書き（main だけを数えた・期間全体へ伸ばした など）                                                                                                          |
| `denominator`        | 割合の分母。`kind` は `consumedTokens`（期間のトークンの消費量。入力・キャッシュ読み・キャッシュ作成・出力の重みなしの和）、`value`、種類ごとの数 `byType`、`cacheReadTokens` |
| `mainReadSharePct`   | 式に入った main の読みが、キャッシュ読みの合計に占める割合                                                                                                                    |
| `thresholds`         | 効きめの境目（`largePct` / `mediumPct`）                                                                                                                                      |
| `assumptions`        | この回に使った仮定の値（`resultTrim` / `memoryTrim` / `sessionThreshold`）                                                                                                    |
| `upperBoundSharePct` | `items` の `sharePct` を足した数。**重なりを除かない上限**                                                                                                                    |
| `items`              | 見積もりの1件ずつ（`sharePct` の大きい順。種類ごとに上位3件まで）                                                                                                             |
| `notEstimated`       | 見積もりを出していない種類と理由（`kind` / `reason`）                                                                                                                         |

`items` の1件の持ち物:

| キー              | 中身                                                                                                                                                                                                                                                                                                               |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `kind`            | 提案の種類。tsukumo の `USAGE_PROPOSAL_KINDS` と同じ語（`unused-mcp` / `memory-file` / `skill-definition` / `tool-result` / `session-length`）                                                                                                                                                                     |
| `target`          | 対象。決まりは `USAGE_PROPOSAL_KIND_TARGETS` と同じ（MCP はサーバ名、ツールは名前、全体なら空）。メモリは開始日で分け target に `（<日> 開始）` 付き、`Project` はファイル名で束ねる                                                                                                                               |
| `key`             | 提案の識別子（`kind:target`。tsukumo の `usageProposalKey` と同じ作り方）                                                                                                                                                                                                                                          |
| `estimatedTokens` | 期間中に減っていたトークンの消費量の見積もり（重みなし。`session-length` は増えるキャッシュ作成を差し引いた数）                                                                                                                                                                                                    |
| `sharePct`        | 分母に占める割合（%）                                                                                                                                                                                                                                                                                              |
| `impact`          | 効きめ（`large` / `medium` / `small`）。`sharePct` が 3% 以上で大、0.5% 以上で中。境目の数は費用の割合だった v1 のまま据え置いた（上限に照らした較正の材料が無く、変えるのも推測になる）。分母がトークンになって同じ提案の割合は v1 より大きく出る（キャッシュ読みが費用では約2/3、トークンでは約98%を占めるため） |
| `confidence`      | 確かさ（`high` / `medium` / `low`）。定義を外す見積もりは、内訳のあるステップが半分未満だと1段下げる                                                                                                                                                                                                               |
| `bound`           | `estimate` か `upper`（全部外した場合の上限）                                                                                                                                                                                                                                                                      |
| `basis`           | 根拠の母数（`turns` / `sessions`。種類によって `steps` / `scaledToSteps` / `calls` / `restarts`）                                                                                                                                                                                                                  |
| `assumptions`     | その件が使った仮定の値                                                                                                                                                                                                                                                                                             |
| `note`            | 式の一言                                                                                                                                                                                                                                                                                                           |

見積もりの式（どれも **main の読みだけ**を数える）:

- `unused-mcp`: 期間中1度も呼ばれていないツールの定義（サーバごと）× main のステップ数。deferred のぶんはコンテキストウィンドウの外なので、MCP の分類の used の比で按分して除く
- `memory-file`: ファイルの大きさ × main のステップ数 × 削れる割合（`--memory-trim`、既定 0.3）
- `skill-definition`: スキルの定義の合計 × main のステップ数（上限。どれを外すかは利用者が決める）
- `tool-result`: 結果のトークン（4バイト/トークン）× そのあとに続く main のステップ数（そのターンの残りは半分とみなす）× 絞れる割合（`--result-trim`、既定 0.5）。自動圧縮の時点は記録に無いので、1ステップあたりの読みが前のターンの半分を下回ったところで打ち切る。それでも大きめに出る
- `session-length`: main のコンテキストがしきい値（`--session-threshold`、既定 200,000）を超えた時点で区切り、土台（定義ぶん）から作り直したとして減る読み − 区切りで増えるキャッシュ作成

**「1ステップあたりのキャッシュ読み ≒ コンテキストの大きさ」は main でだけ確かめてある**（セッションの内訳の使用量と2分以内のターンで中央値 0.99 倍）。subagent はコンテキストの記録が無く確かめられないので、ステップに掛ける式には使わない（見積もりは小さめに出る）。`model-choice` は見積もらない。モデルの単価の違いはトークンの数を変えず、持ち場ごとのモデルの内訳も記録に無く「移せるターンの割合」が推測にしかならないため（SKILL.md 4章の終わり）。`subagent-share` と `cache-reuse` は比率の診断で、減る量の式が無い。

# HTML 版とレポート版の見比べ

同じ題材を、Claude に自由な HTML で書かせた版（HTML 版）と、tsukumo の `report` で書かせた版（レポート版）にして並べ、
レポート版が届かないところ（**穴**）を探す。HTML 版は比べる相手で、tsukumo には載せない（`docs/architecture/adr/0032-free-html-block.md`）。
穴の扱いと梯子は `docs/architecture/display/block-criteria.md`「見比べで見つかった穴」が正典。

## 守ること

- 題材は**架空のものだけ**。実物の会話・transcript・SDK のイベントを題材や疑似セッションに入れない（`docs/coding-standards/conversation-content.md`）
- 書き出し・画像は `/tmp/html-comparison/<日付>/` に置き、リポジトリに入れない。記録に残す画像だけを `docs/research/` へ写す
- 判定は撮った画像を自分で開いて見てから付ける。数（字数・はみ出し・紙面の物差し）は補助で、勝ち負けを数だけで決めない

## 手順

### 1. 題材を決める

既定は同じディレクトリの `topics.json`（6本。流れと分岐・2案の比較・前後の数・状態の一覧・時間の経緯・構造の前後）。
利用者が特定の形を試したいと言ったら、同じ形（`id`・`request`・`facts`）の json を `/tmp/html-comparison/topics-<名前>.json` に書いて使う。
`facts` の頭は「材料（すべて架空）:」にし、数・名前・未確認の点を具体的に入れる（数が無いと図や数の札を試せない）。

### 2. 両版を書かせる

```bash
node scripts/dev/html-comparison-write.ts --topics .claude/skills/html-comparison/topics.json \
  --out /tmp/html-comparison/<YYYY-MM-DD> [--only <id>] [--model opus] [--effort <段>]
```

- 題材ごとに HTML 版（`<id>/page.html`）とレポート版（`<id>/report.json`）を書き、描けた題材から `session/index.json`（撮影用の疑似セッション）を組む
- レポート版は本番の差し戻しと同じ順（引数の形 → 構造 → 省けない欄 → 記法の条）で判定し、差し戻しの文を書き手に返して書き直させる。構造と記法の条は本番と同じく1回ずつしか差し戻さない
- 書き終えた版は飛ばすので、途中で止まっても同じコマンドで続きから回る。ばらつきを見るときは `--out` を変えてもう1回回す
- 1題材あたり `claude -p` を2〜5回起こす（1回30秒前後）。6本で数分かかるので、待つものを利用者に言ってから打つ
- 最後に題材ごとの「HTML あり／レポート 描ける・呼び出し n 回・差し戻し 段(条)」が出る。描けない題材は撮らずに、差し戻しの条を結果に書く

### 3. 同じ幅で撮る

```bash
pnpm run build
node scripts/capture/compare-html.ts --html /tmp/html-comparison/<日付>/<id>/page.html --scene <id> \
  --session /tmp/html-comparison/<日付>/session/index.json --topic <id> --date <日付> \
  --widths 1400,390 --height 2400 --out-dir /tmp/html-comparison/<日付>/<id>
```

- レポート版はメインビューの中でスクロールするので、`--height` を伸ばさないと最初の1画面しか写らない
- 出力は穴ドラフトの本文の前4箇条の下書き（画像のパス・横のはみ出し・字数・紙面の物差し）。手順5で使うので控えておく

### 4. 観点ごとに勝ち負けを付ける

題材ごとに `report-<幅>.png` と `html-<幅>.png` を Read で開いて見比べ、次の観点に「HTML／同等／tsukumo」を付けて、根拠を場所の言葉で1文書く。

| 観点 | 見ること |
| --- | --- |
| 結論の見つけやすさ | 最初の1画面で、結論と結論に効く数が目に入るか |
| 数の見せ方 | 前後・割合・大小が、読まずに形で分かるか |
| 流れと構造 | 段・分岐・戻り・依存が図で追えるか |
| 状態の色分け | 通った・落ちた・未確認が色と印で見分けられるか |
| 枠と題 | まとまりごとに枠と題があり、どこからどこまでが一つか分かるか |
| 読む順 | 上から読んで迷わないか。狭い幅（390）で順が崩れないか |
| 事実の欠けと足し | 材料の事実が落ちていないか、材料に無い事実が足されていないか |

`report.json` の差し戻しも見る。書き手が同じ条でつまずいた題材は、表現力より道案内の穴（梯子の2）の材料になる。

### 5. 穴をドラフトに積む

「HTML」が付いた観点ごとに、`block-criteria.md`「梯子」を上から問い、段を決める。

- 段1（今の部品で書ける）: 書き方を試した記録として結果に書くだけで、ドラフトは積まない
- 段2〜4: 穴1件につき `tw new --draft` で1件積む（採否は聞かない。承認は後の `/plan-tasks`）。本文は `block-criteria.md`「穴ドラフトの本文の型」に従い、前4箇条は手順3の下書きを写す
- 段5（採らない穴）: ドラフトを積まず、結果に理由を1行書く

### 6. 結果を報告する

- 題材ごとに、2枚の画像（同じ幅）と観点の表を並べる。画像は `report` の `BeforeAfter`（image の両側）か `Picture` で載せる
- 全体は「観点 × 題材」で HTML が勝った数を数え、多い観点から並べる。積んだドラフトの ID を添える
- 利用者が記録を残したいと言ったら、`docs/research/html-comparison-<日付>/index.md` に表と画像を置く（画像は架空の題材なので写してよい）

## 限界

- 書き手は素の `claude -p` で、キャラクターの人格・会話の前後・作業の道具を持たない。本番のセッションより材料が整った条件で書く
- 手続きの差し戻し（ワークプラン・背景のシェル・新しい事実が無い）はターンの外の状態を読むので、ここでは見ない
- 1回の書き出しは1標本。勝ち負けが割れた観点は、もう1回回して揃うかを見てから穴にする

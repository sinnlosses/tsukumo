# TypeScript の書き方

規則の正典はこのファイル。理由と例外は `docs/coding-standards.md` の括弧の節（子のファイルは `docs/coding-standards.md` の目次で引く）。

- 関数はファイル内で「外から使うもの → その内部で使うもの」の順。テストのためだけに公開しない（「関数の並び順」）
- 変数・コレクションはイミュータブル。**引数の入れ物が呼び出し先で書き変わる契約にしない**（「変数は基本イミュータブル」）
- **契約で設計する**: 事前条件は型か境界の parse で満たし内側で確かめ直さず、不変条件は判別合併型・branded 型で守る。`core`・`shared`・`domain` は純粋に保ち、時計・乱数・DOM・IO は引数で受ける（「契約による設計と純粋関数」）
- 型を迂回するキャストを書かない。外部由来の値は境界で検証し、変換を1箇所に封じ込める（「型を迂回するキャストを使わない」）
- 定数・テーブル・設定の定義は型注釈ではなく **`satisfies`** で検査する（「型注釈より `satisfies`」）
- **常駐プロセスは描画1回の失敗で落ちない。** 即時終了は起動時の前提不足だけ。描画ループに `try`/`catch` を散らさない（「エラーハンドリング」）
- 環境変数・パスはモジュールのトップレベルで触らない（「外部の入力を読む場所を1つにする」）
- **`| undefined` は6つの場所でだけ**書き、`?:` は使わない。2つ以上の `| undefined` が1つの状態なら判別可能な合併型。「無い」は入口で畳む（「「無いかもしれない」値」）
- **`null` を自前の型・戻り値・`shared` に出さない**（外来の `null` は境界で `undefined` に畳む。「null は自前の型に出さない」）
- 可読性が良くなる場合は **remeda** を優先する（「可読性が良くなる場合は remeda を優先する」）
- **案が2つ以上あるときは、書いたあとのコードを読む人が把握しやすいほうを選ぶ**（工数と行数は指標にしない）。**機械的な仕組みをヒューリスティックより優先する**（「案を選ぶときの指標」「仕組みをヒューリスティックより優先する」）
- コードの識別子は `docs/glossary.md` の「英語識別子」（`英語識別子（予定）` を含む）に合わせる。変えるなら、コードより先に用語集を直す（「識別子は用語集に合わせる」）

- **`develop/progress.md` の衝突を、カスタムのマージドライバで畳む**（2026-09-23 にユーザーが依頼。

  - **測ったこと**: `develop/progress.md` を触った直近40コミットのうち、タスクの完了コミットは
    **ほぼ全部が `@@ -57` から始まる**（`## 完了したこと（このセッション）` の直下に小節を差し込む
    動きを、全セッションがやっている）。T-393 と T-388 の衝突もこの1か所だけで、中身は
    「両側が別々の小節を先頭に足しただけ・共通祖先は空」という純粋な追加どうしだった
  - **採る案**: `.gitattributes` に `develop/progress.md merge=progress` を置き、
    `scripts/merge-progress.ts` を3wayのマージドライバとして登録する（`%A %O %B` を受け取り、
    `## 完了したこと` の節を `### ` 見出しで小節に割って、両側が**足した**小節を両方残し、
    両側が**消した**小節は消えたままにして書き戻す）。`## 未解決` と `## 注意` は通常の3wayに任せる
  - **確かめたこと**（空のリポジトリで実験、2026-09-23）: (1) `.gitattributes` に `merge=progress`
    と書いてあってもドライバが `git config` に無ければ**git は黙って既定の3wayに落ちる**ので、
    設定し忘れても今と同じ挙動にしかならない（壊れない）。(2) 作業ツリーの中で
    `git config --local` を打つと**共通の `.git/config` に書かれる**ので、登録は1リポジトリに1回で
    全部の作業ツリーに効く
  - **採らない案**（蒸し返さない）: `merge=union` は削除を打ち消すのでアーカイブが巻き戻る
    （既に「未解決」に書いてある）。**1タスク1ファイル**（`develop/progress/T-xxx.md`）は衝突は
    消えるが、`~/.claude/skills/task-workflow/scripts/` の `archive.py` / `status.py` が
    `## 完了したこと` の `### ` 小節を数える作りで、しかもこのスクリプトは**複数のプロジェクトで
    共通**なので、ここの都合で触らない。**並び順を変える**（古い順にして末尾へ足す）のは、
    両側が同じ位置へ足すことに変わりがなく衝突が消えない
  - **効き目の範囲**: アーカイブ判定の `is_newest_first` は**日付だけ**を非増加で見ているので、
    同じ日の小節どうしの前後は自由。ドライバが両側の小節を並べる順は問わない
  - **出し先**:
    1. 実装のタスク（`scripts/merge-progress.ts` と `.gitattributes`。割る/畳むの処理は純粋な
       関数にして `test/scripts/` にテストを置く。「両側が足した」「片方が消した（アーカイブ）」
       「節が無い」「片方だけが触った」を確かめる）

       `git config merge.progress.driver` を1回打つことを足すタスク（`- 新しい作業ツリーの
       立ち上げは人がやる` の箇条書きと揃える）

       1行足すタスク（`develop/progress.md` はドライバが畳むので手が要らない、それ以外が
       衝突したら止めて預ける）
    4. 通ったら「未解決」の **`develop/progress.md` の完了ブロックを分けるかは未決** の行を畳む

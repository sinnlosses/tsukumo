#### 1. 現状の経路（イベント → 筆先の座標 → 立ち絵の位置）

1. **出る引き金は「確定したレポートが、やり取りを描き始めたあとに現れたとき」だけ。**
   `turn.tsx` が `final` の立っている最後のステップを選び、**マウント時点で既にあった本文なら選ばない**
   （過去のタブ・再読み込みでは出ない）。`prefers-reduced-motion: reduce` では演出ごと走らない
2. `report-reveal.ts` がレポートの根を受け取り、`reveal-plan.ts` が**トピック**（見出し・水平線が境目）に
   割って、塊ごとに「出し始め／出し終わりの時刻」を決める（文字1つ 40ms、塊ごとに下限 2400ms・
   上限 8000ms）。DOM は完成品のまま置き、**見せる範囲だけ**を進める
3. 毎フレーム `advanceBlock()` が走る。塊の中の行を上下2つの**帯**に割り、帯を左から右へなぞって
   斜めに戻る（Z字）。横の振れ幅は**塊を囲む枠の幅**（`frameOf`＝いちばん広い要素の幅）で、
   縦は帯の上端・下端。**文字の要素は `clip-path`、図・グラフは `opacity`** で見せる
4. そのフレームの筆先を `{ x, top, bottom }`（**ビューポート座標**）で `publishBrushTip()` に渡す。
   同時に `brush-scroll.ts` が、筆先が器の上下 96px に入ったら器を送る
5. `mini-portrait.tsx` が `useBrushTip()` で受け、**筆先があることだけ**を条件に描く
   （`character.mini` が無いパックは `portraits.default` の縮小に落ちる）。位置は
   `transform: translate3d(x, bottom) translateY(-100%)` ＝ **筆先の右・いまの帯の下端に立つ**。
   `position: fixed` + `left: 0.4rem` なので、姿の左端は筆先の 6.4px 右
6. 出し切る／利用者がホイール・指・ポインタ・キーで打ち切ると `publishBrushTip(undefined)` で**消える**

**いまの調整箇所は6つだけ**（`mini-portrait.module.css`）: 高さ（本文の行の3倍）・不透明度（1）・
筆先との余白（0.4rem）・追従の時定数（0.05s）・縁の drop-shadow（地の色×2）・暈の drop-shadow（差し色×2）。
**`<Portrait>` の4つの動き（呼吸・移動・完了の反応・失敗でびくっ）は渡していない**ので、
ミニ立ち絵が持つ動きは筆先への追従だけ。

##### (4) ターンの途中の `turn-finished`（場面 `narration-flash`）

```

```

`turn-finished` で `turnInProgress` が false になると `hideUnsettledReport` が効かなくなるので、

  transcript を読み終わる前に依頼を送る、という細い窓を狙う必要がある。
  手順としては「`TSUKUMO_NEW_SESSION` を付けずに起こし、URL が出た直後に入力欄へ送る」
- **`limitTurnEntries`（#6）**: 作為的な並び（1ターンに中間レポート45件）でなら
  「古い中間レポートが落ちる」ことを畳みの上で確認したが、**現実の会話では到達しない**
  （2026-09-17 の実測で1つのやり取りの最大は6件・p99 で4件）。台本は足していない
- **#9 / #10**: コードを読んで閉じていることを確認しただけで、外す実験はしていない
  （`useReportReveal` は `useLayoutEffect`、`applyFrame` は `reduce` して1回 publish）

#### 4. 経路ごとの案

##### (4) ターン途中の `turn-finished`

- **案4-a: `hideUnsettledReport` の条件から `turnInProgress` を外す。** 「最後のステップに
  ツールが付いていないなら出さない」だけにする。壊れるもの: **ツールを1度も呼ばないターンの
  最終レポートが永久に出なくなる**ので、「そのターンは終わった」を別に持つ必要がある
  （例: `turn-finished` を受けた時点の記録に確定の印を立て、畳みはその印を見る）。
  **経路(4)と(5)を同時に塞げる唯一の案**だが、`MainViewStep` に状態が1つ増える
- **案4-b: 復元の再生を依頼より前に終わらせる。** `replayRestoredSession` を待つ／再生中は
  入力欄を止める。壊れるもの: 起動から入力できるまでが transcript の長さぶん遅くなる
- **案4-c: 入れ子の `result` を `turn-finished` にしない**（`parent_tool_use_id` があれば捨てる）。
  未確認の経路への保険で、単体では安い。壊れるもの: ほぼ無い
- **案4-d: 何もしない。** 起きる条件が狭く、実測の露出も 1.2 秒

##### (5) ツールが続かない実況が残る

- **案5-a: 構造の印（`isInterimReport`）を全ての本文に掛ける。** 「ツールが続いたか」を問わず、
  **印が無く短い本文は落とす**。ただし**そのターンの最終レポートだけは常に残す**という例外を
  付ける（でないと短い返事のターンで本文が空になる）。いまの判定を1つ緩めるだけで、
  `keepOnlyInterimReports` の二条件が「構造の印」1つに寄る。**いちばん素直**
- **案5-b: `speech` もツールに数える。** `mainViewEntries` が落としている `speech` を
  `MainViewEntry` に残し、`hasToolRun` を「あとに何か続いたか」に広げる。壊れるもの:
  「質問はツールに数えない」という既存の例外と並んで、数える／数えないの表が増える
- **案5-c: 最後のステップ以外も「次の本文が出たら落とす」。** 乱暴。まとまった資料が
  連続するターンで中間レポートが全部消える
- **案5-d: 何もしない。** 出たまま残るだけで、出たり消えたりはしない

##### (3) 中間レポートの畳み

- **案3-a: いまのまま**（開いて出し、後続が出たら畳む）
- **案3-b: 最初から畳んで出す。** 「一度出したものは畳まない」が守られ、経路(3)が消える。
  壊れるもの: 中間レポートを読むのに毎回1クリック要る
- **案3-c: 畳まず、地を落として小さく出す。** 壊れるもの: 何件も積むと見通しが悪い
  （2026-09-16 の指摘がそのまま戻る）

#### 5. 推奨

1. **まず切り分ける。** ユーザーが見た「一瞬出て消える」が T-258 で消えているかを次の数ターンで確認する。
   まだ出るなら経路(4)、「出たまま消えない実況が混ざる」なら経路(5)
2. 経路(5)が当たりなら **案5-a**（構造の印を全ての本文に掛け、最終レポートだけ例外）。
   判定が1つに寄るぶん、あとで読む人が追う条件が減る
3. 経路(4)が当たりなら **案4-c**（入れ子の `result` を捨てる）を先に入れ、それでも出るなら
   **案4-a**（確定の印）。**案4-a は経路(5)も同時に塞ぐ**ので、両方出るなら案4-a 1本でよい
4. 経路(3)は**いまのまま（案3-a）**を推す。畳むのは仕様で、出てから畳まれるまでの時間は
   「次のレポートが出るまで」＝読む時間として意味がある

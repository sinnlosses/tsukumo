# 未対応の指示メモ（ここに書くと次のセッションが `/plan-tasks` でタスク化する。正典: `docs/workflow.md`）

## 2026-09-11 方針の全面見直し（grilling Q1〜Q16 の回答）

出発点のユーザーの言葉: 「今までの履歴を見れば分かる通りあまりうまくいっていない。なので改めて
tsukumo の要件を詰めたいのと、どの技術でそれが実現できるか一緒に考えてほしい。」

### 合格シーン（Q1）

- **TUI を一度も見ない**のが理想。「この orca のように統合されたアプリケーション内でキャラと
  一緒に仕事がしたい」
- v1 の合格シーン: **1コマンドで起動すると1つの画面が開く。そこで依頼を打つと、左下のキャラが
  話し、左上にレポートが出て、キャラが質問したら画面上のボタンで答えられる。Claude Code の
  TUI は一度も見ない**

### 技術の選択（Q2〜Q4）

- **Q2: Claude Code の TUI を捨て、Agent SDK（`@anthropic-ai/claude-agent-sdk`）で tsukumo が
  Claude Code を動かす。** 会話・ツール実行・許可プロンプト・質問を構造化イベントで受け取り、
  入力欄・許可ボタン・質問の選択肢を tsukumo が描く。transcript 追従・追従先の乗り換え・
  hook の状態ファイル・Orca 経由の入力送信は役目を終える。端末（PTY）は「後から同じ画面に
  足せる余地」だけ残し、最初は作らない
- **Q3: セリフはテキストの規約ではなく、tsukumo が提供する MCP ツール `speak(text, expression)`
  で受け取る。** 行頭 `アスナ: ` の切り出しは補助に格下げ。ツールの戻り値は「ok」だけにして、
  実質的な逆流はさせない
- **Q4: 箱は当面 Orca のブラウザタブ。** ページは「どの箱でも動く Web アプリ」として作り、箱の
  差し替えを1箇所に閉じる。**最終形は「使い勝手が上がるなら」Electron 等のスタンドアロン**。
  Electron の判断は縦1本が動いてから
- **Bun のまま**（SDK は Bun を公式にサポート。Electron に行くときも Bun のプロセスを子として
  起こせば済む）
- 原則「tsukumo から Claude Code へ戻る経路は無い」は消える。代わりに**「会話は tsukumo の
  プロセスの外へ出さない」**が残る（SDK もツールもローカルのプロセス内で閉じる）

### 画面の中身（Q5、Q7〜Q12、Q16）

- **Q5: メインビュー（左上）はレポートだけ。** 作業の進行（ツールの流れ）はサイドバーへ
- **Q7: 許可プロンプトはキャラが聞く。** 吹き出しに「これ実行していい？」と出て、その下に
  許可／拒否のボタン。AskUserQuestion の選択肢と同じ見た目。許可モード（毎回聞く／編集は
  自動／全部許す／プラン）を画面から切り替えられる。既定はいまの auto モード相当
- **Q8: 入力欄の v1 は (1) 複数行入力＋送信、(2) 実行中の中断、(3) `/` のコマンド補完**
  （`system/init` の `slash_commands` から）。入力履歴と「`/loop` 代替の繰り返しトグル」は次。
  画像・ファイル貼り付けはやらない
- **Q9: セッションは毎回新規（TUI と同じ）。** 再開は要らない。モデルの切り替えは `/model` を
  送るのではなく画面の選択肢から SDK のオプションで渡す
- **Q10: `speak` の引数は `text` と `expression`**（キャラ定義ファイルにある表情名から選ぶ）。
  衣装はモデル連動のまま。**表情は引数を主にして、ツール実行中は自動で「作業中」の顔**
  （いまの `src/expression.ts` の推測を流用）。呼ぶタイミング（着手の一言・ステップごと・
  完了報告・質問や許可のとき）は出力スタイル側に書く
- **Q11: サイドバーは上から (1) いま何をしているか**（実行中のツールを1行、終わったものは
  薄く数行）、**(2) `develop/tasks.json` のタスク一覧**（要約列）、**(3) セッション情報**
  （モデル・許可モード・経過時間）。コンテキスト使用量は出さない
- **Q12: レポートはリッチのまま。** 「今の表示は改善点はありつつわりと気に入っているから、
  不要なライブラリは削除していいけど簡素になるのは避けてね」。**highlight.js / mermaid /
  Chart.js / HTML 直書き（サニタイズ付き）は全部残す。** 捨てるのは PTY 路線の xterm だけ
  （stash に退避済み）。1ターン＝1枚、T-025「レポートはキャラの口調で書かない」は維持
- **Q16: 応答の途中経過をリアルタイムに流す。** メインビューに書きかけのレポートが
  流れていき、完成した瞬間に整形し直す

### 進め方（Q13〜Q15）

- **Q13: 順番**
  1. **スパイク（半日）**: SDK で claude を起動し、出力スタイル（`asuna.md`）が効くか・`speak`
     ツールが呼ばれるか・許可と質問が `canUseTool` に届くか・auto モード相当の許可モードが
     SDK にあるかを実機で確かめる。駄目なら方針に戻る
  2. **縦1本**: 入力欄 → SDK → セリフが吹き出しに、本文がレポートに → 許可と質問にボタンで
     答える。Orca のタブ1枚で、合格シーンが1往復だけ成立する。**触れる状態になるのはここの
     終わり**
  3. **横に広げる**: サイドバー3区画、作業中の自動表情、コマンド補完、中断ボタン
  4. **Electron の判断**: 3 まで使ってみて決める
- **Q14: PTY 路線の未コミット分は捨てる**（承認済み。auto モードの安全弁で削除が止まったため
  `git stash`「PTY路線（T-032後の未コミット分。方針転換で不採用）」に退避した。戻す予定は無い）
- **Q15: 既存タスク（T-020〜T-034）は「方針転換で不要」として一括アーカイブし、`/plan-tasks` で
  切り直す。** ドキュメント（`CLAUDE.md` の「サイドカー方式が唯一の解」、`requirements.md`
  3章、`architecture.md` の設計判断）の書き換えを**新しいタスクの1件目**にする（コードより先に
  正典を直す）。**出力スタイル `~/.claude/output-styles/asuna.md` の改訂も1タスク**にし、
  グローバル設定なので実行時に承認をもらう
- **Q6: 作り直し前提で始め、使えるものだけ拾う**: キャラクター定義・表情の対応・レポートの
  HTML 化・レイアウトページ・SSE 配信

# 未対応の指示メモ（ここに書くと次のセッションが `/plan-tasks` でタスク化する。正典: `task-workflow` の `WORKFLOW.md`）

## ユーザーから

- **差分（```diff）を出すときは、ファイル名を左上にラベルとして出す。** いまは `+` / `-` の
  色分けだけで、どのファイルの差分か地の文に書かないと分からない（実測: 2026-09-22 のレポートで
  `develop/tasks.json` の差分を出したが、ファイル名はブロックの外にしか無かった）
  - 出し先: 記法の側（`src/server/core/report-notation.ts`「内容ごとの印」の表の「変更の前後は
    ```diff」の行）と、描く側（`src/browser/features/main-view/markdown/markdown.tsx` が `pre` を
    上書きしている。mermaid / chart と同じ経路）
  - 決めること: ファイル名をどう渡すか（フェンスの info 文字列に載せるのか、別の印にするのか）。
    書き忘れたときにどう出すか（ラベルを出さない／`diff` のまま出す）

- **左に縦罫＋地の色を変える囲い（`note`）は見やすいので、種別を整理して左上に種別のラベルを出す。**
  いまラベルが出るのは「お願い」（`note-favor`）だけで、`note` / `note-warn` / `note-ng` は
  色の違いしかない。ユーザーが挙げた種別の候補は **お願い・情報・注意・異常（危険）・メモ・疑問**
  - 出し先: `src/server/core/report-notation.ts`（「内容ごとの印」の表の `note` の行を種別ごとに
    割る）と、`src/browser/features/main-view/markdown/notation.tsx`（class から種別を引いて
    ラベルを足す。いまは `note-favor` だけ特別扱い）と
    `src/browser/features/main-view/main-view.module.css`
  - 決めること:
    - 種別の最終セット（6つで確定か、統合するか。「注意」と「異常（危険）」は段が違うだけ、
      「メモ」と「情報」も近い）
    - **色。`docs/design.md` 13.1 原則5 が「状態の3色（ok / warn / ng）は増やさない」と
      言っている**ので、新しい種別の色は**状態の3色を増やさずに**差し色（accent）や導出
      （`ink-quiet` / `rule`）から作るか、原則5のほうを書き換えるかを決める
    - ラベルの文字を tsukumo 側で足すか（`note-favor` は既にそうしている。モデルが書き忘れても
      種別が消えないのが利点）、モデルに書かせるか
    - 「1つのレポートに1〜2個まで」という既存の上限を種別ごとに持つのか、全体で持つのか


## エージェントのドラフト

- **起こし直さないと変わらないものを確かめる作法を `docs/workflow.md`「起こすときの作法」に足す**（振り返り: T-302）
  - 根拠: T-302 の完了条件「`speak` の enum に `bored` が入っている」は、enum が**セッション起動時**に
    `expressionChoices(pack.definition)` から組まれるため、動いているセッション自身では確かめられない
    （実測: 定義ファイルを直したあとに `zzz-not-a-face` を投げても候補は8件のまま）。さらに別インスタンスを
    既定のまま起こすと**同じ作業ツリーの直近セッションを resume する**ので、`TSUKUMO_NEW_SESSION=1` が要る
  - 出し先: `docs/workflow.md`「起こすときの作法」に、`TSUKUMO_VIEW_PORT` と並べて
    `TSUKUMO_NEW_SESSION=1` を足し、「起動時に作られるもの（`speak` の enum・パックの読み込み）は
    起こし直さないと変わらない」を1行で書く

- **「触らない」と書く資源は、完了条件の確認手順と突き合わせてから書く**（振り返り: T-302）
  - 根拠: T-302 の `## 注意` は「`~/.tsukumo/state.json` には触らない」だったが、完了条件
    「`characters/local` に切り替えても壊れない」を確かめると画面のパック切り替えが state.json を書き換える
    （実測: `{"character":"tsukumo"}` → `local`。確認後に画面から戻して復旧した）。禁止と手順が矛盾していた
  - 出し先: `docs/workflow.md`「タスクを書くとき・受け入れるとき」に、**確認手順が触る資源は
    「触らない」ではなく「確認後に元の値へ戻す」と書く**を足す

- **語彙を1つ増やす変更は、型検査が挙げない「件数に依存したテスト」を疑う**（振り返り: T-302）
  - 根拠: `EXPRESSIONS` に `bored` を足したとき、型検査が挙げた漏れ（`character-definition.ts` /
    `character.ts` / フィクスチャ16ファイル）を全部埋めてもテストが1件落ちた
    （`character-edit.test.tsx` の立ち絵の無い枠の期待値 5→6）。タスク本文の「やること2」は
    `bun run typecheck` の漏れだけを指していて、この1件は `bun test` で初めて出た
  - 出し先: `docs/coding-standards.md`「テスト」節に、**語彙（`EXPRESSIONS` など）の長さに
    依存する期待値をテストに直書きするなら、語彙を増やす側から見つかる形にする**（定数から導く、
    またはタスクの書き方として「typecheck のあとに必ず test も見る」）を足す

- **キャラクターのフィクスチャを `test/fixture/` の組み立て関数1つに寄せる**（振り返り: T-302。
  ユーザーが振り返りをレビューして指摘した分）
  - 根拠: T-302 の diff 22行のうち **20行が `bored: undefined` の1行**で、14ファイルに散らばっていた。
    `test/` 配下には表情キーを1行ずつ並べただけの行が **222行**、差し色キーが31行ある。
    表情を1つ足すたびに、振る舞いを何も変えないまま 20行が増える
  - 原因: 14個のテストが `NonNullable<SessionState["character"]>` を**手で全キー書き下している**。
    `?:` を使わない規約のため全キーが必須で、語彙が伸びると全ファイルに波及する
  - 出し先（タスク）: `test/fixture/character.ts` に既定値と組み立て関数を置き、各テストは
    **差分だけ**渡す形にする。`docs/coding-standards.md`「消すかどうか」の表が既に
    「同じモックの準備が複数ファイルに重複している → 準備を共通のフィクスチャに寄せる」と
    言っているので、規約の変更は要らない（守れていないだけ）。オプション引数の中身は
    `?:` を使ってよい5つ目の場所に当たる（`CLAUDE.md`「`| undefined` は5つの場所でだけ」）
  - 順序: **T-314 より先にやると T-314 が小さくなる。** T-314 は `CharacterInfo.portraits` を
    全域の `Record<Expression, string>` に畳むので、フィクスチャは「8つの undefined」から
    「9つの文字列」に書き換わるだけで、寄せていないと同じ14ファイルをもう一度触ることになる

## レポートを読む時間を減らす（T-062 の決定からの後続。2026-09-13）

決定の本文は `docs/requirements.md` 4.2「読む時間を減らすために足すのは、規約の側」。
**足すのは規約が主**で、コードは規約が要求する分だけ足す。3件を想定している。

1. **`src/presentation/report-notation.ts` の文面を「印」の語彙表に作り直す**（いちばん重要）。
   いまの文面は「使ってよい構造」の一覧止まりで、**どの内容にどれを当てるかの判断が書かれていない**。
   内容の型（結論 / 比較 / 手順 / 状態 / 根拠 / 長い補足）ごとに当てる `class` と書き方の例を
   与える。冒頭は結論、根拠は `details` に畳む、状態は `badge`、並置は `cols` + `card`、を
   例つきで。**書き手が最初からその構造で書くのは再構成ではない**（決定の線引き）
2. **GFM テーブルの列揃え `:---:` に対応する**（`renderMarkdownToHtml` の `consumeTable`）。
   区切り行のコロンを読んで `th` / `td` に左・中央・右を当てる。数値の桁が揃わないのが
   読む速度に効くため。T-063（引用・ネスト・水平線）と同じ関数を触るので、まとめてよい
3. **`dl` / `dt` / `dd` の CSS を `main-turns.css` に足す。** 許可リストには入っているのに
   見た目が無く、用語と説明の対（`.detail-block dl`）が素の字下げのまま出る。
   T-092（セッション情報のラベルと値を縦に揃える）と見た目の方針を揃える

**やらないと決めたもの**（蒸し返さないこと。理由は 4.2 の決定に書いた）: 外部 Markdown
ライブラリの同梱、`img` の許可、レンダラによる自動の段組み・目次・要約の生成、`.note` の種類追加。

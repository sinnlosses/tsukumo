- 根拠: GH-468 の段4で、後段6件の `tw edit` が GitHub の 500 で再試行を重ね、1回の呼び出しが2分の上限を超えて背景へ回った（長く待った呼び出し 227秒・131秒）。Beads への書き込みは済んでいて、反映の落ちた分は `tw sync` で打ち直せるので、待っても得るものが無かった
- 出し先: claude-skills の task-workflow の `tw edit`（Beads 方式のトラッカーへの反映）。5xx のときは再試行を短く切って `TRACKER\tFAILED` を返し、打ち直しは `tw sync` に任せるタスク

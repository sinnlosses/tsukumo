## 目的

タスクの状態名 `hold` を `pending` に、`dropped` を `cancel` に改める（2026-09-27 ユーザーの指示）。

## 完了条件

- task-workflow スキル（`WORKFLOW.md`・`scripts/`）と、それを使うスキル（`next-task`・`plan-tasks`・`list-tasks`・`retrospect`・`setup-tasks`）の状態名を改め、スキルの検査（`./check.sh`・`selftest_task.py`）が通る。claude-skills のリポジトリで別の作業ツリーを作って行う
- このリポジトリの `develop/task/` の既存のファイルと、git の外の台帳の状態名を移している（`task status` が `invalid 0` を返す）
- `docs/workflow.md` と CLAUDE.md の状態名を直している（`docs/history/` は当時の記録なので直さない）
- tsukumo の読み手（`src/shared/task-summary.ts` とそれを使うタスク板・成果）が新しい状態名を読み、WORKFLOW.md「タスクファイル」の読み取りの見本がそのテストにも写っている
- `bun run check` が通る

## 背景

- 状態名の正典は `~/.claude/skills/task-workflow/WORKFLOW.md`。`task` コマンドの出力（`HOLD` など）や `--hold` のフラグ名も状態名に結びついている
- 登録時、`develop/task/` を使っているのはこのリポジトリだけ
- 状態名は tsukumo の読み手にも結びついている（`src/shared/task-summary.ts` の文法、`src/server/achievement/` の成果、タスク板の表示）。スキルの改名と同じ時点で読み手も新しい名前を受けるようにする（着手時に `grep -rn "'hold'\|\"hold\"\|'dropped'\|\"dropped\"" src test scripts` で一覧を取り直す）

## 注意

- 前段（T-733）は GitHub Projects へ移さないと結論した（`docs/research/github-projects.md`）。この改名は今の `develop/task/` と台帳の運用のまま行う
- `~/.claude/skills` は claude-skills の本体の作業ツリーへの symlink。本体で枝を切ると動いている全セッションのスキルが入れ替わるので、別の作業ツリーで編集してから `main` に入れる
- 古い名前で書かれたファイルを読んだときの扱い（読み替える・`invalid` にする）を決める。tsukumo の成果（`src/server/achievement/`）は `git log` で過去の版のタスクファイルを読むので、過去の版の `hold`・`dropped` は改名のあとも読めなければならない

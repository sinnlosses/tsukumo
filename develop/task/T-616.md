## 目的

`components/ui/` に `select.tsx`・`select.module.css`・`image-zoom.tsx`・`image-zoom.module.css` が平たく並んでいて、部品が増えると見づらい。`ui/select/`・`ui/image-zoom/` のように部品ごとのディレクトリへ分ける（ユーザーの希望）。後段で variant 部品が増える前に置き方を決めて移す。

## 完了条件

- `src/browser/components/ui/select/select.tsx`・`select.module.css`、`src/browser/components/ui/image-zoom/image-zoom.tsx`・`image-zoom.module.css` に移り、読む側の import（`components/domain/sidebar/character-switch.tsx`・`session-switch.tsx`、`components/domain/screen-nav/components/screen-nav-model-permission.tsx`・`screen-nav-settings.tsx`、`image-zoom` の読み手）が新しいパスを指している
- テストも同じ形に移っている（`test/browser/components/ui/select.test.tsx` → `test/browser/components/ui/select/select.test.tsx`。テストの置き方の正典は `docs/coding-standards.md`「テスト」節）
- `docs/design.md` 2章の「1部品1フォルダは真似しない」の一文に、`components/ui/` だけは部品ごとのディレクトリを切る例外を足してある（理由: 語彙を持たない部品は数が増え、部品と CSS の対が平たく並ぶと見づらい。2026-09-25 のユーザーの希望）。同章の部品の置き場の段落（「語彙を持たない `<Select>`・`<ImageZoom>` は `components/ui/`」）など、パスを書いた箇所も追随している
- `test/architecture.test.ts` の「`components/ui/` はいまサブディレクトリを持たないので、そのまま全体を対象にする」のコメントが実態に合っている（検査の中身は、部品ごとのディレクトリになっても `components/ui/` 全体を見続けること）
- `bun run check` が通る。移しただけなので絵は変わらない（サイドバーのプルダウンと画像の拡大を開いて見た目が同じことを目視し、結果に書く）

## 決まっていること（蒸し返さない）

- **`index.tsx` は作らない。** ユーザーは「作ってもいい」と言ったが、`docs/coding-standards.md`「barrel file を作らない」（tree-shaking と、`index` という名前が何も指さないこと）に当たるので、ディレクトリの中のファイル名は部品の名前（`select.tsx`）のままにし、import は `../ui/select/select.tsx` と実ファイルを指す
- ディレクトリを切るのは `components/ui/` だけ。`components/domain/` の直下や機能の中の部品には広げない

## 背景

- いまの `components/ui/` は `select.tsx`（56行）・`select.module.css`・`image-zoom.tsx`（76行）・`image-zoom.module.css` の4ファイル
- `docs/design.md` 2章（378行付近）は「手本から採るのはディレクトリの形だけで、kebab-case のファイル名・barrel file（`index.ts`）を作らない・`@/` を使わない相対 import はそのまま（PascalCase・1部品1フォルダは真似しない）」と書いている
- `test/architecture.test.ts` の「browser/ の機能をまたぐ箱」の検査は、`browser/components/ui/` で始まるパスを全部対象にしている

## 目的

`test-audit` スキルのキャンペーンモード（同スキルの `CAMPAIGN.md` の8段）で、`test/server/chat/` `test/server/diary/` `test/server/achievement/`（10ファイル・約3,700行） のテストを刈り込む。価値の低いテスト・実装に結合したテスト・より強い証明と重なるテストと、テストしか呼ばない本番コードを消し、残す契約はより強い境界のテストに寄せる。

## 完了条件

- 対象範囲のテストの宣言ごとに `R` / `F` / `C` / `D` の印と1行の証拠を付けた台帳を作り、印ごとの件数と、`C` / `D` の宣言ごとの残す側（keeper）を タスクの結果 に書く（台帳の全文はリポジトリに置かない）
- `D` / `C` の編集と、それで消せるようになったテスト専用の本番コードの継ぎ目の削除を済ませる
- 移した（`C` / `F`）契約ごとに、本番側の持ち主にわざと1つ変異を入れて keeper が落ちることを確かめ、元に戻す
- 基準線（着手時）と完了時の、対象範囲のテストの `it` の数と行数、本番コードの増減を タスクの結果 に書く
- `bun run check` が通る
- 確信の持てる候補が無ければ、台帳の件数だけ書いて編集なしで `done` にしてよい

## 背景

- 2026-09-25 に `test-audit` スキル（openclaw/openclaw の同名スキルを日本語化して claude-skills に入れたもの）を取り込み、監査モードの試運転で、テストだけが呼んでいた `parseAnswer`（`src/shared/pending-ask.ts`）と `newFormatTaskSummaries`（`src/shared/task-summary.ts`）を消した。固有の検査は `test/shared/command.test.ts` と `test/server/repository/adapter/task-summary.test.ts` に移した（`0b3ef70a`）
- テスト全体は 205 ファイル・約4.7万行で、機能ごとに1タスクに分けた。このタスクはserver の chat・diary・achievementの範囲

## 決まっていること（蒸し返さない）

- 消すかどうかは `docs/coding-standards.md`「テスト」節の「消すかどうか」「埋めないと決めた穴」と突き合わせる。スキルの残す基準とリポジトリの規約が食い違ったら、リポジトリの規約を優先し、食い違いを タスクの結果 に書く
- 残す基準は、スキルの `SKILL.md`「残す基準」のとおり（とくに、出力の書式を固定するテストと過去のバグの退行テストは残す）
- `CAMPAIGN.md` の段7（プロダクトの欠陥）で見つけた欠陥は、このタスクでは直さず、`develop/direction.md` の 「エージェントのドラフト」節 に積む。段8（`main` の merge）はタスクが短いので要らない
- 1タスク＝1コミット。対象範囲の外のテストは、範囲内の契約を吸収する keeper になるときだけ触る

  `test/server/achievement/`（2ファイル・1,136行）の計10ファイル・3,712行・216件の `it`。
  タスク本文の見立てと一致し、範囲は崩れていない。基準線は `bun test --isolate` で
  216 pass / 0 fail
- `test-audit` スキルと `CAMPAIGN.md` の8段のうち、段3〜6（レーンごとの読み取り専用の台帳→層の
  計画→切り替え→保全のレビュー）を、本文の「注意」の指示どおり自分でレーンを順に読んで行う
  （別エージェントを立てない）。段7（プロダクトの欠陥）は直さず `develop/direction.md` へ、
  段8は本文の指示どおり省く
- レーンは本番側の持ち主の境界で切る: (1) `chat/core`（`chat-compact` / `chat-memory-prompt`、
  純関数）(2) `chat/adapter`（`chat-archive` / `chat-summary` / `persona-memory`、実ファイル
  システム境界）(3) `diary/core`（`diary-tool`、純関数＋パーサ）(4) `diary/adapter`
  （`diary` は実 git 境界、`sdk-diary` は SDK の生メッセージを畳む純粋な観測）
  (5) `achievement/core`（`achievement`、純関数）(6) `achievement/adapter`（`main-history`、
  実 git 境界）
- 全10ファイルを本番側の持ち主と突き合わせて読んだ結果、ほとんどは境界ごとに1つの強い持ち主
  （実ファイルシステム・実 git）に主たる契約を置き、core 側の純関数はその手前の分岐を1つずつ
  別テストで固定する、という設計になっており、目立った重複は薄かった。見つけた確信の持てる
  候補は次の2種類のみ:
  - `chat-archive.test.ts` と `chat-summary.test.ts` に1件ずつあった「テストは一時ディレクトリ
    だけに書き、本物のホームには触らない」という名前のテスト（`D`）。名前が約束する「本物の
    ホームに触らない」ことは検査しておらず（毎回明示的に一時ディレクトリを渡しているので
    触りようがない）、実際にアサーションしている「書いた場所にファイルが並ぶ」は同じ
    `describe` 内の別のテスト（パック・日ごとに別ファイルになる／write すると読める）が
    既に固定している
  - `persona-memory.test.ts` の `forgetRememberedLineFromScreen` が、`forget` と同じ共有の
    突き合わせロジック（`forgetTarget` / `personaWithoutRememberedLine`）を経由するにも
    関わらず、その突き合わせの細部（`- ` の印を吸収する・一致しなければ何もしない・人が書いた
    箇条書きは消さない）を独自にもう一度検査していた3件（`C`。まとめ先は `forget` の同名の
    3テスト）。ラッパー固有の契約（1ターン1行の上限が掛からない・戻り値そのもの・
    `characters/local` の除外）は個別の持ち主なので残す
- 作業として、上の `D` 2件・`C` 3件を消す。残りは編集なしで進める（確信の持てる候補が無い、
  完了条件の最後の1行のとおり）

## 注意

- 変異を入れて確かめるときは、退避したコピーから戻す（`git checkout --` で戻すと、同じファイルへの先行の編集ごと消える）
- `CAMPAIGN.md` の段3・段6は、別のエージェントに読ませることを求めている。サブエージェントの中で別のエージェントを立てられないなら、レーンごとに順に自分で読み、段6の保全のレビューは受け入れのときにメインが行う
- ブラウザに出る絵は自動テストで守らない方針（`docs/architecture.md`）なので、描画のテストを消すときも、足すときも、その方針の範囲で判断する

## 目的

成果の画面の一番上の日記の区画（立ち絵と吹き出し）が狭く、日記が書かれると吹き出しが縦に長く伸びる。区画の横幅を広げて、同じ本文でも縦に伸びにくくする（2026-09-25 のフィードバック。スクリーンショットでは 9 行に折り返していた）。

## 完了条件

- 日記の区画が今より横に広く、同じ長さの本文（全角 250 字前後）で吹き出しの行数が目に見えて減る
- 狭い窓（Orca の半分幅くらい）で横スクロールが出ない
- 広げた幅と理由が `docs/screen-design.md` 13.10 に書かれている
- `bun run check` が通り、`bun run build` のあと成果の画面を開いて、日記のある日とない日の両方で見え方を目視で確かめる

## 背景

- 画面全体の幅は `src/browser/features/achievement/achievement.module.css` の `.achievement` の `max-width: 40rem` で決まっている。日記の区画 `.achievement-diary` は `grid-template-columns: minmax(7rem, 9.5rem) minmax(0, 1fr)` で、立ち絵の列が最大 9.5rem を取る
- 画面の形の正典は `docs/screen-design.md` 13.10「成果の画面」

## 決まっていること（蒸し返さない）

- 広げるのは幅。本文の字の大きさは変えない（書体の段は `docs/screen-design.md` の書体の表のまま）

## やること

前提の調べ直し: T-582〜T-585 の移行は着手時点で完了しており、成果の画面は
`src/browser/components/page/achievement/`（`features/achievement/` ではない）にある。
CSS は `achievement.module.css`、日記の区画は `diary-section.tsx` + `.achievement-diary`。
`.achievement` は T-596 のあとも `max-width: 40rem` のまま（吹き出しは `.achievement-diary-bubble`、
本文の書体は `--font-serif` / `--font-body`（0.9375rem）・`line-height: 2` で未変更）。前提は崩れておらず、
作業は要る。

- **区画だけでなく画面全体（`.achievement`）の `max-width` を 40rem → 60rem に広げる。** 理由:
  - 日記の区画 `.achievement-diary` の下に並ぶしおり・小さな驚き・灯りの暦は同じ `.achievement`
    の中で縦に並ぶ1本の列（`docs/screen-design.md` 13.10 の見本のとおり）。日記の区画だけを
    はみ出させると、区画の幅が下のカード列とだけ揃わなくなり見た目が崩れる。全体を広げれば
    どの区画も同じ列幅のまま広がり、しおり・小さな驚き・灯りの暦のグリッド（`auto-fill` /
    `repeat`）はいずれも `fr` 単位・`minmax` で組んであるので、広げても列が増えるかカードが
    広がるだけで崩れない
  - 60rem は既存のトークン消費の画面（`token-usage.module.css` の `.token-usage`。
    `src/browser/components/page/token-usage/`）が使っている値と同じ。値を新しく作らず、同じ
    「1枚で縦に流す画面」どうしで幅を揃える
  - 計算根拠: 立ち絵の列（最大 9.5rem）・区画のパディング（1.5rem×2）・区画どうしの
    gap（1.25rem）・吹き出しのパディング（1.25rem×2）・画面のパディング（0.25rem×2）を除いた
    本文の実効幅は、40rem のとき約 23rem（≈372px）で全角 24〜25字/行 → 250字で約10行。60rem
    なら本文幅は約 43rem（≈690px）で全角 46字前後/行 → 250字で約6行に減る（目視でも確認する）
  - `.achievement` は `max-width` であって固定幅ではないので、狭い窓では変わらずビューポート幅に
    追従する。ほかの CSS（グリッドの列・パディング・書体）は変えない
- `docs/screen-design.md` 13.10「成果の画面」に、広げた幅（40rem → 60rem）とその理由
  （区画だけでなく画面全体を広げたこと・60rem はトークン消費の画面と揃えたこと）を書き足す。
  節の索引を壊さないよう `\n### 13.10 ` から位置を特定し、編集前後で節の見出し数
  （`grep -c '^#\{2,3\} ' docs/screen-design.md`）を確認する

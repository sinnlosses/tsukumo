## 目的

ランタイム・束ね・タイマーを変えるタスクを、既知の E2E の揺れのタスクより先に進めると、揺れが表に出て移行の差分ごと戻すことになる。登録のときに依存を見落とさないようにする。

## 完了条件

- `docs/workflow.md`「タスクを書くとき・受け入れるとき」の箇条に、「ランタイム・束ね・タイマーを変えるタスクは、`task status` の件名に「ときどき落ちる」とある未完了のタスクを `dependencies` に入れて登録する」旨の1項目がある
- いま未完了で、この項目に当たるタスク（少なくとも T-682・T-683・T-684・T-738 を見る）について、揺れのタスク（T-671・T-739・T-755 など、その時点で未完了のもの）を依存に足すか、足さない理由を結果に書く。依存を足すときは front matter の `dependencies` を行で直す
- `bun run check` が通る

## 背景

- T-682（Bun から Node へ移す）は `bun run check` を完了条件にしていたが、揺れの既知のタスク T-672 を依存に入れずに登録された。サーバを node で起こすと、bun ではときどきだった E2E の揺れが3回とも表に出て（落ちる件は2件・1件・0件と変わった）、移行の差分を丸ごと戻して T-672 を先にやり直した（T-682 の振り返り）
- T-672 は済み。今も件名に「ときどき落ちる」とある未完了のタスクは T-671・T-739。T-755（許可のモーダルの揺れ）も同じ類い

## やること

- 前提を確認した結果：T-682・T-684・T-755 は完了済み（develop/task/ に無し）。T-683 は done。T-738（E2E を並列化。ランタイム・タイマーを変える）が未完了で、現在未完了の揺れのタスク T-671（立ち絵テストが全体実行でときどき落ちる）・T-739（E2E がときどき落ちる）を依存に足すべき
- T-738.md の `dependencies` 行を `[T-671, T-739]` に直す
- `docs/workflow.md`「タスクを書くとき・受け入れるとき」の箇条に、「ランタイム・束ね・タイマーを変えるタスクは、`task status` の件名に「ときどき落ちる」とある未完了のタスクを `dependencies` に入れて登録する」旨の1項目を追加

## 注意

- 追記は1項目にとどめる。`plan-tasks` スキル（claude-skills）側は直さない（このリポジトリの上乗せとして `docs/workflow.md` に書く）

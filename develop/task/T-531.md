## 背景

2026-09-24 に `/simplify` の4観点（再利用・単純化・効率・根本対処）でリポジトリ全体を洗った結果の1件（`docs/history/direction.md` の 2026-09-24「改修コストを下げる直し9件」）。

`src/browser/features/screen-nav/domain/model-label.ts` の `MODEL_FALLBACK`（`"opus"`）と `permission-mode-label.ts` の `PERMISSION_MODE_FALLBACK`（`"auto"`）は値を直に書いていて、コメントは「`src/server/core/session-driver.ts` の `DEFAULT_MODEL` / `DEFAULT_PERMISSION_MODE` と同じ」と言う。しかしその定数はもう無く、既定の正典は `src/shared/session-default.ts` の `BUILTIN_SESSION_DEFAULT` になっている（browser から import してよい shared 層）。既定を変えても帯の表示だけが古い値のまま残る。

同じ2ファイルの `modelLabel` / `permissionModeLabel` は export されているが、定義以外から呼ばれていない（帯は `MODEL_LABELS` / `PERMISSION_MODE_LABELS` を直に map している）。

## やること

1. 2つの FALLBACK 定数とそのコメントを消し、`BUILTIN_SESSION_DEFAULT.model` / `.permissionMode` を使う
2. 着手時に `grep -rn "modelLabel\b\|permissionModeLabel\b" src test scripts` で参照が定義だけなのを確かめ直し、2つの関数と、それだけを守るテストがあれば消す

着手時（2026-09-24）に確かめ直した結果: `src/shared/session-default.ts` の `BUILTIN_SESSION_DEFAULT` は現存し、`model: "opus"` / `permissionMode: "auto"` で両 FALLBACK 定数の値と一致する。`grep -rn "DEFAULT_MODEL\b\|DEFAULT_PERMISSION_MODE\b" src` はコメント2件（両 FALLBACK 定数の doc comment）のみで、定数自体はもう無い。`grep -rn "modelLabel\b\|permissionModeLabel\b" src test scripts` は各自の定義行1件ずつだけで、呼び手は無い（テストファイルも `model-label` / `permission-mode-label` を名指すものは無し）。前提は書かれている通りで、作業を進める。

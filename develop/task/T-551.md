## 目的

`README.md`「環境変数」の表を、利用者が設定できる環境変数の実物に合わせる。

## やること

### 前提の調査結果

環境変数の既定値と説明は以下から確認した：

1. `src/cli.ts` — help メッセージでユーザー向けの説明と既定値の表示
2. `src/server/core/config.ts` — 環境変数を読み取り関数の定義
3. `src/server/adapter/` — 実装の詳細（port-resolution.ts, tsukumo-home.ts など）
4. `docs/design.md` 5章「config.ts」— 正典の表（9個の環境変数）

### 表に追加すべき変数

現在の README.md の表には以下の6個がある：

- TSUKUMO_VIEW_PORT
- TSUKUMO_CHARACTER
- TSUKUMO_OPEN_VIEW
- TSUKUMO_DRIVER
- TSUKUMO_NEW_SESSION
- TSUKUMO_WATCH_UI

docs/design.md 5章の正典の表との比較で、以下の2個が欠けている：

1. **TSUKUMO_FAKE_SCENE** — fake driver で起こした直後に流す疑似セッションの場面の名前。既定値は「流さない」
2. **TSUKUMO_HOME** — tsukumo が自分の持ち物を置くホーム。既定値は `~/.tsukumo`

### 表に載せない変数とその理由

`src/` で使用されているが、README.md の表に載せない変数：

- **TSUKUMO_MCP_SERVER_NAME** — これは環境変数ではなく、ソースコード内の定数。`src/server/core/sdk-message.ts` 行25に `export const TSUKUMO_MCP_SERVER_NAME = "tsukumo"` として硬くコードされており、ユーザーが設定するものではない
- **TSUKUMO_VIEW_PORT_FALLBACK_BASE** — テスト用の内部的な口。`test/cli.test.ts` の「全部塞がっている」テストが実際の 7327〜7346 帯を使わずにテストするためだけに用意されたもので、通常のユーザーは使わない。docs/design.md 5章にも「この口が要る場面は1つだけ」と説明されている

## 完了条件

- `README.md` の表に `TSUKUMO_FAKE_SCENE` と `TSUKUMO_HOME` の行があり、既定値と説明が `docs/design.md` 5章・`src/server/adapter/` の読み取り・`--help` の出力と食い違っていない
- 表に載せない変数（`TSUKUMO_MCP_SERVER_NAME`・`TSUKUMO_VIEW_PORT_FALLBACK_BASE` など、内部やテストのためのもの）があれば、載せない理由を完了時の結果に書く
- `bun run check` が通る

## 背景

表はいま6行（`TSUKUMO_VIEW_PORT` / `TSUKUMO_CHARACTER` / `TSUKUMO_OPEN_VIEW` / `TSUKUMO_DRIVER` / `TSUKUMO_NEW_SESSION` / `TSUKUMO_WATCH_UI`）。`src/` が読む `TSUKUMO_` の変数はほかに `TSUKUMO_FAKE_SCENE`・`TSUKUMO_HOME`・`TSUKUMO_MCP_SERVER_NAME`・`TSUKUMO_VIEW_PORT_FALLBACK_BASE` がある。`TSUKUMO_HOME` は並行して目視確認するときに分ける必要がある（`CLAUDE.md`「タスク運用」）ので、利用者が知るべき変数に入る。

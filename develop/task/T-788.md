## 目的

`/plan-tasks` で処理して消したドラフトが、別の作業ツリーの付け替えや merge で `develop/direction.md` に戻り、次の `/plan-tasks` が処理済みかどうかを毎回 `docs/history/direction.md` と照らし直している。消したものが戻らない持ち方にする。

## 完了条件

- ドラフトの持ち方を決め、`## 決まっていること（蒸し返さない）` に書く
- 決めた持ち方で、ドラフトを消す側と末尾に積む側が並行しても、付け替え・merge のあとに消した項目が戻らない（2つの枝で「消す」「積む」を作って付け替える手順で確かめる）
- ドラフトを積む・読む・消すスキル（`retrospect`・`next-task`・`plan-tasks`・`setup-tasks`・`task-workflow` の `layout.py`・`init.py`）と `docs/workflow.md` を新しい持ち方に揃える。claude-skills 側は `./check.sh` が通り main に入っている
- いま `develop/direction.md` に残っているドラフトを新しい持ち方へ移す
- `pnpm run check` が通る
- 1コミットに収まらなければ、決めた持ち方で後段のタスクへ分ける

## 背景

- `.gitattributes` の `develop/direction.md merge=union`（T-757 で入れた。衝突の印が develop/ に残るのを防ぐため）は、衝突した塊の両側を残す。ドラフトは節の末尾に積むので、片側が末尾のドラフトを消し、もう片側が末尾に積むと衝突した塊になり、消した行が戻る
- 2026-09-27 に起きたこと: 12件の処理済みドラフトが T-750・T-685・tsukumo-6 のマージなどで戻っていた。`/plan-tasks`（T-784 の回）が5件を消したコミットは、`task ship` の付け替えで `develop/direction.md` の削除だけが落ち、残りのファイルだけで main に入った
- 積む側は `retrospect` の SKILL.md（節の末尾に足す）と `next-task` の手順6a、消す側は `plan-tasks` の手順6。節の名前は `task-workflow/scripts/layout.py` の `SECTION_DRAFT`
- `test/conflict-marker.test.ts` が develop/ に残った衝突の印を落とす

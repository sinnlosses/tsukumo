## 目的

`/plan-tasks` で処理して消したドラフトが、別の作業ツリーの付け替えや merge で `develop/direction.md` に戻り、次の `/plan-tasks` が処理済みかどうかを毎回 `docs/history/direction.md` と照らし直している。消したものが戻らない持ち方にする。

## 完了条件

- ドラフトの持ち方を決め、`## 決まっていること（蒸し返さない）` に書く
- 決めた持ち方で、ドラフトを消す側と末尾に積む側が並行しても、付け替え・merge のあとに消した項目が戻らない（2つの枝で「消す」「積む」を作って付け替える手順で確かめる）
- ドラフトを積む・読む・消すスキル（`retrospect`・`next-task`・`plan-tasks`・`setup-tasks`・`task-workflow` の `layout.py`・`init.py`）と `docs/workflow.md` を新しい持ち方に揃える。claude-skills 側は `./check.sh` が通り main に入っている
- いま `develop/direction.md` に残っているドラフトを新しい持ち方へ移す
- `pnpm run check` が通る
- 1コミットに収まらなければ、決めた持ち方で後段のタスクへ分ける

## 背景

- `.gitattributes` の `develop/direction.md merge=union`（T-757 で入れた。衝突の印が develop/ に残るのを防ぐため）は、衝突した塊の両側を残す。ドラフトは節の末尾に積むので、片側が末尾のドラフトを消し、もう片側が末尾に積むと衝突した塊になり、消した行が戻る
- 2026-09-27 に起きたこと: 12件の処理済みドラフトが T-750・T-685・tsukumo-6 のマージなどで戻っていた。`/plan-tasks`（T-784 の回）が5件を消したコミットは、`task ship` の付け替えで `develop/direction.md` の削除だけが落ち、残りのファイルだけで main に入った
- 積む側は `retrospect` の SKILL.md（節の末尾に足す）と `next-task` の手順6a、消す側は `plan-tasks` の手順6。節の名前は `task-workflow/scripts/layout.py` の `SECTION_DRAFT`
- `test/conflict-marker.test.ts` が develop/ に残った衝突の印を落とす

## 解くべき論点

- ファイル名（slug）の付け方と、1件のファイルの書式（今の太字の見出し1行・`根拠`・`出し先` を front matter に分けるか）

## やること

着手時（2026-09-27）に調べ直した前提:

- tsukumo の `develop/direction.md` の `## エージェントのドラフト` は空（移すものは無い）。claude-skills の `develop/direction.md` のドラフト12件は、作業中に claude-skills の `main` で T-025〜T-030 として処理済みになった（移すものは無く、節の見出しだけを新しい骨組みに直す）
- `task status` は `develop/direction.md` を形式の目印に使うだけで、中身は数えていない。数えているのは `init.py` の `check_direction` だけ
- `.gitattributes` の `merge=union` は `## ユーザーから` のために残す。`test/conflict-marker.test.ts` は `develop/` を再帰で見るので `develop/draft/` もそのまま対象に入る

論点の決定:

- 置き場とファイル名: `develop/draft/<YYYY-MM-DD>-<英小文字とハイフンの要約>.md`。日付と要約で並行する作業ツリーのドラフトが同名にならず、ASCII に限るので macOS のファイル名の正規化とシェルの引用に左右されない
- 書式: front matter にしない（機械が読むのはファイルの数だけ）。1行目 `# <何を変えるか>（<出どころ>）`、続けて `- 根拠:`・`- 出し先:` の箇条書き。今の1件の形から太字を見出しに替えただけで、`docs/history/direction.md` へ移すときに形を変えずに済む
- `develop/direction.md` の `## エージェントのドラフト` の節は消し、1行目の見出しの括弧に置き場を書く（本文の行を足すと PENDING の数に入る）
- `init.py` の PENDING は「ユーザーから N行、エージェントのドラフト M件」（M は `develop/draft/*.md` の数）。旧い節に行が残っていれば「旧ドラフト節 K行（develop/draft/ へ移す）」を添えて PENDING にする（移し忘れを黙って見落とさない）。`task status` は変えない

手順:

1. claude-skills（`feature/tsukumo-T-788` の作業ツリー）: `layout.py` に `DRAFT_DIR` を足し、`init.py` の骨組みと `check_direction` を直して `selftest.py` を合わせる。`check_repo.py` の直書き検査に新しい値を足す
2. `task-workflow/WORKFLOW.md`（置き場の表・1サイクル・指示メモ）、`retrospect`・`next-task`・`plan-tasks`・`setup-tasks` の SKILL.md を新しい持ち方に揃える
3. claude-skills の `develop/direction.md` を新しい骨組みに直し、旧い置き場を指している未着手タスクの本文（T-028）を直す。`./check.sh` を通して main へ入れる
4. tsukumo: `develop/direction.md` の見出しと節を新しい骨組みに合わせ、`README.md` の構成図の `develop/` の行に `draft/` を足す（`docs/workflow.md`・`.gitattributes`・`test/conflict-marker.test.ts` はドラフトの置き場に触れていないので直さない）。`pnpm run format` → `pnpm run check`
5. 一時ディレクトリの使い捨てリポジトリで、2つの枝で「ドラフトを消す」「ドラフトを積む」を作り、rebase と merge のどちらで付け替えても消したドラフトが戻らないことを確かめる

## 目的

画面の部品を置き換えるタスクで、目視で確かめたい状態を疑似セッションで出せるようにする。

## 完了条件

- `test/fixture/fake-session.json` と `scripts/capture-catalog.ts` の件で、次の状態を出して撮れる: 帯の「いまの作業」の実行中・失敗・背景のタスク、表情やキャラクターを消す確認のモーダル、日記帳の見開き
- すでに出せる状態があれば、足さずに、どの場面・件で出せるかを `docs/architecture.md`「手で確かめること」から辿れるようにする
- 撮った画像を見て確かめ、何が見えたかをタスクの結果に書く
- `bun run check` が通る
- 調べて前提が成り立たなければ、理由を書いて `dropped` で閉じてよい

## 背景

- 部品の置き換え（T-607・T-608・T-610）の目視で、この3つの状態と確認のモーダルを疑似セッションで出せず、毎回「組み立てた CSS の計算値を元の宣言と突き合わせる」で代えた。T-610 はツールのエラー5件、`screen-nav-current-work.tsx` の編集7回だった
- `fake-session.json` にはすでに `background-task` の場面がある（帯に出るかは確かめていない）

## やること

前提を洗い直した結果、5つの状態のうち「背景のタスク」だけは既存の場面（`background-task`）で
出せるが、残り4つは `capture-catalog.ts` に対応する件が無く、うち2つは疑似セッションの場面も
足りない。具体的には:

- **実行中**: `screen-nav-current-work.tsx` の `state` は `src/shared/turn-step.ts` の
  `currentTurnSteps` が「最後の `request` より後の `tool` の記録」を拾う作りで、**`request` を
  持たない場面（`report` など）を `TSUKUMO_FAKE_SCENE` で直接起こしても「依頼が一度も無い」に
  畳まれ、`tool-started` があっても帯の一覧に出ない**。既存の場面はどれも「直接起こして20秒以上
  ターンが進行中のまま」という条件を満たさないので、**自分の `request` を持つ新しい場面
  `current-work-running` を足す**（20秒走る Bash 1つ）
- **失敗**: 同じ理由で、`isError: true` を持つ既存の場面（`report`）もそのままでは使えない
  （`request` が無い）。**新しい場面 `current-work-failed` を足す**（`request` → 失敗する Bash →
  `turn-finished`）
- **背景のタスク**: `background-task` 場面は自分の `request` を持つので、そのまま
  `TSUKUMO_FAKE_SCENE=background-task` で「背景で作業中」になる。**場面は足さず**、
  `capture-catalog.ts` に件を足すだけでよい
- **表情・キャラクターを消す確認のモーダル**: `PortraitClearConfirm` /
  `CharacterDeleteConfirm` は、画面から変えられるパック（`character.editable`）でしか出ない
  （`characters/local` と同名でなければ true）。同梱のパックは変えられるが、**「消す」ボタンが
  `shown` になるのは `isRemovableExpression(expression) && url !== undefined`**（`default` 以外の
  立ち絵があること）で、`CharacterDeleteConfirm` は `removal !== "none"`（ホームにしか無いパック）
  が要る。`capture-catalog.ts` は「起こす側が覚えている立ち絵を上書きしない」ためキャラクターを
  指定しない作りなので、**件専用の隔離ホーム（`TSUKUMO_HOME` を `--out` の下の `home/` に差し替え）
  に、同梱の `chou` を別名（`chou-sample`）でコピーしたパックを置いてから起こす**。疑似セッションの
  場面は変えなくてよい（キャラクター画面への `hash` 遷移だけで出る）
- **日記帳の見開き**: `diary-written` 場面と「日記帳で開く」自体は既にあるが、日記の中身
  （本文・しおり）は `~/.tsukumo/diary/<リポジトリ>/2026-09-20.json` に無いと「白紙」のまま。
  **件専用の隔離ホームへ、`appendDiaryParagraph`（`src/server/diary/adapter/diary.ts`）で架空の
  日記を1件書いてから起こす**。書いたパックは同梱の `tsukumo`（`characterPacks` に常にあるので
  立ち絵が引ける）

`capture-catalog.ts` の `CatalogEntry` に `homeSetup`（`default` / `diary` / `character` の3種）を
足し、6件（`current-work-running` / `current-work-failed` / `current-work-background` /
`diary-book` / `portrait-clear-confirm` / `character-delete-confirm`）を追加する。
`docs/architecture.md`「手で確かめること」に、どの件で何が出せるかを追記する。

## 結果

- 検証コマンド: 2720 pass / 0 fail（+1）
- 疑似セッションに `current-work-running` / `current-work-failed` を足し、`capture-catalog.ts` に帯の3状態・日記帳の見開き・消す確認2つの6件を足した（件ごとの隔離ホーム `homeSetup`）。サブエージェントが6件を広い窓・狭い窓で撮って見た。既定のホームに痕跡が無いことはメインも確かめた
- 振り返り: 同じファイルを3回以上直した（6件と隔離ホームの仕組みを足した分。ドラフト 0件）

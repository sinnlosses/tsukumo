## 目的

`docs/research/server-procedure-proposal.md` の段3。画面からのコマンドを機能ごとの契約と手続きにし、どのコマンドも「ルータ → 契約 → 手続き → 機能の `core`」の同じ4段で辿れるようにする。

## 完了条件

- T-652 の機能ごとの受け手の表が、`docs/design.md` 2章「コマンドの受け手と手続きの置き方」の形に写っている: 契約は `src/shared/contract/<機能>.ts`（`session` `character-pack` `chat` `visit` `usage-review` `host` の6機能）、手続きは `<機能>/adapter/<機能>-procedure.ts`、束ねは `src/router.ts`（`src/command-route.ts` はここへ吸われて消える）
- 断る条件は契約の `meta`（`{ chatOnly, idleTurn }`。値は段1の列と同じ `false` か `FRAME_ERROR_REASON` の定型文）へ移り、段1の行からは列が消えている（二重に持たない）。`meta` を見るのは `rpc-guard.ts` の1箇所で、順は「雑談の外か」→「ターン中か」のまま
- 手続きの中身は段1の受け手（`<機能>/core/<機能>-command.ts` の行）へ委ねる数行で、`session` の手続きは `CommandSession` を oRPC の context で受ける。機能どうしの辺の表は増えていない
- `/ws` のメッセージを oRPC の `RPCHandler` が受け、`src/shared/command.ts` の `ClientCommand` の和と `parseClientCommand`、`session-socket.ts` の `receive` が消えている
- 受け取る1メッセージの上限（`MAX_MESSAGE_BYTES`、16 MiB）と、起動トークン・`Origin` の照合が保たれている
- ブラウザの `src/browser/stores/session.tsx` の `dispatch` が型付きの client で呼んでいる
- 押し出し（`hello` と `events` のフレーム、`subscribe`）は変えていない
- `bun run check` が通り、fake driver で依頼・答え・キャラの切り替え・雑談の切り替え・画像2枚つきの依頼が目視で通った

## 背景

- コマンドは `src/shared/command.ts`（約590行、28種）で定義され、`src/server/view-server/adapter/session-socket.ts` の `receive` が `parseClientCommand` で検証して `session-manager` の `dispatch` へ渡す
- 読み取り5本は T-653 で先に手続きになっている

## やること

着手時（2026-09-26）にいまのコードで確かめた前提:

- 段1の表（`<機能>/core/<機能>-command.ts` の6つ、束ねる `src/command-route.ts`、断る条件を見る
  `session/core/command-dispatch.ts`）と、段2の `src/router.ts`・`src/shared/rpc.ts`・`rpc-guard.ts`
  はある。`ClientCommand`（28種）はまだ `src/shared/command.ts` にあり、`session-socket.ts` の
  `receive` が検証して `SessionManager.dispatch` へ渡している
- `@orpc/server/websocket`（と `/ws`）の型宣言は `@orpc/interop` を辿らない。`/ws` には押し出しの
  フレームと手続きの応答が同じ接続で流れるので、**ブラウザは届いたものをフレームか手続きの応答かで
  振り分けてから** `@orpc/client/websocket` の `RPCLink` に渡す（フレームを渡すと読めずに落ちる）
- **いまの `error` フレームは画面が読んでいない**（畳み込みが捨てる）。断る理由の定型文が画面に
  出るのは、ブラウザが状態から操作子を塞ぐときの `title` だけ。手続きにすると断る理由は応答の
  エラー（契約の `REFUSED`）で返るので、`error` フレームは送り手が無くなる

作業:

1. 契約: `src/shared/contract/{session,character-pack,chat,visit,usage-review,host}.ts` に28種の
   入力と `meta`（`{ chatOnly, idleTurn }`）を写す。共通の `meta` の型・既定と、断るときのエラー
   （`REFUSED`、理由は `FRAME_ERROR_REASON` の定型文）は `src/shared/command.ts` に置き、
   `ClientCommand` の和・`clientCommandSchema`・`parseClientCommand`・`DriverCommand` を消す。
   コマンドの契約を束ねたものは `src/shared/rpc.ts` に並べる（読み取りは HTTP、コマンドは `/ws` と
   載せる先が違うので束は2つ）
2. 段1の行: 各 `<機能>-command.ts` の表を手続きの名前で引く形にし、断る条件の列を消す。行の型と、
   葉の機能の行（`write` / `call`）を呼ぶ関数は共有の `core/command-receiver.ts` へ（`session` の型を
   読まずに済む context の形にする）。`command-dispatch.ts` は受け手の口（`CommandSession`）だけに
   なるので名前を概念に合わせる
3. 手続き: `<機能>/adapter/<機能>-procedure.ts` を6つ。`session` は `CommandSession` を context で
   受ける。失敗を契約のエラーへ訳すのはここ
4. 束ね: `src/router.ts` にコマンドのルータを足し、`src/command-route.ts` を消す。`rpc-guard.ts` に
   `meta` を見る門（「雑談の外か」→「ターン中か」）を足す
5. `/ws`: `session-socket.ts` の `receive` を `@orpc/server/websocket` の `RPCHandler` に置き換える
   （`MAX_MESSAGE_BYTES` の `WebSocketServer`・upgrade の照合はそのまま。読めないメッセージの
   中身をログに出さない）。`SessionManager` の `dispatch` と `commands` を外し、`CommandSession` を
   出す
6. ブラウザ: `lib/socket.ts` で振り分け、`stores/session.tsx` の `dispatch` を型付きの client にし、
   呼び出し側を `dispatch.<機能>.<手続き>(入力)` へ書き換える
7. テスト・`test/architecture.test.ts`・正典（`docs/design.md` など）を追随させ、`bun run check`、
   fake driver で目視

## 注意

- 着手時に T-653 の結果（oRPC の WebSocket での振る舞い、`rpc-guard.ts` の形）で本文を読み直す
- 葉の機能の手続き（`write` / `call` の行を呼ぶもの）が `session` の型を import しないで済む context の形にする（`session` への辺を足すと core・adapter どちらかで輪になりうる）

## 結果

- 検証コマンド: 2696 pass / 0 fail（増減なし）。目視は fake driver＋headless Chrome で依頼・答え・キャラと雑談の切り替え・画像2枚つき（11.56MB）・雑談の外の nudge の REFUSED を確認。繋ぎ直し後の送信・Orca の実タブ・16 MiB 超の切断は未確認（繋ぎ直しは送るたびにその時点の接続の link を引くことをコードで確かめた）
- 束は `/rpc`（読み取り・本文 64 KiB）と `/ws`（コマンド）の2つにし、正典 2章をその形に書き直した。`error` フレームを廃し `PROTOCOL_VERSION` を 21 に上げた
- 振り返り: 検証コマンドの打ち直し（ドラフト 0件。28種と docs を一度に写す規模に見合った回数で、次の振る舞いは変わらない）

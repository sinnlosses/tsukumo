## 目的

`components/page/` の規約（ページの直下は `domain/` `hooks/` `components/` と container / presenter の
対（と `<ページ>.module.css`）だけ、部品は1部品1ディレクトリ）を、読んで守る約束から検査で落ちる
仕組みにする。

## やること

前提を調べ直した。`test/architecture.test.ts` には `components/page/` の形そのものを検査する項目は
まだ無かった（`browser/ の機能どうしの import` や `components/ui/ の置き方` など隣接する検査は
あるが、ページ・部品の直下の名前や、部品の外から中身を import しない縛りは検査で落ちていなかった）。
前提は崩れておらず、作業が要る。

- `test/architecture.test.ts` に `describe("components/page/ の形", …)` を足す
  - ページ直下（`components/page/<ページ>/`）と部品のディレクトリ（`components/<部品>/`）を同じ
    再帰関数で検査する。許す名前はディレクトリ名から作る
    （`<dir>.tsx` / `presentational-<dir>.tsx` / `<dir>.module.css` / `domain` / `hooks` /
    `components`）。部品はさらに概念のディレクトリ（いまは `markdown` のみ）を名前の一覧で許す
  - `components/` の直下はディレクトリだけ（`hooks/` は部品の形を求めない固定の置き場、それ以外は
    部品として上の再帰へ回す）
  - 部品の `components/`（＝子部品）はさらに `components/` を持てない（ネストは1段だけ）
  - 部品のディレクトリの外から、中の `<部品>.tsx` 以外を import していないか（`main.tsx` は除く。
    テストは `src/` の外にあるので対象外）を、相対 import の辺を集めて検査する
  - 実装は `BROWSER_SCREENS`（既存）を起点に、いまの4画面すべてを対象にする
- `docs/design.md` 2章「ページの形」の段落から、足した検査の `describe` 名を引く
- いまのコード（4画面ぶんの `components/page/`）に規約違反は無かった（検査を足した時点で
  既存コードは無傷で通った）ので、規約に合わせる直しは発生しなかった

検査が実際に落ちることは、一時ファイル・一時的な1行 import で3種類の違反
（ページ直下の余分なファイル、`components/` 直下のディレクトリでないもの、子部品の `components/`、
部品の外からの import）を作って確かめ、確認後にすべて手で戻した。

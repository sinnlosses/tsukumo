## 目的

T-666 でサイドバーの単体テストを監査したとき、`test/browser/components/domain/sidebar/task-section.test.tsx` の
操作のテスト5件は「E2E が通らない」ので残した。E2E `task-list` にクリックの手順を足し、押したあとの
DOM を写しで固定すれば、この5件を上位で守れるようになり単体テストを消せる。

## 完了条件

- E2E `test/e2e/task-list.test.ts` がタスクの区画のチップと「一覧を見る」を押し、押したあとの状態を
  DOM の写し（`test/e2e/expected/` の期待値）で固定している
- `task-section.test.tsx` の次の5件のうち、足した E2E が守るものを消している（本番コードに1行の変異を
  入れて E2E が落ちることを確かめてから消す）:「一覧を見る」で表が開く／チップを押すと絞る／
  もう一度押すと全件に戻る／別のチップへ切り替わる／`aria-pressed` が選んだチップにだけ付く
- 消したテストごとに、どの E2E が守るかをタスクの結果に書いている
- 調べて E2E で守れないと分かったもの（写しに現れない、など）は残し、理由を書く。1件も消せないなら
  `dropped` で閉じてよい
- `bun run check` が通る

## 背景

- E2E の足場 `test/e2e/scenario-run.ts` は `room.page`（Playwright の `Page`）を渡すので、クリックできる
  （`test/e2e/permission-answer.test.ts` が「許可」を押している）
- DOM の写し（`DOM_TREE_SCRIPT`）には `role`・`data-*`・`aria-*`・`disabled`・`value`・`open` が残る。
  class は残らない。`aria-pressed` は残るので、チップの選択状態は写しで見える
- `task-list` は一時の cwd に `git init` して `develop/task/*.md` を2件（未着手・完了）書き、`main` へ
  コミットして `tasks-changed` を待ってから撮る。絞り込みを見るには、状態の違うタスクが2件以上要る
  （すでに2件ある）
- 判定の規則は `docs/coding-standards.md`「消すかどうか」の表と「E2E の台本が通している、とは」

## やること

前提の再確認（2026-09-27時点）: `task-section.test.tsx` に該当5件が現存し、
`test/e2e/task-list.test.ts` は一覧の表示だけを撮る1本の `it` で、クリックはまだ足していない。
`TaskSection` は開閉の state と絞り込みの state を持ち、`TaskCountChipList` が `aria-pressed`
を出す（`task-count-chip-list.tsx`）。前提は崩れていないので作業する。

- `test/e2e/task-list.test.ts` に、git 初期化とタスク2件のコミット・`tasks-changed` 待ちを
  まとめた `openTaskListRoom` を足し、既存の `it` をそれに寄せる
- 新しい `it` を4本足す（`room.page` でクリックし、`settleAndMatch` は1回ずつ）:
  - `task-list-board-open`: 「一覧を見る」を押して表が開いた状態を撮る
  - `task-list-filtered`: 「未着手 1」を押して絞った状態を撮る（`aria-pressed` が
    このチップにだけ付くこともここで固定する）
  - `task-list-filtered-off`: 同じチップをもう一度押して全件に戻った状態を撮る
  - `task-list-filtered-switched`: 「未着手 1」→「完了 1」の順に押して切り替わった状態を撮る
- `pnpm run test:e2e:update` で期待値を書き、`git diff` で意図した差分だけかを確かめる
- 本番コードへ退避コピーを取ってから1行の変異を入れ、対応する E2E が落ちることを確かめてから
  戻し、`task-section.test.tsx` の該当5件を消す
- `pnpm run format` → `pnpm run check`

## 注意

- 1本のシナリオで撮れる写しは `settleAndMatch` 1回につき1つで、期待値のファイル名はシナリオ名で
  決まる。押す前と押したあとを両方撮るなら、`it` を分けるかシナリオ名を分ける
  （`background-task` が `-running` / `-resumed` の2つに分けている例がある）
- 変異を入れて確かめるときは、退避したコピーから戻す（`git checkout --` で戻さない）
- 期待値は `bun run test:e2e:update` で書き直し、差分を読んで意図した変化だけかを確かめる

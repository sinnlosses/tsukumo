## 目的

入力欄を、素の `<textarea>` と「書きながら装飾が見える」マークダウンエディタの間で切り替えられるようにする。
その前段として、エディタの部品・状態の持ち方・補完と画像のつなぎ方・切り替えの口を決め、
`docs/research/` に提案書として書く。

## 完了条件

- `docs/research/` に提案書がある。少なくとも「## 解くべき論点」の各項に結論と理由がある
- 採る案が要件・表示物の正典に効くなら、`docs/requirements.md` 4.2 と `docs/display.md` 4.2「入力欄」に
  切り替えの仕様を足す（見出しを足すなら `grep -c '^#\{2,3\} '` の前後と `bun run scripts/find-stray-reference.ts` を見る）
- 後段のタスク（T-701）の `## 背景` と
  `## 注意` を設計の結論に合わせて直す。実装の広がり（足す依存・`use-composer.ts` / `use-suggestion.ts`
  の作り替えの量・E2E の数）を見て後段の `difficulty` も見直す
- `bun run check` が通る

## 背景

- 入力欄は `src/browser/components/page/conversation/components/dispatch/components/composer/` にある。
  `presentational-composer.tsx` が `<textarea>` の器、`hooks/use-composer.ts` が下書き
  （`draft: { text, caret }`）とキー操作、`hooks/use-suggestion.ts` が `/` と `@` の補完、
  `hooks/use-prompt-image.ts` が画像の貼り付け・ドロップ
- `use-composer.ts` は `textAreaRef: RefObject<HTMLTextAreaElement>` と `selectionStart` を直接読み、
  キー操作の型も `KeyboardEvent<HTMLTextAreaElement>`。補完の差し込みもこの前提で書かれている
- キー操作はすでに「Enter は改行、Command+Enter で送信、IME 変換確定の Command+Enter は送らない」
  （`use-composer.ts` 冒頭）。補完中の Tab / Enter は確定だけ
- Markdown の描画は `react-markdown` + `remark-gfm` + `rehype-highlight` をレポートで使っている。
  編集中の装飾（ライブプレビュー）の部品は依存に無い
- `docs/requirements.md` 2.2 の対象外には当たらない（端末を持つこと・ファイルの貼り付けとは別物）

## 決まっていること（蒸し返さない）

2026-09-26 にユーザーが決めた:

- エディタの形は**書きながら装飾が見える**もの（記号は残り、見出し・太字などがその場で装飾される。
  Obsidian のライブプレビュー風）。編集とプレビューの2枚並べ・WYSIWYG ではない
- **素の `<textarea>` にいつでも戻せる**。**書いた内容は両方のモードに反映される**（切り替えても
  下書きは1つで、失われない）
- `/` と `@` の補完、画像の添付は**エディタのモードでもそのまま使える**
- Enter は改行、送信は別のキー（いまの Command+Enter）。エディタのモードでも同じ

## 解くべき論点

- エディタの部品（CodeMirror 6 の Markdown 拡張・Milkdown・自作の装飾層など）。束の大きさ、IME
  （日本語入力）との相性、`happy-dom` での単体テストと E2E の張りやすさで比べる
- 下書きの持ち主。`draft: { text, caret }` を2つのモードで共有する形と、`use-composer.ts` の
  `HTMLTextAreaElement` 依存をどこで切るか（`docs/coding-standards.md`「React」の `useEffect` の4類型に収める）
- 補完の候補窓の位置とキー操作をエディタでどうつなぐか（エディタ側のキー処理と `use-suggestion.ts` の読み替えの衝突）
- 画像の貼り付け・ドロップをエディタの中でどう受けるか
- 切り替えの口（道具の行のボタン・キー）と、選んだモードを覚えるか（覚えるならどこに）
- 質問の間の自由入力（`docs/display.md` 4.2）など、入力欄の他の状態とどう併存するか

## 注意

- 依存を足すのは npm のライブラリで、外部コマンドではない。ただしブラウザの束が大きく増えるなら
  提案書に数を書く
- 調べて「書きながら装飾が見える」形が IME と両立しないと分かったら、実装に進まず提案書に理由を
  書き、ユーザーの判断を仰ぐ（そのときは後段を `hold` に回すよう `favor` で頼む）

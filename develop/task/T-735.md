## 目的

完了したタスクの履歴を、`docs/history/tasks.md` の1ファイルでなく `docs/history/task/` の下にタスクIDごとのファイルで置くかを検討する（2026-09-27 ユーザーの指示）。

## 完了条件

- 推奨（置く・置かない）と理由を `docs/research/` に書く。置くなら段取り（`tasks.md` の分け方・`task prune` を「消す」から「移す」に変えるか・スキルの何を変えるか）も書く
- 推奨が実装を要するなら、実装のタスクの案を `develop/direction.md` のエージェントのドラフトに書く
- `bun run check` が通る

## 背景

- 登録時の実際: `docs/history/tasks.md`（約 31700 行・521 件）は旧形式の時代の履歴で、**読むだけで書き足さない**（`WORKFLOW.md` の置き場の表）。新しい形式では、完了したタスクファイルは `develop/task/` に残り、振り返りが済んだものが10件溜まると `task prune` でまとめて消す（本文は git の履歴から読む）。つまり新しいタスクの履歴は今 `tasks.md` には入っていない
- `docs/history/` の読み方は CLAUDE.md の索引（通読せず `grep` で節を当てる）

## 注意

- 前段（T-733）が GitHub Projects へ移すと決めたら、履歴の置き場もそちらの結論に従う。前段がこの本文を直す

## 結果

- 着手しないで閉じた（2026-09-27 ユーザーの判断「OK、閉じよう」）
- 理由: 新しい形式では完了したタスクは `docs/history/tasks.md` に入らず、振り返り済みのものを `task prune` で消して本文は git の履歴から読む。消しても困る参照は無い（`docs/` は `history/` を除きタスク番号を書かない）。残る論点は旧形式の `tasks.md` を ID ごとに分けるかだけで、分けても grep で当てる読み方は変わらない

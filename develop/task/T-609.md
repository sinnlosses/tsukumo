## 目的

`<h1>`〜`<h4>` に付いた見出しの規則（`margin: 0` + `font-size: var(--font-*)` + `font-weight`）が画面ごとに手書きされ、太さが `normal` / `600` / `700` / `bold` とばらついている。見出しの部品を1つ作り、段と色を variant で表して揃える。

## 完了条件

- `docs/design.md` 2章「`components/ui/` の部品（variant の作法と一覧）」の一覧どおりの `Heading`（`level`・`size`・`tone`・`weight`・`className`。props はすべて必須）が `src/browser/components/ui/heading/heading.tsx`（と既定の `margin: 0` を `:where()` に書く `heading.module.css`）にあり、**size・tone・weight の対応表は前段の `ui/text/` のものを読んでいる**（表を二重に持たない）。`test/browser/components/ui/heading/heading.test.tsx` に、`level` → `<h1>`〜`<h4>`、軸ごとのすべての値 → 付く class、`className` が足されることのテストがある
- `src/browser/` の `<h1>`〜`<h4>` のうち、見た目が語彙（`--font-*` の段・`--ink` / `--ink-quiet` などの色・400 / 600 / 700 の太さ）だけで書けるものが `Heading` に置き換わり、対応する規則が消えている（`margin` や字間 `letter-spacing` は `className` に残す）。計画時の実測で対象になるのは、タスク一覧（`.task-board-heading`）・成果の画面（`.achievement-title` ×2・`.achievement-card-label`・`.achievement-surprise-heading`・`.achievement-calendar-title`・`.diary-book-toc-heading`）・キャラクターの画面（`.character-section-heading` ×6・`.character-create-heading` ×2・`.character-profile-name`・`.character-delete-question`）・サイドバーの区画の見出し（`.sidebar-block h2`）・質問の記録（`.question-record h4`）
- **置き換えないもの**: トークン消費の画面の見出し（`--usage-ink` / `--usage-ink-label` を使う9箇所。語彙と同じ property で画面固有の値を持つ）、見た目を中の要素が持つ `.turn-title`、Markdown が生む見出し（`markdown.tsx`）。ほかに残したものがあれば理由を結果に1行ずつ書く
- `test/architecture.test.ts`「components/ui/ の部品の className」が `Heading` を対象にして通る（検査がまだ無ければこのタスクで足す。足し方は T-607 の完了条件と同じ）
- `docs/design.md` 6.1「部品の置き場」の段落に `<Heading>` を足してある
- 置き換えた画面（タスクの一覧・成果の画面と日記帳の目次・キャラクターの画面と作成・名前の編集・削除の確認・サイドバー・メインビューの質問の記録）を起動して目視し、見出しの大きさ・太さ・色・間隔が置き換え前と同じであることを確かめている（何を見たかを結果に書く。モーダルの中も見る）
- `bun run check` が通る

## 背景

- 計画時の実測（2026-09-25）で `<h1>`〜`<h4>` は 20ファイル29箇所（`markdown.tsx` を除く）。太さは `normal` / `600` / `700`（= `bold`）の3通りで、語彙の `normal` / `semibold` / `bold` にそのまま写る
- 字の大きさのトークンは `src/browser/styles/theme.css` の `--font-label` / `--font-action` / `--font-secondary` / `--font-subheading` / `--font-body` / `--font-heading`
- `.step-heading`・`.turn-history-heading`・`.screen-nav-work-*-heading`・`.screen-nav-settings-heading` は `<h*>` でない要素に付いているので、このタスクではなく文字の部品（T-610 / T-611）の対象
- 作法は `docs/design.md` 2章「`components/ui/` の部品（variant の作法と一覧）」が正典

## 決まっていること（蒸し返さない）

- level と size は別の props（level から size を決めない）
- **見た目を変えない。** 太さの 600 と 700 は分けたまま（`semibold` / `bold`）。揃えるかは別の判断として持ち越し
- `Heading` は `Text` の語彙（size・tone・weight）と対応表を共有する。違いは要素と `margin: 0` の既定だけ
- 汎用の `as` は持たない

## やること（着手時に前提を取り直して追記）

- `src/browser/components/ui/heading/heading.tsx` に `Heading` を作る。`ui/text/text.tsx` の
  `TEXT_SIZE_CLASS` / `TEXT_TONE_CLASS` / `TEXT_WEIGHT_CLASS` をそのまま import して使い、
  対応表は二重に持たない。`level: 1 | 2 | 3 | 4` → `<h1>`〜`<h4>`、`size`/`weight` は `Text` の型から
  `"inherit"` を除いた合併型、`tone` は `Text` と同じ（`inherit` あり）。`className: string` は
  必須（空文字を渡せる）。`heading.module.css` は `:where(.heading) { margin: 0; }` だけを持つ
  （字の段・色・太さの CSS は `text.module.css` 側にすでにあるので heading 側には作らない）

  `level` → `<h1>`〜`<h4>`、`size`/`tone`/`weight` の軸ごとにすべての値が対応する class を持つこと、
  `tone: "inherit"` は class を付けないこと、`className` が足されること

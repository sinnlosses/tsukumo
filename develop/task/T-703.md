## 目的

`report` を「ターンを閉じるツール」にする案（`docs/research/report-block.md` 13章）が、tsukumo の構成で本当に動くかを小さく試して確かめる。検証に通った `report` の結果に `_meta["claude/endTurn"]` を付けてターンを閉じられれば、`report` のあとに本文を書き足して Stop hook に差し戻される問題が無くなり、締めのセリフを `report` の引数に移せる（2026-09-26 ユーザーが案を承認）。

## 完了条件

- 次の3点を実物で確かめ、結果を `docs/research/report-block.md` 13章に書き足す（確かめた版と、何が見えたか）:
  - プロセス内 MCP サーバ（`createSdkMcpServer` の `tool()`）の返り値に `_meta: { "claude/endTurn": true }` を載せると、CLI がそこでターンを閉じるか（`result` のメッセージが来て、そのあと assistant の発言が来ないか）
  - `is_error` の結果ではターンが閉じず、モデルが打ち直せるか
  - 閉じたターンの transcript を、`src/server/session-driver/core/sdk-message.ts` のセッションの復元と `resumeSessionAt` がそのまま読めるか
- 試すためのコードは使い捨てのスクリプトにし、本体（`src/`）には入れない。スクリプトはリポジトリに残さない（残すなら `scripts/` に置く理由を書く）
- 動くと分かったら、本体へ入れる実装タスクの案（`closing` の欄・中間レポートの扱い・Stop hook の要否の見直し）を `develop/direction.md` の `## エージェントのドラフト` に書く。動かないと分かったら、その理由を13章に書いて閉じる
- `bun run check` が通る

## 背景

- CLI 2.1.280 の本体では、ツールの結果の `_meta["claude/endTurn"] === true` でターンを閉じ、`is_error` のときは閉じない。SDK の `sdk.d.ts` にも「End-turn tool sessions」として載っている
- `report` の定義は `src/server/session-driver/adapter/sdk-tool.ts` と `src/server/report/core/report-tool.ts`、Stop hook は `src/server/session-driver/adapter/sdk-driver.ts`

## 目的

子プロセスを起こす境界（`orca-host.ts` `git.ts`）を含む2機能を、`src/server/<機能>/{core,adapter}/` へ移す。

## 完了条件

- `docs/design.md` 2章「いまの `src/server/` から移す先（移行の対応表）」で段が「3」の6行が移っている。テストも同じ置き換えで移っている
- 同じ節の検査の表のうち、`orca` の文字列リテラルの行と、`node:child_process` の許可リストの行の `orca-host.ts` `git.ts` の部分が直っている
- `SERVER_FEATURES` と `SERVER_FEATURE_IMPORTS` に `host` と `repository` が足されている
- 移したパスを指す記述が直っている（`scripts/open-views.ts` `scripts/open-room-grid.ts` `scripts/room-grid.ts` の `orca-host.ts` の import を含む）
- `bun run check` が通る
- 着手時に対応表の前提が崩れていたら、表を直してから移す。移す意味が無くなっていたら `dropped` で閉じてよい

## 背景

- `tracked-file.ts` は `host/`、`git.ts` は `repository/` に置く。理由は `docs/history/decision.md`「design.md 2. 全体構成 / ディレクトリ（`src/server/` を機能で割った）」

## やること

着手時に前提を調べ直した（2026-09-25）。対応表の段3の6行はそのまま成り立っている:

- **6ファイルは実在し、対応表のパスと一致**: `src/server/adapter/orca-host.ts`
  `src/server/core/host.ts` `src/server/core/tracked-file.ts` `src/server/adapter/git.ts`
  `src/server/adapter/repository-file.ts` `src/server/adapter/task-summary.ts`

  `test/server/adapter/repository-file.test.ts` `test/server/adapter/task-summary.test.ts` の3本
  だけがあり（表の「あり」3件）、`orca-host.ts` `host.ts` `git.ts` にはテストが無い（表の「—」3件）
- **6ファイル間の import は全部いま移す2機能の中に閉じている**（`orca-host.ts` → `./host.ts`・
  `tracked-file.ts` → `./host.ts`・`repository-file.ts` → `./git.ts`・`task-summary.ts` →
  `./git.ts` と `../../shared/task-summary.ts`）。**他機能への辺は無い**ので、2章の表の
  `host` `repository` が「そのほか — 葉」（他機能を読まない）なのと合う。表に足す行は無い

  読んでいる。これは移行の途中規則（「共有の箱は機能を読まない」検査は段8まで止める）の対象で、
  段3では問題にならない

  （`test/architecture.test.ts:165`）、**`node:child_process` の許可リスト**も

  ままだった（`test/architecture.test.ts:203-205`）。どちらも今回 `orca-host.ts` `git.ts` の部分を
  新パスに直す（`bundle.ts` は触らない）

前提は崩れていない。対応表・完了条件どおりに段3（`host/` `repository/`）を移す。

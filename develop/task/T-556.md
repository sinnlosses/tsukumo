## 目的

`task done`・`task new` と、登録・振り返りのコミットで書いたファイルを、コミットの前に整形コマンドへ通す。付け替え後の検証が整形だけで落ちて、手で `bun run format` → amend → 送り直しになるのをなくす。

## 完了条件

- 次のどちらかが入っている（どちらにするかは着手時に決め、理由を完了時の結果に1行）: (a) `task.py` の `done` と `new` が、書き込んだファイルに「タスク運用」節の整形コマンドをかける（`なし` なら何もしない）/ (b) `next-task` 手順7・`plan-tasks` 手順7・`retrospect` 手順5 に、コミットの直前に整形コマンドを打つ手順がある
- claude-skills の `./check.sh` が通り、変更が claude-skills の `main` に入っている
- tsukumo の `bun run check` が通る

## 背景

2026-09-24 の振り返り（`develop/retrospective.md` の `f1adaf96`..`7ef5a7ba`）で見つけたもの。T-527 の `task ship` が付け替え後の `format:check` で落ちた。原因は2つで、`task done --result-file` が書き込んだ結果の表（`oxfmt` が列を揃え直す）と、先に `main` へ入っていた登録のコミット（`115a3843`）が `develop/direction.md` に残した空行2行。どちらも `next-task`・`plan-tasks` の手順に整形が無いために起きる。

## やること

着手時にコードを読み直した。claude-skills の `skills/task-workflow/scripts/task.py` は
`ship.read_verify_command`（`CLAUDE.md` の `- 検証コマンド:` 行を読む）と同じ形の
`read_branch_setting`（`- ブランチ:` 行）は既に持つが、`- 整形コマンド:` 行を読む関数は無い。
`cmd_new`（5.4）は本文をそのまま書き込み、`cmd_done`（5.7）は `taskfile.set_result_section` で
結果の節を差し込むだけで、どちらも書き込んだ後に整形をかける処理を持たない。一方
`skills/next-task/SKILL.md` 手順6は「受け入れる」時点（`task done` を打つ**前**）に
「整形コマンド → 検証コマンドを打つ」と既に書いてあり、手順7で `task done` が結果の表を
書き込んだ**後**には整形が無い。`skills/plan-tasks/SKILL.md` 手順7・`skills/retrospect/SKILL.md`
手順5も、`develop/direction.md`・`develop/retrospective.md` を直接書き換えたあと、整形を挟まず
そのまま `git add` してコミットしている。背景に書かれた2つの実例（`task done --result-file` の表と、
`plan-tasks` 相当のコミットが `direction.md` に残した空行）はどちらも「書いた直後に整形していない」
という同じ原因で、しかも後者は `task.py` の外（`develop/direction.md` への直接の書き換え）で
起きているため、**`task.py` の `new`/`done` だけを直しても2件目は防げない**。

以上より完了条件は **(b)** を選ぶ。(a) は `task done`／`task new` が書くファイルしか押さえられず、
`plan-tasks`・`retrospect` が書く `direction.md`／`retrospective.md` の空行は放置されたままになる。
(b) は3つの手順すべての「書き換え→コミット」の間に整形コマンドを挟めるので、背景の2件とも
防げる。また claude-skills 自身の「タスク運用」節は `整形コマンド: なし`（このリポジトリでは
効かない）なので、コードで自動化しても検証できるのは他プロジェクトの温床だけであり、
手順書に書き足す (b) のほうが「どのプロジェクトの整形コマンドを使うか」を素直に扱える。

`skills/next-task/SKILL.md` 手順7・`skills/plan-tasks/SKILL.md` 手順7・
`skills/retrospect/SKILL.md` 手順5に、`git add` する前に（`タスク運用`節の）整形コマンドを
打つ一文を足す（`なし` なら不要、の断り書きつき）。`task.py` 自体は変更しない。

## 注意

- 作業するのは claude-skills のリポジトリ（`~/ghq/github.com/sinnlosses/claude-skills`。`~/.claude/skills/` の各スキルはそこへの symlink で、書き換えは全プロジェクトへ即座に効く）。**着手時に `git -C ~/ghq/github.com/sinnlosses/claude-skills status --short` が空でなければ止めて預ける**
- claude-skills の枝は本体の作業ツリーで checkout せず、`git worktree add` で別の作業ツリーを切ってそこで作業する（本体で切り替えると全プロジェクトのスキルが変わる）。枝の名前は `feature/tsukumo-<このタスクのID>`。検証コマンドは claude-skills の `CLAUDE.md` に従う（`./check.sh`）
- コミットは claude-skills の側に入る。tsukumo のタスクの結果には claude-skills のコミットハッシュを書く

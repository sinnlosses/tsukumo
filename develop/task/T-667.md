T-660 の続き。`test/browser/features/task-board/` の単体テストを `test-audit` で監査し、T-658・T-659 の E2E（`test/e2e/`）が守っている振る舞いだけを確かめている単体テストを消す。

## 完了条件

- `test/browser/features/task-board/` を監査し、E2E が守っている振る舞いだけを確かめている単体テストを消している。消した1件ごとに、どの E2E が守るかをタスクの結果に書いている（テストの跡にコメントは残さない）
- 消す前に、その契約を本番コードで変異させて keeper の E2E が落ちることを確かめている
- `docs/coding-standards.md`「消すかどうか」表の「残す」行（回帰テスト・書式の固定）と、`docs/design.md` 10章「E2E に任せず単体テストに残すもの」に当たるテストは残している
- 消したあと、カバレッジ（閾値は置かない）で守られなくなった分岐が無いかを見て、あれば E2E か単体テストで埋めるか、埋めない理由を「埋めないと決めた穴」に書いている
- 消す前後のテスト件数と `bun run check` の所要時間を結果に書く
- `bun run check` が通る

- T-660 で「会話の画面」（`test/browser/components/page/conversation/`）を監査して40宣言・45件を消した。領域が広く1コミットに収まらないため、残りの領域を1件ずつに分けた
- 消す判定は `docs/coding-standards.md`「消すかどうか」表の「E2E の台本が通している振る舞い」の行と、その下の「E2E の台本が通している、とは」の段落に従う
- T-660 の例: `data-brush-origin` のように、定数と JSX の直書きが一致するかを見るテストは、E2E では捕まらないので残した

## やること

前提を洗い直した結果、`test/browser/features/task-board/` を守っている E2E は
`test/e2e/task-list.test.ts` の1本だけ（`grep -ln "task-board\|一覧を見る\|task-run-confirm" test/e2e/*.test.ts`
で確認）。このシナリオは「一覧を見る」のモーダルを一度も開かず、タスクIDのボタンも押さない。
DOM の写し（`test/e2e/scenario-run.ts` の `DOM_TREE_SCRIPT`）は `class` と `title` を残さず、
0属性の `div`/`span` は子に畳んで消える。`TaskMark`（`components/task-item.tsx`）が出す印は
`className` と `title` だけの空 `<span>` なので、todo/done/その他/無しのどの分岐でも DOM 写しには
何も残らない。したがって**状態の色分け・打ち消し線・印（`task-mark-*` / `task-done` /
`task-status-*` の class を見るテスト）は原理的に E2E では守れない**。E2E が実際に守っているのは:

1. サイドバーの件数チップの並びと文言・0件でも出す（`taskListCounts`。チップの `<li>` は
   テキストとして DOM に残る）
2. サイドバー一覧が doing 無しのときファイルの順のまま並ぶこと（`orderTasksForSidebar` の
   「doing 無し」分岐と `TaskItem` の描画）
3. doing が無ければ「進行中」バッジ付きのカード（`TaskRunningCard`）ではなく通常の行
   （`TaskItem`）で出ること（カードは「進行中」という文字と別の入れ子を持つため、混同すると
   DOM 写しが変わる）

モーダル（`task-board.tsx`）・確認ダイアログ（`task-run-confirm.tsx` 経由の実行）・件数チップを
実際に押しての絞り込み（`filterTasksForSidebar` / `taskListFilterLabel` / 進行中カードだけを残す
分岐）は、いまの E2E では一切踏まれていない。よって消す候補は次の3件に絞られる（変異での確認は
このあと行う）:

- `test/browser/features/task-board/domain/task-list-count.test.ts` の `taskListCounts`
  describe 配下2件（順序・0件を省かない）
- `test/browser/features/task-board/domain/task-sidebar-order.test.ts` の
  「doing が無ければ running は空で、rest はファイルの順のまま全件」
- `test/browser/features/task-board/task-list.test.tsx` の
  「doing が無ければ進行中のカードを出さない」

残りは、モーダル・確認ダイアログ・絞り込みの操作・状態の色分けのいずれかに当たるため、いまの
E2E では守られておらず残す。

## 注意

- 残したテストのうち、E2E に操作・材料・場面を足せば届くものは、候補として報告に挙げる（後段の T-716 がそれを E2E に移して消す）
- 変異を入れて確かめるときは、退避したコピーから戻す（`git checkout --` で戻さない）
- サブエージェントの中では別のエージェント（fork を含む）を立てず、レーンを順に自分で読む

## 結果

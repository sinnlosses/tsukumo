## 目的

`components/domain/layout/` を**画面共通のレイアウト**の置き場にする（2026-09-26 ユーザーの指示）。
いまの `layout/` の中身は会話の画面の4領域（メイン・サイドバー・キャラビュー・入力欄）専用なので、
会話の画面（`components/page/conversation/`）へ移す。いま画面共通のレイアウトは
`src/browser/main.tsx` の `Root` に直接書かれているので、それを `domain/layout` へ移す。

## 完了条件

- 会話の画面の4領域のレイアウト（`<Layout>`・`presentational-layout.tsx`・`hooks/use-layout.ts`・
  `layout-resizer.tsx`・`split.ts`・`layout.module.css`）が `components/page/conversation/` の下にあり、
  `presentational-conversation.tsx` から組まれている
- `components/domain/layout/` には、画面のナビの帯（`<ScreenNav>`）を最上部に置き、その下に画面を
  差し込む**画面共通の枠**がある。枠は差し込み口を props で受け、画面も他の枠（`screen-nav`）も
  import しない。`main.tsx` の `Root` は、どの画面を出すかを選んで枠に渡すだけになっている
- 画面の見た目と振る舞いが変わらない。4領域の比率の保存（`localStorage` の `tsukumo-layout-split:v1`。
  キーは変えない）・仕切りのドラッグ・狭い画面のタブ・雑談モードで畳む/地にする・帯が奪う高さの分だけ
  縮む、がどれも今と同じ
- テスト（`test/browser/components/domain/layout/` の4ファイル）をソースと同じ形の場所へ移してある。
  `test/architecture.test.ts` の `BROWSER_FRAMES` と、`docs/design.md`（2章の置き場所の表・枠の表・
  `split.ts` を例に挙げている3箇所）・`docs/coding-standards.md`・コード中のコメントのパスを追随させてある
  （`grep -rn "domain/layout" src test docs scripts README.md CLAUDE.md` で着手時に一覧を取り直す）
- 会話の画面・キャラクター画面・成果の画面を `TSUKUMO_DRIVER=fake` で出し、
  `scripts/capture-view.ts --measure '[data-region]'` で4領域の位置と大きさが移す前と同じであること、
  帯が各画面の最上部にあることを数値と撮った画像で確かめた
- `bun run check` が通る

## 注意

- **`presentational-conversation.tsx` はフックも算出も持たない器**（`docs/design.md` 2章「ページの形」）。
  ユーザーは「presentational-conversation.tsx に書くのが自然」と言っているが、比率の state やドラッグの
  読み替えまでそこへ入れると器の規則に反する。**器が4領域の組み立てを持ち、ロジックはページの
  `hooks/` か `components/<部品>/` へ置く**形を、ページの形の規則に沿って選ぶ
- 画面共通の枠に `<Activity>` の切り替えまで持たせるか、`Root` に残すかは、枠が「画面を知らない」を
  守れるほうにする（どの画面を出すかの判断は `Root`、置く場所の形は枠）
- 移すだけで見た目を変えない。CSS の中身を書き換えない（class 名は CSS Modules でハッシュになるので、
  ファイルを移しても外からは `data-region` で指せる）

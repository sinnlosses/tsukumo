## 決まっていること（蒸し返さない）

ユーザーの指示（2026-09-25）と、そのときの問答で決まったこと:

- ページの形:
  - `page/<ページ>/domain/` … そのページだけで使うドメインの機能。2つ以上のページで使うものは共通の側へ
    （部品なら `components/domain/`、部品でないものは `src/browser/domain/`。2章の既存の線に合わせる）
  - `page/<ページ>/hooks/` … そのページだけで使うフック。共通のものは `src/browser/hooks/`
  - `page/<ページ>/components/` … そのページで使う部品。**1部品1ディレクトリ**
    （`components/<部品>/<部品>.tsx`。その部品の CSS も同じディレクトリ）
  - `page/<ページ>/components/hooks/` … `components/` の下の部品だけが使うフック
  - `page/<ページ>/presentational-<ページ>.tsx` … presenter
  - `page/<ページ>/<ページ>.tsx` … container（例: `achievement.tsx`。いまの `achievement-screen.tsx` の
    ような名前は、構成要素として `components/` へ行く）
- **ページの直下に置くのは上のディレクトリと container / presenter の対だけ**。例外として、
  container / presenter が使う `<ページ>.module.css` は直下に置いてよい（部品専用の CSS は部品の隣）
- 直下の container / presenter は**ページに1対だけ**。`character` の create / edit / list のような
  2つ目以降の画面は `components/` の下の部品にする（部品が自分の container / presenter の対を持つのはよい）
- 会話の画面は**1ページ**にする（`conversation.tsx` / `presentational-conversation.tsx` を作り、4領域は
  `conversation/components/` の下へ入れる）

## 解くべき論点

- 会話の画面を1ページにするとき、`<Layout>` の差し込み口を誰が埋めるか（`main.tsx` のまま領域を
  差し込むのか、`conversation.tsx` が `<Layout>` を描くのか）と、2章「領域の機能と、置かれる機能」の
  「領域は `main.tsx` だけが import する。互いに import しない」との折り合い
- `components/<部品>/` の中に部品の container / presenter / 専用の hooks・道具（`markdown/` の
  `split-blocks.ts` など）を置くときの形。ページの `domain/` へ出すものとの線
- `diary-notice.tsx` のように、ページの部品なのに `main.tsx` が画面の外に置くものの扱い
- 規約を `test/architecture.test.ts` で落とす形（直下に許す名前の決め方）

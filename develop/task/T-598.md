## 目的

日記帳の書体をキャラクターごとに決められるようにする（2026-09-25 のフィードバック）。書体はパックに同梱したファイルを `127.0.0.1` から配る。

## 完了条件

- `character.json` に日記の書体を指す任意の項目があり、パックの中の書体ファイル（`woff2` / `woff` / `ttf` / `otf`）を指せる。無いパックは今までどおり `--font-serif`（端末の明朝体）で描く
- 書体を持つパックでは、成果の画面の日記の吹き出しと日記帳の見開きの本文がその書体で描かれ、キャラクターを切り替えると書体も替わる
- 定義の検証（`src/shared/character-definition.ts`）が不正な値・パックの外を指すパスを拒み、そのテストがある
- `docs/screen-design.md` の書体の決まり（「外部フォントは足さない」と 13 章「例外は日記の本文だけで、端末の明朝体に寄せる」の「書体ファイルも同梱しない」）を「キャラクターパックに同梱した日記の書体だけは配ってよい（外からは取らない）」に改め、`docs/design.md` 7章と `characters/README.md` に項目を書く
- `bun run check` が通り、仮の書体ファイルを置いたパックで日記の書体が替わることを目視で確かめる（仮のファイルはコミットしない）

## 背景

- キャラクター定義は `src/shared/character-definition.ts`（検証）と `src/shared/character.ts`、パックは `characters/<名前>/character.json`（`accent`・`chatAccent`・`portraits`・`background` など）
- 日記の本文の書体は `src/browser/features/achievement/achievement.module.css` の `font-family: var(--font-serif)`（10箇所）。`--font-serif` は `theme.css`
- パックの素材の配り方は `docs/design.md`「7. キャラクターパック」

## 決まっていること（蒸し返さない）

- 書体ファイルはパックに同梱して配る（2026-09-25 にユーザーが「パックに同梱する」を選んだ）。ネットワークから取らない
- 効かせるのは日記の本文（成果の画面の吹き出しと日記帳）だけ。レポートや吹き出しの書体は変えない

## やること

着手時の `main` で前提を調べ直した結果（背景節との差分）:

- 成果の画面は `src/browser/components/page/achievement/`（`features/` からは移動済み）に、
  `--font-serif` は `achievement.module.css` に17箇所（T-597 で見開きの幅を広げた際などに増え、
  10箇所ではない）。うち**「日記の本文」に当たる4箇所だけ**を差し替える対象にする
  （`.achievement-diary-bubble p` / `.achievement-diary-bubble-empty p` /
  `.diary-book-paragraph` / `.diary-book-blank-body`）。見出し・ラベル・卒業の印・署名などの
  残り13箇所は明朝体の意匠として残す（完了条件の「日記の吹き出しと日記帳の見開きの本文」の
  範囲そのもの）
- `character.json` の型・検証は `src/shared/character-definition.ts`（`CharacterDefinition`
  / `toCharacterDefinition`）、画面に渡す URL 化は `src/shared/character.ts`
  （`CharacterInfo` / `toCharacterInfo`）の2段。`background` / `face` が同じ2段を通っており、
  そのままなぞれる
- パックの素材を配る経路は `src/server/character-pack/adapter/character-pack.ts`
  （`characterPackFileNames` の allowlist と `characterAssetContentType` の拡張子仕分け）→
  `src/server/view-server/adapter/server.ts`（`/character/<pack>/<file>`）。拡張子の仕分けは
  `src/shared/character-asset.ts`（`classifyPortraitFile` は svg/raster しか知らない）
- 新規: `src/shared/character-diary-font.ts` に `isDiaryFontFileName`（背景と同じ、半角英数字と
  `. _ -` だけ・拡張子は4形式）と `diaryFontMimeType`（`woff2→font/woff2` など）を置き、
  `character-definition.ts` の `toCharacterDefinition` で `diaryFont` を検証、
  `character-pack.ts` の `characterPackFileNames` に足し、`characterAssetContentType` の
  フォールバックに `diaryFontMimeType` を足す
- `CharacterInfo.diaryFont` は `face` と同じ「無ければ undefined（`default` へは畳まない）」。
  `character.json` に無いパックはこの項目自体が無い
- ブラウザ側は `background-image` と同じ `document.documentElement.style` への書き込み
  （`src/browser/stores/session.tsx`）を踏襲するが、**`font-family` は `url()` を直接差せない**
  ので FontFace API で読み込んでから登録名を `--font-diary` に流す（useEffect の「外部からの
  読み込み」類型）。`theme.css` に `--font-diary: var(--font-serif);` を足し、対象4箇所の
  `font-family` を `var(--font-diary)` に差し替える。書体を持たないパックは変数ごと外すので
  `var()` のフォールバックで `--font-serif` に戻る
- キャラクター編集の画面（`character-screen`）に差し替える口は作らない（完了条件どおり要件に
  1行残す。この本文と `characters/README.md` の `diaryFont` の項目がその1行を兼ねる）

## 注意

- キャラクターの中身をコードに書かない（原則4）。書体の名前や経路は定義ファイル側
- キャラクター編集の画面（`character-screen`）で書体を差し替える口までは作らなくてよい。作らないなら要件に1行残す
- `src/browser/features/achievement/` は T-582〜T-585 で移る途中かもしれない。着手時の `main` の場所に合わせる

## 結果

- `character.json` に任意の `diaryFont`（パックの中の `woff2`/`woff`/`ttf`/`otf` のファイル名。パス区切りと `..` を拒む）を足し、立ち絵と同じ `/character/<pack>/<file>` で拡張子に合う Content-Type で配る。ブラウザは FontFace API で登録して `--font-diary` に流し、成果の画面の日記の本文4か所だけに効かせる（無い・読めないパックは明朝体）。編集画面の口は作らず `characters/README.md` と `docs/design.md` 7章に残した。`docs/screen-design.md` 13.3 の書体の決まりを改めた
- 検証コマンド: 2674 pass / 0 fail（+9）、`bun run build` 成功。一時ホームの架空パックに macOS の書体を写して疑似セッションで起こし、日記の吹き出しと見開きの本文の `font-family` と `document.fonts` の `loaded` を測り、書体の無いパックへ切り替えると明朝体に戻ることを確かめた
- 振り返り: 同じファイルを3回以上直した（ドラフト 0件）

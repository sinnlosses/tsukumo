## 目的

帯の右端の歯車で覚える新しいセッションの既定（`docs/screen-design.md` 13.6）に effort を足し、次に起こすセッションがその effort で始まるようにする。

## 完了条件

- `src/shared/session-default.ts` の既定に effort が入り、同梱の既定は今と同じ `medium`
- `set-session-default` コマンドが effort も運び、`~/.tsukumo/state.json` に覚える。**effort が無い古い `state.json` も読めて、そのときは同梱の既定に落ちる**（前に覚えたモデル・許可モードを捨てない）
- 起こすときに `src/server/adapter/sdk-driver.ts` が `DEFAULT_EFFORT` の代わりに覚えた effort を渡す
- 歯車の画面で effort を選べる（選択肢と表示名は T-577 の帯のドロップダウンと同じものを使う）
- テスト: 既定の読み書き（古い形の `state.json` を含む）・コマンドの検証・起こすときに渡る値
- `bun run check` が通る。歯車の見た目は目視で確かめ、どの端末で何が見えたかを結果に書く
- T-576 が「成り立たない」で終わっていたら、着手せず `dropped` で閉じてよい

## 背景

- 既定の型と同梱の値は `src/shared/session-default.ts`（`model` / `permissionMode`。45〜46行目）、読み書きは `src/server/adapter/remembered-default.ts`（`readRememberedSessionDefault` / `writeRememberedSessionDefault`。`docs/design.md` の覚え先の表）
- コマンドは `src/shared/command.ts` の `set-session-default`。コメントのとおり、モデルと許可モードを**1つのコマンドで運び、1組で書き換える**形になっている
- effort はいま `sdk-driver.ts:64` の `DEFAULT_EFFORT` を起動時に渡すだけ

## やること

T-576 は「成り立たない」で終わっていない（64abe293 で完了済み。帯から effort を途中で変えて
読めることを実機で確かめてある）ので、そのまま着手する。

いまのコードを読み直した結果:

- `SessionDefault`（`src/shared/session-default.ts`）は `model` / `permissionMode` の2つで1組。
  `effort` を足して3つで1組にする。選べる段は `SESSION_DEFAULT_PERMISSION_MODES` のような
  部分集合を作らず、`command.ts` の `EFFORT_LEVELS`（5段）をそのまま使う（除外する値が無いため）
- `remembered-default.ts` の `sessionDefaultStateSchema` は `model` / `permissionMode` が
  必須の1つの `z.object`。**同じ扱いで `effort` を必須にすると、effort の無い古い
  `state.json` を渡したときに `sessionDefault` 全体が読めなくなり、覚えたモデル・許可モードまで
  同梱の既定へ落ちてしまう**（完了条件が禁じている動き）。そこで `effort` だけ
  `z.enum(EFFORT_LEVELS).optional()` にし、読んだあとで `?? BUILTIN_SESSION_DEFAULT.effort` へ
  畳む（model / permissionMode が壊れている・知らない値のときは今までどおり3つとも同梱の既定へ
  倒れる——ここは「1組で書き換える」の対象のまま変えない）
- `set-session-default` コマンド（`command.ts`）・`session-manager.ts` の `case "set-session-default"`
  （`rememberSessionDefault` へ渡す組み立て）はどちらも `effort` を素通りさせるだけの箇所
- 起こす経路は `session-launch.ts` → `session-start.ts` の `startDriver` → `sdk-driver.ts` の
  `startSdkDriver`/`buildQuerySeedOptions`。**`SessionDriverOptions`（`core/session-driver.ts`）に
  `effort: EffortLevel` が無い**ので足す。`startDriver` が `seed.sessionDefault.effort` をそこへ渡し、
  `buildQuerySeedOptions` は `DEFAULT_EFFORT` 定数ではなく `options.effort` を使う。
  **`DEFAULT_EFFORT` は同梱の既定（`BUILTIN_SESSION_DEFAULT.effort`）と同じ語彙を二重に持つだけに
  なるので削除**し、`docs/design.md`・`session-driver.ts` 冒頭のコメントの言及も外す
  （`fake-driver.ts` の `FAKE_DEFAULT_EFFORT` は別物なので触らない——あちらは「疑似セッションで
  いま効いている effort」を表すランタイムの変数の初期値で、本物の駆動でも `effort` は
  `session-info` に乗らず `Stop` フックでしか読めない非対称を疑似しているため、
  起動時の既定と同期させる理由が無い）
- 歯車（`use-settings.ts` / `screen-nav-settings.tsx`）は、帯の効果対応判定
  `resolveEffortSelect`（`domain/effort-label.ts`）をそのまま再利用する。`modelEffortSupport` は
  `supportedModels()` の全モデル分の対応表（駆動起動直後に1回届く）で、**いま選んでいる帯の
  モデルとは無関係に「その他のモデル」の対応も引ける**ため、歯車の既定モデル（帯とは別に
  選べる）に対しても同じ関数で「対応しない（haiku）」「まだ対応表が届いていない」「選べる」の
  3状態を出せる。表示名は `EFFORT_LABELS`/`effortLabel` をそのまま使う（二重に持たない）。
  対応しないモデルが既定に選ばれているときは `<select>` を `disabled` にする（帯と同じ扱い）。
  値そのものは常に持ち続け（`model` を haiku に変えても `effort` の欄は消さない）、駆動へは
  常に渡す（今の `DEFAULT_EFFORT` も対応外のモデルへ無条件に渡していた既存の挙動のままで、
  SDK 側が対応しないモデルの `effort` を無視する前提を崩さない）
- `set-session-default` は `model`・`permissionMode`・`effort` を1組で書き換える契約のまま
  （2つから3つに増えただけ）
- 状態（`SessionState.sessionDefault` の形）とコマンド（`set-session-default` の形）の両方が
  変わるので `PROTOCOL_VERSION` を 18 → 19 に上げる
- `docs/screen-design.md` 13.6 の本文（表の行は T-576 の時点で先取りして直してあるが、
  「新しいセッションの既定（モデル・許可モード）は…」で始まる段落と「同梱の既定
  （Opus・`auto`）」がまだ2つのまま）と `docs/design.md` の覚え先の表（965〜972行目の
  `remembered-default.ts` の節）を直す。どちらも見出しの節数が前後で変わらないことを
  `grep -c '^#\{2,3\} '` で確かめる

対応しないモデルの扱い（帯と揃える）: **歯車の既定モデルが effort に対応しないと分かっている
ときは `<select>` を選べなくする**（帯の `unsupported` と同じ）。**対応表がまだ届いていない・
知らないモデルのときも選べなくする**（帯の `unknown` と同じ）。どちらも `resolveEffortSelect`
をそのまま使うことで実現し、歯車専用の判定は書かない。実機での見え方は目視確認の節に書く。

## 目的

前段で作った並べる部品を、残る `components/page/` の画面（会話・キャラクター・成果・使用量）にも行き渡らせ、並べるだけの手書きの flex 規則を無くす。

## 完了条件

- `src/browser/components/page/` の `*.module.css` で、**flex の向き・間隔・揃え・折り返しに置き方だけを足した規則のうち、gap が `Stack` の段（0 / 0.25 / 0.5 / 0.75 / 1 / 1.25rem）に乗るもの**が前段の `Stack` に置き換わり、規則が消えている（置き方は `className` に残す）。段に乗らない gap の規則（計画時の実測で 22。`.achievement-review` 0.4rem・`.character-profile` 1.1rem・`.turn-meta` 0.6rem など）と、箱の見た目（余白・枠・地）も持つ規則は残す。置き換えなかった規則を結果に1行ずつ書く
- トークン消費の画面・日記帳の中でも、並べるだけの規則は置き換えてよい（`Stack` は色を持たないので、画面固有の色と競らない）
- 部品の API を広げたなら（`element` の値など）、`test/browser/components/ui/stack/stack.test.tsx` にその行を足してある
- `test/architecture.test.ts`「components/ui/ の部品の className」が通る（置き換えで渡した class が `Stack` の持つ property と重ならない）
- 会話の画面（メインビュー・キャラビュー・入力欄・振り分け）、キャラクターの画面、成果の画面（日記帳の見開きを含む）、使用量の画面を起動して目視し、並びと間隔が置き換え前と同じであることを確かめている（何を見たかを結果に書く。モーダルの中も測る）
- `bun run check` が通る

## 背景

- 計画時の実測（2026-09-25）で、`page/` の「並べるだけ（＋置き方）」の規則は 60、うち gap が段に乗るのが 38。量が多いのは `page/character/character-screen.module.css`、`page/achievement/achievement.module.css`、`page/token-usage/token-usage.module.css`

- 作法は `docs/design.md` 2章「`components/ui/` の部品（variant の作法と一覧）」が正典

## 決まっていること（蒸し返さない）

- **見た目を変えない。** 段に乗らない gap は丸めずに CSS に残す（丸めるかは別の判断として持ち越し）
- 箱の見た目も持つ規則は2つに割らない

## やること

着手前にコードで前提を取り直した（2026-09-25）。`src/browser/components/page/` の全13個の `*.module.css`（`markdown/report-notation.module.css` は対象外）の `display: flex` / `inline-flex` 規則を1つずつ数え、gap が段（`none`/`xs`/`sm`/`md`/`lg`/`xl`）に乗るか・箱の見た目（padding・border・border-radius・background のいずれか）を持たないかで振り分けた。加えて計画時点の完了条件には無かった制約を3つ実地で見つけた（後述）。

- **置き換える**: 対応する `.tsx` を開き、`display: flex` の親要素が実際に `div` / `section` / `span` で、`aria-*` 属性や `ref` を要求していないことを確かめたうえで `Stack`（向きが決まっていれば `VStack` / `HStack`）に差し替え、CSS 側の並べる規則（`display` / `flex-direction` / `gap` / `align-items` / `justify-content` / `flex-wrap`）を削り、置き方（`margin` / `flex` / `min-width` / `position` など）だけを残す
- **置き換えない**（完了条件にある2条件に加えて、実装時に見つけた3条件）:
  1. gap が段に乗らない（22 規則、計画どおり）
  2. 箱の見た目（余白・枠・地）を持つ
  3. **`Stack` の `element` が `"div" | "section" | "span"` しか無いので、実際の要素が `<p>` / `<ul>` / `<li>` / `<ol>` / `<header>` / `<footer>` / `<label>` / `<form>` / `<dt>` の規則は置き換えられない**（`question-ask.module.css` の3規則が丸ごと該当）
  4. **`Stack` は `aria-label` / `aria-labelledby` を props に持たない**ので、その属性が要る要素（`<section aria-label>` など）は置き換えない
  5. **`Stack` は `ref` を forward しない**ので、`scrollIntoView` や `getBoundingClientRect` に使う ref 付きの要素は置き換えない（`main-view.tsx` の `data-brush-origin` も同じ理由で対象外——`ref` と `data-*` 属性の両方を失う）
- 画面ごとの対象ファイルと `.tsx`:

  - キャラクター: `character-screen.module.css`（`character-list.tsx` / `components/character-profile.tsx` / `presentational-character-edit.tsx` / `components/portrait-card.tsx` / `components/portrait-clear-confirm.tsx` / `components/accent-swatch.tsx` / `components/face-field.tsx` / `components/background-field.tsx` / `components/character-delete-confirm.tsx` / `presentational-character-create.tsx`）
  - 成果: `achievement.module.css`（`day-switch.tsx` / `lantern-calendar.tsx` / `diary-book.tsx`）、`diary-notice.module.css`（`diary-notice.tsx`）。`surprise-section.tsx` の `.achievement-surprise` は `aria-label` が要るので対象外

## 注意

- 画面が多く1コミットに収まらない量だと分かったら、画面単位で後続タスクに切り出してよい
- 前段（T-607）で `VStack` は作ったが、置き換え先は0件だった。`components/domain/sidebar/profile-card.tsx` の `.profile-card-text`（column・gap 0.25rem）は `VStack` にすると読み手が1機能だけになり「browser/ の機能をまたぐ箱」に落ちるので残してある。このタスクで `page/` 側に `VStack` の読み手ができたら、一緒に置き換える
- 狭い画面でメディアクエリから `flex-direction` を反転させている規則（`.screen-nav-work`・`.screen-nav-model-permission` のような形）は、`Stack` の向きが props だけなので見た目を変えずには置き換えられない。`page/` にも同じ形があれば残して結果に書く

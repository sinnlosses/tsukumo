## 目的

`test-audit` スキルのキャンペーンモード（同スキルの `CAMPAIGN.md` の8段）で、`test/shared/`（34ファイル・約6,600行。サーバとブラウザの両側で共有する契約） のテストを刈り込む。価値の低いテスト・実装に結合したテスト・より強い証明と重なるテストと、テストしか呼ばない本番コードを消し、残す契約はより強い境界のテストに寄せる。

## 完了条件

- 対象範囲のテストの宣言ごとに `R` / `F` / `C` / `D` の印と1行の証拠を付けた台帳を作り、印ごとの件数と、`C` / `D` の宣言ごとの残す側（keeper）を タスクの結果 に書く（台帳の全文はリポジトリに置かない）
- `D` / `C` の編集と、それで消せるようになったテスト専用の本番コードの継ぎ目の削除を済ませる
- 移した（`C` / `F`）契約ごとに、本番側の持ち主にわざと1つ変異を入れて keeper が落ちることを確かめ、元に戻す
- 基準線（着手時）と完了時の、対象範囲のテストの `it` の数と行数、本番コードの増減を タスクの結果 に書く
- `bun run check` が通る
- 確信の持てる候補が無ければ、台帳の件数だけ書いて編集なしで `done` にしてよい

## 背景

- 2026-09-25 に `test-audit` スキル（openclaw/openclaw の同名スキルを日本語化して claude-skills に入れたもの）を取り込み、監査モードの試運転で、テストだけが呼んでいた `parseAnswer`（`src/shared/pending-ask.ts`）と `newFormatTaskSummaries`（`src/shared/task-summary.ts`）を消した。固有の検査は `test/shared/command.test.ts` と `test/server/repository/adapter/task-summary.test.ts` に移した（`0b3ef70a`）
- テスト全体は 205 ファイル・約4.7万行で、機能ごとに1タスクに分けた。このタスクはsharedの範囲

## 決まっていること（蒸し返さない）

- 消すかどうかは `docs/coding-standards.md`「テスト」節の「消すかどうか」「埋めないと決めた穴」と突き合わせる。スキルの残す基準とリポジトリの規約が食い違ったら、リポジトリの規約を優先し、食い違いを タスクの結果 に書く
- 残す基準は、スキルの `SKILL.md`「残す基準」のとおり（とくに、出力の書式を固定するテストと過去のバグの退行テストは残す）
- `CAMPAIGN.md` の段7（プロダクトの欠陥）で見つけた欠陥は、このタスクでは直さず、`develop/direction.md` の 「エージェントのドラフト」節 に積む。段8（`main` の merge）はタスクが短いので要らない
- 1タスク＝1コミット。対象範囲の外のテストは、範囲内の契約を吸収する keeper になるときだけ触る

## 解くべき論点

- `shared` の型とスキーマはサーバとブラウザの両側が読む契約で、スキルの残す基準の「プロトコル」に当たるものが多い。どのテストが契約を独立に守り、どれが両側の入口のテストと重なっているかを、読み手（`src/server/` と `src/browser/`）のテストまで辿って決める

## やること

前提を確認した（2026-09-25 着手、基準線は `f522763e`）:

- 対象は `test/shared/`（`lib/byte-length.test.ts` を含む）の **34ファイル・6,649行・`it` 497件**
  （`bun test --isolate test/shared` で 497 pass / 0 fail）。本文の見立てと一致し、前提は崩れていない。
  試運転（`0b3ef70a`）で `task-summary` の一部はすでに `test/server/repository/adapter/` へ移っている
- レーンは本番側の持ち主（`src/shared/<名前>.ts`）ごとに切り、1ファイル＝1レーンで順に自分で読む
  （別エージェントを立てない）。論点の「両側の入口のテストと重なっているか」は、各読み手を
  `test/server/` と `test/browser/` から `grep` で辿って確かめた。ブラウザ・サーバ側の読み手の
  テストは通信・取得の配線（取れない・読めない形に倒す）を見るもので、`shared` のスキーマの枝を
  独立に固定しているのは `shared` 側だけ。**層をまたいだ重複で消せるのは `diary` の「段落が2つ以上」
  の1件だけ**（`test/server/diary/adapter/diary.test.ts` が実ファイルで2段落を読み戻している）
- 残りの候補は同じファイルの中の重なりで、次の3種類:
  - より強い（全体を `toEqual` で比べる・同じ入力で多く検査する）兄弟のテストに含まれている
    （例: `session-state` の「request でターンが進行中に…」は「request で起点を打ち…」に、
    `main-view` の「ターンが終われば、短い最終レポートも出る」は「短い返事だけのターン…」に含まれる）
  - 畳み込みが分岐しない入力の言い直し（例: `usageReview` の後始末は `outcome` を見ないので
    「割り込まれて終わっても」は「結果を渡さずに終わると」と同じ枝。`character-changed` は残りを
    丸ごと写すので `chatAccent` / `tagline` 個別の検査は全体の `toEqual` と同じ枝）
  - 落ちようのない検査（`achievement` の「会話の文面は入らない」は入力に無い文字列の不在を見るだけ、
    「関わらないターンの終わりでは idle のまま」は後始末が壊れて idle に倒れても通る）
- 名前がアサーションと食い違うテストは名前だけ直す（`prompt-image` の「上限（2 MiB）」は実際の上限
  5 MiB と違う、`portrait-motion` の「ターンが進行中でも」は終わったターンを渡している、
  `session-state` の「段は戻らない」は戻らないことを検査していない）
- テスト専用の本番コードの継ぎ目は見つからなかった（`shared` の export はどれもサーバかブラウザが
  呼んでいる）。本番コードは変えない
- 作業: 上の候補（D 24件・C 11件）を消し、F 3件の名前を直す。C は keeper が既に同じ
  アサーションを持っているので運ぶものは無く、keeper ごとに本番側へ変異を入れて落ちることを
  確かめてから戻す

## 注意

- 変異を入れて確かめるときは、退避したコピーから戻す（`git checkout --` で戻すと、同じファイルへの先行の編集ごと消える）
- `CAMPAIGN.md` の段3・段6は、別のエージェントに読ませることを求めている。サブエージェントの中で別のエージェントを立てられないなら、レーンごとに順に自分で読み、段6の保全のレビューは受け入れのときにメインが行う
- ブラウザに出る絵は自動テストで守らない方針（`docs/architecture.md`）なので、描画のテストを消すときも、足すときも、その方針の範囲で判断する

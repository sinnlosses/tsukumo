## やること

対応表の段2の7行の前提を調べ直した結果、崩れは無かった（表どおりに移してよい）。

- 7ファイルはすべて存在し、テストの有無も表と一致（`core/context-usage.ts` だけ「テストあり」欄が
  「—」で、実際に `test/server/core/context-usage.test.ts` は無い）
- `core/context-usage.ts` は `./session-driver.ts`（共有の箱の `server/core/` 直下。段7で
  `session-driver/core/` へ移る）を import している。これは2章の辺の表
  `context-usage | session-driver | core → core（駆動の契約）` のとおりで、`session-driver` は
  まだ `SERVER_FEATURES` に無い（段7）ため、移した後も「機能どうしの辺」としては現れない
  （相手が共有の箱のまま）。よって `SERVER_FEATURE_IMPORTS` に足す行は無い
- 他の6ファイル（`context-usage-log.ts` `token-usage.ts` `token-usage-log.ts` `usage-review-tool.ts`
  `previous-usage-review.ts` `usage-proposal-dismissal.ts`）の import は shared・共有の箱
  （`lib/json-file.ts` `lib/jsonl.ts` `local-time.ts` `tsukumo-home.ts`）だけで、他機能への辺は無い
- 逆方向（まだ移していない `server/adapter/sdk-driver.ts` `server/adapter/sdk-tool.ts` が
  `core/usage-review-tool.ts` を import）は、共有の箱側がまだ動いていないだけなので、段8まで
  検査を止めておく規則どおりで問題ない
- 3機能（`context-usage` `token-usage` `usage-review`）とも `SERVER_FEATURES` へは足すが、
  `SERVER_FEATURE_IMPORTS` の集合はすべて空（葉）

以上より対応表・作業方針に変更なく、7ファイルと対応するテスト6本を `git mv` で移し、参照を直す。

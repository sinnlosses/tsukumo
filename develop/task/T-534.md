## 背景

2026-09-24 に `/simplify` の4観点（再利用・単純化・効率・根本対処）でリポジトリ全体を洗った結果の1件（`docs/history/direction.md` の 2026-09-24「改修コストを下げる直し9件」）。

画面（`conversation` / `character` / `token-usage` / `achievement`）を1枚足すたびに、次の4箇所を揃える必要がある。1つ抜けると「hash には乗るがメニューに出ない」「メニューにはあるが描かれない」が黙って起きる。

- `src/browser/stores/location-hash.ts` の `SCREENS`
- 同じファイルの画面名の表（`achievement: "achievement"` などが並ぶもの）
- `src/browser/features/screen-nav/hooks/use-screen-nav.ts` の帯のメニューの配列（`{ screen, label }`）
- `src/browser/main.tsx` の画面部品の import と `screen === "..." ? <X /> : null` の分岐

着手時に `grep -rn '"achievement"' src/browser` で、ほかに画面の一覧を持つ場所が無いか取り直す。

## 解くべき論点

- 表を置く場所。`stores/` は部品（React）を知らないので、画面の名前とラベルの表（`stores/` か `domain/`）と、名前から部品を引く表（`main.tsx` の側）の2つに分けてもよい。そのときも「名前の一覧」は1つにし、部品の表は `Record<Screen, ...>` で抜けを型エラーにする

## やること

1. 画面の名前・ラベルの一覧を1つにし、`SCREENS`・帯のメニュー・`main.tsx` の分岐をそこから導く
2. 部品の表は `satisfies Record<Screen, ...>` などで、画面を足したのに部品を登録し忘れたら型エラーになるようにする

## 完了条件

- 画面を1つ足すときに触る場所が「名前とラベルの一覧」と「部品の表」の2つだけになり、部品の登録漏れが `bun run typecheck` で落ちる（`evidence` に仮の画面で確かめた結果を書き、仮の画面は戻す）
- 帯のメニューの並び順と表示名が変わっていない

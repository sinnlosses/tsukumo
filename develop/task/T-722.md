## 目的

`src/browser/lib/` を「固有のライブラリ（orpc のように特定の用途のもの。react・remeda のような汎用は除く）に依存する道具を、腐敗防止層として包む場所」に絞り、それ以外の汎用の道具を `src/browser/utils/` に置く（2026-09-27 ユーザーの指示）。

## 完了条件

- `docs/design.md`「`lib/` と `utils/` に置く基準」の手順2の表と例を、上の線引きに書き換えている（実行環境の API（`FileReader`）と React は `utils/` 側。`browser/` の置き場の一覧の `lib/` と `utils/` の説明も揃える）
- `src/browser/lib/` に残っているのが、固有のライブラリを包むファイルだけになっている。移したファイルは import ごと直している
- `src/shared/` と `src/server/` の `lib/` に新しい基準に合わないものがあれば、移すか、移さない理由を結果の節に書く
- `bun run check` が通る

## 背景

- `src/browser/lib/` の7ファイルの import（登録時）:
  - `rpc-client.ts` / `socket.ts`: `@orpc/*` を包む（残る側）
  - `data-url.ts`: import なし（`FileReader`）
  - `debounce.ts`: `react` だけ
  - `refresh.ts`: `shared/frame.ts` の `RefreshTarget` と `utils/clock.ts` だけ（名前が tsukumo の語彙なら `domain/` の線もある。手順1で判定する）
  - `session-token-url.ts`: `shared/session-socket.ts` だけ
  - `tool-summary.ts`: `remeda` だけ（今の基準では「外部システムの語彙」として `lib/`）
- 今の基準は `docs/design.md`「`lib/` と `utils/` に置く基準」で、`FileReader` と React の hook を `lib/` の例に挙げている。`utils/` の歯止め3（別のプロジェクトへそのままコピーして意味が通る）もそこにある

## やること

- `docs/design.md`「`lib/` と `utils/` に置く基準」の手順2の表・例・歯止め1を、「固有のライブラリ
  （`orpc` のように特定用途のパッケージ）を包むか、それ以外か」の線引きに書き換える。`browser/`
  の置き場の一覧の `lib/` / `utils/` の説明も同じ線引きに揃える
- `src/browser/lib/` の7ファイルを判定し直す:
  - `rpc-client.ts` / `socket.ts`: `@orpc/*` を包む → `lib/` に残す
  - `session-token-url.ts`: どのパッケージも包まないが、`rpc-client.ts` / `socket.ts` の結線
    （起動トークン付き URL の組み立て）を支える内部ヘルパー → `lib/` に残す
  - `data-url.ts`（`FileReader`）・`debounce.ts`（`react` の hook）: 汎用の実行環境 API / 汎用
    ライブラリ → `src/browser/utils/` へ移す
  - `refresh.ts`: `refresh` / `RefreshTarget` は `docs/glossary.md` に載る tsukumo の語彙 →
    手順1に従い `src/browser/domain/` へ移す
  - `tool-summary.ts`: `remeda` は汎用ライブラリで `lib/` の基準に合わず、`shared/utils/` への
    import があるので `utils/` の歯止め（プロジェクト外へコピーして意味が通る）も満たさない →
    `src/browser/domain/` へ移す（2つ以上の領域が読む表示の整形として、既存の `domain/` の
    ファイル群と同じ性質）
  - 移した4ファイルの呼び出し側の import と、コメントに残るパス表記を直す
- `test/architecture.test.ts` の `ALLOWED_BROWSER_BOX_IMPORTS` など、`refresh.ts` /
  `tool-summary.ts` の移動で辺の意味が変わる箇所を確認し、必要なら直す
- `src/shared/lib/byte-length.ts`（`TextEncoder` のみで外部パッケージなし）は新しい基準では
  `utils/` 側 → `src/shared/utils/` へ移し、呼び出し側とコメントを直す
- `src/server/adapter/lib/json-file.ts` / `jsonl.ts` は `docs/design.md` の別の基準
  （`adapter/lib/` は「境界を名乗らず技術の扱い方だけを知っている道具」）で判定されており、今回の
  `lib/` / `utils/` の線引きの対象外。`node:fs` を使うこと自体は妥当なので移さない
- `bun run check` を通す

## 注意

- 置き場所は `test/architecture.test.ts` が検査している。基準を変えて検査と食い違うなら検査も直す

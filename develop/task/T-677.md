## 目的

まだ作業が続いている（背景の仕事を待っている・通知で続きのターンが走っている）あいだに、末尾のレポートが「最終レポート」と名乗って画面に出ないようにする。札は「このやり取りでもうレポートは増えない」と機械的に言えるときだけ立てる。

## 完了条件

- 「最終レポート」の札（`MainViewStep.final` と、それに基づく地の段・ラベル）は、いちばん新しいやり取りでは**ターンが `running` でなく、背景のタスク（`SessionState.backgroundTasks`）も残っていない**ときだけ立つ。それ以前のやり取りは今までどおり
- 背景のタスクを待って SDK ターンが一度閉じた場面・通知で続きのターンが走っている場面で、末尾のレポートに札が出ないことを E2E で守る（既存の `background-task-running` / `background-task-resumed` のシナリオと期待値に寄せられるなら寄せる）
- やり取りが閉じたら札が立つ（閉じたあとの表示は今と同じ）
- `docs/display.md`・`docs/screen-design.md` 13.2・`docs/glossary.md`「最終レポート」の定義を合わせる
- 手で確かめる: 背景の仕事を待っているあいだ札が出ず、閉じたら出ること。何が見えたかを結果の節に書く
- `bun run check` が通る

## 背景

- 札を立てるのは `src/shared/main-view.ts` の `markFinalReport`（「最後の、中間でない本文」に `final`、中間レポートがあれば `hasInterimReport`）。描くのは `src/browser/components/page/conversation/components/main-view/components/turn/turn.tsx`（`finalLabel`）
- 伏せる判定は `src/browser/stores/main-view-turn.ts` の `unsettledBodies`。`report` は「いま走っている SDK ターンで届いたもの（`bodiesInTurn.report`）」だけを伏せる。背景の仕事を待って黙ると SDK が `result` を出して `turn-finished` が届き、前の SDK ターンの最後の `report` が確定扱いになる。その結果、続きのターンが走っているあいだも・背景のタスクが残っているあいだも、`markFinalReport` がそれに札を立てる（これが利用者の見た症状）
- 伏せる判定（`report` を出すかどうか）は変えない。前の SDK ターンの `report` を伏せると、合図が届くたびに出ていた中間レポートが消えて出直す問題が戻る（`unsettledBodies` のコメント）。変えるのは札だけ

## 決まっていること（蒸し返さない）

- 閉じていないあいだの末尾のレポートは、札も地の段上げも付けない（中間レポートの破線の枠にもしない。追い越されたら今までどおり中間レポートとして畳まれる）

## やること

現状のコードを読み直した前提:

- `markFinalReport`（`src/shared/main-view.ts`）は、いちばん新しいやり取りかどうかに関わらず
  「最後の、中間でない本文」に無条件で `final` を立てている。閉じたかどうかの情報は一切見ていない
- `mainViewTurns` は `entries` と `unsettled: TurnBodies` の2引数で、`TurnBodies` は
  `{ report: boolean, utterance: boolean }`。`unsettled.report` は
  `state.turn.kind === "running" && state.bodiesInTurn.report`（`main-view-turn.ts` の
  `unsettledBodies`）で、**`state.backgroundTasks` を見ていない**。背景のタスクを待って
  `turn-finished` が届くと `state.turn.kind` が `running` でなくなるので `unsettled.report` は
  false になり、`selectToolReports` はいちばん新しい `report` を確定扱いにする——ここまでは
  「本文を出す」ための判定で、変えない（決まっていること）
- その確定した本文に対して `markFinalReport` が無条件で `final` を立てるのが今回直す箇所。
  `final` は同じやり取りに中間レポート（`interim`）が1件以上あるときだけラベルを出す
  （`turn.hasInterimReport`）ので、症状が見えるのは **`report` ツールを2回以上呼んだあとに
  背景の仕事へ入り、`turn-finished` を挟んで `turn-resumed` する場面**（1回しか呼んでいなければ
  `hasInterimReport` が false でラベルは出ない）
- 既存の E2E シナリオ `background-task` / `background-task-short`（`test/fixture/fake-session.json`）
  は本文を素の `utterance` で出しており `report` ツールを呼んでいない。この経路
  （`selectLastText`）では `interim` が一度も立たないため `hasInterimReport` は常に false で、
  今回の「札を早く立てすぎる」症状はそもそも再現しない。既存の期待値 JSON にも「最終レポート」の
  文字列は1つも出ていない（確認済み）。そのため今回のシナリオは既存の2つに寄せず、
  `report` ツール2回＋背景のタスク待ちを組み合わせた新しい場面を1つ足す

やること:

1. `src/shared/main-view.ts`: `mainViewTurns` に3つめの引数 `closed: boolean` を足す（呼び出し側が
   「セッション全体が閉じているか」を渡す）。いちばん新しいやり取りだけ、この `closed` を
   `markFinalReport` に渡す（それより前のやり取りは常に閉じている扱いのまま今までどおり）。
   `markFinalReport(turn, closed)` は、`closed` が false のときは `finalId` を求めず（`final` を
   一切立てない）、`hasInterimReport`（`interim` の集計）はこれまでどおり `closed` に関係なく計算する
2. `src/browser/stores/main-view-turn.ts`: `unsettledBodies` の隣に「セッションが閉じているか」
   （`state.turn.kind !== "running" && state.backgroundTasks.length === 0`）を計算する関数を足し、
   `mainViewTurnsOf` から3つめの引数として渡す
3. `test/shared/main-view.test.ts`: 既存の `mainViewTurns(...)` 呼び出しすべてに3つめの引数
   （既存の期待値を壊さない値、今までの前提＝やり取りが閉じている `true`）を足し、新しく
   「`report` を2回呼んだあと、閉じていない（`closed=false`）あいだは最後の `report` に `final` が
   立たない」「閉じたら（`closed=true`）立つ」を確かめるテストを足す
4. `test/browser/stores/main-view-turn.test.ts`: 背景のタスクが残っているあいだ／続きのターンが
   走っているあいだは `mainViewTurnsOf` が返す最終ステップに `final` を立てないことを確かめるテストを足す
   （必要なら）
5. `test/fixture/fake-session.json` に、`report` ツール2回＋背景のタスク待ちを1本にした場面を
   1つ追加し、`test/e2e/` に対応するシナリオを1本足す。背景のタスクが残っている・続きのターンが
   走っている時点で撮った DOM に「最終レポート」の文字列が出ていないこと、待ちが終わって
   `turn-resumed` のあとの最終 `turn-finished` まで進めて撮った DOM には出ていることを、
   期待値 JSON（`bun run test:e2e:update` で書く）で確かめる
6. `docs/display.md` 4.2・`docs/screen-design.md` 13.2・`docs/glossary.md`「最終レポート」の
   「同じやり取りに中間レポートが1つ以上あるときだけ出す」という条件に、「かつ、やり取りが
   閉じているときだけ」を足す

## 注意

- `mainViewTurns` の2つめの引数（`TurnBodies`）に「やり取りが閉じたか」を足すか別の引数にするかは、読む人が追いやすいほうを選ぶ

## 目的

描けた `progress` の塊が、使われ方の記録で「知らない種類で落とした塊」と数えられている不具合を直し、塊を足したときに一覧から抜ける経路を型で塞ぐ。

## 完了条件

- `src/shared/report/report-block.ts` の `REPORT_BLOCK_KINDS` が `progress` を含み、`reportBlockSchema` の全種類を持つことが型か導出で保証されている（塊を1種類足して一覧に書き忘れたら型検査かテストが落ちる）
- `progress` の塊を含むレポートで `unknownBlockCount` が0になることをテストで確かめている
- `scripts/report-block-usage.ts` の集計の表が `progress` を既知の種類として持ち、0件でも行が出る
- `pnpm run check` が通る
- 調べて成り立たなければ（すでに直っているなど）、理由を書いて `dropped` で閉じてよい

## 背景

- `REPORT_BLOCK_KINDS`（`src/shared/report/report-block.ts`）は8種で `progress` が無い。`satisfies readonly ReportBlock["kind"][]` は部分集合しか検査しない
- そのため `parseReportSections` の `unknownBlockCount` に `progress` の塊が数えられ、2026-09-27 の記録112件のうち `progress` を含む3件すべてが「知らない種類で落とした塊1つ」と記録された
- 提案書 `docs/research/report-architecture.md` 7章の段0

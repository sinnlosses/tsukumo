## 目的

見本 SEIKA-4 の (d) 暦の日を押す と (e) まだ振り返っていない日を押す の場面を作り、過去の日記を読み返せるようにする。

## 完了条件

- 暦の日（と吹き出しの「日記帳で読む」）から見開きのモーダルが開く。左ページにしおり・この日に終えたこと・卒業や節目、右ページに縦書きの本文・漢数字の日付・曜日・灯り・署名と顔
- 前後の送りは**前後の日記のある日**へ飛び、目次は暦の応答の `diaryDates`（すべての日記のある日）を並べる（`docs/screen-design.md` 13.10「日記帳の見開き」の仮決め）。閉じられる（Esc と枠の外も）
- 書き足された日は段落の区切りが見える（同じ節の仮決め）
- まだ振り返っていない日は白紙のページと「この日を振り返る」が出て、押すとその日付で `reflect-achievement` が送られる（T-565）
- 書いたパックが一覧に無いときは、名前だけを出して顔を出さない（13.10「書いたパックが無いとき」）
- 漢数字の日付への変換は純粋関数でテストしてある。部品の振る舞いのテストがあり、`bun run check` が通る
- 目視確認（(d)(e) の場面と縦書きの見え方）を結果に書く

## 背景

- 見本は `docs/history/mockup/achievement-diary-2026-09-25/SEIKA-4d-OpenDay.dc.html` と `SEIKA-4e-OpenBlank.dc.html`
- モーダルの先例はセリフのログ（`src/browser/features/character-view/speech-log.tsx`、`src/browser/hooks/use-modal-dialog.ts`）
- 目視はモーダルの中まで測る（横スクロールの有無など）

## やること

**前提の調べ直し**: 委譲メモは「`diary-section.tsx` の頭の行に「日記帳で読む」がある」としていたが、
実物（`src/browser/features/achievement/diary-section.tsx` の `Header`）にはまだ無い。完了条件が
「暦の日（と吹き出しの「日記帳で読む」）から」開くことを求めているので、このタスクでボタンごと
追加する。それ以外の前提（`diary-section.tsx`・`lantern-calendar.tsx`・`use-achievement-calendar.ts`・
`diary-writer.ts`・`theme.css` の `--diary-gold-*` / `--font-serif`・`browser/domain/reveal/`）は
実物と一致していた。作業は要る。

**部品の割り方**: 開閉・見ている日・目次の開閉という「保つ」、`<dialog>` の DOM 同期と
`GET /achievement?date=` の取得という「外と同期」、漢数字・しおり・終えたこと・卒業と節目の
畳み込みという「畳む」の3種がそろうので `hooks/use-diary-book.ts` を切る。**ただし container /
presentational の3分割は採らない**——開く口が暦のマスと日記の区画の2箇所にまたがり、どちらも
`achievement-screen.tsx`（既存の container）から配る値を必要とするため、`useDiaryBook` は
`achievement-screen.tsx` から直接呼び、戻り値をそのまま渡す部品を `diary-book.tsx`
（`DiaryBook`。`presentational-` は付けない）に置く。これは `DiarySection` / `LanternCalendar` が
`useAchievement` の戻り値をそのまま受ける形と同じ（`docs/design.md` 2章の「外の世界に触るフックだけが
余分」の並びに近い）。漢数字変換の純関数（`kanjiNumeral` / `kanjiDateLabel` / `kanjiWeekdayLabel`）は
`use-diary-book.ts` を呼ぶ側（＝このフックだけ）が使うので、`domain/` は切らずフックの下に
`export function` で置き、そのままテストから import する（`docs/design.md` 2章「フックでない純関数は
まず hooks/use-<名前>.ts に入らないかを見る」）。

**1日ぶんの取り方**: 見開きの左右ページは、開いている日の分だけ `GET /achievement?date=<日付>` を
`useQuery`（`queryKey: ["achievement", date]`）で取る（`use-achievement.ts` の取得と同じ経路・
同じ応答形。日付が変わるたびに引き直す）。前後の日・目次は暦の `diaryDates`
（`use-achievement-calendar.ts` が既に持っている）を `achievement-screen.tsx` からそのまま渡す
（新しい経路は増やさない）。

**モーダルの先例の使い方**: `useModalDialog`（開閉を `<dialog>` の DOM へ写す）と、Esc は
`<dialog onClose>` で拾う・枠の外は `event.target === event.currentTarget` で判定する形を
`speech-log.tsx` からそのまま踏襲する。`<dialog>` は開閉に関わらず常に描画し、中身だけ
`open` で出し分ける（`ref` を安定させるため）。

**正典と実物・仮決めのすり合わせ（この場で判断し、実装を進める）**:

1. **目次のしおりのタスク ID は載せない。** 正典は「1行に日付・曜日・しおりのタスク ID」と
   書くが、`GET /achievement-calendar` の `diaryDates` はファイル名の一覧だけで中身を読まない
   （`src/server/adapter/diary.ts` の `listDiaryDates` のコメントに明記）。全件の日記ファイルを
   開いてしおりを拾うのはサーバ側の設計変更（I/O が増える）になるので、このタスクの範囲外とし、
   目次は日付・曜日だけにする。後でしおり付きにしたくなったら、`diaryDates` を文字列の配列から
   `{date, bookmarkTaskId}` の配列へ広げるタスクを別に切る
2. **開いた口の添え書き**は「灯りの暦から開きました」（暦経由）のほかに、正典が「など」としか
   書いていない「日記帳で読む」経由の文言を「この日の日記から開きました」と仮に決める
3. **書かれた日記でしおりが無い日**（`bookmark.kind === "none"`）の左ページは、成果の画面本体の
   `BookmarkSection` と同じくしおりの区画ごと省く（正典は白紙の日の置き換え文言しか書いておらず、
   「書けたがしおりが無い」ケースは明記が無いため）
4. **縦書き本文のオーバーフロー**は `overflow: auto` にする。正典は「ページの中を縦に
   スクロールさせる（仮）」と書くが、`writing-mode: vertical-rl` の自然な伸び先は列（横方向）
   なので、`overflow-y` だけに絞らず両軸を `auto` にして実際に必要な向きにブラウザの標準動作へ
   任せる。厳密な軸合わせは今後の「使いながら直す」に委ねる

上記4点はどれも「仮に決めたこと」の範囲内の判断で、実装を止めるほどの重さではないと判断した。

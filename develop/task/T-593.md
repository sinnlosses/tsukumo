## 目的

セッション駆動の15ファイル（契約・`sdk-*` の5つ・fake driver ほか）を `src/server/session-driver/{core,adapter}/` へ移す。

## 完了条件

- `docs/design.md` 2章「いまの `src/server/` から移す先（移行の対応表）」で段が「7」の15行が移っている。テストも同じ置き換えで移っている
- `SERVER_FEATURES` と `SERVER_FEATURE_IMPORTS` に `session-driver` が足されている（→ `chat` `diary` `report` `usage-review` `view-server`）
- `SDK_BOUNDARY_FILE` から古い位置（`server/adapter/sdk-`）の許可が外れている
- 移したパスを指す記述が直っている（`docs/design.md` 5章「session-driver.ts（core）と sdk-driver.ts（adapter）」「fake-driver.ts（adapter）」、`docs/architecture.md`、`docs/glossary.md` のパスを含む）
- `bun run check` が通る
- 着手時に対応表の前提が崩れていたら、表を直してから移す。移す意味が無くなっていたら `dropped` で閉じてよい

## 背景

- `sdk-context-usage.ts` と `claude-account.ts` と `plan.ts` はここへ入る。`driver-command.ts` は入らず `session/` へ行く（最後の段）。理由は `docs/history/decision.md`「design.md 2. 全体構成 / ディレクトリ（`src/server/` を機能で割った）」

## やること

着手前に段7の15行の前提を調べ直した結果、崩れは無かった（表どおりに移せる）:

- 15ファイルは表どおりの場所にすべて存在した（`src/server/adapter/` に `claude-account.ts` /
  `fake-driver.ts` / `sdk-context-usage.ts` / `sdk-driver.ts` / `sdk-session.ts` / `sdk-tool.ts`、
  `src/server/core/` に `pending-answer.ts` / `plan.ts` / `prompt-image-shelf.ts` /
  `sdk-message.ts` / `self-started-turn.ts` / `session-driver.ts` / `session-restore.ts` /
  `session-title.ts` / `visible-output-nudge.ts`）
- テストの有無（表の「あり」12本・「—」3本）も実物と一致した（`claude-account` /
  `sdk-session` / `session-driver` の3つだけテストが無い）
- import の辺も表・2章の記述どおりだった。`session-driver` の中の15ファイルが読むのは
  `chat`（`sdk-tool.ts` → `chat-memory-prompt.ts`、`sdk-driver.ts` → `chat-compact.ts`）・
  `diary`（`session-driver.ts` → `diary-tool.ts`、`sdk-driver.ts` → `diary.ts`/`diary-tool.ts`）・
  `report`（`fake-driver.ts`/`sdk-driver.ts`/`sdk-tool.ts` → `report-review.ts`/`report-tool.ts`、
  `session-restore.ts` → `report-review.ts`）・`usage-review`（`sdk-driver.ts`/`sdk-tool.ts` →
  `usage-review-tool.ts`）の4つだけ。`session-restore.ts` → `port-resolution.ts` は下の「view-server
  はまだ…」のとおり機能の表の対象外のまま
- **表・完了条件に無い追加の発見**: `context-usage/core/context-usage.ts` が
  `../../core/session-driver.ts` を import している。移すまでは `session-driver.ts` が共有の箱に
  居たので機能どうしの辺として検査されていなかったが、移すと `context-usage → session-driver` の
  機能どうしの辺になる。2章の辺の表にはもとからこの組が載っている（「`context-usage` |
  `session-driver` | core → core（駆動の契約）」）ので、`SERVER_FEATURE_IMPORTS` の
  `context-usage` の行にも `session-driver` を足した（`chat` / `system-prompt` の2行だけでは
  `bun run check` の「機能どうしの import」検査が落ちる）

## 注意

- `view-server` はまだ共有の箱の場所に居るので、`session-restore.ts` → `port-resolution.ts` の辺は機能の表の対象外のまま通る
- `SERVER_FEATURE_IMPORTS` の `chat` と `system-prompt` の行は、`session-driver` がまだ機能でなかったので `session-driver` への辺を足さずにある（`chat` の行にコメントあり）。`session-driver` を機能にしたら、2章の辺の表どおりにこの2行にも `session-driver` を足す

## 結果

- 段7の15ファイル（`session-driver/`）とそのテストを移し、`SERVER_FEATURES` に `session-driver` を足した。辺は表どおり `chat` `diary` `report` `usage-review` へ（`view-server` はまだ機能でないので除き、コメントを残した）。`chat`・`system-prompt`・`context-usage` の行に `session-driver` を足した（`context-usage` は表にある組で、移したことで初めて機能どうしの辺になった）。`SDK_BOUNDARY_FILE` から古い位置の許可を外した
- 検証コマンド: 2663 pass / 0 fail、`scripts/find-stray-reference.ts` 0件
- 振り返り: 兆候なし

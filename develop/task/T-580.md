## 目的

設計を書くタスクと、その設計に従う実装タスクを同時に登録したときに、後段の本文が設計の結論を先取りして書かれ、設計の着地後に何件も書き直しになるのをなくす。

## 完了条件

- claude-skills の `plan-tasks/SKILL.md` 手順3「方針決めが要るものは前段のタスクに切り出して」の後ろに、「前段が設計を書くなら、後段の `## 背景` には設計の結論を先取りして書かず、前段の完了条件に後段の本文の追随を入れる」旨が入っている（言い回しは合わせてよい）
- claude-skills の `./check.sh` が通り、変更が claude-skills の `main` に入っている
- tsukumo の `bun run check` が通る

## 背景

2026-09-25 の T-561・T-562 の振り返りで見つけたもの（`docs/history/direction.md` の 2026-09-25「振り返りのドラフト3件」）。T-561〜T-568 を1コミット（+1041行）で一度に登録し、T-561 が設計を書いたあとに T-562〜T-568 の7件を +36/-27 で書き直した（`a34a98a5`）。T-561 の結果の節にも「後続の本文は未反映」とある。T-569〜T-575（T-573 が出し方をデザインし、T-574 がそれに従って描く）も同じ形で登録されている。

## やること

`claude-skills/skills/plan-tasks/SKILL.md` 手順3を読み直した。「方針決めが要るものは前段のタスクに
切り出して `dependencies` で後ろに置く」はすでにあるが、切り出したあとの**後段タスクの本文の書き方**
（設計の結論を先取りしない）と、**前段側の完了条件に後段の追随を入れる**旨はまだ無い。同じ趣旨は
手順4「`## やること` は書かない」（別の話題：着手直後に書く運用）にも無い。ほかの節（手順1〜2、5〜7、
完了報告のフォーマット）にも重複は無い。→ `dropped` にせず作業する。

手順3の「方針決めが要るものは前段のタスクに切り出して `dependencies` で後ろに置く。」の直後に、
以下の趣旨の1文（言い回しは実装時に調整してよい）を足す:

> 前段が設計を書くタスクなら、後段の `## 背景` には設計の結論を先取りして書かず、前段の
> `## 完了条件` に「後段（対象のタスクIDの範囲）の本文を設計の結論に合わせて直す」を足す。

その他:

- 挿入は手順3の当該文の直後（「1タスクは1コミットで説明が付く大きさに。」より前）。
- `./check.sh` を通し、claude-skills 側でコミット（末尾 `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`）。
- `git worktree add` で別作業ツリーを切って作業し、本体では checkout しない。

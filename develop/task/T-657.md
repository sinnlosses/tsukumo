## 目的

T-656 で決めた形の E2E を動かし、成果物（DOM の構造のスナップショットと WebSocket のメッセージ列）で判定する1本目を `bun run check` に入れる。後続のシナリオが同じ土台に乗れるようにする。

## 完了条件

- `docs/design.md` 10章「E2E の走らせ方」「E2E の成果物と再現」のとおりの足場が `test/e2e/` にある（起こす・開く・成果物を書く・比べる・後始末。シナリオはそれを呼ぶだけ）
- 疑似セッションの場面 `report-tool` でターンの流れ（依頼 → ツール → report → 締めの speak）を通す E2E が1本あり、`test/e2e/expected/` の期待値（DOM の構造とメッセージの列）と比べて判定する。スクリーンショットは `/tmp/tsukumo-e2e/` に出る。同じ入力で2回走らせて成果物が一致する
- 時計の固定: `TSUKUMO_FIXED_CLOCK` が `src/server/core/config.ts` にあり、サーバで `Temporal.Now` を読むのが `src/server/adapter/local-time.ts` だけになっている（`src/session-start.ts` の3箇所を移す）。サーバの `local-time.ts` とブラウザの `src/browser/utils/clock.ts` の外に `Temporal.Now` が無いことを `test/architecture.test.ts` が縛っている
- `package.json` に `test:e2e`（`bun run build` のあと `test/e2e/` を走らせる）と `test:e2e:update` があり、`test` は `test/e2e/` を外し、`check` の最後の段が `test:e2e` になっている。`CLAUDE.md`「よく使うコマンド」と、正典の「足場はまだ無い」の断り書き（`docs/design.md` 10章・`CLAUDE.md`「テスト方針」・`docs/architecture.md`「手で確かめること」）が実物に合っている
- Chrome が無いときに E2E の段が前提不足の文言で落ちることを確かめている（飛ばさない）
- `bun run check` が E2E を含んで通る。E2E の段の所要時間を結果に書く
- 調べて前提が成り立たなければ、理由を書いて `dropped` で閉じてよい

## 背景

- 設計の正典は `docs/design.md` 10章「E2E の走らせ方」「E2E の成果物と再現」（T-656 が書いた）。ここに書いていない判断が要ったら、先に正典を直す
- 実測（2026-09-26）: 一時の cwd とホームで fake を起こすと URL まで約 110ms。`page.clock.install` は `Temporal.Now` を差し替えない（`addInitScript` で `Temporal.Now.instant()` を `Date.now()` に従わせる）。`newContext({ timezoneId, reducedMotion })` は効く。`bun test` はディレクトリ指定で `*.test.ts` しか拾わない
- 起こし方の手本: `scripts/capture-catalog.ts`（`TSUKUMO_DRIVER=fake` と `TSUKUMO_FAKE_SCENE` で場面を名指しして1件ずつ起こす）。ブラウザは `playwright-core` の `chromium`（`channel: "chrome"`）
- 疑似セッション: `src/server/session-driver/adapter/fake-driver.ts` と `test/fixture/fake-session.json`

## やること

前提を調べ直した結果（2026-09-26）: 前提は成り立つ。`src/session-start.ts` の `Temporal.Now` は3箇所（`now` / 振り返りの書き手の `now` / 訪問の台本の `localTime`）、`src/server/adapter/local-time.ts` と `src/browser/utils/clock.ts` の外には無い。`TSUKUMO_FIXED_CLOCK` は未定義。`test/e2e/` は無く、`package.json` の `check` は `bun test --isolate` で終わる。`playwright-core` は devDependencies にある。場面 `report-tool` は 8.4 秒で `turn-finished` まで流れる。

1つだけ設計が見落としている点がある: **名指しした場面は起こした直後（`opening` の終わり＝200ms）から流れ始める**ので、ページが繋がるより前に届いたイベントは `hello` の状態へ畳まれ、どこまでが `events` に出るかが走らせるたびに変わる（メッセージの列が一致しない）。`opening` の 200ms の発話も同じ。時間で待たずに機械で揃えるため、**fake driver は `opening` と名指しの場面を最初のビューが繋がってから流す**ようにする（`src/session-start.ts` が `subscribe` を包んで最初の購読を知らせる。起こし直しの代は既に繋がっているので待たない）。正典（`docs/design.md` 5章の fake driver の節・10章「E2E の走らせ方」）もそれに合わせて直す。

1. 時計: `src/server/core/config.ts` に `TSUKUMO_FIXED_CLOCK`（`fixedClock`）、`local-time.ts` にサーバの時計を作る関数を置き、`session-start.ts` の3箇所をそれへ移す。`test/architecture.test.ts` に `Temporal.Now` の置き場の検査を足す
2. fake driver の「最初のビューを待つ」を足し、`fake-driver.test.ts` を合わせる。`scripts/capture-catalog.ts` の待ちを見直す
3. `test/e2e/` に足場（起こす・開く・成果物を書く・比べる・後始末）と `report-tool` のシナリオ、`test/e2e/expected/` の期待値
4. `package.json`（`test` から `test/e2e/` を外す・`test:e2e`・`test:e2e:update`・`check` の最後の段）、`CLAUDE.md`・`docs/design.md` 10章・`docs/architecture.md`「手で確かめること」の「足場はまだ無い」の断り書き
5. Chrome が無いときの前提不足の文言を確かめる（`channel` を存在しない実行ファイルに向けるなどで）。2回走らせて成果物が一致することを確かめる

## 注意

- T-632（`bun test --isolate` がときどき 100% CPU のまま終わらない）が未解決。E2E を足して症状が増えたら、E2E の側の後始末（サーバとブラウザを閉じる）を先に疑う
- 成果物に入るのは疑似セッションの手書きの会話だけにする（「会話内容の扱い」）。起動トークンと絶対パスを期待値に入れない
- `bunfig.toml` の preload（happy-dom の DOM のグローバル）が `playwright-core` と干渉したら、E2E の段だけ preload を外す形を作り、正典にその形を書き足す

## 結果

- 検証コマンド: 単体 2723 pass / 0 fail（+3）、E2E 1 pass / 0 fail（段は約10秒）。2回走らせた成果物が一致、Chrome 不在時は前提不足で落ちることを確認
- 設計の修正: fake driver は最初のビューが繋がってから場面を流す（接続前のイベントが hello に畳まれ列が揃わないため）。期待値は整形の対象外。日付キー（todayLocalDateKey）は凍らせていない
- 振り返り: 兆候なし

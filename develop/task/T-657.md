## 目的

T-656 で決めた形の E2E を動かし、成果物（DOM の構造のスナップショットと WebSocket のメッセージ列）で判定する1本目を `bun run check` に入れる。後続のシナリオが同じ土台に乗れるようにする。

## 完了条件

- `docs/design.md` 10章「E2E の走らせ方」「E2E の成果物と再現」のとおりの足場が `test/e2e/` にある（起こす・開く・成果物を書く・比べる・後始末。シナリオはそれを呼ぶだけ）
- 疑似セッションの場面 `report-tool` でターンの流れ（依頼 → ツール → report → 締めの speak）を通す E2E が1本あり、`test/e2e/expected/` の期待値（DOM の構造とメッセージの列）と比べて判定する。スクリーンショットは `/tmp/tsukumo-e2e/` に出る。同じ入力で2回走らせて成果物が一致する
- 時計の固定: `TSUKUMO_FIXED_CLOCK` が `src/server/core/config.ts` にあり、サーバで `Temporal.Now` を読むのが `src/server/adapter/local-time.ts` だけになっている（`src/session-start.ts` の3箇所を移す）。サーバの `local-time.ts` とブラウザの `src/browser/utils/clock.ts` の外に `Temporal.Now` が無いことを `test/architecture.test.ts` が縛っている
- `package.json` に `test:e2e`（`bun run build` のあと `test/e2e/` を走らせる）と `test:e2e:update` があり、`test` は `test/e2e/` を外し、`check` の最後の段が `test:e2e` になっている。`CLAUDE.md`「よく使うコマンド」と、正典の「足場はまだ無い」の断り書き（`docs/design.md` 10章・`CLAUDE.md`「テスト方針」・`docs/architecture.md`「手で確かめること」）が実物に合っている
- Chrome が無いときに E2E の段が前提不足の文言で落ちることを確かめている（飛ばさない）
- `bun run check` が E2E を含んで通る。E2E の段の所要時間を結果に書く
- 調べて前提が成り立たなければ、理由を書いて `dropped` で閉じてよい

## 背景

- 設計の正典は `docs/design.md` 10章「E2E の走らせ方」「E2E の成果物と再現」（T-656 が書いた）。ここに書いていない判断が要ったら、先に正典を直す
- 実測（2026-09-26）: 一時の cwd とホームで fake を起こすと URL まで約 110ms。`page.clock.install` は `Temporal.Now` を差し替えない（`addInitScript` で `Temporal.Now.instant()` を `Date.now()` に従わせる）。`newContext({ timezoneId, reducedMotion })` は効く。`bun test` はディレクトリ指定で `*.test.ts` しか拾わない
- 起こし方の手本: `scripts/capture-catalog.ts`（`TSUKUMO_DRIVER=fake` と `TSUKUMO_FAKE_SCENE` で場面を名指しして1件ずつ起こす）。ブラウザは `playwright-core` の `chromium`（`channel: "chrome"`）
- 疑似セッション: `src/server/session-driver/adapter/fake-driver.ts` と `test/fixture/fake-session.json`

- T-632（`bun test --isolate` がときどき 100% CPU のまま終わらない）が未解決。E2E を足して症状が増えたら、E2E の側の後始末（サーバとブラウザを閉じる）を先に疑う

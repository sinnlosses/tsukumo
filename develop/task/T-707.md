## 目的

セッション一覧に同じ題が並ばないようにする。`/clear` のあとに始まったセッションでも、`report` の
`title` で渡した題がそのセッションの見出しになるようにする。

## 完了条件

- `/clear` の合図（`conversation-cleared`）を受けたあと、そのとき SDK 側にある `customTitle`
  （本体が前のセッションから書き写した題）を tsukumo が書いたものとして扱い、次の `report` の題で
  上書きできる
- 利用者が `/rename` で付けた題を上書きしない、というこれまでの振る舞いは変わらない
- 上の2点を守る単体テストがある（`decideSessionTitle` の純粋な判断で書けるならそこで）
- `bun run check` が通る
- 過去のセッションに残っている題は直さなくてよい

## 背景

- 本体（Claude Code）は `/clear` のたびに、前のセッションの `customTitle` を新しいセッションの
  transcript の1行目（`{"type":"custom-title",...}`）へ書き写す。直後の行は `SessionStart:clear`。
  2026-09-26 に tsukumo-task・tsukumo-3 の transcript 約10件で、全件が 1行目から
  「T-581 components の3段設計」になっているのを確かめた（大もとは tsukumo-2 のセッション
  `ff5b7d08` が `report` の `title` で書いたもの）
- `src/server/session-driver/core/session-title.ts` の `decideSessionTitle` は、現在値
  （`customTitle`）が `undefined` でも `state.lastWritten` でもなければ `skip` する（利用者の `/rename`
  とみなす）。書き写された題は tsukumo のこのプロセスが書いたものではないので `lastWritten` と合わず、
  以後その セッションで渡した題（例: b23b772c では8種類）が1度も書かれない
- 題を書くのは `src/server/session-driver/adapter/sdk-session.ts` の `createSessionTitleWriter`
  （状態 `SessionTitleState` を閉じ込めている）。`/clear` の合図は
  `src/server/session-driver/adapter/sdk-driver.ts` の `relayMessages` が
  `event.kind === "conversation-cleared"` で受けている（いまは雑談の写しの印を戻すだけ）

## 決まっていること（蒸し返さない）

- 直し方は「`/clear` の合図を受けたときに、その時点の `customTitle` を `lastWritten` として覚える」
  （ユーザーが 2026-09-26 に承認）。セッションIDが変わったら状態を戻す案は採らない

## やること

- 実物で確かめた結果、背景の主張（ファイル・行番号・`decideSessionTitle` の現在の判断）は
  現在のコードと一致していた（2026-09-27 時点）
- `src/server/session-driver/core/session-title.ts`
  - `SessionTitleState` に `adoptCurrentTitleNext: boolean` を足す（`INITIAL_SESSION_TITLE_STATE`
    も追随）
  - `/clear` の合図を状態へ持ち越す純粋関数 `noteConversationCleared` を足す
  - `decideSessionTitle` は、`state.adoptCurrentTitleNext` が立っていれば現在値
    （`currentTitle`）を「tsukumo が最後に書いたもの」とみなして通す
- `src/server/session-driver/adapter/sdk-session.ts`
  - `SessionTitleWriter` に `noteConversationCleared` を足し、`createSessionTitleWriter` の
    閉じ込めた状態を `noteConversationCleared` で更新できるようにする
  - `writeTitle` は `decideSessionTitle` を呼ぶたびに（書く/書かないに関わらず）
    `adoptCurrentTitleNext` を消費し、`lastWritten` は書けたときだけ進める
- `src/server/session-driver/adapter/sdk-driver.ts`
  - `relayMessages` の `event.kind === "conversation-cleared"` の分岐で
    `titleWriter.noteConversationCleared()` を呼ぶ
- `test/server/session-driver/core/session-title.test.ts`
  - 既存の `SessionTitleState` リテラルに `adoptCurrentTitleNext: false` を足す
  - 完了条件の2点（合図のあと書き写された題を上書きできる／`/rename` は変わらず上書きしない）を
    守る単体テストを `decideSessionTitle` の純粋な判断で足す

## 注意

- 合図を受けた時点では新しいセッションIDがまだ分からない・`customTitle` がまだ書かれていない、
  ということがありうる。そのときは「次に題を書くときに、合図のあとの最初の1回だけは現在値を
  tsukumo のものとみなす」のように、合図を状態として持ち越す形でもよい（機械的に判定できる形を選ぶ）
- tsukumo を起こし直して題の付いたセッションを resume したときも `lastWritten` は `undefined` に戻り、
  同じく上書きできなくなる。この件は範囲外だが、直し方が自然に両方を覆うなら含めてよい
- 調べて本体が題を書き写していない（前提が成り立たない）と分かったら `dropped` で閉じてよい

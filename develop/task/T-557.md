## 目的

`task` を、`python3 <フルパス>/task.py` を変数に入れずに `task status` のように打てるコマンドにする。zsh で変数に入れた呼び出しが単語に分かれずに空振りし、`;` でつないだ後続の `git commit` だけが走る事故を、手の注意ではなく仕組みで防ぐ。

## 完了条件

- claude-skills に `task` の入口（`task.py` を呼ぶだけのラッパー。例: `bin/task`）があり、どのディレクトリから呼んでも `task status` がそのリポジトリの一覧を出す
- PATH への置き方（どこに symlink を張るか、外すときのコマンド）が claude-skills の README か `task-workflow` の `WORKFLOW.md` に書いてある。**symlink を張るのは人**（グローバルなツールの導入にあたる。tsukumo の `bun link` と同じ扱い）で、このタスクでは張らない
- 共通スキル（`next-task`・`plan-tasks`・`retrospect`・`list-tasks`・`setup-tasks` と `WORKFLOW.md`）の「以下の `task` は … の略」の説明が、「PATH に `task` があればそれを、無ければフルパスを打つ。**どちらも変数に入れない**」になっている
- claude-skills の `./check.sh` が通り、変更が claude-skills の `main` に入っている
- 完了報告で、利用者に張るコマンドを1行で伝える

## 背景

2026-09-24 の振り返り（`develop/retrospective.md` の `f1adaf96`..`7ef5a7ba`）で見つけたもの。`T="python3 …/task.py"; $T …` が zsh で「no such file」になった件が2回目になった（1回目は T-537 で `task done` だけ落ちて `git commit` が走り、`todo` のままのコミットができた。2回目は T-533 の `task status` で害は無かった）。1回目のときに「2回目が起きたら仕組みで防ぐ」と決めていた。いまの PATH には `task` という名のコマンドは無い（`which task` が not found。2026-09-24 時点）。

## やること

前提を確認した（2026-09-25 時点）。`which task` は not found のままで前提は崩れていない。
`task.py` は `~/ghq/github.com/sinnlosses/claude-skills/skills/task-workflow/scripts/task.py`
にある。「以下の `task` は…の略」の文言は `next-task`・`plan-tasks` の2スキルにしか無く、
`list-tasks`・`retrospect`・`setup-tasks`・`task-workflow/SKILL.md` は `python3 …/task.py` を
直接インラインで呼んでいた（説明なし）。正典 `WORKFLOW.md`「`task` コマンドの参照」には
「PATH には入れない」と明記されていた。

1. `claude-skills` に `bin/task`（`task.py` の実体を `os.path.realpath(__file__)` で探して呼ぶだけの
   Python の薄い入口。symlink 越しでも正しく動く）を追加する
2. `WORKFLOW.md`「`task` コマンドの参照」を正典として書き換え、「PATH に `task` があればそれを、
   無ければフルパスを打つ。どちらも変数に入れない」にし、symlink の張り方・外し方
   （`~/.local/bin/task` への `ln -s` / `rm`）を添える
3. `next-task`・`plan-tasks`・`list-tasks`・`retrospect`・`setup-tasks` の各 SKILL.md と
   `task-workflow/SKILL.md`・`task.py` の docstring・`docs/task-workflow-redesign.md` の該当箇所を
   同じ文言に揃える
4. `./check.sh` を通し、claude-skills の `main` へ ff-only で入れる

## 注意

- 作業するのは claude-skills のリポジトリ（`~/ghq/github.com/sinnlosses/claude-skills`。`~/.claude/skills/` の各スキルはそこへの symlink で、書き換えは全プロジェクトへ即座に効く）。**着手時に `git -C ~/ghq/github.com/sinnlosses/claude-skills status --short` が空でなければ止めて預ける**
- claude-skills の枝は本体の作業ツリーで checkout せず、`git worktree add` で別の作業ツリーを切ってそこで作業する（本体で切り替えると全プロジェクトのスキルが変わる）。枝の名前は `feature/tsukumo-<このタスクのID>`。検証コマンドは claude-skills の `CLAUDE.md` に従う（`./check.sh`）
- コミットは claude-skills の側に入る。tsukumo のタスクの結果には claude-skills のコミットハッシュを書く

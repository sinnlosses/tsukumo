## 目的

`report` の塊の種類を実際の使われ方の数で増減できるように、使われ方を記録して集計する道を作る（`docs/research/report-block.md` 6章・11章の3段目）。

## 完了条件

- `report` を描くたびに、塊の種類ごとの数と、逃げ道の中に出た記法の種類ごとの数だけを `$TSUKUMO_HOME` に記録する（中身は持たない）。知らない種類の塊を境界で落としたときは、その数も記録する
- 記録を集計するスクリプトを置く（「逃げ道の中の記法 × レポート数」と「塊の種類 × レポート数」）
- 足す基準（逃げ道の中の同じ記法が直近2週間のレポートの3%以上）と外す基準（塊の種類が直近4週間で0回）を `docs/display.md` に書く
- `bun run check` が通る

## 背景

- 記録の前例は `token-usage` と `context-usage`（`$TSUKUMO_HOME` の下）

## やること

前提を洗い直した結果、T-705 で `report` は `sections`（節と塊。`src/shared/report-block.ts`）へ
切り替え済みで、境界の緩い検証（`parseReportSections`）が崩れた塊・知らない種類の塊を落としている
（`src/server/session-driver/core/sdk-message.ts` の `reportEvents`）。逃げ道の中の記法の検出は
`src/server/report/core/report-violation.ts` の `hasNotation` / `splitFences` にすでにあり、
差し戻し（`reportViolations`）が使っている。前提は崩れておらず、作業は要る。

- `src/shared/report-block.ts`: `parseReportSections` を `{ sections, unknownBlockCount }` を返す形に
  変え、知らない種類（`REPORT_BLOCK_KINDS` に無い `kind`）で落とした塊の数を数える
- `src/shared/session-event.ts`: `report` イベントに `unknownBlockCount: number` を足す（画面には
  出さず、使われ方の記録だけが読む）
- `src/server/session-driver/core/sdk-message.ts`: `reportEvents` が `unknownBlockCount` を運ぶ
- `src/server/report/core/report-violation.ts`: 逃げ道の中の記法の検出を `notationsInSections`
  として切り出し、`MARKDOWN_NOTATIONS` を export する（差し戻しの判定と使われ方の記録の両方が使う）
- `src/server/report/core/report-usage.ts`（新規）: 描いた `report` の `SessionEvent` から
  記録1行ぶんの中身（塊の種類の集合・逃げ道の記法の集合・`unknownBlockCount`）を作る純関数と、
  書き込み口の契約 `ReportUsageLog`
- `src/shared/report-usage-record.ts`（新規）・`src/server/report/adapter/report-usage-log.ts`
  （新規）: 記録の行の形と、`~/.tsukumo/report-usage/<YYYY-MM-DD>.jsonl` への書き込み
  （`token-usage-log.ts` / `context-usage-log.ts` と同じ形）
- `src/server/session/core/session-manager.ts`: `SessionManagerOptions` に `reportUsageLog` を足し、
  駆動由来（`origin === "driver"`）の描いた `report`（差し戻されなかったものだけが届く。
  `ReportReview.pass`）でセッションIDが分かっているときに1行書く
- `src/session-start.ts`: `createReportUsageLog()` を起こして `session-manager` へ渡す（配線）
- `test/architecture.test.ts` と `docs/design.md` 2章: `session` が `report` を import してよい辺を足す
  （`session-manager.ts` が `report-usage.ts` を読むため）
- `scripts/report-block-usage.ts`（新規）: 記録を読み、「塊の種類 × レポート数」「逃げ道の中の
  記法 × レポート数」を出す（`--days` で期間を選べる。既定28日）
- `docs/display.md` 4.2 に節「塊を足す・外す基準」を足す（足す基準3%・外す基準0回・記録と
  集計スクリプトの置き場）
- 既存テストのうち `SessionEvent` の `report` を直接組み立てているもの（`sdk-message.test.ts` ・
  `session-restore.test.ts` ・`fake-driver.test.ts` ・`report-review.test.ts` ・`report-tool.test.ts` ・
  `session-state.test.ts` ・`main-view.test.ts` ・`turn-step.test.ts` ・`main-view-turn.test.ts`）に
  `unknownBlockCount` を足す。`session-manager.test.ts` は `createSessionManager` の呼び出し全箇所に
  `reportUsageLog` を渡す
- 新規テスト: `report-usage.ts`（純関数）・`report-usage-log.ts`（jsonl の読み書き）・
  `session-manager.test.ts` に「report の塊の使われ方の記録」の節を足す

## 注意

- 記録に会話の中身を入れない。数だけにする（`docs/coding-standards.md`「会話内容の扱い」）

## 結果

- 検証コマンド: 2713 pass / 0 fail（+8）、E2E 24 pass / 0 fail
- 受け入れで直したこと: 新規ファイルのコメントを刈り込み、`parseReportSections` の `let` の積み上げを畳み、集計スクリプトに割合の列を足した
- 気になった点: 知らない種類として数えるのは `kind` が未知の塊だけで、既知の種類の値が崩れた塊は数えない
- 振り返り: 受け入れのときにメインが直したもの・同じファイルを3回以上直した・ツールのエラー（ドラフト 1件）

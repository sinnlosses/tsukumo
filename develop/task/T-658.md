## 目的

会話画面の複雑な機能を、T-657 の土台に乗った E2E で確かめる。後段の監査で、ここが守る振る舞いの単体テストを消せるようにする。

## 完了条件

- `docs/design.md` 10章「E2E のシナリオの一覧」で担当が「会話」の行ごとに E2E が1本ずつある: 入力欄から送る、speak → キャラビューの吹き出し、report → メインビュー（記法・差し戻し・整え）、途中の発話と流れる本文、許可のモーダル、質問（単数・複数・プレビュー）、続きのターン
- 見たい状態が `class` にしか出ていなければ `data-*` か `aria-*` に出している（`docs/coding-standards.md`「DOM の構造と画面の流れは E2E、見た目は目視」）
- 各 E2E が、どの振る舞いを守っているかをテストの名前で言っている（後段の監査が「どのシナリオが守るか」を書くときに引く）
- 台本に場面が足りなければ `test/fixture/fake-session.json` に足している（手書きの架空の会話だけ）
- `bun run check` が通る

## 背景

- 使える場面: `fake-session.json` の `report`・`long-report`・`permission`・`question-multi`・`question-pair`・`question-long`・`question-preview`・`notation`・`narration` など
- シナリオと場面の対応は `docs/design.md` 10章「E2E のシナリオの一覧」に従う（食い違ったらそちらを直す）
- `docs/architecture.md`「手で確かめること」に、質問の場面を Playwright で自動操作すると `turnInProgress` が解けないまま残ることがある、という既知の症状がある。踏んだら条件を書き足し、E2E の側の待ち方（押す前に何のイベントを待つか）を先に疑う

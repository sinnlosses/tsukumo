## 目的

サイドバー「セッション情報」のコンテキストの行を、ユーザーが用意した見本
（`/Users/sinnlos/Downloads/サイドバーのコンテキスト表示-html/SB-Context.dc.html` の「案1」）の形に
作り直す。いまは「コンテキスト」の文字ごとリンクを張った1行で、割合と自動圧縮までの残りが読めない。

## 完了条件

- リンクは右端の `›`（ホバー中は「詳しく ›」）だけ。「コンテキスト」のラベル・割合・量・棒はリンクにしない（ホバーで下線を出さない）
- 1段目に「コンテキスト」のラベル・大きめの割合（例 `28%`）・`使っている量 / 窓の大きさ`・右端の `›`、
  2段目に棒、3段目に「自動圧縮まで あと N」が出る
- ホバー（とキーボードのフォーカス）で札の背景と枠が浮き、右端が「詳しく ›」になる
- 割合が 70% 以上のときは割合の数字と棒を警告の色にし、3段目を「そろそろ区切りどき。自動圧縮まで あと N」にする
- リンク（`›`）の `aria-label` で「コンテキスト N% 使用。トークン消費の画面で詳しく見る」と読める
- 取得中・取れないときも札の高さが変わらない（いまの約束を保つ）
- `docs/screen-design.md` の「#### 使用量の行」を新しい形に書き直す
- `bun run check` が通る。加えて `bun run build` のあと実画面で、通常・ホバー・70% 以上（値を差し替えて）の3つを目視し、何が見えたかをタスクの結果に書く

## やること

見本 HTML（`~/Downloads/サイドバーのコンテキスト表示-html/SB-Context.dc.html`）は現存していた。
「案1」3種（通常・ホバー・残りが少ないとき）を確認した。**見本は行全体を `<a>` にしているが、
本文「決まっていること」でユーザーが訂正した通り（右端の `›` だけをリンクにする）に従い、見本の
markup をそのまま写さない。**

- `src/browser/features/sidebar/context-usage-row.tsx` を書き直す。外枠は `<a>` ではなく `<div>`
  にし、中に3段（1段目: ラベル・割合・量・右端の `›` を包む `<a href="#token-usage">`、2段目: 棒、
  3段目: 自動圧縮までの残り）を持たせる
- **高さを揺らさないため、pending/unavailable でも1段目の割合・量の場所に何かしらのテキストを
  出す**（割合は "—"、量の場所に "取得中…" / "いまのコンテキストは取れていない" を出す）。3段目は
  pending/unavailable のとき空け（` ` で高さだけ保つ）、ready のときだけ「自動圧縮まで
  あと N」（70%以上は「そろそろ区切りどき。自動圧縮まで あと N」）を出す
- 警告の境目 70% は `context-usage-row.tsx` 内だけの定数にする。**`context-usage-card.tsx`
  （トークン消費の画面の札）には今回手を入れない**——札はまだ警告色の仕組みを持っておらず、
  読み手が2つ目にならない（docs/design.md 2章「上げる引き金は「2つ目の読み手が出たとき」」）ため
- ホバーで浮く背景・枠は `--surface-raised`（読む面の上に浮く塊の地。profile-card などと同じ
  語彙）と `--rule` を使う。警告時の背景・枠・文字・棒は `--state-warn` からの `color-mix` 導出
  にする（見本の16進は写さない。`.sidebar-footer` 内の `.profile-card` が同じ手口で
  `--accent` を導出している）
- 割合・量は等幅にする（見本の IBM Plex Mono に対応する `--font-mono` を使う。数字が主の場所は
  `token-usage.module.css` の `.usage-card-value` と同じ考え方）。割合は `--font-body`
  （15px 相当）、量と3段目は `--font-label`（11px）
- `aria-label` は ready のとき「コンテキスト N% 使用。トークン消費の画面で詳しく見る」、
  pending は「コンテキスト 取得中。トークン消費の画面で詳しく見る」、unavailable は
  「コンテキストは取れていない。トークン消費の画面で詳しく見る」にする
- `sidebar.module.css` の `.context-usage-row` 一式を書き直し、`docs/screen-design.md`
  「#### 使用量の行」も新しい形に合わせて直す
- `test/browser/features/sidebar/context-usage-row.test.tsx` に、リンクが `›` だけであること
  （`<a>` は1つだけで、ラベル・割合・量・棒はその外にある）・`aria-label` の文言・70%以上の
  警告文言のテストを足す

## 注意

- 札のホバーで「詳しく ›」に変わるのか、`›` のホバーで変わるのかは見本で確かめ、見本に無ければ札のホバーで変える
- 警告の境目 70% は見本の説明文から取った値。定数を1つ置き、札（`context-usage-card.tsx`）と揃えるかは着手時に見て決めてよい
- 取得中・取れないときの3段目の扱い（空けて高さを保つか、一言を入れるか）は着手時に決めてタスクの結果に書く
- 見本のファイルはリポジトリの外（`~/Downloads`）にある。消えていたら、この本文の寸法と色だけで進めてよい

## 結果

- 検証コマンド: 2298 pass / 0 fail（+3）
- 目視（fake driver、headless Chrome 1400x900）: 通常は 61%・122k / 200k・棒・「自動圧縮まで あと 33.5k」で下線なし。ホバーとフォーカスで地と枠が浮き右端が「詳しく ›」。応答を 75% に差し替えると割合・棒・3段目が黄色系になり「そろそろ区切りどき。」が付く。札の高さは取得中・取れない・通常・警告のどれでも 83.5px
- 決めたこと: ホバーの起点は札全体（`:hover` と `:focus-within`）。70% の定数は行だけが持つ（札には警告色が無いため）。取得中・取れないときは割合を「—」、量の場所に一言、3段目は空けて高さを保つ

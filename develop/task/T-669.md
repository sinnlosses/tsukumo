## 完了条件

- `test/browser/stores/` を監査し、E2E が守っている振る舞いだけを確かめている単体テストを消している。消した1件ごとに、どの E2E が守るかをタスクの結果に書いている（テストの跡にコメントは残さない）

- 消したあと、カバレッジ（閾値は置かない）で守られなくなった分岐が無いかを見て、あれば E2E か単体テストで埋めるか、埋めない理由を「埋めないと決めた穴」に書いている

- `bun run check` が通る

## やること

`test/browser/stores/` の6ファイルを1つずつ、対応する E2E（`test/e2e/*.test.ts` と
`test/fixture/fake-session.json`）と突き合わせた。分かったこと:

- `test/e2e/question-ask.test.ts` の冒頭コメントに明記されている既知の制約として、**E2E は
  質問に自動で答えない**（`docs/architecture.md`「手で確かめること」に、質問の場面を Playwright で
  自動操作すると `turnInProgress` が解けないまま残ることがある、とある）。E2E が撮るのは答え待ちの
  札が出た時点の DOM だけで、選ぶ・答える・戻るの操作は一切流れない
- `test/e2e/` は `location.hash` を一度も直接操作しない（`grep` で0件）。画面遷移・パック選択・
  成果の日付選択・見ているターンの選択はすべて hash 経由だが、E2E はシナリオ名の指定で場面を
  開くだけで hash を書き換えない
- E2E は `settleAndMatch` で `turn-finished` などのイベントを待った**あとの静止した DOM**しか
  撮らない。ターンが `running` の途中・書きかけ（`partialUtterance`）が残っている途中のような
  過渡状態は、どのシナリオでも撮られない

これにより6ファイルは次のとおり:

- `location-hash.test.ts`: hash の parse/format の境界検証。E2E が hash を一切操作しないため、
  全172行が唯一の持ち主。消すものなし
- `screen.test.ts`: 同上（`useScreen`・`navigateTo`・パック/成果日の選択は hash 経由で、E2E は
  一度もこの経路を通らない）。消すものなし
- `session.test.tsx`: 購読の粒度（`Profiler` で描き直し回数を数える）と、サーバとの版の食い違い
  （`hello` の `protocolVersion` 不一致）。どちらも DOM の構造やメッセージの列では観測できない
  （version 不一致は `docs/design.md` 10章「E2E に任せず単体テストに残すもの」が明示的に残す対象）。
  消すものなし
- `turn-selection.test.tsx`: `window.location.hash` を直接書き換えて hash→選択・選択→hash の
  往復を見る。E2E は hash を操作しないので唯一の持ち主。消すものなし
- `main-view-turn.test.ts`: `mainViewTurnsOf` のメモ化（WeakMap）・`unsettledBodies`（running中は
  未確定として伏せる）は、E2E が静止後の DOM しか撮らないため過渡状態を検出できず、唯一の持ち主
  （変異で確認: `unsettledBodies` の `report` を常に `false` にしても、`test/e2e/` 全体で1件も
  落ちなかった）。一方 `isClosed`（背景タスクが残っているあいだは最終レポートの札を立てない）の
  2分岐は、`test/e2e/final-report-label.test.ts` の `background-task-interim-report` 場面
  （waiting / closed）が同じ並びを流して DOM で固定しており、変異（`isClosed` を
  `state.backgroundTasks.length` を見ずに判定・常に `false` を返す、の2通り）でどちらも
  該当の E2E が落ちることを確認したため消した。`isClosed` の「running のあいだは立てない」分岐
  （3件目のテスト）は、同じ変異（常に `true`）を入れても `test/e2e/` が1件も落ちなかったため残した
- `question-answer.test.tsx`: 対話系（`onToggle`・`onAnswer`・`onAnswerWithText`・`onBack`・
  `session.answer` へ送る payload の組み立て）は、上記の「E2E は質問に自動で答えない」制約により
  丸ごと唯一の持ち主。選択肢の並び（辞書順）・自由入力の除外・`(Recommended)` の印も、
  どの疑似セッションの場面もこの分岐が観測できる形でデータを作っていない（辞書順はフィクスチャが
  もとから昇順、自由入力と `(Recommended)` はどの場面にも登場しない）ため唯一の持ち主。
  `preview` と `description` のそのままの受け渡し（`optionRows`）だけは、`question-preview` 場面
  （preview）と `question-pair`/`question-multi`/`question-long` 場面（description）が同じ値を
  DOM に出して固定しており、変異（`optionRows` で `description: ""`・`preview: undefined` に
  差し替え）で `test/e2e/question-ask.test.ts` の4件すべてが落ちることを確認したため消した

## 注意

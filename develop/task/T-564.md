## 目的

振り返りのターンでキャラクターが書いた日記（本文・しおり・表情）を受け取り、後から何度でも読み返せるように保存して、成果の画面へ届ける。

## 完了条件

- `diary` ツール（欄の並びと説明は `docs/design.md`「日記の受け取りと保存」）が仕事と雑談の両方のセッションに載る
- 同じ節の「関所」の表の条（書く日が無い・1ターンに2回・本文やしおりの形・保存の失敗）が突き返され、モデルが呼び直せる（`usage_review_result` / `report` の関所と同じ形）。受け付けたら `diary-written` を流す
- 「いま書く日」（日付とその日の終えたタスク）を窓口（`createDiaryIntake`）へ渡す口がある。渡すのは T-565 の `reflect-achievement` なので、この段ではテストから直接渡して確かめればよい
- 受け取った日記が同じ節の「保存の形」のとおり（`~/.tsukumo/diary/<リポジトリ>/<日付>.json`・書き足し・しおりの差し替え・パックのディレクトリ名と表示名・読めないファイルの置き換え）に残る
- ブラウザが日記を受け取れる: 1日ぶんは `DailyAchievement.diary`（written / none / unreadable）、日記のある日の一覧は独立の経路ではなく暦の応答の `diaryDates`（`docs/design.md`「成果の集め方と配り方」。配線は `src/view-delivery.ts`）
- 保存・読み出し・書き足し・突き返しをテストで確かめてある（フィクスチャは架空の文面）
- `bun run check` が通る

## 背景

- ツールの先例は `src/server/adapter/sdk-tool.ts`（`usage_review_stage` / `usage_review_result`、`report`）と、形の検査の `src/server/core/usage-review-tool.ts` / `src/server/core/report-tool.ts`
- ホームへの書き込みの先例は `src/server/adapter/chat-summary.ts`（`tsukumoHomeDir()`）。リポジトリの見分けは `src/server/adapter/task-summary.ts` の `git rev-parse --git-common-dir`
- `TSUKUMO_HOME` を分けて並行して動かす運用がある（`CLAUDE.md`「## タスク運用」）

## やること

前提を調べ直した結果（着手前）:

- `createDiaryIntake` / `diary-written` / `DailyAchievement.diary` / `diaryDates` は着手前は
  どこにも無かった。`src/shared/achievement.ts` の `DailyAchievement` に `graduations` /
  `milestones` は既にあるが `diary` は無く、`src/shared/achievement-calendar.ts` の
  `AchievementCalendar` には `diaryDates: readonly string[]` が既にあるものの、
  `src/server/adapter/main-history.ts` は常に `[]` を返す実装のまま（「日記の保存（別タスク）」の
  プレースホルダ）だった
- 依存タスク T-561 は docs（`docs/design.md`「日記の受け取りと保存」「成果の集め方と配り方」）を
  書いただけで、実装は無し。T-562/T-563（卒業・節目・暦）は完了済みで、成果の集計まわりは
  ここから素直に積める状態
- 完了条件にある `src/view-delivery.ts` はそのままのパスで存在し、`readAchievement` /
  `readAchievementCalendar` を配る配線を持っている（想定どおり）

設計の正典（`docs/design.md`）と実物の食い違いは無かった。実装は次の形で行った:

- `src/shared/diary.ts`（新規）: `Diary` / `DiaryParagraph` / `DiaryBookmark` /
  `DailyDiaryStatus` の型と、保存の形の読み手 `readDiary`（zod）。`DiaryWriting` /
  `DIARY_STAGES`（3段の進み）は次のタスクの持ち物なのでここでは追加しない
- `src/server/adapter/diary.ts`（新規）: `~/.tsukumo/diary/<リポジトリ>/<日付>.json` の読み書き
  （`appendDiaryParagraph` / `readDiaryDay` / `listDiaryDates`）。リポジトリの見分けは
  `git rev-parse --path-format=absolute --git-common-dir`（`./git.ts` の `runGit`）+
  SHA-256 の先頭12桁。書き込みは一時ファイル→`rename` で原子的
- `src/server/core/diary-tool.ts`（新規）: ツールの名前・説明文、`DiaryDay` / `DiaryIntake`、
  `createDiaryIntake`（関所の判定・保存呼び出し・`diary-written` の発行）。3段目の合図を拾う
  純関数はここには入れない（進みの表示は別の関心事で、今回のスコープ外）
- `src/shared/session-event.ts` に `diary-written { date }` を追加。`src/shared/session-state.ts`
  の畳み込みには no-op の1ケースだけ足す（`SessionState.diaryWriting` 自体は次のタスクの持ち物）
- `src/server/adapter/sdk-tool.ts`: `tsukumoServer` に `diaryIntake` を追加し、`diary` ツールを
  仕事・雑談の両方に登録
- `src/server/adapter/sdk-driver.ts` / `src/server/core/session-driver.ts` /
  `src/session-start.ts`: `SessionDriverOptions` に `diaryWriter`（書いた時点のパックの
  ディレクトリ名と表示名）を足し、`createDiaryIntake` を組み立てて `tsukumoServer` へ渡す
- `src/shared/achievement.ts` の `DailyAchievement`（`known`）に `diary: DailyDiaryStatus` を
  追加。`src/server/adapter/main-history.ts` はここに `{ kind: "none" }` のプレースホルダを
  返すだけにとどめ（数だけを持つ層の責務のまま）、`src/view-delivery.ts` の
  `readAchievement` / `readAchievementCalendar` の配線で `diary.ts` の読み取りと合わせて
  差し替える（`diaryDates` も同じ形ですでにプレースホルダになっていたので、同じ扱いに揃えた）

## 注意

- 日記はモデルが書いた文で、会話の逐語ではない。ただしログに全文を出さない（`docs/coding-standards.md`「会話内容の扱い」）
- Agent SDK に触るのは `src/server/adapter/` の `sdk-` で始まるファイルだけ（`CLAUDE.md` 原則3）

## 目的

`docs/research/server-procedure-proposal.md` の段4（確度は「推測」）。サーバからの押し出しも手続き（Event Iterator の購読）にできるなら、受け口を1つの仕組みに揃える。

## 完了条件

- oRPC の Event Iterator が `/ws` の上で「`hello`（スナップショット）が先、`events` があと」の順序と、再接続のときの取り直しを保てるかを、実物で確かめて結果に書いている
- 保てるなら: `src/shared/frame.ts` のフレームと `session-manager` の `subscribe` を購読の手続きへ置き換え、再接続で今と同じ状態に戻ることを目視で確かめている
- 保てないなら: 押し出しは今の `subscribe` のまま残し、理由を `docs/research/server-procedure-proposal.md` 9章に書いて `dropped` で閉じてよい
- `bun run check` が通る

## やること

前提の調べ直し（2026-09-26、`b7c6d8e3`）: 段3（T-654）は入っていて、`/ws` のコマンドは oRPC の
`RPCHandler`（`session-socket.ts`）に載っている。押し出しは `session-manager` の `subscribe(send)`
（呼んだ瞬間に `hello` を同期で送り、以後 `events` を配る。起こし直しでは途中でも `hello` を配る）を
`session-socket.ts` が生の JSON で送り、ブラウザ（`src/browser/lib/socket.ts`）が `i` の有無で
フレームと手続きの応答を振り分けている。`refresh` は `view-delivery.ts` が同じ `send` へ押す。
前提は崩れていないので作業する。

1. 実物で確かめる（リポジトリの外に試しのコードを置く）: `ws` + `RPCHandler` + `RPCLink` の上で
   async generator の手続きを購読し、(a) `hello` が先・`events` があとの順序と大量の束の連続性、
   (b) 途中の `hello`（起こし直し）、(c) 接続が切れたときのサーバ側の後始末（購読が外れるか）と
   クライアント側の終わり方、(d) つなぎ直したときの `hello` の取り直し、を Bun と Chrome で測る
2. 保てるなら置き換える:
   - 契約 `src/shared/contract/frame.ts`（`frame.subscribe`。出力は `ServerFrame` の Event Iterator。
     検証は受け取る側だけという 4章の決めを守り、サーバでは検証しない）を足し、`/ws` に載せる束
     （`src/shared/rpc.ts`）に入れる
   - 受け手 `src/server/view-server/adapter/frame-procedure.ts`: 接続の `subscribe` をコールバックから
     取りこぼさず・捨てずに async generator へ写し、手続きの `signal` で購読を外す
   - `session-socket.ts` は生の `send` をやめ、`subscribe` を接続の context に載せる
   - ブラウザ `lib/socket.ts` は振り分け（`CommandChannel`）をやめ、接続ごとに `frame.subscribe` を
     呼んで届いた値を `parseServerFrame` で見てから渡す。購読が終わったら繋ぎ直す
   - E2E の記録（`test/e2e/scenario-run.ts`）は購読の封筒をほどいてフレームとして記録する
     （成果物の列は変えない）。テスト・`docs/design.md`・`docs/glossary.md` を追随させる
3. 結論と根拠を `docs/research/server-procedure-proposal.md` 9章に書く
4. 再接続で今と同じ状態に戻ることを、疑似セッションで起こしたページの `/ws` を切って目視で確かめる

## 背景

- いまは接続ごとに `session-manager` の `subscribe` が `hello` を1つ送ってから `events` を流す（順序を決めているのは `session-manager` 側。`session-socket.ts` の `attachSessionSocket` のコメント）
- oRPC の文書は Event Iterator を SSE の例でしか示しておらず、WebSocket 上の振る舞いは確かめていない（提案書 3章）

## 結果

- 検証コマンド: 2718 pass / 0 fail（+2）、E2E 15 pass / 0 fail
- oRPC の購読（Event Iterator）を `/ws` に載せても「`hello` が先・`events` があと」と繋ぎ直しの取り直しが保てると、`@orpc/*` 1.15.4・Bun・Chrome で確かめた。押し出しを `frame.subscribe` の購読へ置き換え、`PROTOCOL_VERSION` を 22 に上げた。受け手は切断の `signal` で購読を外し、フレームを捨てない。サブエージェントが 39055 番でタブの `/ws` を切り、繋ぎ直すと別タブと同じ画面に戻るのを見た
- この変更をまたぐ古いタブには `hello` が届かず「読み込み直して」の知らせも出ない（一度だけ。読み込み直せば戻る）
- 振り返り: 兆候なし

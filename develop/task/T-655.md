## 目的

`docs/research/server-procedure-proposal.md` の段4（確度は「推測」）。サーバからの押し出しも手続き（Event Iterator の購読）にできるなら、受け口を1つの仕組みに揃える。

## 完了条件

- oRPC の Event Iterator が `/ws` の上で「`hello`（スナップショット）が先、`events` があと」の順序と、再接続のときの取り直しを保てるかを、実物で確かめて結果に書いている
- 保てるなら: `src/shared/frame.ts` のフレームと `session-manager` の `subscribe` を購読の手続きへ置き換え、再接続で今と同じ状態に戻ることを目視で確かめている
- 保てないなら: 押し出しは今の `subscribe` のまま残し、理由を `docs/research/server-procedure-proposal.md` 9章に書いて `dropped` で閉じてよい
- `bun run check` が通る

## 背景

- いまは接続ごとに `session-manager` の `subscribe` が `hello` を1つ送ってから `events` を流す（順序を決めているのは `session-manager` 側。`session-socket.ts` の `attachSessionSocket` のコメント）
- oRPC の文書は Event Iterator を SSE の例でしか示しておらず、WebSocket 上の振る舞いは確かめていない（提案書 3章）

## 目的

依頼を送ってから、メインエージェントがサブエージェントへ背景で委譲した時点で入力欄の時間が「所要」で止まってしまうのを直し、メインが最後に完了したところまでを1つの依頼の所要時間として出す。

## 完了条件

- 依頼を送ったあと、メインが背景の委譲でターンを終えても、背景のタスクが残っている間は「経過」のまま数え続ける
- 委譲の完了の知らせなどで claude が自分で始めた続きのターン（`turn-resumed`）では、起点の時刻を依頼を送った時刻のまま引き継ぐ（付け直さない）
- 背景のタスクが残っていないターンの終わりで「所要」（失敗なら「失敗」）として止まり、その値は依頼を送った時刻からの時間になる
- 利用者が途中で新しい依頼を送ったら、そこから数え直す（いまのまま）
- 状態の畳み込みのテストと、入力欄の時間の行の E2E（委譲して続きのターンで終わる流れ）で確かめている
- `docs/display.md` の入力欄の経過時間の記述と、`TurnProgress` の説明を合わせている
- `pnpm run check` が通る
- 調べて前提が崩れていたら、理由を書いて `dropped` で閉じてよい

## 背景

- 経過時間は `src/browser/components/page/conversation/components/dispatch/components/turn-status/hooks/use-turn-status.ts` の `elapsedText` が `state.turn`（`TurnProgress`）の `startedAt` / `finishedAt` から出している
- `src/shared/session/session-state.ts` の `turn-finished` は `finishTurn` で `finished` にし、そこで「所要」になる。続きのターンの `resumeTurn` は `turn: { kind: "running", startedAt: at }` で**起点を付け直している**ので、再開すると経過が0から数え直しになる
- 背景のタスクの一覧は `SessionState.backgroundTasks`（`background-tasks-changed` で丸ごと置き換え、`turn-finished` で空にする）

## 解くべき論点

- 「メインの完了」を何で判定するか。`backgroundTasks` が空かを見るのが第一案だが、`turn-finished` で空にしているので、ターンが終わった時点で背景が残っていたかをどう持つか
- 背景を待つ間の送信・中断ボタンの扱い（時間の行だけを変え、ボタンは `turn.kind` のままにするのが第一案）
- 時間の起点を `TurnProgress` に持ち続けるか、依頼単位の起点を別の値として持つか（起きない組み合わせを型に残さない形を選ぶ）

## 注意

- 立ち絵の「完了の反応」など、`turn.kind` の `finished` を見ているほかの振る舞いを変えない（時間の表示だけを直す）

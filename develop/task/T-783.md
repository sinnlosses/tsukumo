## 目的

人の訂正・方向転換・差し戻しを振り返りの兆候にする。外部の研究（arXiv 2605.29442）も Claude Code 向けのツール（agent-retro・claude-reflect）も、これを一番強い信号として使っているが、いまの兆候の表は委譲先の手数しか見ていない。

## 完了条件

- 人の差し戻しを拾う手段が決まり、`retrospect` の兆候の表に行がある（札は T-779 の語彙）
- 拾うときに会話の中身（人の発言・Claude の返答の文）を記録・ドラフト・ログに写さない。写すのはタスクID・札・時刻・件数などだけ
- 決めた手段が `material.py`（または T-762 のあとの材料）に入っているか、メインが受け入れで自分で書き留める手順として書かれている
- claude-skills 側の検査（`./check.sh`）が通り、claude-skills の `main` に入っている
- このリポジトリの `pnpm run check` が通る
- 会話の中身を読まずに拾う手段が無いと分かったら、そこで止めて理由を `## 結果` に書き、`hold` にして人に預ける（規約を広げない）

## 背景

- `retrospect` の「守ること」3: トランスクリプトから取るのはツール名・ファイルパス・コマンドの先頭2語・件数・時刻だけ。`material.py` がこの線を引いている
- このリポジトリの規約（CLAUDE.md の IMPORTANT、`docs/coding-standards.md`「会話内容の扱い」）は他のどの規約よりも優先する
- `/loop` から回るときは人がいないので差し戻しは起きない。人がいるセッションで `/next-task` を回したとき・受け入れのあとに人が直させたとき・`task done` 後に人が戻させたとき（revert など）が対象

## 決まっていること（蒸し返さない）

- 2026-09-27 ユーザー決定: 外部のプラクティス4つ（friction log・運良く助かった・札の繰り返しを数える・人の差し戻しを拾う）をすべて取り込む
- 会話の中身は写さない。会話内容の規約の例外を広げる判断はこのタスクではしない

## 解くべき論点

- 差し戻しを何で検知するか: メインが自分で1行書き留める（手順）／人の発言の直後にツールの流れが変わったことを数だけで拾う（`material.py`）／git の revert・同じファイルへの直後の手直し、など
- 検知したものに札（S2 意図の読み違い・S3 制約違反など）を付けるのは誰か。中身を読まずに札を決められるか

## 目的

人の訂正・方向転換・差し戻しを振り返りの兆候にする。外部の研究（arXiv 2605.29442）も Claude Code 向けのツール（agent-retro・claude-reflect）も、これを一番強い信号として使っているが、いまの兆候の表は委譲先の手数しか見ていない。

## 完了条件

- 人の差し戻しを拾う手段が決まり、`retrospect` の兆候の表に行がある（「札の候補」の列は `retrospect` の SKILL.md の節「札と1行の書式」の語彙。差し戻しは人が止めたので色は `赤`）
- 拾うときに会話の中身（人の発言・Claude の返答の文）を記録・ドラフト・ログに写さない。写すのはタスクID・札・時刻・件数などだけ
- 決めた手段が `material.py`（または T-762 のあとの材料）に入っているか、メインが受け入れで自分で書き留める手順として書かれている
- claude-skills 側の検査（`./check.sh`）が通り、claude-skills の `main` に入っている
- このリポジトリの `pnpm run check` が通る
- 会話の中身を読まずに拾う手段が無いと分かったら、そこで止めて理由を `## 結果` に書き、`hold` にして人に預ける（規約を広げない）

## 解くべき論点

- 差し戻しを何で検知するか: メインが自分で1行書き留める（手順）／人の発言の直後にツールの流れが変わったことを数だけで拾う（`material.py`）／git の revert・同じファイルへの直後の手直し、など
- 検知したものに札（`意図の読み違い`・`制約違反` など）を付けるのは誰か。中身を読まずに札を決められるか

## やること

前提の確かめ: T-779 で `retrospect` の SKILL.md に節「札と1行の書式」が入り、兆候の表（手順3・「1件だけ振り返る」）に「札の候補」の列がある。`material.py` と `transcript.py` はサブエージェントのトランスクリプト（`subagents/*.jsonl`）だけを読み、メインのセッションは読まない。`scan.py` は `## 結果` に `- 振り返り:` があるタスクを `reviewed` に回して `tasks` から外すので、`task done` のあとに入った revert はまとめての振り返りでも見えない。

論点への答え:

- 検知は**メインが自分で書き留める手順**を主にし、**git の revert を `scan.py` が機械で拾う**のを裏打ちにする。人の発言の直後のツールの流れを数で拾う案は採らない。メインのセッションのトランスクリプトはタスクIDに割り付けられず（1セッションが何件も回す）、人の発言が差し戻しか承認・問いへの答え・次の依頼かは中身を読まないと区別できない（数だけでは当て推量になり、読めば規約に触れる）
- 札を付けるのは**メイン**。人の発言からではなく、**差し戻しで自分が直した差分**（何を直したか）から節「札と1行の書式」の語彙で決める。記録に残すのは札・色（人が止めたので `赤`）・タスクID・コミット・パス・件数だけ

変えるもの（claude-skills）:

- `skills/retrospect/SKILL.md`: 「1件だけ振り返る」の兆候の表に「人の差し戻し」の行（見る場所はこのセッションで人が止めた・直させた・やり直させたこと、目安は1回でも、札は直した差分に合わせる、色は `赤`）。手順3の兆候の表に、`scan.py` の `reverted` と `## 結果` の `- 振り返り:` に出た差し戻しの行。`task done` のあとに人に戻された・直させられたときに、その場でドラフトを1件積む短い節（会話の中身を写さない・revert の件名は git の既定のまま残す）
- `skills/retrospect/scripts/scan.py`: 件名が `Revert "` で始まるコミットのタスクIDは、1件ごとに振り返り済みでも `tasks` に戻し、`reverted` の行に出す
- `skills/retrospect/scripts/selftest.py`: `scan.py` の revert の自己テスト（入力に SKILL.md の記録ファイルの雛形の行をそのまま含める）
- `skills/next-task/SKILL.md` 手順6: 受け入れの間に人が差し戻したら、そのことを一言メモしておく（手順6aで使う）

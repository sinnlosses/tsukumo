## 目的

`test` と `scripts` のコメントを、`docs/coding-standards.md`「コメント」の「別の場所を指すとき」に揃え、以後のコード修正・改名・移設でコメントを直す箇所を減らす。

## 完了条件

- `test/comment-reference-backlog.ts` から、`test/` か `scripts/` で始まるファイルがすべて消えている
- コメントの意味（今の挙動の制約・前提）を落としていない。指し方を変えるだけで消えてしまう情報は、規則に沿った形で残す
- 番号だけの節参照が残っていない: `grep -rnE '（原則[0-9]+）|（[0-9]+(\.[0-9]+)+）|（[0-9]+章）|原則[0-9]+「' <このタスクの範囲>` が0件（振り返り: T-709。検査に載らない番号だけの形へ縮めて検査を通す直し方が出たため）
- `bun run check` が通る

## やること

- `bun run test` で `test/comment-reference.test.ts` を落とし（一覧から外したファイルの違反が行番号つきで出る）、ファイルごとに直して一覧から外す。外し忘れは同じテストの2つめが落とす
- ソースファイル名: シンボルの名前に替える（JSDoc の中でそのファイルから見えるものは `{@link}`、それ以外はバッククォートの名前）。自分のファイルは「ここ」。呼ぶ側・使う側を並べているだけのもの（「〜が呼ぶ」「〜が使う」）は消し、呼ぶ側に求める条件だけを残す。実在しないファイル名（すでに古くなった名指し）は、今そのことを持つシンボルを探して指すか、要らなければ消す
- 節番号つきの参照: `docs/x.md 4.2「句」` は番号を消すだけ。番号だけで句が無いもの（`docs/design.md 7章`）は、その番号の見出しの句を足す。ファイル名の無い番号だけの参照（`（13.9）`）も同じく `docs/…md「句」` に直す（検査には載っていないので目で拾う）
- `//` の中の `{@link X}`: バッククォートの `X` に替えるか、宣言に付いた説明なら JSDoc（`/** */`）に替える
- 節の句を変えたら `bun run scripts/find-stray-reference.ts` で迷子が0件かを見る

## 背景

- 着手時点の違反は `test` 124 ファイル・373 行、`scripts` 16 ファイル・56 行。`test/architecture.test.ts` はファイル名の規則だけ対象外（パスが検査の中身）
- 規則・検査・一覧は T-708 で入った。範囲は後段のタスクと重ならないように、パスの先頭で分けてある

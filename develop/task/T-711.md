## 目的

`test` と `scripts` のコメントを、`docs/coding-standards.md`「コメント」の基準（無いと明らかに不都合を招くことだけ）で見直し、残すものを「別の場所を指すとき」に揃える。読む量を減らし、以後のコード修正・改名・移設でコメントを直す箇所を減らす。

## 完了条件

- `test/comment-reference-backlog.ts` から、`test/` か `scripts/` で始まるファイルがすべて消えている
- 範囲のコメントが `docs/coding-standards.md`「コメント」の基準（無いと明らかに不都合を招くことだけ）で見直されている。消したコメントが持っていた制約・前提のうち、無いと壊すものは残っている
- 用語の出典が残っていない: `grep -rn 'docs/glossary\.md' test scripts` のうちコメントの行が0件（用語は正典が持ち、使う箇所から指さないため）
- 規約への参照は、種類の表の「規約の例外」に当たるものだけが残っている: `grep -rn 'docs/coding-standards\.md' test scripts` のコメントの当たりを、残した理由（どの例外・どの規則か）つきで結果に並べている（`（docs/coding-standards.md「会話内容の扱い」）` のように従っていることを示すだけのものは消す）
- 番号だけの節参照が残っていない: `grep -rnE '（原則[0-9]+）|（[0-9]+(\.[0-9]+)+）|（[0-9]+章）|原則[0-9]+「' test scripts` が0件（振り返り: T-709。検査に載らない番号だけの形へ縮めて検査を通す直し方が出たため）
- `bun run check` が通る

## やること

- 範囲のファイルを1つずつ開き、コメントのブロック（長いものは段落）ごとに `docs/coding-standards.md`「コメント」の判定の1問（消したときに、コードだけを見て直した人が壊す・誤って使う場面を具体的に1つ挙げられるか）と種類の表で、書く／書かない／正典へ移すを決める。書かないものは消す。正典へ移すものは先に正典の該当箇所を見て、無ければ書いてから消す
- 消す側に入りやすいもの: 規約・方針に従っていることの説明と、その参照（「（docs/coding-standards.md「エラーハンドリング」）」のような括弧だけのもの）、用語の出典（`docs/glossary.md「…」` を添えるだけのもの）、正典の要約、「〜と同じ形」の照らし合わせ、呼ぶ側・使う側の一覧、名前の言い直し
- 残す側: ファイルの責務、素直に書き直すと壊れる制約（空の `catch` の理由など、誤りに見えて意図どおりのもの）、外部との対応、外から使うものの契約、一緒に直さないと壊れる相手。迷ったら残し、迷って残したものを結果に並べる
- 残したコメントの指し方を「別の場所を指すとき」に揃える。ソースファイル名はシンボルの名前に替える（JSDoc の中でそのファイルから見えるものは `{@link}`、それ以外はバッククォートの名前。自分のファイルは「ここ」）。節の参照は、残す制約の理由が長くて正典にあるときだけ `docs/x.md「句」` の形で残す（番号は消し、番号だけのものは見出しの句にする）。`//` の中の `{@link X}` はバッククォートの `X` か JSDoc に替える
- 消した・縮めたことで制約が失われないようにする。書き足すのは、消した段落が持っていた制約の言い直しだけ（責務のコメントを一斉に足さない）
- `bun run test` で `test/comment-reference.test.ts` を落とし（一覧から外したファイルの違反が行番号つきで出る）、ファイルごとに直して `test/comment-reference-backlog.ts` から外す。外し忘れは同じテストの2つめが落とす
- コメントで補っている分かりにくいコードはリファクタの候補として結果に挙げ、コードは直さない
- 節の句を変えたら `bun run scripts/find-stray-reference.ts` で迷子が0件かを見る

## 背景

- 着手前の量（T-729 で測った値）: `test` 237 ファイル・コメント行 2538（コードの 6%）、`scripts` 17 ファイル・コメント行 634。一覧に載っているのは `test` 124 ファイル、`scripts` 16 ファイル
- テストのコメントは、期待値やフィクスチャの形の理由（なぜこの値か）が多い。それは残す側。テスト名の言い直しは消す側
- `test/architecture.test.ts` はファイル名の規則だけ対象外（パスが検査の中身）。規約を機械で検査するテスト（`test/comment-reference.test.ts` など）が検査する規則を指すのは、種類の表の「規約の例外」の行に当たるので残す。フィクスチャの「すべて手で書いた架空のもの（docs/coding-standards.md「会話内容の扱い」）」は従っていることを示すだけなので消す側。テスト名（`it` の文字列）はコメントではないので、この見直しの範囲に入れない
- 規則・検査・一覧は T-708 で入った。範囲は後段のタスクと重ならないように、パスの先頭で分けてある
- コメントが疎で判定も軽いので `sonnet`。規約を検査するテストで判断に詰まったら `opus` に上げて再開する

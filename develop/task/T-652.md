## 目的

`docs/research/server-procedure-proposal.md` の段1のうちコマンドの側。どの機能がどのコマンドを受け、どの条件で断るかを、機能のディレクトリの中の表から辿れるようにする。

## 完了条件

- T-651 が正典に書いた形のとおり、`src/server/session/core/session-manager.ts` の `dispatch` から振り分けと断る条件の `switch` が抜け、機能ごとの受け手の表と、それを束ねるファイルへ移っている
- 28種のコマンドのすべてが表のどこかに1行ずつあり、漏れを型（`satisfies` で種類を網羅させるなど）で落とせる
- 断る理由（`FRAME_ERROR_REASON` の値）とその順序（雑談の外か → ターン中か）は変わらない。既存のテストが通る
- `bun run check` が通る

## 背景

- `dispatch`（`session-manager.ts` の 672行目あたり）は、雑談の外で断る `switch`・ターン中に断る `switch`・振り分けの `switch` の3つを順に持ち、最後に `isCharacterEditCommand` と `dispatchToDriver`（`driver-command.ts`）へ落とす
- 受け手の中身の多くは `SessionManagerOptions` の口（`createCharacter` `rememberVisitEnabled` など約20本）で、`src/session-start.ts` が渡している

## 注意

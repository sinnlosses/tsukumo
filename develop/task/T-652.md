## 目的

`docs/research/server-procedure-proposal.md` の段1のうちコマンドの側。どの機能がどのコマンドを受け、どの条件で断るかを、機能のディレクトリの中の表から辿れるようにする。

## 完了条件

- `docs/design.md` 2章「コマンドの受け手と手続きの置き方」の段1の形のとおりになっている:
  - 機能ごとの表 `session/core/session-command.ts`・`character-pack/core/character-pack-command.ts`・`chat/core/chat-command.ts`・`visit/core/visit-command.ts`・`usage-review/core/usage-review-command.ts`・`host/core/host-command.ts`（28種の割り振りは同節の表のとおり）
  - 行の型（`write` / `call` と断る条件の `chatOnly` / `idleTurn` の列）は `src/server/core/command-receiver.ts`、`CommandRoute`・`CommandSession`（`state` / `driver` / `restart` / `generation` の4口）・`DispatchResult` は `session/core/command-dispatch.ts`
  - 束ねるのは配線の `src/command-route.ts`（`satisfies CommandRoute` で28種の網羅を型で落とす）
- `session-manager.ts` の `dispatch` から `switch` が消え（`grep -c 'case "' src/server/session/core/session-manager.ts` が 0）、`command-dispatch.ts` へ渡すだけになっている
- `SessionManagerOptions` から書き込みの口（`editCharacter` `createCharacter` `deleteCharacter` `forgetRememberedLine` `rememberSessionDefault` `rememberVisitEnabled` `dismissUsageProposal` `openFile`）と `readAchievementDay` `diary` が抜け、`commands: CommandRoute` の1本になっている
- 断る理由（`FRAME_ERROR_REASON` の値）とその順序（雑談の外か → ターン中か）は変わらない。既存のテストが通る（口の形が変わったぶんの書き換えは最小に）
- `test/architecture.test.ts` の機能どうしの辺の表は増えていない（配線で束ねるため）
- `bun run check` が通る

## 背景

- `dispatch`（`session-manager.ts` の 672行目あたり）は、雑談の外で断る `switch`・ターン中に断る `switch`・振り分けの `switch` の3つを順に持ち、最後に `isCharacterEditCommand` と `dispatchToDriver`（`driver-command.ts`）へ落とす
- 受け手の中身の多くは `SessionManagerOptions` の口で、`src/session-start.ts` が渡している。移したあとは同じ中身を各機能の `<機能>Commands(ports)` の `ports` へ渡す

## やること

前提は崩れていない（2026-09-26 に調べ直した）。`dispatch`（`session-manager.ts` の 672行目）は
`switch` 3つ（雑談の外で断る2種・ターン中に断る4種・振り分け）と `isCharacterEditCommand` →
`dispatchToDriver` の順で、`case "` は20個。28種は design.md の割り振りの表のとおりに分かれる
（session 12・character-pack 12・chat / visit / usage-review / host 各1）。`DispatchResult` は
`driver-command.ts` にあり、`view-server/adapter/session-socket.ts` とそのテストが読む。

- `src/server/core/command-receiver.ts`: 断る条件の2列（`false | FrameErrorReason`）、`write` /
  `call` の行の型、機能の表の型（種類 → 行の写像）
- `src/server/session/core/command-dispatch.ts`: `DispatchResult`（`driver-command.ts` から移す）、
  `session` の行、`CommandRoute`、`CommandSession`（4口）、`dispatchCommand`（断る条件を
  雑談の外か → ターン中かの順で見て、行の種類ごとに呼ぶ。`write` のイベントは `generation().emit`）
- 機能ごとの表: `session/core/session-command.ts`（駆動へ渡す6種・`nudge`・起こし直し3種・
  `reflect-achievement`・`set-session-default`）、`character-pack/core/character-pack-command.ts`、
  `chat/core/chat-command.ts`、`visit/core/visit-command.ts`、
  `usage-review/core/usage-review-command.ts`、`host/core/host-command.ts`。`ports` の形は
  いまの `SessionManagerOptions` の口のまま（テストの差し替えを最小にする）
- `src/command-route.ts`: 機能ごとの `ports` を受けて表を束ね、`satisfies CommandRoute`
- `session-manager.ts`: `SessionManagerOptions` から10口を抜いて `commands` を足し、`dispatch` は
  `CommandSession` を作って `dispatchCommand` へ渡すだけ。`reflectAchievement` / `write` /
  `openFile` を表の側へ移す
- `session-start.ts` を `commandRoute(...)` を渡す形に、`session-socket.ts` の import 先を直す
- テスト: `session-manager.test.ts` の `createSessionManager` の呼び出しを `commands` に寄せる
  （口の中身はそのまま）。`session-socket.test.ts` の import 先
- `docs/design.md` の「いまの実装はまだ段1の前」と機能の表の `session` の `core/` の並び、
  `view-server` の辺の説明（`driver-command` → `command-dispatch`）を移したあとの姿に直す

## 注意

- 表を `session/core/` で束ねない（`session` → `usage-review` / `host` の辺が要り、束ね役に戻る。design.md の同節）
- `reflect-achievement` は `session` の表に残す（代の `emit` と `diarySignal` を使うため。依頼文を組む判断を `diary/core/` の純関数へ下ろすのは任意）
- `write` の受け手が返したイベントを流すのは `command-dispatch.ts`（`CommandSession.generation().emit`）で、各機能の表は流し方を知らない

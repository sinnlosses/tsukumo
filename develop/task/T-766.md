## 目的

T-682 で scripts を Node へ移したあとも、目視の手順の口 `node scripts/capture-catalog.ts` が起動直後に落ち、委譲先は `bun` で打って回避している。Node で撮れるようにして、目視の手順を書いてあるとおりに動かす。

## 完了条件

- `node scripts/capture-catalog.ts --only notation` が `ReferenceError` で落ちず、撮影まで進む
- 原因（循環 import か宣言順か）を突き止め、同じ形で落ちる箇所がほかに無いかを `node` で起こす scripts の入口で確かめた結果を `## 結果` に書く
- `bun run check` が通る

## 背景

- 2026-09-27 に main で `node scripts/capture-catalog.ts --only notation` を打つと、次で落ちる:
  `src/shared/frame.ts:95` `z.object({ type: z.literal("events"), events: z.array(stampedEventSchema) })` → `ReferenceError: Cannot access 'stampedEventSchema' before initialization`（Node v26.10.0）
- `serverFrameSchema`（`src/shared/frame.ts` 89行目あたり）がモジュールのトップレベルで `stampedEventSchema` を使っている。`stampedEventSchema` がまだ初期化されていないので、`frame.ts` を含む import の輪があり、Node の ESM の評価順で先に `frame.ts` の本体が走っている見込み（bun では同じ入口が通る）
- 振り返り（T-684）で、委譲先が目視の撮影で `node` から打って落ち、`bun` で回避したと報告された。T-684 は `frame.ts` に触れていない

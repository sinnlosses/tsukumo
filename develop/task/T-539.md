## 背景

2026-09-24 に `/simplify` の4観点（再利用・単純化・効率・根本対処）でリポジトリ全体を洗った結果の1件（`docs/history/direction.md` の 2026-09-24「改修コストを下げる直し9件」）。

`bun run test` は 21.3秒（2026-09-24 実測、172ファイル）。テストの中の固定時間の待ちは3種類ある。

| 種類                   | 例                                                                                                                                                 | 何を待っているか                                                                                                                      | 扱い                                                                               |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| デバウンスの待ち       | `test/browser/features/character-screen/use-character-edit.test.tsx` の `setTimeout(resolve, 250)`、`character-edit.test.tsx` の `waitForDebounce` | 差し色の送信が 200ms（`src/browser/features/character-screen/hooks/use-character-edit.ts` の `ACCENT_DEBOUNCE_MS`）まとまり終えるまで | 置き換える（計約1.2秒）                                                            |
| 1拍の待ち              | `character-edit.test.tsx` などの `setTimeout(resolve, 20)`                                                                                         | `FileReader` の読み込みが終わって dispatch されるまで                                                                                 | 置き換える（縮むのは数十msだが、遅いマシンで20msに間に合わず落ちることが無くなる） |
| 何も起きないことの確認 | `test/server/adapter/task-summary.test.ts` の `sleep(QUIET_PERIOD_MS)`                                                                             | 変化が無いときに知らせが来ないこと                                                                                                    | **残す**（待たないと確かめられない）                                               |

着手時に対象を取り直す:

```bash
grep -rnE "setTimeout\(r(esolve)?, *[0-9A-Z_]+\)" test
```

## 決まっていること（蒸し返さない）

- 置き換えるのはデバウンスの待ちと1拍の待ちだけ。「何も起きないこと」の待ちは残す（2026-09-24 に利用者が選んだ）
- `src/` 側は変えない（待ち時間を注入できる形にするなどはしない）

## 解くべき論点

- `bun:test` の偽のタイマーが React の `act` と一緒に効くか（リポジトリに使った前例は無い）。効かなければ、条件が満たされるまで短い間隔で見に行く待ち方に揃える。どちらにするかを最初に確かめて決める

## やること

1. 変える前の `bun run test` の所要時間を3回測る
2. 上の論点を小さく試して、待ち方を決める
3. デバウンスの待ちと1拍の待ちを置き換える。条件で待つ関数を複数のテストファイルが使うなら `test/` の下の1か所に置く
4. 変えたあとの所要時間を3回測る。**縮みが1秒未満なら変更を捨て、測った数を `evidence` に書いて閉じる**

## 完了条件

- 変える前と後の所要時間（各3回）が `evidence` にある
- 上の grep に残っているのが「何も起きないこと」の待ちだけで、残した理由がその場のコメントか `evidence` にある
- `bun run check` が通る

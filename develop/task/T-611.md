## 目的

前段で作った文字の部品を、残る `components/page/` の画面（会話・キャラクター・成果・使用量）にも行き渡らせる。

## 完了条件

- `src/browser/components/page/` で、**字の段・色・太さ（と `margin`・文字の組み）だけを持つ規則が付いた `<p>` / `<span>`**（空の表示 `.speech-log-empty` `.chat-empty` などを含む）が前段の `Text` に置き換わり、規則が消えている。ほかの見た目も持つ規則を残したときは、その理由を結果に1行ずつ書く
- **置き換えないもの**: トークン消費の画面の `--usage-*` の色を持つ規則と、日記帳の `--diary-gold-*` の色・明朝を持つ規則（語彙と同じ property で画面固有の値を持つ。`docs/design.md` 2章「`components/ui/` の部品（variant の作法と一覧）」）。`<summary>` など `Text` の `element` に無い要素に付いた規則は、要素を増やすか残すかを決めて結果に書く
- 部品の API を広げたなら（`element` の値など）、`test/browser/components/ui/text/text.test.tsx` にその行を足してある
- `test/architecture.test.ts`「components/ui/ の部品の className」が通る
- 会話の画面・キャラクターの画面・成果の画面（日記帳の見開きを含む）・使用量の画面を起動して目視し、字の大きさ・色・太さ・間隔が置き換え前と同じであることを確かめている（何を見たかを結果に書く。モーダルの中も測る）
- `bun run check` が通る

## 背景

- 計画時の実測（2026-09-25）で、`page/` の「字の段と色だけ」の単独の class の規則は 52、うち `--usage-*` の色が 17
- 量が多いのは `page/token-usage/token-usage.module.css`（`--usage-*` が多く、置き換えの対象は少ない）、`page/achievement/achievement.module.css`（明朝と `--diary-gold-*` を使う日記帳）、`page/character/character-screen.module.css`
- `main-view/markdown/report-notation.module.css` は Markdown から生まれる HTML に当たる規則で、React の部品では置き換えられない

## 決まっていること（蒸し返さない）

- 画面固有の色（`--usage-*`・`--diary-gold-*`）は `Text` の語彙に入れず、`className` で上書きもしない。その要素は機能の CSS のまま残す
- **見た目を変えない**

## やること

いまのコードで前提を取り直した結果（2026-09-25 実行時）:

- `page/` 配下の全 `*.module.css`（会話4領域・キャラクター・成果・使用量）を総ざらいし、
  「字の段・色・太さ」を持つ規則を洗い出した。対象は当初の見積もり（52件・8ファイル）を
  大きく超え、achievement / character / conversation（main-view・chat-view・dispatch・
  character-view）/ token-usage の全ファイルで見つかった（成果の画面だけでも診断時に
  見落としていた `diary-notice.module.css`・`presentational-achievement-screen.tsx` の
  `.achievement-note` があった——**画面ごとに1ファイルとは限らない**ので、
  `grep -rn "className={styles\[" src/browser/components/page/` で全 `.tsx` を
  洗い直してから着手する）
- `Text` の `element` は `"p" | "span"` のみだったが、`.turn-request > summary`（main-view）・
  `.question-previews > summary`（同）・畳んだ中間レポートの `<summary>`（`turn.tsx`）の3箇所が
  文字の段・色だけの `<summary>` だったので、`"summary"` を足した（`docs/design.md` 2章の
  「採らなかった部品」表が Disclosure を見送った理由に「`<summary>` の見た目は字の段と色だけ」と
  あり、`Text` の語彙で表せることの裏付けになる）。`id` / `aria-hidden` など `Text` が持たない
  属性が要る箇所（見出しの `id`・装飾マークの `aria-hidden` など）は、その属性だけを持つ素の
  `<span>` で包み、内側に `Text` を置く（`Heading` 側で「顔」「表情」の id に使われている
  手口と同じ）
- 「字の段・色・太さ」以外の property が同じ規則に同居していても（padding・background・
  border-radius の "chip" 形・flex アイテムの `flex` / `min-width` など）、それらは
  `Text` の `className` に残したまま段・色・太さだけを抜く（完了条件の例に挙がっている
  `.chat-empty` 自体が padding・background・border-radius を持つ）。**抜かないのは**
  (1) 画面固有の色（`--usage-*` ・`--diary-gold-*`。日記帳は明朝の書体も含む）、
  (2) `Text` の `tone` に無い色（`--ground` など。`.character-in-use` ・
  `.token-usage-review-badge` ・`.character-card-badge`）、(3) 複数の状態のうち一部だけが
  画面固有色を使う規則（`.usage-review-stage-mark` は既定 `accent` だが未着手の状態だけ
  `--usage-ink-faint` に化ける）、(4) `<button>` / `<label>` / `<li>` / `<td>` / `<time>` /
  `<div>` に付いた規則（`Text` の語彙に要素が無い。`<li>` の状態色は T-610 と同じく包まない）、
  (5) `<label>` と共有している規則で値が `Text` の `weight` に無い（`character-create-label`
  の `font-weight: 500`）
- UA 既定の margin に頼っていた `<p>`（margin を1度も書いていない規則）は、`Text` の既定
  `margin: 0` に上書きされるので margin を明示し直す（`main-view.module.css` の `.placeholder`
  が該当。T-610 の `.task-empty` と同じ事故パターン）——**`margin: 0` を明示している規則は
  そのまま削ってよい**（`Text` の既定と一致するため）

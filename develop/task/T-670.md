## 目的

T-660 の続き。`test/server/` の単体テストを `test-audit` で監査し、T-658・T-659 の E2E（`test/e2e/`）が守っている振る舞いだけを確かめている単体テストを消す。

## 完了条件

- `test/server/` を監査し、E2E が守っている振る舞いだけを確かめている単体テストを消している。消した1件ごとに、どの E2E が守るかをタスクの結果に書いている（テストの跡にコメントは残さない）
- 消す前に、その契約を本番コードで変異させて keeper の E2E が落ちることを確かめている
- `docs/coding-standards.md`「消すかどうか」表の「残す」行（回帰テスト・書式の固定）と、`docs/design.md` 10章「E2E に任せず単体テストに残すもの」に当たるテストは残している
- 消したあと、カバレッジ（閾値は置かない）で守られなくなった分岐が無いかを見て、あれば E2E か単体テストで埋めるか、埋めない理由を「埋めないと決めた穴」に書いている
- 消す前後のテスト件数と `bun run check` の所要時間を結果に書く
- `bun run check` が通る

## 背景

- T-660 で「会話の画面」（`test/browser/components/page/conversation/`）を監査して40宣言・45件を消した。領域が広く1コミットに収まらないため、残りの領域を1件ずつに分けた
- 消す判定は `docs/coding-standards.md`「消すかどうか」表の「E2E の台本が通している振る舞い」の行と、その下の「E2E の台本が通している、とは」の段落に従う
- T-660 の例: `data-brush-origin` のように、定数と JSX の直書きが一致するかを見るテストは、E2E では捕まらないので残した

## やること

前提を調べ直した結果、`test/server/` には T-660・T-666〜T-669（browser の部品テスト）と同型の
「E2E が守っている振る舞いだけを確かめている単体テスト」がほぼ無いと判明した。理由:

- fake driver（`test/e2e/scenario-run.ts` が起こす）は `TSUKUMO_DRIVER=fake` で実 SDK を呼ばず、
  `test/fixture/fake-session.json` に**手書きした `SessionEvent` の並びをそのまま流す**。
  `report-rejected`・`report-tidied` の場面は `tool-finished` の `content`（差し戻しの理由文）や
  `isError` を手書きしており、`report-review.ts`/`report-violation.ts` の判定ロジックそのものは
  実行されない（`test/fixture/fake-session.json` 1434〜1535行）。同様に `system-prompt`・
  `report-notation`・`chat-memory-prompt` などのプロンプト文面は、実 SDK を呼ばない E2E では
  一度も生成されない
- E2E が固定する成果物は DOM の構造と WebSocket のメッセージ列の2つだけ（`docs/design.md` 10章）。
  `test/server/` の大半（ストレージ・設定・時刻計算・純粋関数の集計・プロンプト文面）は、この
  2つの成果物には現れない別の観測点を見ている
- `docs/design.md` 10章「E2E に任せず単体テストに残すもの」が、`sdk-` で始まるファイルの写しの
  全部・時刻に依る計算・再接続・版の食い違い・バッチの束ね方・エラー方針の分岐を単体テスト残留と
  明示している。`session-driver/` のほぼ全ファイルがこれに当たる
- `docs/design.md` 10章の表が、`session-manager`（hello → events の順序・バッチ・dispatch の分岐）
  と `server（ws）`（購読 → hello 先着・順序取りこぼしなし・切断で購読が外れる・トークン無し 403・
  Origin 違い 403・コマンド → 受け手が呼ばれる）の確認場所として
  `test/server/session/core/session-manager.test.ts` と
  `test/server/view-server/adapter/session-socket.test.ts` を明示的に指定している。これは
  `docs/coding-standards.md`「消すかどうか」表の「残す」側にある**呼び出しの順序**の例外に当たり、
  E2E の各シーンでも同じ順序（hello が先に届く等）が結果として見えるとしても、design.md が単体
  テストの持ち場と定めている以上は消す候補にしない
- `docs/design.md` 10章「まだ無いシナリオ」に `visit-long-tool`・`visit-background`・
  `diary-written` などが挙がっており、対応する E2E シーンが存在しない。`visit/core/visit-watch.test.ts`
  の `it("visit-long-tool: ...")`／`it("visit-background: ...")` はこの未実装のシーン名を
  単体テストの中だけで模しているもので、E2E が守ってはいない

`test/server/` 全66ファイルを一覧化し、各ファイルに「E2E が守る振る舞いだけを見ているテストが
あるか（有/無）」を検討した（下表）。**消す候補は0件。** WS メッセージ列を直接観測する
`session-socket.test.ts`／`session-manager.test.ts` の一部（hello 先着・イベントの順序）だけが
E2E の各シーンでも同じ結果が見えるが、上の理由で「残す基準」の順序の例外に当たり、design.md 自身が
持ち場として指定しているため消さない。

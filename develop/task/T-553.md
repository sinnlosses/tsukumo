## 目的

サイドバーのセッションのプルダウン（`src/browser/features/sidebar/session-switch.tsx`）で、どの行がなんのセッションかを見出しだけで見分けられるようにする。中身を知っている Claude 自身に短い題を付けさせ、tsukumo が SDK の `renameSession()` で書き込む。

## 完了条件

- 仕事のモードで、Claude が付けた題が次に一覧を読んだときの見出しに出る（`SDKSessionInfo.summary` は custom title を最優先するので、一覧側の読み口は変えずに済むはず。変える必要があれば変えてよい）
- 利用者が `/rename` で付けた題を tsukumo が上書きしない
- 題の書き込みに失敗してもターンは止まらない（動作中の一時的な失敗として諦める）
- `renameSession` を呼ぶのは `src/server/adapter/sdk-session.ts`（原則3）。題を付けるかどうかの判断は `src/server/core/` に置き、テストで守る
- `bun run check` が通る
- 目視: `bun run start` で依頼を1つ流し、ターンが終わったあとにプルダウンの見出しが付けた題になっていることを確かめて結果に書く

## 背景

- 見出しは `src/server/core/session-restore.ts` の `headingFrom(value.summary)` が SDK の `summary` をそのまま使い、`session-switch.tsx` の `sessionLabel` が24字（`MAX_HEADING_LENGTH`）で切って時刻を足している
- 2026-09-24 に数えたところ、tsukumo の印が付いた直近40件のうち11件の見出しが「/next-task」、2件が「/clear」で、時刻でしか見分けられなかった。`/rename` 由来の `customTitle` を持つものは8件
- `SDKSessionInfo` には `customTitle` / `firstPrompt` / `gitBranch` / `createdAt` もある（`node_modules/@anthropic-ai/claude-agent-sdk/sdk.d.ts` の `SDKSessionInfo`）。`renameSession(sessionId, title, options)` も同ファイルにある
- 題を受け取る口の候補は `report` ツール（`src/server/adapter/sdk-tool.ts`。仕事のときだけ載る。説明文は `src/server/core/report-tool.ts`）に任意の欄を足す形。専用のツールを足す形でもよい。雑談モードは `report` を載せないので対象外でよい

## 決まっていること（蒸し返さない）

- 方針は「Claude に題を付けさせて `renameSession` で書く」（2026-09-24 ユーザー決定。見出しの選び方を賢くする案・`<select>` をやめる案は採らなかった）
- 題は `MAX_HEADING_LENGTH`（24字）に収まる長さで付けさせる

## 解くべき論点

- 付ける契機: 最初の `report` で1回だけか、論点が変わったら付け直してよいか（`/loop /next-task` のように1セッションで複数タスクを進む場合がある）
- `/rename` の題と tsukumo が書いた題は、どちらも `customTitle` に入るので SDK の値だけでは区別できない。tsukumo が最後に書いた題を覚えておいて見比べる、などの見分け方を決める

## やること

前提を確かめ直した（コードは 2026-09-25 時点のまま生きている。`docs/history/tasks.md` に
「追加のモデル呼び出しはしない」という 2026-09-23 の古い決定が残っているが、これは 2026-09-24 に
本タスクの方針で上書き済み——「決まっていること」のとおり蒸し返さない）。`report` ツールに任意の
`title` を足す形で実装する。

- `src/shared/session-choice.ts`: 見出しの上限（いま `session-switch.tsx` に private な
  `MAX_HEADING_LENGTH = 24` として重複しうる）を `MAX_SESSION_HEADING_LENGTH` として export し、
  `session-switch.tsx` 側はそれを import して使う（表示側の切り詰めと、モデルに指示する長さの
  両方が同じ値を指すようにする）
- `src/server/core/session-title.ts`（新規）:
  - `decideSessionTitle(state, candidate, currentTitle)`: 純粋な判断。`candidate` を
    `MAX_SESSION_HEADING_LENGTH` に切り詰め、**それが SDK 側の現在値（`currentTitle`。
    `customTitle`）と同じなら書かない**、**`currentTitle` が「無い」でも「tsukumo が最後に書いた
    もの」でもなければ（＝ `/rename` などで利用者が書き換えたと見なし）書かない**、それ以外は
    書く、の3分岐。状態は `{ lastWritten: string | undefined }` だけを持ち回る
  - `createSessionTitleIntake()`: `report` の handler から届いた `title` を1件だけ覚え、
    ターンの終わりに1回だけ取り出す（`note` / `take`）。合否は呼び出し側で見て、通った
    `report` のときだけ `note` を呼ぶ
  - テストは `test/server/core/session-title.test.ts` に置く（3分岐＋切り詰め＋intake の
    note/take を純粋関数のテストとして守る。会話の実物は使わず、架空の文字列だけ使う）
- `src/server/adapter/sdk-session.ts`: `createSessionTitleWriter()` を足す。`scheduleMarkSession`
  と同じ `SESSION_TAG_DELAY_MS` だけ遅らせてから `getSessionInfo` で現在の `customTitle` を読み、
  `decideSessionTitle` の判断に従って `renameSession` を呼ぶ（呼ぶのはここだけ。原則3）。**遅らせる
  理由も `scheduleMarkSession` と同じ**（本体がターンの終わりに書く自分の要約と競合するため）。
  失敗は諦める（`markSession` と同じ形）。状態（`lastWritten`）はこの writer のクロージャに
  閉じ込め、呼び出し側には見せない（「引数の入れ物を書き換えない」規約を、可変な参照を
  渡し合う形ではなく、`ReportGate`/`ReportReview` と同じ「工場関数が閉じ込める」形で守る）
- `src/server/adapter/sdk-tool.ts`: `reportTool` の zod スキーマに任意の `title` を足し、通った
  （`isError` でない）ときだけ渡された `onReportTitle` へ渡す。`tsukumoServer` の引数に
  `onReportTitle: (title: string) => void` を足す（仕事のときだけ効くが、生成自体はいつもと同じ
  無条件でよい）
- `src/server/adapter/sdk-driver.ts`: `startSdkDriver` で `titleIntake` /
  `titleWriter` を1つずつ作り、`tsukumoServer` へ `titleIntake.note` を渡す。`relayMessages` に
  両方を渡し、`turn-finished` で `scheduleMarkSession` を呼んでいるすぐ側で
  `titleIntake.take()` を見て、値があれば `titleWriter.schedule(sessionId, title, options)`
  を呼ぶ
- `report` ツールの `title` 引数の説明文に「見出しにする短い題。話の中心がはっきりした最初と、
  大きく変わったときだけ渡す」といった条を書く（人格ではなくここに書く。「注意」参照）

**契機の論点**は「`report` が `title` を渡したときだけ」に倒す（毎回渡す必要はなく、モデルの
判断に任せる）。**見分け方の論点**は「tsukumo が最後に書いた題」を writer の中で覚えて
`currentTitle` と比べる形で解く（上記）。

## 注意

- `sdk-session.ts` の `SESSION_TAG_DELAY_MS` のコメントにあるとおり、本体はターンの終わりにセッションの要約を自分で書き、その直後に付けた印は消えた実測がある。`renameSession` も同じ競合を受けるかを確かめ、受けるなら印と同じく遅らせる／付け直す
- 会話の中身（題そのものを含む）をログに全文で出さない（`docs/coding-standards.md`「会話内容の扱い」）
- 題を付ける指示は人格ではなく tsukumo 側の条（`report-tool.ts` など）に書く

## 目的

T-562・T-563 で受け入れのときに直した2つの罠を規約に書き、次に同じ形のコードを書くサブエージェントが最初から避けられるようにする。

## 完了条件

- `docs/coding-standards.md` に次の2項目が入っている（置く節は着手時に決め、言い回しは合わせてよい）
  - **`bun test` はプロセスのタイムゾーンを UTC にして走らせる**（`process.env.TZ` は未設定のまま、`Temporal.Now.timeZoneId()` が `UTC` を返す。2026-09-25 に実測）。日付の境目を見るテストは、オフセットを `+09:00` のように固定せず、`Temporal.Now.timeZoneId()` を基準に時刻を組む。候補は「テスト」節か「`Date` を使わない」節
  - **状態を持つ入れ物（キャッシュなど）を配線から渡すときは、作る側の閉包に閉じ込めて、覚える・引く口だけを渡す**（中の `Map` を型に出して呼び出し先に `.set` させない）。「変数は基本イミュータブル」節の「引数として渡した入れ物が呼び出し先で書き変わる契約にしない」の例として
- 冒頭の「節の索引」と `grep -c '^#\{2,3\} ' docs/coding-standards.md` の節の数が、節を足したときはそれに合わせて揃っている
- `bun run check` が通る

## 背景

2026-09-25 の振り返りで見つけた2件（`docs/history/direction.md` の 2026-09-25「振り返りのドラフト3件」）。

- T-562 で `test/server/adapter/main-history.test.ts` のコミット日時を `+09:00` 固定で組んだら日の境目がずれ、`isoDateAt`（`Temporal.Now.timeZoneId()` 基準）に組み直した。`docs/coding-standards.md` と `docs/architecture.md` に UTC の記述は無い
- T-563 で `src/server/adapter/main-history.ts` の `AchievementCommitCache` が `readonly dailyCounts: Map<string, number>` を型に出し、`readCommitCalendar` の中で `.set` していた。受け入れのときに `dailyCountOf` / `rememberDailyCount` などの口を持つ形（`createAchievementCommitCache` の閉包）に包み直した。設計書が「入れ物は配線で作って渡す」と指定していたことと規約がぶつかる例が、規約に書かれていなかった

## 目的

メモ化を React Compiler に任せ、手で書くメモ化とその判断を部品から消す。

## 完了条件

- React Compiler が `vite.config.ts` の組み立てに入っている（背景の (a)・(b) のどちらかを選び、選んだ理由を結果に書く）
- `src/browser/` の `memo(` / `useCallback(` / `useMemo(` が、Compiler では足りない理由があるものを除いて
  消えている（残したものは理由を1行のコメントで書く）
- `docs/coding-standards.md`「React」節に、手でメモ化しない旨と例外の条件が書かれている
- CLAUDE.md の「`ReactElement` を返す関数は `function` で書く（`const` は `memo` で包むときだけ）」の1行を
  今の形に合わせている
- 検証コマンド（移した後の `check`）が通り、会話の画面でターンが流れている間に描き直しが増えていないことを
  目で見て確かめている

## 背景

- 2026-09-26 に数えた手書きのメモ化は `memo(` 3・`useCallback(` 11・`useMemo(` 2 の 16 か所
- React は 19（`package.json`）。組み立ては `T-684` で Vite になる
- 入っている `@vitejs/plugin-react` 6.1.1 には babel の口が無い。README「React Compiler」（`node_modules/@vitejs/plugin-react/README.md`）が示す道は2つ: (a) `react({ compiler: true })`（Rust 移植の `oxc-transform-react` を任意の peer として足す。README は experimental と書く）、(b) `@rolldown/plugin-babel` と `@babel/core` と `babel-plugin-react-compiler` を足し、`babel({ presets: [reactCompilerPreset()] })` を並べる。t3code の `apps/web/package.json` は (b)（`docs/research/browser-library.md`）

## 注意

- Compiler が最適化を諦めた部品（ルール違反の検出）があれば結果の節に並べる。直すのは別タスクでよい
- テスト（Vitest）側でも Compiler を通すかは、通さなくてもテストの意味が変わらないならそのままでよい

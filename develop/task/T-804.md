ユーザーの着想「タスクの性質ごとに HTML テンプレートを複数用意し、Claude の応答の JSON を埋める。合うテンプレートが無ければ自由形式で書き、その出力からテンプレートへ落とし込める仕組みも持つ」を、**効力が不十分な叩き台とみなして**、それより良いレポートのアーキテクチャを提案する。提案を読んだユーザーが、採る形と実装の段取りを選べる状態にする。

## 解くべき論点

- 「タスクの性質」を誰が決めるか（モデルが種類を選ぶ／tsukumo が依頼や道具の使われ方から推す／決めない）と、選び違えたときの壊れ方
- テンプレートの単位を「レポート全体」にするか、いまの塊より大きい「部品の組」（例: 調査の結論＋根拠の表＋未確認）にするか
- 自由形式の出力からテンプレート（や塊）へ昇格させる判断を、記録の集計で機械的に行えるか
- JSON Schema の大きさ（毎ターン載る道具の定義の字数）とモデルの書き違いの増え方

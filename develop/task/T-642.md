## 目的

雑談の記憶の容量を1つの定数の表に集め、値を書き換えるだけで上げ下げできるようにする（ユーザーの指示）。後段の実装タスクはこの表から値を読む。

## 完了条件

- `src/shared/chat-memory-budget.ts` に `CHAT_MEMORY_BUDGET` の表（`recentBytes`・`synopsisBytes`・`recallListBytes`・`recallListsPerTurn`・`recallEpisodeBytes`・`recallEpisodesPerTurn`・`consolidateEveryBytes` の7つ。値は `docs/design.md` 7章「エピソード索引はどこに置くか」）があり、型 `ChatMemoryBudget` に対して `satisfies` で検査されている。採点の表 `CHAT_RECALL_SCORE` は同じファイルに置くが、足すのは採点を書く後段のタスク
- いまの `src/shared/chat-log.ts` の容量の定数のうち、新しい仕組みでも使うもの（逐語の窓 → `recentBytes`・`recall` の読み戻し → `recallEpisodeBytes`）は表から読むように置き換わり、`chat-log.ts` から消えている。消える口に属する定数（畳む閾値・旗）は、その口を消す後段のタスクが消すので、このタスクでは残してよい
- 表の値を1つ変えたとき、読む側がその値に従うことをテストで確かめている（既存のテストが値を直書きしているなら表から読むように直す）
- `bun run check` が通る

## 背景

- 容量の定数は `src/shared/chat-log.ts` に `CHAT_COMPACT_THRESHOLD_BYTES`・`CHAT_RECENT_READBACK_BYTES`・`CHAT_KEPT_READBACK_BYTES`・`CHAT_RECALL_READBACK_BYTES` が別々の `const` で並ぶ
- 読む側: `src/session-start.ts`（配線）、`src/server/session/core/session-manager.ts`、`src/server/session-driver/core/session-driver.ts`、`src/server/chat/core/chat-memory-prompt.ts`、`src/server/system-prompt/core/system-prompt.ts`、`test/server/session/core/session-manager.test.ts`
- 表の置き場と形の正典は `docs/design.md` 7章「エピソード索引はどこに置くか」、値の根拠は `docs/chat-mode.md` 4.9「記憶の圧縮と忘却」の容量の表

## 決まっていること（蒸し返さない）

- T-641 で正典に入れた目安（`recallListsPerTurn: 2`、採点の半減期30日、`gist` 120字・`cues` 20字の上限、定着のモデルは haiku・時間切れ120秒）はこの値で進める（2026-09-26 ユーザー決定）

## やること

いまのコードで前提を調べ直した結果、背景に書かれた前提はそのまま成り立っている（作業は要る）:

- `src/shared/chat-log.ts` には背景どおり4定数が並んでいた。**このうち新しい仕組みでも使うのは
  `CHAT_RECENT_READBACK_BYTES`（→ `recentBytes`）と `CHAT_RECALL_READBACK_BYTES`
  （→ `recallEpisodeBytes`）の2つだけ**。`CHAT_COMPACT_THRESHOLD_BYTES`（畳む閾値）と
  `CHAT_KEPT_READBACK_BYTES`（旗）は `/compact` と `keep` の口が残っているあいだは読む側
  （`session-start.ts` の `chatCompactThresholdBytes`、`system-prompt.ts` の `keptBytes`、
  `session-manager.ts`・そのテスト）が生きているので、完了条件どおり**このタスクでは残す**
- `session-manager.ts` とそのテストが読むのは `CHAT_COMPACT_THRESHOLD_BYTES` だけで、これは表に
  移らない定数なので**この2ファイルは変更不要**（背景の「読む側」一覧に載っているが、触るのは
  他の4ファイル）
- `session-driver.ts`・`chat-memory-prompt.ts` は定数を import せず、doc コメントの文中に
  `CHAT_RECENT_READBACK_BYTES` / `CHAT_KEPT_READBACK_BYTES` の名前を書いているだけ
  （型 `ChatReadbackLimits` の説明）。名前を挙げている先が消えるので、コメントの参照先を
  `CHAT_MEMORY_BUDGET.recentBytes` に直す
- `CHAT_RECALL_SCORE` 用の型 `ChatRecallScore` はまだ無い（後段タスクの担当。今回は作らない）
- 既存テストで値を直書きしていたのは `test/server/system-prompt/core/system-prompt.test.ts` と
  `test/server/chat/core/chat-memory-prompt.test.ts`（`{ recentBytes: 65_536, keptBytes: 8_192 }`）
  の2ファイル。表から読むように直し、`toSystemPromptMode`（表から実際に読む生産コード側の関数）
  を直接呼ぶテストも1本足して、表の値を変えたら読む側が従うことを確かめる

## 注意

- 値の根拠は doc コメントに二重に書かず、`docs/chat-mode.md` 4.9 を指すだけにする
- 表は `shared` に置く（ブラウザは読まないが、サーバの複数の機能と配線が読む。正典で決着済み）
- 表から導ける値（定着の1回の入力 = `consolidateEveryBytes * 2`）は定数にしない
- まだ読む側の無い鍵（`synopsisBytes` など）も表には置く。読むように直すのは後段

## 結果

- 検証コマンド: 2712 pass / 0 fail（±0。`toSystemPromptMode` が表を読むテストを1本足した）
- `chat-log.ts` に残した `CHAT_COMPACT_THRESHOLD_BYTES`・`CHAT_KEPT_READBACK_BYTES` は、`/compact`・`keep` の口を消す後段のタスクが消す
- 振り返り: 受け入れのときにメインが直したもの（やることに無い仕事モードのテストを外した。ドラフト 0件）

## 背景

2026-09-24 に `/simplify` の4観点（再利用・単純化・効率・根本対処）でリポジトリ全体を洗った結果の1件（`docs/history/direction.md` の 2026-09-24「改修コストを下げる直し9件」）。

`src/server/adapter/repository-file.ts` の `listRepositoryFiles`（入力欄の `@` 補完。`git ls-files -z`）は、`node:child_process` の `execFile` を自前で呼び、上限の定数 `LIST_TIMEOUT_MS`（5000）と `MAX_OUTPUT_BYTES`（16MiB）も自前で持っている。`src/server/adapter/git.ts` の `runGit` は同じ値（`GIT_TIMEOUT_MS` / `MAX_OUTPUT_BYTES`）で同じ呼び出しをし、失敗を `failed` / `timed-out` で返す。git を起こす場所が2つあるので、上限の方針を変えるときに2箇所を合わせる必要がある。

`test/architecture.test.ts`「子プロセスを起こす箇所」は `node:child_process` を import してよいファイルを `orca-host.ts`・`bundle.ts`・`repository-file.ts`・`git.ts` の4つに絞っている。`docs/architecture.md` の表と `docs/design.md` のディレクトリ図は `repository-file.ts` を「`git ls-files` を起こす唯一の場所」と書いている。

## やること

1. `listRepositoryFiles` を `runGit(cwd, ["ls-files", "-z"])` で書き、`output` 以外は空を返す。自前の上限の定数と `node:child_process` の import を消す
2. `test/architecture.test.ts` の許可から `repository-file.ts` を外し、テスト名と上のコメントの「4つの境界」を直す
3. `docs/architecture.md` と `docs/design.md` の `repository-file.ts` / `git.ts` の説明を直す（`git.ts` が git を起こす唯一の口になる）

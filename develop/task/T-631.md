## 目的

`scripts/serve-revision.ts` で取り出した変更前のリビジョンでも、`main` の履歴を読む成果の画面が出るようにし、変更の前後を撮り比べられるようにする。

## 完了条件

- 取り出し先で起こした tsukumo の成果の画面が「main が読めない」にならず、履歴を表示する（目視で確かめ、何が見えたかをタスクの結果に書く）
- 本体のリポジトリの `.git` を書き換えない（読むだけで済む形にする）
- `docs/architecture.md`「手で確かめること」の撮り比べの段落を、新しい挙動に合わせる
- `bun run check` が通る
- 調べて前提が成り立たなければ、理由を書いて `dropped` で閉じてよい

## 背景

- `scripts/serve-revision.ts` は、いま居る作業ツリーの `node_modules` を symlink で貸している（133〜141行目あたり）が、`.git` は貸していない
- T-597 のサブエージェントが変更前の成果の画面を撮ろうとしたら、取り出し先に `.git` が無いため画面が出ず、本体の `.git` への symlink を手で張って比べた

## やること

- 前提を確認した: 成果の画面が読む `main` の履歴は `src/server/achievement/adapter/main-history.ts` の `mainHeadCommit`（`git rev-parse --verify refs/heads/main^{commit}`）から始まり、`runGit(process.cwd(), ...)`（`src/server/repository/adapter/git.ts`）を経由する。`process.cwd()` は `serve-revision.ts` が `spawn(..., { cwd: revision.treeDir })` で起こすため `revision.treeDir` になり、そこに `.git` が無いので `rev-parse` が失敗 → `{ kind: "unknown" }`（背景の症状どおり再現した）
- `src/server/repository/adapter/git.ts`（`node:child_process` を import してよい唯一のファイル。`test/architecture.test.ts` が絞る）を経由する `git` 呼び出しを `grep` で洗い出した結果、`rev-parse` / `log` / `ls-tree` / `rev-list` / `cat-file --batch` / `ls-files` のみで、書き込み系のコマンドは無い。よって取り出し先の `.git` を「いま居る作業ツリーの `.git` への symlink」にしても、本物の index・ref・working tree を書き換える呼び出しは無い
- いま居る作業ツリー自体が linked worktree（`.git` はディレクトリではなく `gitdir: <絶対パス>` を指すファイル）だが、symlink はファイルでもディレクトリでも指せるので `node_modules` と同じ手法がそのまま使える
- 前提は崩れていなかった。対応: `scripts/serve-revision.ts` に `lendGitDirectory` を足し、`lendNodeModules` と同じタイミング（`extractRevision` の末尾）で `.git` を symlink で貸す。`docs/architecture.md`「変更前と撮り比べる」の該当段落を更新する

## 結果

- 検証コマンド: 2712 pass / 0 fail
- 取り出し先に `.git` を symlink で貸した（駆動は fake 固定で、取り出し先の `git` は読むだけ）。サブエージェントが 39001 番で起こし、成果の画面に「終えたタスク 4」「コミット 8」と灯りの暦が出るのを目視した
- 振り返り: 同じファイルを3回以上直した（コメントに書いたタスク番号を検査が落とした分。仕組みが効いたのでドラフト 0件）

## 目的

フラットに50ほどのファイルが並んでいる `src/shared/` を、`src/server` と同じく機能ごとのまとまりに割る形を決め、正典に書く（2026-09-27 ユーザーの指示。移設は後段）。

## 完了条件

- `docs/design.md` の置き場の章（`src/server` の「サーバの機能と、機能どうしの辺」と並ぶ位置）に、`src/shared/` の割り方（ディレクトリの名前・何を置くか・`contract/`・`lib/`・`utils/` との関係）を書いている
- 各ファイルの移し先の対応表を後段のタスク（T-732）の背景に書き、実装の広がり（ファイル数・import の数・検査の変更）を見て後段の `difficulty` を見直す
- 割り方を `test/architecture.test.ts` で守るかを決め、守るなら後段の完了条件に入れる
- `bun run check` が通る

## 背景

- 登録時の `src/shared/` 直下: 約50ファイル（`achievement.ts`・`character-*.ts`・`report-*.ts`・`session-*.ts`・`turn-*.ts`・`token-usage*.ts` など）と `contract/`（機能ごとの orpc 契約11ファイル）・`lib/`（`byte-length.ts`）・`utils/`（`optional-string.ts`）
- `src/server` は `src/server/<機能>/{core,adapter}/` で、機能の名前は `achievement` / `chat` / `report` / `session` / `token-usage` など（`docs/design.md`「サーバの機能と、機能どうしの辺」）。`contract/` はすでに同じ機能の名前で割れている

## 解くべき論点

- 機能の名前を `src/server` と揃えるか（`shared/<機能>/` に契約も寄せるか、`contract/` を残すか）
- どの機能にも属さない語彙（`frame.ts`・`rpc.ts`・`command.ts` など）の置き場
- ブラウザ側（`src/browser/`）の置き場との対応をどう書くか

## やること

いまのコードで調べ直した前提（2026-09-27）:

- `src/shared/` 直下は54ファイル。`contract/` は12ファイル（登録後に1つ増えた）。`lib/` は T-722 で `utils/` に寄り、いまは `utils/`（`byte-length.ts` `optional-string.ts`）だけ。`test/architecture.test.ts` の `SHARED_DIRECTORIES` は `contract` `lib` `utils` を許している
- `shared` の中の相対 import を機能の単位で束ねると、`session-state.ts` / `session-event.ts` がほぼすべての語彙を読む（サーバの `session/` と同じ「束ねる」形）。直下に残す候補の `frame.ts` は `session-state.ts` を読み、`command.ts` は `frame.ts` を読む
- `contract/` のファイル名は手続きの名前（`rpc.ts` の鍵・`server/<機能>/adapter/<名前>-procedure.ts`）で、機能の名前と1対1ではない（`session-digest` は `session/`、`frame` は `view-server/` の手続き）
- 移すと `src/`・`test/`・`scripts/` の相対 import が約630行・約300ファイル、コメントのパスが約210行、`docs/`（`history/` を除く）のパスが約120か所動く

やること:

1. `docs/design.md` 2章の「サーバの機能と、機能どうしの辺」の後ろ（「ディレクトリ」の前）に `### shared の機能` を足し、割り方（機能の名前・機能の決め方・直下と `contract/` `utils/` `lib/` の役割・ブラウザ側との対応）を書く。同じ章の「ディレクトリ」の木と「`lib/` と `utils/` に置く基準」の判定1、2章の索引の行を合わせる
2. T-732 の `## 背景` に各ファイルの移し先の対応表を書き、広がりと `difficulty` の見直し案、`test/architecture.test.ts` に足す検査を完了条件に書く
3. `pnpm run check` を通す

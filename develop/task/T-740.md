## 目的

CSS Modules の型の生成を、保守が止まった `happy-css-modules` から後継の css-modules-kit（`@css-modules-kit/codegen`）へ移す。

## 完了条件

- 依存を `happy-css-modules` から `@css-modules-kit/codegen` に入れ替え、`happy-css-modules` を外す
- `package.json` の `css-types` を `cmk` の呼び出しにし、`build` と `typecheck` から今と同じ順で呼ばれる
- `tsconfig.json` に `cmkOptions` を足し、`rootDirs` を生成先に合わせ、`include` が `*.module.css` を含む
- CSS に無い class 名を `styles["..."]` で引くと `bun run typecheck` が型エラーになることを確かめる（確かめたら元に戻す）
- `docs/design.md` の `styles["..."]` の型を述べた箇所を css-modules-kit に合わせる
- `bun run check` と `bun run build` が通る
- 最初に `cmk` が Bun の実行環境（`bun run`）で動くかを確かめる。動かず回避策も無いなら、分かったことを `docs/research/css-modules-kit.md` に足し、依存を戻して `dropped` で閉じてよい

## 決まっていること（蒸し返さない）

- 移す（2026-09-27 ユーザー決定。`docs/research/css-modules-kit.md` の推奨を承認）
- 依存の入れ替えはユーザーが承認済み（2026-09-27 ユーザー決定）
- Vite への移行とは依存し合わないので、どちらを先にしてもよい

## 背景

- 今の `package.json`: `"css-types": "hcm 'src/**/*.module.css' --outDir dist/css-module-type --logLevel silent"`。`build` と `typecheck` の頭で `bun run css-types` を呼ぶ
- 今の `tsconfig.json`: `"rootDirs": [".", "dist/css-module-type"]`、`include` は `src/**/*.ts` などの拡張子限定。css-modules-kit の get-started は、`include` に `*.module.css` が入らない形を避けるパターンに挙げている
- `docs/design.md` の2397行あたりに `happy-css-modules` と `dist/css-module-type/` の説明がある
- 調べた結果（仕組み・保守の状況・確かめていないこと）は `docs/research/css-modules-kit.md`
- `@css-modules-kit/codegen` の `engines.node` は `>=22.12.0`

## 注意

- エディタ用の `@css-modules-kit/ts-plugin` はこのタスクに入れない（エディタへの導入は人がやる）
- class 名はキャメルケースへ変換しない方針のまま（css-modules-kit も変換しない）

## 目的

キャラクターが古い雑談を2段階で引けるようにする。`recall(言葉)` はエピソードの候補の一覧を返し、`recall_episode(id)` がその1件の逐語を返す。索引はもう定着が書くので、キャラクターが書く `index` と、`weight` に吸収される `keep` を消す。

## 完了条件

- 雑談モードのとき、`recall` が候補の一覧（`id`・`title`・`gist`）を、`recall_episode` が1件の逐語を返す。量（`recallListBytes`・`recallEpisodeBytes`）と1ターンの回数（`recallListsPerTurn` = 2・`recallEpisodesPerTurn` = 2）は容量の表に従うことをテストで確かめている。当たらない・知らない `id`・回数を超えたときは短い一言だけで、会話の文面を返さない
- `index` と `keep` のツール、その口（`ChatRecall` の `index`・`ChatKeep`・`ChatArchive` の `keep`・`writeIndex`）、`index.jsonl` を読み書きするコードと `kept.jsonl` へ書くコードが消えている（`kept.jsonl` を読む `readRecent` の旗のぶんと `systemPrompt` の旗の節は、`/compact` をやめるタスクが消す）
- 作法の条（`src/server/chat/core/chat-manner.ts`）とツールの説明が、2段階の引き方に合わせて書き直されている
- `docs/display.md` 4.2 と `docs/architecture.md`（ツールの一覧の行・「戻り値は `"ok"` だけにする」の節）の「戻り値が `"ok"` だけではないツール」の数え方とツールの数を、`recall_episode` を足し `keep`・`index` を消して直している
- `bun run check` が通る

## 背景

- ツールの定義は `src/server/session-driver/adapter/sdk-tool.ts`（`KEEP_TOOL_NAME`・`INDEX_TOOL_NAME`・`RECALL_TOOL_NAME`）
- `recall` の戻り値の文面は `src/server/chat/core/chat-memory-prompt.ts` の `chatRecallText`
- 口の型は `src/server/session-driver/core/session-driver.ts`
- 正典: `docs/chat-mode.md` 4.9「古い雑談は索引を引いて思い出す」、`docs/design.md` 7章「エピソード索引はどこに置くか」

## やること

前提を調べ直した結果（2026-09-26 時点）:

- `src/server/chat/adapter/chat-archive.ts` の `ChatArchive.recallList` / `recallEpisode`
  （エピソード索引を採点・開く側）は T-645 までで既に実装済み。`episode.jsonl` /
  `recalled.jsonl` の読み書きもできている。**このタスクで新しく作るのは「ツールの口」側**
  （`recallList` / `recallEpisode` を1ターンの回数で縛り、MCP ツールとして出す層）だけ
- 一方 `ChatArchive.writeIndex` / `ChatArchive.recall`（旧・日ごとの索引を引く1段の実装）と
  `ChatArchive.keep`（「残す」旗を書く実装）、`sdk-tool.ts` の `index` / `keep` ツールは
  まだ残っている。`ChatRecall`（`session-driver/core/session-driver.ts`）も旧形（`index` /
  `recall`）のまま。`src/session-start.ts` の `chatRecallFor` も旧 `ChatArchive.recall` を
  呼んでいる
- 1ターンの回数の上限（`recallListsPerTurn` = 2 / `recallEpisodesPerTurn` = 2）を数える場所が
  まだ無い。`docs/design.md` 7章「エピソード索引はどこに置くか」の指定どおり `chat/core/` に
  新しいファイル（`chat-recall.ts`）を作り、`ChatArchive.recallList` / `recallEpisode` を
  回数で包む
- `ChatArchive.keep` を消すと、`ChatArchive.finishTurn`（`session-manager.ts` がターンの終わりに
  呼ぶ）の中身が空になる（もともと「残す」旗の書き込みと、旧 `index` / `recall` の1ターン
  1回の判定をリセットするためだけの関数だった。後者も本タスクで消える）。**`finishTurn` は
  このタスクの完了条件に明記されていないが、消さずに残すと呼び出されるだけの空関数が残る**ので、
  `ChatArchive.finishTurn` 自体・`session-manager.ts` の呼び出し・関連テスト（アーカイブへの
  合図を確かめるテスト2件）も一緒に消す
- 新しい `ChatRecall`（`recallList` / `recallEpisode` / `finishTurn`）のターンの区切りは、
  `PersonaMemory.finishTurn` と同じ呼び出し口（`sdk-driver.ts` の `turn-finished` 分岐）に
  相乗りさせる（`docs/design.md` 7章の「ターンの終わりの合図は今の finishTurn に相乗りする」）

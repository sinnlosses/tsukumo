## 目的

画面から effort を切り替えられるようにする前段として、SDK 0.3.280 で「セッションの途中で effort を変える」「いま効いている effort を外から読む」の2つが実機で成り立つかを確かめ、その結果で `docs/requirements.md` 4.1 の「effort を画面の要素にしない」を書き直すか保つかを決める。

## 完了条件

- 本物の claude を SDK で起こし、`applyFlagSettings({ effortLevel })` で途中から effort を変えたとき、次のターンで効いている値が変わるかを実測し、`docs/history/decision.md` の「effort が外から観測できないことの実測」の近くに日付つきで記録している（打った手順と、読めた値の形だけ。会話の中身は書かない）
- **2つとも成り立ったとき**: `docs/requirements.md` 4.1 の effort の段落を「帯から切り替えられる。表示するのは読み取った値」に書き直し、`docs/screen-design.md` 13.9（帯）と 13.6（設定の置き場所）に effort の置き場所（下の「決まっていること」）を書き足している
- **どちらかが成り立たなかったとき**: 4.1 の決定を保ち、成り立たなかった実測を 4.1 から `docs/history/decision.md` へ指す1行を足す。後ろに続く2件（帯のドロップダウン・歯車の既定）は `dropped` で閉じてよい、とタスクの結果の節に書く
- コードは変えない（実測に使った使い捨てのスクリプトはコミットしない）
- `bun run check` が通る（節の参照の検査を含む）

## 背景

- いまは `src/server/adapter/sdk-driver.ts:64` の `DEFAULT_EFFORT = "medium"` を `query()` に渡すだけ。`docs/requirements.md` 4.1 に「effort は外から観測できない（`init` に無く、`setModel` はモデル名しか取らない。2026-09-12 の実測、`docs/history/decision.md` 220行目）ので画面の要素にしない」とある
- `node_modules/@anthropic-ai/claude-agent-sdk/sdk.d.ts`（0.3.280）の型には次がある:
  - 変える口: `Query.applyFlagSettings({ effortLevel })`（2798行目。`low`〜`xhigh`、`max` はセッション限り。`null` でモデルの既定へ戻る）。tsukumo はすでに `applyFlagSettings({ outputStyle })` を使っている（`sdk-driver.ts:399`）
  - 読む口の候補: hook の入力の `effort`（189行目。`Stop` など道具の文脈で発火する hook に載り、`{ level }` の形。モデルが対応していないときは無い）。tsukumo は仕事のときに `Stop` フックを登録している（`sdk-driver.ts` の `report` の関所）。ほかに制御要求 `get_settings` の `applied.effort`（4046・5719行目）があるが、`Query` の公開メソッドには出ていない
  - 対応の有無: `Query.supportedModels()` の `ModelInfo` にモデルごとの effort 対応と選べる段（1341・1345行目）

## やること

前提の調べ直し（2026-09-25）:

- SDK は `node_modules/@anthropic-ai/claude-agent-sdk` の `0.3.280`（背景に書かれたバージョンと一致）
- `sdk.d.ts` 2798行目 `Query.applyFlagSettings`: `effortLevel` は `EffortLevel | null` を受け、`'max'` はセッション限り（設定ファイルへ書かれない）。JSDoc に「`effortLevel` はモデルの既定の effort へ戻す」ともある
- `sdk.d.ts` 189行目 `BaseHookInput.effort?: { level: string }`: 「tool-use context（PreToolUse, PostToolUse, Stop, SubagentStop など）で発火する hook に、その model が effort に対応していれば載る。セッション寿命の hook（session-lifecycle）には載らない」と明記。tsukumo は仕事のときに `Stop` フックを登録済み（`reportGateHooks`、`sdk-driver.ts:327` 付近）なので、生のプロセスを起こさずとも読み口は既にある形
- `sdk.d.ts` 2858行目 `Query.supportedModels(): Promise<ModelInfo[]>`。`ModelInfo` は `supportsEffort` / `supportedEffortLevels` を持つ（1341・1345行目付近）が、**いま効いている値ではなく対応の有無・選べる段だけ**
- `get_settings`（4046行目）はプロトコルの `subtype` としてのみ型に出ており、`Query` の公開メソッド一覧（`applyFlagSettings` / `updateSettings` / `initializationResult` / `supportedModels` など）には `getSettings` に相当するものが無い。5719行目の `effort` フィールドは Remote Control ブリッジの init フレーム（Desktop/VS Code 等のホスト向け）のものと明記されており、`query()` を素で使う tsukumo の経路には無い
- `src/server/adapter/sdk-driver.ts:78` の `DEFAULT_EFFORT: EffortLevel = "medium"` は `buildQuerySeedOptions`（256行目）で `query()` の `effort` に渡すだけ。`applyFlagSettings` は現状 `outputStyle` だけに使っている（`applyNeutralOutputStyle`、444行目付近）。effort を変える呼び出しはまだ無い
- `docs/requirements.md` 4.1: 「`effort` は `query()` に渡すだけで、画面には出さない。**effort は外から観測できない**（実測は `docs/history/decision.md`）ので、画面の切り替えで保たれるかは分からない。分からないことを前提に、effort を画面の要素にしない」
- `docs/history/decision.md` 220行目「effort が外から観測できないことの実測」（2026-09-12）: 「`init` のシステムメッセージに `effort` は無く、`setModel` はモデル名しか取らない」— この実測はモデル切り替えの口（`setModel`）と `init` イベントしか見ていない。**hook 入力の `effort`（`sdk.d.ts` 189行目）はこのとき調べた形跡が無い**ので、今回はそこを実測の主眼にする

実測の手順（本タスクで行うこと）:

1. スクラッチに使い捨てスクリプトを置き、`query()` をストリーミング入力モードで起こす（`persistSession: false`、`cwd` はスクラッチ、ツールは最小、`hooks.Stop` を登録して届いた `input.effort` を記録）
2. 1ターン目「ok とだけ答えて」を送り、`Stop` hook で読めた `effort` の形を記録する
3. `session.applyFlagSettings({ effortLevel: <1ターン目と違う段> })` を呼ぶ
4. 2ターン目を送り、`Stop` hook で読めた `effort` を記録する
5. (a) 成立の判定は「2ターン目の `effort.level` が `applyFlagSettings` に渡した段に変わって見えたか」。(b) 成立の判定は「読み口（hook の `effort`）が存在し、値の形が読み取れるか」。**(b) は (a) の手段でもある**ため、2つの完了条件は同じ実測から同時に判定できる
6. ログには打った手順（呼び出しと引数）と読めた値の形（`{ level: "..." }` のような形・実際の段名）だけを残し、応答本文・ツールの入出力は記録しない

## 決まっていること（蒸し返さない）

2026-09-25 のユーザーの判断:

- effort の切り替えは**帯のモデルのドロップダウンの隣に、別のドロップダウンで置く**（モデルの選択肢に混ぜない）。並びはモデル → effort → 許可モード
- **新しいセッションの既定（帯の右端の歯車・`~/.tsukumo/state.json`）にも effort を覚えさせる**
- **効いている値を外から読めないなら出さない**（送った値を画面に出すだけの形は採らない）。そのときは 4.1 の決定を保つ

- 検証コマンド: 2626 pass / 0 fail（±0。docs のみ）。SDK 0.3.280 の実機で、`applyFlagSettings({ effortLevel })` で途中から変えると次のターンの `Stop` hook 入力の `effort` が `{ level: "low" }` → `{ level: "high" }` に変わった。2つとも成り立ったので 4.1 を書き直し、13.9・13.6 に effort の置き場所を足した。後続の2件は dropped にしない

## 目的

雑談のターンの終わりに、作業記憶の窓から溢れた未定着の行が溜まっていたら定着の `query()` を背景で1本だけ走らせ、返ってきたエピソードとあらすじをディスクに書く。サイドバーの「最近の話題」もあらすじから出す。

## 完了条件

- 雑談モードのターンの終わりに、未定着の行が容量の表の量以上あるときだけ定着が走る。同時に走るのは1本だけで、走っているあいだの契機は捨てる（次のターンの終わりにまた数える）ことをテストで確かめている
- 定着が失敗しても常駐プロセスは落ちず、行は未定着のまま残って次の契機で拾い直される
- 返ってきたエピソードが索引に追記され、そのあとであらすじが `~/.tsukumo/chat-summary/<パック名>.md`（いまの写しと同じファイル・同じ口 `ChatSummary.write`。印は「渡し済み」）に上書きされる。本文の最後に tsukumo が `<topics>` の組を置き、上限は `synopsisBytes`。書いた直後のファイルから取った「最近の話題」（`chat-topics-changed`）が画面に届く
- 前のあらすじとして同じファイルの本文（印の行と `<topics>` の組を除く）を渡す。初めての定着ではこれが `/compact` の写しになり、種に使うのは構造上1回だけになる（別の移し替えは作らない）
- `PostCompact` のフックであらすじのファイルへ写すこと（`sdk-driver.ts` の `chatSummaryHooks`）と、そこから流していた `chat-topics-changed` をやめている（書き手を定着の1つにする。`/compact` を投げること自体は後段が消す）
- 仕事モードと疑似セッション（`TSUKUMO_DRIVER=fake`）では定着が走らない
- `bun run check` が通る

## 背景

- ターンの終わりの扱いと、いまの `/compact` の見張りは `src/server/session/core/session-manager.ts`（`tally.chatCompact.add` / `requestIfNeeded`、`createChatCompactWatch` は `src/server/chat/core/chat-compact.ts`）
- 話題の取り出しは `src/server/chat/core/chat-compact.ts` の `chatTopics` / `readChatTopics`、画面へは `chat-topics-changed`（いまは `src/server/session-driver/adapter/sdk-driver.ts` の `chatSummaryHooks` の `PostCompact` から出る）
- 要約の写しは `src/server/chat/adapter/chat-summary.ts`
- 配線は `src/session-start.ts`
- 正典: `docs/chat-mode.md` 4.9「窓から溢れた会話は定着で畳む」、`docs/design.md` 7章「定着はどこで走るか」「雑談の記憶の要約はどこに置くか」

## 解くべき論点

- 背景で走る定着と、次のターン・パックの切り替え・プロセスの終了が重なったときの扱い。正典は「待たない・書きかけで止まれば追記済みまでが定着・遅れて届いた結果は届いた側のパックのファイルに書き、話題を流すのは今のパックと同じときだけ」と決めた。これを `session-manager` の作り直し（起こし直し）とどう噛み合わせるか
- 溜まったぶんは「1ターンの終わりに1回・1回の入力は契機の2倍まで」で自然に抑えられる（正典で決着済み）。走り終えても次のターンの終わりまで次を起こさないことをテストで確かめる

## やること

前提の調べ直し: T-643（呼び出し側の前段）と T-644（`chat/core/chat-consolidation.ts`・
`chat/adapter/sdk-chat-consolidation.ts`）は済んでいる。`ChatArchive.unconsolidated` /
`appendEpisodes` はあるが、**直前のエピソードの見出しを読む口が無い**（`unconsolidated` は最後の
エピソードの `to` を読んでいるのに、見出しを返していない）。`/compact` の見張り
（`createChatCompactWatch`）と `PostCompact` の写し（`sdk-driver.ts` の `chatSummaryHooks`）はまだ
動いている。`session-manager` は1プロセスに1つで、起こし直しでは作り直さず代（`SessionGeneration`）
だけを作り直す。前提は崩れていないので作業する。

- `ChatUnconsolidatedBatch` に `previousEpisodeTitle`（無ければ空文字）を足し、`chat-archive.ts` の
  `readUnconsolidated` が同じ読みで返す
- `chat/core/chat-compact.ts`（`<topics>` の印を持つファイル）に、あらすじの本文の最後へ話題の組を
  置く関数と、写しの本文から話題の組を除く関数を足す（組を書く側と読む側を同じファイルに保つ）
- `chat/core/chat-consolidation-writer.ts` を新しく作る（`visit-script-writer.ts` と同じ形）。
  パック名と中断の信号を受け、(1) `unconsolidated`（窓 = `recentBytes`、上限 =
  `consolidateEveryBytes` の2倍）で数え、契機に届かなければ `not-due` (2) 届いていれば前のあらすじ
  （話題の組を除いた本文）と直前の見出しを添えて `query()` を起こし（時間切れ 120 秒を合成）
  (3) 検査を通ったらエピソードを追記 → あらすじ＋話題の組を `ChatSummary.write`（印は渡し済み）
  (4) 書いたあとのファイルから `readChatTopics` で取った見出しを返す。起こせない・中断・時間切れ・
  形の崩れはどれも `failed` で、reject しない。中断のあとに結果が届いても書かない。出どころは
  `consolidate` / `dont-consolidate` の合併型（疑似セッションは後者）
- `session-manager` に出どころを渡し、**雑談の駆動由来の `turn-finished` のときだけ**、走って
  いなければ1本起こす。**走っているかどうかの1ビットは代ではなく `session-manager` が持つ**
  （起こし直しをまたいでも同時に1本。同じパックへ起こし直した直後に同じ行を2本で畳まない）。
  待たずに次へ進み、書けたら**そのときの状態が雑談で同じパックのときだけ** `chat-topics-changed`
  を今の代へ流す。`close` で走っている1本を中断する
- `chat-summary.ts` の上限を `CHAT_MEMORY_BUDGET.synopsisBytes` にする
- `sdk-driver.ts` の `chatSummaryHooks`（`PostCompact` の写しと `chat-topics-changed`）をやめる
- 配線 `src/session-start.ts`: 本物の駆動のときだけ `consolidate`（`queryChatConsolidation` を
  引き継いだ `cwd`・環境で起こす）
- テスト: 書き手（数えて契機に届かないと起こさない・書く順と中身・崩れた出力と失敗と中断で書かない）、
  `session-manager`（雑談のターンの終わりだけ・同時に1本で契機を捨てる・走り終えても次のターンの
  終わりまで起こさない・失敗しても落ちず次で拾い直す・仕事では起こさない・話題を流す条件）、
  `chat-archive` の `previousEpisodeTitle`。`chatSummaryHooks` のテストは消す
- 正典の追随: `docs/design.md` 7章の「起こし直しで作り直した `session-manager` は…」の記述を、
  ビットを代の外に持つ形に合わせる

## 注意

- `/compact` を投げる見張りを消すのは後段のタスク。このタスクのあいだは `/compact` が走り続けてよい（写しを取らないので、あらすじを書くのは定着だけになる）
- 会話の文面をログ・stderr・`error` フレームに出さない

## 結果

- 検証コマンド: 2739 pass / 0 fail（+6）、E2E 15 pass / 0 fail（受け入れの1回目は E2E「入力欄から送る」が落ち、打ち直しで通った）
- 雑談のターンの終わりに `session-manager` から定着を背景で1本だけ起こし、エピソード → `<topics>` つきのあらすじの順に書く（`chat-consolidation-writer.ts`）。失敗・時間切れ・中断では何も書かず次に拾い直す。`PostCompact` の写しは消した
- 先頭の1件が 16 KiB を超えると定着が止まり続ける件は範囲外で、ドラフトに積んだ
- 振り返り: 兆候なし

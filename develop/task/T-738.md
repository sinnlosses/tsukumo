## 目的

`pnpm run check` の最後の段（`pnpm run test:e2e`）が全シナリオを直列に流していて時間がかかる。検証のたびに全件を流す運用のまま、段の所要時間を縮める（2026-09-27 ユーザーの指示）。

## 完了条件

- 手を入れる前と後で `pnpm run test:e2e` の所要時間を同じ機械で測り、タスクファイルの結果の節に前後の秒数を書く
- 並列化などの変更のあと、`pnpm run test:e2e` を続けて3回通し、落ちないことを確かめる（揺れを増やしていない証拠）
- `docs/design.md` 10章「E2E の走らせ方」の所要時間の目安と「`--parallel` を足す」の条（Bun の時代の書き方のまま）と `fileParallelism: false` の条を、入れた形に合わせて直す
- 検証コマンド `pnpm run check` を通す
- 調べて速くする手が無い（並列にすると揺れる等）と分かったら、測った数と理由を結果の節に書いて `dropped` で閉じてよい

## 決まっていること（蒸し返さない）

- 改修した範囲に関わる E2E だけを走らせるルールは作らない。関わる分だけ走らせても `task ship` が検証で全件を流すので2回走ることになるため、検証時には全件を流し、その全件を速くする（2026-09-27 ユーザーの判断）
- 件を削って速くしない（`docs/design.md` 10章「E2E の走らせ方」の「件を削らずに `--parallel` を足す」。Vitest では並列の口を開けることに読み替える）

## 背景

- 2026-09-27: テストの走らせ手は Bun から pnpm + Vitest へ移った。`package.json` の `test:e2e` は `pnpm run build && vitest run --config vitest.e2e.config.ts`。`check` は `nice sh -c '... typecheck && lint && format:check && test && test:e2e'` の順
- `vitest.e2e.config.ts` は `fileParallelism: false`（「並べると負荷で待ちが揺れて落ちる」とコメントがある）で、ファイルを直列に流している。`testTimeout` / `hookTimeout` は 60 秒
- シナリオは `test/e2e/<シナリオ>.test.ts` の15ファイルに分かれていて、足場は `test/e2e/scenario-run.ts`
- `docs/design.md` 10章「E2E の走らせ方」: ブラウザは1ファイルに1つ（`beforeAll`）、tsukumo は1件ごとに1つ起こし、ポート（`TSUKUMO_VIEW_PORT=0`）もホームも cwd も1件ごとに分かれている。「所要時間の目安は E2E の段で 60 秒まで。超えたら件を削らずに `--parallel` を足す」とある（`--parallel` は Bun の口の名前で、いまは `fileParallelism` / `maxWorkers` にあたる）。同じ節に `fileParallelism: false` の理由も書かれている
- `task ship` は CLAUDE.md「## タスク運用」の検証コマンド（`pnpm run check`）を自分で走らせてから main へ送る

## やること

- 前提の再確認: `dependencies` の T-671・T-739 と、本文中の T-672・T-785 はいずれも完了済みで `develop/task/` から除去済み（`docs/history/direction.md` に経緯が残る）。前提は崩れていない
- 実測: `sysctl -n hw.ncpu` は 10（性能4・効率6）。`vitest.config.ts`（単体テスト）は T-785 で `maxWorkers: "30%"` を既に持つ。`vitest.e2e.config.ts` は `fileParallelism: false` のみで `maxWorkers` の指定は無い
- `vitest.e2e.config.ts` の `fileParallelism: false` を外し、単体テストと同じ比率 `maxWorkers: "30%"`（10コアの30%で3ワーカー）を足す。値は単体テストと合わせることで、並行する作業ツリーが重なっても1本あたりの負荷がコア数を超えない設計を保つ
- `docs/design.md` 10章「E2E の走らせ方」の「所要時間の目安は E2E の段で 60 秒まで。超えたら件を削らずに `--parallel` を足す」を、Vitest の `maxWorkers` に置き換えて書き直す。同じ節にある `fileParallelism: false` の理由の文も、外した経緯（負荷の測り直しで揺れが出なかった）に合わせて直す

## 注意

- 並列の口は Vitest の `fileParallelism` と `maxWorkers`（`pool` の種類も）。挙動は手元の Vitest の版とその場の実物で確かめる（記憶の知識を前提にしない）。`fileParallelism: false` を外す理由になった揺れが今も出るかを、まず並べて測る
- 並列にすると Chrome を同時に複数起こす。`docs/design.md` 10章の「場面が流れ終わるのを時間で待たない」前提が崩れていないか、負荷で落ちる件が出ないかを見る
- T-672（`input-dispatch.test.ts` が `pnpm run check` の中でときどき落ちる）と重なる。並列化で落ち方が変わったら T-672 の本文の背景の節に書き足す
- T-725（検証結果に時間を添える）と測り方が重なる。段ごとの時間を測る仕組みを作るならそちらに寄せる
- 2026-09-27: T-785 で単体テストの `maxWorkers` に上限を置く。E2E を並列にするなら、並行する作業ツリーで重なっても1本あたりの負荷がコア数を超えない本数にする

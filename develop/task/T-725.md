## 目的

レポートの検証結果（単体テスト・E2E・型検査など）に、かかった時間を添える条を足す。E2E などにどれだけ時間がかかっているかを把握し、遅いものに手を打てるようにする（2026-09-27 ユーザーの指示）。

## 完了条件

- 検証を走らせたターンのレポートで、測れた検証ごとに所要時間が `checks` の `detail` に出るように、記法の条（`REPORT_NOTATION_PROMPT`）と `report` の `checks` の引数の説明を直している。測れなかったときの扱い（書かない・「未計測」と書く）も決めて書いている
- 所要時間をどう得るかを決めている（下の論点）。決めた方法で、実際に `bun run check` を走らせたターンのレポートに時間が出ることを確かめて結果の節に書く
- 条を足したことを `docs/display.md` の検証結果の帯の仕様に反映している
- `bun run check` が通る

## 背景

- 検証結果の帯は `src/shared/report-check.ts`（`ReportCheck` の `status` / `label` / `detail`）。`checks` の引数の説明は `src/server/report/core/report-tool.ts`、記法の条は `src/server/report/core/report-notation.ts` の `REPORT_NOTATION_PROMPT`
- ツールの一歩（`src/shared/turn-step.ts`）は登録時、所要時間を持っていない。Bash ツールの結果にも時間は付かない

## 解くべき論点

- 時間をモデルに測らせる（`time` で包む・`bun test` の出力の時間を拾う）か、tsukumo がツールの一歩の開始と終了から機械で測って添えるか。`docs/coding-standards.md`「仕組みをヒューリスティックより優先する」に照らして選ぶ。機械で測る案が1コミットに収まらないなら、条だけ先に入れ、機械の案をドラフトに書く

## やること

- 前提の確認: `src/shared/report-check.ts`（`ReportCheck`）・`src/server/report/core/report-tool.ts`
  （`REPORT_CHECKS_DESCRIPTION`）・`src/server/report/core/report-notation.ts`
  （`REPORT_NOTATION_PROMPT`）・`src/shared/turn-step.ts` は本文どおりの場所・中身だった。
  `tool-started` / `tool-finished`（`src/server/session-driver/core/sdk-message.ts`）は Bash を含む
  すべてのツール呼び出しを通るが、SDK のメッセージにも tsukumo 側の記録（`SessionRecord` の
  `kind: "tool"`）にも時刻を持たせていない。テストの走らせ手は `bun` から `pnpm` へ移っている
  ので、本文中の `bun run check` は `pnpm run check` と読み替える
- 論点の選択: 機械測定（`tool-started`/`tool-finished` に時刻を持たせ、経過を `SessionRecord` /
  `TurnStep` まで運んで `report` の引数の説明で読ませる）は `src/shared/session-event.ts` ・
  `src/shared/session-state.ts` ・`src/server/session-driver/core/sdk-message.ts` ・
  `src/shared/turn-step.ts` の4箇所に跨る変更になり、1コミットに収まらないと判断した
  （`docs/coding-standards.md`「仕組みをヒューリスティックより優先する」参照）。今回は
  ヒューリスティック（記法の条でモデルに時間を測らせ、`checks` の `detail` に書かせる）だけを
  先に入れ、機械案は結果の報告に書く
- `REPORT_CHECKS_DESCRIPTION`（`src/server/report/core/report-tool.ts`）と
  `REPORT_NOTATION_PROMPT` の条1（`src/server/report/core/report-notation.ts`）に、測れた検証は
  `detail` に所要時間を添え、測れなかった・測っていない確認（目視など）は `detail` に
  「未計測」と書く条を足す
- `docs/display.md` の検証結果の帯の仕様（4.2）に、この条を足したことを1行足す
- `test/server/report/core/report-notation.test.ts` に、新しい条の文面を検査するテストを足す
- 完了条件にある「実際に `bun run check`（pnpm 移行後は `pnpm run check`）を走らせたターンの
  レポートに時間が出ることを確かめる」は、tsukumo の実セッションをこの作業では起こせないため
  確かめられない。代わりに記法の条とツールの説明の文面・単体テストで確かめる

## 注意

- `bun run check` のように複数の検証をまとめて走らせるときは、中の段（typecheck・lint・test・test:e2e）ごとに時間が分かると目的に効く。分けられるかも見る

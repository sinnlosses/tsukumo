## 目的

E2E の揺れと「揺れずに間違った期待値」が何度も出て、そのたびに1件ずつ直してきた。過去の失敗から共通の型を取り出し、E2E を書く人・直す人・レビューする人が同じ取りこぼしをしないよう、書き方の条とレビューで見ることを正典に置く（2026-09-27 ユーザーの指示）。

## 完了条件

- `docs/design.md` 10章に節「E2E の揺れを生まない書き方」を足し（`E2E の成果物と再現` の後ろ）、少なくとも次の条を、それぞれ元になった失敗（シナリオ名と起きたこと。タスク番号は書かない）を1行添えて書く:
  1. 操作（送る・押す）の前に、場面のタイマーで届くイベント（`opening` の一言など）を回数つきで待つ。場面の `afterMs` と操作で流れるイベントを競わせない
  2. 撮る前に、非同期の取得（TanStack Query など）が済んだことを DOM の印で待つ。「取得中」の文字や途中の `data-motion` を期待値に入れない
  3. 期待値を撮り直したら `git diff test/e2e/expected/` の中に途中の状態（取得中・`success`/`failure` のまま戻らない反応など）が入っていないかを見る（揺れずに間違っている期待値は揺れより見つけにくい）
  4. 揺れを見たら、打ち直す前に落ちた it の名前と `/tmp/tsukumo-e2e/<シナリオ>/` の成果物を控える（打ち直すと上書きされて原因が追えなくなる）
  5. シナリオを足した・待ち方を直したときは、そのファイルを続けて回して（回数を決めて書く）落ちないことを確かめ、回数を `## 結果` に書く
- `docs/coding-standards.md` の `## テスト` 節に、E2E の差分をレビューするときに見ることを箇条書きで足し（上の条を言い直さず、`docs/design.md` 10章の節を句で指す）、冒頭の「節の索引」の行を要るなら直す。`/code-review` の Standards 軸が読むのは `docs/coding-standards.md` なので、レビューの入口はこちらに置く
- 既に正典にある条（「場面が流れ終わるのを時間で待たず、届いたイベントを待つ」・時計の固定）と二重にしない。重なる条は既存の文に寄せる
- 編集の前後で `grep -c '^#\{2,3\} '` の数が、足した見出しのぶんだけ増えていることを確かめる
- `pnpm run check` が通る

## 背景

過去の E2E の失敗（`git log --oneline main | grep -i e2e` と消したタスクファイルの `## 結果` から）:

| 起きたこと                                                                                          | 原因                                                                                                                                                            | 直し方                                                                                                  |
| --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `input-dispatch` が `check` の中でときどき落ちる                                                    | `opening` の speech（`afterMs` 200）と依頼後の `partial-utterance` が同じ時刻に届いて競う                                                                       | 送る前に `waitForEvent("speech")`、比べる前に `partial-utterance` を畳む（`collapsePartialUtterances`） |
| `permission-answer` が揺れる                                                                        | 押して流れる `pending-changed` と場面の `speech`（`afterMs` 200）の競り合い                                                                                     | `waitForEvent("speech", 2)` を待ってから押す                                                            |
| 立ち絵の反応が `success`/`failure` のまま戻らず、期待値11ファイルがその状態を正解として記録していた | ブラウザの時計が `pauseAt` までは実時間で進み、反応を解くタイマーの遅延が負になる                                                                               | 時計を最初から凍らせ、期待値の `data-motion` を取り直した。揺れていなかったので長く気づかれなかった     |
| `background-task` のコンテキスト使用量が「取得中…」のまま撮られる（T-790 で扱う）                   | 取得が済む前に DOM を撮っている疑い。`settledDom`（`test/e2e/scenario-run.ts`）は DOM が2回続けて同じなら落ち着いたとみなすので、取得中の表示が続いていても通る | 未解決                                                                                                  |
| `speak-bubble` が1回だけ落ち、打ち直し3回は通過                                                     | 打ち直しで `/tmp/tsukumo-e2e/` が上書きされ、原因を控えていない                                                                                                 | 未解決（別のタスク）                                                                                    |
| 疑似セッションの場面がページの接続前に流れ、メッセージの列が揃わない                                | 接続前のイベントが `hello` に畳まれる                                                                                                                           | fake driver が最初のビューの接続を待ってから流す（正典に既にある）                                      |

- いま `waitForEvent("speech", …)` で開幕の一言を待っているのは `input-dispatch`・`permission-answer`・`question-ask`・`task-list` の4ファイルで、待つかどうかは書く人に任されている
- 足場は `test/e2e/scenario-run.ts`（`useScenarioRun` / `openRoom` / `settleAndMatch` / `settledDom`）

## 注意

- 足場の仕組みで塞ぐ別のタスク（失敗の成果物を残す・開幕の場面を足場が待つ）がこの節の条を直す。ここでは仕組みを先取りせず、いまの書き方の条として書く
- 会話の実物を例に使わない（疑似セッションの場面名だけで言う）

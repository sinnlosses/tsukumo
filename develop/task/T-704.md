## 目的

`report` の本文を型付きの塊で受ける案（`docs/research/report-block.md`）の最初の段として、記録と表示の側を節と塊の形（`sections`）に切り替える。ツールの引数はまだ文字列の `body` のままにし、利用者から見た変化を出さずに、塊の形と「塊 → Markdown」の組み立てを入れる。

## 完了条件

- `src/shared/report-block.ts` に節と塊の zod の形（提案書4章）と、塊から Markdown を組む関数（5章の逃がし方）を置く
- 記録（`src/shared/session-state.ts` の `report`）と `SessionEvent` の `report` を `body: string` から `sections` に替える
- `src/server/session-driver/core/sdk-message.ts` の `reportEvents` が、文字列の `body` を逃げ道の塊（`markdown`）1つに畳む（7章）。描く側に「文字列か塊か」の分かれ道を持ち込まない
- 過去のレポートの見た目が変わらないことを E2E と目視で確かめ、何が見えたかを結果の節に書く
- `docs/glossary.md` に「節」「塊」を足す
- `bun run check` が通る

## 背景

- 提案書の4章（塊の一式と schema の案）・5章（インラインの Markdown）・7章（過去の記録との互換）・11章の1段目
- 型で受けて描く前例は `checks`（`src/shared/report-check.ts`）

## やること

前提は崩れていない（`main` の今のコードで確かめた）: `report` の引数を読むのは `sdk-message.ts` の
`reportEvents` だけで、`body` は `SessionEvent` → `session-state.ts` の記録 → `main-view.ts` の
`reportMarkdown`（ここで `tidyReportBody`）の順に文字列のまま流れている。`src/shared/report-block.ts` はまだ無い。

1. `src/shared/report-block.ts` を置く
   - 提案書4章の8種（`text` / `list` / `table` / `note` / `stats` / `code` / `mermaid` / `markdown`）と節の zod の形。
     `heading` / `fold` / `path` / `done` の「無い」は zod の既定値で空文字と `false` に畳み、型に `?:` を出さない
   - 文字列の `body` を節に畳む関数（空白だけなら `[]`、それ以外は見出しの無い節1つに `markdown` の塊1つ。7章の表）
   - 節の並びから Markdown を組む関数。塊の文字は5章の通りに逃がす（行頭の塊の記法と `<` を逃がし、改行を畳む。
     表のセルは `|` も。inline code の中は触らない）。HTML の中に埋める文字（`stats`・`fold` の見出し）は
     HTML として逃がし、その関数は `report-check.ts` の帯と共有する
2. `SessionEvent` の `report` と記録の `report` の `body: string` を `sections: readonly ReportSection[]` に替え、
   `reportEvents` で `body` を1の関数で畳む
3. `main-view.ts` の `reportMarkdown` は `markdown` の塊ごとに `tidyReportBody` を掛けてから1の関数で組む
   （「文字列か塊か」の分かれ道は持たない）
4. 送り直しの判定（`report-review.ts` の `isSameReport`）は、handler の `body` を1の関数で畳んだ節と、
   描いた `report` の節を `isDeepEqual` で比べる（ツールの引数は `body` のまま）
5. テスト: `test/shared/report-block.test.ts` に塊ごとの組み立てと逃がし方を足し、`body` を持つ既存のテストと
   フィクスチャを `sections` に直す。E2E の `*.messages.json` は `body` → `sections` の差分だけが出て、
   `*.dom.json` は変わらないことを見る
6. `docs/glossary.md` に「節」「塊」を足し、「report ツール」の注記を合わせる。目視で過去のレポートが同じに描かれるのを見る

## 注意

- ツールの引数（`src/server/session-driver/adapter/sdk-tool.ts` の schema）と記法の文面はこのタスクでは変えない（次のタスクで切り替える）

## 結果

- 検証コマンド: 2698 pass / 0 fail、E2E 24 pass / 0 fail。`*.dom.json` は不変で、`*.messages.json` 6件は `body` → `sections` の差分だけ
- 目視: 変更前（`serve-revision.ts HEAD`）と並べ、`report-tidied`（見出し・太字の表見出し・2列の表・引用・フェンス）と `background-task-interim-report`（中間2枚＋最終1枚、横はみ出し 0px）が同じに描かれた。画素の差分は取っていない
- 送り直しの判定は畳んだ節どうしを比べるので、先頭行の字下げだけ違う送り直しは別物と見なす（前は `trim` で同じ）
- 振り返り: 報告に残した気になる点・ツールのエラー5件（ドラフト 1件）

## 目的

`bun run check` の全体実行で単体テストが1件ときどき落ち、受け入れの検証が打ち直しになるのを止める。

## 完了条件

- 揺れの原因（待ちの時間切れ・`FileReader` の非同期・並べた作業ツリーの負荷など）を突き止め、結果の節に原因を1行で書く
- 原因に沿って待ち方かテストの組み方を直す（時間を延ばすだけの直しにしない。延ばすなら、なぜそれで足りるかを根拠つきで書く）
- 同じファイルの単独実行を10回続けて落ちない。`bun run check` が通る
- 調べて再現も原因も掴めなければ、試したことを結果の節に書いて `dropped` で閉じてよい

## 背景

- `test/browser/components/page/character/components/character-edit/character-edit.test.tsx:286` の「立ち絵を選ぶと data URL を載せた characterPack.setPortrait を dispatch し、入力欄を空に戻す」（振り返りの時点では `set-portrait` の名前だった）
- T-656 の受け入れで `bun run check` が 2711 pass / 1 fail（このテスト）。差分は docs とテストのコメントだけ。同じファイルを単独で5回回すと 45 pass / 0 fail、全体の打ち直しで 2712 pass / 0 fail
- 同じファイルに背景（:535）・顔（:598）を選ぶ同じ形のテストがある。原因が共通なら一緒に直す
- 2026-09-27、T-702 の受け入れ（文書だけの変更）で `test/browser/components/page/character/character.test.tsx:130` の「新しく作るはダイアログを開き、作れたら閉じて一覧でそのパックを選ぶ」も全体実行で1回だけ落ちた（2673 pass / 1 fail、打ち直しで通った）。立ち絵のファイルを選んだあと `setTimeout` 20ms で待つ同じ形なので、原因が共通なら一緒に直す

## やること

- 原因: 3件とも `fireEvent.change`（または `fireEvent.drop`）で選んだファイルを
  `src/browser/utils/data-url.ts` の `readDataUrl`（`FileReader.readAsDataURL` を Promise で包んだもの）で
  読み、その解決を待たずに固定の `setTimeout(resolve, 20)` で実時間20msだけ待ってから
  `dispatch` の結果を確かめている。`jsdom` の `FileReader` は読み込みを実タイマー
  （内部で `setTimeout`）に乗せて非同期に解決するため、`pnpm run check` の全体実行のように
  他の多数のテストファイルが同じイベントループを取り合っているときは、20ms経っても
  `FileReader.onload` がまだ発火していないことがある。単独実行や少数実行では周りが空いているため
  20msで足り、揺れが再現しないのはこのため。時間を延ばすだけでは根本的に直らない
  （どれだけ延ばしても、それより重い実行では同じ揺れが起き得る）
- 直し方: 固定時間の `sleep` をやめ、「その状態になるまで待つ」形にする。
  `@testing-library/react` の `waitFor`（`test/browser/components/domain/portrait.test.tsx` などで
  既に使っている実績のある道具）に載せ替え、`dispatch` の呼び出し結果や `canSubmit` に連動する
  ボタンの活性状態など、実際に確かめたい条件が満たされるまでポーリングで待つ
- 対象は同じファイル内に4か所（同じ形）:
  - `character-edit.test.tsx:187`「カードに画像を落とすと、その表情の characterPack.setPortrait を dispatch する」
    （`fireEvent.drop`。タスク登録時には挙がっていなかったが同じ固定 `setTimeout(20)` を使っており、
    同じ原因が当てはまるので合わせて直す）
  - `character-edit.test.tsx:282`
    「立ち絵を選ぶと data URL を載せた characterPack.setPortrait を dispatch し、入力欄を空に戻す」
  - `character-edit.test.tsx:531`
    「背景を選ぶと data URL を載せた characterPack.setBackground を dispatch し、入力欄を空に戻す」
  - `character-edit.test.tsx:594`
    「顔を選ぶと data URL を載せた characterPack.setFace を dispatch し、入力欄を空に戻す」
  - 上の4つは `expect(calls).toEqual([...])` を `waitFor` の中に入れる形にそろえる
- 背景に書かれている `character.test.tsx:126`（新しく作るダイアログ）も同じ形の固定 `setTimeout` だが、
  ここは `dispatch` 待ちではなく `use-character-create.ts` の内部状態 `portraitImage`
  （`readDataUrl` の解決で埋まる。埋まると「作る」ボタンの押せるかが変わる）を待っている。
  `Button`（`docs/coding-standards.md`）は `aria-disabled` で押せないを表す（native の `disabled`
  ではない）ので、`waitFor` で `aria-disabled` が `"false"` になるのを待ってから click する形に直す
- `character.test.tsx` には登録時に挙がっていなかった同じ形がもう1か所あった（:172
  「一覧で別のパックを選ぶと右側がそのパックに替わり、差し替えた立ち絵はそのパックへ書く」）。
  同じ原因なので合わせて直す
- `pnpm run test -- character-edit.test.tsx` を10回連続で落ちないことを確かめ、`pnpm run check` を通す

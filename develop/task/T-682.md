## 目的

Bun から Node + Vite + Vitest へ移す5段の1段目。TS を Node で直接走らせ、Bun の型から離れる。

## 完了条件

- mise が入っていて、リポジトリの `mise.toml` が Node 26 を固定している。`node --version` がリポジトリの
  中で 26 系を返す
- `bin/tsukumo` の shebang が node になり、`tsukumo` コマンド（`bun link` で `~/.bun/bin/tsukumo`）が
  Orca のタブから起動できる
- `package.json` の scripts のうち TS を実行するもの（`start`・`dev`・`build`・`grid`）が node で走る
  （テストの scripts は次段で移すので `bun test` のままでよい）
- `spawn("bun")` / `execFileSync("bun")` の4か所（`scripts/capture-catalog.ts`・`scripts/serve-revision.ts`×2・
  `test/cli.test.ts`）、E2E の `spawn(process.execPath, ["run", ...])`（`test/e2e/scenario-run.ts`）、
  `.claude/settings.json` の hook（`bun run scripts/deny-broad-kill.ts`）が node で走る
- `tsconfig.json` の `types: ["bun"]` が `@types/node` と `lib: ["DOM", ...]` になり、`@types/bun` を外しても
  `tsc --noEmit` が通る（`bun:test` の型だけが要るなら次段まで残してよい）
- `README.md` のセットアップと CLAUDE.md の「セットアップ / 環境構築」が mise と Node 26 の手順になっている
- `bun run check` が通る

## 背景

- 手元の Node は nodebrew の v22.13.1（`~/.nodebrew/current/bin/node`）で、PATH の先に nodebrew の
  bun 1.4.2 もある。`~/.bun/bin/bun` 1.3.8 と2つ並んでいる（`docs/research/external-dependency.md`）
- Node の型剥がしはフラグ無しで `.ts` を実行できるが `.tsx` と enum などは扱えない。いまの import は
  すべて拡張子付きで、enum・namespace は無く、`src/server`・`src/shared`・`src/cli.ts` は `.tsx` を
  import していない（2026-09-26 に確かめた）
- `@types/bun` がブラウザの型（`document` / `EventSource`）も持っていたので、DOM の型は `lib` で足す
  （`docs/architecture.md` の組み立ての節）
- `bundle.ts` の `bun build` はこの段では触らない（3段目）

## 分かったこと（次段以降に響く）

- **`bun link` は常に `~/.bun/bin/tsukumo` に置かれる**（`BUN_INSTALL` 未設定だと、実行している
  bun のバージョンやインストール元に関係なく既定が `~/.bun`）。よって「`~/.bun/` を消す→mise の
  bun で `bun link` を打ち直す」の順でないと `~/.bun/bin/tsukumo` が復活しない
- **mise の shim は、cwd にそのツールを指す設定（プロジェクトの `mise.toml` かグローバルの
  default）が無いと、そのツール自身の判定では止まらず PATH 上の次の実行ファイルへ素通りする**
  （`mise ls-remote` 等ではなく実測: shims だけの PATH で未設定だと `mise ERROR No version is
set for shim: node` で落ちるが、後ろに `~/.nodebrew/current/bin` が残っていると素通りして
  node 22 が使われる）。**このリポジトリの `mise.toml` はこのリポジトリの中でしか効かない**ので、
  `tsukumo` コマンドを**このリポジトリの外の任意のプロジェクト**（README が掲げる本来の使い方）
  で起動すると、mise の shim は node 26 を選べず PATH 上の次の node（今は nodebrew の v22.13.1）
  に落ちる。node 22.13.1 は素の `.ts` 実行に対応していないため、**nodebrew を消すと `tsukumo`
  コマンドがリポジトリの外では起動できなくなる**（`/tmp` で実測: `ERR_UNKNOWN_FILE_EXTENSION`）
- 対策のグローバルな既定（`~/.config/mise/config.toml` に node 26.10.0・bun 1.4.2）は
  2026-09-27 に張った（下の「決まっていること」）
- **E2E のサーバを node で起こすと、`bun run check` の E2E が毎回1〜2件落ちる**（落ちる件は回すたびに
  変わる。bun で起こすと24件とも通る）。見えた不一致は `input-dispatch` の partial-utterance の区切りで、
  T-672 と同じ正体（`EVENT_BATCH_INTERVAL_MS` の 100ms と `test/fixture/fake-session.json` の
  `afterMs` が同じ時刻に重なり、どちらのタイマーが先に走るかがランタイムで変わる）

## 注意

- Orca から起こされるプロセスが対話シェルの `mise activate` を通らない場合がある。`tsukumo` を
  Orca のタブから起動して node 26 で動いているかを確かめ、通らなければ mise の shims を PATH に置く
  などで解く
- nodebrew と `~/.bun/bin` を PATH に足している行（`~/.zshrc` など）も消す。消したあと新しいシェルで
  `which -a node bun` が mise のものだけを返すことを確かめる

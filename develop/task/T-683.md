## 目的

Bun から Node + Vite + Vitest へ移す5段の2段目。`bun test` の罠（`mock.module` がほかのファイルへ
漏れる・`--isolate` がまれに返らない）を消す。

## 完了条件

- `bun:test` を import するファイルが無く、単体テストと E2E が Vitest で走る
- `package.json` の `test`・`test:e2e`・`test:e2e:update`・`check` が Vitest を使い、`bunfig.toml` が消えている
- `@types/bun` が devDependencies から消えている
- 移す前の `bun run test`（約26秒）と移した後の所要時間を測り、結果の節に書く
- CLAUDE.md の「よく使うコマンド」の `bun test --isolate` の注意と、`docs/coding-standards.md` の
  `--isolate` の節（644行あたり）が Vitest の形になっている
- `bun run check`（または移した後の同等のコマンド）が通る

## 背景

- `bun:test` を import するファイルは 223。使っている API は `describe`・`it`/`test`・`expect`・
  `beforeEach`/`afterEach`/`beforeAll`/`afterAll` がほぼすべてで、`mock` 4・`spyOn` 6・
  `mock.module` 4か所（`test/browser/.../turn/turn.test.tsx`・`.../report/report.test.tsx`）
- `bunfig.toml` の preload は `test/dom-environment.ts`（101行。happy-dom の DOM の名前だけを
  `globalThis` へ借りる）と `test/css-module-loader.ts`（34行。`*.module.css` を書いた class 名のまま返す）
- E2E は `test/e2e/` の 22 件で、`--timeout=60000` で走る

## 決まっていること（蒸し返さない）

- テストランナーは Vitest（2026-09-26 ユーザーの判断）

## 注意

- `mock.module` は Vitest の `vi.mock` と巻き上げの意味が違う。2ファイルは書き直す
- DOM を借りるのは部品のテストだけにする（実際の fetch / WebSocket を使うテストに happy-dom を
  混ぜない、という `dom-environment.ts` の方針を保つ）。ファイルごとの環境指定か projects で分ける
- `T-671`・`T-672`（全体実行でときどき落ちるテスト）が残っていたら、移した後にも再現するかを見て結果の節に書く

## 目的

Bun から Node + Vite + Vitest へ移す5段の2段目。`bun test` の罠（`mock.module` がほかのファイルへ
漏れる・`--isolate` がまれに返らない）を消す。

## 完了条件

- `bun:test` を import するファイルが無く、単体テストと E2E が Vitest で走る
- `package.json` の `test`・`test:e2e`・`test:e2e:update`・`check` が Vitest を使い、`bunfig.toml` が消えている
- `@types/bun` が devDependencies から消えている
- 移す前の `bun run test`（約26秒）と移した後の所要時間を測り、結果の節に書く
- CLAUDE.md の「よく使うコマンド」の `bun test --isolate` の注意と、`docs/coding-standards.md` の
  `--isolate` の節（644行あたり）が Vitest の形になっている
- `bun run check`（または移した後の同等のコマンド）が通る

## 背景

- `bun:test` を import するファイルは 223。使っている API は `describe`・`it`/`test`・`expect`・
  `beforeEach`/`afterEach`/`beforeAll`/`afterAll` がほぼすべてで、`mock` 4・`spyOn` 6・
  `mock.module` 4か所（`test/browser/.../turn/turn.test.tsx`・`.../report/report.test.tsx`）
- `bunfig.toml` の preload は `test/dom-environment.ts`（101行。happy-dom の DOM の名前だけを
  `globalThis` へ借りる）と `test/css-module-loader.ts`（34行。`*.module.css` を書いた class 名のまま返す）
- E2E は `test/e2e/` の 22 件で、`--timeout=60000` で走る

## 決まっていること（蒸し返さない）

- テストランナーは Vitest（2026-09-26 ユーザーの判断）

## やること

- 前提を数え直すと、`bun:test` を import するファイルは 230（`*.test.ts(x)` が 229、
  `test/css-module-loader.ts` と `test/e2e/scenario-run.ts` が残り2つ）。`mock`/`spyOn`/
  `mock.module` を使うのは10ファイルだけで、残りは `describe`/`it`/`expect`/`beforeEach` などの
  素の import なので機械的に `"bun:test"` → `"vitest"` に置き換えられる
- 10ファイルは手で直す: `mock(` → `vi.fn(`、`spyOn(` → `vi.spyOn(`、`mock.module(` → `vi.mock(`、
  `mock.restore()` の後始末は `vi.mock` の巻き上げと per-file isolation により不要になるので消す
- `bunfig.toml` を消し、`test/dom-environment.ts` は中身をそのまま単体テストの設定の
  `setupFiles` に渡す（Reflect ベースの実装は Bun 固有 API に依存していないため無改造）
- `test/css-module-loader.ts` は Bun の `plugin()`（esbuild プラグイン）を使っているので書き直しが
  要る。Vite の既定の CSS Modules 変換はハッシュ付きの名前を生成してしまうため、`resolveId` で
  仮想 id（`\0` 始まり、拡張子を変えて `vite:css` に横取りされないようにする）に差し替えて `load`
  で「CSS の綴りのまま返す」対応表を作る Vite プラグインに書き直す
- 単体テスト用 `vitest.config.ts` と E2E 専用 `vitest.e2e.config.ts` を新設。E2E 側は
  `fileParallelism: false`（ファイルごとに tsukumo とブラウザを1組起こす重いテストを並べると
  負荷で待ちが揺れることを実測で確認）。両方に `env.TZ = "UTC"` を渡し、`bun test` が常に UTC で
  走っていた前提を保つ
- 移行の途中で見つかった副作用も直す: `bun:test` 由来の `toStartWith`/`toEndWith`（Vitest には無い
  matcher）を `.startsWith`/`.endsWith` + `toBe(true)` に、`test/browser/rpc-fetch-stub.ts` の
  `fetch.preconnect`（`@types/bun` が生やしていた型）を素の `fetch` の代入に、`markdown.tsx` ほか
  2ファイルの `import { type X } from "hast"`（"hast" は型だけの package で実体が無い）を
  `import type { X } from "hast"` に直す。後者は `verbatimModuleSyntax` と esbuild の組み合わせで
  `import {} from "hast"` という実行時の import が残ってしまう組み合わせ限定の問題で、Bun の
  トランスパイラでは起きなかった差分
- CLAUDE.md・`docs/coding-standards.md`・`docs/design.md`・README.md の `bun test`/`bun:test`/
  `bunfig.toml`/`@types/bun` の記述を Vitest の形に直す（`docs/history/` と、過去の決定の経緯を
  そのまま残す `docs/architecture.md` の記述は触らない）

## 注意

- `mock.module` は Vitest の `vi.mock` と巻き上げの意味が違う。2ファイルは書き直す
- DOM を借りるのは部品のテストだけにする（実際の fetch / WebSocket を使うテストに happy-dom を
  混ぜない、という `dom-environment.ts` の方針を保つ）。ファイルごとの環境指定か projects で分ける
- `T-671`・`T-672`（全体実行でときどき落ちるテスト）が残っていたら、移した後にも再現するかを見て結果の節に書く

## 結果

- 検証コマンド: 単体 2716 pass / 0 fail（213ファイル）、E2E 24 pass / 0 fail。単体の所要は移す前の約26秒から約15秒に縮んだ
- E2E は並べると待ちが揺れて落ちたので `fileParallelism: false`。T-671 の揺れは移した後の単独10回では再現せず、T-672 はタスクファイルが無く見られなかった。`import { type X } from "hast"` は Vite の変換で実行時の import が残るので `import type` に直した
- 振り返り: 同じファイルを3回以上直した・ツールのエラー・受け入れのときにメインが直したもの（経緯を語るコメントを削った）（ドラフト 0件）

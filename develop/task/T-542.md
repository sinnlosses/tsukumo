## 背景

2026-09-24 の振り返り（T-448）から、利用者の承認を得て登録した。

`test/fixture/fake-session.json` の `background-task` の場面は、続きのターンが1回だけで `report` も無い。吹き出しが空になっても0.4秒後に次のセリフで埋まるので、`docs/architecture.md`「手で確かめること」の目視でも、続きのターンで中間レポートが消える・吹き出しが空に戻る不具合（2026-09-24 の 7b06eec3・1cdf60fd で直したもの）が見えなかった。

## やること

1. `test/fixture/fake-session.json` に、中間 `report` → 合図2通（それぞれ `turn-resumed` → `speech` → ターンの終わり）→ 完了の返事 → 最終 `report` の場面を足す
2. `docs/architecture.md`「手で確かめること」から、この場面をどう呼んで何を見れば合格かを引けるようにする（`scripts/capture-catalog.ts` の場面の一覧に載せる必要があれば載せる）

### 調べ直した前提（着手前）

- `test/fixture/fake-session.json` は `{ opening, turns: [{ name, steps: [{ afterMs, event }] }] }`。`TSUKUMO_FAKE_SCENE=<name>` を渡すと、`opening` の続きとしてその場面の `steps` がすぐ流れる（`src/server/adapter/fake-driver.ts` の `startFakeSession`）。場面の1手目に `request` イベントを置けば、それがそのやり取りの依頼になる（`background-task` など既存の場面と同じ形）
- 既存の `background-task` の場面は `turn-resumed` を1回しか含まず、`report` も無い（`utterance` だけ）。委譲を2回はさんで `report` が持ち越されるかは、この場面だけでは目視できなかった（背景の記述どおり）
- `kind: "report"` イベント（`report` ツールの呼び出し）は `src/server/core/report-review.ts` の `pass()` が**同じ `toolUseId` の `tool-finished` が届くまで預かる**。届けば `[report, tool-finished]` の順で流し、届かないまま `turn-finished` が来たらその直前に流す。既存の `report-tool` の場面に倣い、`report` の直後に `isError: false` の `tool-finished`（`content: "ok"`）を対で置けば、狙った時点で main view に出せる
- `src/shared/session-state.ts` の `resumeTurn`（`turn-resumed` の畳み込み）は `beginTurn`（`request`/`turn-started`）と違い、`speeches` / `speechExpression` / `speechCalledInTurn` を初期化しない（1cdf60fd の直し）。`src/browser/stores/main-view-turn.ts` の `unsettledBodies` は、いま走っている続きのターンが自分の `report`/`utterance` をまだ出していなければ、前の SDK ターンで確定した `report` を伏せない（7b06eec3 の直し）。どちらも T-541 で単体テスト（`test/browser/stores/main-view-turn.test.ts`）が付いたが、実ブラウザでの目視は無かった
- `scripts/capture-catalog.ts` は場面が流れ終わってから固定 `SCENE_TAIL_MS`（1.5秒）待って1枚だけ撮る作りで、「合図のあいだ（進行中）の状態」を撮るようにはできていない。**`background-task` も同じ理由でカタログに載っていない**（15秒の背景待ちを挟むため）。今回の場面も合図の間隔を挟むので、カタログには載せない判断にした
- `docs/architecture.md`「手で確かめること」には場面ごとの索引が無く、個別の場面名は代わりに `docs/screen-design.md` 13.9 など呼び出し元のドキュメントから引かれている（例: `docs/requirements.md` の `background-task` の引用）。今回は「手で確かめること」自体に、場面名・呼び出し方・見るべき点を1段落で足すことにした
- 前提は崩れておらず、作業はそのまま実施できた

## 完了条件

- 疑似セッションでその場面を流すと、合図のあいだも中間 `report` がメインビューに出たままで、吹き出しが「（まだ発話がありません）」に戻らない。撮った画面か DOM を測った結果を `evidence` に書く
- `docs/` の節の数が編集の前後で変わっていない
- `bun run check` が通る

### evidence（DOM を時系列で測った結果）

- 足した場面: `test/fixture/fake-session.json` の `resumed-report`（依頼 → 速攻の一言 → ツール1件 → 中間 `report` → ターンの終わり → (`turn-resumed` → `speech` → ターンの終わり) ×2 → `turn-resumed` → 完了の一言 → 最終 `report` → ターンの終わり。セリフ・本文はすべて作り物）
- 起こし方: `TSUKUMO_DRIVER=fake TSUKUMO_FAKE_SCENE=resumed-report TSUKUMO_VIEW_PORT=47912 TSUKUMO_HOME=<スクラッチの一時ディレクトリ> TSUKUMO_OPEN_VIEW=0 TSUKUMO_WATCH_UI=0 bun run src/cli.ts`
- Playwright（headless Chromium、1400x900）で `[data-region="main"]` と `[data-region="character"]` の `innerText` を、起動直後から100msおきに測った
  - 合図1（`turn-resumed` 3200ms → `speech` 3800ms、場面内の相対時刻）と合図2（`turn-resumed` 5100ms → `speech` 5700ms）の間隔をそれぞれ跨いで測定（実測 t=2906〜3894ms・t=4832〜5932ms、21サンプル）: **どのサンプルでも吹き出しに「（まだ発話がありません）」は出ず、main view には中間 `report` の結論文（「中間の結論（架空）：ここまでで分かったことをいったんまとめた。」）が出続けた**
  - 300msおきの粗い測定でも、中間 `report` が出てから最終 `report` に差し替わるまで（実測 t=1867〜8056ms）main view から一度も消えず、吹き出しは前のセリフを保ったまま次のセリフへ1件ずつ積み替わった（プレースホルダは一度も出なかった）
  - 最終 `report`（「最終の結論（架空）：合図をまたいでも報告は消えなかった。」）は t=8365ms で main view に出て、中間 `report` は「中間レポート」の折りたたみへ回った
- 測定後 `bun run scripts/stop.ts --port 47912` で止め、`lsof` でポートが空いたことを確認した

## 目的

`docs/`・`develop/` の Markdown しか変えていないのに、build を含む E2E まで走らせて待つのをやめる。待ち時間と、E2E 側の揺れに当たる機会を減らす。

## 完了条件

- `pnpm run check` の中身を `scripts/` の1ファイルに移している。変えたファイルが文書だけなら typecheck・lint・`test:e2e` を省き、省いたことを1行出す。それ以外はいまと同じ5段を同じ順に走らせる
- 「変えたファイル」は、主ブランチとのマージベースからの差分・作業ツリーの未コミットの変更・未追跡のファイル（`.gitignore` の対象を除く）を合わせたもの。1つでも文書でないものがあれば全段を走らせる
- 「文書」は `docs/`・`develop/` の下の `.md` と、直下の `README.md`・`CLAUDE.md` だけ。`src/` の下の `.md`（同梱パックの `persona.md` など）は文書に入れない
- `format:check` と単体テスト（`test/task-id.test.ts` や節の参照の検査が文書を見ている）は省かない
- 全段を強制する口（環境変数か引数）がある
- 判定をテストで確かめている（文書だけ・文書とコード・`src/` の下の `.md`・未追跡のファイル）
- `README.md` の「開発」と CLAUDE.md の「よく使うコマンド」の `pnpm run check` の説明を合わせている
- `pnpm run check` が通る

## 背景

- いまの `check` は `package.json` の `nice sh -c 'pnpm run typecheck && pnpm run lint && pnpm run format:check && pnpm run test && pnpm run test:e2e'`。`test:e2e` は `pnpm run build` を含む
- `task ship` の付け替え後の検証もこの `pnpm run check` を呼ぶので、スキル側は直さなくても効く
- T-786（委譲先と受け入れで同じ中身を2回検証しない）とは別の話で、重ならない

## やること

前提を実物で確かめた結果、`## 背景` の主張（`package.json` の `check` が
`nice sh -c 'pnpm run typecheck && pnpm run lint && pnpm run format:check && pnpm run test && pnpm run test:e2e'`）は
そのとおりだった。`README.md`「開発」の `pnpm run check` の1行目コメントと CLAUDE.md「よく使うコマンド」の
説明も同じ5段の並びで揃っている。前提は崩れていないので実装する。

- `scripts/lib/document-change.ts`（純粋関数）: `isDocumentPath(path)` で「文書」（`docs/`・`develop/`
  配下の `.md`、直下の `README.md`・`CLAUDE.md` だけ、`src/` 配下の `.md` は含めない）を判定し、
  `isDocumentOnlyChange(paths)` で1件以上かつ全件が文書のときだけ true を返す
- `scripts/lib/changed-path-repository.ts`（`git` と `node:fs` だけを呼ぶ）:
  - `resolvePrimaryBranch(root)`: `~/.claude/skills/task-workflow/WORKFLOW.md`「主ブランチの名前は
    `main` に固定しない」と同じ順で決める。CLAUDE.md「## タスク運用」の `- 主ブランチ:` 行（あれば）→
    `git symbolic-ref --short refs/remotes/origin/HEAD` → `main`/`master`/`trunk` の実在するもの→
    どれも無ければ例外
  - `collectChangedPaths(root, primaryBranch)`: `git merge-base HEAD <primaryBranch>` を求め、
    `git diff --name-only <mergeBase>`（コミット済みの差分と未コミットの変更をまとめて拾う）と
    `git ls-files --others --exclude-standard`（`.gitignore` 対象を除く未追跡ファイル）を合わせて返す
- `scripts/check.ts`（エントリ。`package.json` の `check` から呼ぶ）: `--full` 引数で強制的に全段を
  走らせる口を持つ。強制していなければ `resolvePrimaryBranch` → `collectChangedPaths` →
  `isDocumentOnlyChange` の順で判定し、文書だけなら「文書だけの変更のため typecheck・lint・test:e2e を
  省く」の1行を出し、`typecheck`・`lint`・`test:e2e` を飛ばす。`format:check`・`test` は常に走らせる。
  5段は元と同じ順（`typecheck` → `lint` → `format:check` → `test` → `test:e2e`）で、`spawnSync` で
  `pnpm run <stage>` を1つずつ呼び、途中で失敗したらその終了コードで止める（`&&` の直列と同じ挙動）
- `package.json` の `"check"` を `"node scripts/check.ts"` に差し替える
- `test/scripts/check-plan.test.ts` で `isDocumentPath`・`isDocumentOnlyChange` を検証する
  （文書だけ・文書とコードの混在・`src/` 配下の `.md`・未追跡ファイル相当のパスを含む）
- `README.md`「開発」と `CLAUDE.md`「よく使うコマンド」の `pnpm run check` の説明文はそのままでも
  実際の5段と順は変わらないため、内容の食い違いが出ないことを確認する（変更が要れば直す）

## 注意

- 主ブランチの名前は `main` と決め打ちせず、`task ship` の付け替え後（マージベースが主ブランチの先端になる）でも判定が崩れないことを確かめる
- 外部コマンドへの依存を増やさない（`git` と node だけで書く）

## 結果

- 検証コマンド: 単体 2760 pass / 0 fail、E2E 31 pass（1回目は fake-driver.test.ts が1件落ち、単独と打ち直しで通過）
- 受け入れで直した: テストの git を非同期の fixture へ・git から集める側の一時リポジトリのテスト・コメントのファイル名とタスク番号・`STAGES` を `satisfies` に・git の stderr を黙らせる
- 振り返り: 受け入れで直した・揺れ・自己申告の不正確さ（ドラフト 1件）

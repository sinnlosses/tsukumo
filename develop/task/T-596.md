## 目的

成果の画面の「<キャラクターの名前>と振り返る」で、日記を会話のセッションの外で書かせる。依頼文もレポートも会話のメインビューに残らないようにする（形は T-595 で決める）。

## 完了条件

- 振り返りのボタンを押しても、会話のメインビューに依頼文・レポート・ターンが増えず、キャラビューにセリフが出ない。会話の SDK セッションに `diary` ツールが載っていない
- 会話のターン中でも振り返りを頼め、書いている最中の2回目は断られる
- 日記は今までどおり `diary` で受け取られ、成果の画面と日記帳に出る。書けなかったとき（受け付けずに終わった・時間切れ）は「書けなかった」が出てボタンが戻る
- `docs/requirements.md` 4.11「振り返りの依頼」と `docs/design.md`「日記の受け取りと保存」の形に沿うテストがある（少なくとも: 書き手が窓口を問い合わせごとに作って `diary-written` / `diary-failed` を流す・session-manager がターン中に受けて書いている最中は断る・会話の `turn-finished` / `session-ended` で `diaryWriting` が動かない・代を閉じると中断する）
- `docs/design.md` 2章「サーバの機能と、機能どうしの辺」の機能の表と辺の表が、移した後のファイルと辺に揃っている（`test/architecture.test.ts` が通る）
- `CLAUDE.md` 原則3の括弧（SDK の境界を置く機能の例: 「駆動は `session-driver/`、訪問の台本は `visit/`」）に、日記の問い合わせ（`diary/`）が足されている
- `bun run check` が通り、`bun run build` のあと実際に振り返りを1回押して、会話の画面に何も増えず成果の画面に日記が出たことを目視で確かめる

## 決まっていること（蒸し返さない）

- 日記は**会話とは別の使い捨ての `query()`** で書かせる。持たせるのは `diary` だけ（`tools: []`・プロセス内の MCP に `diary` 1つ・`strictMcpConfig: true`・`allowedTools` は `mcp__tsukumo__diary` だけ・`permissionMode: "dontAsk"`）。`settingSources: []`・`persistSession: false`・`includePartialMessages: true`・`maxTurns: 4`（仮）・`thinking: { type: "disabled" }`（`effort` は渡さない）・120 秒で諦める（仮）
- 指示文は `systemPrompt` を文字列で丸ごと置き換え、人格（`persona.md` の全文）と日記を書く役目の短い指示だけを入れる。雑談の記憶の読み戻しは載せない。依頼文はモードで変えない
- モデルは会話のいまのモデル（`SessionState.model`。分からなければ既定）。作業ディレクトリと環境変数は会話と同じ
- 会話の SDK セッションから `diary` を外し、`SessionDriver.beginDiaryDay` と `diary-drafting` の変換（`sdk-message.ts`）・窓口と追跡（`sdk-driver.ts`）を消す。`session-driver` → `diary` の辺は無くなり、`diary` が `session-driver/core/sdk-message.ts` の `tsukumoToolFullName` を読む
- 新しいファイルは `src/server/diary/core/diary-writer.ts`（書き手。`visit-script-writer.ts` と同じ形）と `src/server/diary/adapter/sdk-diary.ts`（使い捨ての `query()`。`diary` の zod の形もここへ移す）。窓口 `createDiaryIntake` は書く日を1つ受け取って問い合わせごとに作る（`beginDay` / `forgetDay` を無くす）
- 会話のターン中・答え待ちでも受ける。断るのは書いている最中（`diaryWriting.kind === "writing"`。理由は新しく足し、ターン中の理由は外す）と、成果が読めない・空の日
- 書き手は代の持ち物。起こし直しで代を閉じたら中断し、閉じたあとに届いたイベントは捨てる。受け付けずに終わった（時間切れ・失敗）ときは書き手が `diary-failed { date }` を流す。`diary-failed` を足すので `PROTOCOL_VERSION` を上げる
- `diaryWriting` は会話の `turn-finished` / `session-ended` で動かさない。起こし直しで初期値に戻るのは今までどおり
- 使用量（token-usage / context-usage）は記録しない（訪問の台本と同じ）
- 疑似セッション（`TSUKUMO_DRIVER=fake`）では起こさず、`diary-requested` のすぐ後に `diary-failed` を流す
- 画面: 押せないのは書いている最中だけ（書いている日は「振り返り中…」、ほかの日は「いま<日付>の日記を書いているので送れない」）。「会話の画面で様子を見る ›」を外す。帯の「いまの作業」は「作業中」を「振り返り中」より上にする

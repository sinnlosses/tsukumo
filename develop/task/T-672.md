## 目的

`bun run check`（単体テストのあとに E2E）の中で E2E が1件ときどき落ち、`task ship` と受け入れの検証が打ち直しになるのを止める。

## 完了条件

- 落ちたときの expected / received を残して原因を突き止め、結果の節に原因を1行で書く
- 流れてくる途中のセリフの区切りが配信のタイミングで変わっても落ちない待ち方・比べ方に直す（確かめたいこと — `prompt` が `request` として戻り続きの場面が流れる — は弱めない）
- `bun run check` を続けて3回通す
- 再現も原因も掴めなければ、試したことを結果の節に書いて `dropped` で閉じてよい

## 背景

- `test/e2e/input-dispatch.test.ts:16` の「入力欄に書いて ⌘Enter で送ると prompt が流れ、request が戻って続きの場面が流れる」
- 2026-09-26 の tsukumo-2 で、`bun run check` の中で4回落ちた（どれも `toEqual` の不一致）。単体で `bun run test:e2e` を回すと続けて6回通る
- T-639 のサブエージェントの見立てでは、ずれていたのは partial-utterance の文字の区切り（流れてくる途中のセリフをどこで切るか）で、DOM の構造は合っていた
- E2E の走らせ方は `docs/design.md` 10章「E2E の走らせ方」

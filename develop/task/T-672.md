## 目的

`bun run check`（単体テストのあとに E2E）の中で E2E が1件ときどき落ち、`task ship` と受け入れの検証が打ち直しになるのを止める。

## 完了条件

- 落ちたときの expected / received を残して原因を突き止め、結果の節に原因を1行で書く
- 流れてくる途中のセリフの区切りが配信のタイミングで変わっても落ちない待ち方・比べ方に直す（確かめたいこと — `prompt` が `request` として戻り続きの場面が流れる — は弱めない）
- `bun run check` を続けて3回通す
- 再現も原因も掴めなければ、試したことを結果の節に書いて `dropped` で閉じてよい

## 背景

- `test/e2e/input-dispatch.test.ts:16` の「入力欄に書いて ⌘Enter で送ると prompt が流れ、request が戻って続きの場面が流れる」
- 2026-09-26 の tsukumo-2 で、`bun run check` の中で4回落ちた（どれも `toEqual` の不一致）。単体で `bun run test:e2e` を回すと続けて6回通る
- T-639 のサブエージェントの見立てでは、ずれていたのは partial-utterance の文字の区切り（流れてくる途中のセリフをどこで切るか）で、DOM の構造は合っていた
- E2E の走らせ方は `docs/design.md` 10章「E2E の走らせ方」

## やること

調べ直した前提（崩れていない。作業が要る）:

- `test/e2e/scenario-run.ts` の `EventBatch`（`EVENT_BATCH_INTERVAL_MS=100ms`）は連なる
  `partial-utterance` を束の中でだけ畳む（`event-batch.ts` の `joinPartialUtterances`）。束の
  切れ目は走らせるたびに変わるので、E2E の `messages.json` は畳む前の粒度で捕まえてしまい、
  同じ内容でも分割が揺れる
- さらに `input-dispatch` 固有の重なりがある: `opening` の1言（`speech`, `afterMs: 200`）と、
  依頼を送って始まる `report` ターンの書きかけの本文（`afterMs: 100/150/200`）が、ほぼ同じ実時間
  （ページに繋がってから200ms前後）で競合する。どちらが先に届くかで `speech` が
  `partial-utterance` の連なりのどこに割り込むかが変わり、割り込む位置が変わると分割される
  テキストの境界も変わる（見えた不一致はこれ）

直したこと:

- `test/e2e/scenario-run.ts` に `collapsePartialUtterances` を足し、`messages.json` を比べる前に
  連なる `partial-utterance` を1件に畳む（束の切れ目の揺れを吸収する）
- `test/e2e/input-dispatch.test.ts` で、依頼を送る前に `opening` の1言（`speech`）を
  `waitForEvent` で待つように直した。これで `speech` が必ず依頼より先に届くようになり、
  `report` の書きかけの本文と競合しなくなる（`test/fixture/fake-session.json` の `afterMs` を
  直す案も試したが、共有の `opening` の長さが変わり `turn-history`（別タスク T-739）の
  キャラクターの動き（`data-motion`）が3回中3回落ちるようになったので撤回した）
- `test/e2e/expected/input-dispatch.dom.json` ・ `input-dispatch.messages.json` ・
  `long-report.messages.json` ・ `report-notation.messages.json` を `test:e2e:update` で
  書き直し、差分が意図した変化だけであることを確認した

## 注意

- 判断が想定より要ると分かったら押し切らず `difficulty` を上げて再開する

## 結果

- 原因: `opening` の speech（afterMs 200）と依頼後の partial-utterance が同じ時刻に届いて競い、束の切れ目が走るたびに動いていた。送る前に speech を待ち、比べる前に partial-utterance を畳んで直した
- 検証コマンド: 2674 pass / 0 fail、E2E 24 pass / 0 fail（委譲先で bun 3回・node 26 のサーバで E2E 3回とも通過）
- 振り返り: 報告に残した気になる点・受け入れで直したもの（ドラフト 1件）

## 目的

`pnpm run check` の中で `test/cli.test.ts` の「既定ポートから上限まで全部塞がっていると、試した範囲を伝えて終了コード1で終わる」がときどき落ちる揺れを止める（2026-09-27 振り返りのドラフト、ユーザー承認）。

## 完了条件

- 落ちる原因を当てて、テストかコードのどちらかを直している（原因と、そう判断した根拠を結果に書く）
- `pnpm run check` を続けて10回流し、このテストが1度も落ちない
- `pnpm run check` が通る
- 調べて再現せず原因も当たらなければ、試したことを結果に書いて `dropped` で閉じてよい

## 背景

- 落ちたのは `holdFallbackBand`（`test/cli.test.ts` の 100 行付近）が投げる「連続した 20 個の空きポートを握れない」。OS に選ばせたエフェメラルポートを起点に `VIEW_PORT_FALLBACK_ATTEMPTS` 個の連続した空きを握り、1つでも塞がっていれば手放して選び直す。選び直しは `MAX_BAND_PICKS = 10` 回まで
- つまり帯はすでに既定ポート（7327〜）から外してある。落ちたのは「エフェメラルの範囲で連続した20個の空きが10回とも見つからなかった」とき
- T-725 の受け入れで1回落ち、単独の `vitest run test/cli.test.ts` と直後の打ち直しでは通った。直前の T-738 で E2E をファイル単位で3本並べていて、同時に開くポートが増えた疑いがある（確かめていない）

## 注意

- 実際の既定ポートの帯は、ほかの作業ツリーの tsukumo と共有している。テストで塞がない

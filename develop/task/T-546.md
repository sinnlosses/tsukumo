## 目的

雑談モードのターンが `speak` のツール呼び出しで終わるせいで、Claude Code 本体が「応答が空だった」催促（`[Your previous response had no visible output. ...]`）を利用者の発言として差し込み、1往復増える入口が残っている。塞ぐかどうかと、塞ぐならどういう終え方にするかを決める。

## 完了条件

- 塞ぐ／塞がないの結論と理由が `docs/chat-mode.md` の該当節に書かれている
- 塞ぐなら、実装のタスクが `task new` で登録されている（決めた終え方を `## 決まっていること` に焼いてある）

## 背景

仕事のターンは「`report` → 締めの `speak` → 1行」の並びへ反転して、ツール呼び出しで終えないことで催促を消した（`src/server/core/report-notation.ts` の終え方の条、`docs/architecture.md`「レポートはテキストではなく `report` ツールで受け取る」）。雑談は `src/server/core/chat-manner.ts` が「本文を書かない。言いたいことはぜんぶ `speak` で言う」と決めているので、仕事の側の反転がそのまま当てはまらない。英語に滑る分は `src/server/adapter/sdk-driver.ts` の `settings.language: "japanese"` が保険になっているが、往復そのものは残る。

## 解くべき論点

- 雑談で本文を1行だけ許すか（画面のどこにも出ない本文を書かせるのは chat-manner の「本文を書かない」と衝突する）
- 催促の往復がどれだけ起きているかを、`token-usage/` の記録で先に測るか
- 何もしない（保険のまま残す）という結論もありうる

## 注意

- 人の判断待ち（`hold`）。塞ぐかどうかは利用者が決める

## 結果

塞ぐ。環境変数 `CLAUDE_CODE_TERMINAL_MCP_TOOLS=mcp__tsukumo__speak`（同梱の `claude` 2.1.280 のバイナリで判定を確かめた。公式の文書には無い）と、雑談にも「完了」の1行を書かせる条の両方で塞ぎ、催促が届いたら気づける見張りを置く（2026-09-24 ユーザー決定）。結論と理由は `docs/chat-mode.md` 4.9「雑談モードで変わるもの」の催促の段。実装は T-554 に登録した。`hold` のまま人がいるセッションで決めたので、`claim` を通さずに `status` と結果を手で書いた。

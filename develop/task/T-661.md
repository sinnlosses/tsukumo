## 目的

規約「型を迂回するキャストを書かない」を、テストの DOM 要素のキャストについて機械で守る。いまは手本にされて増え続けている（T-626 で新しく書いたテストに入り、受け入れで直した）。

## 完了条件

- `.oxlintrc.json` に、テストで `as HTMLSelectElement` のような型アサーションを書くと `bun run lint` が落ちる規則がある
- `test/` の `as HTML*Element`（2026-09-26 時点で 15 ファイル・74 か所）が `instanceof` の型ガード（合わなければテストを落とす形）に置き換わっている
- 規則の範囲と、範囲に入れなかったものの理由が `docs/coding-standards.md` の型を迂回するキャストの節から辿れる
- `bun run check` が通る
- oxlint に範囲を絞れる規則が無く、下の論点のどれも成り立たなければ、理由を書いて `dropped` で閉じてよい

## 背景

- 出典: T-626 の振り返り（`develop/direction.md` のエージェントのドラフト、2026-09-26 にユーザー承認）。`character-switch.test.tsx` に `as HTMLSelectElement` が入り、受け入れでメインが `instanceof` のガードに直した。隣の `session-switch.test.tsx` と `session-info.test.tsx` にも同じキャストが残っている
- `.oxlintrc.json` の `rules` にはいま型アサーションを縛る規則が無い（`typescript/consistent-type-imports` と `typescript/no-explicit-any` はある）
- `src/` には `as HTML*Element` は無い。`as const` 以外の型アサーションは `src`・`test`・`scripts` 合わせて約 95 行あり、うち `src` には `children as ReactNode`（`src/browser/components/page/conversation/main-view/markdown/`）や `value as Record<string, unknown>`（`src/shared/character-background.ts`）のような、HTML 要素以外のものもある

## 解くべき論点

- 規則の範囲: `typescript/consistent-type-assertions` を `assertionStyle: "never"` にすると全部の `as`（`as const` を除く）を落とす。`overrides` で `test/` だけに掛けるか、全体に掛けて `src` の残りも直すか、ファイル単位の除外で済ませるか。直す量と「前提が変わったときに黙って効かなくならないか」で選ぶ

## やること

調べ直した前提（2026-09-26、`0ca36500` の上）:

- T-660 は「会話の画面」（`test/browser/components/page/conversation/`）だけを対象に完了済みで、
  それ以外の領域は手つかずのまま。対象は減っていない
- `test/` の `as HTML*Element` は 15 ファイル・73 か所（`grep -rn "as HTML[A-Za-z]*Element"
test/` で実測。`character-switch.test.tsx` は T-626 の受け入れで既に `instanceof` の
  ガードに直っていて、隣の `session-switch.test.tsx` と `session-info.test.tsx` にはまだ
  残っている、という背景の記述と一致する）
- oxlint 1.85 には ESLint の `no-restricted-syntax` に相当するセレクタ規則が無く、
  「`as HTMLXxxElement` のような特定の型名だけ」を狙い撃つ規則も無い。掛けられるのは
  `typescript/consistent-type-assertions`（`assertionStyle: "never"`）だけで、これは
  `as const` 以外の `as` を全部落とす
- この規則を `test/**` に掛けると、`as HTML*Element` 以外にも `test/` の中に21か所ほど別の
  `as` が引っかかる（`JSON.parse(...) as unknown`、`readonly` タプルの widen、
  `NodeJS.ErrnoException` の組み立て、`globalThis` / happy-dom の `Window` への動的な
  プロパティの読み書き、`getBoundingClientRect` の戻り値の `DOMRect` の偽装、`fetch` の
  スタブの差し替えなど）。ファイル単位の除外で `as HTML*Element` がある15ファイルだけに
  絞ることもできるが、それだと**新しく増えるテストファイルの `as HTML*Element` を機械的に
  拾えなくなる**（目的にある「いまは手本にされて増え続けている」を防げない）ので、
  `test/**` 全体に掛け、ついでに出てきた21か所も annotation・実物の構築・`Reflect` への
  置き換えで直し、直せない1か所だけ理由付きの `oxlint-disable-next-line` を残す側を選ぶ
- `src/` の `as`（`children as ReactNode`・`value as Record<string, unknown>` など）は
  `as HTML*Element` と性質が違う別の関心事で、`src/` に `as HTML*Element` は無いので、
  `src/` には掛けない

手順:

1. `.oxlintrc.json` の `test/**` の overrides に `typescript/consistent-type-assertions`
   （`assertionStyle: "never"`）を足す
2. `test/typed-element.ts` に `instanceof` の型ガード `typedElement(value, ctor,
description)` を1つ足し、73か所の `as HTML*Element` と、同じ理由で残っていた
   `as Element` を置き換える。`test/dom-environment.ts` が新しく要求する
   `HTMLImageElement` / `HTMLTableCellElement` / `HTMLDetailsElement` を借りる DOM
   グローバルの一覧に足す
3. 規則を `test/**` 全体に掛けたことで引っかかる残りの `as` を、annotation・実物の構築
   （`DOMRect` は `new DOMRect(...)`、`NodeJS.ErrnoException` は `Object.assign`）・
   `Reflect.get` / `Reflect.set` に置き換える。`fetch` のスタブ差し替え（構造的に
   合わない代役を許すのが目的そのもの）だけ、理由付きの `oxlint-disable-next-line` で残す
4. `docs/coding-standards.md`「型を迂回するキャストを使わない」に「テストの DOM 要素の
   キャスト」小節を足し、範囲・置き換え・`src` に掛けなかった理由・残った例外の基準を書く

## 注意

- T-660（単体テストの監査）で消えるテストがあるので、先に入っていれば直す量が減る。依存にはしない

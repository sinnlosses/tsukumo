## 目的

`task ship` が付け替え後の検証で `VERIFY_FAILED` になったあと打ち直すと、付け替えが済んでいるため `rebased=no verify=skipped` で `SHIPPED` になり、検証に落ちた中身がそのまま `main` に入りうる。これを塞ぐ（振り返り: T-686）。

## 完了条件

- `VERIFY_FAILED` のあとに打ち直した `ship` は、付け替えが無くても検証コマンドを走らせる（`VERIFY_FAILED` の印を残して次の `ship` が読む、など）
- 検証が通れば印が消え、以後の `ship` は今までどおり付け替えのあるときだけ検証する
- claude-skills 側の検査（`./check.sh`）が通り、claude-skills の `main` に入っている
- このリポジトリの `pnpm run check` が通る
- T-762 の作り直しのあとの `ship` で同じことが起きないと確かめられたら、根拠を `## 結果` に書いて `dropped` で閉じてよい

## 背景

- `task` は `~/.claude/skills/task-workflow/scripts/task.py`。`ship` は「rebase が実際に付け替えたとき」だけ検証を走らせる
- T-686 で1回目の `ship` が付け替え後の検証で落ち、2回目は `rebased=no verify=skipped` で `SHIPPED` になった。T-680 でも同じことが起きている
- T-762 が同じスキル群を Beads を錠と履歴に使う形へ作り直している（ファイル方式と併存）。その結果の `ship` に対して直す

## 注意

- `~/.claude/skills` は claude-skills の本体の作業ツリーへの symlink。本体で枝を切らず、`git -C ~/ghq/github.com/sinnlosses/claude-skills worktree add` で別の作業ツリーを作って編集してから `main` に入れる

## 目的

タスクの管理（`develop/task/` の1件1ファイルと git の外の台帳）を GitHub Projects へ移すかを検討する。特に、コミットを積まずに着手の排他制御ができるかを見る（2026-09-27 ユーザーの指示）。

## 完了条件

- `docs/research/` に検討の結果を書く。少なくとも「解くべき論点」の各項に結論と理由がある
- 移す・移さないの推奨と、移すなら段取り（スキルの何を変えるか・移行の順番）を書く
- 後段のタスク（T-734 の状態名の改名）の本文を結論に合わせて直す（移すなら改名は GitHub Projects の状態の設計に畳む、など）
- `bun run check` が通る

## 背景

- 運用の正典は `~/.claude/skills/task-workflow/WORKFLOW.md`（claude-skills のリポジトリ。全プロジェクト共通）と、このリポジトリの上乗せの `docs/workflow.md`
- 今の排他制御: `task claim` が git の外の台帳に着手の印を立て、タスクファイルの状態はコミットで `main` へ送る（`task ship`）。採番の錠もある
- 登録時、`develop/task/` を使っているのはこのリポジトリだけ

## 解くべき論点

- GitHub Projects（と Issues）の API で、着手の印を原子的に取れるか（競合したときに片方だけが勝つ仕組みがあるか）
- `/loop /next-task` の無人運転・オフライン・`gh` の認証・API の回数制限への影響
- タスクの本文（背景・完了条件・結果）をどこに置くか。git の履歴に残らなくなることの損得
- 外部サービスへの公開になる範囲（非公開の Project でも、会話内容の扱いの規約（`docs/coding-standards.md`「会話内容の扱い」）に触れないか）

## やること

2026-09-27 に main（a2338ed1）で調べ直した前提:

- 着手の印はすでにコミットを積まない。`task claim` は共有の `.git` の下の台帳に `mkdir claim/T-xxx` で印を立て（`ledger.py` の `claim_dir`）、`main` を動かさない。指示の「コミットを積まずに排他制御ができそう?」の前半は今の運用で満たされている。残るコミットは登録（「指示をタスクにする」）・完了（作業と同じ1コミット）・剪定（「振り返り済みのタスクファイルを消す」）で、2026-09-20 以降の main のコミット 1214件のうち `develop/task/` を触ったのは 283件、タスクIDを持たないものが 92件（登録 51・剪定 36 など）
- tsukumo 自身が main の `develop/task/*.md` を読んでいる（`src/server/repository/adapter/task-summary.ts` のタスク板、`src/server/achievement/` の成果）。`retrospect` の `scan.py` も登録から完了までのタスクファイルの差分を git から読む
- `gh` はこの端末で未ログイン。tsukumo と claude-skills のリポジトリは GitHub で公開されていて、`develop/task/` も `origin/main` に載っている

したがって作業は要る（移す/移さないの判断は残る）が、論点の重心は「排他制御の可否」から「GitHub に原子的な取り方があるか」と「残るコミットを減らす価値が失うものに見合うか」へ移る。

1. GitHub の Issues・Projects の API（GraphQL・REST）の条件付き更新・競合の挙動・回数制限・`gh` の認証を docs.github.com と cli.github.com で確かめる（書き込みも、このリポジトリの内容を送る呼び出しもしない）
2. 解くべき論点の4項に結論と理由を書き、推奨と、移すならの段取りを `docs/research/github-projects.md` に書く
3. 結論に合わせて `develop/task/T-734.md` の本文を直す
4. `bun run format` と `bun run check`

## 注意

- 検討と提案だけ。GitHub に Project や Issue を作るのは外部への公開に当たるので、試すならユーザーの承認を得る

## 結果

- 検証コマンド: 単体 2699 pass / 0 fail、E2E 24 pass / 0 fail
- 結論: 移さない（docs/research/github-projects.md）。着手の印はすでにコミット不要で、Projects・Issues の更新は後勝ちで原子的に取れない。T-734 は今の運用のまま改名する前提に直した
- 振り返り: 検証コマンドの打ち直し（ドラフト 0件。研究文書のタスク番号は機械の検査が止め、もう1件は原因不明の一時的な落ち）

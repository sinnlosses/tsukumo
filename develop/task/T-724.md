## 目的

`src/browser/` で手書きされている操作子（`<button>`・`<select>`・`<dialog>`）を `components/ui/` の `Button` / `Select` / `Dialog` に置き換え、操作子の見た目と振る舞いを部品の1箇所に寄せる（2026-09-27 ユーザーの指示）。

## 完了条件

- `components/ui/` の外の `.tsx` に残る `<button>`・`<select>`・`<dialog>` が、部品に置き換えられないものだけになっている。残したものは種類ごとの理由を結果の節に書く
- 置き換えた画面ごとに、見た目と操作（押す・選ぶ・開閉）が変わっていないことを確かめて結果の節に書く
- `bun run check` が通る（E2E が操作子を `role` で拾っているので、崩れればそこで落ちる）

## 背景

- 登録時の数（`components/ui/` の外の `.tsx`）: `button` 45・`select` 18・`dialog` 10
- 見出し・文字は別のタスク（同じ日に登録）で扱う

## 決まっていること（蒸し返さない）

- 2026-09-27 ユーザー決定: 既存の8 variant に寄せて見た目が変わる置き換えは受け入れない。足りない variant（常に点線の下線を持つ link・不透明な地を持つ outline など）を `Button` に足してから、置き換えた15箇所を見た目を変えずにやり直す

## やること

前提を調べ直した結果、`select`・`dialog` は実物のタグ（コメント中の言及ではなく）が
すでに0件——登録時の45/18/10という数はコメント中の `` `<select>` `` / `` `<dialog>` `` という
言及まで数えた誤カウントで、実体は Select / Dialog 部品にすでに置き換え済みだった。
このタスクでやることは `button` だけになる。

`button` の置き換えは、元の見た目（枠・地・字の色・hover・選択・押せないとき）を変えない
ことを条件にする。既存の variant で顔が合わないときは、その顔を `Button` の variant として
足してから置き換える（`docs/design.md` 2章「`components/ui/` の部品（variant の作法と一覧）」の
「使っている組み合わせごとに1つの値にする」）。呼び出し側の class は箱だけにして
`test/architecture.test.ts`「components/ui/ の部品の className」を満たす。

同じ節が `Button` にしないと決めているもの（押せる行・押せる文字・件数のチップ、
`--usage-*` などの画面固有の値を持つもの）は `<button>` のまま残す。

最初の塊（15箇所）の行き先:

- `Button` に置き換える9箇所: `.character-list-new`（点線の枠）、`.question-ask-back` /
  `.question-ask-to-newest`（hover で warn の枠）、`.dispatch-interrupt`（hover で ng の枠と字。
  太字は中の `Text`）、`.speech-log-close`（accent の枠と不透明な地）、`.layout-reset-split`
  （半透明の accent の枠と不透明な地）、`.turn-to-newest`（既存の outline）、
  `.prompt-image-zoom` ×2（既存の ghost）
- `<button>` のまま残す6箇所: `.task-id-button`・`.task-count-chip-button`・
  `.diary-book-toc-day`（押せる文字・チップ・行）、`.token-usage-choice`・
  `.usage-review-stop`・`.usage-review-proposal-dismiss`（`--usage-*` の色）
- 置き換えた箇所は、実ブラウザで元の宣言と computed style（border・background・color・
  text-decoration・font-weight）を通常と hover で比べる

## 注意

- 量が1コミットに収まらないと分かったら、要素の種類か領域で分けてタスクを足し、このタスクは最初の塊で閉じてよい
- `<div>` の並べ方を `Stack` / `HStack` / `VStack` に替えるのはこのタスクの外。数だけ結果の節に書く

## 結果

- 最初の塊で閉じた。`select`・`dialog` は実物が0件（登録時の数はコメントの言及まで数えていた）。`<button>` 15箇所のうち9箇所を `Button` にし（variant を5つ足す: `outline-dashed`・`outline-hover-warn`・`outline-hover-danger`・`outline-accent-tinted`・`tinted-accent`）、6箇所は `docs/design.md` 2章が除く押せる文字・チップ・行と `--usage-*` の色を持つもので `<button>` のまま。残り約26件は `ref`・`aria-expanded`・`disabled` の専用の見た目などが要り、後続をドラフトに積んだ。`<div` は142件（Stack 系への置き換えは対象外）
- 見た目: fake driver の実ブラウザで、足した variant と元の宣言の computed style（枠・地・字の色・下線・太さ・opacity・cursor）を通常と hover で比べて一致（字の無い絵のボタンの color だけ差があり画面に出ない）。中断ボタン・質問の札・比率リセットは実物の場面を出さず並べ比べのみ
- 検証コマンド: 単体 2723 pass・E2E 24 pass（全段が緑になった回は委譲先の1回。受け入れでは負荷 35〜68 で回ごとに違う2〜4件が揺れで落ち、どれも単独では通る）
- 振り返り: 受け入れのときにメインが直したもの・検証コマンドの打ち直し（ドラフト 2件）

## 目的

「tsukumo と振り返る」を押してから日記が書き上がるまで（見本 SEIKA-4 b）の状態を、成果の画面が描ける形でブラウザへ届ける。

## 完了条件

- 画面は依頼文を組まず、コマンド `reflect-achievement { date }` を送る。session-manager がその日の成果を読む口（`SessionManagerOptions` に足す）で数え直し、依頼文を組んで送り、窓口（T-564）に「いま書く日」を渡して `diary-requested` を流す。ターン中・成果が読めない・空の日は断る（`docs/design.md`「日記の受け取りと保存」の「コマンドと依頼」）
- 依頼文の関数を `achievementReflectionRequestText` に改名し（`docs/glossary.md`「成果の振り返り」）、`docs/requirements.md` 4.11「振り返りの依頼」の形（卒業と節目・既に日記がある日の書き足しの1行・しおりの指示）にしてある
- 3段の進みが `diary-requested` / `diary-drafting` / `diary-stage` から `SessionState.diaryWriting` に載り、ブラウザが読める。3段目の合図（引数の断片の最上位の鍵 `bookmark`）を拾う純関数が断片の切れ目をまたいでも拾えることをテストで確かめてある。`PROTOCOL_VERSION` を上げてある
- `writing` のままターンが終わったら `failed` が載る
- 帯のいまの作業に「振り返り中」と「<日付>の日記を書いています」が出る（`docs/screen-design.md` 13.9「いまの作業」の表）
- 状態の移り変わりを shared の畳み込みのテストで確かめてある
- `bun run check` が通る

## 背景

- 依頼はいまブラウザが `dispatch({ type: "request", text })` で送る（`src/browser/features/achievement/hooks/use-achievement.ts`）。これを `reflect-achievement` に置き換える。依頼文は `src/shared/achievement.ts`
- `report` の塊が開いた合図を拾う先例は `src/server/core/sdk-message.ts` の `reportDraftingEvents`
- 見直しの進みを姿に載せる先例は `usageReview`（`src/shared/session-state.ts`、`src/shared/usage-review.ts`）
- 帯のいまの作業は `src/browser/features/screen-nav/components/screen-nav-current-work.tsx`

## やること

前提を実物で確かめ直した結果（着手前の調査。設計の正典は `docs/design.md`「日記の受け取りと保存」）:

- `reflect-achievement` コマンドはまだ影も形も無い（`src/shared/command.ts` に無い）。ブラウザは今も
  `achievementReviewRequestText` を組んで `dispatch({ type: "prompt", text, images: [] })` を送っている
  （`use-achievement.ts`）。`diaryIntake.beginDay` / `forgetDay` を呼ぶ経路も無い
  （`createDiaryIntake` は `sdk-driver.ts` の中で作られるだけ）。前提は崩れておらず、このタスクの
  完了条件どおりに作る。

置き場・配線の計画:

- `src/shared/diary.ts`: `DIARY_STAGES = ["read", "write", "pick"] as const` と `DiaryStage` を足す。
  `SessionState.diaryWriting` が使う判別可能な合併型 `DiaryWriting`（`idle` / `writing` / `written` /
  `failed`）もここに置く（設計どおり）
- `src/shared/session-event.ts`: `diary-requested { date }` / `diary-drafting { toolUseId }` /
  `diary-stage { stage }` を `SessionEvent` に足す
- `src/shared/session-state.ts`: `SessionState.diaryWriting: DiaryWriting`（初期値 `idle`）と、上の
  3イベント＋`diary-written`／`turn-finished`（`writing` のまま終われば `failed`）／`session-ended`
  （`idle` に戻す）の畳み込みを足す。`PROTOCOL_VERSION`（`src/shared/frame.ts`）を上げる
- `src/shared/achievement.ts`: `achievementReviewRequestText` を `achievementReflectionRequestText` に
  改名し、引数に `graduations` / `milestones` / `alreadyWritten`（その日の日記が既にあるか）を足して、
  `docs/requirements.md` 4.11「振り返りの依頼」の見本の形（「日記を書いてほしい」「小さな驚き:」
  「書き足す」の1行・`diary` ツールの指示）に書き直す
- `src/shared/command.ts`: `reflect-achievement { commandId, date }` を `clientCommandSchema` に足し、
  `DriverCommand` の `Exclude` にも足す（`nudge` と同じく駆動へそのまま渡らず session-manager が
  捌くため）
- `src/shared/frame.ts`: `FRAME_ERROR_REASON` に `achievementReflectionDuringTurn` /
  `achievementReflectionUnavailable` を足す
- `src/server/core/diary-tool.ts`: 3段目の合図を拾う純関数 `diaryArgumentHasBookmarkKey(buffer)`
  （文字列の中かどうかと深さを数えて最上位の鍵 `bookmark` を探す）と、駆動の世代ごとに1つ持つ
  状態機械 `createDiaryStageTracker(diaryToolFullName)`（`content_block_start` / `_delta` / `_stop`
  の生の `stream_event` メッセージを渡すと、`bookmark` が現れた回だけ `"pick"` を返す）を足す
- `src/server/core/sdk-message.ts`: `reportDraftingEvents` と同じ形で `diaryDraftingEvents`
  （`content_block_start` で `diary` の塊が開いたら `diary-drafting` を出す）を足し、`stream_event`
  の変換に混ぜる
- `src/server/core/session-driver.ts`: `SessionDriver` に `beginDiaryDay: (day: DiaryDay) => void` を
  足す（`diary-tool.ts` の `DiaryIntake.beginDay` をそのまま呼ぶだけの薄い口）
- `src/server/adapter/sdk-driver.ts`: `beginDiaryDay` を実装（`diaryIntake.beginDay` を呼ぶ）。
  `relayMessages` に `createDiaryStageTracker` のインスタンス（世代に1つ）を渡し、`fromMain` の
  メッセージごとに `observe` して `diary-stage` を流す。`turn-finished` の処理へ
  `diaryIntake.forgetDay()` を足す
- `src/server/adapter/fake-driver.ts`: `beginDiaryDay` に no-op を足す（疑似セッションは日記の中身を
  持たないが、`reflect-achievement` から呼ばれても落ちないようにする）
- `src/server/core/session-manager.ts`: `SessionManagerOptions` に
  `readAchievementDay: (date: string) => Promise<DailyAchievement | undefined>` を足す。
  `dispatch` に `reflect-achievement` の分岐を足し、ターン中は
  `achievementReflectionDuringTurn` で断る。それ以外は `readAchievementDay` で数え直し、
  空の日・読めなかったときは `achievementReflectionUnavailable` で断る。通れば
  `achievementReflectionRequestText` で文を組み、駆動へ `prompt` を送り、`beginDiaryDay` を呼び、
  `diary-requested` を流す
- `src/session-start.ts`: `readAchievementDay` を `main-history.ts` の `readAchievement` から組み立てて
  渡す（`view-delivery.ts` の `readAchievement` の配線と同じ形。`achievementCommitCache` は
  session-manager 用に別途1つ作る——共有すると `view-delivery.ts` と `session-start.ts` が
  依存し合うことになり、層を越える）
- `src/browser/features/achievement/hooks/use-achievement.ts`: `onReview` を
  `dispatch({ type: "reflect-achievement", date })` に置き換える
- `src/browser/features/screen-nav/hooks/use-current-work.ts`:
  `ScreenNavCurrentWorkState` に `"diary"` を足し、`pending` の次・`running` の前に判定する
  （`state.diaryWriting.kind === "writing"`）。語「振り返り中」と要約
  「<日付>の日記を書いています」（`9月23日` の形）を足す
- `src/browser/features/screen-nav/components/screen-nav-current-work.module.css`: `data-work-state="diary"`
  に `running` と同じ見た目（枠と印を `--accent`）を足す

## 目視確認（evidence）

`bun run build` のあと、`TSUKUMO_DRIVER=fake TSUKUMO_HOME=<一時ホーム> TSUKUMO_OPEN_VIEW=0
TSUKUMO_VIEW_PORT=48292 bun run src/cli.ts` で起こし、Playwright（headless chromium）で
`#achievement` を開いて「つくもの精霊と振り返る」を押した。100ms 刻みで帯の
`[data-work-state]` を見たところ、t=300ms〜900ms の間 `data-work-state="diary"`・語「振り返り中」・
要約「9月25日の日記を書いています」が出て、t=1000ms（疑似セッションの `turn-finished`）で
「依頼待ち」に戻った（帯のスクリーンショットで確認。`--accent` の縁取りと丸も見本どおり）。
確認後は `bun run scripts/stop.ts --port 48292` で止め、一時ホームも消した。

## 目的

「tsukumo と振り返る」を押してから日記が書き上がるまで（見本 SEIKA-4 b）の状態を、成果の画面が描ける形でブラウザへ届ける。

## 完了条件

- 画面は依頼文を組まず、コマンド `reflect-achievement { date }` を送る。session-manager がその日の成果を読む口（`SessionManagerOptions` に足す）で数え直し、依頼文を組んで送り、窓口（T-564）に「いま書く日」を渡して `diary-requested` を流す。ターン中・成果が読めない・空の日は断る（`docs/design.md`「日記の受け取りと保存」の「コマンドと依頼」）
- 依頼文の関数を `achievementReflectionRequestText` に改名し（`docs/glossary.md`「成果の振り返り」）、`docs/requirements.md` 4.11「振り返りの依頼」の形（卒業と節目・既に日記がある日の書き足しの1行・しおりの指示）にしてある
- 3段の進みが `diary-requested` / `diary-drafting` / `diary-stage` から `SessionState.diaryWriting` に載り、ブラウザが読める。3段目の合図（引数の断片の最上位の鍵 `bookmark`）を拾う純関数が断片の切れ目をまたいでも拾えることをテストで確かめてある。`PROTOCOL_VERSION` を上げてある
- `writing` のままターンが終わったら `failed` が載る
- 帯のいまの作業に「振り返り中」と「<日付>の日記を書いています」が出る（`docs/screen-design.md` 13.9「いまの作業」の表）
- 状態の移り変わりを shared の畳み込みのテストで確かめてある
- `bun run check` が通る

## 背景

- 依頼はいまブラウザが `dispatch({ type: "request", text })` で送る（`src/browser/features/achievement/hooks/use-achievement.ts`）。これを `reflect-achievement` に置き換える。依頼文は `src/shared/achievement.ts`
- `report` の塊が開いた合図を拾う先例は `src/server/core/sdk-message.ts` の `reportDraftingEvents`
- 見直しの進みを姿に載せる先例は `usageReview`（`src/shared/session-state.ts`、`src/shared/usage-review.ts`）
- 帯のいまの作業は `src/browser/features/screen-nav/components/screen-nav-current-work.tsx`

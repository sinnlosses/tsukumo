## 目的

質問が出ているあいだ、入力欄の文字を書く面（`.dispatch-text`）にフォーカスすると枠がアクセントカラーになり、黄色（答え待ちの色 `--state-warn`）で揃えた周りと合っていない。答え待ちのあいだは、この枠も答え待ちの色の系統にする。

## 背景

- `src/browser/features/dispatch/dispatch.module.css` の `.dispatch-text:focus-visible` が `border-color: color-mix(in srgb, var(--accent) 60%, var(--rule))` で、答え待ちかどうかを見ていない
- 答え待ちのあいだは、同じファイルで領域の枠（`.dispatch-pending-glow`）と送信ボタン（`.dispatch-form.is-answering .dispatch-send`）がすでに `--state-warn` になっている。`is-answering` はフォームに付く class
- 質問の札（`src/browser/features/main-view/question-ask.module.css`）も地と枠が `--state-warn` の系統

## 決まっていること（蒸し返さない）

- 答え待ちのあいだだけ変える。質問が無いときのフォーカスの枠はアクセントカラーのまま
- 色は `theme.css` のトークンから導く（`--state-warn` と `--rule` の混ぜ方は、いまの accent の混ぜ方に揃えてよい）

## やること

- `src/browser/features/dispatch/dispatch.module.css` の `.dispatch-text:focus-visible`
  （316行目付近、`border-color: color-mix(in srgb, var(--accent) 60%, var(--rule))`）はそのまま
  残し、`.dispatch-form.is-answering .dispatch-text:focus-visible` を新しく足して
  `border-color: color-mix(in srgb, var(--state-warn) 60%, var(--rule))` で上書きする
  （いまの accent の混ぜ方 `60%, var(--rule)` にそのまま揃える）
- `docs/screen-design.md` を確認した結果、`.dispatch-text` のフォーカス枠そのものについての
  決まりは無かった（`state-warn` は答え待ちの色として固定という表の記載はあるが、混ぜ方の指定は
  無い）。追随させる箇所は無し
- `question-ask.module.css` の答え待ちの枠は `1px solid var(--state-warn)`（混ぜていない）で、
  `.dispatch-pending-glow` も同様に混ぜていない。今回はフォーカス時の枠なので
  「いまの accent の混ぜ方に揃える」という指示のとおり `.dispatch-text:focus-visible` 側の
  `color-mix` の形を踏襲する

## 完了条件

- 答え待ちのあいだ、`.dispatch-text` のフォーカスの枠が `--state-warn` の系統になる。質問が無いときはいまのまま
- `docs/screen-design.md` に入力欄の枠の色の決まりが書いてあれば追随させる
- `bun run check` が通る
- `bun run build` のあと実画面で、質問が出ている状態と出ていない状態のそれぞれで入力欄にフォーカスし、枠の色を目で見て結果に書く

## 結果

- 検証コマンド: 2295 pass / 0 fail

- `docs/screen-design.md` には入力欄のフォーカス枠の決まりが無く、追随なし。T-544/T-545 のファイルは front matter 直後の空行が無く format:check に落ちていたため、整形の1行を同じコミットに入れた

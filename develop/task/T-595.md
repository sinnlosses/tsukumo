## 目的

成果の画面の「<キャラクターの名前>と振り返る」を押すと、いまは会話のセッションに1ターンの依頼が流れ、依頼文もレポートも会話のメインビューに残る。ユーザーはこれを会話から独立させたい（2026-09-25 のフィードバック。「今の規約を変えることになるかも」と本人が承知している）。どう切り離すかを決め、正典を書き換える。

## 完了条件

- 切り離した形（何で日記を書かせるか・どこに何が出るか・会話のセッションに何が残らないか）が `docs/requirements.md`「4.11 成果の振り返り」と `docs/design.md`「日記の受け取りと保存」に書かれ、「会話へ1ターンの依頼を送る」の決まりが改まっている
- 採らなかった案と理由が正典のどこかに1〜2行で残っている
- 実装タスク（このタスクに依存する後続）の本文の `## 背景`・`## 決まっていること（蒸し返さない）` を、決めた形に揃えてある
- `bun run check` が通る

## 背景

- 送り口は `src/server/core/session-manager.ts` の `reflectAchievement`。成果を読み直し、会話のターン中なら断り、`generation.driver` に `beginDiaryDay` で書く日を渡してから `prompt` で依頼文を送る。`diary-requested` のイベントを会話の流れに流す
- `diary` ツールは `src/server/core/diary-tool.ts`。会話の SDK セッションの MCP ツールとして載っている
- 依頼文は `achievementReflectionRequestText`（`docs/requirements.md` 4.11 の例文）。雑談モードの有無も読む
- `docs/requirements.md` 4.11「決まっていること」に「会話へ1ターンの依頼を送る」「押しても画面は会話へ移らない」、`docs/screen-design.md` 13.10 に振り返り中の帯の表示（`diaryWriting`）がある

## 解くべき論点

- 何で書かせるか: 会話とは別の SDK の問い合わせ（別の子プロセス・`diary` だけを持たせる）か、同じ駆動の中で会話に見えないターンにするか。人格（`persona.md` と append）は効かせたい
- 会話のターン中でも振り返れるようにするか（いまは断っている）。同時に走ったときの消費
- 書いている最中と書き終えたときの吹き出し・セリフを成果の画面でどう見せるか（会話のキャラビューに出さないなら、成果の画面の立ち絵の吹き出しに出すか）
- 使用量の記録（token-usage）に振り返りの分をどう数えるか
- 作業ディレクトリ・許可モード・モデル・effort は何を使うか（ファイルを読みに行かせない依頼なので、ツールを絞れるか）

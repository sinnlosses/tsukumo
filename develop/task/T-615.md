## 目的

`<dialog>` を `showModal()` で開く箇所が10ファイルあり、`useModalDialog` の呼び出し・`::backdrop` の規則・閉じる口の置き方を各自が書いている。ダイアログの部品を作って背景の暗さ・置き方を variant で表し、置き換える。

## 完了条件

- `docs/design.md` 2章「`components/ui/` の部品（variant の作法と一覧）」の一覧どおりの `Dialog`（`open`・名前（`aria-label` か `aria-labelledby` の合併型）・`backdrop`・`placement`・`onClose`・`className`・`children`。props はすべて必須）が `src/browser/components/ui/dialog/dialog.tsx`・`dialog.module.css` にある。`useModalDialog` の呼び出し・Esc の `close`・backdrop のクリックの読み替え（`event.target` が `<dialog>` 自身のときだけ）を部品が持ち、どれも `onClose` を呼ぶ。`backdrop` は `dim`（`ground` の 70%）/ `deep`（88%）/ `clear`（透明）、`placement` は `{ kind: "auto" }` / `{ kind: "at"; top; left }`。顔と箱（幅・余白・地・枠・角丸・影）は持たない
- `test/browser/components/ui/dialog/dialog.test.tsx` に、`open` への追随（開く・閉じる）、Esc（`close` イベント）と backdrop のクリックで `onClose` が呼ばれること、中のクリックでは呼ばれないこと、`backdrop` のすべての値 → 付く class、`placement: "at"` の座標、名前の付き方のテストがある
- 下の「背景」の10個の `<dialog>` が `Dialog` に置き換わり、各機能の `::backdrop` の規則と「backdrop を押したら閉じる」の読み替え（フックの `onDialogClick` など）と `useModalDialog` の呼び出しが消えている。残したものは理由を結果に1行ずつ書く
- `ImageZoom` が `Dialog` を使っている（`components/ui/` どうしの import）
- `test/architecture.test.ts`「components/ui/ の部品の className」が `Dialog` を対象にして通る（検査がまだ無ければこのタスクで足す。足し方は T-607 の完了条件と同じ）
- `docs/design.md` 6.1「部品の置き場」の段落に `<Dialog>` を足してある
- 置き換えたダイアログをすべて開いて目視し、背景の暗さ・置き方・閉じ方（閉じる口・Esc・外側クリック）が置き換え前と同じであることを確かめている（何を見たかを結果に書く。重ねて開く2箇所は、下のダイアログの上に出ることと、上だけが閉じることも見る）
- `bun run check` が通る

## 背景

- `<dialog>` を持つファイル（計画時は12と数えたが、`task-table.tsx`・`task-run-button.tsx` はコメントの中だけだった）: `features/task-board/presentational-task-board.tsx`・`components/task-run-confirm.tsx`、`components/domain/sidebar/persona-memory-section.tsx`、`page/achievement/diary-book.tsx`、`page/character/components/character-delete-confirm.tsx`・`character-profile-edit-dialog.tsx`・`portrait-clear-confirm.tsx`、`page/character/presentational-character-create.tsx`、`page/conversation/character-view/presentational-speech-log.tsx`、`components/ui/image-zoom/image-zoom.tsx`
- 10個すべてが `useModalDialog` と backdrop のクリックの読み替えを書き写している（フックに持つもの: `use-task-board.ts`・`use-diary-book.ts`・`use-character-create.ts`・`use-speech-log.ts`）
- `::backdrop` の規則は 9。`ground` の 70% が6、88% が日記帳、透明が2（`.character-clear-confirm`・`.speech-log`）
- `portrait-clear-confirm.tsx` は位置を inline style の座標で指定する（`placement: "at"`）。`.speech-log` は CSS の anchor positioning で置く（`placement: "auto"` のまま `className` で置く）
- `use-speech-log.ts` は開いた直後にスクロールを下端へ送る effect を持ち、`showModal()` のあとに走る必要がある（コメントあり）。`Dialog` は子なので、その effect は親のフックより先に走る
- 開閉は `src/browser/hooks/use-modal-dialog.ts` の `useModalDialog(open)`。重ねて開く（表のモーダルの上に確認を開く）箇所がある（`task-run-confirm.tsx`・`persona-memory-section.tsx`）
- 作法は `docs/design.md` 2章「`components/ui/` の部品（variant の作法と一覧）」が正典

## 決まっていること（蒸し返さない）

- `Dialog` が持つのは振る舞い（開閉・Esc・外側クリック）と背景（`backdrop`）と置き方（`placement`）だけ。顔と箱は呼び出し側の `className`（顔を揃えるかは別の判断として持ち越し）
- **見た目を変えない。** 日記帳の 88% は `deep` として残す
- 外側クリックで閉じるのは全部のダイアログ共通なので、variant にしない

## 注意

- `Dialog` の読み手には機能の外（`ImageZoom`）も数えられる。「browser/ の機能をまたぐ箱」の検査はそのまま通る

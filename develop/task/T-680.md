## 目的

ブラウザ側の自作 store（`useSyncExternalStore` の定型と Context の Provider）を zustand に寄せる
最初の1件。小さい store を1つ置き換えて、残りへ広げるときの形（store の置き場所・セレクタの書き方・
テストでの差し込み方）を決める。

## 完了条件

- `src/browser/stores/question-scroll.tsx`（56行）か `src/browser/stores/turn-selection.tsx`（83行）の
  どちらか1つが zustand の store になり、`subscribe` / `getSnapshot` / listeners の定型が消えている
- `zustand` が `dependencies` に入っている
- `docs/coding-standards.md`「React」節に、zustand の store の書き方と `useShallow` の使いどころ
  （セレクタがその場で配列・オブジェクトを作るときだけ）が書かれている
- 後段（zustand の残りを置き換えるタスク）の本文を、決めた形に合わせて直している
- `bun run check` が通る

## やること

前提を確かめ直した: `T-669`（`test/browser/stores` の単体テスト監査）はまだ済んでおらず、
`test/browser/stores/turn-selection.test.tsx` は残っている（`question-scroll.tsx` 側の単体テストは
元から無い）。前提は崩れていないので作業する。

- `question-scroll.tsx` を選ぶ。`turn-selection.tsx` は `useSessionSelector`（Context ベースの
  `session.tsx`）と `useHashRoute`（`location-hash.ts`）という**他の store の hook が返す値から
  毎レンダー導く値**を持ち、zustand の store（React の外に置く独立した状態）にすると逆に
  読みにくくなる。`question-scroll.tsx` は「押された回数」と「増やす」だけの自己完結した状態で、
  最小の形をまず決めるのに向く
- `src/browser/stores/question-scroll.tsx` を `create<QuestionScrollState>()((set) => ({ signal, requestScroll }))`
  に書き換え、`QuestionScrollContext` / `QuestionScrollProvider` を消す。呼び出し側
  （`question-ask.tsx`・`use-current-work.ts`）はセレクタで自分が読む値だけを購読する形
  （`useQuestionScroll((state) => state.signal)`）に直す。`app.tsx` から `<QuestionScrollProvider>`
  を外す
- テストで値を差し込んでいた4ファイル（`main-view.test.tsx`・`screen-nav.test.tsx`・
  `settings.test.tsx`・`current-work.test.tsx`・`question-ask.test.tsx`）を、`Provider` を経由せず
  `useQuestionScroll.getState()` / `setState()` を直接読み書きする形に直す
- `docs/coding-standards.md`「React」節に `### zustand の store` を足し、置き場所（`stores/` の
  `create()`）・セレクタの書き方・`useShallow` の使いどころ・テストでの差し込み方
  （`getState()` / `setState()`）を書く
- `develop/task/T-681.md` の本文を、決めた形と `question-scroll.tsx` が済んだ事実に合わせて直す

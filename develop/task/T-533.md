## 背景

2026-09-24 に `/simplify` の4観点（再利用・単純化・効率・根本対処）でリポジトリ全体を洗った結果の1件（`docs/history/direction.md` の 2026-09-24「改修コストを下げる直し9件」）。

`src/server/adapter/character-edit.ts` の `applyEdit` で、`set-portrait` と `set-background` の枝が「画像をほどく → ファイル名を決める → 上限を確かめる（`withinImageFileLimit`）→ 前のファイル名を控える → 書き込む → 定義を書き換える → 参照されなくなった画像を消す（`removeUnreferencedImage`）」を同じ順で書き写している。`clear-portrait` と `clear-background` も同じ3行の写し。画像の扱いを変えるたびに4箇所を揃える必要がある。

また、読めなければ `undefined` を返す `readOptionalFile` が `character-edit.ts` と `src/server/adapter/character-pack.ts` に同じ中身で1つずつある。

## やること

1. 立ち絵と背景で違うもの（画像のほどき方・ファイル名・定義の読み書き）だけを受け取る関数を1つ作り、set の2枝と clear の2枝をそれで書く
2. `readOptionalFile` を `character-pack.ts` の側から export し、`character-edit.ts` はそれを使う（`character-edit.ts` はすでに `character-pack.ts` から import している）

## やること（着手前の調査で確認）

現状のコード（`src/server/adapter/character-edit.ts` の `applyEdit`、247〜297行）は背景に書かれた
4枝の重複と `readOptionalFile` の二重定義（同ファイル419行と `character-pack.ts` 387行）が
そのまま残っており、前提は崩れていない。

1. `applyEdit` に、立ち絵と背景で違う部分だけを受け取る共通関数 `applyImageEdit` を1つ追加する。
   引数は `dir` / `definitionPath` / `content` / `edit`。`edit` は「消す」を素の `| undefined`
   にせず判別可能な合併型（`{ kind: "set"; image; parseImage; fileName; previousFileName;
withImage } | { kind: "clear"; previousFileName; withoutImage }`）で表す型 `ImageEdit<Image>`
   （`Image` は画像の型で総称化）。**当初は `action`（`set`/`clear`）と `descriptor`
   （`parseImage`・`fileName`・`previousFileName`・`withImage`・`withoutImage`の5つを持つ1つの型）
   を分ける設計にしたが、`clear-portrait` の表情は `RemovableExpression`（`default` を除く）、
   `set-portrait` の表情は `Expression`（`default` を含む）で型が違い、1つの `descriptor` に
   両方の `withImage` と `withoutImage` を同居させると型検査が通らなかった（`tsc --noEmit` が
   実際に検出）。`action` と `descriptor` を1つの判別可能な合併型 `ImageEdit` に統合し、
   `kind` ごとに必要なフィールドだけを持たせて解決した**。中身は「ほどく → ファイル名を決める →
   上限を確かめる → 前のファイル名を控える → 書き込む → 定義を書き換える → 参照されなくなった
   画像を消す」を1回だけ書く（`clear` はほどく・上限確認・書き込みを飛ばす）
2. 立ち絵向け・背景向けの `ImageEdit` を組み立てる関数（`portraitSetEdit(expression, image)` ・
   `portraitClearEdit(expression)` ・ `backgroundSetEdit(image)` ・ `backgroundClearEdit()`）を作る
3. `set-portrait` / `clear-portrait` / `set-background` / `clear-background` の4枝を、それぞれ
   `applyImageEdit` を1回呼ぶだけの形に書き換える
4. `character-pack.ts` の `readOptionalFile`（387行）を `export function` にし、
   `character-edit.ts` の同名関数（419行）を消して import に差し替える

**調査で分かった追加の前提のずれ**: `grep -rn "function readOptionalFile" src` は着手前の時点で
実際には4件（`character-edit.ts` ・ `character-pack.ts` ・ `persona-memory.ts` ・
`chat-summary.ts` ・ `vendor-asset.ts` 、ただし `vendor-asset.ts` は `Buffer | undefined` を返す
別物）だった。`## 背景` は `character-edit.ts` と `character-pack.ts` の2件しか把握していない。
完了条件の「1件」を素直に満たすため、`persona-memory.ts` と `chat-summary.ts` の同一の中身の
`readOptionalFile`（どちらも `string | undefined` を返す、`character-pack.ts` の版と全く同じ実装）
も import に差し替える。`vendor-asset.ts` は返り値が `Buffer` で概念が異なる別物
（`character-pack.ts` の `readOptionalBinaryFile` と同じ役割）なので、名前の衝突だけを解くために
`readOptionalBinaryFile` へ改名する（呼び出し側はファイル内の1箇所だけで、実装は変えない）。

## 目的

委譲先の報告の「気になった点」を、終わってから思い出して書く自由記述から、作業中にその場で書き留める札つきの1行（friction log）に替え、取りこぼしを減らして受け入れで数えられるようにする。

## 完了条件

- `next-task` 手順5の依頼文が、委譲先に `retrospect` の SKILL.md の節「札と1行の書式」の1行（`- <色> <札>: <何が起きたか>（<根拠の場所>）`）で friction log を書かせ、報告に載せさせる（「気になった点」の自由記述を置き換える）
- `retrospect` の「1件だけ振り返る」の兆候の表の「報告に残した気になる点」の行が friction log を読み、`赤` の行は1件でも手順4の物差しにかける（札の候補の列は T-779 で「行に付いた札」になっている）
- friction log が空のときの扱い（何も無かったのか、書き忘れか）を決めて書いてある
- claude-skills 側の検査（`./check.sh`）が通り、claude-skills の `main` に入っている
- このリポジトリの `pnpm run check` が通る

## 背景

- いまの `next-task` は手順5で委譲し、報告の「気になった点」を `retrospect` の「1件だけ振り返る」の兆候の表（「報告に残した気になる点」の行）で拾う
- T-706 では委譲先が前例のコメントを写し、メインが受け入れで7ファイル刈り込んだ。委譲先が自分で「規約に反するかも」と書き留める口があれば受け入れの前に見えた
- 語彙と書式は T-779 で `retrospect` の SKILL.md の節「札と1行の書式」に入った（札10個・色は `赤`・`黄` の2段で緑は書かない）。ここでは書かせる口と読む口を作る
- 委譲先は `${CLAUDE_SKILL_DIR}` を持たないので、依頼文ではメインが解決した SKILL.md のパスと節の名前を渡す。`next-task/REQUIRES` はいま `task-workflow` だけで、`retrospect` を足すかもここで決める

## やること

前提を確かめ直した。`retrospect` の SKILL.md には T-779 で「札と1行の書式」節と「1件だけ振り返る」の
兆候表がすでにあり、背景の記述と一致している（前提は崩れていない）。一方 `next-task` の SKILL.md
手順5の依頼文には「気になった点」を書かせる行が無く、委譲先が終わってから自由記述で書くのは
暗黙の運用だった。よって:

- `next-task` の SKILL.md 手順5に、委譲先へ「気になった点」を friction log（`retrospect` の節
  「札と1行の書式」の1行）で書かせ、報告に載せさせる指示を足す。SKILL.md のパスは
  `${CLAUDE_SKILL_DIR}/../retrospect/SKILL.md` を書き、実際に委譲するときはメインがこれを解決した
  絶対パスに置き換えて渡す旨を注記する（委譲先は `${CLAUDE_SKILL_DIR}` を持たない）
- friction log が空のときの扱い: 何も起きなければ「friction log: なし」と明記させる（行自体が
  無ければ書き忘れ、`なし` と書いてあれば確認済みで何も無かった、と区別できるようにする）
- `retrospect` の SKILL.md「1件だけ振り返る」の兆候表の「報告に残した気になる点」の行を、
  委譲先の報告の自由記述ではなく friction log を読む形に更新し、`赤` の行が1件でもあれば
  手順4の物差しにかけると明記する
- `next-task` の `REQUIRES` に `retrospect` を足す（手順6a・手順5の両方で retrospect の
  SKILL.md を直接指すようになるため）
- claude-skills 側は別の作業ツリーで編集し `./check.sh` を通してから `main` へ入れる

## 注意

- `~/.claude/skills` は claude-skills の本体の作業ツリーへの symlink。本体で枝を切らず、`git -C ~/ghq/github.com/sinnlosses/claude-skills worktree add` で別の作業ツリーを作って編集してから `main` に入れる
- 依頼文を長くしすぎない（委譲のたびに載る）。札の定義は正典を指し、依頼文に写さない

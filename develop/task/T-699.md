## 目的

`docs/coding-standards.md`「コメント」の「Markdown の記法を使わない」に、既存のコードを合わせる。
強調の `**…**` は機械的に消せるので、一括で消したうえで、再び入り込まないよう検査を足す。

## 完了条件

- `src` / `test` / `scripts` の `*.ts` / `*.tsx` のコメント行から、強調の `**` がなくなっている
  （着手時の件数は `grep -rcE '^\s*(//|\*).*\*\*[^*]+\*\*' src test scripts` で数え直す。
  2026-09-26 の時点では 446 ファイル・2654 行）
- `test/architecture.test.ts` に、コメント行が強調の `**` を含まないことを確かめる検査がある。
  既にある「コメント中の日付」（`COMMENT_LINE_START`）と同じく、行頭がコメントの行だけを対象にする
- 変わっているのはコメントだけ（コードの差分が無い）。`git diff` の `+`/`-` 行が、どれもコメント行であることを確かめてある
- `bun run check` が通る

## 背景

- 規約: `docs/coding-standards.md`「コメント」の「書き方は2つ守る」（2026-09-26 に足した）
- 検査の手本: `test/architecture.test.ts` の `describe("コメント中の日付")`（`COMMENT_LINE_START = /^\s*(\/\/|\*|\/\*)/`）

## 決まっていること（蒸し返さない）

- 消すのは強調の `**` だけ。囲まれていた文字は残す（2026-09-26 ユーザーの決定）
- 意味の切れ目での改行は機械で検査できないので、このタスクでは直さない。そのファイルを触るときに直す
  （同日ユーザーの決定。規約に書いてある）

## 注意

- **JSDoc の開き `/**` を消さない。** 行頭が `/**` の行や、`/** … */` の1行コメントの開きは強調ではない
- 強調は2行にまたがることがある（行末で開き、次の行で閉じる）。行ごとに `**` の対を探すのではなく、
  コメント行の中の強調の `**` をすべて消す形にする。消したあとに `**` が1つだけ残る行が無いかを見る
- コメントでない行（文字列リテラル・コード）の `**`（べき乗など）には触らない
- 400ファイルを超える差分になり、並行する作業ツリーと衝突しやすい。着手したら寄り道せずに1コミットにまとめて送る
- 人に委ねる判断は無いので `Y`

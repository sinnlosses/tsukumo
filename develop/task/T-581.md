## 決まっていること（蒸し返さない）

利用者との会話（2026-09-25）で決まったこと:

- **合わせるのはディレクトリだけ。** kebab-case のファイル名・barrel file（`index.ts`）を作らない・`@/` を使わず相対 import、の規約は残す。手本の PascalCase・1部品1フォルダ・`index.ts`・`@/` は真似しない
- **`features/` は残す。** bullet-proof-react と同じ役割。ただし `features/` から `components/` へ丸ごと引っ越す機能も出てくる
- **会話の画面の領域は「枠は domain、中身は page」。** `layout`・`screen-nav`・`sidebar` は全画面で共有する枠なので `components/domain/`。`main-view`・`character-view`・`chat-view`・`dispatch` は `components/page/conversation/`。キャラクター・使用量・成果の画面は `components/page/<画面>/` に並べる
- **`domain` の意味は1つ: このリポジトリ固有（ドメイン）のものを置くところ。** `browser/domain/` は全体で使う語彙、`components/domain/` は画面を構成する部品のうちドメインのもの。改名しない
- いまの `browser/components/` のうち語彙を持たない部品（Select・ImageZoom など）は `components/ui/`
- 移動は段に分ける（このタスクの後ろに、枠・会話の画面・残りの画面の順で移すタスクが並ぶ）

## 解くべき論点

- **`features/` に何が残るか。** 上の決定を当てると11機能のうち10が `components/` へ移り、`task-board`（置かれる機能）だけが残る。各機能の中の `hooks/` `domain/` `components/` や `.module.css` を、移る部品と一緒に運ぶのか、`features/<機能>/` にロジックとして残すのか（bullet-proof-react の features の役割との整合）
- **箱どうしの依存の向き。** `components/page` → `components/domain` → `components/ui` の向きと、`features/` `stores/` `browser/domain/` との辺。`components/page/conversation/` の中の4つ（main-view など）どうしの横の import をいまの「領域どうしは import しない」と同じく禁じるか
- **`Portrait` `CharacterFace` `PromptImage` `ProtocolMismatch`** は tsukumo の語彙を持つので `components/domain` か `ui` か。`browser/hooks/` の3本（`use-modal-dialog` など）の置き場
- **画面の組み立て（`main.tsx` の `<Root>` と `OVERLAY_SCREEN`）** を入口に残すか、手本の `Application.tsx` / `TopPage` のように `components/domain` や `components/page/<画面>/` の部品へ移すか
- `components/page/<画面>/` の画面名（`conversation` `character` `token-usage` `achievement`）を `stores/location-hash.ts` の `Screen` の値と揃えるか

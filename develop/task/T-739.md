## 目的

`test/e2e/turn-history.test.ts` の「複数のやり取りが札として積み上がり、長い依頼の1行目は省略される」が、差分と関係なく `bun run check` の中でときどき落ちる。揺れを止め、受け入れの検証を打ち直さずに済むようにする。

## 完了条件

- 落ちる原因を特定し、タスクファイルに書く（待ちの条件・順序の前提など、どこが揺れるのか）
- 原因を直し、`bun run test:e2e` を続けて10回流して落ちないことを確かめる（回数と結果を報告に書く）
- `bun run check` が通る
- 手元で何度流しても再現せず原因も見当たらないときは、試した回数と調べたことを書いて `dropped` で閉じてよい

## 背景

- 2026-09-27、ドキュメントだけの差分の受け入れで `bun run check` を3回流したところ、2回目にこの E2E が1件落ちた（23 pass / 1 fail）。3回目は通った
- テストは `test/e2e/turn-history.test.ts` の18行目。`room.waitForEvent("turn-finished", LAST_TURN_FINISHED_OCCURRENCE)` でターンの終わりを待ってから札を数えている
- E2E の走らせ方は `docs/design.md`「E2E の走らせ方」

## 注意

- 別の E2E の揺れ（「⌘Enter で送ると prompt が流れ…」）を直すタスクと、E2E を速くするタスクがある。原因が共通だと分かったら、そのタスクの `## 注意` に書き添える
- 待ち時間を延ばすだけの直し方はしない（何を待つかを直す）

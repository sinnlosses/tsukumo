## 目的

`report` の塊の型が持つ意味を見た目に写し、書き手に何も選ばせずに表と長いレポートを読みやすくする（`docs/research/report-block-richness.md` 2章・7章の1）。schema は変えない。

## 完了条件

- `table` の列の全セルが数なら右揃えと `tabular-nums` で描く（判定は組み立ての1箇所に置き、列に `align` を持たせない）
- `table` の `status` のセルを列の中で中央に揃え、バッジの文字（OK / 要注意 / NG）を tsukumo が必ず付ける。行は塗らない（`docs/screen-design.md` 13.2 の決定のまま）
- 書き上げる演出のトピックの単位を、見出しを DOM から探す判定から節（`sections`）に置き換える（`src/browser/domain/reveal/plan.ts`）。見出しの見た目は変えない
- 表（数の列・状態の列）と演出の区切りを目視で確かめ、何が見えたかを結果に書く
- `docs/display.md` 4.2 の描き方の記述を合わせる
- `pnpm run check` が通る
- T-705 のあとの形で成り立たないと分かったら、理由を書いて `dropped` で閉じてよい

## 背景

- 提案と実測: `docs/research/report-block-richness.md`（数だけの列を持つ表が本文の有るレポートの 5.6%、見出しが3つ以上のレポートが 21.1%）
- 塊の形は `docs/research/report-block.md` 4章。塊から Markdown を組むのは `reportSectionsMarkdown`（`src/shared/report/report-block.ts`）で、描き方の判定はここに置く
- T-804 の提案（`docs/research/report-architecture.md`）で、この段はそのまま残した（モデルの出力を変えないので、記録の語彙を足すタスクと並べて進めてよい。7章の2段）
- 演出の割り方はいま `src/browser/domain/reveal/plan.ts` が見出しから決めている

## やること

- 前提の確認: T-705・T-804 はどちらも main に入っている（`git log --all --oneline | grep "T-705\|T-804"`）ので、
  依存は崩れていない。`src/shared/report/report-block.ts` の `cellSchema`（`status` セルとバッジ）・
  `tableMarkdown` は背景の主張どおり存在し、判定を置く場所として使える
- `report-block.ts` の `tableMarkdown` に列ごとの揃えの判定（`columnAlign`）を足す。列の全セルが
  `{status,text}` なら `center`、全セルが数（符号・桁区切り・小数点・末尾 `%` を許す正規表現）なら
  `right`、それ以外は `left` とし、GFM の列揃え記法（`---:` / `:---:`）で出す（`align` は列に持たせない）
- `report-notation.module.css` の表のセルに `font-variant-numeric: tabular-nums` を足す（列の揃えは
  GFM の列揃えが `th` / `td` の style 属性で届くので CSS の揃えは足さない）
- 状態のセルのバッジに、状態の語（OK / 要注意 / NG）を tsukumo が付ける。書き手の文字が同じ語なら重ねない
- 演出のトピックの単位を節に置き換える件は、見出しタグ（`h4` 等）や水平線を DOM から探す形に
  narrowing するだけでは「見出しを DOM から探す判定」が残ってしまうため、**節を組み立てる側
  （`reportSectionsMarkdown`）が節と節の境目にだけ見た目を持たない印（`<div
class="report-section-break"></div>`）を挟み**、`plan.ts` はその印の前後で切るだけにする
  （印そのものはトピックの要素に数えない）。見出しの無い節どうしの境目にも印が入るので、
  見出しの無い節も1つのトピックになる。印は `report-notation.module.css` で装飾しない
  （高さ0の空 `div` のまま。CSS Modules を経由しない生の class 名で、`badge` / `note` と同じ
  「モデル・tsukumo が書く class 名とスタイルを直接つながない」慣習に乗る）
- `plan.ts` の `TOPIC_START_SELECTOR` を `.report-section-break` の一致に置き換え、`toTopics` は
  印に当たったら「次の要素から新しいトピック」を覚えるだけにする（印自体はメンバーに含めない）
- `test/browser/domain/reveal/plan.test.ts` を新しい境目の印に合わせて書き換え、見出し・副見出し・
  水平線だけでは塊を分けないこと、見出しの無い節どうしの境目にも印が入ることを足す
- `test/shared/report/report-block.test.ts` に数の列の右揃え・境目の印のテストを足す
- `docs/display.md` 4.2 に、表の揃えの決め方と、節を演出の単位にする決め方（印の仕組み）を追記する
- 目視: Storybook にこの2点の見本（`AutoAlignedTable` / `Sections`）を足し、`pnpm run storybook` +
  Playwright のスクリーンショットで確認する
- `pnpm run build` と `pnpm run check` を通す

## 注意

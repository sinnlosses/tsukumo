## 背景

切り替え（T-526）と `progress.md` の解体（T-527）のあと、tsukumo の `CLAUDE.md`（「## タスク運用」「進捗管理とHandoff」「Git運用」「導入済みスキル」）と `docs/workflow.md` にはまだ旧運用（`doing` のコミット、アーカイブを単独で送る、`git merge main`、マージドライバ）の説明が残っている。共通スキル（T-524）が手順を持つようになったので、tsukumo 側には共通版が知らない事情だけを残す。承認済みの方針は `docs/history/direction.md` の 2026-09-24 の「タスク運用の作り直し」の項にある（1件1ファイル・着手の印は共有の `.git` の中・完了は作業のコミットに同梱して rebase → ff-only で1回送る・錠の中で採番・`progress.md` をなくす・登録は粗く着手時に確かめ直す・手順は `task` コマンドに）。

## やること

1. `docs/workflow.md` を、tsukumo 固有の事情（`loopable` の判定、目視の道具、`summary` の40字、参考画像の残し方、確認手順が触る資源の書き方など）だけに縮める。旧運用の決定の経緯は `docs/history/` 側へ寄せる
2. `CLAUDE.md` の上の4節を、共通スキルの設定（検証コマンド・整形コマンド・ブランチ）と `docs/workflow.md` への参照に縮める。`git merge main` を `task ship`（rebase → ff-only）に置き換える
3. `docs/architecture.md` の worktree と `doing` の設計判断を新しい形に直す
4. T-525 で残した旧形式（`develop/tasks.json`）の読み口をタスク板から消す

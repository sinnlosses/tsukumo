## 背景

`task` コマンド（T-521〜T-523）、書き直したスキル（T-524。claude-skills の枝 `feature/tsukumo-T-524` にあり `main` には未投入）、新しい形式を読むタスク板（T-525）がそろったので、一度に切り替える。承認済みの方針は `docs/history/direction.md` の 2026-09-24 の「タスク運用の作り直し」の項にある（1件1ファイル・着手の印は共有の `.git` の中・完了は作業のコミットに同梱して rebase → ff-only で1回送る・錠の中で採番・`progress.md` をなくす・登録は粗く着手時に確かめ直す・手順は `task` コマンドに）。

途中の作業ツリーが古い `develop/tasks.json` に done を書くと行き場がなくなるので、**tsukumo の全作業ツリー（`git worktree list`。登録時は本体と tsukumo-2〜6・tsukumo-task）が手を止めている間に**行う。

## やること

1. 利用者に全作業ツリーの手が止まっていることを確かめてもらう。`main` の `develop/tasks.json` に doing が無く、各作業ツリーに `main` へ入っていないコミットや未コミットの変更が無いことを確かめる（あれば止めて預ける）
2. claude-skills の枝 `feature/tsukumo-T-524` を claude-skills の `main` へ入れる。claude-skills 自身の `develop/tasks.json` も `task migrate` で移す
3. tsukumo の `main` で `task migrate` をかけ、`develop/tasks.json` を `develop/task/` に移す
4. T-519 の検査の読み元を `develop/task/` と `docs/history/tasks.md` に差し替える
5. `todo` のタスク本文と tsukumo の `CLAUDE.md`「## タスク運用」から `develop/tasks.json` を名指ししているところを、新しい形で読める程度に直す（全面の書き直しは T-528）
6. `/list-tasks` と `task status` の一覧が移行前と ID・status で一致すること、タスク板に一覧が出ることを確かめる

## 完了条件

- 移行前後の一覧が一致する（`evidence` に件数）
- tsukumo の `bun run check` と claude-skills の `./check.sh` が通る
- このタスク自身の完了が新しい形式（`develop/task/T-526.md` の `## 結果`）で記録されている

## 注意

- `loopable` が N なのは、全作業ツリーが手を止めていることを確かめられるのが利用者だけだから
- 他のプロジェクト（Git-Bulk-Maestro・gitlab-watari-dori・helm-yadokari）は移さない。次にスキルを呼んだときに移行の案内で止まることを、完了報告で利用者に伝える
- 各作業ツリーは再開するとき、`git rebase main` で追い付いてから始める

## やること

前提の確認（2026-09-27、実物で）: `T-684`（4db639a1）で `pnpm run build` は `vite build` になっている。
`docs/research/ui-catalog.md` は Storybook を見送っており、理由は背景の2つのとおり（class 名の綴りと依存の数）。
`scripts/capture-catalog.ts` は疑似セッションの場面を Playwright で撮っている。前提は崩れていない
（ui-catalog.md の日付は本文では 2026-09-21。指示が 09-20）。

- `storybook` / `@storybook/react-vite` 10.6.0 を devDependencies に入れ、`pnpm run storybook` を足す
- `.storybook/main.ts` は `vite.config.ts` をそのまま読む（`viteConfigPath`）。立ち絵の
  `/character/<pack>/<file>` は `staticDirs` で同梱の `characters/` を、`/vendor/<name>` は
  `readVendorAsset` を呼ぶ Vite の middleware で配る（対応表を二重に持たない）。telemetry は切る
- `.storybook/preview.tsx` で `theme.css` と QueryClientProvider を、`preview-head.html` で
  コードの色付けのテーマを読む
- story は3つ: `Report`（note 6種・badge・表・mermaid・Chart.js・全部入り）、`Portrait`（SVG・ラスタ・動き）、
  `PresentationalCharacterView`（立ち絵と吹き出し。空・長文・立ち絵なし）。文面はすべて架空
- CSS Modules の綴りが `dist/browser/main.css` と一致することを実測で確かめる

論点の結論:

- **`capture-catalog.ts` は残す。** Storybook は部品を props で切り替えて見る道、`capture-catalog.ts` は
  tsukumo を起こして画面に入れたときの見え方（スクロール・モーダル・補完・狭い窓・実データ）を撮る道として
  分ける。ui-catalog.md 2章のとおり崩れの多くは領域に入れたときに出るので、`evidence` は
  `capture-catalog.ts` のまま。story を撮る形に寄せると疑似セッションとサーバの組み合わせが写らなくなる
- **story は `src/` に置かず `story/` の下に、部品と同じ相対パスで置く**（`src/X.tsx` → `story/X.story.tsx`。
  テストの `test/` と同じ写し方）。`src/browser/` に置くと、箱・機能の辺の検査（「引き金は逆にも引く」の
  読み手の数え方など）が story を読み手に数え、例外を足すことになる。外に置けば既存の辺は触らずに済み、
  読む人は「部品の story は同じパスの story/ にある」だけを覚えればよい
- `test/architecture.test.ts` に「story の置き場」を足す: `src/` に story が無い・`story/` の story は
  同じパスの部品を持つ・story の相対 import は `src/browser/` と `src/shared/` だけ。
  コメントの日付と強調の検査の対象に `story` `.storybook` を足す（lint の対象と揃える）
- Storybook の型定義が TypeScript 7 と噛み合わず（`react-docgen-typescript` の `.d.ts`）、`skipLibCheck` が要る。
  本体の `tsconfig.json` には掛けず、`tsconfig.storybook.json`（story と `.storybook` だけ）に分けて
  `typecheck` で両方を回す
- docs: `docs/architecture.md`「手で確かめること」に分担、`docs/design.md` 2章「ディレクトリ」に置き場、
  11章「ビルドと依存」に依存と設定、`docs/research/ui-catalog.md` に採り直しの追記、README の「開発」に起動

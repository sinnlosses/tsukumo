## 目的

`display: flex` + `flex-direction` + `gap` + `align-items` だけで書かれた「並べるための規則」を、`components/ui/` の並べる部品に寄せる。まず全画面で共有する枠（`components/domain/`）と置かれる機能（`features/`）から置き換え、部品の API を固める。

## 完了条件

- T-606 が `docs/design.md` 2章に書いた作法どおりの並べる部品が `src/browser/components/ui/` にあり、`test/browser/components/ui/` にその振る舞い（variant → 描かれる class・要素）のテストがある
- `src/browser/components/domain/` と `src/browser/features/` の `*.module.css` から、並べるだけの規則（flex の向き・間隔・揃えしか持たないもの）が消え、部品に置き換わっている。並べる以外の見た目も持つ規則を残したときは、その理由を結果に1行ずつ書く
- 置き換えた画面（サイドバー・画面のナビの帯・タスクの一覧と表）を起動して目視し、崩れが無いことを確かめている（何を見たかを結果に書く）
- `bun run check` が通る

## 背景

- 計画時の実測で、`display: flex; flex-direction: column; gap` の規則は 15ファイル72、`display: flex; align-items: center; gap` は 19ファイル46。`domain/` と `features/` のうち量が多いのは `sidebar/sidebar.module.css`（560行）、`screen-nav/` の各 `*.module.css`、`layout/layout.module.css`、`features/task-board/task-board.module.css`（502行）
- `components/page/` の置き換えは後段のタスクが受け持つ

- 描画の目視確認の手順は `docs/architecture.md`「手で確かめること」

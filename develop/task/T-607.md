## 目的

`display: flex` + `flex-direction` + `gap` + `align-items` だけで書かれた「並べるための規則」を、`components/ui/` の並べる部品に寄せる。まず全画面で共有する枠（`components/domain/`）と置かれる機能（`features/`）から置き換え、部品の API を固める。

## 完了条件

- `docs/design.md` 2章「`components/ui/` の部品（variant の作法と一覧）」の一覧どおりの `Stack`（`element`・`direction`・`gap`・`align`・`justify`・`wrap`・`className`。props はすべて必須）が `src/browser/components/ui/stack/stack.tsx`・`stack.module.css` にあり、`test/browser/components/ui/stack/stack.test.tsx` に、軸ごとのすべての値 → 付く class、`element` → 描く要素、`className` が足されることのテストがある。対応表は `satisfies Record<合併型, string | undefined>` で検査している
- `src/browser/components/domain/` と `src/browser/features/` の `*.module.css` で、**flex の向き・間隔・揃え・折り返しに置き方（margin・flex・min-width など）だけを足した規則のうち、gap が段（0 / 0.25 / 0.5 / 0.75 / 1 / 1.25rem。`8px` を含む）に乗るもの**が `Stack` に置き換わり、規則が消えている（置き方は `className` に残す）。段に乗らない gap の規則（`.task-item-body` 0.625rem・`.task-board-head` 0.6rem・`.screen-nav-identity` 10px・`.screen-nav-gates` 2px）と、箱の見た目（余白・枠・地）も持つ規則は残す。置き換えなかった規則を結果に1行ずつ書く
- `VStack`（`ui/v-stack/v-stack.tsx`）・`HStack`（`ui/h-stack/h-stack.tsx`）があり、それぞれ `Stack` の `direction` を `column` / `row` に固定して残りの props を渡すことを見るテストがある。置き換えた箇所は、向きが決まっているものを `VStack` / `HStack` で書いている
- `Stack`・`VStack`・`HStack` のどれも、読むのが2つ以上の領域・機能（か `ui` の部品）になっている（`test/architecture.test.ts`「browser/ の機能をまたぐ箱」が通る）
- `test/architecture.test.ts` に「components/ui/ の部品の className」の検査（`docs/design.md` 2章の同じ節の「検査で守る」）があり、`Stack` がその対象に入っている。**まだ無ければこのタスクで足す**（先に別のタスクが足していれば、対象に入っていることを確かめる）。足したときは、重なる property を持つ class をわざと渡して落ちることを確かめ、戻してある（壊しは一時ファイルか、このタスクで編集していないファイルに入れる）
- `docs/design.md` 6.1「部品の置き場」の段落に `<Stack>`・`<VStack>`・`<HStack>` を足してある
- 置き換えた画面（サイドバー・画面のナビの帯・タスクの一覧と表・実行の確認）を起動して目視し、並びと間隔が置き換え前と同じであることを確かめている（何を見たかを結果に書く）
- `bun run check` が通る

## 背景

- 計画時の実測（2026-09-25）で `display: flex` の規則は 186。そのうち flex の向き・間隔・揃え・折り返しに置き方だけを足した規則が 72（`page/` 60・`domain/`+`features/` 12）で、gap が段に乗るのは `domain/`+`features/` で 8、`page/` で 38
- `components/page/` の置き換えは後段（T-608）が受け持つ
- 作法（variant の表し方・`:where()` の既定・`className` で渡してよいもの・テストの範囲）は `docs/design.md` 2章「`components/ui/` の部品（variant の作法と一覧）」が正典

## 決まっていること（蒸し返さない）

- 向きの決まった並べは `VStack`（縦）・`HStack`（横）で書く。どちらも `Stack` に `direction` を渡すだけの薄い部品で、`src/browser/components/ui/v-stack/v-stack.tsx`・`ui/h-stack/h-stack.tsx` に置く（CSS と対応表は `Stack` だけが持つ）。向きを値で切り替える箇所だけ `Stack` を直接使う（2026-09-25 ユーザー決定）
- **見た目を変えない。** gap は段（`none` / `xs` / `sm` / `md` / `lg` / `xl` = 0 / 0.25 / 0.5 / 0.75 / 1 / 1.25rem）だけを受け、段に乗らない規則は丸めずに CSS に残す（丸めるかは別の判断として持ち越し）
- 汎用の `as` は持たない。`element` は `"div" | "section" | "span"` から始め、要るものが出たらテストの行と一緒に足す
- 箱の見た目も持つ規則は、このタスクでは2つに割らない（`Stack` と `className` に分けてよいのは作法の上だけで、置き換えの対象は「並べるだけ（＋置き方）」の規則）

## やること

いまのコードで `display: flex` の規則を洗い直した（`domain/` + `features/` の全 `*.module.css`。
`page/` は対象外のまま触らない）。「向き・間隔・揃え・折り返しに置き方（margin・flex・min-width
など）だけを足した」規則は12件、うち gap が段に乗るのは8件。ただし実装に入って分かった2つの
制約により、実際に置き換えるのは6件（すべて `HStack`。`VStack` の置き換え先は今回は無し）。

**置き換える6件**（すべて row。`HStack` に直す）:

- `.screen-nav-settings-row`（`screen-nav-settings.module.css`）→ `screen-nav-settings.tsx` の
  7箇所（色の行×N・モデル/effort/許可モード/速さ/訪問/リセットの各行）
- `.session-info-value`（`sidebar.module.css`）→ `session-info.tsx`・`session-switch.tsx`
- `.context-usage-row-top`（`sidebar.module.css`）→ `context-usage-row.tsx`（残る置き方が無いので
  `className` は `""`。class 自体を削除）
- `.sidebar-persona-memory-confirm-actions`（`sidebar.module.css`）→ `persona-memory-section.tsx`
- `.task-running-head`（`task-board.module.css`）→ `task-running-card.tsx`（`className` は `""`。
  class 自体を削除）

**置き換えない8件と理由**（各1行）:

- `.task-item-body` 0.625rem・`.task-board-head` 0.6rem・`.task-board-body` 0.6rem・
  `.screen-nav-identity` 10px・`.screen-nav-gates` 2px: gap が段に乗らない（丸めない）
- `.screen-nav-work`（`screen-nav-current-work.module.css`）・`.screen-nav-model-permission`:
  gap は段に乗る（後者は8px）が、**同じ要素に `shellStyles`（`screen-nav.module.css`）の
  class も重ねて**広い画面での非表示・狭い画面での縦積みを出し、`.screen-nav-panel .screen-nav-work`
  / `.screen-nav-panel .screen-nav-model-permission` が `flex-direction: column` で**メディアクエリ
  越しに向きを反転**させている。`Stack` は向きを props（JS の値）でしか持てず、`className` は
  部品の property と重ねられない（検査で守る）ので、この向き反転を保ったまま `Stack` に置き換える
  手が無い。見た目を変えずに済ませるため、この2件は現状の CSS のまま残す
- `.profile-card-text`（`sidebar.module.css`、column・gap 0.25rem・箱の見た目無し）: `Stack`/
  `VStack`/`HStack` 単体としての条件はすべて満たす唯一の column 候補だが、**domain/ + features/
  の範囲でこの1箇所しか使う場所が無い**。置き換えると `VStack` の読み手が
  `components/domain/sidebar` の1機能だけになり、`test/architecture.test.ts`「browser/ の機能を
  またぐ箱」（Stack・VStack・HStack のどれも読み手が2つ以上、の検査）に落ちる。`bun run check`
  を通すことを優先し、このタスクでは置き換えない（`VStack` 自体は作り、テストも用意する。
  実際の置き換え先は T-608（`page/` の置き換え）が別の column 候補と合わせて持つのが妥当）

## 目的

tsukumo で `/next-task` を回したときのレポート（`report` ツールで渡す本文）を、人が読んで「何が終わり、何をしたのか」がすぐ分かる形にする。いまは `/loop` の続行判断に使う機械向けの行（`SHIPPED` の範囲・消したタスクファイルの件数・`task status` の件数・`develop/direction.md` の行数・`stale`）がそのままレポートに並び、肝心の中身が埋もれている。

## 完了条件

- `/next-task` を1件回したときのレポートの `conclusion` が「`T-xxx <summary>` を完了して main へ送りました。」の形になる（タスクIDに要約を添え、`SHIPPED` の範囲と `branch=` は書かない）
- レポートの本文に、結論と重なる「完了したタスク」の行・消したタスクファイルの件数・`task status` の件数・`develop/direction.md` の行数・`stale`／`legacy_progress` を並べない。代わりに**何をしたのかを3項目程度**で書く
- `SHIPPED` 以外で止まったとき（`VERIFY_FAILED`・`CONFLICT` など）と、作業中に起きた人に知らせるべきこと（直したこと・残した判断）は、引き続きレポートに出る
- `/loop /next-task` の続行判断が、上の変更のあとも壊れない（続行に要る情報をどこから読むかが決まっていて、そのとおりに書かれている）
- 変えた先がこのリポジトリなら `bun run check` が通る。`claude-skills` 側を変えたなら、そのリポジトリでのコミットまで済んでいる
- 調べた結果、ここに書いた前提が成り立たなければ `dropped` で閉じてよい

## 背景

- 完了報告の形を決めているのは共通のスキル `~/.claude/skills/next-task/SKILL.md` の「## 完了報告のフォーマット」節（`/loop` が続行判断に使う、と書いてある）。`~/.claude/skills/` は `~/ghq/github.com/sinnlosses/claude-skills/skills/` への symlink で、**ほかのプロジェクトとも共有している**
- このリポジトリでの上乗せは `docs/workflow.md`「タスクを書くとき・受け入れるとき」にある（共通版が知らないこのリポジトリの事情だけを置く場所）
- tsukumo では、`report` の外に書いた本文は画面に出ず、締めの `speak` のあとに本文を書くと Stop hook に差し戻される。機械向けの行を「レポートの外に書く」逃げ道は無い
- レポートの記法（10か条）は `src/server/system-prompt/core/` から `systemPrompt` に載る。違反の検査は `src/server/report/core/report-violation.ts`
- ユーザーが示した直し方（2026-09-26、T-643 の完了レポートへのフィードバック）:
  - 結論は「T-643 エピソード索引の読み書きと採点を雑談のアーカイブに足す を完了して main へ送りました。」の形
  - 本文の「完了報告」の塊のうち、完了したタスク（結論と重複）・消したタスクファイル・`task status`・`develop/direction.md` の行数・`stale`／`legacy_progress` は要らない
  - 必要なのは、何をしたのかを3項目程度で説明すること

## 解くべき論点

- **どこを直すか**: (a) 共通の `next-task/SKILL.md` の完了報告の節を「人に見せる報告」と「`/loop` が読む行」に分ける、(b) このリポジトリの `docs/workflow.md` に tsukumo での上乗せとして書く、(c) tsukumo 側（`systemPrompt` やレポートの規約）に置く。**ほかのプロジェクトでも同じ直しが効くべきか**と、**`/loop` が続行判断に何を読んでいるか**（レポートの `report` ツールの引数もモデルには見えているので、どこかに1行あれば足りるのか）を確かめてから決める
- `/loop` 用の件数（`ready`・`hold`・`N`）を残すなら、どこに置けば「人に要らない情報」にならないか（例: レポートの外に置けない以上、`<details>` に畳むか、`/loop` のときだけ出すか）
- `plan-tasks` など、ほかのタスク運用のスキルの完了報告にも同じ直しを広げるか（広げるなら別タスクに切る）

## 注意

- `claude-skills` を直すときは、本体の作業ツリーで枝を切らない（`~/.claude/skills` は本体の作業ツリーへの symlink なので、checkout すると全プロジェクトのスキルが即座に変わる）。別の作業ツリーで作業する
- 共通のスキルにこのリポジトリの事情（tsukumo・`report`・`speak`）を書き込まない

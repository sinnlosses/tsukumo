## 目的

Vitest で単体テストのファイルが並列に走るようになってから、文書しか変えていない差分でも `pnpm run check` が落ちるようになった。個別の揺れを直したうえで、`pnpm run test` を続けて回して落ちないところまで持っていく（振り返り: T-686）。

## 完了条件

- `main-history.test.ts` の「通算250件目」の it が、既定の 5000ms で時間切れにならない（背景の T-739 の行）
- `test/architecture.test.ts` の `components/ui/` の `className` の作法の検査が、既定の 5000ms で時間切れにならない（重い検査だけ `testTimeout` を個別に伸ばすか、検査を軽くする）
- 依存の T-774（`bundle.test.ts` と `cli.test.ts`）・T-775（`main-history.test.ts` の EPIPE）が済んだ状態で `pnpm run test` を10回続けて回し、1度も落ちない（回数と結果を `## 結果` に書く）
- 10回のうちに別の揺れが出たら、実物のファイルやプロセスに触るファイルを直列にする（`vitest.config.ts` の `poolOptions` など）か、揺れのタスクを別に切り出して `## 結果` に書く
- `pnpm run check` が通る

## やること

- 前提を確認した: T-774・T-775 はどちらも `status: done`。`test/architecture.test.ts` の className の検査
  （1165行目）は単独で走らせると 981ms、`test/server/achievement/adapter/main-history.test.ts` の
  「通算250件目」は単独で 1334ms だった（現在の load average は 6 前後）。どちらも既定の 5000ms
  以内だが、`pnpm run test` で全ファイルが並列に走ると負荷が上がって時間切れになりうる背景の記述どおり
- className の検査は、`files.flatMap` の中で `targets.flatMap` するたびに `ownExternalProperties(dirName)`
  と `stylesImportPath` 先の CSS を毎回読み直していた（ファイル数 × 部品数の掛け算）。
  `ownExternalProperties` は部品ごと（`files` に依らない）の結果なので、ファイルの外側で1回だけ
  計算する `Map` に置き換え、CSS の中身も相対パスをキーにしたキャッシュで使い回すよう直した
  （検査を軽くする側で対応。986ms → 86ms）
- `main-history.test.ts` の「通算250件目」は 248件＋2件のコミットで `git` を何度も起動する重い検査
  なので、件数を作り直すのではなく `it` の第三引数で `testTimeout` をこの1件だけ 20000ms に伸ばした
- `vitest.config.ts` はテスト用の一時ディレクトリと実プロセス（`git`・`vite build` 等）を触るファイル
  同士が競合する構造ではなく、`poolOptions` を触って直列化する必要は無いと判断した
- `pnpm run test` を10回続けて回す中で、上記2件とは別の揺れが1回（20回中2回）出た:
  `test/browser/components/page/character/components/character-create/hooks/use-character-create.test.tsx`
  の「必須の立ち絵を選ぶと押せるようになる」。原因は T-671 と同じ形（`FileReader` の非同期な解決を
  固定 `setTimeout(20)` で待っていたため、負荷が高いと間に合わない）で、T-671 が直した
  `character-edit.test.tsx` / `character.test.tsx` にはこの局所コピーの `pickPortrait` が
  含まれていなかった。同じ原因なので別タスクに切り出さず、ここで `waitFor`（`portrait.image.kind`
  が `"picked"` になるまでポーリング）に置き換えて直した

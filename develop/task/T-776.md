## 目的

Vitest で単体テストのファイルが並列に走るようになってから、文書しか変えていない差分でも `pnpm run check` が落ちるようになった。個別の揺れを直したうえで、`pnpm run test` を続けて回して落ちないところまで持っていく（振り返り: T-686）。

## 完了条件

- `main-history.test.ts` の「通算250件目」の it が、既定の 5000ms で時間切れにならない（背景の T-739 の行）
- `test/architecture.test.ts` の `components/ui/` の `className` の作法の検査が、既定の 5000ms で時間切れにならない（重い検査だけ `testTimeout` を個別に伸ばすか、検査を軽くする）
- 依存の T-774（`bundle.test.ts` と `cli.test.ts`）・T-775（`main-history.test.ts` の EPIPE）が済んだ状態で `pnpm run test` を10回続けて回し、1度も落ちない（回数と結果を `## 結果` に書く）
- 10回のうちに別の揺れが出たら、実物のファイルやプロセスに触るファイルを直列にする（`vitest.config.ts` の `poolOptions` など）か、揺れのタスクを別に切り出して `## 結果` に書く
- `pnpm run check` が通る

## 背景

- T-686 の受け入れと送り出しで `check` が3回落ちた: `test/architecture.test.ts` の className の検査が 5000ms で時間切れ・`test/cli.test.ts` が `dist/browser/` の対を読めない（T-774 で扱う）・`main-history.test.ts` の実行中に unhandled error（T-775 で扱う）。どれも単独では通る
- `vitest.config.ts` は `testTimeout` も `poolOptions` も指定していない（既定のまま）
- className の検査は `test/architecture.test.ts` の it「渡す className は styles["…"] の組み合わせだけで…」（1165行目。`CLASSNAME_PROP_PATTERN` で `components/ui/` の部品を動的に拾い、呼び出し側の式を調べる）
- 2026-09-27 の振り返り（T-724）: className の検査は単独でも 4.6 秒かかり、負荷 35〜68 のもとで `check` 6回のうち4回時間切れになった。ファイル×部品ごとに `ownExternalProperties` と CSS を読み直している。締め切りを延ばすだけにせず、部品の property と CSS の読み取りを1回にまとめて速くする
- 2026-09-27 の振り返り（T-751）: T-750・T-751 の委譲先もどちらも、差分と無関係にこの時間切れで1回目の検証を落とし、単体か `--no-file-parallelism` で流し直して通した
- 2026-09-27 の振り返り（T-739）: 受け入れの `pnpm run check` で `test/server/achievement/adapter/main-history.test.ts` の it「タスクの節目: 通算250件目（仮の刻み）に届いたタスクを返す」が 5000ms で時間切れになった（load average 9 前後、単独では通過）。T-775 の EPIPE とは別の揺れ。`commitManyNewFormatTasks` で248件＋2件のコミットを作っているので、時間を測って `testTimeout` を個別に伸ばすか件数の作り方を軽くする
- ほかの揺れのタスク: T-671（`character-edit.test.tsx`）・T-739（E2E）・T-738（E2E の並列化）

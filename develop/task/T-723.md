## 目的

`src/browser/` で手書きされている見出し・文字の要素を `components/ui/` の部品（`Heading` / `Text`）に置き換え、字の大きさ・色の決め方を部品の1箇所に寄せる（2026-09-27 ユーザーの指示）。

## 完了条件

- `components/ui/` の外の `.tsx` に残る `<h1>`〜`<h4>`・`<p>`・`<span>` が、部品に置き換えられないものだけになっている。残したものは種類ごとの理由（例: 行の中の一部の字だけを包む・部品が出せない要素が要る）を結果の節に書く
- 置き換えで見た目が変わっていないことを、触った画面ごとに目で確かめて結果の節に書く（`docs/architecture.md`「手で確かめること」）
- `bun run check` が通る

## 背景

- 登録時の数（`components/ui/` の外の `.tsx`）: `h1` 1・`h2` 6・`h3` 5・`h4` 1・`p` 38・`span` 140
- `components/ui/` にあるのは `button` / `dialog` / `h-stack` / `heading` / `icon` / `select` / `stack` / `text` / `v-stack`
- ボタン・選択・ダイアログは別のタスク（同じ日に登録）で扱う

## やること

前提を調べ直した結果、現在の実測は以下（登録時の数と少しずれている。以前のタスクで一部は
すでに `Text` に置き換え済み）。

- `components/ui/` の外の `.tsx`: `h1` 1・`h2` 4実（`markdown.tsx` のコメント2件は数えない）・
  `h3` 5・`h4` 1・`p` 38・`span` 133
- `h1`・`h2`・`h3` の実物は、ほぼ全部が `components/page/token-usage/` に集中（4ファイルで
  h1×1・h2×3・h3×5）。残る `h2` 1件は `components/page/conversation/.../turn-header.tsx`
- `h4` 1件は `markdown.tsx` の react-markdown 用カスタムレンダラ（動的な要素マップの1エントリ）
  で、要素を固定で差し替えられる部品では代われない

`components/page/token-usage/` の中身を見ると、見出し・字の**色**はこの画面専用の
`--usage-ink` 系トークン（`docs/screen-design.md` 13.2「この画面の中でだけ使う固定の色」）を
使っており、`Text`/`Heading` の `tone` 語彙（`ink` / `ink-quiet` / `accent` / `state-*`）には
無い。当初は「`tone="inherit"` を指定すれば色のクラスを足さないので、色だけ呼び出し側の
`className` に残せる」と考えたが、`test/architecture.test.ts`「渡す className は styles["…"]
の組み合わせだけで、その class は部品の property と重ならない」は **`tone` の値を見ず、渡した
class が `color` プロパティを持つかどうかだけで重なりを判定する**ため、`tone="inherit"` でも
`className` 側に `color` が残っていれば機械的に落ちると実測で分かった（`bun run check` で実際に
落ちて確認）。色をこの画面専用の語彙として `Heading`/`Text` に足す変種は、13.2 の「この画面の
中でだけ使う固定の色」という明示の設計判断に反するので足さない。結果、色を持つ見出し・字
（この画面の `h1`〜`h3` と大半の `span`/`p`）は**部品に置き換えられないので残す**。

量が1コミットに収まらないと分かった時点では領域を `components/page/token-usage/
presentational-token-usage.tsx` 1ファイルに絞っていたが、上の制約が分かった結果、その中で
実際に置き換えられたのは、色・大きさの指定を一切持たない生の `<span>{props.formatted}</span>`
（`BarredValue`）1件だけ。ほかの `h1`/`h2`/`h3`/`span`（`token-usage-review-badge` は
`role="status"` も追加で持つ）は全部この画面専用の色を持つため残した。

残りの3ファイル（`period-usage-card.tsx` / `context-usage-card.tsx` / `usage-review-card.tsx`）
は同じ `--usage-ink` 系の色を使う見出し・字がほとんどで、同じ理由でおそらく大半が残る側になる
見込み。`token-usage` は置換できる数が薄すぎるとメインから指摘があり、方針を直した。

**標準の `tone`/`size`（`--ink` / `--ink-quiet` / `--accent` / `--state-*` と `--font-*`
そのまま）を使っている領域を数えたところ、`domain/sidebar` は置換可7・不可9、
`features/task-board` は置換可5・不可6**（不可の理由は主に3種: (a) 直接の文字を持たない
装飾・入れ物の要素、(b) `title`/`aria-hidden`/`role` など `Text`/`Heading` が転送しない属性を
持つ、(c) `font-weight` が語彙（400/600/700）に無い値、または状態違いの入れ子セレクタ
（`.context-usage-row-warn .context-usage-row-percentage` 等）が同じ class 名に色を足していて
`test/architecture.test.ts` の重なり検査に必ず引っかかる）。この2領域を今回の最初の領域として
実際に仕上げた（置換12件）。

`token-usage` の残り3ファイルと、`token-usage`/`domain/sidebar`/`features/task-board` 以外の
全ページ（`achievement` / `character` / `conversation`（`turn-header.tsx` の `h2` 含む）/
`domain/screen-nav`）はこのタスクでは触っていない。

## 注意

- 部品に足りない変種（大きさ・色）があるときは、部品に足すか、置き換えずに残すかを決める。足すなら `docs/screen-design.md` の書体・色の節と合わせる
- 量が1コミットに収まらないと分かったら、領域（`components/page/<ページ>` など）で分けてタスクを足し、このタスクは最初の領域で閉じてよい

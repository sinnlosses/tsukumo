## 目的

同じ種類の引っかかりが何回目かを見えるようにし、繰り返したものから仕組み（検査・スクリプト・正典）で塞ぐ（Feedback flywheel の「繰り返したものだけを昇格させる」）。いまはドラフトを1件ずつ判断していて、たとえば制約違反が何回目なのかが見えない。

## 完了条件

- 札ごとの件数（とタスクID）を過去の振り返りの記録から数えて出す口がある（`scan.py` などのスクリプトの出力。承認済みのドラフトの行頭 `- 札: <色> <札>` と見出しの `（振り返り: T-XXX）` から読む）
- `retrospect` の手順（1件ごと・まとめての両方）が、積む前にその札の件数を見て、2回目以上なら出し先を「仕組みで塞ぐ」（検査・スクリプト・正典の条）にすると書いてある
- ドラフトの1件に「札の何回目か」が載る
- claude-skills 側の検査（`./check.sh`）が通り、claude-skills の `main` に入っている
- このリポジトリの `pnpm run check` が通る

## 背景

- 承認済みのドラフトは `docs/history/direction.md` に日付見出しで移る（当時の記述のまま）。札が付くのは T-779 以降で、それより前の分は数えない（遡って札を付けない）
- T-779 で、振り返りのドラフト（`develop/draft/` の1件1ファイル）は見出しの下に `- 札: <色> <札>` を1行だけ持つ形になった（`retrospect` の SKILL.md 手順4と節「札と1行の書式」）。承認されると中身ごと `docs/history/direction.md` に移るので、行頭の `- 札:` を数えれば承認済みの分だけが数えられる。Beads 方式でもドラフトと `docs/history/direction.md` はファイルのまま
- 「ドラフトの1件に何回目かが載る」は `- 札:` の行の後ろに足す形が素直（行頭は変えない）
- 2026-09-27 の `/plan-tasks` では、ドラフト9件のうち6件が処理済みの項目の復活（マージで戻った）だった。数える元がドラフトの節だと二重に数えるので、承認・処理の済んだ記録から数える

## やること

前提を実物で確かめた: `docs/history/direction.md` には現行の2トークン書式（`- 札: <色> <札>`）の行がまだ無く、
既存の2件（T-725・T-738 由来）は色を伴わない1トークンの `- 札: 揺れ` / `- 札: 正典の不備` で、
背景が言う「T-779 より前で数えない」対象と一致する。`retrospect` の同梱スクリプト（`scan.py`・
`material.py`・`transcript.py`）には `check.sh` から呼ばれる自己テストがまだ無いので、
`task-workflow/scripts/selftest.py` と同じ形（`check()` ヘルパー・`tempfile` で使い捨てのファイルを
作る）で `retrospect/scripts/selftest.py` を新設し、`check.sh` に呼び出しを足す。

1. claude-skills 側を別の作業ツリー（`/tmp/t782-worktree`、枝 `t782-tally`）で編集する
   - `skills/retrospect/scripts/tally.py` を新設: `docs/history/direction.md` を読み、
     見出し `### ...（振り返り: T-xxx, T-yyy）` に続く `- 札: (赤|黄) <札>` の行を集め、
     札ごとの件数（そのタスクIDの見出しが何回出たか）とタスクIDを出す。引数に札を1つ渡すと
     その札だけの件数とタスクIDを返す（次のドラフトで「何回目か」＝件数+1 を決めるのに使う）。
     ファイルが無ければ `MISSING`、該当が無ければ `EMPTY` を返し、traceback を出さない
   - `skills/retrospect/scripts/selftest.py` を新設し、`tally.py` の主要な分岐（2トークン書式だけ
     数える・1トークンの旧書式は数えない・見出し無しの扱い・`MISSING`・`EMPTY`・単一札の問い合わせ）
     を検査する
   - `check.sh` に `retrospect: tally.py の自己テスト` の呼び出しを足す
   - `skills/retrospect/SKILL.md` を直す:
     - 「札と1行の書式」節の直後か手順3・手順4に、ドラフトを積む前に `tally.py` でその札の件数を
       見て、2回目以上なら出し先を「仕組みで塞ぐ」（検査・スクリプト・正典への追記）にする、という
       条を足す（1件ごとの振り返り「1件だけ振り返る」の手順4でも同様に触れる）
     - 手順4のドラフトの雛形の `- 札:` 行に「（N回目）」を足す形を示す
   - `./check.sh` を通す
   - 個別ファイルを `git add` してコミット（Claude の署名行は入れない）。本体（claude-skills の
     作業ツリー）が `main` を指し clean なら `git merge --ff-only t782-tally` で入れ、
     一時の作業ツリーと枝を片付ける。本体が `main` 以外・汚れていたら入れずに報告する
2. tsukumo 側はこのタスクファイル以外の `develop/` を触らない。`docs/` 側に retrospect の
   札の語彙を写した記述は無い（`grep -rl 札 docs/` はドラフト由来の `docs/history/direction.md` の
   みで確認済み）ので、コード・ドキュメントの追随は不要。`pnpm run check` を通すだけでよい

## 目的

手書きの `reduce` での合計・グループ分け・比較関数などを、remeda に同じ関数があれば使う方針を規約にする。あわせて「寄せないもの」の線引きを書き、置き換えのための置き換えを防ぐ。

## 完了条件

- `docs/coding-standards.md` に、可読性が良くなる場合は remeda を優先する規則と、寄せないものの線引きが書かれている（節を足すなら冒頭の「節の索引」の表にも行を足す）
- 線引きには少なくとも次の2つが入っている: 標準の慣用句で差が無いもの（`[...new Set(xs)]`・`Array.from({ length })`・名前付きの関数に包んだ clamp）は寄せない / 戻り値の型が変わって呼び出し側まで直すことになるもの（`Map` を返す集計を `Record` を返す `groupBy`・`countBy` にする、など）は寄せない
- `CLAUDE.md`「コーディング規約・レビュー方針」のルール一覧に要約の1行を足すかどうかを判断し、足したなら理由の正典は `docs/coding-standards.md` 側に置く
- `bun run check` が通る

## 背景

- remeda は依存にある（`package.json`。`docs/design.md` 11章の表で「型ガードなど一般的な小物（`isPlainObject` / `isObjectType`）」として 2026-09-22 に承認）。いま `src/` で使っているのは `isPlainObject`・`isObjectType`・`fromKeys` だけ
- `docs/coding-standards.md`「型を迂回するキャストを使わない」（82行〜）に `isPlainObject` を使う規則がある。`docs/design.md` 2章（764行付近）に「ライブラリに依存しない小物は、`utils/` を作る前に remeda にあるかを見る」がある
- 2026-09-25 の調査で、`token-usage.ts` の名前ごとの集計（`new Set` → `filter` → `reduce` → 手書きの比較関数）、合計の `reduce` 約10箇所、`a < b ? -1 : a > b ? 1 : 0` の比較関数5箇所が見つかった。実際の書き直しは別のタスク

## 決まっていること（蒸し返さない）

- 基準は「可読性が良くなる場合」。行数の削減は理由にしない（`docs/coding-standards.md`「案を選ぶときの指標」）

## やること

- 前提の調べ直し: `docs/coding-standards.md`「型を迂回するキャストを使わない」節（83行〜）に
  remeda の `isPlainObject` を使う規則があるが、「可読性が良くなる場合に remeda を優先する」
  という一般則そのものは無い。`docs/design.md` 2章「`lib/` と `utils/` に置く基準」（669行〜、
  remeda の言及は764行付近）は「`utils/` を作る前に remeda にあるかを見る」という**置き場所**
  の判断であって、`reduce`・比較関数のような**インラインの書き方**の判断ではない。両者は
  重なる部分（「remeda を先に見る」）はあるが対象が違うので、範囲の狭い置き場所の判断は
  `docs/design.md` を正典のまま残し、コーディングスタイルとしての一般則を
  `docs/coding-standards.md` に新規で書く。`src/` を `grep` した結果、いま使っているのは
  `isPlainObject`・`isObjectType`・`fromKeys` の3つだけで、集計・比較関数への適用はまだ無い
- 置き場: `docs/coding-standards.md`「型を迂回するキャストを使わない」節の直後、
  「型注釈より `satisfies`」節の前に新しい節「## 可読性が良くなる場合は remeda を優先する」を
  足す。**理由**: 直前の節で remeda の `isPlainObject` を使う規則を既に書いており、remeda に
  関する規約を近くにまとめたほうが読む人が見つけやすい
- 索引表に行を1つ足し、末尾に新しい `##` 節を追加（優先する基準・寄せないものの線引き2点・
  `docs/design.md` への参照の4点を記述）
- `docs/design.md` 側は書き換えない（置き場所の判断として独立に成立しており、内容を書き換える
  完了条件は無い）。`docs/coding-standards.md` 側の新節から一方向に参照することで二重化を解く
- `CLAUDE.md`「コーディング規約・レビュー方針」のルール一覧は、同じ「ライブラリを優先する」
  種類の規約（`Bun.*` の固有APIに寄せない・`Date` を使わない）が既に1行ずつ要約されている
  先例があるので、同じ形式で1行足す（置き場所は「`Bun.*` の固有APIに寄せない」の直後）

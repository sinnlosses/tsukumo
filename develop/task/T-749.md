## 目的

`report` の結果に `_meta["claude/endTurn"]` を付けて、審査を通った `report` でターンを閉じる。`report` のあとに本文を書き足して Stop hook に差し戻される問題を仕組みで無くし、締めのセリフは `report` の引数で受け取る（`docs/research/report-block.md` 13章）。

## 完了条件

- 審査（`ReportReview`）を通った `report` の結果にだけ `_meta: { "claude/endTurn": true }` を付ける。差し戻し（`isError`）には付けない
- `report` に締めのセリフの引数 `closing`（`speak` と同じ `text` と `expression`）を足し、レポートを描いたあとに吹き出しへ回す。`REPORT_TOOL_DESCRIPTION`・`SPEAK_TOOL_DESCRIPTION`・`REPORT_NOTATION_PROMPT`・`SPEECH_CADENCE_PROMPT` の締めの条と、`docs/display.md`「出力の分離（セリフと詳細）」を合わせる
- 中間レポートの扱いを決めて実装する（下の論点）
- `Stop` の関所（`createReportGate` と `stopHooks`）を、閉じるツールの上で要る分だけに縮めるか外す。`stopHooks` の effort の読み取りは残す
- 疑似セッションか E2E で、`report` のあとにターンが閉じ、`closing` のセリフが吹き出しに出ることを守る
- 実物のセッションで1ターン試し、`report` のあとに assistant の発言が来ないことと吹き出しの出方を目視で確かめて結果に書く
- `bun run check` が通る

## 背景

- 実物（SDK 0.3.280・CLI 2.1.280）で確かめた: `_meta["claude/endTurn"]: true` を返すと assistant を挟まず `result(success)` でターンが閉じる。`isError` では閉じずに打ち直せる。閉じたターンの transcript は `toSessionEvents` / `toRestoredEvents` が読め、`resume` でも続きを話せる（`docs/research/report-block.md` 13章）
- `_meta` は生のストリームの `tool_use_result._meta` にだけ乗り、`getSessionMessages` の transcript には残らない。閉じたかどうかは流れているイベントから判定する
- `report` の handler は `src/server/session-driver/adapter/sdk-tool.ts`、審査は `src/server/report/core/report-tool.ts` の `ReportReview`（T-721 で「新しい事実の無い `report`」の差し戻しが入った）、関所は `sdk-driver.ts` の `stopHooks`

## 解くべき論点

- 中間レポート: `report` に `final` の欄を足して最終のときだけ閉じるか、`report` は常に閉じて途中経過は `speak` だけにするか。委譲中の待ちのターン（サブエージェントの合図で始まるターン）で、何も渡さずに終える形とどう噛み合うか
- `closing` を必須にするか。締めのセリフを言わないターン（新しい事実の無いターン）との関係
- 雑談モード（`docs/chat-mode.md`）の終え方にも同じ仕組みを使うか

## 決まっていること（蒸し返さない）

2026-09-27 エージェント決定（論点の答え）:

- **中間レポート: `report` は常にターンを閉じる。`final` の欄は置かない。** ターンの途中の経過は `speak` で言う。理由: 「`report` を呼んだらターンが終わる」の1本の規則だけで読め、`final` の付け間違いで関所（ヒューリスティック）に戻る経路が残らない。委譲中の待ちのターンは今までどおり何も呼ばずに終え、合図で始まったターンで `report` を呼べばそこで閉じる。1つのやり取りの中の中間レポートは、SDK のターンをまたいで（背景のタスク・委譲の完了で始まるターン）今までどおり生まれるので、メインビューの中間／最終の描き分けはそのまま使う
- **`closing` は必須。** `report` を呼ぶターンには必ず締めのセリフが付くことを型（zod）で保証する。締めのセリフを言わないターン（新しい事実の無いターン）は `report` そのものを呼ばないので、ぶつからない
- **雑談モードには使わない。** 雑談には `report` も `Stop` の関所も無く、1ターンに `speak`・`remember`・`recall` を何度か呼ぶのが普通の形で、閉じるツールを置くと切れてしまう。本体の催促は環境変数で塞いであり、このタスクが解く問題（`report` のあとの書き足し）は雑談では起きない

## やること

前提（2026-09-27 に調べ直した）: `report` の handler（`src/server/session-driver/adapter/sdk-tool.ts`）は通したとき `"ok"` だけを返し `_meta` を付けていない。締めは `REPORT_NOTATION_PROMPT`・`SPEECH_CADENCE_PROMPT` が「`report` → 締めの `speak`」と言い、関所（`createReportGate`）は `report` のあとの本文も `REPORT_GATE_AFTER_REPORT_REASON` で差し戻している。前提は崩れていない。

1. `report` の handler: 審査を通したときだけ `_meta: { "claude/endTurn": true }` を付ける。引数に必須の `closing: { text, expression }` を足す
2. `report` イベント（`src/shared/session-event.ts`）に `closing`（締めのセリフ。`closing` の無かったころの transcript は `none`）を持たせ、変換（`toSessionEvents`）で取り出す。`ReportReview.pass` が描いた `report` の後ろに `speech` として出す（差し戻した `report` の `closing` は出さない。復元も同じ経路を通る）
3. 関所を縮める: `report` のあとの本文は起きないので `REPORT_GATE_AFTER_REPORT_REASON` と「済んだか」の区別を外し、`report` の無いターンの本文だけを差し戻す。`stopHooks` の effort の読み取りは残す
4. 文面を合わせる: `REPORT_TOOL_DESCRIPTION`・`SPEAK_TOOL_DESCRIPTION`・`REPORT_NOTATION_PROMPT`・`SPEECH_CADENCE_PROMPT`・`REPORT_GATE_REASON`、`docs/display.md`「出力の分離（セリフと詳細）」、用語集の `report` ツール・中間レポート
5. 疑似セッションの `report` に `closing` を足し、`report-rejected` / `report-tidied` の締めを `closing` へ移す（E2E で、ターンが閉じて締めのセリフが吹き出しに出ることを守る）

## 注意

- 閉じたあとに届く `speak` は無くなるので、締めのセリフの間合い（`src/server/core/speech-cadence.ts`）の文面も食い違わないか見る
- 調べて成り立たないと分かったら、理由を書いて `dropped` で閉じてよい

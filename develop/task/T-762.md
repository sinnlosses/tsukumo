## 目的

`task` を Beads（`bd`）とトラッカーと git をつなぐ薄い包みにし、今の排他制御と情報を落とさずに Beads の上へ移す（`docs/research/github-projects.md` の「移行の段取り」2）。

## 完了条件

- 研究文書の「今あるものの行き先」の表の行がすべて、`task-workflow`（`WORKFLOW.md`・`scripts/`・`selftest_task.py`）で実現されている（着手・採番・`NOT_OWNER`・取り残しの4区分・状態・見送り・`difficulty`・`loopable`・依存・本文の各節・結果・送り出し）
- トラッカーの方式（`github`・`jira`・なし）を設定で選べる。`github` は `bd github sync --push-only` と Project の Status 欄の橋渡しを行い、`jira` は `bd jira sync --pull` だけを打って「Jira で閉じてほしいもの」を `status` に出す
- `.beads` の `bd backup`（または `bd export`）を git の外の決まった場所へ取る手段がある
- `next-task`・`plan-tasks`・`list-tasks`・`retrospect`（`scan.py`・`material.py` の材料を `bd history`・notes・comments へ）・`setup-tasks`（`bd init --stealth`）が新しい形に合っている
- claude-skills の検査（`./check.sh`）が通る

## 背景

- `~/.claude/skills` は claude-skills の本体の作業ツリーへの symlink。本体で枝を切ると動いている全セッションのスキルが入れ替わるので、別の作業ツリーで編集してから `main` に入れる
- 切り替え（`develop/task/` から移す）は T-764 が行う。それまで今の `task` が動き続ける必要がある
- 確かめた Beads の挙動は研究文書の「Beads で確かめたこと」。独自の状態 `cancelled:done` は依存を解決しないので、見送りは `bd close` と label で表す

- 2026-09-27 ユーザー決定: 今のファイル方式（`develop/task/` と git の外の台帳）と Beads 方式を併存させ、プロジェクトの設定（または `.beads` の有無）で `task` が方式を切り替える。この形で claude-skills の `main` へ入れてよい（入れても `develop/task/` の運用はそのまま動く）。切り替えは T-764 で設定を変えて行う。ファイル方式を消すのは T-764 のあとの別タスク

## やること

調べ直し（2026-09-27、claude-skills main 1a387fa・`bd` 1.3.0）: 前提は崩れていない。`task.py` は
`develop/task/` と台帳だけを読み、Beads の分岐は無い。`bd` で新たに分かったこと: `bd update --claim` は
依存を見ない（`task` 側で確かめる）、claim に5分の lease が付くが期限後も他の actor は取れない
（外すのは `bd reclaim` だけ）、依存の開いた課題は `bd close` が拒む、`bd history --json` は版の配列、
`bd kv` で値を持てる、`bd rename` で番号を振り直せる。

1. claude-skills を別の作業ツリー（枝 `beads-backend`）で直す。方式は「## タスク運用」の任意行
   `- タスクの置き場: beads` で切り替え、行が無ければファイル方式のまま（出力・終了コードを変えない。
   既存の `selftest_task.py` を通したまま）
2. `scripts/beads.py`（`bd` の包みと、課題 ↔ `Task`・本文 ↔ description/acceptance/notes の写し）、
   `scripts/tracker.py`（`github`: `bd github sync --push-only` と Status 欄の橋渡し、`jira`: `--pull` だけ）
   を足し、`task.py` の各サブコマンドに Beads 方式の道を足す。`claim`・`ship` の git の手順は両方式で共有する
3. Beads 方式だけのサブコマンド: `show`（両方式）・`edit`・`adopt`（振り分け前の課題に番号を振る）・
   `sync`・`backup`・`jira-closed`。`done` は comment と label `ship:*`、`ship` が送ったあとに `bd close`
4. `init.py` が Beads 方式なら本体で `bd init --stealth -p t` と独自の状態 `pending:frozen` を用意する
5. `retrospect` の `scan.py`・`material.py` を Beads の comment・`bd history` から読めるようにする
6. `WORKFLOW.md` に「Beads 方式」の節、`next-task`・`plan-tasks`・`list-tasks`・`retrospect`・`setup-tasks`・
   README に読み替えの注記を足す
7. `selftest_beads.py`（本物の `bd`、偽の `gh` と sync）を足して `./check.sh` に入れる

## 注意

- `bd init` を `--stealth` なしで打つと `AGENTS.md`・`CLAUDE.md` に書き足して自動でコミットする
- `bd export` の JSONL には作成者のメールアドレスが入る。公開リポジトリにコミットしない
- `bd jira sync` の実際の挙動は試していない（Jira のサイトとトークンが要る）。試すならユーザーに用意を頼む

## 目的

T-761 で決めた GitHub Projects の運用を、タスクを扱うスキル群が行えるようにする（`docs/research/github-projects.md` の「移行の段取り」3）。

## 完了条件

- `task-workflow`（`WORKFLOW.md`・`scripts/`・`selftest_task.py`）が、一覧・登録・着手（紐づく枝）・完了（結果のコメントと Status）・取り残しの判定を GitHub で行う
- `next-task`・`plan-tasks`・`list-tasks`・`retrospect`（`scan.py`・`material.py` の材料を Issue のコメントと `userContentEdits` へ）・`setup-tasks` が新しい運用に合っている
- 認証の失敗・二次制限を終了コードで区別し、`/loop` が止まる理由を先頭語で出す
- claude-skills の検査（`./check.sh`）が通る

## 背景

- `~/.claude/skills` は claude-skills の本体の作業ツリーへの symlink。本体で枝を切ると動いている全セッションのスキルが入れ替わるので、別の作業ツリーで編集してから `main` に入れる
- 移行（`develop/task/` の未完了を Issue へ移す）は後段のタスクが行う。切り替えるまで今の `task` が動き続ける必要がある

## 注意

- `develop/task/` を使っているのは登録時このリポジトリだけ。旧形式と今の形式の読み取りをどこまで残すかは、`retrospect` が過去の範囲を読むことを見て決める

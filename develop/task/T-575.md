## 目的

訪問が仕事の邪魔になるときや、うまく動かないときに、コードを戻さずに利用者が画面から止められるようにする。

## 背景

- 設定の歯車は `src/browser/features/screen-nav/components/screen-nav-settings.tsx`（ロジックは `hooks/use-settings.ts`）。いまの群は「画面の色」「新しいセッションの既定」「書き上げる演出の速さ」の3つ（`docs/screen-design.md` 13.6・13.9「設定の歯車」）
- 訪問の契機の判断は T-571 で `src/server/core/` の純関数に置く

## 決まっていること（蒸し返さない）

- オフなら契機の判断が「来ない」を返す（訪問中にオフにしたらその場で帰る）
- 値の覚え方は、いまの設定の群と同じ置き方に合わせる
- **あとで元に戻せる形で入れる**（2026-09-25 ユーザー決定: 「上手くいかず元に戻すかもしれないから revert 可能なようにすることが条件」）
  - このタスクの変更は1コミットにまとめ、訪問と関係の無い変更（ついでの整理・名前の変更・整形だけの差分）を混ぜない。`git revert` 1回でこのタスクの分だけ戻せるようにする
  - 訪問のコードは訪問専用の新しいファイルに置き、既存のファイルへの差し込みは呼び出し・分岐・型の足し込みなど最小にとどめる
  - 完了時の結果の節に「差し込んだ既存のファイル」を列挙する（戻すときに見る場所）
  - 訪問のタスクは後ろから順に revert すれば戻る並びにする（前のタスクが後のタスクの部品に依存しない）

## やること

**前提を調べ直した結果**（着手前に読み直す。2026-09-25 に一度「ディスクに覚えない」で実装したが、
受け入れの指摘で「値の覚え方は、いまの設定の群と同じ置き方に合わせる」（決まっていること）を
汲み取れていないと判明し、下記のとおり覚え方を直した）:

- 歯車の3群の値の覚え方は3通りに分かれている。①画面の色・書き上げる演出の速さ:
  ブラウザの `localStorage`（`src/browser/domain/appearance-color.ts` /
  `reveal-speed.ts`。サーバは知らない）。②新しいセッションの既定（モデル・許可モード）:
  `~/.tsukumo/state.json`（`src/server/adapter/remembered-default.ts`）に**起こすたびに1回だけ**
  読み直す値で、`set-session-default` で書き換えても**いま動いているセッションには効かない**
  （次に起こすときから）
- 訪問の契機の判断（`visitArrival` / `visitDeparture`）は `src/server/core/` の純関数で、
  `session-manager.ts` が駆動1代ぶんの `visit-watch.ts` を通して毎イベント呼ぶ。**目的は
  「うまく動かないときに画面から止められる」ことなので、止めたつもりが起こし直すたびに戻るのは
  目的に合わない**——だから②と同じ `~/.tsukumo/state.json` に覚える。一方で「訪問中にオフに
  したらその場で帰る」は**いま動いているセッションにも即座に効く**ことを求めるので、②の
  「次に起こすときから効く」だけでは足りない
- 結論: **「覚え方」は②（新しいセッションの既定）とまったく同じにし、「効き方」だけ足す。**
  `remembered-default.ts` に3つ目の欄として `visitEnabled` を持たせ、`readRememberedVisitEnabled` /
  `writeRememberedVisitEnabled` を②の関数と同じ形で足す。起こすときは `session-launch.ts` が
  ②と同じく1回読んで `visit-enabled-changed` を流す（`SessionState.visitEnabled` の初期値になる）。
  **書き換えたときだけ挙動が違う**——②の `rememberSessionDefault` は書いて画面へ流すだけ
  （いまのセッションには効かない）が、③の `rememberVisitEnabled` が返す `visit-enabled-changed`
  は**ほかの駆動由来のイベントと同じ `receive` の道を通る**ので、`session-manager.ts` の
  `tally.visit.observe` にも同じタイミングで届き、`visitArrival` / `departureReason` のゲートに
  即座に反映される（駆動には渡さない・セッションは起こし直さない、という「覚え方は同じ・
  効き方は違う」を1つの `SessionEvent` の配り先だけで作る）

**触るファイル**（新しいファイルは1つ。訪問専用の既存ファイル〔`visit-timing.ts` /
`visit-script.ts`〕への追加と、汎用ファイルへの型・分岐・口の足し込みだけで収まった）:

- 新規: `src/browser/features/screen-nav/domain/visit-toggle-label.ts`
  （`model-label.ts` / `permission-mode-label.ts` と同じ形の、オン/オフの表示ラベルとブール値の
  変換。歯車の中でしか読まない対応表）
- 訪問専用の既存ファイル（拡張）:
  - `src/server/core/visit-timing.ts`: `visitArrival` に `!state.visitEnabled` のゲートを足す。
    `departureReason` に `"visit-enabled-changed"` の分岐を足し、`visitEnabled: false` なら
    `"disabled"` で帰す
  - `src/server/core/visit-script.ts`: `interruptsVisitScript` に
    `"visit-enabled-changed"` の分岐を足す（`visitEnabled: false` なら常に中断——台本を
    作っている最中にオフにしたときも、来かけた客を止める）
  - `src/shared/visit.ts`: `VisitEndReason` に `"disabled"` を足し、同梱の既定
    `DEFAULT_VISIT_ENABLED`（= `true`）を足す（`INITIAL_SESSION_STATE` と
    `remembered-default.ts` の読めないときの既定が同じ1つを指すように）
- 汎用ファイル（型・分岐・口の足し込みだけ）:
  - `src/shared/session-event.ts`: `SessionEvent` に
    `{ kind: "visit-enabled-changed"; visitEnabled: boolean }` を足す
  - `src/shared/session-state.ts`: `SessionState` に `visitEnabled: boolean` を足し、
    `INITIAL_SESSION_STATE.visitEnabled = DEFAULT_VISIT_ENABLED`、`applySessionEvent` に1ケース足す
  - `src/shared/command.ts`: `set-visit-enabled`（`commandId` + `enabled: boolean`）を
    `clientCommandSchema` に足し、`DriverCommand` の除外一覧にも足す（駆動へは渡さない）
  - `src/shared/frame.ts`: `FRAME_ERROR_REASON.visitEnabledFailed` を足し、`PROTOCOL_VERSION` を
    16 → 17 へ（`SessionState` の形が変わるため）
  - `src/server/adapter/remembered-default.ts`: 3つ目の欄として `visitEnabled` を足す
    （`readRememberedVisitEnabled` / `writeRememberedVisitEnabled`。書き込みは3欄を読み直してから
    載せ替えるので、既存の2欄を消さない）
  - `src/server/core/session-launch.ts`: `SessionLaunchPorts` に `readVisitEnabled` を足し、
    `readSessionDefault` と同じ場所（起こす一続きの中）で1回読んで `visit-enabled-changed` を流す
  - `src/server/core/session-manager.ts`: `SessionManagerOptions` に `rememberVisitEnabled` を足し、
    `dispatch` の switch の `"set-visit-enabled"` がそれを呼ぶだけに直す（起こし直さない）
  - `src/session-start.ts`: `readVisitEnabled` / `rememberVisitEnabled` を
    `remembered-default.ts` の読み書きへ結ぶ配線を足す（`rememberSessionDefault` と対の関数を
    1つ追加）
  - `src/browser/features/screen-nav/hooks/use-settings.ts` /
    `components/screen-nav-settings.tsx`: 歯車に「訪問」の見出しと1行（オン/オフの `<Select>`）を
    足す（`sessionDefault` / `revealSpeed` と同じ並びの4群目）
- 触らない: `visit-watch.ts`（`observe` は既存のまま、`"visit-enabled-changed"` も他のイベントと
  同じ経路で流れて `visitArrival` / `departureReason` のゲートだけで正しく効く）

## 結果

- 検証コマンド: 2626 pass / 0 fail（+28）。疑似セッションと Playwright で、歯車に「訪問／客の出入り」が出ること（1400/400px で横スクロールなし）、オフで `visit-started` が来ないこと、訪問中にオフで `visit-ended`（disabled）が届くこと、オフが `state.json` に覚えられ上げ直しても「しない」のままであることを確かめた

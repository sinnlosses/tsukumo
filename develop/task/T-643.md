## 目的

定着で作られるエピソード索引をディスクに読み書きし、引く言葉に対して採点して候補を返す口を用意する。定着（後段）と `recall` の2段階（後段）がこの口を使う。

## 完了条件

- `docs/design.md` 7章（T-641 で書く）が定める `episode.jsonl` と `recalled.jsonl` を、追記だけで書き、読める
- 引く言葉に対して、正典の採点の要素（一致・重み・新しさ・思い出した回数）で並べた候補を、容量の表の一覧の量まで返せる。日本語の言い換えを2文字の重なりでも拾うことをテストで確かめている
- エピソードの `id` を渡すと、その範囲のアーカイブの逐語を容量の表のエピソードの量まで返せる。開いたことが `recalled.jsonl` に残る
- 最後のエピソードの終わりから、「作業記憶の窓の外にあって、まだどのエピソードにも入っていない行」を取り出せる（定着の入力になる）
- ファイルに触るのは雑談のアーカイブの adapter の1ファイルにとどまり、採点は `core/` の純粋な関数になっている
- `bun run check` が通る

## 背景

- 雑談のアーカイブは `src/server/chat/adapter/chat-archive.ts`（`~/.tsukumo/chat-archive/<パック名>/` の日付の JSONL・`kept.jsonl`・`index.jsonl` を扱う。`readRecent` と `recall`）。テストは `test/server/chat/adapter/chat-archive.test.ts`
- 口の型は `src/server/session-driver/core/session-driver.ts`（`ChatArchive`・`ChatRecall`）
- 提案の段階の形は `docs/research/chat-memory-index.md`「エピソード索引の形」「引き方」

## 注意

- 既存の `index.jsonl` と `kept.jsonl` を読む口は、それを消す後段のタスクが消す。このタスクでは残してよい
- 外部コマンドも埋め込みの API も使わない（`node:fs` と TypeScript だけ）
- テストのフィクスチャに実際の会話を使わない（`docs/coding-standards.md`「会話内容の扱い」）

## 目的

定着で作られるエピソード索引をディスクに読み書きし、引く言葉に対して採点して候補を返す口を用意する。定着（後段）と `recall` の2段階（後段）がこの口を使う。

## 完了条件

- `docs/design.md` 7章「エピソード索引はどこに置くか」が定める `episode.jsonl`（`v: 2`・`id`・`from`/`to`・`title`・`gist`・`cues`・`weight`）と `recalled.jsonl`（`v: 1`・`id`・`at`）を、追記だけで書き、読める。`id` は `to` のローカル日付＋その日の通し番号で tsukumo が振る
- 引く言葉に対して、正典の採点の式（一致・足切り・新しさ・点。同じ節の表）で並べた候補の `id`・`title`・`gist` を、`recallListBytes` まで返せる。係数は `src/shared/chat-memory-budget.ts` に足す `CHAT_RECALL_SCORE` から読む。日本語の言い換えを2文字の重なりでも拾うこと・思い出した回数で沈み方が緩むことをテストで確かめている
- エピソードの `id` を渡すと、その範囲（`from`〜`to`）のアーカイブの逐語を**古いほうから** `recallEpisodeBytes` まで返せる（返す形は `readRecent` と同じ。溢れたかどうかも分かる）。開いたことが `recalled.jsonl` に残る
- 最後のエピソードの `to` より後で、作業記憶の窓（`recentBytes`）の外にある行を、古いほうから `consolidateEveryBytes * 2` まで取り出せる（定着の入力。エピソードが無ければアーカイブの最初の行から）。溜まっている量が契機に届いているかも分かる
- ファイルに触るのは雑談のアーカイブの adapter の1ファイルにとどまり、採点は `core/` の純粋な関数になっている
- `bun run check` が通る

## 背景

- 雑談のアーカイブは `src/server/chat/adapter/chat-archive.ts`（`~/.tsukumo/chat-archive/<パック名>/` の日付の JSONL・`kept.jsonl`・`index.jsonl` を扱う。`readRecent` と `recall`）。テストは `test/server/chat/adapter/chat-archive.test.ts`
- 口の型は `src/server/session-driver/core/session-driver.ts`（`ChatArchive`・`ChatRecall`）
- 正典: `docs/design.md` 7章「エピソード索引はどこに置くか」（形・読む口・採点の式・係数の表）、`docs/chat-mode.md` 4.9「古い雑談は索引を引いて思い出す」

## やること

前提を洗い直した（2026-09-26）。`src/shared/chat-memory-budget.ts` は T-642 で `CHAT_MEMORY_BUDGET`
まで先に入っており、`CHAT_RECALL_SCORE` はまだ無かった（このタスクで足す）。`ChatArchive` /
`ChatRecall` の型（`src/server/session-driver/core/session-driver.ts`）にはまだ
`unconsolidated` / `appendEpisodes` / `recallList` / `recallEpisode` が無い。前提は崩れていない
（作業は要る）。

- `src/shared/chat-memory-budget.ts` に `ChatRecallScore` 型と `CHAT_RECALL_SCORE` を足す
  （値は `docs/design.md` 7章の表のまま）
- `src/server/session-driver/core/session-driver.ts` の `ChatArchive` に4つの口を足す
  （既存の `append` / `keep` / `finishTurn` / `readRecent` / `writeIndex` / `recall` は触らない。
  `docs/coding-standards.md`「「無いかもしれない」値」に沿って判別可能な合併型で結果を返す）:
  - `unconsolidated(packName, { recentBytes, maxBytes })` → 未定着の行（`at`・`speaker`・`text`）と
    返した文面のバイト数の合計（契機に届いたかは呼び出し側が比べる）
  - `appendEpisodes(packName, episodes)` → `id` を振って `episode.jsonl` に追記
  - `recallList(packName, keyword, limitBytes, now: Temporal.Instant)` → 採点した候補
    （`id`・`title`・`gist`）| 当たらない
  - `recallEpisode(packName, id, limitBytes)` → その範囲の逐語（古いほうから、形は
    `ChatArchiveRecentEntry` と同じ）と溢れたかどうか | 無い（開いたら `recalled.jsonl` に追記）
- 採点は新しいファイル `src/server/chat/core/chat-episode-score.ts` に純関数として書く
  （一致・足切り・新しさ・点の式は `docs/design.md` 7章の表のとおり。日本語の2文字重なり・
  1文字語の特例・同点は新しい順のタイブレークを含む）
- `src/server/chat/adapter/chat-archive.ts` に4つの実装を足す（ファイルに触るのはここだけを保つ。
  `episode.jsonl` は `v:2`、`recalled.jsonl` は `v:1`。読めない行は1行ずつ落とし例外は投げない）
- `docs/design.md` 2章の `chat/` の行とディレクトリの図に `chat-episode-score.ts` を足す
- テストは `test/server/chat/core/chat-episode-score.test.ts`（採点の純関数）と
  `test/server/chat/adapter/chat-archive.test.ts`（4つの口の読み書き）に足す。完了条件が挙げる
  「日本語の言い換えを2文字の重なりでも拾う」「思い出した回数で沈み方が緩む」を確かめる
- `recall` の1ターンの回数制限・`ChatRecall` 型への配線・ツール自体・`index.jsonl` /
  `kept.jsonl` を消すことは後段のタスクの範囲なので、このタスクではやらない

## 注意

- 既存の `index.jsonl` と `kept.jsonl` を読む口は、それを消す後段のタスクが消す。このタスクでは残してよい
- 外部コマンドも埋め込みの API も使わない（`node:fs` と TypeScript だけ）
- 1ターンに引ける回数・開ける件数を数えるのはツールを足す後段のタスク。このタスクは読む口と採点まで
- 新しい core のファイルを足したら `docs/design.md` 2章の `chat/` の行とディレクトリの図を直す
- テストのフィクスチャに実際の会話を使わない（`docs/coding-standards.md`「会話内容の扱い」）

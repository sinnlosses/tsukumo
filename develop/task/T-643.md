## 目的

定着で作られるエピソード索引をディスクに読み書きし、引く言葉に対して採点して候補を返す口を用意する。定着（後段）と `recall` の2段階（後段）がこの口を使う。

## 完了条件

- `docs/design.md` 7章「エピソード索引はどこに置くか」が定める `episode.jsonl`（`v: 2`・`id`・`from`/`to`・`title`・`gist`・`cues`・`weight`）と `recalled.jsonl`（`v: 1`・`id`・`at`）を、追記だけで書き、読める。`id` は `to` のローカル日付＋その日の通し番号で tsukumo が振る
- 引く言葉に対して、正典の採点の式（一致・足切り・新しさ・点。同じ節の表）で並べた候補の `id`・`title`・`gist` を、`recallListBytes` まで返せる。係数は `src/shared/chat-memory-budget.ts` に足す `CHAT_RECALL_SCORE` から読む。日本語の言い換えを2文字の重なりでも拾うこと・思い出した回数で沈み方が緩むことをテストで確かめている
- エピソードの `id` を渡すと、その範囲（`from`〜`to`）のアーカイブの逐語を**古いほうから** `recallEpisodeBytes` まで返せる（返す形は `readRecent` と同じ。溢れたかどうかも分かる）。開いたことが `recalled.jsonl` に残る
- 最後のエピソードの `to` より後で、作業記憶の窓（`recentBytes`）の外にある行を、古いほうから `consolidateEveryBytes * 2` まで取り出せる（定着の入力。エピソードが無ければアーカイブの最初の行から）。溜まっている量が契機に届いているかも分かる
- ファイルに触るのは雑談のアーカイブの adapter の1ファイルにとどまり、採点は `core/` の純粋な関数になっている
- `bun run check` が通る

## 背景

- 雑談のアーカイブは `src/server/chat/adapter/chat-archive.ts`（`~/.tsukumo/chat-archive/<パック名>/` の日付の JSONL・`kept.jsonl`・`index.jsonl` を扱う。`readRecent` と `recall`）。テストは `test/server/chat/adapter/chat-archive.test.ts`
- 口の型は `src/server/session-driver/core/session-driver.ts`（`ChatArchive`・`ChatRecall`）
- 正典: `docs/design.md` 7章「エピソード索引はどこに置くか」（形・読む口・採点の式・係数の表）、`docs/chat-mode.md` 4.9「古い雑談は索引を引いて思い出す」

## 注意

- 既存の `index.jsonl` と `kept.jsonl` を読む口は、それを消す後段のタスクが消す。このタスクでは残してよい
- 外部コマンドも埋め込みの API も使わない（`node:fs` と TypeScript だけ）
- 1ターンに引ける回数・開ける件数を数えるのはツールを足す後段のタスク。このタスクは読む口と採点まで
- 新しい core のファイルを足したら `docs/design.md` 2章の `chat/` の行とディレクトリの図を直す
- テストのフィクスチャに実際の会話を使わない（`docs/coding-standards.md`「会話内容の扱い」）

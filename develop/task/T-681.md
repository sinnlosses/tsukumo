## 目的

`T-680` で決めた形（`create()` で書き、`Context` の `Provider` は作らない。セレクタは
`useStore((state) => state.field)`、その場で配列・オブジェクトを作るセレクタだけ `useShallow`
で包む。テストへの差し込みは `Provider` ではなく `getState()` / `setState()` を直接呼ぶ——
`docs/coding-standards.md`「React」節「zustand の store」）に合わせて、残りの自作 store をすべて
zustand にする。

## 完了条件

- `src/browser/` に `useSyncExternalStore` で自作した store が残っていない（`location-hash.ts` のように
  React の外のもの（`location.hash`）を購読するだけのものは、zustand にしないほうが読みやすければ
  残してよい。残したものと理由を結果の節に書く）
- store を配るだけの Context の Provider が消えている
- `docs/architecture.md` の状態管理の記述と `docs/design.md` 6.2 が zustand の形になっている
- `bun run check` が通り、会話の画面・キャラクター画面・成果の画面を開いて描き直しが止まらない
  （CPU が張り付かない）ことを目で見て確かめている

## 背景

- 対象は `src/browser/stores/` の `session.tsx`（335行）・`question-answer.tsx`（274行）・
  `location-hash.ts`（178行）・`screen.tsx`（110行）・`turn-selection.tsx`（83行）・
  `main-view-turn.ts`（61行）（`question-scroll.ts` は `T-680` で zustand に置き換え済み）、
  `src/browser/domain/reveal/brush-tip.ts`、
  `src/browser/components/page/achievement/hooks/use-diary-book-open-request.ts`
- `session.tsx` の `createSessionStore` は oRPC のクライアント（`dispatch`）と接続（`attachSocket`）を
  抱え、届いたフレームを畳む `receive` がトランジションに載っている。部品のテストは
  `SessionStoreContext` で姿を差し込んでいる

## 解くべき論点

- `session.tsx` の接続とトランジションの扱いを zustand の store のどこに置くか（`dispatch` や
  `receive` のような React に属さない口も store の外に出さず、`create()` が返す同じ store に
  持たせられるかを見る）

## 目的

`T-680` で決めた形（`create()` で書き、`Context` の `Provider` は作らない。セレクタは
`useStore((state) => state.field)`、その場で配列・オブジェクトを作るセレクタだけ `useShallow`
で包む。テストへの差し込みは `Provider` ではなく `getState()` / `setState()` を直接呼ぶ——
`docs/coding-standards.md`「React」節「zustand の store」）に合わせて、残りの自作 store をすべて
zustand にする。

## 完了条件

- `src/browser/` に `useSyncExternalStore` で自作した store が残っていない（`location-hash.ts` のように
  React の外のもの（`location.hash`）を購読するだけのものは、zustand にしないほうが読みやすければ
  残してよい。残したものと理由を結果の節に書く）
- store を配るだけの Context の Provider が消えている
- `docs/architecture.md` の状態管理の記述と `docs/design.md` 6.2 が zustand の形になっている
- `bun run check` が通り、会話の画面・キャラクター画面・成果の画面を開いて描き直しが止まらない
  （CPU が張り付かない）ことを目で見て確かめている

## 背景

- 対象は `src/browser/stores/` の `session.tsx`（335行）・`question-answer.tsx`（274行）・

## 解くべき論点

- `session.tsx` の接続とトランジションの扱いを zustand の store のどこに置くか（`dispatch` や
  `receive` のような React に属さない口も store の外に出さず、`create()` が返す同じ store に
  持たせられるかを見る）

## やること

前提の調べ直し（2026-09-27）: 対象はすべて残っている。`useSyncExternalStore` の自作は
`session.tsx`・`location-hash.ts`・`brush-tip.ts`・`use-diary-book-open-request.ts` の4つ、
store を配る Context は `SessionStoreContext`・`TurnSelectionContext`・`QuestionAnswerProvider` の
3つ。`screen.tsx` と `main-view-turn.ts` は自前の購読を持たず、`location-hash.ts` と
`session.tsx` を読むだけ（呼び先の口を合わせるだけで済む）。`T-669` はまだで、
`test/browser/stores/` の単体テストは残っている。テストは `bun:test` のまま。

論点への答え:

- `session` は `create()` の1つの store に、姿（`state`・`connection`・`protocol`）と、
  React に属さない口（`dispatch`・`receive`・`setConnection`・`attachSocket`）を同じく持たせる。
  繋いでいる接続は `create()` に渡す関数の閉包に置き（姿ではないので購読させない）、
  `dispatch` は store を作るときに1回だけ作る（参照が変わらない）。`receive` のトランジションは
  今と同じく `receive` の中で `startTransition(() => set(...))` にする（zustand の `useStore` も
  `useSyncExternalStore` なので、効き方は今と変わらない）
- 接続を張る `useEffect`（外部システムの購読）は、store の横の hook `useSessionConnection()` にして
  `<Root>` で1回呼ぶ。`<SessionProvider>` が持っていたパックの見た目（`accent`・背景・日記の書体を
  `documentElement` へ差す）は `components/app/` の hook にして同じく `<Root>` で呼ぶ。
  `<SessionProvider>` は無くなる

置き換え:

1. `brush-tip.ts`・`use-diary-book-open-request.ts`: モジュールの `let` と `listeners` を `create()`
   の store にする。外から呼ぶ口（`publishBrushTip` など）の名前は変えない
2. `session.tsx` → `session.ts`: `useSession`（`create()`）。部品の `useSessionSelector(sel)` は
   `useSession(sel)`、`useSessionDispatch()` は `useSession((session) => session.dispatch)` にする。
   テストは Provider で包まず、`test/browser/session-store.ts` が `getInitialState()` で戻してから
   `hello` を入れる
3. `turn-selection.tsx` → `turn-selection.ts`: 持つ状態は無い（hash と姿からの導出）ので store を
   作らず、`useTurnSelection()` が `useSession` と `useHashRoute` から直接導く。`selectTurn` は
   `getState()` で今回を読むモジュールの関数にする。テストは hash と姿で差し込む
4. `question-answer.tsx` → `question-answer.ts`: 組み立て中の答えを `create()` の store に置き、
   どの答え待ち（`PendingAsk.id`）に対する下書きかも一緒に持つ。id が違えば空として読むので、
   描画中に捨て直す処理は無くなる
5. 残す: `location-hash.ts` の `useHashRoute`（正典が React の外の `location.hash` で、zustand に
   写すとモジュールの読み込み時に `hashchange` を張る二重の持ち方になる）。`screen.tsx` はそれを
   読むだけなので触らない
6. docs: `docs/design.md` 2章の `stores/` の段落と 6.2、`docs/architecture.md` の各ファイルの責務、
   `docs/coding-standards.md`「zustand の store」の `useSessionSelector` への言及、
   `docs/screen-design.md` の `<SessionProvider>` への言及を追随させる

## やること

調べ直した前提（`test/browser/components/domain/sidebar/` は9ファイル・46宣言。T-658・T-659 の
サイドバー4行の E2E は `current-work`・`background-task`（開始後・再開後の2件）・`turn-history`・
`task-list`、雑談2行の E2E は `chat-compact-boundary`・`chat-restored-history`。前提は崩れていない）:

- E2E の DOM 成果物（`test/e2e/expected/*.dom.json`）は `data-region="sidebar"` の中身を丸ごと
  captureする（class は残らず role・data-・aria-・value・href などだけが残る）。9ファイルを1つ
  ずつ読み、各 `it` が固定している契約が、この成果物にすでに同じ形（同じタグ・同じ文字列・同じ
  属性値）で写っているかを台帳に起こす
- `.sidebar-footer:has(> .session-info:empty) { display: none; }`（`sidebar.module.css`）で、
  雑談中かつセッション一覧が空だとセッション情報の帯ごと E2E の成果物から消える。逆に非雑談の
  4本の E2E は毎回キャラクター1体・セッション一覧0件の状態なので、`session-switch.tsx` の
  「一覧が空でない」分岐はどの E2E にも一度も現れない
- D にした契約ごとに本番コードへ1行の変異を入れ、対応する keeper の E2E（`bun test --isolate
test/e2e/<keeper>.test.ts`）が落ちることを確かめてから、退避したコピーから戻す
- 消したあとに要らなくなった import・ヘルパー（`selectValue`・`changeSelect` など）を片付ける

## 注意

- 変異を入れて確かめるときは、退避したコピーから戻す（`git checkout --` で戻さない）
- サブエージェントの中では別のエージェント（fork を含む）を立てず、レーンを順に自分で読む

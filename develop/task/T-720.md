## 目的

背景の委譲を待つあいだに、新しい事実の無いセリフ（「待ってるよ」「まだ作業中」の言い直し）が吹き出しに並ばないようにする。待機中にモデルが話すのは、サブエージェントの合図が届いたときだけにする。

## 完了条件

- `SPEECH_CADENCE_PROMPT` の委譲中の間合いの節に、次の条がある: 背景の委譲を待つあいだ、合図（`SendMessage` の報告・完了の知らせ）の届いていないターン（Claude Code 本体の「しばらく話していない」催促で始まるターンを含む）では、`speak` も `report` も呼ばず、何も書かずに終える
- 同じ節の「合図が届いたら `speak` を呼ぶ」と食い違わない（合図1通につき `speak` 1回。合図を言い直すための `report` は求めない）
- `docs/display.md` のセリフの間合いの記述が新しい条と食い違っていない
- `bun run check` が通る

## 背景

- 2026-09-26 の T-708・T-709 の委譲中に、催促が届くたびに「待ってるよ」の `speak` → 中身の無い `report` → 「書いたぞ」の `speak` を1周していた。催促が来ていないのに同じ1周を十数回くり返したターンもあった
- 催促の文面（"The user hasn't heard from you in a while"）は tsukumo の `src` には無く、Claude Code 本体から来る。止められる設定があるかは確かめていない
- 今の条は「吹き出しが長く止まると引っ込んだように見える」ので間を空けないことを求めていて、待機中の扱いを決めていない。これが待機中の言い直しを後押ししている
- 待機中に居ることを表情で見せる案（tsukumo が背景のタスクの間は待ち顔を出す）は、今回はタスクにしないとユーザーが決めた
- 締めの `speak` と中身の無い `report` の側は、T-721 が扱う

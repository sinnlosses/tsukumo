## 目的

タスクの置き場が GitHub へ移ったあとも、tsukumo のタスク板と成果が正しく出るようにする（`docs/research/github-projects.md` の「移行の段取り」4）。

## 完了条件

- タスク板が Issue と Project の状態を出す（または、Orca のタブで Project のボードを開く形にしてタスク板を消す。どちらかをユーザーと決めて行う）
- 成果が、移行の日より前は git の `develop/task/`、後は Issue の閉じた時刻から数える
- `bun run check` が通る。描画を変えたなら何をどう確かめたかを添える

## 背景

- 今の読み手: `src/server/repository/adapter/task-summary.ts`（`main` のファイルと台帳を見張る）、`src/server/achievement/`（`git log` でタスクファイルの出入りを読む）、`src/shared/task-summary.ts`（文法）、`src/browser/features/task-board/`
- `docs/coding-standards.md`「会話内容の扱い」には、tsukumo 自身がネットワークへ出る経路を足さないという線がある

## 解くべき論点

- tsukumo のサーバが GitHub へ問い合わせる経路を足すか、タスク板を消して Project のボードに任せるか（前者は上の線に触れるのでユーザーが決める）
- 問い合わせるなら、`gh` を外部コマンドとして `adapter/` に閉じ込めるか、トークンで REST を直接呼ぶか（`orca` 以外の外部コマンド依存の追加はユーザーの承認が要る）

## 注意

- 移行の日の前後で成果の数が二重にも欠けにもならないこと

## 目的

「コード・ドキュメントにタスク番号（`T-` + 3桁）を書かない」の規約（唯一の例外は `docs/requirements.md` 7章の対応タスク列）に、いまのリポジトリを合わせる。

## 完了条件

- `grep -rnE 'T-[0-9]{3}' docs --exclude-dir=history` の残りが `docs/requirements.md` 7章の対応タスク列と、規約そのものを説明する行だけになっている
- `src/` と `test/` の、テスト名・コメントに書いたタスク番号が消えている（タスクファイルの形を確かめるテストの**データ**としての `T-001` などは残す）
- `src/` と `test/` のコメント・テスト名に**新しく**タスク番号（`develop/task/T-xxx.md` のパスを含む）が入ったら落とすテストがある（`test/section-reference.test.ts` と同じ形。データとしての `T-001` と、既知の例外 `T-225` は除く）
- `bun run check` が通る（節の参照の検査を含む）

## 背景

着手時点の実測（2026-09-24）で、`docs/` では `architecture.md`（7件）・`design.md`（1）・`screen-design.md`（4）・`workflow.md`（2）と `docs/research/` の7ファイル（計約70件）に残っている。`test/` では `test/shared/main-view.test.ts`・`test/browser/features/main-view/main-view.test.tsx` のテスト名（T-161 / T-165）、`test/server/core/session-manager.test.ts`（T-250）・`test/server/core/usage-review-tool.test.ts`（T-500）・`test/server/adapter/task-summary.test.ts`（T-525）・`test/browser/features/character-screen/character-screen.test.tsx`（T-493）のコメントにある。

再発を止める検査が要る理由（2026-09-25 に足した。T-553 の振り返りから）: T-553 のサブエージェントが CLAUDE.md の禁止を読んだうえで `develop/task/T-553.md` をコメントに4か所書き、`bun run check` は通った。受け入れのときにメインが消した。

## やること

着手時点で前提を調べ直した（`grep -rnE 'T-[0-9]{3}' docs --exclude-dir=history`、`src/`・`test/`・`scripts/` の同様の grep、`test/task-id.test.ts` / `scripts/task-id.ts` / `test/section-reference.test.ts` の中身）。

- `docs/`（`docs/history/` 除く）: `architecture.md`（5行）・`design.md`（1）・`screen-design.md`（4）・`workflow.md`（2）に加え、背景に無かった `docs/research/` の7ファイル（計約54件・`app-shell.md` は `T-046` が中心）が残っていた。全てタスク番号を落とすか、`docs/history/` の日付・節へ言い換える形で消した
- `src/`: 背景では言及が無かったが、実測では `achievement.ts`・`task-summary.ts`（adapter/shared）・`sidebar.module.css`・`character-view.module.css`・`main-view.tsx`・`task-board.module.css`・`task-id-list.tsx`・`character-profile-edit-dialog.tsx` に計13件あった。ID の**形**を説明する例（`T-521` など）は `T-xxx` / `T-NNN`（非数字のプレースホルダ）に置き換え、実際の経緯・evidence の参照だった箇所は番号を落とした
- `test/`: 背景の一覧どおり（`main-view.test.ts` 系のテスト名 `T-161`/`T-165`、`session-manager.test.ts` の `T-250`、`usage-review-tool.test.ts` の `T-500`、`character-screen.test.tsx` の `T-493`）。`task-summary.test.ts`（T-525 相当）は着手時点で既に消えていた（先行タスクの副作用）
- `scripts/`: `task-id.ts` の `T-225`（既知の例外。残す）以外に `capture-view.ts` に実測の evidence 参照が1件あったので落とした
- `test/task-id.test.ts` の既存テストは develop/tasks.json と docs/history/tasks.md の**ID 重複**を見る別の検査で、本タスクの「新しい番号の書き込みを検出する」目的とは別物。ただし指示どおり同ファイルを拡張し（新しい `describe` を足す）、既存のペア構造（`scripts/task-id.ts` + `scripts/lib/task-id-repository.ts`）に倣って `scripts/task-mention.ts` + `scripts/lib/task-mention-repository.ts` を新設した

解くべき論点への回答:

- `docs/research/` の番号は基本すべて消した。決定・完了した内容を指すものは日付や既に隣接している説明（例:「箱の方針（Orca のタブのままか、アプリに包むか）」）に言い換え、`docs/history/` の節へのリンクが要るほど固有の経緯は無かった（研究メモはどれも「当時の判断」を地の文で既に説明していたため）
- 経緯を指していた箇所（`docs/architecture.md`・`docs/screen-design.md` など）も、`docs/history/direction.md`「2026-09-22」のような**日付**が既に併記されているものはそちらへ寄せ、日付も無ければ番号を落として文意が通るかを確認して落とした。`docs/history/tasks.md` は `## T-xxx` 見出ししか節名を持たないため、「ファイル名＋節名」で指そうとすると結局タスク番号そのものを書くことになり、`docs/`（履歴除く）にも `src/`/`test/` にも番号を残せない今回の完了条件の下では使えないと判断し、この形の参照は採らなかった
- `test/task-id.test.ts` と `scripts/task-id.ts` の `T-225` は指示どおり残した（検査の意味を変えないため）

## 解くべき論点

- `docs/research/` の調査メモは当時の記録の性格が強い。番号を消すか、番号の代わりに何を書くか（決まったことの節への参照など）を決める
- 番号で経緯を指していた箇所は、番号を消すと追えなくなる。経緯が要るものは `docs/history/` の該当の節を指す形にする

## 注意

- `docs/` を編集するときは `CLAUDE.md`「ドキュメントを編集するときの罠」に従い、節の数の前後を `grep -c '^#\{2,3\} '` で確かめる
- `test/task-id.test.ts` と `scripts/task-id.ts` の T-225 は既知の例外としてテストが名指ししているもので、消すと検査の意味が変わる。扱いは着手時に決める

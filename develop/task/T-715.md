## 目的

T-666 でサイドバーの単体テストを監査したとき、
`test/browser/components/domain/sidebar/persona-memory-section.test.tsx` の操作のテストは
「E2E に覚えた行のある場面が無い」ので残した。覚えた行を持った雑談の E2E を足し、チップの開閉・
編集・消す操作を DOM の写しとメッセージの列で固定すれば、それらの単体テストを消せる。

## 完了条件

- 覚えた行が1行以上ある状態で雑談のサイドバーを撮る E2E が `test/e2e/` にあり、期待値が
  `test/e2e/expected/` にある
- その E2E が次の操作を行い、結果を DOM の写しかメッセージの列で固定している: チップを押して全文を
  開く／「編集」で × を出す／× → キャンセルで何も送らない／× → 確認の「消す」で
  `chat.forgetRememberedLine` を送る（送信はメッセージの列の `"sent"` に出る）
- `persona-memory-section.test.tsx` のうち、足した E2E が守るものを消している（本番コードに1行の変異を
  入れて E2E が落ちることを確かめてから消す）。「長い行は先頭で切り `…` を付ける」は書式を固定する
  テストなので残す（`docs/coding-standards.md`「消すかどうか」）
- 消したテストごとに、どの E2E が守るかをタスクの結果に書いている
- 覚えた行を fake driver の場面に載せるのに本番コードの変更が要ると分かったら、足す範囲を
  テストの足場に留めて済むかを先に確かめ、済まないなら作業せず `dropped` にすべき理由を報告してよい
- `bun run check` が通る

## 背景

- E2E の足場 `test/e2e/scenario-run.ts` は tsukumo ごとに一時のホームを作って `TSUKUMO_HOME` に渡し、
  `room.page` でクリックできる。送った RPC はメッセージの列に `"sent": "<procedure>"` として残る
  （`test/e2e/expected/permission-answer.messages.json` の `session.answer`）
- 覚えた行の置き場は `<ホーム>/characters/<pack>/persona.md`（`src/server/chat/adapter/persona-memory.ts`）。
  更新は `remembered-lines-changed` で画面へ流れる（配線は `src/session-start.ts`）
- 既存の雑談の E2E（`chat-compact-boundary`・`chat-restored-history`）は疑似セッションの
  `chat-mode-changed` で雑談へ入る。どちらも覚えた行が空の状態で撮っている
- 判定の規則は `docs/coding-standards.md`「消すかどうか」の表と「E2E の台本が通している、とは」

## 注意

- ホームの `characters/<pack>/` にディレクトリを作ると、同梱の同じ名前のパックを覆う（素材の無い
  パックとして読まれうる）。起動時に覚えた行を読む経路と、パックの読み込みがどう重なるかを先に確かめる
- 覚えた行を起動時に読む経路が fake driver の雑談（`chat-mode-changed` の直流し）で通るかは確かめて
  いない。通らなければ、既存の場面か足場のどちらで補うかを着手時の作業の一覧に書いてから進める
- 変異を入れて確かめるときは、退避したコピーから戻す（`git checkout --` で戻さない）
- 期待値は `bun run test:e2e:update` で書き直し、差分を読んで意図した変化だけかを確かめる

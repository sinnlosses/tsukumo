## 目的

T-660 の続き。`test/shared/` の単体テストを `test-audit` で監査し、T-658・T-659 の E2E（`test/e2e/`）が守っている振る舞いだけを確かめている単体テストを消す。

## 完了条件

- `test/shared/` を監査し、E2E が守っている振る舞いだけを確かめている単体テストを消している。消した1件ごとに、どの E2E が守るかをタスクの結果に書いている（テストの跡にコメントは残さない）
- 消す前に、その契約を本番コードで変異させて keeper の E2E が落ちることを確かめている
- `docs/coding-standards.md`「消すかどうか」表の「残す」行（回帰テスト・書式の固定）と、`docs/design.md` 10章「E2E に任せず単体テストに残すもの」に当たるテストは残している
- 消したあと、カバレッジ（閾値は置かない）で守られなくなった分岐が無いかを見て、あれば E2E か単体テストで埋めるか、埋めない理由を「埋めないと決めた穴」に書いている
- 消す前後のテスト件数と `bun run check` の所要時間を結果に書く
- `bun run check` が通る

## 背景

- T-660 で「会話の画面」（`test/browser/components/page/conversation/`）を監査して40宣言・45件を消した。領域が広く1コミットに収まらないため、残りの領域を1件ずつに分けた
- 消す判定は `docs/coding-standards.md`「消すかどうか」表の「E2E の台本が通している振る舞い」の行と、その下の「E2E の台本が通している、とは」の段落に従う
- T-660 の例: `data-brush-origin` のように、定数と JSX の直書きが一致するかを見るテストは、E2E では捕まらないので残した

## やること

`test/fixture/fake-session.json` の全 32 場面を走査し、実際に流れる `SessionEvent` の種類を洗い出した。
`question-answered`・`conversation-cleared`・`tasks-changed`（`session-state.ts` の畳み込みとしては。
`task-summary.ts` のファイル解析は別）・`sessions-changed`・`usage-review-*`・`model-changed`・
`model-effort-support`・`effort-changed`・`remembered-lines-changed`・`chat-topics-changed`・
`diary-*`・`rate-limit-changed`・`api-retry`・`api-error` は、どの `test/e2e/*.test.ts` の
`scene:`/`scenario:` にも出現しない（`diary-written`・`rate-limit`・`api-retry`・`api-failure`・
`visit-long-tool`・`visit-background`・`background-task`（長い版）は fixture に定義があるだけで
どの E2E からも呼ばれていない）。この事実により、`test/shared/` 31 ファイルのうち
E2E との直接の重なりが成立しうるのは、これらのイベントを畳み込む `session-state.ts` の
`test/shared/session-state.test.ts` だけだと分かった。

`test/shared/` の残り30ファイルは、いずれも次のどれかで「残す」に当たる（1ファイル1行）:

- `achievement-calendar.test.ts` / `achievement.test.ts`: 日付計算・依頼文の組み立て。E2E は日記・成果の振り返りのイベントを流さない
- `character-asset.test.ts` / `character-background.test.ts` / `character-diary-font.test.ts`: パス・data URL の境界検証（セキュリティ）。E2E は固定の1キャラクターしか使わず、この経路を通らない
- `character-definition.test.ts` / `character.test.ts` / `expression-choice.test.ts`: 定義ファイルの JSON 解析・編集・畳み込みの境界検証。E2E は `character-changed` を1回だけ固定値で流す
- `character-visit.test.ts` / `visit.test.ts`: `visit-*` イベントは前述のとおりどの E2E にも登場しない
- `chat-log.test.ts`: 日の境目の判定は時刻計算（凍らせた時計では観測できない）。record 変換の一部は chat 系シナリオと重なるが、同じテストが time 計算も検査しており分離が割に合わない
- `command-suggestion.test.ts`: `session-info` を複数回流して上書きを見る契約。`opening` は1回しか流さない
- `contract/command-input.test.ts` / `frame.test.ts` / `session-default.test.ts`: RPC・プロトコル封筒の境界検証（zod）。E2E は `SessionEvent` の出力側しか触らない
- `diary.test.ts` / `usage-review.test.ts`: 対応イベントが E2E に無い
- `expression.test.ts`: モデル名→衣装の対応表。E2E で切り替えるモデルは1種類のみ
- `lib/byte-length.test.ts` / `room.test.ts`: SessionEvent と無関係な純粋ヘルパー
- `main-view.test.ts` / `report-tidy.test.ts` / `report-check.test.ts`: 出力の書式の固定（favor・checks・見出しの整形など）。E2E の3シナリオは1例ずつしか通さず、組合せの大半は未到達
- `portrait-image.test.ts` / `prompt-image.test.ts` / `question.test.ts`: data URL・SDK 入力の境界検証。E2E は固定の質問データしか使わない
- `portrait-motion.test.ts`: 時刻窓の状態遷移。E2E は撮る前に settle させるため遷移の途中を捉えない
- `task-summary.test.ts`: `taskReadiness` の依存判定・`parseNewTaskFile` の INVALID 分岐は `task-list.test.ts` が書く2件の正常系タスクでは通らない
- `turn-speech.test.ts` / `turn-step.test.ts` / `turn.test.ts`: 窓トリミングとの番号整合・複数状態の組合せで、実在の fixture が作らない組合せを検査する最強所有者のテスト

`test/shared/session-state.test.ts`（90件）は、fake-session.json の実際の並びと突き合わせ、
E2E の DOM 期待値が直接固定している7件を消す候補にした（詳細は完了時の報告）。残りの83件は、
上と同じ理由（未使用イベント・時刻計算・エラー方針の分岐・書式固定・境界検証・最強所有者）で残す。

## 目的

サイドバーの下端の帯にあるキャラクターとセッションの切り替えを、帯の左上（キャラクターのアイコンと「〜の間」の横の短縮セッションID）を押して行う形へ移す（2026-09-27 ユーザーの指示）。
セッションは、短縮IDの札を押すと開く切り替え画面（探す＋要約）で選ぶ。

## 完了条件

- 帯の左上のキャラクターのアイコンを押すとキャラクターを切り替えられる
- 部屋の名前が「〜の間 - FA」のように短縮セッションIDつきで出て、**そのIDは押せる札**（プルダウンにしない）。ホバーでセッションの一行（ID・開始・依頼の数・「押して切り替え ⌘K」）が出る
- 札を押すか ⌘K で切り替え画面が開く。左に探す欄（ID・依頼・タスク番号）と日付で区切ったセッションの一覧、右に選んでいるセッションの要約（複数行）と切り替えのボタン。↑↓ で選び、Enter で切り替え、Esc で閉じる。「＋ 新しいセッション」もここに置く
- サイドバーのセッションの一言要約を消している
- 狭い画面で帯が「≡」に畳まれるときも同じ操作ができる
- 仕様を `docs/screen-design.md`（帯とサイドバーの節）と `docs/display.md` に反映し、E2E で操作の流れを守る。見た目は目で確かめて結果の節に書く
- `bun run check` が通る

## 背景

- 今の切り替えはサイドバー下端の帯の `SessionInfo`（`src/browser/components/domain/sidebar/session-info.tsx`・`character-switch.tsx`・`session-switch.tsx`）
- 帯の部屋の名前は `ScreenNavRoom`（`src/browser/components/domain/screen-nav/components/screen-nav-room.tsx`）。押せない字で、狭い画面では「≡」の中の先頭に出る
- 登録時のエージェントの見立て: サイドバーが空き、利用枠の表示の置き場にもなるので良さそう。気がかりは「≡」に畳まれるときの置き場と、要約がひと目で見えなくなること

- 切り替え画面は「探す＋要約」の2列。要約は1行ではなく複数段落で、関わったタスクの札と、
  最後のひとこと（キャラクターのセリフ）を添える

2026-09-27 ユーザー決定（前提調査の論点）:

- 複数段落の要約は `report` に任意の引数 `sessionSummary` を足し、`title` と同じく毎ターン claude が書き直す。
  切り替え画面は transcript から読み戻す（引数を足す前のセッションは要約が空）
- 関わったタスクの札は出さない
- 探す欄が引くのは短縮ID・題（無ければ最初の依頼）・タスク番号だけ。依頼の全文はブラウザへ渡さない
- 短縮IDは UUID の先頭2字を大文字にし、一覧の中で重なったときだけ3字に伸ばす

## やること

### 前提の確かめ（2026-09-27）

- `## 背景` のパスはすべて実在し、主張どおり（`session-info.tsx`・`character-switch.tsx`・
  `session-switch.tsx`・`screen-nav-room.tsx`。部屋の名前は押せない `<span>` で、`screen-nav-menu.tsx`
  が「≡」の中の先頭にも同じ部品を出す）
- サイドバーの「セッションの一言要約」は `SessionSwitch` の `<select>` の行の見出し
  （`SessionChoice.heading`＝SDK の `summary`。tsukumo は `report` の `title` から24字の題を
  `renameSession` で書く）
- 切り替え画面に要る値を、いまの記録から出せるかどうか:

| 見本の値                           | 出せるか | 出どころ                                                                                                                   |
| ---------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------- |
| 一覧の1行（見出し・時刻）          | 出せる   | `listSessions` の `summary`・`lastModified`（いまの `SessionChoice`）                                                      |
| 開始時刻                           | 出せる   | `SDKSessionInfo.createdAt`（いまは捨てている）                                                                             |
| 依頼の数                           | 出せる   | `getSessionMessages` で transcript を読み、利用者の発言を数える（復元と同じ読み方）                                        |
| 最後のひとこと（セリフ）           | 出せる   | 同じく transcript の最後の `speak`（または `report` の締め）の引数。127.0.0.1 のビューへ出すだけ                           |
| 短縮ID（FA・7K）                   | 作れる   | セッションID（UUID）から機械的に作る。ただし UUID は16進なので見本の `7K`・`M2` のような字にはならない                     |
| **複数段落の要約**                 | 出せない | 誰も作っていない。SDK の `summary` は1行の題で、雑談のあらすじは雑談だけ・パック単位                                       |
| **関わったタスクの札（番号と題）** | 出せない | セッションとタスクを結ぶ記録が無い（台帳の印にもセッションIDは無い）。transcript の `T-` + 3桁を拾うのはヒューリスティック |

### 論点（決まった。`## 決まっていること` の2026-09-27 の2つ目の組）

要約は `report` の `sessionSummary`・タスクの札は出さない・探す欄は短縮ID・題・タスク番号だけ・
短縮IDは先頭2字大文字で重なったら3字。

### 作業の骨子

1. サーバ: `report` に任意の `sessionSummary` を足す（引数の説明・「レポートの記法（tsukumo）」の1段落・
   `report` イベントの欄）。一覧（`SessionChoice`）に始まった時刻 `startedAt` を足す
2. サーバ: 依頼の数・要約・最後のセリフは**選んだ1件だけ**読む手続き `sessionDigest.read` にする
   （一覧を作るたびに全件の transcript を読まない。実測で transcript は中央値 1.5MB・上位1割 3.9MB 以上で、
   起こすたびに最大10件読むと起動と切り替えが重くなる）。読んでよいIDは一覧に載ったものといまの
   セッションだけ。fake driver は疑似セッションの `sessionDigests` を返す
3. サーバ: 「＋ 新しいセッション」のためのコマンド `session.startNewSession`（続きを探さずに新規で起こす）
4. ブラウザ: 帯の左上の顔を押すと開くキャラクターの選び口（歯車の設定と同じポップオーバーの形。
   顔の右下に ⌄）。部屋の名前の札「〜の間 - FA」（ホバーで一行・押すと切り替え画面）。⌘K。
   切り替え画面（探す欄・今日/昨日/それより前・↑↓/Enter/Esc・＋ 新しいセッション・右に要約と最後のひとこと）
5. ブラウザ: サイドバーの下端の帯からキャラクターとセッションの `<select>` を外す（使用量の札だけ残る）
6. 狭い画面: 「≡」の面の先頭に同じ顔と札を置く。切り替え画面は2列を縦に積む
7. docs: `docs/screen-design.md`（帯とサイドバーの節）・`docs/display.md`・`docs/glossary.md`（短縮ID・
   セッションの要約）・`docs/requirements.md`・`docs/design.md`（E2E の一覧）
8. E2E `session-switch`（札を押す・⌘K → ↓ → Enter・狭い画面の「≡」）と、広い画面・狭い画面の目視

## 注意

- 見本の要約は `要約は [サンプル文]` と注記された作り物。セッションごとの複数段落の要約・関わったタスク・
  最後のひとことを、いまの記録から出せるかを最初に確かめる。出せないものがあるなら、作り方
  （要約を誰がいつ作るか）はユーザーの判断なので、実装に進まず確かめる
- 見本の探す欄は ID・依頼・タスク番号で引く。依頼の文面で引くなら、会話の中身をブラウザへ渡す経路が
  増えるので `docs/coding-standards.md`「会話内容の扱い」を見る

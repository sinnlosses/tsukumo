## やること

前提の確かめ（2026-09-27）: 5章は `docs/design.md` 1394〜2164 行（12 節・約 770 行）。
各節のファイル単位の中身は、対応するファイルの冒頭と doc コメント（`diary.ts` の置き場と
`<リポジトリ>` の決め方、`main-history.ts` の 503、`task-summary.ts` の見回り、`sdk-diary.ts` の
起こし方など）にほぼ揃っている。成果と日記の数え方・契機は `docs/requirements.md` 4.11 に
すでにある。見直しと訪問の規則は requirements に置き場が無い。前提は崩れていない。

- 5章を横断の規則だけにする: 境目の基準（shared の語彙で書けるか）、SDK に触るファイルの
  分け方、共有する定数の置き場、代の持ち物と起こし直し、イベントを受けて記録するものの寄せ方、
  ツールで受け取るものの形（誰がイベントを流すか・検査の2段・戻り値）、使い捨ての `query()` の形
- 見直しの規則（ツールの分け方・見直し中の契機・識別子・見送りと前回の結果の持ち方）は
  requirements に 4.12 を足して移す。訪問の契機・しきい値・客の選び方・台本の上限と落とし先は
  4.13 を足して移す（索引も2行足す）
- 日記の上限（本文・理由の文字数、120 秒、回数）・書き手のモデル・3段の進みの合図は
  4.11「日記」「会話から切り離す」へ足す。成果の取り直す契機と「今日に倒す」は 4.11 へ
- 「成果は `SessionState` に入れず、画面を開いたときに手続きで取りに行く」は 4.2 へ
  （`connection` と同じ「状態の外側の決定」）
- `config.ts` の表は消し、既定値のうち doc コメントに無いものを `config.ts` の doc コメントへ移す
  （利用者向けの表は `README.md`「環境変数」に残っている）
- 5章の節と句を引いていた参照（コードのコメントと docs）を、ファイルの doc コメント・
  requirements の節・残した5章の句へ張り替える

論点への答え: 成果と日記の応答の形・保存の形（`DailyAchievement` / `AchievementCalendar` /
`Diary` / `DiaryWriting` の型の全文）は、4章の方針（型の doc コメントが正典で、design.md には
コードから読み取れない決定だけを残す）に寄せて消す。型と zod は `shared` にあり、保存の置き場と
`<リポジトリ>` の決め方は `diary.ts` の冒頭が持っている。プロトコルの不変条件として design.md に
残すのは型ではなく次の決まりだけにする。成果は状態に入れず取りに行く。応答はサーバの `today` を
持ち、ブラウザは時計を読まない。`main` が読めないときは `unknown`、読み取りの失敗は部分的な数を
配らない（503）。日記が読めなくても数は配る。これらは 4.2 に置く。

## 目的

長い待ち（背景のタスク・走りっぱなしのツール）が続いたら客が訪ねてきて、利用者やあるじが動いたら帰る、という訪問の出入りをサーバの状態として持つ。台本はまだパックの `scripts` だけで回す（生成は後のタスク）。提案 `docs/research/character-visit.md` の論点1・論点5・「表情の源」。

## 背景

- 待ちの信号は2つ: 背景のタスク（SDK の `background_tasks_changed` → `src/server/core/sdk-message.ts` → `SessionState.backgroundTasks`）と、トップレベルの `tool-started` に `tool-finished` が来ない状態（`src/shared/session-event.ts`）
- 背景のタスクが終わると tsukumo が `turn-resumed` を補う（`src/server/core/self-started-turn.ts`）
- 状態の畳み込みは `src/shared/session-state.ts`。表情は `speechExpression`（直近の `speak`）と `records`（過去のターン用）から読まれる

## 決まっていること（蒸し返さない）

- 判断は `src/server/core/` の純関数（案: `visit-timing.ts`）、時計を回すのは adapter。時刻は `Temporal`
- 出発点の値: 信号が続けて 90 秒で来る・1回の待ちに1度・前の訪問から 30 分は来ない・答え待ちと雑談モードでは来ない
- 帰る合図（依頼の送信・答え待ち・本物の `speak`・待ちの終わり（`tool-finished` / `turn-resumed`）・セッションの終わりと切り替え・台本の終わり）はサーバで1つの `visit-ended` にまとめる
- 台本の表情は `SessionState.visit`（判別可能な合併型）に持ち、`speechExpression` と `records` には書かない
- **あとで元に戻せる形で入れる**（2026-09-25 ユーザー決定: 「上手くいかず元に戻すかもしれないから revert 可能なようにすることが条件」）
  - このタスクの変更は1コミットにまとめ、訪問と関係の無い変更（ついでの整理・名前の変更・整形だけの差分）を混ぜない。`git revert` 1回でこのタスクの分だけ戻せるようにする
  - 訪問のコードは訪問専用の新しいファイルに置き、既存のファイルへの差し込みは呼び出し・分岐・型の足し込みなど最小にとどめる
  - 完了時の結果の節に「差し込んだ既存のファイル」を列挙する（戻すときに見る場所）
  - 訪問のタスクは後ろから順に revert すれば戻る並びにする（前のタスクが後のタスクの部品に依存しない）

## 解くべき論点

- 90 秒を数えるタイマーをどの adapter に置くか（いまのセッションの駆動とどうつなぐか）
- 訪問の行を進める間（2秒の出発点）をサーバとブラウザのどちらが刻むか。再接続したときのスナップショットで同じ行が出ること
- 客のパックの選び方（`visit` を持つパックが複数あるとき・あるじ自身は除く）

## やること

### 調べ直した前提（2026-09-25 のコード）

- 前提は崩れていない。待ちの信号 A は `SessionState.turn`（`finished`）と `backgroundTasks`、信号 B は `records` の `tool`（`nested: false`・`status.kind === "running"`）と `turn`（`running`）から読める。`speak` と `report` は `tool-started` にならない（`src/server/core/sdk-message.ts`）ので、B に混ざらない
- 状態を持つのは `src/server/core/session-manager.ts` の `receive` だけで、ここが駆動由来（`"driver"`）と復元の再生（`"restored"`）を分けて受ける。代のあいだだけ意味のある勘定は `GenerationTally` に集めてあり、起こし直し（キャラクター・雑談モード・セッションの切り替え）は代を丸ごと作り直す（状態も `INITIAL_SESSION_STATE` へ戻る）
- タイマーの先例は2つ。core の `event-batch.ts` が `setTimeout` を直に持ち、adapter の `task-summary.ts` が `setTimeout` + `unref()` で見回る。見張りを駆動と同じ寿命で起こす口は `session-launch.ts` の `watchTasks` だが、これは状態を見られない
- `PROTOCOL_VERSION` は 15（`src/shared/frame.ts`）。状態の形を変えたら上げる（`docs/design.md` 4.5）。イベントを足すだけなら上げない
- パックの `visit` は `CharacterDefinition.visit`（`src/shared/character-visit.ts`）にあり、画面へ配る `CharacterPackEntry` には載っていない。客の立ち絵は全パックぶん既に配っている（`docs/design.md` 7.2）ので、ブラウザは客のパック名が分かれば描ける

### 論点への答え

1. **タイマーは新しい adapter `src/server/adapter/visit-clock.ts`（遅れて1回呼ぶ・取り消せる、`setTimeout` + `unref()`）に置き、セッションの駆動とは session-manager の代の持ち物でつなぐ。** 訪問の見張り（`src/server/core/visit-watch.ts`）を `GenerationTally` に1つ足し、`receive` が駆動由来のイベントを畳んだあとに1行で渡す。見張りは純関数（`visit-timing.ts`）に「来る／まだ（何時に）／来ない」を聞き、「まだ」ならその時刻に時計を掛け、起きたら聞き直す。出すイベントは `receive` へ戻して畳む（配る束も状態も今までと同じ1本の経路）
   - 理由: 待ちの信号を読める状態はここにしか無い。`watchTasks` の形（session-launch の見張り）は状態を見られないので、見張りが自前でイベントを畳み直すことになる。代の持ち物に入れると、起こし直しで時計ごと捨てられ、`restart` に戻す行を足さずに済む（`docs/design.md` 5章の表の約束どおり）。session-manager が知るのは「代ごとに1つ作る・イベントを渡す・閉じる」の3か所だけ
   - 前の訪問から 30 分の勘定も代の持ち物になる（起こし直すと数え直す）。起こし直しは利用者の操作なので、その直後に待ちが 90 秒続くまで来ないことは変わらない
2. **行を進める間はサーバが刻む。** 状態は `visiting` の中に「いま何行目か」（`line`）を持ち、見張りが 2 秒ごとに `visit-line-advanced`（行の番号つき）を出し、最後の行のあとに `visit-ended`（台本の終わり）を出す。再接続したタブは `hello` の snapshot の `line` をそのまま読むので、同じ行が出る
   - 理由: 「台本の終わり」も帰る合図の1つで、帰る合図はサーバで1つの `visit-ended` にまとめると決まっているので、サーバはどのみち台本の時間を数える。ブラウザも数えると時計が2つになり、ずれたときにどちらが正しいかを読む人が追うことになる。ブラウザは添字で引くだけで済む
   - 帰りの一言は来たときに選んで `visit-started` に載せ、`visit-ended` で状態が `left`（客・一言・帰った時刻）になる。一言を何秒出して引っ込めるかは描き方の側（後続のタスク）が帰った時刻から決める（立ち絵の「失敗でびくっ」が `lastToolFailureAt` から窓を決めるのと同じ形）
3. **客は「`visit` を持ち、台本（`scripts`）が1本以上あるパック」から、あるじ（`state.character.pack`）を除き、来るたびに等しい確率で1つ選ぶ。** 台本と帰りの一言も同じく1つずつ選ぶ。乱数は呼び出し側から渡す（テストは固定の値）。パックの一覧は来るときに1回読む（画面から作った・直したパックもその場で反映される）
   - 理由: 提案は「候補が複数なら毎回ひとり選ぶ」で、順番や重みは決めていない。巡回にすると前に誰が来たかの記憶が要り、持ち物が1つ増える。台本の生成はまだ無いので、台本を持たないパックは来られない（「それも無ければ来ない」）。あるじがまだ分からない（`character-changed` の前）ときは来ない

### 置くファイル

- 新しいファイル（訪問専用）

  - `src/server/core/visit-timing.ts`: 待ちの信号・来る／まだ／来ない・帰る合図・次の行の判断（純関数）と、しきい値の表（本番と、疑似セッションで確かめるための縮めた表）

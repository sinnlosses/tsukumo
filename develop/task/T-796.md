## 目的

t3code（https://github.com/pingdotgg/t3code/tree/main/apps）のように、ブラウザ側とサーバ側をそれぞれ `package.json` を持つパッケージ（pnpm workspace）に分けるほうが良いかを調べ、分けるか据え置くかを決めて正典に書く（2026-09-27 ユーザーの問いかけ「分けるほうが良さそうな印象を持ったけどどうかな?」）。

## 完了条件

- `docs/research/` に提案書を書く。据え置き（今の1パッケージ＋`test/architecture.test.ts` の辺の検査）と、パッケージに割る案（`apps/server`・`apps/browser`・共有の `packages/*` など、t3code の割り方を含む）を表で並べ、各案で「依存の宣言が層ごとに分かれるか・層の辺をパッケージ境界で守れるか（今のテストの検査と比べて）・`pnpm run build` / `check` / E2E / `bin/tsukumo` / `pnpm link --global` の変わり方・`tsconfig` と Vite と Vitest の設定の数・同梱パック（`characters/`・`assets/`）の解き方」を書き、推奨を付ける
- 分けると決めたら、決定を `docs/architecture/adr/` に書き（`0019-layer-as-directory.md` との関係を書く）、移行の段階ごとの実装タスクの案を `develop/draft/` に1件1ファイルで書く（登録はユーザーの承認のあと）。据え置くと決めたら、据え置く理由と「いつ分けるか」の目安を提案書に書いて終える
- 結論が T-731（`src/shared/` を機能ごとに割る）・T-732・T-736 の前提を変えるなら、そのタスクの `## 背景` か `## 注意` に書き足す
- `pnpm run check` が通る

## 背景

- 今は1つの `package.json`（ルート）で、`dependencies` にサーバ側（`@anthropic-ai/claude-agent-sdk`・`ws`・`@orpc/server`）とブラウザ側（`react`・`mermaid`・`chart.js`・`react-markdown` など）が混ざっている。`pnpm-workspace.yaml` は無い
- 層は `src/shared` / `src/server` / `src/browser` のディレクトリで表し、辺は `test/architecture.test.ts` が import を読んで落とす（`docs/architecture/adr/0019-layer-as-directory.md`、`docs/design.md` 2章）
- 以前の調査 `docs/research/architecture-rethink.md` の構成の行は「ワークスペース（`packages/`）にするほどの規模ではまだ無い。必要になったら分ける」。同じ文書の66行目付近に「共有パッケージが無いことの」写しの話がある。今回はこの判断の見直しで、そのとき挙げた「必要になったら」の条件に今が当たるかから始める
- ブラウザ側は起動前に `pnpm run build`（`scripts/build-ui.ts`、`vite.config.ts`）で `dist/browser/` に組み立てる（`docs/architecture/adr/0006-prebuild-browser.md`・`0007-vite-build-cli.md`）。mermaid と chart.js は版を固定して同梱する（`0012-bundle-vendor-library.md`）
- 関係する既存のタスク: T-731/T-732（`src/shared/` の割り方）・T-736（t3code の依存を含むブラウザ側のライブラリの検討）・T-738（`check` の高速化）

## 解くべき論点

- パッケージ境界が、今のテストによる辺の検査に何を足すか（依存の宣言の分離・型検査の分割）と、何を失うか（設定ファイルの増加・`link --global` と同梱パスの解き方）
- 共有の語彙（`src/shared`）を独立したパッケージにするか、どちらかに寄せるか
- `server` の中の機能（`src/server/<機能>/`）までパッケージにするか（t3code の `packages/*` との対応）

## 注意

- このタスクは提案と決定まで。ファイルを動かすのは後段のタスク
- 依存を足す・`orca` 以外の外部コマンドを増やす案になるなら、提案書にそう書き、実装はユーザーの承認のあと

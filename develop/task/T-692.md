## 目的

仕事のセッションでも、1つの記憶（あらすじ・作業記憶・エピソード索引）を思い出せるようにする
（T-690 で正典に書いた形で）。

## 完了条件

- 仕事のセッションを新しく起こしたとき（と `/clear` のあと）、`systemPrompt` にあらすじと
  作業記憶の新しいほうから T-690 で決めた量（16 KiB 程度）が載る。雑談の作法（`chat-manner.ts`）は載らない
- 雑談のセッションに載るものは変わらない（仕事の行も同じ記憶として作業記憶に入る）
- 仕事のセッションでも `recall` / `recall_episode` が使え、仕事の行も引ける
- 定着が仕事のターンの終わりにも T-690 で決めた条件で走り、プロセスをまたいで同時に2本走らない
- 上をテストで守っている（フィクスチャに実際の会話を使わない）
- `bun run check` が通る

## 背景

- 読み戻し: `src/server/system-prompt/core/system-prompt.ts`（`mode.kind !== "chat"` なら載せない）、
  `src/server/chat/core/chat-memory-prompt.ts`、容量は `src/shared/chat-memory-budget.ts` の `CHAT_MEMORY_BUDGET`
- 定着の契機: `src/server/session/core/session-manager.ts`（`turn-finished` かつ `state.chatMode`）、
  本体は `src/server/chat/core/chat-consolidation.ts` と `chat-consolidation-writer.ts`
- `recall` / `recall_episode` を載せる所: `src/server/session-driver/adapter/sdk-tool.ts`・`sdk-driver.ts`
- 決定と形は T-690 が正典に書く

## 注意

- T-690 の結論で、排他の置き方・`remember` / `forget` を仕事でも載せるかが決まる。本文が T-690 の
  あとで直されていればそちらに従う
- 実物の claude を使った確かめは要らない（`systemPrompt` の組み立てと契機は単体テストで守れる）

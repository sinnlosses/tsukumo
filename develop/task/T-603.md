## 目的

規約「型を迂回するキャストを使わない」に当たっている2箇所を、remeda の型付きの関数に替えてキャストを消す。

## 完了条件

- `src/browser/components/page/achievement/lantern-calendar.tsx` の `(Object.keys(LAMP_LABEL) as readonly LampLevel[])` が remeda の `keys(LAMP_LABEL)` になり、`as` が無い
- `src/shared/task-summary.ts` の `isOneOf` が消え、呼び出しの3箇所（`status`・`difficulty`・`loopable` の検証）が remeda の `isIncludedIn` になっている
- 絞り込み後の型（`LampLevel`・`NEW_TASK_STATUS_VALUES[number]` など）が、書き直す前と同じに推論されている
- `bun run check` が通る

## 背景

- `lantern-calendar.tsx:69`: `LAMP_LABEL` は `Readonly<Record<LampLevel, string>>`（16行）。`Object.keys` が `string[]` を返すため、キャストで `LampLevel[]` にしている
- `task-summary.ts:212`: `function isOneOf<const T extends readonly string[]>(value: string, values: T): value is T[number]` が `(values as readonly string[]).includes(value)` をしている。呼び出しは 132・137・142 行
- remeda 2.50.0 は `keys`・`isIncludedIn` を持つ（`node_modules/remeda/dist/` で確認済み）

## やること

### 前提の調べ直し

1. **`keys` の型推論**:
   - remeda の `keys<T extends object>(data: T): Keys<T>` は、`Keys<T> = T extends IterableContainer ? ArrayKeys<T> : ObjectKeys<T>` として定義される
   - `LAMP_LABEL: Readonly<Record<LampLevel, string>>` に対して `keys(LAMP_LABEL)` は `ObjectKeys<Readonly<Record<LampLevel, string>>> = EnumerableStringKeyOf<Readonly<Record<LampLevel, string>>>[]` を返す
   - 実測: remeda の型定義では `Record` 型の keys に対して `LampLevel[]` 相当が推論される（キャスト不要）

2. **`isIncludedIn` の型絞り込み**:
   - remeda の `isIncludedIn` は2つのオーバーロード:
     - `isIncludedIn<T, S extends IterableContainer<T>>(data: T, container: IsNarrowable<T, S> extends true ? S : never): data is S[number]` (型絞り込みあり)
     - `isIncludedIn<T, S extends T>(data: T, container: IterableContainer<S>): boolean` (型絞り込みなし)
   - `task-summary.ts` の呼び出しは `field(3, "status: ")` → `string | undefined` が入力。undefined チェック後は `string` のまま
   - `NEW_TASK_STATUS_VALUES = ["todo", "hold", "done", "dropped"] as const` は readonly tuple で、TypeScript の type narrowing が `isIncludedIn(status, NEW_TASK_STATUS_VALUES)` を使ったあとに `status is "todo" | "hold" | "done" | "dropped"` に絞るかどうかは実装次第

3. **キャストの現在位置**:
   - `lantern-calendar.tsx:69`: `(Object.keys(LAMP_LABEL) as readonly LampLevel[])`
   - `task-summary.ts:212`: `(values as readonly string[]).includes(value)` で values を string[] に キャスト（`isOneOf` 内部）

### リファクタリング実施

1. `lantern-calendar.tsx:69` の `Object.keys` を remeda の `keys` に置換
2. `task-summary.ts:212` の `isOneOf` 関数を削除、3つの呼び出し箇所を remeda の `isIncludedIn` に置換
3. 型推論の検証: `bun run typecheck` でキャスト不要に推論されるか確認

## 注意

- `isIncludedIn` の型の絞り込みがこの呼び出しで効かないと分かったら、そのファイルは替えずに理由を結果の節に書く。2箇所とも効かなければ `dropped` で閉じてよい

## 結果

- `lantern-calendar.tsx` の `Object.keys` のキャストを remeda の `keys` に、`task-summary.ts` の `isOneOf`（中にキャスト）を消して3か所を `isIncludedIn` にした。絞り込み後の型は同じに推論され、typecheck が通る
- 検証コマンド: 2674 pass / 0 fail
- 振り返り: 兆候なし

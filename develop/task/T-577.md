## 目的

帯（`docs/screen-design.md` 13.9）から、いまのセッションの effort を切り替えられるようにする。表示するのは送った値ではなく、T-576 で確かめた口から読み取った値。

## 完了条件

- ブラウザ → サーバのコマンドに effort の切り替え（`set-model` と同じ形の1つ）があり、サーバがそれを `applyFlagSettings({ effortLevel })` で SDK へ渡している（SDK に触るのは `src/server/adapter/` の `sdk-` で始まるファイルだけ）
- 読み取った effort が状態に入り、帯のモデルのドロップダウンの隣（モデル → effort → 許可モードの並び）に出ている。選択肢はいまのモデルが選べる段だけで、effort に対応しないモデルでは選べない（理由を `title` で出す）
- 疑似セッション（`src/server/adapter/fake-driver.ts`）も切り替えに応じる
- ターン進行中の扱いがモデルの切り替えと揃っている
- テスト: コマンドの検証・状態の畳み込み・帯の部品の振る舞い
- `bun run check` が通る。帯の見た目は目視で確かめ、どの端末で何が見えたかを結果に書く
- T-576 が「成り立たない」で終わっていたら、着手せず `dropped` で閉じてよい

## 背景

- モデルの切り替えの経路が手本になる: `src/shared/command.ts` の `set-model`（236行目）→ `src/server/core/driver-command.ts:53` の `setModel` → `src/server/adapter/sdk-driver.ts:160`。帯の部品は `src/browser/features/screen-nav/components/screen-nav-model-permission.tsx`、表示名は `src/browser/features/screen-nav/domain/model-label.ts`
- effort は今 `sdk-driver.ts:64` の `DEFAULT_EFFORT` を起動時に渡すだけで、状態にも画面にも無い
- 読む口・変える口の実測と、要件の書き直しは T-576 の結果と `docs/requirements.md` 4.1 を見る

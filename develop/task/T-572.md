## 目的

同じ掛け合いの繰り返しで飽きないように、訪問1回ぶんの台本をその場の仕事に合わせて作る。提案 `docs/research/character-visit.md` の論点2（2b を主に、2c を落とし先）。

## 背景

- SDK の `query()` を呼ぶのはいま `src/server/adapter/sdk-driver.ts` の1つだけ。SDK に触るファイルは `src/server/adapter/` 直下の `sdk-` で始まるファイルに閉じ込める（CLAUDE.md 原則3）
- `@anthropic-ai/claude-agent-sdk` の `Options` に `persistSession: false` と `outputFormat`（json_schema）がある
- 成果は `src/server/core/achievement.ts` が数える。セリフの指示文を core の定数に置く先例は `src/server/core/speech-cadence.ts`
- パックごとの表情の選択肢は `src/shared/expression-choice.ts`

## 決まっていること（蒸し返さない）

- 仕事の会話を渡してよい（2026-09-25 ユーザー決定）。渡すのは2つの人格・いまの仕事の抜き書き（このターンの依頼・直近のセリフ・待っている相手の説明）・経過時間・時間帯・今日の成果
- 起こし方: 軽いモデル・`tools: []`・`maxTurns: 1`・`persistSession: false`・json_schema で「話し手・表情・セリフ」の並び。受け取ったら境界で検証する
- 帰る合図で中断する。失敗・時間切れ・形の崩れはパックの `visit.scripts` へ落とし、それも無ければ来ない。常駐プロセスは落ちない
- 台本はメモリにだけ持ち、ディスク・ログに書かない（`docs/coding-standards.md`「会話内容の扱い」）
- **あとで元に戻せる形で入れる**（2026-09-25 ユーザー決定: 「上手くいかず元に戻すかもしれないから revert 可能なようにすることが条件」）
  - このタスクの変更は1コミットにまとめ、訪問と関係の無い変更（ついでの整理・名前の変更・整形だけの差分）を混ぜない。`git revert` 1回でこのタスクの分だけ戻せるようにする
  - 訪問のコードは訪問専用の新しいファイルに置き、既存のファイルへの差し込みは呼び出し・分岐・型の足し込みなど最小にとどめる
  - 完了時の結果の節に「差し込んだ既存のファイル」を列挙する（戻すときに見る場所）
  - 訪問のタスクは後ろから順に revert すれば戻る並びにする（前のタスクが後のタスクの部品に依存しない）

## 解くべき論点

- 抜き書きの量（直近のセリフを何件まで・依頼の文面を何字まで）と、軽いモデルで台本の質が足りるか
- 作るのに掛かる時間を 90 秒のしきい値の中に収めるか（先に作り始めるか、来てから作るか）

## やること

### 着手時に調べ直した前提（2026-09-25 のコード）

- 台本を選んでいるのは `src/server/core/visit-watch.ts` の `arrive`。`chooseVisit`（`visit-guest.ts`）で客・台本・帰りの一言を同時に選び、その場で `visit-started` を出している（同期）。客になれるのは `visit.scripts` が1本以上あるパックだけ
- `node_modules/@anthropic-ai/claude-agent-sdk`（0.3.280）の `Options` に `persistSession?: boolean`・`outputFormat?: { type: "json_schema"; schema }`・`maxTurns?`・`tools?: string[]`（`[]` で組み込みのツールを全部外す）・`abortController?`・`model?`・`settingSources?`（`[]` で設定ファイルを読まない）・`systemPrompt?: string` がある。成果は `result` の `structured_output?: unknown`
- `query()` を呼ぶのは `src/server/adapter/sdk-driver.ts` だけ。SDK の境界は `sdk-` で始まるファイル（`test/architecture.test.ts` が守る）
- 読み取り口: 人格と表情は `listCharacterPacks`（`CharacterPack.persona`・`definition`）と `expressionChoices`、今日の成果は `readAchievement`（`main-history.ts`）、時刻は `localTimeHHMM`（`local-time.ts`）、仕事の抜き書きは `SessionState.records`（`request` / `speech` / `tool`）と `backgroundTasks`
- 前提は崩れていない

### 論点への答え

- **抜き書きの量**: 依頼は最後の1件を先頭 200 字まで、直近のセリフは最後の 3 件を各 100 字まで、待っている相手は走っているトップレベルのツールの名前と `description` / `command`（先頭 150 字）か背景のタスクの `description`（3 件まで・各 150 字）、今日の成果はコミット数と終えたタスクの summary（5 件まで）。人格は丸ごと渡す（キャラクターの中身そのもので、削ると口調が崩れる）。理由: 掛け合いの話題に要るのは「いま何を待っているか」までで、長い文脈はトークンを食うだけ（提案の論点2）。数は core の定数1か所に置き、実物で足りなければそこだけ直す。軽いモデル（`haiku`）で質が足りるかは実物の確認で見る
- **作る時間を 90 秒に収めるか**: **来てから作る**（しきい値に届いた時点で作り始め、できたら `visit-started`）。先に作り始める案は、待ちが途切れたときに捨てる・作ったあとに仕事が進んで話題が古くなる、の2つを見張りが余分に持つことになり、読む人が追う状態が増える。来てから作ると、見張りの状態は「作っている最中」1つだけ増え、抜き書きは来る瞬間の仕事を写す。代わりに客が来るのが作る時間（数秒〜十数秒）だけ遅れるが、90 秒はもともと出発点の値なので受け入れる。時間切れは 30 秒で、切れたらパックの台本へ落とす

### 形

- **作っている最中に帰る合図**（依頼・本物の `speak`・答え待ち・待ちの終わり・セッションの終わり）が来たら `query()` を中断し、来ない（その待ちでは聞き直さない）
- 落とし先: 作れなかった（起こせない・時間切れ・形の崩れ）→ 客のパックの `visit.scripts` から1本 → それも無ければ来ない。これに合わせて、客の候補を「`visit` を持つパック」に広げる（台本の無いパックも、作れたときは来られる）
- 疑似セッション（`TSUKUMO_DRIVER=fake`）では作らず、パックの台本だけを使う（いままでと同じく、しきい値に届いたその場で来る）
- 台本の検証: 形（`lines` の並び・3〜6 行・各行 60 字まで）、話し手（`host` / `guest` のどちらか・1行目は客・両方が1回以上話す）、表情（**その行の話し手のパック**の選択肢にあるか）。崩れていたら丸ごと落とし先へ
- 置くファイル（訪問専用の新しいファイル）:
  - `src/server/core/visit-script.ts`: 抜き書き・指示文・JSON Schema・台本の検証（純関数と定数）
  - `src/server/core/visit-script-writer.ts`: 材料を集めて `query()` の口を呼び、時間切れ・中断・検証を1つの結果に畳む（作る口の型もここ）
  - `src/server/adapter/sdk-visit-script.ts`: 使い捨ての `query()`（`tools: []`・`maxTurns: 1`・`persistSession: false`・`settingSources: []`・MCP なし・json_schema・`abortController`）
- 起こし方に `thinking: { type: "disabled" }` を足す（実測: 考える段つきだと `haiku` でも 1 回 66〜70 秒掛かり、30 秒の時間切れで毎回落とし先へ回る。切ると 5〜7 秒で、3 回とも検査を通る台本が返った。`maxTurns: 1` のままで `result` は `success`（`num_turns` は 2 と数えられるが止まらない））
- 差し込む既存のファイル: `src/server/core/visit-watch.ts`（作る口を受けて、作っている最中の中断と落とし先）、`src/server/core/visit-guest.ts`（候補の条件と落とし先の台本の形）、`src/session-start.ts`（配線）、それぞれのテスト、`docs/design.md` 5章「訪問の契機と状態」

### 実物での確認（2026-09-25）

- 本物の claude で起こした（`TSUKUMO_VIEW_PORT=48731`・`TSUKUMO_HOME` はスクラッチの空ディレクトリ・`TSUKUMO_OPEN_VIEW=0`・`TSUKUMO_VISIT_QUICK=1`。あるじは同梱の既定パック、客は `visit` を持つ同梱の帳ちゃんのパック）。WebSocket から架空の短い依頼（40 秒眠るだけのコマンドを前景で1回実行して一言報告する）を送った
- 1回目は `sleep 40` を頼んだが、Claude Code 側が単独の `sleep` を1秒で返したため待ちにならず、訪問は起きなかった（見張りの不具合ではない）。2回目は `python3` で 40 秒眠らせた
- 2回目: 依頼から 8 秒で Bash が走り始め、縮めたしきい値（5 秒）で作り始めて、19 秒に `visit-started`（作るのに約 6 秒）。台本はパックの `visit.scripts` のどれとも一致しない（＝ `query()` で作られた）5 行で、話し手は客→あるじ→客→あるじ→客。1〜3 行目が依頼のコマンド・40 秒・待っていることに触れていた。2 秒おきに行が進み、29 秒に `script-finished` で帰った。そのあと Bash が戻り、ターンが終わった
- サーバの標準出力・標準エラーは起動の2行だけ（台本も文面も出ていない）。スクラッチのホームにできたのは `token-usage/` と `context-usage/`（仕事のセッションの記録）だけ。プロセスは `bun run scripts/stop.ts --port 48731` で止めた

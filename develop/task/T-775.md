## 目的

`pnpm run check` の中で `test/server/achievement/adapter/main-history.test.ts` がときどき未処理の `EPIPE` を出して落ちる揺れを消す（振り返り: T-750）。

## 完了条件

- 子プロセスが stdin を読む前に終わっても、`runGitCatFileBatch` の stdin への書き込みの失敗が未処理のエラーにならない（`kind: "failed"` などの既存の結果に畳む）
- `pnpm run test` を10回続けて回し、未処理の `EPIPE` が1度も出ない（回数と結果を `## 結果` に書く）
- `pnpm run check` が通る
- 調べて EPIPE の出どころが `runGitCatFileBatch` でないと分かったら、出どころを `## 結果` に書き、そこを直す（直せなければ理由を書いて `dropped` で閉じてよい）

## 背景

- `src/server/repository/adapter/git.ts` の `runGitCatFileBatch` は 108〜109行目で `child.stdin.write(...)`・`child.stdin.end()` を呼ぶが、`child.stdin` の `error` を拾っていない。`child` の `error` と `close` だけを見ている
- `src/server/achievement/adapter/main-history.ts` が `runGit`・`runGitCatFileBatch` を使う
- T-750 の受け入れで、2718 件すべて pass のまま「main ブランチが無いリポジトリでは「不明」」の直後に未処理の `EPIPE`（`child.stdin.end` への書き込み）が1件出て `check` が落ち、打ち直すと通った。T-750 は `src/browser` だけを触っていた
- 既存の揺れのタスク（T-671・T-739・T-774）はこのファイルを扱っていない

## やること

- 前提を確認した: `src/server/repository/adapter/git.ts` の `runGitCatFileBatch`（57〜111行目）は今も
  108〜109行目で `child.stdin.write(...)` と `child.stdin.end()` を呼び、`child.stdin` の `error` を
  拾っていない。`child` 自体の `error`（91行目）と `close`（92行目）だけを見ている構造は背景の記述
  どおりなので、まず `child.stdin.on("error", ...)` を足して `finish({ kind: "failed" })` に畳んだ
- 実際に10回 `pnpm run test` を回すと、`main-history.test.ts` を出どころとする未処理の `EPIPE` が
  再現した。スタックを見ると書き込み元は `runGitCatFileBatch` ではなく
  `test/fixture/subprocess.ts:45` の `runSubprocess`（`child.stdin.end(options.input ?? "")`）で、
  こちらも `child.stdin` の `error` を拾っていなかった。T-750 で見えた EPIPE もこの経路だと分かった
- `test/fixture/subprocess.ts` の `runSubprocess` に `child.stdin.on("error", ...)` を足す。ただし
  最初に `reject` へつなぐと、標準入力を読まずに終わる `git` コマンド（`init` など）で本来成功する
  実行が `EPIPE` で失敗扱いになる揺れが新たに出たため、無視して `close` の結果に任せる形へ直した
  （コメントもその旨に書き換え）
- 両方の修正を入れたうえで `pnpm run test` を10回続けて回し、未処理の `EPIPE` が出ないことを確かめて
  `## 結果` に件数と結果を書く
- `pnpm run check` を通す

## 注意

- 揺れのまとめのタスク（Vitest の並列化で増えた揺れを10回で確かめる側）がこのタスクに依存している。ここでは EPIPE だけを直す

## 結果

- 検証コマンド: 2718 pass / 0 fail（単体）・24 pass / 0 fail（E2E）
- EPIPE の出どころは `runGitCatFileBatch` ではなく `test/fixture/subprocess.ts` の `runSubprocess`（`child.stdin.end`）だった。両方で `child.stdin` の `error` を拾い、`runSubprocess` では無視して終了コードを `close` で見る（`reject` にすると `git init` などの成功が失敗扱いになる）
- `pnpm run test` を10回続けて回し、未処理の EPIPE は0回（`architecture.test.ts` の時間切れと `cli.test.ts` の揺れは T-774・T-776 の範囲で出た）
- 振り返り: 同じファイルを3回以上直した（ドラフト 0件）

## 目的

`pnpm run check` の中で `test/server/achievement/adapter/main-history.test.ts` がときどき未処理の `EPIPE` を出して落ちる揺れを消す（振り返り: T-750）。

## 完了条件

- 子プロセスが stdin を読む前に終わっても、`runGitCatFileBatch` の stdin への書き込みの失敗が未処理のエラーにならない（`kind: "failed"` などの既存の結果に畳む）
- `pnpm run test` を10回続けて回し、未処理の `EPIPE` が1度も出ない（回数と結果を `## 結果` に書く）
- `pnpm run check` が通る
- 調べて EPIPE の出どころが `runGitCatFileBatch` でないと分かったら、出どころを `## 結果` に書き、そこを直す（直せなければ理由を書いて `dropped` で閉じてよい）

## 背景

- `src/server/repository/adapter/git.ts` の `runGitCatFileBatch` は 108〜109行目で `child.stdin.write(...)`・`child.stdin.end()` を呼ぶが、`child.stdin` の `error` を拾っていない。`child` の `error` と `close` だけを見ている
- `src/server/achievement/adapter/main-history.ts` が `runGit`・`runGitCatFileBatch` を使う
- T-750 の受け入れで、2718 件すべて pass のまま「main ブランチが無いリポジトリでは「不明」」の直後に未処理の `EPIPE`（`child.stdin.end` への書き込み）が1件出て `check` が落ち、打ち直すと通った。T-750 は `src/browser` だけを触っていた
- 既存の揺れのタスク（T-671・T-739・T-774）はこのファイルを扱っていない

## 注意

- 揺れのまとめのタスク（Vitest の並列化で増えた揺れを10回で確かめる側）がこのタスクに依存している。ここでは EPIPE だけを直す

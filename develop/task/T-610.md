## 目的

`color: var(--ink-quiet)`・`font-size: var(--font-secondary)` / `var(--font-label)` のような「文字の段と色だけ」の規則が各機能の CSS に散っている。文字の部品を作って大きさ・色（静か・強調・状態）を variant で表し、まず `components/domain/` と `features/` から置き換える。空の表示（「まだ何もない」の一文）もここに寄せる。

## 完了条件

- `docs/design.md` 2章「`components/ui/` の部品（variant の作法と一覧）」の一覧どおりの `Text`（`element`・`size`・`tone`・`weight`・`className`。props はすべて必須）が `src/browser/components/ui/text/text.tsx`・`text.module.css` にある。size・tone・weight の対応表は `satisfies Record<合併型, string | undefined>` で検査し、**見出しの部品（T-609）が同じ表を読めるように置く**（`ui/text/` の中。形は実装で決めてよいが、表は1つ）。既定の `margin: 0` は `:where()` に書く。`test/browser/components/ui/text/text.test.tsx` に、軸ごとのすべての値 → 付く class、`"inherit"` で class が付かないこと、`element` → 描く要素、`className` が足されることのテストがある
- `src/browser/components/domain/` と `src/browser/features/` で、**字の段・色・太さ（と `margin`・文字の組み）だけを持つ規則が付いた `<p>` / `<span>`** が `Text` に置き換わり、規則が消えている（`margin` と文字の組み——1行で切る・字間・桁揃え・書体——は `className` に残す）。計画時の実測で対象になるのは、空の表示（`.task-empty` ×5・`.sidebar-empty` ×2・`.screen-nav-work-empty`）、`.task-run-question`、`.task-ready` / `.task-blocked`、`.protocol-mismatch-title`、`.screen-nav-work-failure-mark`、`<p>` に付いた見出し風の字（`.screen-nav-work-heading`・`.screen-nav-work-full-heading` など・`.screen-nav-settings-heading` ×4）
- **置き換えないもの**: 表のセル・行・リストの項目に付く状態の色（`domain/task-status.ts` が選ぶ `.task-status-*`、`.task-board-row.task-done`、`.screen-nav-work-step-done` / `-failed`。要素が `<td>` / `<li>` で、`Text` を挟むと DOM が1段増える）。ほかに残したものがあれば理由を結果に1行ずつ書く
- `Text` を読むのが2つ以上の領域・機能になっている（`test/architecture.test.ts`「browser/ の機能をまたぐ箱」が通る）
- `test/architecture.test.ts`「components/ui/ の部品の className」が `Text` を対象にして通る（検査がまだ無ければこのタスクで足す。足し方は T-607 の完了条件と同じ）
- `docs/design.md` 6.1「部品の置き場」の段落に `<Text>` を足してある
- 置き換えた画面（サイドバー・画面のナビの帯の「いまの作業」と設定の歯車・タスクの一覧と表・実行の確認・版違いの知らせ）を起動して目視し、字の大きさ・色・太さ・間隔が置き換え前と同じであることを確かめている（何を見たかを結果に書く）
- `bun run check` が通る

## 背景

- 計画時の実測（2026-09-25）で、字の段と色（と太さ・`margin: 0`）しか持たない単独の class の規則は 68（`page/` 52・`features/` 10・`domain/` 6）。うち 17 は `--usage-*` の色（トークン消費の画面）
- 色のトークンは `src/browser/styles/theme.css` の `--ink` / `--ink-quiet` / `--accent` / `--state-ok` / `--state-warn` / `--state-ng` / `--state-ask`
- `.sidebar-block p { margin: 0.2rem 0 }` のような親からの要素の選択子は `:where()` の既定より強いので、置き換えても効き続ける
- `components/page/` の置き換えは後段（T-611）が受け持つ
- 作法は `docs/design.md` 2章「`components/ui/` の部品（variant の作法と一覧）」が正典

## 決まっていること（蒸し返さない）

- 語彙は size（`--font-*` の6段 + `inherit`）・tone（`ink` / `ink-quiet` / `accent` / `state-*` + `inherit`）・weight（`normal` / `semibold` / `bold` + `inherit`）の3軸。書体（等幅・明朝）は語彙に入れず `className` で渡す
- **見た目を変えない。** 太さの 600 と 700 は分けたまま
- `element` は `"p" | "span"` から始め、要るものが出たらテストの行と一緒に足す（汎用の `as` は持たない）

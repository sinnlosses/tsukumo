## 背景

`develop/progress.md` は「未解決」14.5k字と「注意」23.9k字（登録時点で計86項目）を持ち、共通の規則が「未解決・注意は移さない」なので減らない。セッションを始めるたびに読まれる。新しい運用では `progress.md` をなくし、知見は done の前に正典かタスクへ置く。承認済みの方針は `docs/history/direction.md` の 2026-09-24 の「タスク運用の作り直し」の項にある（1件1ファイル・着手の印は共有の `.git` の中・完了は作業のコミットに同梱して rebase → ff-only で1回送る・錠の中で採番・`progress.md` をなくす・登録は粗く着手時に確かめ直す・手順は `task` コマンドに）。

## やること

1. 項目を1つずつ今のコードとドキュメントに照らし、次のどれかに振り分ける: 人の判断待ち → `hold` のタスク（`task new`）/ 直すもの → `todo` のタスク / 長く効く知見 → 正典（`docs/architecture.md`「既知の制約」、`docs/workflow.md`、`docs/coding-standards.md` など該当する節）/ すでに解消・古い → 捨てる
2. `develop/progress.md` を消す。`scripts/merge-progress.ts`・`scripts/progress-done-section.ts`・それらのテストとフィクスチャ（`test/scripts/merge-progress-git.test.ts`・`test/scripts/progress-done-section.test.ts`・`test/fixture/progress-doc.ts`）・`.gitattributes` の `merge=progress` の行を消す。`CLAUDE.md` のマージドライバの登録手順を消す
3. `grep -rn 'progress.md' CLAUDE.md docs src scripts test`（`docs/history/` を除く）で残る参照を直す

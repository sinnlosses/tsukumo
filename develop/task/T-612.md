## 目的

ボタンの見た目（枠だけ・塗り・地なし・リンク風・危険）が十数通り手書きされ、中身が同一の規則まである。ボタンの部品を作って顔と大きさ・押された状態を variant で表し、まず `components/domain/`・`features/`・`components/ui/` から置き換える。

## 完了条件

- T-606 が `docs/design.md` 2章に書いた作法どおりのボタンの部品が `src/browser/components/ui/<部品>/`（T-616 の形）にあり、`test/browser/components/ui/` に variant → class、`disabled` / `aria-pressed`、押したときの呼び先のテストがある
- `src/browser/components/domain/`・`src/browser/features/`・`src/browser/components/ui/image-zoom.tsx` の `<button>` のうち、ボタンの見た目だけを持つものが部品に置き換わり、規則が消えている。残したものは理由を結果に1行ずつ書く
- 置き換えた画面（サイドバー・画面のナビの帯・タスクの一覧と表と実行の確認・画像の拡大）を起動して目視し、押す前・hover・focus-visible・押せないときの見た目を確かめている（何を見たかを結果に書く）
- `bun run check` が通る

## 背景

- 計画時の実測で `<button>` は 41ファイル92箇所、`cursor: pointer` の規則は 23ファイル74
- `features/task-board/task-board.module.css` の `.task-board-close` と `components/ui/image-zoom.module.css` の `.image-zoom-close` は中身が同一（`padding: 0.2rem 0.6rem; border: 1px solid var(--rule); border-radius: 0.4rem; background: none; font-size: var(--font-secondary)`、hover で `border-color: var(--accent)`）
- ほかの顔の例（`page/` 側。後段が受け持つ）: `.character-button` / `.character-button-danger`、`.character-link-button`、`.diary-book-review-button`（accent の塗り）、`.achievement-review-button`（accent の枠）、`.screen-nav-chat-mode-button`（`aria-pressed`）、`.turn-nav-button`（四角のアイコン）
- 押せないときの書き方が `:disabled` と `[aria-disabled="true"]` の2通りある（11ファイル29箇所）

## 解くべき論点

- **Text と Heading の境目**: 見出しは `<h1>`〜`<h4>` の意味（文書の構造）と見た目の大きさが一致しない箇所がある（例: `.character-section-heading` は `--font-body`、`.step-heading` は `--font-label`）。level と size を別の props にするか、level から size を決めるか
- **Stack の粒度**: `Stack`（direction を props）1つか、`HStack` / `VStack` の2つか。gap の値を段（トークン）に丸めるか、数値を受けるか（いまは `0.2rem`〜`0.75rem` 程度がばらばらに書かれている）。**段に丸めると見た目が少しずつ変わる**ので、許すかどうか
- **表示の小さな差をどこまで吸収するか**: ボタンの高さ（`30px` / `34px` / `2.25rem` / `2.5rem` / `2.75rem`）や角丸（`0.4rem` / `0.5rem` / `0.5625rem` / `8px`）は画面ごとに違う。size の段に寄せて揃えるか、画面固有の見た目は各機能の CSS に残すか
- **Markdown から出るレポートの印**（`report-notation.module.css` の `.report-badge-*` など）は unified が生む HTML に当たる class で、React の部品ではない。Badge の対象に入れるか外すか
- **ダイアログの形**: `useModalDialog`（`src/browser/hooks/use-modal-dialog.ts`）を包む `<Dialog>` を作るか。背景を暗くするもの／透明にするもの（`.character-clear-confirm::backdrop`）、中央／位置指定（`portrait-clear-confirm.tsx` の inline style）を variant にするか
- **Card / Surface（地の段 ground / surface / surface-raised）と Disclosure（`<details>`、4箇所）** を候補に入れるか
- **「読み手が1つだけのものは機能の中へ下ろす」との兼ね合い**: `test/architecture.test.ts` の「browser/ の機能をまたぐ箱」は、`components/ui/` のファイルを読むのが1つの機能だけなら落とす。作り始めの段（読み手がまだ1機能）に部品が落ちないか、読み手が1つしかない汎用部品（Dialog の置き方の variant など）を ui/ に置いてよいかを決める
- `components/ui/` は `stores` を読めない（`test/architecture.test.ts`）。部品は値と呼び先を全部 props で受け取る、の原則を崩さない形になっているか

## 目的

新しい中身の無い `report` と、それに付く締めの「書いたぞ」の `speak` が画面に並ばないようにする。締めの `speak` は、そのターンで新しいレポートを渡したときにだけ付ける。

## 完了条件

- `REPORT_NOTATION_PROMPT` の「ターンは `report` → 締めの `speak` の順で終える」の条が、`report` を呼ぶターンの終え方として書かれている。伝える新しい事実が無いターンは、`report` も締めの `speak` も呼ばずに終えてよいと読める
- 新しい事実の無い `report` を、機械で差し戻す仕組みが `ReportReview` にある。何を「新しい事実が無い」とみなすかは下の論点で決め、テストで固定する
- `persona.md`「締めのセリフの言い方」（同梱パック）と `docs/display.md` が新しい条と食い違っていない
- `bun run check` が通る

## 背景

- 2026-09-26 の T-708・T-709 の委譲中に、「T-709 はまだ作業中です。」のような結論だけの `report` と、締めの「書いたぞ」がターンごとに出て、吹き出しに十数個並んだ
- 今の `ReportReview` が差し戻すのは、同じターンの中で同じ引数の `report` を送り直したときだけ（`isSameReport`）。ターンをまたいだ言い直しや、1語違いの言い直しは素通りする
- `Stop` の関所（`createReportGate`）は1行以下の本文を通すので、何も書かずに終えるターンは今でも通る
- 待機中に話す契機の側は、T-720 が扱う

## 解くべき論点

- 「新しい事実が無い」を何で判定するか。候補: 直前の `report` から今の `report` までに、`speak` と `report` 以外のツールの結果も、サブエージェントの合図も届いていない / 直前のレポートと `conclusion` が一致する / その両方。ヒューリスティック（文面の近さ）より、ターンの中で起きたことで決める機械的な判定を優先する
- 差し戻しの文面で、何も書かずに終えてよいことを伝えるか（差し戻されたモデルが、別の言い回しの `report` で押し切らないように）

## 注意

- 差し戻しは利用者の画面に出ない。差し戻しの文面にモデルの本文を写さない（`REPORT_RESEND_REJECTION_TEXT` と同じ線）
- 本当に新しい事実のある途中の `report`（中間レポート）を落とさない

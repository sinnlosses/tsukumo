## 目的

新しい中身の無い `report` と、それに付く締めの「書いたぞ」の `speak` が画面に並ばないようにする。締めの `speak` は、そのターンで新しいレポートを渡したときにだけ付ける。

## 完了条件

- `REPORT_NOTATION_PROMPT` の「ターンは `report` → 締めの `speak` の順で終える」の条が、`report` を呼ぶターンの終え方として書かれている。伝える新しい事実が無いターンは、`report` も締めの `speak` も呼ばずに終えてよいと読める
- 新しい事実の無い `report` を、機械で差し戻す仕組みが `ReportReview` にある。何を「新しい事実が無い」とみなすかは下の論点で決め、テストで固定する
- `persona.md`「締めのセリフの言い方」（同梱パック）と `docs/display.md` が新しい条と食い違っていない
- `bun run check` が通る

## 背景

- 2026-09-26 の T-708・T-709 の委譲中に、「T-709 はまだ作業中です。」のような結論だけの `report` と、締めの「書いたぞ」がターンごとに出て、吹き出しに十数個並んだ
- 今の `ReportReview` が差し戻すのは、同じターンの中で同じ引数の `report` を送り直したときだけ（`isSameReport`）。ターンをまたいだ言い直しや、1語違いの言い直しは素通りする
- `Stop` の関所（`createReportGate`）は1行以下の本文を通すので、何も書かずに終えるターンは今でも通る
- 待機中に話す契機の側は、T-720 が扱う

## 解くべき論点

- 「新しい事実が無い」を何で判定するか。候補: 直前の `report` から今の `report` までに、`speak` と `report` 以外のツールの結果も、サブエージェントの合図も届いていない / 直前のレポートと `conclusion` が一致する / その両方。ヒューリスティック（文面の近さ）より、ターンの中で起きたことで決める機械的な判定を優先する
- 差し戻しの文面で、何も書かずに終えてよいことを伝えるか（差し戻されたモデルが、別の言い回しの `report` で押し切らないように）

## やること

いまのコードで確かめた前提:

- `ReportReview` の `pass` に届くのはメインの SDK 由来のイベントだけ。本物の駆動では `request` / `turn-started` は `pass` を通らずに流れる（疑似セッションの駆動は通している）
- `speak` は `tool-started` を出さないが、その `tool_result` は `tool-finished` として `pass` に届く。`report` の `tool-finished` は預かった `report` と突き合わせて消える
- 背景のタスクが終わると `background-tasks-changed`（顔ぶれから消える）がターンの外で届き、そのあと `init`（`session-info`）で続きのターンが始まる（`docs/history/decision.md` の実測）。サブエージェントの `SendMessage` や `task_notification` そのものは変換していない
- 2026-09-26 の事象は、サブエージェントの合図で claude が自分で始めたターン（ツールを呼ばない）ごとに `report` と締めの `speak` が出たもの

決めた判定（「新しい事実が無い」）:

- 直前に描いた `report` のあと、次の3つのどれも届いていなければ、その `report` を差し戻す。(1) 利用者からの依頼（`request` / `turn-started`）、(2) メインが呼んだ `speak` / `report` 以外のツールの結果（`pass` が見た `tool-started` と同じ id の `tool-finished`）、(3) 背景のタスクの終わり（`background-tasks-changed` で前の顔ぶれから消えた id）
- ターンの区切りでは戻さない（背景のタスクの終わりはターンの外で届くため、ターンをまたいで持つ）。候補のうち「`conclusion` が一致する」は採らない。1語違いの言い直しを拾えず、文面の近さに寄せるとヒューリスティックになる。サブエージェントの `SendMessage` の合図は事実の入力に数えない。合図は `speak` で言い直すもので（`SPEECH_CADENCE_PROMPT`）、今回の事象そのものだから
- サブエージェントの合図の到着は、いまのサーバからは見えない。`SendMessage({ to: "main" })` は SDK の型の上では `origin: { kind: "peer", senderTaskId }` の付いた `user` メッセージとして載りうるが、流れに出るかを実測しておらず、変換もしていない（`toSessionEvents` は `user` の `tool_result` だけを拾う）。見えるのは合図で始まったターンの頭の `init` だけで、これは依頼で始まったターンと見分けが付かない（`request` はそこを通らない）。実測していない形を判定の根拠にしない
- そのため、合図のあとの `report` は、そのターンでツールを呼んでいなければ差し戻す。落ちるのは「合図の1行を言い直しただけの `report`」で、これは `speak` の担当（`SPEECH_CADENCE_PROMPT`）。合図のあとにモデルがツールで確かめた（タスクファイルを読む・`TaskOutput` を引くなど）なら (2) で通り、委譲が終わったときの結果は (3) で通る。差し戻しは1ターンに1回なので、それでも送り直した `report` は通る（本当に新しい事実のある中間レポートが二度は落ちない）
- 差し戻しは送り直し・規約違反とは別の枠で1ターンに1回まで（2回目は通す）。判定の順は送り直し → 新しい事実 → 規約違反
- 本物の駆動の `request` / `turn-started` も `ReportReview.pass` に通す（疑似セッションと同じ形にそろえる）

差し戻しの文面:

- 何も書かずに終えてよいことを伝え、言い回しを変えた `report` で送り直さないよう言う。固定の文面で、モデルの本文も画面の状態も写さない
- `Stop` の関所の `REPORT_GATE_AFTER_REPORT_REASON` の「レポートに無い事実を足すときだけ `report`」を、「レポートのあとに届いたツールの結果で分かった事実」に絞り、差し戻しと食い違わないようにする

ほかに直すもの: `REPORT_NOTATION_PROMPT` の締めの条（`report` を呼ぶターンの終え方として書き、新しい事実が無ければどちらも呼ばずに終えてよいと足す）、`docs/display.md`「出力の分離（セリフと詳細）」の差し戻しの説明。同梱パックの `persona.md`「締めのセリフの言い方」は「締めの `speak` はレポートを渡したあとに言う」で新しい条と食い違わないので直さない。

## 注意

- 差し戻しは利用者の画面に出ない。差し戻しの文面にモデルの本文を写さない（`REPORT_RESEND_REJECTION_TEXT` と同じ線）
- 本当に新しい事実のある途中の `report`（中間レポート）を落とさない

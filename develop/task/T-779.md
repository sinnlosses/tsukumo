## 目的

振り返りで拾う引っかかりを、決まった小さな札の語彙と1行の書式で書き留められるようにする。後段（委譲先の friction log・「運良く助かった」の兆候・札の繰り返しを数える・人の差し戻しを拾う）がすべてこの語彙と書式を使うので、先に1か所で決める。

  - Friction log（Google の DevRel 発）: 作業の流れに沿って引っかかりをその場で書き、赤（諦めかけた）・黄（手間取った）・緑（うまくいった）で色分けする
  - 開発者とエージェントのずれの分類（arXiv 2605.29442、20,574 セッション）: S1 診断違い / S2 意図の読み違い / S3 制約違反（最多38%）/ S4 頼まれていない拡張 / S5 実装の誤り / S6 操作の誤り / S7 自己申告の不正確さ
  - Blameless postmortem の「Where we got lucky」（Google SRE）
  - Feedback flywheel（martinfowler.com）: 信号を文脈・指示・手順・失敗に分けて行き先を決め、繰り返したものだけを昇格させる
- いまの `retrospect` の兆候は手数の数（打ち直し・同じファイル・エラー）が中心で、何のずれかという分類が無い。「1件だけ振り返る」の表と、手順3の表の2つがある

- T-762 が `retrospect` の材料（`scan.py`・`material.py`）を Beads の `bd history`・notes・comments へ移している。その結果の上で書く

## 解くべき論点

- S1〜S7 だけで足りるか。エージェントのずれではない摩擦（環境・揺れ・正典の不足・道具の不具合）の札をいくつ足すか。語彙は小さく保つ（繰り返しを数えられる粒度）
- 色（赤・黄・緑）を札と別の軸で持つか。緑（うまくいった）は「うまくいったは書かない」いまの物差しとぶつかるので、持つなら何に使うかを決める
- 札の定義を置く1か所（`retrospect` か `task-workflow` か）。`next-task` の依頼文からも引ける場所にする

## やること

- 前提の確かめ（claude-skills の main `8add707`）: 兆候の表は2つ（手順3と「1件だけ振り返る」）で合っている。T-762 の結果（`scan.py`・`material.py` が Beads の `bd history`・comments・notes を読む）も入っている。ドラフトの1件の形は `## 背景` の `- **<何を変えるか>**` ではなく、af0a736 で `develop/draft/` の1件1ファイルの `# <何を変えるか>（振り返り: T-XXX）` に変わっていた（前提が古い。見出しに `（振り返り: T-XXX）` が付く点は同じなので、作業は要る）
- 論点への答え
  - 札は10個。S1〜S7 を `診断違い`・`意図の読み違い`・`制約違反`・`頼まれていない拡張`・`実装の誤り`・`操作の誤り`・`自己申告の不正確さ` の語で持ち、エージェントの外の摩擦に `正典の不備`・`揺れ`・`道具` の3つだけを足す（環境の故障と道具の不具合は直す先が同じなので `道具` に畳む）。両方に当たるときは直す先が決まるほうを選ぶ
  - 色は札と別の軸（どれだけ響いたか）で、`赤`（止まった・人に預けた・壊れたまま進みかけた）と `黄`（その場で戻せた）の2段だけ。緑は持たない（「うまくいった」は次に振る舞いを変えず、物差しで落ちる）。`赤` は1件でも物差しにかける
  - 定義は `retrospect` の SKILL.md の新しい節「札と1行の書式」の1か所。`/next-task` は手順6aで既にこの SKILL.md を読んでいるので、依頼文からも同じ節を指せる。`task-workflow` の WORKFLOW.md「指示メモ」はドラフトの形に `- 札:` の行があることだけを書いて節を指す
- 1行の書式: `- <色> <札>: <何が起きたか（1文）>（<根拠の場所>）`。ドラフトは見出しの下に `- 札: <色> <札>` を1行だけ持つ（札が2つ要るなら別の話としてファイルを分ける。承認後も `docs/history/direction.md` に中身ごと移るので、T-782 はそこから数えられる）
- 兆候の表2つに「札の候補」の列を足す
- T-780〜T-783 の本文を、決めた語と節の名前に合わせて直す

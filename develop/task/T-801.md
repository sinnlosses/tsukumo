## 目的

レポートの中の、利用者が写してよそへ渡す前提の文章（デザインの依頼文・コミットメッセージの案・コマンドなど）を、選んでコピーする手間なしにクリック1つでクリップボードへ写せるようにする（2026-09-27 ユーザーの指示。デザインの依頼文を `code` の塊で出したとき、写すのにドラッグで選ぶ必要があった）。

## 完了条件

- 写して使う前提の塊に、クリックで全文をクリップボードへ写すボタンが出る。写したことが目で分かる（ボタンの文字が短いあいだ「コピーした」に変わる、など）。写した文字は塊の中身そのまま（行番号・ファイル名の見出し・ボタンの文字を含まない）
- モデルが「写して使う文章」をその塊で出すように、記法の条（`REPORT_NOTATION_PROMPT`）と `report` の塊の説明（`src/server/report/core/report-tool.ts`）を直している
- `docs/display.md` の塊の仕様に反映している
- E2E か単体テストで、ボタンが出ることと写す中身を守っている（クリップボードの API は偽物に差し替えてよい）
- `pnpm run check` が通る

## 背景

- 塊の型は `src/shared/report-block.ts`（`codeBlockSchema` など）。塊は Markdown に組み立ててから描かれ、描き手は `src/browser/components/page/conversation/components/main-view/markdown/`（`markdown.tsx`・`sanitize-schema.ts`・`code-file-name.ts`）
- いま `src/` にクリップボードへ写す仕組みは無い（貼り付けの受け口 `use-prompt-image.ts` だけ）
- tsukumo は `127.0.0.1` で配るので、`navigator.clipboard.writeText` は安全な文脈として使える見込み（確かめていない）

## 解くべき論点

- 口の形: (a) すべての `code` の塊にコピーのボタンを付ける、(b) `code` の塊に「写して使う」を示す欄を足す、(c) 新しい塊（例: `copy`）を足す。モデルが選び分ける手間と、画面の騒がしさ（コードの抜粋すべてにボタンが出る）で比べる
- 写して使う文章が地の文（Markdown）のときは、描いた見た目ではなく元の Markdown を写すか

## 注意

- 描く前のサニタイズ（`sanitize-schema.ts`）でボタンや `data-*` の属性が落ちないようにする。落ちる形なら、Markdown の外（React の部品）で包む
- 書き上げる演出（筆）が塊の中身を後から伸ばすので、写す中身は描き終えた全文になるようにする

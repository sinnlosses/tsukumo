## 目的

入力欄から「利用上限が近い」を消し、サイドバーのコンテキストの行の下に5時間枠と週の利用枠を出す。再読み込みのボタンを添える（2026-09-27 ユーザーの指示）。

## 完了条件

- 入力欄の経過時間の行に「利用上限が近い」が出ない
- サイドバーのコンテキストの行の下に、5時間枠と週の枠の状態が出て、再読み込みのボタンで取り直せる（出どころと出し方は前段の設計に従う）
- 画面の流れを E2E で守り、見た目を目で確かめて結果の節に書く
- `pnpm run check` が通る

## 決まっていること（蒸し返さない）

- 利用枠の出どころに、SDK の実験中の口 `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET` を使ってよい（2026-09-27 ユーザー決定）
- サイドバーの利用枠の札の見た目は、ユーザーがデザインを用意する（2026-09-27 ユーザー決定）。届くまで `hold` にしておく
- 札のデザインは `/Users/sinnlos/Downloads/サイドバーの「利用枠」の札 — 5つの状態と寸法-html/QUOTA-Sidebar.dc.html` に従う（2026-09-27 ユーザー決定）。状態は「ふだん」「高いとき（80% 以上）」「取得中（前の値あり／開いた直後）」「取れない（API キー／失敗）」「狭いとき（サイドバー 280px 未満で棒を畳む）」、寸法・色・ふるまいはファイル末尾の「寸法」「色」「ふるまい」の欄が正。値はインラインの `style` と `<helmet><style>` にある（`support.js`・`vendor/` は描画用で設計ではない）

## 背景

- 出どころと出し方は前段が決めた（`docs/research/plan-usage.md`。正典は `docs/display.md` 4.2「各表示物」のサイドバー・入力欄、`docs/requirements.md` 4.1、`docs/glossary.md`「利用上限」「利用枠」）。要点:
  - 出どころは SDK の `Query.usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET({ skipBehaviors: true })`（戻り値 `SDKControlGetUsageResponse`）。読むのは `rate_limits.five_hour` / `seven_day` の `utilization`（0〜100）と `resets_at`（ISO 8601）、`rate_limits_available` だけ
  - 再読み込みはこの口を呼び直す。取り直す契機は開いたとき・ターンが終わるたび・ボタンだけ（時計で回さない）
  - 入力欄から消すのは「利用上限が近い」（`warning`）だけで、「利用上限に達した」（`rejected`）は残す。`RateLimit` から `warning` を外し、`allowed_warning` は `clear` に畳む
- 経路はコンテキストの内訳と同じ形で足す（前例: `src/server/session-driver/adapter/sdk-context-usage.ts` → `SessionDriver.readContextUsage` → `SessionManager.readContextUsage` → `src/server/context-usage/adapter/context-usage-procedure.ts` と `src/shared/contract/context-usage.ts` → `src/browser/domain/context-usage.ts` の `useContextUsage`）。対応表は `docs/research/plan-usage.md`「論点2」
- 入力欄の知らせは `useTurnStatus` の `turnStatusNotice`（`src/browser/components/page/conversation/components/dispatch/components/turn-status/hooks/use-turn-status.ts`）。`warning` の読み手はここだけ
- `allowed_warning` を `RateLimit` に写しているのは `src/server/session-driver/core/sdk-message.ts` の `toRateLimit`、型と説明は `src/shared/rate-limit.ts`
- サイドバーのコンテキストの行は `src/browser/components/domain/sidebar/context-usage-row.tsx`
- 見た目の正典 `docs/screen-design.md`「使用量の行」と「何を外すか」の結びの一文（「下端の帯に残るのはいまのコンテキストの使用量の札だけ」）はまだ利用枠の札を書いていない

## 解くべき論点

- 届いたデザイン（「決まっていること」）の寸法・色・ふるまいを `docs/screen-design.md`「使用量の行」に写してから実装に着手する。デザインの外にある判断（取った時刻の書式など）はデザインの見本に合わせる

## 注意

- 口は実験中の名前なので、呼ぶのは `sdk-` で始まるアダプタ1本に閉じ、戻り値は zod で確かめて、読めない・落ちた・`rate_limits_available: false` は「取れない」に畳む（例外を外へ出さない）
- `skipBehaviors: true` を必ず渡す（渡さないと本体が手元の transcript を7日ぶん走査する。`docs/coding-standards.md`「会話内容の扱い」）
- 認証情報を読んで `/api/oauth/usage` を直接呼ぶ形にはしない（要承認。`docs/research/plan-usage.md`「採らない」）
- 偽の駆動（`fake-driver.ts`）には固定の値を返す口を足し、E2E はそれで流れを守る。本物の値（claude.ai の契約で取れること・単位が百分率であること）は起こした tsukumo で1回確かめて結果に書く
- 前段で確かめたのは型と同梱の本体の中身までで、生きたセッションでは呼んでいない
- 札の形（行の並び・再読み込みのボタン・取った時刻・取れないときの一言）を決めたら `docs/screen-design.md`「使用量の行」に書き、「何を外すか」の結びの一文も直す

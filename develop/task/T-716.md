## 目的

T-667 では、`test/browser/features/task-board/` の単体テストのうち「いまの E2E がすでに守っているもの」だけを消す。そのとき
「E2E に操作や材料を足せば守れるが、いまは守っていない」ために残るテストが出る。T-666 のあとの
T-714・T-715 と同じく、そうしたテストについて E2E の側を強化し、単体テストを消す。

## 完了条件

- T-667 の監査のあとに残った `test/browser/features/task-board/` の単体テストを見直し、E2E を強化すれば届くものを洗い出している
  （T-667 の結果に候補が書かれていればそれを出発点にする）
- 届くものについて、`test/e2e/` のシナリオに操作・材料・場面を足し、結果を DOM の写しかメッセージの列の
  期待値で固定している
- その E2E が守る単体テストを消している（本番コードに1行の変異を入れて、足した E2E が落ちることを
  確かめてから消す）。消した1件ごとに、どの E2E が守るかをタスクの結果に書いている
- 本番コード（fake driver など）を変えないと届かないもの、`docs/coding-standards.md`「消すかどうか」表の
  「残す」行、`docs/design.md` 10章「E2E に任せず単体テストに残すもの」に当たるものは残し、理由を結果に書く
- テストコードの足し算だけで消せるものが1件も無ければ、作業せず `dropped` で閉じてよい
- 消す前後のテスト件数と `bun run check` の所要時間を結果に書く
- `bun run check` が通る

## 背景

- E2E の足場 `test/e2e/scenario-run.ts` でできること:
  - `room.page`（Playwright）でクリックや選択ができる（`test/e2e/permission-answer.test.ts`）
  - 一時のホーム（`TSUKUMO_HOME`）と cwd に材料を書ける（`test/e2e/task-list.test.ts` は cwd に `git init` する）
  - 疑似セッションの場面は `test/fixture/fake-session.json` に足せる
- DOM の写し（`DOM_TREE_SCRIPT`）に残るのは `role`・`data-*`・`aria-*`・`disabled`・`value`・`open`・`href`・img の `alt`/`src`。
  class・`title`・`<select>` の選択肢は残らない。送った RPC はメッセージの列に `"sent": "<procedure>"` として残る
- fake driver が固定しているもの（本番コードを変えないと動かせない）: セッション一覧は常に空
  （`src/session-start.ts` の `listPackSessions`。`canResume` が偽）、コンテキストの使用量は61%
  （`src/server/session-driver/adapter/fake-driver.ts` の `FAKE_CONTEXT_USAGE`）
- 判定の規則は `docs/coding-standards.md`「消すかどうか」の表と「E2E の台本が通している、とは」

## 注意

- E2E のシナリオは1本あたり数秒かかる。消える単体テストが1〜2件しかないのにシナリオを1本足す、
  といった釣り合わない強化はしない（既存のシナリオに手順を足せる場合はそちらを優先する）
- 変異を入れて確かめるときは、退避したコピーから戻す（`git checkout --` で戻さない）
- 期待値は `bun run test:e2e:update` で書き直し、差分を読んで意図した変化だけかを確かめる
- サブエージェントの中では別のエージェント（fork を含む）を立てず、レーンを順に自分で読む

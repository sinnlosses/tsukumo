## 背景

- `token-usage-diet` スキル（`~/.claude/skills/token-usage-diet/`。`SKILL.md` と `scripts/summarize_usage.py`）は tsukumo の使用量の記録（`$TSUKUMO_HOME` の `token-usage/` と `context-usage/`）を集計して、減らし方を提案する。見積もりの割合の分母は `costUsd`（期間の費用。無いときだけ `cacheReadTokens`。`SKILL.md` の見積もりの節の `denominator`）で、提案の文面も「約 N トークン・約 $X、期間の費用の約 P%」と費用で言う
- 利用者の契約は Claude Max 20x（サブスクリプション）で、ドルは API の単価で換算した目安にすぎない。減らしたいのは利用枠を食うトークンの消費量
- 2026-09-24 に `/claude-api cost-optimize`（Claude API のアプリ向けの費用削減の手順）をこのリポジトリに当てた。そこで diet に無い分析として出てきたもの:
  - 種類別の内訳（キャッシュ読み 66%・出力と思考 17%・キャッシュ作成 14%。**ドルで割った数**）
  - モデルの単価の違い（Opus 5 → Opus 5.5 でキャッシュ読みの単価が下がった分）。diet は `model-choice` を「持ち場ごとのモデルの内訳が記録に無い」として見積もっていない（`summarize_usage.py` の `not_estimated`）が、`totals.by_model` にはモデル別の数がある
  - 歩数の見積もり（記録に残らない `speak` だけの歩が、1歩ごとに文脈を丸ごと読み直す）
  - 無料の削り方とトレードオフ（effort・モデル）の区別、見送った候補とその理由
- 見直しの結果は `mcp__tsukumo__usage_review_result` でトークン消費の画面の提案の札に渡る（`SKILL.md` 7章。提案の型は効きめ・見出し・根拠・やること）

## 決まっていること（蒸し返さない）

- 費用ではなくトークン消費量で考える。そのうえで、cost-optimize が出していた分析がトークンの物差しでも使えるかを1つずつ判断して、使えるものだけ取り入れる（2026-09-24 ユーザー決定）
- diet の集計と見直しの画面（提案の札）は残す

## 解くべき論点

- 物差しにする「トークン消費量」の定義。種類（入力・キャッシュ読み・キャッシュ作成・出力・思考）をそのまま足すのか、重みを付けるのか。**サブスクリプションの利用枠が種類ごとにどう数えられるかは公開されていない**ので、確かめられないことは確かめていないと書き、重みを推測で置かない
- 割合の分母を `costUsd` からトークンへ替えたとき、効きめ（大・中・小）のしきい値と、画面の提案の札の文面（「約 $X」）をどう変えるか
- cost-optimize 由来の4つ（種類別の内訳・モデルと effort・歩数・無料とトレードオフの区別と見送りの一覧）それぞれが、トークンの物差しで意味を持つか。例: モデルの単価の違いはトークンの数を変えないので、トークンで考えると効きが消える可能性がある
- 取り入れたものを `SKILL.md` の「4. 何を候補にするか」とスクリプトの `--json` の形のどちらに置くか（画面の提案の型を変えずに済むか）

## やること

1. 上の論点を決め、`SKILL.md` とスクリプトを直す。取り入れないと判断したものは、その理由を `SKILL.md` に1行ずつ残す
2. スクリプトの出力の形を変えたら、それを読む画面側（`src/browser/features/token-usage/` と `usage_review_result` の検証）が壊れないことを確かめる。直す必要があれば直す
3. 手元の記録でスクリプトを走らせ、トークンで言い直した見積もりが出ることを確かめる

### 調べ直した前提（2026-09-25）

- 前提は崩れていない。`summarize_usage.py` の分母は `estimate_denominator` で `costUsd`（無いときだけ `cacheReadTokens`）、各件は `estimatedCostUsd` を持ち、並べ替え（`top_items`）も費用で行っている。単価は `unit_prices` が記録から最小二乗で逆算している。`SKILL.md` の3章の文面は「約 N トークン・約 $X、期間の費用の約 P%」のまま
- **リポジトリ側はスクリプトの `--json` を読んでいない。** `src/` に `estimates` / `sharePct` / `estimatedCostUsd` を読むコードは無い。画面に届くのは `usage_review_result` の引数（`kind` / `target` / `impact` / `title` / `basis` / `action` / `followUp`。`src/shared/usage-review.ts`、検証は `src/server/core/usage-review-tool.ts` と `src/server/adapter/sdk-tool.ts`）だけで、`basis` は自由文、費用の欄は無い。**`kind` を増やさなければ画面側は直さずに済む**
- 思考は出力に含まれる（`src/shared/token-usage.ts` の `StepTokenUsage` の注記）。消費量を足すときに思考を足すと二重になる
- 手元の直近7日（4日ぶん・1369ターン）で、種類ごとの数の比はキャッシュ読みが約98%。費用では約2/3だったので、分母をトークンに替えると同じ提案の割合は約1.5倍に出る
- `main` の歩（ステップ）は assistant のメッセージごとに数えている（`src/server/core/token-usage.ts`）ので `speak` だけの歩も歩数に入っているが、どの歩が `speak` だけかは記録に無い（`speak` は `tools[]` に残らない）

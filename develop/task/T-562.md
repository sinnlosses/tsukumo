## 目的

成果の画面の「小さな驚き」に出す、その日の卒業（登録から日が経って done になったタスク）と節目（通算 N 件目のタスク、N コミット目）を tsukumo が数える。

## 完了条件

- その日に done になったタスクのうち、**新形式（`develop/task/`）で登録したもの**について、ファイルが初めて `main` に入ったコミットの日付から「登録から N 日」を出せる。旧形式（`tasks.json` 時代）のタスクと、**形式の切り替えのコミット（`develop/tasks.json` を消したコミット）で入ったファイル**は卒業に出さない（`docs/requirements.md` 4.11「卒業と節目」）
- **`develop/task/` から消えたファイルを、消える直前の版で読んで数える**（その日の終えたタスクにも通算の件数にも入る。`docs/requirements.md` 4.11「`done` になった日」）。`task prune` で同じ日のうちに消されたタスクが漏れないことをテストで確かめてある
- 卒業とみなす日数の下限と、節目の刻み（タスクの件数・コミット数）、何件目がどれかの決め方は `docs/requirements.md` 4.11「卒業と節目」の仮の値に従う
- 読み方は `docs/design.md`「成果の集め方と配り方」の手順6・7のとおり（タスクファイルの出入りは `git log` 1回、消えたファイルの親の版は切り口の `git cat-file --batch` に混ぜる、通算のコミットの数は今日以外を覚える）
- 結果が `DailyAchievement` の `graduations` / `milestones` に載り、ブラウザが受け取れる
- `bun run check` が通る

## 背景

- 1日ぶんの集計は `src/server/adapter/main-history.ts` の `readAchievement`、型と依頼文は `src/shared/achievement.ts`
- タスクファイルの置き場は `develop/task/T-xxx.md`（done のあと `docs/history/tasks.md` へアーカイブされることがある。アーカイブ後も登録日が取れるかは調べる）

## 目的

成果の画面の「小さな驚き」に出す、その日の卒業（登録から日が経って done になったタスク）と節目（通算 N 件目のタスク、N コミット目）を tsukumo が数える。

## 完了条件

- その日に done になったタスクのうち、**新形式（`develop/task/`）で登録したもの**について、ファイルが初めて `main` に入ったコミットの日付から「登録から N 日」を出せる。旧形式（`tasks.json` 時代）のタスクと、**形式の切り替えのコミット（`develop/tasks.json` を消したコミット）で入ったファイル**は卒業に出さない（`docs/requirements.md` 4.11「卒業と節目」）
- **`develop/task/` から消えたファイルを、消える直前の版で読んで数える**（その日の終えたタスクにも通算の件数にも入る。`docs/requirements.md` 4.11「`done` になった日」）。`task prune` で同じ日のうちに消されたタスクが漏れないことをテストで確かめてある
- 卒業とみなす日数の下限と、節目の刻み（タスクの件数・コミット数）、何件目がどれかの決め方は `docs/requirements.md` 4.11「卒業と節目」の仮の値に従う
- 読み方は `docs/design.md`「成果の集め方と配り方」の手順6・7のとおり（タスクファイルの出入りは `git log` 1回、消えたファイルの親の版は切り口の `git cat-file --batch` に混ぜる、通算のコミットの数は今日以外を覚える）
- 結果が `DailyAchievement` の `graduations` / `milestones` に載り、ブラウザが受け取れる
- `bun run check` が通る

## 背景

- 1日ぶんの集計は `src/server/adapter/main-history.ts` の `readAchievement`、型と依頼文は `src/shared/achievement.ts`
- タスクファイルの置き場は `develop/task/T-xxx.md`（done のあと `docs/history/tasks.md` へアーカイブされることがある。アーカイブ後も登録日が取れるかは調べる）

## やること

前提を調べ直した結果（2026-09-25）: T-561（`docs/design.md`「成果の集め方と配り方」手順6・7と
`docs/requirements.md` 4.11「卒業と節目」）は済んでいるが、**コードは手順6・7を何も実装していない**
（`src/server/core/achievement.ts` は登録日・消えたファイル・通算の数のどれも扱わず、
`src/server/adapter/main-history.ts` も `develop/task/` の出入りを読んでいない。
`src/shared/achievement.ts` の `DailyAchievement` にも `graduations` / `milestones` が無い）。
前提は崩れていないので、以下を実装する。

- `src/server/core/achievement.ts`:
  - `TaskFileHistoryCommit`（`localDateKey` 込み）と `DeletedTaskFile` の型を足す
  - `taskRegistrationDates`: ファイルごとの登録日（最古の `A`）の表。`develop/tasks.json` の
    `D` を含むコミットで入ったファイルは表に入れない
  - `deletedDoneTaskSummariesBefore`: 消えたファイルのうち、指定した時刻より前に消え、消える
    直前の版が `status: done` のものを id → summary で返す
  - 上を `doneTaskSummaries` の結果と足し合わせて「その日の終えたタスク」「通算のタスクの数」の
    両方に混ぜる（`unionDoneMaps`）
  - `graduationsOf`: 登録から7日（仮の下限）以上のものを登録日の古い順で返す
  - `taskMilestoneOf` / `commitMilestoneOf`: 250件・1,000件（仮の刻み）をその日にまたいだかを
    判定し、またいだ最大の1つだけを返す（何件目がどのタスク／時刻かも一緒に返す）
- `src/server/adapter/main-history.ts`:
  - `git log H --first-parent --format=... --name-status -- develop/task/ develop/tasks.json` を
    1回起こしてタスクファイルの出入りを読む
  - 消えたファイルの消える直前の版（`<コミット>^:<パス>`）を1回の `git cat-file --batch` で読む
  - `git log H --no-merges --until=<end> --format=... --name-only` を1回起こし、通算のコミットの
    数（`start` までと `end` まで）を出す。**今日以外を覚える仕組み（暦と共有する入れ物）は
    このタスクの範囲外**（`docs/design.md` の「覚える」は暦（T-563）の話で、1日ぶんの応答は
    リクエストごとに数え直してよい。値は毎回同じになるので描画に影響しない）
  - 上を `readAchievement` に組み込み、`DailyAchievement` の `graduations` / `milestones` を返す
- `src/server/adapter/local-time.ts`: 節目のコミット時刻を `HH:MM`（ローカル時刻）で出す関数を足す
  （時計・OSのタイムゾーンを読む場所をこのファイルに保つ。既存の `localTimeAt` を使う）
- `src/shared/achievement.ts`: `AchievementGraduation` / `AchievementMilestone` の型と、
  `DailyAchievement` の `known` に `graduations` / `milestones` を足し、zod のスキーマも合わせる。
  **振り返りの依頼文（`achievementReviewRequestText`）は変えない**（T-565 に回す。上の「注意」）
- テスト: `test/server/core/achievement.test.ts`・`test/server/adapter/main-history.test.ts`・
  `test/shared/achievement.test.ts` に、登録日・消えたファイル・卒業・節目（タスク・コミット）の
  ケースを足す。**`develop/task/` から同じ日のうちに消えた（=剪定された）タスクが、その日の
  終えたタスク・卒業・通算の件数のどれからも漏れないケース**を1つ用意する（完了条件の
  「`task prune` で…漏れない」はこのテストで満たす。`task prune` コマンド自体は T-560 が別に持つ
  ので、ここでは「ファイルが消えた」状態を git 操作で直接作って確かめる）

## 注意

- 振り返りの依頼文へ卒業と節目を載せるのは T-565（依頼文を作り直して改名する）に回す。このタスクは数えて応答に載せるまで

- 通算の件数の数え方（アーカイブ済みを含めるか）で迷ったら、T-561 の `docs/requirements.md` 4.11 に従い、書かれていなければ仮に決めて `docs/requirements.md` に書き足す

## 結果

- 検証コマンド: 2332 pass / 0 fail（+47）
- 通算のコミットの数の「今日以外を覚える」はまだ無く、応答ごとに数え直す（`main` で 0.2 秒ほど）。入れ物は暦と共有する形で足す（T-563 の注意に書き足し、`docs/design.md` 手順7にも明記）。消えたファイルの親の版は、切り口の読みとは別の1回の `git cat-file --batch` で読む形にし、手順6の書き方をこちらに合わせた
- `bun test` は `TZ` を UTC にするので、`main-history.test.ts` のコミット日時を `+09:00` 固定で組むと日の境目がずれる。`Temporal.Now.timeZoneId()` 基準で組む形に直した

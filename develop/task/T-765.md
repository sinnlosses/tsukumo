## 目的

T-705 で `report` の引数を `sections` に替えたら、実物の `tools/list` が返す `inputSchema` が 1198 → 5086 字になり、`REPORT_NOTATION_PROMPT` の縮み（−1565）と差し引きで毎ターン +2323 字重くなった。押し上げている2つ（`.readonly()` が出す `readOnly: true` と、塊ごとに繰り返し展開される `fold` の説明）を削り、ツールの定義を軽くする。

## 完了条件

- 実物の `tools/list` が返す `report` の `inputSchema` に `readOnly` が出ない
- `fold` の説明文が `inputSchema` の JSON に1回だけ現れる（または塊ごとの説明から外して、説明を1か所に寄せる）
- `inputSchema` の字数が 5086 字から減り、`docs/display.md` 4.2 の「ツールの定義の重さ」の表を取り直した値にする（測った日付も直す）
- `src/shared/report-block.ts` の型（`z.infer` で得る読み取り専用の配列など）がブラウザ・サーバ側で今までどおり使える
- `bun run check` が通る

## 背景

- 塊のスキーマは `src/shared/report-block.ts`。12行目で `const fold = z.string().default("").describe("畳むときの見出し（畳んでも結論が通る塊だけ）")` を1度だけ定義し、各塊の `z.object` に `fold,` として並べている（9か所）。JSON Schema に出すと参照ではなく塊ごとに展開され、説明文が繰り返される
- 同じファイルの配列の多く（30・47・49・51・77・128・170行目）に `.readonly()` が付き、JSON Schema に `readOnly: true` として出る。モデルにとって意味の無い字数
- `report` ツールの定義は `src/server/report/core/report-tool.ts`、SDK へ渡すのは `src/server/session-driver/adapter/sdk-tool.ts`
- `docs/display.md` の `### 4.2 表示` の中に「**ツールの定義の重さ**」の表（`report` の `inputSchema` 1198 / 5086、`REPORT_NOTATION_PROMPT` 5334 / 3769、合計）がある

## 注意

- `readOnly` を消すために TypeScript 側の読み取り専用の型まで捨てない。JSON Schema に出すところで落とす・`z.infer` の型に `Readonly` を付ける、など型を保つ手を選ぶ
- 塊ごとに言い分けたい `fold` の説明（`text` の説明で fold に触れている箇所など）は残してよい。削るのは同じ文が繰り返されている分
- T-746・T-747 が同じ `src/shared/report-block.ts` に欄と塊を足す。先に入っていたら、足された分にも同じ手を当てる
- 調べて、SDK が `readOnly` を落とすなどして実物の `tools/list` に既に出ていないと分かれば、その項目は完了条件から外して結果に書く

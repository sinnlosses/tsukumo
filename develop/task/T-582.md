## 目的

T-581 で決めた新しい箱（`components/domain` `components/page` `components/ui`）を検査に載せ、最初の段としていまの共有部品を移す。後ろの段（枠・会話の画面・残りの画面）はこの検査の上で移す。

## 完了条件

- `test/architecture.test.ts` が `docs/design.md` 2章「いまの `src/browser/` から移す先（移行の対応表）」の段1の行のとおりになっている: 箱の一覧が `components/page` `components/domain` `components/ui` を含み（古い `components` の箱は無い）、辺が2章の箱の表と一致する。**移行の途中だけ `features` → `components/domain` の辺を許し**、そのことがコメントに書かれている
- 領域と置かれる機能の一覧が**パスで引く形**になっている（まだ `features/` にある10の領域も `features/<名前>` のパスで載っている）。一覧に無いディレクトリが `features/` と `components/domain/` の直下・`components/page/` の下にあれば `throw` する
- 「1つの領域（機能）だけが読むファイル」の検査が `browser/lib/` `browser/domain/` に加えて `components/domain/` の直下と `components/ui/` にも掛かっている
- 対応表の段1の6部品（と `.module.css`）が表どおり `components/ui/`（`select` `image-zoom`）と `components/domain/`（`portrait` `character-face` `prompt-image` `protocol-mismatch`）にある。`browser/hooks/` は動かさない。対応するテストも `test/browser/` の同じ相対パスへ移っている
- 移したファイルを読む import がすべて新しいパスを指し、古い `src/browser/components/` 直下にファイルが残っていない。移したパスを指す記述（`docs/` の `history/` 以外・`CLAUDE.md`・`src/` と `test/` のコメント。`src/server/adapter/server.ts` を含む）が新しいパスになっている
- `bun run check` が通る。`bun run build` が通る

## 背景

- 検査は `test/architecture.test.ts` の `BROWSER_BOXES` / `ALLOWED_BROWSER_BOX_IMPORTS` / `browserBoxOf`（未知のディレクトリは `throw`）と、`features/` の横の辺の `BROWSER_REGIONS` / `BROWSER_PLACED_FEATURES` / `browserFeatureOf`、`browser/lib/` と `browser/domain/` の読み手の検査（`SHARED_BROWSER_BOXES`）
- いまの `src/browser/components/`: `select.tsx` `image-zoom.tsx` `portrait.tsx` `character-face.tsx` `prompt-image.tsx` `protocol-mismatch.tsx`（`character-face` 以外は `.module.css` を持つ）。`image-zoom.tsx` を読むのは `prompt-image.tsx` だけ（共有の部品からの読み手なので、読み手の検査では対象外になる）
- 移す先・箱の辺・段ごとの検査の直し方の正典は `docs/design.md` 2章の対応表と箱の表（T-581 が書いた）。後ろの段（枠・会話の画面・残りの画面）は領域の一覧のパスを直すだけで済むように、この段で検査の形を作る

## 目的

E2E（`report-main-view`・`turn-flow` など）がときどき `settledDom` の「DOM が落ち着かない」で落ちる揺れの原因を突き止めて直し、`pnpm run check` の打ち直しを要らなくする。

## 完了条件

- 揺れの原因を、落ちた回に何が動き続けていたか（落ち着かなかった DOM の差分）を根拠にして特定し、`## 結果` に書いている
- 原因を直して、`pnpm run test:e2e` を続けて10回流しても「DOM が落ち着かない」で落ちない
- `/next-task` の委譲の依頼文に「検証を打ち直して通ったことも friction log に `揺れ` の札で書く」を足すかを決め、足すなら `~/.claude/skills/next-task/SKILL.md` を直している（足さないなら、その理由を結果に書く）
- `pnpm run check` が通る
- 10回流しても再現せず、原因を当てられなければ、再現しなかったことを書いて `dropped` で閉じてよい

## 背景

- T-732 の委譲先の1回目の `pnpm run check` で落ち、単独で打ち直したときと2回目の check では通った。T-732 は import のパスを移しただけで、振る舞いは変えていない
- 「DOM が落ち着かない」を投げているのは `test/e2e/scenario-run.ts` の `settledDom`（`SETTLE_INTERVAL_MS * SETTLE_ATTEMPTS` の間に DOM が止まらないと投げる）
- 2026-09-27 の plan-tasks の `task ship` の検証でも `turn-flow.test.ts` が同じ「DOM が落ち着かない（5000ms）」で落ちた（単独では5回とも通過）。出るのは全件を並べて負荷が掛かったときだけ
- 委譲先は揺れたことを friction log に書かず、「なし」と報告していた

## 完了条件

- 揺れの原因を、落ちた回に何が動き続けていたか（落ち着かなかった DOM の差分）を根拠にして特定し、`## 結果` に書いている
- 原因を直して、`pnpm run test:e2e` を続けて10回流しても「DOM が落ち着かない」で落ちない
- `/next-task` の委譲の依頼文に「検証を打ち直して通ったことも friction log に `揺れ` の札で書く」を足すかを決め、足すなら `~/.claude/skills/next-task/SKILL.md` を直している（足さないなら、その理由を結果に書く）
- `pnpm run check` が通る
- 10回流しても再現せず、原因を当てられなければ、再現しなかったことを書いて `dropped` で閉じてよい

## やること

- 前提の確認: `test/e2e/scenario-run.ts` の `settledDom` は実在し、記述どおり
  `SETTLE_INTERVAL_MS * SETTLE_ATTEMPTS` の間 DOM が2回連続で同じにならないと投げる。前提は
  合っていた
- `diagnosing-bugs` の方針どおり、理論より先に再現ループを作る: `pnpm run test:e2e` を
  CPU 負荷（`yes` の多重起動・実物の `pnpm run check` の並行実行）の下で複数回・複数並列で
  流し、実際に落ちた回の「最後の2回の DOM の差分」を機械的に取れるようにする
- 原因1（本命）: `src/server/session-driver/adapter/fake-driver.ts` の `play()` が、疑似
  セッションの手をシーン開始からの絶対時刻 `setTimeout(startMs + step.afterMs)` で一括登録して
  いた。この tsukumo プロセスが OS から長く CPU をもらえないと、複数の手の絶対時刻が同時に
  期限切れになり、再開した瞬間にまとめて（バーストで）発火する——手のあいだの間隔が消え、
  `waitForEvent` が意図した手より先まで進んだ状態を捉える（`final-report-label` で実際に
  再現・確認）。直しは、次の手の `setTimeout` を前の手が実際に発火したあとに差分の ms で
  登録する鎖状のスケジューリングに変更（同じ `afterMs` の手は `setTimeout` を挟まずその場で
  続けて流す）
- 原因2（別系統・低頻度）: `aria-busy` で機械的に待っている本物のネットワーク往復
  （`readContextUsage` など）が、同じ機械の負荷でまれに `SETTLE_ATTEMPTS` の予算を超える
  （負荷下で2回、DOM の差分が無いまま予算を使い切って投げたのを確認）。待ち方自体は
  design.md の意図どおり正しいので、予算を実測の根拠（2回とも「差分なし」で予算を使い切って
  投げた）を添えて3倍（5000ms→15000ms）に広げた
- `settledDom` が投げるときに最後の2回の DOM 差分を `outDir/<scenario>.settle-diff.txt` に
  常設で残す診断を追加（変わり続けた属性・文字のパスだけ、1件80文字に絞る）
- 検証: typecheck/lint/format:check/単体テスト全部/`fake-driver.test.ts`/`pnpm run check`
  （単独）が通ることを確認したうえで、`pnpm run test:e2e` を実物の `pnpm run check` の並行
  実行（3並列）と一緒に10回連続で流し、10回とも成功した

## 注意

- `~/.claude/skills/` は全プロジェクトで共有されている。スキルを直すなら、`docs/workflow.md` にあるスキルの直し方に従う
- 同じ系統の揺れを T-795（`speak-bubble`）が扱っている。原因が共通だと分かったら、そちらと突き合わせる

## 結果

- 原因: 疑似セッション（`fake-driver.ts` の `play()`）が手を開始からの絶対時刻でまとめて `setTimeout` しており、CPU を奪われたあとに期限切れの手がまとめて発火していた。もう一つの原因は、`aria-busy` が待つ本物の往復が負荷の下で 5000ms を超えたこと。前者は手を鎖にして登録する形に直し、後者は待ちの上限を 15000ms に広げた。落ち着かずに投げた回は `settle-diff.txt` に DOM の差分が残る
- 検証コマンド: 単体 2743 pass・E2E 31 pass。委譲先が `pnpm run check` 3本と並べて `pnpm run test:e2e` を10回続けて流し、10回とも通過
- next-task の依頼文: 「打ち直して通ったことも `揺れ` で書く」を足すべきと判断したが、共有のスキルなのでユーザーの判断に預けた
- 振り返り: 受け入れのときにメインが直したもの（引数の Map を書き換える作りと、経緯を書いたコメント。既存のドラフトが扱っているのでドラフト 0件）

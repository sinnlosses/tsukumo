## 目的

見本 SEIKA-4 の (c) 書き終わり の場面を作り、振り返りのあいだに別の画面へ移っていても、ページができたことが分かるようにする。

## 完了条件

- `SessionState.diaryWriting` が `written` になったら「<日付>のページができました」の知らせが出て、「日記帳で開く」でその日の見開きが開き、× で消える
- 出す画面と消え方は `docs/screen-design.md` 13.10「書き終わりの知らせ」の仮決めのとおり（どの画面でも出す。×・開く・次の振り返り・起こし直しで消え、時間では消えない。消したかどうかはタブのメモリにだけ持つ）
- 部品の振る舞いのテストがあり、`bun run check` が通る
- 目視確認（(c) の場面）を結果に書く

## 背景

- 見本は `docs/history/mockup/achievement-diary-2026-09-25/SEIKA-4c-Written.dc.html`（画面の下の中央に浮く札）
- 画面をまたぐ知らせの部品はまだ無い。見開きは T-567 の部品を開く

## やること

**前提を調べ直した結果**: `SessionState.diaryWriting`（`shared/diary.ts`）は
`idle → writing → written/failed` を辿り、**`written`/`failed` は次の `diary-requested` まで
保持される**（`session-state.ts`）。つまり「次の振り返りを押す」「起こし直す」の2つは、知らせの側で
何もしなくても `diaryWriting.kind` が `written` から外れることで自然に消える。知らせが自分で
持つ必要があるのは「×」「日記帳で開く」による**この起動の間だけの既読**（タブのメモリ）だけ。

日記帳の見開き（`features/achievement/hooks/use-diary-book.ts` の `useDiaryBook`）は
`achievement-screen.tsx` からしか呼ばれておらず、`main.tsx` の `OVERLAY_SCREEN` の仕組み上
**成果の画面を離れると丸ごとアンマウントされる**。知らせは「どの画面でも出す」必要があるので、
見開きを成果の画面の外からも開ける形にする必要がある。

**判断（見開きをどこから開くか）**: 見開き本体（`useDiaryBook` の状態と `<DiaryBook>` の描画）は
`achievement-screen.tsx` に残す（T-567 で「container/presenter の3分割は採らない」と決めた設計を
崩さない）。知らせの「日記帳で開く」は、(1) `selectAchievementDate(date)` で成果の画面のその日へ
遷移し、(2) 新しい小さな信号（`features/achievement/diary-book-request.ts`。module-level の
`useSyncExternalStore`。`stores/question-scroll.tsx` と同じ「一回限りの合図」の形だが、
両方の呼び手が `features/achievement/` の中だけなので `stores/` へは上げない）で「この日を開いて」を
伝える。`useDiaryBook` はこの信号をマウント時と、マウント中の変化の両方で拾い、`BookState` を
`open`（`source: "notice"`）にする（React 公式の「prop の変化に応じて描画中に state を合わせる」
形——比較用の `useState` を1つ持ち、effect は使わない。`docs/coding-standards.md`「useEffect は
4類型だけ」に当てはまらないため）。

**足すもの**:

1. `src/browser/features/achievement/diary-book-request.ts`（新規）: `requestDiaryBookOpen(date)` /
   `useDiaryBookOpenRequest()`
2. `src/browser/features/achievement/hooks/use-diary-book.ts`: `DiaryBookOpenSource` に `"notice"` を
   追加し、`useDiaryBookOpenRequest` を拾って開く
3. `src/browser/features/achievement/diary-notice.tsx` + `hooks/use-diary-notice.ts`（新規）: 画面の
   下中央に浮く札。`session.state.diaryWriting` を読み、`written` のときだけ出す。既読
   （タブのメモリ、モジュール外の React state。リロードで消える）は日付＋書いた時刻をキーにする
4. `src/browser/main.tsx`: `<ScreenNav />` と同じ高さ（`<Activity>` の外）に `<DiaryNotice />` を
   常駐させる（`features/achievement/` から import。入口はどの機能も import してよい役目）
5. `src/browser/utils/month-day-label.ts`（新規）: 「9月23日」の形は
   `use-diary-book.ts`（`monthDayLabel`）・`screen-nav/hooks/use-current-work.ts`
   （`diaryDateLabel`）に private のまま2箇所あり、知らせが3箇所目の読み手になるので
   `docs/design.md`「`lib/` と `utils/` に置く基準」の「2つ目の読み手」に沿って `utils/` へ上げ、
   3箇所とも import に差し替える
6. 灯りの暦の鈴アイコン（`lantern-calendar.tsx` の private `Bell`）を `export` して知らせの鈴にも使う
   （同じ `features/achievement/` の中の共有なので `domain/` へは上げない）

**目視確認の場面**: `test/fixture/fake-session.json` に `diary-requested` →
（`diary-drafting`・`diary-stage` 相当のイベント。実際のイベント名は `shared/frame.ts` /
`session-state.ts` の reducer を見て合わせる）→ `diary-written` 相当を流す場面を1つ足す。中身の
表示も要るので、一時ホームの `achievement/diary/` 相当の下に同じ日付の架空の日記ファイルを1つ
置く（`src/server/adapter/diary.ts` の置き場所の形に合わせる）。

## 結果

- 検証コマンド: 2521 pass / 0 fail（+13）。疑似セッションの場面 `diary-written` を足し、Playwright で会話の画面と成果の画面の両方に知らせが出ること・「日記帳で開く」で見開きが開くこと・× で消えて画面を移っても戻らずリロードで再び出ることを 1400/400px で見た（横スクロールなし）。書き上げの演出の途中は撮れなかった
- 受け入れで直した: 知らせの合図の「拾った」印を部品の state に持っていたため、一度使うと成果の画面を開き直すたびに見開きが開いた。印を React の外に移し、マウントし直しても開かないテストを足した。知らせから見開きを開く経路は `docs/screen-design.md` 13.10 にまだ書いていない
- 振り返り: 受け入れで不具合を直した（ドラフト 1件）

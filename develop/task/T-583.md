## 目的

全画面で共有する枠（レイアウト・画面のナビの帯・サイドバー）を、手本の `components/domain/`（AppHeader・AppLayout の置き場）に合わせて移す。

## 完了条件

- `src/browser/features/layout/` `screen-nav/` `sidebar/` が、`docs/design.md` の対応表の段2の行どおり中身ごと（`hooks/` `components/` `domain/` と `.module.css` を含む。ファイル名は変えない）`components/domain/layout/` `components/domain/screen-nav/` `components/domain/sidebar/` にある。テストも `test/browser/` の同じ相対パスへ移っている
- `test/architecture.test.ts` の領域の一覧の3つのパスが `components/domain/<枠>/` になっている
- 古いディレクトリにファイルが残っていない。`main.tsx` の import が新しいパスを指す。移したパスを指す記述（`docs/` の `history/` 以外・`CLAUDE.md`・`src/` と `test/` のコメント。`src/server/adapter/fake-driver.ts` を含む）が新しいパスになっている
- `bun run check` と `bun run build` が通る。移したあとに画面を1回開き、帯・サイドバー・領域の境目のつまみが以前と同じに見えることを目視で確かめ、何を見たかを結果に書く

## 背景

- `features/layout/`（`layout.tsx` `presentational-layout.tsx` `layout-resizer.tsx` `split.ts` `hooks/use-layout.ts`）、`features/screen-nav/`（`components/` に7部品と `.module.css`、`domain/` に4ラベル、`hooks/` に3本）、`features/sidebar/`（`task-section.tsx` が置かれる機能 `task-board` を import する、唯一の「領域 → 置かれる機能」の辺。移したあとは `components/domain` → `features` の辺で、箱の表が許している）
- 移す先・依存の向きの正典は `docs/design.md` 2章（T-581 が書いた対応表・箱の表・「領域の機能と、置かれる機能」）

## やること

`docs/design.md` 2章の対応表・箱の表・「段と、test/architecture.test.ts の直し方」（T-581 が書いた）を読み直した。段2の行（`features/layout/` → `components/domain/layout/`、`features/screen-nav/` → `components/domain/screen-nav/`、`features/sidebar/` → `components/domain/sidebar/`、いずれも中身ごと）はタスク本文の完了条件と食い違わないので、そのまま作業する。

- **移す（`git mv`）**: `src/browser/features/layout/`（`hooks/use-layout.ts`・`layout-resizer.tsx`・`layout.module.css`・`layout.tsx`・`presentational-layout.tsx`・`split.ts`）→ `src/browser/components/domain/layout/`。`src/browser/features/screen-nav/`（`components/` 7部品＋`.module.css`・`domain/` 4ラベル・`hooks/` 3本・`presentational-screen-nav.tsx`・`screen-nav.module.css`・`screen-nav.tsx`）→ `src/browser/components/domain/screen-nav/`。`src/browser/features/sidebar/`（10ファイル）→ `src/browser/components/domain/sidebar/`。テストも `test/browser/features/layout/` `screen-nav/` `sidebar/` を同じ振り分けで `test/browser/components/domain/layout/` `screen-nav/` `sidebar/` へ
- **`test/architecture.test.ts` を直す**: `BROWSER_REGIONS` の3行を `"features/layout"` → `"components/domain/layout"`、`"features/screen-nav"` → `"components/domain/screen-nav"`、`"features/sidebar"` → `"components/domain/sidebar"` に替える（判定ロジック `browserFeatureOf`・箱の判定 `browserBoxOf` は変えない。移した3領域は `components/domain` という1つの箱に入り、`ALLOWED_BROWSER_BOX_IMPORTS["components/domain"]` が既に `features` を許しているので `sidebar` → `task-board` の辺はそのまま通る）
- **import を直す**: 移した3領域を読んでいる `src/browser/main.tsx` と、移した領域どうし・領域の中の相対 import（深さが変わる分）を新しいパスに合わせる
- **記述を直す**（`docs/` の `history/` 以外・`CLAUDE.md`・`src/` と `test/` のコメント。`src/server/adapter/fake-driver.ts` を含む）: `features/layout` `features/screen-nav` `features/sidebar` への言及を新しいパスに直す。`docs/design.md` 2章の対応表自体は段4が終わるまで「いまのパス」欄を残す設計なので触らない

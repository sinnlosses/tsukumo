## 目的

委譲先のサブエージェントが `report` を呼ぶと、メイン側に新しい事実が無いときに `REPORT_NOTHING_NEW_REJECTION_TEXT`（「何も書かずに終えてよい」）が返り、委譲先の最終報告が短くなる恐れがある。サブエージェントの呼び出しを判定に掛けないようにする。

## 完了条件

- `report` の handler でサブエージェントの呼び出しを見分けられるかを確かめ、見分けられるならサブエージェントの呼び出しは新しい事実の判定（と送り直しの判定）に掛けず "ok" を返す。その挙動を守るテストがある
- 見分けられないと分かったら、確かめた根拠（SDK の handler に届く引数・`tool_use_id` と `parent_tool_use_id` の対応が取れるか）を結果に書き、`report-review.ts` 冒頭の「handler はサブエージェントの呼び出しとメインの呼び出しを見分けられない」の注記に、新しい事実の判定でも同じことが起きる旨を足して閉じてよい
- `bun run check` が通る

## 背景

- `src/server/report/core/report-review.ts` の `createReportReview` が、規約違反・送り直し・新しい事実の無い `report` の3つを差し戻す。判定の窓口は `src/server/session-driver/adapter/sdk-tool.ts` の `reportTool` の handler（`review.judge`）
- 同ファイル冒頭の注記は「MCP の handler に `parent_tool_use_id` は届かない」ので見分けられないとしており、規約違反の差し戻しの1回を失う件だけを書いている。新しい事実の判定で委譲先に「何も書かずに終えてよい」が返る件は書いていない
- T-721 の振り返りで、委譲先の報告が指摘した（未実測）

## 注意

- 見分ける手がかりの候補: handler の第2引数（`extra`）に届くもの、`assistant` メッセージの変換で `parent_tool_use_id` 付きの `report` の `tool_use_id` を先に控えておき handler と突き合わせる形（ただし SDK は handler と `assistant` メッセージの届く順を決めない。`report-review.ts` 冒頭の注記）
- 順序を当てにする形しか無いなら採らず、上の「見分けられない」側で閉じる

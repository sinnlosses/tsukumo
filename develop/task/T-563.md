## 目的

成果の画面の「灯りの暦」（直近5週の日ごとの灯りと日記ありの鈴）に要る数を、開くたびに重くならない形でブラウザへ渡す。

## 完了条件

- 直近5週ぶん（T-561 が決めた範囲）の日ごとの終えたタスクの数とコミットの数を、`git log` 1回（と、タスクの記録を読むのに要る最小の呼び出し）で集める関数がある
- 今日以外の日の数はプロセスの中で覚え、2回目からは取り直さない（今日の分だけ取り直す）ことをテストで確かめてある
- 経路と型（T-561 が `docs/design.md` に書いたもの）でブラウザが受け取れ、読めない形は「取れなかった」に倒れる
- 灯りの段階（灯りなし／ほのか／ともる／明るい）の判定は shared の純粋関数で、区切りの値は T-561 の仮決めに従う
- `bun run check` が通る

## 背景

- いまの1日ぶんの集計は `src/server/adapter/main-history.ts` の `readAchievement`（`git log --since` に7日の余裕、タスクの中身は `git ls-tree` と `git cat-file --batch`）。git の呼び出しは `src/server/adapter/git.ts` の `runGit`
- 経路の先例は `ACHIEVEMENT_PATH`（`src/shared/achievement.ts`、`src/server/adapter/server.ts`）
- 「日記あり」の印は日記の保存（別タスク）ができるまで出せない。この段では数と灯りまででよく、日記ありの欄を型に持つかは T-561 の設計に従う

## 注意

- 会話の中身・コミットの件名は運ばない（`docs/coding-standards.md`「会話内容の扱い」）
- 調べて、いまの `readAchievement` の形では1回にまとめられない事情が見つかったら、その理由を結果の節に書いて最小の呼び出しの数で済ませてよい

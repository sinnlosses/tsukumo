## 目的

CSS の方式を CSS Modules のまま続けるか、Tailwind に移るかを決める。

## 完了条件

- 結論と理由が `docs/design.md` の CSS の方式を扱う節（CSS Modules の決定の近く）に書かれている
- 移るなら、移行のタスクが `task new` で登録されている

## 背景

CSS の方式を検討したとき Tailwind は見送り、先に CSS Modules へ移した（移行は完了済み）。そのとき「CSS Modules で足りたかを見てから決める」として保留にしてあった。採るなら `--ground` / `--surface` / `--ink` / `--accent` と `color-mix` の導出を `@theme` へ移し、`docs/screen-design.md` のデザインのトークン（もとの `docs/design.md` 13章）を書き直すことになる。設計言語そのものの作り替えにあたる。

## 解くべき論点

- CSS Modules に移ったあと、どこで困っているか（困っていなければ見送りで閉じる）
- 追加の npm 依存になるので、入れるなら利用者の承認が要る

## 注意

- 人の判断待ち（`hold`）。困りごとが出るまで動かさない

## 結果

- 利用者の判断（2026-09-24）で CSS Modules のまま続け、Tailwind には移らないと決めた。結論と理由は `docs/design.md` 6.6 CSS に書いた
- 移らないので、移行のタスクは登録していない

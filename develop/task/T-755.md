## 目的

`test/e2e/permission-answer.test.ts` が `bun run check` の中でときどき落ちる。イベントの並びを決まった順にして揺れを無くす。

## 完了条件

- 「許可」を押す前に、並びを競う相手（場面の `speech`）が届くのを待つなどして、押したあとの `pending-changed` と `speech` の順が毎回同じになっている。確かめている内容（押すと answer が流れ、答え待ちの箱が消える）は弱めない
- `bun run test:e2e` を同じテストについて繰り返し（10回以上）走らせて落ちないことを結果に書く
- `bun run check` が通る
- 調べて競う相手が別のものだと分かったら、それに合わせて直してよい。揺れが再現せず正体も確かめられないなら、確かめたことを結果に書いて `dropped` で閉じてよい

## 背景

- 落ち方は `toEqual`（`room.settleAndMatch` の比べ合わせ）。許可を押したときの `pending-changed` と、疑似セッションのシナリオ `permission-answer` の場面 `permission` にある `speech`（`afterMs` 200）が別々のタイマーで競い、並びが入れ替わる（T-672 の委譲先の指摘）
- 疑似セッションの手は `src/server/session-driver/adapter/fake-driver.ts` が場面の始まりからの `afterMs` で流す
- T-672 で E2E の入力欄の場面（`input-dispatch`）に同じ正体の揺れがあり、開幕の一言を待ってから送る形で直した（コミット dbe904b0）

## やること

- `test/e2e/permission-answer.test.ts` に、押す前に場面 `permission` の `speech`（`afterMs`
  200）を待つ行を足す。`opening` 自身が起こした直後に1回 `speech` を流す（`test/fixture/fake-session.json`
  の `opening`）ので、名指しした場面の `speech` は2回目——`waitForEvent("speech")` を素で呼ぶと
  1回目（`opening` の分）で即座に解けてしまい、待ったことにならない。`waitForEvent("speech", 2)`
  で名指しにする
- 待つ行を足すと、押したあとの `pending-changed`（箱が消える）より先に場面の `speech`
  （「許可がほしいところ。答えてみて。」）が記録されるようになり、`messages` の並びが変わる。
  `bun run test:e2e:update` で `test/e2e/expected/permission-answer.messages.json` を書き直し、
  `git diff` で「`speech` が `pending-changed`（空）より前に来ただけ」であることを確かめる
- `bun run test:e2e` の対象テストだけを10回以上繰り返し走らせ、落ちないことを確かめる（T-672 は
  この形で `input-dispatch` を直した。今回は束の切れ目の畳み〔`collapsePartialUtterances`〕は
  要らない——`permission` の場面に `partial-utterance` は無い）

## 結果

- 検証コマンド: 2706 pass / 0 fail、E2E 24 pass / 0 fail。`permission-answer.test.ts` を単体で12回続けて走らせ、12回とも通った
- 揺れの正体は、押して流れる `pending-changed` と場面の `speech`（`afterMs` 200）のタイマーの競り合い。`opening` の一言が1回目なので `waitForEvent("speech", 2)` で待ってから押す
- 振り返り: 受け入れのときにメインが直したもの（テスト冒頭の説明コメントを1行に縮めた）（ドラフト 0件）

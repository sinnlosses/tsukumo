## 目的

質問の回答を選んだあとにメインビューに残る記録で、単一選択も複数選択も同じ `●`/`○` になっていて区別がつかない。複数選択の質問だけ、印を `■`/`□` にする。

## 背景

- 印は `src/browser/features/main-view/presentational-question-record.tsx` の `QuestionMark` が出していて、`chosen` しか受け取らず、常に `●`/`○`
- 記録（`SessionRecord` の `kind: "question"`、`src/shared/session-state.ts`）は `questions: readonly Question[]` を持ち、`Question` には `multiSelect: boolean` がある（`src/shared/question.ts`）。取得側に足すものは無いはず
- 同じ印は、選択肢の行と、折りたたみの中の preview の札（`question-preview-label`）の2か所で使われている
- 色の決まりは `src/browser/features/main-view/question-record.module.css` の `.question-mark`（選んだ側だけ accent。形の違いが選択を運ぶ、`docs/screen-design.md` 13.1 原則5）

## 決まっていること（蒸し返さない）

- 単一選択は `●`/`○` のまま、複数選択は `■`（選んだ）/`□`（選ばなかった）。利用者が選んだ
- 文字は DOM に残す（`::before` に移さない）。色の当て方はいまの `QuestionMark` と同じ

## 完了条件

- 複数選択の質問の記録では、選択肢の行と preview の札の両方で `■`/`□` が出る。単一選択は `●`/`○` のまま
- 単一選択と複数選択で印が変わることを確かめるテストがある
- `bun run check` が通る
- `bun run build` のあと実画面（または疑似セッション）で単一選択と複数選択の記録を1つずつ出し、印を目で見て結果に書く

## やること

前提を確かめ直した結果、記述どおりで着手できる（前提崩れなし）:

- `Question.multiSelect: boolean`（`src/shared/question.ts`）はすでにあり、取得側（`question-answered` イベント → `SessionRecord` の `kind: "question"`）に足すものは無い
- `QuestionMark` は `src/browser/features/main-view/presentational-question-record.tsx` にあり、`AnswerRow`（選択肢の行）と `PreviewBlock`（`question-preview-label` の札）の両方から `chosen` だけ受け取って呼ばれている。現状は `multiSelect` を知らない
- `QuestionRecordQuestionModel`（`hooks/use-question-record.ts`）が問1件ぶんの形で、`answers` / `previews` の行の並びを持つが `multiSelect` は持っていない

変更方針:

1. `hooks/use-question-record.ts`: `QuestionRecordQuestionModel` に `readonly multiSelect: boolean` を足し、`useQuestionRecord` で `question.multiSelect` をそのまま渡す
2. `presentational-question-record.tsx`: `QuestionBlock` が `question.multiSelect` を `AnswerRow` と `PreviewBlock` に渡し、それぞれが `QuestionMark` に渡す。`QuestionMark` は `multiSelect` を受け取り、`multiSelect` なら `■`/`□`、そうでなければ `●`/`○` を出す（色の当て方・`is-chosen` の付け方は変えない）
3. CSS（`question-record.module.css`）は `.question-mark` を文字ではなく class で判定しているので変更不要
4. テスト（`test/browser/features/main-view/question-record.test.tsx`）に、複数選択の質問で `■`/`□` が出る観点を足す（選択肢の行と preview の札の両方）。単一選択が `●`/`○` のままであることは既存のテストがすでに押さえている

## 結果

- 検証コマンド: 2284 pass / 0 fail（+3。既存の複数選択の期待値1件を ■ に更新）
- 目視: 疑似セッション（question-multi / question-pair）を Playwright で答えて、複数選択は「■ A案 □ B案 ■ C案」、単一選択は ●/○ のままを確認。preview の札は場面に無いためテストで代えた

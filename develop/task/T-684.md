## 目的

Bun から Node + Vite + Vitest へ移す5段の3段目。組み立てを Vite に揃え、Vite 前提の道具
（Storybook・React Compiler）を本物と同じ組み立てで使えるようにする。

## 完了条件

- `bun run build`（名前は変えてよい）が `vite build` で `dist/browser/` に JS と CSS を出し、起動した
  tsukumo がそれを配って画面が動く
- CSS Modules の class 名が JS と CSS で同じ綴りに焼かれている（1回の組み立てから出る対）
- `src/server/view-server/adapter/bundle.ts` の `readUiBundle` の「成果物が古ければ知らせる」挙動が保たれている
- `vite` と `@vitejs/plugin-react` が devDependencies に入っている
- `bun run check` が通り、会話の画面でレポート（表・mermaid・Chart.js）が描けることを目で見て確かめている

## 背景

- `src/server/view-server/adapter/bundle.ts`（239行）が `bun build` をプロセスとして起こし、入口
  `src/browser/main.tsx` から JS と CSS を1本ずつ `dist/browser/` に出す。`scripts/build-ui.ts`（20行）が
  その呼び口、`src/server/view-server/adapter/source-fingerprint.ts`（49行）が新しさの比較
- mermaid と Chart.js は `vendor/` から別に配っていて、組み立てには入っていない
- E2E は CSS Modules のハッシュ付きの綴りに頼っていない（2026-09-26 に確かめた）

## 解くべき論点

- 成果物のファイル名と、サーバが `dist/browser/` から読む口の対応（Vite はハッシュ付きの名前を出す）
- `bundle.ts` を Vite の JS API で呼ぶか CLI を起こすか（`adapter/` の1ファイルに閉じ込める原則は保つ）

## やること

前提は今のコードで確かめ直した（2026-09-27）: `bundle.ts` は `bun build` の子プロセスで `main.js` / `main.css` を出し、
`readPair` は `dist/browser/` から拡張子で1本ずつ拾う。サーバは起動時に読んでメモリに持ち、`/assets/ui.js` と
`/assets/style.css` の固定のパスで配る（ファイル名は URL に出ない）。見張り（`ui-rebuild.ts`）は `buildUiBundle` を呼ぶだけ。

- `vite` と `@vitejs/plugin-react` を devDependencies に足し、リポジトリ直下に `vite.config.ts` を置く
  （入口 `main.tsx`、出す名前を `main.js` / `main.css` に固定、`emptyOutDir`、`minify: false`）
- 論点1（ファイル名と読み口）: ハッシュを付けずに名前を固定し、`readPair` は拡張子で探すのをやめてその2つの名前を読む。
  配信の URL は変えない
- 論点2（JS API か CLI か）: CLI を `node` の子プロセスで起こす。JS API は呼んだプロセスの `process.env.NODE_ENV` を
  書き換えるので、常駐するサーバ（見張り）の中で呼ばない。子プロセスは前と同じ `bundle.ts` の1ファイルに閉じる
- `bundleWithBun(entry, outDir)` を `bundleWithVite(sourceDir, outDir)` に替え、失敗の理由から色の制御文字と vite のスタックを落とす
- `bundle.test.ts` を追随させ、CSS の選択子のハッシュ付きの名前が JS の対応表に同じ綴りで入っていることを見る
- `bun build` を指しているコメントと、`docs/design.md` 11章・`docs/architecture.md`・`docs/coding-standards.md` を直し、
  `docs/architecture.md` に決定の節を足す
- 起動した tsukumo（fake の駆動）で会話の画面を開き、表・mermaid・Chart.js が描けることを目で確かめる

## 注意

- 開発中の作り直し（`ui-rebuild.ts`）は4段目で扱う。この段では今の見張りが `vite build` を呼ぶ形で動けばよい

## 結果

- 検証コマンド: 単体 2716 pass / 0 fail、E2E 24 pass / 0 fail
- 出す名前を `main.js` / `main.css` に固定し、`vite` の CLI を `node` の子プロセスで起こす（JS API は `NODE_ENV` をプロセスごと書き換えるため）。React は本番版を束ねるようになり、`main.css` は縮めないので 142KB → 356KB
- 振り返り: 報告に残した気になる点（ドラフト 1件）

## 目的

全幅の入れ物（`.mermaid` / `.chart-block`）に入った図・グラフがある塊では、書き上げる演出の帯が全幅のままになる。中身の `svg` / `canvas` の実際の幅を右端に使って帯を縮めるかを決め、縮めるなら直す。

## 完了条件

- 縮めない結論なら、理由が完了時の結果に書かれている
- 縮めるなら、図・グラフを含む塊で帯の右端が描かれた図の右端になっていることを疑似セッション（`notation` の場面）と `scripts/capture-view.ts --measure` で確かめ、`bun run check` が通る

## 背景

`src/browser/features/main-view/reveal/measure.ts` の `lineBoxesOf` は図・グラフの要素の box をまるごと1行として扱う。要素は `plan.ts` の `FIGURE_SELECTOR` で拾った入れ物なので、mermaid や Chart.js のように全幅の入れ物に入っていると、筆がなぞる幅が 950px 前後のまま残る（筆は実際にその上を通るので誤りではない）。帯の幅を塊の枠ではなく行の右端にそろえた直しのときに、範囲外として残した。

## 決まっていること（蒸し返さない）

- 帯の右端を、描かれた `svg` / `canvas` の右端まで縮める（2026-09-24 ユーザー決定）

## やること

`src/browser/features/main-view/reveal/measure.ts` の `lineBoxesOf` を読み直した結果:

- `kind === "figure"` の分岐は、`shape.member.element`（`plan.ts` の `FIGURE_SELECTOR` で
  拾った入れ物。`.mermaid` / `.mermaid-broken` / `.chart-block` / `canvas` / `svg` / `img`）の
  box をまるごと使っている。mermaid・Chart.js は `<pre class="mermaid">` /
  `<div class="chart-block"><canvas>...` のように**全幅の入れ物の中**に描くので、右端が入れ物の
  幅（950px 前後）のまま残る
- `canvas` / `svg` が直接の要素（入れ物を持たない）場合と、`img` は元から実寸なので今回は
  変えない。直すのは「入れ物の中に描かれた `svg` / `canvas` を持つ」場合だけ
- 直し方: 要素自身が `svg` / `canvas` ならそれ自身、そうでなければ中を `querySelector("svg,
canvas")` で探し、見つかった box を使う（top/bottom も含めてそちらに揃える）。見つからない
  とき（描画前・`mermaid-broken`）は今まで通り入れ物の box に落とす
- 実装は `measure.ts` に閉じる（`plan.ts` の `RevealMember` / `FIGURE_SELECTOR` は変えない）。
  `frameOf`（枠。塊が枠から出ないための落とし先）は今回の対象外——右端は帯（`band.ts`）が
  決めるもので、枠はその上限でしかない

## 注意

- 演出はマウント時の DOM しか見ないので、目視には新しい依頼（か疑似セッションの読み直し）が要る

## 結果

- `reveal/measure.ts` の `lineBoxesOf` で、図・グラフの行の box を入れ物ではなく中に描かれた `svg` / `canvas` から取るようにした（見つからなければ入れ物に落とす）。`measure.test.ts` を新しく足した（6件）
- 疑似セッション `notation` で測った値: `.mermaid` の右端 981.4px に対して中の svg は 233.4px になり、行の右端はこちらを使う。`.chart-block` の canvas は Chart.js が入れ物いっぱいに描く（981.4px）ので差は出ない。帯の右端は同じ帯に入る行のうちいちばん右のものなので、図が表や note と同じ帯に入ると、帯はそちらの幅まで広がったまま
- 検証コマンド: 2284 pass / 0 fail

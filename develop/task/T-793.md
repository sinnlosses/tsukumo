## 目的

E2E が揺れて1回だけ落ちると、打ち直した回が `/tmp/tsukumo-e2e/<シナリオ>/` を上書きし、落ちた回の DOM・メッセージの列・スクリーンショットが消える。揺れの原因を追えるよう、食い違った回の成果物を足場が自動で残す（2026-09-27 ユーザーの指示「E2E の失敗を振り返ってタスク化」）。

## 完了条件

- `test/e2e/scenario-run.ts` の `matchArtifact`（か、その呼び元の `settleAndMatch`）が、期待値と食い違ったときにその回の DOM の構造・メッセージの列・スクリーンショットと、期待値との差分を、あとで通った回に上書きされない場所へ書く
- 落ちたときのエラー文に、残した場所のパスが出る
- 残す場所は `/tmp/tsukumo-e2e/` の下に限り、溜まりすぎない決まり（例: シナリオごとに直近 N 回まで）を決めて書く。名前に時刻を使うなら `Temporal` で取り、`Date` を使わない
- 期待値に合った回の振る舞い（`/tmp/tsukumo-e2e/<シナリオ>/` を毎回書き直す）は変えない
- わざと期待値を1か所変えて落とし、残った成果物と差分・エラー文のパスを確かめて `## 結果` に書く（期待値は戻す）
- `docs/design.md` 10章「E2E の成果物と再現」と、前段で足した「E2E の揺れを生まない書き方」の「成果物を控える」条を、仕組みに合わせて直す（人が控える手順が要らなくなったらその条を縮める）
- `pnpm run check` が通る

## 背景

- `settleAndMatch`（`test/e2e/scenario-run.ts`）は `OUTPUT_ROOT = "/tmp/tsukumo-e2e"` の下の `<シナリオ>/` にスクリーンショットを書き、`matchArtifact` に DOM とメッセージの列を渡している
- 2026-09-27、文書だけの変更の受け入れで `speak-bubble.test.ts` が1件落ち、打ち直し3回は通過した。成果物は上書きされていて原因を控えられなかった
- 成果物には疑似セッションの手書きの会話しか入らない（`docs/design.md` 10章「E2E の成果物と再現」の置き換え）。残す成果物にも同じ置き換えが掛かっていること

## 注意

- 会話の実物は成果物に入らない前提を崩さない（起動トークンと絶対パスは置き換えたまま残す）
- 期待値の更新（`pnpm run test:e2e:update`）の流れで残したものが期待値に混ざらないこと

## 目的

複雑な機能を E2E で確かめ、E2E で置き換えられる低シグナルの単体テストを消す見直し（2026-09-26 にユーザーと合意）の前段として、E2E の形と規約の線を先に決める。削る判定は E2E が何を捕まえるか決まってからでないとできないため、この設計が後段すべての前提になる。

- `bun run check` が通る

## 背景

- 疑似セッション: `src/server/session-driver/adapter/fake-driver.ts` が `test/fixture/fake-session.json` の `turns[].name` の場面（`permission`・`question-*`・`notation`・`narration`・`chat-compact-boundary` など約30）を `TSUKUMO_DRIVER=fake` / `TSUKUMO_FAKE_SCENE` で流す。本物の claude は E2E から起こせないので、E2E が通るのはこの台本だけ
- ブラウザを動かす足場: `playwright-core`（driver だけ、手元の Chrome を `channel: "chrome"` で使う）。`scripts/capture-view.ts`（1枚撮る・要素を測る）と `scripts/capture-catalog.ts`（場面ごとに起こして撮る）がある。どちらも撮るだけで判定はしない
- いまの `bun run check` は `typecheck && lint && format:check && bun test --isolate`。単体テストは 206 ファイル・2705 件で 26 秒（2026-09-26）
- `docs/coding-standards.md`「テスト」節の「消すかどうか」表は回帰テストと書式を固定するテストを残すと決めている。この行は変えない前提で、E2E で置き換えられるものを消す候補に足す
- 隣のタスク: T-634（疑似セッションに場面を足す）、T-632（`bun test --isolate` が終わらないことがある）

## 解くべき論点

- E2E を `bun test --isolate` の中で走らせるか、check の中の別の段にするか（T-632 の症状と、1件ごとにサーバとブラウザを起こす時間）
- DOM の構造のスナップショットに何を残し何を落とすか（クラス名・テキスト・属性のどこまで。落としすぎると捕まえず、残しすぎると見た目の変更で毎回割れる）
- サーバが打つ時刻を固定する口をどこに作るか（原則3。外の世界の値を読む1箇所に注入する）
- SDK のイベントの畳み込み（`test/shared` が中心）は台本に無い並び・未知の `type` を E2E で通せないので、単体テストに残す範囲をどう書くか

## やること

前提を 2026-09-26 のコードで調べ直した結果（前提は崩れていない。作業は要る）:

- 疑似セッションの場面は 28（`turns[].name`）。場面の手は `afterMs` どおり本物の `setTimeout` で流れ、最長は `visit-long-tool` の約 31 秒、`long-tool` 20 秒、`interim-flicker` 19 秒、`background-task` 17 秒。ほかは多くが 1.5 秒以内
- fake driver は `SessionEvent` を直に流す。**SDK のメッセージから `SessionEvent` への写し（`sdk-` のファイル）は E2E を1行も通らない**
- 起こし方: `TSUKUMO_DRIVER=fake`・`TSUKUMO_VIEW_PORT=0`・`TSUKUMO_OPEN_VIEW=0` と、一時の `TSUKUMO_HOME` と一時の cwd（git 管理外）で、URL が出るまで約 110ms（実測）。同梱のパックは tsukumo 自身の場所から解くので cwd に依らない。タスクの一覧は cwd の `main` の `develop/task/` を読むので、一時の cwd では「不明」になる
- 時刻を読む場所: サーバは `src/session-start.ts` の3箇所（`Temporal.Now.instant()`）と `src/server/adapter/local-time.ts`（今日の日付・タイムゾーン）。ブラウザは `src/browser/utils/clock.ts` だけ。**どちらも「そこだけ」を縛る検査は無い**
- Playwright（`playwright-core` 1.63・手元の Chrome）の実測: `page.clock.install({ time })` は `Date.now()` を差し替えるが **`Temporal.Now` は差し替えない**（ページの時計はそのまま進む）。`newContext({ timezoneId })` は `Temporal.Now.timeZoneId()` に効き、`reducedMotion: "reduce"` はレポートの演出（`use-report-reveal.ts`）を切る。子プロセスの `TZ` 環境変数は Bun の `Temporal.Now.timeZoneId()` を決める
- `bun test` はディレクトリを指したとき名前が `*.test.ts` のファイルしか拾わず、`--path-ignore-patterns` で外せる。`bun run build` は即座に終わる程度の時間
- `ServerFrame` の `events` は `batchIntervalMs` ごとに束ねられ、束の切れ目は時間に依る。`hello` には同梱パックの一覧・絶対パス・ポートが入る
- CSS Modules の class 名は組み立てのたびに `名前_ハッシュ` に焼かれる。状態は `data-*`（`data-region`・`data-state`・`data-work-state`・`data-expression` など）に出ているものが多い
- `docs/architecture.md`「手で確かめること」に「質問の場面を Playwright で自動操作すると `turnInProgress` が解けないまま残ることがある」という既知の症状がある
- 「描画は自動テストで守らない」は `docs/coding-standards.md` の節の見出しで、`docs/architecture.md`・`docs/design.md`・同ファイル内から引かれている。`CLAUDE.md` の「ブラウザに出た絵は自動テストで守らない」は `test/browser/components/page/conversation/main-view/question-record.test.tsx` のコメントが引いている

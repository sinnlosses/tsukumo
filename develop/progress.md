### 2026-09-14 レポートの行長の上限を撤去した（T-112）

**T-112 完了。表がつぶれなくなった。** 原因は `.detail-block { max-width: 36.36rem }` が
**子孫すべて**に効くことで、`width: 100%` の表も 581.7px に閉じ込められていた。**ユーザーは
「表・コード・図だけ上限から外し、本文は 42 全角のまま保つ」案ではなく「上限そのものをやめる」
方を選んだ**（1400px の窓で本文の行長が約 67 全角に戻ることを示したうえでの選択）。そのため
`docs/design.md` 13.1 原則4「読む面は行長を測る」と 13.3「行長は 42 全角で切る」は**例外を
足すのではなく撤回**し、理由と日付を残した。

**器だけでは足りず、セルの下限も要った。** 表を `div.table-scroll`（`overflow-x: auto`）で
包む実装だけでは、`width: 100%` の表は列の数だけ縮んで器に収まってしまい、**横スクロールが
一度も働かない**（実測: 12列で最小セル 41px、器の `scrollWidth == clientWidth`）。
`min-width: 4em` を th / td に足して「どのセルも最低4全角は1行で出す」を決め、入りきらない
ぶんだけ器が転がる形にした。**`em` はセル自身の字の大きさ基準で全角の字はちょうど 1em** なので、
px の実測値を持たずに「4全角」と書ける（撤去した 36.36rem のような環境依存の数が増えない）。

器を `src/ui/report/markdown.tsx` の `components` に置いたので、**Markdown の表とレポートが
直接書いた `<table>` の両方に効く**（`rehype-raw` が同じ hast の木に入れるため）。
`sanitize-schema.ts` は触っていない（器は React 側で作られ、サニタイズを通らない）。

### 2026-09-14 キャラクターごとにセッションを持つ（T-109）

**T-109 完了。切り替えても会話が消えなくなった。**

**スパイクで分かったことが、そのまま設計の土台になった。** `resume` したセッションでは
`systemPrompt` の append が**差し替わらない**（新しい人格の絶対命令すら効かず、前の口調が残る）。
最初はこれを「会話を継ぐ案が潰れた」と読んだが、**ユーザーが「キャラクターごとにセッションを
持つ」形を提案してくれて、欠点が利点に反転した** — そのパックのセッションを `resume` すれば、
**そのパックの人格と会話がまとめて戻る**。

実装は思ったより小さかった。`selectSessionToResume(sessions, tag)` が**印を引数で受け取る**形に
なっていたので、印を `tsukumo:<パック名>` にして、起動時も切り替え時も「これから起こすパックの
印」で探すだけ。画面の履歴は移行の段9の `replayRestoredSession` がそのまま使えた。
**会話を tsukumo 側に保存していない**（4.8 の決定は変えていない。claude の transcript を読むだけ）。

ユーザーのもう1つの案「会話の内容を保存してロード」は採らなかった。4.8 が
「復元のために会話を保存しない。キャッシュ・スナップショットは作らない」と決めており、
これは「会話内容の扱い」の「別の場所に複製しない」を満たすための決定だから。
**保存しなくても同じ結果が出る**ので、規約を曲げる必要が無かった。

実機で両方向を確認した。A で1ターン → B へ切替で画面がリセットされ B の口調になる →
**A へ戻ると前の会話が画面に戻り、claude も覚えていて A の口調** → **B へ戻っても B の会話と
口調がそのまま**。`docs/design.md` 7章の「会話は続かない」は、**なぜ変えたのか**（段9で材料が
増え、スパイクで `resume` が人格を保つと分かったこと）を添えて書き直した。

**申し送り**: `startDriver` の戻りが `Promise<SessionDriver>` になった（切り替え先の探索が
非同期のため）。`persona.md` を編集しても既にあるセッションには効かない（`resume` が最初の
append を保つため、新しく起こしたセッションから効く）。ターンを1つも終えずに切り替えると、
そのパックのセッションは次回見つからず新規になる（印はターン終了の3秒後に付く）。

## 目的・背景

行頭の `>` は、キャレットの行では後ろの半角空白まで打ったときに初めて罫だけになり、`>` だけの段階では `>` と罫が並んで見える（`markdown-mark-concealment.ts` の `leadingMarkEnd`）。2026-10-24 の実機の確かめで、利用者から「Slack のように `>` を打った時点で罫にしたい」と要望が出た。

## 決まっていること（蒸し返さない）

- 文面は `> ` のまま持つ（見た目だけ置き換える）
- 対象は行頭の `>` だけ。`-` は `-` 一文字が記号そのものとして打たれやすいので、いまのまま後ろの空白まで打ったときに `•` にする（変えない）
- `>` を打った時点で罫にしたあと、空白を打たずに字が続いた場合も、文面は変えず罫のまま見せる（`>a` は引用として読まれるので矛盾しない）

## 解くべき論点

なし

## やること

### 1. 置き換えの契機を直す
`markdown-mark-concealment.ts` の `leadingMarkEnd` は、`ListMark` と `QuoteMark` の両方から呼ばれ、キャレットが記号に触れていて空白がまだ無いと `undefined` を返す。`QuoteMark` の呼び出し（53行目）だけ、この条件を外して `node.to`（`>` の終わり）までを置き換える。`ListMark`（61行目）は変えない。`leadingMarkEnd` の説明コメントは、`>` と `-` で契機が違うことに合わせて直す。
- 満たす完了条件: 1, 3
### 2. 単体と E2E を直す
`markdown-mark-concealment.test.ts` の、キャレットの行で `>` だけのケースを「罫に置き換わる」に直し、`-` だけのケースは「置き換わらない」ままであることを確かめる。`test/e2e/markdown-composer.test.ts`（120行目の「キャレットの行でも行頭の `- ` `> ` は見た目だけ替わり…」）は、`>` の直後の日本語の変換・確定と Backspace が文面を壊さないことを確かめる形に合わせる。
- 満たす完了条件: 2, 3

## 完了条件

1. 行頭で `>` を打った時点で罫だけに見える（`- ` は後ろの空白を打ったときに `•` になる、いまのまま）
2. 置き換えた形のまま日本語の変換・確定と Backspace が文面を壊さない
3. `pnpm run check` が通る

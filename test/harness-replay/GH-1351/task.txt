## 目的・背景

- 出どころ: GH-1321 の棚卸し（モデルの出力を字面で判定している検査）
- 棚卸しの行（Stop の関所。`src/server/report/core/report-tool.ts` の `ONE_LINE_MAX_CHARS`）: 改行を含むか100字を超える本文を、レポートにすべき本文とみなす。背景の仕事を待つ2行の一言は止められる。逆に100字以内の1行の本文は止められず、画面に出ない（関所の理由文が言うとおり、`report` を通らない本文は画面に出ない）。止めた回数は記録していないので、件数は記録から読めない。方針は構造の印に置き換える: 背景の仕事が走っているかで決め、走っていなければ、`report` の無い本文が1字でもあれば止める
- 出し先: 背景の仕事の有無は、`src/server/report/core/report-review.ts` が background-running の差し戻しに使っている `news.backgroundTasks()` から取れる。関所（`createReportGate`）にその問い合わせを渡す。`src/server/session-driver/adapter/sdk-driver.ts`・`src/server/session-driver/adapter/sdk-query-seed.ts` で関所を組む所も合わせる。100字という閾の根拠だった `docs/research/report-tool-trial.md` の試行（通ってよい1行は64字以下）は、背景の待ちの一言を通すためのものだったので、印に置き換えれば閾は要らなくなる
- 変えるファイル: `src/server/report/core/report-tool.ts`、`src/server/session-driver/adapter/sdk-driver.ts`、`src/server/session-driver/adapter/sdk-query-seed.ts`。止めた回数を診断か使用量の記録に足すかも決める
- GH-1076・GH-1275・GH-993 との重なり: なし（report の schema も差し戻しの条も変えない）

## 決まっていること（蒸し返さない）

- report の schema も差し戻しの条（`CallReview.judgeReport` の判定）も変えない。変えるのは Stop の関所の止める条件だけ

## 解くべき論点

**背景の仕事に、shell だけでなくサブエージェントの委譲も含めるか。** `report-review.ts` の background-running は shell だけを見ている。委譲中の待ちの一言を止めないために、台帳が委譲を数えているかを段1で読んで決め、数えていないなら委譲を足すか今の範囲で済ませるかを報告に理由つきで書く。
**背景の仕事が無いのに、短い一言だけで止まりたい正当な場面が残るか。** 確認の問いかけは `AskUserQuestion` を通る前提だが、通らない場面（例: 許可待ちの直前の一言）が無いかを `sdk-query-seed-stop-hook.test.ts` の既存の場面から読んで決める。

### 2. 関所を背景の仕事の有無で決める
`createReportGate` に「背景の仕事が走っているか」の問い合わせ（`() => boolean`）を渡す。背景の仕事が走っていれば `report` の無い本文を通し、走っていなければ、`report` の無い本文が1字でもあれば止める。`ONE_LINE_MAX_CHARS` と `exceedsOneLine` は消し、`sdk-driver.ts` の組み立てで `callReview` の台帳の `backgroundTasks` から問い合わせを渡す。止めた回数を診断か使用量の記録に足すかは、既存の足跡の置き場（`swallowed-failure` など）を読んで決め、足すなら理由を報告に書く。
- 満たす完了条件: 1, 2, 3
### 3. テストと文書を合わせて検証する
`test/server/report/core/report-tool.test.ts` に、背景の仕事が走っているとき短い本文を通す・走っていなければ短い1行でも止める・`stopHookActive` と `nothingNewRejected` は今のとおり通すことを足す。`sdk-query-seed-stop-hook.test.ts` の「1行以内なら何も返さない」の場面と、`createReportGate` を1引数で呼ぶテストを新しい形に合わせる。`docs/research/report-tool-trial.md` の閾の根拠と `docs/glossary/conversation-tool.md` の関所の説明（「1行を超える本文」）が食い違えば現状に合わせる。検証コマンドを通す。

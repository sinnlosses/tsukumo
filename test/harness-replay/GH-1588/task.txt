## 目的・背景

- 出どころ: 振り返り: GH-1580
- 観点: 赤 機械の検査
- 根拠: GH-1580 は tw 側（STAGE 行の読み取り・台帳の stages・tw metrics）と tsukumo-plugins の check.sh までで、tsukumo の scripts/dev/check.ts は作業先の外のため触っていない。そのため完了条件1の「選ばれたテストが0件の段は unobserved」は、tsukumo の検証ではまだ起きず、台帳の stages は空のまま
- 出し先: scripts/dev/check.ts（段ごとに `STAGE<TAB><段名><TAB>pass|fail|unobserved|blocked` を出す。選ばれたテストが0件の段・飛ばした段は unobserved、ポートの取り合い・E2E の上限は blocked）

## 決まっていること（蒸し返さない）

- 書式は check.sh と同じ `STAGE<TAB><段名><TAB>pass|fail|unobserved|blocked`（`tw verify` が読む。`vendor/tsukumo-plugins/check.sh` の `emit_stages`）。段名は `Stage.name`（`typecheck`・`lint`・`format:check`・`token-limit`・`test`・`test:e2e` など）
- 値の決め方: 走って終了コード0は `pass`、非0は `fail`、`planRerun` が `skip` にした段と、選ばれたテストが0件だった段は `unobserved`、E2E の回数の上限（終了コード2）と `--full` の E2E の錠の待ち切れ（`LockWaitTimeoutError`）は `blocked`
- 行は `check.ts` の標準出力の最後（`describeFailedStages` の行のあと）に、段の順でまとめて出す。途中で止めた段（`stopped`）は `blocked` にしない（`unobserved`）
- tsukumo-plugins 側（`tw verify`・`check.sh`）は変えない

## 解くべき論点

なし

## やること

### 1. 値の決め方を純関数にする
`scripts/dev/lib/` に、段の結果（`BufferedResult` と飛ばしたか）から4値を返す関数を足し、単体テストで4値と境界（0件・終了コード2・錠の待ち切れ・stopped）を確かめる。選ばれたテストの数は、段が書く JSON レポートの総数から読む（`readReport` の延長）。
- 満たす完了条件: 1, 2
### 2. check.ts が STAGE 行を出す
`scripts/dev/check.ts` の `runConcurrently` の出力と、`rerunPlan` で飛ばした段（`skip`）について、段の順に STAGE 行を出す。文書だけの変更の3段でも同じ。
- 満たす完了条件: 1, 3
### 3. 実際に流して確かめる
`tw verify` を打ち、台帳の stages に4値が書かれること（`tw metrics --stages`）を見る。
- 満たす完了条件: 3
### 4. 検証を通す
整形し、`pnpm run check` を通す。
- 満たす完了条件: 4
### 名指すファイル
- `scripts/dev/check.ts`
- `scripts/dev/lib/check-record.ts`（読む）
- `scripts/dev/lib/check-failure.ts`

## 完了条件

1. `pnpm run check` の出力の最後に、走った段・飛ばした段のすべてについて `STAGE<TAB><段名><TAB><値>` の行が1段1行で出る
2. 選ばれたテストが0件の段と、前回通って飛ばした段は `unobserved`、E2E の上限と錠の待ち切れは `blocked` になる（単体テストで確かめる）
3. `tw verify` を実際に打つと台帳の stages に4値が残り、`tw metrics` の `verify_unobserved`・`verify_blocked` で数えられる
4. `pnpm run check` が通る

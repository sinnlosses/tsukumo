## 目的・背景

戦略 3.5.2。Bash の結果を既定200行に切り、全文はファイルに落としてパスを返す。直近28日の委譲先の Bash の結果は探索 114MB・その他 82MB・git 46MB。新しい hook なので log-only で7日走らせてから block に上げる（戦略 3.7.1）。

## 決まっていること（蒸し返さない）

- 新しい hook は log-only で7日走らせ、誤って切る形が無いことを見てから block に上げる
- 切った事実は記録に残す
- Claude Code の PostToolUse は組み込みの Bash の出力を差し替えられない（差し替えられるのは MCP のツールの `updatedMCPToolOutput` だけ）。block の段は PreToolUse の `updatedInput` でコマンドを包み直し、全文を `.tw/local/` の下へ落として先頭200行だけを返す形にする（2026-11-02 に利用者が決定）
- このタスクは段1（log-only）だけで送り出す。block に上げる段は別のタスクに分けた（2026-11-02 に利用者が決定）

## やること

### 1. log-only の hook を足す

- `scripts/hook/` に Bash の PostToolUse の hook を足し、結果が200行を超えた件数と、切ったであろう行数を `hook-denials/` と同じ置き場・同じ流儀（時刻・hook の名前・規則のキー・呼び手・数だけ。コマンドの全文と出力の中身は入れない）で記録する。まだ切らない
- 同じ行に、そのコマンドが PreToolUse で包み直せる形か（heredoc・バックグラウンド・対話を待つコマンドなど包むと壊れる形でないか）の判定を規則のキーとして残す。後続の block の段で、7日分を再生して誤って切る形を見るための材料にする
- `.claude/settings.json` に PostToolUse の Bash の hook を登録する（既存のエントリを壊さず追記）

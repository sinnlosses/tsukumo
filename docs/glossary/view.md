# 用語集: ビューと画面の面

ステータス: **正典**。入口は `docs/glossary.md`（用語集の方針と、子のファイルの一覧）。

責務: ビューと画面（会話の画面・キャラクター画面・メインビュー・キャラビュー・ビューサーバ）と、画面の面や部品（背景のオーバーレイ・画面の頭・引き出し・ボトムシート・サイドシート・一覧モード・タスクの段・探す欄・設定の点）の用語を持つ。
読む時: ビュー・画面・画面の面を指す語の表記に迷ったとき。
直す時: この範囲の用語を足す・識別子を変えるとき（用語はこの子に足し、親には足さない）。

## 表示

### ビュー

- **英語識別子（予定）**: `view`（識別子は `ViewName` = `main` / `character` / `sidebar`）
- **定義**: tsukumo が HTML で組み立て、ホストのブラウザタブに出す表示単位。
  メインビュー・キャラビュー・サイドバーの3つがあり、**入力欄と合わせて1枚のページ**に入る
- **注記**: **表示はすべてビューである**（全 HTML 化した。
  `docs/architecture/adr/0016-html-instead-of-terminal.md`）
- **避ける言い方**: ウィンドウ、パネル。**「画面」はビューの言い換えに使わない**（ページを丸ごと
  使う単位を指す別の語。下記）

### 画面

- **英語識別子**: `screen`（`stores/screen.tsx` の `useScreen()` が返す値は
  `conversation` / `character` / `character-create`）
- **定義**: ページを丸ごと使う表示の単位。**会話の画面**（4つのビューと入力欄）、
  **キャラクター画面**、**作る画面**の3つで、同時に出るのは1つ。切り替えは URL の hash
  （`docs/architecture/screen-design.md` 13.6）
- **注記**: ビューは会話の画面の中の領域で、画面はそれらを入れ替える器。「メイン画面」と
  言いたくなったら、それはメインビューか会話の画面かのどちらか
- **避ける言い方**: ページ（HTML は1枚なので、画面が変わってもページは変わらない）、ルート、タブ

### 機能

- **英語識別子**: `feature`（`src/browser/features/<機能>/`）
- **定義**: tsukumo の語彙1つで閉じた部品・状態の縦切り。置かれる場所を知らずに書く
- **注記**: `shared/` に同じ名前の機能を持つ語彙の塊（`report`）か、2つ以上の枠・画面に置かれるものを機能にする

### キャラクター画面

- **英語識別子**: `character-screen`（`src/browser/components/page/character/`。hash は
  `#character`、一覧で選んだパックは `#character?pack=<名前>`。作る画面は同じ機能の中の
  `character-create`、hash は `#character/new`）
- **定義**: 左にパックの一覧、右に選んでいるパックの立ち絵・差し色・背景を並べ、画面から直す画面。
  使用中以外のパックも直せ、そこから切り替えられる。新しいパックを作る**作る画面**へ入るボタンもここ
  （`docs/architecture/screen-design.md` 13.6）
- **注記**: **会話の画面と入れ替わる**（重ねない）。入るボタンも戻るボタンも全画面の最上部の帯（狭い画面は引き出しの歯車の面と画面の頭の「‹ 会話へ」）
  （`docs/architecture/screen-design.md` 13.9）
- **避ける言い方**: 見た目の引き出し（無くした。いまの「引き出し」は狭い画面の別の面）、設定画面、オプション

### メインビュー

- **英語識別子**: `main`
- **定義**: レイアウトの左上に置く、いちばん広いビュー。**レポートだけ**を出す
- **注記**: **作業の進行はサイドバーへ移した**。1ターン＝1枚で、書きかけの
  本文がリアルタイムに流れる（`docs/architecture/display.md` 4.2）
- **注記**: 以前は「詳細ビュー」と呼んでいた
- **避ける言い方**: 詳細ビュー、詳細ペイン、プレビュー

### キャラビュー

- **英語識別子**: `character`
- **定義**: レイアウトの左下に置くビュー。**立ち絵と席のアイテムだけを置く**（セリフは会話の流れに出る。狭い画面だけ顔と最新の1件の吹き出しを出す）
- **注記**: 許可プロンプトと質問のボタンは**ここには出さない**。メインビューの**お伺い**に出る
  （以前は入力欄の上の箱だった。吹き出しの下に出したときは気づきにくかった）
- **注記**: ターミナルのペインではなく HTML のビュー。**これが決まったことで、端末の画像
  プロトコルが通らない問題は関係なくなった**
- **注記**: **狭い画面（760px 以下）では出さない**。立ち絵の舞台の代わりに、入力欄の上に顔と最新1件の
  吹き出しを出す（`docs/architecture/screen-design.md` 13.9「狭い画面（760px 以下）」）
- **避ける言い方**: キャラペイン、立ち絵ペイン

### ビューサーバ

- **英語識別子**: `view-server`（機能のディレクトリ `src/server/view-server/`）
- **定義**: ビューをブラウザに配るローカルの HTTP サーバ。`127.0.0.1` にだけバインドし、
  ページ・束ねた JS と CSS・同梱物・立ち絵を配り、イベントは WebSocket 1本で流し、
  コマンドは oRPC で受ける（`docs/architecture.md`「動きの流れ」）
- **注記**: **本文をファイルに書き出さない。** 会話の一部を含むため
  （`docs/coding-standards.md`「会話内容の扱い」）
- **避ける言い方**: プレビューサーバ、開発サーバ

### 背景のオーバーレイ

- **英語識別子**: `veil`（`character.json` の `background.veil`。「背景のオーバーレイ」の識別子での名前）
- **定義**: キャラビュー（と雑談中のメインビュー）に敷いた**背景画像の上に1枚かぶせる、
  `ground` 一色の膜**。値はその膜の不透明度で、`0.75` なら画像が見えるのは 25%。DOM の要素では
  なく、`.layout-ground` の `background` に積む2枚目のレイヤ（`linear-gradient()` に `ground` を
  同じ値で2回並べた平らな面）を指す
- **注記**: 画像の明暗によらず地の明るさを `ground` の側へ引き戻すために置く。これがあるので
  画像を `#ffffff` / `#000000` の2点と仮定するだけでコントラストの最悪値を押さえられる。
  **下限は 0.7**（`docs/architecture/screen-design.md` 13.8）。立ち絵より奥にあるので立ち絵は薄くならない
- **避ける言い方**: 覆い（以前の呼び名。別の意味の語にも当たる）、単独の「オーバーレイ」（`screen-design.md` では帯を画面の上に浮かべる部品を指す。**必ず「背景の」を付ける**）、マスク、フィルタ、暗幕

### 画面の頭

- **英語識別子**: `PhoneHead`
- **定義**: 狭い画面（760px 以下）の会話の画面の最上部に置く2行。1行目に顔・状態の語と経過・今のフェーズの題・引き出しを開く ≡、
  2行目にフェーズの点・n/N・「手順 n」（`docs/architecture/screen-design.md` 13.9「狭い画面（760px 以下）」）
- **注記**: 広い画面の帯の名乗りといまの作業と、進み具合のプログレスバーを1つにまとめたもの。カードの頭・レポートの頭（合図の行）とは別物（この2つと紛れる「頭」から「画面の頭」へ改めた）
- **避ける言い方**: 頭（以前の呼び名。別の意味の語にも当たる）、ヘッダー、ナビバー、帯（帯は広い画面の全画面の最上部の帯を指す）

### 引き出し

- **英語識別子**: `NavDrawer`
- **定義**: 狭い画面（760px 以下）で画面の頭の ≡ を押すと右から出る幅 330 の面。名乗りの行・動き方の段（仕事・雑談の門、モデル・effort・
  許可モード）・「やり取り / タスク / 使用量」の切り替え・下端の「＋ 新しいやり取り」と設定の歯車を持つ
  （`docs/architecture/screen-design.md` 13.9「狭い画面（760px 以下）」）
- **注記**: 広い画面の帯とサイドバーが持つものの行き先。無くした「見た目の引き出し」（キャラクター画面の前身）とは別物
- **避ける言い方**: メニュー、サイドメニュー、ドロワー、「≡」の面（以前の、帯の中身が縦に落ちてくる面）

### ボトムシート

- **英語識別子**: `BottomSheet`
- **定義**: 狭い画面（760px 以下）で下から上がる面。中間レポート・依頼の手順の一覧・答え待ちのカードの「ほか n」と添え書きを読む。
  上端につまみ、下端に前後へ移るボタン（中間レポートのとき）を持ち、面の外を押す・つまみを下へ払う・Esc で閉じる
  （`docs/architecture/screen-design.md` 13.9「狭い画面（760px 以下）」）
- **避ける言い方**: 板（旧称。一文字の一般語で、どの面か読み取れなかった）、単独の「シート」（必ず「ボトムシート」と書く）、モーダル（`<dialog>` で中央に開くもの）、ポップオーバー

### サイドシート

- **英語識別子**: `TaskSheet`（開いているタスクは `stores/task-sheet.ts` の `useTaskSheet`）
- **定義**: 広い画面（761px 以上）でサイドバーのタスクの行を押すと、サイドバーの左に開く非モーダルの面。1件のタスクの状態・番号・題・属性・つながり・本文の全文と頼む口を出し、ドラフトの段の「仕分ける」からはドラフトの分類の場面になる。中央の列の進行の帯の下から入力欄の上までに収まり、開いたまま入力欄に書いて送れる
  （`docs/architecture/adr/0061-sidebar-task-stages-and-side-sheet.md` 論点 2）
- **注記**: サイドバーの行から開いていたプレビュー（`TaskPeek`）を置き換えた。狭い画面（760px 以下）には無く、行を押すと一覧モードが開く
- **避ける言い方**: 単独の「シート」（ボトムシートと紛れる）、プレビュー、ドロワー、詳細パネル

### 一覧モード

- **英語識別子**: `TaskBoard`（`src/browser/features/task-board/`。開く頼みは `useTaskBoardRequest`）
- **定義**: サイドバーの「一覧を見る」とサイドシートの「一覧モードで開く」で開く、全件を見渡すためのモーダル。左に1行1件の表（番号・題・難しさ・ループ可）、右に選んだタスクの詳細を出し、境の仕切りで幅を変えられる
  （`docs/architecture/display/task-modal.md`、`docs/architecture/adr/0061-sidebar-task-stages-and-side-sheet.md` 論点 6）
- **注記**: 「タスクのモーダル」と同じもの。正典の見出しと識別子は「タスクのモーダル」・`TaskBoard` のまま残し、画面の口と説明では「一覧モード」と呼ぶ。1件を読むのはサイドシート、全件を見渡すのは一覧モード
- **避ける言い方**: タスク板、盤、カンバン

### タスクの段

- **英語識別子**: `TaskStage`（`now`・`next`・`waiting`・`draft`・`done`。段に分ける関数は `domain/task-stage.ts`）
- **定義**: サイドバーの一覧と一覧モードの表で、タスクを状態で分けた並びのまとまり。上から **いま**（進行中）・**つぎ**（着手可）・**待ち**（待ち・保留・想定外の値）・**ドラフト**・**済み**（完了）。段の見出しに件数を出し、0件の段は出さない。サイドバーでは済みの段を畳んでおく
  （`docs/architecture/adr/0061-sidebar-task-stages-and-side-sheet.md` 論点 1）
- **注記**: 段の名前は並びの位置の語で、状態の語（進行中・着手可・待ち・保留・ドラフト・完了）とは別。行の印と語は状態の側を出す
- **避ける言い方**: グループ、レーン、列（一覧モードの表の列と紛れる）、フェーズ（作業の段取りと紛れる）

### 探す欄

- **英語識別子**: `TaskSearchField`
- **定義**: サイドバーのタスクの区画の頭に常に出ている欄。番号・題・本文の部分一致で段の一覧を絞り、↑↓ で当たりの行を移り、Enter で開く。語は保存せず、一覧モードを開くと検索欄へ引き継ぐ
  （`docs/architecture/adr/0061-sidebar-task-stages-and-side-sheet.md` 論点 5）
- **注記**: 一覧モードの中の欄は「検索欄」と呼び分ける。`/` は入力欄へ移るキーに使う予定なので、探す欄には割り当てない
- **避ける言い方**: 検索ボックス、フィルタ

### 設定の点

- **英語識別子**: `SettingMark`（セッションごとの束は `SettingMarks`、`SessionState.settingMarks`）
- **定義**: モデル・effort・許可モードの選択欄の右肩に出す7pxの丸。切り替えを受け付けたこと（空洞）と、
  受け付けた値で効いているのを見届けたこと（塗り）を言い分ける。字は出さず、ポインタを載せたときの `title` だけが言う
  （`docs/architecture/screen-design/nav-mode-control.md` 13.9「設定の点」）
- **避ける言い方**: 設定の口の右肩の点（旧称。「設定の口」が `tw config` を指す語だったため紛れる）

### デザイントークン

- **英語識別子（予定）**: `--space-*`・`--radius-*`・`--shadow-*`・`--motion-*`（色は `--ink`・`--surface` など、字の大きさは `--font-*`。値は `src/browser/styles/theme.css`）
- **定義**: 画面の見た目の値（色・字の大きさ・余白・角丸・影・動き）に付けた名前で、CSS のカスタムプロパティ。CSS はトークンを `var()` で読み、値を直に書かない
  （`docs/architecture/screen-design/design-token.md` 13.14）
- **注記**: 余白・角丸は大きさの語（`md`）、影・動きは使う場面の語（`raised`・`fast`）で付ける
- **避ける言い方**: 単に「トークン」（LLM のトークン消費と紛れる。画面の文書は「デザイントークン」と書く）

### 見本帳

- **英語識別子（予定）**: `design`（画面の hash は `#design`）
- **定義**: デザイントークン・`ui/` の部品・カタログの全部品を 1 ページに並べて確かめる専用の画面。帯には出さず、hash を打って開く
  （`docs/architecture/screen-design/design-token.md` 13.17）
- **避ける言い方**: Storybook（入れない。`docs/architecture/adr/0041-design-system-tokens-and-gallery.md`）、スタイルガイド

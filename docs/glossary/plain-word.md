# 用語集: わかりにくい語の言い換え

ステータス: **正典**。入口は `docs/glossary.md`（用語集の方針と、子のファイルの一覧）。

責務: レポートの本文と `speak` のセリフに出さない「わかりにくい語」と、その言い換え先を持つ。
読む時: レポートや文書の語を、概念を知らない人にも意味が取れる語に言い換えるとき。
直す時: 利用者が「この語は意味が取れない」と指摘したとき（`PLAIN_WORDS` に1行足す）。

## 言い換えの方針

短さより、語だけで意味が分かることを優先する。少し長くてもよい。
新しい言い換えは、語が表す概念の説明と推奨をセットで利用者に示して決める。
文書・コメント・画面の文言に残る旧語を標準語へ置き換える対応と進め方は `docs/glossary/standard-word.md` が持つ（置き換えが済んだ語は、この表から外す）。

**新しい語を作る・言い換えるときは、次のどれかに当てはまる語を選ぶ**。初見の人が辞書どおりに読んで、意味を当てられるかを問う。

- 辞書どおりに読めば意味が当たる語
- 素直なカタカナ語（ステップ・セクション・カード・プログレスバー）
- 説明的な複合語（描画領域・内容部品・欄外注）

1〜2文字の漢字名詞（帯・面・葉・札・塊・段）を、辞書の意味から離れた用語にしない。

**正典はコードの `PLAIN_WORDS`（`src/server/report/core/rules/plain-word.ts`）で、下の表は `pnpm run format` がそこから書き直す**ので、表は手で直さない。
コードを正典にしたのは、`report` の本文の検査（`src/server/report/core/rules/prose/plain-word-find.ts`）が実行時に表を読むため（文書を実行時に読む経路を作らない）。文書の表を作るときに読むのは `scripts/document/` で、`test/` も対応を見る。
語を足すときは `PLAIN_WORDS` に1行足して `pnpm run format` を打つ。長い綴りを先に置く（「再演集」は「再演」より前）。
「塊」も単独では足さず（氷の塊・岩の塊を巻き込むため）、レポートの部品を指す複合語の綴りで足す。言い換え先は「X の部品」で、画面の頭に出る失敗のまとまりを指す「失敗の塊」だけ「失敗の表示」。足した綴りは、失敗の塊・振り返りの塊・お願いの塊・逃げ道の塊・検証結果の塊・ファイルの塊・画像の塊・前後の塊・図の塊・何個目の塊の 10 語。「塊の種類」「塊の欄」「塊の数」「塊の間」「塊ごと」「塊の中」「既存の塊」「本文の塊」は「氷の塊の数」「岩の塊の間」のように普通の語の後ろにも当たるので足していない。足した「図の塊」は「意図の塊」に当たる。本文での実例が無いので残し、テスト（`plain-word-find.test.ts`「既知の巻き込み」）で当たることを固定してある。
「札」も単独では足さず（お札・名札・改札・入札・表札・札幌を巻き込むため）、画面の表示物を指す複合語の綴りで足す。言い換え先は、四角い面に複数の部品を載せる表示物なら「カード」、地も枠も無い字だけの表示なら「ラベル」、地か枠の付いた小さな印なら「バッジ」、形を指す「形の札」は「形の名前」。「親の札」は「母親の札」のように普通の語の後半に当たるので足していない。足した「数の札」は「複数の札束」に当たる。本文での実例が無いので残し、テストの「既知の巻き込み」で当たることを固定してある。
1文字の語（帯・面・葉）は単独では足さず、複合語の綴りで足す（「画面」「携帯」「言葉」を巻き込まないため）。「面の名前」のように「画面の名前」にも当たる綴りは足さない。普通の語の前半に当たりやすい綴り（葉ごと・葉を直接・葉の機能・葉の実装・葉専用・設定の面・エディタの面・読む面）は、「言葉ごと」「設定の面倒」「読む面白さ」まで巻き込むので足していない。足した綴りにも例外が残る。「葉の部品」は「言葉の部品」に、「ワークフローの面」「入力欄の面」「詳細の面」「並べた面」は「〜の面倒」「〜の面積」のような面で始まる語に当たる。どちらも本文での実例が無いので残し、テスト（`plain-word-find.test.ts`「既知の巻き込み」）で当たることを固定してある。
ワークプランの旧称「段」も、単独では足さない。「段」で終わる綴り（最後の段・前の段・今の段・済んだ段・飛ばした段）は「最後の段落」「今の段階」「飛ばした段落」に、「段」で始まる綴り（段のまとめ・段の並び・段の数）は「後段のまとめ」「手段の数」に当たるので足していない。足したのは、続きに段落・段階が自然に来ない6語（まとめ待ちの段・並列の段・委譲先の段・段ごとの時間・段の群・段の閉じ方）で、「並列の段」は「並列の段階」に当たる（テストの「既知の巻き込み」で固定）。
「棚」「台本」も単独では足さない。「棚」は棚卸し・本棚、「台本」は再現の手順を書いた台本（`- 確かめ方:` の「再現の台本」・疑似セッションの台本・再生の台本）に当たる。足したのは、画像を置いておく場所を指す3語（画像の棚・棚に置・棚から。原寸の棚・棚の原寸は置き換えが済んで外した）と、Claude Code のワークフローのスクリプトを指す2語（台本の完了・台本の中の委譲先）。言い換え先は「置き場」「ワークフロースクリプト」。「棚に置」「棚から」は「本棚に置く」「本棚から」にも当たるが、本文での実例が無いので残し、テスト（`plain-word-find.test.ts`「既知の巻き込み」）で当たることを固定してある。
「柱」「包み」も単独では足さない。「柱」は大黒柱を、「包み」は包み紙・包み込むを巻き込む。足したのは、本文の右の余白の列を指す2語（余白の柱・傍注の柱。言い換え先は「欄外注の列」）、画面の部品を囲む要素を指す4語（余白の柱の包み・傍注の包み・題つきの包み・並列のフェーズの包み。余白の柱の包みは「欄外注の列の外枠」、傍注の包みは「欄外注の外枠」、題つきの包みは「題つきの外枠」、並列のフェーズの包みは「並列のフェーズの外枠」）、コードの層を指す2語（包み関数・包み hook。言い換え先は「ラッパー関数」「ラッパー hook」）の8語。足していない綴りは、「題の包み」（議題の包み紙に当たる）、「包みの中」「包みの外」（動詞の包むの活用や包みの中身に当たる）、中くらいの窓幅でサイドバーを畳む縦の領域（`rail`）を指す「窓幅の柱」「柱の口」（柱の口は柱のボタンと書く。柱の言い換えは決めない）。graph の箱の形を決める丸括弧・波括弧は「括弧」と書く。
「口」も単独と「の口」では足さない（入口・出口・人口を巻き込む）。足したのは、画面の操作を指す4語（押す口・押せる口・開く口・選び口。言い換え先は「ボタン」「開くボタン」「選択メニュー」）と、コードの関数を指す5語（読み書き口・書き込み口・受け取り口・知らせ口・手続きが使う口。言い換え先は「読み書きの関数」「書き込みの関数」「〜する関数」）の9語。足していない綴りは、「読む口」「使う口」「書く口」（読む口調・使う口調・書く口調に当たる）、「書き口」「読み口」「受け口」「差し込み口」（文体・読み心地・受け口・ソケットの意味の普通の語）、「入る口」「戻る口」「公開口」「逃がし口」、セレクトの閉じたときのボタンを指す「閉じた口」（言い換え先は「閉じたときのボタン」）、ダイアログや見開きを開いたときに押したボタンを指す「開いた口」（言い換え先は「開いたボタン」）、「柱の口」（柱の口は柱のボタンと書く。柱の言い換えは決めない）。文書ではこれらも、画面の操作なら「ボタン」、コードなら「関数」、`work_plan`・`report` を指すなら「ツール」、差し込みの印なら「差し込みの印」、逃がし口は「逃げ道」と書く。足した「押す口」は「押す口調」に当たる。既存の「窓」も「窓口」に当たる。どちらも本文での実例が無いので残し、テストの「既知の巻き込み」で当たることを固定してある。
「合図」も単独では足さない。通知を指さない用法（合図する・合図した・合図にする・合図を鍵に）や、検証結果の行を指す「合図の行」を巻き込むため。足したのは、委譲先やバックグラウンドタスクからの通知を指す4語（合図が届・合図の届・合図を受け・合図を送。言い換え先は「通知が届」「通知の届」「通知を受け」「通知を送」）。足していない綴りは、合図の行（検証結果の行を指し、通知ではない）・合図にする・合図を鍵に・合図した・合図する。
表の綴りは、レポートの本文と `speak` のセリフの地の文に使わない（引用・コード・パスの中は除く）。別の意味で使う綴り（例: テストで同じ操作をなぞる意味の「再演」）が要るときは、別の言い方にする。

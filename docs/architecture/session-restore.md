# アーキテクチャ詳細: セッションの復元と複数化

ステータス: **正典**。入口は `docs/architecture.md`（全体構造の入口と、子のファイルの一覧）。

責務: 復元を新しい形に載せる仕組みと、複数化をやらないこと、ビューの本文の持ち方と再接続を持つ。
読む時: セッションの続きから起こす・切り替える仕組みや、`SessionManager` が1つだけ持つ理由を確かめたいとき。
直す時: 復元の組み直し方・切り替えの選び方・複数化の扱いを変えたとき（復元の要件は `docs/requirements.md` 4.8）。

## セッションの復元と複数化

**復元の決定は `docs/requirements.md` 4.8 のまま**（`cwd` + tsukumo の印（パックごと。`docs/architecture/character-pack.md`）、
常に自動で続きから、**復元のためには**会話を保存しない、失敗したら新規で起こす）。**会話の
アーカイブ（`docs/architecture/character-pack.md`「会話の記録の置き場」）は復元の材料ではない** — 画面を組み直すのは transcript からで、アーカイブは読み戻さない。

- 画面の履歴の組み直しは「`getSessionMessages` → `SessionEvent[]`（時刻付き）→ `session-manager` の
  `state` に畳む」だけ。接続したブラウザは `hello` の snapshot でそのまま同じ姿になる
  （**ブラウザ側に復元の特別な経路は要らない**）
- 依頼は欄で見分ける。駆動は送る依頼に `origin: { kind: "human" }` を付け、組み直しは `origin` があればその `kind` だけで依頼かを決め、
  `origin` の無い古い記録だけ `is_meta` で除いて読む。`isCompletedLocalCommand` の出力は `origin` によらず依頼にしない
- 組み直した記録の時刻は transcript の `timestamp` から戻す（段・ツール・checks のコマンドの所要と、
  最後のやり取りの「所要」が開き直しても出るように。2026-10-04・2026-10-07 の利用者の決定）。
  `getSessionMessages` は型に無い `timestamp` を各メッセージに載せて返すので、出来事ごとに持たせて
  `applyRestoredEvents` で畳む。読めなければ「分からない」
- 起動・キャラクターの切り替えは常に新規のセッション（2026-10-10。環境変数の逃げ道は持たない）。モードの切り替えは戻す先のモードの直前のセッションの続き（2026-10-11。覚えていない・使用中なら新規）
- **どのセッションの続きから始めるかは画面から選べる**（帯のセッションの札から開く切り替え画面 →
  `session.switchSession` → `session-launch` の起こし直し）。並ぶのは**同じパック・同じモードの、
  目印（`@7327` / `@7328`）違い**で、新しいほうから `MAX_SESSION_CHOICES` 件まで。**起動時は
  新規から始まる**（選ばせる画面は出さない）
- **別の窓が使っているセッションは切り替え画面で選べない**（`docs/requirements.md` 4.8「別の窓で使用中のセッション」）
- **ビューの本文はメモリにしかない。** プロセスを落とすとブラウザのタブは繋ぎ先を失う
  （WebSocket が指数バックオフで繋ぎ直し続ける。「再接続」）。起動し直せば
  同じ URL でそのまま復帰し、**前の続きから始まる**（claude 側の会話は `resume`、画面の履歴は
  transcript の読み直しで戻る。`docs/requirements.md` 4.8）

**複数化はやらない**（`docs/requirements.md` 2.2）。**`SessionManager` はセッションを1つだけ持ち、
鍵（`sessionId`）を持たない**。キャラクター・雑談モード・セッションの切り替えは、同じ `SessionManager` の
中で駆動を起こし直す（何代目かの印で古い駆動のイベントを捨てる）ので、古い側と新しい側を
並べて持つ場面が無い。`hello` も `sessionId` を名乗らない（画面に出るセッションのIDは
`SessionState` の側にある claude 自身のID）。広げるときの形はここに描かない
（要件から落としたので、描いておくと布石として読まれる）。

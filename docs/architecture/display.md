### 4.2 表示

#### 出力の分離（セリフと詳細）

**1つのターンを「セリフ」と「詳細（レポート）」に分け、別々の領域に出す。** 同じ内容が2箇所に
出ると、キャラクターとのやり取りがノイズに埋もれる（`docs/history/direction.md` 2026-09-09）。

**セリフは MCP ツール `speak(text, expression)` で受け取る**（2026-09-11 決定）。

- tsukumo がプロセス内の MCP サーバとして `speak` を提供し、モデルが呼んだらその `text` を
  吹き出しに出す。`expression` はキャラクター定義にある表情名から選ぶ（4.3）
- **戻り値は `"ok"` だけ**にする。ツールの結果はモデルの文脈に戻るので、ここに情報を載せると
  tsukumo からモデルへの逆流路ができる。**例外は `recall` / `recall_episode`（雑談と仕事の両方）と、仕事の
  `report` の3つ**。`recall` / `recall_episode` が返すのは tsukumo の状態ではなく**その会話自身の
  過去**（4.9「古い雑談は索引を引いて思い出す」、2026-09-25 に2段階へ組み替えた）。`report` が
  返すのは、差し戻すときの**規約違反とその直し方だけ**で、
  描けたか・どこに出たかといった画面の状態は載せない（2026-09-23 ユーザー決定。レポートの出力を
  「検査 → 整形 → 描画」に分けた検査の段。検査するのは「レポートの記法」の条のうち機械で判定
  できるものだけで、差し戻すのは1ターンに1回まで。同じターンで受け取った `report` と同じ引数の
  送り直しも、固定の一文で別に1ターンに1回まで差し戻す。直前に描いた `report` のあとに、新しい依頼・
  メインが呼んだツールの結果・背景のタスクの終わりのどれも届いていない `report` も、新しい事実の無い
  言い直しとして固定の一文で別に1ターンに1回まで差し戻す（文面の近さでは判定しない。サブエージェントの
  合図は `speak` で言い直すもので、流れにも見えないので数えない）。`src/server/report/core/report-review.ts`）。
  **4つ目を足すにはユーザーの決定が要る**
- **検査を通った `report` の本文は、描く前に整形する**（同じ決定の整形の段。
  `src/shared/report/report-tidy.ts`）。落とすのは**落としても意味が変わらないものだけ**で、言い換え・
  要約・並べ替えはしない: 本文の冒頭で `conclusion` を繰り返しているもの（冒頭の `text` の塊か、
  逃げ道の頭の行）・前置きと締めの定型だけの `text` の塊と逃げ道の行（閉じた一覧との丸ごとの一致。
  型で当てると中身のある行まで黙って消えるので置かない）・逃げ道の中の中身の無い見出し・
  塊が残らなくなった節。**分担の基準は「直すのに書き直しが要るか」**——要るもの（段落を表へ移す・
  結論を短くする）は検査が差し戻し、消すだけで直るものは整形が黙って落とす。同じ条を両方には
  置かない。**記録は引数のまま持ち、メインビューの導出（`src/shared/session/main-view.ts`）で掛ける**ので、
  規則を変えると過去のやり取りと、セッションの復元で組み直したやり取りにも効く。**空行の連続は
  詰めない**（CommonMark でも本文を塊に割る側でも1つの切れ目と同じに描かれ、フェンスと HTML の
  塊の中では中身なので、落としても見え方が変わらない）。`report` の無いやり取りの本文には掛けない
- **呼ぶ頻度・契機・セリフに入れる中身は tsukumo 側が持つ**（2026-09-16 決定。書く場所は
  `src/server/system-prompt/core/speech-cadence.ts` の `SPEECH_CADENCE_PROMPT`）。回数は数で縛らず契機で言い、
  ツールを走らせる前に1回、その結果で分かったことがあればもう1回。セリフの中身は
  **「いま何をしていて、そこでどう感じているか」**が分かるものにする（ユーザーへの問いかけを
  増やすのではない）。**どのパックでも吹き出しが長く止まらない**ことは tsukumo 全体の体験なので、
  パックの `persona.md` には書かない（パックが決めるのは口調・言い回しだけ）。
  tsukumo は呼ばれたら出すだけで、判定に推測が要らない
- **サブエージェントへの委譲は背景で行い**（2026-09-16 決定）、進み具合をサブエージェントからの
  合図（`状況 | n/N | …` の1行）で受け取ってメインが `speak` で言い直す。フォアグラウンドの委譲は
  ツール呼び出しの中でメインを止め、吹き出しが数分単位で止まるため。**合図（進み具合の1行か、
  委譲の完了の知らせ）の届いていないターンでは `speak` も `report` も呼ばない**（2026-09-27 決定。
  Claude Code 本体の催促 "The user hasn't heard from you in a while" で始まるターンも含む）。新しい事実の無いセリフの言い直しを防ぐため
- **レポートは MCP ツール `report(task, conclusion, checks, sections, favor, closing)` で受け取る**（2026-09-24 決定。
  `checks` は 2026-09-26 に、`closing` は 2026-09-27 に、`task` は 2026-09-30 に足し、本文は 2026-09-27 に文字列の `body` から
  `sections` に替えた。
  仕事のセッションでは常に載り、雑談では載らない）。**検査を通った `report` はそこでターンを閉じる**
  （2026-09-27 決定。handler が結果に `_meta["claude/endTurn"]` を付け、本体は assistant を挟まずに
  ターンを終える。差し戻した呼び出しには付けないので、モデルは直して呼び直せる。
  `docs/research/report-block.md` 13章）。`report` のあとに本文を書き足す形が起きないので、
  **締めのセリフは必須の引数 `closing`（`speak` と同じ `text` と `expression`）で受け取り**、
  レポートを描いたすぐ後ろに吹き出しへ出す（差し戻した呼び出しの `closing` は出さない）。
  **任意の引数 `sessionSummary` にはセッション全体の要約を毎回書き直して入れる**（2026-09-27
  ユーザー決定。中立の文体で2〜3段落・1200字以内、残っていることは「残り：」の段落）。レポートには
  描かず、セッションの切り替え画面が transcript の最後に通った `report` から読み戻す
  （`docs/architecture/screen-design.md`「切り替え画面」）。tsukumo は要約を別の場所へ書き出さない（transcript の
  ツールの入力に残るだけなので、`docs/coding-standards.md`「会話内容の扱い」の例外を増やさない）。
  書かせる条は引数の説明と「レポートの記法（tsukumo）」の1段落で、任意の `title`（セッション一覧の
  見出し）と同じく差し戻した呼び出しの値は使わない
  ターンの途中の経過は `speak` で言う。雑談には使わない（`report` が無く、1ターンに `speak` を
  何度か呼ぶのが普通の形なので、閉じるツールを置くと切れる）。`report` の外に書いたターンの本文
  （`assistant` のテキスト）は、`report` が1つでも呼ばれたターンでは画面に出さない。呼ばれなかった
  ターンだけ、本文を詳細として扱い、下の「メインビュー」の選び方でレポートにする

**本文は `report` の `sections`（節と塊の並び）で受け取る**（2026-09-27。形の案は
`docs/research/report-block.md`、用語は `docs/glossary.md`「節」「塊」）。

  外すかは「塊を足す・外す基準」の外す基準〔28日0回〕で決める）

  - `list` の項目の `label`: 印なしのラベルと本文の2列に組み、項目の間を細い横線で区切る

    結論には、`task` があれば作業の名前を頭に添える
- **`checks` の `detail` に所要時間を添える**（2026-09-27 ユーザー指示。E2E などにどれだけ時間が
  かかっているかを把握するため）。**条1**（`REPORT_NOTATION_PROMPT`）と `checks` の引数の説明
  （`REPORT_CHECKS_DESCRIPTION`）の両方に、測れた検証は所要時間を添え、測っていない・測れない
  確認（目視など）は `detail` に「未計測」と書く条を足した。tsukumo 側はツールの呼び出しに時刻を
  持たせていないため、モデルに測らせるヒューリスティックだけを先に入れた。
  **のちに機械測定へ置き換え、この条は外した**（2026-09-27）。`tool` の記録が開始と終了の時刻を持ち、
  所要時間は帯の「依頼の手順」の一歩に出す（`docs/architecture/screen-design.md`「いまの作業」）。
  `checks` にしなかったのは、モデルが書く検証の行とツールの呼び出しを機械的に対応付ける手段が無いため
  （2026-09-28 に `command` の完全一致で対応付けて、`checks` にも出すようにした。次の項目）
- **検証結果はカードで描き、`figure` と所要時間を載せる**（2026-09-28 ユーザー決定。文字を並べた帯では
  結果をひと目でつかみにくく、所要時間も出ていなかった）。
  - **1項目1枚のカード**を幅に合わせて並べる（書いた順のまま）。状態は縦罫と地の染めの色と文字の
    両方で見せる。**毎回出る脇役なので高さは抑える** — 段は「`label` → 状態」の見出し、「`figure` と
    所要時間」を中央に寄せた段、「`detail`」の段の3つまでで、中身の無い段は置かない（2026-09-28 に
    状態を行頭から見出しの後ろへ移した。行頭の「✓ OK」だけでは何が通ったのか読めなかった）
  - **`figure`** はモデルが書く、結果を1つの数で言う短い文字列（「2849 / 56」「25px」など）。数で
    言えなければ空文字で、描かない。**数だけを書かせ、「が通過」のような述語は付けさせない**
  - **`detail` は NG・未確認の理由だけを書く欄で、ok のカードには描かない**（2026-09-28 ユーザー決定。
    ok の detail には「が通過」のような言わずもがなの述語や、打ち直した経緯のような利用者に要らない
    文が入っていた。心がけの条ではなく描かないことで塞ぐ）。detail の長さで差し戻す仕組みは、
    それでも経緯が混ざるようなら足す
  - **所要時間は tsukumo が測った値だけを出す。** モデルは確かめに打った Bash のコマンドを
    **`command` に打った文字列のまま**書き（コマンドでない確認は空文字）、tsukumo は同じやり取り
    （最後の依頼より後）の `tool` の記録のうち、`Bash` の `command` が**完全一致する最後の1件**の
    所要時間を添える（サブエージェントの中の呼び出しも含む。所要時間の測り方は「依頼の手順」と同じ
    `toolDuration` で、復元した記録は測れないので添えない）。一致しなければ添えない。
    **モデルに時間を書かせる欄は作らない**（2026-09-27 に外した理由がそのまま効く）
  - 突き合わせはメインビューの組み立て（`main-view.ts`）で描くたびに行い、所要時間を記録には持たない。
    `figure` / `command` の無い前の形の記録は、2つを空文字として読む（`parseReportChecks`）。
    `report` のイベントの形が変わったので `PROTOCOL_VERSION` を 24 に上げた
- **検証結果はカードでなく、1項目1行の表で描く**（2026-09-28 ユーザー決定「案A」。毎回出る脇役なのに
  1項目1枚のカードは箱と段が多く、場所を取っていたため）。入力の形（`status` / `label` / `figure` /
  `command` / `detail`）は変えない
  - 上に「検証 N」＋全体の状態の1行を置く。`ng` があれば「✕ k 件が落ちた」（赤・太字）、無くて
    `unverified` があれば「？ k 件を確かめていない」（黄・太字、`?` は全角）、どちらも無ければ
    「✓ すべて通った」（緑）
  - 項目は状態・`label`・`figure`・所要時間の4列の grid で1行に並べる。**通った行は「✓ OK」の
    文字だけに色を付け、行の地や枠は染めない**。`ng` / `unverified` の行だけ左に縦罫を引き、状態と
    `label` を太字にし、`figure` を本文色にし、`detail` を2段目（4列の2列目〜末尾）に描く
    （`ok` の行は `detail` を描かない。既存どおり）
  - `figure` の書式は「56 件中 1 件」のように何の数かを付けて描かせ、「2849 / 56」のような割り算・
    分数に見える書き方はさせない（`REPORT_CHECKS_DESCRIPTION` と `reportCheckSchema` の `figure` の
    `describe`）
  - HTML は `report-check.ts` の `reportChecksMarkdown` が組み、表は `role="table"`・行は `role="row"`
    （`REPORT_SANITIZE_SCHEMA` はもとから `role` を通す）。帯の class は変わらず
    `REPORT_DRAWN_MARK_NAMES` に置く

#### 段取り

**作業中に「いまどの段にいて、あと何が残っているか」を画面で追えるように、claude から段取り（段の並びと
今の位置）を MCP ツール `work_plan` で受け取る**（2026-09-29 ユーザー決定。用語は `docs/glossary.md`
「段取り」「work_plan ツール」）。`progress` の塊は `report` を渡したときにしか出ず、依頼の手順は
ツールの実行を1回ずつ並べるだけなので、作業中の段は今まで見えなかった。Claude Code の TodoWrite を
拾う案（使うかどうかも項目の粒度も tsukumo から縛れない）と、ツールの手順から段を推し量る案
（推測になる）は採らない。

- **入力は `{ phases, current, phaseSummary }` で、毎回段の並びごと渡す**（位置だけの呼び出しは作らない。tsukumo が
  前の並びを覚える状態と、並びの無い位置の扱いが要らなくなる）。`phases` は1つ以上・空白だけの名前は
  不可、`current` は0始まりで全部済んだら段の数。`phaseSummary`（段のまとめ）は下の「段が移ったときの
  中間レポートと段の知らせ」。形は zod の形が、`current` が段の数を超えた呼び出し・段のまとめの足りない
  呼び出しは `parseWorkPlan`（`src/shared/session/work-plan.ts`）が差し戻す。変換（`sdk-message.ts`）も同じ
  `parseWorkPlan` を通ったメインの呼び出しだけを `work-plan` のイベントにし、サブエージェントの
  呼び出しは捨てる。戻り値は `"ok"` で、ターンは閉じない。**仕事のときだけ載る**
- **段はファイル単位・操作単位で切らず、作業のまとまりで切る**（2026-09-29 ユーザー決定）。この粒度は
  ツールと引数の説明と、仕事の append の節「段取り（tsukumo）」（`WORK_PLAN_PROMPT`。セリフの間合いと
  レポートの記法のあいだ）で伝える。委譲中は `## やること` の段で切る（下の「委譲中の合図」の条）
- **呼ぶ条件は条として書き、差し戻しでは縛らない。** 条は「作業をするターンは段の数にかかわらず呼ぶ。
  作業のまとまりが1つなら1段の段取りを渡す（札には `1/1` のように出る）。答えるだけ・1回調べて答える
  だけの依頼では呼ばない」（2026-09-30 ユーザー決定）。機械で縛れるところは機械に寄せた（雑談では
  載らない・0段の段取りは形の検査が受け付けない）。呼ばなかったことはターンの終わりにしか判定できず、
  そこで差し戻すと着手時に渡すはずの段取りを後から書かせるだけになる。呼ばなくても札と一覧はいままでの
  表示のままで壊れない
- **委譲中の合図の `n/N` は tsukumo が段の位置として描かない。** 合図は自由文で、読むのは文字列の
  解釈になる。代わりに、`## やること` の段で書かれたタスクを委譲しているあいだは、メインが段を
  「計画・`## やること` の各段・受け入れ」にして渡し、段の終わりを知らせる合図に応える `speak` と
  同じ応答で `work_plan` を呼んで `current` を n+1 に進める（2026-10-02 ユーザーがエージェントの判断に
  任せた）。段を進めるたびに中間レポートが出てメインビューの札が増えるのは受け入れた。合図の N を
  `## やること` の段の数にそろえるのは `next-task` の側。合図の来ない段の中の進みでは呼ばない
- **段を進める `work_plan` と、その契機の `speak` は同じ応答の中で並べて呼ぶ**（段が変わるのは論点が
  切り替わるときで、`SPEECH_CADENCE_PROMPT` の契機に当たる。別々の応答にすると往復が1回増える）。
  **全部の段を終えた印（`current` = 段の数）も `report` と同じ応答で渡す。** 途中で止めて `report` を
  呼ぶときは進めないので、止まった段が「今」のまま残る
- **出す場所は4つ**: いまの作業の札（今の段の名前と位置。会話の画面以外）と依頼の手順の一覧の頭（全部の段と、段ごとに
  区切った手順）は `docs/architecture/screen-design.md`「いまの作業」。会話の画面では、札と一覧の頭の代わりに
  作業の地図が段の並びを持つ（同 13.13「作業の地図」）。最後のレポートは、`report` が
  届いた時点で同じやり取りにある最後の段取りを、**`conclusion` の下（検証結果より上）に `progress` の
  塊と同じ組み方で描く**（`main-view.ts` の `reportMarkdown`。記録には持たず描くたびに導く）。中間
  レポートもその時点の段取りで描く。段取りを渡したターンでは同じ段の `progress` の塊を書かないよう
  条に入れた。4つ目はメインビューの段の移り（次の項）
- **段が移ったときの中間レポートと段の知らせ**（2026-09-30 ユーザー決定）: 段が移ると、メインビューに
  終えた段の中間レポートと、次の段に入ったことを知らせる1行（段の知らせ）を出す。段の移り変わりが
  帯の札の書き換わりにしか残らず、分かりにくかったため。**働くあいだメインビューに出るのは作業の地図
  （`docs/architecture/screen-design.md` 13.13）なので、段のまとめは地図の済んだ段の行に出て、ここで言う
  中間レポートと段の知らせは、渡したあとのレポートの札に出る**（2026-10-02）。
  - **中間レポートの中身は、段を進める `work_plan` の `phaseSummary`（段のまとめ）で受け取る**。
    「終えた段でしたこと・分かったこと」を1〜2文で、記法は `report` の `conclusion` と同じ。`report` に
    「途中」の印を足してターンを閉じない形にする案は採らない（段の切れ目と中間レポートを仕組みで揃える）。
    `sections` まで借りる案も採らない（畳まれる中間レポートに要るのは段の結論だけで、詳しいことは
    最終レポートが持つ）
  - **`current` が途中の位置（0 より大きく段の数より小さい）の呼び出しでは段のまとめを必須にし、無ければ
    差し戻す。3文以上も差し戻す**（`parseWorkPlan`。文の数え方は `report` の結論と同じ `sentenceCount`）。
    段を前へ進める呼び出しは、全部の段を終えたものを除けば必ず途中の位置に着地するので、段が進んだのに
    まとめが無い、は起きない。「前より進んだか」で縛らないのは、`parseWorkPlan` が1回の引数しか見ず、
    handler と変換が同じ関数を通して「差し戻した呼び出しは記録しない」を揃えているため（前と比べて
    差し戻すには、`report` のように結果まで預かる仕組みが変換にも要る）。代わりに、途中の位置で戻る・
    組み替えるだけの呼び出しにもまとめを書かせる（画面には出さない）
  - **何を出すかは、同じ依頼の直前の段取りと比べて決める**（`phaseShiftOf`。記録から描くたびに導く）:

    | 呼び出し                                                         | 中間レポート                   | 段の知らせ                         |
    | ---------------------------------------------------------------- | ------------------------------ | ---------------------------------- |
    | その依頼で最初の段取り                                           | 出さない                       | 出さない（帯の札が出す）           |
    | 段を進める（前の今の段が、新しい並びで今の段より前にある）       | 出す                           | 出す                               |
    | 戻る・組み替えたが前の今の段は済んでいない（今の段以降・消えた） | 出さない                       | 今の段の名前か位置が変わったら出す |
    | 全部の段を終えた（`current` = 段の数）                           | 出さない（最終レポートが担う） | 出さない                           |

    終えた段は名前で探すので、段を進めながら後ろの段を組み替えても見失わない。1段だけの段取りは
    `0 → 1` しか取らないので、どちらも出ない

  - **段の知らせは、中間レポートの札とは別の、字だけの1行**（「ここから 2/3 段の名前」）。札の末尾に
    添える案は採らない（中間レポートは次のまとめが来ると畳まれ、知らせが `<summary>` の奥に隠れる。
    まとめを持たない戻りの呼び出しでは載せる札が無い）。見た目は `docs/architecture/screen-design.md`
    13.2「段の知らせは字だけの1行にする」
  - **段のまとめの中間レポートは、目録の1行にラベルと終えた段（「中間レポート · 1/3 段の名前」）を並べ**、
    畳んだ `<summary>` にも終えた段を出す。**届いた時点で中間と決まるので、ターンが動いているあいだも
    伏せずに出す**（下の「各表示物」のメインビューの「確定するまで出さない」の例外）。最後の本文・最後の
    `report` の候補にはならない
- **段取りと検証結果は1つのまとまり（`status`）に包み、結論・本文とのあいだを広く空ける**（2026-09-30
  デザイン「レポートの頭の空間 案1」）。段取りには小さな見出し「進み具合」を載せ、あきは結論→まとまり 28px・
  段取り→検証 26px・まとまり→本文 44px。最終レポートの札の内側は上下 28px・左右 32px。検証の行は左右に
  はみ出させ、「✓ OK」の左端を段取りの丸の左端にそろえる
- 状態は `work-plan` の記録を届いた位置に積むだけで、今の段取り（`latestWorkPlan`）と手順ごとの段
  （`currentTurnSteps`）は記録から導く。記録の形が増えたので `PROTOCOL_VERSION` を 25 に上げ、段のまとめを
  足したときに 27 に上げた

#### レポートの記法は、TUI と tsukumo で出し分ける

**出力スタイル（`~/.claude/output-styles/asuna.md`）は `~/.claude/settings.json` の
`outputStyle` で全プロジェクトに同じものが当たる**ため、そこに HTML の記法を書くと、tsukumo 以外の
素の TUI でもタグが文字のまま見える。

**tsukumo が `systemPrompt` の append で差分を足す形にする**（2026-09-12 決定）。

- グローバルの `asuna.md` は **TUI 向け**に保つ。人格・`speak` の分岐・セリフと詳細の書き分けは
  残し、**HTML の記法（`note` / `badge` / `cols` / `card` / `details` / `blockquote` / `hr`）と
  mermaid / chart のフェンスを外す**
- **レポートの文体は tsukumo が決める**（2026-09-14 決定）。**本文は中立の技術文**にし、
  キャラクターの口調を担うのは `speak` のセリフのほうにする。どのパックに切り替えても
  本文の読みやすさが変わらないようにするため（**長く読み続ける面**なので、読みやすさを
  キャラクター性より優先する）。書く場所は `src/server/report/core/report-notation.ts` で、
  **`persona.md` の側には書かない**
- **レポートは必ず日本語で書かせる**（2026-09-23 決定）。`CLAUDE.md` の「対話言語」だけでは
  本文が英語で出たことがあるため、同じ `report-notation.ts` の文面で縛り、送る前の検算にも入れる。
  英語のまま残してよいのは識別子・パス・コマンド・コード・エラー文・原文の引用だけ
- **HTML・mermaid・chart の規約は tsukumo が持つ。** `query()` の
  `systemPrompt: { type: "preset", preset: "claude_code", append }` で足す。正典がリポジトリ内に
  来るので、**描ける記法の一覧が `src/browser/components/page/conversation/components/main-view/markdown/sanitize-schema.ts` と同じコミットで動く**
  （レンダラを直したのに規約が古いまま、が起きない）
- **`~/.claude/settings.json` には触らない**（`outputStyle` も、orca が専有する hooks /
  statusLine も無傷のまま）。書き換えるのは `asuna.md` 1ファイルだけ

**この2つの案は採らない**（理由は `docs/history/decision.md`「requirements.md 4.2 表示 /
レポートの記法は、TUI と tsukumo で出し分ける」）: 出力スタイルを2ファイルに分けて選ぶ案と、
1ファイルのまま条件分岐で書く案。

**文面は `src/server/report/core/report-notation.ts` の `REPORT_NOTATION_PROMPT` にあり、
`startSdkDriver`（`src/server/session-driver/adapter/sdk-driver.ts`）が `query()` の `systemPrompt` へ渡す。**

#### 読む時間を減らす物差しと線引き（2026-09-13 決定、2026-09-30 改訂）

**物差しは、レポートを読んで分かるまでの時間が短くなるか。** 短くなるなら、3層（レンダラ /
通す HTML と CSS / 組み立ての規約）のどこに足してもよい。レポートのレイアウトの設計・画像 `img`・
`svg`・`chart`・`cols`（のち `compare` の塊に上げた）もこの物差しで採る（2026-09-30 ユーザーの方針）。文字を減らすこと自体は
目的ではなく、図・グラフ・画像のほうが速く分かる内容をそれで描く。規約を書く場所は
`src/server/report/core/report-notation.ts` で、グローバルの `~/.claude/output-styles/asuna.md` は
TUI 向けのまま触らない。

- **見せ方と再構成の線引き**: **本文の文字列を変えないものが見せ方**（CSS・要素の付け替え・
  段組み・折りたたみ・列揃え・書き手が渡した数や寸法や画像を図にして描くこと）で、これは足してよい。
  **レンダラが本文から目次・要約を起こす・中身を削る・並べ替える・言い換えるのは再構成**
  （2.2 のスコープ外）なので採らない。**書き手（モデル）が最初からその構造で書くのは
  執筆であって再構成ではない**ので、規約で促してよい。この線引きは同じ議論が再燃したときの基準
- **画像を描く条件**: tsukumo 自身のサーバが配る手元の画像だけを描き、外部の URL は読まない
  （会話の載るページに外部を読みに行く経路を作らない）。会話の中身が写る画像（スクリーンショット）は
  同じマシンのディスクに留める（`docs/coding-standards.md`「会話内容の扱い」）。`image` の塊の画像は次のとおり
  扱う（2026-10-02 利用者の決定）:
  - **tsukumo は画像を書き出さない**。描いた `report` を受けた時点で書き手のファイルを1回読み、プロセスの
    メモリの棚にだけ持つ。読んでメモリ上のビューに出すだけなので、「会話内容の扱い」の複製の例外は増えない
  - **棚から消えるのは**、プロセスの終わり・記録の窓（`MAX_SESSION_STATE_TURNS`）からレポートが落ちたとき・
    合計が 64 MiB を超えたとき（古いレポートから）。起こし直し・続きからの復元のあとは「画像を出せない」の札になる
    （記録に残るのはパスだけ）
  - **書き手が撮ったファイルそのものは tsukumo が作りも消しもしない**（`scripts/capture-view.ts` は既定で `/tmp` に撮る）
  - **読む場所では絞らない**。拡張子と先頭の印が png・jpeg・gif・webp のどれかに合う、5 MiB 以下の普通のファイル
    だけを読む（モデルは元々どのファイルも読めるので、場所で絞っても守れるものが増えない）
  - **経路は起動トークン付きの `/report-image/` だけで、URL にはファイルを読ませない**（経路は棚を引く鍵で、
    要求の時点ではファイルに触らない）
- **足さないもの**: **レンダラによる目次・先頭の要約の生成**（上の線引きで再構成の側）/
  **`.note` の種類を増やす**（ok / warn / ng の3つで区別がつく。増やすと選ぶ手が止まる）

**`class` の語彙を増やすときは、同じコミットで規約の文面・`sanitize-schema.ts` の許可リスト・
CSS の3つを揃える**（レンダラを直したのに規約が古いまま、が起きない）。**記法の表の行を削ることは
許可リストを同じコミットで削ることを意味する。**

**効くのは書く前だけ。** 規約は `systemPrompt` の append なので、**本文が書かれたあとに tsukumo が
削る経路は無い**（例外は `report` の本文の整形で、落とすのは意味の変わらない行だけ。上の
「出力の分離」）うえ、**規約の変更が効くのは次にプロセスを起こしたときから**（定数なので、
動いているセッションには当たらない）。**量の上限は数で書かない**（行数や項目数で縛ると、長い調査の
報告まで同じ長さに押し込められる。ユーザーの選択）。**ただし段落の単位にだけは数で縛る**
（地の文の段落は3文まで、4文目が要るなら表・箇条書き・`<details>` へ移す。2026-09-23 決定。
全体の量ではなく段落が続くことを止めるための上限なので、長い報告を押し込める話にはならない）。

改訂の経緯（6回ぶん）は `docs/history/decision.md`「requirements.md 4.2 表示 / 読む時間を減らす
ために足すのは、規約の側」、短縮の案と実測は `docs/research/report-notation-shortening.md`。

#### 塊を足す・外す基準（2026-09-27 決定、2026-09-30 改訂）

**塊の種類・欄・逃げ道の中の記法を足すかは、上の物差し（読んで分かるまでの時間が短くなるか）で
決める。外すかは使われ方の数で決める**（docs/research/report-block.md 6章、記録の語彙は
`docs/research/report-architecture.md` 6章）。`report` を描く（差し戻されなかった）
たびに、その回に出た塊の種類・既定の値でない塊の欄（表のセルの `from` / `to`・`stats` の `before` / `total`・
`list` の `label`・`list` の `flow`・`dimension` の `before`）と、逃げ道（`markdown` の塊）に出た記法の種類（重複無し。同じ種類が
同じレポートに何回出ても1回と数える）を `~/.tsukumo/report-usage/<YYYY-MM-DD>.jsonl` に1行記録する。
逃げ道に出た記法は3つに分けて持つ: **塊のある記法**（表・箇条書き・`note` など、逃げ道の外側
〔HTML の容れ物の中でないところ〕に出たもの）・**同じ塊のある記法が HTML の容れ物
（`<details>` / `<div>`）の中に出たもの**（複数の塊を畳む・並べるのは逃げ道の役目なので、
差し戻しではなく別に数える）・**塊の無い記法**（`cols` / `card`〔規約から外したので、書かれ続けるかを見る数〕・
`svg`・`dl`・引用・区切り線・`<details>` そのもの。塊に当てはまらないので昇格のきっかけになる）。知らない種類で境界で
落とした塊の数（`parseReportSections` の `unknownBlockCount`）も同じ行に足す。中身は一切持たない
——数と名前だけ（`docs/coding-standards.md`「会話内容の扱い」）。書くのは
`src/server/report/adapter/report-usage-log.ts`、何を1行にするかは
`src/server/report/core/report-usage.ts` と `src/server/report/core/report-violation.ts` が持つ。

**集計するスクリプトは `scripts/report-block-usage.ts`**（`node scripts/report-block-usage.ts
--days <日数>`、既定28日）。「塊の種類 × レポート数」「塊の欄 × レポート数」「逃げ道の外の記法 × レポート数」
「逃げ道の容れ物の中の記法 × レポート数」「塊の無い記法 × レポート数」の5つの表を出す。欄を記録する前の
行（版2）も読み、欄の表だけは欄を記録した行を分母にする（欄を足す前後で逃げ道の使われ方を見比べるため）。

- **足すきっかけ**: 塊の無い記法の同じ種類が、直近2週間（14日）のレポートの3%以上に出たら、
  塊に上げるタスクを立てる。**数が届かないことは足さない理由にならない**（書くのが重い記法は、
  速く分かる内容でも使われない。`chart` は 2026-09-27〜09-30 の364回で1回）
- **容れ物の判断**: 塊のある記法が容れ物の中に出た数を見て、`<details>` / `div` の使われ方
  （畳む・並べる）を判断する。足す・外す基準の対象にはしない
- **外す基準**: 塊の種類か塊の欄が、直近4週間（28日）で0回だった。数が決めるので、あとの判断は
  「タスクを立てるかどうか」だけになる。**`markdown`（逃げ道そのもの）は外す基準の対象にしない**
  ——逃げ道を無くす話は塊の一覧の増減とは別の議論になる

#### 各表示物

**表示はすべて HTML である**（2026-09-09 決定。`docs/architecture/adr/0016-html-instead-of-terminal.md`）。
ターミナルに文字と絵を描く経路は持たない。4つの領域は
**1枚のページ**として tsukumo のローカル HTTP サーバから配られ、**Orca 内のブラウザタブ**に出る
（4.7）。

- **立ち絵**: HTML の `<img>` で表示する。ドット絵ではなく本物の立ち絵を出せることを狙う。
  ターミナルの画像プロトコル（Sixel / iTerm inline images）は使わない
- **吹き出し**: `speak` で受け取った**セリフだけ**を、キャラビューの中に立ち絵と同居させて
  表示する。**セリフ1件につき吹き出し1つ**とし、今のターンの分を縦に積んで**最新を一番下**に
  見せる（並びは自前でスクロールする。2026-09-12 決定）。**主役は立ち絵**で、**立ち絵は領域の
  左下・吹き出しの並びは右上**に置き、最新の吹き出しの左辺から立ち絵へ向けて尻尾を伸ばす
  （下の尻尾の段落）。
  **「どれが最新か」は位置と見た目の強弱の両方で示す**（最新だけ濃く大きく、過去は小さく薄く）。
  吹き出しの幅は中身なり。**ターンの
  本文は出さない**（本文はメインビューに回る）。**折り返し・全角文字の幅・禁則処理はブラウザに
  任せる**。**最新の吹き出しの下端の位置は固定し、過去のセリフが上へスライドする**形にする
  （2026-09-13 決定。**下端揃え＋固定の下余白**で、最新の Y 座標はセリフの件数によらず一定に
  なり、入りきらない分だけ内側でスクロールする）。位置と幅が往復した経緯は
  `docs/history/decision.md`
- **最新の吹き出しにだけ話し手の名前（`character.json` の `name`）を添える**（2026-09-23。
  名前が無いパックには添えない。反応の吹き出しにも添える）。**流れていったセリフは右上の「ログ」から
  読み返す** — **キャラビューの舞台をそのまま上へ伸ばす**モーダルで（2026-09-23 決定。見本は
  ユーザーの「発話ログ案2」）、左右と下端はキャラビューの領域に揃え、上端は帯のすぐ下まで伸ばす。
  背景（`docs/architecture/screen-design.md` 13.8）も領域と同じ縮尺・同じ位置で敷いてそのまま上へ続け、
  領域の上端から上で地へ溶かす（開いても立ち絵の後ろの絵は動かない）。
  立ち絵はキャラビューと同じ表情・同じ高さで同じ場所に立ち、吹き出しは古い→新しいを上→下に
  積んで、ターンの境目に依頼の区切り（依頼の1行目と、分かれば依頼の時刻）を挟む。開いた直後は
  最新（キャラビューの最新の吹き出しと同じ見た目・同じ位置）が下端に見え、上へ転がして遡る
  （上へ転がせるときだけ「もっと前を読む ↑」の印が出る。読み込みの口ではない）。過去の吹き出しは
  古いほど薄いが、いちばん薄い段でも字の比は 4.5:1 を割らない。閉じるのは「ログを閉じる」・Esc・
  枠の外を押すこと（枠の外を押しても閉じるだけで、下の画面は操作しない）。材料は過去のターンの
  吹き出しを遡らせるのと同じ記録で、別に溜めない
- **吹き出し・セリフのログの行を押すと、そのセリフの表情へ立ち絵が遡る**（2026-09-28 決定。
  雑談モードの「会話を遡る」の仕事モードでの対応物。docs/architecture/screen-design.md「会話を遡る」）。
  押し方・印・解き方（新しいセリフが来たら解ける・ドラッグで文字を選んだときは押したことに
  しない・キーボードで押せる）は雑談と揃えた。留めた状態は吹き出しとログで1つ共有する
  （ログの床の立ち絵はキャラビューのものと同じ立ち絵なので、片方で留めればもう片方にも
  そのまま映る）。以下は雑談と揃えなかった:
  - **タブ（過去のやり取りの札）を切り替えても留めた選択は解けない**。留めた行は「ターンの
    通し番号とそのターンの中の位置」の組で持ち、過去のターンは記録から不変に導けるので、
    雑談の「窓から古い記録が落ちて番号の指す先がずれる」ような失効が要らない。ログはどの
    ターンのセリフでも押せる1つの窓という扱いで、タブとは独立に動く
  - **何も留めていないときに印が付くのは「いま表示しているターン」の最後の行だけ**（吹き出しは
    そのターンのぶんしか描かないため）。ログは全ターンぶんを並べるが、印は表示中のターンの
    最後の行にしか付かない
  - **ログの行はどのターンのものでも押せる**。表示中のターンと違うターンの行を押すと、
    立ち絵の表情はそのセリフに合わせて変わるが、吹き出しの並び（表示中のターンのぶんだけ）には
    印が付く行が無くなる——ログは会話全体を読み返す窓、吹き出しは「いま」の窓という役目の違いを
    そのまま残した
- **吹き出しに出るのは `speak` で来たセリフだけ**（2026-09-17 決定）。**ツールを実行している
  間だけ「作業中の一言」を重ねる案は採らない**（表情の自動の上書きと一緒に撤去した。4.3）
- **尻尾の向き**: 立ち絵は左にいるので、**尻尾は吹き出しの左辺から真横（左）へ出し、先端を左に
  向ける**（2026-09-13 決定）
- **許可と質問**: **キャラが聞く**（2026-09-11 決定）。吹き出しに「これ実行していい？」と出て、
  答えるのは画面の口。押すと答えが `canUseTool` の戻り値として SDK へ返り、口は消える。
  **許可モード**（毎回聞く／編集は自動／全部許す／プラン）も画面から切り替えられる。
  **許可要求も質問（`AskUserQuestion`）も、同じ形の札「お伺い」にして、メインビューの作業の地図の
  今の段の席に出す**（2026-10-02 決定。形・寸法・キー操作は `docs/architecture/screen-design.md` 13.13「お伺い」）。
  それまでは許可要求が入力欄の上の箱、質問がメインビューの札と2か所に割れていて、許可を待つあいだ
  送信ボタンと許可のボタンが主役を取り合っていた（旧い形は `docs/history/decision.md`「display.md 4.2
  各表示物（許可と質問の置き場・メインビューはレポートだけ・入力欄の経過時間と API の知らせ。2026-10-02 に覆した記録）」）。
  **実物はまだ旧い形**で、下の条のうち札の見た目を言うものは質問の札のいまの形。移し終えたらこの但し書きを消す。
  許可要求は対象の全文と選択肢「1 許可」「2 拒否」を持つお伺いになり、選択肢の決まりは質問と同じ番号つきの
  カードに揃える。お伺いにフォーカスがあるときだけ、1〜9 で選び Enter で進む:
  - **札はいまのやり取りのレポートの下**に出し、枠と地は答え待ちの色（`--state-warn`）の系統。
    頭に「質問」のチップと `header`、右端に「n / N」（何問目か）。**過去のやり取りを見ている
    間も札は消さず**、いまのやり取りへ戻る口を添える
  - **選択肢は横に並べたカード**（丸い選択の印・太字のラベル・説明）。**選んだカードは枠が
    `--state-warn`** になる。幅が足りなければ折り返す（狭い画面では1列になる）。
    **ラベル末尾の `(Recommended)` は「おすすめ」のバッジにして字からは外す**
    （SDK へ返す答えは元のラベルのまま）
  - **自由入力は入力欄が担う**（2026-09-23 決定。札の中の自由入力の欄は無くした）。質問が
    出ている間、入力欄は上に帯「↑ <キャラクター名> が質問しています。上の選択肢から選ぶか、
    ここに書いて答えてください」を出し、プレースホルダは「選択肢以外の答えを書く…」、
    送るボタンの字は「答える」、枠と送るボタンの塗りは `--state-warn` になる。書いて送った字は
    **いま見ている1問の答え**になる（`AskUserQuestion` の "Other" 相当。モデルが選択肢に自由入力を
    含めてこなかったときの受け皿でもあるので、**選択肢の側の「その他」は札に出さない**）
  - **質問が複数あるときは1問ずつ出す**（2026-09-15 決定）。選んでから「これで答える」
    （最後の1問でなければ「次へ」）で進み、**最後の1問を答えた時点でまとめて返す**。
    送る前なら「戻る」で選び直せる（単一選択でも、選んだ瞬間には次へ進まない。札に確定の
    ボタンがあるので、押す前に選び直せるほうが素直）
  - **選択肢は送られた順ではなく、ラベルの辞書順（`localeCompare`）に並べ替えて出す**
    （2026-09-21 決定。並べ替えはブラウザ側で行う（`/` コマンド補完と同じ立場）。質問そのものの並び
    （1問ずつ出す側）はこの並べ替えの対象外）
  - **選択肢に `preview`（Markdown）が付いていたら、その選択肢の説明の下に出す**
    （2026-09-21 決定。**描くのはレポートと同じ経路**で、表・mermaid・chart の
    フェンス・記法の class・同じサニタイズがそのまま効く。`preview` が無ければ何も足さない）
  - **複数選択はチェックボックス**（単一選択は radio）。選んだぶんすべてに印が付き、
    入力欄に書いた答えは選んだラベルの末尾に足す。SDK へ返すときに1つの文字列へ畳むのは
    `src/server/session-driver/core/pending-answer.ts` だけの仕事にした
  - **答えた質問は、そのやり取りのメインビューに「何を聞いて、どう答えたか」の記録として
    残す**（2026-09-16 決定。答えが確定した時点で1回だけ積み、あとから書き換えない。
    答えずに終わった質問は残さない）。**自由入力の答えは選択肢の下に別の行で出す**
    （選択肢のどれとも一致しないため）。**見返せるのは直近のターンの札に限る**
    （`MAX_MAIN_VIEW_TURNS`。それより古いぶんは画面から落ちる）
- **メインビュー**: **ターンの局面ごとに、迎える口 / 作業の地図 / レポートを出し分ける**（2026-10-02 決定。
  局面の判定・入れ替える瞬間は `docs/architecture/screen-design.md` 13.13）。
  **本文として出すのは確定したレポートだけ**で、作業の地図は本文ではない（作業の**進行**——いま何をしているか、
  その依頼で実行中／終わった手順の一覧、失敗したツールの引数・出力——を、働くあいだメインビューで見せる一覧。
  2026-09-11 からは「レポートだけを出し、進行は帯の「いまの作業」が持つ」だった。実物は出し分けの器まで移したが、
  作業の地図の席にはまだレポートの札を出している）。
  **ツールの実行は種類を問わずレポートに出ない。** ツールの記録から描くのは質問の記録と、レポートの札の
  末尾に畳んで残す作業の地図だけ。
  **レポートは `report` ツールで受け取る**（2026-09-24 決定）。`report` が1つでも呼ばれたターンは、
  最後の呼び出しを最終レポート、それより前を中間レポートにし、`report` の外に書いた本文は出さない。
  **段を進めた `work_plan` の段のまとめも中間レポートになり**、その後ろに段の知らせの1行が付く（上の
  「段取り」の「段が移ったときの中間レポートと段の知らせ」）。
  **最終レポートの札（ラベル・地の段上げ）は、いちばん新しいやり取りではそのやり取りが閉じている
  （ターンが動いておらず、背景のタスクも残っていない）ときだけ立つ**（2026-09-26 決定）。ターンが
  終わって本文が確定扱いになっても、背景のタスクを待つあいだや、通知で claude が続きのターンを
  自分で始めたあいだは、次の `report` でいま最後の本文が中間レポートへ回るかもしれない——確定して
  いないものに札を立てない。閉じるまでは中間レポートの枠にもせず、素の本文のまま出す。
  **ラベル（「中間レポート」「最終レポート」）は結論部の目録の1行の頭に置く**（2026-09-30。上の
  「タスクの作業のレポートは、結論部を「目録の1行・見出し・一文」の3段にする」）。最終レポートの
  ラベルは、中間レポートのあるやり取りか、本文に `task` があるときだけ出す。畳んだ中間レポートは
  `<summary>` がラベルと先頭行（段のまとめなら終えた段、`task` があれば結論。結論が空なら作業の名前）を持つので、目録の1行にはラベルを置かない。
  **`task` のある中間レポートの先頭行に作業の名前を使わない**（2026-10-01 決定）。同じ作業の中間レポートが

  **タスクIDは押すと実行を頼める**（2026-09-23 決定）: 区画の一覧でIDを押すと

  **押せるのは「着手できる」タスクのIDだけで、それ以外（待ち・保留・進行中・完了・取り下げ）は
  押せない字のまま出す**（2026-09-29 ユーザー決定。待ちのあるタスクを区画から頼めてしまったため。

  黙らせない）。モーダルの中では ID を押しても頼まず、下の帯の「tsukumo に頼む」が同じ確認を開く。
  **画面からタスク（`develop/task/`・Beads）を書き換える口は作らない。**
  件数のチップで絞っているかどうかは表示上の状態なので**保存しない**
  （セッションの間だけ保つ）。

  区画の伸び縮みと内側スクロールは広い画面と同じように働く

  **(3) と (5) の候補は同時に出ない。**

  **入力欄は素の `<textarea>` と、書きながら装飾が見えるマークダウンエディタを切り替えられる**
  （2026-09-26 決定）。エディタは見出し・太字・コードなどにその場で字の大きさ・太さ・色を付け、
  **キャレット（選択範囲）の無い行の記号（`#`・`**`・`` ` ``・`>`・リンクの `(URL)` など）は隠して
  装飾だけを見せ、キャレットのある行では記号を字の色を落として出す**（2026-10-01 決定。2枚並べの
  プレビューでも、記号を打てない WYSIWYG でもない）。コードフェンスはキャレットがフェンスの中に
  あれば開きと閉じの記号を両方出す。箇条書きの印は `•`、引用は行の左の罫で見せ、隠したリンクの
  行き先は字に添える（マウスを置くと出る）。番号付きの印と表は記号のまま。**下書きは1つ**で、切り替えても書いた字・キャレットの位置・添えた
  画像はそのまま残る。**Enter で改行・Command+Enter で送信・`/` と `@` の補完・画像の貼り付けと

  モードは利用者の端末に覚え（`localStorage`）、既定は `<textarea>`。**エディタの面にだけ、面の
  上に書式のボタン**（太字・斜体・取り消し線・コード・リンク・箇条書き・引用）**の行が出る**。
  選んだ範囲を Markdown の記号で囲み（行の書式は行頭に付ける。範囲が無いときは記号の対だけ入れて
  間にキャレットを置く）、書式のキーは付けない。**範囲を選んで `http://` か `https://` の URL を

#### タスクのモーダル（2026-09-28 決定）

サイドバーの「一覧を見る」で開くモーダル。**左に一覧、右に選んだタスクの詳細**（本文を Markdown で
描く）の2列で、**形は見本2枚が正**（`docs/history/mockup/task-board-2026-09-28/` の
`TASK-1-List.dc.html`・`TASK-2-Jump.dc.html` と同名の `.png`。見本の中のタスクの文言はダミー）。
寸法・色・狭い画面の並びは `docs/architecture/screen-design.md` 13.12。ここには中身とふるまいを置く。

- **本文の出どころ**: タスクの本文は**一覧の要約と一緒に届ける**（選んだときに取りに行く口は作らない）。
  見回りが読んだものから作るので、一覧と本文の新しさがずれず、検索が本文まで引ける。
  ファイル方式は `main` の `develop/task/<ID>.md` の front matter より後ろ（見回りがすでに全文を読んでいる）。
  Beads 方式は課題の `description`・`acceptance_criteria`・`notes` を `task show` と同じ順
  （task-workflow の `beads.py` の `compose_body`。枠の節の順で、`## 完了条件` と `## やること` を
  差し戻す）に組んだもの。`## 結果` は Beads の comment にあり `bd list` に載らないので出さない。
  `bd list` は `--brief` を外しても1回の時間は変わらない（2026-09-28 の手元で 67件・約0.4秒、出力は
  48KB → 273KB）ので、見回りの間隔は変えない
- **並び**: 一覧に載る範囲はサイドバーと同じ（Beads 方式の閉じた課題は新しいほうから10件）で、
  並びは**ID の順**（進行中を先頭へ寄せない。完了も混ざる）。行は1段目に ID・状態・ループの印・
  難易度、2段目に要約（2行で省略）。済んだ行（`done`・`dropped`）は薄く出す
- **状態の言い方**は一覧の行・詳細の情報の表・つながりの札で同じにする。`todo` は依存から計算して
  「着手できる」か「待ち」（まだ済んでいない依存の ID を必ず字で添える。`task-workflow` の
  `status.py` と同じ規則で、一覧に無い依存はアーカイブ済みとして止めない）、`hold` は「保留」
  （済んでいない依存があれば ID を添える）、`doing` は「進行中」（着手した作業ツリーの名前が分かれば
  添える）、`done` は「完了」、`dropped` は「取り下げ」、想定外の値は注意色〔`--state-warn`〕の「!」と
  値のまま。**色だけで伝えない**（印の形と字が言う）
- **ループの印は `loopable` が `Y` の行だけに出す**（2026-09-16 の「`N` は空欄」の理由のまま。
  全行に印が並ぶと `Y` が埋もれる）。**難易度**は点3つのうち haiku 1・sonnet 2・opus 3 を塗り、
  名前も添える（点の数と名前が言う。色で分けない）
- **見出しの帯**: 「タスク」・件数・キーの案内（`↑↓` 選ぶ・`Esc` 閉じる）・閉じるボタン。件数は
  サイドバーの件数のチップと同じ数え方（進行中・未着手〔`todo`〕・完了〔`done`〕。`taskListCounts`）
- **絞り込みの札**: すべて・着手できる・待ち・保留・進行中・完了の6つで、それぞれに件数を添える。
  1つだけ選べ、既定は「すべて」。「着手できる」と「待ち」はサイドバーの「未着手」（`todo`）を
  着手できるかで2つに割ったもの、「保留」は `hold`、「進行中」は `doing`、「完了」は `done` だけ
  （サイドバーの「完了」と揃える）。**`dropped` と想定外の値はどの札にも属さず、「すべて」でだけ出る**
  （サイドバーの「想定外の status は何も選んでいないときだけ出る」と同じ規則）。サイドバーで選んでいる
  チップはモーダルへ持ち込まない
- **検索**: 引くのは **ID・要約・本文**（大文字小文字を区別しない部分一致。絞り込みの札と組み合わさる）。
  ファイル名はタスクの ID をそのまま名前にしているので別には引かない（案内の文言は「ID・言葉で探す」）。
  ID の形を決め打ちしない（`T-` も `GH-` も同じ部分一致で当たる）。絞った結果が0件なら一覧に
  「当てはまるタスクが無い」と出し、詳細は空にする
- **開いたときの選択**: 開くたびに検索は空・絞り込みは「すべて」・選択は一覧の先頭の行から始める。
  サイドバーに「見ていたタスク」の状態は無い（区画の ID を押すと頼む確認が開くだけ）ので、見本の
  「サイドバーで見ていたタスクを選んだ状態にする」は持たない。**開いている間に一覧が届き直しても**
  選んでいるタスクが一覧に残っていれば選択を保ち、消えていれば先頭の行へ移る
- **キー操作**: ↑↓ で行を移ると詳細がすぐ切り替わる。Esc・閉じるボタン・モーダルの外側のクリックで
  閉じる（`<dialog>` の `showModal()` に任せ、フォーカスは開く口へ戻る）。行を押すと選ぶだけで、
  頼まない
- **詳細**: ID と status の生の値・タイトル（要約）・情報の表（着手・難易度・ループ・置き場所）・
  本文。**置き場所の行はタスクの置き場で変わる**: ファイル方式は「ファイル」に
  `develop/task/<ID>.md`、Beads 方式は「Issue」に課題の `external_ref`（`https://` で始まる URL の
  ときだけ。無ければ行ごと出さない）。依存を1つでも持つタスクは**本文の上に「先に終わっていてほしいもの」
  の札**を依存ごとに並べる（ID・状態・要約。一覧に無い依存は ID に「一覧に無い」を添え、押せない）
- **本文中の ID の自動リンク**: 本文の地の文と、中身がまるごと1つの ID の inline code のうち、
  **いまの一覧に載っている ID と字面が一致するもの**だけを押せる字にする（語の途中は当てない。
  フェンスの中は当てない）。ID の形の正規表現は持たない——一覧が知っている ID だけを当てるので、
  `T-xxx` から `GH-<n>` へ移っても（移行の途中で混ざっても）そのまま当たり、一覧に無い ID
  （閉じて一覧から落ちたタスク）は押せない字にならない
- **本文の描き方**: レポートの描画（`markdown.tsx`）は流用せず、タスクのモーダルが専用に持つ。
  使うのは `react-markdown` と `remark-gfm`・`remark-cjk-friendly` だけで、**生の HTML は解釈しない**
  （字のまま出す）。描くのは見出し・段落・箇条書き・番号・チェック（静的な印。押せない）・
  inline code・フェンス（色付けしない）・表（横に溢れたら表だけ転がす）・リンク（`http(s)` だけ
  新しいタブで開き、それ以外は字のまま）。レポートの記法（`note` などの class）・mermaid・Chart.js・
  パスを押すとエディタで開く部品は持たない。流用しないのは、置かれる機能（`features/`）が
  会話の画面の部品を import できず（`docs/architecture.md`「領域の機能と、置かれる機能」）、

### 4.2 表示

#### 出力の分離（セリフと詳細）

**1つのターンを「セリフ」と「詳細（レポート）」に分け、別々の領域に出す。** 同じ内容が2箇所に
出ると、キャラクターとのやり取りがノイズに埋もれる。

**セリフは MCP ツール `speak(text, expression)` で受け取る**（2026-09-11 決定）。

- tsukumo がプロセス内の MCP サーバとして `speak` を提供し、モデルが呼んだらその `text` を
  吹き出しに出す。`expression` はキャラクター定義にある表情名から選ぶ（4.3）
- **戻り値は `"ok"` だけ**にする。ツールの結果はモデルの文脈に戻るので、ここに情報を載せると
  tsukumo からモデルへの逆流路ができる。**例外は `recall` / `recall_episode`（雑談と仕事の両方）と、仕事の
  `report` の3つ**。`recall` / `recall_episode` が返すのは tsukumo の状態ではなく**その会話自身の
  過去**（4.9「古い雑談は索引を引いて思い出す」、2026-09-25 に2段階へ組み替えた）。`report` が
  返すのは、差し戻すときの**規約違反とその直し方だけ**で、
  描けたか・どこに出たかといった画面の状態は載せない（2026-09-23 ユーザー決定。レポートの出力を
  「検査 → 整形 → 描画」に分けた検査の段。検査するのは「レポートの記法」の条のうち機械で判定
  できるものだけで、差し戻すのは1ターンに1回まで。同じターンで受け取った `report` と同じ引数の
  送り直しも、固定の一文で別に1ターンに1回まで差し戻す。直前に描いた `report` のあとに、新しい依頼・
  メインが呼んだツールの結果・背景のタスクの終わりのどれも届いていない `report` も、新しい事実の無い
  言い直しとして固定の一文で別に1ターンに1回まで差し戻す（文面の近さでは判定しない。サブエージェントの
  合図は `speak` で言い直すもので、流れにも見えないので数えない）。段取りの閉じていない `report` も別に差し戻す
  （下の「段取り」の「段取りの閉じていない `report` を差し戻す」）。`src/server/report/core/report-review.ts`）。
  **2026-10-06 に、文字の並びで判定できる条を検査に足した**: `conclusion` の1文目が全角50字超
  （`long-first-sentence`）・見出しが30字超か疑問文（`bad-heading`）・`checks` の `figure` の分数
  （`fraction-figure`）・地の文と表のセルの `A → B`（`arrow-in-prose`。インラインコードの中・`from` / `to`・
  `flow` は通す）・`list` の項目の頭の「名前: 説明」（`label-in-item`。URL・時刻・インラインコードの頭・
  20字を超える頭は通す）・仮名も漢字も無く英語の語が3つ以上の地の文と見出し（`non-japanese`。インラインコード・
  リンク・パスは数えない）。`checks` の素の文字のバッククォートは差し戻さず、整形で外す
  **2026-10-03 に、仕事の `speak` を4つ目に足した**（ユーザー決定「仕組みで解決する」）。返すのは新しい事実の無い呼び出しを差し戻す固定の一文だけ
  （下の委譲の箇条）。**5つ目を足すにはユーザーの決定が要る**
- **検査を通った `report` の本文は、描く前に整形する**（同じ決定の整形の段。
  `src/shared/report/report-tidy.ts`）。落とすのは**落としても意味が変わらないものだけ**で、言い換え・
  要約・並べ替えはしない: 本文の冒頭で `conclusion` を繰り返しているもの（冒頭の `text` の塊か、
  逃げ道の頭の行）・前置きと締めの定型だけの `text` の塊と逃げ道の行（閉じた一覧との丸ごとの一致。
  型で当てると中身のある行まで黙って消えるので置かない）・逃げ道の中の中身の無い見出し・
  塊が残らなくなった節。**分担の基準は「直すのに書き直しが要るか」**——要るもの（段落を表へ移す・
  結論を短くする）は検査が差し戻し、消すだけで直るものは整形が黙って落とす。同じ条を両方には
  置かない。**記録は引数のまま持ち、メインビューの導出（`src/shared/session/main-view.ts`）で掛ける**ので、
  規則を変えると過去のやり取りと、セッションの復元で組み直したやり取りにも効く。**空行の連続は
  詰めない**（CommonMark でも本文を塊に割る側でも1つの切れ目と同じに描かれ、フェンスと HTML の
  塊の中では中身なので、落としても見え方が変わらない）。`report` の無いやり取りの本文には掛けない
- **呼ぶ頻度・契機・セリフに入れる中身は tsukumo 側が持つ**（2026-09-16 決定。書く場所は
  `src/server/system-prompt/core/speech-cadence.ts` の `SPEECH_CADENCE_PROMPT`）。回数は数で縛らず契機で言い、
  ツールを走らせる前に1回、その結果で分かったことがあればもう1回。セリフの中身は
  **「いま何をしていて、そこでどう感じているか」**が分かるものにする（ユーザーへの問いかけを
  増やすのではない）。**どのパックでも吹き出しが長く止まらない**ことは tsukumo 全体の体験なので、
  パックの `persona.md` には書かない（パックが決めるのは口調・言い回しだけ）。
  tsukumo は呼ばれたら出すだけで、判定に推測が要らない
- **サブエージェントへの委譲は背景で行い**（2026-09-16 決定）、tsukumo が `PreToolUse` の `updatedInput` で
  メインの `Agent` 呼び出しの `run_in_background` を `true` に固定する（書き忘れても差し戻さず、`prompt` など他の引数には
  触らない。サブエージェント内の呼び出しは対象外。`src/server/session-driver/core/background-delegation.ts`）。進み具合をサブエージェントからの
  合図（`状況 | …` の1行）で受け取ってメインが `speak` で言い直す（帯の段は合図ではなく、返却を受けたメインの `work_plan` で進む。下の「段取り」）。フォアグラウンドの委譲は
  ツール呼び出しの中でメインを止め、吹き出しが数分単位で止まるため。**合図（進み具合の1行か、
  委譲の完了の知らせ）の届いていないターンでは `speak` も `report` も呼ばない**（2026-09-27 決定）。新しい事実の無いセリフの言い直しを防ぐため。
  **条だけでは守られなかったので、仕事では仕組みで止める**（2026-10-03 ユーザー決定）:
  直前に描いたセリフのあとに新しい事実が届いていない `speak` は、handler が `isError` で差し戻し、
  吹き出しに出さない（新しい事実が届くまで毎回。差し戻しの一文は `src/server/session-driver/core/speech-review.ts` の1か所）。
  新しい事実に数えるのは `report` の差し戻しと同じもの（依頼・メインのツールの結果・背景のタスクの終わり）と
  ターンの頭（合図や完了の知らせで claude が自分で始めたターンを含む）で、`speak` 自身・`work_plan`・差し戻した呼び出しは
  数えない。雑談では差し戻さない（1ターンに `speak` を何度か呼ぶのが普通の形）。
  Claude Code 本体は `speak` を利用者に見える出力に数えず、`speak` だけのステップが続くと
  "The user hasn't heard from you in a while" をターンの途中に差し込んで言い直しを誘うので、子プロセスに
  `CLAUDE_CODE_SILENT_TURN_REMINDER=0` を渡して切る（`src/server/session-driver/core/visible-output-nudge.ts`。仕事・雑談の両方）
- **レポートは MCP ツール `report(task, conclusion, checks, sections, favor, closing, waitingLine)` で受け取る**（2026-09-24 決定。
  `checks` は 2026-09-26 に、`closing` は 2026-09-27 に、`task` は 2026-09-30 に、`waitingLine` は 2026-10-05 に足し、本文は 2026-09-27 に文字列の `body` から
  `sections` に替えた。
  仕事のセッションでは常に載り、雑談では載らない）。**検査を通った `report` はそこでターンを閉じる**
  （2026-09-27 決定。handler が結果に `_meta["claude/endTurn"]` を付け、本体は assistant を挟まずに
  ターンを終える。差し戻した呼び出しには付けないので、モデルは直して呼び直せる。
  `docs/research/report-block.md` 13章）。`report` のあとに本文を書き足す形が起きないので、
  **締めのセリフは必須の引数 `closing`（`speak` と同じ `text` と `expression`）で受け取り**、
  レポートを描いたすぐ後ろに吹き出しへ出す（差し戻した呼び出しの `closing` は出さない）。
  **必須の引数 `sessionSummary` にはセッション全体の要約を毎回書き直して入れる**（2026-09-27
  ユーザー決定。2026-10-06 に schema で必須にした。中立の文体で2〜3段落・1200字以内、残っていることは「残り：」の段落）。レポートには
  描かず、セッションの切り替え画面が transcript の最後に通った `report` から読み戻す
  （`docs/architecture/screen-design.md`「切り替え画面」）。tsukumo は要約を別の場所へ書き出さない（transcript の
  ツールの入力に残るだけなので、`docs/coding-standards.md`「会話内容の扱い」の例外を増やさない）。
  書き方は引数の説明が持ち、毎回入れることは schema（必須）が持つ。任意の `title`（セッション一覧の
  見出し）と同じく差し戻した呼び出しの値は使わない。
  **必須の引数 `waitingLine`（待ちの一言。`closing` と同じ `text` と `expression`）には、依頼を待つ間に
  1回だけ吹き出しに出す一言を毎回書かせる**（2026-10-05 利用者決定。2026-10-06 に schema で必須にした。出す条件は下の「機械の出来事への反応」の6）。
  記録を読み戻す側は、必須にする前の記録のために欄が無いものも読める。
  `report` の記録に写り、transcript から組み直しても同じ値が戻る
  ターンの途中の経過は `speak` で言う。雑談には使わない（`report` が無く、1ターンに `speak` を
  何度か呼ぶのが普通の形なので、閉じるツールを置くと切れる）。`report` の外に書いたターンの本文

  - 突き合わせはメインビューの組み立て（`main-view.ts`）で描くたびに行い、所要時間を記録には持たない。

#### 段取り

**作業中に「いまどの段にいて、あと何が残っているか」を画面で追えるように、claude から段取り（段の並びと
今の位置）を MCP ツール `work_plan` で受け取る**（2026-09-29 ユーザー決定。用語は `docs/glossary.md`
「段取り」「work_plan ツール」）。`progress` の塊は `report` を渡したときにしか出ず、依頼の手順は
ツールの実行を1回ずつ並べるだけなので、作業中の段は今まで見えなかった。Claude Code の TodoWrite を
拾う案（使うかどうかも項目の粒度も tsukumo から縛れない）と、ツールの手順から段を推し量る案
（推測になる）は採らない。

- **入力は `{ phases, current, finishedInGroup, phaseSummary }` で、毎回段の並びごと渡す**（tsukumo が前の並びを覚えて
  位置だけを動かす呼び出しは作らない。`phases` を省く呼び出しも作らない）。`phases` は1つ以上の要素の並びで、要素は段の名前か
  段のまとまり（同時に走る段の名前の配列。下の「同時に走る段は、段のまとまりで受ける」）。空白だけの名前は不可。
  `current` は0始まりの要素の位置で、全部済んだら要素の数。`finishedInGroup` は今のまとまりの中で済んだ段の名前で、省けば空。
  `phaseSummary`（段のまとめ）は下の「段が移ったときの
  中間レポート」。1本道の段取りは `{ phases: string[], current, phaseSummary }` のまま渡せる。形は zod の形が、`current` が要素の数を超えた呼び出し・段のまとめの足りない
  呼び出しは `parseWorkPlan`（`src/shared/session/work-plan.ts`）を通して `WorkPlanReview` が差し戻す。変換（`sdk-message.ts`）も
  呼び出しの形を読めたメインの呼び出しだけを `work-plan-called` にし、サブエージェントの
  呼び出しは捨てる。戻り値は `"ok"` で、ターンは閉じない。**仕事のときだけ載る**
- **段は1つずつ進める**（2026-10-04 利用者の決定）。同じ依頼の中で同じ段の並びのまま、済んだ段（並びを平らにして数える）を
  1回で2つ以上増やした呼び出しは `WorkPlanReview`（`src/server/session-driver/core/work-plan-review.ts`）が差し戻す。飛ばした段は
  段のまとめを持たず、中間レポートがその段だけ抜けるため。覚えるのは同じ依頼で最後に受け付けた段取りだけで、
  依頼で忘れる。委譲中も段を動かすのはメインの呼び出しだけなので、同じ決まりがそのまま効く。
  変換は呼び出しの id を付けた `work-plan-called` を出し、`WorkPlanReview` が結果まで預かって差し戻されたものを捨てる
  （transcript から組み直すときも同じ）。これに伴い、上の「前の並びを覚える状態が要らない」は差し戻しの判定にだけは当てはまらない
- **同時に走る段は、段のまとまりで受ける**（2026-10-07 利用者決定。用語は `docs/glossary.md`「段のまとまり」）。並列にできるかを決めるのは
  段取りを渡す側で、tsukumo は段の並列を推し量らず、受けて描くだけ。口の形はスキルの書式（`## やること`・返却の1行目・`tw`）に依存しない
  - **形**: まとまりは `phases` の1要素で、2つ以上の段の名前を重ならずに並べる。段の番号は並びを平らにした読み順で振る
    （`[A, [B, C], D]` なら B が 2、C が 3）。「段ごとに、どの段のあとに走れるか」を持たせる形は採らない（位置が1つの数で言えず、
    1本道の段取りの形も変わる）
  - **今の段の集合**: `current` の要素が段ならその1つ、まとまりならその中で `finishedInGroup` に無い段のすべて。
    `finishedInGroup` はまとまりを指していないときは空で、まとまりの段を全部入れることもできない（全部済んだら `current` を進める）
  - **済ませ方**: メインはまとまりの中の段を1つ済ませるたびに、その名前を `finishedInGroup` に足して `work_plan` を呼ぶ。
    まとまりの最後の段を済ませる呼び出しは `current` を1つ進め、`finishedInGroup` を空に戻す。委譲先がどの順で返っても、メインが
    済んだ段を名指すので、後ろの番号から済んでも帯は戻らず取りこぼさない。委譲の返却は今までどおり読まない（ADR 0024）
  - **一足飛びの判定**は、平らにした並びで済んだ段の数で行う（上の「段は1つずつ進める」）。まとまりに入る呼び出しで、同時に中の段を
    済ませたことにすると2段増えるので差し戻す
- **段はファイル単位・操作単位で切らず、作業のまとまりで切る**（2026-09-29 ユーザー決定）。この粒度は
  ツールと引数の説明で伝える（仕事の append の節「段取り〔tsukumo〕」〔`WORK_PLAN_PROMPT`〕には重ねない）。委譲中もメインが渡した段で切る（下の「委譲中も、段はメインが返却を受けるたびに `work_plan` で進める」）
- **呼ぶ条件は条として書き、差し戻しでは縛らない。** 条は「作業をするターンは段の数にかかわらず呼ぶ。
  作業のまとまりが1つなら1段の段取りを渡す（札には `1/1` のように出る）。答えるだけ・1回調べて答える
  だけの依頼では呼ばない」（2026-09-30 ユーザー決定）。機械で縛れるところは機械に寄せた（雑談では
  載らない・0段の段取りは形の検査が受け付けない）。呼ばなかったことはターンの終わりにしか判定できず、
  そこで差し戻すと着手時に渡すはずの段取りを後から書かせるだけになる。呼ばなくても札と一覧はいままでの
  表示のままで壊れない
- **委譲中も、段はメインが返却を受けるたびに `work_plan` で進める**（2026-10-07 利用者決定。境界は
  `docs/architecture/adr/0024-no-skill-dependency.md`、用語は `docs/glossary.md`「委譲の返却」）。
  tsukumo は委譲の返却（`SubagentHandback`）の中身も書式も読まない。返却の書式は委譲を回す側（スキル）が決めるもので、
  tsukumo が読むとスキルに依存する
  - **並びはメインが `phases` で渡す。** 「計画」「受け入れ」を段にするかも渡す側が決め、tsukumo は並びの形を前提にしない
  - **メインは返却を受けたら、返却の中身から段のまとめを書いて `work_plan` で1段進める**。次の段を委譲先へ送るのは
    メイン自身なので、返却の直後には必ずメインのターンがあり、帯はそこで進む。返却からのずれはメインが返却を読んで
    呼ぶまでの数秒で、段の時間の区切りは前後とも同じだけずれる。1回の返却で2段以上済んだら、段ごとに呼ぶ
    （上の「段は1つずつ進める」）。受け入れを済ませたら段の閉じ方が `finished` の `report` を渡す（`WORK_PLAN_PROMPT`）
  - **組み直しでも委譲中の段が戻る**。メインの `work_plan` はメインの transcript に残り、ほかの呼び出しと同じく
    `WorkPlanReview.pass` を通る
  - **委譲先の `SendMessage` の合図は帯を動かさない**（2026-10-06）。合図は吹き出しの途中の一言として残し
    （`SPEECH_CADENCE_PROMPT`）、tsukumo は読まない。背景のタスクの顔ぶれの変化も帯を動かさない
  - **採らなかった形**: 2026-10-03〜10-05 は委譲先が `SendMessage` で送る合図から段取りを引き直していたが、
    合図の番号で何段でも飛び、合図が来ないと帯が止まった。2026-10-06〜10-07 は返却の1行目の段の番号で位置を決め、
    着手したタスクの本文の段から並びを作っていたが、どちらもスキルの書式を読む形で、返却で進めた段は組み直しで
    戻らなかった（経緯は同じ ADR）
  - **防げないこと**: メインが返却を受けたのに `work_plan` を呼ばないと帯が止まる（条で頼み、差し戻しでは縛らない。
    呼ばなかったことは次の呼び出しか `report` の段の閉じ方でしか分からない）
- **段を閉じるのは `report` の欄 `workPlanClosing`（段の閉じ方）で、最後の段は tsukumo が閉じる**（2026-10-06）。
  それまでは「全部の段を終えたら `report` と同じ応答で `current` に段の数を渡す」を条で頼むだけで、呼び忘れると
  帯が最後の段の「今」のまま止まり、止めたのか閉じ忘れたのかを記録から見分けられなかった。済ませたか止めたかの
  判断はモデルが書き、書き忘れは差し戻しで落とし、閉じる操作は tsukumo が受け持つ
  - **欄は `finished`（全部の段を終えた）か `stopped`（途中で止めた）**。`task.outcome` を広げる案は採らない
    （タスクの `report` にしか無く、タスクに紐付かない作業のターンを覆えない）。帯を閉じるときに読むのはこの欄だけで、
    `task.outcome` は目録の1行の終わり方のまま帯には使わない
  - **`finished` の `report` を受け付けたら、同じ依頼の最後の段取りを `closedByReport` で閉じる**。閉じるのは最後の
    段にいるときだけで、`current` を段の数にした `work-plan` の記録を `report` の記録の直前に積む（同じ時刻を持つ）。
    段が2つ以上残っている・全部済みの位置からは動かさない（帯は1回に1段しか進めない）。`stopped` では積まず、止まった段が
    「今」のまま残る。`WorkPlanReview` も同じ決まりで覚えた段取りを閉じる。差し戻されなかった `report` だけが
    イベントとして流れるので、閉じるのはイベントの側で、transcript から組み直すときも同じ変換を通って閉じた帯が戻る
  - **`work_plan` で `current` に段の数を渡す呼び出しは受け付けたまま残す**（組み直した古い transcript と、メインが自分で
    閉じた呼び出しを壊さない）。閉じたあとの `finished` は残りが 0 なので何もしない。条と引数の説明からは、`current` に
    段の数を渡す頼み方を外した
- **段取りの閉じていない `report` を差し戻す**（2026-10-06 利用者決定。`ReportReview`。`src/server/report/core/report-review.ts`）。
  `report` を通すとターンが閉じ、差し戻しに応える番が来ないため。段取りの立ち位置は `WorkPlanReview.standing`
  （`WorkPlanStanding`）から読む
  - **同じターンで差し戻した `work_plan` にまだ応えていない `report`**: 受け付けた `work_plan` の呼び出しがあれば
    応えたことになり、通る。差し戻しの覚えはターンの区切り（`session-info`・`turn-finished`）で戻る
  - **段の閉じ方が合わない `report`**: 同じ依頼に段取りがあるときだけ見る。欄が無い（全部済みのあとでも）・
    `finished` なのに段が2つ以上残っている・`task.outcome` が `finished` なのに `stopped` で段が残っている、の
    どれかなら差し戻す。残りは同じ依頼で受け付けた最後の段取りで数える。段取りの無い
    依頼では欄が無くてもあっても通す。それまでの「`shipped` なのに段が残っている」の差し戻し（タスクの `report` にしか
    効かなかった）はこれに置き換えた
  - **枠の数え方**: 応えていない `work_plan` と段の閉じ方でそれぞれ1ターンに1回まで（段の閉じ方の3つは1つの枠を
    共有する）で、使い切ったら通す（無限に往復させない）。規約違反・送り直し・新しい事実の無い呼び出しの枠とは
    分けて数える。規約違反と枠を共有すると、記法の差し戻しで枠を使ったターンでは段の閉じていない `report` が
    そのまま通り、差し戻しに応える番が来ないまま閉じるため。見る順は、送り直し → 新しい事実の無い呼び出し →
    応えていない `work_plan` → 段の閉じ方 → 規約違反
  - **防げないこと**: handler はメインとサブエージェントの呼び出しを見分けられないので、委譲先が `work_plan` を
    呼んで差し戻されると、メインの `report` が1回差し戻されることがある（`report` のほかの差し戻しと同じ制約）。
    済ませたのに `stopped` と書く・止めたのに `finished` と書く取り違えは見分けない（判断はモデルに残す）
- **段を進める `work_plan` と、その契機の `speak` は同じ応答の中で並べて呼ぶ**（段が変わるのは論点が
  切り替わるときで、`SPEECH_CADENCE_PROMPT` の契機に当たる。別々の応答にすると往復が1回増える）
- **出す場所は3つ**: いまの作業の札（今の段の名前と位置。会話の画面以外）と依頼の手順の一覧の頭（全部の段と、段ごとに
  区切った手順）は `docs/architecture/screen-design.md`「いまの作業」。会話の画面では、札と一覧の頭の代わりに
  メインビューの上端の進み具合の帯が段の並びと状態のチップを持ち、レポートを読むあいだも済んだ姿で残る（同 13.13「進み具合の帯」）。
  **最終レポートと中間レポートには段取りを描かない**（2026-10-02 ユーザー決定。帯と同じことが2か所に出る。
  旧い形は `docs/history/decision.md`「screen-design.md 13.13 作業の地図・会話の画面の浮かぶ札・レポートの進み具合
  （2026-10-02 に覆した記録）」）。同じ依頼に段取りがあれば、整形が `progress` の塊を落とす（`tidyReportSections`。判定は「同じ依頼に段取りがあるか」だけで、段の名前は照らさない）。
  3つ目はメインビューの段の移り（次の項）。段の並びの代わりに、最終レポートには段ごとの所要時間の横棒グラフを置く（次の項）
- **段ごとの所要時間は、tsukumo が記録の時刻から求めて最終レポートに横棒グラフで描く**（2026-10-05 利用者決定。
  モデルに書かせると書き忘れと、測っていない数が混じる。表から横棒グラフにしたのは 2026-10-07 の利用者決定で、
  どの段に時間がかかったかを長さの比で一目で見るため）。`report` の引数は増やさず、モデルに時間を書かせる欄も作らない
  - **時刻は記録が持つ。** `work-plan` の記録（`finished` の `report` で tsukumo が閉じたものも）と `report` の記録が、届いたイベントの時刻
    （`RecordTime`）を持つ。復元した記録は transcript の時刻が読めれば `recovered`、読めなければ `restored`（不明）になる
  - **求め方**（`phaseDurations`。`src/shared/session/phase-duration.ts`）: 段 n の時間は、n が今の段の集合に入った記録の時刻から、
    集合を出た記録の時刻まで。段のまとまりの段は、まとまりに入った記録の時刻から一斉に始まり、それぞれ自分が済んだ記録の時刻で終わるので、
    重なって走った段もそれぞれの所要が出る。最後まで今だった段は全部の段を終えた記録（`finished` の `report` で tsukumo が閉じたものも）の時刻で閉じ、無ければ `report` を受け付けた時刻で閉じる。
    同じ段に戻ったら測れた区間を足す。読む範囲は最後の依頼より後の記録だけ
  - **段のまとまりの所要は壁時計**: `current` がそのまとまりを指していた区間で、中の段の所要の和ではない。依頼全体の所要は進み具合の帯の
    「所要」が壁時計で持ち、重なった段を二重に数えない
  - **開き直したときも同じ求め方**: 区間の端は記録の時刻だけで、復元した記録も transcript の時刻（`recovered`）を持つので、まとまりの段の区間も
    動いていたときと同じに戻る。端が `restored` なら下の「不明」
  - **棒の長さは、測れた段（とまとまりの壁時計）のうち一番長いものに対する比**（一番長いものが全幅）。時間の字（`formatElapsed`）を棒の横に添える。
    測れない段は棒にしない（次の項目）
  - **段のまとまりは、見出しの行と中の段の行で描く**: 見出しの行は「並列 2·3」とまとまりの壁時計の棒、その下に中の段の行を字下げして並べ、
    どれも同じ左端（まとまりの開始位置）から棒を描く。1本道の段の行は今までどおり。依頼全体の合計の行は置かない（帯の「所要」が持つ）
  - **測れない段は棒無しで「不明」と描き、数を推し量らない**: 一度も今の段にならなかった段（一足飛び）・端が `restored` の区間を含む段・
    依頼の最初の段取りが途中の位置で始まったときのその段より前（前の依頼で始まった段。雑談を挟んだ時間を段の時間に混ぜない）
  - **段取りを組み替えたら、最後の段の並びで描く。** 段は名前と同じ名前の中の何番目かで追うので、並びに残った段は組み替える前の
    時間を引き継ぎ、並びから消えた段の時間はグラフに残さない（依頼全体の時間は進み具合の帯の「所要」が持つ）
  - **置き場は最終レポートの検証の表の下**（合図の行と同じ `status` の包みの中）。段取りの無い依頼では描かない。中間レポート
    （段のまとめ）には、終えた段1つぶんの所要を同じ求め方で添える（次の項）。見た目は `docs/architecture/screen-design.md`「レポートの頭（合図の行）」
- **段が移ったときの中間レポート**（2026-09-30 ユーザー決定）: 段が移ると、メインビューに
  終えた段の中間レポートを出す。段の移り変わりが帯の札の書き換わりにしか残らず、分かりにくかったため。
  働くあいだも渡したあとも、中間レポートはいちばん新しいやり取りの札の本文に出る
  （上端の進み具合の帯の下。`docs/architecture/screen-design.md` 13.13）。
  - **中間レポートの中身は、段を進める `work_plan` の `phaseSummary`（段のまとめ）で受け取る**。
    「終えた段でしたこと・分かったこと」を1〜2文で、記法は `report` の `conclusion` と同じ。`report` に
    「途中」の印を足してターンを閉じない形にする案は採らない（段の切れ目と中間レポートを仕組みで揃える）。
    `sections` まで借りる案も採らない（畳まれる中間レポートに要るのは段の結論だけで、詳しいことは
    最終レポートが持つ）
  - **途中の位置（済んだ段が1つ以上あり、全部済みでない）の呼び出しでは段のまとめを必須にし、無ければ
    差し戻す。3文以上も差し戻す**（`parseWorkPlan`。文の数え方は `report` の結論と同じ `sentenceCount`）。
    段を前へ進める呼び出しは、全部の段を終えたものを除けば必ず途中の位置に着地するので、段が進んだのに
    まとめが無い、は起きない。「前より進んだか」で縛らないのは、`parseWorkPlan` が1回の引数しか見ず、
    handler と変換が同じ関数を通して「差し戻した呼び出しは記録しない」を揃えているため（前と比べて
    差し戻すには、`report` のように結果まで預かる仕組みが変換にも要る）。代わりに、途中の位置で戻る・
    組み替えるだけの呼び出しにもまとめを書かせる（画面には出さない）
  - **中間レポートは、その段でしたこと（段のまとめ）と所要の両方を必ず出す**（2026-10-07 利用者決定）。
    所要は `phaseDurations` が求める終えた段の時間で、モデルには書かせない。測れない所要（`restored` の端・
    依頼の最初の段取りが途中の位置で始まった段）は「不明」と出し、数を推し量らない。
    目録の1行は「中間レポート · 1/3 段の名前 · 所要 12秒」、畳んだ `<summary>` は「中間レポート: 1/3 段の名前 · 所要 12秒」
  - **したことが空のまま段を進める呼び出しは差し戻す。** 途中の位置は上の `parseWorkPlan` が、
    同じ段の並びのまま済んだ段を増やして（最後の段を `work_plan` で閉じる呼び出しを含む）まとめが空の呼び出しは
    `WorkPlanReview` の `empty-summary` が差し戻す。段の並びを組み替えた呼び出しと、戻る呼び出しには掛けない
  - **何を出すかは、同じ依頼の直前の段取りと比べて決める**（`phaseShiftOf`。記録から描くたびに導く）:

    | 呼び出し                                                         | 中間レポート                   |
    | ---------------------------------------------------------------- | ------------------------------ |
    | その依頼で最初の段取り                                           | 出さない                       |
    | 段を進める（前の今の段の1つが、新しい並びで済んだ段にある）      | 出す                           |
    | 戻る・組み替えたが前の今の段は済んでいない（今の段以降・消えた） | 出さない                       |
    | 全部の段を終えた（`current` = 要素の数）                         | 出さない（最終レポートが担う） |

    終えた段は名前と同じ名前の段の中で何番目かで探すので、段を進めながら後ろの段を組み替えても見失わず、同じ名前の済んだ段とも取り違えない。1段だけの段取りは
    `0 → 1` しか取らないので出ない。段のまとまりの中の段は1回に1段ずつ済むので、別々に済めば段ごとに1つずつ中間レポートが出て、
    所要はその段の区間（まとまりに入った時刻から、その段が済んだ時刻まで）

  - **段のまとめの中間レポートは、目録の1行にラベルと終えた段（「中間レポート · 1/3 段の名前」）を並べ**、
    畳んだ `<summary>` にも終えた段を出す。**届いた時点で中間と決まるので、ターンが動いているあいだも
    伏せずに出す**（下の「各表示物」のメインビューの「確定するまで出さない」の例外）。最後の本文・最後の
    `report` の候補にはならない
- **合図の行は1つのまとまり（`status`）に包み、結論・本文とのあいだを空ける**（2026-09-30
  デザイン「レポートの頭の空間 案1」。2026-10-02 に段取りを外した。2026-10-03 に検証結果から合図の行へ広げた）。
  あきは結論→まとまり 14px・まとまり→本文 26px（見本 `report-redesign.html` の値）。最終レポートは箱を
  持たない（下の「各表示物」のメインビュー）。検証の行は左右にはみ出させ、「✓ OK」の左端を本文の左端にそろえる
  （それまでの 28px・44px と最終レポートの札の内側の余白は `docs/history/decision.md`「display.md 4.2 / screen-design.md 13.2
  最終レポートの箱と、常に開いた検証の表（2026-10-03 に覆した記録）」）
- 状態は `work-plan` の記録を届いた位置に積むだけで、今の段取り（`latestWorkPlan`）と手順ごとの段
  （`currentTurnSteps`）は記録から導く。記録の形が増えたので `PROTOCOL_VERSION` を 25 に上げ、段のまとめを
  足したときに 27 に、委譲の合図（`delegate-signal` と記録の `source`）を足したときに 31 に、委譲先の終わり
  （`source` の `delegate-ended`）を足したときに 33 に、記録に時刻（`time`）を足したときに 39 に、合図を委譲の
  返却（`delegate-returned`）に替えて記録の `source` を外したときに 40 に、`report` のイベントに段の閉じ方
  （`workPlanClosing`）を足したときに 42 に、委譲の返却（`delegate-returned`）を外したときに 45 に、段のまとまり（`phases` の配列の要素と `finishedInGroup`）を足したときに 46 に、
  脇の話（イベントと記録の `aside`・セリフの `answersAside`）を足したときに 47 に上げた

#### 脇の話

**委譲中（背景のタスクが残っているあいだ）に入力欄から送った言葉は、新しい依頼にせず「脇の話」として親のやり取りに
吊るす**（2026-10-07 利用者決定。用語は `docs/glossary.md`「脇の話」。見本は `docs/history/mockup/aside-thread-2026-10-07.html`）。
それまでは送った言葉がいつも `request` になり、「いまどう？」の一言でも札が割れて、帯が段取りの無い新しい札に切り替わり、
帯・経過・中間レポートが消えた。委譲中のやり取りは状況の確認や一言の頼みに近い。

- **脇の話かどうかは、サーバが `prompt` を受けた瞬間に機械的に決める**。条件は、仕事のとき（雑談では決めない）・
  サーバの姿の `backgroundTasks` が1件以上・送り方（`PromptRouting`）が `aside-when-background` の3つ。本文は読まない。
  ブラウザが渡すのは送り方だけで、背景のタスクの有無は見ない（駆動が動くのはサーバの姿の上なので、判定もそこで1回だけ行う）。
  入力欄の ⌘⏎ は `aside-when-background`、⌘⇧⏎ は `new-request` で、背景のタスクがあっても新しい依頼として札を割る。
  迎える口・タスクの実行・見直しから送る依頼は送り方を省き、`new-request` になる
- **脇の話は `request` ではない別の出来事と記録 `aside` にする**（`text`・`images`・時刻。ターンの通し番号は持たない）。
  `request` でないので、札の割り方（`splitIntoTurns`）・記録の窓・同じ依頼の範囲を読むもの（段取り・依頼の手順・
  `WorkPlanReview`）は、脇の話を親のやり取りの中として読む。札も「n / N」も増えず、帯は親の段取り・今の段・経過を出し続ける。
  経過は親の依頼を送った時刻から数え続け（続きのターンと同じ）、吹き出しと表情は脇の話のターンの頭で空に戻す
- **claude へ送る文面は `<tsukumo-aside>` の包みに入れる**。claude は包みで脇の話と分かり、組み直し
  （`src/server/session-driver/core/session-restore.ts`）は transcript の `user` の包みを見て `aside` に戻す。
  判定を transcript に残る形にしたのは、組み直すときには背景のタスクの顔ぶれが分からないため。組み直しでは、
  `<task-notification>` だけの `user` メッセージで続きのターンを区切り、委譲の続きのセリフを脇の話の答えに混ぜない
- **答えは `speak` で受け、`report` は求めない**。脇の話のターン（`aside` から、次の依頼・続きのターン・ターンの終わりまで）の
  セリフには `answersAside` の印を付け、メインビューは脇の話とその後ろの印の付いたセリフを対にする。答えは吹き出しと、
  親の札の脇の話の欄（上の「各表示物」のメインビュー）に出る。条は `WORK_PLAN_PROMPT` の「脇の話」の項で、包まれた言葉には
  `speak` の1〜2文で答え、親の作業が進んだ（委譲の返却が届いた）ときだけ、いつもどおり親の段取りへ `work_plan` と `report` を
  渡す、と頼む。「レポートの記法」には足さない（脇の話では本文を書かない。`Stop` の関所もそのまま）
- **脇の話のターンの `report` には段の閉じ方の差し戻しを掛けない**（`ReportReview`。`src/server/report/core/report-review.ts`）。
  脇の話のターンでも同じ依頼の段取りは残っているので、掛けると答えるだけの `report` まで `workPlanClosing` を求めて差し戻すため。
  ほかの差し戻し（送り直し・新しい事実の無い呼び出し・応えていない `work_plan`・規約違反）はそのまま掛かり、`aside` は新しい事実に数える。
  ターンの頭の `session-info` は脇の話のターンの頭にも届くので、脇の話の印はそこでは戻さない
- **「止めて」「方針を変えて」も、親の段取りを引き継いだまま受ける**。脇の話のターンの `work_plan` はそのまま親の帯を
  進める・組み替える（委譲の返却が脇の話のターンの最中に届いたときも同じ）。止めるなら `stopped` の `report` で親の帯を
  止めた姿にする。委譲先を止める操作は claude 自身が行い、tsukumo は持たない
- **背景のタスクが終わって親のやり取りが閉じても、欄は親の札に残す**。開いているあいだは開いて出し、閉じたら畳んで
  「脇の話 n件」の行だけにする
- **やり取りの列では、親のやり取りの行の2行目に「脇 n」を出して畳む**（上の「各表示物」のメインビュー）
- **防げないこと**: 背景のタスクの顔ぶれは SDK の知らせが届いた時点のものなので、終わった直後で知らせがまだ届いていない
  一瞬に送った言葉は脇の話になる。そのときは ⌘⇧⏎ で送り直せる

#### レポートの記法は、TUI と tsukumo で出し分ける

**出力スタイル（`~/.claude/output-styles/asuna.md`）は `~/.claude/settings.json` の
`outputStyle` で全プロジェクトに同じものが当たる**ため、そこに HTML の記法を書くと、tsukumo 以外の
素の TUI でもタグが文字のまま見える。

**tsukumo が `systemPrompt` の append で差分を足す形にする**（2026-09-12 決定）。

- グローバルの `asuna.md` は **TUI 向け**に保つ。人格・`speak` の分岐・セリフと詳細の書き分けは
  残し、**HTML の記法（`note` / `badge` / `cols` / `card` / `details` / `blockquote` / `hr`）と
  mermaid / chart のフェンスを外す**
- **レポートの文体は tsukumo が決める**（2026-09-14 決定）。**本文は中立の技術文**にし、
  キャラクターの口調を担うのは `speak` のセリフのほうにする。どのパックに切り替えても
  本文の読みやすさが変わらないようにするため（**長く読み続ける面**なので、読みやすさを
  キャラクター性より優先する）。書く場所は `src/server/report/core/report-notation.ts` で、
  **`persona.md` の側には書かない**
- **レポートは必ず日本語で書かせる**（2026-09-23 決定）。`CLAUDE.md` の「対話言語」だけでは
  本文が英語で出たことがあるため、同じ `report-notation.ts` の文面で縛り、検査（`non-japanese`）でも差し戻す。
  英語のまま残してよいのは識別子・パス・コマンド・コード・エラー文・原文の引用だけ
- **HTML・mermaid・chart の規約は tsukumo が持つ。** `query()` の
  `systemPrompt: { type: "preset", preset: "claude_code", append }` で足す。正典がリポジトリ内に
  来るので、**描ける記法の一覧が `src/browser/components/page/conversation/components/main-view/markdown/sanitize-schema.ts` と同じコミットで動く**
  （レンダラを直したのに規約が古いまま、が起きない）
- **`~/.claude/settings.json` には触らない**（`outputStyle` も、orca が専有する hooks /
  statusLine も無傷のまま）。書き換えるのは `asuna.md` 1ファイルだけ
- **毎ターン載る規約の節に何を残すか**（2026-10-05 決定）: 仕事の append の4節（セリフの間合い・
  段取り・レポートの記法・質問の書き方）と、`report` / `work_plan` の引数・塊の `describe` は同じターンに
  そろって載る。**同じ条は1か所にだけ置き**（欄の書き方は引数の説明、ターンの終わり方と締めは記法の節、
  段を進めるときのセリフとの並べ方と委譲中の `n/N` は段取りの節）、**差し戻しの文が直し方まで言う条は
  文面から外す**（`fold` の入れ子・候補の数・見出しの欠け・逃げ道に書いた塊の記法・段の飛ばし・段のまとめの欠け）。
  ただし最初の1回で外しやすい条（`conclusion` の長さ・地の文の段落の長さ）、差し戻しのたびに1往復が要る条
  （新しい事実の無いターンは `report` を呼ばない）は残す。文面の正典は各定数で、
  ここには写さない。削った前後で差し戻しが増えていないかは、変更の前後の同じ日数の transcript で
  メインの `report` / `work_plan` の呼び出しと差し戻しの数を、差し戻しの1行目の種類ごとに数えて比べる
  （数え方は `docs/history/decision.md`「display.md 4.2 レポートの記法（ツールの定義の字数の推移と切り替えの
  前の差し戻しの集計）」と同じ）

**この2つの案は採らない**（理由は `docs/history/decision.md`「requirements.md 4.2 表示 /
レポートの記法は、TUI と tsukumo で出し分ける」）: 出力スタイルを2ファイルに分けて選ぶ案と、
1ファイルのまま条件分岐で書く案。

**文面は `src/server/report/core/report-notation.ts` の `REPORT_NOTATION_PROMPT` にあり、
`startSdkDriver`（`src/server/session-driver/adapter/sdk-driver.ts`）が `query()` の `systemPrompt` へ渡す。**

#### 読む時間を減らす物差しと線引き（2026-09-13 決定、2026-09-30 改訂）

**物差しは、レポートを読んで分かるまでの時間が短くなるか。** 短くなるなら、3層（レンダラ /
通す HTML と CSS / 組み立ての規約）のどこに足してもよい。レポートのレイアウトの設計・画像 `img`・
`svg`・`chart`・`cols`（のち `compare` の塊に上げた）もこの物差しで採る（2026-09-30 ユーザーの方針）。文字を減らすこと自体は
目的ではなく、図・グラフ・画像のほうが速く分かる内容をそれで描く。規約を書く場所は
`src/server/report/core/report-notation.ts` で、グローバルの `~/.claude/output-styles/asuna.md` は
TUI 向けのまま触らない。

- **見せ方と再構成の線引き**: **本文の文字列を変えないものが見せ方**（CSS・要素の付け替え・
  段組み・折りたたみ・列揃え・書き手が渡した数や寸法や画像を図にして描くこと）で、これは足してよい。
  **レンダラが本文から目次・要約を起こす・中身を削る・並べ替える・言い換えるのは再構成**
  （2.2 のスコープ外）なので採らない。**書き手（モデル）が最初からその構造で書くのは
  執筆であって再構成ではない**ので、規約で促してよい。この線引きは同じ議論が再燃したときの基準
- **画像を描く条件**: tsukumo 自身のサーバが配る手元の画像だけを描き、外部の URL は読まない
  （会話の載るページに外部を読みに行く経路を作らない）。会話の中身が写る画像（スクリーンショット）は
  同じマシンのディスクに留める（`docs/coding-standards.md`「会話内容の扱い」）。`image` の塊の画像は次のとおり
  扱う（2026-10-02 利用者の決定）:
  - **tsukumo は画像を書き出さない**。描いた `report` を受けた時点で書き手のファイルを1回読み、プロセスの
    メモリの棚にだけ持つ。読んでメモリ上のビューに出すだけなので、「会話内容の扱い」の複製の例外は増えない
  - **棚から消えるのは**、プロセスの終わり・記録の窓（`MAX_SESSION_STATE_TURNS`）からレポートが落ちたとき・
    合計が 64 MiB を超えたとき（古いレポートから）。起こし直し・続きからの復元のあとは「画像を出せない」の札になる
    （記録に残るのはパスだけ）
  - **書き手が撮ったファイルそのものは tsukumo が作りも消しもしない**（`scripts/capture-view.ts` は既定で `/tmp` に撮る）
  - **読む場所では絞らない**。拡張子と先頭の印が png・jpeg・gif・webp のどれかに合う、5 MiB 以下の普通のファイル
    だけを読む（モデルは元々どのファイルも読めるので、場所で絞っても守れるものが増えない）
  - **経路は起動トークン付きの `/report-image/` だけで、URL にはファイルを読ませない**（経路は棚を引く鍵で、
    要求の時点ではファイルに触らない）
  - **質問の選択肢の `preview` に書いた画像も同じ棚・同じ読む範囲で扱う**（2026-10-05。書き方と鍵は「各表示物」の
    「許可と質問」）。積まれた質問を受けた時点で1回読み、**棚から消えるのは**、答えずに答え待ちから抜けた
    とき・答えたあとの記録が記録の窓から落ちたとき・合計が 64 MiB を超えたとき・プロセスの終わり。
    続きからの復元は質問の記録を組み直さないので、画像の扱いも増えない
- **足さないもの**: **レンダラによる目次・先頭の要約の生成**（上の線引きで再構成の側）/
  **`.note` の種類を増やす**（ok / warn / ng の3つで区別がつく。増やすと選ぶ手が止まる）

**`class` の語彙を増やすときは、同じコミットで規約の文面・`sanitize-schema.ts` の許可リスト・
CSS の3つを揃える**（レンダラを直したのに規約が古いまま、が起きない）。**記法の表の行を削ることは
許可リストを同じコミットで削ることを意味する。**

**効くのは書く前だけ。** 規約は `systemPrompt` の append なので、**本文が書かれたあとに tsukumo が
削る経路は無い**（例外は `report` の本文の整形で、落とすのは意味の変わらない行だけ。上の
「出力の分離」）うえ、**規約の変更が効くのは次にプロセスを起こしたときから**（定数なので、
動いているセッションには当たらない）。**量の上限は数で書かない**（行数や項目数で縛ると、長い調査の
報告まで同じ長さに押し込められる。ユーザーの選択）。**ただし段落の単位にだけは数で縛る**
（地の文の段落は3文まで、4文目が要るなら表・箇条書き・`<details>` へ移す。2026-09-23 決定。
全体の量ではなく段落が続くことを止めるための上限なので、長い報告を押し込める話にはならない）。

改訂の経緯（6回ぶん）は `docs/history/decision.md`「requirements.md 4.2 表示 / 読む時間を減らす
ために足すのは、規約の側」、短縮の案と実測は `docs/research/report-notation-shortening.md`。

#### 塊を足す・外す基準（2026-09-27 決定、2026-09-30 改訂）

**塊の種類・欄・逃げ道の中の記法を足すかは、上の物差し（読んで分かるまでの時間が短くなるか）で
決める。外すかは使われ方の数で決める**（docs/research/report-block.md 6章、記録の語彙は
`docs/research/report-architecture.md` 6章）。`report` を描く（差し戻されなかった）
たびに、その回に出た塊の種類・既定の値でない塊の欄（表のセルの `from` / `to`・`stats` の `before` / `total`・
`list` の `label`・`list` の `flow`・`dimension` の `before`・`image` の `notes`）と、逃げ道（`markdown` の塊）に出た記法の種類（重複無し。同じ種類が
同じレポートに何回出ても1回と数える）を `~/.tsukumo/report-usage/<YYYY-MM-DD>.jsonl` に1行記録する。
逃げ道に出た記法は3つに分けて持つ: **塊のある記法**（表・箇条書き・`note` など、逃げ道の外側
〔HTML の容れ物の中でないところ〕に出たもの）・**同じ塊のある記法が HTML の容れ物
（`<details>` / `<div>`）の中に出たもの**（複数の塊を畳む・並べるのは逃げ道の役目なので、
差し戻しではなく別に数える）・**塊の無い記法**（`cols` / `card`〔規約から外したので、書かれ続けるかを見る数〕・
`svg`・`dl`・引用・区切り線・`<details>` そのもの。塊に当てはまらないので昇格のきっかけになる）。知らない種類で境界で
落とした塊の数（`parseReportSections` の `unknownBlockCount`）も同じ行に足す。中身は一切持たない
——数と名前だけ（`docs/coding-standards.md`「会話内容の扱い」）。書くのは
`src/server/report/adapter/report-usage-log.ts`、何を1行にするかは
`src/server/report/core/report-usage.ts` と `src/server/report/core/report-violation.ts` が持つ。

**集計するスクリプトは `scripts/report-block-usage.ts`**（`node scripts/report-block-usage.ts
--days <日数>`、既定28日）。「塊の種類 × レポート数」「塊の欄 × レポート数」「逃げ道の外の記法 × レポート数」
「逃げ道の容れ物の中の記法 × レポート数」「塊の無い記法 × レポート数」の5つの表を出す。欄を記録する前の
行（版2）も読み、欄の表だけは欄を記録した行を分母にする（欄を足す前後で逃げ道の使われ方を見比べるため）。
`report` が差し戻されたときも同じファイルに1行書く（`kind: "rejected"`・時刻・セッションID・差し戻しの種類の名前だけで、
手続きの6種〔送り直し・新しい事実が無い・段取りへの応え・段の閉じ方の3種〕と記法の違反の `kind`。本文も文面も持たない）。
集計は6つめの表「差し戻しの種類 × 回数」で、割合は `report` の呼び出し（受け付け＋差し戻し）の数に対して出す。
よく当たる規則は欄の形や説明で防ぎ、当たらない規則は削る判断に使う。

- **足すきっかけ**: 塊の無い記法の同じ種類が、直近2週間（14日）のレポートの3%以上に出たら、
  塊に上げるタスクを立てる。**数が届かないことは足さない理由にならない**（書くのが重い記法は、
  速く分かる内容でも使われない。`chart` は 2026-09-27〜09-30 の364回で1回）
- **容れ物の判断**: 塊のある記法が容れ物の中に出た数を見て、`<details>` / `div` の使われ方
  （畳む・並べる）を判断する。足す・外す基準の対象にはしない
- **外す基準**: 塊の種類か塊の欄が、直近4週間（28日）で0回だった。数が決めるので、あとの判断は
  「タスクを立てるかどうか」だけになる。**`markdown`（逃げ道そのもの）は外す基準の対象にしない**
  ——逃げ道を無くす話は塊の一覧の増減とは別の議論になる

#### 各表示物

**表示はすべて HTML である**（2026-09-09 決定。`docs/architecture/adr/0016-html-instead-of-terminal.md`）。
ターミナルに文字と絵を描く経路は持たない。4つの領域は
**1枚のページ**として tsukumo のローカル HTTP サーバから配られ、**Orca 内のブラウザタブ**に出る
（4.7）。

- **立ち絵**: HTML の `<img>` で表示する。ドット絵ではなく本物の立ち絵を出せることを狙う。
  ターミナルの画像プロトコル（Sixel / iTerm inline images）は使わない
- **吹き出し**: `speak` で受け取った**セリフだけ**を、キャラビューの中に立ち絵と同居させて
  表示する。**セリフ1件につき吹き出し1つ**とし、今のターンの分を縦に積んで**最新を一番下**に
  見せる（並びは自前でスクロールする。2026-09-12 決定）。**主役は立ち絵**で、**立ち絵は領域の
  左下・吹き出しの並びは右上**に置き、最新の吹き出しの左辺から立ち絵へ向けて尻尾を伸ばす
  （下の尻尾の段落）。
  **「どれが最新か」は位置と見た目の強弱の両方で示す**（最新だけ濃く大きく、過去は小さく薄く）。
  吹き出しの幅は中身なり。**ターンの
  本文は出さない**（本文はメインビューに回る）。**折り返し・全角文字の幅・禁則処理はブラウザに
  任せる**。**最新の吹き出しの下端の位置は固定し、過去のセリフが上へスライドする**形にする
  （2026-09-13 決定。**下端揃え＋固定の下余白**で、最新の Y 座標はセリフの件数によらず一定に
  なり、入りきらない分だけ内側でスクロールする）。位置と幅が往復した経緯は
  `docs/history/decision.md`
- **最新の吹き出しにだけ話し手の名前（`character.json` の `name`）を添える**（2026-09-23。
  名前が無いパックには添えない。反応の吹き出しにも添える）。**流れていったセリフは右上の「ログ」から
  読み返す** — **キャラビューの舞台をそのまま上へ伸ばす**モーダルで（2026-09-23 決定。見本は
  ユーザーの「発話ログ案2」）、左右と下端はキャラビューの領域に揃え、上端は帯のすぐ下まで伸ばす。
  背景（`docs/architecture/screen-design.md` 13.8）も領域と同じ縮尺・同じ位置で敷いてそのまま上へ続け、
  領域の上端から上で地へ溶かす（開いても立ち絵の後ろの絵は動かない）。
  立ち絵はキャラビューと同じ表情・同じ高さで同じ場所に立ち、吹き出しは古い→新しいを上→下に
  積んで、ターンの境目に依頼の区切り（依頼の1行目と、分かれば依頼の時刻）を挟む。開いた直後は
  最新（キャラビューの最新の吹き出しと同じ見た目・同じ位置）が下端に見え、上へ転がして遡る
  （上へ転がせるときだけ「もっと前を読む ↑」の印が出る。読み込みの口ではない）。過去の吹き出しは
  古いほど薄いが、いちばん薄い段でも字の比は 4.5:1 を割らない。閉じるのは「ログを閉じる」・Esc・
  枠の外を押すこと（枠の外を押しても閉じるだけで、下の画面は操作しない）。材料は過去のターンの
  吹き出しを遡らせるのと同じ記録で、別に溜めない
- **吹き出し・セリフのログの行を押すと、そのセリフの表情へ立ち絵が遡る**（2026-09-28 決定。
  雑談モードの「会話を遡る」の仕事モードでの対応物。docs/architecture/screen-design.md「会話を遡る」）。
  押し方・印・解き方（新しいセリフが来たら解ける・ドラッグで文字を選んだときは押したことに
  しない・キーボードで押せる）は雑談と揃えた。留めた状態は吹き出しとログで1つ共有する
  （ログの床の立ち絵はキャラビューのものと同じ立ち絵なので、片方で留めればもう片方にも
  そのまま映る）。以下は雑談と揃えなかった:
  - **タブ（過去のやり取りの札）を切り替えても留めた選択は解けない**。留めた行は「ターンの
    通し番号とそのターンの中の位置」の組で持ち、過去のターンは記録から不変に導けるので、
    雑談の「窓から古い記録が落ちて番号の指す先がずれる」ような失効が要らない。ログはどの
    ターンのセリフでも押せる1つの窓という扱いで、タブとは独立に動く
  - **何も留めていないときに印が付くのは「いま表示しているターン」の最後の行だけ**（吹き出しは
    そのターンのぶんしか描かないため）。ログは全ターンぶんを並べるが、印は表示中のターンの
    最後の行にしか付かない
  - **ログの行はどのターンのものでも押せる**。表示中のターンと違うターンの行を押すと、
    立ち絵の表情はそのセリフに合わせて変わるが、吹き出しの並び（表示中のターンのぶんだけ）には
    印が付く行が無くなる——ログは会話全体を読み返す窓、吹き出しは「いま」の窓という役目の違いを
    そのまま残した
- **吹き出しに出るのは `speak` で来たセリフだけ**（2026-09-17 決定）。**ツールを実行している
  間だけ「作業中の一言」を重ねる案は採らない**（表情の自動の上書きと一緒に撤去した。4.3）
- **尻尾の向き**: 立ち絵は左にいるので、**尻尾は吹き出しの左辺から真横（左）へ出し、先端を左に
  向ける**（2026-09-13 決定）
- **許可と質問**: **キャラが聞く**（2026-09-11 決定）。吹き出しに「これ実行していい？」と出て、
  答えるのは画面の口。押すと答えが `canUseTool` の戻り値として SDK へ返り、口は消える。
  **許可モード**（毎回聞く／編集は自動／全部許す／プラン）も画面から切り替えられる。
  **許可要求も質問（`AskUserQuestion`）も、同じ形の札「お伺い」にして、メインビューの進み具合の帯の
  下の本文に出す**（2026-10-02 決定。形・寸法・キー操作は `docs/architecture/screen-design.md` 13.13「お伺い」）。
  それまでは許可要求が入力欄の上の箱、質問がメインビューの札と2か所に割れていて、許可を待つあいだ
  送信ボタンと許可のボタンが主役を取り合っていた（旧い形は `docs/history/decision.md`「display.md 4.2
  各表示物（許可と質問の置き場・メインビューはレポートだけ・入力欄の経過時間と API の知らせ。2026-10-02 に覆した記録）」）。
  許可要求は対象の全文と選択肢「1 許可」「2 拒否」を持つお伺いで、選択肢の決まりは質問と同じ番号つきの
  カード。お伺いにフォーカスがあるときだけ、1〜9 で選び Enter で進む:
  - **札はいまのやり取りの札の頭（題の行と進み具合の帯）の真下**に出し、枠と地は答え待ちの色（`--state-warn`）の系統。
    頭に「お伺い」のチップ・種類（許可 / 質問）・`header` かツール名、右端に「n / N」（何問目か）と待っている時間。
    **過去のやり取りを見ている間は札を出さず**、知らせの行の「お伺いが届いた」がいまのやり取りへ連れて戻る
    （2026-10-03。それまでは過去のやり取りを見ていても札を出し、戻る口を添えていた）
  - **選択肢は横に並べたカード**（番号・選択の印・太字のラベル・説明）。**選んだカードは枠が
    `--state-warn`** になる。幅が足りなければ折り返す（狭い画面では1列になる）。
    **ラベル末尾の `(Recommended)`・`(推奨)`（全角の括弧も可）は「おすすめ」のバッジにして字からは外す**
    （SDK へ返す答えは元のラベルのまま）
  - **自由入力は入力欄が担う**（2026-09-23 決定。札の中の自由入力の欄は無くした）。質問が
    出ている間、入力欄は上に帯「↑ <キャラクター名> が質問しています。上の選択肢から選ぶか、
    ここに書いて答えてください」と「お伺いへ」の口を出し、プレースホルダは「選択肢以外の答えを書く…」、
    送るボタンの字は「答える」（最後の1問でなければ「次へ」）、枠は `--state-warn` になる。送るボタンは
    **自由入力の字があるときだけ** `--state-warn` で塗り、字が無ければ塗らない（お伺いの札の「次へ」と主役を
    取り合わない。2026-10-03）。書いて送った字は
    **いま見ている1問の答え**になる（`AskUserQuestion` の "Other" 相当。モデルが選択肢に自由入力を
    含めてこなかったときの受け皿でもあるので、**選択肢の側の「その他」は札に出さない**）
  - **許可を待つ間の入力欄はふつうの下書きのまま**で、上に帯「↑ <キャラクター名> が実行の許可を待っています」と
    「お伺いへ」の口だけを出す。送るボタンの席は「中断」のまま
  - **接続が切れているあいだの入力欄**は、上の帯に「サーバとつながっていません。送れず、下書きは残してあります。

  通らないことは送る手の前に要る）。仕事のときは経過・再試行中・失敗の理由を行に出さない。

  プレビューでも、記号を打てない WYSIWYG でもない）。コードフェンスはキャレットがフェンスの中に

#### タスクのモーダル（2026-09-28 決定）

サイドバーの「一覧を見る」で開くモーダル。**左に一覧、右に選んだタスクの詳細**（本文を Markdown で
描く）の2列で、**形は見本2枚が正**（`docs/history/mockup/task-board-2026-09-28/` の
`TASK-1-List.dc.html`・`TASK-2-Jump.dc.html` と同名の `.png`。見本の中のタスクの文言はダミー）。
寸法・色・狭い画面の並びは `docs/architecture/screen-design.md` 13.12。ここには中身とふるまいを置く。

- **本文の出どころ**: タスクの本文は**一覧の要約と一緒に届ける**（選んだときに取りに行く口は作らない）。
  見回りが読んだものから作るので、一覧と本文の新しさがずれず、検索が本文まで引ける。
  課題の `description`・`acceptance_criteria`・`notes` を Beads の欄の順に、tsukumo が決めた見出しで並べたもの
  （節を並べ替えない。`docs/architecture/adr/0024-no-skill-dependency.md`）。Beads の comment は `bd list` に載らないので出さない。
  `bd list` は `--brief` を外しても1回の時間は変わらない（2026-09-28 の手元で 67件・約0.4秒、出力は
  48KB → 273KB）ので、見回りの間隔は変えない
- **並び**: 一覧に載る範囲はサイドバーと同じ（閉じた課題は新しいほうから10件）で、
  並びは**作った時刻の順**（進行中を先頭へ寄せない。完了も混ざる）。行は1段目に ID・状態、
  2段目に要約（2行で省略）。済んだ行（`done`）は薄く出す
- **状態の言い方**は一覧の行・詳細の情報の表・つながりの札で同じにする。`todo` は依存から計算して
  「着手できる」か「待ち」（まだ済んでいない依存の ID を必ず字で添える。閉じていない課題に無い依存
  〔閉じた課題・一覧に無い ID〕は止めない）、`hold` は「保留」
  （済んでいない依存があれば ID を添える）、`doing` は「進行中」、`done` は「完了」、想定外の値は注意色〔`--state-warn`〕の「!」と
  値のまま。**色だけで伝えない**（印の形と字が言う）
- **課題のラベルは詳細の情報の表に「ラベル」の行として字のまま札で並べる**（2026-10-08。Beads の `labels` をそのまま出し、
  意味は解釈せず並べ替え・絞り込み・色分けに使わない。無い課題では行ごと出さない。担当は出さない。
  `docs/architecture/adr/0024-no-skill-dependency.md`）
- **見出しの帯**: 「タスク」・件数・キーの案内（`↑↓` 選ぶ・`Esc` 閉じる）・閉じるボタン。件数は
  サイドバーの件数のチップと同じ数え方（すべて・進行中・未着手〔`todo`〕・完了〔`done`〕。`taskListCounts`）
- **絞り込みの札**: すべて・着手できる・待ち・保留・進行中・完了の6つで、それぞれに件数を添える。
  1つだけ選べ、既定は「すべて」。「着手できる」と「待ち」はサイドバーの「未着手」（`todo`）を
  着手できるかで2つに割ったもの、「保留」は `hold`、「進行中」は `doing`、「完了」は `done` だけ
  （サイドバーの「完了」と揃える）。**想定外の値はどの札にも属さず、「すべて」でだけ出る**
  （サイドバーの「想定外の status は『すべて』のときだけ出る」と同じ規則）。サイドバーで選んでいる
  チップはモーダルへ持ち込まない
- **検索**: 引くのは **ID・要約・本文**（大文字小文字を区別しない部分一致。絞り込みの札と組み合わさる）。
  ファイル名はタスクの ID をそのまま名前にしているので別には引かない（案内の文言は「ID・言葉で探す」）。
  ID の形を決め打ちしない（Beads の ID のまま、部分一致で当たる）。絞った結果が0件なら一覧に
  「当てはまるタスクが無い」と出し、詳細は空にする
- **開いたときの選択**: 開くたびに検索は空・絞り込みは「すべて」・選択は一覧の先頭の行から始める。
  **サイドバーののぞき窓の「全文を開く ↗」とレポートのタスク ID から開いたときは、そのタスクを
  選んだ状態で開く**（絞り込みの外でも一覧に出す）。**開いている間に一覧が届き直しても**
  選んでいるタスクが一覧に残っていれば選択を保ち、消えていれば先頭の行へ移る
- **キー操作**: ↑↓ で行を移ると詳細がすぐ切り替わる。Esc・閉じるボタン・モーダルの外側のクリックで
  閉じる（`<dialog>` の `showModal()` に任せ、フォーカスは開く口へ戻る）。行を押すと選ぶだけで、
  頼まない
- **詳細**: ID と status の生の値・タイトル（要約）・情報の表（着手・ラベル・置き場所）・
  本文。**置き場所の行**は「Issue」に課題の `external_ref`（`https://` で始まる URL の
  ときだけ。無ければ行ごと出さない）。依存を1つでも持つタスクは**本文の上に「先に終わっていてほしいもの」
  の札**を依存ごとに並べる（ID・状態・要約。一覧に無い依存は ID に「一覧に無い」を添え、押せない）
- **本文中の ID の自動リンク**: 本文の地の文と、中身がまるごと1つの ID の inline code のうち、
  **いまの一覧に載っている ID と字面が一致するもの**だけを押せる字にする（語の途中は当てない。
  フェンスの中は当てない）。ID の形の正規表現は持たない——一覧が知っている ID だけを当てるので、
  ID の形が変わってもそのまま当たり、一覧に無い ID
  （閉じて一覧から落ちたタスク）は押せない字にならない
- **本文の描き方**: レポートの描画（`markdown.tsx`）は流用せず、タスクのモーダルが専用に持つ。
  使うのは `react-markdown` と `remark-gfm`・`remark-cjk-friendly` だけで、**生の HTML は解釈しない**
  （字のまま出す）。描くのは見出し・段落・箇条書き・番号・チェック（静的な印。押せない）・
  inline code・フェンス（色付けしない）・表（横に溢れたら表だけ転がす）・リンク（`http(s)` だけ
  新しいタブで開き、それ以外は字のまま）。レポートの記法（`note` などの class）・mermaid・Chart.js・
  パスを押すとエディタで開く部品は持たない。流用しないのは、置かれる機能（`features/`）が
  会話の画面の部品を import できず（`docs/architecture.md`「領域の機能と、置かれる機能」）、
  本文の読み物としての字の段（14px・行間 1.85）もレポートと違うため
- **下の操作の帯**: 「ID をコピー」（クリップボードへ ID の字だけ）・置き場所を開く口
  （「Issue を開く」で、`external_ref` を新しいタブで開く。`external_ref` が無ければ出さない）・「tsukumo に頼む」
  （サイドバーののぞき窓の「これを始める →」と同じ確認を開き、OK で固定の文面の `{id}` を ID にして送る）。**「tsukumo に頼む」を押せるのは
  「着手できる」タスクと、依存がすべて済んだ保留のタスク**（2026-10-02 ユーザー決定。2026-10-06 に既定が平文になったあとも同じ。
  送る文面の末尾に「このタスクは保留なので、着手の前に判断を聞いて。」を添え、確認にもその文面がそのまま出る）で、それ以外は薄くして押せず、横に理由を添える（待ちと、
  依存が残る保留 → 「待ちが終わると頼めます」、進行中 → 「着手済みです」、完了 →
  「終わったタスクです」）。
  ターンが動いている間の断り方は区画の確認と同じ
- **つながりをたどる**（見本2）: 「先に終わっていてほしいもの」の札・本文中の ID を押すと、
  **モーダルの中で詳細だけが切り替わり、一覧の選択も追いかける**。詳細の上にパンくず
  （「‹ <前の ID> に戻る › <いまの ID>」）を出し、**直前の1つだけ**を持つ（履歴を積まない）。
  戻るは `Alt+←` でも同じ。一覧で別の行を選ぶとパンくずは消える。飛んだ先には逆向きの
  **「これを待っているもの」**（いまの一覧のうち、このタスクを依存に持つもの）の札も出す。
  飛んだ先が絞り込みや検索で一覧から隠れているときは、**その行だけを一時的に一覧に出し
  「絞り込みの外」と小さく添える**（一覧で別の行を選ぶと引っ込む）
- 検索・絞り込み・選択・パンくずは表示上の状態なので**保存しない**（閉じると捨てる）

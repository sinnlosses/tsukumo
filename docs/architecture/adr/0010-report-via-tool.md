# レポートはテキストではなく `report` ツールで受け取る

レポート（メインビュー本文）とセリフ・実況の分離を、**本文の構造を読んで推測する**形で何度も
継ぎ足してきた: 構造の印（見出し・箇条書き・コードブロックの有無）で「まとまった資料」を選び
（`selectShownReports`）、位置と長さで実況を落とし（2026-09-16〜09-21）、締めの本文が実況で
しかなければ資料へ繰り上げ（2026-09-21）、日本語でなければ席を戻す（2026-09-23）……
**規約が破られるたびに、推測へ条件を1つ継ぎ足す**形になっていた（経緯は
`docs/history/decision.md`）。推測はいつまでも「今回はたまたま当たった」の域を出ず、条件を
足すほど次の例外を呼び込んだ。

`speak` と同じ発想で、**レポートも呼び出しの事実で受け取る**ことにした:
`report(conclusion, body, favor)` を tsukumo 側の MCP ツールとして提供し、呼ばれた事実そのものを
本文の区切りにする。

**1回目の試行（2026-09-23、`docs/research/report-tool-trial.md`）は不採用にした。** 3条件のうち
「`report` の呼び忘れが1件以下」を満たさず（20ターン中6件）、そのすべてが「最後の `report`
のあと（または `report` 無し）に、1行を超える本文を書いてターンを終えた」という同じ形だった。
利用者は**推測へ戻さず、この形を仕組みで塞いでから同じ条件で試し直す**と決めた:

1. **`Stop` の関所**（`src/server/report/core/report-tool.ts`）: SDK のターンの終わりに、最後の
   `report` のあとの本文が1行を超えていたら `block` にして渡し直させる
2. **検査**（`src/server/report/core/report-review.ts`）: `report` の引数を機械で判定できる規約違反で
   検査し、違反と直し方を戻り値で返して書き直させる
3. **整形**（`src/shared/report/report-tidy.ts`）: 意味を変えずに落とせるもの（定型の前置き・締めの行・
   余分な空行）を落として描く

**2回目の試行（2026-09-23〜24）は3条件とも満たし、2026-09-24 に採用と決めた**
（`docs/research/report-tool-trial.md`「試し直しの判定」）。呼び忘れは0件（16ターン中）で、
関所の `block` 4回はすべて `block` のあとに直った。

**2026-09-25 に、関所の差し戻しの理由をそのターンで `report` が済んでいるかで分けた。** 済んだ
ターンで「`report` → 締めの `speak` → レポートと同じ中身のまとめの本文」と書いて止まったとき、
一律の理由（「画面に出ていない、`report` で渡し直せ」）に従って中身のほぼ同じ `report` が出し
直され、最初の1枚が中間レポートになって似た2枚が並んだ。締めのセリフも「今度は画面に出した」と
利用者には見えない差し戻しに触れた。済んだターンでは「レポートはもう画面に出ている。言い直しなら
何も呼ばずに終える」と返し、両方の理由に「差し戻しにはセリフでもレポートでも触れない」を足した。

**2026-09-27 に、通った `report` でターンを閉じるようにした**（`docs/research/report-block.md` 13章）。
handler は検査を通した呼び出しの結果にだけ `_meta["claude/endTurn"]` を付け、本体はそのあと
assistant を挟まずにターンを終える。`report` のあとに本文を書き足す形そのものが起きないので、
締めのセリフは `report` の必須の引数 `closing` で受け取って描いたあとに吹き出しへ出し、関所は
`report` を呼ばなかったターンの本文だけを差し戻す（済んだターン向けの理由は外した）。`report` は
常に閉じ、`final` のような欄は置かない——中間レポートは、背景のタスクや委譲の合図で始まる続きの
ターンをまたいで今までどおり生まれる。`_meta` は transcript に残らないので、復元は閉じたかどうかを
読まず、差し戻しの `is_error` だけで描くかを決める。

`report` が1つでも呼ばれたターンは、最後の呼び出しが**最終レポート**、それより前が
**中間レポート**になり、`report` の外に書いた本文は出さない（`docs/glossary.md`「report
ツール」「最終レポート」「中間レポート」）。**`report` が呼ばれなかったターンは、推測をやめて
最後の本文をそのまま最終レポートにする**（2026-09-24 決定。それまで積んでいた実況・英訳・
資料の判定は `docs/history/decision.md` へ移した）。

**戻り値は `speak` と同じ考え方で絞る**: `"ok"` か、差し戻すときの規約違反だけを返し、画面の
状態は載せない（tsukumo からモデルへの逆流路を広げない。上の「セリフはテキストの規約ではなく、
ツール呼び出しで受け取る」の「戻り値は `"ok"` だけにする」と同じ理由）。

**ターンが `speak` で終わると本体が催促を差し込む**（`[Your previous response had no visible
output. ...]` を利用者の発言として足し、1往復増える）。塞ぐのは子プロセスに
`CLAUDE_CODE_TERMINAL_MCP_TOOLS=mcp__tsukumo__speak` を渡すこと（`src/server/session-driver/core/visible-output-nudge.ts`。
2026-09-25 実装。公式の文書に無い変数なので、催促が届いたら stderr に固定の1行を出す見張りを
`sdk-driver.ts` に置く）。2026-09-23〜25 は最後の `speak` のあとに「完了」の1行を書かせる条で
塞いでいたが、`report` を呼ばないターンでその1行が最終レポートとして画面に出たので外した
（`docs/architecture/chat-mode.md` 4.9「雑談モードで変わるもの」）。往復の数は条でも変数でも同じ
（どちらも最後のツール結果への応答1回は要る）。

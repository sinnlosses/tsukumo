# 地図のモジュールに、読み始めるファイルの任意の欄 `entrypoints` を足す（2026-11-27）

ステータス: 採用

**地図のモジュールに任意の欄 `entrypoints`（読み始めるファイルのパスの配列。1件以上）を足す。大・中・小のどの段にも書け、外の世界のモジュール（`external: true`）には書かない。どれもそのモジュールの `paths` に当たるファイルであることを作り手の義務にし、ずれ（`findings`）の種類は足さない。tsukumo は `paths` に当たるものだけを説明の枠に「エントリポイント」として出し、押すとエディタで開く。版は `1` のまま上げない。作り手が入口を選ぶ方針は、人が地図の定義に書いたものを最優先にし、無ければディレクトリの直下の決まった名前のファイルを1つ選ぶ。** 契約の正典は `docs/architecture/architecture-map.md` で、この ADR は判断の理由を持つ。

形（見出し「エントリポイント」の下に入口を1行ずつ、字はパスの末尾の2区切り。中のモジュール「メインビュー」なら `main-view/main-view.tsx`。規模の行の次、依存先・依存元の前）は、見本 `docs/history/mockup/map-panel-2026-11-27/compare.html` の「言い直し（メインビュー・中）」の列の「エントリポイント」の節に合わせる。

## 何が困っていたか

- 地図を読む人がモジュールの役割を読んだあと次に知りたいのは「どのファイルから読み始めればよいか」だが、契約の「モジュール」の表にはそれを書く欄が無い
- 説明の枠はパス・ADR・依存先と依存元・規模・変更頻度を出すが、どれも読み始める1つのファイルを指さない。`paths` の glob（`src/browser/**` など）からは入口のファイルが読めない

## 前提の裏取り

- **任意の欄を足しても版を上げない**: 契約の「版」の2つ目の箇条は「版を上げないもの: 任意の欄を足す」と定め、区画の欄（`lanes`・`lane`）も版 `1` に足した前例がある（ADR 0085 の論点 1）
- **tsukumo は知らない欄を読み捨てる**: `src/shared/architecture-map/architecture-map.ts` の `largeBoxSchema`・`mediumBoxSchema`・`smallBoxSchema` は zod の `z.object` で、知らない欄は落ちる。欄の無い今の地図も、欄のある地図も、欄を知らない tsukumo で読める
- **作り手は小のモジュールをディレクトリから、大・中を人の定義から作る**: `vendor/tsukumo-plugins/plugins/tsukumo-architecture-map/skills/architecture-map/scripts/architecture_map.py` の `small_box` は抽出したディレクトリから小のモジュールを組み、`parse_box` は人が書いた TOML の大・中の定義を読む。入口の選び方（論点 2）はこの分け方に沿う
- **開く口**: 説明の枠の ADR の一覧（`architecture-map-panel.tsx` の `AdrList`）は `host.openFile` でファイルを開く。入口も同じ口で開ける

## 決めたこと

### 論点 1: 欄の形 — パスの配列を全部の段に、`paths` の外は作り手が止め tsukumo は読み捨てる

**採る: モジュールの任意の欄 `entrypoints` を、読み始めるファイルのパスの配列（1件以上）にする。リポジトリの根からの相対で、契約の「パスの書き方」に沿い、ワイルドカード（`*`）を含まない。大・中・小のどの段にも書け、外の世界のモジュールには書かない。どれもそのモジュールの `paths` に当たる抽出したファイルであることを作り手の義務にする。ずれの種類は足さない。tsukumo は `paths` に当たらないものを説明の枠から読み捨てる。形が外れた値（配列でない・空・`*` や `./` を含む・外の世界のモジュールに書いた）は、ほかの欄と同じく契約に沿わない地図として読めない扱いにする。版は `1` のまま。**

- 配列にしたのは、入口が1つに決まらないモジュールがあるため。起動の口と外から呼ばれる口を別のファイルに持つモジュールでは、どちらかに絞ると読み手が片方を見落とす
- 全部の段に書けるのは、どの段の説明の枠でも同じ問い（どこから読むか）が立つため。外の世界のモジュールは `paths` が空で、当たるファイルが無い
- `paths` の外を指す入口は、作り手が定義の誤りとして書き出しの前に止める。地図に残る形のずれにならないので、`findings` の種類を足さない
- tsukumo が `paths` に当たらないものを読み捨てるのは、利用者独自の作り手が義務を破ったときに、地図の外のパスを `host.openFile` へ渡さないため。全部外れたモジュールは節を出さない
- 版を上げないのは、契約の「版」が任意の欄を足すことを版を上げないものに数えるため。欄を知らない tsukumo は欄を読み捨てて今の説明の枠を出す

### 論点 2: 作り手が入口を選ぶ方針 — 人の定義を最優先、無ければ決まった名前のファイル

**採る: 人が地図の定義に書いたものを最優先にする。無ければ、モジュールの `paths` の共通の頭のディレクトリの直下で、`index.<拡張子>` → ディレクトリと同名のファイル → `main.<拡張子>` の順に最初に見つかった1つを選ぶ。どれも無ければ欄を書かない。被依存の多いファイルは選ばない。** この方針は作り手の側の決まりで、契約には書かない（契約が縛るのは欄の形と `paths` の中にあることだけ）。

- 大・中のモジュールは人が定義に書くので、人が読み始める場所を名指せる。小のモジュールはディレクトリから作るので、名前の決まりで選ぶ
- 決まった名前の順は、JS・TS で入口に使われる名前の慣習の順（`index`、ディレクトリと同名、`main`）。見本の `main-view/main-view.tsx` は2つ目に当たる
- どれも無いときに欄を書かないのは、当てずっぽうの入口が読み手を誤った場所へ連れていくため

### 論点 3: 判断の置き場 — 新しい ADR にする

**採る: この判断を新しい ADR（この文書）に書き、ADR 0082 に書き足さない。** 区画の欄を足したときも 0082 に書き足さず ADR 0085 を起こした前例に合わせる。0082 は地図の契約を最初に決めた記録で、欄を足すたびに書き足すと、どの判断がいつ足されたかが読めなくなる。

## 採らなかった案

- **ファイル1つだけの欄（`entrypoint: "<パス>"`）**: 入口が2つ以上あるモジュールを表せない。あとで配列に替えると欄の意味を変えるので版を上げることになる（契約の「版」）
- **`findings` に新しい種類（`missing-entrypoint` など）を足す**: `paths` の外の入口は作り手が定義の誤りとして止めるので、地図に残る形のずれにならない。種類を足しても書き出される場面が無い
- **被依存の多いファイルを入口に選ぶ**: よく import されるのは末端の道具のファイル（型・小さな関数）で、読み始める場所にならない
- **ADR 0082 に書き足す**: 論点 3 のとおり、区画の前例に合わせて分ける

## 結果

- 欄のある地図では、説明の枠に「エントリポイント」の節が出て、押すとそのファイルが開く。欄の無い地図と古い作り手の地図は今のまま読め、節を出さない
- 契約の版は `1` のままで、古い tsukumo も欄を読み捨てて読める
- 作り手が欄を書くのは、作り手の側の後続の直しで行う

# ピルの「手順」の頭に、ワークフローのエージェントの図を出す（2026-11-22）

ステータス: 採用

**ワークフロースクリプトが流れている依頼では、ピルの「手順」を押したときの全体の詳細（ADR 0070 論点 8）の頭に、フェーズを列・エージェント1体を箱にした図を出し、図の下に選んだ体の手元（手順の並び）を置く。図の材料は SDK の `task_progress` の `workflow_progress` の `workflow_agent` の行だけから組み、矢印は時刻とエージェントの種類（`agentType`）から機械的に引く。全体の詳細の幅はピルの幅にそろえる。手元に申し送り（委譲先の進みの1行）は出さない。** 見本は `docs/history/mockup/workflow-agents-2026-11-22/pill.html`（`?scene=seq|par&open=1`）。エージェントの種類は、同じ見本の箱の2行目の頭の札と、手元の頭の種類の全名で示す。

この ADR が決めるのは、全体の詳細の幅と、図・手元の材料・形・量・部品の割り当てまで。閉じているあいだのピルの1行（「n 体が並んで動いています」）と「手順」の口の赤い点は、利用者が決めた形のまま後段で入れる。狭い画面（760px 以下）は今のまま変えない。`report`・`work_plan`・`phase_result` の入力に欄は足さない。

## 何が困っていたか

- ワークフローの実行中に、各エージェントがどの段で何をしているか、済んだか・待っているか・落ちたかが画面から読めない。ピルの一文は、いちばん新しく始まった手順を1つ言うだけ
- `src/server/session-driver/core/message/sdk-background-message.ts` の `workflowAgent` は `index`・`agentId`・`state`・`phaseTitle` だけを写し、`agentId` の無い行（並びの待ち）を捨てる。`src/shared/session/workflow-event-fold.ts` はワークフロー1本につき最新の手順1つだけを持ち、`workflowItemsOfTasks` は顔ぶれから外れたワークフローの写しを捨てる。図の材料が残らない
- 全体の詳細は幅 30rem でピルの右端にそろえていて（`turn-card/work-strip-steps-pop.css` の `.work-strip-steps`）、列を並べる幅が無い

## 利用者が決めたこと（2026-11-22）

- 置き場はピルの「手順」を押したときの面の中だけ。サイドバー・会話の流れ・立ち絵の側には出さない（`compare.html` の案 A〜C は採らない）
- 面の幅はピルの幅にそろえる。部品はできる限り Astryx（`ui/` の包み）で組む
- 列はフェーズ、箱1つがエージェント1体、走っている体は差し色の縁、済んだ体は結果の一言、待ちは点線、失敗は赤い縁と理由。図の下に選んだ体の手元、下端に目安の残り
- 図から、各体がどのエージェントの種類で動いているかが読める（見本に無かったので、この ADR で見本に足した）
- 閉じているあいだのピルの1行は今のまま。並んで2体以上が走るときだけ「n 体が並んで動いています」。失敗した体があるときだけ「手順」の口に赤い点
- 言葉と見本が食い違ったら見本が勝つ（「見本と違う決定」の節に挙げたものを除く）

## 決めたこと

### 論点 1: 矢印の出どころ

**採る: 矢印は `workflow_agent` の行の時刻と種類から tsukumo が引く。ワークフロースクリプトに申告の形は足さない。**

- 体の並びは `index`（`agent()` を呼んだ順）。体 B が体 A の「後」なのは、A が終わっていて（`done`・`error`）、A の終わり（`startedAt` + `durationMs`）が B の `queuedAt` 以前のとき。この「後」の関係から推移で言えるものを除いた組（A→C→B があれば A→B は引かない）を矢印にする。最初に並んで始まる体が2体以上なら、列の左に始まりの点を置き、そこから各体へ矢印を引く
- 走っている体へ入る矢印は差し色、待ちの体へ入る矢印は点線、ほかは薄い線
- **差し戻し（橙の矢印と「差し戻し」の字）**: 体 B の `agentType` が、B より前の列で走った体の `agentType` と同じとき、B へ入る矢印を差し戻しにする（前の列の仕事を同じ種類の体がやり直している）。`agentType` が無い体と `general-purpose` の体は差し戻しにしない。`task-flow` では、受け入れの列の直し（`tsukumo-workflow:no-delegate`）が実装の列の実装役と同じ種類なので差し戻しになり、受け入れ 2（`tsukumo-workflow:acceptor`）は同じ列の受け入れ 1 と同じ種類だが前の列ではないので差し戻しにならない
- 体がまだ1体も呼ばれていない後ろのフェーズは、列に点線の空きの箱（フェーズの名前と「これから」）を1つ置き、最後の体からそこへ点線を引く
- 採らなかった案:
  - **ワークフロースクリプトがつながりを申告する（`agent()` の欄や `log` の決まった文）**: SDK の `workflow_agent` に任意の欄は無く、運べるのは名札（`label`）だけ。名札に決まった書き方を課すと、ADR 0079 の部品の作り手が知る契約（印・タスクの ID・結果の語）が増える
  - **フェーズの並びだけで、前の列の全員から次の列の全員へ引く**: 同じ列の中の順番（受け入れ 1 → 直し 1 → 受け入れ 2）が言えない
  - **名札の語（「直し」「fix」）で差し戻しを見分ける**: 名札はスクリプトの自由な語で、言語にも縛られる。種類は SDK が運ぶ事実

### 論点 2: 手元に申し送りを出すか

**採る: 出さない。手元は、選んだ体の状態・種類・モデルと手順の並びだけにする。**

- 委譲先の進みの1行（`delegate-progress` の `summary`）はワークフロー1本の `task_progress` にしか無く、体ごとの申し送りは SDK から取れない（前提の裏取り）。体ごとに出すには会話の中身（`lastToolSummary`・`resultPreview`）を写すことになり、会話内容の扱い（`docs/coding-standards/conversation-content.md`）が禁じる、ブラウザへの会話の断片の持ち出しを新しく足すことになる
- 進みの1行はメインがセリフで言い直している（`docs/architecture/display/speak-tool.md`）。手元にも出すと同じ情報が2か所に出る
- 手順の行は、今のピルの一文と同じ材料（`workflow-step-started` の道具の名前と要約に使う欄1つ）で、画面に出すだけでログにもファイルにも書かない
- 採らなかった案: **ワークフロー1本の進みの1行を手元の頭に出す**: 体ごとの言葉ではなく、選んだ体と食い違う。会話の断片をブラウザへ送る経路も新しく要る

### 論点 3: 持つ手順の量と、終わったあとに残すか

**採る: 体ごとに直近 20 件の手順と、始まった手順の総数を持つ。手元は直近 4 件を見せ、「手順 n件をすべて見る」で持っている 20 件まで同じ面の中に開く（20 件を超えた分は「ほか n件」と数だけ言う）。ワークフローが終わっても、その依頼（やり取り）のあいだは図を残し、次の依頼を送ると捨てる。**

- 手順1件が持つのは、道具の名前・要約に使う欄1つ・始まりと終わりの時刻・失敗したか。体1体が持つのは `index`・`agentId`・名札・種類・モデル・`phaseIndex`・`phaseTitle`・`state`・`queuedAt`・`startedAt`・`durationMs`・`tokens`・`toolCalls`・`attempt`・止まり方の語（論点 6 の失敗の語）。`lastToolSummary`・`resultPreview`・`promptPreview`・`promptFramed`・`error` の文は写さない
- 行は前の行の欄を引き継がないので、種類・名札は `index` ごとに最後に届いた空でない値を残す（キャッシュの行と並びの中で落ちた行に種類が無い）
- 顔ぶれから外れたワークフローは、捨てずに「終わった」印を付けて残す（`workflowItemsOfTasks` はピルの一文の選び方にだけ使う）。終わったワークフローの走っている体は、最後の行の `state` のまま描かず、止まった体として描く
- 依頼が完了した全体の詳細では、ADR 0070 論点 8 の「完了したら畳まずに全フェーズを並べる」と同じく、図も畳まずに全部の列と体を出す。同じ依頼でワークフローが2本以上流れたら、新しいものを上に並べ、終わったものは見出し1行（名前・体の数・所要）に畳んで押すと開く
- 採らなかった案:
  - **体ごとに全部の手順を持つ**: 長い実装役は数百の手順を持ち、手元に出すのは直近だけ。状態がセッションの長さで伸び続ける
  - **ワークフローが終わったら図を消す**: 受け入れが済んだあとに何が起きたか（差し戻しの回数・落ちた体）を見返せない。完了の面で全体を出す ADR 0070 論点 8 と食い違う

### 論点 4: Astryx の部品の割り当て

**採る: 箱・印・件数・手順の並び・所要は `ui/` の包み（Astryx）で描き、自前で描くのは矢印の SVG と、箱を列に置く座標だけにする。**

| 図の要素                                  | 部品                                                                                 | 包み                                                    |
| ----------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------- |
| 箱（押すと手元が替わる）                  | `ClickableCard`。走っている・失敗・待ちの縁は包みの `tone`（差し色・赤・点線）で出す | 足す: `ui/clickable-card/`                              |
| 状態の印（走っている・済み・失敗・待ち）  | `StatusDot`（`accent`・`success`・`error`・`neutral`）。回さず脈打たせない           | 足す: `ui/status-dot/`                                  |
| 種類の札・頭の件数（動いている・済み・…） | `Badge`                                                                              | 今の `ui/badge/`                                        |
| 名札・一言・列見出し・所要の字            | `Text`（所要は今の `formatElapsed` の字を等幅で）                                    | 今の `ui/text/`                                         |
| 手元の手順の並び                          | `List`（行は今の全体の詳細の手順の行と同じ形）                                       | 今の `ui/list/`                                         |
| 手元の囲み・面の区切り                    | `Surface`・`Divider`                                                                 | 今の `ui/surface/`・`ui/divider/`                       |
| 矢印・始まりの点                          | 自前の SVG（`path` と `marker`）。座標は箱を置いたあとに測る                         | 図の部品（`main-view/` の下）に置き、`ui/` には置かない |

- 所要は `Timer`・`Timestamp` を使わない。tsukumo の秒の書き方（`formatElapsed`。ピルの一文・フェーズの所要と同じ）とそろわないため
- 走っている体の印に `Spinner` を使わない（会話の画面に回る印を置かない。ADR 0070 論点 2・4）
- 箱は `aria-pressed` で選ばれた体を示し、読み上げの名前は「<名札>、<種類の短い名>、<状態>」

### 論点 5: 体の数の上限と畳み方

**採る: 列1つに箱は5つまで。6体以上なら4つを出し、5つ目を「ほか n 体」の箱にする。残す4つは、走っている体・失敗した体・待ちの体・済んだ体の順に、同じ種の中では新しい順で選ぶ。「ほか n 体」を押すとその列だけ全部を出す（面の中で転がす）。列は今の列を含めて4つまでで、それより前の済んだ列は「済んだ n フェーズ」の細い列1つに畳み、押すと開く。**

- 列になるのは、体が載ったフェーズと、今より後ろのフェーズ。体が載らずに済んだフェーズ（メインが進めた段）は列にせず、図の下のフェーズの一覧に今の形で残す
- 「ほか n 体」の箱の矢印は、中の体の矢印を1本にまとめる
- 採らなかった案: **箱を小さくして全部を並べる**: 名札と一言が読めない幅になる。並んで回る体が多いときに知りたいのは、走っている体と落ちた体

### 論点 6: 名札の扱いと失敗の語

**採る: 箱の名前は名札（`label`）をそのまま出し、1行で末尾を「…」に縮めて全部は `title` に入れる。名札が無ければ種類の短い名、それも無ければ「エージェント n」（n は `index`）。**

- `task-flow` の名札を日本語にするのは別のタスク（`workflows/task-flow.js` 側）。tsukumo はスクリプトの語を言い換えない
- 失敗の理由は `error` の文を写さず、サーバで決まった語に畳む: `skipped` は「飛ばした」、`blocked` は「安全の判定で止まった」、応答が止まった（CLI の決まった文）は「応答が止まった」、ほかは「失敗した」。済んだ体の一言は「済み」と手順の数（「済み · 手順 12」）、差し戻しの矢印の元になった体は「差し戻し」
- 採らなかった案: **`resultPreview` の頭を一言に出す**: 会話の中身で、論点 2 と同じ理由で写さない

### 論点 7: 面の高さと転がし方

**採る: 高さの上限は今のまま（`max-block-size: min(70dvh, 35rem)`）。面全体を1つの転がす器にし、頭（「手順」・ワークフローの名前・件数）と下端（目安の残り）は器の中で上下に貼り付ける。図と手元が収まらなければ、図・手元・フェーズの一覧の順に並んだまま転がす。**

- 列ごとの箱の上限（論点 5）で、図の高さは5つの箱の分（約 300px）を超えない。図の中には別の転がす器を作らない（入れ子の転がしを避ける）
- 「すべて見る」「ほか n 体」を開いた状態は、面を閉じて開き直すと畳んだ姿に戻る（今の畳みと同じ）

### 論点 8: エージェントの種類の出どころと出し方

**採る: 種類は `workflow_agent` の `agentType` から取り、箱の2行目の頭に `Badge` の札で短い名を、手元の頭に全名とモデルを出す。短い名はプラグインの接頭辞（最後の `:` より前）を外した語（`tsukumo-workflow:acceptor` → `acceptor`）。**

- 名札と短い名が同じ語（大文字と小文字を区別しない）なら、箱の札を出さない（手元の頭の全名は出す）
- 種類が取れない体（`agent()` に `agentType` を渡さない素の体）は、箱の札を出さず、手元の頭に「既定のエージェント」と書く
- 見本の画: `pill.html?scene=seq&open=1` の各箱の2行目の頭の札（`no-delegate`・`acceptor`・`retrospector`）と、手元の頭の「tsukumo-workflow:no-delegate · sonnet」。`?scene=par` は種類を渡さない並んで回るレビューで、箱に札が無く手元の頭が「既定のエージェント」
- 採らなかった案:
  - **hook の入力の `agent_type` から取る**: 体の中で道具を使うまで届かず、待ちの箱と考え中の箱に種類が出ない。行の `agentType` が同じ値を先に運ぶ
  - **エージェントの定義の `description` から短い名を引く**: 定義のファイルをサーバが探して読む経路が要り、`description` は呼ぶ側への長い説明で札に入らない
  - **全名を箱に出す**: 箱の幅（約 200px）で名札と並ばない。全名は手元の頭で読める

### 全体の詳細の形（ADR 0070 論点 8 を改める範囲）

**採る: 全体の詳細の幅を、ワークフローの有無を問わずピルの幅にそろえる（左右の端をピルの左右の端に重ねる）。ワークフローがある依頼では、頭の見出しの下に図、その下に選んだ体の手元、その下に今の詳細の中身（「バックグラウンドタスク」の区画と、図の列にならなかったフェーズの一覧）、最下端に目安の残りを置く。**

- 図の列になったフェーズは、フェーズの一覧の行にしない（名前と所要は列の見出しが持つ）。そのフェーズのまとめは、区間を押したフェーズの詳細（ADR 0070 論点 7）だけが持つ
- ワークフロースクリプト自身の行は「バックグラウンドタスク」の区画に出さない（ワークフローの名前は図の頭が持つ）
- 手元の最初の選びは、走っている体（2体以上なら最後に手順が始まった体）、走っている体が無ければ最後に終わった体
- ワークフローの無い依頼は、幅のほかは今の全体の詳細のまま
- 依頼全体の経過はピルの1行が持つので、詳細の下端には出さない

## 採らなかった案

| 案                                                           | 物差し                                                                              | 判定     |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------- | -------- |
| サイドバーや流れに常設の図を置く（`compare.html` の案 A〜C） | 利用者はずっと見張りたいわけではなく、押したときだけ見たい                          | 採らない |
| 全体の詳細の幅を、ワークフローがあるときだけピルにそろえる   | 依頼の途中でワークフローが始まると面の幅が跳ぶ。1つの形のほうが読む人に分かりやすい | 採らない |
| 図をフェーズの詳細（区間を押したとき）にも出す               | 同じ図が2か所に出る。区間の詳細はそのフェーズのまとめと手順を持つ                   | 採らない |

## 見本と違う決定

- 見本の手元の申し送りの行（「…」と「申し送り」）は出さない（論点 2）
- 見本の済んだ体の一言「指摘 2件」「指摘 3件」は、数を写す材料が SDK に無いので「済み · 手順 n」にする。失敗の理由「ターンの上限に達した」は決まった語（論点 6）にする
- 見本は後ろの段の体（受け入れ 2・振り返り）を先に点線の箱で描く。SDK は呼ばれる前の体を送らないので、まだ呼ばれていないフェーズは点線の空きの箱1つにする（論点 1）。並びの門で待つ体は点線の箱で描く
- 見本の走っている矢印は破線が流れ、状態の印は回る。どちらも動かさない（ADR 0070 論点 2・4。止まった差し色の線と点）
- 見本の下端の「経過」は出さない（ピルの1行が持つ）
- 見本の面は「外を押す・Esc で閉じる」の字を下端に置く。字は置かず、閉じ方は今の全体の詳細のまま

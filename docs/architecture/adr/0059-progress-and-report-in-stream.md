# 進行とレポートの出し方: 帯は位置だけ・「いま」は流れの末尾の1行・お願いは最下部（2026-11-15）

ステータス: 採用

**会話の流れ（ADR 0058）の上で、進み具合のプログレスバーは位置（状態・フェーズの丸・今のフェーズの名前・経過・「手順」）だけを1行で言い、走っている手順は流れの末尾の1行（「いま」の行）に回る印と一緒に出す。「手順」を押すと計画の全体とフェーズごとの道具の呼び出しが帯の下に開いたままになる。レポートの冒頭は結論の直後を検証の結果だけにし、利用者への用件「お願い」は今と同じレポートの末尾に置く。この ADR は ADR 0056 を置き換え、ADR 0058 の対応表の4行（進み具合のプログレスバー・段の丸の吹き出し・段の札・最終レポート）の扱いを上書きする。**

この ADR が決めるのは、進行とレポートの情報の置き場・出し方・送る順まで。見た目の寸法・色・字の大きさは決めない（見本と、器・トークンの ADR が持つ）。`report`・`work_plan`・`phase_result` の入力に欄は足さない。

## 何が困っていたか

- ADR 0058 の対応表は、進み具合のプログレスバー・段の丸の吹き出し・段の札・最終レポートを、中身は今のまま会話の流れへ載せるとしている。見本 A2 の進行の帯は1行で、今のプログレスバーの2行目（走っている手順。`docs/architecture/screen-design/work-strip.md` の「2行目」の項）の置き場が決まっていなかった。
- 今のフェーズの名前が、帯と流れの札の2か所に出る。「いま」の行がセリフのたびに流れの途中で動き、のぞく位置が定まらない。
- 利用者への用件があることを知らせるのは、頭の「お願い 1 ↓」の印だけだった（用件の本文は紙の末尾）。
- ADR 0056 は「採用」のままだが、実装は 2026-11-15 の revert でツリーに無い。その中心（1枚の紙・`report` の6つの欄・読む深さの3段）は、今回の決定と合わない。

## 利用者が決めたこと（2026-11-15）

- 見本の案2（`docs/history/mockup/report-progress-2026-11-15/index.html?plan=tail`。3案の比較は同じディレクトリの `compare.html`）を採る。言葉と見本が食い違ったら見本が勝つ。
- お願いは最下部のまま、見出しの語も「お願い」のまま（見出しは質問への答え）。
- 狭い画面（760px 以下）は今のまま残す。
- 後回しにしたもの（うち、手順の言い換え・止まって見えるときの言い方・委譲先の役の1行は ADR 0062 論点 3 が解いた）: 走っている手順を人の言葉の文に言い換えること・止まって見えるときの言い方・委譲先の役ごとの1行・見込みの時間・やり直しの周と計画を直した理由・前回との対応・置いた前提・背面のときの通知と音。

## 決めたこと

見本の画は `docs/history/mockup/report-progress-2026-11-15/` の下にある（以下、画の名前だけ書く）。

### 論点 1: 実行中の手順の置き場

> この論点の「行の文は今の2行目と同じ（道具の名前と引数の要約）」は、ADR 0062 論点 3（動詞・対象・経過）が上書きした。行の位置は変わらない（2026-11-16）。

**採る: 進み具合のプログレスバーは1行で、位置（状態・フェーズの丸・今のフェーズの名前・経過・「手順」）だけを出す。走っている手順は、会話の流れの末尾の1行（「いま」の行）に出す。流れに今のフェーズの札は置かず、足すのは済んだフェーズの札だけ。行の文は今の2行目と同じ（道具の名前と引数の要約）。**

- 今のフェーズの名前の置き場が帯の1か所になり、「いま」の行は入力欄の 40px 上の決まった位置に出て、セリフのたびに動かない。
- 流れは足すだけで、書き換わる札が無い。
- 該当する画: `tail-work-1400.png`・`tail-back-1400.png`。

### 論点 2: 回る印

**採る: 回る印は、末尾の行の頭の1個だけ。プログレスバーの今のフェーズの丸と、開いた「手順」の一覧の実行中の行は回さない。**

- ADR 0058 論点 9 の「ぼかしの面の中で無限に動くものを置かない」と同じ向き。帯はぼかしの面で、そこに動くものを置かない。
- 該当する画: `tail-work-1400.png`・`tail-work-steps-1400.png`。

### 論点 3: 「手順」の一覧

**採る: 「手順」を押すと、プログレスバーの下に、計画の全体（全フェーズの印・名前・所要）とフェーズごとの道具の呼び出しが開いたままになる。済んだフェーズの手順は畳み、今のフェーズは開く。フェーズの丸の吹き出しはやめ、丸を押すと同じ一覧をそのフェーズの位置で開く。読むあいだは、フェーズごとの所要時間の帯をこの一覧の末尾に出し、最終レポートの冒頭からは外す。**

- これからのフェーズの名前は、これまで丸の吹き出しを1つずつ押さないと読めなかった。一覧にすれば全部を1回で読める。
- 所要時間の帯は進行の情報で、レポートの冒頭に置くと「進行は帯と一覧、結論はレポート」の線が崩れる。
- 該当する画: `tail-work-steps-1400.png`・`tail-read-steps-1400.png`。

### 論点 4: レポートの冒頭

**採る: 結論の直後は検証の結果だけにする。検証の行に、打ったコマンドと照らせた行は「記録あり」、それ以外は「申告のみ」の印を付ける。終わり方のバッジ（「完了」など）は冒頭から外し、プログレスバーの状態の語とやり取りの列の印が言う。**

- 状態の語が帯・やり取りの列・冒頭の3か所に出るのをやめる。
- 該当する画: `tail-read-1400.png`。

### 論点 5: お願いと入力欄の上の知らせ

**採る: お願いの本文の位置は今と同じレポートの末尾、見出しの語も「お願い」のまま。続けて頼める選択肢は今の「次の一手」の行が持つ。冒頭の「お願い 1 ↓」の印はやめ、入力欄の上の帯に知らせを出す（お願いが見えているあいだは出さない）。**

- 利用者が動く用件は入力欄のそばに置く。結論の直後や上部へ移さない。
- 該当する画: `tail-read-end-1400.png`（末尾のお願いまで送った形）。

### 論点 6: 離席の境目

**採る: ページが隠れていたあいだに流れへ足された行の手前に、境目の線を1本出す。前に見た位置はタブのメモリだけに持つ。**

- 戻ってきたときに、どこから新しいかが線で分かる。保存はしないので、別のタブや再読み込みでは出ない。
- 該当する画: `tail-back-1400.png`。

### 論点 7: タブの題

**採る: 題の頭に状態の印を付ける。答え待ちは今の「● 」のまま。作業中・失敗・ページが隠れているあいだの完了と止めたを足す。**

- 背面のタブでも、題だけで状態が読める。通知と音は後回し。
- 題は画面の幅によらないので、狭い画面でも同じ印を付ける。
- 該当する画: なし（タブの題は見本の画に写らない）。

## 採らなかった案

比較ページ `docs/history/mockup/report-progress-2026-11-15/compare.html` の案1・案3。数は `compare.js` の `PLANS` の値（1400×900 の実測）を写した。

| 案                       | 形                                                                         | 働く場面の流れの高さ | 今のフェーズの名前の置き場 | 「いま」の行の上端                  |
| ------------------------ | -------------------------------------------------------------------------- | -------------------- | -------------------------- | ----------------------------------- |
| 案1 今の計画のまま       | フェーズごとの札が流れに並び、今のフェーズの札に「いま」と「できた」が出る | 702px                | 2か所（帯と流れの札）      | 620px → 675px（セリフのたびに動く） |
| 案2 帯と末尾の行（採る） | 帯は位置だけ、「いま」は流れの末尾の1行                                    | 702px                | 1か所（帯）                | 729px → 729px（動かない）           |
| 案3 頭に計画の一覧       | 働くあいだ、中央の列の頭に計画の一覧を開いたまま置く                       | 511px                | 1か所（頭の一覧）          | 181px → 292px（一覧の中で下がる）   |

- **案1を採らない理由**: 今のフェーズの名前が帯と流れの札の2か所に出る。「いま」の行が流れの途中でセリフのたびに動き、のぞく位置が定まらない。
- **案3を採らない理由**: 働くあいだの流れの高さが 702px から 511px に減る（4フェーズのとき。増えるとさらに減る）。ADR 0058 の「フェーズの札は流れの中」を改める必要がある。お伺いが届いたら一覧を畳む決まりが要り、畳むたびに流れの高さが変わる。案2 でも「手順」を開けば同じ一覧が読める。

## 送る順

タブの題のほかは、会話の流れ（ADR 0058 の送る順の段1）が主ブランチに入ったあとに送る。タブの題は流れの行を使わないので、先に送れる。1件送るごとに画面が使える状態を保つ。

1. **末尾の行と回る印。** 流れの末尾に「いま」の行を足し、進行の帯の2行目と今のフェーズの札を外し、回る印を末尾の行の1個にする（論点 1・2）。
2. **「手順」の一覧。** 計画の全体とフェーズごとの手順を帯の下に開いたままにし、丸の吹き出しをやめて丸から同じ一覧を開く（論点 3）。1 のあとに送る。
3. **所要時間の帯の移動。** フェーズごとの所要時間の帯を、最終レポートの冒頭から「手順」の一覧の末尾へ移す（論点 3）。2 のあとに送る。
4. **レポートの冒頭。** 結論の直後を検証の結果だけにし、「記録あり」「申告のみ」の印を付け、終わり方のバッジを外す（論点 4）。
5. **お願いの知らせ。** 冒頭の「お願い 1 ↓」をやめ、入力欄の上の帯に知らせを出す（論点 5）。4 のあとに送る。
6. **離席の境目。** ページが隠れていたあいだの行の手前に線を出す（論点 6）。1 のあとに送る。
7. **タブの題。** 状態の印を足す（論点 7）。

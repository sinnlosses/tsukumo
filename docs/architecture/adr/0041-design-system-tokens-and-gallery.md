# 画面全体のデザインシステム: 余白・角丸・影・動きのトークンと見本帳（2026-10-28）

ステータス: 採用

**余白・角丸・影・動きにも、色と字の大きさと同じくトークンを持たせる。余白は 4px 刻みの 7 段（`2xs`〜`2xl`）、名前は大きさの語（`--space-md`）、直書きは `font-size.test.ts` と同じ形の検査で止める。`ui/` には `Surface`・`Badge`・`Divider` を足し、見本帳は帯に出さない専用の画面 `#design` に置く。Storybook は入れない。** 範囲は画面全体で、カタログの部品（`report` の a2ui の面）と `ui/` の部品が同じトークンを読む（利用者決定 2026-10-28）。余白の段・名前の付け方・見本帳の形は利用者が選んだ（2026-10-28）。

トークンの役割と使い分けは `docs/architecture/screen-design/design-token.md`。この ADR は、決めた理由・今の値の分布・採らなかった案・置き換えの順を持つ。この文書でいう「デザイントークン」は CSS のカスタムプロパティで、LLM のトークン（トークン消費）とは別の語。

## 何が困っていたか

- 色（`color.md`）と字の大きさ（`principle-and-type.md`「13.3 Type」）にはトークンがあり、字の大きさは `test/architecture/font-size.test.ts` が直書きを止めている。余白・角丸・影・動きにはトークンも検査も無い。
- 値が揃わないまま増えている。同じ「少し空ける」が `0.4rem`・`0.5rem`・`0.6rem`・`6px`・`8px`・`10px` に散らばる。
- `ui/stack` の間隔だけが `xs`〜`xl` の 5 段を持ち、事実上の最初の段になっている。ほかの部品は見ていない。
- `ui/` の 18 部品はどれも「箱（余白・角丸）は呼び出し側が `className` で渡す」作りで、箱の語彙が `ui/` に無い。同じ形の箱を 216 の規則が別々に書いている。
- カタログの部品（`a2ui-surface.tsx`）は葉を Markdown に戻して旧い描画で描いており、`ui/` の部品もトークンも使っていない。

## 決めたこと

### 論点 1: トークンの段と値

**余白は 4px 刻みの 7 段。角丸は 4 段と 2 つの形。影は 2 段と輪。動きは 2 段。単位は `rem` に揃える。**

| 種類 | トークン（値）                                                                                                                                                                           |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 余白 | `--space-2xs`（0.125rem）・`xs`（0.25rem）・`sm`（0.5rem）・`md`（0.75rem）・`lg`（1rem）・`xl`（1.25rem）・`2xl`（1.5rem）                                                              |
| 角丸 | `--radius-sm`（0.25rem）・`md`（0.5rem）・`lg`（0.75rem）・`xl`（1rem）・`pill`（999px）・`round`（50%）                                                                                 |
| 影   | `--shadow-raised`（`0 8px 24px rgb(0 0 0 / 0.3)`）・`--shadow-overlay`（`0 20px 50px color-mix(in srgb, var(--ground) 80%, transparent)`）・`--shadow-ring`（`0 0 0 2px var(--accent)`） |
| 動き | `--motion-fast`（0.12s）・`--motion-base`（0.2s）                                                                                                                                        |

- **余白の寄せ方は「近い段へ。同点は大きい段へ」。** 同点になる 6・10・14・18px を大きい段（`sm`・`md`・`lg`・`xl`）へ寄せるのは、押す的と読む余白が小さくならない向きにするため。
- 段は `ui/stack` の既存の `xs`〜`xl`（0.25〜1.25rem）をそのまま土台にし、`2xs`（0.125rem）と `2xl`（1.5rem）だけを足す。**`Stack` の `gap` の語がそのままトークンの名前になる。**
- **寄せたときに動く幅**（余白 1212 個・角丸 309 個を、この規則で寄せた数え。数えた個数は宣言の中の長さ 1 つずつ）:

  | 種類 | そのまま乗る | 1px 以内 | 2px 以内 | 2px を超える | 直書きのまま許す        |
  | ---- | ------------ | -------- | -------- | ------------ | ----------------------- |
  | 余白 | 594          | 130      | 402      | 0            | 28px 以上 34・負の値 22 |
  | 角丸 | 124          | 67       | 112      | 6            | `999px` 以上 15         |

  余白は最大 2px、角丸は 6 個（18〜22px）だけが 2px を超えて `--radius-xl` へ寄る。置き換えの課題は、寄せた画面の前後を撮って目視で確かめる。

- 余白の寄せ先の件数（上の規則で数えた）: `2xs` 68・`xs` 175・`sm` 375・`md` 273・`lg` 146・`xl` 64・`2xl` 25。
- **28px 以上の余白は直書きのまま許す。** 余白ではなく領域の寸法（余白の柱・仕切りなど）で、段を増やす理由にならない。負の余白は `calc(-1 * var(--space-xs))` と書く。
- 角丸の寄せ先: `sm` 55・`md` 145・`lg` 66・`xl` 43。`50%`（45 個）は `--radius-round`、`999px`（15 個）は `--radius-pill`。
- 影の寄せ方: ぼかし 30px 以下の 9 宣言を `--shadow-raised`、40px 以上の 10 宣言を `--shadow-overlay` に寄せる。向きのある 2 宣言（引き出し・下の板）と、輪・内側の線 24 宣言は、色・幅・向きがそれぞれ違うので直書きのまま許す。輪のうち `0 0 0 2px var(--accent)` の形（3 宣言）は `--shadow-ring` に寄せる。
- 動きは `transition` の時間だけをトークンにする（`0.12s`→`--motion-fast`、`0.18s`・`0.2s`→`--motion-base`）。`animation` は立ち絵・吹き出し・回転がそれぞれの時間を持つので、局所のつまみ（`--portrait-*-duration` など）のまま。緩急は `ease-out` が大半でキーワードのまま書く。
- **減らす設定（`prefers-reduced-motion: reduce`）への対応は足さない。** `theme.css` の `@media (prefers-reduced-motion: reduce)` が全要素の `transition-duration`・`animation-duration` を `0.01ms` にしているので、トークンの時間もそのまま従う。
- **色と字の大きさは変えない。** 値の正典は `theme.css`、役割の正典は `color.md`・`principle-and-type.md` のまま。キャラクターのパックが差す色のつまみ（`accent` など）の仕組みも変えない。

### 論点 2: トークンの名前

**大きさの語で付ける（`--space-md`・`--radius-md`）。** 影と動きだけは使う場面の語（`--shadow-raised`・`--motion-fast`）にする。

- `ui/stack` の `gap="md"` と `var(--space-md)` が同じ値を指す。語を 2 つ持たない。
- 字の大きさは役の名前（`--font-label`・`--font-body`）で、色も役の名前を持つ。余白と角丸は役が無く連続した量なので、段の名前で呼ぶ。役の名前（`--space-card-pad`）は余白 1,291 宣言の分だけ増え続け、値を揃える目的が薄れる。
- 段を足すときは**端に足す**（`3xl` のように）。`md` の意味を動かさない。
- **用語集との関係**: 「トークン」は tsukumo では LLM のトークン消費（`docs/glossary/usage-review.md`・`local-record.md`）を指す語として使われている。紛れるので、画面の文書は「デザイントークン」と書く（`docs/glossary/view.md` に項目を足す）。CSS のカスタムプロパティの名前は変えない。

### 論点 3: `ui/` の部品の語彙

**18 部品に、箱を持つ 3 つ（`Surface`・`Badge`・`Divider`）を足す。** カタログの部品の土台は、枠＝`Surface`、見出し＝`Heading`、並べる入れ物＝`Stack`・`HStack`・`VStack`、印＝`Badge`。

| 分け         | 今ある部品                                                      | 足す部品  |
| ------------ | --------------------------------------------------------------- | --------- |
| 並べる       | `Stack`・`HStack`・`VStack`                                     | なし      |
| 字           | `Text`・`Heading`                                               | なし      |
| 操作         | `Button`・`Select`・`TextField`・`Field`・`Menu`                | なし      |
| 重なる面     | `Dialog`・`BottomSheet`・`ImageZoom`                            | なし      |
| 読み込み・絵 | `Spinner`・`Skeleton`・`TypingDotList`・`Icon`・`LayoutResizer` | なし      |
| 箱           | なし                                                            | `Surface` |
| 印           | なし                                                            | `Badge`   |
| 区切り       | なし                                                            | `Divider` |

足す根拠は規則の数。`border-radius` を持つ 370 の規則のうち 216 が、地と枠か影を合わせて持つ箱の形で、`card` を名前に含む class が 83、`mark`・`tag`・`chip`・`badge` が合わせて 98、`divider` が 5 ある。

- **`Surface`**: 地・枠・角丸・余白を持つ箱。地の段は `color.md` の `--surface`・`--surface-raised`・`--surface-accent` の 3 つ（`tone`）、余白は `--space-*`・角丸は `--radius-*`、影は `none`・`raised`・`overlay`。`Button` と同じく、持つのは顔で、置き方（margin・flex）は呼び出し側が `className` で渡す。
- **`Badge`**: 小さな印。`tone` は `neutral`・`ok`・`warn`・`ng`・`accent`、字は `--font-label`、角丸は `--radius-pill` か `--radius-sm`。
- **`Divider`**: 罫。`--rule`・`--rule-soft`・`--rule-quiet` の 3 段。

部品の props は、既存の `ui/` と同じく**全部必須にして型で縛る**（`Stack` の作り）。足す 3 部品は、見本帳が並べる前に入れる。既存の箱を部品へ移すのは、見本帳ができてから領域ごとに別の課題で進める（論点 5 の置き換えは値だけを直す）。

### 論点 4: 見本帳の置き場と形

**専用の画面 `#design` を足す。帯には出さず、hash を打って開く。** 初期読み込みの束には入れない（`Character`・`TokenUsage`・`Achievement` と同じく `deferredScreen` で `import()` に外す）。

- 並べるのは 3 つ: デザイントークン（色・字・余白・角丸・影・動きの値と使われ方）、`ui/` の部品（状態ごと）、カタログの全部品（26 部品）。
- **カタログの部品の例は `report_part_card` が返す例（スキーマを通ることが検査済み）をそのまま使い**、a2ui の面で描く。見本のために例を二重に持たない。
- `scripts/capture/capture-catalog.ts` と E2E から hash で開いて撮れる。撮影の道具に新しい仕組みは要らない。
- 画面を足すと、`Screen` の型（`stores/location-hash.ts`）・`Layout` の `OVERLAY_SCREEN`・E2E の見張りの表（`scripts/shared/e2e-watch.ts`）に 1 行ずつ要る。
- **Storybook は入れない**（利用者から判断を任された。2026-10-28）。理由は 3 つ。
  1. カタログの部品の例は `report_part_card` の側に既にあり、story を並べると例を二重に持つ。
  2. 撮影と E2E は疑似セッションと `capture-catalog` で既に回っており、Storybook は別の起動と別の撮影の経路を持つ。
  3. 画面ごとに `import()` で外す作りがあり、専用の画面なら同じ道具立て（Vite・CSS Modules・型の生成）で足せる。Storybook の依存の重さ・版の追随（Vite 8・React 19）は測っていないが、測る前から採らない側に倒せる理由が上の 3 つで足りる。

### 論点 5: 既存の直書きの置き換えの順と大きさ

**トークンと検査を入れたあと、領域ごとに 1 課題 1 コミットで置き換える。** 1 課題は宣言 220 以下・ファイル 20 以下を目安にし、`ui/` を先頭にする（ほかの領域が `Stack` の段を読むため）。

| 順  | 課題の題（置き換えの対象）                                                      | 宣言 | ファイル |
| --- | ------------------------------------------------------------------------------- | ---- | -------- |
| 1   | 直書きの置き換え（`ui/`・`app/`・`portrait`・`protocol-mismatch`・`skip-link`） | 67   | 17       |
| 2   | 直書きの置き換え（`run-setting`・`current-work`・`sidebar`）                    | 152  | 18       |
| 3   | 直書きの置き換え（トークン消費の画面）                                          | 103  | 8        |
| 4   | 直書きの置き換え（成果の画面）                                                  | 118  | 8        |
| 5   | 直書きの置き換え（キャラクターの画面）                                          | 145  | 5        |
| 6   | 直書きの置き換え（`task-board`）                                                | 195  | 20       |
| 7   | 直書きの置き換え（`screen-nav`）                                                | 216  | 13       |
| 8   | 直書きの置き換え（会話の画面: 入力欄・キャラビュー・雑談・外枠）                | 168  | 13       |
| 9   | 直書きの置き換え（会話の画面: お伺い・保留の札・画像・リポジトリのリンク）      | 84   | 5        |
| 10  | 直書きの置き換え（会話の画面: メインビュー）                                    | 185  | 18       |

- **会話の画面の `markdown/`（314 宣言・15 ファイル）は、この表に入れない。** 葉の部品を Markdown に戻さず React の部品で直接描く課題（カタログの葉の移行）が、この CSS ごと書き直す対象と重なる。置き換えても捨てる可能性が高いので、その課題が何を残すかを決めてから、残るぶんだけ置き換える。残るぶんは検査の除外の一覧に載ったままになる。
- 置き換えの課題は、寄せ方の規則（論点 1）を当て、前後を撮って動いた画面を目視する。1 課題の中で `Surface`・`Badge`・`Divider` への差し替えはしない（値の置き換えと部品への移行を同じコミットに混ぜない）。部品への移行は、見本帳ができてから領域ごとに別の課題で進める。
- 余白の `0` と、局所のつまみ（`--report-block-gap` など `var()` で書いたもの）は置き換えの対象外。

### 論点 6: 検査の形

**`test/architecture/font-size.test.ts` と同じ形にする。** `theme.css` 以外の `*.css` の、コメントでない行の宣言を読み、次を通す。

| 対象                       | 通す値                                                                                                   |
| -------------------------- | -------------------------------------------------------------------------------------------------------- |
| `padding`・`margin`・`gap` | `0`・`auto`・`var(--space-*)`・局所のつまみ・`em`・`%`・28px 以上・`calc()` が上のものだけで組まれるもの |
| `border-radius`            | `0`・`var(--radius-*)`・`%`・`999px` 以上                                                                |
| `box-shadow`               | `none`・`var(--shadow-*)`・ぼかしが 0 の輪・`inset`・向きのある影の例外                                  |
| `transition` の時間        | `var(--motion-*)`                                                                                        |

- **今の違反は、ファイルごとの件数で除外の一覧に載せて通す。** 件数が増えたら落ち、減ったら一覧を減らすよう促す。一覧は減る向きにだけ動く。
- **除外の一覧の上限の見込み**（上の規則を今の CSS に当てた数え）: 126 ファイル（155 ファイル中）・1,222 宣言（余白 898・角丸 297・影 21・`transition` 6）。置き換えの課題が `markdown/` 以外を空にし、`markdown/` の 15 ファイルが最後に残る。
- 字の大きさの検査と違い、局所のつまみは 1 つずつ名前を列挙せず、`var(--*)` の形なら通す。余白で `var()`・`calc()` を使う箇所が 79 あり、字の大きさの局所のつまみ 4 つより桁が多く、列挙が保守の負担になるため。

## 採らなかった案

| 案                                           | 採らなかった理由                                                                                          |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 余白を 2px 刻みの 9 段にする                 | 見た目はほぼ変わらないが、段が増えて「どれを使うか」の迷いが残り、`Stack` の 5 段と別の段を足すことになる |
| 段の番号で名前を付ける（`--space-3`）        | `ui/stack` の語（`xs`〜`xl`）と別の語が並び、値を毎回 `theme.css` で引く必要がある                        |
| 使う場面の名前で付ける（`--space-card-pad`） | 1,291 宣言ぶん名前が増え続け、同じ値が別名で並ぶ。値を揃える目的が薄れる                                  |
| 見本帳を疑似セッションの場面だけで済ませる   | カタログの部品しか並ばず、トークンと `ui/` の部品を並べる場所が無い                                       |
| Storybook を入れる                           | 論点 4 の 3 つの理由                                                                                      |
| 置き換えを 1 課題でまとめて行う              | 1,754 宣言・126 ファイルの差分は 1 コミットで説明が付かず、動いた画面の目視も追えない                     |

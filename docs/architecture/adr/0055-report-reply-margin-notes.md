# 返す層の見た目: 選んだ所の横の余白に「聞く・頼む」を1つ出し、欄と答えは余白の札にする（2026-11-11）

ステータス: 採用

**何も押していないときは「聞く・頼む」のボタンを出さない。字を選ぶか、行・案・主張・部品の題の行を押すと、その横の余白に「聞く・頼む」を1つ出す。押すと余白に札が開き、本文は押し下げない。札はそのまま問いと答えの札になり、指した所の横に残る。字を選ぶ「引いて聞く」は、この口にまとめる。「この案で進める」「確かめて」のボタンは置かず、案・主張を指して頼む。余白の無い狭い幅では、「聞く・頼む」を行の右に出し、欄と答えは下から出すシートにする。**

この ADR は 0051 の論点 1 のボタンの置き場と、「利用者が決めたこと」の聞く・頼むの出し方を置き換える。残りは 0051 を読む。聞く・頼む・続きの意味、待ちのときの補足メッセージ、指した所の形（`ReplyTarget`）、付箋の置き場、まとめた下書きの文面、次の一手、機能の境界（0051 の論点 2〜7）は変えない。

## 何が困っていたか

利用者は 2026-11-10 に、0051 で入れた返す層について「ボタンが並んでうるさい」「入力欄と答えの出方が落ち着かない」の2つを挙げた。`docs/research/reply-interaction-rethink-2026-11-10.md` の「3. 数の比較」によると、表 10 行・案 3 つ・主張 2 つのレポートでは、返す層のボタンが 30 個ある。ポインタを重ねられる画面で見えるのは、何も押していないときに 4 個、表の行に重ねると 8 個。触れる画面では 30 個が常に見える。欄を開くと本文が 208.78px 押し下がる。

### 論点 2: どこを指したかの見せ方と、キーボードだけで指して開く道

**採る: 指せる単位は、表の行・`Options` の案・`Claims` の主張・内容部品の題の行の4つにする。指した単位には左端に差し色の線を引き、地を差し色でわずかに染める。札の頭に、指した所の1行（`検査ごとの所要 › 表 1 › E2E（会話）`）を出す。**

- 押す: 単位を押す（触れる画面では触れる）と指す。字を選び終えたときは、選んだ字を含む単位を指す（論点 4）。指せる単位の外を押すか Esc で、指すのをやめる。指せるのは一度に1か所。
- 行を持たない内容部品（コード・文・図など）は、題の行だけが指せる単位になる。題の行を押すと部品全体を指す（`rowIndex` なし）。表・案・主張の部品も、題の行を押せば部品全体を指せる。
- 配置の部品・頭の欄（要点の数・確かめたこと・振り返り）・`Report.figure` は、0051 の論点 1 と同じく指せる単位にしない。

**何も押していないときの手がかりは、余白の書き添え1つで足りるとする。** `a-idle-1400.png` のように、レポートで最初に指せる単位の横の余白に「字・行・案を選ぶと、ここに「聞く・頼む」が1つ出る」と1つだけ書く。足りるとした理由は2つ。まず、画では書き添えが表の1行目の横にあり、読み始めて最初の表に目が行く所に入る。次に、書き添えは押せない字なので、0051 の論点 1 の線（押せる見た目の部品は、押した結果が必ず画面に出る）に触れない。WCAG 3.2.7 Hidden Controls の解説（比較の文書の「2.」）が言う見つけにくさは、この書き添えと、Tab で単位に入ったときに口が出ることで補う。書き添えを出すのは、余白を出していて、そのレポートに指せる単位があり、まだ一度も指していないときだけ。狭い幅では余白が無いので書き添えを出さない（`a-idle-700.png` にも無い）。触れる画面では、行を押すと指す形を初回の書き添えなしで使うことになる。困る様子が見えたら決め直す。

**キーボードの道:**

| 操作                       | キー                                                                   |
| -------------------------- | ---------------------------------------------------------------------- |
| 部品の指せる単位に入る     | Tab（内容部品ごとに止まり場は1つ。前に入っていた単位、無ければ題の行） |
| 部品の中で単位を動く       | ↑ ↓（ほかの止まり場を増やさない）                                      |
| 指す                       | 単位にフォーカスが来たら指したことにして、余白に「聞く・頼む」を出す   |
| 札を開く                   | Enter、または ⌘⌥M（字を選んでいるときも同じ）                          |
| 札の聞く・頼むを切り替える | 札の中の切り替え（Tab で入る）                                         |
| 札を閉じて単位へ戻る       | Esc                                                                    |

- 部品の中を ↑ ↓ で動く形（roving tabindex）にするのは、表 10 行・案 3 つ・主張 2 つのレポートで、単位ごとに Tab の止まり場を置くと止まり場が 15 を超えるため。今の形の 30 個のボタンをキーボードの道に置き直すことになり、狙い（数を減らす）に反する。
- **⌘⌥M が macOS・ブラウザのキーとぶつかるかは確かめていない。** Google ドキュメントがコメントに使うキーだが、macOS では ⌥ を押しながらのメニューの「最小化」が「すべてを最小化」になる例がある。ぶつかったら ⌘⌥M をやめ、⌃⌥M に退ける。どちらにするかは、後段の課題が macOS の Chrome・Safari で押して目視で確かめてから決める。Enter で開く道はどちらのときも残るので、キーボードだけで開く道が無くなることはない。

| 案                                                        | 種類   | 物差し                                                                         | 判定     |
| --------------------------------------------------------- | ------ | ------------------------------------------------------------------------------ | -------- |
| 部品ごとに Tab の止まり場1つ、中は ↑ ↓、Enter・⌘⌥M で開く | 仕組み | 止まり場は内容部品の数で済む。単位に入れば口が出るので、見えない操作が無い     | 採る     |
| 単位ごとに Tab の止まり場を置く                           | 仕組み | 表の行の数だけ Tab が増え、今の形のボタンの数と同じ重さになる                  | 採らない |
| 1文字のキー（Hypothesis の a・h）で開く                   | 仕組み | 入力欄・札の欄へ字を打つときとぶつかる。どこにフォーカスがあるかで意味が変わる | 採らない |

### 論点 3: 答えの置き場・鍵の部品が無いときの退避・「聞 n」「頼 n」

**採る: 答えは余白の札が持つ。本文は押し下げない。** 札は「指した所の1行 → あなたの問い → つくもの答え → 続けて聞く・これを頼む」の順に並ぶ（`a-answered-1400.png`）。答えが吹き出しにも出ること、答え待ちのあいだ「作業は始めていない」と出すこと、答えの下の「これを頼む」「続けて聞く」は 0051 のまま。

- 札は、指した単位の上端の高さにそろえて余白に置く。前の札と重なるときは下へずらす（Google ドキュメントのコメントと同じ並べ方）。頼むの札（付箋）も同じ列に並ぶ（`a-notes-1400.png`）。
- 開いている欄は、レポートの中で1つだけにする。0051 の「部品の中で1つ」を広げる。答えた札と付箋の札は、いくつでも残る。
- **0051 の論点 2・3 の鍵（`reportToolUseId`・`componentId`・`rowIndex`）で札を出す先を探すことは変えない。** 鍵の部品が画面に描かれていないときは、0051 の論点 3 のまま、親のカードの補足メッセージの欄に、指した所の1行を添えて出す。札を出す先が「部品の下」から「部品の行の横の余白」に変わるだけで、探し方も退避の道も同じ。答えが消える道は無い。
- **狭い幅（余白を出さない幅）では、欄と答えを下から出すシートにする**（`a-open-700.png`・`a-answered-700.png`）。比較の文書によるとシートの高さは 205.77px で、本文は押し下げない。シートに出すのは開いている札1つだけ。答えが返ったら、そのシートに答えを出す。閉じた札は、指した所の「聞 n」「頼 n」の印を押すとシートで開き直す。鍵の部品が画面に無いときの退避は広い幅と同じで、親のカードの補足メッセージの欄に出す。
- **やり取りの列の節の「聞 n」「頼 n」は残す。** `a-answered-1400.png`・`a-notes-1400.png` のやり取りの列に、節ごとの「聞 1」「頼 1」が出ている。見返す入口が余白の外にも要るのは今と同じで、数え方（`askCount`・`noteCount`）も変えない。
- **部品の題の行のバッジ（「聞 n・答え待ち」「聞 n・答えた」）は消し、指した単位の横の印に移す。** 画は、聞いた行の1列目の横に「聞 1」、頼んだ案・主張の題の横に「頼 1」「頼 2」を付けている。部品全体を指したときは題の行に付ける。答え待ちか答えたかは札の中で見えるので、印は「聞 n」「頼 n」だけにする。

| 案                                                | 種類   | 物差し                                                                       | 判定     |
| ------------------------------------------------- | ------ | ---------------------------------------------------------------------------- | -------- |
| 札を余白に置き、鍵と退避は 0051 のまま            | 仕組み | 探し方と退避は既存のまま使え、変えるのは出す先の要素だけ                     | 採る     |
| 札を出す先が無いときは答えを捨てる                | 仕組み | 0051 の「答えが消える道は無い」を崩す                                        | 採らない |
| 部品の題の行のバッジも残し、単位の印と2か所に出す | 仕組み | 同じ数が2か所に出る。何も押していないときの見た目を静かにする狙いに反する    | 採らない |
| やり取りの列の「聞 n」「頼 n」を消す              | 仕組み | 狭い幅でシートを閉じたあと、どの節で聞いたかを見返す入口が本文の印だけになる | 採らない |

### 論点 4: 字を選ぶ「引いて聞く」との関係

**採る: 「引いて聞く」の口（`selection-ask.tsx` の浮く帯）はやめ、字を選んだときも余白の「聞く・頼む」を出す。** 選んだ字が指せる単位の中にあれば、その単位（行・案・主張。それ以外の部品では部品全体）を指す。札を開くと、欄の書き始めに選んだ字を引用の形（`quoteOf` の形）で入れる。

- `ReplyTarget` の形は変えない（0051 の論点 2）。選んだ字は `label` にも `key` にも入れず、問いの字の一部として送る。そのため Claude には、指した所の1行と、引用を頭に置いた問いの字が届く。
- 選んだ字が指せる単位の外にあるとき（頭の欄・`Report.figure`・配置の部品の見出しなど）は鍵が作れない。そのときも同じ余白の「聞く・頼む」を出し、押すと今の「引いて聞く」と同じく、入力欄の頭へ引用を入れてフォーカスを送る。余白が無い幅では、選んだ字の行の右に出す。口の形と字は1つにまとめ、行き先だけが鍵の有無で分かれる。
- 置き場: 選んだ字から単位を求める処理（`use-selection-ask.ts` の `reportSelectionOf` の結果から、単位の要素を探す）は、余白の口と同じく `features/report` に置く。単位の外のときの行き先は、0051 の論点 7 の口 `ReplyPort` に、入力欄の頭へ引用を入れる手続きを1つ足して渡す。`composer-draft.ts` の `prependToDraft` は、この手続きの実装として残る。`selection-ask.tsx` と、浮く帯の CSS（`turn-card/selection-ask.css`・`main-view.module.css` の `selection-ask`）は消す。
- **0051 の「残すこと」の1項（引いて聞くを残す）は、この節で置き換える。** 字の範囲を指す手段は残るが、口は返す層と1つになる。

| 案                                                             | 種類   | 物差し                                                                           | 判定     |
| -------------------------------------------------------------- | ------ | -------------------------------------------------------------------------------- | -------- |
| 字を選んでも余白の口を出す。単位の中なら札、外なら入力欄へ引用 | 仕組み | 口が1つになる。鍵が作れない所でも字を指す手段が消えない                          | 採る     |
| 選んだ字を `ReplyTarget` の欄（`label.quote` など）に足す      | 仕組み | 契約の型・控え・組み直しまで変わる。0051 の論点 2 を変えないと決めたことに反する | 採らない |
| 単位の外の字では口を出さない                                   | 仕組み | 頭の欄や図の説明の字を指す手段が今より減る                                       | 採らない |
| 「引いて聞く」の浮く帯を今のまま並べて残す                     | 仕組み | 字を選ぶと口が2つ（帯と余白）出て、口を1つにまとめると利用者が決めたことに反する | 採らない |

### 論点 5: 後段のタスクの分け方と順

**採る: 後段は今の2件のまま、ボタン・口の課題 → 札・答えの置き場の課題の順にする。**

- 理由: 変えるのはブラウザの描画だけで、送る仕組み（`src/shared` の契約・`ReplyTarget`・`ReplyPort` の `ask`）と出来事・記録は変えない。0051 の「入れる順」の 1（待ちのときの補足）と 6（次の一手）には触れない。触る部品は、0051 の返す層の名前（`AskButtons`・`AskFrame`・`AskBox`・`AskThreadView`・`ReplyNoteCard`・`RowAskContext`・`openRow`・`openRowNote`）を含むファイルが `src` に6本・`test` に1本（2026-11-11 に `rg -ln` で数えた）。ほかに指せる単位を持つ `options-leaf.tsx`・`claims-leaf.tsx` と、引いて聞くの3ファイル（`selection-ask.tsx`・`use-selection-ask.ts`・`turn-card/selection-ask.css`）がある。
- 1件目（ボタン・口）: 指せる単位と指した印、余白の列（論点 1 の幅の規則）、余白の「聞く・頼む」と書き添え、キーボードの道、引いて聞くの統合（論点 4）、「この案で進める」「確かめて」の撤去と頼むの書き始めの字。部品の右上と行の右端のボタンを外す。
- 2件目（札・答えの置き場）: 余白の札（開いた欄・答え・付箋）、札の縦の並べ方、狭い幅のシート、単位の横の「聞 n」「頼 n」の印、部品の題の行のバッジの撤去、退避の確かめ直し。
- 1件目のあと、2件目が入るまでの間は、札を余白に出すまで今の欄（部品の下の `AskBox`）を開く。そうすれば、どちらの段でも聞く・頼むが動く。

## 採らなかった案

- 案 B「行の印とまとめて頼む」: 欄を開くと本文が 94.18px 押し下がり、答えと付箋の行が本文に残る（比較の文書の「3.」）。利用者が選ばなかったので、この ADR は蒸し返さない。
- 案 C「入力欄へ引用」: 答えが指した所から離れ、入力欄が依頼と聞く・頼むを兼ねる。利用者が選ばなかったので、この ADR は蒸し返さない。

## 残すこと

- 付箋は再読み込みで消える（0051 の「残すこと」のまま）。消えて困る使われ方が見えたら、ブラウザ側に永続化せずに残す置き場を改めて決める。
- ⌘⌥M と ⌃⌥M のどちらにするか（論点 2）。後段の課題が macOS の Chrome・Safari で押して確かめる。

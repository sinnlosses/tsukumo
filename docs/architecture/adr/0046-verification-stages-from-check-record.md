# 作業の記録の「確かめたこと」の段と件数を、検証の控え `.check-record.json` から木の SHA で照らして運ぶ（2026-11-03）

ステータス: 採用

**最終レポートの「作業の記録」の「確かめたこと」の行に出す検証の段と件数は、`pnpm run check` が作業ツリーの根に書く控え `.check-record.json` から運ぶ。**
`check.ts` が控えに段ごとの件数を足し、tsukumo のサーバは `task` のある `report` が届いたときに cwd の控えを読み、控えの木の SHA が report の時点の作業ツリーの木と一致したときだけ、段と件数を画面へ流す。
段名の表示名（`typecheck` → 型検査 など）はブラウザの表に持つ。控えが無い・読めない・木が合わないリポジトリやターンでは、いまの書き手の `checks` を1行ずつ並べる形のまま出す。

運ぶ道と結びつけ方の2点は 2026-11-03 に利用者が選んだ。

## 何が困っていたか

- 「確かめたこと」の件数は、書き手が `checks` の `figure` に自由に書いている。2026-11-03 の最終レポートの1件では単体の件数が書き落とされた
- `scripts/dev/check.ts` は単体と E2E の件数（vitest・Playwright の JSON の通ったテスト）を内に持つが、STAGE 行にも控えにも出していない
- `tw verify` は STAGE 行の成否をスキルの台帳に残すが、tsukumo の core はスキルの台帳を読まない（core が見るのは契約の口と Beads の欄だけ）
- ワークフロースクリプトの流れ（ADR 0045）では検証が委譲先の中で走り、メインの会話の Bash には現れない

## 決めたこと

### 1. 運ぶ道: 検証の控え `.check-record.json`

- `check.ts` は `RecordedStage` に件数 `count`（その段で通ったテストの数。数えない段は欄を置かない）を足す。`result` が `carried` になる経路は2つあり、件数の扱いを分ける。同じ木で前回通ったので飛ばした段は、前の控えの件数を引き継ぐ。落ちたファイルだけに絞って通した段は件数を置かない（前の控えは落ちた回で、通ったテストの全数がどこにも無いため）
- 札に出す件数は、その木で通ったテストの全数か、件数なしのどちらかに限る
- 控えの形はこの ADR と `docs/architecture/workflow-contract.md` に「検証の控え」の口として書き、tsukumo のサーバはその形だけを見る。形が違う・欄が欠ける控えは無いものとして扱う
- 控えには段名・成否・件数・木の SHA だけを置く。会話の中身は入らない
- 控えを書くのはプロジェクトの検証のスクリプトで、スキルでも `tw` でもない。tsukumo の core がスキルの台帳を読まない決まりは破らない

### 2. 結びつける検証: 木の SHA で照らす

- サーバは `task` のある `report` が届いたら、cwd の作業ツリーの木を `worktreeTree` と同じ求め方で取り、控えの `tree` と比べる
- 一致したときだけ、段と件数を流す（`report-change-summary` と同じく、裏で数えて別の出来事で流し、`report` そのものは遅らせない）
- 一致しなければ流さない。検証のあとに直した中身を、検証したかのように見せないため
- 誰が・どのターンで打ったか（委譲先・ワークフロースクリプト・メイン・`tw finish` の preship）は問わない

### 3. 表示名の置き場: ブラウザの表

- 段名から表示名への表（`typecheck` → 型検査、`lint` → lint、`format:check` → 整形、`token-limit` → 字数の上限、`test` → 単体、`test:e2e` → E2E）はブラウザの「作業の記録」の部品の近くに置く
- 表に無い段名はそのまま出す。控えは機械の名前だけを持ち、言葉は画面が決める

### 4. 画面

- 段と件数が届いたレポートでは、「確かめたこと」の行の頭に段の札を並べ（見本 `docs/research/report-work-record-2026-11-03/mock.html`）、その下に書き手の `checks` のうちコマンドの検証以外の行を続ける
- 届かないレポートでは書き手の `checks` を1行ずつ並べる今の形のまま
- `failed` の段があれば札を落ちた印で出す（`checks` に `ng` が無くても隠さない）

## 採らなかった案

| 案                                                    | 採らなかった理由                                                                                         |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 会話の Bash の出力から STAGE 行を読む                 | ワークフロースクリプト・委譲先の中で走った検証はメインの会話に出ないので、いまの流れではほとんど届かない |
| `tw verify` が件数を Beads の欄に載せ、tsukumo が読む | plugin の改修が要り、タスクに紐付かない検証（手で打つ `pnpm run check`）は届かない                       |
| 書き手に件数を書かせる                                | 書き落としが起きた。値の運搬を自由記述に頼らない                                                         |
| そのターンで最後に打った検証を出す                    | 検証のあとに直した中身を、検証したかのように見せてしまう                                                 |
| 表示名を控えに持たせる                                | 言葉を変えるたびに検証のスクリプトと控えの形が動く。言葉は画面の持ち物                                   |

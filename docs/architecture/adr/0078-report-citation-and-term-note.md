# レポートの出典を番号札と末尾の一覧で、用語を初出の注で示す（2026-11-21）

ステータス: 採用

**レポートに、外部の出典を本文の番号札で指す仕組み（astryx の `Citation` の number 型に当たる）と、用語に短い注を添える仕組み（`InfoTip` に当たる）を足す。書き手は `Report` の欄に出典の一覧 `sources` と用語の一覧 `terms` を書き、出典だけは本文の主張の直後に行内の印 `{{cite: s1}}` を置く。番号は描く側が初出の順に振り、本文の末尾に出典の一覧を出す。用語の注は描く側が本文の初出の1か所に点線で付け、触れると札が出る。HTML 書き出しでは用語を「注n」と末尾の用語の一覧に開く。注は1つのレポートで閉じる。**

見た目と振る舞いは見本 `docs/history/mockup/report-citation-2026-11-20/index.html` の「案」と「案の HTML 書き出し」のとおり（2026-11-20 に利用者が「いいね、加えよう」と決めた）。ただし見本の狭い幅で札が紙の下端に出て出典の一覧に重なるのは見本の限りで、実装では札を語の下に出し、本文にも一覧にも重ねない。

## 何が困っていたか

- 外部の出典は、記法の条7「外部の出典は `[ドメイン](URL)` を主張の文の直後に置く」（`src/server/report/core/prompt/report-notation.ts`）と、部品の `aside`（欄外注）で書かれていた。同じ出典を何度も指すと、ドメインの札が同じ字で何度も文の流れに入る。出典の題は本文に出ず、レポートの末尾に一覧も無い。
- 読み手が知らない用語は、本文の括弧で言い換えるしかなく、文の流れが長くなる。
- 書き出した HTML（ADR 0073）でも同じで、出典を一覧で引けない。

## 決めたこと

### 論点 1: 本文の番号の印は、行内の印 `{{…}}` に種類 `cite` を足す

**採る: 出典を指す印は `{{cite: s1}}` と書く。1か所で2つ以上を指すときは `{{cite: s1 s2}}`（空白か `,` で区切る）。** 既存の行内の印（`src/shared/report/inline-mark.ts` の前後の差・`spark`・帯）と同じ読み方の表に `cite` の種類を足し、描き手 `rehypeInlineMark` が番号のバッジ（`a` で末尾の一覧の行へ飛ぶ・触れるか焦点で題とドメインの札が出る）に替える。

- 番号はレポート全体で決まる（初出の順・同じ出典は同じ番号）ので、1つの文字だけを見る畳み `foldInlineMarks` は番号を知らない。畳みでは `cite` を空の文字にする（セリフ・要約・セッションの中身では出典の印を消す）。番号を出すのは描き手だけで、描き手はレポートの頭で1回組んだ「id → 番号」の表を `rehypeChartTerm` と同じく引数で受ける。
- 書式に当たらない `{{cite: …}}`（id が空・id の形に当たらない）は、今の印と同じく壊れた印として字のまま残り、`brokenInlineMarkCount` が数えて差し戻す。inline code の中は読まない。
- 採らなかった案:
  - **見本の `[^s1]`**: 描画の `remark-gfm` は既に `[^1]` を脚注として読み、同じ文字の中に `[^1]: …` の定義があると「脚注」の節を描く（`src/browser/features/report/renderer/markdown-renderer.tsx` の `FOOTNOTE_OPTIONS`）。定義の無い参照は字のまま残るので、同じ書き方が「同じ部品の中の脚注」と「`Report` の出典」の2つの意味を持つ。畳み・壊れた印の数え・inline code の除き方も、`{{…}}` 側の仕組みを使えず二重に持つことになる。
  - **主張ごとの欄（例: `Claims` の項目に `sources: ["s1"]`）**: 番号を置けるのが構造を持つ部品だけになり、`Paragraph` の文の途中や表のセルを指せない。文のどこを支える出典かが落ちる。

### 論点 2: 番号を置ける欄は、行内の印が描かれる本文の欄に限る

**採る: `{{cite: …}}` を置けるのは、本文の内容部品のうち行内の印を描き手が通す欄（`Paragraph` の text・`Table` のセルと行の詳細・`ItemList` の項目の text・`Claims` の claim と basis）に限る。結論・見出し・`keyFigures`・`checks`・`favor`・図の題とラベル・セリフの欄には置けない。**

- 置けない欄は、画面でも素の文字へ畳んで描く（あるいは描かない）ので、印が黙って消える。置けない欄に `cite` があったら差し戻す（論点 5）。
- 結論に置けないのは、結論が要約・セッション一覧・次の一手でも素の文字として読まれるため。結論の根拠は節の本文で指す。
- `Claims` の basis が実際に `rehypeInlineMark` を通るか（`InlineMarkdown` の経路）は実装（出典の番号札のタスク）が確かめ、通らない欄は描き手を通すか、置ける欄から外して差し戻しの表に足す。

### 論点 3: 用語の注は1つのレポートで閉じる

**採る: 用語の注は、そのレポートの `terms` に書いた語に、そのレポートの本文の初出の1か所にだけ付く。同じセッションの前のレポートで注を付けた語でも、次のレポートで要るなら書き手がもう一度 `terms` に書く。描く側は前のレポートを見て注を省いたり足したりしない。**

- レポートは1つずつ単独で読まれる（畳んだ前のレポートは開かない・HTML 書き出しは1つのレポートだけを1ファイルにする・セッションを替えて読み戻す）。前のレポートに頼ると、書き出したファイルや読み戻した画面で注が欠ける。
- セッションをまたいで語を覚える置き場（サーバの状態）を足さずに済む。
- 採らなかった案: **セッションで1回だけ付ける**（2つ目以降のレポートでは付けない）。上の単独で読む場面で注が欠け、`report` の受け口が前のレポートの `terms` を持ち続ける必要がある。

### 論点 4: `Report` の欄は `sources[{id,title,url}]` と `terms[{term,note}]`

**採る: 見本の形のまま、`Report` に省ける欄を2つ足す。**

- `sources`: 1〜10件。各要素は
  - `id`: 英小文字か数字で始まり、英小文字・数字・`-` の1〜16字（`s1`・`rfc9110` など。例と案内は `s1` から振る形で示す）。番号ではなく名前で、画面の番号は描く側が初出の順に振る。
  - `title`: 出典の題。1〜60字・1行・素の文字（記法を描かない）。
  - `url`: `http:` か `https:` の絶対 URL。描く側は札と一覧にドメイン（ホスト名）を出し、URL は `a` の行き先にだけ使う。
- `terms`: 1〜8件。各要素は
  - `term`: 本文に出る字そのもの。1〜20字・1行。照らし合わせは字の完全一致（大文字と小文字を区別する）。
  - `note`: 1〜80字・1行・素の文字。何であるかを1文で言う（語の言い直しや出典は書かない）。
- 番号と「注n」は描く側が決めるので、書き手は番号を書かない。`id` の順と画面の番号は一致しなくてよい。
- 件数と字数の上限は zod の形（`src/shared/report/a2ui-report-catalog.ts` の `reportComponentSchema`）で拒む。上限の値は `src/shared/report/report-limit.ts` に名前つきで置く。
- 読み戻しの形（`a2uiWrittenComponentSchema`・`a2uiReportComponentSchema`）も同じ欄を受ける。欄の無い記録済みのレポートは今のまま描く。

### 論点 5: 形と字数は型で拒み、照らし合わせは差し戻しの規則にする

**採る: 1つの値だけで決まること（件数・字数・`id` の形・URL の形）は論点 4 の zod の形で拒む。本文と一覧を照らし合わせないと決まらないことは、`src/server/report/core/rules/` の差し戻しの規則にする。** 差し戻しの規則は次の7つ（名前は実装で付け直してよい）。

1. **無い id を指す**: 本文の `{{cite: x}}` の x が `sources` の `id` に無い
2. **どこからも指さない出典**: `sources` に載せたのに、論点 2 の欄のどこにも `{{cite: …}}` が無い
3. **同じ id の重複**: `sources` の `id` が2回以上出る
4. **同じ URL の重複**: `sources` の `url` が2回以上出る（末尾の `/` と `#` 以降は比べない）
5. **置けない欄の印**: 論点 2 の欄の外（結論・見出しなど）に `{{cite: …}}` がある
6. **本文に無い用語**: `terms` の `term` が、論点 2 の欄の本文（inline code と印の中を除く）に1度も無い
7. **同じ用語の重複**: `terms` の `term` が2回以上出る

- 差し戻しの文には、規則の名前と書き直し方（「`sources` に足すか印を消す」など）だけを書き、本文の字は写さない（`docs/coding-standards/conversation-content.md`「会話内容の扱い」）。指した id・語は書き手が書いた識別子なので、差し戻しの文に出してよい。
- 採らなかった案:
  - **照らし合わせも zod の `superRefine` に入れる**: 本文の印は部品の一覧（`components`）の葉に散っていて、`Report` の形だけでは読めない。部品の木を組んだあとに読む今の差し戻しの規則（`brokenInlineMarks` と同じ段）に置くのが、本文の欄の範囲を1か所に持てる。
  - **無い id の印を黙って字のまま描く**: 書き手が気づかず、読み手に `{{cite: x}}` が見える。

### 論点 6: 外部の出典は番号へ寄せ、`[ドメイン](URL)` と `aside` は役目を分けて残す

**採る: 外部の出典（主張を裏づける外の文書）は `sources` と `{{cite: …}}` で書くと条7 を改める。Markdown のリンク `[字](URL)` は描けるまま残し、出典ではない行き先（開いてほしいページ・ダッシュボード）に使う。部品の `aside`（欄外注）も残し、役目を「その部品のどこを見るか・部品全体への1行の注」にして、出典は書かない。**

- 番号に寄せると、同じ出典を何度指しても字が増えず、題と一覧が付く。リンクと `aside` を外すと、出典でない行き先と部品への注を書く口が無くなり、表現力が落ちる（2026-10-27 の方針で採らない）。
- 書き手が選ぶ基準は「主張を裏づける外の文書なら番号、読み手に開かせたい場所ならリンク、部品のどこを見るかなら `aside`」の1行で案内する（論点 7）。
- 採らなかった案:
  - **番号と `[ドメイン](URL)` を書き手の好みで併存させる**: 同じ出典が2つの形で出て、一覧に載らない出典が残る。
  - **`aside` を出典の一覧へ吸収して外す**: 部品への注を書く口が無くなる。
  - **出典を指す Markdown のリンクを差し戻す**: 出典かどうかを機械で決められず、行き先のリンクまで拒む。

### 論点 7: 書き手の案内は、毎ターン載る所には1行ずつ、細かい書き方は `Report` の部品カードに置く

**採る: 次の5か所に書く。記法の本文 `REPORT_NOTATION_PROMPT` の字数の上限（今 1883 字で、上限ちょうど。`test/server/report/core/prompt/report-notation.test.ts`）は、この ADR の分として 60 字まで上げてよい（1943 字まで）。** 案内を書くタスクは、上げた幅と実際に増えた字数を報告に書く。

- **`REPORT_NOTATION_PROMPT` の条7**: 外部の出典は `sources` に載せ、主張の文の直後に `{{cite: id}}` で指す（`[ドメイン](URL)` の言い方を置き換える）
- **`REPORT_NOTATION_PROMPT` の条6**: 読み手が知らない外の用語は `terms` に1文の注を書き、本文の括弧で言い直さない（今回生まれた名前を本文で言う今の条はそのまま）
- **`REPORT_FIELD_DESCRIPTIONS`（`report` の定義。毎ターン載る）**: `sources`・`terms` の欄の説明を1行ずつ（いつ書くか）
- **`REPORT_FIELD_CARD_NOTES`（`Report` の部品カード）**: `id` の形・複数の指し方・置ける欄（論点 2）・番号は描く側・リンクと `aside` との使い分け（論点 6）・注の書き方（1文・言い直さない）・注はレポートごと（論点 3）
- **`REPORT_SECTIONS_CARD_NOTE`（`Section` の部品カード）**: `aside` の役目から「出典」を外し、「どこを見るか・部品全体への注」にする

- 部品を材料の形から引く条（`REPORT_PART_CHOICE_GUIDE`）は部品の選び方の条で、`sources`・`terms` は部品ではないので書かない。
- 通る呼び出しの例（`src/shared/report/part-example-list.ts` の `Report` の例）に `sources` 1件と `{{cite: s1}}` 1か所を足し、例が差し戻しの規則を通ることを例のテストで守る。
- 用語の言い換えの台帳（`src/server/report/core/rules/plain-word.ts`）は、本文に出す語の台帳で、この欄の名前を足す必要は無い。画面に出す見出し「出典」「用語」は台帳の言い換え先と食い違わない。

### 論点 8: 後段は4件のまま、出典 → 用語 → 書き出しと案内の順に送る

**採る: 出典の番号札・用語の注・HTML 書き出し・書き手の案内の4件で足りる。** 出典と用語は同じ `Report` の形・同じ差し戻しの段・同じ描き手を触るので、用語は出典のあとに送る（並べて進めると同じファイルでぶつかる）。

- 出典の番号札: `cite` の印（読み方・畳み・壊れた印）・`sources` の形と上限・出典の5つの差し戻し（論点 5 の表の上5行）・id → 番号の表・番号のバッジと札・本文の末尾の出典の一覧・用語集の行。
- 用語の注: `terms` の形と上限・用語の2つの差し戻し・初出の決め方（論点 2 の欄を本文の順に読んで最初の1か所。inline code・リンク・印の中は除く）・点線と札・図の項目名の印（`rehypeChartTerm`）との重なり。
- HTML 書き出し: ADR 0073 の「画面の操作だけのもの」に札（番号と用語の両方）を足して落とし、用語を「注n」と末尾の用語の一覧に開く。出典の一覧と番号のバッジの行き先（`#…`）は残す。
- 書き手の案内: 論点 7 の5か所と例。

## 描く側の決まり

- 番号は論点 2 の欄を本文の順（`Report.children` の節の順、節の中は部品の順、部品の中は欄の順）に読み、`{{cite: …}}` に最初に出た順に 1 から振る。同じ出典は同じ番号。草稿では届いた部品だけで振り、`sources` がまだ届いていない印は番号の代わりに控えめな「…」のバッジにする（届けば番号になる）。
- 出典の一覧は、最後の節のあと（振り返りの節の前）に見出し「出典」で番号の順に並べる。各行は番号・題・ドメイン。バッジは一覧の行へ飛ぶ。
- 用語の注は、論点 2 の欄を同じ順に読んで最初に出た1か所の語に点線を付け、触れるか焦点で「用語」と注の札が出る。図の項目名の印と同じ語に当たったら、用語の注を優先し、図の項目名の印はその語を飛ばす。
- 札は語・番号の下か上に、紙の内側に収まる向きで出す。狭い幅（ADR 0058 論点 4 の境目、本文の器の幅 692px より狭い器）でも語の下に出し、出典の一覧や本文を覆わない。動きを減らす設定では出入りの動きを付けない。
- 札の字と一覧の題・注は素の文字で描き、記法を効かせない。

## 結果

- 書き手は `report` の入力の欄2つと行内の印1種を覚える。部品は増えない。
- `foldInlineMarks` を通る経路（セリフ・要約・セッションの中身）からは出典の印が消える。
- 記録済みのレポートは `sources`・`terms` を持たないので、今と同じに描く。
- この ADR は ADR 0073 の「画面の操作だけのもの」を広げるだけで、書き出しの仕組み（画面の DOM の写し）は変えない。

## 残したこと

- `terms` の照らし合わせを字の完全一致にしたので、活用や表記ゆれ（「指数バックオフ」と「指数的バックオフ」）には付かない。使われ方を見てから決める。
- 出典の札にファビコンを出すか（astryx の `Citation` の `icon`）。外部への読み込みになるので、今は出さない。

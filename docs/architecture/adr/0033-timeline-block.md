# 時刻の軸に行ごとの帯を並べる図は、`timeline` の塊として HTML で描く（2026-10-24）

ステータス: 採用

**`report` に `timeline` の塊を足す。** 書き手は行（名前・開始・終了か一点・延びた分・レーン）と出来事の印と
差し色にする行の名前だけを渡し、目盛り・色・幅は tsukumo が決める。描くのは shared が組む HTML の `div`・`span` と
CSS で、Chart.js にも `svg` の塊の経路にも載せない。形の札 `time` の第一候補をこの塊にする。

## 何が困っていたか

時間の順・所要・経過を見せる塊が無かった。`chart` の `span`（`report-diagram-markdown.ts` の `chartConfigOf`）は
項目ごとの始まりと終わりを分の数の浮き棒にするだけで、時刻の目盛り・差し戻しで延びた分・割り込みの印を持てない。
2026-10-24 の疑似セッション（8 手順の時刻と往復 2 回）では、`span` の棒が 1 文字分の幅になり、始まりと終わりの
分の数が並ぶだけだった。`mermaid` の `gantt` は見た目を制御できず、`sequenceDiagram` は往復を表せるが縦に長い（546px）。
形の札 `time` は直近 28 日で 0 件（`node scripts/runtime/report-block-usage.ts --days 28` の「札 × 節数」で 0 / 270）で、
内容が無いのではなく道具が無かった。

## 決めたこと

### 塊の欄

```ts
{
  kind: "timeline",
  title?: string,                  // 図の題（図 n）
  rows: {
    name: string,                  // 項目名
    start: string | number,
    end?: string | number,         // 省くと start の一点（菱形）
    extra?: (string | number)[],   // end より後の区切りの時刻の昇順の並び（延びた分）
    lane?: string,                 // 役ごとのまとまり
  }[],
  events?: { at: string | number, label: string }[],  // 出来事の印
  emphasis?: string[],             // 差し色にする行の名前
  fold?: string,
  aside?: string,
}
```

- `figure` と `sections` のどちらにも置ける（`reportFigureSchema` と `reportBlockSchema` の両方の枝）
- 欄の名前に色・幅・目盛りは無い。書き手は形だけを渡す（`docs/architecture/adr/0028-report-block-priority.md`「SVG（論点3）」と同じ分担）

### 尺度の受け方（論点1）

**`unit` の欄は置かず、値の形から tsukumo が判別する。** 宣言の欄を置くと、宣言と値の食い違いという新しい誤りが
1 つ増えるだけで、判別そのものは値の形で機械的に決まるため。

| 値の形                                                                                         | 尺度               |
| ---------------------------------------------------------------------------------------------- | ------------------ |
| `HH:MM`（`/^\d{1,2}:\d{2}$/`）                                                                 | 時刻（同じ日の中） |
| `YYYY-MM-DD`、`YYYY-MM-DDTHH:MM`、`YYYY-MM-DDTHH:MM:SS`（末尾に `Z` か `±HH:MM` を付けてよい） | ISO の日時         |
| 数、または数だけの文字列（`"45"`・`"12.5"`）                                                   | 分の数             |

- 1 つの塊の中で判別が 2 種類以上に割れたら `mixed-scale` で差し戻す。ISO で、末尾の `Z`・時差が値ごとに違うときも `mixed-scale`
- どれにも当たらない値（`"14時"` など）は、その行か出来事の `unreadable`
- 日をまたぐ時刻は ISO で書かせる。`HH:MM` で前より小さくなった値は日をまたいだとは読まず、`not-ascending` になる
- 読みは `Temporal` で書き、`Date` を使わない（`docs/coding-standards.md`「`Date` を使わない」）

### 目盛りの決め方（論点2）

- 間隔の候補は 1・2・5・10・30 分、60 分、360 分、1440 分（1 日）。その先は 1 日の 2・5・10・20・50… 倍
- 範囲（全部の値の最小〜最大）を、目盛りの区間の数が 8 以下になる最小の間隔で切る。軸の端は、最小を間隔で切り下げ、最大を間隔で切り上げる。
  14:00〜15:12 なら 5 分では 15 区間になるので 10 分を選び、軸は 14:00〜15:20 の 8 区間（目盛りの字は 9 個）になる
- 軸の字:

| 尺度   | 字                                                                                           |
| ------ | -------------------------------------------------------------------------------------------- |
| 分の数 | `n分`。間隔が 60 分以上なら `n時間`                                                          |
| 時刻   | `HH:MM`                                                                                      |
| ISO    | `HH:MM`。軸の最初の目盛りと日が変わった目盛りだけ `M/D HH:MM`。間隔が 1 日以上なら全部 `M/D` |

### 描き方（論点3）

**shared が HTML の `div`・`span` を組み、位置は `style="margin-left: x%; width: w%"` だけで書き、見た目は
`report-notation-timeline.css` が当てる。** 前例は `report-phase-time.ts` の段の滝（同じ書き方の % の位置）と、
`card-chain-markdown.ts` のカードの連鎖（HTML で組み、器の幅で並びを変える）。

| 見た目   | 書き方                                                                                                                            |
| -------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 区間     | 帯（`timeline-bar`）。灰。`emphasis` の行だけ差し色（`timeline-bar-emphasis`）                                                    |
| 一点     | 回した正方形の菱形（`timeline-point`）                                                                                            |
| 延びた分 | 帯の末尾に続く斜線の区間（`timeline-extra`。`repeating-linear-gradient`）。区切りごとに細い切れ目                                 |
| 所要     | 区間の行の帯（延びた分があればその最後）の右に、尺度に合わせた長さの字（`timeline-duration`）。一点の行には付けない               |
| 待ち     | `after` で待たれる行の終わりから、待つ行の最も早い始まりまでの灰の細い斜線（`timeline-wait`）。止まりうる区間のある行には描かない |
| 出来事   | 行の上に重ねた層（`timeline-events`）の縦の点線（`border-inline-start: dotted`）とラベル                                          |
| 凡例     | 図の下に、使った見た目の種類だけ: 差し色「注目」・灰「ほか」・斜線「延びた分」・斜線「待ち」・菱形「一点」・点線「出来事」        |

- 帯・菱形・出来事の `title` に、書き手の時刻の字をそのまま入れる（`14:00–14:25（延び 14:40・14:52）`）。色だけで意味を言わず、凡例と `title` の字で言う
- 幅は包みが `min(100%, 63em)`（項目名の列 11em + 軸）。高さは「行数 × 32px + レーン数 × 24px + 60px」（レーンを使わなければレーンの項は 0）
- 器が 761px 以上（`@container report-body (min-width: 761px)`）は項目名の列と軸の格子。760px 以下は項目名を帯の上に置き、軸を全幅にする
- `sanitize-schema.ts` と `style-allowlist.ts` は変えない。`div`・`span`・`class`・`title` と、`style` の `margin-left`・`width` はどちらも許可済み。`left`・`position` は `style` に書けない（許可に無い）ので、重ねる層の位置は CSS 側で決める

### 延びた分の表し方（論点4）

**行は 1 本のまま、`extra` を「`end` より後の区切りの時刻の昇順の並び」にする。** `start`〜`end` が帯、
`end`〜`extra[0]`、`extra[0]`〜`extra[1]` … がそれぞれ斜線の区間で、行の最後は `extra` の最後の値になる。
差し戻しの往復が 2 回ある行は `extra: ["14:40", "14:52"]` と書く。`extra` が昇順でない・`end` 以前の値を含むと `not-ascending`。
`end` を省いた一点の行に `extra` は書けない（書いたら `not-ascending`）。

### 項目名の折り返しとレーン（論点5）

- 項目名は 11em の列の中で 2 行まで折り返し（`overflow-wrap: anywhere`）、超えた分は `-webkit-line-clamp: 2` で切り、全文を `title` に置く。行の高さは 32px のまま変えない
- `lane` を 1 つでも書いた塊は、行をレーンの初出の順にまとめ、レーンの中は書いた順を保つ。`lane` を省いた行は名前の無いレーンとして先頭にまとめ、見出しの行を出さない
- 名前のあるレーンの境には、高さ 24px の見出しの行（レーンの名前）を置く
- 開始の昇順の検査はレーンの中で行う（別のレーンどうしは前後してよい）

### `chart` の `span` との線引き（論点6）

- `timeline` の説明: 「延び・出来事・一点のどれも無く、項目ごとの区間の長さを比べるだけなら `chart` の `span`」
- `chart` の `span` の説明の末尾: 「時刻の軸・延びた分・出来事・一点があるなら `timeline`」
- 形の札 `time` は、第一候補を `timeline`、許す代替を `mermaid`（`sequenceDiagram`）・`list`（`ordered`）、許さないを `table` にする。
  `mermaid` の `gantt` は札の候補から外す（`mermaid` の塊で描ける種類の並びからは外さない）

### 入口の差し戻し

違反の種類は `broken-timeline` の 1 つで、誤りごとに位置と理由を持つ。位置は「何個目の `timeline` の塊の何行目」
（出来事なら何個目の出来事、`emphasis` なら `emphasis`）だけで、行の名前・時刻の字は文面に入れない。

| 理由               | 当たる入力                                                                             |
| ------------------ | -------------------------------------------------------------------------------------- |
| `unreadable`       | 尺度の表のどれにも当たらない値                                                         |
| `mixed-scale`      | 1 つの塊の中で尺度が割れる                                                             |
| `not-ascending`    | 同じレーンの中で開始が前の行より前、出来事が前より前、`extra` が昇順でない・`end` 以前 |
| `end-before-start` | `end` が `start` より前                                                                |
| `unknown-emphasis` | `emphasis` に行に無い名前がある                                                        |

## 採らなかった案

| 案                                            | 採らなかった理由                                                                                                                                                                                                 |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Chart.js（`span` の経路）を広げる             | 斜線・縦の点線・菱形・自動の凡例を、描く側の plugin（`chart-direct-label.ts`）に足すことになる。canvas の中なので 760px で項目名を帯の上へ並べ替えられず、字も選べない                                           |
| `svg` の塊と同じく HTML の svg を組む         | 斜線に要る `pattern` が `sanitize-schema.ts` の `ALLOWED_TAG_NAMES` に無く、属性 `patternUnits`・`patternTransform` も無い。viewBox は字ごと縮むので、760px で項目名を帯の上へ移すには svg を 2 枚組むことになる |
| `unit` の欄で尺度を宣言させる                 | 値の形で機械的に判別でき、宣言を足すと宣言と値の食い違いという誤りが 1 つ増える                                                                                                                                  |
| 延びた分を別の行（本体と延び）にする          | 行の数と項目名が倍になり、`emphasis` の行名の照合がどちらの行かで割れる。往復が 2 回あると 3 行になる                                                                                                            |
| `mermaid` の `gantt` を札 `time` の候補に残す | 見た目を制御できず、延びた分・出来事の印・差し色の凡例を持てない。`timeline` で受けられない時間の内容は `sequenceDiagram` と `list` の `ordered` が受ける                                                        |

## 追記: 待つ行の矢印と止まりうる区間を足した（2026-11-04）

日程の図で、どの作業がどれを待つかを別の `Graph` に分けると2枚の図を照らし合わせることになり、
止まるかもしれない区間は `extra`（終わりの後ろに延びた分）では言えなかった。**行に `after`（待つ行の `name` の並び）と
`uncertain`（終わり〔`extra` があればその最後〕より後ろに続く止まりうる区間。終わりの時刻 `until` と一言 `label`）を足す。**

- `after` は、待たれる行の右端（`uncertain` があればその終わり、一点ならその位置）からこの行の開始へ入る矢印で描く。
  名前が行に無い・空（`unknown-after`）、同じ名前の行が2つ以上（`ambiguous-after`）、自分を含めて循環する（`cyclic-after`）は差し戻す。
  待つ行の開始が待たれる行の終わりより前なのは差し戻さない（重なって進む計画を書ける）
- `uncertain` は `extra` と別の欄にし、棒の内側（`start`〜`end`）は許さない。区間は延びた分の後ろに、警告色と帯の灰の縞（`extra` の警告色と透明の縞と見分ける）で続け、
  一言は区間の左端に揃えて棒の下に置く。凡例に「止まりうる分」を足す。`until` が終わり以前・一点の行にあるのは `uncertain-before-end` で差し戻す
- 項目名を左の列に置く切り替えの幅を、器 761px から 560px に下げる。幅 1400 の本文（739px）でも名前が棒と同じ段に並ぶ。
  559px 以下は今までどおり名前を棒の上に置き、矢印もそのまま描く
- 項目名は1行に収め、超えた分は省いて全文を `title` に置く（2行の折り返しをやめる）。矢印の縦の長さを固定の高さの倍数で決めるため、
  行（32px。名前を棒の上に置く幅では名前の 18px を足す）・レーンの見出し（26px）・一言（18px）の高さを中身で変えない

上の「幅と高さ」の 761px の線は、この追記の 560px に替わる。「採らなかった案」の svg の理由は、図全体を svg で組む案について言ったもので、
矢印には当たらない。今の描画は `sanitize-schema.ts` を通らない React の部品で、矢印は斜線の `pattern` を要らず、
帯・斜線・菱形・字は `div`・`span` のまま残して、矢印1本ごとに伸ばす線の `svg` と伸ばさない矢じりの `svg` を待つ行の帯の段に重ねる。
横の位置は layout が出す軸の %、縦は layout が数える「間に挟まる行・レーンの見出し・一言の数」と上の固定の高さから CSS の `calc` で決めるので、
名前の列の出し入れで svg を組み替えなくてよい。

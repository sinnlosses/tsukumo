# レポートの配置の部品に、器の幅で折り返す格子 `Grid` を足す（2026-11-18）

ステータス: 採用

**`report` の配置の部品に、tsukumo のカタログの部品 `Grid` を足す。`Grid` は子の ID の並びだけを受け、列の数は描く側が器の幅から決める（子の最小幅 14em と間で入る数を出し、段の数を変えずに列を均す）。狭い器と余白の札の横では1列に積む。A2UI の基本カタログの写しである `Row` は形も描き方も変えない。この ADR は、ADR 0064 の論点 1 の「Astryx の `Grid`・`GridSpan`」の行（見送り）と「残したこと」の1項目を決める（ADR 0064 には上書きした旨の行だけを足す）。**

この ADR が決めるのは、格子を新しい部品にするか `Row` を変えるか、列の数を誰が決めるか、余白の札・狭い器・`Row` のセルとの組み合わせ、入れてよい子の縛り方まで。部品が閉じる前の字・書き手が続きの依頼を渡す欄は扱わない。

## 何が困っていたか

2026-11-18 に、架空の題材の疑似セッション3本（短い表4つ・`Card` 3つ・棒の図4つを `Row` に並べたもの）を撮って測った。画は `docs/history/mockup/report-grid-2026-11-18/` に置いた。

- `Row` は器（`report-body` の container）の幅が 761px 以上のときだけ横に並べ、760px 以下では全部を縦に積む（`src/browser/features/report/renderer/report-notation-summary.css`）。1400×900 の紙の内側は 724.92px なので、いちばん多い幅で `Row` は一度も横に並ばない。
- 1400×900 で、短い表4つの `Row` は縦に積まれて高さ 763.94px、棒の図4つは 1509.56px になった（1920×1080 では横に4つ並び、それぞれ 181.98px と 368.39px）。表1つの幅は 724.92px で、2列の表の右側の大半が空いた。
- 1920×1080 の紙の内側は 882px で、`Row` は子の数で等分する（4つなら 211.5px ずつ）。子が5つ以上だと、狭い器でも広い器でも、等分か1列かの2通りしかない。
- 横に並べる配置の部品は `Row` だけで、`Row` の形は A2UI の基本カタログの写し（`src/shared/report/a2ui-basic-part-list.ts`）。

## 決めたこと

### 論点 1: 新しい部品 `Grid` を足し、`Row` は変えない

**採る: tsukumo のカタログの自作の部品として `Grid`（`children` に子の ID を2つ以上）を足す。A2UI の基本カタログの写しの6部品には入れない。**

| 案                                           | 種類   | 物差し                                                                                                                                                                   | 判定     |
| -------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- |
| 自作の部品 `Grid` を足す                     | 仕組み | 書き手は「同格のものを幅で折り返して並べる」ときに選ぶ部品が1つ増える。`Row` を使っている今のレポートの見え方は変わらない                                                | 採る     |
| `Row` に「折り返す」指定の欄を足す           | 仕組み | 基本カタログの写しが公開物と食い違い、写しの一致を確かめるテストを外すことになる。書き手は部品でなく欄で選び分けるだけで、選ぶ手間は減らない                             | 採らない |
| 欄を足さず、`Row` の描き方を折り返しに替える | 仕組み | 入力は変わらないが、今の `Row` の使い方（左に数と段落、右にコードの2つ）が 1400×900 で約 356px ずつに割れ、コードが折り返す。`Row` の「1行に並べて読み比べる」役が消える | 採らない |
| 何もしない（`Row` のまま）                   | 仕組み | 1400×900 では短い表4つが 763.94px、図4つが 1509.56px の縦の積みのまま                                                                                                    | 採らない |

- `Row` と `Grid` の役を分ける: `Row` は2〜4個を1行で読み比べるもの（狭い器では縦に積む）、`Grid` は同格の子（数の札・短い表・図・`Card`）を、幅に合わせて段に折り返して並べるもの。
- Astryx の `Grid` は依存にあるが、描画には使わない。列の数を均す規則（論点 2）が Astryx の `columns`（`{minWidth}` の自動の折り返し）に無く、本文の CSS の容れ物（`report-body` の container と余白の列）と組み合わせるため、`Row` と同じく本文の CSS の格子で描く。列の数は `src/browser/features/report/hooks/use-grid-column-count.ts` の `useGridColumnCount` が格子の幅を測って CSS の変数で渡す。
- 書き手が選び分ける手間: `report` の定義に載る `Grid` の説明は「同格の部品の ID を2つ以上。広い紙では横に並び、狭い器では段に折り返す」の1文で、向く子・向かない子と `Row` との分け方はカード（`report_part_card` の `Grid`。823 字。`Row` のカードは 694 字）にだけ載せる。
- `report` の引数の schema は、`Grid` の定義（262 字）と区切りの分だけ増えて 23,669 字になった。`REPORT_INPUT_SCHEMA_MAX_CHARS` を 23,500 字から 23,770 字に上げた（ADR 0048 の「増えた分だけ上げ、上げ幅は実装で測って書く」に従う）。

### 論点 2: 列の数は描く側が決め、段の数を変えずに均す

**採る: 書き手は列の数もまたがる数も書かない。描く側が、格子の幅に子の最小幅（14em）と間で入る列の数を出し、子の数より多ければ子の数に縮め、そのうえで段の数を変えずに列を均す。**

- 均すのは、余りの1つだけが下の段に残るのを避けるため。子が4つで3列入るなら 2×2、5つで4列入るなら3と2、6つで4列入るなら3と3にする。
- 1400×900（内側 724.92px）では3列、1920×1080（882px）では4列まで入る。390×844 では1列。
- 書き手は「何を並べるか」だけを申告し、形は描く側が決める（`report` の記法の原則）。Astryx の `GridSpan`（子が何列にまたがるか）は写さない。全幅に出したい子は格子の外に置く。

| 案                                                     | 種類   | 物差し                                                                                                           | 判定     |
| ------------------------------------------------------ | ------ | ---------------------------------------------------------------------------------------------------------------- | -------- |
| 器の幅と子の最小幅から描く側が決め、段の数を変えず均す | 仕組み | 書き手の欄が増えない。4つの子が 3＋1 に割れない                                                                  | 採る     |
| 書き手が列の数を書く                                   | 仕組み | 書き手は紙の幅を知らないので、狭い器のときの列の数を決められない。欄が1つ増え、間違えたときの差し戻しも増える    | 採らない |
| CSS の `auto-fit` だけで折り返す                       | 仕組み | 4つの子が 1400×900 で 3＋1 に割れ、下の段に1つだけ残る                                                           | 採らない |
| `list` の `cols` と同じ約数の規則を container query で | 仕組み | 子の数の全部か約数か1列にしかならず、5つ・7つは1列に落ちる。余白の札の横で格子だけが狭まっても器の幅は変わらない | 採らない |

- 列の数の規則は `src/browser/features/report/domain/grid-column-count.ts` の `gridColumnCount`。最小幅は本文の字の大きさで測る（本文 14px で 196px）。

### 論点 3: 狭い器・余白の札の横・`Row` のセル

**採る: 余白の札の横に来た `Grid` は、`Row` と同じく1列に積む（ADR 0064 論点 5 の決まりを `Grid` にも当てる）。格子のセルは `Row` のセルと同じく器にし、セルの中の部品はセルの幅で狭い形に替わる。**

- 余白の札の横の塊の印（`data-beside-card`）は、`Row` と同じく `Grid` 全体に付け、セルの中の塊には付けない。`Grid` は印の付け外しを見て、付いているあいだ列の数を1にする。
- `Row` のセルや `Card` の中に置いた `Grid` は、置かれた場所の幅で列の数を決めるので、セルが狭ければ1列になる。
- 列を出せない幅（子の最小幅が1つしか入らない）では、子は器の幅いっぱいに縦に並ぶ。

### 論点 4: 入れる子は縛らず、カードで向き不向きを言う

**採る: `Grid` の子の種類は縛らない（差し戻しの検査を足さない）。部品のカード（`report_part_card` の `Grid`）で、向く子（数の札・短い表・図・`Card`）と向かない子（長い段落・コード）を言う。子の数は2つ以上を入力の形で求める。**

- 向かない子を入れても、描く側は子の最小幅を守るので字が潰れない（狭くなるほど列が減る）。読みにくさは、長い子が隣の短い子の段を高くすることだけで、差し戻すほどの崩れではない。
- 子の種類で差し戻すと、書き手が `Row` との選び分けに加えて子の種類も覚えることになる。崩れが出たら、使われ方の記録で数えてから縛るかを決める。

| 案                                   | 種類   | 物差し                                                                     | 判定     |
| ------------------------------------ | ------ | -------------------------------------------------------------------------- | -------- |
| 縛らず、カードで向き不向きを言う     | 道案内 | 差し戻しが増えない。向かない子を入れても字は潰れない                       | 採る     |
| 長い段落とコードを差し戻す           | 仕組み | 差し戻しが1種類増え、書き手の選び分けが増える。崩れはまだ1件も測っていない | 採らない |
| 入れてよい子を列挙し、ほかを差し戻す | 仕組み | 内容部品が増えるたびに一覧を直す。表現力を狭める                           | 採らない |

## 見本と実物で確かめたこと

- `Row` のままの画（`row-tables-1400.png`・`row-charts-1920.png`）は、上の架空の疑似セッションを同梱の撮影の道具で撮った。
- `Grid` の見本の画（`grid-1400.png`・`grid-1920.png`）は、紙の内側の幅だけを写した見本（`grid.html`。子の最小幅は 14em に近い 200px）を撮った。1400×900 の幅で表4つと図4つが 2×2、`Card` 3つが3列、1920×1080 の幅で表4つと図4つが4列、`Card` 3つが3列になり、横のはみ出しはどちらも 0px。
- 実装のあと、同じ3つの並びを `Grid` で書いた疑似セッションの場面 `a2ui-grid-sample` を撮って測った。

| 見たもの     | `Row`（1400×900） | `Grid`（1400×900）            | `Grid`（1920×1080） | `Grid`（390×844） |
| ------------ | ----------------- | ----------------------------- | ------------------- | ----------------- |
| 短い表4つ    | 1列・763.94px     | 2×2・375.97px（1つ 356.45px） | 4列・181.98px       | 1列・763.94px     |
| `Card` 3つ   | 1列               | 3列（1つ 233.64px）           | 3列（1つ 286px）    | 1列               |
| 棒の図4つ    | 1列・1509.56px    | 2×2・748.78px                 | 4列・368.39px       | 1列・1509.56px    |
| 横のはみ出し | 0px               | 0px                           | 0px                 | 0px               |

- 余白の札の横で1列に積むことは、単体テスト（印の付け外しで列の数が 1 と 4 を往復する）で確かめた。札を開いた画は撮っていない。

## 残したこと

- 子の種類ごとに最小幅を変えること（図は広く、数の札は狭く）。いまは1つの値。
- `Grid` の使われ方の記録（どの子を入れたか）を数えて、論点 4 の縛りを見直すこと。

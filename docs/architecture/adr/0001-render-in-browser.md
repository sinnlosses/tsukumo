# 描く層をブラウザ側へ移す（2026-09-13）

**「サーバが HTML を組み立てて SSE で押し、ブラウザが morph で当てる」形をやめ、両側が共有する
型付きプロトコルでイベントを押し、React の部品が状態から描く形へ移す。** 言語（TypeScript）と
ランタイム（Node で動く形）は変えない。設計そのものは `docs/architecture.md` が正典。

決め手は1つ。**これから足したいものの重心が、ブラウザ側で状態を持つ部品にある**（立ち絵の動き・
複数セッション・入力履歴・質問の複数選択・Electron 化）。HTML 文字列を丸ごと押して morph する
形はそこが最も苦手で、部品ごとに `MutationObserver` や `data-` 属性で状態を持ち直す配線が増え続ける。
下の「描画にフレームワークを入れず…」（2026-09-12）は当時の3つの不足に対しては正しかったが、
問いが「不足を埋める」から「これから足すものに耐える」へ動いた。

残すもの（SDK 駆動・`speak`・答え待ちの列・畳み込み・会話を外へ出さない）と、変えるもの、
採らなかった案（Python・Rust・Next.js・HTMX・Svelte）と、判断の基準は
`docs/research/architecture-rethink.md` に経緯として残してある。

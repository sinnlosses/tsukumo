# Claude Code の TUI を捨て、SDK で動かす

**2026-09-11 の方針転換。** それまでは TUI をそのまま使い、別ペインの常駐プロセスが transcript を
追従して覗き見ていた。一式動くようにはなったが、**合格シーンに構造的に届かない**ことが分かった
（「1コマンドで起動すると1つの画面が開く。…**Claude Code の TUI は一度も見ない**」。
`docs/requirements.md` 1章）。TUI が画面に残る限り同じ内容が2箇所に出て、入力は簡素なほうへ移る。
加えて**Orca はエージェント端末への合成入力を弾く**（2026-09-11 実測。`orca terminal send` は
`agent_prompt_blocked`、`orca keypress` は前面のペインにしか届かず、前面にしても入らなかった）
ため、**画面から答えることすらできなかった**。

検討した案:

- **案A: PTY を自前で持ち、その中で TUI を動かして画面に埋め込む** — **採らない**。TUI の
  二重表示が残る（キャラの吹き出しと TUI が同じことを言う）うえ、キー入力を合成する壊れやすい
  層が増える。実験までは通したが、方針転換で不採用にした
- **案B: headless CLI（`claude -p --input-format stream-json`）** — **採らない**。**中断ができず**、
  `--permission-prompt-tool` が手元の版（v2.1.x）に無い
- **案C: Agent SDK（`@anthropic-ai/claude-agent-sdk`）で動かす** — **採用**。会話・ツール実行・
  許可・質問が構造化イベントで届き、ストリーミング入力モードで追加入力と中断ができる。
  スキル・`.claude/commands`・hook・MCP もそのまま使える（一次情報で確認済み。
  `docs/requirements.md` 3章）

**代償**: 「本体のログを読んでいるだけなので Codex / Gemini CLI にも流用できる」という副次的な
利点は消えた。汎用のログ tailer ではなく、Claude Code に固有の駆動役になる。目的は
「キャラクターと一緒に楽しく仕事をする」ことであって汎用性ではないので、これは払ってよい。

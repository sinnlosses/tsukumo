# デザインシステムを Astryx の見た目に寄せる: 色は tsukumo から写し、形と大きさは Astryx に従う（2026-11-10）

ステータス: 採用

**`ui/` の部品は、Astryx の部品の見た目のまま使う。今の見た目を CSS Modules やトークンの写しで作り直さない。tsukumo から Astryx へ写すのは色とコードの書体だけにして、字の段・本文の書体・余白・角丸・影は向きを逆にし、tsukumo のトークンが Astryx の値を引く。本文の行の高さだけは日本語の長文に合わせて上書きする。テーマが見出しと段落に当てる既定は打ち消さない。`reset.css` は `ui/` の移行が済んでから読ませる。**

利用者が決めたのは次の4つ（2026-11-10）。今の見た目を保つより、Astryx の部品を使って見た目を整えることを選んだ。本文の行の高さだけは日本語向けに残す。`ui/` の外の画面も、tsukumo のトークンを Astryx の値から引いて同じ段にそろえる。`reset.css` は `ui/` の移行が済んでから読ませる。

この ADR は 0052 を置き換える。0052 の論点 1（テーマの組み立てと版の固定）・2（CSS の読ませ方と層の順）・5（境界の検査と置き場）・7（E2E と単体テストの役）・8（根の `Theme`）は、結論も理由もそのまま引き継ぐ。その本文と、0052 の「前提」にある試作とパッケージの記録は 0052 を読む。改めるのは論点 3・4・6 と課題の分け方で、この ADR が持つ。

## 何が困っていたか

0052 は `ui/` の中身を Astryx に替えつつ、見た目は今のまま保つ形だった。保つ仕掛けは次の4つ。

- テーマの定義（`ui/theme-root/tsukumo-theme.ts`）が、色だけでなく字の段・行の高さ・本文の書体・余白・角丸・影まで tsukumo の値へ写していた。
- `theme.css` の `tsukumo-base` の層が、テーマが見出し・段落に当てる既定を `revert` で打ち消していた。
- 部品ごとの課題が、Astryx の部品に無い差（`button` の 27 の `variant` など）を CSS Modules で作り直す決まりだった。
- 字と並びの課題の計画は、Astryx の `Text` が当てる行の高さ・書体・太さを打ち消して、今の値に戻す段を持っていた。

利用者の狙いは、Astryx の部品を使って見た目を整えることだった。保つ仕掛けはその逆を向いていて、Astryx に替えても見た目は変わらず、打ち消しの規則だけが増える。

## 論点 1: トークンの向き

**採る: 色は tsukumo が正典で、Astryx へ写す（0052 の論点 4 の色の行のまま）。字の段・本文の書体・余白・角丸・影は Astryx が正典で、tsukumo のトークンが `var()` で Astryx の値を引く。テーマの定義からは、字の段・本文の書体・余白・角丸・影の写しを外す。**

| 種類                                     | 正典              | 向き                                                                                                                 |
| ---------------------------------------- | ----------------- | -------------------------------------------------------------------------------------------------------------------- |
| 色（地・字・枠・差し色・状態・覆いなど） | tsukumo           | `--ink` などを Astryx の `--color-*` へ写す                                                                          |
| コードの書体                             | tsukumo           | `--font-code`（IBM Plex Mono）を `--font-family-code` へ写す                                                         |
| 本文の行の高さ                           | tsukumo（上書き） | 新しいトークン `--line-height-reading` を `--text-body-leading` へ写し、`--line-height-body` がそれを引く            |
| 本文・見出しの書体                       | Astryx            | `--font-sans` が `--font-family-body` を引く                                                                         |
| 字の段                                   | Astryx            | `--font-body`・`--font-heading-1` などが `--text-*-size`・`--font-size-*` を引く                                     |
| 余白・角丸・影                           | Astryx            | `--space-*`・`--radius-*`・`--shadow-raised`・`--shadow-overlay` が `--spacing-*`・`--radius-*`・`--shadow-*` を引く |
| 部品の高さ・動き                         | Astryx            | tsukumo に対応するトークンは無い。tsukumo の動きの 2 段（`--motion-*`）は今回変えない                                |
| キャラクターの書体                       | tsukumo           | `--font-serif`・`--font-diary` は Astryx に対応が無く、今のまま                                                      |

tsukumo のトークンが引く先の下書き（広い画面の値。土台の課題が見本帳で 1 段ずつ見て決め直してよく、決め直したら `design-token.md` に書く）:

| tsukumo のトークン                          | 引く先（Astryx）                                           | 値の前 → 後                   |
| ------------------------------------------- | ---------------------------------------------------------- | ----------------------------- |
| `--font-body`                               | `--text-body-size`                                         | 15px → 14px                   |
| `--line-height-body`                        | `--text-body-leading`（`--line-height-reading` の上書き）  | 1.73 → 1.7 前後               |
| `--font-label`                              | `--font-size-sm`                                           | 12px → 12px                   |
| `--font-secondary`                          | `--text-supporting-size`                                   | 13px → 12px                   |
| `--font-subheading`                         | `--font-size-base`                                         | 14px → 14px                   |
| `--font-heading-1`                          | `--text-heading-1-size`                                    | 21px → 24px                   |
| `--font-heading-2`                          | `--text-heading-2-size`                                    | 19px → 20px                   |
| `--font-heading-3`・`--font-heading`        | `--text-heading-3-size`                                    | 17・18px → 17px               |
| `--space-2xs`〜`--space-4xl`                | `--spacing-0-5`〜`--spacing-12`                            | 同じ値                        |
| `--radius-sm`・`--radius-md`・`--radius-lg` | `--radius-inner`・`--radius-element`・`--radius-container` | 4・8・12px → 6・10・12px      |
| `--radius-pill`                             | `--radius-full`                                            | 形は同じ                      |
| `--shadow-raised`・`--shadow-overlay`       | `--shadow-med`・`--shadow-high`                            | 1 層の影 → 2 層の影と明るい縁 |

理由:

- 色を tsukumo に残すのは、0052 で利用者が試作の B を選んだのと同じ理由で、パックの accent を部品に出すため。
- 形と大きさの向きを逆にするのは、`ui/` の外の画面（移していない画面）も同じ段にそろえるため（利用者決定）。tsukumo の CSS は今のトークンの名前を読み続けるので、呼ぶ側も、0041 の直書きの検査も変わらない。土台の課題の 1 回で、画面全体が Astryx の段になる。
- 本文の行の高さを上書きするのは、Astryx の本文の行の高さ（広い画面で 1.43、触る画面で 1.5）が英字の UI 向けで、レポートと会話の長い日本語の段落では行が詰まるため（利用者決定）。見出し・名札・ボタンの行の高さは Astryx のまま。
- 値を `theme.css` の `--line-height-reading` に置くのは、テーマの定義の値を tsukumo のトークンの `var()` とそれを組んだ式だけに保つため（0052 の論点 4 の縛りを続ける）。
- 写しを両方向に書くと値が循環する。そこでテーマの定義から、Astryx が正典になる種類の写しを外す。
- 字の下限 12px（`principle-and-type.md`「13.3 Type」）は保つ。12px を割る Astryx の段（`--font-size-xs` の 10px より下）は、tsukumo のトークンから引かない。13.3 の「大きさはこの 9 つだけ」は、土台の課題が Astryx の段に合わせて書き直す。
- neutral は触る画面で `lg` より狭いとき（`pointer: coarse`）に字の段を組み直す。tsukumo の段は Astryx を引くので、この組み直しに自動で付いていく。`theme.css` の `@media (max-width: 760px)` で字の大きさを上げる規則は外す。テーマの `adaptations` に残すのは、本文の行の高さの上書きを同じ条件で書き直す規則だけにする。

確かめること:

- Temporal を持たないブラウザに出す案内（`main.tsx`）は `Theme` の外で、Astryx のトークンが届かない。案内が tsukumo の字や余白のトークンを読むなら、`var()` の代わりの値で崩れないことを土台の課題が確かめる。

採らなかった案:

- 0052 のまま、全部を tsukumo から写す: 上の「何が困っていたか」。
- `ui/` の部品だけ Astryx の値にする: 移行が済むまで、部品と画面の残りで字の大きさ（14px と 15px）と角丸（10px と 8px）が食い違う。
- 本文の行の高さも Astryx のまま: 長い日本語の段落が詰まる。

## 論点 2: 見出し・段落の既定と `reset.css`

**採る: `tsukumo-base` の層で見出し・段落の既定を打ち消す規則を外し、テーマの `@layer reset` の規則をページ全体に効かせる。`reset.css` は、`ui/` の部品を移す 5 つの課題（字と並び・操作と印・入力・重なる面・箱）が済んでから読ませる。** それまでに、`reset.css` の既定（`box-sizing: border-box` など）に頼る Astryx の部品が崩れたら、テーマの `components` の `base` でその部品だけを補う。

理由:

- テーマの見出し・段落の規則は、字の段と本文の行の高さのトークンを読む。打ち消さなければ、`ui/` を通さない素の見出しと段落も Astryx の段になる。論点 1 と同じく、画面全体を同じ段にそろえる側に立つ。
- `reset.css` は、全要素の `box-sizing`・余白・枠・箇条の印・`img` の表示・ボタンの地を変える。tsukumo の `styles/` には全体の `box-sizing` の規則が無い（2026-11-10 に grep で 0 件）。読ませると、移していない画面の寸法がどこで動くかは読ませてみるまで分からない。試作では見本帳の全体の高さが 18,567px から 18,240px に動いた（0052 の試作の 5）。
- `ui/` を移し終えれば、移していない画面は `ui/` の部品を使わない素の要素だけになり、`reset.css` で動く範囲を画面ごとに測って直せる。
- 部品ごとに補う規則をテーマの `components` に書くのは、Astryx が用意した上書きの口だから。部品の CSS Modules に書くと、論点 3 の「見た目を CSS Modules で作り直さない」と区別できなくなる。

採らなかった案:

- 打ち消しを残す（0052 のまま）: 素の見出しと段落だけが Astryx の段から外れる。
- 土台の見直しで今すぐ `reset.css` を読ませる: 上の理由。

## 論点 3: `ui/` の部品の当て方

**採る: `ui/` の部品の props（tsukumo の語彙）は今のまま残し、呼ぶ側は触らない。中身は props を Astryx の props へ写し、tsukumo の複数の語が Astryx の 1 つの見た目に落ちてよい。今の見た目を CSS Modules で作り直さない。** 0052 の論点 6 の対応表のうち、当てる Astryx の部品と課題の分け方は引き継ぎ、「語彙の合わせ方」の列はこの論点で読み替える。

- tsukumo が意味で分けている区別に Astryx の `variant` が無いとき（`text` の状態の色・`badge` の `accent` など）は、テーマの `components` の上書きと、`variant` の型の拡張（`ButtonVariantMap`・`BadgeVariantMap` など）で足す。Astryx の拡張の口で、neutral も `badge` の `variant` に `gray` を足している（`neutral.variants.d.ts`）。見た目だけの区別（枠の点線・hover の色の違いなど）は足さずに落とし、落とした区別と呼ぶ側の数を課題の報告に表で書く。
- `ui/` の部品の CSS Modules に書いてよいのは、置き場所・寸法のように Astryx の props に口が無い配置だけ（`dialog` の `placement` の座標など）。
- `button` の 27 の `variant` は、Astryx の 4 つ（`primary`・`secondary`・`ghost`・`destructive`）のどれかへ写す。呼ぶ側の語を減らすのは、操作と印の課題が対応表と件数を添えて、別の課題に切り出す。
- 例外の候補は 3 つ。`typing-dot-list` は Astryx に入力中の点の部品が無いので、今の CSS のまま残す（0052 のまま）。`text` の `element="summary"` は Astryx の `Text` の `as` に `summary` が無いので、素の `<summary>` に Astryx の字の段のトークンを当てる。`layout-resizer` は箱の課題が確かめる（0052 の未決のまま）。例外の部品も、論点 1 で Astryx を引くトークンだけを読む。
- 役（role）・アクセシブルネーム・状態の aria は今のものを保つ（0052 の論点 7 のまま）。見た目が Astryx になっても、読み上げと E2E の当て方は変えない。

理由:

- props を残すのは 0052 と同じく、呼ぶ側（`text` だけで 93 ファイル。0052 の数）の書き換えと見た目の移行を、1 つの差分に混ぜないため。
- 作り直さないのは、作り直すと Astryx に替えても見た目が変わらず、狙いに届かないため。
- 拡張をテーマに書けば、組み立て物（`astryx theme build`）と `--check` の見張りに乗る。

採らなかった案:

- props を Astryx の props に合わせて替える: 0052 の論点 6 と同じ理由。
- 区別の足りない分を CSS Modules で足す: 上の理由。

## 課題の分け方

| 順  | 課題                    | 中身                                                                                                                                                                                                           |
| --- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 土台の見直し            | テーマの定義を色・コードの書体・本文の行の高さに絞る。tsukumo のトークンが Astryx を引く（論点 1）。`tsukumo-base` の打ち消しと狭い画面の字の規則を外す（論点 2）。`design-token.md` と E2E の期待値を書き直す |

- 2〜6 は 1 件ずつ進める理由も、7 を 2・3・6 のあとに置く理由も、0052 の論点 6 と同じ。

## 0041・0042 との関係

- 0041 のトークンの名前・段の数・見本帳・直書きの検査は続く。変わるのは字の段・角丸・影の値の出どころで、0041 が決めた tsukumo の値の代わりに Astryx の値を引く。余白は値が同じ。
- 0042 は覆さない。内容部品は React の部品として直に描き、その土台が `ui/` の Astryx の部品になる。

## 未決

1. `reset.css` の既定に頼る Astryx の部品の崩れ（論点 2）。見つけた課題がテーマの `components` で補う。補えない部品が出たら、`reset.css` を読ませる時期を見直す。
2. happy-dom で描けない Astryx の部品（0052 の未決 2 のまま）。
3. `layout-resizer` を例外にするか（0052 の未決 3 のまま）。
4. `main.css` が約 30 万バイト増えたときの読み込みの手間（0052 の未決 4 のまま）。
5. 新しい部品（Tree List・Hover Card）をレポートのカタログに足すか。
6. `button` の呼ぶ側の語を減らすか（論点 3）。操作と印の課題が対応表を添えて提案する。

## 影響

- `ui/theme-root/tsukumo-theme.ts` の写しが、色・コードの書体・本文の行の高さだけになる。
- `theme.css` の字の段・余白・角丸・影のトークンが Astryx の値を引き、`--line-height-reading` が増える。`tsukumo-base` の打ち消しと、狭い画面で字を上げる規則がなくなる。
- 画面全体の字・角丸・影が一度に変わる。E2E の DOM の写しと見本帳を土台の見直しで撮り直す。
- 後段の課題の本文を、この ADR に合わせて直す。

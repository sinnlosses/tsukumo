# 別の利用者のプロセス（`EPERM`）は生きている扱いに揃え、生死の判定を1つにする（2026-11-06）

ステータス: 採用

**`process.kill(pid, 0)` が `EPERM` で失敗したときは、権限が無いだけでプロセスは生きている。生きているかの判定は `isProcessAlive(pid)` の1つに置き、`scripts/` もこれを読む。** ADR 0026 の「`EPERM`（別の利用者のプロセス）も捨てる」を改める（0026 は凍結なので書き換えない）。

## 何が困っていたか

「pid のプロセスが生きているか」を見る関数が4か所にあり、`EPERM` の扱いが2対2に割れていた。

| 場所                                       | `EPERM` の扱い |
| ------------------------------------------ | -------------- |
| `scripts/runtime/stop.ts`                  | 死んでいる     |
| `scripts/shared/live-instance-location.ts` | 生きている     |
| `scripts/dev/lib/check-running.ts`         | 生きている     |
| `session-driver` の占有ファイルの読み      | 死んでいる     |

`stop.ts` は SIGTERM を送ったあとに生死を見て「まだ生きている」を出す。`EPERM` を死んでいる扱いにすると、権限の無い相手が居ても「止まった」と言い切る。

## 決めたこと

- **`EPERM` は生きている。** それ以外の失敗（`ESRCH` ほか）は死んでいる
- **判定は `src/server/session-driver/adapter/process-alive.ts` の `isProcessAlive` 1つに置く。** 読み手が `session-driver` だけなので、その機能の adapter に置き、`scripts/` はこのファイルを import する
- **変わる挙動は2つ。**
  - `stop.ts` は、権限の無い相手が居るとき「まだ生きている」を出す
  - 占有ファイルの読みは、`EPERM` の占有を生きている占有として数える（これまでは数えず、消しもしなかった）。死んでいると分かった占有ファイルは消す

## 0026 との関係

0026 の他の決めごとは覆さない。覆すのは、読む側の「`EPERM` も捨てる」の1点だけで、占有ファイルの置き場・中身・書く順・生存だけで決める線は変えない。

| ADR  | 決めごと                                           | この ADR が覆すか | 理由                                    |
| ---- | -------------------------------------------------- | ----------------- | --------------------------------------- |
| 0026 | 読む側は `EPERM`（別の利用者のプロセス）も捨てる   | 覆す              | `EPERM` は生きている。判定を1つに揃える |
| 0026 | 占有ファイルの置き場・中身・書く順                 | 覆さない          | 判定の揃え方と関わらない                |
| 0026 | 使用中かを占有ファイルとプロセスの生存だけで決める | 覆さない          | 生存の判定を1つにしただけ               |

振る舞いの正典は `docs/requirements/session-restore-condition.md`。

# ビューは1枚のページにまとめる

メインビュー・キャラビュー・サイドバー・入力欄を**1枚の HTML にまとめ、CSS の grid で領域を
分ける**。ブラウザタブは1つだけになる（**2026-09-11 の方針転換で入力欄が加わり、
ターミナルのペインは1つも要らなくなった**。`docs/requirements.md` 4.7）。

**当初は3つを別々のビューとして開き、`orca terminal split` でペインを組み立てるつもりだった。
これは成立しない。** 実際に組み立てを実行したところ、ビューは**ブラウザタブとして開くだけ**で、
ターミナルのペインのグリッドには入らなかった（2026-09-10、ユーザーの実機で確認）。

原因を Orca のコマンドスキーマ全件で確かめたところ、**ブラウザタブをペインのグリッドに配置する
コマンドが存在しない**。`tab` 系は `create` / `close` / `list` / `switch` / `show` / `profile` のみ。
`terminal split` はターミナル同士を割るもので、タブは対象外。**タブとペインは別の面**であり、
CLI から両者を1つのレイアウトに組むことはできない（UI 上で手で並べることはできる）。

1枚にまとめると、**3領域の比率をこちら側で完全に制御できる**。`orca terminal split` に比率を
指定するフラグが無いという制約は、この3領域については関係がなくなる。利用者が手で並べるのも
「ブラウザタブ1つ」と「claude のターミナル1つ」の2つだけになる。

**代償**: 領域を別々のウィンドウ（別モニタなど）に分けることはできなくなる。今の構想では不要と判断した。

**個別ビューのページ（`/main` `/character` `/sidebar`）は 2026-09-12 に消した。** 上の当初案
（3つを別々のタブで開いてペインに並べる）の名残として「デバッグしやすさのため」残していたが、
実際の目視確認は合成データで `buildLayoutPage` を呼んで静的 HTML に書き出す方法で行っており
（当時の `docs/coding-standards.md` の節「描画は自動テストで守らない」）、個別ページの経路は使われていなかった。
`/` はこのまとめたレイアウトページ（`LAYOUT_PATH`）そのものを返す。

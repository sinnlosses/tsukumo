# 最終レポートを図が先に立つ形にする: 主の図・主張ごとの裏づけ・結果を見て選ぶお願い（2026-11-15）

ステータス: 採用

**最終レポートを、見本の案A「前と後」の形へ3段で進める。段1 は、結論のすぐ下に報告の種類で決まる主の図を置き、節を「主張の見出し・図・注記」の組で書き、色を状態・強調の1色・灰の3役に分ける（`report` の入力に欄は足さない）。段2 は、検証の結果を主張ごとの印と控えにして、冒頭の「確かめたこと」の一覧を裏づけの帯の1行に置き換え、やっていないことの欄を足す。段3 は、お願いを結果の見える札で選べるようにし、対の見せ方を紙の上で切り替えられるようにする。この ADR は、段2 が入った時点で ADR 0059 の論点 4 を上書きする。**

この ADR が決めるのは、最終レポートの骨組み・主の図の決め方・色の役割・裏づけの出し方・お願いの形・送る順まで。寸法と字の大きさは決めない（見本と、部品の CSS が持つ）。進行の帯・「いま」の行・お願いの置き場と知らせは ADR 0059 のまま変えない。

## 何が困っていたか

- 最終レポートは文と表が主で、図は添え物になっている。部品の使用の記録（`docs/research/report-catalog-usage-2026-10-28.md` の a2ui の 206 件）では、`Table` を含むレポートが 78%、図の部品を含むレポートが 17%、配置の部品は 0.5% だった。部品は 32 種あり、足りないのは数ではなく選ばれ方だった。
- 報告の種類（`task.genre`）は `report` の定義にあり、種類ごとの図の第一候補も `src/server/report/core/rules/template.ts` の `REQUEST_TEMPLATES` が持つが、数えるだけの検査に使われていて、描く側は種類を読まない（`src/browser` に `genre` を読む所は 0 件）。
- 確かさが、冒頭の検証の行（`checks`）と本文の `Claims` の2か所に分かれ、証拠の画や出力とは結ばれていない。主張を読んでいる場所から、その裏づけが見えない。
- 色の役割が重なっている。差し色の既定 `#f2b0a0` と `state-ng` の `#f2a0a0` は、OKLab の色差を 100 倍した値で 4.0（色覚に関わらず見分けにくい下限は 15）。手元のパックの差し色の1つ（`#ff9e9e`）とは 2.1。系列色6色のうち5色も、状態の色と 15 未満の差だった（「実物で確かめたこと」）。
- お願いは文の塊で、続けて頼める選択肢は tsukumo が材料から起こす4種（再開する・続ける・確かめる・別の案で進める）だけ。書き手が「どちらにするか」を選択肢として示す口が無い。

### 論点 1: 紙の骨組み

**採る: 最終レポートは、結論 → 冒頭の検証 → 主の図 → 主張ごとの節 → 変えていないこと → やっていないこと → お願い → 続きの提案、の順にする。冒頭の検証は、段1 では ADR 0059 のまま「確かめたこと」の一覧、段2 からは裏づけの帯の1行。お願いと続きの提案は、無ければ置かない。作業の名前を持たない短い答えは、結論と本文だけで、図も帯も置かない。**

- 並びは今の欄の固定の順（結論・検証・`figure`・節・お願い・次の一手）と同じで、足すのは「変えていないこと」の節と「やっていないこと」の欄だけ。
- 「変えていないこと」は欄にせず、その見出しの節として書く（記法の条で言う）。結論の2文目に書いている「変えていないもの」と同じ中身を、確かめた手段と並べて置く場所になる。
- 該当する画: `pair-work-1400.png`（頭）・`pair-work-end-1400.png`（末尾）・`case-short.png`（短い答え）。

### 論点 2: 主の図は報告の種類で決める

**採る: 主の図（`figure`）の型と、対の見出しを、報告の種類と終わり方で決める。対の見出しは「前｜後」に限らず、題材に合わせて読み替える。対にならない題材は、無理に対へ寄せない。**

| 報告の種類・終わり方                   | 主の図                          | 対の見出し                             | 部品                                    |
| -------------------------------------- | ------------------------------- | -------------------------------------- | --------------------------------------- |
| 画面を変えた（`work`・`screen`）       | 前後の画                        | 前｜後                                 | `Compare`（画像・`before-after`）       |
| 数を良くした（`work`）                 | 前と後の数を同じ軸の1枚に重ねる | 前｜後                                 | `Chart`（`arrow`）                      |
| 構造を組み替えた（`structure`）        | 前後の構成図                    | 前｜後                                 | `Compare`（`svg` か `mermaid`）         |
| 不具合を直した（`diagnosis`）          | 前後の画かコードと、原因の流れ  | 前｜後                                 | `Compare`、`ItemList`（`flow`）         |
| 案を比べて決めた（`decision`）         | 今と採ったあと、案の比べ        | 今｜採ったあと                         | `Compare`、`Matrix`・`Options`          |
| 調べて分かった（`research`・`status`） | 分かったことの図が1枚           | 対にしない。行は「問い｜分かったこと」 | `Chart`・`Plot`・`Graph`、`Table`       |
| 時間の順（`timeline`）                 | 時間の図が1枚                   | 対にしない                             | `Timeline`                              |
| 途中で止めた（`stopped`）              | 狙いと今                        | 狙い｜今                               | `Compare`、`Trace`                      |
| 戻せない操作の前（`awaiting-answer`）  | 今としたあと                    | 今｜したあと                           | `Compare`（`points`）、`Note`（`warn`） |
| 作業の名前を持たない短い答え           | 置かない                        | 対にしない                             | `DescriptionList`                       |

- 種類ごとの第一候補は、今の `REQUEST_TEMPLATES` の並びを上の表に合わせて改める（`decision`・`structure`・`diagnosis` は `compare` を先頭にする）。検査は今の `template-miss` のまま数えるだけで、差し戻しには上げない（ADR 0038）。
- 書き手には、`report` の定義の `task.genre` と `figure` の説明と、部品の引き方の手引き（`REPORT_PART_CHOICE_GUIDE`）で、種類ごとの主の図と対の見出しを伝える。対の見出しは `Compare` の側の `heading` に書ける（欄は足さない）。
- 該当する画: `case-bug.png`・`case-shape.png`・`case-speed.png`・`case-study.png`・`case-plan.png`・`case-halt.png`・`case-ask-end.png`。

### 論点 3: 節は「主張の見出し・図・注記」の組で書く

**採る: 節の見出しは主張の文にし（今の決まりのまま）、節の先頭に図を置き、注記は図の直後に2行までにする。図は紙の幅いっぱい、文は今の上限（42em）のまま。変化を言う行は、`Table` の「前から後」のセルで「名前｜前｜後」の行として書く。**

- 図に書けることを地の文で繰り返さない（今の条 3）。図の中の名前と値は図に直接書き、凡例は強調の1色だけにする。
- 差が小さい数は棒にしない（2,853 と 2,861 の棒は見分けられない）。前と後の数を並べ、増えた分だけを言う。
- 描く側は、対の「後」の見出しに強調の印を付け、`Table` の「前から後」のセルは前を灰・後を明るい字で描く。
- 該当する画: `pair-work-1400.png`・`case-bug.png`（原因の流れとコードの前後は、この画の下に続く）。

### 論点 4: 色は状態・強調の1色・灰の3役に分ける

**採る: 状態の色（通った・要る・落ちた）の値を、画面全体で次の値に替える。変わった所・後・採る案・足した行には強調の1色（今の `chart-series-1`）を使い、前と文脈は灰にする。紙の中では、差し色を内容の意味に使わない。**

| 役割                   | トークン                     | 今の値    | 替えたあと | 根拠                                                       |
| ---------------------- | ---------------------------- | --------- | ---------- | ---------------------------------------------------------- |
| 落ちた                 | `state-ng`                   | `#f2a0a0` | `#ef6b6b`  | 差し色の既定との色差が 4.0 から 15.3 になる                |
| 通った                 | `state-ok`                   | `#7ee081` | `#5fd38a`  | 「要る」との色差が 12.6 から 17.9 になる                   |
| 要る・申告のみ・お願い | `state-warn`                 | `#e3c766` | `#f2b544`  | 同上                                                       |
| 強調の1色              | `chart-series-1`             | `#87bafd` | 変えない   | 替えたあとの状態の3色と、全部の組で色差 17.9 以上          |
| 増減の数               | `--report-change-added` ほか | 状態の色  | 強調と灰   | 足した行は「通った」ではなく、消した行は「落ちた」ではない |

- 状態の色は、記号と語を必ず添える（今の決まりのまま）。替えたあとも、手元のパックの差し色の1つ（`#ff9e9e`）とは色差 11.9 で 15 に届かず、色覚の見分けは最小 7.5 で注意の帯に入るため、色だけでは言い分けない。
- 紙の中で差し色を外す所は、お願いの地と左の罫（`report-note-favor`）、変えたファイルの種別の印（`--report-outcome-finished`）、表の強調の列の地（採った案の列）。強調の列は、強調の1色の薄い地にする。差し色を残すのは、利用者の操作の場所（返す層で指した単位・入力の印）だけにする。
- 「情報」と「疑問」（`state-info`・`state-ask`）は、系列色の1番・3番と色差 4.1・2.2 で見分けられない。この ADR では値を替えず、紙の中の `Note` は語と記号で言い分ける今の形を保つ。値の選び直しと、系列色（`chart-series-1`〜`6`）の選び直しは後回しにする。
- 新しい強調の色のトークンは足さない。数の図は今も「見る項目だけ `chart-series-1`、ほかは灰」で描いている（`docs/architecture/screen-design/color.md`）。
- 該当する画: `pair-work-1400.png`（囲みと「後」の印）・`case-speed.png`（縮んだ所だけ強調）・`case-halt.png`（落ちた目盛りと囲み）。

### 論点 5: 裏づけは主張ごとに付け、冒頭は帯の1行にする（段2）

**採る: 検証の行を、裏づける主張（節）に結ぶ。主張ごとに、印（落ちた・記録あり・申告のみ）と控え（打ったもの・数・所要）を図の下に出す。冒頭の「確かめたこと」の一覧は、主張の数だけ目盛りを並べた帯の1行に置き換える。やっていないことの欄を足し、無いときも「無い」と出す。印は tsukumo が記録から導き、書き手に申告させない。**

- 入力に足す欄は2つ。検証の行に、裏づける節を指す欄（節の ID の並び。提案する名前は `supports`）。`Report` に、やっていないことの欄（文字の並び。提案する名前は `notDone`）。名前は用語集に足してから使う。
- 印の導き方: 節に結ばれた行に `ng` があれば「落ちた」。全部が `ok` で、全部が同じやり取りで打ったコマンドと照らせれば「記録あり」。それ以外（照らせない行・`unobserved`・`blocked` を含む）は「申告のみ」。照らし方は ADR 0059 論点 4 の印と同じで、広げない。
- 帯の目盛りは、検証の行が結ばれた節ごとに1つと、やっていないことの1件ごとに1つ。並びは、落ちた・申告のみ・記録あり・やっていない、の順。色だけで言い分けず、落ちたは背を高く、申告のみは中抜き、やっていないは破線にする。
- どの節にも結ばれていない検証の行（全体の検査など）は、帯のすぐ下に今の「通った行の畳み」と同じ形で残す。落ちた行・確かめていない行は、結ばれていなくても開いて出す（今の並びの決まりのまま）。
- やっていないことの欄は、作業の名前を持つレポートで渡す。空の並びなら「無い」と描く。省いたレポートは、欄ごと描かない（黙っていることと、無いと言うことを区別する）。省いたことは数えるだけの検査で数える。
- 段2 が入った時点で、ADR 0059 論点 4 の「結論の直後は検証の結果だけ」は、「結論の直後は裏づけの帯の1行」に変わる。印の語（記録あり・申告のみ）と照らし方は引き継ぐ。
- 該当する画: `pair-work-lv1-1400.png`（段1。冒頭に一覧が残る）・`pair-work-lv2-1400.png`（段2。帯と印）・`case-halt.png`（落ちた目盛り）。

### 論点 6: 変わった所は、機械で比べた囲みで示す（段2）

**採る: 両側が画像の `before-after` の対で、書き手が場所の枠（`region`）を渡していないとき、tsukumo が2枚を比べて変わった範囲を「後」の側で囲む。2枚の大きさが違うときと、変わった範囲が画の半分を超えるときは囲まない。**

- 書き手に座標を書かせない。画像の上に番号の丸を置かない決定（座標の外れを測れない）は変えない。
- 書き手が `region` を渡したら、それを使う（今の形のまま）。
- 該当する画: `pair-work-lv2-1400.png`（「後」の1行の囲み）。

### 論点 7: お願いは、結果の見える札で選べるようにする（段3）

**採る: お願いに、書き手が選択肢を添えられるようにする。選択肢は3つまでで、名前・押したときに入力欄へ入る下書き・選んだ結果を言う短い字を持ち、勧めるものは1つまで。確かめていない検証の行は、お願いの欄に「確かめた・違った」の対で出す。続けて頼める提案は、今の「次の一手」の行のまま。**

- 入力に足すのは、`Report` のお願いの選択肢の欄（提案する名前は `favorOptions`）の1つ。要素は、名前・下書き・結果の字（省ける）・勧める印（1つまで）・戻せない印。
- 押しても送らない（下書きを入れるだけ。ADR 0051）。置き場はお願いの本文の下で、最下部のまま（ADR 0059 論点 5）。
- 戻せない印のある選択肢があるときは、札の上に注意の行を1つ立てる。わけは、お願いの本文に書く。
- 「確かめた・違った」は、`unobserved` の行と確かめ方（`howToVerify`）から tsukumo が起こす。欄は足さない。入力欄の上の知らせの件数は、お願いの本文と合わせて数える。
- 該当する画: `pair-work-end-1400.png`・`case-halt-end.png`・`case-ask-end.png`。

### 論点 8: 対の見せ方は、紙に1つの切り替えで替える（段3）

**採る: 対のある紙に、見せ方の切り替え（並べる・後だけ・前だけ）を1つ置き、同じ紙の対の全部に効かせる。選んだ値はタブのメモリだけに持つ。画像の対の「重ねる」と境の操作は、対ごとの操作として今のまま残す。**

- 後だけ・前だけは、対の片側だけを出す。狭い幅で対が縦に積まれるときも、同じ切り替えで片側だけにできる。
- 控えから打ったコマンドの出力を覗く操作は、後回しにする。控えに出すのは、打ったもの・数・所要まで。出力を tsukumo が引いて見せるかは、会話内容の扱いと合わせて別に決める。

## 送る順

1件送るごとに、紙が読める状態を保つ。段1 は `report` の入力に欄を足さない。

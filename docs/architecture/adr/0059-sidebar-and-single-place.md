# 常設サイドバーと「同じ情報は1か所」: 3列の器・置き場の表・入力欄の下の行・キーの体系（2026-11-14）

ステータス: 採用

**会話の画面は、どの姿勢でも左から舞台・紙・サイドバーの3列を保ち、上のバーを置かない。情報の種類ごとに置き場を1つに決め、同じ情報を2か所以上に出さない。成果・キャラクター・使用量は独立したメニューの群にせず、概要を出している場所を入口にする。入力欄は Astryx の `ChatComposer` の骨格に合わせ、いま動いているセッションのモデル・effort・許可モードを下の行から変えられるようにする。キーは ⌘ と ⌃ の組合せに置く。**

この ADR が決めるのは器の列の数・置き場・入力欄の操作・キーの体系まで。紙の中の進行の出し方と、成果・キャラクター・使用量・設定・タスクの紙の中身は変えない。見本は `docs/history/mockup/ui-overhaul-2026-11-14/final.html` で、言葉の説明と見本が食い違ったら見本が勝つ。

## 何が困っていたか

- 同じ情報が複数の場所に出ている。2026-11-14 に疑似セッションを 1400x900 で撮った画から数えた値は次のとおり。
  - 依頼文が、舞台の流れ・紙の頭・欄外の3か所
  - 段の位置が、紙の頭・入力欄の帯・吹き出しの3か所
  - 状態の語が、部屋の頭・紙・欄外の3か所
- 旧い器から後退した点がある。タスクの一覧・使用量・実行設定の操作子が、常時表示から外れた。見るには紙を開くか検索を通す手数が要る。
- 入口が右上の群（探す・成果・キャラ・設定の札）と部屋の頭の2つに散り、どこから何へ行くかが場面で変わる。
- 迎えるでは舞台を広げ紙を出さないので、姿勢が替わるたびに列の数と位置が動く。

## 利用者が決めたこと

- 2026-11-14 に、会話の画面の3案の比較（`docs/history/mockup/ui-overhaul-2026-11-14/index.html`）から案A「常設パネル型」を選んだ。
- 条件は2つ。進行の出し方は今の実物のまま変えない。同じ情報を2か所以上に出さない。
- 注文は3つ。成果・キャラクター・使用量は概要の場所を入口にする。入力欄は `ChatComposer` の骨格に合わせる。使用量は取り直しのボタンと一緒にサイドバーの下へ置く。
- 見本は `docs/history/mockup/ui-overhaul-2026-11-14/final.html`。置き場の表は同じディレクトリの `index.html`「採用案の置き場」にある。

## 決めたこと

### 論点 1: 器の列

**採る: どの姿勢でも、左から舞台（幅 328px）・紙・サイドバー（幅 340px）の3列。上のバーは置かない。雑談で舞台を広げる幅と、760px 以下の縦1列は今のまま。**

使用量を上のバーから外すと中身が残らないので、バーを無くし、場所と検索はサイドバーの頭へ、名札とモードは舞台の頭へ移す。

### 論点 2: 情報の置き場

**採る: 情報の種類ごとに置き場を1つに決め、同じ情報を2か所以上に出さない。置き場は見本の `index.html`「採用案の置き場」の表のとおり。**

- 紙の中の進行の出し方（頭の札・灯り・「n段のうちm段目」・経過、計画の一覧）は今のまま変えない。
- やり取り（依頼とセリフ）は舞台の流れにだけ出し、依頼の行を押すとその回を紙に出す。欄外の「この部屋のやり取り」と紙の頭の依頼文は置かない。
- 進行（段の位置・手元・経過）は紙の頭と紙の中の計画の一覧にだけ出す。広い幅（761px 以上）の入力欄の帯の灯りと経過、サイドバーには置かない（760px 以下は今のまま出す）。吹き出しの「手元」の行は、紙が働いている回の計画を出しているあいだだけ置かない（過去の回・計画を持たない作業・背景の待ちでは進行が画面のどこにも出ない時間を作らないため出す）。
- 状態（作業中・完了）は紙の頭の札にだけ出す。部屋の頭の状態の行と欄外の行は置かない。
- タスク・セッションはサイドバーに置く。待機の推薦3件だけは紙に出す。

### 論点 3: 成果・キャラクター・使用量・設定の入口

**採る: 成果・キャラクター・使用量は、独立したメニューの群にせず、概要を出している場所を入口にする。設定とキーの一覧はサイドバーの下。**

- 今日の灯り（舞台の頭）を押すと成果の紙が開く。
- 名札（舞台の頭）からキャラクターを選び、メニューの末尾の「キャラクターを管理」でキャラクターの紙を開く。
- 使用量の欄の見出し（サイドバーの下）を押すと使用量の紙が開く。使用量（文脈・5時間・7日間）は取り直しのボタンと一緒にここに置く。
- 成果・キャラクター・使用量・設定・タスクの紙の中身と、右から重ねる出し方は変えない。タスクの紙の入口は検索に残す。
- 右上の群と欄外は無くなる。

### 論点 4: 入力欄と実行設定

**採る: 入力欄は Astryx の `ChatComposer` の骨格（角丸 28px・内側 12px・上に添付の引き出し・下の行に操作・円形の送信と中断）に合わせる。モデル・effort・許可モードは、入力欄の下の行から、いま動いているセッションの値を変えられる。**

### 論点 5: キーの体系

**採る: キーは ⌘ と ⌃ の組合せに置く。**

| キー  | 働き               |
| ----- | ------------------ |
| ⌘K    | 検索               |
| ⌘J    | タスク             |
| ⌘O    | セッション         |
| ⌘⇧O   | 新規セッション     |
| ⌃1〜9 | キャラクターの切替 |
| ⌘B    | サイドバーの開閉   |
| ⌘/    | キーの一覧         |
| ⌘,    | 設定               |

⌘N・⌘T・⌘W は使わない。

### 論点 6: 雑談のサイドバー

**採る: 雑談では、サイドバーの中段に、今の欄外の中身（覚えていること・最近の話題）をそのまま置く。** 見本に無い場面で、計画を立てたセッションが決めた。

### 比較した3案

| 案                 | 物差し                                                                                 | 判定     |
| ------------------ | -------------------------------------------------------------------------------------- | -------- |
| 案A 常設パネル型   | タスク・セッション・使用量が開かずに見える。配置が場面で変わらず、入力欄も紙も動かない | 採る     |
| 案B コマンド中心型 | 舞台は最も広い。常時見える情報が最少で、タスクとセッションが呼び出すまで見えない       | 採らない |
| 案C タブとボード型 | タスクが主役になり、キャラクターが脇役になる。セッションとタスクの対応づけが裏側に要る | 採らない |

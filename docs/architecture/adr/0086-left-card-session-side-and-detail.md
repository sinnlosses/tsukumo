# 左の列の札を「やり取り｜セッション」の切り替えにし、選んだセッションの詳細を札の右隣に開く（2026-11-25）

ステータス: 採用

**左の列の札（やり取りの列）の頭を「やり取り n｜セッション n」の切り替えにし、セッション側にこの作業ツリーの今日・昨日のセッションを並べる。セッションの行を押すと、切り替え画面（⌘J）の右側と同じ詳細を札の右隣のパネルに開き、切り替えるのは詳細の「〇〇 に切り替える」ボタンだけにする。一覧の行の組み立て・選んだ1件の取得・詳細の部品は、置かれる機能 `src/browser/features/session-switcher/` に移して、切り替え画面と札が共用する。この ADR は、ADR 0058 の左の列の「やり取りの列」の記述と「セッションの選択は今のまま」の項を改訂する（ADR 0058 の本文は書き換えず、1行の追記で指す）。**

見本は `docs/history/mockup/left-sessions-2026-11-24/compare.html` の案B と B1（`scene.html?form=b-turns`・`form=b`・`form=b-detail`。画は同じディレクトリの `b-turns.png`・`b.png`・`b-detail.png`）。言葉と見本が食い違ったら見本が勝つ。

## 何が困っていたか

- 左の列の札（`src/browser/components/page/conversation/components/main-view/presentational-report-outline.tsx`。ADR 0058 の「やり取りの列」）には、いまのセッションのやり取りしか出ない。
- 過去のセッションは、上部の帯の短縮IDの札（`screen-nav-session-tag.tsx`）か ⌘J で開く切り替え画面（`src/browser/components/frame/screen-nav/components/session-switcher.tsx`）からしか見えない。どちらも押すまで何も見えず、「さっきの作業はどこだったか」を開かずに読めない。

## 利用者が決めたこと（2026-11-24〜25）

見本の3案（A 二段の札・B 札の頭で切り替え・C セッションの木）を比べ、案B と B1 を選んだ。次の項は蒸し返さない。

- 形は見本の案B と B1。言葉と見本が食い違ったら見本が勝つ。
- 札は1枚のまま、頭に「やり取り n｜セッション n」の切り替えを置く。やり取り側の開いた形（行の並び・高さ）は今のまま（2026-11-17 の決定）。
- セッション側の行は、切り替え画面の一覧と同じ材料（見出し・時刻・今日／昨日／それより前・「いま」・ほかのタブで使用中の印）を使う。札の末尾に「ほかの作業ツリー・探す ⌘J」の口を置き、ほかの作業ツリーと探す欄は切り替え画面に残す。
- 行を押すと詳細を開くだけで、切り替えるのは詳細の「〇〇 に切り替える」ボタン。詳細の中身は切り替え画面の右側（`SessionSwitcherDetail`）と同じ5つ（短縮ID・期間と依頼数・キャラクター、要約、残り、最後のひとこと、切り替えるボタン）。
- 詳細は札の右隣に、札と同じ上端で開き、会話の流れに重なる。流れの面を差し替える形（B2）は採らない。
- 狭い画面（760px 以下）は左の列が出ないので今のまま。

## 実物で確かめたこと

- **一覧の出どころ**: 一覧は `SessionState.sessions` で、サーバがセッションを起こすたびに `sessions-changed` で流す（`src/server/session/core/session-launch.ts` の `announceSessions`）。ターンのたびには流れないので、時刻は起こした時点の姿。サーバは作業ツリーを問わず新しい順に `MAX_SESSION_CHOICES`（10件）で切る（`session-catalog.ts` の `listMarkedSessions`）。
- **いまのセッションは一覧に無いことが多い**: 起動と切り替えは新規のセッションから始まる（用語集「セッション」の注記）。新規のセッションは、起こした時点の一覧にまだ載っていない。切り替え画面は、一覧に無いいまのセッションを行に出さない。
- **使用中の印**: `useOccupiedSessions(open)` は切り替え画面を開いているあいだだけ手続き `sessionClaim.occupied` を聞く。「今日」「昨日」の分け方の基準も、画面を開いた時刻（`useSessionSwitcherRequest` の `openedAt`）。
- **部品の置き場**: 行の組み立て（`use-session-switcher.ts` の `switcherRow`・`groupOf`）・選びと要約の取得（`use-session-switcher-selection.ts`・`use-session-digest.ts`）・使用中（`use-occupied-session-list.ts`）・短縮ID（`domain/session-short-id.ts`）・詳細（`session-switcher.tsx` の `SessionSwitcherDetail`・`DigestBody`）は、どれも `components/frame/screen-nav/` の下にある。会話の画面の始め方の一覧（`use-welcome-card-list.ts`）は、すでに `frame/screen-nav/hooks/use-session-digest.ts` を直に読んでいる。
- **層の上限**: `browser/hooks/` は `stores/` を読めない（`.dependency-cruiser.cjs` の `ALLOWED_BROWSER_BOX_IMPORTS`）。行の組み立ては `useSession` と `useSessionSwitcherRequest` を読むので、`browser/hooks/` には置けない。枠（`components/frame/<枠>/`）どうしと画面どうしは読み合えず、置かれる機能（`features/<機能>/`）は枠と画面のどちらからも読める。
- **詳細を重ねる層**: 左の列と札は、`contain: layout style`（ADR 0058 論点 6）と `backdrop-filter`（札の透ける面）を持つ。どちらも子の位置の基準と重なりの文脈を作るので、札の中に置いたパネルは中央の列の上へ確実には出ない。`ui/popover/popover.tsx` は Astryx の `Popover` で最上層（`[popover]`）に出し、`at` の置き方（ビューポートの座標）・外の `pointerdown` で閉じる・Esc で口へフォーカスを戻す、を持つ。
- **雑談モード**: ADR 0075 で、広い画面の雑談は左の列を出さない2ペインになった。`presentational-conversation.tsx` も雑談では札を置かない（`outline={!props.chatMode && <ReportOutline />}`）。

## 決めたこと

### 論点 1: 部品とフックの置き場と共用、同じ情報を2か所に出す理由と役割の分け方

**採る: 置かれる機能 `src/browser/features/session-switcher/` を作り、一覧の行の組み立て・短縮ID・使用中の取得・選びの芯（↑↓ の移り・使用中を飛ばす・選んだ1件の要約の取得）・詳細の部品（`SessionSwitcherDetail` と `DigestBody`）を移す。切り替え画面の器（探す欄・「＋ 新しいセッション」・一覧の作業ツリーの塊・Enter で切り替える）と帯の札は `frame/screen-nav/` に残し、機能の直下のファイルを読む。札のセッション側は会話の画面（`main-view/`）に置き、同じ機能を読む。**

- 2つの置き場（帯の枠と会話の画面）が読むので、`docs/architecture/directory.md` の「2つ以上のページ・枠」に当たる。部品・フック・語彙が1つの塊で、フックが `stores/` を読むので、`browser/hooks/` と `components/frame/` の直下に分けると層の上限に当たる。置かれる機能の定義（2つ以上の枠・画面から置かれるもの）にそのまま合う。
- 機能を足すときは `.dependency-cruiser.cjs` の `BROWSER_PLACED_FEATURES` と、地図（`docs/architecture/architecture-map.toml`）の置かれる機能の区画に1つずつ足す。外から読むのは機能の直下のファイルだけ（`browser-feature-public-surface`）。
- 始め方の一覧が直に読んでいる `use-session-digest.ts` も同じ機能へ移す。会話の画面が帯の枠の中を直に読む道は、これで無くなる。
- **2か所に出す理由**: 札のセッション側は「この作業ツリーで最近した作業」を開いたまま読む常設の置き場で、切り替え画面は押したときだけ出るモーダル（ほかの作業ツリー・それより前・探す・新しいセッション）。モーダルは覆いで札を隠すので、同じ行が同時に2か所で操作できる時間は無い。札は画面の部分集合しか出さず、それ以上を求めたら末尾の口で画面へ渡す。
- **役割の分け方**: 札は「見る・中身を読む・切り替える」、画面は「探す・ほかの作業ツリーへ移る・新しく始める」。Enter で切り替えるのは画面だけ（論点 4）。切り替え画面を開いたら、札の詳細は閉じる。

### 論点 2: 切り替えの選択を覚えるか、既定の側

**採る: 覚えない。既定は「やり取り」。選んだ側は会話の画面のメモリの store（`components/page/conversation/stores/` の下）に持ち、`localStorage` にもサーバにも書かない。セッションの世代（`session.generation`）が替わったら「やり取り」へ戻す。再読み込みでも「やり取り」から始まる。**

- 札の本務は、いま見ているセッションのやり取りを移ること（ADR 0058 論点 1 の `[` `]` と行）。セッション側は切り替える前の寄り道で、切り替えたあとに見たいのは新しいセッションのやり取りになる。覚えると、切り替え直後にセッションの一覧が残って、新しいやり取りが見えない。
- 部品の state にしないのは、札がやり取り0件の帯と開いた札とで別の部品として描き直され（`report-outline.tsx` の `EmptyReportOutline`・`ShownReportOutline`）、そのたびに側が「やり取り」へ戻るため。
- セッション側を出しているあいだも `[` `]` のキーは効き、流れのやり取りは移る（札は側を替えない）。やり取り側の見出しの行は、やり取り側に戻ったときに出る。

### 論点 3: セッション側に出す件数と群

**採る: この作業ツリーの行だけを、「今日」「昨日」の2群で出す（見本の `form=b` と同じ。件数 6 は2群の合計）。「それより前」とほかの作業ツリーの行は札に出さず、末尾の「ほかの作業ツリー・探す ⌘J」の口から切り替え画面で見る。群ごとの上限は置かず、行がサーバの上限（10件）まで来ても札の高さの上限で止め、一覧だけが転がる。いまのセッションは、一覧に無くても「今日」の群の先頭に「いま」の行として必ず出す。**

- 頭の「セッション n」の n は、札に出す行の数（いまの行を含む）。
- いまの行の見出しは、一覧にあればその見出し、無ければやり取りの列の最初のやり取りの題、やり取りも無ければ一覧と同じ「（題なし）」。時刻の位置には「いま」を出す（見本）。セッションのIDがまだ無いあいだ（新規に起こして最初の依頼を送る前）は、いまの行は押せない（詳細を取る相手が無い）。
- 一覧は起こした時点の姿のまま（実物で確かめたこと）で、札のために取り直す道は足さない。新規のセッションは一覧に載っていないので、いまの行を足さないと札の先頭が見本と違って空く。
- 「今日」「昨日」の基準は、セッション側を出した時刻にする。切り替え画面の `openedAt` は画面を開いた時刻なので、札は自分の時刻を持つ（同じ store に持つ）。
- 使用中の印は、セッション側を出しているあいだだけ `sessionClaim.occupied` を聞き、出すたびに取り直す（切り替え画面と同じ `staleTime: 0`）。印は見本の白抜きの丸で、行の `title` に「別のウィンドウで使用中」を出す。使用中の行は切り替え画面と同じく選べない（押しても詳細を開かない）。
- 一覧に出せる行が無いとき（この作業ツリーの今日・昨日の行が無く、いまの行も出せない）は、「今日と昨日のセッションは無い」の1行と末尾の口だけを出す。

### 論点 4: 詳細のパネルの層・閉じ方・キー操作

**採る: 詳細は `ui/popover/popover.tsx` の `Popover`（最上層）で出す。口は選んだ行、置き方は `at` で、左は札の右端から 8px、上は札の上端にそろえる。幅は 468px（見本）を上限に、ビューポートの右端との間に 16px を残すまで縮める。高さは札の高さの上限を上限に中身で決め、溢れたら本文（要約から最後のひとことまで）だけが転がる。閉じるのは、Esc・パネルと選んだ行の外を押す・同じ行をもう一度押す・「やり取り」の側へ替える・札を畳む・切り替え画面を開く、の6つ。↑↓ はセッションの行のあいだでフォーカスを移し、詳細が開いていれば中身が新しい行を追う。Enter と Space は行を押したのと同じで、詳細を開くか閉じるだけにし、切り替えない。**

- 最上層に出すのは、札の `contain` と `backdrop-filter` が作る文脈の外へ出さないと、中央の列の上に重ならないため（実物で確かめたこと）。`Popover` は口を押したときを外に数えないので、「同じ行をもう一度押すと閉じる」は行の `onClick` が開閉を替えて書ける。
- 別の行を押したときは、詳細はその行へ移る（閉じて開き直す見え方にしない）。外を押して閉じる判定がほかの行の押下を拾うので、セッションの一覧の中の押下は外に数えない。
- Esc で閉じたら、フォーカスは選んでいた行へ戻る（`Popover` が口へ戻す）。
- Enter で切り替えないのは、利用者が「行を押すと詳細を開くだけ」と決めたため。切り替え画面の Enter は、探す欄にフォーカスがある画面の操作なので画面に残す。キーボードで切り替えるときは、詳細を開いたまま Tab で詳細の「切り替える」ボタンへ移り、ボタンを押す。最上層のパネルへ Tab が届かないときは、実装の段が実ブラウザで確かめ、届く口を足す。
- 詳細の足元には、見本どおり「↑ ↓ 選ぶ」「Esc 閉じる」のキーの印を出す（Enter の印は出さない）。
- 詳細の中身は切り替え画面の右側と同じ5つに、見本の題の1行（行の見出し）を短縮IDの行の下に足す。題は札の詳細だけに出し、切り替え画面の詳細には出さない。札の幅（見本で 232px）では行の見出しが9〜10字で切れるが、切り替え画面では左の一覧の選んだ行が題を出しているため。共用の部品は題を出すかを受ける。
- 切り替えるボタン・いまの行で押せないこと・`restartRefused` のあいだ押せないことと理由の `title` は、切り替え画面の詳細と同じ（同じ部品を使う）。押したら詳細を閉じて切り替え、世代が替わると札は「やり取り」へ戻る（論点 2）。
- 選んだ行には見本の印（差し色の地と左の縦線）を付け、詳細が閉じたら外す。

### 論点 5: 畳んだ形（見出しの帯）と迎える場面（やり取り 0 件の帯）での見せ方

**採る: 切り替えが今の頭の行（「やり取り」と畳む口）に代わる。畳む口は切り替えの右端に残し、畳んだ形は切り替えの1行だけの帯にする（両側の件数が読める）。畳んだ帯で側の名前を押すと、その側で札が開く。迎える場面（hello のあと、やり取りが1件も無いあいだ）は、同じ切り替えの帯を出し、「やり取り 0」は押せず（`title` は今の帯と同じ「依頼を送ると、ここに並ぶ」）、「セッション n」を押すとセッション側で札が開く。**

- 見本は開いた形しか描いていない。畳む口は 2026-11-17 の決定（畳んだ形は見出しの帯）と ADR 0058 論点 7 の畳む印から残すもので、見本の切り替えの右に今と同じ大きさの口を足す。保存（「選んでいない / 畳む / 開く」）は今のまま。
- 迎える場面でセッション側を開けるようにするのは、始め方の一覧の「前のやり取りを見る」と同じく、この場面がいちばん前の作業へ戻りたい場面だから。
- 今の札は、始め方の一覧を出していて過去のやり取りを見ていないあいだ（やり取りが1件以上）は何も出さない（`report-outline.tsx` の `shown`）。その場面も、迎える場面と同じ帯を出す（側の名前を押すと開く）。札がある場面と無い場面が混ざると、セッション側への入口が場面で消える。
- 列の中身の幅が 182px 以下のときは、今の帯と同じく件数を出さない（側の名前と口が1行に収まらないため）。

### 論点 6: 雑談モードで同じ札を出すか

**採る: 出さない。** 広い画面の雑談は ADR 0075 で左の列を出さない2ペインになり、札を置く列が無い。雑談のセッションは仕事と別のモードの印で一覧も別になり（`listMarkedSessions` が同じモードだけを並べる）、前のセッションへは今と同じく切り替え画面から戻る。

### 論点 7: 後段2件の difficulty

**採る: 2件とも `sonnet` のまま。** この ADR が置き場・既定・件数・層・閉じ方・キー・畳んだ形をすべて決めたので、残る判断は前例（置かれる機能の切り出しは `features/run-setting/`、最上層の面は進み具合のプログレスバーの `Popover`、帯は今のやり取りの列）に倣って決められる。広がりは下の「送る順」に段ごとに書いた。

## 送る順

1件送るごとに画面が使える状態を保つ。

1. **一覧の行を置かれる機能へ移し、札の頭を切り替えにしてセッション側を描く。** 行の組み立て・短縮ID・使用中の取得を `features/session-switcher/` へ移し（`.dependency-cruiser.cjs` と地図に1つ足す）、切り替え画面と帯の札はそこから読む。札の頭を切り替えにし、セッション側（論点 3）・畳んだ帯と迎える場面の帯（論点 5）・選んだ側の store（論点 2）を足す。行を押すと選んだ印だけが付き、詳細はまだ開かない。→ 札でこの作業ツリーの今日・昨日のセッションが読め、末尾の口で切り替え画面が開く。
2. **詳細の部品と選びの芯を同じ機能へ移し、札の右隣に詳細を開く。** `SessionSwitcherDetail`・`DigestBody`・選びの芯・`use-session-digest.ts` を移し（始め方の一覧の読み先も替える）、切り替え画面はそこから読む。札の詳細を `Popover` で開き、閉じ方とキー（論点 4）を足す。→ 見本の B1 になる。

それぞれの段は、画面の仕様（`docs/architecture/display.md` 4.2・`docs/architecture/screen-design/layout.md` 13.4「やり取りの列」・`docs/architecture/screen-design/nav-room-and-switch.md`「切り替え画面」）と用語集（`docs/glossary/block.md`「やり取りの列」・`docs/glossary/session-and-plan.md`）のうち、自分の触った記述を実装と同じコミットで書き換える。

## 採らなかった案

- **案A 二段の札**: やり取りの札の下にセッションの札を足す。両方開くとやり取りの行が高さを分け合い、2026-11-17 に決めた「やり取り側の開いた形は今のまま」が崩れる。
- **案C セッションの木**: いまのセッションの下にやり取りを入れ子で開く。やり取りの開いた形が変わり、列の幅 232px では題が 9〜10字で切れる。
- **B2 流れの面を差し替える**: 広いが、今の材料（要約・残り・最後のひとこと）だけでは下半分が空き、「いまのセッションへ戻る」の口が1つ増える。
- **選んだ側を `localStorage` に覚える**: 論点 2 の理由で採らない。
- **詳細を札の中（`position: absolute`）に置く**: 札の `contain` と `backdrop-filter` の文脈で中央の列の上に重ならない（論点 4）。
- **「それより前」も札に出す**: 見本の案B は2群だけを出す。この作業ツリーの古い行まで並べると、札の高さの上限で転がる量が増え、切り替え画面との役割の差（近い作業か、全部か）が消える。

## この ADR が改訂するもの

- `docs/architecture/adr/0058-three-column-single-stream.md` の「利用者が決めたこと」の「セッションの選択（短縮IDの札 → 切り替えのダイアログ）…は今のまま」: 帯の札と切り替え画面は今のまま残し、左の列の札にセッション側と詳細の入口を足す（論点 1）。
- 同じ ADR の対応表「左の列」の「やり取りの列（行・見出しの一覧・畳む口・仕切り）」の行: 頭の行（「やり取り」と畳む口）を「やり取り n｜セッション n」の切り替えと畳む口に替え、セッション側と詳細のパネルを持つ（論点 3〜5）。
- 同じ ADR の論点 2 と論点 3 の「同じ情報を2か所に出さない」: セッションの一覧は札と切り替え画面の2か所に出る。理由と役割の分け方は論点 1。

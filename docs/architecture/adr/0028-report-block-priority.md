# レポートの塊は、内容の形で並べた1本の梯子を上から試して選ぶ（2026-10-12）

**塊の選び方を、内容の形で並べた1本の梯子にする。** 書き手は梯子の上の段から順に「この内容はその段の形を
持っているか」を見て、持っていればその段の塊で描き、持っていなければ1つ下の段へ落ちる。最上段は図
（画像 → `mermaid`・`graph` → SVG の順）で、**迷ったら上の段で描く。** 上の段の塊を使ったこと自体は
数えても差し戻さない（図を避けさせる仕組みを置かない）。SVG は逃げ道（`markdown` の塊の中の `<svg>`）から
新しい `svg` の塊に上げる。順位の違反は、まず使われ方の記録で数え、差し戻しにするかは数を見てから決める。

## 何が困っていたか

規約の条8（`src/server/report/core/report-notation.ts`）は、内容の型5つ（経路・流れ・層の構造／画面の見た目／
時間順のやり取り・状態／前後の数／候補の比較）に第一候補の塊を1つずつ挙げる表だけを持ち、**第一候補で
描けないとき・どの型にも当たらないときの落ち先を決めていない。** 当たらない内容（文書・手順の変更、
閾値のような設定の値の変更、複数の観点からの調べもの）は、暗黙の既定の `list`・`text` に落ちる。

2026-10-12 に測った直近28日（`node scripts/runtime/report-block-usage.ts --days 28`、受け付けた `report` 1663件）の
使用率と、各塊の `describe`（`src/shared/report/report-block.ts`）が言う「描ける条件」:

## 決めたこと

### 梯子（論点1）

**順位は塊の全体で1本で、段の条件は「内容がどんな形を持っているか」にする。** 内容の型（何の話か）で
分けると、型に当たらない内容の行（「その他」）が要り、そこがまた `list`・`text` になる。形（名前どうしの
つながり・時間の順・位置・数・同じ形の項目の並び）はどの内容にも問えるので、最後の段まで落ち先が決まる。

| 段            | 塊（上から試す順）                                      | その段の形                                                     |
| ------------- | ------------------------------------------------------- | -------------------------------------------------------------- |
| 1. 図         | `image` → `mermaid`・`graph` → `svg`                    | 撮った画像・つながり・時間の順・状態の移り変わり・位置と重なり |
| 2. 数の図     | `chart` → `stats` → `dimension`                         | 大小や傾きを見せる数・結論に効く数・積む寸法                   |
| 3. 揃えた並び | `options` → `compare` → `matrix` → `table`              | 採否・2つの見比べ・状態の対応・同じ形の項目                    |
| 4. 並び       | `list`（`label`・`flow`・`ordered`・`check`・`bullet`） | 項目が2つ以上                                                  |
| 5. 文         | `text`                                                  | 一息で言い切れる                                               |

- **前と後があるときは、選んだ段の塊を `beforeAfter` の側に入れる。** `beforeAfter` は段ではなく容れ物で、
  側には段1の図と `code`・`points` を置ける（`svg` の側を足す）。1つの値の前後は
  `table` のセルの `from` / `to` か `stats` の `before`
- **迷ったら上の段で描く。** 上の段の形を持っているかがはっきりしないときは、上の段の塊で描いてみる
- **梯子に乗らない役割の塊**: `note`（読み飛ばされると困る一文）・`files`（ファイルの一覧）・`code`
  （そのまま写すもの）・`progress`（段の位置）・`markdown`（引用・区切り線・2つ以上の塊を畳む）。
  中身の形ではなく役割で決まるので、梯子とは別に使う
- 文書・手順の変更は、手順に分岐・合流・戻りがあれば段1の `graph`、状態の移り変わりなら `mermaid` の
  `stateDiagram-v2`、どちらでもなく変わった点が2つ以上なら `beforeAfter`（側は `points`）、値1つなら
  `table` の `from` / `to` に落ちる

### 「描ける」の判定（論点2）

**段の条件は各塊の `describe` だけに書き、条8は梯子の並び（塊の名前と段の名前）だけを持つ。** 条件を
条8と `describe` の両方に書くと毎ターンの文脈に2回載り、片方だけ直すずれが起きる。条8の表の
「避ける書き方」の列と、条8の末尾の `beforeAfter` の但し書きは各塊の `describe` へ移す。

**条件は上の段を試す入口で、上の段を塞ぐ制限にしない。** 次の言い直しをする:

- `graph` の `describe` の「一本道なら `list` の `flow`」をやめ、**一本道でも段の名前が短ければ `graph`**
  にする。`list` の `flow` は、段ごとに文が要る一本道（`graph` のラベルに収まらない）に残す
- `mermaid` の `describe` には制限を足さない。9種のどれかで描ける内容は `mermaid` で描く
- `image` は「この作業で撮った画像がある」ときだけ段1の先頭に当たる（現行の条8の例外のまま）

### SVG（論点3）

**SVG は新しい `svg` の塊に上げ、座標つきの図形の並びで書く。** 書き手は SVG の文字列を書かず、
描画の側が図形から SVG を組む。色は書けない（`chart` と同じく、テーマの色を描画の側が当てる。2026-10-21 の改訂で `tone` の5値だけ書ける）。

```ts
{
  kind: "svg",
  title: string,
  width: number, height: number,       // viewBox の大きさ
  shapes: Array<
    | { kind: "rect", x, y, width, height, label: string, emphasis: boolean, tone: "none" | "a".."e" }
    | { kind: "line", x1, y1, x2, y2, arrow: boolean, label: string }
    | { kind: "text", x, y, text: string }
  >,
  legend: Array<{ tone: "a".."e", label: string }>,
  fold,
}
```

- 段の条件は「位置・重なりそのもの」（画面の領域の配置・重なり方）。つながりだけなら `graph`・`mermaid` で足り、
  `svg` は試さない（段1の並びの最後）
- 図形が `width` × `height` の外にはみ出すのは描き損じとして、`broken-mermaid` と同じく初めから差し戻す
  （順位の違反ではなく、描いた図が崩れる）
- **改訂（2026-10-21）: 「色は書けない」を `tone` の5値に改める。** 書けるのは色の名前でなく意味の目印
  `rect`・`line` の `tone`（`a`〜`e`。描く側が系列色 `--chart-series-1`〜`5` に当てる）と
  `line` の `dashed`（点線）だけで、色そのものは書き手が持たない。
  色だけで意味を言わない（`docs/research/report-block-craft.md` の C4）ので、`tone` を使う図は
  `legend`（`tone` と名前の並び）を必ず付け、`legend` に無い `tone` は差し戻す
- 逃げ道の `<svg>` は条8の記法の表から外す。記録の「塊の無い記法」の `svg` は残し、塊に上げたあとも
  書かれ続けるかを見る

### 画像（論点4）

**撮っていない作業では `image` を飛ばして同じ段の `mermaid`・`graph` へ落ちる。** 撮れる作業（描画を変えた
作業）で画像を必須にする線は tsukumo の core に引かない。「描画を変えた作業」はパスや拡張子で見分ける
ヒューリスティックになり、tsukumo が動かすほかのプロジェクトに当てはまらない。機械で見られる信号は
「**このターンにメインが画像のファイル（png・jpeg・gif・webp）を `Read` したのに `image` の塊が無い**」で、
これを記録に足して数える。委譲先が撮って受け入れ役が見た画像はメインの流れに見えないので、この信号は
メインが自分で撮った回だけを拾う。

### 機械で見る点と測り方（論点5）

**順位の違反は、まず記録で数え、差し戻しは数を見てから決める**（`docs/architecture/display/reading-time.md`「規則と置き場の
対応」の「書き手に強制したい規則」の行のとおり）。機械で見られるのは「上の段を見落として下の段へ落ちた」
信号のうち、塊の外から分かるものだけで、内容がつながりや時間の順を持っていたかは機械では分からない
（地の文から「まず…次に」を拾うのはヒューリスティックなので採らない）。そこは条8の文で誘導する。

数えるもの（記録の版を5に上げて足す）:

| 数                                                      | 何を見るか                                      |
| ------------------------------------------------------- | ----------------------------------------------- |
| 段1の図（`image`・`mermaid`・`graph`・`svg`）を含む割合 | 効き目。全レポートと `task` の最終レポートの2つ |
| 画像を `Read` したのに `image` が無い回                 | 画像の見落とし（論点4）                         |
| `modified` があるのに前後図も画像も無い回（既存）       | 変更の前後の見落とし                            |
| 塊の無い記法の `svg`（既存）                            | `svg` の塊に上げたあとも逃げ道に書かれるか      |
| `svg` のはみ出しの差し戻し                              | `svg` の塊の書きにくさ                          |

上の段の塊を条件を満たさずに使った回（名前2つの `graph` など）は数えない。数えると、それを減らす規則
（上の段を塞ぐ規則）を足す材料になり、「迷ったら上の段で描く」と逆を向く。

効き目は、条8を梯子に替えた日から28日の窓で「段1の図を含む割合」を、替える前の値（記録の全期間で10.3%、
`task` の最終レポートで18件中1件）と比べて見る。

## 採らなかった案

| 案                                                   | 採らなかった理由                                                                                               |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 内容の型ごとの表に落ち先の列を足す                   | 型に当たらない内容の「その他」の行が要り、そこが `list`・`text` に戻る。型ごとに同じ塊が何行も出て文面が膨らむ |
| いまの第一候補の表のまま様子を見る                   | 文書・手順の変更のような型に当たらない内容の落ち先が決まらないまま残る                                         |
| 段1を `mermaid`・`graph` → SVG → 画像の順にする      | 撮った画像があっても図を描き直すことになり、画面の変更で実物が出にくい                                         |
| SVG を逃げ道のまま梯子に載せる                       | 座標を書き手が SVG の文字列で書き、描き損じを検査する口が無い。利用者の判断で塊に上げる                        |
| 上の段の乱用（条件を満たさない図）を差し戻す・数える | 図を避けさせる向きに働き、上の段を先に試させる梯子の狙いと逆になる                                             |
| 描画を変えた作業で画像を必須にする                   | 描画を変えたかの判定がパス・拡張子のヒューリスティックになり、ほかのプロジェクトに当てはまらない               |

## 追記: 図を欄で必須にした（2026-10-13）

梯子の条8は選び方を言うだけで、図を使わない判断を書き手が黙って済ませられた（直近28日の `report` 1805件で、
段1の図を含むのは10.2%、`task` の最終レポートで20件中1件）。**`report` に必須の欄 `figure` を足し、図を1つ置くか、
置かない理由を enum（`short-answer`・`no-shape`・`single-value`・`no-material`）で言わせる。** 図を置く条件と最小の形は
欄の説明（`REPORT_FIGURE_DESCRIPTION`）に置き、条8の頭は欄を指す1行だけにする。

順位の違反は数えてから差し戻しを決める線は変えない。差し戻すのは理由と本文が食い違う回（`figure-contradiction`）だけで、
理由の分布は記録の版6（`figureKind`・`noneReason`）で数える。`modified` があるのに図の無い最終レポートを差し戻すかは、
その数を見てから決める。欄・描き方・記録の詳細は `docs/architecture/display.md`「出力の分離（セリフと詳細）」と「塊を足す・外す基準」が持つ。

## 追記: 画面のファイルの判定を外した（2026-10-17）

論点4の線（撮れる作業で画像を必須にする線を core に引かない）にいったん反して、画像の載せ忘れを仕組みで防ぐ
利用者決定で、ターンの頭から `src/browser/` の下のファイルが変わったのに `image`・`beforeAfter` の塊が無い `report` を
差し戻す判定（`no-screenshot`）を入れ、続けて `checks` の理由つきの `unverified` で抜ける逃げ道を足していた。
**この判定と差し戻しを、変更ファイルを読む口ごと外す。** 誘導は条8の文面（画面を変えた作業は撮った画像を
`image` で載せ、撮れないときは `unverified` に理由を書く）に残す。

- 差し戻しが画像を増やしていない（差し戻しのあとに画像が足された回は0。数と採らなかった案は
  `docs/history/decision.md`「adr/0028 追記 画面のファイルの判定を外した（数と採らなかった案）」）
- 判定が tsukumo 自身のディレクトリ構造の決め打ちで、tsukumo が動かすほかのプロジェクトでは効かず、
  `src/browser/` に画面でないファイルがあれば要らない差し戻しになる（論点4の理由がそのまま当たった）
- 「画面に出る変更か」は機械で決められず、条8の文面はプロジェクトに依らない形でそれを既に言っている

機械で見る信号は記録の「画像を `Read` したのに `image` が無い回」（`readImageWithoutImageBlock`）で、
差し戻さず数える（2026-10-20）。2,448 件中 7 件、5 件は `modified` 無しで読むだけの回を含みうる。

## 追記: 条8を形の札の表に替えた（2026-10-18）

**条8が持つ表を、梯子の並びから形の札の表に替える。** 書き手は節ごとに札（`shapeTag`。節が表す内容の形）を
先に決め、その札の第一候補の塊で描き、描けなければ許す代替を使い、許さない塊は使わない。表は
`src/shared/report/report-shape-tag.ts` の `REPORT_SHAPE_TAG_RULES` から組み、条8に手で同じ表を書かない
（札の中身は `docs/research/report-shape-tags.md`「5. 札の設計」）。

- 梯子の「上の段を先に試す」は、札ごとの第一候補が受ける。関係を描く札の第一候補は図で、上の段を先に勧める向きは変わらない
- 段の条件（描ける条件）は、これまでどおり各塊の `describe` に置く。条8は札と塊の名前・見本だけを持つ
- 「許さない」は下の段（`table`・`list`・`text`）だけを塞ぎ、上の段の乱用は数えない線を変えない
- 札が許さない塊を使った節は、まず使われ方の記録（版13）で数え、差し戻すかは数を見てから決める
  （`docs/architecture/display/block-criteria.md`）

## 追記: 差し戻しの条を全部、数えてから上げる（2026-10-25）

**「まず数え、差し戻すかは数を見てから決める」を、塊の優先順位から `report` の差し戻しの条の全部に広げる。**
条は足しては外すを繰り返していた（画面のファイルの判定は上の追記で外し、2026-10-24 に `browser-change-without-image` で入れ直した）。新しい条は `REPORT_REJECTION_MODES` に `count` で入れて記録の `kind: "counted"` の行で数え、
`reject` へ上げるときは数と日付を `docs/history/decision.md` に1行書く。既存の条は「導入時は数えていない」の1行で許す
（同「adr/0028 追記 差し戻しの条ごとの根拠」）。根拠の行の有無は文書の検査が見る。

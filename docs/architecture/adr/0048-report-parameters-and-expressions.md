# 触れるレポート: つまみの部品と、独自関数 `expr` の中置の式・名前つきの式で値を結ぶ（2026-11-05）

ステータス: 採用

**`report` に、読み手が値を振るつまみの部品 `ParameterSlider`・`ParameterCheckBox` と、値を式で計算する独自関数 `expr`・`format` を足す。式は中置の文字列で書き、eval を使わない構文解析器で評価する。同じ計算は `Report.defs` に名前つきの式として一度だけ書く。式の値を結べるのは、最初は `Stats`・`Paragraph`・`Chart` の決まった props だけにする。サーバは初期値で評価した静的な部品の一覧を作り、検査・記録の分類・会話の画面の外の見せ方はその一覧を読む。会話の画面だけが式を持つ一覧を描き、つまみを振るたびにブラウザで計算し直す。**
描画を tsukumo の部品とデザインのまま行うこと、計算を tsukumo が実装する関数の名前で呼ぶこと（A2UI の `{call, args}` の形）、中置の式と名前つきの式を入れること、振った値を記録に残さないことは、2026-11-05 に利用者が決めた。つまみの形・文の切り替え・結べる部品の範囲・画面の外の見せ方も同じ日に利用者と決めた。それ以外の論点（部品の名前・式の言語の範囲・数の丸め・構造の検査・差の向き・書き手への説明の分量・演出との兼ね合い）は、試作 `docs/research/report-function-prototype-2026-11-05/` を根拠にこの ADR が決める。

## 何が困っていたか

- ADR 0039 は、基本カタログの入力の部品（`Slider`・`CheckBox` など）と関数の呼び出しを書き手のスキーマから外し、動く値をリテラルと `{path}` に絞った。そのため、読み手が前提の値を振って図・数・文の変わり方を確かめるレポートを書けない。
- 試作の第1版（A2UI の `{call, args}` の入れ子だけ。`index.html`・`catalog.md`）は、宣言が 3181 字になり、同じ式を 4 回書き写した。最速の値を式で求められず、書き手はリテラルで埋めたので、式を変えると食い違う。
- 試作の第2版（`expr` に中置の式を渡し、`Report.defs` に名前つきの式を置く。`index-v2.html`・`catalog-v2.md`・`report-v2.js`）は、宣言が 1925 字で、式を 1 回だけ書き、最速の値も `argmin` で求めた。評価の誤りは 0 件で、`Chart`・`Table` の強調を式に結べた。
- 第2版の書き手が挙げた穴は 3 つ: `format` の `${…}` に文字を入れるとエスケープが重なる、`Stats` に強調が無い、数の丸めの決まりが説明から読めない。
- A2UI v0.9 の関数は名前で参照し、実装はクライアントのカタログが持つ（独自の関数は仕様の想定どおり）。基本カタログの関数（`node_modules/@a2ui/web_core/src/v0_9/schemas/catalogs/basic/catalog.json` の `functions`）は `required`・`regex`・`length`・`numeric`・`email`・`formatString`・`formatNumber`・`formatCurrency`・`formatDate`・`pluralize`・`openUrl`・`and`・`or`・`not` の 14 個で、算術は無い。名前つきの計算値は仕様に書かれていない。最も近い前例は Vega-Lite の params（`bind` で入力、`expr` で派生の値、中置の式の文字列）。

## 決めたこと

### 1. つまみの部品: `ParameterSlider`・`ParameterCheckBox`

- 数のつまみは `ParameterSlider`（`name`・`label`・`min`・`max`・`step`・`initial`）、真偽のつまみは `ParameterCheckBox`（`name`・`label`・`initial`）。形は第2版のまま（利用者の決定）。
- 名前を基本の `Slider`・`CheckBox` と分けるのは、基本の `Slider` が `label`・`min`・`max`・`value` だけで `step` を持たず（`unevaluatedProperties: false`）、ADR 0039 の論点 2 が「基本と同じ名前に基本と違う props を付けない」と決めているため。頭の `Parameter` は、式から名前で読む値（Vega-Lite の params と同じ意味）を置く部品だと語から読めるように付けた。
- `name` は式から読む名前で、英字か `_` で始まり英数字と `_` が続く。`defs` の名前・ほかのつまみの `name`・関数の名前・`true`・`false` と重ならない。
- `ParameterSlider` は `min < max`・`step > 0` で、`initial` は範囲の中で `min` から `step` の倍数の位置にある。目盛りの数（`(max - min) / step + 1`）は 101 以下。
- 置き場は内容部品と同じ（`Section` の子、配置の部品の子）。`Report.figure` には置けない。
- 振った値はデータモデルの `/view/<部品の ID>/value` に置く（ADR 0039 の論点 7 と同じ置き場の規則。書き手は path を書かない）。式は `name` で読み、tsukumo が `name` から部品の ID を引く。開き直すと初期値に戻り、`ReportEvent`・transcript・記録に載せない。

### 2. 値の形: `expr` と `format`

結べる props には、リテラルの代わりに次のどちらかを書ける。どちらも A2UI v0.9 の `FunctionCall`（`{call, args}`）の形で、関数の名前は基本カタログの 14 個と重ならない。

- `{ "call": "expr", "args": { "source": "<式>" } }`: 式の結果。
- `{ "call": "format", "args": { "template": "…${<名前か短い式>}…" } }`: 文字の中の `${…}` を式の結果で埋める。

文を条件で切り替えるときは、`defs` の式が文字を返す（`"mode": "e2e ? \"E2E を含めると\" : \"単体テストだけなら\""`）。`${…}` の中には名前か短い式だけを書かせ、文字のリテラル（`"`）を書いたら構造の検査で差し戻す（利用者の決定。第2版の書き手が挙げたエスケープの重なりを避ける）。

### 3. 名前つきの式: `Report.defs`

- `Report.defs` は名前 → 式（文字列）の対応。A2UI の仕様の外なので tsukumo の拡張とする（利用者の決定）。ほかの式からその名前で読める。
- 書き手への説明は「同じ計算を 2 か所以上で使うなら `defs` に名前を付けて一度だけ書く」。第1版で式を 4 回書き写したことへの答え。
- `defs` の名前は 20 個まで、式 1 つは 200 字まで。第2版の書き手は 8 個・最長 21 字で足りた。

### 4. 式の言語

- 値の型は数・文字・真偽と、それらの並び。入れ物（オブジェクト）は無い。
- 書けるもの: 名前（つまみの `name` と `defs` の名前）、数、`"文字"`、`true`・`false`、並び `[1, 2, 3]`、括弧。
- 演算子: `+ - * / %`、`< <= > >= == !=`、`&& || !`、`条件 ? A : B`。片方か両方が並びなら要素ごとに計算し、数は並びの長さに広げる。並び同士の長さが違えば評価の誤り。
- 関数は次の 13 個。第2版の 13 個から `zip`（`Table.rows` 用で、`Table` は最初の範囲に入らない）を外し、`fixed` を足した。

| 関数                           | 返すもの                                                                         |
| ------------------------------ | -------------------------------------------------------------------------------- |
| `range(from, to)`              | from から to までの整数の並び（101 個まで）                                      |
| `min(a, b)`・`max(a, b)`       | 小さいほう・大きいほう（要素ごと）                                               |
| `round(x, digits)`             | 四捨五入した数（digits は省くと 0）                                              |
| `fixed(x, digits)`             | 小数 digits 桁に揃えた文字（表示の桁を決めるとき）                               |
| `sum(list)`・`len(list)`       | 合計・長さ                                                                       |
| `minOf(list)`・`maxOf(list)`   | 並びの最小・最大                                                                 |
| `argmin(list)`・`argmax(list)` | 最小・最大の位置（0 始まり。同じ値が並ぶときは前のほう）                         |
| `at(list, i)`                  | i 番目の要素（範囲の外は評価の誤り）                                             |
| `text(list, suffix)`           | 数の並びを、下の丸めの決まりで文字の並びにする（`labels` 用。suffix は省くと空） |

- 構文解析器と評価器は `src/shared/report/` に純粋な関数として置き、サーバ（検査と初期値の評価）とブラウザ（振ったあとの評価）が同じものを使う。eval・`Function` は使わない。
- 評価は名前ごとに 1 回で、同じ評価の中では値を使い回す。並びの長さは 101 個まで（`range` の上限と同じ）。

### 5. 数の丸めと差の向き

- 数を文字にするとき（`format` の `${…}`、`Stats` の文字の欄に数を返す `expr`、`text`）は、整数はそのまま、それ以外は小数 1 桁に四捨五入し、末尾の 0 を落とす。桁を変えたいときは `fixed(x, digits)` で文字にしてから渡す。第2版の表示（`fmt`）と同じ決まりで、書き手への説明に 1 行で書く。
- `Chart` の `series[].values` は数のまま渡し、丸めは `Chart` の描画が今と同じに持つ。
- 差の向き（増えて良いか減って良いか）は、差を計算させない。`Stats` の `before` と `value` を両方結び、今ある `better` で向きを言うと、tsukumo が差と印を出す。第2版の「w = 1 との差」は、書き手が引き算の向きを決めて符号を付けていたが、`before`・`better` を使えば向きの決め方が 1 つになる。

### 6. 式の値を結べる props（最初の実装）

利用者の決定どおり `Stats`・`Paragraph`・`Chart` に絞る。`Table` などへ広げるのは使われ方を見てから、別に決める。

| 部品        | 結べる props                                        | 評価した値の形                                    |
| ----------- | --------------------------------------------------- | ------------------------------------------------- |
| `Paragraph` | `text`                                              | 文字                                              |
| `Stats`     | `items[].value`・`items[].before`・`items[].target` | 文字か数（数は 5 の丸めで文字にする）             |
| `Chart`     | `title`・`labels`・`series[].values`・`emphasis`    | 文字・文字の並び・有限の数の並び・`labels` の一部 |

- `Chart` の `emphasis` は今の意味（`labels` の一部の文字の並び）のまま結ぶ。式が文字 1 つを返したら 1 要素の並びとして読む。位置（数）で強調する第2版の形は採らない。今の `Chart` の強調と意味が 2 つに分かれるため。最速の点は `at(labelsの名前, argmin(...))` で書ける。
- `Stats` に強調（tone）の欄は足さない。`Stats` は `better`・`target` で達否の印を tsukumo が付ける仕組みを持っていて、`target` を結べば振った値で達否が変わる。別の色の欄を足すと、同じ項目の状態を言う欄が 2 つになる。
- ほかの部品と、ここに挙げない props はリテラルだけ（今のまま）。

### 7. 初期値で評価した一覧と、会話の画面の外

- サーバは受け口で、つまみを初期値に置いて式を全部評価し、式をリテラルに置き換えた「静的な一覧」を作る（`expr`・`format` を持たない、今の型どおりの部品の一覧）。つまみの部品は静的な一覧では「`label`: 初期値」の 1 行の `Paragraph` 相当として扱う。
- 今の検査（`ReportReview` の体裁の条・図の規則）・使われ方の記録の分類・Markdown 化・日記の材料・テキストの要約は、静的な一覧を読む（利用者の決定: 触れない場では初期値で評価した値を出す）。式を持つ部品のために今の規則を書き直さずに済む。
- `ReportEvent`・transcript・`SessionRecord` には、書き手が書いたままの一覧（式を持つ）を載せる。開き直し・復元は同じ評価器で初期値から描き直す。
- 使われ方の記録には、つまみの数と式を持つ props の数を足す。`Table` などへ広げるかを決める材料にする。

### 8. 構造の検査で差し戻すもの

受け口で、静的な一覧を作る前に生の一覧へ掛ける。エラー文は今と同じ `VALIDATION_FAILED` の形（落ちた欄を指す JSON Pointer と短い理由）。

| 検査       | 差し戻す形                                                                                                                                                                                             |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 式の構文   | 読めない字・括弧の閉じ忘れ・余った字。`${…}` の中の `"`                                                                                                                                                |
| 名前と関数 | 無い名前・無い関数・引数の数の違い。`expr`・`format` 以外の `call`                                                                                                                                     |
| `defs`     | 循環（`a → b → a`）。数と字数の上限                                                                                                                                                                    |
| つまみ     | `name` の重なり・予約語との重なり。`min`・`max`・`step`・`initial` の整合。どの式からも読まれないつまみ                                                                                                |
| 歯止め     | つまみが 4 個を超える。式があるのにつまみが 1 つも無い（動かない値は式で書かず、リテラルで書く）                                                                                                       |
| 評価       | 初期値と、つまみを 1 つずつ端（`min`・`max`、真偽は両方）に振った値で評価し、誤り・有限でない数・形の違い（6 の表）が出る。`Chart` の `labels` と `values` の長さが違う。`emphasis` が `labels` に無い |

- 評価を端の値まで掛けるのは、初期値だけでは 0 での割り算や範囲の外の `at` を拾えないため。つまみ 4 個で評価は最大 9 回（真偽は 2 通り）で、静的な一覧の検査より軽い。
- それでも組み合わせで出る誤り（2 つのつまみを同時に端へ振ったときだけ出る、など）は拾えない。会話の画面では、評価に誤りが出た値は「—」で描き、ほかの部品の計算は続ける。

### 9. 書き手への説明の分量と、使わせる依頼

- `report` ツールの説明には、つまみと値の形・式の書き方・関数の表・丸めの決まりを、第2版の `catalog-v2.md` の「値」「式の書き方」の節と同じ程度（約 1,500 字）で載せる。部品の props の説明はカタログの JSON Schema の `describe` に置く（ADR 0039 の未決 4 で、全部載せる形を維持すると決めた）。
- ツールの入力の schema は、値の形（`expr`・`format` かリテラル）を結べる props ごとに書き写さず、1 か所の定義を参照させる。増えた分だけ `REPORT_INPUT_SCHEMA_MAX_CHARS` を上げ、上げ幅は実装で測って書く。
- 使わせる依頼: 読み手が前提の値を振って結果の変わり方を比べたい問い（どの値がよいか・しきい値で何が変わるか・条件を足すとどうなるか）。説明にこの 1 文を書き、結論の文は初期値のまま読めるように書かせる。
- 使い過ぎの歯止めは、説明の文より機械の検査に置く（8 の「歯止め」: つまみは 4 個まで、つまみの無い式は差し戻す）。

### 10. 演出と草稿

- 書き上げの演出（`use-report-reveal`）はマウント時の DOM だけを見る（ADR 0039 の論点 4 (d)）。演出は初期値で評価した DOM に掛け、演出が終わるまでつまみは操作できない。振ったあとの計算し直しは、内容部品の中の文字と図を置き換えるだけで、演出を掛け直さない。
- 部品が閉じるたびの草稿（ADR 0040）では、つまみは操作できない。式を持つ部品は、その時点までに閉じた部品（`defs` とつまみ）で初期値の評価ができれば描き、できなければ描かずに待つ。

## 採らなかった案

| 案                                                             | 採らなかった理由                                                                                                                                      |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 書き手の HTML・JS を iframe で描く                             | 別のデザインが混ざる（利用者の決定）                                                                                                                  |
| A2UI の `{call, args}` の入れ子だけで計算を書く（第1版）       | 宣言が 3181 字になり、同じ式を 4 回書き写した。最速の値を式で求められずリテラルで埋め、式を変えると食い違う                                           |
| 基本の `Slider`・`CheckBox` を取り、`value` を `{path}` に結ぶ | 基本の `Slider` は `step` を持てず、`unevaluatedProperties: false` で足せない。基本と同じ名前に違う props を付けない決定（ADR 0039 の論点 2）に反する |
| つまみの値を `/params/<名前>` に置く                           | 操作の状態は `/view/<部品の ID>/…` に置く規則（ADR 0039 の論点 7）があり、置き場の規則が 2 つになる。式は `name` で読むので path を書き手に見せない   |
| `format` の `${…}` の中に条件と文字を書かせる                  | 第2版の書き手が挙げたとおり、JSON の文字の中の文字でエスケープが重なる。`defs` で文字を返せば済む（利用者の決定）                                     |
| `Chart`・`Table` の `emphasis` を位置（数）で結ぶ（第2版の形） | 今の `Chart.emphasis` は `labels` の一部で、意味が 2 つに分かれる                                                                                     |
| `Stats` に強調（tone）の欄を足す                               | `better`・`target` の達否の印と、同じ項目の状態を言う欄が 2 つになる。`target` を結べば振った値で印が変わる                                           |
| 差の向きを言う関数（`delta(a, b, "down")` など）を足す         | `Stats` の `before`・`better` が向きと差を持っている                                                                                                  |
| 式を eval・`Function` で評価する                               | 書き手の文字列をブラウザでコードとして走らせることになる。描画で書き手の JS を走らせない決定に反する                                                  |
| 会話の画面の外でもつまみを出す（日記・要約に操作の口を作る）   | 触れない場では初期値で評価した値を出す（利用者の決定）                                                                                                |
| 検査を初期値の評価だけにする                                   | 0 での割り算・範囲の外の `at` が、つまみを振ったときにだけ出る                                                                                        |
| 検査をつまみの全組み合わせで評価する                           | 目盛り 101 個のつまみ 4 個で 1 億通りを超える。端の値の評価で多くを拾い、残りは画面で「—」に倒す                                                      |

## 残すこと

- `Table`（`rows`・行の強調）など、`Stats`・`Paragraph`・`Chart` の外へ結べる props を広げるかは、使われ方の記録（7 の数）を見てから別に決める。広げるときに `zip` を足す。
- 組み合わせで出る評価の誤りが画面でどれだけ「—」になるかは、使われ方を見て、検査の掛け方を見直すかを決める。

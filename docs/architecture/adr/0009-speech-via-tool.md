# セリフはテキストの規約ではなく、ツール呼び出しで受け取る

セリフ（吹き出し）とレポート（メインビュー）の分離を、**出力スタイルの文章の規約**で表そうと
して**3回書き直した**:

1. 引用 `> `（2026-09-09）— TUI で左に縦線が付き、レポート内の普通の引用と区別が付かなくなった
2. 行頭マーカー `アスナ: `（2026-09-10）— 見た目がそのまま意味になるのは良かったが、
   「地の文の中でユーザーに語りかけている部分」が漏れた
3. 役割で決める条項の追加（同日）— **それでも揺れた**

不可視のマーカー（HTMLコメント・独自タグ）は TUI にそのまま表示されるので、そもそも使えない。
**規約は「守られたかどうか」がこちら側から分からない**のが根本で、条項を足しても揺れは減らない。

`speak(text, expression)` を tsukumo 側の MCP ツールとして提供すれば、**呼ばれた事実そのものが
分離**になる。引数に表情も入るので、状態ファイルを介さずに顔が決まる（`docs/requirements.md` 4.3）。

**戻り値は `"ok"` だけにする。** ツールの結果はモデルの文脈に戻るので、ここに情報を載せると
tsukumo からモデルへの逆流路ができてしまう。逆流させないことを戻り値の形で示す。

**2026-09-21 に、雑談の `recall` をこの線の外に置き、2026-09-25 に2段階（`recall` /
`recall_episode`）へ組み替えた。** 返すのは tsukumo の状態でも画面の事情でもなく、**アーカイブに
残っているその会話自身の過去**なので、ここで塞いでいる逆流路には当たらない
（`docs/architecture/chat-mode.md` 4.9「古い雑談は索引を引いて思い出す」に理由が3つ）。
**2026-09-23 に、`report`（当時は試行中、2026-09-24 に採用）もこの線の外に置いた**（ユーザー決定）。返すのは差し戻すときの
規約違反とその直し方だけで、画面の状態は載せない（`docs/architecture/display.md` 4.2）。広げたのはこの3つだけ
（2026-09-22 に `claim` / `finish` も外に置いたが、翌日 worktree の運用ごと撤去した）。

**2026-10-03 に、仕事の `speak` 自身もこの線の外に置いた**（ユーザー決定）。委譲の合図を待つあいだに
新しい事実の無いセリフが続いたのを、条ではなく仕組みで止めるため。返すのは新しい事実の無い呼び出しを
差し戻す固定の一文だけで、画面の状態は載せない（`docs/architecture/display.md` 4.2）。

**行頭マーカーは補助として残す**（環境変数で差し替え可能）。`speak` が呼ばれなかったターンで
吹き出しが空になると、キャラクターが消えたように見えるため。——**この補助は 2026-09-21 に
撤去した**（同梱のどの `persona.md` もマーカーを使えと書いておらず、発火していなかった。
空になる側は 2026-09-16 にプレースホルダーを出す形で解いた。`docs/architecture/display.md` 4.2）。

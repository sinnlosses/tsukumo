# プロジェクトの設定を無くし、Beads を前提にする（2026-10-08）

ステータス: 採用

**設定の置き場は環境変数と歯車の設定の2つになる。** 起動先の `.tsukumo/project.json`（プロジェクトの設定）と、
それを読む・書く口・画面・型は全部無くす。タスクの節と使い方の見直しの「タスクにする」は、
起動先の `.beads` が読めるか（`readBeadsWorkspace` が `found`）だけで決める。
`docs/architecture/adr/0022-three-setting-homes.md` を置き換える。

## 何が困っていたか

プロジェクトの設定が持つ値は `tasks.mainBranch`・`tasks.runPrompt`・`tasks: "off"` の3つで、どれも tsukumo が持つ理由が無くなった。

- **`runPrompt`（「tsukumo に頼む」の文面）**: どのスキルを呼ぶかはスキル側の責務で、tsukumo は特定のスキルに依存しない
  （`docs/architecture/adr/0024-no-skill-dependency.md`）。文面を選ぶ口を持つこと自体が、スキルの名前を tsukumo が知る入口になっていた
- **`mainBranch`（主ブランチ名）**: 成果が Beads の閉じた課題だけで数えるようになり、tsukumo は主ブランチを読まなくなった。
  残る読み手は、このリポジトリを開発する台本（`scripts/`）だけだった
- **`tasks: "off"`（タスク運用を使わない）**: Beads を前提にするので、タスクの節を出すかは `.beads` の有無で足りる。
  「使わない」と書く口と、設定が読めないときの「⚠ 読めない」の分岐が余計に残っていた

## 決めたこと

- **設定の置き場は2つ。** 起動のしかた・マシンに属する値は環境変数、利用者の好みは歯車の設定
  （持ち先は `state.json` か `localStorage`。`docs/architecture/screen-design.md`「13.6 設定の置き場所」）。
  リポジトリに属する値の置き場は作らない。値を足したくなったら、まず tsukumo がその値を持つ理由があるかを問う
  （ワークフローが自分で持つ値を見せて書く口は、下の「2026-10-14 の改訂」）
- **Beads は前提とする**（`docs/requirements.md` 2.3）。タスクの節・タスク一覧・おすすめ・使い方の見直しの「タスクにする」は、
  `.beads` が読めるかだけで出し分ける。`.beads` が無い起動先では、タスクの節ごと出さない（結果は `no-beads`）。
  `.beads` はあって `bd` が読めないときは節の中に「不明」を出す
- **「tsukumo に頼む」の文面は固定。** 「タスク {id} を進めて（bd show {id} で読める）。」で、保留のタスクには
  着手の前に判断を聞く旨を添える。文面を変える口は無い（着手の文面だけは「2026-10-24 の改訂」で口ができた）
- **このリポジトリを開発する台本の主ブランチは `scripts/shared/` の定数 `main`。** 推し量らない
- **`.beads` の有無は、変化の印を読む呼び出し（`bd where`）の結果から決める。** 見回りのたびに `bd` を起こす回数は増やさない

## 採らなかった案

- **`mainBranch` だけを残す**: 読み手が台本だけで、利用者の起動先の設定にする理由が無い。台本はこのリポジトリのためのものなので定数で足りる
- **`runPrompt` を環境変数や歯車の設定に移す**: 文面を選べること自体がスキルの名前を tsukumo が知る入口になる。固定のほうが読む人が把握しやすい
  （「文面を選ぶ」形は今も採らない。「2026-10-24 の改訂」は、利用者が書いたスキル名を送るだけの口で、この案とは別）
- **`tasks: "off"` を残して、`.beads` があっても節を隠せるようにする**: 隠したいだけなら画面に出さないだけで済み、書き込む口と
  確かめるダイアログまで持つ割に合わない

## 2026-10-14 の改訂

**リポジトリに属する値の置き場は今も作らない。ワークフローが持つ値は、ワークフローの口を通して歯車から見せて書く。**
同梱の `tsukumo-plugins` は流れ（`flow`）と各段のパーツ（`parts.<枠>`）を、自分の設定ファイル `.tw/config.toml` に持つ。
作者はこれを tsukumo の画面から選びたい（2026-10-14）。
流れと枠の欄をスキルの並びに置き換える話は `docs/architecture/adr/0030-workflow-as-skill-sequence.md` が引き取る（値の持ち主がワークフローであることは変わらない）。

- **値の持ち主はワークフロー。** 値は `.tw/config.toml` に置いたままで、tsukumo は写しも覚えた値も持たない。
  歯車の「ワークフロー」の面は、ワークフローの設定コマンド（`tw config --schema` で欄の形を受け、`tw config set` で書く。
  `docs/architecture/workflow-contract.md`「設定コマンド」）を呼ぶだけ。置き場が環境変数と歯車の2つであることは変わらない
- **どのリポジトリの値かを面で言う。** 歯車のほかの値は「この利用者がどこで開いても同じ好み」で、この面だけがリポジトリに属する。
  面の見出しの下に作業ツリー名と `.tw/config.toml` の絶対パスを出す。ナビに「このリポジトリ」の群は作らず、項目を1つ足すだけにする（2026-10-14 利用者決定）
- **口が無いときは欄を出さない。** `tw` が無い・設定コマンドを持たない・`.tw/config.toml` が無いときは、ナビの項目を残し、面で何が無いかを言う（`docs/requirements.md` 2.3）
- **採らなかった案**:
  - **tsukumo の置き場（`state.json` や `.tsukumo/`）に写して持つ**: 2つの置き場で値が食い違い、素の Claude Code で走るワークフローには効かない
  - **「このリポジトリ」の群をナビに作る**: 群に入るのがこの1項目だけで、見出しでリポジトリを言えば足りる

## 2026-10-24 の改訂

**着手の文面に限り、歯車の設定で起動するスキルを書けるようにする。** 「文面を変える口は無い」を改める。

- **tsukumo はスキル名を持たない。** 既定値も名前の一覧も無く、保存した文字列に「/」を付けて「/スキル名 {id}」として送るだけ。
  入力欄に `/next-task` と打って送るのと同じ経路（`session.prompt`）で届くので、ADR 0024（特定のスキルに依存しない）とは両立する。
  上の「スキルの名前を tsukumo が知る入口になる」という懸念は、tsukumo が名前を知らず、受け渡すだけの形にして避ける
- **対象は着手（`start`）だけ。** 計画・却下の文面は固定のまま。設定が空・未設定なら、いまの固定の文面（保留に添える旨も同じ）
- **値は利用者の好みなので歯車の設定に置き、持ち先は `localStorage`。** 先頭の `/` と前後の空白は畳み、英数字・`-`・`_`・`:` 以外を含む値は
  未設定として扱う（`requestPromptOf` が持つ）
- **起動スキルは、`tw config --entries` が返す入口のスキルから選ぶ。** 歯車の欄は自由入力でなくプルダウンで、先頭は「未設定」（値は空文字）。
  `tw` が frontmatter の `metadata` の `workflow-entry: "true"` を読んで一覧を返し、tsukumo は SKILL.md を読まない。
  名前の一覧を持つ役が `tw` に移るだけで、tsukumo は画面に出して選ばれた名前を保存して送るだけなので、ADR 0024 と両立する。
  保存済みの名前が一覧に無いときは「（一覧に無い）」を添えて残し、`tw` が無い・古い・読めないときは「未設定」だけを出す
- **採らなかった案の「歯車の設定に移す」を一部改める。** 文面そのものを選ぶ形（複数の文面から選ぶ・文面を丸ごと書く）は今も採らない

**2026-10-24 時点の実物は4つ**（上の「2つ」は 2026-10-08 の決定時の数）。環境変数（`TSUKUMO_*`。起動のしかた）、`~/.tsukumo/state.json`（歯車の既定値）、ブラウザの `localStorage`（見た目・演出・入力欄の下書きなど）、`.tw/config.toml`（ワークフローの値で、tsukumo は持たない）。持ち主で置き場を分ける判断は変えず、4つの一覧と持ち主の表の正典は `docs/readme/configuration.md`「設定の置き場」。

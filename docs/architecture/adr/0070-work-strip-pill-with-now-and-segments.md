# 進み具合のプログレスバーに、いまの手順と目安の残りをまとめ、下線を進み具合にする（2026-11-18）

ステータス: 採用

**広い画面の進み具合のプログレスバー（`WorkStrip`）を、中央の列の上端の1本のピルにする。ピルの1行は「状態の印・見出し（今のフェーズの名前か状態の語）｜いまの手順の一文と秒 … 位置・目安の残り・『手順』」を言い、ピルの下線はフェーズの数で等分した区間の並びで進み具合を言う。働くあいだは、今の区間の中を線が始端から終端まで伸びては始端に戻る。区間を押すとそのフェーズの詳細、「手順」を押すと全体の詳細がピルの下に重なって出て、外を押すか Esc で閉じる。会話の流れの末尾のいまの行（`NowLine`）は広い画面から無くす。この ADR は ADR 0059 論点 1・2・3・7 と ADR 0062 論点 2・3・13 の帯といまの行に関わる部分を改める。**

この ADR が決めるのは、広い画面の帯といまの行の置き場・中身・動き・詳細の開き方・タブの題まで。寸法と色の値は見本と器・トークンの ADR が持つ。`report`・`work_plan`・`phase_result` の入力に欄は足さない。狭い画面（760px 以下）は今のまま変えない。

## 何が困っていたか

- 走っている手順（いまの行）が流れの末尾、入力欄と最新のセリフのあいだに挟まり、見栄えが悪い（利用者の指摘、2026-11-18）。
- 今のフェーズは上端の帯、走っている手順は下端のいまの行と離れていて、目が上下を往復する。
- 帯は番号つきの丸・群の名（前・本・後）・「✓n」・「あと n」を並べ、フェーズが多いと丸が幅を取り、群をまたいだ数と群の中の番号が隣で食い違う（見本 `docs/history/mockup/now-progress-2026-11-18/compare.html#many`）。
- 3案（帯・入力欄の頭・立ち絵の手元）・計画の一覧に育てる案・案A の畳み方は、どれも「デザイン性が悪い」とされた。利用者は今までの決まりと工数を外して、待つ人が満足する出し方を求めた。

## 利用者が決めたこと（2026-11-18）

- 新案のステータスピル（見本 `docs/history/mockup/now-progress-2026-11-18/index.html?form=e`、説明 `island.html`）を、上端に置く形で採る。入力欄の真上に置く形（`?place=dock`）は採らない。
- 完了で緑になるのはチェックの印だけで、下線は差し色のまま。
- 「いつもより長い」の添え書きは冗長なので出さない。
- 働くあいだ、今のフェーズの区間の中を線が始端から終端まで進み、また始端に戻る。
- 下線を押すとそのフェーズの詳細が出て、詳細の外を押すと閉じる。
- 右端の「手順」を押すと全体の詳細が出て、詳細の外を押すと閉じる。
- 言葉と見本が食い違ったら見本が勝つ（「見本と違う決定」の節に挙げたものを除く）。

## 決めたこと

### 論点 1: 置き場と1行の中身

**採る: ピルは中央の列の上端の頭（`TurnCardHead`）に置き、左右の端を入力欄にそろえる。1行は左から、状態の印・見出し・縦線・いまの手順の一文と秒、右端に寄せて位置・目安の残り・「手順」。流れはピルの下に潜るところをぼかす。**

- 広い画面で読む幅の上限（ADR 0062 論点 13 の縁を含めて 976px）と左寄せは変えない。
- 見出しは縮めない。幅が足りないときは、位置の数と委譲先の添え書きから譲り、次に目安の残りを譲る。対象の字は頭から「…」で縮め、最後の語（ファイル名・コマンドの最後の語）を残す。
- 経過（依頼全体）は1行から外し、全体の詳細の下端へ移す（論点 8）。
- 開いた詳細は重ねて出すので、頭の高さは開閉で変わらない。
- 該当する見本: `index.html?form=e&moment=work`、`island.html#anatomy`。

### 論点 2: いまの手順の一文

> 道具の手順の文は、利用者の決定で対象だけに改めた（2026-11-18）。「を」と動詞（「を読んでいます」「を走らせています」など）は、等幅の対象（パス・コマンド）だけで何をしているかが読めて冗長なので付けない。表に無い道具は道具の名前だけ。対象が引けない道具の手順・道具でない状態（「考えています」「レポートを書いています」）・委譲（「実装役に任せています」）・再試行中・ワークフロースクリプトの段の題は、下の決定のまま動詞で言う。手順の替わり目は道具の名前と対象で見分ける。

**採る: ピルの一文は、いまの行の文（ADR 0062 論点 3 の表の「状態・道具 → 動詞・対象」）を「対象 を 動詞」の語順の敬体で言い、手順の秒を添える（「sort-order.ts を書き換えています 18秒」）。流れの末尾のいまの行は、広い画面では描かない。**

- 動詞は表の語の末尾「いる」を「います」にする（「書き換えています」「考えています」）。委譲は「実装役に任せています」のように役を「に」で受ける。対象が無い状態は動詞だけ。
- 一文は、ターンが走っているあいだはいつも出す。最終レポートに入れ替わったあとの続きのターンも同じ（今はいまの行が出ず、回る印が画面のどこにも無い）。
- 長く掛かっているときの添え書き（「長く掛かっている」と回る印を遅くすること。`LONG_RUNNING_SECONDS`）はやめる。秒がそのまま長さを言う。
- 回る印（`Spinner`）は置かない。働いている印は論点 4 の今の区間の線が持つ。
- 再試行中の文（ADR 0062 論点 10）・背景の「背景で」・ワークフロースクリプトの段の題は、今の選び方（`nowLineStatementOf`）のまま一文に載せる。
- 手順が替わると、古い文が上へ抜けて新しい文が下から入る（0.32 秒）。秒は一文と同じ枠に入れ、一緒に入れ替える。
- 該当する見本: `index.html?form=e&moment=work&live=1`。

### 論点 3: 状態ごとの印と見出し

> 状態の語「背景で作業中」と一文の頭の「背景で」は、伝わりにくいという利用者の指摘で「バックグラウンドで作業中」「バックグラウンドで」に改めた（2026-11-18）。下の表は決定時の語のまま残す。

**採る: 状態は、状態の印と見出しの語で言う。形は変えない。**

| 状態         | 状態の印     | 見出し                         | 一文                       |
| ------------ | ------------ | ------------------------------ | -------------------------- |
| 作業中       | 差し色の点   | 今のフェーズの名前             | いまの手順と秒             |
| 背景で作業中 | 差し色の点   | 今のフェーズの名前             | 「背景で」の文と秒         |
| 答え待ち     | 琥珀の点     | 「返事を待っています」（琥珀） | 「質問 n件」               |
| 止めた       | 灰の四角     | 「止めました」                 | 「〈今のフェーズ〉の途中」 |
| 失敗         | 赤の ✕       | 「失敗しました」               | 失敗の理由の語             |
| 完了         | 緑のチェック | 「できました」                 | なし                       |

- 状態の印は 16px の箱に収め、状態が替わっても見出しの位置を動かさない。印は動かさない。
- 緑はチェックの印だけに使い、下線は完了でも差し色のまま（論点 4）。
- 答えるボタンは質問の札にだけ置き、ピルには置かない。止めたときの「続きを頼む」も、流れの止めた表示（ADR 0062 論点 10）が持つのでピルには置かない。
- ワークプランの無いターンは、見出しを「作業中」にし、下線は1つの区間（今の区間）にし、位置と目安の残りを出さない。
- 該当する見本: `island.html#moments`。

### 論点 4: 下線

> 今の区間の線の動きは、利用者の決定で `steps()` の間引きをやめ、`linear` で滑らかに動かす形に改めた（2026-11-18）。見た目を描画の負荷より優先する決定で、ADR 0058 論点 9 の「ぼかしの面で無限に動かすなら `steps()`」の例外になる。`steps(24)` のときの実測は、ぼかしを外した版に比べて GPU が約 2.6 倍だった。
>
> 今の区間の線は、利用者の決定でバックグラウンドで作業中のあいだも伸ばし続ける形に改めた（2026-11-18）。決定時は作業中だけが動き、バックグラウンドタスクだけが残るあいだは線が止まって、進んでいないように見えていた。

**採る: 下線はフェーズの数で等分した区間の並び。済んだ区間は差し色、今の区間は太く、まだの区間は白の薄塗り。ページが隠れていたあいだに済んだ区間は濃い差し色で残す。働くあいだは、今の区間の中を線が始端から終端まで伸び、消えてまた始端から伸びる（2.4 秒で1周）。**

- 区間の数はワークプランの要素の数。並列のフェーズの配列は1つの区間に数える（`work_plan` の `current` と同じ）。委譲の範囲の数が未定のあいだは、範囲を1つの区間に数える。
- 答え待ちの今の区間は琥珀で止まる。止めた・失敗の今の区間は縁だけを残す。完了は全部の区間が済んだ色。
- フェーズが済むと、その区間が一瞬白く光ってから済んだ色に落ち着く。
- 今の区間の線は `transform` だけを動かし、ADR 0058 論点 9（ぼかしの面で無限に動かすなら `steps()`）に従って `steps()` で間引く。描画の負荷は実装のときに測る。
- 動きを減らす設定では、今の区間の線を半分まで伸びた形で止め、着地の光と一文の入れ替えを止める。
- 群の名（前・本・後）・番号つきの丸・「✓n」のまとめ・「あと n」は帯から外す。
- 該当する見本: `index.html?form=e&many=window&at=7`、`island.html#many`。

### 論点 5: 位置の数

**採る: ピルの位置は通し番号「今/全体」（「2/4」）で言う。群ごとの番号は、フェーズの詳細の見出しに添える（委譲の範囲の中のフェーズなら「本 2」）。**

- セリフが委譲先の番号で「フェーズ2が済んだ」と言うときに、詳細で照らせる。
- 「位置の字は出さない」（`docs/architecture/screen-design/work-strip.md` の1行目の項）は改める。

### 論点 6: 目安の残り

**採る: 同じ依頼の中で済んだフェーズの所要の最短と最長から、残りの幅を「あと 3〜5分」で言う。済んだフェーズが無い・範囲の数が未定・答え待ち・止めた・失敗・完了のあいだは出さない。**

- 残りのフェーズの数（今のフェーズを含む）を n、済んだフェーズの所要の最短を a・最長を b、今のフェーズの経過を t として、下の端は n×a−t、上の端は n×b−t を分に切り上げる。下の端は 1 分を下回らせず、上の端は下の端より 1 分以上大きくする。
- フェーズの所要は今の求め方（`phaseDurationOf`）を使う。セッションをまたいだ記録は使わない（今は持っていない）。
- 値は分が替わるときとフェーズが替わるときだけ書き直し、秒ごとには揺らさない。
- 「済んだフェーズの所要から出した目安」であることは、全体の詳細の下端の字に添える。
- ADR 0059・ADR 0062 が後回しにした「見込みの時間」をこの論点で解く。

### 論点 7: フェーズの詳細

**採る: 下線の区間はそれぞれボタンで、押すと押した区間の下にそのフェーズの詳細が重なって出る。済んだフェーズはまとめ（`phaseSummary`）と手順、今のフェーズは走っている手順と直前の手順、まだのフェーズは名前と「これから」。外を押す・Esc・同じ区間をもう一度押すと閉じる。**

- 押せる高さは線の上下に広げ、隣の区間と隙間なく並べる。読み上げの名前は「フェーズ 2/4 名前（いま）」。
- 詳細の見出しは、状態の印・名前・「2/4 · 済み · 48秒」。委譲の範囲の中なら論点 5 の群の番号を添える。
- 開いているあいだも、ピルの1行は替えない。
- 該当する見本: `index.html?form=e&phase=1`・`&phase=2`、`island.html#detail`。

### 論点 8: 全体の詳細（「手順」）

**採る: ピルの右端の「手順」を押すと、ピルの右端にそろえて全体の詳細が重なって出る。中身は今の「手順」の一覧（ADR 0059 論点 3）を引き継ぎ、済んだフェーズにまとめを1〜2行で添える。下端に依頼全体の経過と目安の残りを置く。外を押す・Esc・「手順」をもう一度押すと閉じる。**

- 済んだフェーズが3つ以上なら「済んだ n フェーズ」の1行に畳み、押すと開く。まだのフェーズは3つまで見せ、残りは「ほか n フェーズ」と数で言う。完了したら畳まずに全フェーズを所要つきで並べる。
- 今のフェーズの行の中に走っている手順と直前の手順を並べ、全部は「手順 n件をすべて見る」で同じ面の中に開く。
- 失敗の表示の「失敗した手順を見る」と、別の場所から特定のフェーズの位置で開く操作（今の `openAtFailure`・`openAtPhase`）は、全体の詳細を開いてその行を見せる。
- 所要時間の帯（ADR 0059 論点 3）は、完了したときの全体の詳細の末尾に残す。
- 開いた面は帯の下に重ね、流れを押し下げない（今は帯の下で本文を押し下げている）。
- 「外を押しても閉じない」（`work-strip.md` の「手順」の項）は改める。
- 該当する見本: `index.html?form=e&open=steps`、`island.html#detail`。

### 論点 9: 開閉の仕組み

**採る: 2種類の詳細の開閉は、既存の `usePopover`（外での `pointerdown` と Esc で閉じ、開いている重なりを登録し、Esc で口へフォーカスを戻す）に載せる。同時に開くのは1つだけで、片方を開くともう片方は閉じる。ネイティブの Popover API には移さない。**

- 入力欄のフォーカス寄せ（`isOverlayOpen`）が開いている重なりを知る経路を、今の部品と同じ1つに保つ。
- 開閉の印は ADR 0062 論点 9 の山形の1種で、「手順」が開いているあいだは上を向く。

### 論点 10: タブの題

**採る: 作業中は、題の頭の状態の印（ADR 0059 論点 7）の後ろに位置と今のフェーズの名前を足す（「… 2/4 保存の仕組みを足す」）。答え待ち・失敗・完了・止めたの印と語は今のまま。**

- 別のタブにいても、位置とフェーズが題で読める。ワークプランの無いターンは今のまま印だけ。

### 論点 11: 狭い画面

**採る: 760px 以下は今のまま（帯は出さず、画面の頭の2行と本文の「いまのフェーズ」が言う）。**

## 採らなかった案

| 案                                                                   | 物差し                                                                                                 | 判定     |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | -------- |
| ピルを入力欄の真上に置く（`?place=dock`）                            | 最新のセリフとの距離は近いが、セリフと入力欄のあいだに挟まり、最初の課題が残る。利用者が上端を採った   | 採らない |
| 下線の今の区間を光が流れる                                           | 静止画で今の区間が読めない（設計レビューの指摘）。利用者は区間の中を線が伸びる形を指定した             | 採らない |
| 状態の印から輪が広がって働いている印にする                           | 今の区間の線と動きが2つになる。働いている印は1つで足りる                                               | 採らない |
| 「手順」で同じ面が下へ伸びて計画の一覧になる（外を押しても閉じない） | 利用者は外を押すと閉じる重なりを指定した                                                               | 採らない |
| 群の名と群ごとの番号を帯に残す                                       | 丸の並びが幅を取り、群をまたいだ数と群の中の番号が隣で食い違う。番号はフェーズの詳細で照らせれば足りる | 採らない |
| ネイティブの Popover API で詳細を最上層に出す                        | 外を押すと閉じるは同じだが、開いている重なりを入力欄のフォーカス寄せへ知らせる経路が2つになる          | 採らない |

## 見本と違う決定

- 見本の止めた場面の「続きを頼む」はピルに置かない（論点 3）。流れの止めた表示が同じ操作を持つ。
- 見本は失敗の場面を持たない。失敗の印と見出しは論点 3 の表で決める。
- 見本の全体の詳細の「手順 n件をすべて見る」は押しても何もしない。実装では同じ面の中に開く（論点 8）。
- 見本の詳細はネイティブの Popover API で出している。実装は `usePopover` に載せる（論点 9）。

## 送る順

1. ピルの1行（論点 1・3）と、いまの手順の一文を帯へ移していまの行を外す（論点 2）。
2. 下線の区間と今の区間の線（論点 4・5）。
3. フェーズの詳細（論点 7・9）と、全体の詳細（論点 8・9）。
4. 目安の残り（論点 6）とタブの題（論点 10）。

# 既存の塊で描けない図は、任意の同梱プラグインのスキルが撮った PNG を `image` の塊で載せる（2026-10-26）

**本体には図を撮る手順も口も足さない。** `plugins/tsukumo-figure`（スキル `figure-capture`。図の構造を JSON で書くと
配色と配置を決めて HTML にし、図の部分を PNG に撮る）を tsukumo が任意で載せ、そのスキルが撮った PNG を、既にある
`image` の塊で `report` に載せる。いつ呼ぶかはスキルの `description` が言い、本体（core）はスキルの名前を知らない。

## 何が困っていたか

図のプラグインを任意で載せることにしたが、どの場面で呼び、撮った PNG を `report` にどう載せるかを決めた文書が無かった。
ADR 0032 は自由な HTML の口を持たないと決め、案 A（画像に撮って `image` の塊で載せる）の手順の決まりも本体に足さないとした。
ADR 0034 は図を「書き手が構造だけを書き、tsukumo が描く」とした。図のスキルは案 A に当たるので、0032 と両立するかを確かめる必要があった。

## 確かめたこと（2026-10-26）

画面の画像でない PNG（スキルが撮った図）を、`report` が拒まないかを読んで確かめた。拒まない。

- 読む口 `src/server/report/adapter/report-image-file.ts:61-86` が見るのは、拡張子（`.png` など）・先頭の印・普通のファイルか・
  `MAX_REPORT_IMAGE_BYTES`（5 MiB）以下か・`notModifiedAfter` より後に更新されていないか、だけ。写っているものが画面かは見ない
- 棚 `src/server/report/core/report-image-shelf.ts:78-93` は、読めて寸法を測れた画像を置くだけ
- `image` の塊に掛かる違反規則は無い。画像に関わる規則は、`beforeAfter` の `region` の範囲（`region-range`。`report-block-rule.ts:67-79`）と、
  `src/browser/` の `.tsx`・`.css` を変えたのに画像が無い `browser-change-without-image`（`report-violation-check.ts:201-227`。画像が1枚でもあれば通る）の2つ
- `image` の塊の引数は `path`・`caption`・`notes`・`fold`・`aside`（`src/shared/report/report-block-diagram.ts:154-170`）で、画面を撮ったかを問う欄が無い

## 決めたこと

### 0032 の案 A との関係

0032 が採らなかったのは、案 A を**本体の手順の決まり**として足すことだった。ここで足すのは本体の外の任意のプラグインで、
本体は `image` の塊を今のまま使うだけなので、0032 の「自由な HTML の口は持たない」と両立する。0032 が案 A を外した理由
（縦に長い1枚は高さの上限で縮む・タブやズームが消える）は、使いどころを絞って避ける。

### 使いどころ

- 既存の塊（`graph`・`mermaid`・`timeline`・`chart`）で描けない型（量の流れのサンキーなど）に限る
- 横長で、節点が1列に8以内の図だけ。縦長の図と、節点が1列に8を超える図は文章と表にする（0032 の測定で、縦に長い1枚は読めなかった）
- 触って読む成果物（操作が要るもの）は対象外。それは 0032 の (B) の見直しの話で、ここでは扱わない

### 載せ方

- 撮った PNG は既存の `image` の塊で載せる。本体に新しい塊・手順・口は足さない
- `report` ツールの `image` の塊の説明は、特定の道具の名前（d2）を持たず、「別の道具で描いた図の PNG を渡してよい」と道具に依らない言い方にする。節の説明には足さない
  （塊の説明の1文で足りる。スキルを呼ぶ判断はスキルの `description` が持つ）

## 採らなかった案

| 案                                                  | 採らなかった理由                                                                                                            |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 本体に図を撮る口・手順・塊を足す                    | 0032 が案 A の手順の決まりを本体に足さないとした判断を変えることになる。`image` の塊が既に PNG を受けるので、足す理由が無い |
| 全ての図をスキルにする                              | 既存の塊で描ける図まで画像になり、本文の塊の描き分け・畳み・暗い面が効かなくなる。ADR 0034 の「tsukumo が描く」からも外れる |
| `report` ツールの説明にスキルの名前を書いて呼ばせる | core がスキルに依存する。スキルを載せない環境で、説明が存在しないスキルを指す                                               |

## 見直す条件

- 縦長・節点が多い図の依頼が繰り返し出て、画像に撮る道でしか応えられない
- 画面の画像でない PNG を拒む規則を `report` に足すことになった（上の確かめの前提が崩れる）

## 結果

- 本体の変更は `image` の塊の説明の1文の言い換えだけ
- スキル側の文書（`description`・使いどころ）は tsukumo-plugins の `tsukumo-figure` が持つ

# モデルが自由に書いた HTML を、レポートに載せる口は持たない（2026-10-23）

**自由な HTML の別の口は持たず、見本の質には塊と欄を強くして近づける（(C)）。** 比べたのは3つで、
(A) 外のファイルを画像に撮って `image` の塊で載せる、(B) `report` に `html` の塊を足して `iframe sandbox` で見せる、
(C) 採らずに塊と欄を強くする。(B) の仕様の下書きは、見直すときの出発点として残す。

## 何が困っていたか

「HTML にして」と頼むと、モデルはタブ・リンク・ボタン・色・配置を全部持つ1枚の HTML を書ける（見本は利用者が
2026-10-21 に示したアーキテクチャ図の1枚）。今の `report` は決まった部品の塊でしか描かず
（`docs/architecture/adr/0028-report-block-priority.md`）、モデルが本文に書いた HTML のスクリプト・スタイルは
`sanitize-schema.ts` の `REPORT_SANITIZE_SCHEMA` が落とす。HTML のファイルをブラウザのタブで開く口も無い
（`hostContract.openFile` はエディタで開く口）。1枚の HTML は塊の外にある。

## 試しの測定（2026-10-23）

同じ依頼（このリポジトリの3層と機能の辺を図にして1枚の HTML にする。外のネットワークは読まない）を、素の HTML と
archify スキル（`~/.claude/skills/archify`）で2回ずつ書いた。4回とも同じ日・同じ書き手の繰り返しで、日をまたぐ
ばらつきは測っていない。画は headless Chrome（`scripts/capture/capture-view.ts` と同じ playwright-core）で撮り、目で見た。

| 回          |  所要 | 書き手が出した量                          | できたファイル | 見えたこと                                                               |
| ----------- | ----: | ----------------------------------------- | -------------: | ------------------------------------------------------------------------ |
| 素の HTML 1 |  45秒 | HTML 10.5 KB                              |        10.5 KB | タブ3枚・ボタン・凡例。崩れなし                                          |
| 素の HTML 2 |  41秒 | HTML 10.0 KB                              |        10.0 KB | 目次のリンク・手書きの SVG・カード。崩れなし                             |
| archify 1   |  81秒 | JSON 4.1 KB（ほかに手引き約24 KB を読む） |         821 KB | 7ノードで交差なし。辺の札は 8px ほどで小さい。操作の部品の字は英語のまま |
| archify 2   | 121秒 | JSON 6.1 KB（直し1回）                    |         839 KB | 15ノード・23辺で線が絡み、読めない（自動の検査は通る）                   |

- **素の HTML は2回とも明るい面だけ**で書かれ、`prefers-color-scheme: dark` でも明るいまま。暗い会話画面の中では白い板が浮く。
  archify は暗い面に切り替わる
- **スクリプトを止めると**、素の HTML 1 はタブが切り替わらず最初のタブしか読めない。素の HTML 2 は全部読める。
  archify は図とカードは出るが、ノードの一覧とズームが消える
- **archify の `finalize` は自分の更新の有無を外のネットワークへ確かめに行く**（受領に `update.source: "network"`）。
  できた HTML が開くときの外への要求は4枚とも0件
- **(A) を撮って載せた**: `image` の塊は高さの上限（1440x900 の窓で 343px、1920x1080 で 425px）で縮むので、
  縦に長い1枚はどれも字が読めない。図の部分だけを横長に撮っても、読めるのはノード名まで（辺の札・補足の行は読めない）。
  押して開く拡大の画面なら辺の札まで読めるが、画に写った Export・ズームなどの部品は押せそうに見えて効かない

## (B) の仕様の下書き

### 塊の形と `image` との切り分け

- 塊は `{ kind: "html", path, caption, fold, aside }`。`path` は作業ディレクトリのファイル（`.html` のみ）を指し、
  本文に HTML の文字列を書かせない（`report` の引数の字数を食わず、本文のサニタイズの外に置ける）
- **`image` は「見た結果」を載せる塊、`html` は「触って読む成果物」を載せる塊**と分ける。画面を撮った・図を描いた
  画像は今までどおり `image`。タブ・畳み・ズームなど、触らないと読めない1枚だけを `html` にする。梯子
  （ADR 0028）の段には入れず、利用者が「HTML にして」と頼んだときの塊にする
- 読み込みは `image` と同じ形（`report` を受けた時点で1回読み、プロセスのメモリの棚にだけ置く）。上限は `image` の
  5 MB に揃える（archify の1枚は約 0.8 MB）

### 表示: `iframe` の `sandbox` と CSP

- サーバは `GET /report-html/<toolUseId>/<path>?t=<起動トークン>` で棚の中身を配り、ブラウザは
  `<iframe sandbox src="…">` で開く。`srcdoc` は使わない（応答ヘッダの CSP を掛けられないため）
- `sandbox` の属性は**値なし**（どの `allow-*` も付けない）を起点にする。付けないことで次が止まる:
  スクリプト（`allow-scripts`）・同じ起源の扱い（`allow-same-origin`。付けないと不透明な起源になり、親のページ・
  起動トークン・`/rpc` に届かない）・フォームの送信・親のページの移動・新しいウィンドウ
- 応答ヘッダの CSP: `default-src 'none'; style-src 'unsafe-inline'; img-src data:; font-src data:; sandbox`。
  外のネットワーク・同じサーバの他の経路への読み込みを止め、`iframe` の外から直に開かれても `sandbox` が掛かる。
  あわせて `X-Content-Type-Options: nosniff` と `Referrer-Policy: no-referrer`
- **スクリプトなしで崩れる1枚は崩れたまま見せる**（素の HTML 1 のタブ）。`allow-scripts` を足すかは、
  足すと `default-src 'none'` の下でもインラインのスクリプトを許す CSP が要り、書き手のスクリプトが回す
  アニメーションの計算の代も負うので、この下書きでは足さない。書き手への指示で
  「スクリプトに頼らずに読める形（`<details>`・ページ内リンク）」を求める
- 高さは `iframe` の中から伝えられない（スクリプトが無い）ので、本文の幅で固定の高さ（窓の高さに比例）にして
  中を縦に転がす。押すと `image` と同じ拡大の画面で大きく開く

### テーマの渡し方

- 暗い面を常時とする正典（`docs/architecture/screen-design.md`）は、`iframe` の外枠（題・札・余白）にだけ掛ける。
  **`iframe` の中の色は書き手の自由**にするかは、(B) を見直すときに決める（決めたことの「見直す条件」）
- 渡す手は2つ: `iframe` の要素に `color-scheme: dark` を付け、中の `prefers-color-scheme` を暗い側に寄せる
  （Chromium での効き方は実装の前に実物で確かめる）。もう1つは書き手への指示で、暗い面を既定にして書かせる。
  測定では素の HTML が2回とも明るい面だけだったので、指示なしでは浮く
- サーバが HTML を書き換えて色を差し込む手は採らない（書き手のファイルの中身を変えることになる）

### サニタイズ

- `iframe` の中には `REPORT_SANITIZE_SCHEMA` を掛けない。安全は `sandbox` と CSP で取り、中身は書かれたまま配る
  （本文の Markdown のサニタイズは今のまま。本文に書いた `<iframe>` は今までどおり落ちる）
- 配る前に見るのは、拡張子・大きさの上限・UTF-8 として読めること・先頭が HTML らしいこと（`image` の先頭の印と同じ扱い）だけ

### 会話内容の扱いへの当たり

- `html` のファイルは書き手が作業ディレクトリに書いたもので、tsukumo は読んで**メモリの棚にだけ置き**、書き出さない
  （`image` の棚と同じ扱い。`docs/coding-standards.md`「会話内容の扱い」の4つの例外を広げない）
- 記録（`SessionRecord`）が持つのは塊の引数（パス）だけで、中身は持たない。復元は `image` と同じく、24時間以内で
  更新時刻が古いファイルだけを読み直す
- CSP の `default-src 'none'` で、中身が外へ出る道（画像の読み込み・フォームの送信・リンクを辿ること）を塞ぐ。
  診断ログには塊の数と決まった語（読めた・大きすぎる・HTML でない）だけを入れる

## 決めたこと

**(C) を採る。自由な HTML を載せる口（画像に撮る手順の決まり・`html` の塊・開く口）は足さない。** 見本の
1枚が持つ質（色分けの箱・層の図・カードの並び・凡例）は、塊（ADR 0028 の梯子の中の図と札）と欄
（`docs/architecture/adr/0031-report-body-as-regions.md`）を強くして近づける。

- **描き方を tsukumo が持つことで質を揃える。** 塊は形だけを書き手から受け取り、色・字の大きさ・暗い面を
  tsukumo の部品が決める。測定では、自由に書かせた HTML は回ごとに骨組みが変わり（タブか縦の節か）、
  2回とも明るい面だけで書かれた。archify でも図の込み具合で読めるかが分かれた（7ノードは読め、15ノードは
  自動の検査を通っても読めない）。同じ質を毎回出すことを、書き手の腕に預けない
- **要件との当たり**: `docs/requirements.md`「2.2 対象外とすること」に、自由な HTML を載せることを名指しで
  外した項は無い（2026-10-23 に読んで確かめた）。したがってこれは対象外による却下ではなく、
  「1. 概要・目的」の「技術的な詳細は、セリフとは別の場所に人間が読みやすい形で出す」に、どの道がいま近いかの判断である。
  近いのは塊を強くする道で、(A) は読めず、(B) は崩れた1枚と暗い面の食い違いを書き手任せで残す
- 実装のタスクは立てない

**見直す条件**: 次の3つがそろったら (B) を見直す。上の (B) の仕様の下書きを出発点にし、`iframe` の中の色を
書き手の自由にするかもそのときに決める。

1. 塊と欄を強くしても届かない依頼（触らないと読めない成果物を頼む「HTML にして」）が繰り返し出る
2. 書き手が、暗い面で・スクリプトに頼らずに読める1枚を、毎回同じ質で書けることを測って確かめられる
3. 値なしの `sandbox` と上の CSP の下で読める成果物（`<details>`・ページ内リンクで畳む1枚）が、その依頼の大半になる

## 採らなかった案

| 案                                                                              | 採らなかった理由                                                                                                                                                                                                                                           |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| (A) 外のファイルを画像に撮り、`image` の塊で載せる                              | 高さの上限（343px・425px）で縮み、縦に長い1枚は字が読めない。横長に切り出してもノード名までしか読めない。押して開く拡大の画面なら読めるが、タブ・畳み・ズームは消え、画に写った部品は押せそうに見えて効かない                                              |
| (B) `html` の塊を足し、値なしの `iframe sandbox` で見せる                       | 約25ファイルの実装になる。スクリプトなしではタブなどが効かず、崩れる1枚を崩れたまま見せることになる。暗い面との食い違いは書き手への指示頼みで、安全は `sandbox` と CSP の設計の正しさに載る。描き方を tsukumo が持たないので、質が書き手の回ごとにばらつく |
| HTML のファイルを Orca の別のタブで開く口を足す（ホストの `openFile` を広げる） | 今回は試していない。会話の画面の外へ視線を移すことになり、レポートに載せる口ではない。足すなら別の判断にする                                                                                                                                               |

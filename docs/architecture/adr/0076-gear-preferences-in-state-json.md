# 歯車の設定の localStorage の5つを state.json へ寄せる（2026-11-20）

ステータス: 採用

**歯車で変える利用者の設定のうち、ブラウザの `localStorage` に持っていた5つ（地・領域・字の色、背景の暗さ・パネルのぼかし・パネルの濃さ、書き上げる演出の速さ、動きを減らす、起動するスキル）を `~/.tsukumo/state.json` へ寄せる。描く前に要る値はサーバが HTML に焼いて配り、既存の `localStorage` の値は最初に開いたページが1回だけ写して消す。「設定をファイルで開く」の口は置かない。** ADR 0025 の 2026-10-24 の改訂の「起動するスキルの持ち先は `localStorage`」をこの ADR で上書きする（ADR 0025 の本文は書き換えない）。

## 何が困っていたか

歯車の設定の持ち先が2つに割れていた。新しいセッションの既定・裏方のモデル・話しかける間合いは `state.json`、上の5つは `localStorage`。
`localStorage` はオリジン（`http://127.0.0.1:<ポート>`）ごとに分かれ、ビューのポートは既定の 7327 が埋まっていると次へずれる（`src/shared/view-server/view-port.ts`）。

実測（2026-11-20。同じブラウザのプロファイルで、疑似セッションの tsukumo を `TSUKUMO_VIEW_PORT=7391` と `7392` で2つ起こし、7391 のページで5つの鍵を書いて読み込み直してから比べた）:

| 開いたページ                        | 5つの鍵               | 地の色（`--ground`）   |
| ----------------------------------- | --------------------- | ---------------------- |
| 7391（書いて読み込み直したあと）    | 5つとも書いた値       | 書いた値が根に差さった |
| 7392（同じブラウザ・別のポート）    | 5つとも無い（既定）   | 既定のまま             |
| 7391 を止めて同じポートで起こし直す | 5つとも書いた値が残る | 書いた値が根に差さった |

- **引き継がれないのは本当。ただし分かれ目はポートで、作業ツリーではない。** どの作業ツリーから起こしても、1つだけ動いていれば 7327 に乗り、同じ値を読む
- **ずれるのは2つ以上を同時に動かしたとき。** 2つ目は 7328 に乗り、7327 で整えた色・速さ・起動するスキルが無い既定の画面で始まる。そこで整え直した値は 7328 にだけ残り、次に 7327 で開くと出ない。ブラウザを替えた（orca のタブと既定のブラウザ）ときも同じように分かれる
- 測った時点で既定の帯（7327〜）で待ち受けていた tsukumo は1つだけだった。普段の使い方で毎回起きるわけではないが、並べて動かした回には必ず起きる

## 決めたこと

**採る: 5つとも `state.json` へ寄せ、描く前の値は HTML に焼き、移すのは最初に開いたページの1回。**

| 案                                                        | 種類   | 物差し                                                                        | 判定     |
| --------------------------------------------------------- | ------ | ----------------------------------------------------------------------------- | -------- |
| 5つとも `state.json` へ寄せる                             | 仕組み | ポート・ブラウザ・同時に動かす数に左右されない。歯車の設定の持ち先が1つになる | 採る     |
| `localStorage` に残し、ポートを固定してオリジンを揃える   | 仕組み | 同時に2つを動かせなくなる（2つ目はポートを変えるしかなく、変えれば分かれる）  | 採らない |
| 値ごとに分ける（色と動きは `localStorage`、残りを寄せる） | 仕組み | 一瞬の既定色は避けやすいが、いちばん目に付く色がポートで分かれたまま残る      | 採らない |
| 今のまま                                                  | -      | 同時に動かした回の2つ目は毎回既定の画面で始まり、そこで整えた値が失われる     | 採らない |

### 1. 寄せる値と欄

- 5つは、新しいセッションの既定・裏方のモデル・話しかける間合いと同じ `state.json` に、それぞれ別の欄として持つ（色・調整・演出の速さ・動き・起動するスキル）。欄の英語名は実装の段で `docs/glossary.md` に合わせる
- 読めない・欠けている・知らない値の欄は、その欄だけ今の既定に畳み、ほかの欄と覚えた値は読んだ値のまま（話しかける間合いと同じ扱い）。色の上書き無し・背景の暗さ無し（パックの `veil` に従う）も「欄が無い」で表す
- 歯車で変えると、サーバの手続きで `state.json` に書き、同じ tsukumo が開いているページへ変わった値を流す。別の tsukumo が開いているページは、次に開いた（読み込み直した）ときに新しい値を読む
- 効き方は今のまま。色・調整・動きは変えた瞬間に画面へ効き、演出の速さは次に書き始めたレポートから、起動するスキルは次の着手から
- 残す: 領域の比率・タスク一覧の幅・目次・入力欄の下書きと送り方・離席の印など、歯車の外の `localStorage` の鍵は寄せない（画面の今の形で、ポートで分かれても困らない）

### 2. 一瞬の既定色を避ける: HTML に焼く

- 描き始める前に要る値（色・調整・動き）は、ページの HTML を返すときにサーバが `state.json` から読み、`<script type="application/json">` のデータの塊として埋める。ブラウザの入口（`main.tsx`）は描き始める前にそれを同期で読んで根に差す。今 `localStorage` を同期で読んでいる位置がそのまま置き換わるので、最初の描画から整えた色で出る
- データの塊は実行されないので、今の CSP（`script-src`）は変えない。HTML は `no-store` で返しているので、開き直すたびに最新の値が乗る
- 演出の速さと起動するスキルも同じ塊で配る（最初の応答を待たずに読めるので、読む側を1か所にできる）
- 採らなかった: 最初の応答（手続き・イベント）で配る。描き始めてから届くので、既定の色が一瞬出る

### 3. 既存の値の移し方: 最初に開いたページが1回だけ写して消す

- `localStorage` はブラウザからしか読めないので、移すのはブラウザ側。HTML の塊は欄ごとに「`state.json` に値があるか」も運ぶ
- `state.json` に値が無い欄で、`localStorage` に読める値があれば、そのページはその値で描き始め（一瞬の既定色を出さない）、サーバへ写す手続きを1回送る。書けたと返ってきたら、その鍵を `localStorage` から消す
- `state.json` に値がある欄は `state.json` が勝ち、そのオリジンの古い鍵は消す
- オリジンごとに違う値を持っていたときは、新しい版で最初に開いたページの値が残り、ほかのオリジンの値は捨てる（5つとも歯車で整え直せる値なので、どれを残すかは選ばせない）
- 写す・消すに失敗しても描画は止めない（`localStorage` を読めないときに既定へ倒す今の扱いと同じ）

### 4. 「設定をファイルで開く」の口は置かない

- 歯車で5つとも変えられ、ファイルを直に書けないと困る値は無い
- `state.json` は動いている tsukumo が覚えたキャラクターなどを書き戻すファイルで、ファイルの変化を見張ってもいない。手で書いた値は、動いているあいだは画面に出ず、次の書き戻しで上書きされうる
- 置くとしても、開く手段は今の「ファイルを開く」ホスト（`orca` か `open`）で足り、`test/architecture/outside-world.test.ts` の `ALLOWED_COMMANDS` に名前は増えない。置くかどうかは、見張りと書き戻しの扱いを決めてから別に問う

## 結果

- 歯車の設定はすべて `state.json` に持つ。ポート・ブラウザ・同時に動かす数で値が分かれない。`TSUKUMO_HOME` を分けたときだけ分かれる（ほかの歯車の設定と同じ）
- 画面の正典 `docs/architecture/screen-design/setting-place.md` の表と、`docs/readme/configuration.md`「設定の置き場」の表は、実装と同じコミットで持ち先を `state.json` に直す
- 移す処理（`localStorage` を読んで写す）は、この ADR を上書きする決定があるまで残す

# サイドバーのタスク一覧を段とサイドシートにし、タスクのモーダルを一覧モードの表にする（2026-11-16）

ステータス: 採用

**サイドバーのタスク一覧を「いま・つぎ・待ち・ドラフト・済み」の段に分け、頭に常設の探す欄を置く。1件の詳細は、サイドバーの左に開く非モーダルのサイドシートに出し、今のプレビューを置き換える。全件を見渡すタスクのモーダルは「一覧モード」と呼び、1行1件の表にする。状態の印・属性・頼む口は、サイドバー・サイドシート・一覧モードで同じ部品を使う。送る順は8段で、1段送るごとに画面が使える状態を保つ。**

この ADR が決めるのは、正典の決まりのうち置き換えるもの、サイドシートの置き方と操作の型、行の題の字の大きさの表し方、部品の境界と名前、探す語の持ち方、一覧モードの読み上げの型と仕切り、消す部品と送る順まで。寸法と色の細部は見本と部品の CSS が持つ。会話の画面の3列（ADR 0058）と、進行の帯・入力欄の置き場（ADR 0059）は変えない。

## 何が困っていたか

- 同じ概念を、サイドバーとタスクのモーダルが別の印・色・語で出している。空の輪は、サイドバー（`TaskMark`）では着手可、モーダル（`TaskState`）では待ちの形に近い。状態の語の出どころも `taskStateOf` とプレビューの `statusWordOf`（todo を「未着手」と言う）の2つある。
- サイドバーの行は印・番号・題・ループ可・「›」の5列で、1400×900 では題が約9字しか読めない。進行中だけ先頭のカードで、残りは番号の順に完了と混ざる。
- 1件の詳細を出す場所が、行を押して出るプレビュー（`TaskPeek`。本文の頭だけ）と、モーダル（`PresentationalTaskBoard`。全文）の2つあり、中身と口が重なる。モーダルは開いているあいだ、会話の流れと入力欄を操作できない。
- 正典はコードより古い所がある。サイドバーには凡例（`TaskLegend`）と字の「↻」のループ可が出ているが正典に無く、正典は「プレビューに頼む口を出すのは着手可だけ」と言うが、コード（`isTaskRequestable`）は依存の済んだ保留にも出す。

## 利用者が決めたこと（2026-11-16）

- 構造は見本の「案B の仕上げ」（`docs/history/mockup/sidebar-task-board-2026-11-16/index.html?design=b2`。説明は `refine.html`、課題と3案の比較は `compare.html`）。言葉と見本が食い違ったら見本が勝つ。
- 状態の印は6種（進行中・着手可・待ち・保留・ドラフト・完了）を1つの体系にし、サイドバー・サイドシート・一覧モードで同じ印・色・語を使う。色は差し色（進行中・着手可）・琥珀（保留）・灰（ほか）の3系統。
- ループ可は ∞ の印、難しさはモデル名の語（詳細と一覧モードでは3段の目盛りを添える）。生の値（`done`・`Y`・`N`）は画面に出さない。
- 頼む口は「<キャラクター名> に頼む」と、入力欄の送信と同じ上向きの矢印。
- サイドバーの一覧は「いま・つぎ・待ち・ドラフト・済み」の段に分け、凡例と件数のチップは置かない。行は1段目に印と題（13px・2行まで）、2段目に待ちの相手・タスクの番号・ループ可・難しさ（12px）。済みの段は畳んでおく。
- サイドバーの探す欄は常設で、虫眼鏡の口は置かない。題と件数の行の下に欄を積む。`/` は探す欄に割り当てない（入力欄へ移るキーに使う）。
- 1件の詳細は、サイドバーの左に開く非モーダルのサイドシートに出す（今のプレビューを置き換える）。進行の帯と入力欄を覆わない。
- 一覧モード（今のタスクのモーダル）は残す。1行1件の表で、列はタスクの番号・題・難しさ・ループ可の順。状態の印は番号の前、待ちの相手は題の後ろに添える。一覧と詳細の境は、つまみを引いて動かせる仕切りにする。
- 使用量の帯は、コンテキスト・5時間・7日の3つを同じ形（語・割合・細い棒）で並べる。
- 書き手が既定として決め、利用者に報告したもの（異論が出たら差し替える）: ドラフトの分類はサイドシートに置き、一覧モードには置かない（分類の選択肢の「保留」は「あとで」にする）。狭い幅（760px 以下）は、行を押すとサイドシートではなく一覧モード（今の狭い幅のモーダルの形）でそのタスクを開く。中間の幅（761〜1100px）の柱は今の形のまま。

> 「一覧モードには置かない」は、利用者の依頼で差し替えた。一覧モードにも件数の帯の右端に「仕分ける」を置き、右の欄と下端の帯をサイドシートと同じ分類の場面（`DraftSortPanel`・`DraftSortBand`）に替える（`docs/architecture/display/task-modal.md`。2026-11-18）

## 決めたこと

見本は実ブラウザ（1400×900）で、通常（`view=rest`）・詳細（`view=task`）・探す欄の入力中（`view=typed`）・一覧モード（`view=list`）の4場面を開いて確かめた。サイドシートは幅 480px で、進行の帯の下端から入力欄の上端までに収まり、右端は中央の列の右端にそろう。

### 論点 1: 置き換える決まりと残す決まり

**採る: 正典の決まりは、末尾の「今の正典の決まりの置き換え」の表のとおりに置き換えるか残す。とくに次の4つを決める。**

- **並び**: サイドバーと一覧モードで同じ段の並びにする。段は `taskStateOf` の `kind` で決め、いま＝`doing`、つぎ＝`ready`、待ち＝`blocked`・`hold`・`other`（この順）、ドラフト＝`draft`、済み＝`done`。どのタスクも必ず1つの段に入る。段の中は一覧の順（番号の昇順）で、済みの段だけ番号の降順にする（見本どおり、近く済んだものを上に。閉じた時刻は一覧の項目に無いので番号で代える）。0件の段は出さない。
- **一覧モードを開いたときの選択**: 名指し（`openTask`）があればそのタスク。無ければ「いま」の先頭、無ければ「つぎ」の先頭、どちらも無ければ表の先頭の行。開いた直後に、押せない頼む口と完了のタスクが出るのを避ける。
- **探す語の持ち込み**: サイドバーの探す語は、「一覧を見る」で開くときに一覧モードの検索欄へ写す。サイドシートの「一覧モードで開く」でも写す（名指しのタスクが語に当たらなければ、今の「絞り込みの外」の一時の行で出す）。一覧モードで変えた語はサイドバーへ戻さない。状態の絞り込み（件数の帯）は一覧モードだけにあり、開くたびに「すべて」から始める。
- **サイドバーから頼める範囲**: サイドシートの頼む口は、一覧モードの操作の帯と同じ部品（`TaskBoardAction`）と同じ範囲にする。押せるのは着手可と依存の済んだ保留（保留は今の文面の末尾の一言を添える）で、ほかは押せない口と理由を出す。ドラフトは「却下する」「計画する」。今のプレビューの「着手可だけ・ほかは口ごと出さない」はやめる（コードはすでに保留にも出しており、口が場所によって消えたり出たりするより、押せない理由を見せるほうが読める）。
- 見本の頼む口は保留を「保留を解くと頼める」で押せなくしているが、依存の済んだ保留に頼めることは ADR 0025 の 2026-10-24 の改訂で利用者が決めた振る舞いなので、ここだけは見本より今の振る舞いを残す。異論が出たら差し替える。

### 論点 2: サイドシートの置き方と操作の型

**採る: サイドシートは、会話の画面の中央の列が用意する置き場に、タスク一覧の機能の部品として描く。開いているタスクは新しい状態の置き場（`stores/task-sheet.ts` の `useTaskSheet`。一覧モードの `useTaskBoardRequest` と同じ作り）が持ち、サイドバーの行と、会話の画面のサイドシートの置き場がそれを読む。最上位の層には積まない。**

- **置き場**: 中央の列の、進行の帯の下端から入力欄の上端までの区画に、右端をそろえて重ねる（幅 480px。列が狭ければ列の幅から余白を引いた幅）。置き場は会話の画面の側（`requested-task-board.tsx` と同じ並び）の部品が持ち、帯と入力欄の位置は CSS の grid の区画で決まるので、矩形を測って渡す処理は持たない。置き場の祖先にぼかし（`backdrop-filter`）の面を置かない（サイドバーの領域の `panel.css` のぼかしの外になる）。祖先の CSS の規則が中身に当たらないかは、実装の段で実ブラウザで測る。
- **フォーカス**: 開いても押した行に残す（今のプレビューと同じ）。サイドシートの中の口は Tab で届く。
- **↑↓**: サイドバーの一覧の器が受け、画面の上からの順で隣の行へ移ってサイドシートの中身を入れ替える（端で止まる。畳んだ済みの段は飛ばす）。サイドシートの頭の「前のタスク」「次のタスク」の口も同じ順で動く。探す欄に語があるときは当たりの行の中で動く（論点 5）。
- **閉じ方**: Esc（フォーカスが行かサイドシートの中にあるとき）・「×」・同じ行をもう一度押す。閉じると押した行へフォーカスを戻す。外側を押しても閉じない（開いたまま入力欄に書いて送るため。見本の非モーダルの面と同じ）。開いているタスクが一覧から消えたら閉じる。
- **重なりの順**: 確認（`TaskRunConfirm`）と一覧モードはどちらもモーダルの `<dialog>` で最上位の層に出るので、必ずサイドシートの上に出る。確認を開いている間の Esc は確認だけを閉じる。送るとサイドシートも閉じる。「一覧モードで開く」は、サイドシートを閉じて行へフォーカスを戻してから一覧モードを開く（一覧モードを閉じると行へ戻る。同じタスクの詳細を2か所に出さない）。
- **つながりと本文中の ID**: サイドシートの中で詳細を切り替え、サイドバーの開いている印も追う。一覧モードと同じく直前の1つだけのパンくず（Alt+← でも戻る）を出す。
- **読み上げ**: サイドシートは `<aside>` で、題を `aria-labelledby` で名前にする。行は `aria-expanded` と `aria-controls` を持ち、ポップアップではないので `aria-haspopup` は外す。
- **幅ごと**: 761px 以上（柱から開いたサイドバーを含む）は同じ置き場に開く。760px 以下は、行を押すと `openTask` で一覧モードをそのタスクを選んで開く。

> 「閉じ方」の「外側を押しても閉じない」は、利用者の依頼で上書きした。サイドシート・サイドバー（`data-region="sidebar"`）・入力欄（`data-region="dispatch"`）の外を押すと閉じる（フォーカスは押した先に任せ、行へは戻さない）。入力欄とサイドバーを外すので、開いたまま入力欄に書いて送ることと、別の行を押して切り替えることは残る。下の「採らなかった案」の「サイドシートを外側のクリックで閉じる」も、この範囲で読み替える（2026-11-17）。

### 論点 3: 行の題の 13px

**採る: 字の段は足さず、タスク一覧の機能の CSS の中に局所のつまみ `--task-title-size` を置き、`calc((var(--font-label) + var(--font-body)) / 2)` で `--font-label`（12px）と `--font-body`（14px）の中間から導く。サイドバーの行の題と一覧モードの表の題がこれを使い、`test/architecture/font-size.test.ts` の局所のつまみの一覧と、`principle-and-type.md` 13.3 の局所のつまみの列挙に足す。**

- 広い画面で 13px、触る画面（Astryx が 14px・16px に組み直す）では 15px になり、2つの段の間に留まる。
- 2段目・段の見出し・ラベルは `--font-label`（12px）、サイドシートの題は `--font-heading`（17px）、本文は `--font-body`（14px）で、見本の値は既存の段で表せる。

> この論点の値は、利用者の依頼で上書きした。サイドバーの行の題の `--task-title-size` は `var(--font-label)`（広い画面で 12px）にする。下の「採らなかった案」が退けた「12px は2段目と同じ大きさになり、題と2段目の差が消える」には、色の差で答える（2段目は `--ink-quiet`、ID は等幅）。局所のつまみは残し、「利用者が決めたこと」と置き換えの表の「13px」もこの値に読み替える（2026-11-17）。

### 論点 4: 状態の印を置く部品の境界

**採る: `TaskMark` を消し、`components/task-state.tsx` の `TaskState` を唯一の部品にする。`TaskState` は `TaskStateView` を受け、`display: "mark" | "labeled"` で印だけ・印と語の2つの出し方を持つ。状態の語は `taskStateOf` だけが作り、サイドバーの行もそれを使う（`statusWordOf` はやめる）。**

- 印の絵は `src/browser/components/ui/icon/icon.tsx` に形の名前で足す（`CircleIcon`・`CircleDotIcon`・`HourglassIcon`・`CirclePauseIcon`・`CircleDashedIcon`・`CircleCheckIcon`・`CircleAlertIcon`）。状態から絵への対応は `TaskState` が持つ（`ui/` はタスクの語を知らない）。
- `icon.tsx` へ寄せる範囲は、この作り直しで触る口すべて: 状態の印・ループ可の ∞（`InfinityIcon`）・頼む口の上向きの矢印（入力欄の送信と同じ絵）・閉じる・番号を写す・Issue を開く・前後のタスク・一覧モードで開く。`features/task-board` から `lucide-react` の直の import を無くす（今は10ファイル）。サイドバーの使用量の札の `plan-usage-row.tsx` は範囲の外。
- 用語集（`docs/glossary/view.md`）に、サイドシート（`TaskSheet`）・一覧モード（`TaskBoard` のまま）・段（`TaskStage`。いま `now`・つぎ `next`・待ち `waiting`・ドラフト `draft`・済み `done`）・探す欄（`TaskSearchField`）を足す。

### 論点 5: 探す欄の絞り込みの置き場

**採る: 検索の規則は `domain/task-board-filter.ts` の `matchesQuery` の1つを、サイドバーと一覧モードで共有する。段に分けて語で絞る純粋関数を `domain/task-stage.ts`（今の `task-sidebar-order.ts` を置き換える）に置き、両方が使う。探す語と ↑↓ の位置は `TaskSection` が `useState` で持ち（保存しない）、一覧モードを開く頼み（`useTaskBoardRequest` の `openList`・`openTask`）に語を載せて引き継ぐ。**

- 欄は `role="combobox"`（`aria-controls` が一覧、`aria-activedescendant` が ↑↓ で選んでいる行）。フォーカスは欄に残す。
- ↑↓: 当たりの行の中で動く（最初は最初の当たり、端で止まる）。サイドシートが開いていれば中身も追う。
- Enter: 選んでいる行を押したときと同じ面を開く（広い幅はサイドシート、狭い幅は一覧モード）。変換中（`isComposing`）は見送る。
- Esc: 語があれば語を消す。語が空なら入力欄へフォーカスを戻す（入力欄へフォーカスを寄せる既存の口を使う）。サイドシートが開いているときは、語より先にサイドシートを閉じない（欄の Esc は欄のもの。サイドシートは「×」か行の Esc で閉じる）。
- 語があるあいだは当たりの無い段を出さず、済みの段を開いて出す。

### 論点 6: 一覧モードの表の読み上げの型と仕切り

**採る: 読み上げの型は `role="listbox"` と、検索欄の `aria-activedescendant` のまま残し、見た目だけを列のそろった表にする（行は CSS の grid と `subgrid` で列をそろえ、列の見出しの行は `aria-hidden`）。段は listbox の中の `role="group"`（`aria-label` は段の名前と件数）。選択肢の名前は「番号・題・状態・難しさ・ループ可」の順で読む。**

- 仕切りの可動域は、一覧（表）の最小を 480px（印・番号・題が読める最小・難しさ・ループ可の列の和）、詳細の最小を 360px（今のまま）、既定を箱の幅の 64%（見本の 791px／1231px）にする。
- 保存する幅は新しい鍵 `tsukumo-task-board-list-width:v2` に px で持ち、v1（300〜760px）は読まない（v1 の既定 470px は新しい最小に届かず、写しても表が読めない）。v1 の鍵は消さない（`localPreference` の決まり）。
- 仕切りは今の `LayoutResizer` を使い、つまみを見せる。矢印キーでも動く。

### 論点 7: 消すものと、消す段

**採る: 消す部品は、それを置き換える部品が入る段で消す（2つの面が同じものを出す途中の main を作らない）。**

| 消すもの                                                                                                                              | 消す段                 |
| ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| `TaskMark`（`task-mark.tsx`・CSS）と `statusWordOf`                                                                                   | 段 1（状態の印）       |
| `LOOP_GLYPH`・`TaskLoopMark`・難しさの点3つ                                                                                           | 段 2（属性と口）       |
| 凡例 `TaskLegend`・件数のチップ `TaskCountChipList`・`task-list-count.ts`・`task-sidebar-filter.ts`・進行中のカード `TaskRunningCard` | 段 3（段と行）         |
| プレビュー `TaskPeek`・`useTaskPeek`                                                                                                  | 段 5（サイドシート）   |
| モーダルのドラフトの仕分け `TaskBoardSortChoice`・`TaskBoardSortBand`・`rowSortOf`・`sortBandOf`                                      | 段 6（ドラフトの分類） |
| 使用量の円 `PlanWindowPie`                                                                                                            | 段 8（使用量の帯）     |

### 論点 8: 送る順

**採る: 次の8段で送る。段 4 と段 5 は同じファイル（`task-list.tsx`・`task-section.tsx`）を触るので、並べずに段 4 → 段 5 の順にする。段 8 は、この ADR だけを待ち、ほかと並べられる。**

1. **状態の印**: `TaskState` を唯一の部品にし、`icon.tsx` に状態の絵を足す（論点 4）。
2. **属性と口**: ∞・難しさの語と目盛り・「<キャラクター名> に頼む」と上向きの矢印・閉じると最新化の口（28px・枠なし）・詳細の生の値を外す・番号を写す口を詳細の頭へ。
3. **段と行**: 段の純粋関数（`domain/task-stage.ts`）・2段の行・題の局所のつまみ（論点 3）・凡例とチップとカードを消す・区画の見出しの字の段。
4. **探す欄**: 常設の欄と、語で段を絞る・↑↓・Enter・Esc（論点 5。一覧モードへの語の持ち込みは段 7）。
5. **サイドシート**: 状態の置き場 `useTaskSheet`・中央の列の置き場・頼む口を一覧モードと同じ範囲に・「一覧モードで開く」・狭い幅は一覧モード・プレビューを消す（論点 2）。
6. **ドラフトの分類**: サイドシートの分類の場面と、一覧モードの仕分けを消す。
7. **一覧モードの表**: 段の並び・開いたときの選択・表と読み上げの型・頭の1行・語の持ち込み・仕切りと新しい鍵・Enter で頼む口の確認（論点 1・5・6）。
8. **使用量の帯**: 3つを同じ形にし、語を「コンテキスト」「5時間」「7日」にそろえる。詳しい面の「7日間」も「7日」にする（同じ量に1つの語）。

- 段 5 と段 7 は、置き場・状態の持ち方・キー・読み上げの型を同時に組み替え、消す口と触る機能が多いので、難しさを1段上げる。

## 採らなかった案

# レポートの本文は欄の構造のままブラウザへ渡し、欄ごとに独立して描く（2026-10-22）

**`report` の本文を、HTML 混じりの Markdown 1本に畳まず、欄（頭・節・振り返り・お願い）の並びのまま
メインビューへ渡す。** ブラウザは欄ごとに別の Markdown として解析し、欄の入れ物は React の要素で作る。
書き上げる演出は節の欄の入れ物を1トピックとして受け取り、目次は節の欄の位置（欄の ID）で見出しを突き合わせる。
区切りを class 名の印と DOM の位置から読み戻す推測はやめる。

## 何が困っていたか

`report` の引数は構造化されているのに、`src/shared/session/main-view-entry.ts` が
それを1本の文字列に連結していた（移行の段1で、欄に組む `reportRegionsOf` と、欄から文字列を導く
関数に分け、段2で文字列を導く関数を消した）。

- `conclusion` は `<div class="conclusion">`・`<div class="conclusion-lead">` で、`favor` は
  `<div class="note note-favor">` で、モデルの書いた文字のまま包む（逃がさない）
- 検証結果は `src/shared/report/report-check.ts` の `reportChecksMarkdown` が HTML の文字列で組み、
  `main-view-entry.ts` が `<div class="status">` で包む
- 節の境目と「結論・検証結果の終わり」は、`report-markdown.ts` が挟む見た目の無い `<div>` の印
  （`report-section-break`・`report-sections-start`）で表す
- ブラウザは文字列を空行で塊に割り（`splitReportBlocks`。`<div>` の開き閉じを数えて、HTML の塊の中では割らない）、
  塊ごとに `rehype-raw` で解析し直す
- 書き上げる演出（`src/browser/domain/reveal/plan.ts`）は、根の直下の要素から印の class を探して区切る
- 目次（`use-report-outline.ts`）は DOM の `h4`・`h5` を拾い、`h4` の何番目かを `MainViewStepBody.headings`
  （節の見出しの字の並び）の位置と突き合わせる（`sectionOrdinalOf`）

閉じない `<div>` を混ぜた架空のレポートを、`mainViewEntries` → `splitReportBlocks` → 本番と同じ
remark / rehype の段（`REPORT_SANITIZE_SCHEMA` まで）→ `planReveal` に通して測った（節2つ・検証1項目・お願いあり）:

| 混ぜた場所と文字                               | 塊の数 | 根の直下                            | 演出のトピック            | 目次の見出し（構造 / DOM）           |
| ---------------------------------------------- | -----: | ----------------------------------- | ------------------------- | ------------------------------------ |
| なし                                           |      9 | 9個（印も直下）                     | 2（節A・節B）             | 2 / 2                                |
| `conclusion` に `<div>`                        |      1 | 1個（`conclusion-lead` が全部）     | 1（結論も筆の対象に入る） | 2 / 2（どちらも結論の入れ物の中）    |
| `conclusion` に行頭の ` ``` `                  |      1 | 1個（`conclusion-lead` が全部）     | 1（残り全部がコード）     | 2 / 0                                |
| `conclusion` に `</div>`                       |     10 | 10個（結論の後ろに段落が漏れる）    | 2                         | 2 / 2                                |
| `favor` に `<div>`                             |      9 | 9個                                 | 2                         | 2 / 2（お願いは末尾なので無害）      |
| 逃げ道の `markdown` の塊に閉じない `<details>` |      6 | 6個（節Bとお願いが `details` の中） | 1（節Bが節Aに合流）       | 2 / 1（節Bが閉じた畳みの中で外れる） |
| 逃げ道の `markdown` の塊に `## 見出し`         |     11 | 11個                                | 2                         | 2 / 3（節Bが3番目にずれる）          |

`conclusion`・`favor` を `markdownInline` で逃がしてから包むと、上の2行（`<div>`・` ``` `）は「なし」と
同じ形に戻る。**ただし逃げ道の `markdown` の塊は HTML を通すための塊で、逃がせない。** そこに書かれた閉じない
タグや見出しは、1本の文字列の上で次の節の印と見出しの位置を巻き込む。逃がすだけでは、区切りを印と位置から
読み戻す仕組みが残る。

## 決めたこと

### 構造のまま運ぶ範囲（論点1）

**レポート全体を欄の並びにする。** `MainViewEntry` の `report` と `MainViewStepBody` の `text` は、連結した
文字列の代わりに次の形の本文を持つ。`report` ツール以外の本文（`detail`・段のまとめ）は Markdown 1本の欄にする。

| 欄         | 中身                                                                                  | 演出               |
| ---------- | ------------------------------------------------------------------------------------- | ------------------ |
| 頭         | `conclusion`（`task` の有無で結論の一文か見出しの代わり）と合図の行・段ごとの所要時間 | 最初から出す       |
| 節（並び） | 欄の ID（整形して図を先頭に足したあとの節の並びの位置）・見出しの字・節の Markdown    | 節1つが1トピック   |
| 振り返り   | `retrospective`（見出し「振り返り」の節）                                             | 最後の節と同じ扱い |
| お願い     | `favor`（総括行の印が飛ぶ先の `id` は欄の入れ物が持つ）                               | 最後の節と同じ扱い |

- **欄の中身は今の Markdown のまま**にする。節の中の塊は今の `reportSectionsMarkdown` の記法（許可リスト・mermaid・
  `chart`・余白の柱）で組み、検証結果も `reportChecksMarkdown` の HTML のまま頭の欄に入れる。崩れの届く範囲を
  欄1つに閉じるのが狙いで、記法の描き方は変えない
- **欄ごとに別の `Markdown` として解析し、入れ物は React の要素で作る。** 閉じないタグはその欄の解析の終わりで
  閉じ、次の欄の入れ物は文字列から作られないので巻き込まれない。`conclusion`・`favor` を逃がす直しは足さない
  （欄に閉じれば崩れは欄の中の見た目だけで済み、今の記法〔inline code・太字〕も変えずに済む）
- 最終レポートだけが持つ段ごとの所要時間は、頭の欄の「最終のときの中身」として持つ（`finalMarkdown` の代わり）

### 演出と目次が区切りとして受け取るもの（論点2）

**区切りは部品の境界で、欄の入れ物が `data-report-section`（欄の ID）を持つ。**

- **演出**: `planReveal` は根の直下の `[data-report-section]` を1つずつトピックにし、中の要素を今の包みの扱い
  （題・余白の柱）で並べる。頭の欄は対象にしない。`report-sections-start`・`report-section-break` の印と、
  それを探す selector は消す。欄が節1つだけの本文（`detail`・段のまとめ）は今と同じく全体で1トピック
- **目次**: 節の行（`section`）は構造の見出しの並びから作り、転がす先は同じ欄の ID の入れ物の見出しにする。
  `h5` と、節の中で書かれた余分な `h4`（逃げ道の塊の `##`）は、その欄の下の `sub` の行として DOM から拾う。
  行は欄の ID を持ち、中間から最終で足された節の印（`newSectionIds`）と既読はこの ID で引く。
  `sectionOrdinalOf`（`h4` の何番目かで数える）は消す
- 見出しの無い節（図だけの先頭の節、`body` が文字列だったころの節）は目次の節の行を持たない。中で書かれた
  `h4` は今と同じく `section` の行として拾うが、欄の ID は持たない（足された節の印・既読の対象にならない）

### 復元と保存済みの記録との互換（論点3）

**移す必要のある保存の形は無い。** 記録（`SessionRecord` の `report`）は今も引数の構造のまま持ち、transcript からの
復元（`sdk-report-message.ts`）も同じ記録を組む。`MainViewEntry` と `MainViewStepBody` はブラウザが記録から
描くたびに導く値で、サーバは読まず、送らず、保存もしない。

- `sections` の無い古い transcript（`body` が文字列）は、今と同じく `reportSectionsOfBody` で見出しの無い節1つに
  畳まれ、節の欄1つになる（演出は1トピック、目次の行は中の `h4` から拾う）
- 中身を変えないので、使われ方の記録・差し戻しの判定（サーバの `report-review` など）は触らない

### 移行の段と E2E の期待値（論点4）

3段に分け、どの段も1コミットで説明が付く。

| 段                            | 変えること                                                                                                                                                                                                                                                                                                                                                  | E2E の期待値の撮り直し                                                                                                                                                                                                             |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 共有層の形                 | `MainViewEntry`・`MainViewStepBody` に欄の構造を持たせ、今の文字列（`markdown`・`finalMarkdown`・`report`・`finalReport`）は欄を連結して導く。描く側はまだ文字列を読む。識別子は先に `docs/glossary.md` へ足す                                                                                                                                              | 無し（DOM も手続きの応答も変わらない）                                                                                                                                                                                             |
| 2. 欄ごとに描いて演出を区切る | `Report` と段の一覧の板が欄の構造から描き、`planReveal` が `[data-report-section]` を読む。印（`SECTIONS_START_MARKDOWN`・`SECTION_BREAK_MARKDOWN`）と文字列の欄を消す。入れ物が1段挟まるので、根の直下を前提にした CSS（`.detail-block >`・`.main-step > .detail-block >`）を直す。閉じない `<div>` を混ぜた結論が次の欄を巻き込まないことを単体で確かめる | 本文の入れ物（`data-report-body`）を含む8本（`aside-thread`・`conversation-moment-large`・`inquiry-permission-mouse`・`input-dispatch`・`report-chart`・`report-notation`・`report-task-finished`・`turn-flow`）。演出の目視も要る |
| 3. 目次を欄の ID で引く       | `use-report-outline.ts`・`report-heading.ts`・`new-heading.ts` を欄の ID で突き合わせる形にし、`sectionOrdinalOf` を消す                                                                                                                                                                                                                                    | 目次の DOM は変えない見込みで無し。変わったら `report-turn-outline`・`report-outline-compact` の2本                                                                                                                                |

段2は演出と CSS が同じ入れ物の変更に乗るので、分けると間の版で演出が区切れなくなる。1つにまとめる。

## 採らなかった案

| 案                                                           | 採らなかった理由                                                                                                                                       |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `conclusion`・`favor` を `markdownInline` で逃がすだけにする | その2つは直るが、逃げ道の `markdown` の塊は HTML を通すための塊で逃がせない。閉じない `<details>`・`##` で次の節の印と見出しの位置がずれる（上の測定） |
| `conclusion`・`favor` の欄だけを構造で運ぶ                   | 演出の区切りと目次の突き合わせは節の印と位置に残り、推測が要るまま                                                                                     |
| 塊1つずつを別の欄にする                                      | 欄に閉じる狙いは節1つで足りる。塊ごとにすると余白の柱・`fold` の包みを部品へ移す作業が加わり、塊を足すたびに描く側も触ることになる                     |
| 検証結果の HTML を React の部品で組み直す                    | モデルの文字は `htmlInline` で逃がし済みで、崩れの元ではない。頭の欄に閉じれば足りる                                                                   |
| `splitReportBlocks` の深さの数え方を賢くする                 | 文字列から境界を読み戻す推測をもう1段重ねることになる。境界は書いた側が知っている                                                                      |

# 「舞台と紙」の器: 4局面の姿勢・右から重ねる紙・2つの入口・新旧の切り替え（2026-11-13）

ステータス: 置き換え済み（→ 0058）

この ADR の器は 2026-11-15 の revert でツリーに無い。会話の画面の形は `docs/architecture/adr/0058-three-column-single-stream.md` が全体を置き換えた。

**会話の画面の器を「舞台と紙」に作り直す。背景を全面に敷いて立ち絵を左に立たせ（舞台）、レポートは中央の1枚の紙で読む。ほかの画面は舞台を残したまま、右から紙を重ねて出す。入口は左上の「部屋の頭」と「探す（⌘K）」の2つにまとめる。器の姿勢は、今の `MainViewContent`（送ったときと閉じたときにだけ進む中身）から引き、新しい状態を持たない。重ねる紙は今の画面の登録表と `location.hash` の上に作り、開閉を URL に載せる。新旧の器は、端末ごとの好みの1つの鍵で切り替えて並べて走らせ、利用者が新しい器を了承したら旧い器と鍵を消す。Astryx の部品は使い続け、見た目はテーマとトークンで見本に寄せる。**

この ADR が決めるのは器の形、つまり領域の並び・姿勢・重ね方・入口・切り替えまで。紙の中身（判定の行・確かさの台帳・計画）は ADR 0056 が、トークンの値は意匠のトークンの段が決める。

## 何が困っていたか

- 今の会話の画面は4領域（メインビュー・サイドバー・キャラビュー・入力欄）で、`src/browser/components/page/conversation/components/conversation-layout/presentational-conversation-layout.tsx` が組んでいる。立ち絵は箱の中に小さく収まり、レポートを読む面は画面の半分ほどしか無い（今の値は `docs/architecture/screen-design/stage-and-paper-yardstick.md`「作り直す前の値」）。
- ほかの画面への入口は、上の帯（`src/browser/components/frame/screen-nav/`）のタブ・札・歯車と、サイドバー（`src/browser/components/frame/sidebar/`）のタスクの一覧・使用量の2か所に散っている。
- ほかの画面（キャラ・トークン・成果・見本帳）は、`src/browser/components/app/screen-registry.tsx` の `overlay` に登録され、全面に重なる。`src/browser/components/app/layout.tsx` の `Layout` は、ほかの画面を出すあいだ会話の画面を `<Activity mode="hidden">` で隠す。そのためキャラクターも、読んでいたレポートも見えなくなる。

## 利用者が決めたこと

- 見本は `docs/history/mockup/ui-rebuild-2026-11-12/whole.html`。言葉の説明と見本が食い違ったら見本が勝つ。
- 2026-11-12 に案A「舞台と紙」を選んだ。今の画面のデザインの文書と ADR 0053 の見た目の決まりに縛られずに作り直してよい。データの層とレポートの内容部品は残す。
- 局面は迎える・働く・尋ねる・渡すの4つ。器が姿勢を変える瞬間は、送ったときと閉じたときに限る。
- 幅 760px 以下は縦1列にし、重ねる紙は全面に出す。
- 成果の暦の灯りは、今の狐火（`src/browser/components/page/achievement/components/lamp/lamp.tsx` の `Lamp`）を残す。

## 決めたこと

### 論点 1: 新旧の切り替えの印と、旧い器を消す条件

**採る: 印は、端末ごとの好み（`src/browser/utils/local-preference.ts`）の鍵 `tsukumo-shell:v1` に置く。値は `"classic"`（旧い器）と `"stage"`（新しい器）で、既定は `"classic"`。印を書く口は2つ。1つは設定の「見た目」の項目で、旧い器では歯車のダイアログに、新しい器では設定の紙に置く。もう1つは読み込んだ URL の検索引数 `shell=stage|classic` で、読み込んだときに鍵へ書く。**

- 印は読み込んだときに1回だけ読み、`<html>` に `data-shell` を立てる。器の分かれ目は `Layout` の1か所にし、そこで印を見て旧い器と新しい器のどちらかを描く。会話の画面の中の部品は印を読まない。
- 新しい器のトークンの値は、`:root[data-shell="stage"]` に今と同じ名前で書く。Astryx のテーマはトークンを `var()` で引き、`var()` はテーマの根（`[data-astryx-theme]`）で値が決まる。テーマの根より下で値を書き換えても Astryx の部品には届かないので、根より上の `<html>` で分ける。旧い器を消すときは、この値を `:root` へ移す。
- E2E とキャプチャは、旧い器を既定のまま走らせる。新しい器を撮るときは、URL に `shell=stage` を付けて開く（`scripts/capture/capture-view.ts` は URL を受けるので、道具は増えない）。
- **旧い器を消す条件**は次の3つがそろったとき。
  1. 新しい器の4局面・重ねる紙・狭い幅を組む後段がすべて済んでいる。
  2. `stage-and-paper-yardstick.md` の6場面×3幅が、新しい器で目標の値に届いている。
  3. 利用者が新しい器を触り、既定にしてよいと言った。
- 消すときは、旧い器の部品と CSS、印を書く設定の項目と URL の引数、鍵、`data-shell` をまとめて消す。保存済みの鍵の値は読まなくなるだけにし、移し替えはしない。

| 案                                                  | 物差し                                                                                               | 判定     |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | -------- |
| 端末ごとの好みの鍵＋設定の項目と URL の引数から書く | 組み立てた本番で利用者が触れる。読み直しても保たれる。URL の引数で、E2E とキャプチャが場面を名指せる | 採る     |
| サーバの設定（`~/.tsukumo/` の設定ファイル）に置く  | 表示だけの違いで、サーバは器を知らなくてよい。部屋ごと・タブごとに試し分けられない                   | 採らない |
| `location.hash` の引数に置く                        | hash は画面と見ているターンの経路で、画面を移ると付随の引数が落ちる（`location-hash.ts` の決まり）   | 採らない |
| 開発中だけの印（`import.meta.env.DEV`）             | 既定にする前に、利用者が組み立てた本番で触って了承する手順が取れない                                 | 採らない |

### 論点 2: 4局面の姿勢を何から決めるか

**採る: 姿勢は、今の `MainViewContent`（`src/browser/components/page/conversation/stores/main-view-content.ts`）の `kind` から引く。尋ねるは、働くの姿勢のまま `conversationMoment`（`src/shared/session/conversation-moment.ts`）の `ask` で入力欄の場所の中身だけを替える。新しい状態は持たない。**

`MainViewContent` は「送った」と「閉じた」の2つの遷移でしか進まない。これは「器が姿勢を変えるのは送ったときと閉じたときだけ」と同じ約束なので、そのまま姿勢の出どころにできる。

| 姿勢   | 引く値                                           | 器の形（見本の値）                                                                                                     |
| ------ | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| 迎える | `kind: "welcome"`                                | 紙を出さない。舞台を広げ（`clamp(340px, 42vw, 900px)`）、右に迎えの一言・入力欄・前回の続き・着手できるタスクを置く    |
| 働く   | `kind: "work"`                                   | 舞台（`clamp(300px, 26vw, 600px)`）・中央の紙（最大 880px）・右の欄外（最大 260px）。入力欄は紙の下端に浮く1行         |
| 尋ねる | `kind: "work"` で、`conversationMoment` が `ask` | 働くと同じ配置。入力欄の場所にお伺いが出て、紙の中身が引く（見本は不透明度 0.32）                                      |
| 渡す   | `kind: "report"`                                 | 働くと同じ配置で、紙にレポートを出す。`conversationMoment` が `stumble` のときも渡すの姿勢で、紙の頭に失敗の表示を出す |

- 尋ねるで替わるのは入力欄の場所の中身と紙の濃さだけで、舞台の幅も紙の位置も動かない。お伺いはターンの途中に届くので、配置まで替えると「送ったときと閉じたときだけ」を破る。今の `docs/architecture/screen-design/conversation-phase.md` が尋ねるで中身を替えないのと同じ線引き。
- 過去のやり取りを見ているあいだは、そのやり取りの渡すの姿勢で出す。
- 雑談は姿勢ではなく、モード（`chatMode`）で分ける。紙を消して舞台を広げる形は、舞台を組む段が持つ。
- 新しい器は、旧い器の領域の比率（`use-conversation-layout.ts` の3本の仕切りと `tsukumo-layout-split:v1`）を使わない。

| 案                                                 | 物差し                                                                  | 判定     |
| -------------------------------------------------- | ----------------------------------------------------------------------- | -------- |
| `MainViewContent` から引き、尋ねるは中身だけ替える | 遷移の約束がすでにあり、新旧の器で同じ値を読む。状態が二重にならない    | 採る     |
| `conversationMoment` をそのまま姿勢にする          | `ask` と `work` がターンの途中で行き来し、閉じる前に配置が動く          | 採らない |
| 器の姿勢を新しい store に持つ                      | `MainViewContent` と同じ遷移を2か所で書くことになり、食い違う道ができる | 採らない |

### 論点 3: 右から重ねる紙を何の上に作るか・開閉を URL に載せるか

**採る: 今の画面の登録表（`src/browser/stores/location-hash.ts` の `SCREEN_LIST` と `src/browser/components/app/screen-registry.tsx` の `LAYOUT_SCREENS.overlay`）を、ほかの画面の唯一の表として使い続ける。重ねる紙として描く層は新しい器が持つ。紙の開閉は今と同じ `location.hash`（`#achievement` など）で表し、URL に載せる。**

- 新しい器の `Layout` は、会話の画面を隠さない。ほかの画面は、舞台の右の場所に紙として重ねて描く。紙の幅は `min(100% - 64px, 1000px)` で、レポートの紙を左に 64px 残す（見本の `.over`）。
- 重ねる紙は、タスク・成果・使用量・キャラ・設定の5枚。今の表にあるのはキャラ（`character`）・トークン（`token-usage`。紙の名前は「使用量」）・成果（`achievement`）の3つで、タスク（`tasks`）と設定（`settings`）は表に足す。旧い器では、足した2つも今の画面と同じく全面に重ねて出す。
- 見本帳（`design`）は紙にせず、今のまま全面で出す。帯にもメニューにも出さない。
- 紙の下にある会話の画面の紙と欄外は、紙を開いているあいだ操作できなくする（`inert`）。舞台と部屋の頭は操作できるまま残し、部屋の頭の札で紙を直に切り替えられるようにする（見本のとおり）。
- 紙は Esc と覆いを押したときに閉じ、hash を会話の画面へ戻す。閉じたら、フォーカスを開いた入口へ戻す。ブラウザの「戻る」でも閉じる。
- 探す（⌘K）とセッションの一覧は URL を持たない（`location-hash.ts` の「新しく作るダイアログは URL を持たない」のまま）。
- Astryx の `Drawer` は `<dialog>` を全面のモーダルとして開くので、舞台を操作できるまま残す形に合わないかもしれない。紙の部品を `ui/` に足す段で確かめ、合わなければ Astryx の `Layer` の上か素の要素で組む。

| 案                                                 | 物差し                                                                                                     | 判定     |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | -------- |
| 今の登録表と hash の上に作り、描く層だけ新しくする | 画面の一覧が1つのまま。読み直し・戻る・リンクが今と同じに効き、`pack`・`date` の付随の引数もそのまま使える | 採る     |
| 登録表と別の、紙だけの新しい層（URL を持たない）   | 画面の一覧が2つになる。読み直すと紙が閉じ、成果の日やキャラの選択を URL で名指せなくなる                   | 採らない |
| 見本の試作のとおり検索引数（`?sheet=`）に載せる    | hash の経路と二重になり、`location-hash.ts` の「書き方を決める唯一の場所」が崩れる                         | 採らない |

### 論点 4: Astryx（`@astryxdesign/core`）を使い続けるか

**採る: 使い続ける。部品の振る舞い（フォーカスの扱い・キー操作・読み上げ）は Astryx に任せ、見た目はテーマ（`src/browser/components/ui/theme-root/tsukumo-theme.ts`）とトークンで見本に寄せる。舞台・紙・欄外・重ねる紙の置き場は Astryx の部品ではなく、新しい器の CSS が持つ。**

テーマで届くかは、入っている版（`@astryxdesign/core` 0.7.10）の型と組み立て物を読んで確かめた。

- テーマの `TokenName` には、色の `--color-*` のほかに、字の段（`--font-size-*`・`--font-family-body`・`--font-family-heading`）・角丸（`--radius-*`）・影（`--shadow-low`・`--shadow-med`・`--shadow-high`）・動き（`--duration-*`・`--ease-*`）がある。見本の本文 16px・角丸 12px・浮く面の影・入る動きは、どれもテーマの値で写せる。
- `TokenValue` は `[light, dark]` の組を受け、`light-dark()` に組み立てる。`Theme` は `mode` に合わせて `data-theme` を立て、`reset.css` がそれを `color-scheme` に写す。組み立て物の規則は `@scope ([data-astryx-theme="tsukumo"]) to ([data-astryx-theme])` で、入れ子のテーマで区切られる。見本の昼の紙（`?tone=day`）は、紙の根に `Theme` を `mode="light"` で重ねて出す。入れ子で正しく効くかは、トークンの段で見本帳を昼で撮って確かめる。
- テーマで届かないのは、Astryx に対応する部品が無いものだけ。舞台の背景と覆いのぼかし、立ち絵の縁のぼかし、吹き出し、紙と重ねる紙の置き場がそれに当たり、新しい器の CSS が持つ。
- 新しい器では、字の段・角丸・影・動きの正典を tsukumo のトークンへ戻し、テーマがそれを写す（ADR 0053 論点 1 の向きを逆にする）。見本の値は Astryx の既定（本文 14px・角丸 10px）と違い、Astryx を正典にしたままでは見本に届かない。旧い器のあいだは、論点 1 の `:root[data-shell="stage"]` で値を分ける。
- `ui/` に足す部品は、Astryx に同じ役の部品があればその上に載せる。探すは `CommandPalette`、仕事と雑談の2つ切り替えは `SegmentedControl`、キーの札は `Kbd` が候補になる。

| 案                                         | 物差し                                                                                                   | 判定     |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------- | -------- |
| 使い続け、テーマとトークンで寄せる         | 部品の振る舞いと読み上げを作り直さずに済む。見本の値はテーマの口で写せる                                 | 採る     |
| 新しい器では Astryx を外し、CSS で作り直す | フォーカスの罠・一覧のキー操作・ダイアログの読み上げを自前で持ち直すことになる。`ui/` の境界も二重になる | 採らない |
| ADR 0053 の向き（Astryx が正典）のまま使う | 本文 16px・角丸 12px に届かず、見本と食い違う                                                            | 採らない |

### 論点 5: 狭い幅（760px 以下）で部屋の頭の入口をどこに畳むか

**採る: 見本のとおり、狭い幅では部屋の頭を1行の頭（顔・状態・やり取りの題・「≡」）に縮め、入口はすべて「≡」から開く探すの一覧に畳む。**

- 探すの一覧の「移る」の群に、重ねる紙の5枚（タスク・成果・使用量・キャラ・設定）と、仕事と雑談の切り替えを載せる（見本のとおり）。部屋の頭にあったセッションの切り替えも、同じ群に「セッションを切り替える」の1行として載せる。見本の狭い幅には無い項目だが、ほかに置き場が無いので足す。
- 「文脈 n%」の札は、狭い幅では頭に出さない。一覧の「使用量」から使用量の紙を開く。
- 重ねる紙は全面に出す（見本の `.N .over` は `inset: 0`）。閉じたら一覧ではなく会話の画面へ戻る。
- ⌘K は広い幅と同じく、狭い幅でも探すを開く。

| 案                                       | 物差し                                                                     | 判定     |
| ---------------------------------------- | -------------------------------------------------------------------------- | -------- |
| 「≡」から開く探すに畳む                  | 見本のとおり。入口の一覧が広い幅の探すと1つになり、項目を足す口も1つで済む | 採る     |
| 今の引き出し（`nav-drawer`）に札を並べる | 探すと引き出しの2つに同じ項目を書くことになる                              | 採らない |
| 下端にタブの帯を置く                     | 入力欄と答え待ちのカードが使う下端の高さを奪う                             | 採らない |

## 移行の順

1. **トークンとテーマを入れる。** 見本の値を `:root[data-shell="stage"]` に書き、テーマが写す向きに組み直す。昼の紙のテーマも入れる。
2. **`ui/` の部品を足す。** 重ねる紙・札・2つ切り替え・探すの一覧の行を、Astryx の部品の上に作る。
3. **器の骨組みを印の裏に作る。** `Layout` で印を見て新しい器を描き、渡すの姿勢から組む。続けて、迎える・働く・尋ねる、狭い幅、舞台を足す。
4. **入口を移す。** 部屋の頭と探すを作り、登録表に `tasks`・`settings` を足し、5枚の紙を作る。
5. **既定にして旧い器を消す。** 論点 1 の3つの条件がそろってから。

## 採らなかった案

- **ほかの画面を今のまま全面に重ねる。** 舞台とレポートの紙が消え、キャラクターと一緒にいる感じが画面を移るたびに切れる。
- **旧い器を一度に置き換える（並べて走らせない）。** 姿勢・紙・入口の段が全部そろうまで、画面が中途半端な形で既定になる。
- **見本の試作のとおり、局面と紙を検索引数（`?moment=`・`?sheet=`）で持つ。** 局面はセッションの状態から導く値で、URL に置くと実際の状態と食い違う。

## 残すこと

- Astryx の `Drawer` を、舞台を操作できるまま残す紙に使えるか（論点 3）。紙の部品を足す段で確かめる。
- 入れ子の `Theme`（`mode="light"`）で昼の紙が見本どおりに出るか（論点 4）。トークンの段で確かめる。
- 「≡」の探すに載せるセッションの切り替えの形（論点 5）。狭い幅を組む段で撮って決める。

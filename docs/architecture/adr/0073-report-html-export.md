# 最終レポートを HTML の1ファイルに書き出す（2026-11-18）

ステータス: 採用

**確定した最終レポートの操作に「HTML で保存」を足す。押すと、そのとき画面に描いているレポートを外部の読み込みの無い1つの HTML ファイルにして、サーバが `~/Downloads/` に書く。結果は押した場所のすぐ下に1行で返し、「ブラウザで開く」「Finder で表示」を添える。「広げる」とは同じ操作の組に並べ、広げた板では下端の帯の「閉じる」の左に置く。**

見本は `docs/history/mockup/report-export-2026-11-18/`（`index.html` が画面、`export-sample.html` が書き出したファイル）。

## 何が困っていたか

最終レポートは会話の画面の中でしか読めず、人に渡す・あとで読み返す・印刷するには、画面を撮るか本文を写すしかなかった。利用者から、最終レポートを HTML で書き出すボタンと機能がほしいと頼まれた。

## 決めたこと

### 1. 置き場は「広げる」と同じ操作の組

| 案                                               | 種類   | 物差し                                                                       | 判定     |
| ------------------------------------------------ | ------ | ---------------------------------------------------------------------------- | -------- |
| 「広げる」の左に並べ、板では「閉じる」の左に置く | 仕組み | レポート全体への操作が1か所にまとまる。板の頭に新しい行を足さない            | 採る     |
| 「広げる」を「…」のメニューに替えて中に入れる    | 仕組み | 頻度の高い「広げる」が1手増える                                              | 採らない |
| レポートの末尾に置く                             | 仕組み | 長いレポートでは転がさないと届かない。締めのセリフと次の一手の札の間に挟まる | 採らない |

- 紙の頭の右端は `[HTML で保存] | [広げる]` の順で、間に縦線を1本置く。2つとも「広げる」と同じ控えめな字のボタン（`ghost-hover-rule-soft`・`label` の大きさ）で、印と字の1つの形にする。印は下向きの矢印と下線の線画で、「広げる」の印（`MaximizeIcon`）と同じ置き場に足す。
- 広げた板の頭には操作を足さない。下端の帯で `[HTML で保存] [閉じる]` と並べ、「閉じる」と同じ `outline-surface` にする。
- 760px 以下の狭い画面では、2つとも字を隠して印だけにし（`aria-label` は字のまま）、押せる大きさは今の「広げる」と同じに保つ。
- 出すのは確定した最終レポートだけ。書いている途中の草稿・段のまとめ（中間レポート）・雑談には出さない（「広げる」を出す場面と同じ）。

### 2. 結果は押した場所のすぐ下に1行

- 押すと字が「保存しています」に替わり、押せなくなる。済むと「✓ 保存した」に替わり、紙の頭のすぐ下（板では下端の帯のすぐ上）に1行を出す: `✓ 保存した  <パス>  [ブラウザで開く] [Finder で表示] [×]`。パスは長いと頭を省いて末尾（ファイル名）を残す。
- 失敗したら同じ位置に `保存できなかった  <理由の1文>  [もう一度] [×]`。
- 1行は × で消すか、同じ会話の流れに次のやり取りが来るまで残る。別の場所（入力欄のそば・知らせの帯）には出さない。
- キーは割り当てない（押す頻度が低く、入力欄のキーとぶつけたくない）。

### 3. 書き出すのは画面の DOM の写し、書くのはサーバ

| 案                                                                | 種類   | 物差し                                                                                      | 判定     |
| ----------------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------- | -------- |
| 画面が描いた DOM を写して送り、サーバが画像を埋めてファイルに書く | 仕組み | 図・表の描き方を二重に持たない。そのとき見えている形がそのまま残る                          | 採る     |
| サーバがレポートの部品の一覧から HTML を組み直す                  | 仕組み | 部品ごとの描き方を2か所に持つ。図（Mermaid・Graph）の描画をサーバに足す                     | 採らない |
| 画面がブラウザのダウンロードで保存する                            | 仕組み | Orca のタブでダウンロードがどう扱われるか分からない。棚の画像を画面から埋めると往復が増える | 採らない |

- 画面は、紙の中のレポート（`Report` の根）を複製し、画面の操作だけの要素を落とし、動く部品をそのときの形で止め、効いている CSS の規則だけを集めて、`/ws` のコマンドで送る（本文と CSS は `/rpc` の上限 64 KiB を超えうるので）。
- サーバは、写しの中の棚の画像（`/report-image/` の経路）を棚のファイルから読んで `data:` の URL に替え、表紙の帯と書き出し用の色のトークンを足した1つの文書にして書く。棚に無い画像は「画像を読めなかった: パス」の1行に替える。
- 保存先は `~/Downloads/`。ファイル名は `tsukumo-report-<タスクID、無ければセッションの題を短くしたもの>-<YYYYMMDD>-<HHmm>.html` で、同じ名前があれば末尾に `-2` から足す。
- 「ブラウザで開く」は `open <パス>`、「Finder で表示」は `open -R <パス>` をサーバが起こす。ホストの `openFile`（Orca ではエディタで開く）は使わない。
- 書いた本文はサーバのログに出さない（パスと字数だけ）。書き先は同じマシンのディスクなので、`docs/requirements/purpose-and-scope.md`「2.2」の会話内容の外部送信には当たらない。
- 会話を別の場所へ書き出すことになるので、`docs/coding-standards/conversation-content.md` の「書き出してよいもの」の4つ目の例外として足す（2026-11-18 に利用者が決めた）。押したときに1件ずつ書くだけで、tsukumo が自分から書くことはしない。

### 4. 書き出したファイルの形

中身は画面のレポートと同じで、削る・並べ替える・言い換えることはしない。

| 部品・欄                                 | 扱い       | ファイルでの形                                                         |
| ---------------------------------------- | ---------- | ---------------------------------------------------------------------- |
| 表紙の帯                                 | 足す       | 種類・タスク ID・終わり方・作業の名前・依頼の1行目・日時               |
| 結論・確かめたこと・節・表・コード・図   | そのまま   | 描いた DOM。図は描いた SVG                                             |
| 画像（Picture・Compare の画）            | 埋め込む   | `data:` の URL                                                         |
| 畳んだ部品                               | 開閉できる | `<details>` のまま。印刷では開いて出す                                 |
| 押すと拡大する図・画像                   | 開閉できる | JS を使わず、押すと画面いっぱいに開き、もう一度押すと閉じる            |
| Tabs・前後の切り替え                     | 止める     | 保存したときに見えているタブ・前後の見せ方のまま。切り替えの口は落とす |
| ParameterSlider・ChoicePicker            | 止める     | 保存したときの値で描いた形。部品は値の1行に替える                      |
| `path:line` のリンク                     | 字にする   | 押せない等幅の字                                                       |
| コピーのボタン・欄外注の札・「分かった」 | 落とす     | 画面の操作だけのもの                                                   |
| 締めのセリフ・待ちの一言・立ち絵・背景   | 落とす     | キャラクターの声は画面の側に属し、レポート本文はそれだけで読める       |

- 紙の色は開いた環境の明暗（`prefers-color-scheme`）に合わせる。明るい環境が既定で、暗い環境では今の画面の色に寄せる。
- 印刷（`@media print`）では背景と影を落とし、図・表・コードの途中で改ページしない。
- 640px 以下では余白を詰め、前後の比べを縦に積む。

## 採らなかったこと

- **PDF・Markdown での書き出し**: 頼まれたのは HTML で、PDF は書き出した HTML をブラウザで印刷すれば作れる。
- **雑談・中間レポートの書き出し**: 頼まれたのは最終レポートで、会話のアーカイブ（4.9）とは別の機能。
- **選んでいないタブ・隠した前後の片側も写す**: 画面は選んだタブと見せている側だけを DOM に描く。隠れた中身まで常に描くと、見えない Mermaid が幅 0 で測られて図の幅が崩れ、書き出しの時だけ描き直すと決定3の「画面の DOM の写し」を外れる。見たい形を選んでから保存すれば、その形で残る（2026-11-19 に利用者が決めた）。
- **キャラクターの立ち絵や名前を入れる**: 渡す相手にとってレポート本文だけで足り、画面の外へキャラクターの素材を持ち出さない。

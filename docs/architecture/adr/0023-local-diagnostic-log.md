# 不具合の経緯は手元の1本の JSONL に、決まった語だけで残す（2026-10-04）

**診断ログは `~/.tsukumo/diagnostic/<日付>.jsonl` の1本だけにし、依存を足さずに既存の JSONL の
書き手で書く。** 1行は判別可能な合併型（`DiagnosticRecord`。流れの判別子は `flow`）で、値は数・真偽・
決まった語だけにし、任意の文字列を受ける欄を型に作らない。日付のファイルは14日を過ぎたら消す。

## 何が困っていたか

不具合の経緯が手元に残らなかった。サーバの `catch {}` は記録なしで失敗を捨て、stderr への出力は
ほぼ起動時の前提不足だけで、orca のタブを閉じると消える。`~/.tsukumo/` の JSONL（トークン・
コンテキスト・体験の数）は集計のためのもので、「何がどの順で起きたか」は追えない。

## 決めたこと

- **置き場は1本。** 流れ（イベントの足跡・握りつぶしていた失敗・ブラウザの例外）ごとにファイルを
  分けず、`flow` で見分ける。経緯は流れをまたいで時刻の順に並べて読むので、1本のほうが突き合わせが要らない
- **会話は型で締め出す。** 欄は数・真偽・リテラルの合併だけ。エラーの `name`・code も決まった語に
  写してから入れ、`error.message` は入れない。SessionEvent の足跡に入れるのは種類・時刻・駆動の代だけ
- **書き口は core が型を持ち、配線が adapter を作って渡す**（トークン消費・体験の数の記録と同じ形）。
  イベントは1ターンで数百届くので、足跡は 100 ミリ秒ごとに束ねて1回で書き、閉じるときに残りを書く
- **駆動の代はセッションを持つ係が数える。** プロセスを起こしてから何代目か（1から）で、起こし直すと
  1つ増える。プロセスをまたいだ通し番号は持たない
- **掃除は起動のたびに1回。** 何日も起こしたままにすると古いファイルがその間だけ残るが、量が小さいので
  日の替わり目を見張る仕組みは足さない

## 採らなかった案

- **pino などのロガーを入れる**: 任意の文字列を受ける口なので、会話の混入を型で防げない。単一利用者で
  量も少なく、ローテーションや出力先の切り替えは要らない
- **OpenTelemetry**: 外へ送る経路（エクスポータ）が前提の仕組みで、`docs/coding-standards.md`
  「会話内容の扱い」の「外部に送らない」とぶつかる
- **stderr に出す**: タブを閉じると消え、あとから経緯を追えない。文字列を出す口なので会話も混じりうる
- **場所の名前を1つの大きな語の合併にする**: 失敗の場所を足すたびに shared の1か所が膨らむ。場所の語は
  流れを足すタスクが、機能ごとの語の合併として持つ

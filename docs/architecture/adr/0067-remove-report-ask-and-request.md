# レポートの「聞く」「頼む」を外す（2026-11-18）

ステータス: 採用

**レポートの部品を指して会話へ返す「聞く」「頼む」の操作を丸ごと外す。内容部品・表の行・案・主張を押して出す口、選んだ字の横の「聞く・頼む」、余白の札と狭い幅のシート、その場の入力欄、付箋と入力欄の上の頼みごとの列、聞いた答えを部品の横へ戻す仕組み、「聞 n」「頼 n」の印、余白の案内（初回の説明）を消す。レポートの末尾の次の一手の行（ADR 0051 の「続き」）と、お願いの選択肢の下書き、字を選んで入力欄の頭へ引用を入れる「引いて聞く」は残す。サーバ側の補足メッセージの仕組みと手続きの形（送り方 `ask`・`ReplyTarget`）は変えない。**

この ADR は、ADR 0051 の聞く・頼むの論点、ADR 0055 の全体、ADR 0064 論点 5 と論点 2 の余白の案内を取り下げる。どれも本文は書き換えず、取り下げた論点にこの ADR を指す1行を足す。

## 何が困っていたか

- 聞く・頼むは、内容部品の外枠・表の行・`Options` の案・`Claims` の主張・選んだ字の5か所から出ていた。部品ごとに口と札と印が付き、レポートの見た目と実装の両方が込み入っていた。
- 利用者は 2026-11-18 に「あまり使わなかった」と振り返った。

## 利用者が決めたこと（2026-11-18）

- レポートの「聞く・頼む」のインタラクティブを削除する。理由は、あまり使わなかったことと、いろいろなコンポーネントについていてごちゃついていたこと。

外す範囲と残す範囲の線引き（下の「決めたこと」）は書き手の判断。

## 決めたこと

### 論点 1: 外すもの

**採る: レポートから会話へ「聞く」「頼む」を返す口と、その結果を見せる物を全部外す。**

| 外すもの                                                                      | 元の決定                                           |
| ----------------------------------------------------------------------------- | -------------------------------------------------- |
| 内容部品の題の行・本体・表の行・案・主張を押すと出る「聞く・頼む」            | ADR 0051 論点 1、ADR 0055 論点 2                   |
| `Options` の「この案で進める」、`Claims` の「確かめて」（頼むの書き始めの字） | ADR 0051 論点 1、ADR 0055 論点 1                   |
| その場の入力欄（聞く／頼むの切り替え）と、余白の札・狭い幅のシート            | ADR 0055 論点 3                                    |
| 付箋の store と、入力欄の上の頼みごとの列・まとめた下書き・終わったら頼む     | ADR 0051 論点 4・5                                 |
| 聞いた問いと答えを部品の横の札へ束ねる仕組み                                  | ADR 0051 論点 3、ADR 0055 論点 3                   |
| 単位の横とやり取りの列の節の行の「聞 n」「頼 n」                              | ADR 0055 論点 3                                    |
| 札のある部品にだけ余白の列を空ける規則と、札の横の塊の右の空き                | ADR 0064 論点 5                                    |
| 初回の説明の「余白の案内」（`reply-margin`）                                  | ADR 0055 論点 2、ADR 0062 論点 12、ADR 0064 論点 2 |

- 余白の列が無くなったので、内容部品はいつも本文の幅いっぱいに描く。
- 前のセッションの記録に残った、指した所つきの補足メッセージは、ほかの補足メッセージと同じく流れの投稿と親のやり取りの経過に出す（部品の横には戻さない）。
- 端末の好みに残った `reply-margin` の「見た」の印は、読むときに落とす。ほかの説明の印は保つ。

### 論点 2: 残すもの

**採る: 押すと入力欄に下書きを入れるだけで送らない口と、選んだ字を引用する口は残す。**

- レポートの末尾の次の一手の行と、お願いの選択肢の札は、ADR 0051 論点 6 と ADR 0064 論点 6 のまま。
- レポートが入力欄へ返す口 `ReplyPort` は、下書きを後ろへ足す（`appendDraft`）と頭へ引用を入れる（`prependDraft`）の2つに縮める。問いを送る口（`ask`）は外す。
- 字を選んで入力欄の頭へ引用を入れる「引いて聞く」は、ADR 0055 論点 4 で「聞く・頼む」の口に吸収されていた。吸収の前の形に戻し、本文のどこで選んだ字にも「引いて聞く」を1つ出す。口は選んだ字の行の高さで、本文の右端にそろえる。
- 表の並べ替え・絞り込み・つまみ（ADR 0039 論点 7 の見え方だけの操作）は、聞く・頼むと別の操作なので変えない。

### 論点 3: サーバと手続きは変えない

**採る: 補足メッセージの仕組み、`prompt` の送り方 `ask` と指した所 `ReplyTarget`、記録の形は変えない。手続きの版（`PROTOCOL_VERSION`）も上げない。**

- ブラウザは送り方 `ask` を送らなくなる。受ける側を残すのは、手続きの形を変えずに外せる範囲をブラウザに限るため。受ける側を外すかは、別に決める（下の「残したこと」）。

| 案                                              | 種類   | 物差し                                                                       | 判定     |
| ----------------------------------------------- | ------ | ---------------------------------------------------------------------------- | -------- |
| ブラウザの口と見せる物を外し、サーバは変えない  | 仕組み | 手続きの版が変わらない。古い記録の指した所つきの補足メッセージも読める       | 採る     |
| サーバの送り方 `ask` と `ReplyTarget` まで外す  | 仕組み | 呼ばれない口が残らないが、手続きと記録の形が変わり、古い記録の読み方を抱える | 採らない |
| 口を1か所（例えば部品の題の行だけ）に絞って残す | 仕組み | 部品ごとに付くごちゃつきは減るが、使わなかった操作が残る                     | 採らない |

## 残したこと

- サーバ側で呼ばれなくなった口（送り方 `ask` と `ReplyTarget` の受け取り、補足メッセージの包みの指した所の行）を外すか。外すなら手続きの版と古い記録の読み方を合わせて決める。

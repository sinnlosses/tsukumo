# ワークプラン: 入力・段の進め方・委譲中の段

戻り: `docs/architecture/display.md`「ワークプラン」

**作業中に「いまどの段にいて、あと何が残っているか」を画面で追えるように、claude からワークプラン（段の並びと
今の位置）を MCP ツール `work_plan` で受け取る**（2026-09-29 ユーザー決定。用語は `docs/glossary.md`
「ワークプラン」「work_plan ツール」）。`progress` の塊は `report` を渡したときにしか出ず、依頼の手順は
ツールの実行を1回ずつ並べるだけなので、作業中の段はそれらでは見えない。Claude Code の TodoWrite を
拾う案とツールの手順から段を推し量る案は採らない（tsukumo から縛れない・推測になる）。

- **入力は `{ phases, current, finishedInGroup, phaseSummary }` で、毎回段の並びごと渡す**（引数の意味は
  `docs/architecture/workflow-contract.md`「口」。`phases` を省く呼び出しは作らない）。
  並列の段は「同時に走る段は、並列の段で受ける」、`phaseSummary`（段のまとめ）は「段が移ったときの
  中間レポート」。空白だけの名前は不可。形の崩れ・`current` が要素の数を超えた呼び出し・段のまとめの足りない
  呼び出しは差し戻す。メインの呼び出しだけを受け、サブエージェントの呼び出しは捨てる。
  戻り値は `"ok"` で、ターンは閉じない。**仕事のときだけ載る**
- **段は1つずつ進める**（2026-10-04 利用者の決定）。同じ依頼の中で同じ段の並びのまま、済んだ段（並びを平らにして数える）を
  1回で2つ以上増やした呼び出しは差し戻す（`src/server/work-plan/core/work-plan-review.ts`）。飛ばした段は
  段のまとめを持たず、中間レポートがその段だけ抜けるため。覚えるのは同じ依頼で最後に受け付けたワークプランだけで、
  依頼で忘れる。委譲中に返却で進めた段も同じ決まりで数え、一足飛びの判定は返却で進んだ位置を起点にする
  （「委譲中の段は、委譲先の返却で tsukumo が進める」）。差し戻した呼び出しは結果まで預かって捨てる
  （transcript から組み直すときも同じ）
- **同時に走る段は、並列の段で受ける**（2026-10-07 利用者決定。用語は `docs/glossary.md`「並列の段」）。並列にできるかを決めるのは
  ワークプランを渡す側で、tsukumo は段の並列を推し量らず、受けて描くだけ。口の形はスキルの書式（`## やること`・`tw`）に依存しない
  （`phase_result` の引数は契約の形で、スキルの書式ではない）
  - **形**: 並列の段は `phases` の1要素で、2つ以上の段の名前を重ならずに並べる。段の番号は並びを平らにした読み順で振る
    （`[A, [B, C], D]` なら B が 2、C が 3）。位置は1つの数で言う
  - **今の段の集合**: `current` の要素が段ならその1つ、並列の段ならその中で `finishedInGroup` に無い段のすべて。
    `finishedInGroup` は並列の段を指していないときは空で、並列の段の中の段を全部入れることもできない（全部済んだら `current` を進める）
  - **済ませ方**: 並列の段の中の段を1つ済ませるたびに、その名前を `finishedInGroup` に足す。メインは `work_plan` を呼んで足し、
    委譲中は委譲先の `phase_result` を受けた tsukumo が同じ形で足す。並列の段の最後に残った段を済ませると `current` を1つ進め、
    `finishedInGroup` を空に戻す。委譲先がどの順で返っても、返却の段の番号かメインの呼び出しが済んだ段を名指すので、
    後ろの番号から済んでも帯は戻らず取りこぼさない。どの委譲先が返したかは見ず、済んだ順も推し量らない
  - **一足飛びの判定**は、平らにした並びで済んだ段の数で行う（「段は1つずつ進める」）。並列の段に入る呼び出しで、同時に中の段を
    済ませたことにすると2段増えるので差し戻す
- **段はファイル単位・操作単位で切らず、作業のまとまりで切る**（2026-09-29 ユーザー決定）。この粒度は
  ツールと引数の説明で伝える（仕事の append の節「ワークプラン〔tsukumo〕」には重ねない）。委譲中は委譲先の段を帯の段に
  1つずつ合わせ、その範囲をメインが `work_plan` で渡す（「委譲中の段は、委譲先の返却で tsukumo が進める」）
- **呼ぶ条件は条として書き、差し戻しでは縛らない。** 条は「作業をするターンは段の数にかかわらず呼ぶ。
  作業のまとまりが1つなら1段のワークプランを渡す（札には `1/1` のように出る）。答えるだけ・1回調べて答える
  だけの依頼では呼ばない」（2026-09-30 ユーザー決定）。機械で縛れるところは機械に寄せた（雑談では
  載らない・0段のワークプランは形の検査が受け付けない）。呼ばなかったことはターンの終わりにしか判定できず、
  そこで差し戻すと着手時に渡すはずのワークプランを後から書かせるだけになる。呼ばなくても札と一覧は
  ワークプランの無い表示のままで壊れない
- **委譲中の段は、委譲先の返却で tsukumo が進める**（2026-10-10 利用者決定。メインが返却のあとに `work_plan` を呼び忘れても
  帯の段の時間が実際と離れないように。境界と経緯は `docs/architecture/adr/0024-no-skill-dependency.md`「2026-10-10 の改訂」、
  返却の書式と規則は `docs/architecture/workflow-contract.md`「委譲の返却」、用語は `docs/glossary.md`「委譲の返却」「委譲先の段の範囲」）。
  `phase_result` の引数の形は契約の持ち物で、スキルの依頼文は契約を参照する側なので、受けてもスキルには依存しない
  - **並びと委譲先の段の範囲はメインが `work_plan` で渡す。** 「計画」「受け入れ」を段にするかも渡す側が決め、範囲の前後に置いてよい。
    帯の段と委譲先の段は1つずつ対応し、**範囲の前（前）・範囲（本）・範囲の後ろ（後）の群ごとに1から数える**（2026-10-15 利用者決定。
    受け入れ以降のどこにいるかも数で分かり、委譲先の番号との取り違えが起きないように）。
    本の段は範囲の先頭からの番号と範囲の段の数 `N` で数え、委譲先の段の番号と同じ。前・後の段〔計画・受け入れ・振り返り・送り出し〕も
    群の中の番号と段の数で数え、「前 1/1」「後 2/3」のように群の名を前に付ける。範囲の無い依頼は群が1つで、群の名を付けない。
    帯・札・現在の手順・スマホの頭・中間レポートの見出し・時間の表が同じ式を使う。
    群は範囲の位置だけで決め、後の始まりを宣言する欄は持たない（古い記録も同じ規則で読み戻せる）。
  - **帯は群の先頭の丸の前に群の名を小さく置き、前の群の丸とは線でつながず間を空ける。** 今いる群の名は差し色で、
    右肩に今の位置「後 1/3」を経過の前に出す。ワークプランの一覧は群ごとの行に群の名を置き、印を帯と同じ丸の番号（済んだ段は ✓）にする。
    並列の段の番号は、先頭と末尾を「–」でつなぐ（「2–3」。名前をつなぐ「・」と見分けるため。並列の段の中の段は平らにした並びで隣り合う）。
  - 計画を頼む最初の呼び出しは `{ first }` だけの範囲（`pending`）で渡し、そのあいだ前の段だけが番号を持つ。
    範囲の先頭の丸が「…」、その後ろの丸が「・」で、今の段が範囲の先頭から後ろにあるあいだ右肩は位置を出さない。`phase_result` は帯を動かさない。
    `phase_result` を受けたあとの範囲の無い・`pending` の呼び出しと、範囲の段の数が `count` と違う呼び出しは差し戻す。
  - 段の数の言い方は2つに分ける。「本 2/3」「後 3/3 済」のような分数は番号の話で群の中の段だけを数え、
    「5段すべて済み」「5段のうち3段済み」のような済み具合は全部の段（範囲の外を含む）で数える（範囲の外が残っていれば「すべて済み」と言わない）。
  - 範囲があるあいだ、`speak` の `phase`（セリフが番号で言う委譲先の段）が範囲の外なら差し戻す。本文の段の番号は読まない
    （セリフで番号を言うのは本の段だけで、前・後の段は名前で言う。これは案内で、検査は `phase` の値にだけ掛かる）。
    範囲の端をまたぐ並列の段も差し戻す。範囲を宣言していない（`pending` を含む）依頼では返却は帯を進めない
  - **委譲先の `phase_result` の `finished`・`skipped` が届いたら、tsukumo が `phase` に当たる帯の段を済ませる**。区切りの時刻は受け付けた呼び出しの時刻。
    段が今の段の集合に入っていなければ（一足飛び・もう済んだ段・差し戻しのやり直し）帯は動かない。
    `stopped`・範囲の無い依頼・`count` が宣言した範囲の段の数と違う呼び出しも帯を動かさない。帯を閉じるのは `report` の `workPlanClosing` だけ
  - **メインの `work_plan` とは二重に進まない。** メインは位置ごと渡すので、`phase_result` で進んだあとに同じ位置を渡す呼び出しは「同じ段のまま」。
    メインが並びや位置を組み替えたら、メインの呼び出しが帯を決める
  - **`phase_result` が帯の段を済ませたとき、段のまとめは空のまま届く。**
    その段はまとめ待ちの段になり、メインが同じ位置で渡す `work_plan` の `phaseSummary`（省けない）がその段の中間レポートになる
    （引数と帯の動かし方は `docs/architecture/workflow-contract.md`「スキルの契約」。飛ばした段の描き方は次の項）
  - **飛ばした段は、済んだ段と見分けて同じ面で描く**（2026-10-16 設計。印の付け方は `docs/architecture/workflow-contract.md`「スキルの契約」の「飛ばした段の印の決まり」で、
    どちらの口で付いた印も同じに描く）。飛ばした段は済んだ段の一種で、位置・線・番号・済み具合の数え方は済んだ段と同じ。変えるのは印と色だけで、新しい色は足さない
    - **丸**（帯・スマホの頭の点・一覧の頭のワークプラン）: 「✓」の代わりに「/」を出し、済んだ段の差し色の地と字をやめて、地なし・`--rule` の破線の枠・字 `--ink-quiet` にする。丸の寸法と線のつながりは済んだ段と同じ。
      読み上げと `title` の接尾は「（済）」の代わりに「（飛ばした）」
    - **狭い画面の「済んだ段 · 中間レポート」の一覧**の行と板の頭の印も、飛ばした段は「✓」の代わりに「/」を `--ink-quiet` で出す
    - **一覧の頭のワークプランの名前**は取り消し線と `--ink-quiet`（帯の丸は名前を今の段しか出さない）
    - **帯の段の吹き出し**: 名前の行は「/ 段の名前」、状態の行は「飛ばした · 所要 …」、段のまとめ（飛ばしたわけ）は済んだ段と同じに出し、「この段の手順へ」は出さない
    - **中間レポートは出す。** `docs/architecture/workflow-contract.md` が飛ばした段にも段のまとめ（飛ばしたわけ）を必須にしているため、出さないと契約と食い違う。
      目録の1行は「中間レポート · 1/3 段の名前 · 飛ばした · 所要 0秒」、畳んだ `<summary>` は「中間レポート: … · 飛ばした · 所要 …」。「中間レポートは所要を必ず出す」は保つ
    - 同じ名前の段は印を見分けない（飛ばした段を名前で持つため）
  - **委譲ゲート**: 仕事のセッションで、同じ依頼にメインの受け付けたワークプランがあるときだけ効く（雑談の委譲と、`work_plan` を呼ばない依頼の返却では
    立てない。下ろす口が無い依頼で作業のツールを拒み続けないため。範囲の宣言は条件にしない）。返却が届いたら印を立て、メインの `work_plan` が受け付けられたら下ろす。
    印が立っているあいだ、メインの作業のツール（`Bash`・`Edit`・`Write`・`Agent`・`SendMessage`・`TaskStop` など）を拒み、
    読み取りのツール（`Read`・`Grep`・`Glob`・`ToolSearch`）と tsukumo の MCP ツール（`speak`・`work_plan`・`report` など）は通す。
    返却の中身は読まず届いた事実だけで立てるので、`phase_result` を呼ばなかった返却・差し戻しのやり直し・`stopped` の返却でも立ち、
    同じ位置のまま `work_plan` を呼べば下りる。並列の段の返却が続けて届いても `work_plan` 1回で下りる。差し戻された `work_plan` では下りない。
    委譲先のツールは対象にしない。印はセッションを起こし直すと下り、組み直しでは戻さない。
    拒否文の末尾と受け付けた `work_plan` の戻り値は、返却で進んだあとの帯の位置（今の段。範囲があれば範囲の中の段だけ番号つき）を返し、
    返却を運ぶメインの入力にも同じ文を土台にした注記を添える（`docs/architecture/workflow-contract.md`「委譲の返却」）。
    帯を進めるのは `phase_result` で、委譲ゲートは「メインが返却を読み、並びと範囲を確かめてから次の段を送る」ことを保証する保険。
    `phase_result` を呼ばない委譲先でも、ワークプランを渡した依頼なら委譲ゲートがメインに `work_plan` を呼ばせるので帯は止まらない
  - **組み直しでは返却で進めた帯は戻らない。** `phase_result` の呼び出しは委譲先の transcript にあり、組み直しはメインの transcript だけを読むので、
    組み直した会話の帯はメインの `work_plan` が決める位置になる
  - **委譲先の `SendMessage` の合図は帯を動かさない**（2026-10-06）。合図は吹き出しの途中の一言として残し、tsukumo は読まない。
    バックグラウンドタスクの顔ぶれの変化も帯を動かさない。段の所要の短さで呼び忘れを差し戻す形は、本当に短い段と見分けられないので採らない
  - **防げないこと**: `phase_result` を呼ばない委譲先の段は、メインの `work_plan` でしか進まない（委譲ゲートが呼ばせるが、区切りの時刻はメインが呼んだ時刻になる）。
    `phase_result` の `phase` が実際に済ませた段と違っても、tsukumo は見分けない

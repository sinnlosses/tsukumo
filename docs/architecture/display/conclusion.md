# 出力の分離（セリフと詳細）: /clear・レポートの構造・お願い・振り返り・検証結果の受け取り・結論部

戻り: `docs/architecture/display.md`「出力の分離（セリフと詳細）」

- **`/clear` は例外で、吹き出しに加えて記録（`records`）も空にする**（2026-09-15 決定）。
  普通の `request` は過去のターンを遡れるように記録を残すが、`/clear` は会話そのものを消す操作
  なので記録も落とす。**空にしても
  キャラクターは消えない**（起動直後と同じく挨拶を書き直して迎える〔書けなければ吹き出しは無い〕、
  立ち絵はそのまま）。残すのはキャラクターパック・セッション情報（モデル・許可モード）・
  答え待ちの列で、**消すのは吹き出しとメインビューが読む値だけ**。
  **合図は SDK の `conversation_reset` メッセージ**（実測は `docs/history/decision.md`）。
  tsukumo は依頼の文面が `/clear` かどうかを見ない。**例外は帯の2行目の文言と、入力欄の送信前の判定**（下の
  「`/clear` に続けて文を書いて送ろうとしたとき」）**だけ**（`isClearRequest`。
  依頼の先頭トークンがちょうど `/clear` のあいだ「考えている」の代わりに「会話を片付けている」を出す。
  `conversation_reset` を待たず、依頼が進んでいるあいだずっと出る）。**`/compact` では届かない**ので、要約では何もリセットされない
- **レポートの構造は tsukumo 側の規約（`src/server/report/core/report-notation.ts`）と `report` の
  塊の形（`src/shared/report/report-block.ts`）で決める**（正典は
  下の「レポートの記法は、TUI と tsukumo で出し分ける」。グローバルの `asuna.md` は TUI 向けに
  保ち、HTML の記法と mermaid / chart のフェンスは外してある）。内容の種類ごとに使う構造は
  塊の種類と各塊の説明が持ち、塊に無い記法（`svg` など）だけを規約の表で示す。
  結論は `report` の `conclusion` に、1ターンのレポートは最後に1つ、とした。**図とグラフは同梱した
  mermaid / Chart.js で描く**（2026-09-10 の決定どおり。tsukumo 側で構造を推測・整形しない）。
  **引用 `> ` は Markdown のまま描ける**
- **利用者への「お願い」だけはレポートに置く**（2026-09-16 決定。地の文に紛れると見落とすため）。
  利用者にしか決められない・できないことが実際にあるときだけ、**`report` の `favor`** に1つ入れ
  （tsukumo がお願いの塊として最後に描く。2026-09-24 に本文の末尾の `note-favor` の塊から移した）、
  `speak` では「お願いがある」ことだけを言う（中身はレポートが正典）。**無いターンでは置かない**。
  **`favor` は作業を終えた・止めたあとに残るお願いに限る。** 作業の途中で利用者の手が要るときは、
  `report` でターンを閉じず `AskUserQuestion` で聞き、答えを受けて同じターンで続ける
  （閉じると依頼・中間レポート・最終レポートが2つのやり取りに割れるため。2026-10-08 利用者決定）。
  「語りかけはセリフ」の原則に開ける穴はここだけで、雑談・感想・完了の報告・「次はどうする？」の
  誘いは今までどおりセリフ（呼び名は `docs/glossary.md`「お願い」）
- **振り返りの結果は `report` の任意の欄 `retrospective` で受け取り、`sections` の後ろ・`favor` の前の専用の塊に描く**
  （2026-10-18 利用者決定。最終レポートの本文の末尾に1文で混ざり、振り返りをしたことも積んだドラフトも探せなかったため）。
  形は `{ summary, drafts }`（結果の1〜2文と、積んだドラフトのタスクID）。塊は `retrospective` の印（見出しの行は `retrospective-label`）で、
  お願いの縦罫と取り違えないよう罫は上に引き、地は染めない。**帯の「振り返り」の段の有無は見ず、欄があるときだけ描く**
  （段の名前を契約にすると他のワークフローを縛る。`docs/architecture/workflow-contract.md`）。
  **欠けても差し戻さず、記録でも数えない**（まず運用で欄が使われるかを見る）。入口（`sdk-message.ts`）で欄の無い・崩れた値と
  欄を持たなかったころの記録は `none` に畳む（`src/shared/report/report-retrospective.ts`）。
  記録とイベントの形が変わったので `PROTOCOL_VERSION` を 60 に上げた
- **検証結果は `report` の `checks` で受け取り、tsukumo が結論のすぐ下に描く**（2026-09-26
  ユーザー決定。完了報告の結論に「（`./check.sh` は終了0。push はしていません）」と括弧で混ざって
  読みにくかったため。書き手の規約に任せる案は採らなかった）。1項目は `{ status, label, detail }`
  （2026-09-28 に `figure` と `command` を、2026-10-17 に確かめ方の `howToVerify` を足した。下の「総括行と開く行で描く」）で、
  `status` は **`ok` / `ng` / `unverified` の3つ**（確かめなかった・飛ばした、を分けても読み手の
  次の手は同じ「自分で確かめるか判断する」なので `skipped` は置かず、理由を `detail` に書かせる）。
  状態はいまのバッジに寄せ、`ok` → `badge-ok`「OK」・`ng` → `badge-ng`「NG」・`unverified` →
  `badge-warn`「未確認」と**色と文字の両方**で見せる（2026-09-28 にカードの色と「✓ OK」「✕ NG」「? 未確認」の
  文字へ置き換えた）。**`checks` は省ける**（雑談・調べものだけの
  ターンでは渡さず、帯も出ない。内部では入口〔`sdk-message.ts`〕で空の配列に畳む）。
  **帯は `favor` と同じくメインビューの組み立て（`src/shared/session/main-view.ts`）で本文の HTML に入れる**
  ——中間レポート・最終レポート・transcript からの復元・畳んだ中間レポートの見出し（`firstLine` は
  結論の行のまま）のどれも、本文と同じ経路で同じに出る。別の部品にすると、ステップの本文の型と
  書き上げる演出の両方に2つ目の経路が要る。帯の HTML は `src/shared/report/report-check.ts` が組み、
  モデルの文字列は HTML として逃がして改行を空白に畳む（Markdown は解釈しない）。帯の class
  （`checks` / `check` とカードの部位）はモデルに教えない印として語彙（`src/shared/report/report-notation.ts` の
  `REPORT_DRAWN_MARK_NAMES`）に置く。記録とイベントの形が変わったので `PROTOCOL_VERSION` を
  23 に上げた
- **記法の条の足し方**（同じ 2026-09-26 の決定）: 条を増やさず、**条1** に「検証の結果は `checks` に
  入れ、`conclusion` と本文に書かない」と「結論は、したことではなく読み手から見た変化で書く」を、
  **条8** を「文字より視覚情報で見せる（文のままでよいのは表の前に挙げたときだけ）」に広げた。
  条5 の「確かめていないこと」には `checks` の `unverified` を添え、送る前の検算に1行足した（2026-10-15 に、
  条の再掲だった検算の節と、`checks` の説明が持つ `unverified` の添えは外した）。
  2026-10-12 に、条8 の媒体の梯子を「情報の形 → 塊」の表に書き換えた（図が選ばれず表に偏っていたため）。
  条の番号は他の文書から引かれているので動かさない（`src/server/report/core/report-notation.ts`）
- **タスクの作業のレポートは、結論部を「目録の1行・見出し・一文」の3段にする**（2026-09-30 ユーザー
  決定。見本は `docs/history/mockup/report-conclusion-2026-09-30.html` の案A。作業の名前がインライン
  コードの地に乗って結論の文の途中に埋もれていたため）。
  - **書き手が `report` の任意の引数 `task`（`id` / `name` / `outcome` / `genre`）で渡す。** `outcome` は `finished`
    （作業を終えた）/ `stopped`（止めた）/ `awaiting-answer`（答え待ち）の3つ。どこへ送ったか（主ブランチ・push）は
    tsukumo の関心にしない（`docs/architecture/adr/0024-no-skill-dependency.md`）。前の記録の `shipped`（2026-10-07 までの語）は
    `finished` として読む。
    `checks` に `ng` の行がある間は `finished` にさせない（`finished-with-ng` の差し戻し。`src/server/report/core/report-review.ts`）。
    未コミットの変更とは突き合わせない（どこへ送ったかを関心にしないので、未コミットのまま終えるワークフローの
    `finished` も正しい）。
    **`id` がタスクの一覧に実在するかも突き合わせない**（2026-10-17 ユーザー決定）。`task` 付きの `report` 972 回
    （2026-09-23〜10-16 の記録の構造だけを数えた）のうち実在しない ID は 10 回で約1%、取り違えた別の実在の ID は
    実在の突き合わせでは捕まらず、一覧は閉じた課題を新しい 10 件で打ち切る（`CLOSED_TASK_DISPLAY_LIMIT`）ので、
    閉じた課題の多いプロジェクトでは一覧に無い ID が「実在しない」のか「古い閉じた課題」なのか区別できないため。
    依頼の文面や結論の文字列から ID・終わり方を推し量らない。入口（`sdk-message.ts`）で揃っていない値と
    `task` の無かったころの記録は `none` に畳む（`src/shared/report/report-task.ts`）。記録とイベントの形が
    変わったので `PROTOCOL_VERSION` を 26 に上げた
  - **`task` は省略できる `genre`（報告の種類。`work` 作業／`decision` 判断／`research` 調べもの）を持つ**（2026-10-17。
    終わった仕事の報告は種類で型が違うため。`docs/research/report-excellence-strategy.md` 3.2）。種類ごとの既定の節の並びは
    `REPORT_TASK_DESCRIPTION` が持ち、規約は条15でそれを指すだけ（下の「規則と置き場の対応」）。`stopped` は種類によらず中断の並び。
    描き方は種類で変えない。`genre` の無い・読めない値は `task` を捨てずに `unspecified` に畳む（`parseReportTask`）。
    種類ごとの必須の塊（判断の `options`・調べものの出典か `path:line`・中断の `favor`）は差し戻さず、記録で数える
    （下の「塊を足す・外す基準」の版9）。出来事の形が変わったので `PROTOCOL_VERSION` を 56 に上げた
  - **目録の1行はラベル・タスクID・終わり方・変更の札のうちあるものだけを `·` でつなぐ**（無い要素の区切りは出さない）。
    ラベルは中間レポートなら「中間レポート」、最終レポートなら「最終レポート」で、最終レポートのラベルは
    中間レポートのあるやり取りか `task` があるときに出す（下の「各表示物」のメインビュー）。終わり方は
    記号・言葉・色の3つで見せる（✓ / ？）。**`stopped` は目録に描かない**（2026-10-04 ユーザー決定。
    途中経過のレポートに「止めた」が赤で出て、止まったように読めたため）。**タスクID は、タスクの一覧にあるときだけ押せ**、押すと
    タスクのモーダルをそのタスクを選んで開く（モーダルはサイドバーの中ではなく会話の画面に1つだけ置く。
    狭い画面でタスク一覧が引き出しの中にあっても開けるように）
  - **`task` のある最終レポートだけ、目録の末尾に変更の札「変更 n ファイル +a −b」を出す**（2026-10-17。
    読者の問い「どれだけ変えたか」に答える置き場。`docs/research/report-excellence-strategy.md` 3.1）。
    **数えるのは tsukumo で、モデルには書かせない**（書かせると数が合わない。`report` の `task` の説明もそう言う）。
    依頼（`request`）を受けた時点の HEAD を控え、`task` のある `report` を受理したあとに数え、
    別の出来事 `report-change-summary`（`toolUseId` で `report` と結ぶ）で配る。`report` は数を待たずに配られる。
    **数えるのは指示したタスクで入った変更だけ**（2026-10-18。送り出しの rebase で、並行して別の作業ツリーから
    主ブランチに入った他タスクのコミットが範囲に混ざり、目録の量が他タスクの分だけ膨らんだため）。控えた HEAD より後の
    コミットのうち、件名が `<`task` の ID>:` で始まるもの（大文字小文字は区別しない。`tw finish` が付ける件名）の
    `git show --numstat` を合算し、同じパスは1ファイルに数える。件名が合うコミットが1つも無いときは、従来どおり
    `git diff --numstat <控えた HEAD>`（受理した時点の HEAD と作業ツリー〔未コミットを含む〕まで）を数える。
    ただしその範囲に別のコミットがあった・コミットの一覧が読めなかったときは、他タスクの分が混ざりうるので
    `mixed` を立て、目録の数の後ろに控えめな注記「※他の変更を含みうる」を添える（変更が 0 ファイルなら立てない）。
    **未追跡のファイルは `git diff` に出ないので数えない**。
    控えた HEAD がいまの HEAD の祖先でない（rebase など）・git が打てない・出力が読めないときは何も出さない
    （0 ファイルは数えた結果として出し、「数えられない」と分ける）。git を打つのは tsukumo を起こした作業ディレクトリ
    だけで、疑似セッションでは打たない。transcript から組み直す復元では出さない（復元は git を打たない）。
    記録の `report` に `changeSummary` が増えたので `PROTOCOL_VERSION` を 55 に上げた
    （`mixed` が増えたときも 61 に上げた）
  - **見出しは作業の名前だけ**（`name` のバッククォートは小さいインラインコード）で、終わり方で色を変えない。
    結論の一文は `task` があるときだけ印 `conclusion` で包んで見出しの下の大きさと色にする。`task` の無い
    レポートの結論は、見出しの代わりとして印 `conclusion-lead` で包み、17px・500 で頭に置く（2026-10-03。
    下の「検証の総括とお願いの合図を…合図の行に置き」）
  - 書き手への条は `task` の引数の説明に「渡したら `conclusion` には作業の名前を書かず変わること
    だけを書く」と置く（2026-10-05 に条1 から寄せた。条1 の「1〜2文」とその差し戻しとは食い違わない）。会話のアーカイブに預ける
    結論には、`task` があれば作業の名前を頭に添える
- **`checks` の `detail` に所要時間を添える条は外した**（2026-09-27。経緯は `docs/history/decision.md`「display.md 4.2 検証結果の描き方（所要時間をモデルに書かせた条とカードの形）」）

# 各表示物: メインビュー

戻り: `docs/architecture/display.md`「各表示物」

局面・最終と中間のレポート・畳み・本文の流し方・1ターン＝1枚の札・やり取りの列・脇の話の欄・失敗の塊。

- **メインビュー**: **ターンの局面ごとに、始め方の一覧 / 働くあいだの札 / レポートを出し分ける**（2026-10-02 決定。
  局面の判定・入れ替える瞬間は `docs/architecture/screen-design.md` 13.13）。
  **狭い画面（760px 以下）では見せ方だけが替わる**（2026-10-09 ユーザー決定。広い画面の見せ方は変えない）: 依頼は “ と1行、
  中間レポートは1段1行の一覧（✓・番号・題・所要・›）で、押すと下から上がる板でその段の中間レポートを読み、‹ › で前後の段へ移る。
  一覧の下に今の段と走っている手順の1行。最終レポートのある閉じたやり取りは一覧を出さず、広い画面と同じ 依頼 → 最終 → 経過の畳み
  （2026-10-19）。進み具合の帯は札の上端に置かず、同じものを画面の頭が持つ。寸法は `docs/architecture/screen-design.md` 13.9「狭い画面（760px 以下）」。
- **本文として出すのは確定したレポートだけ**で、札の上端の進み具合の帯は本文ではない（帯は作業の**進行**——いま何をしているか、
  その依頼で実行中／終わった手順の一覧、失敗したツールの引数・出力——を見せる）。
  **ツールの実行は種類を問わずレポートに出ない。** ツールの記録から描くのは質問の記録と、進み具合の帯だけ。
  **サブエージェントの本文は記録に積まない**（委譲先の独り言で、英語のことも多い。進み具合は委譲先が
  `SendMessage` で送り、メインが `speak` で言い直す）。
- **レポートは `report` ツールで受け取る**（2026-09-24 決定）。`report` が1つでも呼ばれたターンは、
  最後の呼び出しを最終レポート、それより前を中間レポートにし、`report` の外に書いた本文は出さない。
  **段を進めた `work_plan` の段のまとめも中間レポートになる**（「ワークプラン」の「段が移ったときの中間レポート」）。
  **`report` が呼ばれなかったターンは、最後の本文（空白だけのものは除く）をそのまま最終レポートに
  する**（2026-09-24 決定）。それより前の本文は、資料らしい形をしていても出さない——中間レポートは
  `report` と段のまとめからしか生まれない。最後の本文の中身（日本語か、実況か）は問わない。
  ターンは通った `report` で閉じ、締めのセリフは `report` の `closing` が持つ（言い方は `persona.md`「締めのセリフの言い方」）。
  Claude Code が英語の催促を差し込む入口は子プロセスへ渡す環境変数で塞ぐ（`docs/architecture/chat-mode.md` 4.9）。
  **規約の条項は残す**（`report-notation.ts` の「前置きと締めを書かない」「レポートは必ず日本語で
  書く」など。素の TUI では tsukumo 側の判定が効かないため）。
- **最終レポートの札（ラベル・箱を外すこと）は、いちばん新しいやり取りではそのやり取りが閉じている
  （ターンが動いておらず、バックグラウンドタスクも残っていない）ときだけ立つ**（2026-09-26 決定）。バックグラウンドタスクを
  待つあいだや、通知で claude が続きのターンを自分で始めたあいだは、次の `report` でいま最後の本文が中間レポートへ
  回るかもしれない——確定していないものに札を立てない。閉じるまでは中間レポートの枠にもせず、素の本文のまま出す。
  **ラベル（「中間レポート」「最終レポート」）は結論部の目録の1行の頭に置く**（`docs/architecture/display/conclusion.md`
  「タスクの作業のレポートは、結論部を「目録の1行・見出し・一文」の3段にする」）。最終レポートの
  ラベルは、中間レポートのあるやり取りか、本文に `task` があるときだけ出す。畳んだ中間レポートは
  `<summary>` がラベルと先頭行（段のまとめなら終えた段、`task` があれば結論。結論が空なら作業の名前）を持つので、目録の1行にはラベルを置かない。
  **`task` のある中間レポートの先頭行に作業の名前を使わない**（同じ作業の中間レポートが全部同じ題で並ぶため）。
- **中間レポートは1ターンに何件でも積む**。1ターンの上限（`MAX_MAIN_VIEW_ENTRIES`）は画面に出るもの
  （レポート・質問の記録）だけを数え、1つのやり取りが際限なく伸びたときの止めとして置く（実際には当たらない）。
  超えた分は古いほうから落として件数だけを残す。
- **中間レポートは見分けが付く形で出す**: 地は最終レポートと同じ `surface` のまま、枠を破線にし、「中間レポート」の
  小さなラベルを載せる（新しい色は作らない。`docs/architecture/screen-design.md` 13章）。**最終レポートは箱（枠・内側の余白）を持たず**、
  領域の `surface` を紙にする（2026-10-03）。中間レポートの破線の箱と箱のない最終レポートは形で見分ける。
- **`memo` の `note` と塊の `aside` は、本文の列の右の余白の柱に出す**（2026-10-17 利用者決定。補足を走り読みの経路から外す）。
  余白の柱の傍注は直前の塊の上端に揃え、本文の列は1本のまま（2段組にしない）。
  本文の列の右に 160px 以上空かないときは、余白の柱に出すものを塊の直後の1行として本文の中に畳む。余白の柱は書き上げる演出の対象外で、
  最初から出す。寸法は `docs/architecture/screen-design/layout.md`「余白の柱」。
- **あとに別のレポートが出た中間レポートは畳む**（2026-09-16 決定。ターンが長いほど画面が伸びるため）。**まだ追い越されていない
  最後の中間レポートは開いたまま**にする。畳んだ `<summary>` には「中間レポート」＋本文の先頭行（見出しなら記号を
  落としてその語）を出す。畳んだ中身は開いたとき（`toggle`）に初めて描き、開いたあとは閉じても DOM に残す（記録からは消さない）。図（mermaid）とグラフ（chart）は見えたときに初めて描く。
  **最終レポートのある閉じたやり取りは、中間レポートを「経過の畳み」1つにまとめて最終レポートの下に置く**（2026-10-18 利用者決定。
  最終レポートを最初の1画面に入れるため。見本は `docs/history/mockup/report-reading-tool-2026-10-18/after-full-w1400.png`）。
  経過の畳みは閉じた `<details>` で、`<summary>` は「経過 n 件」（n は中間レポートの数）に、質問の記録があれば
  「 · 質問 m 件」、段のまとめがあれば
  「 · 所要 <合計>（<段> <所要> · …）」を添える（測れなかった段があれば合計は出さない）。開くと中間レポートを上の1行の畳みの形で、
  質問の記録（最終のステップのものも含む）を答えた札の形で、届いた順に混ぜて並べる。中間レポートが無く質問だけでも畳みを置く。
  脇の話は畳みの外に残る。働くあいだと、最終レポートの無いまま閉じたやり取り（失敗・止めた）は経過の畳みを置かず、
  上の畳み方のまま届いた順に並べる。見出しの一覧（やり取りの列の見出しの行）は閉じた畳みの中を拾わないので、最終レポートの見出しだけが並ぶ。
- **リアルタイムに流す**: 書きかけの本文はそのまま記録の末尾に積まれ、ターンが終わった瞬間に整形し直す。
  **ただしターンが進行中のあいだは、確定していない本文を出さない**（2026-09-21 決定。経緯と実測は `docs/history/decision.md`）——`report` が
  呼ばれなかったターンは本文を1つも出さず、呼ばれたターンはいちばん新しい `report` を出さない
  （次の `report` が来れば中間、来なければ最終になるので、まだ決まっていない）。段のまとめは届いた時点で
  中間と決まっていて形が変わらないので、ターンが動いているあいだも伏せない。**伏せるのは
  いま走っている SDK ターンで届いた本文だけ**で、バックグラウンドタスクの通知やサブエージェントの
  合図で claude が同じやり取りの続きを始めても、前の SDK ターンで確定した本文は出したままにする。**ただし `report` の
  外の本文は、前の SDK ターンのものもターンが動いているあいだとバックグラウンドタスクが残っているあいだは
  出さない**（`report` が来ればどのみち出さない本文なので、伏せても往復は起きない）。**確定するまで
  出さない理由**: 出してから形が変わると前の中間レポートの畳み（`superseded`）が反転して
  `<details>` が閉じてからまた開き、書き上げる演出（4.3）もマウントした時点でしか始まらないので
  確定した本文に掛からない。確定するまで出さなければ**一度出した本文は二度と消えない**。
  **代わりに失うもの**: **進行中の本文は流れて見えない**。流れて見える感じは
  **書き上げる演出**（4.3）が受け持ち、演出は確定した本文の節にだけ掛かる（結論と検証結果は最初から出す）。
- **1ターン＝1枚の札**。札の中の上からの並びはここが正典: 札の右の側の上端に進み具合の帯を固定し、その下を依頼の全文・
  中間レポートとレポート（脇の話の欄は送った順にその間へ足す）・お伺いの札の順に流す。最終レポートのある閉じたやり取りは、
  依頼の全文・最終レポート・脇の話の欄（送った順）・経過の畳み（中間レポートと質問の記録を届いた順に入れる）・
  お伺いの札の順にする（2026-10-18。質問の記録は 2026-10-24 に経過の畳みの中へ移した。最終レポートの無いまま閉じたやり取りは前の並び。狭い画面も同じ並びで、
  `docs/architecture/screen-design.md` 13.9「狭い画面（760px 以下）」）。過去のやり取りでは帯とお伺いの札を出さず、
  やり取りが無いまま届いた答え待ちのお伺いは始め方の一覧の下に出す。札は自分の枠を持たず、領域の縁まで広がって
  領域の枠を札の枠にする（枠が二重に見えないように）。
  - 過去は**直近20件**（`MAX_MAIN_VIEW_TURNS`。仕事のセッション状態が持つ記録の窓と同じ値）まで遡れる。
    **札の頭に題の行は持たない**（2026-10-08 利用者決定。見本は `docs/history/mockup/turn-rail-without-head-2026-10-08.html`）。
  - 前後へはやり取りの列の行か `[` `]` のキーで移り（レポートの見出しの前後へは `{` `}`。`docs/architecture/screen-design.md`
    13.13「札を移るキーと送るキーの案内」）、「n / N」は出さない。最新のやり取りは列のいちばん下の行で、札は付けない
    （過去を見ているときの「最新へ」の口は持たず、列の最新の行と列の頭の知らせの行が代わる）。新しいターンが始まったら
    最新へ移すが、利用者が過去のターンを見ている間は動かさない（最新の行・知らせの行・`]` で端まで戻ると追従に戻る）。
  - **依頼の全文は本文の頭（進み具合の帯の下）の依頼の全文に出す**: 見出し「依頼」（ページの `h2`）の下に依頼の行
    （引用の記号 `> ` と前後の空行は落とす）を並べる。**畳んだ姿は1行（見出し「依頼」と1行目〔切れたら末尾を …〕と
    開く口「全文」〔▾〕）で、開くと全文と添えた画像が出て、「畳む」で畳み直せる**（2026-10-18 利用者決定）。
    1行に収まる短い依頼で、画像も無いときは口を出さない。狭い画面も同じ1行の形。別のやり取りへ移ると畳んだ姿に戻る。
- **札の左にやり取りの列を置く**: 列は札の上端から下端まで伸び、進み具合の帯・依頼の全文・お伺い・本文は列の右に載る。
  列は本文を押しのけて開いておく。**列の頭（見出し「やり取り」の下）に知らせの行を出す**（`docs/architecture/screen-design.md` 13.13「知らせの行」）。
  - **上の段に窓の中のやり取りを古い→新しいの順で縦に並べ**、各行は結果の印と依頼の1行目。**見ているやり取りの行だけを開き、
    印の代わりに「●」を出して、そのレポートの見出し（`##` と `###`）を子の行に出す**（`###` はさらに字下げして小さく、
    いまの節は明るい字、いま読んでいる見出しは地と左の印）。
  - 結果の印は字で区別する（色だけに頼らない）: 完了「✓」・答え待ち「?」・止めた「‖」・失敗「✕」・働いている最中「…」・
    レポートの無いやり取り「–」。失敗で終わったやり取りは失敗、いちばん新しいやり取りが閉じていなければ答え待ちの列の
    有無で答え待ちか働いている最中、閉じたやり取りは最後の本文の `task.outcome` が `awaiting-answer` なら答え待ち、
    `stopped` なら止めた（答えは待っていない）、本文が1つも無ければレポートの無いやり取り、ほかは完了。印は shared で導き、
    ブラウザは描くだけにする。**進み具合の帯の状態のチップも同じ印と字の表を読む**（帯の作業中は今の段の丸の外周を回る弧。
    `docs/architecture/screen-design.md` 13.13「進み具合の帯」）。
  - 依頼の1行目が列の幅に収まらなければ末尾を「…」で切り、全文は行の `title` で読ませる（印は切らない）。
    列は転がしても札の上端に残り、行が多いときは列の中で転がす。**見ているやり取りが替わったら、その行が列の中で
    見える位置まで列だけを転がす**（本文は転がさない）。
  - やり取りの行を押すとそのやり取りへ移り、見出しの行を押すとその見出しへ転がす。押した見出しは、転がりが足りずに
    列の上端まで届かなくても、次に利用者が転がすまで「いま読んでいる見出し」のまま残る。↑↓ でやり取りの行と見出しの行を
    区別なく移り、Enter でやり取りの行ならそのやり取りへ移り、見出しの行ならその見出しへ飛ぶ。
  - **列と本文の境界をドラッグして列の幅を変えられ、列の見出しの口で畳む／開くを切り替えられる**（畳むと列は開き直す
    ボタンだけの幅になり、本文はその幅ぶん広がる）。**幅と畳んだ状態は `localStorage` に保存し、再読み込み後も保つ**
    （会話の中身は保存しない。読み書きの失敗は既定へ落ちるだけ）。
  - **列は札にやり取りが載っているあいだ常に出す**（やり取りが1件で見出しが無くても、札の幅が 36rem を下回る領域でも。
    幅が足りないときは畳んだ細い列〔開き直す口と結果の印〕になり、口で開ける。寸法は `docs/architecture/screen-design.md` 13.4）。
    **狭い画面（760px 以下）だけは列を出さない**。やり取りの並び（依頼の1行目・結果の印・時刻と所要）は引き出しの
    「やり取り」のタブに新しいものを下にして並び、押すと引き出しを閉じてそのやり取りへ移る。見出しの並びは狭い画面では出さない
    （`docs/architecture/screen-design.md` 13.9「狭い画面（760px 以下）」）。**ページは1枚で完結し、別のアプリケーションへ散らさない**（1章）。
  - **脇の話のあるやり取りの行は、2行目に「脇 n」を出す**（行を増やさず、フォーカスの止まり場所も増やさない。「脇の話」）。
- **脇の話は、送った順にいちばん下へ足す**（2026-10-10 利用者決定。「脇の話」、形は `docs/architecture/screen-design.md`
  13.13「脇の話の欄」）。記録 `aside` が届いた時点で最後のステップの後ろに欄を置き、あとから届く中間レポートは欄の後ろに並ぶ。
  欄は利用者の言葉と答えの対を古い順に1行ずつ並べ、答えがまだ無ければ「…」。過去のやり取りを見ているときも、そのやり取りの欄を出す。
- **失敗で終わったやり取りは、本文の頭（最初の節より前）に失敗の塊を出す**（2026-09-24 決定、2026-10-02 に頭へ移し次の手を足した。
  形は `docs/architecture/screen-design.md` 13.13「失敗の塊」）。見出し「失敗で終わった」と、何が起きたかを言う理由の語
  （型の決まった語だけで、SDK の自由文は出さない。4.1）。**内部の綴り（`server_error` など）は理由の語の `title` にだけ出す**。
  次の手は「同じ依頼を入力欄に戻す」（送らない。添えた画像は戻さない）、利用上限で戻る時刻が分かれば同じ口に時刻を添えた
  「18:00に戻る · 依頼を入力欄に戻す」（自動では再開しない）、失敗した手順があれば「失敗した手順を見る」
  （進み具合の帯の手順の一覧を開いて失敗の行へ連れていく）。枠と見出しの字が `--state-ng`。
  記録に残るので、過去のターンを遡っても成功と見分けられる。雑談のログには出さない（雑談では入力欄の行に理由の語と「失敗」が出る）。

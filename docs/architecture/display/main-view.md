# 各表示物: メインビュー

戻り: `docs/architecture/display.md`「各表示物」

局面・最終と中間のレポート・畳み・本文の流し方・1ターン＝1枚のカード・やり取りの列・補足メッセージの欄・失敗の表示。

- **メインビュー**: **ターンの局面ごとに、始め方の一覧 / 働くあいだのカード / レポートを出し分ける**（
  局面の判定・入れ替える瞬間は `docs/architecture/screen-design.md` 13.13）。
  **狭い画面（760px 以下）では見せ方だけが替わる**（広い画面の見せ方は変えない）: 依頼は “ と1行、
  中間レポートは1段1行の一覧（✓・番号・題・所要・›）で、押すと下から上がる板でそのフェーズの中間レポートを読み、‹ › で前後のフェーズへ移る。
  一覧の下に今のフェーズと走っている手順の1行。最終レポートのある閉じたやり取りは一覧を出さず、広い画面と同じ 依頼 → 最終 → 経過の畳み。進み具合のプログレスバーはカードの上端に置かず、同じものを画面の頭が持つ。寸法は `docs/architecture/screen-design.md` 13.9「狭い画面（760px 以下）」。
- **本文として出すのは確定したレポートだけ**で、カードの上端の進み具合のプログレスバーは本文ではない（プログレスバーは作業の**進行**——いま何をしているか、
  その依頼で実行中／終わった手順の一覧、失敗したツールの引数・出力——を見せる）。
  **ツールの実行は種類を問わずレポートに出ない。** ツールの記録から描くのは質問の記録と、進み具合のプログレスバーだけ。
  **サブエージェントの本文は記録に積まない**（委譲先の独り言で、英語のことも多い。進み具合は委譲先が
  `SendMessage` で送り、メインが `speak` で言い直す）。
- **レポートは `report` ツールで受け取る**。`report` が1つでも呼ばれたターンは、
  最後の呼び出しを最終レポート、それより前を中間レポートにし、`report` の外に書いた本文は出さない。
  **フェーズを進めた `work_plan` のフェーズのまとめも中間レポートになる**（「ワークプラン」の「フェーズが移ったときの中間レポート」）。
  **`report` が呼ばれなかったターンは、最後の本文（空白だけのものは除く）をそのまま最終レポートに
  する**。それより前の本文は、資料らしい形をしていても出さない——中間レポートは
  `report` とフェーズのまとめからしか生まれない。最後の本文の中身（日本語か、実況か）は問わない。
  ターンは通った `report` で閉じ、締めのセリフは `report` の `closing` が持つ（言い方は `persona.md`「締めのセリフの言い方」）。
  Claude Code が英語の催促を差し込む入口は子プロセスへ渡す環境変数で塞ぐ（`docs/architecture/chat-mode.md` 4.9）。
  **規約の条項は残す**（`report-notation.ts` の「前置きと締めを書かない」「レポートは必ず日本語で
  書く」など。素の TUI では tsukumo 側の判定が効かないため）。
- **最終レポートのラベル（と、狭い画面で箱を外すこと）は、いちばん新しいやり取りではそのやり取りが閉じている
  （ターンが動いておらず、バックグラウンドタスクも残っていない）ときだけ立つ**。バックグラウンドタスクを
  待つあいだや、通知で claude が続きのターンを自分で始めたあいだは、次の `report` でいま最後の本文が中間レポートへ
  回るかもしれない——確定していないものにラベルを立てない。閉じるまでは中間レポートの枠にもせず、素の本文のまま出す。
  **ラベル（「中間レポート」「最終レポート」）は結論部のタスク見出し行の頭に置く**（`docs/architecture/display/conclusion.md`
  「タスクの作業のレポートは、結論部を「タスク見出し行・見出し・一文」の3段にする」）。最終レポートの
  ラベルは、中間レポートのあるやり取りか、本文に `task` があるときだけ出す。畳んだ中間レポートは
  `<summary>` がラベルと先頭行（フェーズのまとめなら終えたフェーズ、`task` があれば結論。結論が空なら作業の名前）を持つので、タスク見出し行にはラベルを置かない。
  **`task` のある中間レポートの先頭行に作業の名前を使わない**（同じ作業の中間レポートが全部同じ題で並ぶため）。
- **中間レポートは1ターンに何件でも積む**。1ターンの上限（`MAX_MAIN_VIEW_ENTRIES`）は画面に出るもの
  （レポート・質問の記録）だけを数え、1つのやり取りが際限なく伸びたときの止めとして置く（実際には当たらない）。
  超えた分は古いほうから落として件数だけを残す。
- **中間レポートは見分けが付く形で出す**: 地は最終レポートと同じ `surface` のまま、枠を破線にし、「中間レポート」の
  小さなラベルを載せる（新しい色は作らない。`docs/architecture/screen-design.md` 13章）。**広い画面（761px 以上）の最終レポートは、
  領域が面を持たず背景の絵が透けるので、自分で紙の面（ぼかさない濃い地 `--panel-glass-dense`・縁・角丸・影）を持つ**。
  狭い画面（760px 以下）の最終レポートは箱を持たず、領域の `surface` を紙にする。中間レポートの破線の箱と最終レポートの面は、枠の線と札で見分ける。
- **`memo` の `note` と部品の `aside` は、本文の列の右の欄外注の列に出す**（補足を走り読みの経路から外す）。
  欄外注の列の各注は直前の部品の上端に揃え、本文の列は1本のまま（2段組にしない）。
  本文の列の右に 160px 以上空かないときは、欄外注の列に出すものを部品の直後の1行として本文の中に畳む。欄外注の列は書き上げる演出の対象外で、
  最初から出す。寸法は `docs/architecture/screen-design/layout.md`「欄外注の列」。
- **あとに別のレポートが出た中間レポートは畳む**（ターンが長いほど画面が伸びるため）。**まだ追い越されていない
  最後の中間レポートは開いたまま**にする。畳んだ `<summary>` には「中間レポート」＋本文の先頭行（見出しなら記号を
  落としてその語）を出す。畳んだ中身は開いたとき（`toggle`）に初めて描き、開いたあとは閉じても DOM に残す（記録からは消さない）。図（mermaid）とグラフ（chart）は見えたときに初めて描く。
  **最終レポートのある閉じたやり取りは、最終レポートより前の段の札・セリフ・補足の投稿・質問の記録・中間の本文を「作業の経過」1つにまとめて最終レポートの上に置く**（依頼の投稿は畳まない。
  最終レポートを頭から読めるようにするため。見本は `docs/history/mockup/conversation-directions-2026-11-15/layouts.html?layout=a2`）。
  作業の経過は閉じた `<details>` の1行で、`<summary>` は「作業の経過 n 件」（n は中間の本文の数）に、セリフがあれば「 · セリフ s 件」、質問の記録があれば
  「 · 質問 m 件」、補足の投稿があれば「 · 補足 k 件」、フェーズのまとめがあれば
  「 · 所要 <合計>（<フェーズ> <所要> · …）」を添える（測れなかったフェーズがあれば合計は出さない）。開くと段の札を小さな1行、中間の本文を上の1行の畳みの形で、
  セリフと補足の投稿を流れと同じ形で、質問の記録を広い画面では聞いた1行と答えの投稿（畳みの中でも同じ形。「答え直す」は流れの中と同じく、いちばん新しいやり取りの最後の答えだけ）、
  狭い画面では今の札（答えたカード）の形で、届いた順に混ぜて並べる。
  最終レポートの締めのセリフ（記録では紙のすぐ後ろの `speech`）は紙のすぐ上、畳みのすぐ下に置いて紙と1組にする。中間レポートの締めも紙の上に移るが、畳みの中に残る。
  書いているあいだは締めの場所をセリフ1行ぶん空けて押さえ、末尾の行は末尾のままにする。最終レポートより後ろに届いた質問の記録（お願い）は、流れの最下部に残す。
  働くあいだと、最終レポートの無いまま閉じたやり取り（失敗・止めた）は作業の経過を置かず、
  届いた順に流れへ並べる。見出しの一覧（やり取りの列の見出しの行）は閉じた畳みの中を拾わないので、最終レポートの見出しだけが並ぶ。
- **仕事のメインビューは、選んだやり取りの中身を記録の位置の順に1本の流れで出す**（並べ直さない。動かすのは締めのセリフだけ。時刻は行の脇に出すだけで、時刻の無い記録と `restored` の記録には出さない）。
  依頼・補足メッセージは右寄せの投稿、セリフと反応は左寄せの行、中間の本文・最終レポートは流れの中の札と紙にする。
  **答えた質問は、広い画面では「聞いた1行」（印・題・問い。「聞いたときの詳細」と「比べた内容」は開閉）と、右寄せの利用者の答えの投稿（札は「答え」か「任せた」、本文は選んだ案の名前か書いた字、2問以上は1問1行の「題: 答え」。時刻は出さない）に分ける**。
  聞いた1行に選択肢の ●/○ の一覧は出さない。答えの投稿のいちばん新しいものにだけ「答え直す」を付ける（押すと「（答え直し）<題>: 」を入力欄の下書きへ足し、送らない）。狭い画面は今の1枚の札のまま。許可の答えは流れに残さない。
  **隣り合う物とセリフは、届いた順のまま1組にする**（`streamGroupsOf`）。物（本文・質問の記録・畳み・失敗の表示）はすぐ後ろのセリフと先に組み、後ろがセリフでないときだけすぐ前のセリフと組む。
  1つの行は1つの組にしか入らず、並べ替えない。投稿と答えの投稿は単独の組。
  広い画面の行の間は3段で、組の中は 4px、同じ話し手の続きは 16px、投稿の前後は 16px にさらに 8px を足す。
  流れの末尾がセリフのとき、続くお伺いの札との間も 4px にする。済んだフェーズの控え（`✓ n/N 名前` と右寄せの所要）の幅は `min(100%, 560px)` にそろえる。狭い画面（760px 以下）は変えない。
  **いまの一言**は、いちばん新しいやり取りが作業中か答え待ちのあいだ、そのやり取りの最新のセリフ1件（`streamPresentationOf`）。その1件だけを明るくして、左下（立ち絵の側）へ向けた尾を付ける。
  すぐ下に全幅の物（質問の記録・本文・失敗の表示・畳み・書きかけの紙・答え待ちのお伺い）が続くときは尾を出さない。やり取りが完了・失敗・中断で終わるといまの一言は無くなる。尾は吹き出しの形の一部で、セリフ以外の行には付けない。
  セリフと投稿は、話し手の名前（キャラクターの名前・「あなた」）を見えない字で持つ。
  **時刻**は、時刻を持つ行のうち、直前に時刻を出した行と分が変わった行だけ見える字で出す（`visibleClockFlags`）。省いた行の `<time>` は読み上げには渡したまま、行に触れるかフォーカスが入ったときだけ見せる。省いた時刻を読むキーは足さない。
  いまの一言と時刻の規則は仕事の流れだけに当て、雑談の流れは今の見た目と時刻の出し方のまま。
  ワークプランの記録の段の札は、流れの最上位には置かない（今のフェーズの名前はプログレスバーが持つ）。最終レポートの上の「作業の経過」の中にだけ、閉じたやり取りの記録として残る。
  ツールの記録は流れに出さず、進行の帯の「手順」の一覧が持つ。走っている手順は流れの末尾（最後の行の下、入力欄の上）の「いま」の行が持つ
  （回る印・「いま」・文の1行。作業中のあいだだけ出し、答え待ち・過去のやり取り・レポートに入れ替わったあとは出さない。`docs/architecture/screen-design/work-strip.md`）。
  広い画面（761px 以上）では、最終レポートの無いやり取り（作業中・答え待ち・失敗）の流れを入力欄の側へ寄せ、「いま」の行を内容の量によらず入力欄の決まった上に置く。最終レポートのあるやり取りと狭い画面は頭から並べる。
  狭い画面（760px 以下）は左寄せの行と「いま」の行を出さず、依頼は一覧の上の依頼の塊のまま。
  **離れていたあいだに足された行の手前には、境目の線を1本出す**（設計は ADR 0059、見た目は `docs/architecture/screen-design/notice-and-failure.md`「離れていたあいだの線」）。
  ページが隠れた時点の最新のやり取りの流れの行の数と時刻を前に見た位置として持ち、表に戻ったとき、隠れていたのが30秒以上で、そのやり取りに前に見た位置より後ろの行があれば、最初の新しい行の手前に差し込む。
  文は固定で「ここから新しい」に、離れていた時間（1分以上のときだけ）と、そのあいだに済んだフェーズの数（ワークプランの札の数。0なら添えない）を続ける。キャラクターのセリフにはしない。
  線が消えるのは、依頼か補足を送ったとき・別のやり取りを選んだとき・もう一度ページが隠れたとき。前に見た位置はタブのメモリだけに持ち、開き直したあとは出さない。
  線は描くときに差し込むだけで記録を増やさず、流れの末尾の「いま」の行は線の後ろのまま。狭い画面（760px 以下）は出さない。
  新しい行が届いたら、下端を見ているあいだは下端へ追従する（上へ送って読んでいるあいだは動かさない）。レポートを出しているあいだは追従せず、頭から読ませる。
- **リアルタイムに流す**: 書きかけの本文はそのまま記録の末尾に積まれ、ターンが終わった瞬間に整形し直す。
  **ただしターンが進行中のあいだは、確定していない本文を出さない**（経緯と実測は `docs/history/decision.md`）——`report` が
  呼ばれなかったターンは本文を1つも出さず、呼ばれたターンはいちばん新しい `report` を出さない
  （次の `report` が来れば中間、来なければ最終になるので、まだ決まっていない）。フェーズのまとめは届いた時点で
  中間と決まっていて形が変わらないので、ターンが動いているあいだも伏せない。**伏せるのは
  いま走っている SDK ターンで届いた本文だけ**で、バックグラウンドタスクの通知やサブエージェントの
  通知で claude が同じやり取りの続きを始めても、前の SDK ターンで確定した本文は出したままにする。**ただし `report` の
  外の本文は、前の SDK ターンのものもターンが動いているあいだとバックグラウンドタスクが残っているあいだは
  出さない**（`report` が来ればどのみち出さない本文なので、伏せても往復は起きない）。**確定するまで
  出さない理由**: 出してから形が変わると前の中間レポートの畳み（`interim-folded`）が反転して
  `<details>` が閉じてからまた開き、書き上げる演出（4.3）もマウントした時点でしか始まらないので
  確定した本文に掛からない。確定するまで出さなければ**一度出した本文は二度と消えない**。
  **代わりに失うもの**: **進行中の本文は流れて見えない**。流れて見える感じは
  **書き上げる演出**（4.3）が受け持ち、演出は確定した本文のセクションにだけ掛かる（結論と検証結果は最初から出す）。
- **1ターン＝1枚のカード**。カードの中の上からの並びはここが正典: カードの右の側の上端に進み具合のプログレスバーを固定し、その下を会話の流れ
  （依頼・セリフ・質問の記録・中間レポートとレポート・補足メッセージ。上の「仕事のメインビューは…」）・「いま」の行・お伺いのカードの順に流す。最終レポートのある閉じたやり取りは、
  流れの中の最終レポートの上に作業の経過を置く（最終レポートの無いまま閉じたやり取りは畳まない。狭い画面も同じ並びで、
  `docs/architecture/screen-design.md` 13.9「狭い画面（760px 以下）」）。過去のやり取りではプログレスバーとお伺いのカードを出さず、
  やり取りが無いまま届いた答え待ちのお伺いは始め方の一覧の下に出す。カードは自分の枠を持たず、領域の縁まで広がって
  領域の枠をカードの枠にする（枠が二重に見えないように）。
  - 過去は**直近20件**（`MAX_MAIN_VIEW_TURNS`。仕事のセッション状態が持つ記録ウィンドウと同じ値）まで遡れる。
    **カードの頭に題の行は持たない**（見本は `docs/history/mockup/turn-rail-without-head-2026-10-08.html`）。
  - 前後へはやり取りの列の行か `[` `]` のキーで移り（レポートの見出しの前後へは `{` `}`。`docs/architecture/screen-design.md`
    13.13「カードを移るキーと送るキーの案内」）、「n / N」は出さない。最新のやり取りは列のいちばん下の行で、バッジは付けない
    （過去を見ているときの「最新へ」のボタンは持たず、列の最新の行と会話の流れの下端の口〔StreamFloat〕の知らせが代わる）。新しいターンが始まったら
    最新へ移すが、利用者が過去のターンを見ている間は動かさない（最新の行・知らせの行・`]` で端まで戻ると追従に戻る）。
  - **依頼の全文は本文の頭（進み具合のプログレスバーの下）の依頼の全文に出す**: 見出し「依頼」（ページの `h2`）の下に依頼の行
    （引用の記号 `> ` と前後の空行は落とす）を並べる。**畳んだ姿は1行（見出し「依頼」と1行目〔切れたら末尾を …〕と
    開くボタン「全文」〔▾〕）で、開くと全文と添えた画像が出て、「畳む」で畳み直せる**。
    1行に収まる短い依頼で、画像も無いときはボタンを出さない。狭い画面も同じ1行の形。別のやり取りへ移ると畳んだ姿に戻る。
- **やり取りの列は左の列の上（立ち絵の上）に置く**（`docs/architecture/screen-design/layout.md`）。進み具合のプログレスバー・依頼の全文・お伺い・本文は
  中央の列のカードに載る。列の頭は「やり取り」と畳むボタンだけで、**知らせは会話の流れの下端の口（StreamFloat）に出る**
  （`docs/architecture/screen-design.md` 13.13「知らせの行」）。
  - **上の段に記録ウィンドウの中のやり取りを古い→新しいの順で縦に並べ**、各行は結果の印と依頼の1行目。**見ているやり取りの行だけを開き、
    印の代わりに「●」を出して、「やり取り → レポート → セクション（`##`）→ 小節（`###`）」の3段を子の行に出す**。
    レポートの行は見ているやり取りに1行で、ラベル（最終レポートなら「最終」、まだ最終でない最後のレポートなら「レポート」）と題
    （タスクのレポートならタスクの名前、無ければ先頭行）を出す。本文が無いやり取りには出さない。
    字下げはレポートの行が 1.5rem、セクションが 2.5rem、小節が 3.5rem（小節は小さく）。
    いまのセクションは明るい字、いま読んでいる見出しは地と左の印で、最初の見出しより上を読んでいるあいだは印がレポートの行に付く。

# タスクのモーダル

戻り: `docs/architecture/display.md`「タスクのモーダル」

サイドバーの「一覧を見る」で開くモーダル。**左に一覧、右に選んだタスクの詳細**（本文を Markdown で
描く）の2列で、**形は見本2枚が正**（`docs/history/mockup/task-board-2026-09-28/` の
`TASK-1-List.dc.html`・`TASK-2-Jump.dc.html` と同名の `.png`。見本の中のタスクの文言はダミー）。
中身とふるまいは次の箇条書き、寸法・色・狭い画面の並びは下の「13.12 タスクのモーダル」に置く。

- **本文の出どころ**: タスクの本文は**一覧の要約と一緒に届ける**（選んだときに取りに行く口は作らない）。
  見回りが読んだものから作るので、一覧と本文の新しさがずれず、検索が本文まで引ける。
  課題の `description`・`acceptance_criteria`・`notes` を Beads の欄の順に、tsukumo が決めた見出しで並べたもの
  （節を並べ替えない。`docs/architecture/adr/0024-no-skill-dependency.md`）。Beads の comment は `bd list` に載らないので出さない。
  本文を載せても1回の読みの時間は変わらないので、見回りの間隔は変えない
- **並び**: 一覧に載る範囲はサイドバーと同じ（閉じた課題は新しいほうから10件。11件目以降を落としたときは、
  一覧の末尾に「一部のみ（閉じたタスクは新しいものだけで、ほか N 件は載っていません）」の一言を添える）で、
  並びは**ID の番号の昇順**（番号の取れない ID は末尾に作った時刻の順。進行中を先頭へ寄せない。完了も混ざる）。行は1段目に ID・状態、
  2段目に要約（2行で省略）。済んだ行（`done`）は薄く出す
- **状態の言い方**は一覧の行・詳細の情報の表・つながりの札で同じにする。`todo` は依存から計算して
  「着手できる」か「待ち」（まだ済んでいない依存の ID を必ず字で添える。閉じていない課題に無い依存
  〔閉じた課題・一覧に無い ID〕は止めない）、`hold` は「保留」
  （済んでいない依存があれば ID を添える）、`draft` は「ドラフト」、`doing` は「進行中」、`done` は「完了」、想定外の値は注意色〔`--state-warn`〕の「!」と
  値のまま。**色だけで伝えない**（印の形と字が言う）
- **課題のラベルは詳細の情報の表に「ラベル」の行として字のまま札で並べる**（Beads の `labels` をそのまま出し、
  意味は解釈せず並べ替え・絞り込み・色分けに使わない。無い課題では行ごと出さない。担当は出さない。
  `docs/architecture/adr/0024-no-skill-dependency.md`）
- **見出しの帯**: 「タスク」・件数・最新化の ↻・キーの案内（`↑↓` 選ぶ・`Esc` 閉じる）・閉じるボタン。件数は
  サイドバーの件数のチップと同じ数え方（すべて・未完了〔`done` と `draft` 以外〕・ドラフト〔`draft`〕・完了〔`done`〕）
- **最新化の ↻**（見本 `docs/history/mockup/task-refresh-2026-10-12.html`）: サイドバーの見出しの
  「一覧を見る」の左と、この帯に同じ部品を置く。字は出さず、`title` と `aria-label` に「最新化」を持たせる。
  押すと見張りが見回りの次の周期を待たず1回読む（実行中なら今の読みに乗る）。
  応答は読み終えてから返り、そのあいだは2か所とも `--accent` で回って押せない（使用量の行の ↻ と同じ回り方）。
  一覧そのものはいつもの一覧の知らせで届く
- **絞り込みの札**: すべて・着手できる・待ち・保留・ドラフト・進行中・完了の7つで、それぞれに件数を添える。
  1つだけ選べ、既定は「すべて」。「着手できる」と「待ち」は `todo` を
  着手できるかで2つに割ったもの、「保留」は `hold`、「ドラフト」は `draft`、「進行中」は `doing`、「完了」は `done` だけ
  （サイドバーの「完了」と揃える）。**想定外の値はどの札にも属さず、「すべて」でだけ出る**。サイドバーで選んでいる
  チップはモーダルへ持ち込まない
- **検索**: 引くのは **ID・要約・本文**（大文字小文字を区別しない部分一致。絞り込みの札と組み合わさる）。
  ファイル名はタスクの ID をそのまま名前にしているので別には引かない（案内の文言は「ID・言葉で探す」）。
  ID の形を決め打ちしない（Beads の ID のまま、部分一致で当たる）。絞った結果が0件なら一覧に
  「当てはまるタスクが無い」と出し、詳細は空にする
- **開いたときの選択**: 開くたびに検索は空・絞り込みは「すべて」・選択は一覧の先頭の行から始める。
  **サイドバーののぞき窓の「全文を開く ↗」とレポートのタスク ID から開いたときは、そのタスクを
  選んだ状態で開く**（絞り込みの外でも一覧に出す）。**開いている間に一覧が届き直しても**
  選んでいるタスクが一覧に残っていれば選択を保ち、消えていれば先頭の行へ移る
- **キー操作**: ↑↓ で行を移ると詳細がすぐ切り替わる。Esc・閉じるボタン・モーダルの外側のクリックで
  閉じる（`<dialog>` の `showModal()` に任せ、フォーカスは開く口へ戻る）。行を押すと選ぶだけで、
  頼まない
- **詳細**: ID と status の生の値・タイトル（要約）・情報の表（着手・ラベル・置き場所）・
  本文。**置き場所の行**は「Issue」に課題の `external_ref`（`https://` で始まる URL の
  ときだけ。無ければ行ごと出さない）。依存を1つでも持つタスクは**本文の上に「先に終わっていてほしいもの」
  の札**を依存ごとに並べる（ID・状態・要約。一覧に無い依存は ID に「一覧に無い」を添え、押せない）
- **本文中の ID の自動リンク**: 本文の地の文と、中身がまるごと1つの ID の inline code のうち、
  **いまの一覧に載っている ID と字面が一致するもの**だけを押せる字にする（語の途中は当てない。
  フェンスの中は当てない）。ID の形の正規表現は持たない——一覧が知っている ID だけを当てるので、
  ID の形が変わってもそのまま当たり、一覧に無い ID
  （閉じて一覧から落ちたタスク）は押せない字にならない
- **本文の描き方**: レポートの描画は流用せず、タスクのモーダルが専用に持つ。
  使うのは `react-markdown` と `remark-gfm`・`remark-cjk-friendly` だけで、**生の HTML は解釈しない**
  （字のまま出す）。描くのは見出し・段落・箇条書き・番号・チェック（静的な印。押せない）・
  inline code・フェンス（色付けしない）・表（横に溢れたら表だけ転がす）・リンク（`http(s)` だけ
  新しいタブで開き、それ以外は字のまま）。レポートの記法（`note` などの class）・mermaid・Chart.js・
  パスを押すとエディタで開く部品は持たない。流用しないのは、置かれる機能（`features/`）が
  会話の画面の部品を import できず（`docs/architecture.md`「領域の機能と、置かれる機能」）、
  本文の読み物としての字の段（14px・行間 1.85）もレポートと違うため
- **下の操作の帯**: 「ID をコピー」（クリップボードへ ID の字だけ）・置き場所を開く口
  （「Issue を開く」で、`external_ref` を新しいタブで開く。`external_ref` が無ければ出さない）・「tsukumo に頼む」
  （サイドバーののぞき窓の「これを始める →」と同じ確認を開き、OK で文面（固定の文面か、歯車のプルダウンで入口のスキルを選んでいれば「/スキル名 {id}」。選択肢は `tw config --entries` が返すスキルと「未設定」）の `{id}` を ID にして送る）。**「tsukumo に頼む」を押せるのは
  「着手できる」タスクと、依存がすべて済んだ保留のタスク**（保留なら送る文面の末尾に「このタスクは保留なので、着手の前に判断を聞いて。」を添え、確認にもその文面がそのまま出る）で、それ以外は薄くして押せず、横に理由を添える（待ちと、
  依存が残る保留 → 「待ちが終わると頼めます」、進行中 → 「着手済みです」、完了 →
  「終わったタスクです」）。**ドラフトでは「tsukumo に頼む」の代わりに「却下する」「計画する」を並べ**、
  のぞき窓の同じ名前の口と同じ確認を開く。ターンが動いている間の断り方は区画の確認と同じ
- **ドラフトの仕分け**（見本 `docs/history/mockup/task-board-draft-batch-2026-10-24.html`）: 絞り込み「ドラフト」のときだけ、
  ドラフトの行ごとに「計画・却下・保留」を選べる（既定は保留で、触らない）。却下を選んだ行には1行の理由の欄を出す。
  「計画」「却下」を1件以上選ぶと、下端の帯に「仕分けを戻す」（全部保留へ戻す）・「保留の n 件は触らない」・
  選んだ件数を字に出した「計画 2・却下 1 を頼む」（1行だけなら「計画 1 を頼む」）を出し、
  このとき詳細の下の操作の帯は出さない。「頼む」は新しい窓を作らず既存の確認（単件と同じ作り。見出しは「ドラフト n 件を仕分けますか」、OK は「仕分ける」）を開き、
  OK で選んだぶんを1通の `/plan-tasks ドラフトを仕分けた。計画（承認済み）: ABC-1, ABC-2。却下: ABC-3（理由）` にして送る
  （保留の行は含まず、理由が空なら添えない。`/plan-tasks` は承認を得たドラフトだけを進めるので、文面の承認がそのまま使える）。
  送る文面は `requestPromptOf` と同じ置き場で作る。一度に頼める件数に上限は置かない。
  仕分けは表示上の状態なので**保存しない**（モーダルを閉じると初めに戻す。絞り込みや検索を替えても残る）
- **つながりをたどる**（見本2）: 「先に終わっていてほしいもの」の札・本文中の ID を押すと、
  **モーダルの中で詳細だけが切り替わり、一覧の選択も追いかける**。詳細の上にパンくず
  （「‹ <前の ID> に戻る › <いまの ID>」）を出し、**直前の1つだけ**を持つ（履歴を積まない）。
  戻るは `Alt+←` でも同じ。一覧で別の行を選ぶとパンくずは消える。飛んだ先には逆向きの
  **「これを待っているもの」**（いまの一覧のうち、このタスクを依存に持つもの）の札も出す。
  飛んだ先が絞り込みや検索で一覧から隠れているときは、**その行だけを一時的に一覧に出し
  「絞り込みの外」と小さく添える**（一覧で別の行を選ぶと引っ込む）
- 検索・絞り込み・選択・パンくずは表示上の状態なので**保存しない**（閉じると捨てる）

## 13. 画面のデザイン

### 13.12 タスクのモーダル

サイドバーの「一覧を見る」で開くモーダルの見た目。**左に一覧、右に選んだタスクの
Markdown の詳細**で、見本は `docs/history/mockup/task-board-2026-09-28/` の `TASK-1-List.dc.html`
（一覧と詳細）と `TASK-2-Jump.dc.html`（待ちの ID から前のタスクへ飛ぶ）、1440 幅で撮った同名の `.png`。
**値は見本のインラインの style と画面下の「説明」の節が正**で、ここにはその要点と、見本の色を
トークンへ写した対応だけを置く。中身とふるまい（本文の出どころ・絞り込み・検索・ID のつながり）は
この文書の上の節。

- **箱**: 1320×780（窓より大きくしない）・角丸 18・帯の下に少し空けて横の中央（見本は上から 84）。
  地 `--surface`・枠 `--rule`、背景は `<Dialog backdrop="dim">`。見出しの帯は上下 14・左右 20
- **最新化の ↻**: 見出しの帯の件数の右・キーの案内の左に、閉じるボタンと同じ 34px・角丸 9 の枠（`--rule`）で置く。
  サイドバーの見出しでは枠なしの 24px（1.5rem）で「一覧を見る」の左。読んでいるあいだは `--accent` で 1 秒に1回転する
- **字の大きさは見本のまま**（20px のタイトル・16px の本文の見出しなど、13.3 の段に無い値も寄せない。
  切り替え画面〔13.9「切り替え画面」〕の 30px の ID と同じく、このモーダルの中だけの値）
- **左の一覧**: 幅は既定 470 で、詳細との境の仕切り（`LayoutResizer`）をドラッグして 300〜760 の間で
  変えられる（詳細には 360 を残す。幅は `localStorage` に保ち、再読み込み後も同じ）。詳細が残りの幅。検索欄は高さ 36、絞り込みの札は高さ 30・角丸 15・
  間 6。行は上下 10・左 16・右 14 で、1段目は ID 12px 等幅・状態 12px、2段目は要約
  13px・行間 1.55・2行で省略。**選んでいる行は `--surface-accent` の地と左端 3px の `--accent`**
  （色だけで伝えないため、左端の帯の形も添える）。選んでいる絞り込みの札は一段明るい地と字
  （`--surface-raised`・`--ink`）
- **状態の印**: 着手できる → `--accent` の点＋「着手できる」、待ち → `--state-warn` の輪＋「待ち <ID>」、
  保留 → `--ink-quiet` の字＋一時停止の印＋相手の ID、
  ドラフト → `--ink-quiet` の字＋「ドラフト」。サイドバーの行とのぞき窓の印は `--ink-quiet` の破線の丸
  （空の丸の未着手と同じ 12px で、枠だけ破線）
- **属性の札**: タスクの `difficulty`・`loopable` は、ラベル（枠付きの札）とは別の欄で出す。
  サイドバーの行は幅が狭いので属性を出さない（題の幅を取るため）。モーダルの左の一覧の行は1段目の右端に、字を使わずアイコンだけで置く。
  `difficulty` は点3つ（5px・間 2px）のうち haiku 1・sonnet 2・opus 3 を `--ink` の 80% で塗り、残りは `--rule`。
  `loopable` が `Y` のものだけ点の左に lucide の `Repeat`（12px・`--ink-quiet`）を添え、`N` は何も出さない。
  どちらも名前は `role="img"` の `aria-label` に持つ。詳細の情報の表の「難しさ」「ループ」の2行は字の札
  （等幅・`--font-label`・`--ink-quiet` で枠なし。`loopable` が `N` のものだけ `--state-warn` の枠と字）
- **右の詳細**: 上下 22・左右 28。ID 13px 等幅＋status の札、タイトル 20px 太字、情報の表 12px
  （行の間 8・角丸 10）。本文は 14px・行間 1.85、見出しは 16px 太字＋下線、コードは 12px 等幅、
  チェックは 14px。詳細は内側で縦に転がし、見出しの帯と下の操作の帯は動かない
- **下の操作の帯**: 高さ 64。ボタンは高さ 36（「tsukumo に頼む」だけ 40）。「tsukumo に頼む」は
  `--accent` の地で、押せない間は薄くして横に理由の字を添える。ドラフトでは代わりに
  「却下する」（枠。高さ 36）と「計画する」（`--accent` の地。高さ 40）を右寄せで並べる
- **ドラフトの仕分け**（絞り込み「ドラフト」のとき。見本 `docs/history/mockup/task-board-draft-batch-2026-10-24.html`）:
  行の右端に3択（計画・却下・保留）を枠 `--rule-soft`・角丸 8 の1つの組で出す。札は `--font-label`・高さ 28 以上で、
  選んだ札は左の「●」と字の色でも言う（計画は `--state-ok`、却下は `--state-ng` の字と同じ色の 18% の地、保留は `--ink` の字と `--surface-raised` の地）。
  却下の行は要約の下に「却下の理由:」と1行の入力欄を出す。下端の帯は箱の全幅で、高さ 64・左に「仕分けを戻す」（枠。高さ 36）と
  `--ink-quiet` の「保留の n 件は触らない」、右に「計画 n・却下 m を頼む」（`--accent` の地。高さ 40）。
  帯が出ているあいだは詳細の下の操作の帯を出さない
- **つながりの札**（見本2）: 高さ 38・角丸 9・間 6、地 `--ground`・枠 `--rule`。ID 12px 等幅＋状態＋
  要約 13px（1行で省略）＋右端に ›。札の見出しは 12px で、「先に終わっていてほしいもの」は
  `--state-warn` の字、「これを待っているもの」は `--ink-quiet` の字
- **パンくず**（見本2）: 12px・高さ 20。「‹ <ID> に戻る」はリンクの色、区切りの › は `--ink-quiet`、
  いまの ID は等幅。「絞り込みの外」の添え書きは 12px の `--ink-quiet`
- **読み込み中**: 起こしてから最初の一覧が届くまで、サイドバーのタスクの節とこのモーダルの中身は、
  行の形をした帯3本（高さ 14・角丸 4・幅は 88%・72%・80%、色は `--ink` を 10% 重ねた色）で描く。
  文字の「不明」「読めない」は出さない。帯は 1.6 秒周期でゆっくり明滅し、`prefers-reduced-motion: reduce` では止める
- **狭い画面（760px 以下）は2列を縦に積む**（`docs/requirements.md` 4.7）。箱は画面の内側いっぱい
  （`100dvh` から余白を引いた高さ）で、一覧が上で高さは箱の 40% まで（内側で転がす）、詳細が残りの
  高さ（内側で転がす）、下の操作の帯は箱の下端に残す。見出しの帯のキーの案内は畳む

#### サイドバーのタスクののぞき窓

サイドバーのタスクの行と、そこから開くのぞき窓の見た目。見本は
`docs/history/mockup/sidebar-task-peek-2026-10-04.html`（場面1の行のホバーと場面3。画は同じ名前の
`.png`）。**値は見本のインラインの style が正**で、ここには要点と、見本の色をトークンへ写した対応だけを
置く（見本の #1f1e28 は `--surface`、#3a3946 は `--rule`、#2a2933 は `--rule-quiet`、#1f2e2e は
`--surface-accent`、浅葱 #66d1be は `--accent`、ボタンの字 #0d201c は `--ground`）。中身とふるまいは
`docs/architecture/display.md`「サイドバー」の「のぞき窓」。

- **字は 12px を割らない**（13.3。見本で 12px 未満の箇所は `--font-label` へ上げて写した: 窓の状態の語と
  ID・関わるタスクの行〔見本 11.5px〕、行の ID〔見本 11px〕。本文の中のコードの札〔見本 0.9em〕は 12px）
- **行**: 行全体が1つのボタン。4列の grid（印 14px・ID 50px・題 `minmax(0,1fr)`・`›` 16px）、列の間 10px、
  高さ 40px、内側の余白 0 8px 0 10px、角丸 9px、行どうしは 1px 空ける（罫線は引かない）。題は1行で末尾を
  「…」。**ホバーで地が `rgb(255 255 255 / 0.035)` になり、右端の `›`（14px）が `--accent` で出る**
  （ホバーしていない行では透明）。**窓を開いている行は `--surface-accent` の面と、`--rule` と `--accent` を
  混ぜた色の `inset 0 0 0 1px` の枠**（色だけで伝えない）。済んだ行は打ち消し線と弱い字のまま。
  進行中のカードもカード全体が1つのボタンで、1行目の右端に `›` を置き、ホバーと開いている間は枠を
  `--accent` にする

# 出力の分離（セリフと詳細）: 検証結果の描き方

戻り: `docs/architecture/display.md`「出力の分離（セリフと詳細）」

形を移ってきた経緯は `docs/history/decision.md`「display.md 4.2 検証結果の描き方（所要時間をモデルに書かせた条とカードの形）」と
「display.md 4.2 表示（2026-10-18 に display/ の子のファイルを軽くしたときに移した記録）」。

- **検証結果の1項目は `figure` と所要時間を載せる**。
  - **`figure`** はモデルが書く、結果を1つの数で言う短い文字列。数で言えなければ空文字で、描かない。
    **数だけを書かせ、「が通過」のような述語は付けさせない**。書式は「56 件中 1 件」のように何の数かを付けて描かせ、
    「2849 / 56」のような割り算・分数に見える書き方はさせない（`checks` の引数の説明が持つ。差し戻しはしない）
  - **`detail` は NG・未確認の理由だけを書く欄で、ok の行には描かない**（
    心がけの条ではなく描かないことで、言わずもがなの述語や打ち直した経緯を塞ぐ）。detail の長さで差し戻す仕組みは、
    それでも経緯が混ざるようなら足す
  - **所要時間は tsukumo が測った値だけを出す。** モデルは確かめに打った Bash のコマンドを
    **`command` に打った文字列のまま**書き（コマンドでない確認は空文字）、tsukumo は同じやり取り
    （最後の依頼より後）の `tool` の記録のうち、`Bash` の `command` が**完全一致する最後の1件**の
    所要時間を添える（サブエージェントの中の呼び出しも含む。測り方は「依頼の手順」と同じで、復元した記録は
    測れないので添えない）。一致しなければ添えない。
    **モデルに時間を書かせる欄は作らない**。段ごとの所要時間も同じく
    tsukumo が記録から求め、最終レポートでは検証の表の下に1本の帯と一覧で、中間レポートでは目録の1行に描く（「ワークプラン」の節）
  - **`run_in_background` の Bash は、走りだした時刻から完了の知らせが届いた時刻までを所要時間にする**。
    その tool_result は起動を受け付けた時点で返るので、tool_result の時刻で
    測ると起動の瞬間の時間になる。知らせは SDK の `system` / `task_notification` で、`tool_use_id` で記録に結ぶ
    （tool_result の文面は読まない）。**知らせが届かない・結び付けられないときは、起動の瞬間の時間を出さず空にする。**
    完了を待つ別の Bash（待ちのループ）を挟んでも、測るのは背景の Bash そのもの。背景かどうかは記録の `input` の
    `run_in_background === true`（Bash だけ）で決める（前景の Bash・前景のサブエージェントにも数秒を越えると知らせが届くため、
    知らせは背景で走らせた Bash の記録にだけ効かせる）。依頼の手順の所要時間も同じ測り方を通るので同じ値になる
  - 突き合わせはメインビューの組み立てで描くたびに行い、所要時間を記録には持たない。
    `figure` / `command` の無い前の形の記録は、2つを空文字として読む
- **検証の総括とお願いの合図を、結論のすぐ下の1行（合図の行）に置き、通った検証は畳む**（
  提案書 `docs/research/report-redesign.md` 3.1 の骨格の段。末尾のお願いを最初の1画面に入れるため）。
  中身は次の「総括行と開く行で描く」
  - 並びは「目録の1行 → 見出し（`task` があるとき）→ 結論 → `keyFigures`（あるとき）→ 合図の行 → 本文の節 → お願い」
  - 合図の行は本文の HTML に組み、頭の欄に置く。書き上げる演出は節にだけ掛かるので、結論と合図の行は
    最初から出る
  - **所要は合図の行に置かない**（経過と所要は進み具合の帯の1か所。`docs/architecture/screen-design.md` 13.13）
- **検証結果は、総括行と開く行で描く**（提案書 `docs/research/report-excellence-strategy.md` 3.1「判決の頭」。
  確かめていない行に「どう確かめればよいか」を添え、お願いの印を上端に置くため。見本は
  `docs/history/mockup/report-excellence-2026-10-17/after-first.png`〔題の位置は採らない〕）
  - **合図の行**（`role="group"`・`aria-label="検証結果"`）は検証結果だけを運ぶ。`checks` が空なら行ごと置かない
  - **枠と地を持たない**。上下と行の間を `--rule-quiet` の 1px の罫で区切り、色が出るのは記号と状態の語
    （✓ 通った・？ 確かめていない・⊘ 止まっている・✕ 落ちた）だけ
  - **状態は4つ**（`docs/research/harness-strategy.md` 3.4.1）。`ok`（通った）・`ng`（落ちた）・
    `unobserved`（確かめなかった・飛ばした。前の `unverified` はこれに読み替え、記録の `unverified` も `unobserved` として読む）・
    `blocked`（前提が止まっていて確かめられなかった。理由は `detail` に前提を書く）。
    **`unobserved` と `blocked` を `ok` と描かない**。`blocked` は `ng` と別の class（`checks-problem-blocked`・`checks-summary-blocked`）・
    記号（⊘）・語（止まっている）で描き、色は注意の色にせず弱い字の色にする
  - **総括行**: 「✓ 検証 n件 通った <通った行の `figure` を `·` で連ねる>」「？ k件 確かめていない」「⊘ j件 止まっている」「✕ m件 落ちた」を
    この順に並べ、無い部分は出さない（通った行が無ければ頭は「検証」の語だけ）。幅が足りなければ折り返す
  - **お願いの印**: `favor` があるときだけ総括行の右端に「● お願い 1 ↓」を置く。お願いの本体は末尾のままで、
    印はページ内のリンクで飛ぶだけ。押しても `location.hash` は書かずに転がす。演出の途中で押すと、押す操作が演出を打ち切って
    全部出してから転がる
  - **開くのは `ng`・`blocked`・`unobserved` の行だけ**（この順。同じ状態の中は書いた順）。左の列に記号と
    状態の語、右の列に「`label` ＋ `figure`・所要時間」、その下に `detail`、`unobserved` ならさらに「確かめ方: <`howToVerify`>」を置く。
    問題の並びは `role="table"`・`aria-label="検証結果の問題"`
  - **通った行は1行に畳む**: 「✓ 通った n件」と `label` の頭（最初の全角の括弧「（」より前。無ければ全文）を `·` で
    連ねた `<summary>` の `<details>`。開くと ✓・`label`・`figure`・所要時間の一覧（`role="table"`・`aria-label="検証結果"`）。
    全部通ったときも総括行とこの1行だけにする。開閉は保存しない
  - **`howToVerify`**（確かめ方）は `unobserved` の行で必須、`ok`・`ng`・`blocked` では空文字。空の `unobserved` は記法の違反で差し戻す
    （規約違反の1ターン1回の枠）。欄の無い前の形の記録は空文字として読む

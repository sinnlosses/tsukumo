# ワークプラン: フェーズごとの所要時間・フェーズが移ったときの中間レポート・合図の行・状態

戻り: `docs/architecture/display.md`「ワークプラン」

- **フェーズごとの所要時間は、tsukumo が記録の時刻から求めて最終レポートに1本の帯と一覧で描く**（
  モデルに書かせると書き忘れと、測っていない数が混じる。どのフェーズに時間がかかったかを長さの比で
  一目で見る形にした。見本は `docs/history/mockup/phase-time-band-2026-10-14.html`、旧い形は `docs/history/decision.md`
  「display.md 4.2 段ごとの所要時間の横棒グラフ」）。`report` の引数は増やさず、モデルに時間を書かせる欄も作らない
  - **描くのは最終レポートの印が立った本文だけ**（委譲を待つあいだの `report` に、済んでいないフェーズが
    「不明」で並ばないように）。やり取りが閉じていないあいだは印が立たないので出ない
  - **時刻は記録が持つ。** `work-plan` の記録（`finished` の `report` で tsukumo が閉じたものも）と `report` の記録が、届いたイベントの時刻
    を持つ。復元した記録は transcript の時刻が読めればその時刻、読めなければ不明になる
  - **求め方**（`src/shared/session/phase-duration.ts`）: フェーズ n の時間は、n が今のフェーズの集合に入った記録の時刻から、
    集合を出た記録の時刻まで。並列のフェーズの中のフェーズは、並列のフェーズに入った記録の時刻から一斉に始まり、それぞれ自分が済んだ記録の時刻で終わるので、
    重なって走ったフェーズもそれぞれの所要が出る。最後まで今だったフェーズは全部のフェーズを終えた記録（`finished` の `report` で tsukumo が閉じたものも）の時刻で閉じ、
    無ければ `report` を受け付けた時刻で閉じる。同じフェーズに戻ったら測れた区間を足す。読む範囲は最後の依頼より後の記録だけで、
    例外は止めて再開した依頼（前の依頼がフェーズを残して終わり、フェーズの並びが同じなら前の依頼の記録を引き継ぎ、待ちを抜いて区間をつなぐ。
    `finished` で全部のフェーズを終えた依頼のやり直しは引き継がない。決まりは
    `docs/architecture/screen-design/report-head.md`「レポートの頭（合図の行）」の「止めて再開した依頼をまたいで測る」）。
    開き直したときも同じ求め方で、並列のフェーズの区間も動いていたときと同じに戻る
  - **並列のフェーズの所要は壁時計**: `current` がその並列のフェーズを指していた区間で、中のフェーズの所要の和ではない。依頼全体の所要は進み具合のプログレスバーの
    「所要」が壁時計で持ち、重なったフェーズを二重に数えない
  - **帯の区間の長さは時間（ミリ秒）の比で、一覧に時間と割合を添える**: 帯は並列のフェーズが無い回の形で、フェーズごとに1区間（測れないフェーズは固定幅 12px の斜線の区間で、長さの比に数えない）。
    並列のフェーズがある回だけ、帯の代わりに開始の位置をずらした1行1フェーズの横棒（waterfall。`screen-design.md` 13.13）にする。
    **計は測れた区間（フェーズと、並列のフェーズは壁時計1区間）の和**で、見出しの行に「計 …」と書く。割合は「そのフェーズの時間 ÷ 計」の整数%。
    計は依頼全体の壁時計（進み具合のプログレスバーの「所要」）とは別の数で、不明のフェーズがあるときは測れた分の計になる。
    いちばん長い区間（測れたフェーズと並列のフェーズの壁時計のうち最長）だけ帯の色と一覧の行を強める
  - **並列のフェーズは、waterfall では親の棒を描かず中のフェーズの棒だけを1行1フェーズで描いて壁時計の区間を薄い囲みで示し、一覧は見出しの行と中のフェーズの行で描く**: 一覧の見出しの行は「並列 2–3」（範囲があれば「並列 本2–3」）と並列のフェーズの壁時計・割合、
    その下に中のフェーズの行を字下げして並べる（時間は各フェーズの所要、割合は空欄。計と割合には中のフェーズを入れない）
  - **時間を出さないフェーズは「未着手」「飛ばした」「不明」に分け、帯の中の斜線の区間（waterfall の中では幅 2% の欠片）で位置だけ示し、一覧に字で描いて、数を推し量らない。どれも計と割合に数えない**:
    `workPlanClosing: "stopped"` で終えた依頼で、止めて再開した依頼をまたいだ区間を含めて一度も今のフェーズにならず、最後の記録で済んでいないフェーズは「未着手」、
    記録の `skippedPhases` のフェーズは区間が測れていても「飛ばした」。次は「不明」: 停止以外で終えて済んでいないフェーズ・一度も今のフェーズにならなかったフェーズ（一足飛び）・端が不明の区間を含むフェーズ・
    読む範囲の最初のワークプランが途中の位置で始まったときのそのフェーズより前（前の依頼で始まり、フェーズの並びが違う・前の依頼にワークプランが無いなどで引き継がなかったフェーズ。雑談を挟んだ時間をフェーズの時間に混ぜない）。
    最初の `work_plan` が `current` 1 以上で始まる呼び出しも差し戻さず、前のフェーズを済みに数えて測れないフェーズにする
  - **フェーズの開始の記録は、作業の前に必ず残す。** 仕事のメインの `Edit`・`Write` は、その依頼で `work_plan` を受け付けるまで tsukumo が拒む
    （`docs/architecture/workflow-contract/port-and-return.md`「委譲の返却」のワークプラン前の編集の門）。作業を終えてから初めて呼ぶ形でフェーズが測れなくなるのを防ぐ。
    調べる・答えるだけの依頼は縛られず、`work_plan` の前の調べものの時間はフェーズ1の所要に入らない
  - **ワークプランを組み替えたら、最後のフェーズの並びで描く。** フェーズは名前と同じ名前の中の何番目かで追うので、並びに残ったフェーズは組み替える前の
    時間を引き継ぎ、並びから消えたフェーズの時間は帯にも一覧にも残さない（依頼全体の時間は進み具合のプログレスバーの「所要」が持つ）
  - **置き場は最終レポートの検証の表の下**（合図の行と同じ外枠の中）。ワークプランの無い依頼では描かない。中間レポート
    （フェーズのまとめ）には、終えたフェーズ1つぶんの所要を同じ求め方で添える（次の項）。見た目は `docs/architecture/screen-design.md`「レポートの頭（合図の行）」
  - **進み具合のプログレスバーのフェーズの丸の吹き出しも同じ求め方**: 済んだフェーズの所要とフェーズのまとめ、今のフェーズのこのフェーズの経過
    （閉じる時刻はプログレスバーの経過と同じく、数えているあいだはいま、数え終わったターンは終わった時刻）をフェーズごとに引く。
    測れないフェーズは「所要 不明」。見た目は `docs/architecture/screen-design.md` 13.13「進み具合のプログレスバー」
- **フェーズが移ったときの中間レポート**: フェーズが移ると、メインビューに
  終えたフェーズの中間レポートを出す（フェーズの移り変わりをプログレスバーのカードの書き換わりだけに残さない）。
  働くあいだも渡したあとも、中間レポートはいちばん新しいやり取りのカードの本文に出る（置き場は「各表示物」のメインビュー）。
  - **中間レポートの中身は、フェーズを進める `work_plan` の `phaseSummary`（フェーズのまとめ）で受け取る**。
    「終えたフェーズでしたこと・分かったこと」を1〜2文で、記法は `report` の `conclusion` と同じ。`report` に
    「途中」の印を足してターンを閉じない形にはしない（フェーズの切れ目と中間レポートを仕組みで揃える）。
    `sections` は借りない（畳まれる中間レポートに要るのはフェーズの結論だけで、詳しいことは最終レポートが持つ）
  - **途中の位置（済んだフェーズが1つ以上あり、全部済みでない）の呼び出しではフェーズのまとめを必須にし、無ければ
    差し戻す。2文以内は書く量の目安で、3文以上でも差し戻さず切り詰めもしない**（「」の中の句点で数えすぎ、
    差し戻すと呼び出しが丸ごと受け付けられずプログレスバーが進まない手戻りのほうが大きい）。
    差し戻しの固定文は、まとめが無い・それ以外の形の崩れで別になる（呼び出しの内容は入れない）。
    フェーズを前へ進める呼び出しは、全部のフェーズを終えたものを除けば必ず途中の位置に着地するので、フェーズが進んだのに
    まとめが無い、は起きない。「前より進んだか」で縛らないのは、途中の位置で戻る・組み替えるだけの呼び出しにも
    まとめを書かせるため（画面には出さない）。`phase_result` で進んだ位置でも、`summary` を持たない返却で済んだフェーズはフェーズのまとめが要る
    （`summary` を持つ返却で済んだフェーズは要らない）
  - **中間レポートは、そのフェーズでしたこと（フェーズのまとめ）と所要の両方を必ず出す**。
    所要は上の求め方で求める終えたフェーズの時間で、モデルには書かせない。測れない所要（不明の端・
    引き継がずに読む範囲の最初のワークプランが途中の位置で始まったフェーズ）は「不明」と出し、数を推し量らない。
    タスク見出し行の2行目は「中間レポート　1/3 フェーズの名前　所要 12秒」、畳んだ `<summary>` は「中間レポート: 1/3 フェーズの名前 · 所要 12秒」
  - **したことが空のままフェーズを進める呼び出しは差し戻す。** 途中の位置は上の決まりが、
    同じフェーズの並びのまま済んだフェーズを増やしてまとめが空の呼び出しも差し戻す。
    最後のフェーズを `work_plan` で閉じる呼び出し（`current` が要素の数に等しい）も差し戻し、
    閉じるのは `report` の `workPlanClosing` だけ。フェーズの並びを組み替えた呼び出しと、戻る呼び出しには掛けない
  - **何を出すかは、同じ依頼の直前のワークプランと比べて決める**（記録から描くたびに導く）:

    | 呼び出し                                                                      | 中間レポート                   |
    | ----------------------------------------------------------------------------- | ------------------------------ |
    | その依頼で最初のワークプラン                                                  | 出さない                       |
    | フェーズを進める（前の今のフェーズの1つが、新しい並びで済んだフェーズにある） | 出す                           |
    | 戻る・組み替えたが前の今のフェーズは済んでいない（今のフェーズ以降・消えた）  | 出さない                       |
    | 全部のフェーズを終えた（`current` = 要素の数）                                | 出さない（最終レポートが担う） |

    終えたフェーズは名前と同じ名前のフェーズの中で何番目かで探すので、フェーズを進めながら後ろのフェーズを組み替えても見失わず、同じ名前の済んだフェーズとも取り違えない。1フェーズだけのワークプランは
    `0 → 1` しか取らないので出ない。並列のフェーズの中のフェーズは1回に1フェーズずつ済むので、別々に済めばフェーズごとに1つずつ中間レポートが出て、
    所要はそのフェーズの区間（その並列のフェーズに入った時刻から、そのフェーズが済んだ時刻まで）

  - **フェーズのまとめの中間レポートは、タスク見出し行にラベルと終えたフェーズ（「中間レポート · 1/3 フェーズの名前」）を並べ**、
    畳んだ `<summary>` にも終えたフェーズを出す。**届いた時点で中間と決まるので、ターンが動いているあいだも
    伏せずに出す**（「各表示物」のメインビューの「確定するまで出さない」の例外）。最後の本文・最後の
    `report` の候補にはならない
- **合図の行は1つのまとまりに包み、結論・本文とのあいだを空ける**（デザイン「レポートの頭の空間 案1」）。
  あきは結論→まとまり 14px・まとまり→本文 26px（見本 `report-redesign.html` の値）。最終レポートは箱を
  持たない（「各表示物」のメインビュー）。検証の行は左右にはみ出させ、「✓ OK」の左端を本文の左端にそろえる
- 状態は `work-plan` の記録を届いた位置に積むだけで、今のワークプランと手順ごとのフェーズは記録から導く

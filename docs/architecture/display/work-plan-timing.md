# ワークプラン: 段ごとの所要時間・段が移ったときの中間レポート・合図の行・状態

戻り: `docs/architecture/display.md`「ワークプラン」

- **段ごとの所要時間は、tsukumo が記録の時刻から求めて最終レポートに1本の帯と一覧で描く**（2026-10-05 利用者決定。
  モデルに書かせると書き忘れと、測っていない数が混じる。2026-10-14 の利用者決定で案A「1本の帯と一覧」に作り替えた。
  どの段に時間がかかったかを長さの比で一目で見るため。見本は `docs/history/mockup/phase-time-band-2026-10-14.html`、旧い形は `docs/history/decision.md`「display.md 4.2 段ごとの所要時間の横棒グラフ」）。`report` の引数は増やさず、モデルに時間を書かせる欄も作らない
  - **描くのは最終レポートの印（`final`）が立った本文だけ**（2026-10-08 利用者指摘。委譲を待つあいだの `report` にも出て、
    済んでいない段が「不明」で並んでいた）。やり取りが閉じていないあいだは印が立たないので出ない（`markFinalReport` が本文を入れ替える）
  - **時刻は記録が持つ。** `work-plan` の記録（`finished` の `report` で tsukumo が閉じたものも）と `report` の記録が、届いたイベントの時刻
    （`RecordTime`）を持つ。復元した記録は transcript の時刻が読めれば `recovered`、読めなければ `restored`（不明）になる
  - **求め方**（`phaseDurations`。`src/shared/session/phase-duration.ts`）: 段 n の時間は、n が今の段の集合に入った記録の時刻から、
    集合を出た記録の時刻まで。並列の段の中の段は、並列の段に入った記録の時刻から一斉に始まり、それぞれ自分が済んだ記録の時刻で終わるので、
    重なって走った段もそれぞれの所要が出る。最後まで今だった段は全部の段を終えた記録（`finished` の `report` で tsukumo が閉じたものも）の時刻で閉じ、無ければ `report` を受け付けた時刻で閉じる。
    同じ段に戻ったら測れた区間を足す。読む範囲は最後の依頼より後の記録だけ
  - **並列の段の所要は壁時計**: `current` がその並列の段を指していた区間で、中の段の所要の和ではない。依頼全体の所要は進み具合の帯の
    「所要」が壁時計で持ち、重なった段を二重に数えない
  - **開き直したときも同じ求め方**: 区間の端は記録の時刻だけで、復元した記録も transcript の時刻（`recovered`）を持つので、並列の段の区間も
    動いていたときと同じに戻る。端が `restored` なら下の「不明」
  - **帯の区間の長さは時間（ミリ秒）の比で、一覧に時間（`formatElapsed`）と割合を添える**: 帯は並列の段が無い回の形で、段ごとに1区間（測れない段は固定幅 12px の斜線の区間で、長さの比に数えない）。
    並列の段がある回だけ、帯の代わりに開始の位置をずらした1行1段の横棒（waterfall。`screen-design.md` 13.13）にする。
    **計は測れた区間（段と、並列の段は壁時計1区間）の和**で、見出しの行に「計 …」と書く。割合は「その段の時間 ÷ 計」の整数%。
    計は依頼全体の壁時計（進み具合の帯の「所要」）とは別の数で、不明の段があるときは測れた分の計になる。
    いちばん長い区間（測れた段と並列の段の壁時計のうち最長）だけ帯の色と一覧の行を強める。測れない段は次の項目
  - **並列の段は、waterfall の親の棒は壁時計の1本、一覧は見出しの行と中の段の行で描く**: 一覧の見出しの行は「並列 2–3」（範囲があれば「並列 本2–3」）と並列の段の壁時計・割合、
    その下に中の段の行を字下げして並べる（時間は各段の所要、割合は空欄。計と割合には中の段を入れない）。1本道の段の行は今までどおり
  - **測れない段は帯の中の斜線の区間（waterfall の中では幅 2% の欠片）で位置だけ示し、一覧に「不明」と描いて、数を推し量らない**: 一度も今の段にならなかった段（一足飛び）・端が `restored` の区間を含む段・
    依頼の最初のワークプランが途中の位置で始まったときのその段より前（前の依頼で始まった段。雑談を挟んだ時間を段の時間に混ぜない）
  - **ワークプランを組み替えたら、最後の段の並びで描く。** 段は名前と同じ名前の中の何番目かで追うので、並びに残った段は組み替える前の
    時間を引き継ぎ、並びから消えた段の時間は帯にも一覧にも残さない（依頼全体の時間は進み具合の帯の「所要」が持つ）
  - **置き場は最終レポートの検証の表の下**（合図の行と同じ `status` の包みの中）。ワークプランの無い依頼では描かない。中間レポート
    （段のまとめ）には、終えた段1つぶんの所要を同じ求め方で添える（次の項）。見た目は `docs/architecture/screen-design.md`「レポートの頭（合図の行）」
  - **進み具合の帯の段の丸の吹き出しも同じ求め方**（2026-10-14 ユーザー決定）: 済んだ段の所要と段のまとめ、今の段のこの段の経過
    （閉じる時刻は帯の経過と同じく、数えているあいだはいま、数え終わったターンは終わった時刻）を、段の `key` ごとに
    `phaseRecapsOf`（`src/shared/session/phase-recap.ts`。所要は `phaseDurationOf`、まとめは中間レポートと同じ `shiftedPhaseOf`）で引く。
    測れない段は「所要 不明」。見た目は `docs/architecture/screen-design.md` 13.13「進み具合の帯」
- **段が移ったときの中間レポート**（2026-09-30 ユーザー決定）: 段が移ると、メインビューに
  終えた段の中間レポートを出す。段の移り変わりが帯の札の書き換わりにしか残らず、分かりにくかったため。
  働くあいだも渡したあとも、中間レポートはいちばん新しいやり取りの札の本文に出る
  （置き場は下の「各表示物」のメインビュー）。
  - **中間レポートの中身は、段を進める `work_plan` の `phaseSummary`（段のまとめ）で受け取る**。
    「終えた段でしたこと・分かったこと」を1〜2文で、記法は `report` の `conclusion` と同じ。`report` に
    「途中」の印を足してターンを閉じない形にする案は採らない（段の切れ目と中間レポートを仕組みで揃える）。
    `sections` まで借りる案も採らない（畳まれる中間レポートに要るのは段の結論だけで、詳しいことは
    最終レポートが持つ）
  - **途中の位置（済んだ段が1つ以上あり、全部済みでない）の呼び出しでは段のまとめを必須にし、無ければ
    差し戻す（`WorkPlanReview`。`summary-missing`）。3文以上も差し戻す**（`parseWorkPlan` が読まず、`WorkPlanReview` が `summary-too-long` で差し戻す。文の数え方は `report` の結論と同じ `sentenceCount`）。
    差し戻しの固定文は、まとめが無い・3文以上・それ以外の形の崩れ（`malformed`）で別になる（呼び出しの内容は入れない）。
    段を前へ進める呼び出しは、全部の段を終えたものを除けば必ず途中の位置に着地するので、段が進んだのに
    まとめが無い、は起きない。「前より進んだか」で縛らないのは、途中の位置で戻る・組み替えるだけの呼び出しにも
    まとめを書かせるため（画面には出さない）。`phase_result` で進んだ位置でも例外は無く、段のまとめが要る
    （`phase_result` は要約を持たない）
  - **中間レポートは、その段でしたこと（段のまとめ）と所要の両方を必ず出す**（2026-10-07 利用者決定）。
    所要は `phaseDurations` が求める終えた段の時間で、モデルには書かせない。測れない所要（`restored` の端・
    依頼の最初のワークプランが途中の位置で始まった段）は「不明」と出し、数を推し量らない。
    目録の1行は「中間レポート · 1/3 段の名前 · 所要 12秒」、畳んだ `<summary>` は「中間レポート: 1/3 段の名前 · 所要 12秒」
  - **したことが空のまま段を進める呼び出しは差し戻す。** 途中の位置は上の `WorkPlanReview` が、
    同じ段の並びのまま済んだ段を増やしてまとめが空の呼び出しは `WorkPlanReview` の `summary-missing` が差し戻す。
    最後の段を `work_plan` で閉じる呼び出し（`current` が要素の数に等しい）は `closed-by-plan` が差し戻し、
    閉じるのは `report` の `workPlanClosing` だけ。段の並びを組み替えた呼び出しと、戻る呼び出しには掛けない
  - **何を出すかは、同じ依頼の直前のワークプランと比べて決める**（`phaseShiftOf`。記録から描くたびに導く）:

    | 呼び出し                                                         | 中間レポート                   |
    | ---------------------------------------------------------------- | ------------------------------ |
    | その依頼で最初のワークプラン                                     | 出さない                       |
    | 段を進める（前の今の段の1つが、新しい並びで済んだ段にある）      | 出す                           |
    | 戻る・組み替えたが前の今の段は済んでいない（今の段以降・消えた） | 出さない                       |
    | 全部の段を終えた（`current` = 要素の数）                         | 出さない（最終レポートが担う） |

    終えた段は名前と同じ名前の段の中で何番目かで探すので、段を進めながら後ろの段を組み替えても見失わず、同じ名前の済んだ段とも取り違えない。1段だけのワークプランは
    `0 → 1` しか取らないので出ない。並列の段の中の段は1回に1段ずつ済むので、別々に済めば段ごとに1つずつ中間レポートが出て、
    所要はその段の区間（その並列の段に入った時刻から、その段が済んだ時刻まで）

  - **段のまとめの中間レポートは、目録の1行にラベルと終えた段（「中間レポート · 1/3 段の名前」）を並べ**、
    畳んだ `<summary>` にも終えた段を出す。**届いた時点で中間と決まるので、ターンが動いているあいだも
    伏せずに出す**（下の「各表示物」のメインビューの「確定するまで出さない」の例外）。最後の本文・最後の
    `report` の候補にはならない

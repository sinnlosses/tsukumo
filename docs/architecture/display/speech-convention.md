# 出力の分離（セリフと詳細）: セリフの規約と機械の出来事への反応

戻り: `docs/architecture/display.md`「出力の分離（セリフと詳細）」

ツールの定義の字数の推移と、切り替えの前の差し戻しの集計は `docs/history/decision.md`「display.md 4.2 レポートの記法（ツールの定義の字数の推移と切り替えの前の差し戻しの集計）」。

**行頭のマーカーの経路は撤去した**（2026-09-21 決定。根拠は `docs/history/decision.md`）。セリフは `speak` で言う規約に一本化されている。

**tsukumo の中でのセリフの規約は3か所に分かれる**（2026-09-23 改訂）: **呼ぶ回数・契機**は
`src/server/system-prompt/core/speech-cadence.ts`、**ターンの締め方**（`report` は作業を終えてから最後に1回呼び、締めのセリフは
`closing` に入れる。新しい事実の無いターンは `report` を呼ばない、など）は `src/server/report/core/report-notation.ts`、**口調・
言い回し**はキャラクターパックの `persona.md` が持つ。3つとも `systemPrompt` の append として
毎ターン渡る（「レポートの記法は、TUI と tsukumo で出し分ける」と同じ切り分け）。

**`~/.claude/output-styles/asuna.md`「セリフと詳細の書き分け」は TUI 向けの規約で、tsukumo の中では
効かない。** tsukumo はセッションを起こすとき出力スタイルを `default` で打ち消しており、
`asuna.md` を読むのは素の TUI を使うときだけ。

**分離を文章の規約で表す案は採らない**（経緯は `docs/architecture/adr/0009-speech-via-tool.md`）。

**そのほかの決まりごと**:

- **セリフに入れるのは役割で決める**（掛け声・呼びかけ・リアクション・感想・完了報告）。
  レポートに入るのは事実・根拠・手順・コード・表・判断とその理由
- **文体は役割で分ける。** セリフはキャラクターの口調、**レポートの本文は中立の技術文**
  （2026-09-14 決定）。規約を書く場所は `src/server/report/core/report-notation.ts` で、`persona.md` には
  書かない（「読む時間を減らす物差しと線引き」）
- **tsukumo 側のヒューリスティック分類（コードブロックは詳細、地の文はセリフ等）は採らない。**
  判定が壊れやすい。**小さいモデルに分離・整形させる案も採らない**（コスト・遅延に加えて、
  会話内容を外部に送らない規約と衝突する）
- **セリフが1つも来なかったターンの扱い**: **新しいターンが始まった時点（`request`）で
  吹き出しを空にする**（送信した直後に前のターンの一言が残っていると、次のターンに移ったことが
  画面から分からないため。2026-09-16 決定）。**空欄の表示は吹き出しに出さない**（2026-10-02。
  覆した理由は `docs/history/decision.md`「display.md 4.2 空の吹き出しのプレースホルダー（2026-10-02 に覆した記録）」）。
  セリフも反応も無ければ、吹き出しは1つも出ない
- **機械の出来事への反応**（2026-10-02 決定）: **吹き出しに出る話し言葉は `speak` と、迎えの挨拶と、
  挨拶とは別の問い合わせが書いた反応の行と、Claude Code が `report` の引数 `waitingLine` で前もって書く待ちの一言だけ**
  （待ちの一言は 2026-10-05 利用者決定。`docs/requirements/expression.md` 4.3「黙って立つだけの場面の埋め方」）。
  **パックに書いた定型文は出さない**（2026-10-05 利用者決定。パックの `reactions` の節は読まない。
  `docs/architecture/character-pack.md`「キャラクターパック」）。
  - 迎える局面に入るたび（新しく起こした仕事のセッション・仕事のセッションでの `/clear`。続きから起こした
    セッションの `/clear` も含む）と、続きから起こした仕事のセッション（2026-10-05 利用者決定）に、サーバが背景の
    使い捨ての `query()`（`haiku`）でパックの `persona.md` の口調の挨拶を書かせ、
    状態の `welcomeGreeting`（`none` / `writing` / `written` / `unwritten`）で配る。
  - そのセッション用の反応の行（再試行 `retrying`・失敗 `failed`・利用上限 `limited`・待ち `idle` の4つ。
    それぞれ文と表情）は、挨拶とは別の使い捨ての `query()`（`haiku`）が代（起こした1回）につき1回だけ書き、
    書けたときだけ状態の `writtenReactions`（`none` / `written`）に配る（挨拶と同じ答えで書かせると出力が長く、
    挨拶の締め切りに間に合わないため）。挨拶と反応の行は互いに独立で、挨拶が書けなくても反応の行が書けていれば反応は出る。
    書けなかった・まだ書いていないときは、その出来事で吹き出しを出さない（定型文に落とさない）。
  - 反応も挨拶もセッションの状態から導き、**吹き出しに出し始めたものは記録 `reaction` に積んで、
    セリフのログにも残す**（2026-10-15 利用者決定）。積むのは状態の畳み込みで、反応が変わりうる出来事のたびに前後の姿を比べ、
    新しく出たものだけを出し始めた時刻つきで積む（同じ反応の描き直しでは積まない。待ちの一言は待つたびに1件）。
    待ちの一言の2分はサーバの時計で数え、過ぎたら出来事を流して積ませる。組み直した記録を流し直すときは積まない。
    迎えの挨拶は札の名指しを画面だけが知るので、画面が表示した1行（札の名前込み）をサーバへ送り、
    サーバがいまの挨拶から組める文かを確かめて積ませる。挨拶の記録は挨拶1つにつき1件で、札が届いて文が変わったら
    文と表情だけを差し替え、時刻は最初に積んだときのまま。続きから起こした直後のおかえりは札を名指さないので、
    畳み込みが札の無い文で積む。反応の記録は、そのターンの `speak` のセリフと同じ並びでログに出て、押すとその表情へ遡る。

  出す条件は上から先に当たったもの:
  1. 雑談モードでは出さない
  2. API の呼び出しを待ってから呼び直している（`apiTrouble` が `retrying`）→ 書かせた再試行 `retrying` の行
  3. 局面が迎える（`docs/architecture/screen-design.md` 13.13）で、セリフが無い → `welcomeGreeting`
     の状態で出し分ける: `written` ならその文、`writing`（書いている途中）は吹き出しに「…」
     （雑談モードの typing indicator と同じ見た目）、`unwritten`（書けなかった）と
     `none`（書き始める前）は何も出さない
     - **挨拶は2つの文で届く**: 札があるときの文（札の名前の位置に差し込み口 `{札}` を1つ持つ）と、
       札が無いときの文。画面は出すときに、始め方の一覧の先頭の札の名前（タスクは ID、前回の続きは
       「前回の続き」）を差し込む。札の並びが後から変わっても名指しが古くならない
     - 1〜2文・改行なし。指示文で頼むのは50字まで、受け取った側の検査は60字まで（検査に余裕を持たせる）。
       表情は出力の形でパックの表情の選択肢から選ばせる
     - **反応の行は別の問い合わせで書かせる**: 材料は `persona.md` と表情の選択肢だけで、暦・迎え方・直近の挨拶を
       渡さない。出力の形（JSON Schema）で4つの出来事の行をどれも欠かせず、各行の表情を表情の選択肢に限る。
       長さは挨拶と同じく指示文で50字まで頼み、受け取った側が60字まで・改行なし・差し込み口 `{札}` を持たないことを
       検査する（差し込み口は指示文に書かない。検査だけで落とす）。
       1行でも検査に落ちれば答え全体を落として問い合わせ直す。行はそのセッションのどの時点で出ても通じる一言にする。
       直近の覚え（`welcome-greeting/<キャラ名>.json`）には挨拶の2文だけを入れ、反応の行は覚えない
     - **新鮮さ**の材料は月・曜日・時刻の帯と、そのキャラの直近に書いた挨拶5件（`~/.tsukumo/welcome-greeting/<キャラ名>.json`）。
       直近と同じ文は落とす。会話から導いた材料（前のセッションの要約・タスク一覧）は渡さない
       （`docs/coding-standards.md`「会話内容の扱い」）。続きからのおかえりには、続きからの印（迎え方）と
       前回からの経過の帯（transcript の最後の時刻からの経過を「1時間たらず」〜「1週間以上」の決まった語にしたもの。
       時刻が読めなければ「分からない」）を足す。数と決まった語で、会話から導いた材料に当たらない
       （2026-10-05 利用者決定。`docs/requirements/expression.md` 4.3「黙って立つだけの場面の埋め方」）
     - 書くのは新しく起こした仕事のセッションと、続きから起こした仕事のセッションのすべて（前回の待ちの一言が
       あっても、反応の行のために書く。前回の代の行は引き継がない）。続きからの迎え方は組み直した履歴から決め、
       組み直した依頼が1つも無ければ新しく起こしたときと同じ迎え方にする。
       疑似セッション・雑談では書かせない。代を起こしたときは挨拶と反応の行の問い合わせを同時に起こす。
       **起動と画面を開く流れはこの問い合わせを待たない**。どちらの問い合わせも、1回目が失敗（起こせない・API の失敗・
       検査落ち）したら1回だけ問い合わせ直す。**1回目が 5 秒経っても返らないときは、
       1回目を止めずに2回目を並べて起こし、先に書けたほうを使う**（負けたほうは中断し、足跡に残す）。
       **書き始め（問い合わせ直しを含めた全体）から 15 秒経っても届かなければ、
       問い合わせを中断して書けなかったことにする**（挨拶は `unwritten`、反応の行は配らない）。替えたあとで答えが届いても
       差し替えない（吹き出しが揺れないため）。`/clear` が続いたときなど、古い挨拶の問い合わせの答えが後から届いても
       配らない（新しいほうだけが効く）。`/clear` では `welcomeGreeting` をいったん `none` へ戻して挨拶だけを
       書き直し、反応の行の問い合わせは走らせない（`writtenReactions` もそのまま）。起こし直しでは状態が初期値へ戻り、
       新しい代が挨拶と反応の行の両方を書き直す
     - 書き込みを1回終えるたび（書けても書けなくても。中断は除く）に、診断ログへ1行
       （挨拶か反応の行か・結果・全体の所要・各回の結果と所要・検査落ちの理由の語）を残す。書いた文は入れない。
       `node scripts/runtime/diagnostic.ts` が並べたあとに、書いたものごとの失敗率と所要を出す
  4. 局面が渡すで、いちばん新しい依頼が組み直した記録（続きから起こして、まだ依頼を送っていない）→
     おかえり。組み直した最後のやり取りの `report` の `waitingLine`（前回 Claude Code が書いた待ちの一言）があれば
     それを迎える反応として出し、無ければ `welcomeGreeting` を 3. と同じく出し分ける。ただし
     始め方の一覧の札が出ない局面なので、`written` は札が無いときの文を出す。依頼を送れば局面が働くに移って消える
  5. 局面が働く・尋ねるで、そのターンにまだ `speak` が無い → 文を出さず「…」（迎えの挨拶を書いている間と同じ）
  6. 局面がつまずくで、利用上限で閉じた（`rate_limit` のエラーか、利用上限が `rejected`）→ 利用上限
     `limited`、ほかは失敗 `failed`（どちらも書かせた行）
  7. 局面が渡すで、ターンが閉じてから2分経った → 待ちの一言。いちばん
     新しい依頼より後の最後の `report` の `waitingLine` を出し、書かれていなければ（`report` を呼ばなかった・
     引数を省いた）書かせた待ち `idle` の行、それも書けていなければ tsukumo の既定の1文（キャラクターに依らない中立の文と `default` の表情）。依頼を送れば局面が働くに移って
     消え、次のターンが閉じるまで出し直さない（同じ待ちのあいだは出たまま）。続きから起こした直後
     （いちばん新しい依頼が組み直した記録）には出さない（4. のおかえりが出る）。数え始めはサーバが打ったターンの閉じた時刻なので、
     入力欄に打ち始めても、画面を離れて戻ってきても数え直さない（戻ってきたときに2分を過ぎていれば
     もう出ている）。立ち絵の動きは足さない。書く条は `report-notation.ts` の1文と引数の説明
  - **反応はそのターンのセリフより新しい位置（最新）に出し**、話し手の名前を添える。吹き出しの反応は押しても遡らない
    （遡るのはログの行から）。立ち絵は反応の行の表情になる（`docs/requirements/expression.md` 4.3「表情の源」の例外）。
    押して留めたセリフがあれば、そちらの表情が勝つ
  - **`speak` が届けば反応は消える**（受けた間の「…」は「まだ `speak` が無い」、再試行は `speech` が
    呼び直しの印を下ろすので）。最低の表示時間は持たない。失敗・利用上限はターンが閉じたあとなので、
    続きのターンか次の依頼で消える
  - 過去のターンを見ているあいだは出さない
  - 1つの出来事に行は1つで、同じ代のあいだは同じ行が出る（`/clear` でも替わらない。替わるのは起こし直したときだけ）
  - **中断は反応を出さない**（中断は局面が渡すに入り、失敗にも利用上限にも当たらない）
  - **表情 `bored` は自動では出ない。** 出るのは `speak` で選ばれたときか、書かせた反応の行がその表情を
    選んだときだけ

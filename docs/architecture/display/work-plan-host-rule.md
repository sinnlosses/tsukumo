# ワークプラン: tsukumo がメインを縛る振る舞い

戻り: `docs/architecture/display.md`「ワークプラン」

責務: どのワークフローにも同じに掛かる、tsukumo がメインを縛る振る舞い（委譲の返却に添える注記・委譲ゲート・ワークプラン前の編集の門・`phase_result` と `work_plan` の差し戻しの文面・まとめ待ちのフェーズ・組み直しで戻るもの戻らないもの・飛ばしたフェーズの印の差し戻しの判定・`speak` の `phase` の検査）を持つ。
読む時: 返却のあとのメインの作業のツールが拒まれる理由を知るとき、これらの判定・文面を直すとき。
直す時: 委譲ゲート・編集の門・注記・差し戻しの判定・まとめ待ちの扱いを変えたとき。

ワークフローの側はこの振る舞いを選べず、従うだけで守る手を持たない。ワークフローが守る契約は `docs/architecture/workflow-contract.md` と `docs/architecture/workflow-contract/` の子が持つ。

## 委譲の返却の注記

委譲先が `phase_result` を呼んだ返却は、プログレスバーを動かし、委譲ゲートと注記を立てる。呼ばなかった返却（古い plugin・計画だけの回）ではプログレスバーは動かないが、委譲ゲートは立ち、注記は返却ごとに次のどちらかを言う。

- 「委譲先は `phase_result` で結果を返した。」
- 「委譲先は `phase_result` を呼ばなかったので、返却ではプログレスバーは動いていない（計画だけの回なら正しい）。」

「呼んだか」は委譲先ごとに見る。委譲先のメッセージの `parent_tool_use_id` で `phase_result` の呼び出しと返却を対にし、形の合う呼び出しのあとの最初の返却1件だけが「呼んだ」になる。

## 委譲ゲート

- **効く範囲**: 仕事のセッション（`work_plan` が載る）で、同じ依頼にメインの受け付けたワークプランがあるときだけ。雑談のセッションの委譲と、
  ワークプランを渡していない依頼（`work_plan` を呼ばない依頼）の返却では立てない。`delegatedRange` の宣言は条件にしない
- **返却かワークフロースクリプト（`Workflow`）の完了の知らせが届いたら印を立て、メインの `work_plan` が受け付けられたら下ろす。** 中身は見ず、届いた事実だけで立てる
  （`phase_result` を呼ばなかった返却・やり直し・`stopped` でも立つ）。ワークフロースクリプトの完了の知らせは、`task_started` の `task_type` が `local_workflow` だった `task_id` と同じ `task_id` の `task_notification`
  （完了・失敗・停止を区別しない）で、`task_notification` 自体に `task_type` は無いので走り出しの `task_id` を覚えて突き合わせる。走り出しを見ていない知らせとワークフロースクリプトでないタスクの知らせでは立てない。ワークフロースクリプトの中の委譲先が `phase_result` で進めたプログレスバーは、完了の前に既に進んでいる。返却の数は数えず、続けて届いても `work_plan` 1回で下りる。差し戻された `work_plan` では下りない
- **印が立っているあいだ、メインの作業のツールを拒む。** 通すのは読み取りのツール（`Read`・`Grep`・`Glob`・`ToolSearch`）と
  tsukumo の MCP ツール（`speak`・`work_plan`・`report` など）。委譲先のツールは対象にしない。
  拒否文の末尾に、返却で進んだあとのプログレスバーの位置（`work_plan` の戻り値と同じ文）を足す
- **返却を運ぶメインの入力に、返却の本文とは別の tsukumo の注記を1回だけ添える。** 注記は返却ごとに「`phase_result` で結果を返した」か「`phase_result` を呼ばなかったのでプログレスバーは動いていない」かを言い、末尾に次のプログレスバーのフェーズと
  群ごとの数え方と、本の番号が委譲先のフェーズと同じであることと、セリフで番号を言うのは本のフェーズだけなこと（`work_plan` の戻り値と同じ文）を付ける。返却が続けて届けば、まだ添えていない返却の文を重ねる。
  受け付けた `work_plan`・次の依頼で溜めた注記を捨て、組み直しでは足さない。
  ワークフロースクリプトの完了の知らせの注記は「ワークフロースクリプトが完了した。ワークフロースクリプトの中の委譲先が `phase_result` で返した結果で、プログレスバーは進んでいる。」と言い、同じプログレスバーの位置の文を末尾に付ける。
  掛かるのは `UserPromptSubmit` のフックで、返却の入力（`<agent-message` で始まる）とワークフロースクリプトの完了の入力（`<task-notification` で始まる）はメインが手すきでもターンの途中でもここを1回通る
- 印と注記の元は、委譲先の `SubagentHandback` の呼び出し（`delegate-handed-back`）と `phase_result` の呼び出し（`phase-result-called`）、ワークフロースクリプトの走り出し（`workflow-started`）と完了の知らせ（`task-notified`）。
  委譲先のメッセージのうち前の2つだけを `WorkPlanReview` に通し、あとの2つはメインの `system` メッセージから作る。
  委譲先が `SubagentHandback` で返すのは、許可モードが `auto` で auto に対応するモデルのときだけで、それ以外の返却（`<task-notification>`）では印も注記も立たない
- 差し戻しの返却を受けて同じフェーズをやり直させるときは、同じ位置のまま `work_plan` を呼べば下りる
- 印は組み直しでは戻さない
- 許可の判定は `PreToolUse` のフック（許可モードによらず毎回呼ばれ、`agent_id` でサブエージェントの中を見分けられる）。疑似セッションは `work_plan` の判定もしないので、委譲ゲートも効かない
- 判定の実装は `judgeToolAgainstGate`（`src/server/work-plan/core/work-plan-gate.ts`）と `CallReview` の `gateRaised`

画面の側の説明（拒否文の見え方・防げないこと）は `docs/architecture/display/work-plan.md`「委譲ゲート」。

## ワークプラン前の編集の門

- **効く範囲**: 仕事のセッションのメインだけ。雑談のセッションと、サブエージェントの中の呼び出しは対象にしない
- **条件**: その依頼で受け付け済みの `work_plan` が無いあいだ（`WorkPlanReview.planMissing`）。判定は記録の事実だけで、文面は読まない。
  差し戻された `work_plan` のあいだも受け付け済みは無いので拒み続け、`request` で掛かり直す。最後のフェーズを `report` で閉じたあとは掛からない
- **拒むもの**: `Edit` と `Write` だけ。`Bash`・`Agent`・`SendMessage`・`NotebookEdit`・読み取りのツール・tsukumo のツールは通す。
  拒否文は `work_plan` を `current: 0`（フェーズ1）で先に渡すよう言い、プログレスバーの位置は足さない。利用者には見えない差し戻し
- **通すもの**: 自動メモリの置き場（`…/.claude/projects/<1語>/memory/…`。`..` を含むパスは除く）への書き込み
- 委譲ゲートの印（`gateRaised`）とは別の判定で、意味を混ぜない。掛かるのは同じ `PreToolUse` のフック（`judgeEditAgainstMissingPlan`）

## phase_result の差し戻しと動かさない条件

- 引数は zod で検証し、形が合わなければ差し戻す（`phase` と `count` の片方だけ、`phase` が `count` を超える、`reason` の有無が `outcome` と合わない・空白だけの `reason`）。
  メインの呼び出しは `PreToolUse` のフックが `agent_id` の無い呼び出しとして拒む（メインは `work_plan` で進める。SDK の handler は呼び手を知らないので、handler では見分けない）
- プログレスバーを動かさない条件と、段の id を渡したワークプランで順を外れる申告を差し戻す例外は `docs/architecture/workflow-contract/port-and-return.md`「委譲の返却」の「プログレスバーの進め方」が持つ。
  `step` で返した呼び出しは範囲によらず `phases` のその id のフェーズに当たり、今のフェーズの集合にあれば済ませ、済んだフェーズ・先のフェーズは差し戻す
- プログレスバーを動かす判定は handler が行い、プログレスバーを動かしたときだけ、結果を読んだ形の返却のイベントを1件流す（画面のプログレスバーはそれで動く）
- 戻り値は `work_plan` と同じく `ok` の次の行にプログレスバーの今のフェーズ。プログレスバーを動かさなかったときは、その行の頭に「プログレスバーは動いていない。」を付ける
- 計画だけの回は `phase_result` を呼ばない（計画だけの回の返却で範囲の差し戻しは掛からない）
- 委譲ゲートは `SubagentHandback` の返却と、ワークフロースクリプトの完了の知らせで立つ。`phase_result` は許可モードによらず呼べるので、`<task-notification>` で返る委譲でもプログレスバーは進む（ワークフロースクリプトでない委譲の完了の知らせでは委譲ゲートは立たない）

## まとめ待ちのフェーズ

`summary` を持たない `phase_result` で済んだフェーズのまとめは、返却のあとメインが同じ位置で呼ぶ `work_plan` の `phaseSummary` に書く（省けない。`summary` を持つ場合は `docs/architecture/workflow-contract/port-and-return.md`「委譲の返却」）。
まとめの空のまま返却で済んだフェーズは**まとめ待ちのフェーズ**になり、次に受け付けた `work_plan` が `phaseSummary` を持ち、そのフェーズがまだ済んでいれば、そのまとめをそのフェーズの中間レポートにする。
まとめ待ちのフェーズは1つだけ覚えるので、メインの `work_plan` の前に `phase_result` が2件続けてフェーズを済ませると（並列のフェーズ）、先のフェーズはまとめ待ちから外れ、中間レポートが出ない。

## 組み直しで戻るもの・戻らないもの

トランスクリプトからの組み直しは、メインの transcript だけを読み、委譲先の `phase_result` の呼び出しを持たない。

- 確定した範囲は、受け付けた `work_plan` の答えの行「委譲先のフェーズの範囲: first=N count=M」から読む（行が無い古い記録は、呼び出しに書かれた範囲のまま。`pending` は復元後も `pending`）
- 委譲ゲートの印と注記・`phase_result` で付いた飛ばした印は戻さない

## speak の phase の検査

セリフが委譲先のフェーズを番号で言うときは、その番号を `speak` の任意の引数 `phase` で申告する（意味は `docs/architecture/workflow-contract/port-and-return.md`「委譲の返却」）。
範囲があるあいだ、`phase` が 1〜`N` の外なら差し戻す。セリフ・レポート・`phaseSummary` の本文のフェーズの番号は読まず、`phase` を省いた `speak` は検査しない。

## 飛ばしたフェーズの印の差し戻し

`skippedPhases` の意味と描き方は `docs/architecture/workflow-contract/skill-sequence.md`「スキルの契約」と `docs/architecture/display/work-plan.md` が持つ。差し戻す判定は受け付けた呼び出しを覚えている `WorkPlanReview` が行う。

- **メインで走るフェーズの `skipped`**: `skippedPhases` の名前は `phases` に含まれ、その呼び出しで済んでいるフェーズ
  （`current` より前の要素のフェーズか `finishedInGroup` のフェーズ）でなければ差し戻す。
  前に受け付けた呼び出しで印なしに済んでいたフェーズを新しく入れる呼び出しは差し戻す（済ませたフェーズをあとから飛ばしたフェーズに変えない）。
  前に受け付けた呼び出しで `skippedPhases` に入れたフェーズを、その呼び出しでもまだ済んでいるのに外した呼び出しも差し戻す（飛ばしたフェーズをあとから済ませたフェーズに変えない。
  黙って印を消すことも残すこともしない）。そのフェーズが済んでいなくなった（位置を戻した・並びから消えた）呼び出しでは、印も消える。印はフェーズの名前で持つので、同じ名前のフェーズは見分けない
- **委譲先で走るフェーズの `skipped`**: `phase_result` で付いた印は `WorkPlanReview` が覚え、同じ依頼のワークプランのあいだ、そのフェーズが済んでいるかぎり残す
  （受け付けた `work_plan` の記録に足す）。組み直しでは戻らない
- **範囲の外のフェーズ・済んだフェーズの `skipped`**: `phase_result` がプログレスバーを動かさない条件に当たれば、印も付けない。
  `work_plan` では、済んでいないフェーズの名前と、印なしに済んでいたフェーズの名前は差し戻す

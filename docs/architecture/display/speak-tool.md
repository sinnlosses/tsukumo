# 出力の分離（セリフと詳細）: speak と report のツール

戻り: `docs/architecture/display.md`「出力の分離（セリフと詳細）」

**1つのターンを「セリフ」と「詳細（レポート）」に分け、別々の領域に出す。** 同じ内容が2箇所に
出ると、キャラクターとのやり取りがノイズに埋もれる。

**セリフは MCP ツール `speak(text, expression)` で受け取る**（2026-09-11 決定）。

- tsukumo がプロセス内の MCP サーバとして `speak` を提供し、モデルが呼んだらその `text` を
  吹き出しに出す。`expression` はキャラクターパックにある表情名から選ぶ（4.3）
- **戻り値は `"ok"` だけ**にする。ツールの結果はモデルの文脈に戻るので、ここに情報を載せると
  tsukumo からモデルへの逆流路ができる。例外は次の4つで、**5つ目を足すにはユーザーの決定が要る**:
  - 仕事の `report`: 返すのは、差し戻すときの**規約違反とその直し方だけ**と、通ったときの**結論の1文目**
    （モデル自身が書いた文を返すだけで、`conclusion` 配列の1要素目を返す。orca の通知が最後のツール結果を
    本文に使うので、差し戻しの文を通知に残さないため。2026-10-24 決定）。描けたか・どこに出たかといった
    画面の状態は載せない（2026-09-23 ユーザー決定。レポートの出力を「検査 → 整形 → 描画」に分けた検査の段。
    `src/server/report/core/report-review.ts`）。差し戻しは次のそれぞれで別に1ターンに1回まで:
    - 「レポートの記法」の条のうち機械で判定できるもの。文字の並びで判定する条は、`conclusion` の1要素目が全角50字超・3要素以上・
      見出しが30字超か疑問文・地の文と表のセルの `A → B`（インラインコードの中・`from` / `to`・
      `flow` は通す）・`list` の項目の頭の「名前: 説明」（URL・時刻・インラインコードの頭・20字を超える頭は通す。`cards` は除く）・
      項目が 2〜4 の外か `label` の空の項目がある `cards`・
      全部の項目に `label` がある3段以上の `ordered`（`flow` にする）・仮名も漢字も無く英語の語が3つ以上の `text` の塊
      （見出しは対象にしない。インラインコード・リンク・パスは数えない）・行が2つ以上の `table` で、ある列のセルの平均が全角35字以上
      （`sentence-table`。状態のセルは `text`、変わったセルは `from` と `to` を足した長さで数える。インラインコードとリンクの URL は数えない。
      セルは語句・数・状態にし、文の列は `label` 付きの `list` か文の塊へ移す）。`checks` の素の文字のバッククォートは差し戻さず、整形で外す
    - 同じターンで受け取った `report` と同じ引数の送り直し（固定の一文）
    - 直前に描いた `report` のあとに、新しい依頼・メインが呼んだツールの結果・バックグラウンドタスクの終わりのどれも
      届いていない `report`（新しい事実の無い言い直しとして固定の一文。文面の近さでは判定しない。サブエージェントの
      合図は `speak` で言い直すもので、流れにも見えないので数えない）
    - ワークプランの閉じていない `report`（「ワークプラン」の「ワークプランの閉じていない `report` を差し戻す」）
    - `task.outcome` が `finished` なのに `checks` に `status` が `ng` の行がある `report`（固定の一文。本文も `checks` の
      中身も写さない。`task` の無い `report` は見ない）
    - 背景のシェル（`run_in_background` の Bash、または 120 秒を超えて背景に回ったもの）が生きたまま呼ばれた `report`
      （止めるか待つかをモデルに決めさせる固定の一文に、残りのシェルの ID と `description` を載せる。背景のサブエージェント・
      その他の種類・脇の話のターンは対象にせず、`description` は戻り値にだけ載せて `report-usage` の記録には種類の名前だけを残す）
  - 仕事の `speak`（2026-10-03 ユーザー決定）: 返すのは新しい事実の無い呼び出しを差し戻す固定の一文だけ（下の委譲の箇条）
  - 雑談の `remember` / `forget`: 返すのは書けなかった・消せなかった理由の種類ごとの固定の一文だけで、渡された行・
    覚えた行は載せない（4.9「プロフィールの書き戻し」）
- **検査を通った `report` の本文は、描く前に整形する**（同じ決定の整形の段。`src/shared/report/report-tidy.ts`）。
  落とすのは**落としても意味が変わらないものだけ**で、言い換え・要約・並べ替えはしない: 本文の冒頭で `conclusion` を
  繰り返しているもの（冒頭の `text` の塊か、逃げ道の頭の行）・前置きと締めの定型だけの `text` の塊と逃げ道の行
  （閉じた一覧との丸ごとの一致。型で当てると中身のある行まで黙って消えるので置かない）・逃げ道の中の中身の無い見出し・
  塊が残らなくなった節。**分担の基準は「直すのに書き直しが要るか」**——要るもの（段落を表へ移す・
  結論を短くする）は検査が差し戻し、消すだけで直るものは整形が黙って落とす。同じ条を両方には置かない。
  **記録は引数のまま持ち、メインビューの導出で掛ける**ので、規則を変えると過去のやり取りと、セッションの復元で
  組み直したやり取りにも効く。**空行の連続は詰めない**（どこでも1つの切れ目と同じに描かれ、フェンスと HTML の
  塊の中では中身なので）。`report` の無いやり取りの本文には掛けない
- **呼ぶ頻度・契機・セリフに入れる中身は tsukumo 側が持つ**（2026-09-16 決定。書く場所は `SPEECH_CADENCE_PROMPT`）。
  回数は数で縛らず契機で言い、ツールを走らせる前に1回、その結果で分かったことがあればもう1回。
  **無言が続いたときの2つ**（2026-10-14 ユーザー決定。直前の `speak` から読む・探す・編集するツールが5回以上続いたとき、
  数十秒以上かかるコマンドの前）は、直前の `speak` から間もないあいだは足さない（段の切り替えの直後に二度続けて
  話さないため。モデルは時計を持たないので、「一定時間」はツール呼び出しの数で近似する）。セリフの中身は
  **「いま何をしていて、そこでどう感じているか」**が分かるものにする（ユーザーへの問いかけを増やすのではない）。
  **どのパックでも吹き出しが長く止まらない**ことは tsukumo 全体の体験なので、パックの `persona.md` には書かない
  （パックが決めるのは口調・言い回しだけ）。tsukumo は呼ばれたら出すだけで、判定に推測が要らない
- **サブエージェントへの委譲は背景で行い**（2026-09-16 決定）、tsukumo が `PreToolUse` の `updatedInput` で
  メインの `Agent` 呼び出しの `run_in_background` を `true` に固定する（書き忘れても差し戻さず、`prompt` など他の引数には
  触らない。サブエージェント内の呼び出しは対象外）。フォアグラウンドの委譲はツール呼び出しの中でメインを止め、
  吹き出しが数分単位で止まるため。進み具合をサブエージェントからの合図（`状況 | …` の1行）で受け取ってメインが
  `speak` で言い直す（帯の段は合図ではなく、委譲先の `phase_result` で tsukumo が進める。「ワークプラン」）。
  **合図（進み具合の1行か、委譲の完了の知らせ）の届いていないターンでは `speak` も `report` も呼ばない**
  （2026-09-27 決定。新しい事実の無いセリフの言い直しを防ぐため）。**仕事では仕組みで止める**（2026-10-03 ユーザー決定）:
  直前に描いたセリフのあとに新しい事実が届いていない `speak` は、handler が `isError` で差し戻し、
  吹き出しに出さない（新しい事実が届くまで毎回。差し戻しの一文は `speech-review.ts` の1か所）。
  新しい事実に数えるのは `report` の差し戻しと同じもの（依頼・メインのツールの結果・バックグラウンドタスクの終わり）と
  ターンの頭（合図や完了の知らせで claude が自分で始めたターンを含む）で、`speak` 自身・`work_plan`・差し戻した呼び出しは
  数えない。雑談では差し戻さない（1ターンに `speak` を何度か呼ぶのが普通の形）。
  Claude Code は `speak` だけのステップが続くと、言い直しを誘う一文をターンの途中に差し込むので、子プロセスに
  `CLAUDE_CODE_SILENT_TURN_REMINDER=0` を渡して切る（仕事・雑談の両方）
- **委譲中に吹き出しが5分黙ったら、委譲先の進みの1行をメインへ差し込む（進みの差し込み）**（2026-10-18 利用者決定。
  委譲先が合図を送らずに長いコマンドや調べものに入ると、吹き出しが何分も止まるため）。
  SDK に `agentProgressSummaries` を渡し、委譲先の `task_progress` の `summary`（約30秒ごとの「いま何をしているか」の1行）を受ける。
  差し込むかは文面を見ず、3つの状態だけで決める（`progress-nudge.ts`）: 背景のサブエージェントが顔ぶれにいる、
  最後に描いたセリフ（差し戻して描かなかったものは数えない）から5分経った、そのあとに新しい要約が届いた。
  満たせば最新の要約を1通だけ `<tsukumo-progress>` の包みで送る。時計は描いたセリフ・差し込み・委譲の始まりのうち
  最後のものから測る。委譲先の `speak` が描かれても戻る（吹き出しが黙っていないことが目的のため）。
  メインがターンの途中なら次の終わりまで預け、そのあいだにセリフが描かれたら捨てる。
  - **答えは `speak` 1回で、`report` も本文も書かない**。要約をそのまま流さず「いま何をしていて、そこでどう感じているか」に
    言い直す（合図と同じ扱い）。差し込みは `speak` の新しい事実にだけ数え、新しい事実の無い `report` は差し戻したまま
  - **差し込みは利用者の発言にしない**。`request` を流さず、ターンの始まりは続く `init` から `turn-resumed` を補う。
    組み直しも入力の控え（控えに無い入力は包み）で見分けて `turn-resumed` にするので、組み直した画面にもセッションの要約の依頼の数にも出ない
  - **要約は委譲先の会話から作られた字なので、差し込む文面にだけ入れる**。駆動が送り出す手前で捨て、
    畳み込み・ブラウザ・ログに届かない
- **レポートは MCP ツール `report(task, conclusion, checks, figure, sections, favor, closing, waitingLine)` で受け取る**（2026-09-24 決定。
  仕事のセッションでは常に載り、雑談では載らない）。**検査を通った `report` はそこでターンを閉じる**
  （2026-09-27 決定。handler が結果に `_meta["claude/endTurn"]` を付け、Claude Code は assistant を挟まずに
  ターンを終える。差し戻した呼び出しには付けないので、モデルは直して呼び直せる。`docs/research/report-block.md` 13章）。
  - **差し戻しのあとの出し直しは、直す欄だけを渡せばよい**（2026-10-20 利用者決定）。渡さなかった欄は、同じターンで
    直前に差し戻した呼び出し（引き継ぎで組んだ値を含む）の値を引き継ぐ。空の値（`favor: ""`・`checks: []`）を渡すと上書きになる。
    土台を捨てるのは、受け付けたとき・ターンの頭（`session-info`・`turn-started`・`turn-resumed`）と終わり（`turn-finished`）・
    利用者の新しい言葉（`request`・`aside`）。差し戻しが続けば、土台はいちばん新しい差し戻しの組み上げ値に置き換わる。
    この項より下で「必須」と書く欄は組んだ値に欠かせない欄で、schema の上ではどれも任意。
    組んだ値が欠かせない欄を欠くと形の検査で差し戻す（記録の理由は `tool-error`）。
    土台は1つ（`ReportInheritance`）で、動かすのは流れに届いた呼び出しと結果だけ。結果が `isError` なら、handler に届かず
    入力検査で落ちた呼び出しも、組んだ値が欠けた呼び出しも、判定で差し戻した呼び出しも同じに土台になる。
    描く値は `assistant` メッセージの変換のあとにこの土台で埋め、handler も届いた引数を同じ変換（`reportEvents`）で
    イベントの形にしてから同じ土台で埋め、その値で判定と題の書き込みをする（判定と描画は、どの経路のあとも同じ値を見る）。
    handler は直前の呼び出しの結果が先に流れに届いていることを当てにしている（モデルは結果を読んでから呼び直すため）。
    土台はサーバのメモリにだけ置き、復元とセッションの中身は transcript の並びから同じ規則で組み直す
    （見分ける印が無いので、導入より前の transcript にも掛かる）。`sections` は空の配列を受け付けないので、節を全部消す口は無く、
    消したいときは塊1つで置き換える。使われ方の記録には、引き継いだ欄の名前だけを `inheritedFields` に残す
  - **締めのセリフは必須の引数 `closing`（`speak` と同じ `text` と `expression`）で受け取り**、
    レポートを描いたすぐ後ろに吹き出しへ出す（差し戻した呼び出しの `closing` は出さない）。
  - **必須の引数 `sessionSummary` にはセッション全体の要約を毎回書き直して入れる**（2026-09-27 ユーザー決定。
    中立の文体で2〜3段落・1200字以内）。**残っていることは要約に書かず、必須の引数 `sessionRemaining` に入れる**
    （無ければ空の文字列。始め方の一覧の「前回の続き」の札の題と依頼の文になる。欄の無かった頃の `report` だけ、
    要約の段落の頭が「残り」の段落をサーバが残りとして読み、要約から外す）。どちらもレポートには
    描かず、セッションの切り替え画面が transcript の最後に通った `report` から読み戻す
    （`docs/architecture/screen-design.md`「切り替え画面」）。tsukumo は要約を別の場所へ書き出さない（transcript の
    ツールの入力に残るだけなので、`docs/coding-standards.md`「会話内容の扱い」の例外を増やさない）。
    書き方は引数の説明が持ち、毎回入れることは組んだ値の形の検査が持つ。任意の `title`（セッション一覧の
    見出し）と同じく、差し戻した呼び出しの値は、同じターンの出し直しで省いた欄に引き継がれたときだけ使う。
  - **必須の引数 `waitingLine`（待ちの一言。`closing` と同じ `text` と `expression`）には、依頼を待つ間に
    1回だけ吹き出しに出す一言を毎回書かせる**（2026-10-05 利用者決定。出す条件は「機械の出来事への反応」の6）。
    記録を読み戻す側は、必須にする前の記録のために欄が無いものも読める。
    `report` の記録に写り、transcript から組み直しても同じ値が戻る。
  - **必須の引数 `figure` にはレポートの図を1つ置くか、置かない理由を書かせる**（2026-10-13 決定。ADR 0028 の追記）。
    形は図の塊1つ（`image`・`mermaid`・`graph`・`svg`・`beforeAfter`・`chart`・`timeline`・`stats`・`dimension`。`sections` の同じ塊と同じ形）か
    `{ kind: "none", reason }` で、`reason` は `short-answer`・`no-shape`・`single-value`・`no-material` の4つ。
    図を置く条件と理由の意味は引数の説明だけが持ち、`REPORT_NOTATION_PROMPT` の条8は欄を指す1行だけにする。
    図は `checks` の下・`sections` の上に、見出しの無い先頭の節として描き、図の番号は `sections` の図と通しで振る（`figure` の図が「図 1」）。
    `none` は何も描かない（空の枠や札も置かない）。図の塊の検査（構文・はみ出し・種類）と画像の棚も、`figure` を先頭に含めて見る。
    `reason` が本文と合わない回は差し戻す（規約違反の1ターン1回の枠。`no-shape` なのに `sections` に
    `list` の `flow`・`beforeAfter`・`graph`・`mermaid`・`svg` がある回と、`short-answer` なのに節が2つ以上ある回）。
    欄の無い古い transcript の `report` は、理由が `unrecorded` の `none` に畳んで読む（`unrecorded` は書き手には出さない）
- ターンの途中の経過は `speak` で言う。雑談には `report` を使わない（1ターンに `speak` を何度か呼ぶのが普通の形なので、
  閉じるツールを置くと切れる）。`report` の外に書いたターンの本文（`assistant` のテキスト）は、`report` が1つでも
  呼ばれたターンでは画面に出さない。呼ばれなかったターンだけ、本文を詳細として扱い、「メインビュー」の選び方でレポートにする

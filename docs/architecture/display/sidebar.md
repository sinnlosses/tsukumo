# 各表示物: サイドバー

戻り: `docs/architecture/display.md`「各表示物」

- **サイドバー**: 上から (1) **タスク一覧**（起動先の Beads から読む。起こしてから最初の一覧が届くまでは節の中に行の形のスケルトン（帯3本。「不明」とは出さない）、前回読めた一覧が覚えてあればスケルトンの代わりにそれを出して、読んだ結果で差し替え、`.beads` があって `bd` が読めなければ届いたあと節の中に「不明」。起動先に `.beads` が無いときは、節ごと出さない〔`docs/architecture/adr/0025-no-project-settings.md`〕。節の見出しに歯車は無い（`docs/architecture/screen-design.md` 13.6・13.9）。`bd` の閉じていない課題と、閉じた課題のうち閉じた時刻が新しいものから10件〔11件目以降は出さない。サイドバーに断り書きは出さず、タスク板の一覧の末尾に出す〕で、見出しは固定の
  「タスク」で、件数・最新化の口・「一覧を見る」だけを並べる（**件数のチップと印の凡例は置かない**）。
  見出しの下には**探す欄**（`TaskSearchField`。ADR 0061 論点 5）を常設する。虫眼鏡の口は置かず、`/` は割り当てず、欄へ移るキーも持たない。
  語（保存しない）で番号・題・本文を段ごとに絞り、当たりの無い段は出さず、済みの段は開く。
  当たった語は題の中で強調し、欄の右端に件数と語を消す「×」を出す。
  ↑↓ で当たりの行を移り（フォーカスは欄に残す。サイドシートが開いていれば中身も追う）、Enter で行を押したときと同じく開く（広い幅ではサイドシート、狭い幅ではタスクのモーダル。変換中の Enter は開かない）。
  Esc は語があれば消し、語が空なら入力欄へフォーカスを戻す。
  当たりが0件なら段を出さず、探した範囲を言う1文を出す。頭の高さは語の有無とフォーカスで変えない。
  **一覧は状態の段に分ける**（`domain/task-stage.ts` の `stageTasks`。ADR 0061 論点 1）: 上から
  **いま**（進行中）・**つぎ**（着手可）・**待ち**（待ち・保留・想定外の値）・**ドラフト**・**済み**（完了）。
  段の見出しは小さいラベルで段の語と件数を出し、**0件の段は出さない**。**済みの段だけ畳んで始まり**
  （見出しは押せるボタンで、`aria-expanded`。押すと開く。開閉は保存しない）、ほかの段は開いて出す。
  段の中はファイルの順（番号の昇順）、済みの段だけ番号の降順。ドラフトはエージェントが聞かずに積んだドラフトの課題
  （Beads の `deferred` と metadata `draft`=`Y`。Beads アダプタが `draft` に畳む。行の印は破線の輪）。
  **行は2段**: 1段目に状態の印と題（12px・2行まで。入りきらない分は末尾を「…」にし、文節で折り返す）、
  2段目にタスクの番号・難しさの3段の目盛り・ループ可の∞ の順（12px）。保留・待ちは状態の印が言うので字にしない。
  難しさと ∞ は無い行でも同じ幅の空欄を取り、行をまたいで縦の位置をそろえる。
  **status は印の形で区別する**（色だけで伝えない）: 印はモーダルと同じ `TaskState`（絵と色と語は `task-modal.md`「状態の印」）で、着手可は輪、
  待ちは砂時計、保留は円に二本線、ドラフトは破線の輪、完了は円にチェック、想定外の値は注意色〔`--state-warn`〕の円に感嘆符。
  **進行中の行はカードにせず、同じ行の形で面だけ淡く色づける。完了の行に打ち消し線は引かない**。
  **題の中の `` `…` `` は、タスクのモーダルと同じ `TaskSummaryText` で等幅のコードのバッジにする**。
  **行どうしは罫線を引かず 2px 空ける**。**行全体が1つのボタンで、押すとサイドシートが開く**（下の「サイドシート」）。
  **字の大きさは役割で段を付ける**（区画の見出し・段の見出し・2段目は `--font-label`、題は局所のつまみ
  `--task-title-size`〔今は `--font-label` と同じ値。2段目とは色で分ける〔2段目は `--ink-quiet`〕〕、「一覧を見る」は別の段。
  値は `docs/architecture/screen-design.md` 13.3）。**区画の見出しは雑談中の区画と同じ小さいラベルの段・同じ左端**にする。
  **見出しの帯は、区画の中を
  スクロールしても上に止まる**（止まっていて下の一覧が潜っている間だけ、帯の下に
  1pxの線と影を出す。一番上までスクロールしているときは線も影も出さない。スクロールするのは
  段と行だけで、見出しの帯自体はスクロールしない）、(2) **下端の帯**（コンテキスト・5時間・7日の3つを、語・割合・細い棒の同じ形で並べるだけ。
  モデル・effort・許可モードの札は入力欄の下の行にある。3つのどれかを押すと、いまのコンテキストの使用量のカードと**プラン使用量のカード**の
  詳しい面が帯の上に開く。`docs/architecture/screen-design.md`「会話の画面の帯とサイドバーの下端の帯」・
  「使用量の行」）の2つ。
  **プラン使用量のカードは5時間枠と7日間枠の使用率と戻る時刻を1行ずつ出し、再読み込みのボタンを添える**
  （出どころは SDK の `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET`
  で、Claude Code の `/usage` と同じ値。調べた結果と採らなかった案は `docs/research/plan-usage.md`）。
  取り直すのは開いたとき・ターンが終わるたび・再読み込みを押したときと、「該当しない」が返った間
  （2・5・10・20秒の間隔で、値が出れば止まり、使い切れば取れなかった扱いにする）で、時計では回さない。
  再読み込みは出どころへ取りに行き直す（最後の知らせを出し直すのではない）。戻る時刻を過ぎた枠も
  取り直すまでは取った値のまま出し、取った時刻を添える。警告の色は付けない（割合の数字が言う）。
  取れないとき（API キーで使っている場合を含む）はカードの中に一言だけ出し、高さは変えない。**下端の帯は区画ではない**——
  見出しを名乗らず、サイドバーの左右いっぱいに広がり、上端の罫線と一段沈んだ地でタスクの区画と
  切り分ける。**キャラクターとセッションの切り替えはサイドバーに置かない**（
  帯の左上の顔と部屋の名前のラベルを押して選ぶ。`docs/architecture/screen-design.md`「キャラクターの選択メニュー」・
  「セッションのラベル」・「切り替え画面」。モード（仕事 / 雑談）とキャラクター画面へ入るボタンも帯にある）。**雑談中はこの形ごと差し替わる**（タスク一覧を出さず、プロフィール・
  最近の話題・覚えていること・下端の帯の4段になる。4.9「雑談モードで変わるもの」）。
  **経過時間はここに無い。入力欄の送信ボタンと同じ行に出す**。
  **サイドバー全体はスクロールさせず、区画それぞれの
  内側でスクロールする**（区画が増えて見出しごと画面の外へ流れるのを防ぐ）。
  **タスク一覧を見渡すのは区画ではなくモーダル**（サイドバーの領域が小さいため）:
  区画には**全件を段に分けて並べ、入りきらない分は区画の内側で
  スクロール**する（段の分け方は上のとおり）。見出しの右端に **「一覧を見る」** と、
  その左に最新化の口（下の「タスクのモーダル」の「最新化の口」）を置き、押すと**左に一覧の表・右に選んだタスクの詳細のモーダルが開く**（探す欄の語は検索欄へ引き継ぐ。形とふるまいは
  下の「タスクのモーダル」、寸法と色は `docs/architecture/display/task-modal.md` 13.12）。
  **サイドシート**（`TaskSheet`。見本と寸法と色は `docs/architecture/display/task-modal.md`「サイドバーのタスクの行とサイドシート」。ADR 0061 論点 2）:
  広い幅（761px 以上）で行を押すと、**サイドバーの左に、1件の詳細を出す非モーダルのサイドシートが開く**。
  サイドバーの一覧は動かさず、押した行を開いている印にする（行は `aria-expanded` と、開いている行だけ `aria-controls` でサイドシートを指す。`aria-haspopup` は持たない）。
  開いているタスクは `stores/task-sheet.ts` の `useTaskSheet` が持ち、サイドバーの行と会話の画面の置き場の両方が読む。
  **置き場は中央の列の進行の帯の下から入力欄の上まで**（`<ConversationLayout>` の差し込み口 `sheet`。メインビューと同じ区画の右に重ねる）で、
  **進行の帯と入力欄を覆わない**。最上位の層（popover）には出さず、矩形を測って置く処理も持たない。
  開いたまま入力欄に書いて送れる。761〜1100px で柱から開いたサイドバーとも重ならない（重ねたサイドバーの左に寄せる）。
  読み上げは `<aside>` で、名前は題（`aria-labelledby`）。
  中身は上から、前後のタスクへ移る口・「一覧モードで開く」・閉じる「×」 → タスクの詳細（一覧モードの右の欄と同じ `TaskDetail`。
  番号〔押すと写す〕・題・状態と難しさ・ループ・ラベルの表・つながり〔先に終わっていてほしいもの・これを待っているもの〕・本文の全文） →
  下端の操作の帯（一覧モードと同じ `TaskBoardAction`。「Issue を開く」と頼む口）。**作った日と担当は出さない**
  （一覧の項目が持っていないので欄を足さない）。
  **頼む口は一覧モードの帯と同じ範囲**: 押せるのは着手可と、依存の済んだ保留だけで、ほかは押せない口の横に理由を出す（ADR 0061 論点 1）。
  **「<キャラクター名> に頼む」は「<ID> を実行しますか」の確認（主ボタンは塗りの「頼む」）を重ね、OK でそのまま固定の文面
  （「タスク {id} を進めて。」）の `{id}` を ID にして送る**（入力欄に打つのと同じ
  経路。下書きには入れない。送ったらサイドシートも閉じる）。**歯車の「タスクの実行」のプルダウンで起動するスキル（入口のスキルから選ぶ）を選んでいれば、
  文面は「/スキル名 {id}」になる**（先頭の `/` と前後の空白は畳み、英数字・`-`・`_`・`:` 以外を含む値は未設定として
  固定の文面にする。確認に出る文面も同じ。保留なら末尾に「このタスクは保留なので、着手の前に判断を聞いて。」を添える。
  計画・却下の文面は変わらない。ADR 0025「2026-10-24 の改訂」）。キャンセル・Esc では送らず、サイドシートは残る。
  **ターンが動いている間は確認の中で断る**（送るボタンが
  進行中は黙って送らないため、出さずに黙らせない）。
  **ドラフト（`draft`）のサイドシートは頼む口の代わりに「却下する」と「計画する」を並べる**（
  置き場を覗かずに、画面で計画か却下かを選ぶため）。どちらも同じ作りの確認
  （「<ID> の計画を頼みますか」「<ID> の却下を頼みますか」。OK は「頼む」）を重ね、OK で固定の文面を入力欄を経由せず送る
  （計画は「ドラフト {id} を計画して。## 完了条件 と ## やること を書いて、着手できる todo にする。」、
  却下は「ドラフト {id} を却下して。理由を ## 結果 に書いて、dropped で閉じる。」）。
  tsukumo は Beads に書かず、書くのは会話側。送ったらサイドシートも閉じ、キャンセル・Esc では送らずサイドシートは残る。
  **「一覧モードで開く」は、サイドシートを閉じて行へフォーカスを戻してから、そのタスクを選んだタスクのモーダルを開く**
  （探す欄の語も検索欄へ引き継ぐ。モーダルを置くのは仕事の画面だけなので、雑談の画面では口を出さない）。
  **つながりの札と本文中の ID は、サイドシートの中で詳細を切り替える**（一覧モードは開かない）。直前の1つだけへ戻るパンくずを出し、
  Alt+← でも戻る。サイドバーの開いている印も切り替えた先を追う。切り替えたあとはフォーカスをサイドシートの器へ戻す。
  **サイドシートはモーダルにしない**: 開いてもフォーカスは押した行に残り、**開いている間は ↑↓ と前後の口で隣の行
  （画面の上からの順。畳んだ済みの段は飛ばす。端では止まる）へ移ってサイドシートの中身が入れ替わる**。
  **Esc（フォーカスが行かサイドシートの中のとき）・「×」・同じ行をもう一度押すと閉じ、押した行へフォーカスを戻す**。
  **サイドシート・サイドバー・入力欄の外を押すと閉じる**（入力欄は開いたまま書いて送れ、別の行を押すとサイドシートがそちらへ移る）。確認を重ねている間の Esc は確認だけを閉じる。
  **ドラフトの分類**（ADR 0061 論点 2。見本は ADR の参考情報の `view=draft`）:
  ドラフトの段の見出しの右端に「仕分ける」の口を置く（押すと開き、もう一度押すと閉じる。サイドシートの置き場が無い狭い幅では出さない）。
  押すと、サイドシートの面が1件の詳細から**ドラフトの全件を並べる分類の場面**に替わる（`useTaskSheet` の開いている面の種類が `open`〔1件〕か `sort`〔分類〕か。
  器・閉じ方・Esc・閉じたあとのフォーカス〔「仕分ける」の口へ戻す〕は1件のときと同じ。一覧の行を押すと、その1件の詳細へ替わる）。
  1件ごとの札に、状態の印と語・タスクの番号・難しさ・題・本文の頭（見出しを除いた先頭の2行まで）・3択「計画・却下・あとで」を出す。
  既定は「あとで」（触らない）。選んだ選択肢は字と地の色に加えて左のチェックでも言う。却下を選んだ札には「却下の理由」の1行の欄を出す。
  下端は、「計画」「却下」を1件以上選ぶと、左に「仕分けを戻す」（全部「あとで」へ戻す）、口の左に「あとで n 件」、右に件数を字に出した
  「計画 2・却下 1 を頼む」（1行だけなら「計画 1 を頼む」）を出す。選ぶまでは「あとで n 件」と押せない「頼む」だけを出す。
  口は新しいダイアログを作らず既存の確認（見出しは「ドラフト n 件を仕分けますか」、OK は「仕分ける」）を開き、OK で選んだぶんを1通の
  `/plan-tasks ドラフトを仕分けた。計画（承認済み）: ABC-1, ABC-2。却下: ABC-3（理由）` にして入力欄を経由せず送る
  （「あとで」の行は含まず、理由が空なら添えない。`/plan-tasks` は承認を得たドラフトだけを進めるので、文面の承認がそのまま使える。
  文面は `requestPromptOf` と同じ置き場で作る。一度に頼める件数に上限は置かない）。送ったらサイドシートも閉じ、キャンセル・Esc では送らず残る。
  札の列は内側で転がり、頭と下端は動かない。分類は表示上の状態なので**保存しない**（サイドシートを閉じると初めに戻る）。
  ドラフトが1件も無くなったら閉じる。**一覧モード（タスクのモーダル）には置かない**。
  **一覧が届き直して開いているタスクが一覧から消えたら閉じる**（戻っても開き直さない。探す語や畳んだ段で行が隠れただけでは閉じない）。
  **狭い幅（760px 以下）にはサイドシートが無く、行を押すとタスクのモーダル（狭い幅の形）がそのタスクを選んだ状態で開く**。
  **画面からタスク（Beads）を書き換える操作は作らない。**
  済みの段を開いているかどうかは表示上の状態なので**保存しない**
  （一覧を描き直すまで保つ。開き直すと畳んで始まる）。
  高さの配分は (1) タスク一覧が残りの高さのすべて、(2) 下端の帯は中身（使用量の3つ）なりの
  高さのままにする（均等割りにすると中身の短い (2) の下に空白が間延びするため）。狭い画面（4.7）ではサイドバーを出さず、
  (1) タスク一覧（雑談中は雑談の4段）は引き出しの「タスク」（雑談中は「話題」）のタブ、(2) 入力欄の札のモデル・effort・許可モードは
  引き出しの名乗りの行の下の段、下端の帯の目盛りとプラン使用量は「使用量」のタブに入る（`docs/architecture/screen-design.md` 13.9「狭い画面（760px 以下）」）。
  引き出しの高さも画面に固定されるので、区画の伸び縮みと内側スクロールは広い画面と同じように働く

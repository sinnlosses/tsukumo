# 各表示物: サイドバー

戻り: `docs/architecture/display.md`「各表示物」

- **サイドバー**: 上から (1) **タスク一覧**（起動先の Beads から読む。起こしてから最初の一覧が届くまでは節の中に行の形のスケルトン（帯3本。「不明」とは出さない）、前回読めた一覧が覚えてあればスケルトンの代わりにそれを出して、読んだ結果で差し替え、`.beads` があって `bd` が読めなければ届いたあと節の中に「不明」。起動先に `.beads` が無いときは、節ごと出さない〔`docs/architecture/adr/0025-no-project-settings.md`〕。節の見出しに歯車は無い（`docs/architecture/screen-design.md` 13.6・13.9）。`bd` の閉じていない課題と、閉じた課題のうち閉じた時刻が新しいものから10件〔11件目以降は出さない。サイドバーに断り書きは出さず、タスク板の一覧の末尾に出す〕で、見出しは固定の
  「タスク」で、その下に**件数のチップ**（すべて → 未完了 → ドラフト → 完了の順。**0件でも出す**）を並べる。**チップは押すとその状態だけに絞る**
  （1つだけ選べ、既定は「すべて」。選んでいるチップをもう一度押しても何も変わらない。並びは変えない
  （進行中はカード、未着手・完了はファイルの順の行）。選んでいることは色だけで示さず、枠線と
  太字も添える。「未完了」は `done` と `draft` 以外のすべて（保留・想定外の status も含む）、「ドラフト」は
  エージェントが聞かずに積んだドラフトの課題（Beads の `deferred` と metadata `draft`=`Y`。Beads アダプタが `draft` に畳む。
  行の印は破線の丸）で、未完了とドラフトと完了を足すと「すべて」になる。
  絞った結果が0件なら「◯◯のタスクが無い」と出し、選択は外さない）。**進行中（doing）は先頭にカードで
  出す**（2件以上あれば2枚以上並べる。summary は折り返して全文出す）。残りの行は
  **status を印の形で区別する**（色だけで伝えない）: 未着手は空の丸、完了はチェックの印＋字の
  打ち消し線、想定外の値は注意色〔`--state-warn`〕の「!」。todo と done はファイルの順のまま
  混ざる。summary は1行に収め、入りきらない分は末尾を「…」にする。**summary の中の `` `…` `` は、
  タスクのモーダルと同じ `TaskSummaryText` で等幅のコードの札にする**（進行中カードも
  同じ）。**行どうしは罫線を引かず 1px 空ける**（見本
  `docs/history/mockup/sidebar-task-peek-2026-10-04.html`）。**行全体（進行中のカードも）が1つの
  ボタンで、押すとのぞき窓が開く**（下の「のぞき窓」）。**字の大きさは役割で段を付ける**（区画の見出し・
  summary・「一覧を見る」がそれぞれ別の段になる。進行中カードと行の summary は ID や印と
  同じ印の段。
  値は `docs/architecture/screen-design.md` 13.3）。**見出しと件数のチップの行は、区画の中を
  スクロールしても上に止まる**（止まっていて下の一覧が潜っている間だけ、帯の下に
  1pxの線と影を出す。一番上までスクロールしているときは線も影も出さない。スクロールするのは
  行の一覧だけで、見出し・チップの行自体はスクロールしない）、(2) **下端の帯**（モデル・effort・許可モードの口と、
  コンテキストの目盛り・プラン使用量の円。目盛りか円を押すと、いまのコンテキストの使用量の札と**プラン使用量の札**の
  詳しい面が帯の上に開く。`docs/architecture/screen-design.md`「会話の画面の帯とサイドバーの下端の帯」・
  「使用量の行」）の2つ。
  **プラン使用量の札は5時間枠と7日間枠の使用率と戻る時刻を1行ずつ出し、再読み込みのボタンを添える**
  （出どころは SDK の `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET`
  で、Claude Code の `/usage` と同じ値。調べた結果と採らなかった案は `docs/research/plan-usage.md`）。
  取り直すのは開いたとき・ターンが終わるたび・再読み込みを押したときと、「該当しない」が返った間
  （2・5・10・20秒の間隔で、値が出れば止まり、使い切れば取れなかった扱いにする）で、時計では回さない。
  再読み込みは出どころへ取りに行き直す（最後の知らせを出し直すのではない）。戻る時刻を過ぎた枠も
  取り直すまでは取った値のまま出し、取った時刻を添える。警告の色は付けない（割合の数字が言う）。
  取れないとき（API キーで使っている場合を含む）は札の中に一言だけ出し、高さは変えない。**下端の帯は区画ではない**——
  見出しを名乗らず、サイドバーの左右いっぱいに広がり、上端の罫線と一段沈んだ地でタスクの区画と
  切り分ける。**キャラクターとセッションの切り替えはサイドバーに置かない**（
  帯の左上の顔と部屋の名前の札を押して選ぶ。`docs/architecture/screen-design.md`「キャラクターの選び口」・
  「セッションの札」・「切り替え画面」。モード（仕事 / 雑談）とキャラクター画面へ入る口も帯にある）。**雑談中はこの形ごと差し替わる**（タスク一覧を出さず、プロフィール・
  最近の話題・覚えていること・下端の帯の4段になる。4.9「雑談モードで変わるもの」）。
  **経過時間はここに無い。入力欄の送信ボタンと同じ行に出す**。
  **サイドバー全体はスクロールさせず、区画それぞれの
  内側でスクロールする**（区画が増えて見出しごと画面の外へ流れるのを防ぐ）。
  **タスク一覧を見渡すのは区画ではなくモーダル**（サイドバーの領域が小さいため）:
  区画には**全件を並べ（進行中だけ先頭、残りはファイルの順）、入りきらない分は区画の内側で
  スクロール**する（件数のチップでの絞り込みは上のとおり）。見出しの右端に **「一覧を見る」** と、
  その左に最新化の ↻（下の「タスクのモーダル」の「最新化の ↻」）を置き、押すと**左に一覧・右に選んだタスクの詳細のモーダルが開く**（形とふるまいは
  下の「タスクのモーダル」、寸法と色は `docs/architecture/display/task-modal.md` 13.12）。
  **のぞき窓**（見本 `docs/history/mockup/sidebar-task-peek-2026-10-04.html` の
  場面3。寸法と色は `docs/architecture/display/task-modal.md`「サイドバーのタスクののぞき窓」）: 行か進行中の
  カードを押すと、**サイドバーの左に、押した行を尾で指す窓が開く**（行は `aria-haspopup="dialog"` と
  `aria-expanded`）。中身は上から、状態の印と語・ID・閉じる「×」 → 題（`TaskSummaryText`） →
  関わるタスク（`dependencies` の ID。無ければ行ごと出さない） → 本文の頭（タスクのモーダルと同じ
  `TaskBody` の描画を一段小さな字組みで借り、高さの上限で切って下を地の色へ溶かす。本文を
  切り出す処理は持たない） → 「全文を開く ↗」と「これを始める →」。**作った日と担当は出さない**
  （一覧の項目が持っていないので口を足さない）。
  **「全文を開く ↗」はタスクのモーダルをそのタスクを選んだ状態で開き、窓は閉じる**（本文中の ID の
  自動リンクも同じく、その ID を選んで開く）。
  **「これを始める →」は「<ID> を実行しますか」の確認を重ね、OK でそのまま固定の文面
  （「タスク {id} を進めて。」）の `{id}` を ID にして送る**（入力欄に打つのと同じ
  経路。下書きには入れない。送ったら窓も閉じる）。**歯車の「タスクの実行」のプルダウンで起動するスキル（入口のスキルから選ぶ）を選んでいれば、
  文面は「/スキル名 {id}」になる**（先頭の `/` と前後の空白は畳み、英数字・`-`・`_`・`:` 以外を含む値は未設定として
  固定の文面にする。確認に出る文面も同じ。保留なら末尾に「このタスクは保留なので、着手の前に判断を聞いて。」を添える。
  計画・却下の文面は変わらない。ADR 0025「2026-10-24 の改訂」）。キャンセル・Esc では送らず、窓は残る。
  **出すのは「着手可」タスクだけで、それ以外（待ち・保留・進行中・完了）には出さない**
  （待ちのあるタスクを区画から頼めないように。着手できるかは絞り込む前の
  全件で判定する。保留を頼めるのは下の「tsukumo に頼む」だけ）。**ターンが動いている間は確認の中で断る**（送る口が
  進行中は黙って送らないため、出さずに黙らせない）。モーダルの中では、下の帯の「tsukumo に頼む」が
  同じ確認を開く。ドラフトの「却下する」「計画する」も、モーダルの下の帯から同じ確認を開く。
  **ドラフト（`draft`）の窓は「これを始める →」の代わりに「却下する」と「計画する」を並べる**（
  置き場を覗かずに、画面で計画か却下かを選ぶため）。どちらも同じ作りの確認
  （「<ID> の計画を頼みますか」「<ID> の却下を頼みますか」。OK は「頼む」）を重ね、OK で固定の文面を入力欄を経由せず送る
  （計画は「ドラフト {id} を計画して。## 完了条件 と ## やること を書いて、着手できる todo にする。」、
  却下は「ドラフト {id} を却下して。理由を ## 結果 に書いて、dropped で閉じる。」）。
  tsukumo は Beads に書かず、書くのは会話側。送ったら窓も閉じ、キャンセル・Esc では送らず窓は残る。
  **窓はモーダルにしない**: 開いてもフォーカスは押した行に残り、**開いている間は ↑↓ で隣の行
  （進行中のカード → 残りの行の、絞り込み後に出ている順。端では止まる）へ移って窓の中身が入れ替わる**。
  **Esc・「×」・同じ行をもう一度押すと閉じ、押した行へフォーカスを戻す**。区画の外を押しても閉じる
  （別の行を押すと窓がそちらへ移る）。確認を重ねている間の Esc は確認だけを閉じる。**一覧が届き直して
  開いている行が絞り込みの結果から消えたら閉じる**（戻っても開き直さない）。
  **画面からタスク（Beads）を書き換える口は作らない。**
  件数のチップで絞っているかどうかは表示上の状態なので**保存しない**
  （セッションの間だけ保つ）。
  高さの配分は (1) タスク一覧が残りの高さのすべて、(2) 下端の帯は中身（口の組と目盛り）なりの
  高さのままにする（均等割りにすると中身の短い (2) の下に空白が間延びするため）。狭い画面（4.7）ではサイドバーを出さず、
  (1) タスク一覧（雑談中は雑談の4段）は引き出しの「タスク」（雑談中は「話題」）のタブ、(2) 下端の帯のモデル・effort・許可モードは
  引き出しの名乗りの行の下の段、目盛りとプラン使用量は「使用量」のタブに入る（`docs/architecture/screen-design.md` 13.9「狭い画面（760px 以下）」）。
  引き出しの高さも画面に固定されるので、区画の伸び縮みと内側スクロールは広い画面と同じように働く

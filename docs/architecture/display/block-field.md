# 出力の分離（セリフと詳細）: 塊の欄・進み具合・候補とファイル・確度つきの主張

戻り: `docs/architecture/display.md`「出力の分離（セリフと詳細）」

- **「名前: 説明」「A → B」「A → B → C」「12 → 8」は既存の塊の欄で見せる**（
  `docs/research/report-block-richness.md` 2章）。欄は事実を言うものだけで、差や増減の割合は tsukumo が計算しない
  - 表のセルの `{ from, to }`: 前の値と矢印の文字を `ink-quiet`、後の値を `ink` で描く。状態（`status`）と
    同じセルには持たせない（変化の良し悪しは隣の列の `status` で言う）。前と後がどちらも数なら数の列として右に揃える
  - 表のセルの `{ tag }`: 列挙型の札。同じ字は同じ色（出現順の `--chart-series-1`〜`5`、6 種目から灰）。字は常に見える
  - `stats` の項目の `before`: 前の値を矢印の文字と一緒に数の上へ添える
  - `stats` の項目の `total`（全体の数）: 数の後ろに「／ 全体」と小さく添え、`value` と `total` がどちらも
    数字で `0 <= value <= total` のときだけ、割合の帯を数とラベルの間に引く（帯は `aria-hidden` で、割合は数と全体の文字が言う）。
    単位付き・範囲・全体を超える値は帯を出さず文字だけにし、割合へ読み替える推測はしない
  - `stats` の項目の `series`（推移の数の並び。省略可）: 3つ以上のときだけ、`value` の左に語の高さ（4em × 1.2em）の折れ線を描く。
    最大を上・最小を下に写し、全部同じ値なら中央の水平線にする。線は `ink-quiet`・幅 1.5・丸い端、最新の点だけ `ink-bright`。
    基準線は引かず、色は書き手が書かない。1〜2個は差し戻す
  - `stats` の項目の `better`（`up` / `down`。省略可）: `before` と `value` がどちらも数で `better` があるときだけ、
    「前 →」の矢印の字を、増減が `better` の向きなら `state-ok`・逆なら `state-warn` にする。等しいとき・数でないときは色を付けない。
    差や増減の割合は計算も描画もしない
  - `keyFigures`（`report` の欄）: 項目は `stats` と同じ。4個は器 46rem 以下で 2×2。条 16 は掛からない
  - `list` の項目の `label`: 印なしのラベルと本文の2列に組み、項目の間を細い横線で区切る
    `bullet` は印を持たないが、`ordered`（番号）と `check`（済み・未了）は順番・済み未了の意味を
    持つので印を残す。器が狭いとき（screen-design.md 13.4「レポートの塊の横並び」）は1列に積み、ラベルを本文の上に置く
  - `list` の `style` の `flow`: 項目を `<ol>` にし、段ごとに番号の丸を1本の線でつないで上から下へ積む
    **段ごとに文が要る一本道は `flow`、一本道でも段の名前が短ければ・分岐・合流・戻りがあれば `graph`**
    （段数の上限は無い。長い一本道も縦に積めば足りる）。
    **5段以下で各段の `label`＋`text` が50字以内で、どの段にも `source`・`branch` が無ければ、描く側が `flow-row`（箱の間に「→」）にする**。
    書き手は選ばない。器が 40em＋0.75rem 以下なら縦に落ちる
    項目の任意の欄 `source`（段の出どころの1行。ファイル名・コマンド名。小さい字）と `branch`（段の分岐の1文）は `flow` のときだけ描く。
    `branch` の判定は `branchTone`（`ok`・`warn`・`ng`、省略は `warn`）で、色の名前は書き手が持たない。
    どれか1段に `source` か `branch` があれば `<ol class="flow flow-detailed">` になり、各段の内側が角丸の枠で囲まれ（`label` が題）、`flow-row` にはならない。欄が全部空の `flow` は変わらない
    丸・線は `aria-hidden` の飾りで、順番は `<ol>` が伝える。寸法・色は `docs/architecture/screen-design.md` 13.2
  - `list` の `style` の `cards`: 読む順・因果の無い2〜4枚の並列（`label` 必須）。器 760px 超で横1行、以下は縦
  - `text` の塊の説明には「結論に効く数が3つ以上並び前後か推移を見せるなら `stats`」を置く（地の文から数を抜き出して
    タイルにするのは再構成なので、tsukumo は組み替えない）
- **段（フェーズ）の位置は `report` の塊では見せない**（`progress` の塊は直近 28 日で使われた記録が 0 回で外した。段の位置は
  進み具合の帯が持つ。旧い記録の `progress` は読み戻しで知らない種類の塊として落とす）
- **候補の比較は `options`、触ったファイルの一覧は `files` の塊で見せる**（
  `docs/research/report-block-richness.md` 3章。欄は判定と変更の種別の事実だけ）
  - `options`: `title` と、候補（`name` / `verdict`〔`adopt` / `consider` / `reject`〕/ `reason`）の並び。
    候補を1案1行で縦に積み、行は「1始まりの番号・判定の語（採る / 検討 / 採らない）・名前・理由」の順で、
    行どうしは罫で区切る（札の枠と地は持たない。器が狭いときは理由を名前の下の行へ落とす）。
    **候補は採る → 検討 → 採らないの順に書き手が書き、崩れていれば
    差し戻す**（採る候補が必ず先頭〔上〕に来る。tsukumo が並べ替えるのは
    再構成なのでしない）。描く並びは書き手の順のまま。判定の語は「採る」が `state-ok`、「検討」が
    `state-warn`、「採らない」は行全体の文字を `ink-quiet` に沈める。左罫は持たず、キャラクターの色は
    入れない（`docs/architecture/screen-design.md` 13.2 の3本のまま）
  - `files`: `path` / `change`〔`added` / `modified` / `deleted` / `read`〕/ `note` の並びと、任意の
    `title`（何のファイルの一覧かだけを言い、パスは写さない）。`title` を渡すと塊の最下部
    中央に「図 n　題」の行が付き、番号は既存の図と通しで数える。**`title` が空なら題の行も番号も出さない**
    （ほかの図は題が空でも番号を数えるが、`files` だけは既存の番号がずれないよう数えない）。
    塊の末尾（題の行のすぐ上）に、件数のある種別だけの合計の札を中央に並べる。パスは、tsukumo が `path` から
    組む**フォルダを畳んだ樹形図**で、子がフォルダ1つだけのフォルダは1行に「/」で連ね、
    木が分かれる場所（ファイルが入るフォルダ・子が2つ以上のフォルダ）でだけ枝を分ける。全部のパスに共通の
    親は枝のつかない先頭の1行に置き、同じ階層の並びは書き手が書いた順のまま。枝の罫（`├──` `└──` `│`）は
    見た目だけで `aria-hidden`。ファイルの行は頭に種別の記号と語の札（`change` の4種）、
    ファイル名は `code` 要素で、フルパスを `data-file-path` に持たせ、git 管理下かの判定はこのフルパスで
    行う（「レポートに書かれたパスは押すと Orca のエディタで開く」のとおり押せる）。注記があれば続けて
    置く（追加で注記が無い行だけ「新しく作った」を補足色で入れ、空欄にしない）。注記の先頭の `+n −m` は塊の最大に対する棒を行の右に添える（読めなければ無し）。「/」を含むパスが1つも無い
    ときは樹形図にせず、1行に1ファイルの平らな行にする。器が狭いときは注記をパスの下へ回す。見た目の値は
    `docs/architecture/screen-design.md`「ファイルの塊」が正典
  - 表・箇条書きとの取り違えは差し戻さない（表・箇条書きで描かれるだけで、語や
    パスの形での判定はヒューリスティックになる）。代わりに `list` の `bullet` と `table` の説明が
    `options` / `files` を指す。取り違えの程度は使われ方の記録の「塊の種類 × レポート数」で `options` と `table` の比を見る
- **確かめていないこと・推測は `claims`（確度つきの主張）の塊で見せる**（`docs/research/report-shape-tags.md` 6章。
  言葉だけの確度は解釈が割れるので、主張ごとに印と根拠を付ける）
  - 欄: 項目（`claim` / `certainty`〔`confirmed` 確定 / `inferred` 推測 / `unverified` 未確認〕/ `basis` / `howToVerify`）の並び。
    **確定でない項目の `howToVerify` が空なら塊を受け付けない**（入口の型の検査。`checks` の `unobserved` の行の確かめ方と同じ考え）
  - 描き方: 1項目1行で、行どうしは罫で区切る。左に確度を記号と語（✓ 確定 / 〜 推測 / ？ 未確認）で、右に主張と、その下に根拠・確かめ方を置く。
    根拠と確かめ方は Markdown の行内として描くので、`path:line` は押すと開き、`[ドメイン](URL)` は出典の札になる。空の欄は出さない。
    色は `docs/architecture/screen-design/color.md` の確度の段落
  - `note` の `ask` は残し、答えの出ていない問い1つに狭める（消すと `ask` を持つ過去の記録が読み戻しで落ちる）。
    検証の結果（テスト・型検査・手で確かめたこと）は今までどおり `checks` に書き、この塊に入れない
  - TUI には `report` も塊も無いので、出力スタイル（`asuna.md`）の側には何も足さない（「レポートの記法は、TUI と tsukumo で出し分ける」）

# 出力の分離（セリフと詳細）: 塊の欄・進み具合・候補とファイル・表・対応表・見比べ・前後

戻り: `docs/architecture/display.md`「出力の分離（セリフと詳細）」

- **「名前: 説明」「A → B」「A → B → C」「12 → 8」は既存の塊の欄で見せる**（2026-09-27。
  `docs/research/report-block-richness.md` 2章）。欄は事実を言うものだけで、差や増減の割合は tsukumo が計算しない
  - 表のセルの `{ from, to }`: 前の値と矢印の文字を `ink-quiet`、後の値を `ink` で描く。状態（`status`）と
    同じセルには持たせない（変化の良し悪しは隣の列の `status` で言う）。前と後がどちらも数なら数の列として右に揃える
  - `stats` の項目の `before`: 前の値を矢印の文字と一緒に数の上へ添える
  - `stats` の項目の `total`（全体の数）: 数の後ろに「／ 全体」と小さく添え、`value` と `total` がどちらも
    数字で `0 <= value <= total` のときだけ、割合の帯を数とラベルの間に引く（帯は `aria-hidden` で、割合は数と全体の文字が言う）。
    単位付き・範囲・全体を超える値は帯を出さず文字だけにし、割合へ読み替える推測はしない
  - `stats` の項目の `series`（推移の数の並び。省いてよい）: 3つ以上のときだけ、`value` の左に語の高さ（4em × 1.2em）の折れ線を描く。
    最大を上・最小を下に写し、全部同じ値なら中央の水平線にする。線は `ink-quiet`・幅 1.5・丸い端、最新の点だけ `ink-bright`。
    基準線は引かず、色は書き手が書かない。1〜2個は差し戻す（2点では推移の形が読めないため）
  - `stats` の項目の `better`（`up` / `down`。省いてよい）: `before` と `value` がどちらも数で `better` があるときだけ、
    「前 →」の矢印の字を、増減が `better` の向きなら `state-ok`・逆なら `state-warn` にする。等しいとき・数でないときは色を付けない。
    差や増減の割合は計算も描画もしない
  - `list` の項目の `label`: 印なしのラベルと本文の2列に組み、項目の間を細い横線で区切る
    （見本は `docs/history/mockup/report-labeled-list-2026-09-30.html`）。
    `bullet` は印を持たないが、`ordered`（番号）と `check`（済み・未了）は順番・済み未了の意味を
    持つので印を残す。器が狭いとき（screen-design.md 13.4「レポートの塊の横並び」）は1列に積み、ラベルを本文の上に置く（印は残ったまま同じ行に並ぶ）
  - `list` の `style` の `flow`: 項目を `<ol>` にし、段ごとに番号の丸を1本の線でつないで上から下へ積む
    （見本は `docs/history/mockup/report-flow-rail-2026-10-02.html`）。
    **段ごとに文が要る一本道は `flow`、一本道でも段の名前が短ければ・分岐・合流・戻りがあれば `graph`**
    （段の数の上限は言わない。縦に積むので長い一本道も `flow` で足りる）。
    丸・線は `aria-hidden` の飾りで、順番は `<ol>` が伝える。寸法・色は `docs/architecture/screen-design.md` 13.2
  - `text` の塊の説明には「結論に効く数が3つ以上並び前後か推移を見せるなら `stats`」を置く（地の文から数を抜き出して
    タイルにするのは再構成なので、tsukumo は組み替えない）
- **段（フェーズ）の位置は `progress` の塊で見せる**（2026-09-27 決定。`{ steps, current }` で受ける。
  文字列で「N のうち M」と書かせる差し戻しは足さない。`docs/research/report-block.md` 11章）。
  **節（丸）と線でつないだ1本の道で描く**（見本は `docs/history/mockup/report-progress-2026-09-30.html`）。
  済んだ段は丸の地に ✓、いまの段は輪と中の点＋後ろに「進行中」、まだの段は空の輪で見分け、`aria-current="step"` と段ごとの `aria-label`
  （「名前：済／進行中／まだ」）でも状態を言う。`report` が届いた時点で答えを待っている段は無い
  （`report` を呼ぶとターンが終わるため）ので、答え待ちの色（金）の状態は作らない。
  **同じ依頼にワークプランがあれば、整形が `progress` の塊を落とす**（進み具合の帯が同じ段を出すので二度描かない。
  ワークプランの無い依頼では描く。「ワークプラン」の「出す場所は3つ」）
- **候補の比較は `options`、触ったファイルの一覧は `files` の塊で見せる**（2026-09-28。
  `docs/research/report-block-richness.md` 3章。欄は判定と変更の種別の事実だけ）
  - `options`: `title` と、候補（`name` / `verdict`〔`adopt` / `consider` / `reject`〕/ `reason`）の並び。
    候補を1案1行で縦に積み、行は「1始まりの番号・判定の語（採る / 検討 / 採らない）・名前・理由」の順で、
    行どうしは罫で区切る（札の枠と地は持たない。器が狭いときは理由を名前の下の行へ落とす）。
    **候補は採る → 検討 → 採らないの順に書き手が書き、崩れていれば
    差し戻す**（2026-10-04 利用者の決定。採る候補が必ず先頭〔上〕に来る。tsukumo が並べ替えるのは
    再構成なのでしない）。描く並びは書き手の順のまま。判定の語は「採る」が `state-ok`、「検討」が
    `state-warn`、「採らない」は行全体の文字を `ink-quiet` に沈める。左罫は持たず、キャラクターの色は
    入れない（`docs/architecture/screen-design.md` 13.2 の3本のまま）
  - `files`: `path` / `change`〔`added` / `modified` / `deleted` / `read`〕/ `note` の並びと、任意の
    `title`（何のファイルの一覧かだけを言い、パスは写さない）。`title` を渡すと塊の最下部の
    中央に「図 n　題」の行が付き、番号は既存の図と通しで数える。**`title` が空なら題の行も番号も出さない**
    （ほかの図の塊は題が空でも番号を数えるが、`files` だけは既存のレポートの番号がずれないよう数えない）。
    塊の末尾（題の行のすぐ上）に、種別ごとの件数が1つでもある種別だけを中央に並べた合計の札を置く。パスは、tsukumo が `path` から
    組む**フォルダを畳んだ樹形図**で、子がフォルダ1つだけのフォルダは1行に「/」で連ね、
    木が分かれる場所（ファイルが入るフォルダ・子が2つ以上のフォルダ）でだけ枝を分ける。全部のパスに共通の
    親は枝のつかない先頭の1行に置き、同じ階層の並びは書き手が書いた順のまま。枝の罫（`├──` `└──` `│`）は
    見た目だけで `aria-hidden`。ファイルの行は頭に種別の記号と語の札（追加 / 変更 / 削除 / 読んだ）、
    ファイル名は `code` 要素で、フルパスを `data-file-path` に持たせ、git 管理下かの判定はこのフルパスで
    行う（「レポートに書かれたパスは押すと Orca のエディタで開く」のとおり押せる）。注記があれば続けて
    置く（追加で注記が無い行だけ「新しく作った」を補足色で入れ、空欄にしない）。「/」を含むパスが1つも無い
    ときは樹形図にせず、1行に1ファイルの平らな行にする。器が狭いときは注記をパスの下へ回す。見た目の値は
    `docs/architecture/screen-design.md`「ファイルの塊」が正典
  - 表・箇条書きとの取り違えは差し戻さない（取り違えても表・箇条書きで描かれるだけで、「推奨」の語や
    パスの形で判定するのはヒューリスティックになる）。代わりに `list` の `bullet` と `table` の説明が
    `options` / `files` を指す。取り違えの程度は使われ方の記録の「塊の種類 × レポート数」で `options` と `table` の比を見る
- **表の描き方は型から決め、書き手は何も選ばない**（2026-09-27。`docs/research/report-block-richness.md`
  2章）。列の全セルが数なら右揃えで `tabular-nums`（桁が縦に揃う）。列の全セルが `status` なら、記号1つ
  ＋文を1行に並べたタイル（角丸8px・セルの間4pxのすき間、罫線は引かない）にし、地を状態の色で染める
  （NG・要注意は13%、OK は6%。OK は目立たせない。`--state-*` から導出し、16進は書かない）。
  記号には状態の語（OK / 要注意 / NG）を `aria-label` で添え、色だけに頼らない。
  状態のセルがある列の、状態の無いセルは地を塗らず `ink-soft`（見出し行と同じ、読ませる補助の字）の
  ままにし、行の左に色の線は引かない。表に出た状態だけを、題（「表 n」）の直下・表の上に中央揃えの凡例
  （色見本＋記号＋語）で添える。列に `align` は持たせず、Markdown を組み立てるときに1箇所で判定する。
  長い表を切った残りは `rest`（省略できる文字列。「ほか 12 件（0.5% 未満）」）で言い、空でなければ表の直後に
  1行で添える（`ink-quiet`・罫なし）。
  `table` の説明には、行は大きさか重要度の順（1列目のあいうえお順にしない）・単位は見出しに1回だけでセルに書かない・
  セルは語句・数・状態にする、の3条を置く。2行以下なら表にせず `label` 付きの `list` か文に、は
  `REPORT_NOTATION_PROMPT` の条12だけが持つ（2026-10-18 に `table` の説明から外した）。
  セルの条は、ある列のセルの平均が全角35字以上の表を `sentence-table` で差し戻す。
  2行以下の条は差し戻しにはせず、記録の「2行以下の表のあるレポート」で数える
  （「塊を足す・外す基準」の版10）
- **行と列の交点が状態だけの対応表は `matrix` の塊で見せる**（2026-10-01。`columns`・`rows`〔`name` と
  `cells`＝`ok` / `warn` / `ng` / `na`〕を受ける）。交点は印（✓ ！ ✕ －）だけで描き、状態は記号・色・
  `aria-label`（状態の語だけ。行と列の名前は表の見出しが読み上げる）で言う。**交点に補足は持たせない**
  （文や数を添えたい・列の型が混じるなら `table` の状態のセル）。凡例は格子に出た状態だけを1つ添える。
  取り違えは差し戻さず、使われ方の記録の「塊の種類 × レポート数」で `table` と `matrix` の比を見る。
  行のセルの数が `columns` と揃わなければ `table` と同じ違反で差し戻す。列が多い格子は表と同じ横スクロールの器に収まる
- **2つを見比べるときは `compare` の塊で見せる**（2026-10-01。`title`・`sides`〔ちょうど2つ。各 `heading` と
  `points`＝短い1行の並び〕を受ける）。2枚の札を横に並べ、器が狭いときは縦に積む。見分けは見出しの
  文字だけで、判定の色は持たない。**札の中はインラインの文字の箇条だけ**（コードは `code` の `diff`、図は
  `mermaid`、値を揃えるなら `table`）。使い分けは、判定（採る・検討・採らない）を付けるなら `options`、項目ごとに
  両側の値を揃えるなら `table`（セルの `from` / `to` は1つの値の前後）、3つ以上は `table`、**向きのある変化（前 → 後）は
  `beforeAfter`**（`compare` は向きの無い2つ〔案A と案B〕に絞り、側の見出しは書き手が付けるまま）。
  取り違えは差し戻さず、使われ方の記録の「塊の種類 × レポート数」で見る
- **変更の前と後は `beforeAfter`（前後）の塊で左右に並べる**（2026-10-05。`title`・`before`・`after` を受け、
  側はちょうど2つ。3つ以上の並びは `table`）。側は `kind` で判別する合併型で、`image`〔`path`〕/ `code`〔`language`・
  `source`。`diff` にせずその側の中身をそのまま書く〕/ `points`〔短い1行の並び。5つまで〕/ `mermaid`〔`source` だけ。
  flowchart 以外で、時間の順の前後に使う。構文が割れる・種類の外なら差し戻し、位置は `mermaid` のソースの出現順で言う〕/
  `svg`〔`svg` の塊と同じ欄〕のどれか。**左右で種類が違ってよい**（設定の文言 → 画面のような前後を書ける）。
  左に前・右に後の札を同じ幅で並べ、間に `aria-hidden` の「→」を置く。札の頭の見出しは tsukumo が「前」「後」の文字で付け
  （書き手は書かない。前は `ink-quiet`・後は `ink` で、色は補助）、器が狭いときは前を上・後を下に積んで矢印を下向きに回す。
  画像の側は `image` の塊と同じ棚から引き、読めなければ同じ「画像を出せない」の札になる。`alt` は「前の画面」
  「後の画面」に題を添えたもの。**画像の側に `notes` は持たせない**（半分の幅に番号の並びを足すと画像がさらに縮み、
  前と後の両方に1から番号が振られて読み分けが要る。見る場所を言うなら `image` の塊の `notes`）。題は図として
  数え、包みは縮めない。
  - **両側が `image` のときだけ、題の行の右に「並べる」「切り替え」の2つ組（`role="group"`・`aria-label="見せ方"`）を出す**
    （2枚の差は同じ位置で入れかえるほうが速く見つかる。`docs/research/report-block-craft.md` 5章・9.1）。
    並べるは前・後を画像の左上の札つきで並べ、間に「→」を置く。切り替えは大きな1枚と前・後の見本（120px 幅）で、
    見本を押すか、大きな1枚にフォーカスがあるときの Space で、同じ位置で前と後が入れかわる
    （空白も `transition` も挟まない。挟むと変化盲で見えなくなる）。見本は `aria-pressed` で見えている側を示す。
    選んだ見せ方は `localStorage` に覚え、次に開いたときもそこから始める（読めない・壊れた値は並べる）。
    口は24px以上の押せる面を持つ。どちらかの画像が「画像を出せない」の札になったら、2つ組も見本も出さず並べる形にする
  - **前後の塊の中の画像を押すと、前後を入れかえて見られる面（`BeforeAfterZoom`）で、押した側から開く**。
    左上に前／後の2つ組（`aria-pressed`。選んだ側は `accent` の枠と薄い地）、右に案内「← → で前と後 · Esc で閉じる」と ×、
    下に塊の題（「図 N」は等幅。数え方は塊の題と同じ）を中央・13px で置く。← で前、→ で後に替わる（選ぶ動作で、
    2つ組のボタンを押しても同じ）。幅は 960px を上限に画面へ収め、画面の中央に出す。縦に長い画像は面の中で流れ、上の行は残る。
    Esc・背景・×で閉じ、閉じたら押した画像へフォーカスを戻す。面は `document.body` の直下へ描く（塊の中に置くと、
    本文の `p` の測り・図の画像の枠と角丸・側の箱の margin が面の中身と中央寄せに当たる）。塊の外の `image` と、画像が札になった塊の読めた側は、画像ごとの拡大（`ImageZoom`）のまま
  - 使い分けは、向きの無い2つは `compare`、1つの値の前後は表のセルの `from` / `to` か
    `stats` の `before`、行ごとの差分は `code` の `diff`、縦に積む寸法の前後は `dimension` の `before`、構造の前後は `graph` の印。
    書き手への規約（記法の条8）は、形の札から塊を引く表を持ち、画面を変えた作業は撮った画像を `image` で載せ、
    同じ場面の2枚は `beforeAfter` で並べる（見た目に出ない・撮れないときは `checks` の `unverified` に理由を書く）。
    1行の変更に使わせない旨は `beforeAfter` の `describe` が持つ。
  - 箇条の側が6つ以上なら `options`・`compare` と同じ違反で差し戻す。取り違えは差し戻さず、
    使われ方の記録の「塊の種類 × レポート数」で見る

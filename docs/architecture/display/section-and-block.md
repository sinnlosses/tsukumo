# 出力の分離（セリフと詳細）: 本文のセクションと部品、図の部品

戻り: `docs/architecture/display.md`「出力の分離（セリフと詳細）」

**本文は `report` の `components`（A2UI の部品の平らな一覧）で受け取り、セクションと部品の並び（`sections`）に写して描く**（形の案は
`docs/research/report-block.md`、用語は `docs/glossary.md`「セクション」「部品」）。

- 部品の種類は `src/shared/report/report-block.ts` が持ち、逃げ道は `markdown`。**種類ごとの使いどころは各部品の `describe` が持ち**（欄名・enum・型で読めることは持たない。通る呼び出しの例は `REPORT_TOOL_DESCRIPTION` の末尾）、
  `REPORT_NOTATION_PROMPT` の表には逃げ道に残る記法（引用・区切り線・複数の部品をまとめて畳む `<details>`・
  互いに独立した区画を見渡させる `cols` / `card`・区画の状態のバッジ `badge`）だけを置く（板の型が効くかを書かれ方と画で見てから、欄にするかを決める。`docs/research/dashboard-layout-proposal.md` 5.1）。
  同じことを両方に書くと毎ターンの文脈に2回載る。
- 本文を A2UI のカタログと部品の平らな一覧（`components`）で受けて描くことは、`docs/architecture/adr/0039-report-via-a2ui-catalog.md` が決める。
  部品の切り方（`Report` の props と内容部品 22 種、基本カタログから取る 6 部品）は同「論点 2」、変換と `ReportEvent` の形は「論点 3」、ブラウザの描き方は「論点 4」が正典。
  `report` が受け付けるのはこの `components` だけで、旧い変種（`json-schema`・`short-type`・`body-fence`）の受け付けは外した。旧い `sections`・`body` で書かれた過去のセッションの `report` は、復元が読む。
- セクションは `heading` と並んで、省ける欄 `shapeTag`（`docs/glossary.md`「形の名前」）を持つ。省いたセクションは `unspecified` に畳む。
  形の名前と部品の照合は外した。過去の行の扱いは「部品を足す・外す基準」の「形の名前の照合」。
  形の名前は旧い `sections` のセクションの欄で、`components` の `Section` は形の名前を持たず、旧い `body`（下の項）も持たない（どちらも常に `unspecified`）。
  条8は表を持たず、原則 5 つ・条 9 本の並びで、部品は条 9 の目安で材料の形から引き、部品ごとの書き方は定義の `describe` と `report_part_card` が引かせる（ADR 0038）。
  効いたかは図の欄の `none`（省いた回を含む）と、旧い記録に残る `no-shape` の割合で見る
  （省いた回は旧い記録・形の崩れと同じ `unrecorded` に畳まれ、記録から区別できない。ADR 0036）
  **種類の数に上限は置かない**（足すかは「読む時間を減らす物差しと線引き」、
  外すかは「部品を足す・外す基準」の外す基準で決める）
- **どの部品も、`fold`（畳むときの見出し）と `aside`（部品の欄外注。出典・どこを見るかの1行）を省略できる欄として持つ**。
  `aside` と `memo` の `note` は本文の流れに入れず、欄外注の列に出す
  （「各表示物」のメインビュー。`memo` の `note` は本文の位置に残さない）。使いどころは `report` の `Section` の説明
  だけが持ち、書き手の規約（`REPORT_NOTATION_PROMPT`）には書かない
- **部品を横に並べる `Row` と題つきの枠 `Card`（`Column` を子に持つ）は、基本カタログの部品として `components` で書く**。
  `Row` は子を 2〜4 個とり、等分の幅で横に並べ、器が 760px 以下なら縦に積む。
  色・幅・余白・縦に積むかは tsukumo が決め、書き手は選ばない。
  子の図・表の番号と欄外注は、子をセクションの中に平らに並べたときと同じ順で付く。
  差し戻しの検査は子にもセクションの部品と同じく掛かり、隣り合う `note` は縦に積む `Card` の中では数え、横に並ぶ `Row` の中では数えない。
  使い方は `report_part_card` の `Row`・`Column`・`Card` のカードが持つ。
  見え方は疑似セッションの場面 `row-panel-decision`（候補の比較）と `row-panel-status`（件数と一覧）で撮る。
  旧い `sections` の `row`・`panel` は書き手が書く欄が無く、旧い transcript の復元だけが読む（`src/server/report/core/body/legacy-report-section-list.ts`。ADR 0039「追記（2026-10-28）」）。
  読んだ `row` は `Row`、`panel` は題を先頭の段落にした `Card` に組み直す。画面に描くセクションの型 `ReportSection` は内容部品だけを持つ
- **数の推移・割合は `chart` の部品で見せる**。書き手は種類（`bar` / `line` / `pie` / `arrow` / `slope` / `span` / `share`）・項目・
  系列・横棒かを渡し、Chart.js の設定は tsukumo が組む。色は書き手が指定しない（配色のトークンから入れる）。`pie` は
  先頭の系列だけを描く。前後の差が主役なら `arrow`（項目ごとの前→後の矢印）、2時点の多項目は
  `slope`（項目ごとの2点の線）で、どちらも系列は前と後の2つ・`labels` が項目で、2つでなければ差し戻す。
  項目ごとの始まり〜終わりの区間（フェーズの所要と重なり）は `span`（矢じりの無い浮き棒。系列は始まりと終わりの2つ・
  `labels` が項目で、2つでなければ同じく差し戻す。時刻の軸・延びた分・出来事・一点があるなら下の `timeline`）、全体に占める割合の内訳は `share`（100% の積み上げ横棒1本。
  `pie` と同じく `labels` が部分の名前・先頭の系列だけを割合にし、部分の名前と割合を棒の中に、幅に収まらない部分は部分の色の四角を頭に付けて棒の下の行に書く）。
  凡例は出さず、系列名・項目名を線と棒の端に直接書き、格子線は引かない。逃げ道の ```chart フェンスは使わせない。
  図は Tab でフォーカスが入り、左右の矢印・Home・End で項目（`labels` の1つ）を移るたびに、その項目の全系列の値の札（Chart.js のツールチップ）が出る。
  Esc かフォーカスが外れると札は消える。同じ字を読み上げの領域（`aria-live="polite"`）へも出す。
  札は精度を足すだけで、結論に効く値は図に直に書く。
  同じ節の `Paragraph` の中の語が `Chart` の項目名（`labels`）と同じ字なら、書き手が印を付けなくても描く側が結ぶ。
  語の比べは NFKC にして空白を除いた字でし（`6本` と `6 本` は同じ語）、結んだ語は破線の下線で示してフォーカスを受ける。
  重ねる・フォーカスでその項目の札が出て、離れる・フォーカスが外れる・Esc で消える（図が画面の外でもスクロールはしない）。
  1字の項目名と、同じ節の2つ以上の `Chart` に同じ項目名があるときの語は結ばない。
  inline code とリンクの中、`Paragraph` 以外の字（表のセル・箇条・注記）、`ChartGrid` は結ばない（`ChartGrid` はどの図の札を出すかが1つに決まらない）。
  `bar` は系列の数に関わらず、棒の端に値を直書きする（系列が2つ以上なら各系列の先頭の棒に系列名も添える）。
  横棒（`bar` の `horizontal`）の高さは `max(320px, 項目数 × 28px + 48px)` で、項目名の目盛りは間引かない
  （縦棒・`line`・`pie` ほかは 320px）。高さは tsukumo が組む設定の最上位 `tsukumo.height` で描く側へ運び、書き手は何も渡さない。
  `emphasis`（省ける。`labels` の部分集合）は題の主語の項目だけを差し色（`--chart-series-1`）にし、ほかを `--ink` の 26% にする。
  `bar`・`pie`・`share` に効き、`arrow`・`slope`・`span`・`line` では無視する。`labels` に無い名前があれば `unknown-emphasis` で差し戻す。
  `share` だけに、部分ごとの状態の色 `tones`（`labels` と同じ長さの `ok`・`warn`・`ng`・`info`・`none` の並び。省ける）を書ける。
  `ok`・`warn`・`ng`・`info` は `--state-ok`・`--state-warn`・`--state-ng`・`--state-info`、`none` は `--ink` の 26% で塗る。
  `ok` の緑と `warn` の黄は2型色覚で見分けにくいので、色だけで意味を渡さず、部分の名前は棒の中か棒の下の行に必ず書く。
  `tones` を `share` 以外に付けた、長さが `labels` と違う、または `emphasis` と併せたら `chart-tone-range` で差し戻す。
  `line` だけに、目標・上限の基準線 `references`（`{ value, label }` の並び。省ける）を書ける。点の注記 `annotations`（`{ label, index, text }` の並び。
  `label` は系列名・`index` は `labels` の 0 始まりの位置・`text` は値と一言。省ける）は `line`・`bar`・`share`・`arrow` に書ける
  （`share` は `label` が先頭の系列の名前で `index` が部分の位置、`arrow` は `label` が前か後の系列の名前で、輪は `label` の系列が指す端に描く。前の系列なら前の端、後の系列なら後の端）。目標は全部同じ値の2本目の系列で書かず `references` で書く
  （2本目の系列は点つきの実線になり、測った系列と同じ重みで見える）。基準線は点の無い点線（`--report-chart-reference`）を描く領域の端から端まで引き、
  右端の外に名前を書く。値の軸は基準線の値が入るまで広げる。基準線があれば系列が1つでも線端に系列名を書き、基準線の名前と重なれば縦に離す。
  注記は名指した点に輪の印を付け、字を点の下（下に収まらなければ上）に、点が描く領域の右半分なら左へ・左半分なら右へ伸ばして書く（印と字は `--state-ng`）。
  基準線を `line` 以外に、注記を `line`・`bar`・`share`・`arrow` 以外に付けた、または注記の系列名が無い（`share` は先頭の系列以外）か位置が `labels` の外なら `chart-annotation-range` で差し戻す。
  図の囲い（`.captioned`）が 63em の段なので、`share` を含むグラフは読む面が広ければ 63em まで広がる（狭ければ 100%）
  表の数の列に付く横棒（`block-table.md`「表の描き方は型から決め、書き手は何も選ばない」）と役割が重なるので、数が3つ以上並ぶ表を
  `chart` へ差し戻す検査は足さない（正確な値を読ませたい場面は表のままでよい）
- **同じ物差しで測った複数の対象・観点ごとの前後は `ChartGrid` の部品で見せる**（Tufte の small multiples: 同じ軸の小さな図を格子に並べる）。
  書き手は並びの題 `title`、種類 `chartKind`（`bar` か `line` だけ）、全部の図に共通の項目 `labels`、図ごとの `{ heading, series }` の並び
  `panels`（2〜6 個。`heading` は図の小見出し、`series` は `chart` と同じ系列）を渡す。並びの中の図の種類は1つ（`chartKind` が1つなので混ざらない）。
  `pie`・`share`・`arrow`・`slope`・`span` は値の軸が無いか 0〜100 に固定で、揃える目盛りが無いので並べない。
  書き手は値の軸の範囲・列の数・色・余白を選ばない。目盛りは描く側が全部の図の値から1つに決め、`bar` は 0 から全値の最大まで
  （負の値があれば全値の最小から）、`line` は全値の最小〜最大に幅の 8% の余白を足した範囲にする（全値が同じでも幅を 0 にしない）。
  列は器（本文の容れ物 `report-body`）の幅で 3→2→1 に減らし（900px 以上で 3、560px 以上で 2）、幅 390 では 1 列に縦に積む。
  図ごとに小見出しを図の上に置き、並びの題は `chart` と同じく格子の下に「図 n」の番号つきで付ける。
  `panels` の数が 2〜6 の外、いずれかの系列の `values` の長さが `labels` と違う、または `panels` の間で系列の名前の組が違うと `chart-grid-shape` で差し戻す。
  式（`ParameterSlider` で振る値）は `chart` と同じく `title`・`labels`・`values` の欄に書け（ADR 0048 で式を結べるとした `Stats`・`Paragraph`・`Chart` に、この部品を足した）、評価で1つでも誤れば `chart` の「—」と同じく格子ぜんたいを「—」にする。
  `chart` に欄を足す形（梯子の 3）でなく新しい部品（梯子の 4）に置いたのは次の3点による。(1) `chart` の欄
  `emphasis`・`references`・`annotations`・`tones`・`horizontal` は1つの `chartKind`・1組の `labels` を前提にしており、並びに持ち込むと書き手が
  「どの図の欄か」を誤りやすい。(2) `labels` を並びで共通にすると、図ごとに `values` の長さが違う誤りを1本の検査に絞れる。
  (3) 式の置き場が `chart` と同じ `labels`・`values` で済み、誤りの扱いも `chart` の「—」をそのまま使える。
  `Row` に `chart` を並べても図ごとに Chart.js が値の軸を決めて目盛りが揃わないので、梯子の 1・2（今の部品・道案内）では足りない
- **flowchart は `graph` の部品で見せる**（受け付けるのは `source` の文字の記法。
  形が1つのほうがモデルが迷わず、スキーマも短い）。書き手は `direction` と `source` を渡す。`source` は1行1項目で、`A -> B` がエッジ、
  `A -> B: 語` がエッジのラベル、`->` の無い行はノードだけの宣言（空行と行頭・行末の空白は無視）。
  ノードの形は名前の括弧で決め、`(名前)` は始点・終点、`{名前}` は分岐、括弧が無ければ処理。名前が同じなら同じノードで、
  形は最初に括弧で出た行のものを採る。名前の中の `->`・`:` は使えない。tsukumo が `source` を mermaid のソースに組み立て、
  書き手の名前はソースの ID に出さない（ラベルを構文と読んで図が割れないように）。
  描くのは `mermaid` の部品と同じ経路で、図の番号と題も同じ。ノードが1つも無い `source` は入口で落とし、
  読めない行は差し戻す（何個目の部品の何行目かと正しい例の1行だけを返し、書き手の行は写さない）。
  `mermaid` の部品に flowchart を書くと差し戻し、`graph` の部品へ寄せる。
  - **構造の前後は `graph` の1枚に印を付けて見せる**（図を2枚書く手間を無くす）。
    行頭の `+ `（足した）・`- `（消した）・`~ `（変えた）が印で、エッジの行に付ければそのエッジに、
    ノードだけの行に付ければそのノードに掛かる（エッジの印は端のノードに掛けない）。印の無い行は変わらないもの。
    色は書き手が指定せず、足した＝`--state-ok`・消した＝`--state-ng`（エッジと枠は破線）・変えた＝`--state-warn`。
    前だけ・後だけに切り替える部品は付けない。同じノードに違う印をノードだけの行で付けると差し戻す。
  - **群は囲みで見せ、色では言わない**（`docs/research/report-block-craft.md` 1章。見本は
    `docs/history/mockup/report-excellence-2026-10-17/values.html`）。`[群の名]` だけの行で囲みを始め、`[]` だけの行で閉じ、
    間の行のノードがその群で、1階層。入れ子・閉じ忘れ・開いていない閉じ・空の群・別の群に入ったノードを別の群で名指す行は
    差し戻す。囲みの地は `--surface-raised`・枠は破線の `--rule-quiet`（色の目印を付けた群は実線 2px の系列色）。
  - **色の意味と点線は行末・矢印で書く**（座標を書かせずに `svg` と同じ色分けを `graph` で出す）。ノードだけの行・エッジの行・
    群の行（`[群の名] @a`）の行末に ` @a`〜` @e`（空白＋`@`＋1字）を付けると、系列色（`--chart-series-1`〜`5`。`a`〜`e` は `svg` の `tone` の `a`〜`e` と同じで、`graph` の凡例に状態の語は無い）で
    ノード・群の枠線（ノードは線の太さ 3px で、薄い地は付けない）とエッジの線が塗られる。矢印は `A -.> B` で点線のエッジになる（ラベルも付けられる）。
    変更の印 `+ - ~` と併用でき、色は印の色が優先される。同じノードに違う色をノードだけの行で付ける行、`@a`〜`@e` の外の目印、
    名前・ラベルの中の ` @`、閉じの行（`[]`）の目印は読めない行として差し戻す。
    `legend`（`tone` と名前の並び。省ける）を図の下に色見本つきで出し、**色だけで意味を言わない**ので、使った色が `legend` に無い図は
    差し戻す（文面は何個目の部品のどの `tone` かだけ。種類 `unlegended-graph-tone`）
  - **ノードには説明の1行を足せる**。ノードだけの行に `名前 | 説明` と書く（`|` の前後の空白は落とす）。エッジの端の名前には書けず、
    `|` が2つ以上の行・説明が空の行・同じノードに違う説明を重ねる行は読めない行として差し戻す（エッジのラベル〔`:` より後ろ〕の `|` は文字として通す）。
    説明は mermaid ではラベルの2行目に名前より小さい字で描く。
  - **一本道でノードが5以下の `graph` は、tsukumo がカードの連鎖で描く**（書き手は書き方を変えない）。条件は、分岐 `{}`・合流・囲み・点線が無く、
    エッジがノード数 − 1 本で、ノードが2〜5。当たらなければ（6ノード以上・分岐あり・囲みあり）今までどおり mermaid。
    横 1 行（幅 63em、5 枚で各 11em）で、カードに名前・説明・色の目印の帯を載せ、間に矢印とエッジのラベルを置く。器が 760px 以下なら縦に積み、矢印は下向き。
    色の目印 `@a`〜`@e` と変更の印 `+ - ~` は mermaid と同じ色で効き、`legend` に無い目印の差し戻しも同じ（`unlegended-graph-tone`）。
  - **凡例は図の下に自動で出す**。形（始点・終点＝「入口・出口」/ 処理 / 分岐）は図に2種以上出たときだけ、印は `+ - ~` が
    1つでもあるときだけで、両方あれば同じ行に形・印の順で並べる。色の凡例は書き手が `legend` に書いたものを最後に並べる。囲みは名が図に出るので凡例に載せない
- **時刻の軸に行ごとの帯・延びた分・出来事を並べる図は `timeline` の部品で書く**（`docs/architecture/adr/0033-timeline-block.md`）。
  書き手は題・行（`name`・`start`・`end`〔省くと一点〕・`extra`〔`end` より後へ延びた区切りの時刻の昇順の並び〕・
  `uncertain`〔終わり（`extra` があればその最後）より後ろに続く止まりうる区間。終わりの時刻 `until` と一言 `label`〕・`after`〔待つ行の `name` の並び〕・`lane`）・
  出来事（`at`・`label`）・差し色にする行の名前（`emphasis`）を渡し、目盛り・色・幅は tsukumo が決める。`Section` の子にも `Report.figure` にも置ける。
  時刻は `HH:MM`・ISO の日時・分の数のどれでもよく、尺度は値の形で判別する（`unit` の欄は無い）。1つの部品の中で混ぜない。
  目盛りは区間が8以下になる最小の間隔（1・2・5・10・30・60・360 分、1日、その先は1日の倍数）で、軸の字は分の数なら `n分`（`n時間`）、
  時刻なら `HH:MM`、ISO なら日が変わった目盛りに `M/D` を添える。区間は灰の帯（`emphasis` の行だけ差し色）、一点は菱形、
  延びた分は帯の末尾の斜線、止まりうる区間は延びた分の後ろに続く警告色と灰の縞と棒の下の一言 `label`、
  `after` は待たれる行の右端（止まりうる区間があればその終わり）からこの行の開始へ入る矢印、出来事は縦の点線とラベルで、
  使った見た目の意味を図の下の凡例に自動で出す（色だけで意味を言わない）。
  区間の行の帯の右には所要の字を tsukumo が `start` と `end`（`extra` があればその最後）から計算して添える（分の尺度は `25分`、時刻と ISO は `1時間5分`・`2日3時間`。一点の行には付けない）。
  `after` で待たれる行の終わりから、待つ行の最も早い始まりまでに空きがあれば、その間を灰の細い斜線の「待ち」として描き、長さの字を所要の字の前に添えて凡例に「待ち」を足す（止まりうる区間のある行には描かない）。
  レーンの見出しは、上の罫・左の線・太い字で、行の項目名と見分ける。
  幅は 63em（項目名の列 11em ＋ 軸）。行・レーンの見出し・一言の高さは固定（行 32px、見出し 26px、一言 18px）で、項目名は1行に収めて超えた分を省き、全文は `title` に置く。
  器が 560px 以上なら項目名を左の列に置き、559px 以下なら項目名（18px）を帯の上に置いて軸を全幅にする。
  描くのは shared が組む HTML の `div`・`span` で、Chart.js の経路は使わない。矢印だけは、待つ行の帯の段に重ねた `svg`（伸ばす線と、伸ばさない矢じりの2枚）で描き、
  縦の長さは layout が数える「間に挟まる行・見出し・一言の数」と上の固定の高さから CSS の `calc` で決める。読めない値・尺度が混ざる・同じレーンの中で開始が昇順でない・
  出来事が昇順でない・`extra` が昇順でない・終了が開始より前・行に無い名前の `emphasis` は差し戻し（`broken-timeline`）、
  `after` の名前が行に無い・空（`unknown-after`）・同じ名前の行が2つ以上（`ambiguous-after`）・自分を含めて循環する（`cyclic-after`）、
  `uncertain.until` が終わり以前か一点の行にある（`uncertain-before-end`）も同じく差し戻し、文面は何個目の部品の何行目かだけを返す。
  待つ行の開始が待たれる行の終わりより前なのは差し戻さない。
  延び・出来事・一点のどれも無く、項目ごとの区間の長さを比べるだけなら `chart` の `span`。`mermaid` の `gantt` は見た目を制御できないので
  形の名前 `time` の候補から外した（`time` の第一候補は `timeline`、許す代替は `mermaid` の `sequenceDiagram` と `list` の `ordered`）。
  見え方は疑似セッションの場面 `report-timeline` で撮る。
- **図の形を書き手が選ばず、問い・データ・関係を申告するのは `plot` の部品**（`src/shared/report/figure-grammar.ts`。`Section` の子にも `Report.figure` にも置ける）。
  申告は `question`（全角60字以内の1文）・`data`（列の並び。`name`・`type`〔`N`・`O`・`T`・`Q`〕・`values`）・`relation`（8語）の3つで、色・座標は書けない。
  型と値の整合（列の長さの一致・`Q` の列は数だけ）は schema が見て、外れた呼び出しは `report` の入力の検査で弾かれる。
  形は決定表（`src/shared/report/figure-decision.ts` の `plotFormOf`。行と境は `docs/architecture/display/block-criteria.md`「図の決定表」）が申告から決める。
  書き手は任意の欄 `form` で形を上書きでき、置いてはならない形は採らずに決定表の形で描いて `plot-forbidden-form`、図派・文派のどちらの既定で決めた形とも違う形は通して `plot-form-override` と数える（どちらも差し戻さない）。
  形ごとの描き方はまだ無く、どの形も `data` を `table` と同じ表として描く（題は `question`）。
- **`body` は旧い試しの版（`body-fence`）の本文の欄で、いまは受け付けない。復元が旧い transcript の `body` を読むだけ。** Markdown に型つきフェンスを混ぜて書かれていて、フェンスの種類は `graph`・`mermaid`・`table`・`code`・`callout`・`claims`・`image`（`READER_FENCE_KINDS`）と `figure`。
  読んだ結果は見出し空のセクション1つで、セクションの形の名前は持たない。型つきでない言語名のフェンスは散文の一部のまま残す。
  読めない型つきフェンスは差し戻さず素のコードブロックに落とし、数を記録の `brokenFenceCount` に残す（`src/server/report/core/body/body-fence.ts` の `parseReportBody`）。
  `body` は `row`・`panel` を扱わない。フェンスの中にフェンスは入れ子にできず、並べる容れ物には新しい記法が要るため。
- **座標で見せる図は `svg` の部品で書く**（`docs/architecture/adr/0028-report-block-priority.md`「SVG（論点3）」）。
  書き手は題・viewBox の大きさ・図形（`rect`・`line`・`text`）を渡し、SVG の文字列は書かず、描く側が図形から組む。
  `rect` の題は既定で枠の中心、`labelAt: "top-left"` で左上の内側に左寄せで置く（入れ子の外側の枠は `top-left` にして、子の枠・矢印の題と重ねない）。
  `sub`（題の下の説明1行。既定は空）は題より小さい `--ink-quiet` の字で、`center` なら中心を挟んで題の下、`top-left` なら題の下に同じ左端で置く（`label` が空なら描かない。2行以上は `text` を並べる。枠より長い字のはみ出しは検査しない）。
  `text` の `anchor`（`start`・`middle`・`end`。省けば `start`）で字の揃えを選ぶ。字の幅は描くまで分からないので、右端に寄せる字は `end`、点の上に置く字は `middle` で書く。描く側は字を動かして避けないので、重なりは書き手が座標で避ける（重なりと viewBox からのはみ出しは `capture-view.ts --paper-metric` の「svg の字の重なり」「svg の字のはみ出し」で数える）。
  `line` の `label` は線の中点の上に中央寄せで固定で、位置は選べない。12px ほどの間隔の線に付けた語は重なって読めない（見え方は疑似セッションの場面 `svg-line-label` で撮る）ので、近い線に語を付けるときは `label` を空にして `text` を並べる。
  色そのものは書けず、`rect`・`line` の `tone`（`a`〜`e` と状態の `ok`・`warn`・`ng`。既定 `none`）で意味の目印だけ書く（`line` は `dashed: true` で点線にもでき、矢じりは線の色に合う）。描く側が `a`〜`e` を `--chart-series-1`〜`--chart-series-5` に、`ok`・`warn`・`ng` を `--state-ok`・`--state-warn`・`--state-ng`（Table の状態セルと同じ色）に当て（`data-tone` が目印）、
  図の `legend`（`tone` と名前の並び。`a`〜`e`・`ok`・`warn`・`ng` を受ける）を図の下に色見本つきで出す。**色だけで意味を言わない**ので、使った `tone`（状態の `tone` も）が `legend` に無い図は差し戻し、文面は何個目の部品のどの `tone` かだけを返す（見え方は疑似セッションの場面 `report-svg-tone` で撮る）。図形が viewBox の外に出れば差し戻し、文面は何個目の部品の何番目の図形かだけを返す。
  `compare` の側にも置ける。段の条件は位置・重なりそのもので、つながりだけなら `graph`・`mermaid`
- **`mermaid` の部品の構文は、サーバでは検査しない**（足していたサーバの構文検査〔worker〕は、直近 28 日の記録で `mermaid` の部品 2 件・差し戻し 0 件のため外した）。
  種類の外（`REPORT_MERMAID_KINDS` の 2 種以外）は `unknown-mermaid` で差し戻し、構文が割れた図はブラウザの既存のエラー表示が

- **入れ子の境界が主役の構成図だけ、書き手が自分で D2（`d2`）を打って撮った PNG を `image` の部品で渡す**。
  tsukumo は D2 を打たず、部品も検査も足さず、外部コマンド依存も増やさない
  （`d2` は書き手が図を撮るときだけ使う道具で、`mise.toml` が版を固定する）。
  - **誰が打つか**: 書き手が `d2 --layout=dagre <ソース>.d2 <出力>.png` を作業ツリーの外（`/tmp`）へ出し、
    そのパスを `image` の部品に渡す。`image` の置き場は PNG をそのまま受けるので経路は足さない
  - **出力形式**: PNG だけ。D2 の SVG は色と線を `<style>` と `mask` に持ち、同梱の許可リストに通すと色が消える
  - **検査**: しない。壊れた D2 のソースは書き手の `d2` の終了コードで分かる。配置の崩れは機械で見られないので、
    書き手が撮った PNG を自分で開いて確かめてから渡す。2回直しても崩れるなら `graph` に戻す
  - **使い分け**: 入れ子が主役の構成図（機能の中の core と adapter のように、箱の中の箱と、箱をまたぐエッジが要るもの）だけ D2。
    つながりの一覧・木・時間の順・状態・構造の前後は `graph` / `mermaid`。この1行は `image` の `describe` だけが持つ。
    PNG には会話の中身を描かない（`docs/coding-standards.md`「会話内容の扱い」）

# 出力の分離（セリフと詳細）: 本文の節と塊、図の塊

戻り: `docs/architecture/display.md`「出力の分離（セリフと詳細）」

**本文は `report` の `sections`（節と塊の並び）で受け取る**（2026-09-27。形の案は
`docs/research/report-block.md`、用語は `docs/glossary.md`「節」「塊」）。

- 塊の種類は `src/shared/report/report-block.ts` が持ち、逃げ道は `markdown`。**種類ごとの使いどころは各塊の `describe` が持ち**、
  `REPORT_NOTATION_PROMPT` の表には逃げ道に残る記法（引用・区切り線・複数の塊をまとめて畳む `<details>`・
  互いに独立した区画を見渡させる `cols` / `card`・区画の状態の札 `badge`）だけを置く（`cols` / `card` / `badge` は 2026-10-20 利用者決定で
  教え直した。板の型が効くかを書かれ方と画で見てから、欄にするかを決める。`docs/research/dashboard-layout-proposal.md` 5.1）。
  同じことを両方に書くと毎ターンの文脈に2回載る。
- 節は `heading` と並んで、省ける欄 `shapeTag`（`docs/glossary.md`「形の札」）を持つ。省いた節は `unspecified` に畳む。
  札と塊の照合は「塊を足す・外す基準」の「形の札の照合」（数えるだけで差し戻さない）
  **種類の数に上限は置かない**（2026-09-30 改訂。足すかは「読む時間を減らす物差しと線引き」、
  外すかは「塊を足す・外す基準」の外す基準で決める）
- **どの塊も、`fold`（畳むときの見出し）と `aside`（塊の傍注。出典・どこを見るかの1行）を省略できる欄として持つ**
  （`aside` は 2026-10-17 利用者決定）。`aside` と `memo` の `note` は本文の流れに入れず、余白の柱に出す
  （「各表示物」のメインビュー。`memo` の `note` は本文の位置に残さない）。使いどころは `report` の `sections` の説明
  だけが持ち、書き手の規約（`REPORT_NOTATION_PROMPT`）には書かない
- **数の推移・割合は `chart` の塊で見せる**（2026-09-30）。書き手は種類（`bar` / `line` / `pie` / `arrow` / `slope` / `span` / `share`）・項目・
  系列・横棒かを渡し、Chart.js の設定は tsukumo が組む。色は書き手が指定しない（配色のトークンから入れる）。`pie` は
  先頭の系列だけを描く。前後の差が主役なら `arrow`（項目ごとの前→後の矢印）、2時点の多項目は
  `slope`（項目ごとの2点の線）で、どちらも系列は前と後の2つ・`labels` が項目で、2つでなければ差し戻す。
  項目ごとの始まり〜終わりの区間（段の所要と重なり）は `span`（矢じりの無い浮き棒。系列は始まりと終わりの2つ・
  `labels` が項目で、2つでなければ同じく差し戻す）、全体に占める割合の内訳は `share`（100% の積み上げ横棒1本。
  `pie` と同じく `labels` が部分の名前・先頭の系列だけを割合にし、部分の名前と割合を棒の中に、幅に収まらない部分は部分の色の四角を頭に付けて棒の下の行に書く）。
  凡例は出さず、系列名・項目名を線と棒の端に直接書き、格子線は引かない。逃げ道の ```chart フェンスは使わせない。
  `bar` は系列の数に関わらず、棒の端に値を直書きする（系列が2つ以上なら各系列の先頭の棒に系列名も添える）。
  横棒（`bar` の `horizontal`）の高さは `max(320px, 項目数 × 28px + 48px)` で、項目名の目盛りは間引かない
  （縦棒・`line`・`pie` ほかは 320px）。高さは tsukumo が組む設定の最上位 `tsukumo.height` で描く側へ運び、書き手は何も渡さない。
  `emphasis`（省ける。`labels` の部分集合）は題の主語の項目だけを差し色（`--chart-series-1`）にし、ほかを灰（`--ink-quiet`）にする。
  `bar`・`pie`・`share` に効き、`arrow`・`slope`・`span`・`line` では無視する。`labels` に無い名前があれば `unknown-emphasis` で差し戻す。
  図の囲い（`.captioned`）が 63em の段なので、`share` を含むグラフは読む面が広ければ 63em まで広がる（狭ければ 100%）
  表の数の列に付く横棒（「表の描き方は型から決め、書き手は何も選ばない」）と役割が重なるので、数が3つ以上並ぶ表を
  `chart` へ差し戻す検査は足さない（正確な値を読ませたい場面は表のままでよい）
- **flowchart は `graph` の塊で見せる**（2026-10-09 利用者決定。受け口は 2026-10-12 利用者決定で `source` の文字の記法。
  形が1つのほうがモデルが迷わず、スキーマも短い）。書き手は `direction` と `source` を渡す。`source` は1行1項目で、`A -> B` が辺、
  `A -> B: 語` が辺のラベル、`->` の無い行は節点だけの宣言（空行と行頭・行末の空白は無視）。
  節点の形は名前の包みで決め、`(名前)` は始点・終点、`{名前}` は分岐、包みが無ければ処理。名前が同じなら同じ節点で、
  形は最初に包みで出た行のものを採る。名前の中の `->`・`:` は使えない。tsukumo が `source` を mermaid のソースに組み立て、
  書き手の名前はソースの ID に出さない（ラベルを構文と読んで図が割れないように）。
  描くのは `mermaid` の塊と同じ経路で、図の番号と題も同じ。節点が1つも無い `source` は入口で落とし、
  読めない行は差し戻す（何個目の塊の何行目かと正しい例の1行だけを返し、書き手の行は写さない）。
  `mermaid` の塊に flowchart を書くと差し戻し、`graph` の塊へ寄せる。
  - **構造の前後は `graph` の1枚に印を付けて見せる**（2026-10-12 利用者決定。図を2枚書く手間を無くす）。
    行頭の `+ `（足した）・`- `（消した）・`~ `（変えた）が印で、辺の行に付ければその辺に、
    節点だけの行に付ければその節点に掛かる（辺の印は端の節点に掛けない）。印の無い行は変わらないもの。
    色は書き手が指定せず、足した＝`--state-ok`・消した＝`--state-ng`（辺と枠は破線）・変えた＝`--state-warn`。
    前だけ・後だけに切り替える部品は付けない。同じ節点に違う印を節点だけの行で付けると差し戻す。
  - **群は囲みで見せ、色では言わない**（`docs/research/report-block-craft.md` 1章。見本は
    `docs/history/mockup/report-excellence-2026-10-17/values.html`）。`[群の名]` だけの行で囲みを始め、`[]` だけの行で閉じ、
    間の行の節点がその群で、1階層。入れ子・閉じ忘れ・開いていない閉じ・空の群・別の群に入った節点を別の群で名指す行は
    差し戻す。囲みの地は `--surface-raised`・枠は破線の `--rule-quiet`（色の目印を付けた群は実線 2px の系列色）。
  - **色の意味と点線は行末・矢印で書く**（座標を書かせずに `svg` と同じ色分けを `graph` で出す）。節点だけの行・辺の行・
    群の行（`[群の名] @a`）の行末に ` @a`〜` @e`（空白＋`@`＋1字）を付けると、系列色（`--chart-series-1`〜`5`。`svg` の `tone` と同じ）で
    節点・群の枠線（節点は線の太さ 3px で、薄い地は付けない）と辺の線が塗られる。矢印は `A -.> B` で点線の辺になる（ラベルも付けられる）。
    変更の印 `+ - ~` と併用でき、色は印の色が優先される。同じ節点に違う色を節点だけの行で付ける行、`@a`〜`@e` の外の目印、
    名前・ラベルの中の ` @`、閉じの行（`[]`）の目印は読めない行として差し戻す。
    `legend`（`tone` と名前の並び。省ける）を図の下に色見本つきで出し、**色だけで意味を言わない**ので、使った色が `legend` に無い図は
    差し戻す（文面は何個目の塊のどの `tone` かだけ。種類 `unlegended-graph-tone`）
  - **凡例は図の下に自動で出す**。形（始点・終点＝「入口・出口」/ 処理 / 分岐）は図に2種以上出たときだけ、印は `+ - ~` が
    1つでもあるときだけで、両方あれば同じ行に形・印の順で並べる。色の凡例は書き手が `legend` に書いたものを最後に並べる。囲みは名が図に出るので凡例に載せない
- **座標で見せる図は `svg` の塊で書く**（`docs/architecture/adr/0028-report-block-priority.md`「SVG（論点3）」）。
  書き手は題・viewBox の大きさ・図形（`rect`・`line`・`text`）を渡し、SVG の文字列は書かず、描く側が図形から組む。
  `rect` の題は既定で枠の中心、`labelAt: "top-left"` で左上の内側に左寄せで置く（入れ子の外側の枠は `top-left` にして、子の枠・矢印の題と重ねない）。
  `sub`（題の下の説明1行。既定は空）は題より小さい `--ink-quiet` の字で、`center` なら中心を挟んで題の下、`top-left` なら題の下に同じ左端で置く（`label` が空なら描かない。2行以上は `text` を並べる。枠より長い字のはみ出しは検査しない）。
  色そのものは書けず、`rect`・`line` の `tone`（`a`〜`e`。既定 `none`）で意味の目印だけ書く（`line` は `dashed: true` で点線にもでき、矢じりは線の色に合う）。描く側が `a`〜`e` を `--chart-series-1`〜`--chart-series-5` に当て（`data-tone` が目印）、
  図の `legend`（`tone` と名前の並び）を図の下に色見本つきで出す。**色だけで意味を言わない**ので、使った `tone` が `legend` に無い図は差し戻し、文面は何個目の塊のどの `tone` かだけを返す（見え方は疑似セッションの場面 `report-svg-tone` で撮る）。図形が viewBox の外に出れば差し戻し、文面は何個目の塊の何番目の図形かだけを返す。
  `beforeAfter` の側にも置ける。段の条件は位置・重なりそのもので、つながりだけなら `graph`・`mermaid`
- **`mermaid` の塊の構文は、受け付ける前にサーバが同梱の mermaid で検査する**（2026-10-10 利用者決定）。
  割れる図があれば差し戻し、文面は何個目の塊の何行目か・字句の名前だけを返す
  （書き手のソースと mermaid のエラー文の引用は写さない）。検査は `report/adapter/` の1境界で構文だけを見て、配置までは見ない。検査の worker はセッションを起こした直後の手すきに先に起こす。
  読み込みの失敗・時間切れ・検査の異常終了では検査せずに受け付ける（図はブラウザの今のエラー表示に任せる）。
  質問の添え書き（`figures`）の `mermaid` の図にも同じ検査を掛け、割れていれば `question_brief` の呼び出しを同じ形の文面で差し戻す
- **入れ子の境界が主役の構成図だけ、書き手が自分で D2（`d2`）を打って撮った PNG を `image` の塊で渡す**
  （2026-10-14 利用者決定）。tsukumo は D2 を打たず、塊も検査も足さず、外部コマンド依存も増やさない
  （`d2` は書き手が図を撮るときだけ使う道具で、`mise.toml` が版を固定する）。
  - **誰が打つか**: 書き手が `d2 --layout=dagre <ソース>.d2 <出力>.png` を作業ツリーの外（`/tmp`）へ出し、
    そのパスを `image` の塊に渡す。`image` の棚は PNG をそのまま受けるので経路は足さない
  - **出力形式**: PNG だけ。D2 の SVG は色と線を `<style>` と `mask` に持ち、同梱の許可リストに通すと色が消える
  - **検査**: しない。壊れた D2 のソースは書き手の `d2` の終了コードで分かる。配置の崩れは機械で見られないので、
    書き手が撮った PNG を自分で開いて確かめてから渡す。2回直しても崩れるなら `graph` に戻す
  - **使い分け**: 入れ子が主役の構成図（機能の中の core と adapter のように、箱の中の箱と、箱をまたぐ辺が要るもの）だけ D2。
    つながりの一覧・木・時間の順・状態・構造の前後は `graph` / `mermaid`。この1行は `image` の `describe` だけが持つ。
    PNG には会話の中身を描かない（`docs/coding-standards.md`「会話内容の扱い」）

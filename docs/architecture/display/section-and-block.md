# 出力の分離（セリフと詳細）: 本文の節と塊、図の塊

戻り: `docs/architecture/display.md`「出力の分離（セリフと詳細）」

**本文は `report` の `sections`（節と塊の並び）で受け取る**（2026-09-27。形の案は
`docs/research/report-block.md`、用語は `docs/glossary.md`「節」「塊」）。

- 塊は `text` / `list` / `table` / `matrix` / `compare` / `beforeAfter` / `dimension` / `note` / `stats` / `code` / `mermaid` / `graph` / `chart` / `svg` / `progress` / `options` / `image` / `files` と、逃げ道の
  `markdown` の19種。**種類ごとの使いどころは各塊の `describe`（`src/shared/report/report-block.ts`）が持ち**、
  `REPORT_NOTATION_PROMPT` の表には逃げ道に残る記法（引用・
  区切り線・複数の塊をまとめて畳む `<details>`）だけを置く。同じことを両方に書くと毎ターンの文脈に2回載る。
  **種類の数に上限は置かない**（2026-09-30 改訂。足すかは下の「読む時間を減らす物差しと線引き」、
  外すかは「塊を足す・外す基準」の外す基準〔28日0回〕で決める）
- **どの塊も、`fold`（畳むときの見出し）と `aside`（塊の傍注。出典・どこを見るかの1行）を省略できる欄として持つ**
  （`aside` は 2026-10-17 利用者決定）。`aside` と `memo` の `note` は本文の流れに入れず、余白の柱に出す
  （下の「各表示物」のメインビュー。`memo` の `note` は本文の位置に残さない）。使いどころは `report` の `sections` の説明
  （`REPORT_SECTIONS_DESCRIPTION`）だけが持ち、書き手の規約（`REPORT_NOTATION_PROMPT`）には書かない
- **数の推移・割合は `chart` の塊で見せる**（2026-09-30。`chartKind`〔`bar` / `line` / `pie` / `arrow` / `slope` / `span` / `share`〕・`labels`・
  `series`〔`{ name, values }` の並び〕・`horizontal`〔`bar` の横棒〕を受け、Chart.js の設定は
  tsukumo が組む。色は書き手が指定しない（`loadChart` が配色のトークンから入れる）。`pie` は
  `series` の先頭だけを描く。前後の差が主役なら `arrow`（項目ごとの前→後の矢印）、2時点の多項目は
  `slope`（項目ごとの2点の線）で、どちらも `series` は前と後の2つ・`labels` が項目で、2つでなければ
  `ragged-chart` で差し戻す。項目ごとの始まり〜終わりの区間（段の所要と重なり）は `span`（矢じりの無い浮き棒。
  `series` は始まりと終わりの2つ・`labels` が項目で、2つでなければ同じく差し戻す）、全体に占める割合の内訳は
  `share`（100% の積み上げ横棒1本。`pie` と同じく `labels` が部分の名前・`series` の先頭だけを割合にし、
  部分の名前と割合を棒の中に、幅に収まらない部分は棒の下の行に書く）。凡例は出さず、系列名・項目名を線と棒の端に直接書き、格子線は引かない。逃げ道の ```chart フェンス（生の Chart.js 設定を JSON で書く形）は
  この塊に一本化し、記法の表から外した。表の数の列に付く横棒（下の「表の描き方は型から決め、
  書き手は何も選ばない」）と役割が重なるので、数が3つ以上並ぶ表を `chart` へ差し戻す検査は
  足さない（正確な値を読ませたい場面は表のままでよい）
- **flowchart は `graph` の塊で見せる**（2026-10-09 利用者決定。受け口は 2026-10-12 利用者決定で
  節点と辺を構造で渡す形から `source` の文字の記法に替えた。形が1つのほうがモデルが迷わず、
  スキーマも短い）。書き手は `direction` と `source` を渡す。`source` は1行1項目で、`A -> B` が辺、
  `A -> B: 語` が辺のラベル、`->` の無い行は節点だけの宣言（空行と行頭・行末の空白は無視）。
  節点の形は名前の包みで決め、`(名前)` は始点・終点（round）、`{名前}` は分岐（decision）、
  包みが無ければ処理（box）。名前が同じなら同じ節点で、形は最初に包みで出た行のものを採る。
  名前の中の `->`・`:` は使えない。tsukumo が `source` を読み、ID を `n0`, `n1` … と振り、
  ラベルを必ず引用符で包んだ mermaid のソースに組み立てる（mermaid 12.1.0 は引用符の無いラベルの
  `@`・`(`・`end` などを構文と読んで図が割れるため。書き手の名前はソースの ID に出ない）。
  描くのは `mermaid` の塊と同じ経路で、図の番号と題も同じ。節点が1つも無い `source` は入口で落とし、
  読めない行は `broken-graph` で差し戻す（何個目の塊の何行目かと正しい例の1行だけを返し、書き手の行は
  写さない）。`mermaid` の塊に flowchart を書くと `unknown-mermaid` で差し戻し、`graph` の塊へ寄せる。
  **構造の前後は `graph` の1枚に印を付けて見せる**（2026-10-12 利用者決定。`beforeAfter` の側から `graph` を外し、
  図を2枚書く手間を無くした）。行頭の `+ `（足した）・`- `（消した）・`~ `（変えた）が印で、辺の行に付ければその辺に、
  節点だけの行に付ければその節点に掛かる（辺の印は端の節点に掛けない）。印の無い行は変わらないもの。
  色は書き手が指定せず、足した＝`--state-ok`・消した＝`--state-ng`（辺と枠は破線）・変えた＝`--state-warn` を
  `classDef` / `linkStyle` に `var(--…)` で書き、`MermaidBlock` が描く前に hex へ解く。前だけ・後だけに切り替える部品は付けない。
  同じ節点に違う印を節点だけの行で付けると `broken-graph` で差し戻す（文面に何個目の塊の何行目かを添える）。
  **群は囲みで見せ、色では言わない**（`docs/research/report-block-craft.md` 1章。見本は
  `docs/history/mockup/report-excellence-2026-10-17/values.html`）。`[群の名]` だけの行で囲みを始め、`[]` だけの行で閉じ、
  間の行の節点がその群で、1階層。入れ子・閉じ忘れ・開いていない閉じ・空の群・別の群に入った節点を別の群で名指す行は
  `broken-graph` で差し戻す。mermaid の `subgraph g<k>["群の名"]` に組み、地は `--surface-raised`・枠は破線の `--rule-quiet`
  （`themeVariables` の `clusterBkg`・`clusterBorder` と、群ごとの `style`）。始点・終点の節点は stadium（`([…])`）に組む。
  **凡例は図の下に自動で出す**。形（始点・終点＝「入口・出口」/ 処理 / 分岐）は図に2種以上出たときだけ、印は `+ - ~` が
  1つでもあるときだけで、両方あれば同じ行に形・印の順で並べる。色は足さない。囲みは名が図に出るので凡例に載せない
- **座標で見せる図は `svg` の塊で書く**（`docs/architecture/adr/0028-report-block-priority.md`「SVG（論点3）」）。
  `title`・`width`・`height`〔viewBox の大きさ〕・`shapes`〔`rect`・`line`・`text` の判別可能な合併〕・`fold` を受け、
  SVG の文字列は書き手が書かず、描く側が図形から組む。色は書けず、`chart` と同じくテーマの色を当てる。
  図形が `width` × `height` の外に出れば `broken-svg` で差し戻し、文面は何個目の塊の何番目の図形かだけを返す。
  `beforeAfter` の側にも置ける。段の条件は位置・重なりそのもので、つながりだけなら `graph`・`mermaid`
- **`mermaid` の塊の構文は、受け付ける前にサーバが同梱の mermaid で検査する**（2026-10-10 利用者決定）。
  割れる図があれば `broken-mermaid` で差し戻し、文面は何個目の塊の何行目か・字句の名前だけを返す
  （書き手のソースと mermaid のエラー文の引用は写さない）。検査は `happy-dom` を被せた `worker_threads` の
  中（`report/adapter/` の1境界）で `mermaid.parse` だけを走らせ、配置までは見ない。最初の図のときに
  worker を起こして使い回し、読み込みの失敗・時間切れ・worker の異常終了では検査せずに受け付ける
  （図はブラウザの今のエラー表示に任せる）。質問の添え書き（`figures`）の `mermaid` の図にも
  同じ検査を掛け、割れていれば `question_brief` の呼び出しを同じ形の文面（何個目の何行目か・字句の名前）で
  差し戻す
- **入れ子の境界が主役の構成図だけ、書き手が自分で D2（`d2`）を打って撮った PNG を `image` の塊で渡す**
  （2026-10-14 利用者決定。tsukumo は D2 を打たず、塊も検査も足さない）。次の5点で決めた:
  - **載せるか**: 載せる。ただし tsukumo の機能としては組み込まない。`d2` は書き手が図を撮るときだけ使う道具で、`mise.toml` が版を固定する
    （2026-10-14 利用者承認。tsukumo の実行には要らない）。tsukumo の外部コマンド依存（`orca`・`bd`・`dolt`・`gh`・`python3`）は増やさない。依存を増やす案（サーバが `d2` を打つ塊）は
    承認を得られなかったので採らない
  - **誰が打つか**: 書き手が `d2 --layout=dagre <ソース>.d2 <出力>.png` を作業ツリーの外（`/tmp`）へ出し、
    そのパスを `image` の塊に渡す。`image` の棚（`report-image-shelf.ts`）は PNG をそのまま受けるので経路は足さない
  - **出力形式**: PNG だけ。SVG は載せない。D2 の SVG は色と線を `<style>` の class に持ち、`mask` で線の上の
    ラベルを抜くが、`sanitize-schema.ts` は `style` を中身ごと捨て `mask` も通さないので、同梱の許可リストに通すと
    形だけが残って色が消える（2026-10-14 の試作で、core / adapter の入れ子と日本語の辺のラベルを持つ図が
    ほぼ白紙になった）。許可するには `style` と `mask` を通す変更と安全の確認が要り、割に合わない
  - **検査**: しない。壊れた D2 のソースは書き手の `d2` の終了コードで分かり、画像ができなければ `image` の
    塊に渡せない。配置の崩れ（線が回り込む・横に伸びる）は機械で見られないので、書き手が撮った PNG を
    自分で開いて確かめてから渡す。2回直しても崩れるなら `graph` に戻す
  - **使い分け**: 入れ子が主役の構成図（機能の中の core と adapter のように、箱の中の箱と、箱をまたぐ辺が要るもの）だけ D2。
    つながりの一覧・木・時間の順・状態・構造の前後は今の `graph` / `mermaid`。この1行を `image` の `describe` に足し、
    `mermaid` の行には足さない（重なりを増やさない）。PNG には会話の中身を描かない（`docs/coding-standards.md`「会話内容の扱い」）

# 各表示物: 許可と質問

戻り: `docs/architecture/display.md`「各表示物」

- **許可と質問**: **キャラが聞く**（2026-09-11 決定）。吹き出しに「これ実行していい？」と出て、
  答えるのは画面の口。押すと答えが `canUseTool` の戻り値として SDK へ返り、口は消える。
  **許可モード**（毎回聞く／編集は自動／全部許す／プラン）も画面から切り替えられる。
  **許可要求も質問（`AskUserQuestion`）も、同じ形の札「お伺い」にして、メインビューの本文に出す**（2026-10-02 決定。形・寸法・キー操作は `docs/architecture/screen-design.md` 13.13「お伺い」）。
  **狭い画面（760px 以下）だけは、本文ではなく入力欄のすぐ上に固定した答え待ちの札に出す**（2026-10-09 ユーザー決定）。
  選択肢はボタンで、押した瞬間に答える（2問以上は1問ずつ進み、最後の問いで送る。複数選択だけは選んでから「これで答える」）。
  許可は「拒否」「許可」の2つ、「その他」はボタンにせず入力欄が受ける。添え書きは札の「詳しく」から下の板で読む
  （形・寸法・択の数ごとの並びは `docs/architecture/screen-design.md` 13.9「狭い画面（760px 以下）」と 13.13「お伺い」）。
  1か所にまとめ、許可を待つあいだ送信ボタンと許可のボタンが主役を取り合わないようにする（旧い形は `docs/history/decision.md`「display.md 4.2
  各表示物（許可と質問の置き場・メインビューはレポートだけ・入力欄の経過時間と API の知らせ。2026-10-02 に覆した記録）」）。
  許可要求は対象の全文と選択肢「1 許可」「2 拒否」を持つお伺いで、選択肢の決まりは質問と同じ番号つきの
  カード。お伺いにフォーカスがあるときだけ、1〜9 で選び Enter で進む:
  - **札の置き場は「各表示物」のメインビュー**（いまのやり取りの本文の末尾に置く。答えた質問の記録と同じ並びの位置で、答えても上から下へ飛ばない。2026-10-10 利用者決定。経緯は `docs/history/decision.md`）。
    届いたら札まで送り、札が窓の外にあるあいだはメインビューの下端に「お伺い ↓」の口を浮かべる（押すと札まで送る。形は 13.13「お伺い」）。
    枠と地は答え待ちの色（`--state-warn`）の系統。
    頭に「お伺い」のチップ・種類（許可 / 質問）・`header` かツール名、右端に「n / N」（何問目か）と待っている時間。
    **過去のやり取りを見ている間は札を出さず**、やり取りの列の頭の知らせの行「お伺いが届いた」がいまのやり取りへ連れて戻る（2026-10-03）
  - **選択肢は左の縦の並び**（番号・選択の印・太字のラベル・戻せない選択肢の「⚠ 戻せない」）で、**右にフォーカスした選択肢の詳細**
    （`description`・良い点・悪い点・`preview`・図）を出す。添え書きがあれば上に背景と判断の軸、下に畳める比較表（軸 × 選択肢）を置く。
    **選んだ行は枠が `--state-warn`** になる。札の幅が足りなければ詳細が選択肢の下に回る1列になる（形と寸法は 13.13「お伺い」）。
    **ラベル末尾の `(Recommended)`・`(推奨)`（全角の括弧も可）は「おすすめ」のバッジにして字からは外す**
    （SDK へ返す答えは元のラベルのまま）
  - **自由入力は入力欄が担う**（2026-09-23 決定。札の中の自由入力の欄は無くした）。質問が
    出ている間、入力欄は上に帯「↓ <キャラクター名> が質問しています。下の選択肢から選ぶか、
    ここに書いて答えてください」と「お伺いへ」の口を出し、プレースホルダは「選択肢以外の答えを書く…」、
    送るボタンの字は「答える」（最後の1問でなければ「次へ」）、枠は `--state-warn` になる。送るボタンは
    **自由入力の字があるときだけ** `--state-warn` で塗り、字が無ければ塗らない（お伺いの札の「次へ」と主役を
    取り合わない。2026-10-03）。書いて送った字は
    **いま見ている1問の答え**になる（`AskUserQuestion` の "Other" 相当。モデルが選択肢に自由入力を
    含めてこなかったときの受け皿でもあるので、**選択肢の側の「その他」は札に出さない**）
  - **許可を待つ間の入力欄はふつうの下書きのまま**で、上に帯「↓ <キャラクター名> が実行の許可を待っています」と
    「お伺いへ」の口だけを出す。送るボタンの席は「中断」のまま
  - **接続が切れているあいだの入力欄**は、上の帯に「サーバとつながっていません。送れず、下書きは残してあります。
    サーバを起こし直したなら、ページを開き直してください」を出し（答え待ちの帯より先）、送信は何もせず戻って
    下書きと添付画像を残す。接続が一度切れてから `open` に戻るまでが対象で、初回の接続中は出さない。
    起動トークンが古い場合もただの切断と区別しない
  - **会話が終わったあとの入力欄**（`session-ended` を受けたあと）は、上の帯に「会話が終了しました（理由: <理由>）。新しく始めると、また頼めます」と
    「新しく始める」の口を出す（切断の帯の次、答え待ちの帯より先）。口は `startNewSession` を頼み、サーバは起こし直しを自分では始めない。
    送信は切断のときと同じく何もせず戻って下書きと添付画像を残し、送るボタンは無効にする。サーバも終わった会話への依頼を断る
  - **`/clear` に続けて文を書いて送ろうとしたとき**（先頭のトークンがちょうど `/clear` で、空白のあとに空白でない字が続く。
    Claude Code は引数を捨てて会話を消すだけなので、続きの文は届かない）は、依頼を送らず、下書きと添付画像を残し、上の帯に
    「/clear のあとの文は捨てられるので、送っていません。…」を出す（終了の帯の次、答え待ちの帯より先。色は `--state-warn`）。
    下書きを直すと帯は消える。`/clear` だけの文は今までどおり送る。自動で2つに分けて送ることはしない（2026-10-04 利用者決定）
  - **質問が複数あるときは1問ずつ出す**（2026-09-15 決定）。選んでから「これで答える」
    （最後の1問でなければ「次へ」）で進み、**最後の1問を答えた時点でまとめて返す**。
    送る前なら「戻る」で選び直せる（単一選択でも、選んだ瞬間には次へ進まない。札に確定の
    ボタンがあるので、押す前に選び直せるほうが素直）
  - **選択肢は送られた順ではなく、おすすめ → それ以外の順に分け、それぞれをラベルの辞書順
    （`localeCompare`）に並べ替えて出す**（2026-09-21 決定、おすすめを先頭に寄せるのは 2026-10-04 決定。
    番号はこの並びで振るので、モデルが送った順の番号とは一致しない）。並べ替えはブラウザ側で行う（`/` コマンド補完と同じ立場）。質問そのものの並び
    （1問ずつ出す側）はこの並べ替えの対象外）
  - **選択肢に `preview`（Markdown）が付いていたら、その選択肢の説明の下に出す**
    （2026-09-21 決定。**描くのはレポートと同じ経路**で、表・mermaid・chart の
    フェンス・記法の class・同じサニタイズがそのまま効く。`preview` が無ければ何も足さない）
  - **`preview` に書いた手元の画像は、レポートの `image` の塊と同じ棚から描く**（2026-10-05。撮った画面や
    モックを選択肢ごとに見せるため）。書き方は Markdown の画像 `![説明](パス)` で、パスは絶対か cwd からの
    相対。**拾うのは Markdown の構文木の画像の節点（mdast の `image`）だけ**なので、コードフェンス・
    コードスパン・エスケープ（`\![]()`）の中の記法は拾わず字のまま出る（preview はコード案や ASCII の
    モックを書く欄で、コードの中に画像の記法が入りうる）。サーバはブラウザと同じ Markdown の読み方で `url` を拾い、
    ブラウザは preview を描くときに `url` を替える。どの `url` を棚から引くか（空でなく、スキームと `//` で
    始まらない）は shared の1か所で決める。
    **レポートでは逃げ道の画像を `image` の塊へ差し戻すが、
    質問では Markdown の画像を許す**: `AskUserQuestion` の入力の形は SDK が決めていて `preview` の文字列
    しか無く、`image` の塊のような欄を足せないうえ、差し戻す口も無い（質問を断って聞き直させると利用者を
    待たせる）。生の `<img>` とスキームか `//` で始まる行き先（外部の URL・`data:`）は棚に置かず
    書き換えもしないので、許可リストが `src` を落として「画像を出せない」の札になる。**棚の鍵は質問の
    tool use id と書かれたままのパスの組**で、サーバは新しく積まれた質問を受けた時点で読んで置き、
    ブラウザは描くときに `src` を `/report-image/<id>/<パス>` に替える（質問の中身はサーバで書き換えない）。
    答えたあとの記録も同じ id で同じ棚を引く。画像は札の幅に収め、高さに上限を置く。読む範囲・
    捨てる契機は「読む時間を減らす物差しと線引き」の「画像を描く条件」
  - **質問の前に添え書きを受け取る**（2026-10-08 決定。文脈と選択肢の違いを読み取れるように）。`AskUserQuestion` の入力の形は SDK が決めていて背景や良い点・悪い点の欄が無いので、
    **質問は置き換えず、仕事のときだけ載る `question_brief` ツールで先に渡させる**（答えの経路は今のまま）:
    - **口**: 1回の呼び出しで、次の `AskUserQuestion` 1回ぶんを `questions`（1〜4件）で渡す。1件は
      背景（2〜3文）・判断の軸（1〜5個）・選択肢ごとの良い点・悪い点・軸ごとの評価・戻せない印・図の塊
      （`list`・`table`・`compare`・`mermaid`・`code`・`image`。`report` の塊の型をそのまま使い、新しい記法は作らない）。
      ツールは引数を検査して即座に戻り、答えを待たない
    - **呼んだ時点の差し戻し**: 背景が空（空白だけを含む）・軸が0個か6個以上か重複・選択肢が2件未満か5件以上・
      `label` の空か重複・軸ごとの評価の数が軸と違う・良い点と悪い点がどちらも空・図が選択肢1つに3つ以上・`header` の空か重複は、
      直し方を `isError` で返す
    - **突き合わせ**: 各件は `header` で質問1つに、選択肢は `label`（末尾のおすすめの印を外した字。
      「その他」は両側から除く）の集合で質問の選択肢に合わせる。**選択肢（「その他」を除く）が2つ以上の質問は、
      合う添え書きが無い・合わないときに答え待ちに積まず断る**（2026-10-09 決定。お願いに留めず仕組みで縛る）。
      断る文は、添え書きの無い `header`・当たらない `header`・選択肢の足りない数と余る数と、`question_brief` を呼んでから聞き直すことだけを言い、
      質問文・ラベル・添え書きの字は入れない。選択肢が1つ以下の質問は今までどおり積み、合わない添え書きは捨てる
    - **寿命**: 預かるのは1つで、呼び直すと置き換わる。次の `AskUserQuestion` で合っても合わなくても断っても使い切り、
      許可要求では使わない。ターンの終わり（`turn-finished`）と駆動を閉じたときにも捨てる。添え書きのあと
      質問せずに `report` へ進んだときもターンの終わりに黙って捨て、`report` は差し戻さない
    - **画面へ運ぶ経路**: 合った添え書きは答え待ちの質問に（1問に1件まで。`header` で質問を指す）載って画面へ届く。**札に渡るのは背景・判断の軸・選択肢ごとの良い点・悪い点・
      軸ごとの評価・戻せない印・図**で、軸 × 選択肢の表はモデルに書かせず、軸と軸ごとの評価から画面が組む。
      おすすめは今までどおりラベル末尾の印から出す。札の形は見本
      `docs/history/mockup/inquiry-brief-2026-10-08.svg`（利用者承認済み）
    - **答えたあとの記録には残さない**
    - 添え書きの付いた質問（2問のうち1問だけに添え書き）は、疑似セッションの場面 `question-brief` で出せる
  - **質問の書き方は tsukumo が教える**（2026-10-04 決定）。`src/server/session-driver/core/question-notation.ts` の条を
    仕事モードのときだけ `systemPrompt` の append に足し、`AskUserQuestion` の直前に `question_brief` で
    添え書き（背景・判断の軸・選択肢ごとの良い点と悪い点・軸ごとの評価・戻せない印）を渡して質問文には何を決めるかだけを書く・
    選択肢のラベルは選んだあと何が起きるかを言う語にする・おすすめはラベル末尾に `(推奨)` を付けて理由を `description` の頭に書く・
    見た目や画面の形やデータやコードの構造を選ばせるときは添え書きの各選択肢の `figures` に図を必ず付ける、
    の4条を渡す（`report` は受け付けた時点でターンを閉じるので質問の前には書けない。`preview` は今も描くが、条では求めない）。
  - **複数選択はチェックボックス**（単一選択は radio）。選んだぶんすべてに印が付き、
    入力欄に書いた答えは選んだラベルの末尾に足す。SDK へ返すときに1つの文字列へ畳むのは
    `src/server/session-driver/core/pending-answer.ts` だけの仕事にした
  - **答えた質問は、そのやり取りのメインビューに「何を聞いて、どう答えたか」の記録として
    残す**（2026-09-16 決定。答えが確定した時点で1回だけ積み、あとから書き換えない。
    答えずに終わった質問は残さない）。**自由入力の答えは選択肢の下に別の行で出す**
    （選択肢のどれとも一致しないため）。**見返せるのは直近のターンの札に限る**
    （メインビューが遡れる件数。それより古いぶんは画面から落ちる）

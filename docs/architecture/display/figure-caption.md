# 出力の分離（セリフと詳細）: 寸法図・画像・図と表の題・書き上げる演出・入口の検査

戻り: `docs/architecture/display.md`「出力の分離（セリフと詳細）」

- **縦に積む領域の寸法は `dimension`（寸法図）の塊で見せる**（2026-10-01。`title`・`parts`〔上から順に、領域
  `{ name, size, before }` と余白 `{ gap, before }` を混ぜた並び。先頭・末尾の `gap` は外側の余白〕を受ける）。
  左の列に領域の箱と余白の斜線の帯を積み、右の列に値を置き、余白の値には両端に目盛りのある縦の寸法線を引く。
  **1列だけ**で、横並び・入れ子・重なりは `svg` の塊で書く。**前後は1枚に重ねる**（値ごとの `before` を前の値と矢印にして `ink-quiet` で添える。
  `compare` でも `beforeAfter` でも2枚並べない）。**図は模式**で、箱と帯の高さは値に比例させず、数が寸法を言う。描き方は `div` / `span`
  と CSS で、許可リストに足す物は無く、書き上げる演出では文字の塊として出る。取り違えは差し戻さず、使われ方の
  記録の「塊の種類 × レポート数」で見る
- **手で確かめた画面は `image` の塊で画像として見せる**（2026-10-02。`path`〔撮ったファイル。絶対か cwd からの
  相対〕・`caption`〔何が見えるかの1行〕を受け、1つの塊に1枚）。**前後は `beforeAfter` の塊で左右に並べる**（2026-10-05。
  それまでは `image` を2つ縦に積んでいた）。**`checks` の行とは結ばない**（何を確かめた画像かは `caption` に書く）。
  画像は描いた `report` を受けた時点でサーバが1回読んでメモリの棚に置き（`createReportImageShelf`。続きから復元した
  再生では、記録の窓に残った `report` のうち、時刻が分かり復元の時点から24時間以内のものだけ、更新時刻がその `report` の時刻以前のファイルを読み直す）、鍵は `report` の呼び出しの id と塊に書かれたままのパスの組。ブラウザは
  `/report-image/<toolUseId>/<path>`（起動トークン付き）で棚を引き、許可リストは `img` の `src` を
  `/report-image/` で始まる値だけに絞る（外部の URL・`data:`・ほかのパスは属性ごと落ちる）。読めない・棚に無い・
  `src` が落ちた画像は「画像を出せない」の札になる（2026-10-02 デザイン「流れの塊 案A」。枠ごと斜めの縞の面
  にし、中央に画像に斜線を引いた印、その下に「画像を出せない」とその理由の2行を置く。縞・印・2行は
  `aria-hidden` の飾りで、意味は役割 `img` の `aria-label` が言う）。逃げ道に書いた画像（`![]()` / `<img>`）は
  `image` の塊へ差し戻す。画像は押すと `ImageZoom`（`size="width"`）で拡大して見られる（読めない札には入口が無い）。置き場・消し方は下の「画像を描く条件」。題の扱いは次の「図と表の題」と同じ
- **画像のどこを見るかは `image` の `notes` に番号つきで添える**（2026-10-04。`notes`〔1項目1文の説明の並び。
  既定は空〕を受ける）。新しい塊にせず `image` の欄にしたのは、画像1枚と題という形が同じで、書き手が塊を選ぶ
  判断を増やさないため。**画像の上に番号の印は置かない**（座標はモデルが外しやすく、外れたかを機械で確かめ
  られない）。並びに1始まりの番号を振り、場所は説明の文で言う（「左上の帯」のように場所から書き始める）。
  広い幅では画像の右に並びを置き、器が狭いときは画像の下に積む（`compare` と同じ境目）。並びは親の
  幅を取るので包みを縮めない（`notes` が空なら今までどおり `captioned-fit`）。画像が読めないときも、並びは
  「画像を出せない」の札の横に残る。6つ以上は `options`・`compare` と同じ違反（`too-many-candidates`）で差し戻す
- **図と表には番号つきの題を付ける**（2026-10-03。利用者決定は 2026-10-02。図〔`image`・`dimension`・
  `compare`・`beforeAfter`・`mermaid`・`graph`・`chart`・`svg`・`stats`〕は題を本体の**下**に「図 n」、表〔`table`・`matrix`〕は題を本体の**上**に
  「表 n」。番号は図と表を別々に、`reportSectionsMarkdown` が節をまたいで塊の並びの順に1から数える。
  `options` は候補の採否の札なので数えない）。**題が空でも番号は出し**〔`image` の `caption` が空でも
  「図 n」が付いていた数え方に揃える。題の有無で番号の振り方が変わらない〕、**`fold` で畳んだ中も数える**
  〔畳んでも番号が飛ばない〕。引数は `title`〔`image` だけ従来どおり `caption`〕で、`mermaid`・`graph`・`chart`・`svg` は
  `title` を省いてよい〔空文字〕。`stats` は `title` を持たないので、番号だけの題の行になる。**題は本体の幅を超えない**: 包み（`div.captioned`）が本体の幅に縮み
  〔`captioned-fit`。`image`・`table`・`matrix`・`dimension`・`svg`。20rem を下限にして、短い表の題が何行にも
  折れないようにする〕、題の行は `contain: inline-size` で幅の計算から外れて包みの幅で折り返す。親の幅を
  取る `chart`・`stats`・`compare`・`beforeAfter` と、全幅の `pre` に描く `mermaid`・`graph` は縮めない。題の文字は inline code だけを解く
  〔太字・リンクは効かない〕
- **節を書き上げる演出の塊（トピック）の単位にする**（2026-09-27。`docs/research/report-block-richness.md`
  2章）。見出しのタグや水平線を DOM から探して境目を当てるのはやめ（見出しのレベルは節の中の
  副見出しにも、水平線は節の中の軽い区切り〔`---`〕にも使われるので、タグの一致だけでは節の境目と
  中の区切りを見分けられない）、`reportSectionsMarkdown` が節と節の境目にだけ見た目を持たない印
  （`.report-section-break` の空の `div`）を挟み、演出（`src/browser/domain/reveal/plan.ts`）はその印の
  前後で切るだけにする。見出しの無い節どうしの境目にも印が入るので、見出しの無い節も1つのトピック
  になる。見出しの見た目は変えない。結論・検証結果と節のあいだにも、結論か検証結果があって節も
  あるときだけ、`reportMarkdown` が `.report-sections-start` の印を挟む（2026-10-02。演出はこの印より
  後ろだけを筆の対象にする。印が無い本文は全体が対象）。節の見出し（`h4`・`h5`）と図表の題の行は
  筆の対象から外して最初から出す（2026-10-17。題の行には `NotationBlock` が属性
  `data-reveal-caption` を足し〔class はハッシュ名になり domain から選べない〕、それを子に持つ包みは対象にせず中の本体だけを書く）。
  演出の全体は10秒で終わり、上限をまたぐ塊はそこまでに書き切り、後ろの塊は上限の時刻に一度に出る。
  演出中だけ、ステップの右上に「全部出す」の口（`Report` が置く）を出す
- **型で守られるようになった検査は外した**（表の見出し〔`table.title` が必須〕・`#` の見出し〔見出しは
  節の欄〕・本文の中のお願い〔`note` の種別に無い〕）。代わりに差し戻すのは、行のセルの数が `columns` と
  揃わない表・節が2つ以上あるのに見出しの無い節・**逃げ道の外側（HTML の塊の中でないところ）に塊の種類が
  ある記法**（`#` / `##` の見出し・表・箇条書き・`note`・`stats`・`progress`・フェンス・mermaid）。最後の1つが無いと、
  本文を丸ごと逃げ道に入れて型を素通りできる。HTML の塊の中を見ないのは、複数の塊を `<details>` に
  まとめて畳む・並べる（過去の記録の `cols`）のが逃げ道の役目だから
- 崩れた塊・知らない種類の塊は入口（`sdk-message.ts` の `reportEvents`）で落とし、塊1つの読み損ねで
  レポートを捨てない。切り替える前の transcript の文字列の `body` は同じ入口で逃げ道の塊1つの節に畳むので、
  過去のレポートの見た目は変わらない

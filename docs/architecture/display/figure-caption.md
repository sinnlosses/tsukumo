# 出力の分離（セリフと詳細）: 画像・図と表の題・書き上げる演出・入口の検査

戻り: `docs/architecture/display.md`「出力の分離（セリフと詳細）」

- **寸法は専用の塊を持たない**（`dimension`〔寸法図〕の塊は直近 28 日で使われた記録が 0 回で外した。寸法は `table` か、
  位置・重なりなら `svg` で書く。旧い記録の `dimension` は読み戻しで知らない種類の塊として落とす）
- **手で確かめた画面は `image` の塊で画像として見せる**（2026-10-02。`path`〔撮ったファイル。絶対か cwd からの
  相対〕・`caption`〔何が見えるかの1行〕を受け、1つの塊に1枚）。**前後は `beforeAfter` の塊で左右に並べる**。
  **`checks` の行とは結ばない**（何を確かめた画像かは `caption` に書く）。
  画像は描いた `report` を受けた時点でサーバが1回読んでメモリの棚に置き（復元のあとの読み直しは「画像を描く条件」）、
  鍵は `report` の呼び出しの id と塊に書かれたままのパスの組。ブラウザは `/report-image/<toolUseId>/<path>`（起動トークン付き）で
  棚を引き、許可リストは `img` の `src` を `/report-image/` で始まる値だけに絞る（外部の URL・`data:`・ほかのパスは属性ごと落ちる）。
  棚に置くときにファイルの頭から読めた幅と高さは、`report` の引数ではなくサーバが `report` のイベントと記録に載せ（`imageSizes`）、
  `img` の `width`・`height` になる（読めない画像には付けない）。`img` は `loading="lazy"`・`decoding="async"` で、配る画像は `private, max-age=3600`。
  読めない・棚に無い・`src` が落ちた画像は「画像を出せない」の札になる（枠ごと斜めの縞の面にし、中央に画像に斜線を引いた印、
  その下に「画像を出せない」とその理由の2行を置く。縞・印・2行は `aria-hidden` の飾りで、意味は役割 `img` の `aria-label` が言う）。
  逃げ道に書いた画像（`![]()` / `<img>`）は `image` の塊へ差し戻す。画像は押すと幅に合わせて拡大して見られる（読めない札には入口が無い。前後の塊の中の画像は、前と後を入れかえて見られる別の面で開く。`block-table.md` の前後の塊）。
  置き場・消し方は「画像を描く条件」。題の扱いは次の「図と表の題」と同じ
- **画像のどこを見るかは `image` の `notes` に番号つきで添える**（2026-10-04。`notes`〔1項目1文の説明の並び。
  既定は空〕を受ける。画像1枚と題という形が同じなので、新しい塊にしない）。**画像の上に番号の印は置かない**
  （座標はモデルが外しやすく、外れたかを機械で確かめられない）。並びに1始まりの番号を振り、場所は説明の文で言う
  （「左上の帯」のように場所から書き始める）。広い幅では画像の右に並びを置き、器が狭いときは画像の下に積む（`compare` と同じ境目）。
  並びは親の幅を取るので包みを縮めない（`notes` が空なら本体の幅に縮める）。画像が読めないときも、並びは
  「画像を出せない」の札の横に残る。6つ以上は `options`・`compare` と同じ違反で差し戻す
- **図と表には番号つきの題を付ける**（2026-10-03。利用者決定は 2026-10-02）。図（`image`・
  `compare`・`beforeAfter`・`mermaid`・`graph`・`chart`・`timeline`・`svg`・`stats`）は題を本体の**下**に「図 n」、表（`table`・`matrix`）は
  題を本体の**上**に「表 n」。番号は図と表を別々に、節をまたいで塊の並びの順に1から数える。
  `options` は候補の採否の札なので数えない。**題が空でも番号は出し**（題の有無で番号の振り方が変わらない）、
  **`fold` で畳んだ中も数える**（畳んでも番号が飛ばない）。引数は `title`（`image` だけ `caption`）で、`mermaid`・`graph`・`chart`・`timeline`・`svg` は
  `title` を省いてよい。`stats` は `title` を持たないので、番号だけの題の行になる。
  **題は本体の幅を超えない**: `image`・`table`・`matrix`・`svg` は包みが本体の幅に縮み（20rem を下限にして、
  短い表の題が何行にも折れないようにする）、題の行は包みの幅で折り返す。親の幅を取る `chart`・`timeline`・`stats`・`compare`・`beforeAfter` と、
  `pre` に描く `mermaid`・`graph` は、題と凡例の幅を図の幅の段にそろえる（段の選び方は次の項）。題の文字は inline code だけを解く（太字・リンクは効かない）
- **`mermaid`・`graph` の図は、文字 12px（CSS px。svg の自然な文字 16px × 縮尺）を守る幅の段で描く**（2026-10-24）。
  図を差したあと、描画後の svg の縮尺を 42em（`body`）→ 63em（`wide`）→ 読む面（`full`）の順に当てて測り、12px 以上になる最初の段にする。
  縮尺は svg の箱の幅と高さを `viewBox` の幅と高さで割った小さいほう（高さの上限 70cqh で縮むぶんも含む）。
  どの段でも下回る `flowchart LR`・`graph LR` は、描画側が先頭行を `TD` に置き換えて描き直す（書き手の `direction` は変えず、差し替えたことは図に出さない）。
  それでも下回る図は縮めず自然寸法で描き（高さの上限を外す）、自然幅が 42em の内幅に収まれば 42em のまま（`natural`）、超えれば読む面の幅にして `pre` の中で横に転がす（`scroll`）。
  拡大の口は変えない。`wide`・`full`・`scroll` の包みは本文の列の左端から始め、`body`・`natural` は今までどおりレポートの幅の中央に置く。
  段は描いた時点の幅で決め、窓の幅が変わっても測り直さない。前後の塊の側の図は側の幅に収めるので段を当てない。
  確かめる場面は `report-graph-wide`（LR・12 節点）・`report-graph-scroll`（横に転がる TD）、数は `capture-view.ts --paper-metric` の「svg の文字の最小 px」と「11px 未満の図」（差し戻しにはしない）
- **主経路の長い `graph` は、tsukumo が行を折り返して座標を決める**（2026-10-25。`docs/architecture/adr/0034-figure-description-drawn-by-tsukumo.md`）。
  主経路は戻り道でない辺で辿る最長の一本道で、**6 節点以上**の図を `src/shared/report/graph-fold.ts` が蛇行の行（偶数行は左から右、奇数行は右から左）に並べ、
  `svg` の塊と同じ包み（拡大・縮み方も同じ）で描く。1行の数は 3〜6 個から、図を器（1440x900 のレポートの幅と図の高さの上限）に縦横比を保って収めたとき
  字がいちばん大きく見えるものを採る。主経路に無い節点はつながる主経路の節点の上の段に置き、隣り合わない辺と戻り道は行のあいだの通り道と図の左の外側を回す。
  群は行ごとに属する箱だけを囲み、題は最初の囲みにだけ付ける。主経路に無い節点どうしの辺・同じ節点の上の取り合い・戻り道でない辺の輪がある図と、
  5 節点以下の図は今の mermaid の経路で描く（カードの連鎖が先に当たる）。書き手の `direction` は折り返した図には効かない。確かめる場面は `report-graph-fold`
- **戻り道は `A <- B: 語`**（B から A へ戻る辺。2026-10-25）。配色は書き手が書かず、印から tsukumo が決める: 色の目印の無い群は地の色を3色
  （`--graph-ground-1`〜`3`）で巡らせ、` @a`〜` @e` の節点は枠に加えて地を薄く塗り（`--graph-tone-fill-*`）、戻り道は `--graph-return` の破線にして凡例に「戻り道」を出す。
  変更の印（`+ `・`- `・`~ `）は戻り道と色の目印より先に効く。mermaid の経路と折り返し配置の両方に同じ規則を当てる
- **節を書き上げる演出の塊（トピック）の単位にする**（2026-09-27。`docs/research/report-block-richness.md`
  2章）。見出しのレベルは節の中の副見出しにも、水平線は節の中の軽い区切りにも使われるので、DOM のタグからは
  境目を当てない。本文は欄ごとに入れ物を作り（`docs/architecture/adr/0031-report-body-as-regions.md`）、演出は節の欄の入れ物
  （`data-report-section`）1つを1トピックにする。見出しの無い節も欄1つなので1つのトピックになる。見出しの見た目は変えない。
  頭の欄（結論・検証結果）は筆の対象にせず、振り返りとお願いの欄は最後の節のトピックに入る
  （節の欄を持たない本文は全体が対象）。節の見出し（`h4`・`h5`）と図表の題の行は筆の対象から外して最初から出す（2026-10-17。
  題の行を子に持つ包みは対象にせず中の本体だけを書く）。演出の全体は10秒で終わり、上限をまたぐ塊はそこまでに書き切り、
  後ろの塊は上限の時刻に一度に出る。演出中だけ、ステップの右上に「全部出す」の口を出す
- **型で守られるようになった検査は外した**（表の見出し〔`table.title` が必須〕・`#` の見出し〔見出しは
  節の欄〕・本文の中のお願い〔`note` の種別に無い〕）。代わりに差し戻すのは、行のセルの数が `columns` と
  揃わない表・節が2つ以上あるのに見出しの無い節・`src/browser/` の `.tsx` / `.css` を変えたのに画像が無い（kind `browser-change-without-image`。2026-10-24 から。`checks` の `unobserved`・`blocked` があれば差し戻さない）・**逃げ道の外側（HTML の塊の中でないところ）に塊の種類が
  ある記法**（`#` / `##` の見出し・表・箇条書き・`note`・`stats`・フェンス・mermaid）。最後の1つが無いと、
  本文を丸ごと逃げ道に入れて型を素通りできる。HTML の塊の中を見ないのは、複数の塊を `<details>` に
  まとめて畳む・並べるのが逃げ道の役目だから。記法は逃げ道を構文木（ブラウザと同じ remark の組）にして読み、
  ブラウザが記法として描く形だけを数える（HTML の行に空行なしで続く `- 項目`・段落に続く `2. 項目`・
  区切りの行のセル数が合わない表は数えない）。容れ物の深さは HTML の中の `<details>` / `<div>` のタグを
  1つずつ数えて決める（インラインコードの中は数えない）
- 崩れた塊・知らない種類の塊は入口で落とし、塊1つの読み損ねでレポートを捨てない。切り替える前の transcript の
  文字列の `body` は同じ入口で逃げ道の塊1つの節に畳むので、過去のレポートの見た目は変わらない

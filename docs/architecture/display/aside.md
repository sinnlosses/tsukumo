# 補足メッセージ

戻り: `docs/architecture/display.md`「補足メッセージ」

**委譲中（バックグラウンドタスクが残っているあいだ）に入力欄から送った言葉と、レポートの部品や表の行を指して問う「聞く」は、新しい依頼にせず「補足メッセージ」として親のやり取りに
吊るす**（用語は `docs/glossary.md`「補足メッセージ」。見本は `docs/history/mockup/aside-thread-2026-10-07.html`）。
委譲中のやり取りは状況の確認や一言の頼みに近く、新しい依頼にするとカードが割れてプログレスバー・経過・中間レポートが消えるため。
聞くは作業を始めずセリフで答えさせる操作なので、待ちのとき（バックグラウンドタスクが無いとき）にも補足メッセージにする（`docs/architecture/adr/0051-report-reply-layer.md`）。

- **補足メッセージかどうかは、サーバが `prompt` を受けた瞬間に機械的に決める**。仕事のとき（雑談では決めない）に、次のどちらかなら補足メッセージにする。
  本文は読まない。
  - 送り方が `ask`: バックグラウンドタスクの有無によらず補足メッセージにする。`ask` は指した所 `target`（`ReplyTarget`）を必ず伴う
  - 送り方が `aside-when-background`: サーバの姿のバックグラウンドタスクが1件以上のとき
    ブラウザが渡すのは送り方（と `ask` の指した所）だけで、バックグラウンドタスクの有無は見ない（駆動が動くのはサーバの姿の上なので、判定もそこで1回だけ行う）。
    入力欄の ⌘⏎ は `aside-when-background`、⌘⇧⏎ は `new-request` で、バックグラウンドタスクがあっても新しい依頼としてカードを割る。
    始め方の一覧・タスクの実行から送る依頼は送り方を省き、`new-request` になる
- **補足メッセージは `request` ではない別の出来事と記録 `aside` にする**（`text`・`images`・時刻、聞くのときは指した所 `target`。ターンの通し番号は持たない）。
  `request` でないので、カードの割り方・記録ウィンドウ・同じ依頼の範囲を読むもの（ワークプラン・依頼の手順・
  ワークプランの差し戻し）は、補足メッセージを親のやり取りの中として読む。カードも「n / N」も増えず、プログレスバーは親のワークプラン・今のフェーズ・経過を出し続ける。
  経過は親の依頼を送った時刻から数え続け（続きのターンと同じ）、吹き出しと表情は補足メッセージのターンの頭でも持ち越し、答えのセリフを後ろに足す（空に戻すのは書きかけだけ）
- **claude へ送る文面は `<tsukumo-aside>` のラッパーに入れ、ラッパーの先頭に1行の説明（tsukumo の差し込み・利用者が送った補足メッセージで作業の依頼ではない・作業は始めず `speak` を1回で答え `report` は呼ばない）を添える**。
  指した所があれば、説明の次の行に `指した所: <節> › <部品> › <行>` の1行を置く（節・行は無ければ省く。図表番号は入れない。ブラウザが答えを戻す鍵は claude へ渡さない）。
  ラッパーの見分け方は常設の規約に置かない。説明の1行と指した所の行は組み直しで読み戻すときに本文から分ける（`asideReadingOf`。委譲中に限っていた古い説明も、説明の無い古い transcript も読める）。claude はラッパーで補足メッセージと分かり、組み直しは
  入力の控え（`$TSUKUMO_HOME/input-ledger/`）で `aside` に戻す（組み直すときにはバックグラウンドタスクの顔ぶれが分からないため）。
  控えは指した所の鍵（`reportToolUseId`・`componentId`・`rowIndex`）だけを持ち、字は transcript のラッパーの `指した所:` の行から読む。鍵が無い控えでは指した所を戻さない。
  控えに無い入力（控えを書く前のセッション）だけは transcript の `user` のラッパーを見て戻す。
  控えで親と同じターンが受け取ったと分かる補足メッセージの手前では、組み直しもターンを閉じない。
  組み直しでは、バックグラウンドタスクの知らせの `user` メッセージで続きのターンを区切り、委譲の続きのセリフを補足メッセージへの答えに混ぜない
- **答えは `speak` で受け、`report` は求めない**。補足メッセージのターン（`aside` から、次の依頼・続きのターン・ターンの終わりまで）の
  セリフには `answersAside` の印を付け、メインビューは補足メッセージとその後ろの印の付いたセリフを対にする。答えは吹き出しと、
  親のカードの補足メッセージの欄（「各表示物」のメインビュー。やり取りで1つの欄の中に、送った順で足す）に出る。答え方（`speak` で答え `report` は呼ばない）はラッパーの説明の1行が言い、
  条はワークプランの節の「補足メッセージ」の項で、補足メッセージで止める・方針を変えるよう頼まれたときの組み替えと、親の作業が進んだ（委譲の返却が届いた）ときだけ、いつもどおり親のワークプランへ `work_plan` と `report` を
  渡すことを頼む。「レポートの記法」には足さない（補足メッセージでは本文を書かない。`Stop` の関所もそのまま）
- **補足メッセージのターンの `report` にはフェーズの閉じ方・背景のシェル・画像の無い `report` の差し戻しを掛けない**（`src/server/report/core/review/report-review.ts`）。
  補足メッセージのターンでも同じ依頼のワークプランは残っているので、掛けると答えるだけの `report` まで `workPlanClosing` を求めて差し戻すため。
  判定は `aside` の出来事で見分け、バックグラウンドタスクの有無に頼らない（待ちのときの補足メッセージのターンも同じ）。`Stop` の関所（`createReportGate`）も、補足メッセージのターンは `report` の無い本文を通す。
  ほかの差し戻し（送り直し・新しい事実の無い呼び出し・応えていない `work_plan`・`ng` のある `finished`・規約違反）はそのまま掛かり、`aside` は新しい事実に数える。
  ターンの頭の `session-info` は補足メッセージのターンの頭にも届くので、補足メッセージの印はそこでは戻さない。
  作業中（フォアグラウンドでターンが走っているあいだ）に送った聞くは、別のターンで答える場合と、走っているターンに取り込まれる場合の両方で成り立つ。
  その場で補足メッセージのターンにするのはターンが走っていないときだけで、走っているときに届いた `aside` は保留にし、作業のターンの差し戻しと関所を外さない。
  保留は、最初に届いた `speech`（取り込まれて答えた）か次の依頼で外し、保留のままターンが終わって次のターンが `turn-resumed` で始まったら、そのターンを補足メッセージのターンにする（`src/server/report/core/aside/aside-turn.ts` の `nextAsideTurn`）。
  画面の「答え待ち」も、聞くのあとに最初に届いた `speak` で外す
- **「止めて」「方針を変えて」も、親のワークプランを引き継いだまま受ける**。補足メッセージのターンの `work_plan` はそのまま親のプログレスバーを
  進める・組み替える（委譲の返却が補足メッセージのターンの最中に届いたときも同じ）。止めるなら `stopped` の `report` で親のプログレスバーを
  止めた姿にする。委譲先を止める操作は claude 自身が行い、tsukumo は持たない
- **バックグラウンドタスクが終わって親のやり取りが閉じても、欄は親のカードに残す**。開いているあいだは開いて出し、閉じたら畳んで
  「補足メッセージ n件」の行だけにする
- **やり取りの列では、親のやり取りの行の2行目に「脇 n」を出して畳む**（「各表示物」のメインビュー）
- **防げないこと**: バックグラウンドタスクの顔ぶれは SDK の知らせが届いた時点のものなので、終わった直後で知らせがまだ届いていない
  一瞬に送った言葉は補足メッセージになる。そのときは ⌘⇧⏎ で送り直せる

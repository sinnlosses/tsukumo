# ワークプラン: 段の閉じ方・閉じていない report の差し戻し・出す場所

戻り: `docs/architecture/display.md`「ワークプラン」

- **段を閉じるのは `report` の欄 `workPlanClosing`（段の閉じ方）で、最後の段は tsukumo が閉じる**（2026-10-06。
  止めたのか閉じ忘れたのかを記録から見分けるため）。済ませたか止めたかの判断はモデルが書き、書き忘れは差し戻しで落とし、
  閉じる操作は tsukumo が受け持つ
  - **欄は `finished`（全部の段を終えた）か `stopped`（途中で止めた）**。`task.outcome` は使わない
    （タスクの `report` にしか無く、タスクに紐付かない作業のターンを覆えない）。帯を閉じるときに読むのはこの欄だけで、
    `task.outcome` は目録の1行の終わり方のまま帯には使わない
  - **`finished` の `report` を受け付けたら、同じ依頼の最後のワークプランを閉じる**。閉じるのは最後の
    段にいるときだけで、`current` を段の数にした `work-plan` の記録を `report` の記録の直前に積む（同じ時刻を持つ）。
    段が2つ以上残っている・全部済みの位置からは動かさない（帯は1回に1段しか進めない）。`stopped` では積まず、止まった段が
    「今」のまま残る。差し戻されなかった `report` だけがイベントとして流れるので、閉じるのはイベントの側で、
    transcript から組み直すときも同じ変換を通って閉じた帯が戻る
  - **`work_plan` で `current` に段の数を渡す呼び出しは受け付けたまま残す**（組み直した古い transcript と、メインが自分で
    閉じた呼び出しを壊さない）。閉じたあとの `finished` は残りが 0 なので何もしない。条と引数の説明では、`current` に
    段の数を渡す頼み方をしない
- **ワークプランの閉じていない `report` を差し戻す**（2026-10-06 利用者決定。`src/server/report/core/report-review.ts`）。
  `report` を通すとターンが閉じ、差し戻しに応える番が来ないため
  - **同じターンで差し戻した `work_plan` にまだ応えていない `report`**: 受け付けた `work_plan` の呼び出しがあれば
    応えたことになり、通る。差し戻しの覚えはターンの区切りで戻る
  - **段の閉じ方が合わない `report`**: 同じ依頼にワークプランがあるときだけ見る。欄が無い（全部済みのあとでも）・
    `finished` なのに段が2つ以上残っている・`task.outcome` が `finished` なのに `stopped` で段が残っている、の
    どれかなら差し戻す。残りは同じ依頼で受け付けた最後のワークプランで数える。ワークプランの無い
    依頼では欄が無くてもあっても通す
  - **枠の数え方**: 応えていない `work_plan` と段の閉じ方でそれぞれ1ターンに1回まで（段の閉じ方の3つは1つの枠を
    共有する）で、使い切ったら通す（無限に往復させない）。ほかの枠（送り直し・新しい事実の無い呼び出し・
    `ng` のある `finished`・背景のシェル・画像の無い `report`・規約違反）ともそれぞれ分けて数える。規約違反と枠を共有すると、記法の差し戻しで枠を使ったターンでは段の閉じていない `report` が
    そのまま通り、差し戻しに応える番が来ないまま閉じるため。見る順は、送り直し → 新しい事実の無い呼び出し →
    応えていない `work_plan` → 段の閉じ方 → `ng` のある `finished` → 背景のシェル → 画像の無い `report` → 規約違反
  - **防げないこと**: handler はメインとサブエージェントの呼び出しを見分けられないので、委譲先が `work_plan` を
    呼んで差し戻されると、メインの `report` が1回差し戻されることがある（`report` のほかの差し戻しと同じ制約）。
    済ませたのに `stopped` と書く・止めたのに `finished` と書く取り違えは見分けない（判断はモデルに残す）
- **段を進める `work_plan` と、その契機の `speak` は同じ応答の中で並べて呼ぶ**（段が変わるのは論点が
  切り替わるときで、`speak` の契機に当たる。別々の応答にすると往復が1回増える）
- **出す場所は3つ**: いまの作業の札（今の段の名前と位置。会話の画面以外）と依頼の手順の一覧の頭（全部の段と、段ごとに
  区切った手順）は `docs/architecture/screen-design.md`「いまの作業」。会話の画面では、札と一覧の頭の代わりに
  メインビューの上端の進み具合の帯が段の並びと状態のチップを持ち、レポートを読むあいだも済んだ姿で残る（同 13.13「進み具合の帯」。
  段の丸を押すと、その段の名前・所要・段のまとめの吹き出しが出る）。
  **最終レポートと中間レポートにはワークプランを描かない**（2026-10-02 ユーザー決定。帯と同じことが2か所に出る。
  旧い形は `docs/history/decision.md`「screen-design.md 13.13 作業の地図・会話の画面の浮かぶ札・レポートの進み具合
  （2026-10-02 に覆した記録）」）。
  3つ目はメインビューの段の移り（「段が移ったときの中間レポート」）。段の並びの代わりに、最終レポートには段ごとの所要時間を1本の帯と一覧で置く

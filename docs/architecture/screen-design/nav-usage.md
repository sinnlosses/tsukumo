# 画面のデザイン: 使用量の行と帯が外すもの

ステータス: **正典**。入口は `docs/architecture/screen-design.md`（画面のデザインの全体）。

責務: サイドバーの使用量の行、プラン使用量の札、帯ができて外したもの、帯が奪う面積の実測。
読む時: コンテキストやプラン使用量の札に触るとき、帯の高さを変えるとき。
直す時: 札の形・取り直す契機・帯の寸法を変えたとき。

## 13. 画面のデザイン

### 13.9 画面のナビゲーション

#### 使用量の行

**サイドバーの下端の帯にいまのコンテキストの使用量を1枚の札で出す**（札は下端の帯の
目盛りを押して開く詳しい面の中にある。上の「会話の画面の帯とサイドバーの下端の帯」。ユーザー決定。
見本「案1」の形。キャラクターとセッションの切り替えが帯の左上にあるので、
下端の帯はこの札だけ）。3段組みにする——
1段目にラベル「コンテキスト」・大きめの割合（例 `28%`）・**使っている量と窓の大きさ**
（例 `284k / 1.00M`）・右端の `›`、2段目に細い棒（使っている割合ぶんだけ塗る）、3段目に
「自動圧縮まで あと N」。**押せるのは右端の `›`（ホバー中は「詳しく ›」）だけ**——ラベル・
割合・量・棒はリンクにしない（行全体を押せる札にはしない。ユーザーの訂正）。押すと
トークン消費の画面（`#token-usage`）へ移る。

- **出す数はトークン消費の画面の札（「いまのコンテキスト」`context-usage-card.tsx`）の
  「使っている量」と同じ**——`usage.totalTokens` / `usage.maxTokens` / `usage.percentage`
  （`used` 分類の合計 / 窓の大きさ / その割合）で、自動圧縮バッファ・窓の外のツールの定義
  （`deferred`）は含めない。桁の書き方（`formatCount`。`1234567` → `1.23M`）も札と同じ道具を
  使うので、行の数字と札を開いたときの数字が食い違わない
- **取得と畳み込みは `browser/domain/context-usage.ts`**——トークン消費の画面の札とサイドバーの
  この行の2つの機能が読むので、`components/page/token-usage/` から `browser/domain/` へ上げてある
  （docs/architecture/browser-box.md「上げる引き金は「2つ目の読み手が出たとき」」）
- **取り直すのはターンが終わるたび**（開いたときの1回に加えて）。合図は
  `state.finishedTurnCount`（ターンが終わった回数。次のターンが始まっても戻らない）で、`useQuery` の `queryKey` に含めるだけで取り直せるので、`useEffect` は要らない。ターンの
  途中は前に取った値のまま出し続ける
- **会話の画面を隠している間もサイドバーは外れない**（`components/app/layout.tsx` の `<Activity mode="hidden">`）
  ので、トークン消費の画面を開いている間もこの行はマウントされたまま。同じ `queryKey` を見る
  2つの機能が同時に居ても、`useQuery` の cache 1本に相乗りするので取り直しは1回で済む
- **割合が70%以上のときは警告にする**（見本の説明文から取った境目。`context-usage-row.tsx` の
  `WARN_THRESHOLD_PERCENTAGE`）。割合の数字と棒を警告の色にし、3段目を「そろそろ区切りどき。
  自動圧縮まで あと N」にする。**この定数はサイドバーの行だけが持つ**——トークン消費の画面の札
  （`context-usage-card.tsx`）はまだ警告色の仕組みを持たず、読み手が2つ目にならないので
  `browser/domain/` へは上げていない
- **`›` にホバー（とキーボードのフォーカス）すると、「詳しく」が左へ伸びながら現れる**
  （幅と不透明度の短い transition）。**札の地と枠はホバーで変えない**——札が浮くと全体を
  押せるように見えるため（ユーザーの指示）。警告時の札の地と枠はホバーに関係なく
  `--state-warn` からの `color-mix` 導出で敷く（16進は写さない）。**取れないとき・
  まだ届いていないときも札の高さは変わらない**——1段目の割合は「—」、量の場所に一言
  （「取得中…」「いまのコンテキストは取れていない」）を出し、3段目は空けて高さだけ保つ。
  押す先はどの状態でも `#token-usage` のまま。**`ContextUsageCardSkeleton` のような灰色の
  塊は使わない**——文字だけなので、実物の文字と同じ行の高さで自然に揃う
- **`›` の `aria-label` は「コンテキスト N% 使用。トークン消費の画面で詳しく見る」**（届いて
  いない・取れないときは割合の代わりにその旨を読む）

#### プラン使用量の札

**コンテキストの札の下に、5時間枠と7日間枠の使用状況を1枚の札で出す**（
ユーザー決定。出どころと採らなかった案は `docs/research/plan-usage.md`）。見た目の出どころは
見本「サイドバーの「プラン使用量」の札 — 5つの状態と寸法」（`QUOTA-Sidebar.dc.html`）の inline
style と `<helmet><style>`、値は末尾の「寸法」「色」「ふるまい」の欄。5つの状態は
**ふだん・高いとき（80%以上）・取得中（前の値あり／開いた直後）・取れない（失敗／API キー・列を使い切った後）・
狭いとき（サイドバー280px未満で棒を畳む）**。

- **寸法**: コンテキストの札と同じ余白で1段下に続く——上に1px の `--rule` の罫線を引き、
  余白は上10px・左右0（コンテキストの札の内側にそのまま続く）・下12px。1段目（見出し）は
  高さ18px:「プラン使用量」のラベル（12px）・取った時刻（12px 等幅）・↻（24×24、アイコン14相当）。
  2・3段目（5時間枠・7日間枠）は高さ20px:列はラベル 3.2em／棒 残り／割合 5ch 右寄せ
  （13px 等幅）／戻る時刻（12px 等幅）。棒は高さ4px・角丸2px。段の間は6px。**札の高さは
  どの状態でも変わらない**（コンテキストの札の3段目までと同じ考え方）
- **色**: 地は帯と同じ（`--ground`。見本の「一段沈んだ地」に当たる。`.sidebar-footer` が
  すでにその地を敷いている）。棒の溝は `--rule`、棒そのものは `--accent`
  （コンテキストの棒と同じ——ここは character の差し色を受け取ってよい場所ではないが、
  「ふだんの状態を表す色」という役割はコンテキストの棒と同じ立場なので揃える）。ラベルと
  戻る時刻は `--ink-quiet`、割合は `--ink`（見本は3段階の弱さ〔`--text`/`--text-2`/`--text-3`〕を
  持つが、`theme.css` には2段階〔`--ink`/`--ink-quiet`〕しか無いので `--ink-quiet` に集約する
  ——`context-usage-row.tsx` も同じ簡略化をしている）。**高い（80%以上）は割合と棒を
  `--state-warn`** にし、割合を太字にして▲を前に付ける。**取得中は時刻の場所に「取得中…」を
  `--accent`** で出し、↻ が回る。**失敗は×アイコンだけ `--state-ng`**、文は `--ink-quiet`。
  **警告の色は棒・割合にしか付けない**——サイドバーの札全体を警告色で染めない（コンテキストの
  札は70%以上で地ごと`--state-warn`寄りに染めるが、プラン使用量の札はしない。見本にその指示が無い
  ことと、`docs/research/plan-usage.md`「論点3」の「境目を tsukumo が決めると Claude Code の判断と
  ずれる」という判断に揃える）
- **ふるまい**: ↻ はアイコンだけ（`aria-label` と `title` は「プラン使用量を取り直す」/「取り直す」）。
  **取得中は押せない**。前の値があれば薄く残し（不透明度0.45）、無ければ「—」と幅0の棒。
  **取れないときは2・3段目をまとめて一言にし、高さは変えない**。サーバが「該当しない」
  （`not-applicable`）を返した間は、2・5・10・20秒の間隔で取り直し（合計37秒。起動直後は claude が
  契約の種類をまだ持たず、同じ応答が返るため）、その間の合間も札は「取得中…」のまま、↻ は押せない。
  値が出れば止め、20秒の回でも「該当しない」なら取れなかったときの一言（↻ で取り直せる）にする。
  API キーで使っていても同じ一言が出る。↻ は押すたびに1回だけ取り直し、列は始めない。
  **戻る時刻を
  過ぎた値も、取り直すまではそのまま出す**（取った時刻を添えて古さを読めるようにする）。
  **狭いとき（サイドバー280px未満）は棒を畳み、割合と戻る時刻だけにする**（`@container`。
  基準は詳しい面 `.sidebar-footer-detail` の幅）
- **取り直す契機は開いたとき・ターンが終わるたび・↻を押したとき・「該当しない」が返った間の取り直しの列**（時計では回さない。
  `docs/architecture/display.md` 4.2）。出どころは SDK の
  `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET`——`docs/glossary.md`「プラン使用量」

#### 何を外すか

帯ができると同じ口が2つになるので、**古いほうを外す**:

| 外すもの                                                      | 置き換え先                                   |
| ------------------------------------------------------------- | -------------------------------------------- |
| サイドバーのキャラクターの行のリンク「整える」                | 帯の「キャラ」                               |
| キャラクター画面の左上「← 会話へ戻る」                        | 帯の「会話」                                 |
| トークン消費の画面の左上「← 会話へ戻る」                      | 帯の「会話」                                 |
| 上の2つに付いていた答え待ちの印                               | 帯のいまの作業の「答え待ち」                 |
| 帯の右端の答え待ちの印（`screen-nav-pending.tsx`）            | 帯のいまの作業の「答え待ち」                 |
| 帯のモデル・許可モードの読み（`screen-nav-status.tsx`）       | 帯のドロップダウン（操作子が読みを兼ねる）   |
| サイドバー「セッション情報」のモードの `<select>`             | 帯の仕事・雑談の門                           |
| サイドバー「セッション情報」のモデルの `<select>`             | 帯のモデルのドロップダウン                   |
| サイドバー「セッション情報」の許可モードの `<select>`         | 帯の許可モードのドロップダウン               |
| サイドバーの「いま何をしているか」の区画（`activity.tsx`）    | 帯のいまの作業と、押すと開く依頼の手順の一覧 |
| キャラクター画面の「画面の色」の組（3つの色）                 | 帯の歯車の「画面の色」                       |
| サイドバーの下端の帯のキャラクターの `<select>` と顔          | 帯の顔と、押すと開くキャラクターの選び口     |
| サイドバーの下端の帯のセッションの `<select>`（見出しの一行） | 帯のセッションの札と、押すと開く切り替え画面 |

**サイドバーは タスク一覧 と下端の帯になり、下端の帯に残るのはいまのコンテキストの使用量の札と
プラン使用量の札だけ**（`docs/architecture/display.md`「各表示物」）。使用量の札・プラン使用量の札は帯ができる前から無い
機能なので「外す」対象ではない（上の「使用量の行」「プラン使用量の札」）。

**作る画面の「← キャラクターへ戻る」は残していた**（帯に出ない画面だったため、置き換え先が
無かった。作る口が独立した画面からダイアログへ変わり、この戻る口ごと無くなった。
13.6「作るダイアログ」）。

#### 帯が奪う面積（実測）

帯を 30px（body の padding の内側・gap 0.4rem）から、画面の端から端まで出る帯（上端の線 3px と
下の罫線 1px を加えた外寸・gap 1rem）に広げる前後を、同じ疑似セッション・同じ窓の大きさ
（高さ 900px）で `scripts/capture/capture-view.ts` と同じ手順（Playwright で DOM の矩形を読む）で直接
測った値（fake driver。`docs/architecture/testing.md`「手で確かめること」）。帯の地はいちど
見本どおりの 60px（外寸 64px）にし、そのあと 52px（外寸 56px）に下げた:

| 幅   | 領域         | 帯 30px（最初） | 帯 60px（見本どおり） | 帯 52px（上端の線 3px があったとき） |   30px との差 |
| ---- | ------------ | --------------: | --------------------: | -----------------------------------: | ------------: |
| 1400 | メインビュー |           483.6 |                 467.0 |                                471.8 | -11.8 (-2.4%) |
| 1400 | キャラビュー |           322.4 |                 311.4 |                                314.6 |  -7.8 (-2.4%) |
| 390  | メインビュー |           482.9 |                 482.9 |                                482.9 |             0 |
| 390  | キャラビュー |           152.0 |                 152.0 |                                152.0 |             0 |

**上端の線をなくしたあとは、外寸が 56px から 53px へ 3px 縮む**
（上の「帯の形」）。この表の値は線があったときの記録のままで測り直していない
——線をなくした差（3px）は 30px→60px の変化よりずっと小さいうえ、この表の期間に
他のタスクがキャラビューの既定の split 比率にも触れているため、いま測り直しても
「上端の線の有無」だけの差を切り分けられない。

広い画面で grid の上端は 52.4px から 72px へ下がる（奪う高さが 19.6px 増える）。内訳は、帯の外寸が
30px から 56px へ 26px 伸びるうち 16px は上の padding の中へはみ出して打ち消し、帯の下の隙間が
6.4px から 16px へ 9.6px 伸びたぶん。上下の行は `fr` で比例配分されるので、**メインビューも
キャラビューも同じ割合（-2.4%）減る**。表の 390 の行は、狭い画面で帯をタブ帯の右端の「≡」にオーバーレイで
畳んでいたころの値（差0）。いまの狭い画面は帯を出さない（下の「狭い画面（760px 以下）」）。

**帯の高さの床は「押せる口の最小」（24px）。** 広い画面の口はマウスで押すので、狭い画面の口
（指で押す・40〜44px）に揃える理由は無い。口（`.screen-nav-gate`）は帯の高さいっぱいに
伸びる（帯の地の 52px に、下線を罫線に重ねる 1px を足した 53px）ので、床を大きく上回る。

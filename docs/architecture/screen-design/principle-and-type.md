## 13. 画面のデザイン

見た目の正典。**ここに書いてあるのは計画であって、CSS はこれを写したもの**（写す先は
各機能の `*.module.css`。トークンは `src/browser/styles/theme.css` に置く。`docs/architecture/browser.md`「CSS」）。
**ただし色の 16 進の値は `src/browser/styles/theme.css` が正典で、ここには書かない**（ここが持つのは、
どの色をつまみ・導出・固定のどれにするかと役割・導き方）。

### 13.1 Principles

**色はキャラクターの持ち物、静けさは画面の持ち物。** これが他の4つの根拠になる。

1. **読む面はキャラクターの色を受け取らない。** レポートの本文・サイドバーの文字・入力欄の
   文字は、誰が来ても同じ濃さで読める。色が現れるのは**キャラクターが居る場所**（立ち絵・
   吹き出し）と、**機械が指し示す場所**（フォーカスの輪・`:hover` の縁・選ばれたタブ・
   選んだ選択肢・送信・お願いの縦罫）と、**読む面を仕切る罫線**（レポートの `##` の
   下の罫。`###` と表の見出し行の下は引かない。13.2「レポートの見出しに」）と、
   **チェックリストの済みの印**（枠・✓・地。利用者の注文。✓ の文字が
   必ず添うので色だけで済みを伝えない。原則5）だけ。
   **見出しやツール名も「文字」の側**なので `ink` 系（レポートの見出しは拾う字 `ink-bright`）で、色を持つのは隣の縦罫・枠のほう
   （当ててみたうえで確定）。ただしレポートの `note` のうち、縦罫を持たない情報・疑問・メモは、
   種別のラベルの字が種類の色を運ぶ（縦罫を持つのは注意・異常・お願いだけ。13.2）。**仕切る罫線に出すのは弱めた色**で、素の `accent` は
   キャラクターが居る場所と機械が指し示す場所に残す。
   **リンクだけは例外の扱いが要る**: 色を取り上げるかわりに**下線**で区別する。色だけに
   頼らないので、どのパックの `accent` が来てもリンクだと分かる。
   **出典の札**: レポートの外部リンクのうち、字が href のホスト名（先頭の `www.` を除き、大文字小文字を揃えて比べる）と同じものは、
   下線のかわりに等幅 12px・`ink-soft` の字・1px の `--rule` の枠・角 4px の札で描く（`[ドメイン](URL)`。規約は「外部の出典」の条）。押すと今どおり外へ開く
2. **枠を持たないのはキャラクターだけ。** 付喪神は器物に宿るのであって、ウィジェットの中に
   座っているのではない。**大胆さはこの1箇所に使い**、他の3領域は静かな枠のまま保つ
3. **機械が付けた名前は等幅、人が書いた言葉は本文書体。** タスクのID・ツール名・キー・モデル名・
   経過時間は等幅。レポートとセリフは本文書体。**装飾ではなく区別**で、等幅は「これは機械の側の
   名前だ」という情報を運ぶ
4. **読む面の幅は3段で決める。** **本文 42em**（全角 42 字。段落・箇条書き・`note`・お願い・`checks`・
   見出しとその罫）、**広 `min(内幅, 63em)`**（図・表・コード・数の札・`cards`・候補・ファイル・画像）、
   **全（内幅）**（見比べ・前後の見比べと、列が 7 以上の表・`matrix`）。広も全も左端は地の文に揃えて
   右へ伸ばす（JLReq 2.4.2・WCAG 1.4.8。経緯は下の `docs/history/decision.md` の節）。余白の柱を持つ塊は、表と図でも 42em に収まる
   （13.4「余白の柱」）。経緯は
   `docs/history/decision.md`「design.md 13.1 Principles（原則4。行長の上限を撤回した経緯）」と
   「screen-design.md 13.1 原則4（地の文だけに上限を戻した決定）」
5. **意味を固定した色は誰が来ても変わらず、文字と対でだけ増やす。** ok / warn / ng / ask / memo の
   意味がキャラクターごとに動くと、色が情報を運べなくなる。**色を1つ足してよいのは、その色が
   指すものに tsukumo が文字のラベルを必ず添えるときだけ** — モデルの書き忘れで消えない文字が
   付いていれば、色は読みやすさのための重ねがけになり、色だけで意味を伝えることにならない
   （レポートの `note` は6種に割り、6種すべてにラベルを出したうえで `state-ask` と `state-memo` を足してある）。ラベルを添えられないところでは色を足さず、**既にある色・地の段・枠・文字の印**で
   区別する

### 13.3 Type

**書体は `system-ui` と等幅の2本**にする。**ネットワークへ出る外部フォントは足さない。同梱して
`127.0.0.1` から配るもの（`docs/architecture/adr/0012-bundle-vendor-library.md` の経路）は足してよい。**
この画面が抱える問題は書体の選択ではなく**寸法と行長**のほうにあるため、仕事はそちらにさせる。

- 本文は `system-ui` のまま。レポートの範囲（`.detail-block`）に `font-size-adjust: ex-height 0.545` を
  当て、SF Pro の欧文の小文字を Hiragino Sans の x-height に揃える
- レポートのコード（フェンスと inline code・`kbd`・`samp`）だけ、同梱の IBM Plex Mono（latin の 400 と 600）で
  描く。トークンは `--font-code`（`theme.css`）で、読めなければ `--font-mono` に落ちる。
  `--font-mono` が指す ID・ツール名・キーなど機械のラベルの書体は変えない。コードの中では
  `font-size-adjust` を打ち消す

| 役割                                 | 寸法                                                      | 書体     |
| ------------------------------------ | --------------------------------------------------------- | -------- |
| 印・小さなラベル                     | 0.75rem（12px）                                           | 本文書体 |
| 枠なしの入口（リンク風の操作）       | 0.75rem（12px）                                           | 本文書体 |
| 出典の札（字がホスト名と同じリンク） | 12px                                                      | 等幅     |
| 補助・サイドバーの本文               | 0.8125rem（13px）                                         | 本文書体 |
| 区画の見出し・強調した要約           | 0.875rem（14px）                                          | 本文書体 |
| 本文（レポート・セリフ）             | 0.9375rem（15px）                                         | 本文書体 |
| 大きな見出し（画面・ダイアログの題） | 1.125rem（18px）                                          | 本文書体 |
| 入力欄の見出し3段目（`###`）         | 1.0625rem（17px）                                         | 本文書体 |
| 入力欄の見出し2段目（`##`）          | 1.1875rem（19px）                                         | 本文書体 |
| 入力欄の見出し1段目（`#`）           | 1.3125rem（21px）                                         | 本文書体 |
| ID・ツール名・キー                   | 0.8125rem（13px）。サイドバーのタスクのIDは印の段（12px） | 等幅     |

- **字の下限は 12px**（旧い決定は
  `docs/history/decision.md`「screen-design.md 13.3 Type」）。これを割る字を足さない。印と入口は
  役が違うので `--font-label` と `--font-action` に分けたまま、値は同じ 12px にしてある
- 大きさは**この8つだけ**（役の行は上の表の9つ）。これ以外の寸法を足さない。**同じ mock で 14px が出ても、機械のラベルに近い字（`dispatch` の送信ボタン）は
  新しい段を使わず既存の 13px に寄せた**（採らなかった理由は
  `src/browser/components/page/conversation/components/dispatch/dispatch.module.css` の該当コメント）——段を増やすのは
  「差をはっきり見せたい」という要求があるときだけで、寄せられるところは寄せる。
  **`test/architecture/font-size.test.ts` が、`theme.css` 以外の `*.css` の `font-size` を `var(--font-*)`・`var(--report-heading-*)`・
  `em`・`%`・`inherit` と、部品の中で `--font-*` から導いた局所のつまみ（日記の `--diary-text`・`--diary-title` は `--font-heading`・`--font-heading-1` に縮める倍率 `--diary-scale` を掛けた値、
  吹き出しの `--balloon-latest-scale`・`--balloon-past-scale` は `--font-*` を `clamp` で挟んだ値）に限る**。
  `px`・`rem`・`clamp`・`calc` を `font-size` に直接書くと落ちる
- **入力欄の見出し3段は、入力欄のマークダウンエディタの `#`〜`###` にだけ使う**。
  打った段が見て分かるよう2px 刻みにした（1px 刻みでは太字どうし隣り合う段が見分けにくかった）。
  `#` は「大きな見出し」（18px）を超えるが、画面の他の見出しと混ぜないよう `--font-heading` とは
  別の変数（`--font-heading-1`〜`-3`）にしてある
- **レポートの結論部の見出しと `##` は、入力欄と同じ大きさを別のつまみで持つ**。
  `--report-heading-2`（21px）・`--report-heading-3`（17px）は `--font-heading-2`/`-3` を参照せず
  値を直に持つので、入力欄のマークダウンエディタの見出しとは別に動く（`theme.css`）。`##` は 21px・700・行間 1.4・字間 0.01em・`palt`・`ink-bright`、
  `###` は `--report-heading-3`（17px）・700・罫なし- **依頼の全文（`RequestBlock`）は、見出し「依頼」を `--font-secondary`・`ink-quiet`、依頼の行を
  `--font-secondary`・`--ink-soft` で、baseline をそろえた1行に置く**（札の頭に題の行は置かず本文の頭へ置き、畳みは1行。見本は
  `docs/history/mockup/report-reading-tool-2026-10-18/after-first-w1400.png`）。
  **塊は地も枠も左罫も持たない**。1行目は切れたら末尾を …、右に「▾ 全文」（`--font-action`・`accent`）で開く。
  開くと全行と画像と「▴ 畳む」が出て畳み直せる。開いたまま長いときは行の側を窓の 40% で内側に転がす。
  1行に収まる短い依頼で画像も無いときは口を出さない。狭い画面も同じ形。依頼の行頭の引用の記号（`> `）は出さない
- **例外は日記の本文だけで、既定は端末の明朝体に寄せる**（成果の画面の吹き出しと
  見開きの右ページ。13.10）。書体の指定は `theme.css` の `--font-serif`（端末に入っている明朝体の
  名前を並べ、最後を `serif` にする）と、パックが差せる `--font-diary`（既定は `--font-serif` に
  落ちる）。**外部フォントは取らない**——ネットワークへ出るのを避ける理由は変わらないが、
  **キャラクターパックに同梱した書体ファイル（`woff2` / `woff` / `ttf` / `otf`）だけは配ってよい**
  （`character.json` の `diaryFont`。`docs/architecture/character-pack.md`）。書体を持たない
  パックはいままでどおり `--font-serif`（端末の明朝体）のまま。寸法は上の段のまま（本文の 15px）
  で、新しい段は足さない
- **本文の行間は 26px**（15px の字で `calc(26 / 15)`。`--line-height-body`。
  レポートの縦の格子 13 / 26 / 39px に揃えてある。日本語で長時間読むため、欧文の既定より広く取る）
- **幅は3段**（13.1 原則4）。本文 42em は地の文・`note`・お願い・`checks`・見出しの罫、
  広 `min(内幅, 63em)` は図・表・コード・数の札・`cards`・候補・ファイル、全は見比べ・前後の見比べと、
  列が 7 以上の表・`matrix`（CSS では入りきるかを測れないので、列の数で代える）。
  余白の柱を持つ塊だけは、表と図でも 42em に収まる（13.4「余白の柱」）
- **表は中身なりの幅で組む**（`max-width: 100%` で、幅いっぱいには広げない）。
  字は14px（`--font-subheading`）・行間20px、見出し行は13px（`--font-secondary`）・500・`ink-soft`、
  状態のセルは記号+文の1行を角丸8pxのタイルにし、地を状態の色で染める（NG・要注意は13%、OKは6%。
  `color-mix` で `--state-*` から導出）。セルの間は4pxのすき間を空け、罫線は引かない。状態の列の、状態の無いセルは
  `ink-soft`（見出し行と同じ、読ませる補助の字）のまま。行の左の色の線はやめ、表に出た状態だけを
  題（「表 n」）の直下・表の上に中央揃えの凡例（色見本・記号・語）で添える。
  **領域の内幅に入りきらない表は、その表だけ横スクロールさせる**（`.table-scroll`。
  ページ全体は横スクロールさせない）。**表のセルは最低4全角を1行で出す**（`min-width: 4em`）。
  この下限が無いと列の数だけ詰まってセルが1〜2字ずつの折り返しになり、
  表が器に収まってしまうので横スクロールも働かない
- **フォーム部品（`button` / `input` / `select` / `textarea`）の書体は `theme.css` が継がせる。**
  ブラウザの既定では親の書体を継がないので、`theme.css` の `body` 直後の1か所だけが継がせる
  （大きさ・行の高さ・太さも一緒に継ぐ）。機能の CSS には書かない——書くのは大きさなど、既定から
  変える値だけ

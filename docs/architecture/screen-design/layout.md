# 画面のデザイン: レイアウトと差せるもの

ステータス: **正典**。入口は `docs/architecture/screen-design.md`（画面のデザインの全体）。

責務: 領域の並び・揃え・図の高さ・余白の柱・やり取りの列・中くらいの窓幅と、パック・使う人が差すものの受け渡し。
読む時: 領域の配置・比率・レポートの塊の並びに触るとき、差せる値の経路を知りたいとき。
直す時: レイアウトの決まりか、差せるものの受け渡しを変えたとき。

## 13. 画面のデザイン

### 13.4 Layout

構想を1文で。**上の2枠は読む場所、下は居る場所。キャラクターだけが枠を持たない。**

```
┌─────────────────────────────────┬──────────────────┐
│ メインビュー                      │ サイドバー         │
│ レポート（幅は領域に任せる）        │ タスク一覧         │
│ 左揃え・本文書体・行間 26px        │ 使用量（下端の帯）   │
│                                 │ （名前は等幅）      │
│                                 │                  │
└─────────────────────────────────┴──────────────────┘

   ◯  ╭───────────────────╮         ┌──────────────────┐
  立ち絵 │ 吹き出し（最新が下）│         │ 入力欄            │
       ╰───────────────────╯         │                  │
   ↑ 枠も地も持たない。ground の上に直接立つ  │ [送信]  経過: –   │
                                     └──────────────────┘
```

- **文字の揃えは全面左揃え。** 日本語の読み物なので、中央揃えも両端揃えも使わない。**レポートの表と図
  （題つきの塊）だけは、包みをレポートの幅の中央に置き、題（「表 1 …」「図 1 …」）と凡例を包みの中心に揃え、
  42em より狭い本体も包みの中央に置く**（2026-10-03。2026-10-18 に軸を本文の列へ改め、
  2026-10-20 に42em を超える本体もレポートの幅の中央へ戻した。題の外の文字の揃えは変えない）。題を持たない表も、表の幅まで縮めて中央に置く。内幅いっぱいの塊（見比べ・前後・列が 7 以上の表）と、余白の柱を持つ塊（本文の列に収まる）は動かない。
  mermaid の箱は文字 12px を守る最小の段で描き、63em と読む面の段は本文の列の左端に揃える（2026-10-24。`display/figure-caption.md`）。
  題が折り返すときは行の長さを揃えて（`text-wrap: balance`）、「表 1」の番号ごと題の全体を中心に寄せる
- **図の高さは読む面の高さの 70% まで**（2026-10-18。縦に長い図は 2026-10-25 に箱の中で転がす形へ）:
  `graph`・`mermaid`・`svg`・`image` の高さ（`svg` と `image` は包みの高さ）は `--report-figure-max`（`70cqh`。`.layout-main` の
  `container-type: size` の内寸）を超えない。図は縦横比を保って縮むが、`svg` と `image` は原寸の幅の
  `--report-figure-min-scale`（0.75。いまの図が縮む範囲の外で、主ラベルは約 10.5px）倍より小さくしない。
  縦に長くてなお上限を超える図は、包みの中で縦に転がして読む（上限に収まる図は変わらない。前後の塊の画像と
  `mermaid` は対象外）。全体は押して開く拡大（`ImageZoom`、`size="width"`）でも見る。口は `image` に加えて `graph`・`mermaid`・`svg` にも付ける（図そのものを
  押す。キーは Enter・Space。描き終える前の mermaid は開かない）。拡大の面は図を実寸（`viewBox` の幅と高さ）の
  画像にして出し、縦に流れるときの「閉じる」は下端に貼り付く。`chart` の高さは横棒だけ項目数で決まり（`max(320px, 項目数 × 28px + 48px)`）、ほかは 320px のまま。
- **中間レポートの箱（`.main-step.is-interim`）の中は入れ子を1段にする**（2026-10-18）: 箱の中の
  `card`・`stats`・`compare`・`beforeAfter`・畳み（`details`）は枠の色を透明にして（太さは残し、寸法を変えない）、
  地の段（`surface-raised`。`stats` は `surface` から上げる）と余白で分ける。`options` の行の罫も外す。
  枠の色と `stats` の地は `--report-chunk-rule`・`--report-chunk-ground` で、箱が置き、塊の側が
  `var()` の第2引数に元の値を持つので、最終レポート（箱なし）の塊は枠つきのまま変わらない
- **余白の柱**（2026-10-17）: レポートの本文の右の余白に、本文の流れの外の言葉を置く列。載るのは
  `memo` の `note` と、塊の `aside`（出典・どこを見るかの1行）の2つだけで、字は 12px（`--font-label`）・
  行間 18px・`--ink-quiet`、`memo` には「メモ」のラベルを `--ink-soft` で添える。傍注は直前の塊の
  上端に揃える。**本文の列（42em）の右に 160px 以上空くときだけ余白の柱に出し**、列のあきは 28px、
  余白の柱の左に `--rule-soft` の 1px の線を引く。空かないときは、傍注を塊の直後に 12px の1行ずつで畳む。
  1920 幅でも余白の柱は本文の列のすぐ右に置き、本文ごと左揃えのまま。**余白の柱を持つ塊は、表と図でも
  本文の列（42em）に収まる**。余白の柱は演出（筆）の対象にしない
- **レポートの塊の横並びは、窓幅でなく本文の器（`.detail-block`。コンテナ名 `report-body`）の幅で畳む**
  （2026-10-18）: `dl`・名前付きの `list`・`compare`・`beforeAfter`・`image` の説明の並び・`files` の横並びは、
  器の幅が 2 列の下限（1 列 20em を2つとすき間 0.75rem。`.detail-block` の字は 15px なので約 612px）に
  満たないとき 1 列に積む。やり取りの列を開いて本文が狭くなっても、お伺いの札・質問の記録の preview でも、
  同じ幅で畳む。760px の `@media` は画面全体の組み替え（13.9）にだけ使い、レポートの塊には使わない。
  **`stats`・`cols` の列数は全部か約数か 1 列**にし、3＋1 のような半端な段を作らない（項目数は
  `NotationBlock` が `stats-of-<n>`・`cols-of-<n>` の class にする）。列の最小幅は `stats` が 10rem（折れ線・値・
  分母 `36 / 48` が1行に収まる幅）、`cols` が 14rem で、4つは 4→2→1（本文 676px 以上で4列）、3つは 3→1
  （504px 以上で3列）、`cols` は2つ・3つ・4つのとき同様、それ以外は 1 列
- **キャラビューだけが枠と地を持たない**（原則2）。他の3領域は `surface` の地に `rule` の枠
- **キャラビューのアイテムの席**（2026-10-20 利用者決定。一覧と席の持ち方は `docs/architecture/stage-item.md`）:
  席は舞台（`.character-region`）の中に絶対位置で置き、重なりは背景 → 左上 → 立ち絵 → 左下・右下 → 吹き出しの並びと「ログ」の口。
  どの席も縦横比を保って高さ `24cqh`・幅 `14cqw` まで。**左上**は上端に付けて左端から 16px（吊るす。頭に掛かる分は立ち絵の後ろ）。
  **左下・右下**は下端を床（領域の下端）に付け、立ち絵を anchor で引いて、左下は立ち絵の左端から 8px、右下は右端を
  立ち絵の右端から `--balloon-overlap` 内側（吹き出しの列が始まる線）に揃え、幅は立ち絵の幅の 35% まで。
  吹き出しの列と横に重ならず、足元の高さなので顔に掛からない。飾りなので `alt=""`・押せない（`pointer-events: none`）。
  立ち絵が無いパックでは左下・右下を出さない。760px 以下は出さない（13.9）。セリフのログの床と雑談のメインビューにも置かない。
  実装で足した規則（利用者未承認・蒸し返してよい）: 領域の幅が約 21.5rem 以下で吹き出しの列が立ち絵の下へ回り込む幅では、左下・右下も出さない（列に隠れるため）。
  採らなかった案: 立ち絵を寄せて席を空ける（立ち絵と吹き出しの位置は動かさない）・吹き出しより手前に置く
  （字に絵が被る。13.8）・px の固定の大きさ（仕切りで低くすると立ち絵だけが縮む）・ログと雑談にも出す（要るときに足す）
- 領域の比率は使う人が動かせる（既存の仕組みを変えない）
- **押せるものは 24x24 以上、字は 12px 以上、本文の字は 4.5:1 以上**（2026-10-03。WCAG 2.2 の
  最小の的。的は押す箱で測り、ラベルが的の入力・`<select>` の中のボタン・文中リンクは除く。無効のものと
  飾りの記号はコントラストの対象にしない）。13.2 の「コントラストの下限」は色を受け取る側の検算で、
  こちらは画面が守る側の約束。守っているのは E2E の `readability-scan.ts`（`scanReadability`）
- **既定の比率は上下 65:35・上段の左右 75:25・下段の左右 50:50**（経緯は `docs/history/decision.md`「screen-design.md 13.4
  既定の比率と目次の既定（2026-10-02 に覆した記録）」）。「比率を既定に戻す」の戻り先もこの値
- **依頼のあいだ、4領域の位置と比率は動かさない。** 局面で変わるのはメインビューの中身だけ（13.13）
- **メインビューの札の左に、やり取りの列を置く**（2026-10-01 に目次として決定、2026-10-07 にやり取りと見出しの2段にし、
  2026-10-08 に「やり取り」と名付け直して札の上端から下端まで伸ばした。
  仕様は `docs/architecture/display.md` 4.2。見本は `docs/history/mockup/turn-outline-2026-10-07.html`）。
  既定の幅は札の幅の 22%（10rem〜15rem）で、字はやり取りの行と `##` が `--font-secondary`（`###` は `--font-action`）、
  字下げはレポートの行 1.5rem・`##` 2.5rem・`###` 3.5rem（案A。`docs/architecture/display/main-view.md`）。やり取りの行の頭の印（✓ ? ‖ ✕ … – と、
  見ている行の ●）は固定幅で字を揃え、見ている行は開いた子の行ごと `--surface-raised` の面に載せる。
  列の頭は「やり取り」と畳む口で、その下（やり取りの行の上）に知らせの行を出す（13.13「知らせの行」）。「n / N」は出さない。
  「やり取り」の字の `title` に「前後のやり取りへは [ ] キー」を添える。
  **最新のやり取りの行に「最新」の札は付けない**（2026-10-08 利用者決定。いちばん下の行が最新なのは並びで読めるので、
  一度付けた札を外した）。
  脇の話のあるやり取りの行は、依頼の1行目の下に「脇 n」を `--font-action`・`--ink-quiet` で添える（同じ `<button>` の中の
  2行目で、行もフォーカスの止まり場所も増やさない。13.13「脇の話の欄」）。
  列の右に `rule-quiet` の線を引く。**列と本文の境界をドラッグすると幅を 128〜384px の間で自分で決められ、
  決めた値は既定の代わりに使われる**（2026-10-02 決定。`localStorage` に保存し再読み込み後も保つ）。
  **畳むと列は開き直すボタンだけの固定幅（2.5rem）になり、本文はその幅ぶん広がる**。**札の幅が 48rem を
  下回る領域では、列を既定で畳んでおく**（2026-10-02 決定。1024x768 の既定の比率で、列が 225px を取って
  本文の段落が 382px〔1行が約20字〕に詰まっていた）。**利用者が一度でも開く・畳むを選んだら、札の幅に
  関わらずその選択を使う**（保存は「選んでいない / 畳む / 開く」の3つ）。**列は隠さず常に出す**:
  札の幅が 36rem を下回る領域でも、選んでいなければ畳んだ細い列（開き直すボタンと、知らせがあれば知らせの印）として出し、
  ボタンで開ける（2026-10-08 決定。以前は列ごと隠していた）。**760px 以下の画面では列を本文の左に出さず、やり取りの並びは
  引き出しの「やり取り」のタブに移る**（2026-10-09 決定。13.9「狭い画面（760px 以下）」）。
  **畳んだ列の知らせの印**（2026-10-08）: 開き直すボタンの下に、24px 四方・`--state-warn` の枠と字で「!」だけの口を出し、
  知らせの全文は名前と `title` に持たせる。押すと開いた列の知らせの行と同じく最新のやり取りへ移る（お伺いならお伺いの札まで転がす）。
  **畳んだあいだにやり取りを移る口は `[` `]` のキーと知らせの印**で、開き直すボタンで列の上の段へも戻れる。中くらいの窓幅（下の項）ではメインビューが柱のぶんを
  除いた幅を取るので、1024px では札が約 57rem になり列は既定で開く。既定で畳まれるのは、窓が約 860px より
  狭いときと、仕切りで詰めたとき
- **中くらいの窓幅（761〜1100px）では、上段のサイドバーを柱に畳む**（2026-10-02 決定）。4分割のまま縮むと、
  1024 幅でサイドバーが約 242px になり、「進行中」のバッジ・タスクの ID が割れ、カードが下で切れていた:
  - メインビューの右に幅 3rem の柱を置く。柱には、進行中のタスクの件数のチップと開く口（絵は lucide の
    `PanelRightOpen`、開いているあいだは `PanelRightClose`。名前は「サイドバー」で、`aria-expanded`・
    `aria-controls` を持つ）を置き、その下にモデル・effort・許可モードの絵の口を縦に並べる。雑談モードでは
    件数のチップを出さない（雑談のサイドバーにタスク一覧が無い）。上段の左右の仕切りはこの段では出さない
  - 押すとサイドバーが柱の左に、右端を揃えて重なって開く（幅 20rem・高さは上段いっぱい・`--surface` の地と
    `--rule` の枠と影）。外側を押す・Esc・もう一度押すで閉じ、Esc のときは柱の口へフォーカスを戻す
    （`src/browser/hooks/use-dismiss-signal.ts`。帯の歯車・狭い画面の引き出しと同じ閉じ方）。勝手には開かない
  - サイドバーの下端の帯のモデル・effort・許可モードは、この段では柱が持ち、開いたサイドバーの下端には出さない。
    帯へは戻さない（761px の会話の画面で、帯の口の右端から歯車までの空きが 57px しか無い）。コンテキストの
    目盛りとプラン使用量の円は、開いたサイドバーの下端に残す
  - **サイドバー下端・柱のモデル・effort・許可モードの口は、開くと隣のコンテキスト・使用量の目盛りと
    同じ材質の吊り札になる**（2026-10-02 決定。`appearance: base-select` で描く）: 地
    `--surface`・枠 `--rule`・角 12px、札の頭に小さな見出し（「モデル」「effort」「許可モード」）、
    選ばれている行だけ `--surface-accent` の面と左の `--accent` の細線・右に ✓。**モデルの行**は
    頭文字の丸・名前・1行の用途・重さ（狐火の●の数）で、effort に対応しないモデルの行は
    「effort なし」を添える。**effort の行**は縦に伸びる5本の棒をそのまま押せる段にし、下に段の名前、
    いまの段を縁取る（選べない段は出さない）。**許可モードの行**は盾の塗りで段を見せ、「全部許す」
    だけ `--state-ng` の字と一言の注意を添える。**閉じた口の絵は変えない**（短い名前は添えない。
    幅が足りない）。柱（縦並び）でも同じ札を出し、向きは横へ吊る
  - 下段（キャラビュー・入力欄）と上下の仕切りのドラッグはいまのまま
  - **入力欄の道具の行の「＋ 新規」**: 道具の4アイコン（画像・`/`・`@`・面の切り替え）と右の経過時間・送信⇄中断のあいだに、縦の区切り線（`--rule`）を置き、その右に経過時間、経過時間と送信⇄中断のあいだに `outline-accent` の札を置く（2026-10-14 に経過と札の並びを入れ替えた）。
    道具の列は「書く操作」、この札は「会話そのものの操作」で、押すと確認なしで新しいセッションを始める（`/clear` と同じ）。
    ターンの最中やバックグラウンドタスクが動いている間（`restartRefused`）は押せず、`title` にナビの引き出しの「新しいセッション」・サーバが断るときと同じ理由（`FRAME_ERROR_REASON.sessionSwitchDuringTurn`）を出す。
    窓が 1000px 以下では字「新規」を隠して絵だけにする（761px で字ありだと送信の段が2段に折れた）。760px 以下は札も区切りも出さない（ナビの引き出しに「新しいセッション」がある）
  - **境目は 1100px**（2026-10-02 実測: 1101px の窓でサイドバーは幅 261px になり、バッジ・ID・件数のチップ・
    カードは割れない。1024px では 242px で割れていた）
  - 内幅（2026-10-10 実測。`scripts/capture/capture-view.ts` の `--size 761x900`・`--scene turn-outline`）:
    - 窓 761px・メインビュー（`[data-region="main"]`）: 673px。やり取りの列を畳んだときの本文に使える幅は 633px（列の幅 40px を引く）、開いたときは 513px（列の幅 160px を引く）
    - 狭い窓の配置を決めるときは、この幅の中で固定幅の合計を見積もる
  - 採らなかった案: サイドバーに最小幅を持たせる（800px 台でメインビューが約 430px まで詰まる）。上段を
    メインビュー／サイドバーのタブで切り替える（タブの段がメインビューの高さを約 40px 取る。2026-10-09 までの 760px 以下の形）。3つの操作子を帯へ戻す
    （帯の空きに入らない。経緯は `docs/history/decision.md`「screen-design.md 13.4 中くらいの窓幅の操作子を
    帯へ戻す（2026-10-02 に覆した記録）」）

### 13.5 差せるものの受け渡し

- **パック**: `character.json` に `accent` を1つ足す。無ければ既定値に落ちる
- **パック（背景）**: `character.json` の `background`（素材のファイル名と覆いの不透明度）。
  **効くのはキャラビューだけ**で、無ければ背景画像は出ない（13.8）
- **使う人（アイテム）**: 一覧は全キャラ共通・席はキャラクターごと。キャラクター画面（13.6）から足して席に置き、
  `~/.tsukumo/items/` に持つ（`docs/architecture/stage-item.md`）
- **使う人**: `ground` / `surface` / `ink` の3つ。**キャラクター画面から変え、
  `localStorage` に持つ**（13.6）
- どちらも、届いた値は**境界で検証してから CSS 変数に流す**（外部由来の値の扱いは
  `docs/coding-standards.md`）

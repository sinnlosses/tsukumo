# 画面のデザイン: レイアウトと差せるもの

ステータス: **正典**。入口は `docs/architecture/screen-design.md`（画面のデザインの全体）。

責務: 領域の並び・揃え・図の高さ・欄外注の列・やり取りの列・中くらいのビューポート幅と、パック・使う人が差すものの受け渡し。
読む時: 領域の配置・比率・レポートの部品の並びに触るとき、差せる値の経路を知りたいとき。
直す時: レイアウトの決まりか、差せるものの受け渡しを変えたとき。

## 13. 画面のデザイン

### 13.4 Layout

構想を1文で。**左は居る場所、中央は読んで書く場所、右は見渡す場所。キャラクターだけが枠を持たない。** 配置は ADR 0058（`docs/architecture/adr/0058-three-column-single-stream.md`）の論点 6・7。

```
┌──────────┬────────────────────────────┬────────────┐
│ 立ち絵と席 │ メインビュー                  │ サイドバー   │
│ 枠も地も   │ レポート（幅は領域に任せる）    │ タスク一覧   │
│ 持たない   │ 左揃え・本文書体・行間 26px     │ 使用量      │
│ 背景の上に │                            │ （下端の帯） │
│ 直接立つ   ├────────────────────────────┤            │
│          │ 入力欄（中身の高さ）          │ 上端から下端 │
└──────────┴────────────────────────────┴────────────┘
 背景は画面の上端から全面に敷き（帯の裏まで）、覆いを1枚重ねる
```

761px 以上では、メインビューと入力欄の領域は面を持たず（紙と入力欄の殻が背景に直に乗る）、サイドバーは背景の透ける面（`--panel-glass`・縁・影・`--panel-filter`）、やり取りの列も `--panel-glass`、上部の帯は `--panel-glass-strip`、入力欄の本体は `--panel-glass-dense` で、いずれも `--panel-fill` から濃さを導く透ける面になる。値の置き場は `design-token.md`、字の保証は `background.md`。760px 以下は従来の不透明な面のまま。

3列は1つの grid に並べ、それぞれに `contain: layout style` を掛ける。仕切りは左の列と中央の境界・中央とサイドバーの境界の2本。

- **文字の揃えは全面左揃え。** 日本語の読み物なので、中央揃えも両端揃えも使わない。**レポートの表と図
  （題つきの部品）は、外枠をレポートの本文の列の左端から置く**（中央には置かない。13.3「Type」）。**表の題（「表 1 …」）と凡例は左に揃える。
  図の題（「図 1 …」）だけは、図の下で図の幅の中で中央に置く**。題を持たない表も、表の幅まで縮めて左に置く。内幅いっぱいの部品（見比べ・前後・列が 7 以上の表）と、欄外注の列を持つ部品（本文の列に収まる）は動かない。
  mermaid の箱は文字 12px を守る最小の段で描き、63em と読む面の段は本文の列の左端に揃える（`display/figure-caption.md`）。
  図の題が折り返すときは行の長さを揃えて（`text-wrap: balance`）、「図 1」の番号ごと題の全体を図の幅の中心に寄せる。
  実装の CSS はこの揃えへ部品ごとに合わせていく途中で、外枠を中央に置く規則が残っている部品がある
- **図の高さは読む面の高さの 70% まで**（縦に長い図は箱の中でスクロールする）:
  `graph`・`mermaid`・`svg`・`image` の高さ（`svg` と `image` は外枠の高さ）は `--report-figure-max`（`70cqh`。`.layout-main` の
  `container-type: size` の内寸）を超えない。図は縦横比を保って縮むが、`svg` と `image` は原寸の幅の
  `--report-figure-min-scale`（0.75。いまの図が縮む範囲の外で、主ラベルは約 10.5px）倍より小さくしない。
  縦に長くてなお上限を超える図は、外枠の中で縦にスクロールして読む（上限に収まる図は変わらない。前後の部品の画像と
  `mermaid` は対象外）。全体は押して開く拡大（`ImageZoom`、`size="width"`）でも見る。拡大の操作は `image` に加えて `graph`・`mermaid`・`svg` にも付ける（図そのものを
  押す。キーは Enter・Space。描き終える前の mermaid は開かない）。拡大の面は図を実寸（`viewBox` の幅と高さ）の
  画像にして出し、縦に流れるときの「閉じる」は下端に貼り付く。`chart` の高さは横棒だけ項目数で決まり（`max(320px, 項目数 × 28px + 48px)`）、ほかは 320px のまま。
- **中間レポートの箱（`.main-step.is-interim`）の中は入れ子を1段にする**: 箱の中の
  `card`・`stats`・`compare`・畳み（`details`）は枠の色を透明にして（太さは残し、寸法を変えない）、
  地の段（`surface-raised`。`stats` は `surface` から上げる）と余白で分ける。`options` の行の罫も外す。
  枠の色と `stats` の地は `--report-chunk-rule`・`--report-chunk-ground` で、箱が置き、部品の側が
  `var()` の第2引数に元の値を持つので、最終レポート（箱なし）の部品は枠つきのまま変わらない
- **欄外注の列**: レポートの本文の右の余白に、本文の流れの外の言葉を置く列。載るのは
  `memo` の `note` と、部品の `aside`（出典・どこを見るかの1行）の2つだけで、字は 12px（`--font-label`）・
  行間 18px・`--ink-quiet`、`memo` には「メモ」のラベルを `--ink-soft` で添える。欄外注は直前の部品の
  上端に揃える。**本文の列（63em）の右に 160px 以上空くときだけ欄外注の列に出し**、列のあきは 28px、
  欄外注の列の左に `--rule-soft` の 1px の線を引く。空かないときは、欄外注を部品の直後に 12px の1行ずつで畳む。
  1920 幅でも欄外注の列は本文の列のすぐ右に置き、本文ごと左揃えのまま。**欄外注の列を持つ部品は、表と図でも
  本文の列（63em）に収まる**
- **レポートの部品の横並びは、ビューポート幅でなく本文の器（`.detail-block`。コンテナ名 `report-body`）の幅で畳む**
  : `dl`・名前付きの `list`・`compare`・`image` の説明の並び・`files` の横並びは、
  器の幅が 2 列の下限（1 列 20em を2つとすき間 0.75rem。`.detail-block` の字は 15px なので約 612px）に
  満たないとき 1 列に積む。仕切りで本文が狭くなっても、お伺いのカード・質問の記録の preview でも、
  同じ幅で畳む。760px の `@media` は画面全体の組み替え（13.9）にだけ使い、レポートの部品には使わない。
  **`stats`・`cols` の列数は全部か約数か 1 列**にし、3＋1 のような半端な段を作らない（項目数は
  `NotationBlock` が `stats-of-<n>`・`cols-of-<n>` の class にする）。列の最小幅は `stats` が 10rem（折れ線・値・
  分母 `36 / 48` が1行に収まる幅）、`cols` が 14rem で、4つは 4→2→1（本文 676px 以上で4列）、3つは 3→1
  （504px 以上で3列）、`cols` は2つ・3つ・4つのとき同様、それ以外は 1 列
- **キャラビューだけが枠と地を持たない**（原則2）。他の3領域は `surface` の地に `rule` の枠
- **キャラビューの立ち絵は左の列の下端に立つ**。高さは `clamp(260px, 38dvb, 420px)`（1400x900 で 342px）、幅は列の幅いっぱいの箱に縦横比を保って収め
  （`object-fit: contain`・下端揃え）、顔の位置を決め打ちした切り抜きはしない。足元は 12px だけ列の下端より下へずらす。
- **キャラビューのアイテムの席**（一覧と席の持ち方は `docs/architecture/stage-item.md`）:
  席は左の列（`.character-region`）の中に絶対位置で置き、重なりは背景 → 左上 → 立ち絵 → 左下・右下。
  **左上**は立ち絵の後ろの頭上（下端を立ち絵の上端から 44px 下に置き、高さ 104px・左端から 6px）。
  **左下・右下**は立ち絵の手前の足元（下端から 6px。左下は左端・右下は右端から 2px、幅は 78px・80px で、列が狭いときは列の幅の 38% まで）。
  どの席も縦横比を保つ。飾りなので `alt=""`・押せない（`pointer-events: none`）。
  立ち絵が無いパックでは左下・右下を出さない。760px 以下は出さない（13.9）。セリフのログの床と雑談のメインビューにも置かない。
  採らなかった案: 立ち絵を寄せて席を空ける（立ち絵の位置は動かさない）・ログと雑談にも出す（要るときに足す）
- **2本の仕切りは使う人が動かせる**。左の列の幅は 200〜400px（px で持つ）、サイドバーの幅は器の幅の 15〜40%（`tsukumo-layout-split:v2` に持つ）。
  「比率を既定に戻す」は、動かした仕切りの脇にだけ出て、押すと左の列の幅とサイドバーの幅の両方を既定に戻す
- **押せるものは 24x24 以上、字は 12px 以上、本文の字は 4.5:1 以上**（WCAG 2.2 の
  最小の的。的は押す箱で測り、ラベルが的の入力・`<select>` の中のボタン・文中リンクは除く。無効のものと
  飾りの記号はコントラストの対象にしない）。13.2 の「コントラストの下限」は色を受け取る側の検算で、
  こちらは画面が守る側の約束。守っているのは E2E の `readability-scan.ts`（`scanReadability`）
- **既定は左の列 238px・サイドバー 器の幅の 22.8%（1400x900 で約 319px）**（見本 `docs/history/mockup/conversation-directions-2026-11-15/layouts.html?layout=a2` の実測。
  入力欄の高さは中身で決まり、上下の仕切りは無い）。「比率を既定に戻す」の戻り先もこの値。
  前の版の保存（`tsukumo-layout-split:v1` の3本の比率）は読まず、消さない。左の列の幅の無い保存は、やり取りの列の幅（`tsukumo-outline-panel:v1` の `widthPx`）を 200〜400px に収めて引き継ぐ
- **依頼のあいだ、領域の位置と幅は動かさない。** 局面で変わるのはメインビューの中身だけ（13.13）
- **やり取りの列は、左の列の上（立ち絵の上）に置く**（やり取りと見出しの2段。
  仕様は `docs/architecture/display.md` 4.2。変遷は `docs/history/decision.md`「screen-design.md 13.x 画面設計の本文から日付を消した経緯6件」。見本は上の `layouts.html?layout=a2` の `.turn-lane`）。
  幅は左の列の幅に従い、高さは「左の列の高さ − 上下の余白 − 立ち絵の高さ（`--stage-portrait-height`）− 左上の席の分（64px）」で止める。
  超えた分は列の中の一覧だけが縦に転がり、開いたときと、見ているやり取りが替わったとき・やり取りが増えたときは、見ているやり取りの行が見える位置へ送る。
  一覧の上下の端は、その向きに送れるときだけ 1.5rem ぼかす（スクロールに連動する CSS で、送れない向きはぼかさない）。
  列の枠・角丸・地は `surface-edge-rule`・`surface-radius-lg`・`surface-tone-surface`。
  字はやり取りの行と `##` が `--font-secondary`（`###` は `--font-action`）、
  字下げはレポートの行 1.5rem・`##` 2.5rem・`###` 3.5rem（案A。`docs/architecture/display/main-view.md`）。やり取りの行の頭の印（✓ ? ‖ ✕ … – と、
  見ている行の ●）は固定幅で字を揃え、見ている行は開いた子の行ごと `--surface-raised` の面に載せる。
  列の頭は「やり取り」と `[` `]` の印と畳むボタンで、知らせは出さない（知らせは会話の流れの下端の口に出る。13.13「知らせの行」）。「n / N」は出さない。
  「やり取り」の字の `title` に「前後のやり取りへは [ ] キー」を添える。
  **最新のやり取りの行に「最新」のバッジは付けない**（いちばん下の行が最新なのは並びで読めるので付けない）。
  補足メッセージのあるやり取りの行は、依頼の1行目の下に「脇 n」を `--font-action`・`--ink-quiet` で添える（同じ `<button>` の中の
  2行目で、行もフォーカスの止まり場所も増やさない。13.13「補足メッセージの欄」）。
  **列の幅は動かせない**（列と本文の境界の仕切りは外した。幅を決める仕切りは左の列とサイドバーの2本だけ）。
  **畳むと列は頭の行だけの帯（見出しの帯）になる**。帯は左の列の幅いっぱいで、一覧だけが畳まれ、頭の行の上端と口の位置は開いたときと同じ。
  口の絵は開いているとき上向き・畳んでいるとき下向きの山形で、件数（等幅の `--font-label`。読み上げは「n件」）は畳んだときだけ題のあとに出す
  （列の中身の幅が 182px 以下のときは件数を出さない。題・件数・キーの印・口が1行に収まらず、口が開いたときの位置からずれるため。見本は `docs/history/mockup/` の left-pane の見本の `index.html?design=now&moment=many&folded=1&form=bar`）。畳むのは利用者が畳むを選んだときだけで、選んでいなければ開いている
  （本文の幅では畳まない。列は本文の幅を取らないため。保存は「選んでいない / 畳む / 開く」の3つ）。
  hello のあと、やり取りが1件も無いあいだ（始め方の一覧）も、題と件数 0 だけの同じ帯を出す（キーの印と口は無く、畳む／開くの保存に関わらず同じ。
  hello 待ち・雑談・狭い画面では出さない。見本は `docs/history/mockup/` の left-pane の見本の `index.html?design=now&moment=first&empty=bar`）。
  口の無い帯でも畳んだ帯と同じ高さになるよう、頭の行の高さに口の高さを下限として持たせる。
  **畳んだあいだにやり取りを移る操作は `[` `]` のキー**で、畳んでも効く（帯にもキーの印を残す）。
  **760px 以下の画面では左の列ごと出さず、やり取りの並びは引き出しの「やり取り」のタブに移る**（13.9「狭い画面（760px 以下）」。タブの中身は変えない）。
  760px 以下の知らせの行は、今まで通り本文の上端に出す
- **広い画面では、会話の流れ・入力欄・進行の帯に読む幅の上限を置く**（ADR 0062 論点 13）。帯と入力欄は縁を含めて 976px、流れはその組の中で左右に余白を取るので内容は 928px（ADR 0072）。
  上限を置いた組（帯・流れ・お伺い・声の定位置・始め方の一覧・雑談のログ・入力欄）は、縁を含めて 976px の組として中央の列の中で左右の中央に置き、左右の端をそろえる（ADR 0072）。
  流れは帯の下から始め、帯の上下の外には地の色の覆いを敷くので、送っても行が帯の裏で欠けない。
  1400×900 の中央の列は 960px に届かず、上限は効かない。761〜1100px の柱の形と 760px 以下は変わらない
- **中くらいのビューポート幅（761〜1100px）では、サイドバーを柱に畳む**。3列のまま縮むと、
  1024 幅でサイドバーが約 242px になり、「進行中」のバッジ・タスクの ID が割れ、カードが下で切れる:
  - メインビューの右に幅 3rem の柱を置く。柱には、進行中のタスクの件数のチップと開くボタン（絵は lucide の
    `PanelRightOpen`、開いているあいだは `PanelRightClose`。名前は「サイドバー」で、`aria-expanded`・
    `aria-controls` を持つ）を置く（モデル・effort・許可モードの札は入力欄にあるので柱には置かない）。雑談モードでは
    件数のチップを出さない（雑談のサイドバーにタスク一覧が無い）。サイドバーの仕切りはこの段では出さない
  - 押すとサイドバーが柱の左に、右端を揃えて重なって開く（幅 20rem・高さは器いっぱい・`--surface` の地と
    `--rule` の枠と影）。外側を押す・Esc・もう一度押すで閉じ、Esc のときは柱のボタンへフォーカスを戻す
    （`src/browser/hooks/use-dismiss-signal.ts`。帯の歯車・狭い画面の引き出しと同じ閉じ方）。勝手には開かない
  - モデル・effort・許可モードは入力欄の下の行の札が持ち、サイドバーの下端にも柱にも出さない。コンテキストの
    コンテキスト・5時間・7日の使用量の3つは、開いたサイドバーの下端に残す
  - **入力欄の下の行・狭い画面の引き出しのモデル・effort・許可モードのボタンは、開くと隣のコンテキスト・使用量の目盛りと
    同じ材質の吊り下げのカードになる**（`appearance: base-select` で描く）: 地
    `--surface`・枠 `--rule`・角 12px、カードの頭に小さな見出し（「モデル」「effort」「許可モード」）、
    選ばれている行だけ `--surface-accent` の面と左の `--accent` の細線・右に ✓。**モデルの行**は
    頭文字の丸・名前・1行の用途・重さ（狐火の●の数）で、effort に対応しないモデルの行は
    「effort なし」を添える。**effort の行**は縦に伸びる5本の棒をそのまま押せる段にし、下に段の名前、
    いまの段を縁取る（選べない段は出さない）。**許可モードの行**は盾の塗りで段を見せ、「全部許す」
    だけ `--state-ng` の字と一言の注意を添える。**閉じたときのボタンの絵は変えない**（短い名前は添えない。
    幅が足りない）。入力欄の札は閉じたときに名前と開く印を添え、カードは札の上へ開く
  - 左の列（立ち絵と席）と中央の列（メインビューと入力欄）は残し、左の列の仕切りもそのまま出す。サイドバーの仕切りだけを出さない
  - **入力欄の下の行の「＋ 新規」**: 下の行の左に道具の4アイコン（画像・`/`・`@`・面の切り替え）と、縦線1本を挟んでモデル・effort・許可モードの札、右に経過時間と `outline-accent` のボタンと円形の送信⇄中断を並べる（区切り線は無い）。
    道具の列は「書く操作」、このボタンは「会話そのものの操作」で、押すと確認なしで新しいセッションを始める（`/clear` と同じ）。
    ターンの最中やバックグラウンドタスクが動いている間（`restartRefused`）は押せず、`title` にナビの引き出しの「新しいセッション」・サーバが断るときと同じ理由（`FRAME_ERROR_REASON.sessionSwitchDuringTurn`）を出す。
    ビューポートが 1000px 以下では字「新規」を隠して絵だけにする（761px で字ありだと送信の段が2段に折れた）。760px 以下はボタンも区切りも出さない（ナビの引き出しに「新しいセッション」がある）
  - **境目は 1100px**（実測: 1101px のビューポートでサイドバーは幅 261px になり、バッジ・ID・件数のチップ・
    カードは割れない。1024px では 242px で割れていた）
  - 内幅（実測。`scripts/capture/capture-view.ts` の `--size 761x900`・`--scene turn-outline`）:
    - ビューポート 761px・メインビュー（`[data-region="main"]`）: 409px（左の列 238px が既定のとき。左の列は 761〜1100px でも残す）。入力欄は同じ幅
    - 狭いビューポートの配置を決めるときは、この幅の中で固定幅の合計を見積もる
  - 採らなかった案: サイドバーに最小幅を持たせる（800px 台でメインビューが約 430px まで詰まる）。上段を
    メインビュー／サイドバーのタブで切り替える（タブの段がメインビューの高さを約 40px 取る）。3つの操作子を帯へ戻す
    （帯の空きに入らない。経緯は `docs/history/decision.md`「screen-design.md 13.4 中くらいの窓幅の操作子を
    帯へ戻す（2026-10-02 に覆した記録）」）

### 13.5 差せるものの受け渡し

- **パック**: `character.json` に `accent` を1つ足す。無ければ既定値に落ちる
- **パック（背景）**: `character.json` の `background`（素材のファイル名と覆いの不透明度）。
  **効くのはキャラビューだけ**で、無ければ背景画像は出ない（13.8）
- **使う人（アイテム）**: 一覧は全キャラ共通・席はキャラクターごと。キャラクター画面（13.6）から足して席に置き、
  `~/.tsukumo/items/` に持つ（`docs/architecture/stage-item.md`）
- **使う人**: `ground` / `surface` / `ink` の3つ。**キャラクター画面から変え、
  `localStorage` に持つ**（13.6）
- どちらも、届いた値は**境界で検証してから CSS 変数に流す**（外部由来の値の扱いは
  `docs/coding-standards.md`）

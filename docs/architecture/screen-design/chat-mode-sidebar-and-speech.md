## 13. 画面のデザイン

### 13.7 雑談モードの画面

#### 雑談のときのサイドバー

**雑談中はタスク一覧を出さず、上から4段に差し替える**（2026-09-23 決定。ユーザーが示したモック
`docs/history/mockup/chat-sidebar-2026-09-23.png`。辛口レビューの指摘「雑談していても画面の一部が
仕事の話を続けている」）。仕事へ戻すと元の形（タスクの区画＋下端の帯）に戻る。

```
┌────────────────────────────────┐
│ ◯ 名前                           │ 1. プロフィールの札（伸び縮みしない）
│   自己紹介文                      │
├────────────────────────────────┤
│ 最近の話題                       │ 2. ┐ まとめて1つの入れ物に入り、
│ 覚えていること            （編集） │ 3. ┘ 残りの高さを取ってその中で転がる
├────────────────────────────────┤
│ コンテキスト 28%  284k / 1.00M › │ 4. 下端の帯（使用量の札。伸び縮みしない）
└────────────────────────────────┘
```

1. **プロフィールの札**（`components/domain/sidebar/components/profile-card.tsx`）: 顔（13.9「顔」と同じ素材・丸・
   差し色の輪で、大きさだけ 64px）・名前（パックの `name`）・**自己紹介文**
   （`character.json` の新しい欄 `tagline`。検証は `src/shared/character-pack/character-definition.ts`。
   **無いパックは名前だけ**で、空の行を置かない。キャラクターの切り替えは札に置かず、帯の顔から開く選び口が持つ）。領域の左右と上の縁まで
   広げ、地は `surface` を `accent` で**5%だけ**染める（名前という文字のラベルがある塊なので
   13.2「意味を持つ塊の地」の範囲。選ばれたものの地の `surface-accent` とは分ける）。下の罫線は
   `rule` のまま（差し色の仕切り線はレポートの3本に絞ってある。13.2）。**名前とひとことは読む面の
   文字**なので `ink` / `ink-quiet`（13.1 原則1）
2. **最近の話題** / 3. **覚えていること**: 区画の枠（`SidebarSection`）で見出しを出す。
   **最近の話題はあらすじの末尾から取り出した見出し**（`state.chatTopics`。出どころと取り出し方は
   `docs/architecture/chat-mode.md` 4.9「記憶の圧縮と忘却」）を**新しい順に3件まで**、届いた順のまま並べる
   （各行の上に `rule` の細い線。印は付けない。線は区画の幅いっぱいで、文字は左右に 0.75rem ずつ内側へ寄せ、
   覚えていることと揃える）。**更新されるのは定着のときだけ**で、それまでは
   前回の話題のまま。**空のとき**（一度も定着していない・見出しを取り出せなかった）は
   「まだ話題が無い（話が積もると、ここに並ぶ）」を出す。**覚えていることは `persona.md` の
   `## 覚えたこと`**（`state.rememberedLines`。出どころと消し方は `docs/architecture/chat-mode.md` 4.9「プロフィールの書き戻し」）を
   **1行＝チップ1つ**で並べる（各行の上に `rule` の細い線。線は区画の幅いっぱいで、文字は左右に 0.75rem ずつ内側へ寄せる）。
   チップは字数ではなく幅で切り（1行に入りきらない分を `…` にする）、押すとその場で全文に折り返して開く。空のときは「まだ覚えていることが無い」を出す。**「編集」は
   消せる行があるときだけ置く**（空のときに押せても何もできない）——押すと各チップに × が付き、
   × を押すと消す前の確認を挟んで `chat.forgetRememberedLine` を送る（確認で OK を押したらサーバの返事を待たずに閉じる）
3. **下端の帯**: 仕事のときと同じ、モデル・effort・許可モードの口とコンテキスト・プラン使用量の目盛り（13.9「会話の画面の帯とサイドバーの下端の帯」）

**誰が組むか: `<Sidebar>` が `chatMode` を見て自分で差し替える**（`<Root>` から別の部品を渡さない）。
下端の帯は両方のモードで同じ部品で、差し替わるのはその上だけ——`<Root>` が2つのサイドバーを
渡す形にすると、帯を2つの組み立てで重ねて持つことになる。`docs/architecture.md`「区画ひとまとまりは領域の側に
置く」と同じ理由でもある。`<Root>` がメインビューを差し替えるのは `<MainView>` と `<ChatView>` が
**別の領域の機能**だからで、サイドバーは1つの領域の中で段の並びが変わるだけ。`<Layout>` に渡す
旗も増えない。

**どの機能に置くか: `components/domain/sidebar/components/` の中**（`profile-card.tsx` / `recent-topic-section.tsx` /
`persona-memory-section.tsx`）。雑談の側（`components/page/conversation/components/chat-view/`）に置くと、下端の帯を読むために
領域の機能どうしの import が要る（`docs/architecture.md`「全体構成」）。中身を入れたあと、話題や覚えたことがタスクの
`task-board` のようにサイドバーの外でも使う語彙になったら、そのとき「置かれる機能」に切り出す。

**狭い画面（760px 以下）では、この4段が引き出しの「話題」のタブに入り、配分は変えない**（13.9「狭い画面（760px 以下）」）。
札と帯は伸び縮みせず、2段目と3段目をまとめた入れ物だけが残りの高さを取り、入りきらないぶんはその中で転がる。

**採らなかった案**:

- **`<Root>` が `chatMode ? <ChatSidebar /> : <Sidebar />` を渡す。** 下端の帯が2つの組み立てに
  またがる
- **雑談のサイドバーを `components/page/conversation/components/chat-view/` に置く。** 1つの機能が2つの領域を持ち、`chat-view`
  から `sidebar` の帯を読む機能どうしの import が要る
- **札の右端に「変える ⌄」を置く。** 切り替えは帯の顔から開く選び口で足り、ひとこと紹介文の幅を
  圧迫するので置かない（2026-10-14 ユーザー決定。それまでは本物の `<select>` を透明にして重ねていた）
- **2段目と3段目をそれぞれの区画で転がす**（仕事のときのタスクの区画と同じ形）。どちらも短い
  一覧で、区画ごとに転がすと小さな窓が2つ並ぶ
- **見本の色と書体をそのまま写す**（橙の地・淡い橙の字・橙寄りの枠・明朝）。16進を `theme.css`
  の外に書かない・読む面は差し色を受け取らない（13.1 原則1）・書体は2本（13.3）の決定と当たる。
  見本の橙は雑談中の `--accent`（パックの `chatAccent`）にあたるので、札の地の染めと顔の輪・
  `:hover` の縁・フォーカスの輪に写し、字と枠は `ink` / `ink-quiet` / `rule` に写した

#### セリフは全文で現れ、吹き出しは2秒空ける

**届いたセリフは、ログの末尾に全文でそのまま出て、現れる瞬間だけ短く弾む**（2026-09-23
決定。同日のうちに「1文字ずつ育てる」形からここへ変えた——育てる形は「キャラクターと一緒に
居る感じ」を足す狙いで入れたが、**吹き出しどうしが間を置かず続けて現れるとびっくりする**
という指摘を受け、**「ポンと現れる・吹き出しどうしは最低2秒空ける」**に差し替えた）。

- **サーバの契約は変えない**（`SessionEvent` も `SessionState` もそのまま）。セリフは `speech`
  で1件まるごと届く（`speak` の戻りが `"ok"` になる時点で全文がある）ので、**出すタイミングを
  ブラウザ側で持たせるだけ**で足りる（`components/page/conversation/components/chat-view/hooks/use-speech-reveal.ts`）
- **現れる瞬間、0.2秒ほど小さく拡大して落ち着く**（`chat-speech.module.css` の
  `.chat-entry-pop`。CSS のアニメーションなので、`prefers-reduced-motion` は
  `styles/theme.css` の全体規則がそのまま止める——`.chat-typing-dot` と同じ扱いで、ここに
  個別の対応は要らない）
- **キャラクターの吹き出しどうしは、前の吹き出しを出してから最低2秒空けて次を出す。**
  すでに2秒以上空いていれば待たずに出す。**待たせるのは吹き出しどうしの間だけ**——利用者の
  発言・日の区切り・圧縮の区切りは、順番が回ってくれば待たせずそのまま出す。ただし実装は
  「`entries` の先頭から出せるところまで」という前置きを絞る形なので、**待っている吹き出しの
  手前に積まれた行は一緒に足止めされる**。雑談は返事を待っている間、入力欄が塞がる
  （`turnInProgress`）ので、待っている吹き出しの手前に利用者の発言が割り込むことは無い——
  そのため実際に足止めされるのは、1ターンに `speak` を複数回呼んだときのキャラクターの
  吹き出しどうしだけになる
- **画面を開いた時点で並んでいた記録は待たせず全部出す**（マウント時点の件数が起点。前の
  雑談の続きが、開くたびに端から出し直されることにならないように）。**弾む動きも同じ境目**
  ——マウントより後に現れた行だけが弾み、開いた時点の記録は弾まない。**姿が丸ごと入れ替わったとき
  （`hello`。キャラクター・セッションの切り替えで起こし直し、前の記録を組み直したときなど）も
  開き直しとみなし**、雑談ビューを作り直してその時点の記録を全部出す
- **待たせている間、末尾に「...」を出す**（次の節「返事を待つ間の「...」」）。**立ち絵の表情は
  届いたセリフではなく、すでに出した吹き出しのものにする**——待っている間に表情だけ先に
  進むと、まだ出ていない吹き出しの中身が表情から漏れる。ただし新しいターンの始まり
  （まだ何も話していない）は、待っている吹き出しがあっても構わず既定の表情へ戻す
  （キャラビューと同じ扱い）
- **キャラビューの `<Balloon>` は再利用せず、`components/` へも上げない。** 雑談の行はすでに
  吹き出しの見た目を持っており（`chat-view.module.css` の `.chat-entry`）、`<Balloon>` のほうは
  `.balloon-track` の並び（`column-reverse`・押し上げ・薄める）と一体になっている。上げると
  **両方の事情を知る部品**になり、どちらを直しても相手が動く。`components/page/conversation/components/chat-view/` に閉じた
  ままなので、機能どうしの import も増えない（`test/architecture/browser-box.test.ts`）

**採らなかった案**:

- **1文字ずつ育てる**（2026-09-23 に採用したが同日中に差し替えた元の案）。吹き出しの中身の
  ぶんだけ育つので「いま話している」時間は生まれるが、**1ターンに `speak` を複数回呼ぶと
  吹き出しが間を置かず次々に現れ、びっくりする**という指摘のほうを優先した
- **サーバから書きかけを流す**（`speech` を刻んで押す・雑談でも `partialUtterance` を使う）。
  **`speak` は1件まるごと届く**ので、刻むのはサーバ側の作り事になり、`SessionEvent` と
  `SessionState` が1つずつ増える。**同じ絵がブラウザ側だけで出せる以上、契約を増やす理由が無い**
  （13.1 原則2 の「枠を増やさない」と同じ判断を、共有層に当てたもの）

#### 時刻と日の区切り

**発言ごとに時刻（`HH:MM`）を添え、日が変わるところに日付の区切りを1本入れる**（2026-09-23 決定。
LINE / Discord と同じ形で、日の区切りだけの案・ホバーしたときだけ出す案は採っていない）。
雑談は日をまたいで戻ってくる場所なのに、昨日の一言と三十秒前の一言が見分けられなかったのを埋める。
記録の側の形は `docs/architecture.md`「記録の時刻」。

- **時刻は吹き出しの外、下端の内側**（キャラクターの行は右脇、利用者の行は左脇）。**吹き出しの
  中には入れない** — セリフをドラッグで選んでコピーしたときに時刻が混ざらない。DOM の順は
  話者によらず「発言 → 時刻」で、左右は並べる向きだけで返す
- **秒は出さない**（`HH:MM`）。会話の時刻としては分で足り、秒まで出すと行ごとに数字が動いて
  読む面が騒がしくなる
- **時刻と日付は `ink-quiet`**（13.1 原則1）、**時刻は等幅**（13.1 原則3。機械が付けた値）。
  背景（13.8）の上に字が直に乗らないよう、どちらも `ground` 一色の地を1枚敷く（`.chat-empty` と同じ）
- **区切りは日付の字だけ**（`9月23日（水）`。線は引かない）。圧縮の区切り（破線1本・文言なし）と
  **字の有無で見分ける**。年は出さない（ログが持つのは 100 ターンぶんで、年をまたいでも並びの順で
  読める）。「今日」「昨日」とも書かない —— 呼び名は時計に依るので、日付が変わったあとに描き直す
  まで古い呼び名が残る
- **区切りは日が変わった発言の手前にだけ入り、ログの先頭には入れない**。日を比べる相手は1つ前の
  発言で、圧縮の区切りは飛ばす。日の境目は画面を見ている人のタイムゾーン
  （`utils/clock.ts` の `localTimeZoneId`）で決め、並びを組むのは `shared/chat/chat-log.ts` の
  `chatLogRows`（タイムゾーンは引数で受け取る）
- **前のセッションを組み直した発言（時刻が分からない）には時刻を出さない**。そこから
  いまの発言へ移るところに、いまの発言の日付の区切りを入れる。**「時刻の無い行 = 前のセッション
  から引き継いだ行」**として読め、起こし直した直後のログが全部「今日」に見えることはない。
  雑談⇄仕事の切り替えは起こし直しなので、切り替えるたびに、それまでの行は時刻の無い側へ移る
  （受け入れた判断。本当の時刻を運べない理由は `docs/architecture.md`「記録の時刻」）

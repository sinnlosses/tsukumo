## 部屋の頭

**ほかの画面とセッションへの入口は、サイドバーと探す（⌘K）の2つにまとめる。** 部屋の頭は舞台の左上の群と、サイドバーの頭に分かれる。どの姿勢も同じ形で、舞台の器の右上には何も置かない。

```
 ┌ 舞台 ─────────────────┬ 紙 ─────────────────────┬ サイドバー ────────────────┐
 │ [仕事｜雑談]           │                          │ tsukumo ⌄                  │ ← 部屋の名前
 │ ● 作業中               │                          │ [⌕ 検索 ⌘K]                │ ← 検索の入口
 │ └─ 左の群              │                          │ この部屋のやり取り          │
 │                       │                          │ [▥ 文脈 28%] [✦ 成果]       │ ← 入口の行
 │                       │                          │ [☺ キャラ] [⚙ 設定]        │
```

| 群               | 部品                                                                                                                    | 置き場                                                                                           | 並び                                                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| 左の群           | `RoomHead`（見た目は `PresentationalRoomHead`）                                                                         | 舞台のいちばん上の段（`data-slot="room-head"`）。背景の上に直に字を置く                          | 仕事と雑談の門・状態の行を縦に積む                                                                                            |
| サイドバーの入口 | `RoomSidebarSearch`・`RoomSidebarGates`（見た目は `PresentationalRoomSidebarSearch`・`PresentationalRoomSidebarGates`） | どの姿勢でもサイドバーの上端（部屋の名前と検索）と下端（入口の行）。`data-region="sidebar"` の中 | 部屋の名前（押すとセッションの一覧）と検索の入口（押すと探すが開く）、入口の行（「文脈 n%」・紙の入口を `<a href>` で並べる） |

- **各部品の算出は `useRoomHead` の1回だけ**にし、`RoomHeadScope` が全部を包んで同じ値を配る（`src/browser/components/frame/screen-nav/room-head.tsx`）。置き場が離れていても、探すの開閉やセッションの一覧の開閉を2つに分けない。`RoomHeadScope` の外で `RoomHead` を描くと例外にする
- 左の群は背景の上に字を置くので、字に影（`text-shadow`）を敷いて読めるようにする。幅は 336px まで
- 部屋の名前のボタンはサイドバーの頭（検索の入口の上）に置き、長い名前は省略する。押すと今と同じセッションの一覧が開く
- 重ねる紙を開いているあいだも、舞台と部屋の頭は操作できるまま残す（ADR 0057 論点 3）。サイドバーの入口の行で紙を直に切り替えられる

### 状態の行

左の群のいちばん下に、7px の点と状態の語を1行で出す。語は `conversationMoment` から引き、雑談中は局面を問わず「雑談している」にする。

| 局面（`RoomStateTone`） | 語               | 点の色         |
| ----------------------- | ---------------- | -------------- |
| `greet`                 | 依頼を待っている | `--ink-quiet`  |
| `work`                  | 作業中           | `--accent`     |
| `ask`                   | 答えを待っている | `--state-warn` |
| `deliver`               | 終わった         | `--state-ok`   |
| `stumble`               | 止まった         | `--state-ng`   |
| `chat`                  | 雑談している     | `--accent`     |

点は動かさない。色だけで伝えないよう、語を必ず添える。

## 部屋の名前

**ビューのポート1つ＝部屋1つ**で、和の色名12個をポートの並び順に割り当てる（
`src/browser/components/frame/screen-nav/domain/room.ts`）。7327 から順に
空色 / 若葉 / 菜の花 / 夕焼け / 藍 / 藤 / 朱 / 灰 / 若草 / 海 / 桜 / 墨 で、表示は「〜の間」
（語彙は読みにくい名前を避けている）。

- **語彙はコードに置く**（キャラクターパックの定義ファイル側ではない）。**部屋はキャラクターの
  持ち物ではなく、起こした tsukumo の場所**——同じ部屋でキャラクターを入れ替えても部屋は
  変わらないので、`docs/architecture/code-placement.md` 原則4（キャラクターの中身をコードに書かない）の対象外
- **語彙の外のポートはポート番号をそのまま名乗る**（13個め以降・`TSUKUMO_VIEW_PORT` で遠い番号を
  指したとき・OS まかせの `0`）。名前が無いことより、どの番号の部屋かが分かるほうが役に立つ
- **印（セッションの目印）はポート番号のまま**（`docs/requirements/session-restore.md`「鍵（切り替え先の一覧に何を出すか）」）。名前は
  画面のためだけのものなので、語彙を入れ替えても過去のセッションは迷子にならない。環境変数で
  名前を指定する設定も作らない
- **自分がどの部屋かの正典は、ページを配っている URL のポート**（ブラウザは `location.port` を
  読む）。サーバから送り直してもらう値ではないので `SessionState` には乗せない
- **サイドバーの頭の主の字は作業ディレクトリの名前**（`basename(cwd)`。手続き `repository.projectName`）。名前が届く前・取れないときは部屋の名前を出す。字の右に小さな「⌄」を添え、押すとセッションの一覧が開く（`aria-haspopup="dialog"`・`aria-expanded`）

## セッションの切り替え

**部屋の名前を押すと、部屋の頭のすぐ下にセッションの一覧が小さく開く**（`RoomSessionMenu`。`<Dialog>` の `backdrop="clear"`）。

- 並びは上から「この部屋（<部屋の頭の主の字>）」の群・「＋ 新しく始める」・「ほかの部屋」の群。この部屋の群はいまの作業ツリーのセッション、ほかの部屋の群はほかの作業ツリーのセッションで、ほかの部屋の群は行があるときだけ出す。この部屋に行が無いときは「切り替えられるセッションはまだ無い」と出す
- 行は見出し（SDK の `summary`。無ければ「（題なし）」）と、その下の小さな一言。一言は、いま開いている行が「いま開いている」、ほかは時刻（ほかの部屋の行は「<作業ツリーの名前>・<時刻>」）で、別のウィンドウで使っている行は末尾に「・別のウィンドウで使用中」を足す
- **一覧に並ぶのは、リポジトリの全作業ツリーの同じキャラクターパック・同じモードのセッション**（ポートの目印では絞らない）。作業ツリーを問わず新しい順に並べて10件（`MAX_SESSION_CHOICES`）で切り、作業ツリーの名前は `cwd` の末尾のディレクトリ名（取れなければ `gitBranch`。どちらも無いセッションは載せない）。別の作業ツリーの行を選んでも、いまの作業ツリーで続きから起こす
- **別のウィンドウで使用中の行**（`docs/requirements/session-restore-condition.md`「別のウィンドウで使用中のセッション」）は隠さず、押せなくする。使用中かは開くたびに聞く
- **ターン進行中か、委譲先が動いている間は、いま開いている行のほかと「＋ 新しく始める」を押せない**（起こし直しなので）。理由は `title` に `FRAME_ERROR_REASON.sessionSwitchDuringTurn` を出す
- ↑↓ で押せる行のあいだを移り（端で止まる）、Enter で切り替え、Esc と外側の押下で閉じる
- 見出しは `127.0.0.1` のページに出すだけで、ログ・ファイル・外部へは出さない（`docs/coding-standards/conversation-content.md`「会話内容の扱い」）
- 探すの「移る」の群の「セッションを切り替える」からも同じ一覧が開く

## 仕事と雑談の門

**左の群の先頭に、「仕事｜雑談」の2つ切り替え（`ui/` の `Segmented`）を置く。** 送るコマンドは `session.setChatMode` で、違うモードを選ぶと起こし直す。

- **表示はサーバから届いた `chatMode` だけに従う**（押した側へ先に倒さない。断られたときに戻す処理を持たずに済み、次に届く `chat-mode-changed` がそのまま正になる）
- 確かめの一言は挟まない。切り替えのたびに画面が初期化されるのは受け入れ済みで、起こすのは新規のセッション、前のセッションへはセッションの一覧から戻る（`docs/architecture/chat-mode.md` 4.9）
- **ターン進行中か、委譲先が動いている間は送らない**（サーバも同じ条件で断る）。理由の文面は `FRAME_ERROR_REASON.chatModeSwitchDuringTurn` で、切り替えの `title` に出す
- 探すの「移る」の群にも「雑談に切り替える」（雑談中は「仕事に戻る」）の1行を置く

## 「文脈 n%」の札と紙の入口

サイドバーの入口の行が、「文脈 n%」・紙の入口を `<a href>` で並べる（どの姿勢でも同じ）。検索の入口が探すを開く。

- **「文脈 n%」の札は使用量の紙（`#token-usage`）への `<a href>`**。割合は使用量の紙の「いまのコンテキスト」のカードと同じ値（`browser/domain/context-usage.ts`）で、札の下端に割合ぶん塗る細い目盛りを敷く。届くまでは「文脈 —」で、取りに行っているあいだは `aria-busy`。取り直すのはターンが終わるたび（`state.finishedTurnCount` を `queryKey` に含める）
- **紙の入口はタスク・成果・キャラ・設定の4つの `<a href>`**（`#tasks`・`#achievement`・`#character`・`#settings`）。タスクの札は着手できる件数を「タスク 3」の形で添え、Beads の無いリポジトリでは出さない。開いている紙の札に `aria-current="page"` を立てる
- 紙の開閉の正典は `location.hash` のまま（ADR 0057 論点 3）。読み直しても同じ紙が開き、ブラウザの「戻る」で閉じる
- 見本帳（`#design`）は紙にせず全面で出し、部屋の頭にも探すにも出さない。見本帳の頭に会話の画面へ戻るリンクを置く

### 使用量の紙のプラン使用量のカード

**使用量の紙の、コンテキストのカードの下に、5時間枠と7日間枠の使用状況を1枚のカードで出す**（`components/page/token-usage/components/plan-usage-row/`。出どころと採らなかった案は `docs/research/plan-usage.md`）。見た目の出どころは見本「サイドバーの「プラン使用量」の札 — 5つの状態と寸法」（`QUOTA-Sidebar.dc.html`）。

- **高い（80%以上）は割合と棒を `--state-warn`** にし、割合を太字にして▲を前に付ける。**警告の色は棒・割合にしか付けない**（カード全体を警告色で染めない）
- **ふるまい**: ↻ はアイコンだけ（`aria-label` と `title` は「プラン使用量を取り直す」/「取り直す」）。
  **取得中は押せない**。前の値があれば薄く残し（不透明度0.45）、無ければ「—」と幅0の棒。
  **取れないときは2・3段目をまとめて一言にし、高さは変えない**。サーバが「該当しない」
  （`not-applicable`）を返した間は、2・5・10・20秒の間隔で取り直し（合計37秒。起動直後は claude が
  契約の種類をまだ持たず、同じ応答が返るため）、その間の合間もカードは「取得中…」のまま、↻ は押せない。
  値が出れば止め、20秒の回でも「該当しない」なら取れなかったときの一言（↻ で取り直せる）にする。
  API キーで使っていても同じ一言が出る。↻ は押すたびに1回だけ取り直し、列は始めない。
  **戻る時刻を過ぎた値も、取り直すまではそのまま出す**（取った時刻を添えて古さを読めるようにする）
- **取り直す契機は開いたとき・ターンが終わるたび・↻を押したとき・「該当しない」が返った間の取り直しの列**（時計では回さない）。出どころは SDK の
  `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET`——`docs/glossary/session-and-plan.md`「プラン使用量」

## 探す（⌘K）

**サイドバーの検索の入口か ⌘K（Windows などでは Ctrl+K）で、画面の上の方に浮かぶ1枚の一覧を開く**（`SearchPalette`。`<Dialog>` の `backdrop="dim"`）。⌘K はどこにフォーカスがあっても開閉する。開閉は URL に載せない（`location-hash.ts` の「新しく作るダイアログは URL を持たない」）。

- 上に探す欄（「画面・タスク・コマンドを探す」）、下に群ごとの一覧。↑↓ と Enter で選び、Esc と覆いの押下で閉じる。当てはまる項目が無ければ「当てはまるものが無い」
- **絞り方**: 空白で区切った語がどれも、項目の名前か添える語に含まれる項目を残す（大文字と小文字は区別しない。`domain/search-entry.ts` の `matchingSearchEntries`）。並びは群の順にそろえ、群の中は出どころの順のまま
- **群と出どころ**:

| 群           | 項目                                                                                                    | 選ぶと                               |
| ------------ | ------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| 移る         | 重ねる紙の5枚（タスク・成果・使用量・キャラクター・設定）・仕事と雑談の切り替え・セッションを切り替える | その紙を開く・切り替える・一覧を開く |
| タスクを頼む | 頼めるタスク（`taskStartRequest` が頼めると言うもの）を「<ID> <要約>」で。添える語は「↩ で頼む」        | 会話の画面へ戻り、依頼として送る     |
| コマンド     | 入力欄の `/` 補完と同じ候補を「/<名前>」で。添える語はコマンドの説明                                    | 会話の画面へ戻り、依頼として送る     |

- タスクとコマンドは依頼として送るので、**ターンが動いているあいだは載せない**（送っても断られる）。Beads の無いリポジトリではタスクの紙の行も出さない
- 群を足すときは `SEARCH_GROUPS` に足し、その群の項目を並びに加える（群の表「見た目」は置き場だけあり、項目はまだ無い）

## モデルと深さの値の源

**入力欄に、いまのモデルと考える深さ（effort）の札「Fable・High」を添える**（`features/run-setting/run-setting-chip.tsx`）。札は見せるだけで、変える口は持たない。新しいセッションの既定は設定の紙の「動き方」で変える。

- effort の段が分からないあいだ（対応しないモデル・まだ届かない）は、モデル名だけを出す
- **モデル・許可モードは、まだ届いていない値を見た目上の既定に倒す**（字と畳み方は
  `src/browser/features/run-setting/model-label.ts` / `permission-mode-label.ts` の1箇所）。
  **届いたが tsukumo の知らない許可モード（SDK が新しく足した語）は既定に倒さず、届いた語を
  そのまま出す**（許可の強さを誤って伝えないため）
- **effort だけ既定へ倒さない**。字と畳み方は `src/browser/domain/effort-label.ts` の1箇所

**effort の値の源**は3つ: 起こしたときに `query()` へ渡した値（起動直後）、
`applyFlagSettings` が受け付けた値、
hook 入力の `effort.level`（ターンの終わり。実測は `docs/history/decision.md`「requirements.md 4.1 Claude Code の駆動（スパイクの実測）」の
「effort の途中変更と読み取りが成り立った実測」）。前の2つは `effort-changed`、hook 入力は `setting-confirmed`
（設定が `effort`）で届き、どちらも `state.effort` を更新して、後に届いた値が勝つ。

## 設定の紙の面の並び

**設定はサイドバーの入口の行の「設定」から開く重ねる紙（`#settings`）**。紙は群の見出しの下に面の中身を1列で縦に並べ、末尾に「既定に戻す」を1つ置く（`ScreenNavSettingsSheet`）。面は `FACES` に1行ずつ宣言し、群（`SETTINGS_GROUPS`）の `keys` に名前を足すと紙に出る（`screen-nav-settings-face.tsx`）。

| 群               | 面                         | 書く値                                                                                |
| ---------------- | -------------------------- | ------------------------------------------------------------------------------------- |
| 動き方           | セッションの既定           | 新しいセッションのモデル・effort・許可モード・図の既定                                |
| 見た目           | 見た目・演出               | 地・領域・字の色と、書き上げる速さ                                                    |
| 知らせ           | 知らせ                     | 通知・鈴の音・出す出来事（値と許しの求め方は `notice-and-failure.md`「知らせの4段」） |
| このプロジェクト | タスクの実行・ワークフロー | 起動するスキルと、スキルの並び（ワークフローだけはリポジトリに属する値）              |

- **「既定に戻す」は紙に1つ**（色ごと・面ごとには置かない）。**上書きが1つも無ければ押せない**（戻す先が無いことを、押せるかどうかで表す）。戻すのは `foot: "reset"` の面の値で、ワークフローの面（`foot: "own"`）は自分の下の帯（やめる・保存）を持つ
- **見た目の面は、先頭に3色の見本の帯**（「領域の中の字」を領域の色の地で、「地の上の字 あ Aa」を字の色で、
  右端に差し色の輪）。輪は `title` で「差し色はキャラクターが決める」と伝える（差し色はここでは選べない）。
  色の操作は色見本の四角（`<input type="color">`）と16進の読み出し
- **色の操作子は `<input type="color">` のまま**。**検証も保存も `src/browser/domain/appearance-color.ts` のまま**で、`ground` と `ink` の
  コントラストが下限を割る色は受け取らない（13.2）。**受け取らなかったときは、色の行の下に
  理由を1行出す**（どちらの色との差が足りないか。黙って元の色へ戻すと、選んだ色が効かない
  不具合に見えるため）。次に受け取られたとき・既定に戻したとき・紙を閉じたときに消える
- **ワークフローの面**は利用者の見本（`docs/history/mockup/workflow-setting-2026-10-17.png`）の形。「<作業ツリー名> のリポジトリ」の太字と `.tw/config.toml` の絶対パス（どこでも折り返す）を置き、
  罫線で区切って欄を並べる。欄は `tw config --schema` が返した順で、種類は並び `steps`・選択 `choice`・コマンド `command`・読み取り専用 `readonly`（`schema: 2`）。欄の頭は `label`（14px 太字）と、右に `description`（12px の薄い字）。
  欄の `steps`（スキルの並び）は上から次の順に置く:
  - **流れの帯**（角丸 12・内側 10/12 の枠）に、並びの順で「<番号> <`title`>」のバッジ（高さ 28・角丸 14）を「→」でつなぐ。並びを変えるとその場で変わる。「着手」「完了」の語は出さない
  - **行のカード**（細い線・角丸 12・間 10）。左からつかむ点（6つの点 2×3、各 3px・間 3px）・番号の丸（24）・名前（`title`、14px 太字）と識別子（`label`、等幅 12px）・その下に説明（`description` を1行で切り、全文は `title` 属性）・右端に「…」。番号の丸どうしを細い縦線でつなぐ。
    候補に無い今の値は行に残し、名前の位置に値を出して「候補に無い」の印を付ける。保存前の並びと位置が違う行（足した行を含む）は、枠を `--state-warn` にして「● 並びを変えた」の字を添える
  - **つかんで並べ替える**: つかむ点（押すボタン 24×40、名前は「<`title`> を動かす（↑↓ キーでも）」）をポインタで押したまま動かすか、
    フォーカスして Space でつかみ ↑↓ で動かし Space で置く。Esc はつかむ前の位置へ戻し、紙は閉じない。つかんでいるあいだは、つかんだカードを差し色の枠と浅い影で少しずらして浮かせ、
    置き場所を行の間の差し色の線で示す（行そのものは動かさない）。置いた結果は下書きに入り、読み上げに「<`title`> を <n> 番目へ置いた」などの1文を渡す（`aria-live`）。
    並びが1つだけのときと書いているあいだは、つかむ点を押せない。つかむ操作が使えないときの手段として「…」の並べ替えを残す
  - **「…」** は いちばん上へ／ひとつ上へ／ひとつ下へ／いちばん下へ／並びから外す（区切りの下、失敗の色）。先頭の上へ2つ・末尾の下へ2つ・最後の1つの外すは押せない。開くと最初の押せる行にフォーカスし、↑↓ で巡り、Esc でメニューだけ閉じる
  - **並びに入っていないスキル**: 候補（`values`）のうち並びに無いものを、小見出し「並びに入っていないスキル 押すと最後に足す」の下に点線のバッジ「＋ <`title`> <`label`>」で並べ、押すと並びの最後に足す。
    無いときは点線の行「足せるスキルはない（<数>つとも並んでいる）」を押せない字で出す
- 欄の `choice`（選択）は、頭の下に選択肢を全部縦のカードで並べるラジオ（`role="radiogroup"`、名前は欄の `label`）。カードは選択肢の `label`（太字）と `description`（薄い字、折り返す）を持ち、選んだカードは枠を差し色にする
- 欄の `command`（コマンド）は、頭の下に1行のテキスト欄（等幅、全幅）を置き、その下に「無効にしたいときは「なし」と書く。空にして保存はできない。」と言う。空白だけでは「保存」が押せない（「やめる」は押せる）
- 欄の `readonly`（読み取り専用）は、`schema` が言った画面から書けない欄で、頭の下に値を等幅の薄い字で置くだけ（入力もラジオも置かない）。値の文字列の作り方は `docs/architecture/workflow-contract/config-and-beads.md` の `keys` の欄の表に従う。下書き・下の帯の変更の数・「保存」の可否には入れない
- **ワークフローの面の操作は下書きだけを変え、保存するまで書かない**。下の帯は変更中だけ左に、並びだけなら「● 並びを変えた」（1つ外しただけなら「● <`title`>を外した」）、選択・コマンドが1欄だけなら「● <欄の `label`>を変えた」、並び以外を含む複数なら「● 設定を変えた」を出し、右に「やめる」「保存」（変更が無いときと書いているあいだは押せない）。
  保存で、下書きのある欄ごとに1回の `tw config set` で書いて返った値で描き直す（押した側へ先に倒さない）。書く値は、並びは全体を JSON にした文字列、選択とコマンドは下書きの文字列そのまま。ワークフローが値を断ったら、その欄の下に理由を1行出し、下書きは残す。やめるで今の値に戻す。
  **下書きがあるまま紙を閉じると、下書きは黙って捨てる**（確かめない。紙を開くたびに読み直す）。
  `tw` が無い・設定コマンドを持たない・`.tw/config.toml` が無い・読めないときは
  欄を出さず、リポジトリの行の下に何が無いかを1文で言う（`docs/architecture/workflow-contract/config-and-beads.md`「設定コマンド」）

## 顔

**キャラクターの顔を丸く切り抜いた1枚**（`browser/components/frame/character-face.tsx` の `CharacterFace`）。迎えるの一言・雑談の画面・狭い幅の吹き出しの顔・使用量の紙の見直しのカードが使う。大きさと丸の地は置く側の `className` が決め、部品自体は領域の見た目を持たない。

- **素材は `character.json` の欄 `face`**（ファイル名1つ。立ち絵と同じ種類のファイルを
  受け付ける。正方形を勧める）。検証は `src/shared/character-pack/character-definition.ts`、画面へは
  `CharacterInfo` に `/character/<pack>/<file>` の URL として載せる（`mini` と同じ経路・同じ取り直しの印）
- **表情では変わらない1枚**（`mini` と同じ）。表情は舞台の立ち絵が持つ
- **定義に `face` が無いパックでは何も出さない**。空の丸も頭文字の丸も出さない。**`mini` や立ち絵から切り抜いて代わりにしない**（切り抜く位置をコードに書くと、キャラクターの中身をコードに書くことになる）
- **同梱パックには足す。** `tsukumo` は `default.png` から顔を切り出した1枚、`tsukumo-spirit` は
  `default.svg` の `viewBox` を顔に寄せた1枚
- **キャラクターの紙から差し替える／外せる**。詳しい設定の「顔」の区画のボタンは背景と同じ「差し替える」「消す」の2つ
  （`docs/architecture/character-pack.md`「画面から作るときの置き場と受け取り方」）。受け付ける形式・大きさの上限は立ち絵と同じ（`.svg` / `.png` / `.gif`）
- キャラクターの選び直しはキャラクターの紙が持つ（「このキャラクターに切り替える」が `session.switchCharacter` を送る）。部屋の頭には選ぶ口を置かない

## 狭い幅（760px 以下）

狭い幅では舞台を出さないので、部屋の頭の2つの群は出ない。代わりに1行の頭（`RoomNarrowHead`。顔・状態・やり取りの題・「≡」）を出し、入口はすべて「≡」から開く探すの一覧に畳む（ADR 0057 論点 5。形は `narrow-screen.md`「頭」）。探すとセッションの一覧のダイアログは `RoomHeadScope` が1回だけ描くので、どの幅でも同じものが開く。

## 13. 画面のデザイン

### 13.2 Color

**差せるつまみは4つだけ**にする。残りは導出するか固定する。つまみが少ないほど、
どのパック・どの設定でも壊れない。

| トークン                 | 役割                                                                                   | 誰が差すか                            |
| ------------------------ | -------------------------------------------------------------------------------------- | ------------------------------------- |
| `ground`                 | 画面の地                                                                               | **使う人**                            |
| `surface`                | 領域の地                                                                               | **使う人**                            |
| `ink`                    | 本文の字                                                                               | **使う人**                            |
| `accent`                 | キャラクターの色                                                                       | **パック**（`character.json`）        |
| `ink-quiet`              | 補助の字・弱い見出し                                                                   | 固定（`ink` から導出）                |
| `ink-soft`               | 読ませる補助の字（表の見出し行・添え書き・やり取りの列の見出し。`ink-quiet` より強い） | 固定（`ink` から導出 72%）            |
| `rule`                   | 罫線・領域の境目                                                                       | 固定（`surface` から導出）            |
| `rule-soft`              | レポートの表の行罫（`surface` 上で約 1.3:1）                                           | 固定（`surface` から導出）            |
| `rule-quiet`             | 読む面の静かな罫線                                                                     | 固定（`surface` から導出）            |
| `ink-bright`             | レポートの拾う字（見出し・太字・`stats` の数。`surface` 上で約 15:1）                  | 固定（`#f7f6f8`）                     |
| `state-ok`               | 成功・完了                                                                             | **固定**                              |
| `state-warn`             | 注意・答え待ち                                                                         | **固定**                              |
| `state-ng`               | 失敗・エラー                                                                           | **固定**                              |
| `state-info`             | レポートの情報（結論）                                                                 | **固定**                              |
| `state-ask`              | 疑問・未確認                                                                           | **固定**                              |
| `state-memo`             | メモ（覚え書き）                                                                       | 固定（`ink` そのもの）                |
| `chart-series-1`〜`6`    | レポートのグラフの系列色（OKLCH の L 0.78・C 0.11。`accent` の色相は使わない）         | **固定**                              |
| `chart-series-other`     | 7本目以降の系列・7点目以降のデータ点（色相を持たない灰）                               | **固定**                              |
| `graph-ground-1`〜`3`    | `graph` の色の目印の無い群の地（群の順に巡らせる）                                     | 固定（`state-*` などから導出 10%）    |
| `graph-tone-fill-a`〜`e` | `graph` の ` @a`〜` @e` の節点の地                                                     | 固定（`chart-series-*` から導出 22%） |
| `graph-return`           | `graph` の戻り道（`A <- B`）の破線と凡例                                               | **固定**                              |

**罫線は3段ある。** `rule` は**線そのものが輪郭を担う**場所（押せる部品の縁・領域の境目・レポートの表の見出し行の下）、
`rule-soft` はレポートの表の行罫、`rule-quiet` は **「ここで切れている」とだけ言えばよい**場所（カードの枠・凡例の行）。
どれも `surface` に `ink` を混ぜた導出値で、混ぜる割合だけが違う（32%・12%・6%）。

**この表に無い固定の色**が4組ある。**コンテキストの内訳の分類**（`context-*`。分類ごとに違う色で、
凡例に分類名が必ず並ぶ）と、**量の棒**（`usage-bar*`。期間の札の縦棒とモデル別／ツール別の
横棒。分類の色ではなく「その列の最大に対する長さ」を言うだけ）と、**トークン消費の画面の中身の
地・罫・字**（`usage-*`。この画面の中でだけ使う）と、**最終レポートの段ごとの時間のうち、測れなかった段の斜線の灰**
（`phase-band-unknown`。一覧の印・帯の斜線の区間・waterfall の欠片に使う。帯の浅葱の区間は 13.2 の「結論部の色」の節のとおり `accent` から導く）。どれも**誰が来ても変わらない**ので、
つまみにも導出にもしない（値は `src/browser/styles/theme.css`）。

**既定値の選び方。** `accent` の既定値は**立ち絵の頬と耳から採った色**で、原則1を文字どおりに
した結果。地も中性の黒ではなく紫に寄せた暖色の黒で、淡いピンクの立ち絵と喧嘩しないように
してある。

**パックが差すのは `accent` 1つだけ**で、地と字は差さない。キャラクターごとに世界の色が変わる
案も検討したが、**読めるかどうかがパック次第になる**ので採らなかった。

**雑談中の会話の画面では、パックが持てば `chatAccent` の値に差し替わる**（会話以外の画面は雑談のままでも `accent` に固定。
`character.json` の任意の欄、検証は `src/shared/character-pack/character-definition.ts`）。**新しいつまみを
足すのではなく、`accent` という1つの枠がモードに応じて別の値を取るだけ**（`--surface-accent` /
`--surface-raised` などの導出も、値の由来を意識せず `--accent` を読むだけなので自動で追随する）。
`chatAccent` を持たないパックは雑談中も `accent` のまま（仕事と同じ差し色）。仕事へ戻すと
`accent` に戻る（`src/shared/character-pack/character.ts` の `effectiveAccent`。`docs/architecture/screen-design.md` 13.7）。

**コントラストの下限を守る。** `ground` と `ink` の組は、使う人が何を入れても本文が読める比を
下回らないところで止める。下回る値が来たら、受け取らずに既定へ落とす。

**この検算は画像には効かない。** キャラビューに敷く背景画像は、**覆い（`ground` 一色）の
不透明度の下限**で同じ保証を作る（13.8）。

**色付けが薄いのは色相ではなく地の段差。** 「機械の名前に地を敷いて区別する」仕組みは既にあり、
`ground` と `surface` の差が段差として見えていないだけだった。だから足すのは色相ではなく
**地の段**にする（測り方と数字は `docs/history/decision.md`「design.md 13.2 Color（色付けが
薄い原因の実測）」）。

**足すのは導出を1つだけ。差せるつまみは4つのまま。** 上の表に1行だけ加える:

| トークン         | 役割                                                   | 誰が差すか                                   |
| ---------------- | ------------------------------------------------------ | -------------------------------------------- |
| `surface-raised` | 本文の地の上に**浮く**小さな塊（機械の名前・結論の塊） | 固定（敷いた地に `ink` を1割**重ねて**導出） |

`surface-accent` と同じく**計算するだけの値**で、新しいつまみではない。割合は1割
（`surface` の上では比 1.31:1、その上の `ink` は 9.77:1）。

**混ぜるのではなく重ねる**（`color-mix(in srgb, var(--ink) 10%, transparent)`）。`surface` と
混ぜた不透明な色にすると、**浮く塊が浮く塊の中に入ったとき**に親と同じ色になって消える
（実測済み。やり取りの最後の本文は必ず最終レポートなので、その中のインラインコード・
カードが全部沈む）。重ねる形なら `surface` の上での色は不透明に混ぜたときと
変わらず、どの段の上でも必ず1段上がる。

読む面の地はこれで3段になり、段がそのまま意味を持つ:

- **沈む（`ground`）** = 畳んだもの（`details`・コードブロック）
- **基準（`surface`）** = 本文
- **浮く（`surface-raised`）** = 機械の名前（インラインコード・`kbd`）、カード

文中の機械の側の字は3つを見分けられるようにする。インラインコードは `surface-raised` の地・角 4px。
`kbd`（キー）は同じ地に 1px の枠（`rule`）と下 1px の inset の影を足したキーの形。
`samp`（出力）は地を持たず、字を `ink-soft` にして弱める。
押せるパスと files の塊のパスは、折り返しの機会を `/` の直後（`<wbr>`）だけに置く。
ハイフンの後ろには見えない結合子（U+2060。字は変えない）を生成して折れなくする。
`/` を持たない長い葉の名前だけが、列に収まらないとき最後の手段として字の途中で折れる（`overflow-wrap: break-word`）。

**「Slack のような1行への色付け」に印は足さない。** **行を塗る記法は既に1つある**
（` ```diff ` の地を塗る色付け）。`report-notation.ts` に行を塗る印を足すと `badge` と意味が二重になり、色だけで意味を伝える入口に
なる（13.1 原則5）。代わりに、**意味を持つ塊の地を、既にある色で薄く染める**
（`color-mix(in srgb, var(--surface), var(--state-warn) 13%)` の形。割合は塊の強さで変えてよい）。染めてよいのは
`state-*`（ok / warn / ng / ask / memo）と `accent` だけで、**塊に文字のラベルが出ないなら色は足さない**
（13.1 原則5。染めは地との比がごく小さく、その上の `ink` は 10:1 以上を保つ）。

**`note` は6種（情報・注意・異常・疑問・メモ・お願い）に割り、種別のラベルを tsukumo が文字で
描く**（`markdown/renderer/notation.tsx`）。色は 情報＝`state-info`（青） / 注意＝`state-warn` /
異常＝`state-ng` / 疑問＝`state-ask`（紫） / メモ＝`state-memo`（`ink` の白） / お願い＝`accent` で、
**左の色罫を持つのは注意・異常・お願いの3つだけ**（「読み飛ばされると困る」という1つの意味）。
お願いのほかの5種は、地をその色で染める。染めは段差で、注意・異常は 13%、情報・疑問・メモは 6%
（表の状態セルと同じ値。13.3）。頻度の高い穏やかな種類を薄くして、注意・異常を立たせる。
情報・疑問・メモは罫を持たず、種別のラベルの字がその種類の色（`state-info` / `state-ask` / `state-memo`）を運ぶ。
お願いは縦罫と地を `accent`（10%）にし、枠で囲む。
情報＝青・疑問＝紫・メモ＝白にしたのは、結論の塊（情報）に色を持たせ、メモを灰色の側に寄せるため（以前の色割りは `docs/history/decision.md`「screen-design.md 13.x 画面設計の本文から日付を消した経緯6件」）。

**確度つきの主張（`claims` の塊）の確度は、記号と語の字だけが色を持つ**。確定＝`state-ok`（✓）/ 推測＝`state-warn`（〜）/
未確認＝`state-ask`（？）。地は染めず罫も持たない（行どうしは `options` と同じ行罫で区切る）。色だけで言わず、語（確定・推測・未確認）を必ず添える。

**地の文の `strong` / `b` は、`state-info` の薄い地で結論の語を拾わせる。**
地は `color-mix(in srgb, var(--surface), var(--state-info) 10%)`、左右の余白は 0.25em、角丸は 0.2em。
付くのは地の文の段落の直下だけで、表・箇条書き・`stats`・`note` の中の `strong` には付かない。

**引用は灰色の縦罫だけで、地を染めない。** 情報もメモも地を染めるので、
引用とは見分けが付く。

**コードの色付けは同梱のテーマのまま残す**（`highlight.js` の `github-dark`。実測で最も情報量が多く読める）。**ただし箱は1段**（テーマの `.hljs` が敷く地・余白は
`.detail-block` の中で打ち消し、地は `pre` の `ground` だけ）。**差分の行は塊の内幅いっぱいの帯**で、行の器に塗る
（テーマの地は字の幅でしか付かないので打ち消す）。行と語の地は
`theme.css` の固定の4値（追加の行 `#203524`・削除の行 `#372120`・追加の語 `#345d3e`・削除の語 `#603334`。
`color-mix` では `accent` と重なる）。
行頭の `+`・`-` は状態色の字にし、行の字は構文色のまま。
見本の22pxの溝・太字は採らず、行頭の字が見本より1字ぶん左に来る
（地が全幅の帯で記号が赤と緑なので見分けられ、溝は行の器と E2E の DOM を変えるため）。
ただし **Chart.js と mermaid の色は `theme.css` のトークンの実効値を
読んで渡す**（`markdown/renderer/chart.ts`・`mermaid-block.tsx`）。Chart.js は軸の字に `--ink-soft`・軸の線に `--rule`（格子線は引かず、凡例も出さない）、
系列に `--chart-series-*`（内蔵の配色は止め、7本目以降は `--chart-series-other`）。mermaid は
`theme: "base"` + `darkMode: true` に、トークンを hex に解いた `themeVariables`（地は `surface`・
ノードは `surface-raised` を `surface` に重ねた色・字は `ink`・線は `ink-soft` を `surface` に重ねた色・
囲みは `ground`）を渡す。`themeVariables` は hex しか受け取らない。使う人が地や字の色を差し替えたら、
覚えた図を捨てて描き直す。

**最終レポートに印を付ける。** 最終レポートは**箱（地・枠・内側の余白）を持たず**、領域の `surface` を紙にする
（札は枠を持たない、の決定を本文まで広げた。それまでの箱は `docs/history/decision.md`
「display.md 4.2 / screen-design.md 13.2 最終レポートの箱と、常に開いた検証の表（2026-10-03 に覆した記録）」）。
地は本文と同じ `surface` のまま（ユーザー指摘。`ground` に沈めると、同じメインビューに出る質問のカード
〔`surface`〕と地が食い違い、本文なのに「途中のもの」の段に見えた）。中間レポートとの差は
箱（中間だけ破線の箱）・ラベルの2つで（中間レポートの地も `surface`。ユーザー指摘。`ground` のままだと
最終レポートと地が食い違って見えた）。前に中間レポートの目録の1行があるときは、
小さな字の1行どうしが続いて読めないよう、最終レポートの上に 0.75rem のあきを足す（線・枠・色は足さない）。
**箱は既に他の情報（中間かどうか）を運んでいる**ので、最終レポートだと分かるのは実質ラベル1つが支えている。
最終レポートには次の1つを当てる:

- **ラベル「最終レポート」**。中間レポートのラベルと同じ段・同じ色（`--font-label`・`ink-quiet`）に
  置く。**同じやり取りに中間レポートが1つ以上あるときだけ出す** — 本文が1つしか無いやり取りでは
  「最終」が何も区別せず、内容を持たない行になる。**いちばん新しいやり取りでは、そのやり取りが
  閉じている（ターンが動いておらず、バックグラウンドタスクも残っていない）ときだけ出す**
  ——閉じていないあいだは、次の `report` でいま最後の本文が中間レポートへ
  回るかもしれない。箱を外すのも同じ条件で見送る（中間レポートの破線の枠にもしない）

**段のまとめの中間レポートは、目録の1行にラベルの次へ終えた段の見出し**（「1/3 段の名前」）を `·` でつないで添え、
そのあとへ「所要 X」（測れなければ「不明」）を同じく `·` でつないで添える。
畳んだ `<summary>` にも終えた段の見出しのあとへ「· 所要 X」を出す（`docs/architecture/display.md`「ワークプラン」の節）。

**ラベルは結論部の目録の1行の頭に置く**（見本は
`docs/history/mockup/report-conclusion-2026-09-30.html` の案A。仕組みと出す条件は
`docs/architecture/display/conclusion.md`「タスクの作業のレポートは、結論部を「目録の1行・見出し・一文」の3段にする」）。
タスクの作業のレポートは、結論部を目録の1行（ラベル・タスクID・終わり方・変更の札）・見出し（作業の名前）・一文の
3段で描く。寸法は目録 `--font-action`（12px）、見出し `--report-heading-2`（21px。レポート専用のつまみ）太字・行間 1.45・字間 0.01em、一文
`--font-subheading`（14px）・行間 1.85、見出しと一文のあいだ 12px。見出しと一文の中のインラインコードは
0.86em。**見出しは終わり方で色を変えない**（読みやすさを優先する）。終わり方は記号・言葉・色の3つで
見せるので、色だけで意味を伝えることにはならない（13.1 原則5）。

**結論部の色のうち、見本の浅葱だった役は `accent` から `color-mix` で導き**（見本の浅葱は `accent`
そのものだった。新しいつまみは足さない）、字と地は見本の16進を固定の値として置く
（トークン消費の画面と同じ扱い。値は `theme.css`）。導く側は `report-task-id`（`accent` を `ink` へ寄せて明るく）・
`report-task-id-rule`（`surface` へ沈める）・`report-outcome-finished`（`accent` をわずかに `ground` へ沈める）の3つで、
`report-sequence-ink`・`phase-band-longest`・`phase-band` も同じ考え方で導く。答え待ちの金は固定のまま:

| 塗るもの                               | トークン                                                     |
| -------------------------------------- | ------------------------------------------------------------ |
| 目録の字 / 区切りの `·`                | `ink-quiet` / `report-catalog-separator`                     |
| タスクID / その点線の下線              | `report-task-id` / `report-task-id-rule`                     |
| 終わり方（完了 / 答え待ち）            | `report-outcome-finished` / `report-outcome-awaiting-answer` |
| 変更の札の `+a` / `−b`                 | `report-change-added` / `report-change-removed`              |
| 見出し / 一文とインラインコードの字    | `ink-bright` / `ink`                                         |
| 見出しと一文の中のインラインコードの地 | `report-code-surface`                                        |

**レポートの字の色は `ink-bright`・`ink`・`ink-soft`・`ink-quiet` の4段と、色で意味を運ぶ印の色だけ**（印の色は `state-*`・`accent`・`report-*`・`ground`）。`ink-bright` は
拾う字（見出し・太字・`stats` の数）で、固定の `#f7f6f8`（`surface` 上で約 15:1）。見出しが本文より暗く、
段が3つに結論部の固定色3つを足して実質6つあった状態を、4段に畳んだ。字を生の色や `color-mix` で作らない
（`test/architecture/report-color.test.ts` が `report-notation.module.css` の `color` を検査する）。

**見本と揃えなかったもの**は書体（見本の丸ゴシック・IBM Plex Mono。`--font-sans` / `--font-mono` のまま）と、
タスクID の要素（見本の `<a href="#">` ではなくモーダルを開く `<button>`）。

**流れ（`flow`）の丸・線と、図と表の題の「図 n」「表 n」の番号は専用のトークンを使う**（デザイン
「流れの塊 案A」。見本は `docs/history/mockup/report-flow-rail-2026-10-02.html`）。値は結論部の
`report-outcome-finished` と同じ導き方（`accent` から）だが、「完了」とは意味が別なので流用せず、読む順を示す印
という意味を名に持つ `report-sequence-ink` を別に立てる。暗い側は固定値を持たず
`color-mix(in srgb, var(--report-sequence-ink), var(--ground) 65%)` で導く。

**寸法**（見本の実測値をそのまま使う。9段のタイプスケールに無い値も固定で書く）: 丸は直径 28px・枠 1.5px・

**コンテキストの内訳の分類には、固定の色を7つ置く**（`context-system-prompt` /
`context-system-tools` / `context-mcp-tools` / `context-memory-files` / `context-skills` /
`context-messages` / `context-other`。トークン消費の画面の札で、横棒の区間と凡例の四角が同じ
1つを読む）。**差せるつまみは4つのまま**で、これも `state-*` と同じ「意味を固定した色」の側
（誰が来ても変わらない）。**増やしてよい根拠は 13.1 原則5** — 凡例に分類名が必ず並ぶので、色は
読みやすさの重ねがけになり、色だけで意味を伝えることにならない。**知らない分類は
`context-other` に落ちる**ので、SDK 側に分類が増えても色を足さずに出せる。**空きと自動圧縮
バッファには色を割り当てない**（無地と斜線で分ける。柄のほうが「中身ではない」ことを運ぶ）。

**トークン消費の画面の中身は、ユーザーの見本の色に寄せる**（ユーザーの指示
「見本の色をできる限り再現してほしい」。範囲は画面の中身だけで、`ground` / `surface` / `ink` /

`surface-raised` / `rule` / `ink-quiet` の導出では作れない（字だけで6段ある）ので、見本の16進を
そのまま固定の値として置く。**足すのは固定の値で、つまみは4つのまま**（パックからは差せない）:

**量の棒に青を入れるのは、13.1 原則5 の「意味を固定した新しい色を増やさない」より
ユーザーの指示を優先した**もの。数の文字が必ず棒の隣に並ぶので、色だけで意味を伝えることには
ならない。**`context-other` だけは見本に無い**ので、色相を持たない灰にした（「分類できなかった」
ことを言う色で、6色のどれとも色相で張り合わない。明るさを6色より少し上げてあり、色覚の型を
問わず6色・空きと見分けられる）。**見本と揃えなかったもの**は、書体（見本の明朝・丸ゴシック・
IBM Plex Mono）と字の大きさ、「ほか n 件を見る」の色（見本の差し色ではなく `accent`）。

**「減らし方を見てもらう」区画（`token-usage/components/usage-review-card/usage-review-card.tsx`。題の帯といまの
コンテキストの札のあいだ）は、見本の16進を固定の値として置かない。** 上の表（内訳の分類・
量の棒・札の地や罫）は「読むだけの数字」なので見本の色をそのまま固定したが、この区画は
**押せる・キャラクターが動いている区画**なので、既にある `--accent` を `--usage-card` /
`--usage-rule` に `color-mix` で薄く重ねるだけにする（13.1 原則1「色はキャラクターの持ち物」）。
固定値を増やさずに済み、パックの `accent` が変わればこの区画も一緒に動く。**見直し中は枠を
`--accent` そのもの**にして、染めるだけの「ふだん」より状態がはっきり分かるようにする。

結果の場面の見た目の決定のうち色の項目（文言・配置・押せない条件・経過時間の書式は 13.14）:

- **区画の地は「ふだん」と同じ染め**（`.usage-review-invite` と同じ `color-mix`）。「見直し中」の
  ような全力の `accent` 枠にはしない——結果は「押せて動いている」状態ではなく「見終わった」
  静かな状態なので、ふだんと同じ強さでよい
- **効きめの札（大/中/小）は新しい固定色を増やさない**（13.1 原則5）。大は `--accent`
  （キャラクターの色。押せる区画そのものの強調の色を再利用）、中は `--state-warn`
  （すでにある「意味を固定した色」——大小関係を運ぶのも状態の一種として相乗り）、小は色を
  足さず `--usage-rule` の無地にする。見本の3色（`#66d1be` / `#e3b95c` / `#3a3946`）を固定値と
  しては置かない——この区画は13.2「トークン消費の画面の中身は…見本の色に寄せる」が指す
  「読むだけの数字」の表ではなく、押せる・キャラクターが動いている区画の続きだから
- **主ボタンの枠と字は `--usage-rule` / `--usage-ink` に `--accent` を `color-mix` で重ねる**
  だけ（見本の `#2c4744` / `#bfeee4` は固定値として置かない。13.2「染める」と同じ扱い）
- **「もう一度見てもらう」は中立の枠**（`.usage-review-stop` と同じ地味さ）。区画全体の染めが
  すでに「押せる区画」だと言っているので、ボタンにまで `accent` を足すと強すぎる

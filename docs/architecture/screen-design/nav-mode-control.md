## 13. 画面のデザイン

### 13.9 画面のナビゲーション

#### 動き方の操作子

**仕事 / 雑談・モデル・許可モードの3つを、帯から直接変える**（2026-09-23 決定。仕事 / 雑談は
2026-10-11 から、会話の画面への門を押して変える）。**送るコマンドは
いまサイドバーが送っているものと同じ**（`session.setChatMode` / `session.setModel` / `session.setPermissionMode`。
`useSession` の `dispatch`）で、サーバ側は変えない。**表示はサーバから届いた値だけに従う**（押した側へ
先に倒さない。断られたときに戻す処理を持たずに済み、次に届く `session-info` /
`chat-mode-changed` がそのまま正になる。いまの `<select>` と同じ）。

**仕事・雑談の門**（帯の左寄り、部屋の名前の右。2026-10-11 決定。それまでは「仕事｜雑談」のトグル）:

- **門は他の画面の門と同じ文字のタブ**（上の「帯の形」）で、並びは「仕事・雑談」の次に縦の仕切り、
  その右にキャラ・トークン・成果。**どちらも会話の画面（`#`）への `<a href>`**。会話以外の画面は
  モードと無関係で、入力欄も会話の画面にしか無いので、モードを変える口は会話へ行く口と1つにした
- **違うモードの門を1回押すと、会話の画面へ移ると同時に `session.setChatMode` を1回送り、起こし直す。
  確かめの一言は挟まない。** 切り替えのたびに画面が初期化されるのは受け入れ済みで、起こすのは新規の
  セッション、前のセッションへは切り替え画面から戻る（`docs/architecture/chat-mode.md` 4.9）。
  **同じモードの門は移動だけで何も送らない**。起こし直したあとも hash は会話の画面を指したまま
- **いまの印は会話の画面にいて、かつサーバから届いた `chatMode` と一致する門だけ**（押した側へ先に
  倒さない）。戻り先の点の印は上の「帯に何を置くか」
- **ターン進行中か、委譲先が動いている間は、いまと違うモードの門だけ押せない**（起こし直しなので、キャラクターの切り替えと同じ
  条件。サーバも同じ条件で断る）。**門は `<a>` なので `disabled` ではなく `aria-disabled="true"`** にし、
  押しても移動も送信もしない。字を薄くし、理由を `title` に出す（13.7 の立ち絵と同じ扱い）。
  **理由の文面は `FRAME_ERROR_REASON.chatModeSwitchDuringTurn`（「ターン進行中か委譲中は仕事と雑談を切り替えられない
  （中断するか委譲を止めると切り替えられる）」）で、サーバが `session.setChatMode` を断るときも同じ**
- **会話以外の画面の `--accent` はパックの `accent` に固定**し、`chatAccent` は会話の画面で雑談のときだけ流す
  （13.2「雑談中は」）

**モデル・effort・許可モードのドロップダウン**（右端、並びはモデル → effort → 許可モード）:

- **部品は `components/ui/select/select.tsx` の素の `<select>` のまま**にし、見た目だけ帯に合わせる
  （`appearance: none`・枠は `--rule`・下向きの矢印は CSS で描く）。キーボードの操作・読み上げ・
  選択肢の開き方はブラウザに任せる
- **見本の値に揃える**（2026-09-23 決定）: 高さ 32px・左右 10px・角丸 8px・地は透明・字は
  `--ink` の 13px（`--font-secondary`）。**幅は選んでいる値の字の幅**（`field-sizing: content`）
  にし、矢印（12px）を字のすぐ右に置く（既定の幅はいちばん長い選択肢に合うので、「Opus」と
  矢印の間が空いていた）。矢印は `<select>` を包む `<span>` の `::after` に `currentColor` で
  描くので、「全部許す」のときは矢印も `--state-ng` になる
- **見える項目名は置かない。** 値（「Opus」「自動判定」）が何の値かは字で分かり、帯の幅は
  いまの作業の要約に回す。`aria-label` と `title` に「モデル」「effort」「許可モード」を入れる
- **モデルと許可モードは既定どおり**（モデルは等幅、許可モードは本文書体。機械が付けた名前と
  人の言葉。13.1 原則3）。区切りの記号は置かない
- **`bypassPermissions` のときだけ字に `--state-ng` を載せる**（新しい色は足さない）。
  「全部許す」の文字が必ず付いているので、色だけで意味を伝えることにならない（13.1 原則5）
- **ターン進行中も変えられる**（起こし直さない。いまのサイドバーと同じ）
- **モデル・許可モードは、まだ届いていない値を見た目上の既定に倒す**（モデルは `Opus`、
  許可モードは「自動判定」。字と畳み方は
  `src/browser/domain/model-label.ts` / `permission-mode-label.ts` の1箇所）。
  **届いたが tsukumo の知らない許可モード（SDK が新しく足した語）は既定に倒さず、届いた語を
  そのまま出す**（許可の強さを誤って伝えないため。絵は何の強さも名乗らない素の盾）。
  **effort だけ既定へ倒さない**（下の「effort のドロップダウンの値の源」。対応表がまだ届いて
  いない・値がまだ1件も届いていないときは選べなくし、理由を `title` に出す。字と畳み方は
  `src/browser/domain/effort-label.ts` の1箇所）
- **会話の画面のサイドバー下端・柱（13.4 の該当箇所）はこの帯には出ず、絵だけの口と吊り札の
  開いた一覧になる**（2026-10-02 決定）。送るコマンド・押した側へ先に倒さないこと・
  ターン進行中の扱いはここと同じで、見た目だけが違う

**effort のドロップダウンの値の源**は3つ: 起こしたときに `query()` へ渡した値（起動直後）、
`applyFlagSettings` が受け付けた値（押した直後。`setModel` の `model-changed` と同じ扱い）、
hook 入力の `effort.level`（ターンの終わり。実測は `docs/history/decision.md`「effort の途中変更と
読み取りが成り立った実測」）。前の2つは `effort-changed`、hook 入力は `setting-confirmed`
（設定が `effort`）で届き、どちらも `state.effort` を更新して、後に届いた値が勝つ。
2026-09-25 の「押した値へ先に倒さない」（読み取った値だけを出す）は、押しても表示が変わらず
不具合に見えたため 2026-10-02 にユーザーの依頼で改めた。

**設定の点**（モデル・effort・許可モードの口の右肩に出す点。2026-10-12 決定）: 切り替えを受け付けたことと、
効いたのを見届けたことを言い分ける。モデル・effort・許可モードの3つとも、待機中は次ターンから、ターン進行中は
同ターンの次の API 呼び出しから効く（実測）ので、押せなくはしない。

- **点は口の右肩に1つ**（7px の丸。口の寸法と並びは変えない）。受け付けた直後は**空洞**（`--state-warn` の縁）、
  見届けたら**塗り**（`--state-ok`）。新しい色は足さない
- **字は出さない。** ポインタを載せたときの `title` だけが言う（口の `title` の末尾に「 ・ 受け付けた」「 ・ 効いた」）
- 受け付けた合図は `model-changed` / `effort-changed` / `permission-mode-changed`、見届けた合図は
  `setting-confirmed`（`SessionState.settingMarks`）。**見届けた値が受け付けた値と合うときだけ塗り**にする
  （モデルは `sonnet` のような別名がフルネームに含まれれば合い、effort・許可モードは完全一致）。合わないときは
  空洞のまま次の見届けを待つ。見届けられないまま次の切り替えが来たら、空洞を新しい値で付け直す
- **空洞の点は、見届けるか元の値へ戻すまで出し続ける**（まだ効いていないことが見え続けるように）。
  切り替える前に効いていた値（印の `from`）へ見届ける前に戻したときは、点を消す。戻したことが点の有無で
  分かる。`from` が分からないとき（モデル・effort が起動直後でまだ届いていない）は戻しても消えない
- **見届けた点は3秒で消える**（寿命は印を付けた時刻から数えるので、画面を開き直したときに過ぎた印は出ない）。
  消えたあとは元の姿で、見届けた印は残さない。effort に対応しないモデルに切り替えたあとは見届けが来ないので、
  それまでに受け付けていた effort の空洞が残る（次の切り替えか起こし直しで消える）
- **`running` になる前の受け付けは印にしない**（起こした直後の `effort-changed` で、起動のたびに点が出ないように）

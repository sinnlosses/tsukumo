ステータス: **正典**。入口は `docs/architecture/screen-design.md`（画面のデザインの全体）。

責務: 許可要求と質問のカード（お伺い）、迎える局面の始め方の一覧、おすすめのカードの中身の作り方。

## 13. 画面のデザイン

### 13.13 会話の画面の局面

#### お伺い

**許可要求と質問を同じカード（`Inquiry`）にし、メインビューの本文に出す**（許可は
入力欄の上の箱、質問はメインビューのカード、と2か所に割れていたのを1つにした）。働くあいだのカードは働く局面の中身なので、答え待ちが
来ても中身は替わらず、プログレスバーの今のフェーズが答え待ちになり、カードが本文に出るだけ。**カードはいまのやり取りの本文（いまのフェーズ・中間レポート）の末尾に置く**
（答えた質問の記録と同じ並びの位置なので、答えてもカードが上から下へ飛ばない。「依頼の全文の真下」には置かない。
経緯は `docs/history/decision.md`「display.md 4.2 各表示物 / screen-design.md 13.13 お伺い（札の置き場。2026-10-10 に覆した記録）」）。
カードの置き場は `docs/architecture/display.md` 4.2「各表示物」のメインビュー。
部品は `components/page/conversation/components/inquiry/inquiry.tsx`、答えの組み立ては
`conversation/stores/inquiry-answer.ts`（入力欄と同じ1つの答えを読み書きする）。

```
 ┌ お伺い ─ 質問 ─ 保存先 ───────────────── 1 / 2 · 待って 0:42 ┐
 │ どこへ保存する？                                                │
 │ ┌┄ 聞く理由  書き手だけでは決められない理由（1〜2文）┄┄┄┄┄┄┄┄┄┄┐ │
 │ ┊ 事実      [確かめた] 打って確かめた事実                      ┊ │
 │ ┊           [写した]   文書から写した事実                      ┊ │
 │ ┊ おすすめの理由 [確度 高] 勧める理由（`recommended` があるときだけ）┊ │
 │ └┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┘ │
 │ 1 ● A する [おすすめ] │ A の詳細（触った・選んだ1つ。触る前は無し）│  ← 内側でスクロールする
 │   A の説明の1行       │  図・preview                            │
 │ 2 ○ B する            │  （触る前は案内の1行）                  │
 │   B の説明の1行       │                                          │
 │ 3 ○ C する ⚠ 戻せない  │  図も preview も無い質問は、右の欄も     │
 │   C の説明の1行       │  2列も出さない                           │
 │                              [戻る]  [任せる]  [次へ ⏎]   ← 下端に固定 │
 └──────────────────────────────────────────────────────────────┘
```

- **頭**: 「お伺い」のチップ・種類（許可 / 質問）・質問なら `header`、許可ならツール名（等幅）・右端に「n / N」と
  待っている時間（「待って 0:42」。等幅）。その右端に「広げる」の押しボタン
- **広げる**: 押すと、同じ中身（問いの文・添え書きの塊・選択肢・詳細・操作の行）を画面いっぱいの板（`Dialog`）に出す。
  板の中は札の高さの上限を持たず、詳細の欄はビューポートの幅を使う。頭の右端は「閉じる」になり、Esc でも閉じる。
  選択の状態は札と共有し（板を閉じても選んだものは札に残る）、数字キーと Enter は板の中でも札と同じに効く。
  最後の問に答えると板は閉じる（途中の「次へ」では開いたまま）。狭い画面（760px 以下）の答え待ちのカードには出さない
- **本文**: 質問は問いの文と選択肢。許可は対象の全文（`toolInputText`。等幅で折り返し、上限は失敗の中身と
  同じ 8000 字）と、選択肢「1 許可」「2 拒否」。許可も質問と同じく、選んでから「これで答える」で答える
  （選んだ瞬間には送らない）
- **本文は、問いの文・添え書きの塊（聞く理由・事実・おすすめの理由）・選択肢の縦の並びとフォーカスした選択肢の詳細の順**
  （見本は `docs/history/mockup/inquiry-brief-2026-10-08.svg`。見本のうち、判断の軸・良い点・悪い点・比べる表は
  `docs/architecture/adr/0054-question-design-human-ai-guidelines.md` で古くなった）。添え書き（`question_brief`）のある質問だけ塊を出す
- **添え書きの塊**: 破線の枠に、上から 聞く理由（見出し「聞く理由」）→ 事実（見出し「事実」。1件ずつ行頭に出どころの印「確かめた」「写した」）→
  おすすめの理由（見出し「おすすめの理由」に、確度の印「確度 高」「確度 中」「確度 低」。`recommended` のある質問だけ）を出す。
  出どころと確度は字で読め、色（確かめた・確度 高は `ok`、確度 低は `warn`、写した・確度 中は `neutral`）は補いにとどめる。
  事実の印の列は幅を揃え、文が折り返しても印は1行目の字に揃える。広い画面のカード・広げた板・狭い画面の「詳しく」の板・
  答えた質問の記録の「質問のときの詳細」は、この塊を同じ部品で、同じ並びで出す
- **選択肢は左の縦の並び**（1行に番号〔等幅〕・選択の印・ラベル・「おすすめ」のバッジ・戻せない選択肢の「⚠ 戻せない」。
  並べ替えたあとの並びで 1 から振る。その下に `description` の1行を出し、空なら出さない）。戻せない印は色だけに頼らず字を添える（13.1 原則5）。選んだ行は枠が `--state-warn`。
  4つの面（広い画面のカード・広げた板・狭い画面の「詳しく」の板・答えた質問の記録の畳み）は、問いの文 → 聞く理由 → 事実 → おすすめの理由と確度 →
  選択肢の並び → フォーカスした選択肢の図と `preview` → 操作の行の同じ並びで、記録の畳みは操作の行と選ぶ操作を持たない
- **右は、フォーカスした選択肢の詳細の欄**: 図の部品（レポートと同じ部品で描く）と `preview` だけを出す（`description` は選択肢の行に出す）。
  許可は詳細の欄を持たない。詳細は高さを切らず、カードの内側でスクロールする。
  フォーカスは選んだ選択肢（1〜9・クリック）か、Tab で入った選択肢に替わり、詳細が入れ替わる。複数選択は最後に触った選択肢。
  **触る前（選んでも押してもいない）は詳細を出さず**、「選択肢を押すと詳細が出ます」の1行を出す。
  **どの選択肢にも図も `preview` も無い質問は、詳細の欄も案内の1行も出さず、2列にもしない**
- **入力欄に字があるあいだ（単一選択だけ）**: 札の選択を外し、選択肢を薄くして（押せる・数字キーも効く）、選択肢の並びの直前に
  「入力欄の答えで答えます」の1行を `--state-warn` で出す。字を消すと薄いのと案内は消えるが、外した選択は戻さない。
  複数選択は変えない。札・広げた板・狭い画面の板は同じ状態を見る
- **2列にするのは、図か `preview` のある選択肢があり、カードの幅が 44rem 以上のとき**（左 16rem 固定・右が残り。ビューポート幅ではなくカードの幅の container query で切る）。
  未満、または図も `preview` も無い質問は**1列**になり、詳細は選択肢の並びの下へ回る。761px 以上のビューポートでカードが狭いときも、狭い画面の板の中も同じ1列の形
- **「任せる」**: 質問の操作の行（「戻る」と「次へ」/「これで答える」の間）のボタン。押すと、いま見ている1問の判断を Claude に任せた答えとして確定し、
  次の問へ進む（最後の問なら全問ぶんを送る）。問ごとに押し、残りをまとめて任せる口は無い。入力欄の字は答えに使わず、下書きのまま残す。
  許可要求のカードには出さない。広げた板も同じ操作の行を持つ。SDK へ返す文は `src/server/session-driver/core/pending-answer.ts` が組み、
  答えた質問の記録はその問の行に「任せた」と出す（用語は `docs/glossary/conversation-phase.md`「任せる」）
- 並べ替え・`preview`・複数選択・1問ずつの決まりは `docs/architecture/display.md` 4.2「各表示物」
- **操作の行（戻る・任せる・次へ / これで答える）はカードの下端に固定し、選択肢の側がカードの内側でスクロールする。** 1024x768 でも
  「次へ」がスクロールせずに押せる。カードの高さの上限はメインビューの内寸から進み具合のプログレスバーを引いた高さ
- **枠と地は `--state-warn` の系統**（いまの質問のカードと同じ。新しい色は足さない）
- **キーはお伺いにフォーカスがあるときだけ効く**（グローバルなショートカットは持たない）: 1〜9 で選ぶ
  （複数選択は切り替え）、Enter で「次へ」/「これで答える」。押せるボタンにはキーを字で添える
- **フォーカスは勝手に移さない**（打っている途中の字を奪わない）。入力欄の上の帯に「お伺いへ」のボタンを置き、
  押すとお伺いの最初の選択肢へフォーカスを移す。帯の字は、質問なら「↓ <名前> が質問しています。下の選択肢から
  選ぶか、ここに書いて答えてください」、許可なら「↓ <名前> が実行の許可を待っています」
- **カードがビューポートの外にあるあいだ、メインビューの下端に「お伺い ↓」のボタンを浮かべる**。答え待ちが届くとカードまで送る動きに加えて、選択肢を押して詳細が出てカードが伸びたときも、
  カードの下端（「次へ」）が見える範囲に入るまで送り直す。それでもカードが見えない（上へスクロールした・本文が伸びた）ときに気づけるようにする。字は「お伺い ↓」、枠は `--state-warn`、地は面に `--state-warn` を
  薄く混ぜた色（新しい色は足さない）、高さは 24px 以上で、領域の下端の右寄りに貼り付く。押すとカードまで送り、フォーカスは移さない
  （移すのは入力欄の上の帯の「お伺いへ」だけ）。カードが一部でも見えたら消える。出すのは広い画面（761px 以上）の最新のやり取りで答え待ちがあるときだけで、
  過去のやり取りを見ているあいだと狭い画面（カードは入力欄のすぐ上にある）では出さない
- **サーバとの接続が切れているあいだは、入力欄の上の同じ帯に切断の旨を出す**（字は `--state-ng`、ボタンは持たない。答え待ちの帯より先に出す）。
  送るボタンは枠だけの無効にし、下書きと添付画像は残す。出すのは接続が一度切れてから `open` に戻るまでで、初回の接続中は出さない
  （文言は `docs/architecture/display.md` 4.2「各表示物」）
- **会話が終わったあとも、入力欄の上の同じ帯に終了の旨を出す**（字は `--state-ng`、ボタンは「新しく始める」のアウトラインのボタン1つ。切断の次、答え待ちの帯より先に出す）。
  送るボタンは切断のときと同じ無効の見た目にし、下書きと添付画像は残す
- **質問の自由入力は入力欄が受ける**（プレースホルダ・「答える」の字は `docs/architecture/display.md` 4.2「各表示物」）。
  許可のときの入力欄は、ふつうの下書きのまま
- **答え待ちの質問のあいだ、送信ボタンは塗りを外す。** 自由入力の字があるときだけ「答える」で塗る（お伺いと
  主役を取り合わない）。許可のあいだは「中断」のまま（塗らない）
- 待っている時間のために、答え待ちが届いた時刻を状態に持たせる（状態の `pending` の要素を `StampedPendingAsk`
  にし、`pending-changed` を畳んだ時刻を `askedAt` に打つ。駆動とイベントの `PendingAsk` は変えない。
  状態の形が変わるので `PROTOCOL_VERSION` を上げた。`docs/architecture.md`「版と互換」）
- 答えた質問の記録は、いまのまま渡したあとのレポートのカードに残す（許可の答えは残さない）。添え書きのある問には、記録に「質問のときの詳細」の畳みを足す

**狭い画面（760px 以下）では、このカードを本文に出さず、入力欄のすぐ上の答え待ちのカードで答える**（
カードの形・択の数ごとの答えのボタン・「ほか n」の出どころは 13.9「狭い画面（760px 以下）」）。入力欄の上の「お伺いへ」の帯も出さない
（答え待ちのカードがその場所に見えている）。答え待ちのカードの「詳しく」を押すと、下から上がる板の中にこのカードを**1列の形**で出す:

- 上から、頭（「お伺い」のチップ・種類・`header`・「n / N」）・問いの文・添え書きの塊（聞く理由・事実・おすすめの理由）・選択肢の縦の並び（`description` の1行つき）・
  選んでいる選択肢の詳細（`preview`・図）の順に1列に積む。
  詳細は選択肢の横ではなく**選択肢の並びの下**に回し、選ぶ選択肢を替えると詳細が入れ替わる（触る前は詳細の代わりに案内の1行。図も `preview` も無い質問は出さない）
- 選択肢は板の幅いっぱいの行（高さ 44 以上・番号つき）。押すと選ぶだけで、板の下端の「任せる」と「これで答える」（高さ 44）で答える
  （答え待ちのカードのボタンと違い、詳しく読んでから答える場所なので押した瞬間には送らない）。答えたら板を閉じる
- 詳細は高さを切らず板の中でスクロールする（`preview` を途中で切らない）。図の表が板の幅に入りきらないときは表だけ横にスクロールする（13.3）
- 戻せない選択肢の印は字を添える（13.1 原則5）

#### 始め方の一覧

**迎える局面のメインビューに、見出し「何から始める？」・リード・おすすめのカード3枚・「ほかの始め方」を出す**
（`Welcome`。見本は `docs/history/mockup/welcome-cards-2026-10-04/` の案A。書体はいまの
変数のまま）。

- **カード**は3枚まで・3列（`1.3fr 1fr 1fr`。1枚のときは1列、2枚のときは `1.3fr 1fr`）・間 12px・角丸 14px・
  最小の高さ 196px。幅が狭いとき（メインビューの幅が 40rem 以下）は1列に積む。中身は上から、ID（等幅・
  `--accent`）・題（3行まで。バッククォートで囲んだ字は等幅）・顔（18px）と理由の1行（12.5px）・
  区切り線の下にキーの印（1・2・3）と「始める →」のボタン。理由が無いカードは理由の行を出さない。
  顔が無いパックは顔を出さずに理由だけを出す
- **1枚目は「いちばんのおすすめ」**: ID の横に印を付け、`--accent` の枠・`--surface-accent` の地・
  塗りのボタン・題 15px。ほかのカードは題 14px で、ボタンは輪郭だけ（hover で塗りになる）
- **カードの元**は、状態の `recommendation` の並び（作り方は下の「おすすめのカードの中身」）。**前回の続き**はカードの1枚
  として並ぶことがあり、ID の席は前のセッションの見出し・題は前のセッションの残り（`report` の `sessionRemaining`。切り替え画面に配る `SessionDigest` の `remaining`）。
  **前のセッションは、同じ作業ツリー（`cwd` が同じ）・同じパック・同じモードの最新のセッション**で、
  同じ作業ツリーに無ければカードを出さない（別の作業ツリーのセッションからカードは作らない）。
  独立の群は持たない。**タスク**のカードは、ID と要約（題）。空いた枠と、`recommendation` が空のあいだは
  既定の並び（前回の続き → タスク一覧のうち着手できる〔`TaskReadiness` が `ready`〕未着手を上から）で、
  理由なしに埋める。理由が届くと並びと理由を差し替える
- **「始める」とキー 1・2・3 は、入力欄を経由せず依頼の文をすぐ送る**（「タスク <ID> を進めて」
  「前回の続き: <残り>」）。入力欄の下書きには触らない
- **ほかの始め方**: 「自分で書く」（`/`。入力欄へフォーカスを移す）・「タスクの一覧から選ぶ」（タスクの
  モーダルを開く）・「前のやり取りを見る」（`←`。切り替え画面〔13.9〕を開く。いまのセッション以外の行が一覧にあるときだけ出す。別の作業ツリーの行だけでも出す）
- **キーが効くのは、フォーカスが入力欄・ほかの入力の中になく、重なる面が開いておらず、お伺いが出ていない
  ときだけ**（打っている途中の字を奪わない。お伺いの 1〜9 と重ならない）。修飾キー付き・IME の変換中も
  効かせない
- タスクも前回の続きも無いときはカードを出さず、見出しと「自分で書く」を大きく出す
- **選ばないと進めない画面にはしない**（`docs/requirements.md` 2.2）。入力欄はいつもどおり使える
- キャラクターの迎えの一言は、メインビューではなく吹き出しに出す（中身はコードに書かない。原則4・
  出し方は `docs/architecture/display.md` 4.2「出力の分離（セリフと詳細）」）

#### おすすめのカードの中身

**始め方の一覧に並べる候補の並びと理由の1行（おすすめのカード。`recommendation`）は、サーバが背景の使い捨ての
`query()`（`haiku`）1回で作り、状態の `recommendation` で配る**（見本は
`docs/history/mockup/welcome-cards-2026-10-04/` の案A）。ここに書くのは中身の作り方だけで、カードの形は書かない。

- **候補**は「前回の続き」1つと、タスク一覧のうち着手できる（`TaskReadiness` が `ready`）未着手を一覧の順に
  20件まで。タスクは ID・要約・そのタスクを依存に挙げている未完了のタスクの ID を渡す。
  20件を超えて渡せなかった着手できるタスクがあるときは、その件数を依頼の文面の末尾に添え、候補の印にも
  入れる（渡せていれば件数は印に入らない）。画面には出さない
  「前回の続き」は**中身を渡さない固定の候補**で、前のセッションの要約（`sessionSummary`）も、それが有るかも
  渡さない（`docs/coding-standards.md`「会話内容の扱い」）
- **並びと理由は tsukumo が決める。** 3枚まで。理由は「効き目」「軽さ」「つながり（前の作業の続き）」の
  どれかが分かる言い方の1行（40字まで）で、数を競わせる言い方（「最速」「いちばん多い」など）はしない。
  「前回の続き」を選ぶときの理由は「つながり」
- **契機**はタスク一覧が届くたびで、迎える局面かどうかは見ない。**候補の並びが前回と同じなら問い合わせず**、
  `~/.tsukumo/recommendation.json`（候補の並びとカードの組を新しい順に8件まで）から配る。起こし直した直後・
  起動し直した直後もここから即座に届く
- **届くまでは既定の並び**（前回の続き → 着手できる未着手の上から）で、理由は出さない。候補が変わって
  キャッシュに無いときは空の並びを配って既定へ戻し、問い合わせの結果で差し替える。失敗・時間切れ
  （60秒）では何も配らない。**画面を開く流れとセッションを起こす流れはこの問い合わせを待たない**
- 「前回の続き」が選ばれても、画面が前のセッションの残りを持たない（同じ作業ツリーの前のセッションが無い・残りが空）
  ときはそのカードを外す。カードのタスクがいまの着手できる未着手に無いときも外す
- 迎えの吹き出しの出し方・書けなかったときの扱い・カードの名前の差し込みは
  `docs/architecture/display.md` 4.2「出力の分離（セリフと詳細）」

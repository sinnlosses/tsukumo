## 13. 画面のデザイン

### 13.13 会話の画面の局面

#### お伺い

**許可要求と質問を同じ札（`Inquiry`）にし、メインビューの本文に出す**（2026-10-02 決定。許可は
入力欄の上の箱、質問はメインビューの札、と2か所に割れていた）。働くあいだの札は働く局面の中身なので、答え待ちが
来ても中身は替わらず、帯の今の段が答え待ちになり、札が本文に出るだけ。**札はいまのやり取りの本文（いまの段・中間レポート）の末尾に置く**
（2026-10-10 利用者決定。答えた質問の記録と同じ並びの位置なので、答えても札が上から下へ飛ばない。2026-10-08 の「依頼の塊の真下」を覆した。
経緯は `docs/history/decision.md`「display.md 4.2 各表示物 / screen-design.md 13.13 お伺い（札の置き場。2026-10-10 に覆した記録）」）。
札の置き場は `docs/architecture/display.md` 4.2「各表示物」のメインビュー。
部品は `components/page/conversation/components/inquiry/inquiry.tsx`、答えの組み立ては
`conversation/stores/inquiry-answer.ts`（入力欄と同じ1つの答えを読み書きする）。

```
 ┌ お伺い ─ 質問 ─ 保存先 ───────────────── 1 / 2 · 待って 0:42 ┐
 │ どこへ保存する？                                                │
 │ 背景: なぜ今聞くか（2〜3文）  判断の軸: 速さ / 戻しやすさ / 依存の数 │
 │ 1 ● A する [おすすめ] │ A の詳細（フォーカスした1つ）         │  ← 内側で転がる
 │ 2 ○ B する            │  ＋ 良い点  － 悪い点  [図・preview]   │
 │ 3 ○ C する ⚠ 戻せない  │                                       │
 │ ▸ 3つを並べて比べる（軸 × 選択肢の表。畳める）                   │
 │                                       [戻る]  [次へ ⏎]   ← 下端に固定 │
 └──────────────────────────────────────────────────────────────┘
```

- **頭**: 「お伺い」のチップ・種類（許可 / 質問）・質問なら `header`、許可ならツール名（等幅）・右端に「n / N」と
  待っている時間（「待って 0:42」。等幅）
- **本文**: 質問は問いの文と選択肢。許可は対象の全文（`toolInputText`。等幅で折り返し、上限は失敗の中身と
  同じ 8000 字）と、選択肢「1 許可」「2 拒否」。許可も質問と同じく、選んでから「これで答える」で答える
  （選んだ瞬間には送らない）
- **本文は、背景と判断の軸の塊・選択肢の縦の並びとフォーカスした選択肢の詳細・畳める比較表の順**
  （見本は `docs/history/mockup/inquiry-brief-2026-10-08.svg`）。添え書き（`question_brief`）のある質問だけ背景と軸の塊と比較表を出す
- **選択肢は左の縦の並び**（1行に番号〔等幅〕・選択の印・ラベル・「おすすめ」のバッジ・戻せない選択肢の「⚠ 戻せない」。
  並べ替えたあとの並びで 1 から振る）。戻せない印は色だけに頼らず字を添える（13.1 原則5）。選んだ行は枠が `--state-warn`
- **右は、フォーカスした選択肢の詳細の面**: 良い点・悪い点・`preview`・図の塊（レポートの塊と同じ部品で描く）。
  添え書きの無い質問は `description` と `preview` だけを出す。許可は詳細の面を持たない。詳細は高さを切らず、札の内側で転がす。
  フォーカスは選んだ選択肢（1〜9・クリック）か、Tab で入った選択肢に替わり、詳細が入れ替わる。複数選択は最後に触った選択肢
- **下に「並べて比べる」表**（軸 × 選択肢。`<details>` で畳み、初期は畳む）。札の幅に入らなければ表だけ横に転がす（13.3）
- **2列にするのは札の幅が 44rem 以上のとき**（左 16rem 固定・右が残り。窓幅ではなく札の幅の container query で切る）。
  未満は**1列**になり、詳細が選択肢の並びの下へ回る。761px 以上の窓で札が狭いときも、狭い画面の板の中も同じ1列の形
- 並べ替え・`preview`・複数選択・1問ずつの決まりは `docs/architecture/display.md` 4.2「各表示物」
- **操作の行（戻る・次へ / これで答える）は札の下端に固定し、選択肢の側が札の内側で転がる。** 1024x768 でも
  「次へ」が転がさずに押せる。札の高さの上限はメインビューの内寸から進み具合の帯を引いた高さ
- **枠と地は `--state-warn` の系統**（いまの質問の札と同じ。新しい色は足さない）
- **キーはお伺いにフォーカスがあるときだけ効く**（グローバルなショートカットは持たない）: 1〜9 で選ぶ
  （複数選択は切り替え）、Enter で「次へ」/「これで答える」。押せる口にはキーを字で添える
- **フォーカスは勝手に移さない**（打っている途中の字を奪わない）。入力欄の上の帯に「お伺いへ」の口を置き、
  押すとお伺いの最初の選択肢へフォーカスを移す。帯の字は、質問なら「↓ <名前> が質問しています。下の選択肢から
  選ぶか、ここに書いて答えてください」、許可なら「↓ <名前> が実行の許可を待っています」
- **札が窓の外にあるあいだ、メインビューの下端に「お伺い ↓」の口を浮かべる**（2026-10-10 利用者決定）。答え待ちが届くと札まで送る動きはそのままで、
  それでも札が見えない（上へ転がした・本文が伸びた）ときに気づけるようにする。字は「お伺い ↓」、枠は `--state-warn`、地は面に `--state-warn` を
  薄く混ぜた色（新しい色は足さない）、高さは 24px 以上で、領域の下端の右寄りに貼り付く。押すと札まで送り、フォーカスは移さない
  （移すのは入力欄の上の帯の「お伺いへ」だけ）。札が一部でも見えたら消える。出すのは広い画面（761px 以上）の最新のやり取りで答え待ちがあるときだけで、
  過去のやり取りを見ているあいだと狭い画面（札は入力欄のすぐ上にある）では出さない
- **サーバとの接続が切れているあいだは、入力欄の上の同じ帯に切断の旨を出す**（字は `--state-ng`、口は持たない。答え待ちの帯より先に出す）。
  送るボタンは枠だけの無効にし、下書きと添付画像は残す。出すのは接続が一度切れてから `open` に戻るまでで、初回の接続中は出さない
  （文言は `docs/architecture/display.md` 4.2「各表示物」）
- **会話が終わったあとも、入力欄の上の同じ帯に終了の旨を出す**（字は `--state-ng`、口は「新しく始める」のアウトラインのボタン1つ。切断の次、答え待ちの帯より先に出す）。
  送るボタンは切断のときと同じ無効の見た目にし、下書きと添付画像は残す
- **質問の自由入力は入力欄が受ける**（プレースホルダ・「答える」の字は `docs/architecture/display.md` 4.2「各表示物」）。
  許可のときの入力欄は、ふつうの下書きのまま
- **答え待ちの質問のあいだ、送信ボタンは塗りを外す。** 自由入力の字があるときだけ「答える」で塗る（お伺いと
  主役を取り合わない）。許可のあいだは「中断」のまま（塗らない）
- 待っている時間のために、答え待ちが届いた時刻を状態に持たせる（状態の `pending` の要素を `StampedPendingAsk`
  にし、`pending-changed` を畳んだ時刻を `askedAt` に打つ。駆動とイベントの `PendingAsk` は変えない。
  状態の形が変わるので `PROTOCOL_VERSION` を上げた。`docs/architecture.md`「版と互換」）
- 答えた質問の記録は、いまのまま渡したあとのレポートの札に残す（許可の答えは残さない）

**狭い画面（760px 以下）では、この札を本文に出さず、入力欄のすぐ上の答え待ちの札で答える**（2026-10-09 ユーザー決定。
札の形・択の数ごとの答えのボタン・「ほか n」の出どころは 13.9「狭い画面（760px 以下）」）。入力欄の上の「お伺いへ」の帯も出さない
（答え待ちの札がその場所に見えている）。答え待ちの札の「詳しく」を押すと、下から上がる板の中にこの札を**1列の形**で出す:

- 上から、頭（「お伺い」のチップ・種類・`header`・「n / N」）・問いの文・添え書きの背景と判断の軸・選択肢の縦の並び・
  選んでいる選択肢の詳細（`description`・`preview`・良い点と悪い点・戻せない印・図）・軸 × 選択肢の表、の順に1列に積む。
  詳細は選択肢の横ではなく**選択肢の並びの下**に回し、選ぶ選択肢を替えると詳細が入れ替わる
- 選択肢は板の幅いっぱいの行（高さ 44 以上・番号つき）。押すと選ぶだけで、板の下端の「これで答える」（高さ 44）で答える
  （答え待ちの札のボタンと違い、詳しく読んでから答える場所なので押した瞬間には送らない）。答えたら板を閉じる
- 詳細と表は高さを切らず板の中で転がす（`preview` を途中で切らない）。表が板の幅に入りきらないときは表だけ横に転がす（13.3）
- 戻せない選択肢の印は字を添える（13.1 原則5）

#### 始め方の一覧

**迎える局面のメインビューに、見出し「何から始める？」・リード・おすすめの札3枚・「ほかの始め方」を出す**
（`Welcome`。2026-10-04 決定。見本は `docs/history/mockup/welcome-cards-2026-10-04/` の案A。書体はいまの
変数のまま）。

- **札**は3枚まで・3列（`1.3fr 1fr 1fr`。1枚のときは1列、2枚のときは `1.3fr 1fr`）・間 12px・角丸 14px・
  最小の高さ 196px。幅が狭いとき（メインビューの幅が 40rem 以下）は1列に積む。中身は上から、ID（等幅・
  `--accent`）・題（3行まで。バッククォートで囲んだ字は等幅）・顔（18px）と理由の1行（12.5px）・
  区切り線の下にキーの印（1・2・3）と「始める →」のボタン。理由が無い札は理由の行を出さない。
  顔が無いパックは顔を出さずに理由だけを出す
- **1枚目は「いちばんのおすすめ」**: ID の横に印を付け、`--accent` の枠・`--surface-accent` の地・
  塗りのボタン・題 15px。ほかの札は題 14px で、ボタンは輪郭だけ（hover で塗りになる）
- **札の元**は、状態の `recommendation` の並び（作り方は下の「おすすめの札の中身」）。**前回の続き**は札の1枚
  として並ぶことがあり、ID の席は前のセッションの見出し・題は前のセッションの残り（`report` の `sessionRemaining`。切り替え画面に配る `SessionDigest` の `remaining`）。
  **前のセッションは、同じ作業ツリー（`cwd` が同じ）・同じパック・同じモードの最新のセッション**で、
  同じ作業ツリーに無ければ札を出さない（別の作業ツリーのセッションから札は作らない。2026-10-10 決定）。
  独立の群は持たない。**タスク**の札は、ID と要約（題）。空いた枠と、`recommendation` が空のあいだは
  既定の並び（前回の続き → タスク一覧のうち着手できる〔`TaskReadiness` が `ready`〕未着手を上から）で、
  理由なしに埋める。理由が届くと並びと理由を差し替える
- **「始める」とキー 1・2・3 は、入力欄を経由せず依頼の文をすぐ送る**（「<タスクの ID> に着手して」
  「前回の続き: <残り>」）。入力欄の下書きには触らない
- **ほかの始め方**: 「自分で書く」（`/`。入力欄へフォーカスを移す）・「タスクの一覧から選ぶ」（タスクの
  モーダルを開く）・「前のやり取りを見る」（`←`。切り替え画面〔13.9〕を開く。いまのセッション以外の行が一覧にあるときだけ出す。別の作業ツリーの行だけでも出す）
- **キーが効くのは、フォーカスが入力欄・ほかの入力の中になく、重なる面が開いておらず、お伺いが出ていない
  ときだけ**（打っている途中の字を奪わない。お伺いの 1〜9 と重ならない）。修飾キー付き・IME の変換中も
  効かせない
- タスクも前回の続きも無いときは札を出さず、見出しと「自分で書く」を大きく出す
- **選ばないと進めない画面にはしない**（`docs/requirements.md` 2.2）。入力欄はいつもどおり使える
- キャラクターの迎えの一言は、メインビューではなく吹き出しに出す（中身はコードに書かない。原則4・
  出し方は `docs/architecture/display.md` 4.2「出力の分離（セリフと詳細）」）

#### おすすめの札の中身

**始め方の一覧に並べる候補の並びと理由の1行（おすすめの札。`recommendation`）は、サーバが背景の使い捨ての
`query()`（`haiku`）1回で作り、状態の `recommendation` で配る**（2026-10-04 決定。見本は
`docs/history/mockup/welcome-cards-2026-10-04/` の案A）。ここに書くのは中身の作り方だけで、札の形は書かない。

- **候補**は「前回の続き」1つと、タスク一覧のうち着手できる（`TaskReadiness` が `ready`）未着手を一覧の順に
  20件まで。タスクは ID・要約・そのタスクを依存に挙げている未完了のタスクの ID を渡す。
  20件を超えて渡せなかった着手できるタスクがあるときは、その件数を依頼の文面の末尾に添え、候補の印にも
  入れる（渡せていれば件数は印に入らない）。画面には出さない
  「前回の続き」は**中身を渡さない固定の候補**で、前のセッションの要約（`sessionSummary`）も、それが有るかも
  渡さない（`docs/coding-standards.md`「会話内容の扱い」）
- **並びと理由は tsukumo が決める。** 3枚まで。理由は「効き目」「軽さ」「つながり（前の作業の続き）」の
  どれかが分かる言い方の1行（40字まで）で、数を競わせる言い方（「最速」「いちばん多い」など）はしない。
  「前回の続き」を選ぶときの理由は「つながり」
- **契機**はタスク一覧が届くたびで、迎える局面かどうかは見ない。**候補の並びが前回と同じなら問い合わせず**、
  `~/.tsukumo/recommendation.json`（候補の並びと札の組を新しい順に8件まで）から配る。起こし直した直後・
  起動し直した直後もここから即座に届く
- **届くまでは既定の並び**（前回の続き → 着手できる未着手の上から）で、理由は出さない。候補が変わって
  キャッシュに無いときは空の並びを配って既定へ戻し、問い合わせの結果で差し替える。失敗・時間切れ
  （60秒）では何も配らない。**画面を開く流れとセッションを起こす流れはこの問い合わせを待たない**
- 「前回の続き」が選ばれても、画面が前のセッションの残りを持たない（同じ作業ツリーの前のセッションが無い・残りが空）
  ときはその札を外す。札のタスクがいまの着手できる未着手に無いときも外す
- 迎えの吹き出しの出し方・書けなかったときの扱い・札の名前の差し込みは
  `docs/architecture/display.md` 4.2「出力の分離（セリフと詳細）」

# 画面のデザイン: 部屋の名前とセッションの切り替え

ステータス: **正典**。入口は `docs/architecture/screen-design.md`（画面のデザインの全体）。

責務: 帯の部屋の名前、セッションの札、切り替え画面、会話の画面の帯とサイドバーの下端の帯。
読む時: 帯の名乗り・セッションの切り替え・サイドバーの下端の帯に触るとき。
直す時: それらの形や振る舞いを変えたとき。

## 13. 画面のデザイン

### 13.9 画面のナビゲーション

#### 部屋の名前

**ビューのポート1つ＝部屋1つ**で、和の色名12個をポートの並び順に割り当てる（
`src/browser/components/domain/screen-nav/domain/room.ts`）。7327 から順に
空色 / 若葉 / 菜の花 / 夕焼け / 藍 / 藤 / 朱 / 灰 / 若草 / 海 / 桜 / 墨 で、表示は「〜の間」
（語彙は読みにくい名前を避けている）。

- **語彙はコードに置く**（キャラクターパックの定義ファイル側ではない）。**部屋はキャラクターの
  持ち物ではなく、起こした tsukumo の場所**——同じ部屋でキャラクターを入れ替えても部屋は
  変わらないので、`docs/architecture/code-placement.md` 原則4（キャラクターの中身をコードに書かない）の対象外。置き場が
  `src/shared/` の直下なのは、用語集に載る語だから（`docs/architecture.md`「`lib/` と `utils/` に置く基準」の手順1）
- **語彙の外のポートはポート番号をそのまま名乗る**（13個め以降・`TSUKUMO_VIEW_PORT` で遠い番号を
  指したとき・OS まかせの `0`）。名前が無いことより、どの番号の部屋かが分かるほうが役に立つ
- **印（セッションの目印）はポート番号のまま**（4.8 / `docs/requirements.md` 4.8「鍵」）。名前は
  画面のためだけのものなので、語彙を入れ替えても過去のセッションは迷子にならない。環境変数で
  名前を指定する口も作らない
- **出すのは帯の左端（顔の右）1箇所だけ**。名前の右に短縮IDを添えて1つの札に
  する（下の「セッションの札」）。狭い画面は帯が無いので、顔と部屋の名前と短縮IDは引き出しの名乗りの行に出す（主の字は部屋の名前。
  13.9「狭い画面（760px 以下）」）
- **主の字は作業ディレクトリの名前で、部屋の名前は補足**（旧い決定は
  `docs/history/decision.md`）。ポート番号や色名では何の仕事の窓か読めないため、
  `basename(cwd)`（手続き `repository.projectName`）を主に出し、部屋の名前はその右に一段下げて添える。
  **同じディレクトリで2つ起こしたときの見分けは、ポートがずれて変わる部屋の名前と短縮ID**
  （作業ツリーならディレクトリ名そのものが違う）。名前が届く前・取れないときは部屋の名前が主の字
  のまま。長い名前は帯を押し広げず末尾を切り、全文は `title`（「<名前> · <部屋の名前>」）で読める。
  部屋の名前がポート番号のときは、その番号が補足にも `title` にも出る
- **切り替え先の一覧は部屋で絞らない**（「いまの部屋のものだけ」にはしない。
  理由は `docs/history/decision.md`）。絞る鍵は目印を除いた印（パック・モード。`listMarkedSessions`）で、
  部屋＝ポートは起動順で決まる番号なので、行を見分けるのは**部屋の名前ではなく作業ツリーの名前**
  （`SessionChoice.worktree`）。**部屋の名前は行に出さない**。行は作業ツリーの名前に加えて短縮IDと見出し（SDK の
  `summary`）で見分ける（ユーザーの指摘「`/clear` するとセッションIDが変わり、
  行が増えていくので、どこで何をしていたかを辿れない」）。行の形は下の「切り替え画面」

#### セッションの札

**プロジェクト名（と一段下げた部屋の名前）の右に、いまのセッションの短縮IDを添えて「tsukumo-2 浅葱の間 - FA」と並べ、短縮IDを押すと
切り替え画面が開く**（見本 `docs/history/mockup/session-switch-2026-09-27/HD-4-IdTag.png`）。
**押せるのは短縮IDだけで、部屋の名前と「-」はボタンの外**。
**プルダウンにはしない**——短縮IDは押せるボタンで、選ぶ面は下の「切り替え画面」。

- **短縮IDはセッションID（UUID）の先頭2字を大文字にしたもの**。切り替え画面に並ぶ中で2字が重なったもの
  だけ3字に伸ばす（`docs/glossary.md`「短縮ID」）。IDが分かる前（新規に起こして
  最初の依頼を送る前）は短縮IDの場所に「新規」と出し、同じように押すと切り替え画面が開く
- **形**（値は見本の inline style から）: 短縮IDのボタンは角丸 10px。ふだんは枠も地も無く字だけに見せ、
  ホバーと切り替え画面を開いている間は `--accent` の枠と `--surface-accent` の地を敷く。プロジェクト名は
  明朝の太字 18px（`--font-heading`。14rem で切る）、部屋の名前は `--ink-quiet` の小さい字（`--font-secondary`）、区切りの「-」は `--ink-quiet`、短縮IDは等幅 15px で差し色寄りの字に
  点線の下線（押せる札だと分かるように）
- **短縮IDのボタンへのホバー（とキーボードのフォーカス）で、札の真下に一行を重ねる**（部屋の名前や「-」に
  乗っても出さない）: 「セッション FA · 9/27 09:12〜 · 依頼 3」と、控えめな字の「押して切り替え」。明るい地（`--ink`）に暗い字（`--ground`）。
  始まった時刻は一覧（`SessionChoice.startedAt`）から、依頼の数は切り替え画面と同じ手続きで取りに行く
  （出るまでは依頼の数を省く）。いまのセッションが一覧に無いとき（記録前・古すぎる）は時刻を省く
- 読み上げの名前は「セッション <短縮ID>。押すとセッションを切り替える画面を開く」（見本の `aria-label` のまま）
- **自分がどの部屋かの正典は、ページを配っている URL のポート**（ブラウザは `location.port` を
  読む）。サーバから送り直してもらう値ではないので `SessionState` には乗せない

#### 切り替え画面

**札を押すと開くモーダル**（⌘K のショートカットは持たない）。**左に探す欄と日付で区切ったセッションの一覧、右に選んで
いるセッションの要約と切り替えのボタン**（見本
`docs/history/mockup/session-switch-2026-09-27/HD-5-Switcher.png`。値は同じ名前の `.dc.html` から）。

- **箱**: 幅 1040px・高さ 600px（窓より大きくしない）、帯の下に少し空けて横の中央。地 `--surface`・
  枠 `--rule`・角丸 18px・深い影。背景は `<Dialog backdrop="dim">`
- **上の段**: 虫眼鏡・探す欄（「ID・依頼・タスク番号で探す」）・右端に点線の枠の「＋ 新しいセッション」
  （`session.startNewSession`。キャラクターもモードもいまのまま、続きを探さずに新規で起こす）
- **左の一覧**（幅 430px）: **今日 / 昨日 / それより前**の見出しで区切り（最終更新の日で分ける）、
  行は**2段**で、1段目は「短縮ID・見出し・（「いま」または「別の窓で使用中」）」、2段目は見出しの下に
  「作業ツリーの名前・時刻」（見出しが作業ツリーの名前や時刻に押されて縮まないようにする）。見出しは SDK の `summary`（`customTitle` → 自動要約 → 最初の依頼、の順に
  決まる表示用の題）で、無ければ「（題なし）」。時刻は今日・昨日なら `HH:MM`、それより前は `M/D HH:MM`。
  **いま出しているセッションの行には「いま」を添え、時刻は始まった時刻に「〜」**。選んでいる行は
  `--accent` の枠と `--surface-accent` の地（色だけで伝えない）。**一覧に並ぶのは、リポジトリの全作業ツリーの
  同じキャラクターパック・同じモードのセッション**（ポートの目印では絞らない）で、
  **作業ツリーを問わず新しい順**に並べて10件（`MAX_SESSION_CHOICES`）で切る
  （いまの作業ツリーの行が10件に入らないとき、始め方の一覧の「前回の続き」の札は出ない）。**一覧は「この作業ツリー」の塊を上、「ほかの作業ツリー」の塊を下に分け、
  各塊の中は上の日の区切り**。塊の見出しは両方に行があるときだけ出す。**各行の
  2段目に作業ツリーの名前**（作業ツリーが1つのときも出す）（`cwd` の末尾のディレクトリ名。取れなければ `gitBranch`。どちらも無い
  セッションは載せない。長い名前は末尾を切り、全文は `title`）を `--ink-quiet` の等幅で添える。
  別の作業ツリーの行を選んでも、いまの作業ツリーで続きから起こす
- **別の窓で使用中の行**（`docs/requirements.md` 4.8「別の窓で使用中のセッション」）は隠さず、「いま」の位置に
  「別の窓で使用中」を `--ink-quiet` の字で出し、行の字も `--ink-quiet` に落とす（字で伝え、色だけに頼らない）。
  その行は ↑↓・押す・2回押す・Enter のどれでも選べず（`aria-disabled`）、開いた直後の選びも飛ばす。
  使用中かは開くたびに聞き、届くまでは全行を選べるまま描く。選んだ先が起こす直前に使用中と分かって
  断られたら、切り替え画面を開き直す（聞き直すので、その行が使用中で出る）
- **探す欄が引くのは短縮IDと見出しだけ**（大文字小文字を区別しない部分一致。タスク番号は見出しに
  書かれていれば当たる）。**依頼の全文はブラウザへ渡さない**（
  `docs/coding-standards.md`「会話内容の扱い」の経路を増やさない）
- **右の欄**: 大きな短縮ID（等幅 30px）・「始まり – 最終更新 · 依頼 N」・右端にいまのキャラクターの顔と
  名前、その下に「このセッションの要約」の見出しと**複数段落の要約**（段落は改行で区切る）と、
  残り（`sessionRemaining`）があればそのあとに「残り：」を頭に付けた一段控えめな字の段落、「最後のひとこと」の箱（`--ground` の地に「<名前>「<セリフ>」」）、
  右下に「FA に切り替える」のボタン（`--accent` の地）。**要約は `report` の `sessionSummary` を
  transcript から読み戻したもの**（`docs/architecture/display.md`「出力の分離（セリフと詳細）」）で、一度も書かれて
  いなければ、直近5ターンの `conclusion` の1文目を箇条に並べたものを出し、通った `report` がまだ無いときだけ「要約はまだ無い」と出す。関わったタスクの札は出さない
- **右の欄の中身（依頼の数・要約・残り・最後のセリフ）は選んだ1件ぶんだけ取りに行く**（手続き
  `sessionDigest.read`）。一覧を作るたびに全件の transcript を読まないのは、transcript が1件で
  数 MB になり（実測で中央値 1.5MB・上位1割 3.9MB 以上）、起こすたびに10件読むと起動と切り替えが重くなるため。
  サーバは一覧に載ったセッションといま出しているセッションのIDだけを読む
- **キー操作**: ↑↓（Ctrl+P / Ctrl+N でも）で選び、Enter で切り替え、Esc で閉じる（下の段にキーの案内）。開いた直後は、並びの先頭から数えて、いまと使用中を除いた最初の行を選ぶ。行を押すと選び、2回押すと切り替える。
  **いま出している行を選んで Enter しても起こし直さない**（ボタンは「いま出しているセッション」で押せない）
- **ターン進行中か、委譲先が動いている間は切り替えも「＋ 新しいセッション」も押せない**（起こし直しなので。理由は `title` に
  定型文）。開くこと・選ぶこと・読むことはできる
- **狭い画面（760px 以下）は2列を縦に積む**（一覧が上、要約が下）。キーの案内の段は畳む。開く口は
  引き出しの名乗りの行の短縮ID
- **`summary`・要約・最後のセリフは `127.0.0.1` のページに出すだけ**（ログ・ファイル・外部へは出さない。
  `docs/coding-standards.md`「会話内容の扱い」。メインビューが会話を出すのと同じ扱いで、
  複製にはあたらない）

#### 会話の画面の帯とサイドバーの下端の帯

**会話の画面だけ、帯からいまの作業の札とモデル・effort・許可モードを外し、いまの作業は
メインビューの進み具合の帯と知らせの行（13.13）が持ち、3つの操作子はサイドバーの下端の帯に移す**（見本は
「組み合わせ — 案B 改 2 の上の行 ＋ 目次の枝（ふだん）」の `<header>` とサイドバーの `<aside>`）。
ほかの画面の帯は、上の表のまま全部を持つ（ほかの画面にはサイドバーが無いため）。狭い画面は帯もサイドバーも出さず、
同じものを頭と引き出しが持つ（13.9「狭い画面（760px 以下）」）。会話の画面に浮かぶ札は置かない（旧い形は `docs/history/decision.md`
「screen-design.md 13.9 会話の画面の浮かぶ札（2026-10-02 に覆した記録）」と「screen-design.md 13.13 作業の地図・
会話の画面の浮かぶ札・レポートの進み具合（2026-10-02 に覆した記録）」）。
**中くらいの窓幅（761〜1100px）では、3つの操作子をサイドバーの柱に縦に並べる**（13.4）。

| 置き場所                             | 形                                                                                                                                                                                                                             |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 帯の仕事・雑談の門                   | ほかの門と同じ文字のタブ。会話以外の画面では、戻り先のモードの門に差し色の点を添える（13.9「帯に何を置くか」）                                                                                                                 |
| 帯の右端（会話の画面）               | 歯車だけ（`margin-left: auto` で右端へ寄る）                                                                                                                                                                                   |
| メインビュー（進み具合の帯・知らせ） | いまの作業の札は置かない。札の右の側の上端の進み具合の帯が段・走っているツール・経過・依頼の手順の一覧を持ち、過去のやり取りを見ているあいだはやり取りの列の頭の知らせの行が1つだけ出す（13.13「進み具合の帯」「知らせの行」） |
| サイドバーの下端の帯                 | 1行に、左からモデル・effort・許可モードの口の組、右寄せでコンテキストの目盛りとプラン使用量の2つの円                                                                                                                           |

- **モデル・effort・許可モードの口は絵だけ**で、絵の上に透明の `<select>` を重ねる（押すとブラウザの
  選択肢が開く。キーボードの操作・読み上げはブラウザに任せる）。名前は `aria-label` と `title` に
  「モデル Opus」「effort Medium」「許可モード 自動判定」の形で渡す。絵はモデルが頭文字を丸で囲んだ印、
  effort が段の数だけ伸びる棒（いまの段まで塗る。選べないときは全部を弱い色）、許可モードが盾の形
  （lucide の `ShieldQuestionMark` / `ShieldHalf` / `ShieldCheck` / `ShieldEllipsis` / `ShieldOff`。
  「全部許す」だけ `--state-ng`）。送るコマンドと「押した側へ先に倒さない」は上の「動き方の操作子」のまま
  （値と呼び先は `stores/model-permission.ts` の `useModelPermission` を帯と共有する）
- **コンテキストの目盛り**は「文脈 N%」と幅 56px の棒で、棒の上の縦の線が自動圧縮の始まる位置
  （`(使っている量 + 自動圧縮まで) / 窓の大きさ`）。**プラン使用量の円**は5時間枠と7日間枠を、真上から時計回りに
  塗った扇と割合で並べる。警告の境目はそれぞれの札と同じ（コンテキスト 70%・プラン使用量 80%）
- **目盛りと円はどちらも押せる口で、押すと帯の真上に詳しい面が重なって開く**（タスクの区画を押し下げない）。
  面の中身は下の「使用量の行」の札と「プラン使用量の札」そのもの。外側を押す・Esc・もう一度押すで閉じる
- 目盛りと円は1つの塊で右へ寄せ、サイドバーが狭くて1行に入らないときは塊ごと次の行の右端へ折り返す

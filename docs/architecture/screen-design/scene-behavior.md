## 13. 画面のデザイン

### 13.13 会話の画面の局面

#### 場面ごとのキャラクターの振る舞い

**舞台の吹き出し・表情・動きが、場面ごとにいま何をしているか**（実物で確かめた）。
吹き出しは `shownReaction`（反応）と `speeches`（今のターンの `speak`）、表情は反応の行か直近の `speak` の
表情（`speechExpression`）、動きは `resolvePortraitMotion` が決める。どの場面でも、押して留めたセリフが
あれば表情はそちらが勝ち、過去のやり取りを見ているあいだは反応を出さずそのやり取りの最後のセリフと表情に戻る。
吹き出しに何が出るか・出ないときはどうするか・いつ消えるかは
`docs/architecture/display.md` 4.2「出力の分離（セリフと詳細）」が正典で、下の表は見た目の早見表。

#### 舞台の「手元」の行

**手順を持つターンのあいだ、舞台の吹き出しの下に「手元」か「待ち」の1行を出す**（`components/page/conversation/components/main-view/stage-activity.tsx` の `StageActivity`。狭い幅では吹き出しの下の `PhoneActivity`）。字は紙の計画の今の段と同じもの（`domain/work-activity.ts`）を読み、答え待ちは「待ち」、ほかは「手元」の札を頭に置く。
広い幅で、紙が働いている回の計画を出しているあいだは、紙の「いま」の行と同じ内容なので出さない（`useWorkPlanOnPaper`）。過去の回を見ているあいだ・計画を持たない作業・ターンの外の背景の待ちでは出す。

- 字は今のフェーズでいま走っている手順の文（作り方は `components/page/conversation/domain/tool-narration.ts`。表に無い道具は等幅の「名前 要約」）。メインが `report` の引数を書いている途中は「レポートを書いています」、ターンが終わってバックグラウンドタスクだけが動いていれば「背景で <説明>」
- ワークフロースクリプトの中の手順は、走っている agent の手順を出す（SDK はメインの流れに流さないので、`PreToolUse` のフックから `workflow-step-started`、`PostToolUse`・`PostToolUseFailure` のフックから `workflow-step-finished` にして運ぶ）。目視は疑似セッションの場面 `workflow-steps`
- 手順を持たないあいだ（迎える・渡す・雑談）は出さない

#### バックグラウンドタスク

**ターンが終わったあとも claude が背景で動かしているもの（`run_in_background` の Bash・背景の
サブエージェントなど）を、紙の判定の行（「背景で働いている」）と舞台の「手元」の行に出す**（用語は `docs/glossary/turn.md`
「バックグラウンドタスク」）。

- **数えるもの**: SDK の `system` / `background_tasks_changed` に載る全員から、`ambient`
  （SDK が「活動の印から外せ」と言うもの。見張り役など）を除いたもの。知らせは**顔ぶれ全体を
  毎回運ぶ**ので、状態（`backgroundTasks`）は届くたびに丸ごと置き換える。`task_started` /
  `task_notification` などの始まり・終わりの知らせは顔ぶれを数えるのには使わない（対を数えると、取りこぼしで
  「動いている」が居残る）。`task_notification` は背景の Bash の所要時間の終わりにだけ使う
- **終わると消える。** 顔ぶれが空の知らせで判定の行は元に戻る。
  `session-ended` でも空にする（claude のプロセスと一緒に終わる）
- **続きの報告**: バックグラウンドタスクが終わると、claude は依頼なしで続きを報告するターンを始める
  （`docs/requirements.md` 4.1。サブエージェントの `SendMessage` が届いたときも同じ）。tsukumo は
  これを**記録を持たない続きのターンの始まり（`turn-resumed`）** として扱う。
  入力欄の経過時間も測り直す。**吹き出しは空にせず、前のセリフと表情を残したまま続きのセリフを
  積む**（空にすると、通知が届くたびに「（まだ発話がありません）」に戻った）。
  **紙には新しいやり取りを立てず、元の依頼のやり取りに積む**（依頼の記録が無いため）。
  続きの報告がそのやり取りの締めの本文になり、前の本文は中間レポートに回るか落ちる
  （`src/browser/components/page/conversation/domain/main-view/main-view.ts` の選び方のまま）。続きのターンが走っている間は、**そのターンで届いた
  本文だけ**を出さない（まだ伸びうる本文を出さない、と同じ理由。前の SDK ターンで確定した本文は
  出したまま。`docs/architecture/display.md` 4.2）
- **立ち絵の「たいくつ」（`bored`）は自動では出さない。** 表情の源は `speak` の1つだけ
  （`docs/requirements.md` 4.3）で、バックグラウンドタスクの間に表情を上書きする経路は持たない。長い
  待ちを背景に回すときに `bored` を選ぶのはキャラクター自身
- 見え方は疑似セッションの場面 `background-task`（`TSUKUMO_FAKE_SCENE=background-task`）で
  確かめられる。ターンが終わってから約15秒、背景で1件動き続けたあと、続きのターンが走る

#### 採らなかった案

- **局面ごとに舞台と紙の配置を変える**（尋ねるで紙を引っ込めるなど）。器が姿勢を変えるのは送ったときと閉じたときだけで、
  ターンの途中で配置を動かすと読んでいた場所や押そうとしていたボタンを見失う（ADR 0057 論点 2）
- **答え待ちで紙の中身ごとお伺いに替える。** ターンの途中で中身が替わり、驚かせない約束を破る。紙の中身は引くだけにする
- **進行の計測値をトークン消費の画面か成果の画面に出す。** トークン消費の画面は何にいくら使ったかを、成果の画面は
  利用者の仕事の成果を見る場所で、どちらも tsukumo 自身の使い心地の数とは中身が合わない。比べたいときに
  手元で読めれば足りる

## 13. 画面のデザイン

### 13.13 会話の画面の局面

#### 場面ごとのキャラクターの振る舞い

**キャラビューの吹き出し・表情・動きが、場面ごとにいま何をしているか**（実物で確かめた）。
吹き出しは `shownReaction`（反応）と `speeches`（今のターンの `speak`）、表情は反応の行か直近の `speak` の
表情（`speechExpression`）、動きは `resolvePortraitMotion` が決める。どの場面でも、押して留めたセリフが
あれば表情はそちらが勝ち、過去のやり取りを見ているあいだは反応を出さずそのやり取りの最後のセリフと表情に戻る。
吹き出しに何が出るか・出ないときはどうするか・いつ消えるかは
`docs/architecture/display.md` 4.2「出力の分離（セリフと詳細）」が正典で、下の表は見た目の早見表。

- **黙って立つだけの場面の埋め方**: 埋めるのは依頼を待つ間と切り替え画面から再開した
  直後の2つで、雑談はいまのまま。動きは足さない。中身と落とし先の正典は
  `docs/requirements/expression.md` 4.3「黙って立つだけの場面の埋め方」、出す条件は
  `docs/architecture/display.md` 4.2「出力の分離（セリフと詳細）」

- **立ち絵に触れる**（仕事の画面の舞台の立ち絵だけ。雑談の「つつく」は別で変えない）:
  押すと、留めたセリフを解き、従っているセリフが流れの中にあればそこまで流れを送り
  （`scrollIntoView` の `nearest`。動きを減らす設定では滑らせず送るだけ）、そのセリフの出方と立ち絵の1回の動きをもう一度掛ける。
  従っているセリフが入力欄の上の定位置の声のときは、流れを送らない。
  押せることは `role="button"`・`tabIndex=0`・読み上げの名前「<キャラクターの名前>（押すと、いまの一言へ戻る）」と、指の形のカーソルで示し、
  キーは立ち絵にフォーカスがあるときの Enter と Space だけにする（画面のどこからでも効くキーは足さない）。
  入力欄に字があるあいだは、立ち絵が続く動きを止めて傾きと位置を少しずらす「聞く姿勢」（`listeningPose`）を取る。
  フォーカスだけでは取らず、1回の動きの最中は終わってから取り、動きを減らす設定では取らない
  （`docs/architecture/adr/0063-character-voice-place-and-bearing.md` 論点 7）

#### 採らなかった案

- **局面ごとに4領域の比率を変える**（作業中はキャラビューを大きく、読むときはメインビューを大きく）。
  読んでいた場所や押そうとしていたボタンが動いて見失う
- **答え待ちでメインビューの中身ごとお伺いに替える。** ターンの途中で中身が替わり、驚かせない約束を破る
- **お伺いを入力欄の領域に出す**（答えるのは入力の動作、という理由）。下段の高さ
  （1440x900 で約 276px）に選択肢と `preview` が入りきらない
- **読む面を一時的に広げるボタン**（メインビューを最大にする）。仕切りのドラッグで足り、比率が2系統になる
- **進行の計測値をトークン消費の画面か成果の画面に出す。** トークン消費の画面は何にいくら使ったかを、成果の画面は
  利用者の仕事の成果を見る場所で、どちらも tsukumo 自身の使い心地の数とは中身が合わない。比べたいときに
  手元で読めれば足りる

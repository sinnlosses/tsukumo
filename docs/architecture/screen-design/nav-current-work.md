## 13. 画面のデザイン

### 13.9 画面のナビゲーション

#### いまの作業

**tsukumo がいま何をしているかを、帯のまん中の札1つで見せ、押すとその依頼の手順が開く**
（2026-09-23 決定。サイドバーの「いま何をしているか」の区画と、帯の右端の答え待ちの印を
置き換える。用語は `docs/glossary.md`「いまの作業」「依頼の手順」）。

**札**は `<button type="button" aria-expanded aria-controls>` で、字は
「印・状態の語・（あれば）縦線・今の段・（あれば）縦線・実行中の手順の要約」の順に1行で並ぶ
（今の段は下の「ワークプラン」）。要約は
`ツール名: 対象`（`summarizeToolInput`。`src/browser/domain/tool-summary.ts`）で、入りきらなければ
末尾を「…」で切る。状態の語は6つで、上の行ほど強い:

| 語           | いつ                                       | 見た目                            | 右の要約                                                                                                                                                                 |
| ------------ | ------------------------------------------ | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 止まっている | `endedReason` がある                       | 字と印が `--state-ng`             | 出さない                                                                                                                                                                 |
| 答え待ち     | `pending` が空でない                       | 字と印が `--state-warn`           | 先頭の答え待ちが質問なら**質問の要約**、許可要求なら「レポートを書いています」（下）か実行中の手順があれば出す（2026-09-23 決定。下の「答え待ち」）                      |
| 作業中       | `turn.kind === "running"`                  | 枠と印が `--accent`               | メインが `report` の引数を書いている途中（下の「レポートを書いている途中」）なら「レポートを書いています」、それ以外は実行中の手順のいちばん新しいもの。無ければ出さない |
| 振り返り中   | `diaryWriting.kind === "writing"`（13.10） | 作業中と同じ                      | 「<日付>の日記を書いています」（日付は「9月23日」の形。2026-09-25。会話のターンと並んで書くので、作業中より下に置いた）                                                  |
| 背景で作業中 | `backgroundTasks` が空でない               | 印だけ `--accent`（枠は変えない） | バックグラウンドタスクの要約（2026-09-23 決定。下の「バックグラウンドタスク」）                                                                                          |
| 依頼待ち     | どれでもない                               | 印は中抜き（○）、字は `ink-quiet` | 出さない                                                                                                                                                                 |

- **答え待ちの印は札にまとめる**（並べない）。「作業中」と「答え待ち」が並ぶと、どちらが
  いまなのかを読む側が決めることになる。答え待ちはターンの途中で作業が止まっている状態なので、
  札の語が入れ替わるのが事実どおり。狭い画面は札の代わりに頭の状態の語が「答え待ち」になり、答え待ちの札が入力欄の上に
  見えているので、≡ には印を添えない（13.9「狭い画面（760px 以下）」）
- **札は依頼待ちでも消さない。** 消すと帯の要素の位置がターンごとに動く。依頼待ちで押すと、
  前の依頼の手順が読める。**会話の画面だけは札を置かず、メインビューの進み具合の帯と知らせの行が
  同じことを持つ**（2026-10-02。13.13。下の「会話の画面の帯とサイドバーの下端の帯」）
- **札そのものは動かさない**（点滅も脈打ちもしない）。動くのは一覧の中の実行中の印だけで、
  `prefers-reduced-motion: reduce` では回さない
- **札に `aria-live` は付けない**（手順が変わるたびに読み上げると騒がしい）。答え待ちを知らせる
  のは、会話の画面のお伺い（13.13「お伺い」）と、状態が変わった1回だけを読み上げる別の領域
  （13.13「読み上げとフォーカス」）の仕事
- **API の不調（再試行中・利用上限・失敗の理由）は札に出さない**（2026-09-24 決定）。再試行中も
  作業は続いているので語は「作業中」のままで、知らせは入力欄の経過時間の行の枠が持つ
  （`docs/architecture/display/input-box.md`「入力欄」）。いつも見えている入力欄の行に寄せた。**会話の画面の仕事のときは、経過と再試行中は進み具合の帯が持ち、失敗の理由はレポートの頭の
  失敗の塊へ移し、入力欄の行に残るのは「利用上限に達した」だけにする**（2026-10-02。13.13「進み具合の帯」と
  13.13「失敗の塊」）
- **モックの札の頭にある名前（「tsukumo 作業中」）は置かない。** 左端の顔と部屋の名前が
  名乗っているので繰り返さず、その幅を要約に回す
  - **例外は雑談中の依頼待ちだけ**（2026-09-23 決定。13.7「モードの操作子はどこに置くか」）。
    「<名前> とおしゃべり中」は「誰と」おしゃべり中かを言っているので、他の3つの状態の語
    （止まっている・答え待ち・作業中）と違い名を省くと意味が通らない。答え待ち・作業中・
    止まっているは雑談中でもこの節の語のまま変えない
- **札の幅は帯の空きをつねに埋め、中身の伸び縮み（要約の有無・長さ、状態の語の違い）では
  変わらない**（`.current-work-toggle` は `width: 100%`。2026-09-23 決定）。**上限は 600px**
  で、それより広い空きは中央へ寄せる（見本の値）
- **札の外枠・丸・仕切りも見本の寸法に揃える**（2026-09-23 決定）: 高さ 34px・角丸 17px、地は
  `--surface-accent`、枠は `--rule` に `--accent` を 35% 混ぜた色。丸は 7px、周りの薄い輪は
  `currentColor` を 20% 透かした `box-shadow` で、マークの色（上の表の状態ごとの色）にそのまま
  従う。**輪は答え待ち・止まった・依頼待ちでも同じ作りで出す** — 輪そのものは状態を区別する
  新しい意味を持たず、既にある色分けの上に足す飾りなので、状態によって出し分ける理由が無い
  （13.1 原則5）
- **要約の字は見本の 12px ではなく既存の 13px（`--font-secondary`・等幅）に宛てる**。
  13.3 の段は 13px の等幅（ID・ツール名・キー）までしか無く、段を増やさない決定（13.3）を
  優先した。14px の見本を 13px へ寄せた `dispatch-send` と同じ判断

**答え待ち**（2026-09-23 決定。2026-10-03 に、許可と質問を1つにしたお伺い〔13.13「お伺い」〕へ行き先を揃えた。
それまでの「質問へ」と「入力欄の上で答えられる」は `docs/history/decision.md`「screen-design.md 13.9 いまの作業
（答え待ちの質問の「質問へ」と許可要求の「入力欄の上で答えられる」。2026-10-03 に覆した記録）」）:

- **答え待ちの先頭（`pending[0]`）が質問なら、札の要約は実行中の手順ではなく質問の要約になる**
  （許可要求は実行中の手順の要約のまま）。要約は**1問目の `header` をそのまま
  使う**——`AskUserQuestion` の入力の型で「最大12字」と決まっているので、`text` を切り詰める
  必要が無い。**2問以上あれば「ほか n問」を添える**（例: 「競合 ほか1問」）
- **押したときの一覧の中身は変わらない**（依頼の手順を開く）。答え待ちのあいだ（許可要求でも質問でも）は、
  見出しの下に **「お伺いへ」の口**を出す
- **「お伺いへ」を押すと**: 一覧を閉じ、キャラクター/トークン消費の画面を見ていれば会話の画面へ
  戻し（`stores/screen.tsx` の `navigateTo`）、過去のやり取りを見ていれば最新のやり取りへ戻し
  （`stores/turn-selection.ts` の `selectTurn`）、メインビューのお伺いの札までスクロールさせる。
  合図は **`stores/inquiry-jump.ts`** という小さな zustand の store 越しに運ぶ
  ——`browser/` の機能どうしは import できないため、「いまの作業」・知らせの行・入力欄の帯とお伺いの札が
  同じ store を読み書きする。持つのは「呼ばれた回数」と「フォーカスも移すか」だけで、お伺いの札はその値が
  変わるたびに `scrollIntoView({ block: "nearest", behavior: "smooth" })` をやり直す（新しい答え待ちが
  来たときと同じ経路）。フォーカスを移すのは入力欄の帯の「お伺いへ」だけ

**レポートを書いている途中**（`SessionState.sdkTurn` の `reportDrafting` が `drafting`）:

- メインが `report` の引数を書き終えるまで、その呼び出しは依頼の手順として届かない
  （`toRunningStepView` は `findLast(isRunningStep)` で拾うが、書いている途中の `report` はまだ
  手順に無い）。**放っておくと1つ前の手順の要約が残るか、要約が出ない**ので、`reportDrafting` が
  `drafting` のあいだは要約を「レポートを書いています」に差し替える
- **優先の順は、上の表の状態の強さと同じ列の中でだけ働く。** 答え待ちの質問・振り返り中・
  背景で作業中の要約はこれより上で決まっているので変えない。**答え待ちが許可要求のとき・作業中の
  ときだけ**、実行中の手順の要約より「レポートを書いています」を優先する
- `drafting` は同じ `toolUseId` の `report` か `tool-finished`（差し戻されて `report` が届かない
  ときもこちらは届く）、ターンの境目で `idle` に戻る

# 画面のデザイン: 「舞台と紙」の物差し

ステータス: **正典**。入口は `docs/architecture/screen-design.md`（画面のデザインの全体）。

責務: 「舞台と紙」（案A）に作り直す画面の6場面（迎える・頼む・待つ・答える・読む・戻る）ごとの合格の画・数の物差しと目標・手本の製品と、作り直す前の画面の値。紙・進み具合・舞台・書き手の物差しは姉妹の文書が持つ。
読む時: 「舞台と紙」の作り直しに手を付けるとき、作り直した画面が良くなったかを確かめるとき。
直す時: 物差し・目標・手本を変えたとき、作り直す前か後の値を測り直したとき。

## 何を物差しにするか

作り直したあとに「良くなった」と数と画で言えるよう、6場面ごとに合格の画と物差しを先に決める。
合格の画は見本 `docs/history/mockup/ui-rebuild-*/whole.html`（`ui-rebuild-` で始まるディレクトリは1つだけ）の場面で、**言葉と見本が食い違ったら見本が勝つ**。
下の「見本の値」は見本をその URL 引数と `bar=0`（上の試作の切り替えの帯を隠す）で開き、`scripts/capture/capture-view.ts --measure` で測った値。
目標は見本の値から少し余裕を引いて決めた。数で測れないものは見本と同じ場面を同じ幅で撮った画を並べて比べ、比べる点を「画で比べる点」の行に書く。

測る幅は 720×900・1400×900・1920×1080 の3つ。720 は縦1列の配置（`docs/architecture/screen-design/narrow-screen.md`）で、立ち絵の代わりに顔を出す。

数の物差しは次のように測る。

- **面積の割合**は要素の矩形をビューポートで切り取った面積をビューポートの面積で割る。立ち絵が画面の左にはみ出す分は数えない。
- **最初の画面に見える**は、スクロールせずに要素の下端がビューポートの高さ以下にあること。
- **押す回数**は、場面を開いてからその場面の用が済むまでに押すボタン・キーの数で、文字を打つ手は数えない。

## 6場面の物差し

### 迎える

依頼の無い部屋を開いた場面。キャラクターが迎え、次に頼めることが並ぶ。

- 合格の画: `whole.html?moment=greet`
- 画で比べる点: 立ち絵が舞台の主役に見え、挨拶の吹き出しが立ち絵に付いている。

| 物差し                       | 目標（720 / 1400 / 1920） | 見本の値（720 / 1400 / 1920） |
| ---------------------------- | ------------------------- | ----------------------------- |
| 立ち絵の見える面積の割合     | 顔が頭にある / 25% / 25%  | 顔 38×38px / 31% / 36%        |
| 最初の画面に見える「次の手」 | 3件以上（3幅とも）        | 4件 / 4件 / 4件               |
| 入力欄が最初の画面に見える   | 見える（3幅とも）         | 見える / 見える / 見える      |

手本の製品と要点は次のとおり。

- Raycast（https://manual.raycast.com/ ）: 開くと入力欄1つにフォーカスがあり、その下に最近使ったものと候補が並ぶ。打つか選ぶかの2つの手しか無い。
- Google Jules（https://jules.google/docs/ ）: 始める画面は、どのリポジトリで何を頼むかを書く欄が中心で、過去の作業はその下に並ぶ。

### 頼む

迎える場面かタスクの一覧から、キャラクターに作業を頼む場面。

- 合格の画: `whole.html?moment=greet`（入力欄）と `whole.html?sheet=tasks`（タスクの紙の「頼む」）
- 画で比べる点: 送ったあと、受け取った合図（吹き出しか段の行）が紙の上に出る。

| 物差し                             | 目標（720 / 1400 / 1920）  | 見本の値（720 / 1400 / 1920）           |
| ---------------------------------- | -------------------------- | --------------------------------------- |
| 開いてから打ち始めるまでの押す回数 | 0（3幅とも）               | 1（試作は入力欄にフォーカスを置かない） |
| 入力欄の幅                         | 430px / 560px / 560px 以上 | 457px / 606px / 606px                   |

手本の製品と要点は次のとおり。

- Linear の Agent のやりとり（https://linear.app/developers/agent-interaction ）: 依頼を受けたら10秒以内に最初の thought を返し、受け取ったことを示す。
- Devin の Interactive Planning（https://docs.devin.ai/work-with-devin/interactive-planning ）: 始める前に、関係するファイル・分かったこと・仮の計画を返し、利用者が直せる。

### 待つ

頼んだ作業が走っている場面。今の段と経過時間と、止める操作が見える。

- 合格の画: `whole.html?moment=work`
- 画で比べる点: 済んだ段・今の段・次の段が1本の並びで読め、今の段だけが動いて見える。

| 物差し                         | 目標（720 / 1400 / 1920） | 見本の値（720 / 1400 / 1920） |
| ------------------------------ | ------------------------- | ----------------------------- |
| 今の段と経過時間の行の上端     | 画面の上半分（3幅とも）   | 155px / 127px / 127px         |
| 立ち絵の見える面積の割合       | 顔が見える / 10% / 10%    | 顔 38×38px / 12% / 14%        |
| 止める操作が最初の画面に見える | 見える（3幅とも）         | 見える / 見える / 見える      |

手本の製品と要点は次のとおり。

- Claude Code の dynamic workflows（https://code.claude.com/docs/en/workflows ）: 入力欄の下に1行の進み具合を出し、開くと段ごと・agent ごとに降りられる。止める・再開ができる。
- Apple HIG の Live Activities（https://developer.apple.com/design/human-interface-guidelines/live-activities ）: 始まりと終わりのある作業を、いちばん要る情報に絞って一目で追わせる。
- NN/g「Progress Indicators」（https://www.nngroup.com/articles/progress-indicators/ ）: 何を待っているかを書き、長い処理には止める手段を付ける。

### 答える

キャラクターが判断を求めて止まっている場面（質問・許可のお伺い）。

- 合格の画: `whole.html?moment=ask`
- 画で比べる点: お伺いが紙の中で本文と並び、聞く理由・確かめたこと・おすすめが選択肢の前に読める。

| 物差し                             | 目標（720 / 1400 / 1920） | 見本の値（720 / 1400 / 1920） |
| ---------------------------------- | ------------------------- | ----------------------------- |
| 選択肢が切れずに最初の画面に収まる | 全部（3幅とも）           | 3/3 / 3/3 / 3/3               |
| おすすめのまま答えるまでの押す回数 | 1（3幅とも）              | 1（「これで答える」）         |

手本の製品と要点は次のとおり。

- Linear の Agent のやりとり（https://linear.app/developers/agent-interaction ）: 利用者への問いを elicitation という型で分け、推測で進めずに返す。
- tianpan.co「Why you can't put a progress bar on an agent」（https://tianpan.co/blog/2026/07/02/why-you-cant-put-a-progress-bar-on-an-agent ）: 割り込む強い知らせは、判断が要るときだけに使う。

### 読む

作業が終わり、レポートを読む場面。

- 合格の画: `whole.html?moment=deliver`
- 画で比べる点: 紙が画面の中央を占め、立ち絵は左で紙を邪魔しない。結論の札と1〜2文の結論が紙の頭にある。

| 物差し               | 目標（720 / 1400 / 1920）   | 見本の値（720 / 1400 / 1920） |
| -------------------- | --------------------------- | ----------------------------- |
| 読む面の面積の割合   | 70% / 50% / 45% 以上        | 79% / 56% / 45%               |
| レポートの見える高さ | 650px / 850px / 1000px 以上 | 713px / 884px / 1064px        |

手本の製品と要点は次のとおり。

- Linear のプロジェクト更新（https://linear.app/now/how-we-built-project-updates ）: 更新ごとに健康状態の札を1つ選び、短い文を添える。最新の更新を概要に出す。
- GitHub Actions のジョブ要約（https://github.blog/news-insights/product-news/supercharging-github-actions-with-job-summaries/ ）: 生のログの前に人が読む要約を置き、失敗した段だけを開いておく。

### 戻る

席を外していたか別の作業から戻り、作業の途中か終わったあとの部屋を開き直した場面。

- 合格の画: `whole.html?moment=deliver` の紙の頭にある「離れていた6分のあいだに」と、`whole.html?overlay=sessions`（セッションの切り替え）
- 画で比べる点: 最初の画面だけを5秒見て、「終わったか・自分を待っているか」と「何が変わったか」を言える。

| 物差し                   | 目標（720 / 1400 / 1920） | 見本の値（720 / 1400 / 1920） |
| ------------------------ | ------------------------- | ----------------------------- |
| 離れていた間の要約の上端 | 150px 以下（3幅とも）     | 82px / 54px / 54px            |

手本の製品と要点は次のとおり。

- Claude Code の session recap（https://claudeissues.com/issue/48084-docs-session-resumption-docs-missing-recap-command-and-away-summary-controls 。公式文書に記載が無く、二次）: 3分以上離れると要約を作っておき、戻ったときに出す。
- crystl.dev「Reviewing agent work」（https://crystl.dev/blog/reviewing-agent-work/ ）: 戻った人の問いは「終わったか・待たれているか／何が変わったか／判断の分かれ目／やり方は妥当か」の4つ。
- NN/g「Status Trackers and Progress Updates」（https://www.nngroup.com/articles/status-tracker-progress-update/ ）: 過去の更新を日時つきで残し、最新の状態をいちばん見つけやすくする。

手本の要点は、レポートとプログレスの見直しのために一次情報を読んだ調べ（リポジトリの外の手元の控え）から写した。Raycast の URL はその調べに無く、この文書を書いたときに開いて確かめていない。

紙・進み具合・舞台・書き手の物差しと今の値は `docs/architecture/screen-design/stage-and-paper-yardstick-extra.md` にある。

## 作り直す前の値

作り直しに手を付ける前の今の画面を fake driver の疑似セッションで開き、`scripts/capture/capture-view.ts --scene <場面> --size <幅> --measure <selector>` で測った。
画は見本と同じディレクトリの `before/<場面>-<幅>x<高さ>.png` の18枚（6場面×3幅）。
測った要素は、メインビュー `[data-region="main"]`、立ち絵 `[data-region="character"] [class*="portrait"]`、入力欄 `[data-region="dispatch"] textarea`、進み具合 `section[aria-label="進み具合"]`、お伺いの選択肢 `[class*="inquiry-option_"]`、迎える局面のカード `[class*="card-item"]` とほかの始め方 `[class*="other_"]`。
720 では立ち絵を描かず、顔（34×34px）だけが出る。

| 場面   | 画の名前  | 疑似セッションの場面                                  |
| ------ | --------- | ----------------------------------------------------- |
| 迎える | `greet`   | `welcome-recommendation`                              |
| 頼む   | `request` | `welcome-recommendation` に `--type` で依頼を打った画 |
| 待つ   | `work`    | `work-strip-running` を `--until-step 4` で止めた画   |
| 答える | `ask`     | `question-multi`（押す回数だけ `question-brief`）     |
| 読む   | `read`    | `report-tool`                                         |
| 戻る   | `return`  | `session-resume`                                      |

`work-strip-running` は最後まで流すと作業が終わった画になるので、作業中の4手目で止めた。

| 場面   | 物差し                             | 今の値（720 / 1400 / 1920）                                          | 目標（720 / 1400 / 1920）   |
| ------ | ---------------------------------- | -------------------------------------------------------------------- | --------------------------- |
| 迎える | 立ち絵の見える面積の割合           | 顔 34×34px / 26.7% / 26.7%（描かれた絵で測った）                     | 顔が頭にある / 25% / 25%    |
| 迎える | 最初の画面に見える「次の手」       | 4件 / 4件 / 4件（おすすめのカード1件とほかの始め方3件）              | 3件以上                     |
| 迎える | 入力欄が最初の画面に見える         | 見える / 見える / 見える                                             | 見える                      |
| 頼む   | 開いてから打ち始めるまでの押す回数 | 0（画では入力欄に強調の枠が出ている。フォーカスは測っていない）      | 0                           |
| 頼む   | 入力欄の幅                         | 592px / 645px / 905px                                                | 430px / 560px / 560px 以上  |
| 待つ   | 今の段と経過時間の行の上端         | 頭の行（画で上端 約10px） / 69px / 69px                              | 画面の上半分                |
| 待つ   | 立ち絵の見える面積の割合           | 顔 34×34px / 4.1% / 4.0%                                             | 顔が見える / 10% / 10%      |
| 待つ   | 止める操作が最初の画面に見える     | 見える（●） / 見える（中断） / 見える（中断）                        | 見える                      |
| 答える | 選択肢が切れずに最初の画面に収まる | 3/3 / 3/3 / 3/3                                                      | 全部                        |
| 答える | おすすめのまま答えるまでの押す回数 | 1（「これで答える」。`question-brief` はおすすめの行が選ばれて開く） | 1                           |
| 読む   | 読む面の面積の割合                 | 74% / 32% / 35%                                                      | 70% / 50% / 45% 以上        |
| 読む   | レポートの見える高さ               | 669px / 513px / 630px                                                | 650px / 850px / 1000px 以上 |
| 戻る   | 離れていた間の要約の上端           | 無し / 無し / 無し                                                   | 150px 以下                  |

値は次のように出した。

- 待つの立ち絵の割合は、立ち絵の矩形（1400 は 242.55×222px で上端 685px、1920 は 303.11×277px で上端 810px）の下側を画面の下端で切った面積を画面の面積で割った。
- 迎えるの立ち絵の割合は、`<img>` の箱でなく描かれた絵の矩形で測った。`object-fit: contain`・`object-position: left bottom` なので、絵の高さは箱の高さ、幅は素材（874×800px）の縦横比を掛けた値で、左端は箱の左端。これを画面の中（舞台の幅で切る）に収まる分だけ数え、画面の面積で割った。1400×900 は絵 572.03px 高・箱の左端 -35.27px で、見える 588×572.03px が 26.7%。1920×1080 は 734.39px 高・左端 -48.37px で、見える 753.9×734.39px が 26.7%。測った場面は `welcome-recommendation`、立ち絵は唐傘の `default.png`。
- 読む面は、メインビューからやり取りの列を除いたレポートの列（進み具合と同じ幅。1400 は 779px、1920 は 1145px）にメインビューの高さを掛けた。720 はメインビュー（720×669px）をそのまま使った。
- 選択肢は答え待ちのあいだ3幅とも入力欄の場所（dock）に出る。3つめの下端は 720 で 780px（画面の高さ 900）、1400 で 769px（900）、1920 で 949px（1080）で、3つとも画面の中にあり、本文の中の札と二重にならない（`question-multi` は依頼から始め、ターンを閉じない場面にして測った）。
- 戻るの `session-resume` は、迎える局面の「何から始める？」とほかの始め方だけを出し、離れていた間に何が起きたかは出さない。

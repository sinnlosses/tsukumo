# 画面のデザイン: 知らせの行・読み上げ・失敗の塊

ステータス: **正典**。入口は `docs/architecture/screen-design.md`（画面のデザインの全体）。

責務: 会話の画面の知らせの行、読み上げとフォーカス、進行の計測値の記録、失敗の塊。
読む時: 知らせの行・読み上げの領域・フォーカスの寄せ方・計測値の記録・失敗の塊に触るとき。
直す時: それらの形・語・記録の欄を変えたとき。局面の判定は `docs/architecture/screen-design/conversation-phase.md`。

## 13. 画面のデザイン

### 13.13 会話の画面の局面

#### 知らせの行

**やり取りの列の頭（見出し「やり取り」の下・やり取りの行の上）に、いま見ている中身の外で起きたことを
1つだけ押せる行にして出す**（`HeadNotice`。2026-10-08 に札の頭の右端から移した。見本は
`docs/history/mockup/turn-rail-without-head-2026-10-08.html`）。

- 出すのは、過去のやり取りを見ているあいだの最新のやり取りの状態（「作業中 2/3」「お伺いが届いた」
  「失敗で終わった」）。最新のやり取りを見ているあいだは、お伺いが届いたときだけ出す
  （閉じたあとの続きのターンは帯が今の段の名前で言うので出さない。2026-10-14 ユーザー決定）。押すとそこへ移る（最新へ戻す・
  お伺いへ移る）
- 1つの席に1つだけ。強さの順は 13.9「いまの作業」の状態の語の表と同じ
- **形は答え待ちの色（`--state-warn`）の枠と字**で、角 8px・列の幅いっぱい・`--font-secondary`・字の後ろに「→」。
  1行に収め、字が収まらなければ末尾を「…」で切り、全文は `title`
- **畳んだ列では「!」だけの印の口にする**（13.4「やり取りの列」の「畳んだ列の知らせの印」）
- `aria-live` は付けない（状態の変化を読み上げるのは、1回だけ知らせる別の領域。
  13.13「読み上げとフォーカス」）

#### 読み上げとフォーカス

**読み上げは、画面には出ない常設の領域 1 つが受け持ち、フォーカスは入力欄へ寄せる**（2026-10-02 決定）。
札・知らせの行・立ち絵には `aria-live` を付けない。

- **読み上げの領域**（`LiveAnnouncer`）は `role="status"`・`aria-live="polite"` の常設の枠で、中の文だけが
  入れ替わる。同じ文が続いても挿入として1回ずつ読まれる。画面には出さない
- **読むもの**は、新しいセリフ（`speak`）と、局面の変化。語は上の局面の表のまま: 送ったとき「作業を始めた」、
  閉じたあとの続きのターン「続きを作業中」、お伺いが来たとき「お伺いが届いた」（答えて作業へ戻るときは読まない）、
  閉じたとき「レポートが届いた」、失敗で終わったとき「失敗で終わった」。中断で終わったターンは表に別の語が
  無く、「レポートが届いた」と読まれる。セリフが先、局面の語が後
- **読まないもの**: 読み込み・繋ぎ直し（姿が丸ごと入れ替わるとき）。雑談モードの局面の語（セリフだけ読む）。
  別の画面を開いているあいだ（会話の画面ごと隠れる）
- **セリフは姿に届いた時点で読む**。雑談モードの吹き出しが出るまでの間（13.7「セリフは全文で現れ、
  吹き出しは2秒空ける」）には合わせない
- **ランドマーク**は、メインビューの領域が `main`（名前は「メインビュー」）、サイドバーが `aside`、
  キャラビューと入力欄の領域が名前つきの `section`。雑談モードでも領域は同じ
- **スキップリンク**「入力欄へ移る」は、帯より前の最初の Tab 停止。ふだんは画面の外にあり、フォーカスが
  来たときだけ左上に出る。`href` ではなくボタンで入力欄へ移す（画面の切り替えが `location.hash` のため）。
  会話の画面でだけ出す
- **入力欄の名前**は「依頼を書く」。答え待ちの質問があるあいだは「質問への答えを書く」。素の面と
  マークダウンエディタの面で同じ
- **フォーカスの輪**は全体の `:focus-visible`（`--accent` の輪）を出す。入力欄だけ消さないが、面が大きく
  常にフォーカスがあるので、入力欄（素の面とマークダウンエディタの面）の輪は 2px でなく 1px にする。
  枠の色の変化（答え待ちは `--state-warn` の系統）は輪に重ねて残す
- **入力欄へフォーカスが入るのは、やり取りが閉じているとき**（開いた直後・ターンが閉じたとき・別の画面から
  会話の画面へ戻ったとき）。次のときは動かさない: メインビューの中にフォーカスがある、
  重なる面（モーダル・ポップオーバー・メニュー）が開いている、フォーカスが別の入力欄にある
  （打っている途中の字を奪わない）
- **中身を入れ替えるとき、メインビューの中にあったフォーカスはメインビューの根（輪を出さない）へ移す**。
  外れた中身と一緒に `body` へ落とすと、入力欄が寄せてしまう

#### 進行の計測値の記録

**会話の画面の使い心地を改善の前後で比べるために、3つの数（進行の計測値）を手元に記録する**（2026-10-02 決定）。
測るのはサーバで、イベントを畳んだあとの姿から導いた局面の移り変わりと、そのイベントに打たれた時刻だけを見る。
会話の中身は記録しない（`docs/coding-standards.md`「会話内容の扱い」）。

| 数                       | 始まり                                        | 終わり                                | 記録の欄                       |
| ------------------------ | --------------------------------------------- | ------------------------------------- | ------------------------------ |
| 依頼から結論まで         | `request` が届いた                            | 局面が `deliver` / `stumble` に移った | `untilConclusionMs`・`moment`  |
| 答え待ち                 | 依頼が開いているあいだに局面が `ask` に入った | 局面が `ask` から出た                 | `askingMs`（合計）・`askCount` |
| つまずきから立ち直るまで | 局面が `stumble` に移った                     | 次の依頼が `deliver` で閉じた         | `hands`・`untilRecoveryMs`     |

- **「結論が見えた」はやり取りが閉じた時刻**（上の「遷移」。閉じたらすぐレポートに入れ替わる）。サーバが
  まとめて配るぶんの遅れは数えない
- **答え待ちは、お伺いが重なっても止まっていた時間を1回だけ数える**（局面が `ask` だったあいだ）
- **手数は、立ち直るまでに依頼を送った回数と起こし直した回数の和**。中断で閉じた依頼も、表のとおり `deliver`
  として立ち直りに数える
- **仕切りの行は3つの数とは別**: 読む面の広さを検討する材料として、どの仕切りを離したか・離した比率・動かす前の比率だけを残す。
  送るのはブラウザで、離した瞬間だけ
- **記録しないもの**: 雑談モードのあいだ、復元の再生、閉じたあとの続きのターン（入れ替えは1回きり）、
  起こし直しで閉じずに終わった依頼。セッションIDが分からないうちに閉じた依頼も書かない
- **置き場と形**: `~/.tsukumo/experience-metric/<日付>.jsonl` に、閉じた依頼1つにつき `conclusion` の行、
  立ち直りのたびに `recovery` の行を、会話の画面の3つの仕切り（上段の左右・上下・下段の左右）を離すたびに
  `split` の行を1行ずつ積む（動かしている途中は積まない）。行の形と、書いてよいもの（数・時刻・セッションID・
  局面の名前・仕切りの名前〔固定の3語〕と比率〔%〕）の線は `src/shared/experience-metric/experience-metric-record.ts` の `ExperienceMetricRecord`
- **集計は `scripts/runtime/experience-metric.ts` で見る**（`--days <日数>`、既定28日。`--split <YYYY-MM-DD>` でその日の
  前と後に分ける）。中央値と90パーセンタイルで出す。画面には出さない

#### 失敗の塊

**つまずく局面のレポートの頭（最初の節より前）に、何が起きたかと次の手を1つの塊にして出す**（`TurnFailureBlock`。
2026-10-02 決定。見本は `docs/history/mockup/conversation-moment-2026-10-02/` の `stumble-`）。
失敗の記録はやり取りに残るので、過去のやり取りを遡っても出る。

```
 ┌ 失敗で終わった ─────────────────────────────────────────────┐
 │ API のサーバが応えなかった                  ← 内部の綴りは title だけ │
 │ [同じ依頼を入力欄に戻す]  [失敗した手順を見る]                        │
 └────────────────────────────────────────────────────────┘
```

- **見出しは「失敗で終わった」、その下に理由の語**（`turnFailureLabel`。何が起きたかを言う文で、直し方は言わない）。
  内部の綴り（`server_error`・`max-turns` など）は理由の語の `title` にだけ出す
- **「同じ依頼を入力欄に戻す」**は、そのやり取りの依頼の文を入力欄の下書きに入れるだけで、送らない
  （下書きに字があれば上書きせず、改行を挟んで末尾に足す。始め方の一覧と同じ）。添えた画像は戻さない。
  依頼の記録が無いやり取りでは出さない
- **利用上限に達していて戻る時刻が分かるとき**（いちばん新しいやり取りだけ）は、同じ口を「18:00に戻る · 依頼を入力欄に戻す」
  （別の日なら「9/26 18:00に戻る …」）にする。押しても入力欄に戻すだけで、**時刻が来ても自動では再開しない**
- **「失敗した手順を見る」**は、いちばん新しいやり取りで進み具合の帯が出ていて、依頼の手順に失敗した手順が
  あるときだけ出す。押すと帯の手順の一覧を開き、最初の失敗の行へ転がして、その行の開く口へフォーカスを移す
- 枠と見出しの字は `--state-ng`（`.main-step.is-failed`）。口は始め方の一覧と同じ中立の枠で、新しい色は足さない。
  `aria-live` は付けない（読み上げは上の「読み上げとフォーカス」）
- 仕事のときは入力欄の行に失敗の理由を出さない（雑談モードは塊が無いので、行に理由の語を出す。
  `docs/architecture/display/input-box.md`「入力欄」）

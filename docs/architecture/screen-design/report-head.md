## 13. 画面のデザイン

### 13.13 会話の画面の局面

#### 紙の頭の判定の行

**紙の頭のいちばん上に、判定の札と数を1行で並べる**（`src/browser/features/report/paper/paper-stamp.tsx` の `PaperStamp`。何を出すかと読む深さの正典は ADR 0056 論点 2・7、見本は `docs/history/mockup/ui-rebuild-2026-11-12/whole.html`）。紙の根（`PaperReportRoot`）は、判定の行・結論と補い・前回から・あなたの番・続けて頼めることを頭に置き、主要な数・確かさの台帳・本文の節・置いた前提・出どころを続ける。何を出すかは紙の形（`paperFormOf`）で絞る。

```
 ✓ 済んだ   前回から 2件解決   ●●●○ 4段 ・ 2分52秒   +42 −18 ・ 3ファイル   確かめた 3 ・ 確かめていない 1
 └ 判定の札 ┘                  └ 段の狐火と所要 ──┘   └ 変えた量 ─────────┘   └ 確かさの件数 ─────────┘
```

- **判定の札は印と語を対にする**: ✓ 済んだ・◐ 一部済んだ・● あなたの番・■ 止めた・✕ 失敗で止まった。答えの紙は ✓ 答えた。色だけで伝えない（13.1 原則1）。差し色は「あなたの番」の札と今の段の印だけに使う
- **前回から**は解決と新しくの件数だけを並べ、0件の側は語ごと出さない
- **段の狐火**は段ごとに `Lamp` を1つ並べ、「n段 ・ <合計>」を添える。未着手・飛ばしたの段は済んだ印にしない
- **変えた量**は「+a −b ・ nファイル」で、変更が無ければ「変更なし」
- **確かさの台帳**（`features/report/leaf/certainty-ledger.tsx`）は落ちた・確かめていない・確かめたの3群を1行1つの `details` で描く。落ちた行は開いて出し、確かめた行は読む深さが記録でなければ1行に畳む。「記録あり」「申告のみ」の印の正典は ADR 0056 論点 3

#### 働くあいだの紙（紙の計画）

**働くあいだは、判定の行と計画を紙の頭に出し、終わったら同じ並びを紙の末尾の道筋に畳む**（`components/page/conversation/components/main-view/presentational-work-plan-paper.tsx`。ADR 0056 論点 1）。

- 判定の行の語は、働いている・背景で働いている・あなたの番・あなたが止めた・止めた・失敗で止まったの6つ（印は ◌・●・■・✕）
- 計画の行は段ごとに `Lamp` を置き（今の段 22px・ほか 18px）、状態は済んだ・今・これから・飛ばした（「飛ばした」の札）・止まった（「ここで止まった」の札）。今の段には実況（「いま」「できた」「任せた」の行と、委譲先の進み）と「n秒前」を開く
- 今の段が止まって見えるときは、今の段の最初の行に「出力を見る」「止める」「依頼を入力欄に戻す」の3つを置く
- 終わったら、計画は紙の末尾の畳み「この結論に至った道筋 ― <まとめ>」（止めたときは「ここまでの道筋」）に入る。止めた紙は「ここまでにできたこと」「中途半端なもの」を、失敗した紙は「残っているもの」を頭に置く
- 答え待ちは、紙の頭の「あなたの番」に選択肢を出し、入力欄の場所にもお伺いを出す（`inquiry.md`）
- 入力欄に、段ごとの狐火の札（`WorkPlanDockLamps`）を添える。舞台の吹き出しの下の「手元」の行は `scene-behavior.md`
- **ワークフロースクリプトの流れでは、今のフェーズを段の id でワークフロースクリプトの段に結ぶ。**
  段の id は `tw plan-phases` の1か所だけで生まれ（`impl-1`…`impl-n`・`accept`・`retrospect`）、メインは同じ値を `work_plan` の `phases` の `{ id, name }` と Workflow の args `phaseIds` の両方へ渡す。
  ワークフロースクリプトは `phase()` の題を args の id からしか作らない。
  tsukumo はワークフロースクリプトの写し（`task_progress` の `workflow_progress`）の `workflow_agent` の `phaseTitle` を id として引き、`phaseIds` に一致する agent（`state` を問わない）のうち並びでいちばん後ろの段の要素を今の要素にして、前の段を済ませる。
  `workflow_phase` の並びは段の題が起動時に先に振られるので使わない。
  源が重なったら（写し・`phase_result`・`work_plan`）並びの上で進んだ方を採り、写しでは戻さない。
  `phase_result` は id のあるワークプランでは順を外れる申告（済んだフェーズへの戻り・先のフェーズへの飛ばし）を差し戻す。
  `phaseTitle` が `phaseIds` のどれにも一致しないワークフロースクリプトは照合せず、従来の `phase_result` と `work_plan` の道で進む

#### 離れていたあいだのまとめ

**利用者が紙を見ていないあいだに進んだ分を、紙の頭に「離れていたあいだのまとめ」として出す**（`presentational-away-brief.tsx` の `AwayBriefBlock`）。欄は「あなたを待っていること」「変わったこと」「置いた前提」「進め方」（「計画どおり。」か「計画を直した: …」）で、答えが要るときは「あなたの答えが1つ要る。」を添える。前に見た位置には「ここから先は、前に見たあと」の印（`ReadMark`）を置く。渡すの紙の頭にも、終わった紙の頭にも同じまとめを出す。

#### レポートの頭（タスクの見出しの行）

- 頭の上は2行。1行目は「タスクID・作業の名前・終わり方のバッジ」で、作業の名前は `--font-body`（15px）・600・`ink-bright`、
  終わり方のバッジは `ui/` の `Badge`（`shape: square`。完了は `ok`・答え待ちは `warn`）。2行目はラベル・終えたフェーズを
  `--font-action`（12px）・`ink-quiet` で並べ、`·` ではつながず間を空ける。結論の1文目は 21px・700・`ink-bright`、2文目以降は 15px・`ink-soft`
- `task` のある最終レポートは、結論と数のカードの直後に作業の記録（`work-record`）を置く。題を左（7.5em）・中身を右に置く4行
  「したこと／変えたファイル／確かめたこと／かかった時間」で、値の無い行は出さず、行の間は破線の `rule-quiet`、上下は 1px の `rule-quiet`。
  器が 35rem 以下では題を中身の上に積む
- 「変えたファイル」は畳みの題に「n ファイル +a −b」（`+a` を `report-change-added`（`state-ok`）、`−b`（`−` は U+2212）を
  `report-change-removed`（`state-ng`）で塗る。出す条件は `docs/architecture/display.md` 4.2）と、混ざりうるときの注記「※他の変更を含みうる」を置く。
  枠と地は無く、開くと `files` の部品と同じ樹形図が出る。`task` の無い最終レポートは、検証結果とフェーズごとの所要時間の下（`status` の末尾）に同じ畳みを置く
- 「かかった時間」の頭は合計（太字）と隣に「n フェーズ」、その下に帯と一覧
- `task` の無いレポートは見出しが無いので、結論を 17px（`--report-heading-3`）・500 で見出しの代わりに置く

#### フェーズごとの所要時間

**作業の記録の「かかった時間」に、フェーズごとの所要時間を1本の帯と一覧で置く**（案A「1本の帯と一覧」。表や横棒グラフではない。見本は `docs/history/mockup/phase-time-band-2026-10-14.html`（撮影 `.png` つき）で、
見本が正）。求め方の正典は `docs/architecture/display.md` 4.2「ワークプラン」。
左右の空きは持たず、本文の左端に揃える。
ワークプランの無い依頼では描かず、検証が無くワークプランだけある依頼では帯と一覧だけを置く。

```
 ────────────────────────────────────────────────────────────
 [✓ 1件 通った]  12 件
 ────────────────────────────────────────────────────────────
 ✓ 通った 1件        pnpm run test
 ────────────────────────────────────────────────────────────
 かかった時間  計 2分52秒
 ████▏▕███████████████████████▏█████
 ▪ 1/4 今の形を調べる                 20秒   12%
 ▪ 2/4 ID の変換を両方の形に対応させる   40秒   23%
 ▪ 3/4 文書と検証を揃える              1分12秒  42%
 ▪ 4/4 出荷                           40秒   23%
```

並列のフェーズが無い回の形。

停止で終えた回は、後のフェーズを呼ばなかったフェーズが「未着手」になる（割合は空欄、帯の末尾は斜線の欠片、計は測れたフェーズだけ）。

```
 かかった時間  計 1分12秒
 ███████▏▕█████████████████████▏▨▨
 ▪ 1/3 今の形を調べる                 20秒   28%
 ▪ 2/3 ID の変換を両方の形に対応させる   52秒   72%
 ▪ 3/3 文書と検証を揃える              未着手
```

- **見出しの行**は「計 …」（等幅 15px・太字・`ink-bright`）の横に「n フェーズ」（13px・`ink-quiet`。並列のフェーズは中の段を数える）。題「かかった時間」は作業の記録の行の題が持つ。baseline 揃え・間 12px・下 16px
- **帯**は並列のフェーズが無い回の形で、フェーズごとに1区間、長さは時間（ミリ秒）の比（flex）。高さ 14・区間の間 3・角丸 3。**いちばん長い区間だけ `accent` の色、ほかは `accent` を沈めた色**
  （`phase-band-longest` / `phase-band`。どちらも `accent` から導く。値は `src/browser/styles/theme.css`）。区間に `title`（「名前 3分24秒」）を付ける
- **一覧**の行は grid（色の印 14px・名前・時間 auto・割合 3.5em）・間 10px・上下 6・上罫線 `rule-quiet`・13.5px。色の印は 10px 角・角丸 2 で帯の区間と同じ色。
  時間は等幅 12.5px、割合は等幅 12px・右寄せ。**いちばん長いフェーズの行は太字（600）で、名前と時間を `ink` にする**。名前の前の「n/N」は等幅 12px の薄い字
- **計は測れた区間（フェーズと、並列のフェーズは壁時計1区間）の和**で、割合はその区間の時間÷計の整数%。依頼全体の壁時計とは別の数で、
  不明のフェーズがあるときは測れた分の計になる。いちばん長い区間は、測れたフェーズ（と並列のフェーズの壁時計）のうち最長のもの
- **止めて再開した依頼をまたいで測る**: 後の依頼の最初の `work-plan` の記録のフェーズの並び（`phases`。並列のフェーズの配列も含めた形）が
  前の依頼の最後の記録と同じときだけ、前の依頼の記録を引き継いで区間をつなぐ（2回止めて2回再開すれば2つの区間をつなぐ）。
  前の依頼の区間は、その依頼で最後の `report` の時刻（あとに `work-plan` の記録が積まれたらその時刻、`report` が無ければ後の依頼の `request` の時刻）で閉じ、
  後の依頼の最初の `work-plan` の記録の時刻から改めて始める。あいだの利用者の返事を待った時間は、フェーズの所要にも waterfall の開始にも入れない。
  止めたフェーズは前後の区間の和になる。並びが違えば、今までどおり後の依頼の中の記録だけで測る。
  引き継ぐのは前の依頼がフェーズを残して終わったとき（`workPlanClosing: "stopped"` の `report`、または `report` が無い）だけで、
  前の依頼が `workPlanClosing: "finished"` の `report` で全部のフェーズを終えていれば（最後の記録で全部のフェーズが済んでいる）、
  同じ並びでやり直す依頼でも、それより前の区間ごと引き継がない
- **時間を出さないフェーズ**は「未着手」「飛ばした」「不明」の3つに分け、どれも一覧の時間の欄に字を出し、割合は空欄で、計と割合に数えない。色の印は斜線（`repeating-linear-gradient(135deg, …)`）。帯の中は固定幅 12px（高さ 14・角丸 3）の斜線の区間（`phase-band-unknown`）で、フェーズの順に並び、長さの比に数えない。waterfall の中は下の箇条。数を推し量らない。新しい class は足さず、帯と waterfall の欠片の `title` の語だけが変わる
  - **未着手**: 依頼を `workPlanClosing: "stopped"` の `report` で終えたとき、止めて再開した依頼をまたいだ区間を含めて一度も今のフェーズにならず、最後の記録で済んでいないフェーズ。後のフェーズを呼ばなかっただけで、測れなかったのではない。再開をまたいで一度でも今のフェーズになったフェーズは測れたフェーズなので未着手にならない
  - **飛ばした**: ワークプランの記録の `skippedPhases` にあるフェーズ。区間が測れていても「飛ばした」を優先する。要らず飛ばしたフェーズで、時間は見せない
  - **不明**: 上のどちらでもない測れないフェーズ（`finished`・`none` の `report` で終えて済んでいないフェーズ、一足飛びで済んだフェーズ、端が `restored` の区間を含むフェーズ、最初の記録が途中の位置で始まったときに今だったフェーズ）。記録が無いフェーズだけがここに入る
  - 並列のフェーズの行は、中のフェーズが全部「未着手」なら「未着手」、全部「飛ばした」なら「飛ばした」、それ以外は壁時計が測れれば時間、測れなければ「不明」
  - 中間レポートの終えたフェーズの所要は今までどおり、測れなければ「不明」
- **並列のフェーズがある回だけ、帯の代わりに waterfall（行ごとの横棒）を置く**。並列のフェーズが無い回は、測れないフェーズがあっても今の1本の帯のまま。
  1行1フェーズ（`phase-waterfall-row`）で、横の位置は最初のワークプラン記録の時刻からの開始（引き継いだ区間があれば、待ちを抜いて区間をつないだ時間の軸での開始）、長さは所要の、いちばん右の終わりを 100% とした比（`margin-left` と `width` の%）。
  高さ 14・行の間 3・角丸 3・色は帯と同じ（最長は `phase-waterfall-longest`、ほかは `phase-waterfall-bar`）。
  並列のフェーズは親の棒を描かず、中のフェーズの棒を `phase-waterfall-group` で包み、壁時計の区間（開始の位置から壁時計の長さ）を囲み（`phase-time-wall`。棒の最長の色の 14% の地と 1px の細い枠で、棒の外へ 4px はみ出す）で示す（壁時計が測れなければ囲みは無い）。
  最長の強調は壁時計が最長なら囲みの枠の色を強め（`phase-time-wall-longest`）、フェーズの行が最長ならその棒を強める（中のフェーズの棒には付けない）。強調は1か所だけ。
  waterfall の中の測れないフェーズは幅 2% の斜線の欠片（`phase-waterfall-unknown`）で、直前までの棒の終わりに置く。棒には名前を持たせず、名前・時間・割合は下の一覧が持つ（棒は `aria-hidden`、`title` は付ける）
- **並列のフェーズ**の所要は壁時計の1区間（`docs/architecture/display.md`「ワークプラン」の「並列のフェーズの所要は壁時計」）。一覧は見出しの行「並列 2–3」
  （壁時計・割合つき・色の印あり）と、その下に字下げ 12px で並べる中のフェーズの行（時間は各フェーズの所要、割合は空欄。計と割合には中のフェーズの分を入れない）

```
   かかった時間  計 12秒
   █████                          1/4
         ████████████████         並列 2–3（壁時計）
         ████████████████         2/4
         ████████████             3/4
                         █████    4/4
   ▪ 1/4 今の形を調べる                 2秒    17%
   ▪ 並列 2–3                           8秒    67%
       2/4 サーバの処理を直す            8秒
       3/4 画面を直す                    6秒
   ▪ 4/4 文書と検証を揃える              2秒    17%
```

棒の右の名前は図の説明で、画面の棒には名前を持たせない。

- 帯の区間は、0ミリ秒のフェーズも 2px の幅を残して消えない
- 狭い画面でも一覧の名前が列の中で折り返すだけで、横にあふれない
- 時間の書式は検証の行の所要時間と同じ（60秒未満は「N秒」、以降は「M分SS秒」）。時間を出さないフェーズの「未着手」「飛ばした」「不明」は本文の書体
- 左右の内側はカードと同じ 20px で、カードの字の左端にそろえる。カードとのあきは 12px

#### ファイルの部品

**種類のバッジと、フォルダを畳んだ樹形図・説明の3列で見せる**（デザイン案A。パスは樹形図にする。見本の元は `docs/history/mockup/report-files-block-2026-10-03.html` で、樹形図は
それに無い）。この見た目は、最終レポートの頭の「変えたファイル」の畳み（上の作業の記録の行）と、
書き手が使うツールから外した後も旧い記録の読み戻しに残る `files` の部品が共用する。`files` の部品は
`docs/architecture/display/block-field.md` が読み戻し専用として持つ。

```
         tsukumo-2/
         ├── docs/architecture/
 〜変更  │   └── display.md                  2.3 を樹形図に…
         └── src/…/composer/
 ＋追加      └── composer-draft-storage.ts   新しく作った

                    ＋追加 1  〜変更 1
```

- 種類は記号と色の小さなバッジ: ＋追加（`state-ok`）・～変更（`report-outcome-finished`）・
  −削除（`state-ng`）。見本に無い「読んだ」は補足色（`ink-quiet`）のバッジにし、記号は `·`。
  地は色を10%、枠は30%で混ぜる（表の状態セルと同じ `color-mix` の導出）。バッジはファイルの行の頭に置く
- 部品の末尾（題の行のすぐ上）に、種類ごとの件数が1つでもある種類だけの合計のバッジ（「＋追加 1」）を
  中央に並べる（頭に置くと樹形図に被って見えた）。罫は引かない
- 任意の `title` を渡すと、部品の最下部の中央に「図 n　題」の行を出す（ほかの図の題の行と同じ書式で、
  番号は既存の図と通し）。`title` が空なら題の行も番号も出さない。見本は
  `docs/history/mockup/report-files-title-2026-10-14.html`
- 列はバッジ 64px・パス 最大 340px（`minmax(0, 340px)`）・説明の残り（`minmax(0, 1fr)`）、列の間 20px。
  説明はパスの列のすぐ右から始める。フォルダの行はパスの列から右端まで広げる
- 樹形図は子がフォルダ1つだけのフォルダを「/」で連ね、木が分かれる場所でだけ枝を分ける。全部に共通の
  親は罫のつかない先頭の1行。枝の罫は等幅で `ink-quiet` を薄めた色にして `aria-hidden`、
  行は罫線で区切らず上下 4px に詰める。「/」を含むパスが1つも無い部品は、罫もフォルダの行も出さず、
  行の上下 12px・行の間に `rule-quiet` の細い罫を引く平らな行のまま
- フォルダは等幅 13px の暗い字（`ink-quiet`）、ファイル名は明るい字（`ink`）で出し、
  `:not(pre) > code` の既定の地と下線を外す。折り返すのはフォルダの「/」の後（`<wbr>`）だけで、
  ファイル名は列に収まる長さなら割れない（`display: inline-block; max-width: 100%`）。
  列より長いファイル名だけ `overflow-wrap: anywhere` で中から折り返す（`white-space: nowrap` は、
  はみ出た分が画面の外へ消えて読めなくなるので使わない）
- パス 13px 等幅、説明 14px・行間 1.85（`ink`）
- 追加で説明が無い行は「新しく作った」を補足色（`ink-quiet`）で入れ、空欄にしない
  （ほかの種類で説明が無い行は列を空にする）
- 狭い画面（760px 以下）では説明をパスの下（2列目）に回す

#### レポートの部品のあき

**本文の部品どうしのあきは3つの値だけで決める**（部品ごとの margin が 0〜15px でばらつき、
見出しの直後の表が 8px しか空かなくなるのを避ける）。

| あき                                                                    | 値                    | CSS の名前                |
| ----------------------------------------------------------------------- | --------------------- | ------------------------- |
| 部品と部品の間（段落・箇条書き・note・コード など）                     | 12px                  | `--report-block-gap`      |
| 題つきの表と図（`.report-captioned`）の上下                             | 36px                  | `--report-figure-gap`     |
| 見出しの下（`##` は罫から）から、直後の部品まで（直後が表・図でも同じ） | 12px                  | `--report-heading-gap`    |
| 見出しの上（前のセクションとの区切り）                                  | `##` 52px・`###` 24px | `.detail-block h4` / `h5` |

**あきの格子は 12 / 24 / 36px**（見本は
`docs/history/mockup/report-excellence-2026-10-17/values.html` の B 案）。

- 縦の margin は相殺されるので、表・図の隣は 36px、それ以外の部品どうしは 12px になる。見出しの上は表・図のあきより
  広くし、見出しが前のセクションより後ろの部品に付いて見えるようにする
- 表の中の文字は左揃えで、表の外枠（題つきなら `.report-captioned`）は本文の列の左端に置く
  （`layout.md`「文字の揃え」。実装の CSS には `margin-inline: auto` が残っていて、部品ごとに合わせていく途中）。1列目の左と最終列の右の余白は 0。行罫は `rule-quiet`、見出し行の下だけ `rule`。6行以上の表は5行ごとに 6px の隙間を入れる（行ごとの詳しい中身を開いた行は数えない。見本の場面は `report-table-detail`）
- 枠を持つ部品（`fold` の `<details>`・判定の行）の内側は部品のあきを使わず、それぞれの padding で決める
- 部品を足すときは上下の margin に `--report-block-gap`（題つきなら `--report-figure-gap`）を書き、固定の値を書かない。
  器を持たない部品（引用の中の段落）は既定の 1em（15px）が外へ抜けてあきを崩すので、先頭・末尾の margin を 0 にする
- 本文の隣り合う部品のあきが 12px の倍数であることは E2E（`report-spacing`・`spacing-media`・`spacing-verdict`）が実ブラウザで測る

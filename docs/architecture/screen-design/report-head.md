# 画面のデザイン: レポートの頭とファイルの塊

ステータス: **正典**。入口は `docs/architecture/screen-design.md`（画面のデザインの全体）。

責務: レポートの頭の合図の行（検証結果・段ごとの時間）、ファイルの塊、レポートの塊のあき。
読む時: レポートの頭・段ごとの時間の帯・ファイルの塊・塊のあきに触るとき。

## 13. 画面のデザイン

### 13.13 会話の画面の局面

#### レポートの頭（合図の行）

**結論のすぐ下に、検証結果を総括行と開く行で出す**（2026-10-17 に描き替えた。何を出すかの正典は
`docs/architecture/display/check-result.md`「検証結果は、総括行と開く行で描く」。見本は

```
 最終レポート · <タスクID> · ✓ 完了 · 変更 3 ファイル +42 −18
 架空の札に段が1つでも 1/1 のように位置を出す                      ← 見出し 19px
```

- 目録の末尾の変更の札（`task` のある最終レポートだけ。出す条件は `docs/architecture/display.md` 4.2）は
  等幅・`tabular-nums`・`--font-action`（12px）で、`+a` を `report-change-added`（`state-ok`）、`−b`（`−` は U+2212）を
  `report-change-removed`（`state-ng`）で塗り、「変更 n ファイル」は目録の字の色のまま
- 上下と行の間は 1px の `rule-quiet` の罫（表の行罫と同じ `rule-soft` は 12%。ここは 6% のまま）。行の内側は上下 10px、左右の空きは無く本文の左端に揃える
- 総括行は 13px・`ink-quiet`。記号と状態の語は太字で `state-ok`・`state-warn`・`state-ng`。部分どうしは 20px 空け、
  通った件数のすぐ後ろの `figure` は等幅 12px。お願いの印は右端で、● は `accent`・12px、「お願い 1 ↓」は太字・`ink`、押す的は高さ 24px 以上
- 開く行と通った行の畳みは2列（左 136px に記号と状態の語、間 12px、右に中身）。問題の項目の `label` は 14px・600・`ink`、
  `detail` と確かめ方は 13.5px・`ink-soft`（黄や赤の字にしない。「確かめ方:」の語は `ink-quiet`）。
  `figure` と所要時間は `label` のすぐ後ろに等幅 12px・`ink-quiet` で添え、右端に寄せない
- 通った行の畳みは「✓ 通った n件」（太字・`state-ok`）と `label` の頭の並び（`ink-quiet`）。`<details>` の地と枠と開閉の三角は付けない。
  開いた一覧の行は ✓（`state-ok`）と `label`（13px・`ink-quiet`）で、右の列の頭に揃える。「OK」の字は添えない
- `task` の無いレポートは見出しが無いので、結論を 17px（`--report-heading-3`）・500 で見出しの代わりに置く
- 札の頭に「いま: <節の見出し>」を添える案（提案書 3.1）はまだ入れていない

**検証結果の下に、段ごとの所要時間を1本の帯と一覧で置く**（2026-10-05 利用者決定で表、2026-10-07 に横棒グラフ、
2026-10-14 利用者決定で案A「1本の帯と一覧」に作り替え。見本は `docs/history/mockup/phase-time-band-2026-10-14.html`（撮影 `.png` つき）で、
見本が正）。求め方の正典は `docs/architecture/display.md` 4.2「ワークプラン」。合図の行と同じ `status` の包みの中で、検証結果の下の罫のすぐ下に置く。
左右の空きは持たず、検証結果と本文の左端に揃える。
ワークプランの無い依頼では描かず、検証が無くワークプランだけある依頼では帯と一覧だけを置く。

```
 ────────────────────────────────────────────────────────────
 ✓ 検証 1件 通った 12 件
 ────────────────────────────────────────────────────────────
 ✓ 通った 1件        pnpm run test
 ────────────────────────────────────────────────────────────
 段ごとの時間  計 2分52秒
 ████▏▕███████████████████████▏█████
 ▪ 1/4 今の形を調べる                 20秒   12%
 ▪ 2/4 ID の変換を両方の形に対応させる   40秒   23%
 ▪ 3/4 文書と検証を揃える              1分12秒  42%
 ▪ 4/4 出荷                           40秒   23%
```

並列の段が無い回の形。

停止で終えた回は、後の段を呼ばなかった段が「未着手」になる（割合は空欄、帯の末尾は斜線の欠片、計は測れた段だけ）。

```
 段ごとの時間  計 1分12秒
 ███████▏▕█████████████████████▏▨▨
 ▪ 1/3 今の形を調べる                 20秒   28%
 ▪ 2/3 ID の変換を両方の形に対応させる   52秒   72%
 ▪ 3/3 文書と検証を揃える              未着手
```

- **見出しの行**は「段ごとの時間」（12px・字間 0.08em・`ink-quiet`）の横に「計 …」（等幅 12px・`ink-soft`）。baseline 揃え・間 10px・下 14px
- **帯**は並列の段が無い回の形で、段ごとに1区間、長さは時間（ミリ秒）の比（flex）。高さ 14・区間の間 3・角丸 3。**いちばん長い区間だけ `accent` の色、ほかは `accent` を沈めた色**
  （`phase-band-longest` / `phase-band`。どちらも `accent` から導く。値は `src/browser/styles/theme.css`）。区間に `title`（「名前 3分24秒」）を付ける
- **一覧**の行は grid（色の印 14px・名前・時間 auto・割合 3.5em）・間 10px・上下 6・上罫線 `rule-quiet`・13.5px。色の印は 10px 角・角丸 2 で帯の区間と同じ色。
  時間は等幅 12.5px、割合は等幅 12px・右寄せ。**いちばん長い段の行は太字（600）で、名前と時間を `ink` にする**。名前の前の「n/N」は等幅 12px の薄い字
- **計は測れた区間（段と、並列の段は壁時計1区間）の和**で、割合はその区間の時間÷計の整数%。依頼全体の壁時計（帯の「所要」）とは別の数で、
  不明の段があるときは測れた分の計になる。いちばん長い区間は、測れた段（と並列の段の壁時計）のうち最長のもの
- **止めて再開した依頼をまたいで測る**: 後の依頼の最初の `work-plan` の記録の段の並び（`phases`。並列の段の配列も含めた形）が
  前の依頼の最後の記録と同じときだけ、前の依頼の記録を引き継いで区間をつなぐ（2回止めて2回再開すれば2つの区間をつなぐ）。
  前の依頼の区間は、その依頼で最後の `report` の時刻（あとに `work-plan` の記録が積まれたらその時刻、`report` が無ければ後の依頼の `request` の時刻）で閉じ、
  後の依頼の最初の `work-plan` の記録の時刻から改めて始める。あいだの利用者の返事を待った時間は、段の所要にも waterfall の開始にも入れない。
  止めた段は前後の区間の和になる。並びが違えば、今までどおり後の依頼の中の記録だけで測る。
  引き継ぐのは前の依頼が段を残して終わったとき（`workPlanClosing: "stopped"` の `report`、または `report` が無い）だけで、
  前の依頼が `workPlanClosing: "finished"` の `report` で全部の段を終えていれば（最後の記録で全部の段が済んでいる）、
  同じ並びでやり直す依頼でも、それより前の区間ごと引き継がない
- **時間を出さない段**は「未着手」「飛ばした」「不明」の3つに分け、どれも一覧の時間の欄に字を出し、割合は空欄で、計と割合に数えない。色の印は斜線（`repeating-linear-gradient(135deg, …)`）。帯の中は固定幅 12px（高さ 14・角丸 3）の斜線の区間（`phase-band-unknown`）で、段の順に並び、長さの比に数えない。waterfall の中は下の箇条。数を推し量らない。新しい class は足さず、帯と waterfall の欠片の `title` の語だけが変わる
  - **未着手**: 依頼を `workPlanClosing: "stopped"` の `report` で終えたとき、止めて再開した依頼をまたいだ区間を含めて一度も今の段にならず、最後の記録で済んでいない段。後の段を呼ばなかっただけで、測れなかったのではない。再開をまたいで一度でも今の段になった段は測れた段なので未着手にならない
  - **飛ばした**: ワークプランの記録の `skippedPhases` にある段。区間が測れていても「飛ばした」を優先する。要らず飛ばした段で、時間は見せない
  - **不明**: 上のどちらでもない測れない段（`finished`・`none` の `report` で終えて済んでいない段、一足飛びで済んだ段、端が `restored` の区間を含む段、最初の記録が途中の位置で始まったときに今だった段）。記録が無い段だけがここに入る
  - 並列の段の行は、中の段が全部「未着手」なら「未着手」、全部「飛ばした」なら「飛ばした」、それ以外は壁時計が測れれば時間、測れなければ「不明」
  - 中間レポートの終えた段の所要は今までどおり、測れなければ「不明」
- **並列の段がある回だけ、帯の代わりに waterfall（行ごとの横棒）を置く**。並列の段が無い回は、測れない段があっても今の1本の帯のまま。
  1行1段（`phase-waterfall-row`）で、横の位置は最初のワークプラン記録の時刻からの開始（引き継いだ区間があれば、待ちを抜いて区間をつないだ時間の軸での開始）、長さは所要の、いちばん右の終わりを 100% とした比（`margin-left` と `width` の%）。
  高さ 14・行の間 3・角丸 3・色は帯と同じ（最長は `phase-waterfall-longest`、ほかは `phase-waterfall-bar`）。
  並列の段は親の棒を描かず、中の段の棒を `phase-waterfall-group` で包み、壁時計の区間（開始の位置から壁時計の長さ）を囲み（`phase-time-wall`。棒の最長の色の 14% の地と 1px の細い枠で、棒の外へ 4px はみ出す）で示す（壁時計が測れなければ囲みは無い）。
  最長の強調は壁時計が最長なら囲みの枠の色を強め（`phase-time-wall-longest`）、段の行が最長ならその棒を強める（中の段の棒には付けない）。強調は1か所だけ。
  waterfall の中の測れない段は幅 2% の斜線の欠片（`phase-waterfall-unknown`）で、直前までの棒の終わりに置く。棒には名前を持たせず、名前・時間・割合は下の一覧が持つ（棒は `aria-hidden`、`title` は付ける）
- **並列の段**の所要は壁時計の1区間（`docs/architecture/display.md`「ワークプラン」の「並列の段の所要は壁時計」）。一覧は見出しの行「並列 2–3」
  （壁時計・割合つき・色の印あり）と、その下に字下げ 12px で並べる中の段の行（時間は各段の所要、割合は空欄。計と割合には中の段の分を入れない）

```
   段ごとの時間  計 12秒
   █████                          1/4
         ████████████████         並列 2–3（壁時計）
         ████████████████         2/4
         ████████████             3/4
                         █████    4/4
   ▪ 1/4 今の形を調べる                 2秒    17%
   ▪ 並列 2–3                           8秒    67%
       2/4 サーバの口を直す              8秒
       3/4 画面を直す                    6秒
   ▪ 4/4 文書と検証を揃える              2秒    17%
```

棒の右の名前は図の説明で、画面の棒には名前を持たせない。

- 帯の区間は、0ミリ秒の段も 2px の幅を残して消えない
- 狭い画面でも一覧の名前が列の中で折り返すだけで、横にあふれない
- 時間の書式は検証の行の所要時間と同じ（60秒未満は「N秒」、以降は「M分SS秒」）。時間を出さない段の「未着手」「飛ばした」「不明」は本文の書体
- 左右の内側はカードと同じ 20px で、カードの字の左端にそろえる。カードとのあきは 12px

#### ファイルの塊

**種類の札と、フォルダを畳んだ樹形図・説明の3列で見せる**（2026-10-03 デザイン案A、2026-10-14 に
パスを樹形図へ。見本の元は `docs/history/mockup/report-files-block-2026-10-03.html` で、樹形図は
それに無い）。`files` の塊の構造は `docs/architecture/display/block-field.md`「候補の比較は `options`、
触ったファイルの一覧は `files` の塊で見せる」が持つ。

```
         tsukumo-2/
         ├── docs/architecture/
 〜変更  │   └── display.md                  2.3 を樹形図に…
         └── src/…/composer/
 ＋追加      └── composer-draft-storage.ts   新しく作った

                    ＋追加 1  〜変更 1
```

- 種類は記号と色の小さな札: ＋追加（`state-ok`）・～変更（`report-outcome-finished`）・
  −削除（`state-ng`）。見本に無い「読んだ」は補足色（`ink-quiet`）の札にし、記号は `·`。
  地は色を10%、枠は30%で混ぜる（表の状態セルと同じ `color-mix` の導出）。札はファイルの行の頭に置く
- 塊の末尾（題の行のすぐ上）に、種類ごとの件数が1つでもある種類だけの合計の札（「＋追加 1」）を
  中央に並べる（2026-10-14。頭に置くと樹形図に被って見えた）。罫は引かない
- 任意の `title` を渡すと、塊の最下部の中央に「図 n　題」の行を出す（ほかの図の題の行と同じ書式で、
  番号は既存の図と通し）。`title` が空なら題の行も番号も出さない。見本は
  `docs/history/mockup/report-files-title-2026-10-14.html`
- 列は札 64px・パス 最大 340px（`minmax(0, 340px)`）・説明の残り（`minmax(0, 1fr)`）、列の間 20px。
  説明はパスの列のすぐ右から始める。フォルダの行はパスの列から右端まで広げる
- 樹形図は子がフォルダ1つだけのフォルダを「/」で連ね、木が分かれる場所でだけ枝を分ける。全部に共通の
  親は罫のつかない先頭の1行。枝の罫は等幅で `ink-quiet` を薄めた色にして `aria-hidden`、
  行は罫線で区切らず上下 4px に詰める。「/」を含むパスが1つも無い塊は、罫もフォルダの行も出さず、
  行の上下 12px・行の間に `rule-quiet` の細い罫を引く平らな行のまま
- フォルダは等幅 13px の暗い字（`ink-quiet`）、ファイル名は明るい字（`ink`）で出し、
  `:not(pre) > code` の既定の地と下線を外す。折り返すのはフォルダの「/」の後（`<wbr>`）だけで、
  ファイル名は列に収まる長さなら割れない（`display: inline-block; max-width: 100%`）。
  列より長いファイル名だけ `overflow-wrap: anywhere` で中から折り返す（`white-space: nowrap` は、
  はみ出た分が画面の外へ消えて読めなくなるので使わない）
- パス 13px 等幅、説明 14px・行間 1.85（`ink`）
- 追加で説明が無い行は「新しく作った」を補足色（`ink-quiet`）で入れ、空欄にしない
  （ほかの種類で説明が無い行は列を空にする）
- 狭い画面（760px 以下）では説明をパスの下（2列目）に回す

#### レポートの塊のあき

**本文の塊どうしのあきは3つの値だけで決める**（2026-10-03。それまでは塊ごとの margin が 0〜15px でばらつき、
見出しの直後の表は 8px しか空かなかった）。

| あき                                                                  | 値                    | CSS の名前                |
| --------------------------------------------------------------------- | --------------------- | ------------------------- |
| 塊と塊の間（段落・箇条書き・note・コード など）                       | 13px                  | `--report-block-gap`      |
| 題つきの表と図（`.report-captioned`）の上下                           | 39px                  | `--report-figure-gap`     |
| 見出しの下（`##` は罫から）から、直後の塊まで（直後が表・図でも同じ） | 13px                  | `--report-heading-gap`    |
| 見出しの上（前の節との区切り）                                        | `##` 52px・`###` 26px | `.detail-block h4` / `h5` |

**あきの格子は 13 / 26 / 39px（行 26px の半分・1・1.5 倍）**（2026-10-17。見本は
`docs/history/mockup/report-excellence-2026-10-17/values.html` の B 案）。

- 縦の margin は相殺されるので、表・図の隣は 39px、それ以外の塊どうしは 13px になる。見出しの上は表・図のあきより
  広くし、見出しが前の節より後ろの塊に付いて見えるようにする
- 表の中の文字は左揃えで、表の包み（題つきなら `.report-captioned`）は `margin-inline: auto` でレポートの幅の中央に置く
  （2026-10-20。`layout.md`「文字の揃え」）。1列目の左と最終列の右の余白は 0。行罫は `rule-soft`、見出し行の下だけ `rule`。6行以上の表は5行ごとに 6px の隙間を入れる
- 枠を持つ塊（`fold` の `<details>`・合図の行）の内側は塊のあきを使わず、それぞれの padding で決める
- 塊を足すときは上下の margin に `--report-block-gap`（題つきなら `--report-figure-gap`）を書き、固定の値を書かない。
  器を持たない塊（引用の中の段落）は既定の 1em（15px）が外へ抜けてあきを崩すので、先頭・末尾の margin を 0 にする
- 本文の隣り合う塊のあきが 13px の倍数であることは E2E（`report-spacing`・`spacing-media`・`spacing-verdict`）が実ブラウザで測る

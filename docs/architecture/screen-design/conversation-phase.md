## 13. 画面のデザイン

### 13.13 会話の画面の局面

**4領域の位置と比率は依頼のあいだ動かさず、ターンの局面に合わせてメインビューの中身だけを入れ替える**
（2026-10-02 決定。利用者が方向を採り、形はエージェントに任せた）。固定の割り付けのままだと、
依頼前はメインビューに「（まだ作業がありません）」の1行しか無く、作業中は空の箱が残り、レポートを読むときは
読む面が画面の半分ほどしか無かった（実測と、覆した決定は `docs/history/decision.md`「screen-design.md 13.9
会話の画面の浮かぶ札（2026-10-02 に覆した記録）」）。見本は `docs/history/mockup/conversation-moment-2026-10-02/`
（`index.html` と、局面ごとに 1440x900・1024x768 で撮った `.png`。1024x768 は中くらいの窓幅の段で、
`held-` は 2026-10-02 に外した保留の知らせの行で今の形ではない、`deliver-open-` は柱から開いたサイドバー）。

**実物は器と入れ替えまで移した**（局面の判定・中身の出し分け・入れ替える瞬間・知らせの行・フェード）。
始め方の一覧・読み上げとフォーカス・進み具合の帯・お伺いも移し終えた。

**驚かせない約束**（この節のどの部品もこれに従う）:

- 中身が入れ替わるのは、利用者が送ったときとターンが閉じたときだけ。1回の依頼で「働くあいだの札 → レポート」の
  一方向に進み、戻らない
- 利用者が読んでいるあいだは、中身を差し替えず、読んでいる位置も動かさない。届いたことは知らせの行で知らせる
- 自動で伸び縮みするものは置かない（入力欄も含む）。大きさを変えるのは利用者の操作だけ
- レポートに入れ替わったあとも、進み具合の帯は済んだ姿の1行で残り、依頼の手順の一覧を開き直せる
- 動きは短いフェード1回だけで、`prefers-reduced-motion: reduce` では動かさない

#### 局面と判定

**局面（`ConversationMoment`）はセッションの状態から導く**（状態の畳み込みと共有層は変えない。
導く関数は `src/shared/session/conversation-moment.ts` で、`turn-speech.ts` と同じ置き方）。
「閉じている」は `src/shared/session/main-view.ts` の `closed` と同じ判定（ターンが `running` でなく、
バックグラウンドタスクも残っていない）。

| 局面     | 値        | 判定                                                               | メインビューの中身                     | 知らせの行の語（中身の外で起きたとき） |
| -------- | --------- | ------------------------------------------------------------------ | -------------------------------------- | -------------------------------------- |
| 迎える   | `greet`   | そのセッションにやり取りが1件も無い                                | 始め方の一覧                           | —                                      |
| 働く     | `work`    | いちばん新しいやり取りが閉じていない                               | 働くあいだの札                         | 作業中 2/3                             |
| 尋ねる   | `ask`     | 働くのうち、`pending` が空でない                                   | 働くあいだの札（帯がお伺いを知らせる） | お伺いが届いた                         |
| 渡す     | `deliver` | 閉じていて、失敗で終わっていない（中断も含む）                     | レポート                               | レポートが届いた                       |
| つまずく | `stumble` | 閉じていて、`turn.ending` が失敗で終わったか、`endedReason` がある | レポート（頭に失敗の塊）               | 失敗で終わった                         |

- **中身は3つ（始め方の一覧 / 働くあいだの札 / レポート）だけ**で、局面より少ない。答え待ちはターンの途中に
  来るので、中身ごと替えると「送ったときと閉じたときだけ入れ替わる」を破る。尋ねるは帯の今の段が答え待ちに
  なり、答える札が帯の下の本文に出るだけ、つまずくはレポートの頭に塊が付くだけにする。働くあいだの札は
  いちばん新しいやり取りの札で、本文は中間レポートだけ
  （札の中の並びは `docs/architecture/display.md` 4.2「各表示物」のメインビュー。進行中の本文は出さない。`docs/architecture/display.md` 4.2「各表示物」）
- **効くのは仕事のセッションだけ。** 雑談のメインビュー（13.7）は変えない
- 760px 以下でも局面の出し分けは同じで、本文の形だけが替わる（中間レポートは1段1行の一覧、お伺いは入力欄の上の
  答え待ちの札。13.9「狭い画面（760px 以下）」）
- 過去のやり取りを見ているときは、そのやり取りのレポートを出す（進み具合の帯は出さない）

#### 遷移

- **入れ替えるのは2つの瞬間だけ**: 送った（始め方の一覧 / レポート → 働くあいだの札）と、閉じた（働くあいだの札 → レポート）。
  閉じたあとに claude が続きのターン（`turn-resumed`、13.9「バックグラウンドタスク」）を始めても働くあいだの札へは戻さず、
  レポートのまま知らせの行は出さない（帯が今の段の名前を言う）。続きの `report` は、いまの中間レポートの選び方
  （`docs/architecture/display.md` 4.2「各表示物」）でレポートの中に積まれる
- **メインビューにフォーカスがある・転がしている最中でも、閉じたらすぐ入れ替える**（失敗で終わった
  ときも同じ）。閉じた瞬間に入れ替えたときに読んでいた場所は、新しい中身の先頭から読ませる形で手放す
- **動き**: 新しい中身の入れ物に、不透明度 0 → 1 を 160ms で1回（`@keyframes`）。古い中身は消すだけで
  フェードアウトは付けない。`prefers-reduced-motion: reduce` では付けない。筆の演出（`docs/requirements.md`
  4.3）はこの入れ物の中の節（`sections`）にだけ掛かるもので、フェードとは別に動く。結論と合図の行
  （下の「レポートの頭（合図の行）」）はフェードと同時に出る
- 入れ替えたら、新しい中身の先頭から読ませる（`useActiveTurnScroll` と同じく `scrollIntoView`）。
  **過去のやり取りへ移って戻ったとき（`[` `]`・列で選ぶ・hash）は、そのやり取りで最後に読んでいた位置から見せる**。
  覚えるのはやり取りごとの「読む面の上端にいちばん近い見出しの番号」と「その見出しからのずれの px」だけで、
  ページを開いているあいだだけメモリに持つ（`localStorage` にもサーバにも書かない。セッションが替わると捨てる）。
  初めて開くやり取りと、閉じた瞬間（働くあいだの札 → レポート）は先頭から。覚えた番号の見出しが無ければ先頭から
- **閉じた瞬間に、札の中は「依頼 → 最終レポート → 経過の畳み」に並べ替わる**（2026-10-18 利用者決定。並びの正典は
  `docs/architecture/display.md` 4.2「各表示物」のメインビュー）。先頭から読ませるので、入れ替えたあとは依頼の1行の次に結論が来る。
  中間レポートは最終レポートの下の経過の畳み1つにまとまる。働くあいだと、最終レポートの無いまま閉じたやり取りは並べ替えない。
  続きのターンで次の `report` が来て最終レポートが替わると、前の最終レポートは中間レポートとして経過の畳みに移り、
  新しい最終レポートが依頼の下に来る。経過の畳みの見た目: 最終レポートとのあき 24px・上に `--rule-soft` の罫・罫との間 12px、
  `<summary>` は label の字・`--ink-quiet`。760px 以下も同じ並び・同じ畳みで出す（2026-10-19 利用者決定。一覧は出さない。13.9「狭い画面（760px 以下）」）

#### 札を移るキーと送るキーの案内

**ターンの前後へは `[`（1つ古い）と `]`（1つ新しい）で移る**（2026-10-03 決定）。

- **効くのはメインビューの中にフォーカスがあるときだけ**（グローバルなショートカットは持たない。受けるのは
  メインビューの根の `keydown` 1つで、`useEffect` は使わない）。入力欄・入力要素の中、IME の変換中、
  修飾キー付き（⌘[・Alt+← のブラウザの戻る/進むを邪魔しない）では効かない。お伺いの 1〜9 と Enter とは
  文字が重ならない。端では動かない。移ってもフォーカスは動かさない
- **キーはやり取りの列の見出し「やり取り」の `title` に添える**（2026-10-08。キーを添えていた札の頭の ‹ › の
  ボタンを、題の行と一緒に無くした）。画面の字としては出さない
- **離れたやり取りへ一度で移るのはやり取りの列の上の段**（2026-10-07 決定。`docs/architecture/display.md` 4.2）。
  列の中にフォーカスがあるあいだは ↑↓ でやり取りの行・レポートの行・見出しの行を区別なく移り、Enter でやり取りの行なら
  そのやり取りへ移る（フォーカスは列の中に残す）。`[` `]` は列にフォーカスがあっても効き、列を畳んだあいだは
  `[` `]` と畳んだ列の知らせの印がやり取りを移る口になる
- **見出しの前後へは `{`（1つ前）と `}`（1つ後ろ）で移る**（2026-10-18 決定）。`##`・`###` を区別なく、その見出しの頭が
  読む面の上端に来るまで転がす。効く条件は `[` `]` と同じ（メインビューの中にフォーカスがあるときだけ。入力要素の中・
  IME の変換中・修飾キー付きでは効かず、端では動かない）。キーは `KeyboardEvent.key` で読むので配列に依らない。
  まだ見出しを1つも通り過ぎていないときの `}` は最初の見出しへ移る。`[` `]` の働きは変えない
- **送るキーは送信ボタンの中に `⌘⏎` の印で添える**（`data-shortcut` の `::after`。2026-10-03 ユーザー決定。
  入力欄の行に「⏎ 改行 · ⌘⏎ 送る」の案内を出すと行の中ほどに浮いて見えたので戻した）
- **⌘⇧⏎ は新しい依頼として送る**（2026-10-07 利用者決定。`docs/architecture/display.md`「脇の話」）。⌘⏎ と送信ボタンは、
  バックグラウンドタスクが残っていれば脇の話になる。案内は送信ボタンの `title`（「⌘⏎ で送る（委譲中は脇の話）· ⌘⇧⏎ で新しい依頼として送る」）
  にだけ出し、ボタンの中の印は `⌘⏎` のまま
- 旧い決定（ターンの前後にキーを付けない）と戻し方は `docs/history/decision.md`「screen-design.md 13.13 ターンの前後のキー」

#### 脇の話の欄

**委譲中に送った言葉（脇の話）と答えの対を、送った順にメインビューのいちばん下へ、畳める欄で足す**（置き場は `docs/architecture/display.md` 4.2「各表示物」のメインビュー。
欄の形は 2026-10-07、位置は 2026-10-10 の利用者決定で、中間レポートの上に置いていたのを置き換えた。欄は届いた時点で最後のステップの後ろに置き、あとから届く中間レポートは欄の後ろに並ぶ。
欄の無いステップは何も描かず、脇の話だけのステップも空の札の枠は描かない）
（`AsideThread`。仕様は `docs/architecture/display.md`「脇の話」、見本は
`docs/history/mockup/aside-thread-2026-10-07.html`。言葉と見本が食い違ったら見本に従う）。

```
 ┌ 進み具合の帯（札の頭） ─────────────────────────────────────────────┐
 │ ●作業中 ✓─✓─(3◜) 委譲先に任せる ─(4)─(5)   経過 12分04秒             │
 │            背景で · 直前 Bash pnpm run check …                          │
 ├──────────────────────────────────────────────────────────┤
 │ 依頼の全文                                                            │
 │ 中間レポート（親の札のまま残る）                                      │
 │ ┌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌┐ │
 │ ╎ 脇の話 2件 ▾                                                    ╎ │
 │ ╎   きみ: いまどこ？ → 段2で E2E を流している。落ちたのは 0 件     ╎ │
 │ ╎   きみ: コメントも見ておいて → …                                 ╎ │
 │ └╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌┘ │
```

- **形**: `<details>` の欄を `--rule` の 1px の破線の枠で囲む（本文の塊と見分ける。塗りは敷かない）。`<summary>` は
  「脇の話 n件 ▾」（開いている）・「脇の話 n件 ▸」（畳んでいる）で、開閉の印は字の後ろに置き、ブラウザ既定の三角は消す（見本に合わせる）。行は古い順に「きみ: <言葉> → <答え>」で、「きみ:」と「→」は `--ink-quiet`、言葉と答えは `--ink`。
  字は `--font-secondary`。言葉も答えも長ければ切らず、欄の幅で折り返して全文を出す。答えがまだ無ければ「…」
- **開け閉め**: やり取りが開いているあいだは開いて出し、閉じたら畳んで `<summary>` の1行だけにする。利用者が
  開け閉めしたら、そのやり取りが閉じるまでは選んだほうを保つ
- 色は 13.2 のトークンだけで、新しい色は足さない。`aria-live` は付けない（答えは吹き出しが読み上げる）

## 13. 画面のデザイン

### 13.9 画面のナビゲーション

#### いまの作業

**ワークプラン**（2026-09-29 決定。claude が `work_plan` ツールで渡す段の並びと今の位置。受け取り方と
呼ぶ条件は `docs/architecture/display.md`「ワークプラン」）:

- **札**: 作業中・答え待ちのときだけ、状態の語の後ろに今の段を「2/4 段の名前」の形で出す
  （範囲があれば「後 1/3 段の名前」のように群の名を付ける。全部の段を終えていれば「4/4 済」）。**要約とは別の欄で、上の表の要約の決め方
  （`toSummaryView` の判定順）は変えない** — 「レポートを書いています」に差し替わっても段は残る。
  段の名前が長ければ末尾を「…」で切り、札の幅の 40% までに抑えて要約の場所を残す。背景で作業中・
  振り返り中・依頼待ち・止まっているでは出さない（ターンが走っていない）
- **一覧の頭**: 見出しの直下に「この依頼のワークプラン」（ターンが走っていなければ「前の依頼のワークプラン」）と、
  全部の段を、帯の段の丸と同じ顔の丸（済んだ段は差し色の地に「✓」・飛ばした段は破線の枠に「/」で名前に取り消し線・今の段は差し色の枠の番号・残りは番号）を
  頭に置き、矢印でつないで並べる。範囲があれば前・本・後の群ごとに行を分け、行の頭に群の名を置く（今いる群の名は差し色。
  2026-10-15 ユーザー決定。それまでの頭の字「済」「今」と、範囲の外の段の「・」を置き換えた）。状態の語に関わらず、その依頼にワークプランがあれば出す
- **手順を段で区切る**: 手順はそれが始まった時点の段ごとにまとめ、まとまりの上に「2/4 段の名前」の
  小見出しを置く。最初のワークプランより前・全部の段を終えたあとの手順は小見出しを持たない。閉じている間の
  5件の数え方は変えず、見えている5件を区切る
- 範囲は依頼1つで、その依頼の最後の `work-plan` の記録が今のワークプラン（`currentWorkPlan`）。手順ごとの段は
  `currentTurnSteps` が、その手順より前で最後の `work-plan` の記録から導く

**依頼の手順の一覧**は札の真下に重ねて出す（下の領域を押し下げない）。幅の上限は 36rem、
高さの上限は画面の 70% で、超えたら一覧の内側でスクロールする。上から:

1. **見出し** — 札と同じ印と語。答え待ちのときは、上の「答え待ち」のとおり「お伺いへ」の口を出す。ワークプランがあれば、その直下に
   段の並びを出す（上の「ワークプラン」）
2. **実行中の手順の全文**（実行中の手順があるときだけ）— 小見出しは「実行中の <ツール名>」
   （Bash なら「実行中の Bash」）。中身は要約と同じ欄（Bash は `command`、Edit / Write / Read は
   `file_path`）の値を**切り詰めずに**等幅で折り返す（表示を壊さない上限は失敗の中身と同じ
   8000 字）。**どの欄を読むかは `tool-summary.ts` の1箇所で決める** — 全文を返す関数を足し、
   `summarizeToolInput` はそれを切り詰めるだけにする。並んで走っていればいちばん新しいもの
3. **「この依頼での手順」**（ターンが走っていなければ「前の依頼での手順」）— 行は
   **新しい→古い**（上ほどいまに近い。段ごとの区切りも新しい段が上）。ワークプランがあれば段ごとに区切る（上の「ワークプラン」）。1行は 印・ツール名（等幅。幅をそろえる）・対象（要約）。
   印は 済み ✓ / 実行中 回転 / 失敗 字の「失敗」を `--state-ng` で（色だけにしない）。
   済みの行は字を薄く、実行中は普通の濃さ（いまのサイドバーと同じ）。サブエージェントの中の手順
   （`nested`）は1段下げる。**済み・失敗の行は対象の末尾に所要時間を「（N秒）」で添える** —
   `tool` の記録の開始（`startedAt`）と終了（`status.finishedAt`）の時刻から tsukumo が測った値で、
   どちらかが復元で読み戻した時刻（`restored`）なら添えない（再生の速さを所要時間に見せない）。
   `run_in_background` の Bash は、完了の知らせが届くまで所要時間を添えず、届いたら完了までの時間を添える
   （`docs/architecture/display.md`「出力の分離（セリフと詳細）」）
4. **失敗した行は `<details>`** — 開くと出力、引数の順に出る（いまの `activity.tsx` の
   `FailureDetail` をそのまま移す）。**失敗したツールの引数と出力を読める場所はここだけ**になる
5. **閉じている間は新しい5件まで。** 6件以上あれば末尾に「手順をすべて見る（全 n 件）」を置き、
   5件の外に失敗があれば「（全 n 件・失敗 m）」と数を添える（隠れた失敗に気づけるように）。押すと
   **同じ一覧の中で全件に広がり**、字は「新しい5件だけにする」に変わる。一覧を閉じると5件に戻る
6. 手順が無いときは「この依頼ではまだツールを使っていない」、依頼が一度も無いときは
   「まだ依頼が無い」

- **閉じるのは、札をもう一度押す・外側を押す・Esc**（Esc のときはフォーカスを札へ戻す）。
  購読の仕方は歯車の面と同じ（開いている間だけ `document` の `pointerdown` / `keydown` を
  `useEffect` で取る）。**勝手には開かない**（答え待ちや失敗が来ても開かない）。狭い画面では頭の「手順 n」から
  板で開く（13.9「狭い画面（760px 以下）」）
- **開いている間も中身は追従する**（手順が増えれば行が増える）。新しい依頼が始まれば、その依頼の
  手順に入れ替わる
- **モックの「会話ログで全部見る」の字は使わない。** 「会話のログ」は雑談の画面の語で
  （13.7）、別の画面へ飛ぶように読める。やることは同じ一覧を広げるだけなので、字もそう言う

**範囲は依頼1つ**（いまの `finishedTools` の「直近50件」ではない）。**状態の畳み込み（reducer）も
イベントも変えない** — セッションの記録（`records`）が、依頼ごとにツールの記録を結果つきで
すでに持っている（`tool` の記録の `status`）。一覧は `src/shared/session/turn-step.ts` の
`currentTurnSteps` が、**最後の `request` より後の `tool` の記録**を拾って導く（姿から導くだけの
ものなので `session-state.ts` には置かない。`turn-speech.ts` と同じ置き方）:

- 済み / 失敗は `status.result.isError` で分ける。失敗の出力は `status.result.content`
- **結果の届いていない手順は、ターンが終わっていても実行中のまま出す**（背景で走り続ける
  ものがある。いまの `runningTools` も `turn-finished` では空にしない）。**`session-ended` の
  あとは実行中の印を出さない**（いまの `runningTools` が空になるのと同じ）
- **札の要約も同じ一覧のいちばん新しい実行中の行から取る**（実行中を2つの入れ物で持たない）
- **`SessionState` の `runningTools` / `finishedTools` と `ToolActivity` は、読み手が居なくなるので
  消す。** 状態の形が変わるので `PROTOCOL_VERSION` を上げる（`docs/architecture.md`「版と互換」）

**前の依頼の失敗は、次の依頼が始まると読めなくなる**（いまは依頼をまたいで直近50件まで読める）。
これは受け入れる: 読める範囲の区切りが「件数」から「依頼」に変わるだけで、どちらも古いものは
落ちる。依頼の途中で失敗したものは、その依頼が終わったあとも次の依頼を送るまで読める。

#### バックグラウンドタスク

**ターンが終わったあとも claude が背景で動かしているもの（`run_in_background` の Bash・背景の
サブエージェントなど）を、札と一覧に出す**（2026-09-23 決定。用語は `docs/glossary.md`
「バックグラウンドタスク」）。これが無いと `turn-finished` で札が「依頼待ち」に倒れ、背景で何かが
走っていても止まって見える。

- **数えるもの**: SDK の `system` / `background_tasks_changed` に載る全員から、`ambient`
  （SDK が「活動の印から外せ」と言うもの。見張り役など）を除いたもの。知らせは**顔ぶれ全体を
  毎回運ぶ**ので、状態（`backgroundTasks`）は届くたびに丸ごと置き換える。`task_started` /
  `task_notification` などの始まり・終わりの知らせは顔ぶれを数えるのには使わない（対を数えると、取りこぼしで
  「動いている」が居残る）。`task_notification` は背景の Bash の所要時間の終わりにだけ使う
- **種類で出し分けるのは一覧の行の語だけ**（シェル / サブエージェント / その他。SDK の
  `task_type` の `local_bash` / `local_agent` / それ以外）。札の語と数え方は種類を問わない。
  Monitor の見張りは SDK が `ambient` を付けるものとして数えない（未実測）
- **札**: ターンが走っておらず、答え待ちでも止まってもいないときに1件以上動いていれば
  「背景で作業中」。印は ● で `--accent`、**枠は `--accent` にしない**（枠が差し色なのは
  「作業中」だけにして、ターンが走っているかをそこで見分ける）。要約はいちばん新しく始まった
  ものの説明で、2件以上なら「ほか n件」を添える（説明が無ければ種類の語）
- **一覧**: 「背景で動いているもの（n 件）」の区画を、実行中の手順の全文と依頼の手順の間に
  置く。**状態の語に関わらず1件以上あれば出す**（作業中・答え待ちの最中にも、ターンの外に
  残るものが分かる）。行は 回る「…」・種類の語（等幅）・説明の順
- **入力欄の行には出さない。** 札1つにまとめる（答え待ちを札にまとめたのと同じ理由で、並べると
  どちらがいまかを読む側が決めることになる）。入力欄の経過時間はターンの所要のまま
- **終わると消える。** 顔ぶれが空の知らせで札は「依頼待ち」に戻り、区画も消える。
  `session-ended` でも空にする（claude のプロセスと一緒に終わる）
- **続きの報告**: バックグラウンドタスクが終わると、claude は依頼なしで続きを報告するターンを始める
  （`docs/requirements.md` 4.1。サブエージェントの `SendMessage` が届いたときも同じ）。tsukumo は
  これを**記録を持たない続きのターンの始まり（`turn-resumed`）**として扱う。札は「作業中」に戻り、
  入力欄の経過時間も測り直す。**吹き出しは空にせず、前のセリフと表情を残したまま続きのセリフを
  積む**（2026-09-24。空にしていたときは、合図が届くたびに「（まだ発話がありません）」に戻った）。
  **メインビューには新しいやり取りを立てず、元の依頼のやり取りに積む**（依頼の記録が無いため）。
  続きの報告がそのやり取りの締めの本文になり、前の本文は中間レポートに回るか落ちる
  （`src/shared/session/main-view.ts` の選び方のまま）。続きのターンが走っている間は、**そのターンで届いた
  本文だけ**を出さない（まだ伸びうる本文を出さない、と同じ理由。前の SDK ターンで確定した本文は
  出したまま。`docs/architecture/display.md` 4.2）
- **立ち絵の「たいくつ」（`bored`）は自動では出さない。** 表情の源は `speak` の1つだけ
  （`docs/requirements.md` 4.3）で、バックグラウンドタスクの間に表情を上書きする経路は持たない。長い
  待ちを背景に回すときに `bored` を選ぶのはキャラクター自身。立ち絵の動きも、ターンが
  終わっていれば「読んでいる」（呼吸だけ）のまま（`src/shared/session/portrait-motion.ts`）
- 見え方は疑似セッションの場面 `background-task`（`TSUKUMO_FAKE_SCENE=background-task`）で
  確かめられる。ターンが終わってから約15秒、背景で1件動き続けたあと、続きのターンが走る

## 13. 画面のデザイン

### 13.9 画面のナビゲーション

**会話・キャラクター・トークン消費の3枚を、全画面の最上部に置いた帯から行き来する**
（案を3つ出し、面積を実測して比べたうえでユーザーが帯を選んだ）。13.6 は
「ページ最上部のナビは置かない（**画面が3枚以上になったら検討し直す**）」としていたが、
トークン消費の画面（`#token-usage`）が入って4枚になり、**その1枚だけ UI からの入口が無い**
（`location.hash` を手で打つしかない）状態になったので、書いてあったとおり検討し直した。

**帯は「名乗り、動き方を触らせ、いまの作業を見せる場所」**
（ユーザーがモック `docs/history/mockup/header-2026-09-23.png` を示し、この形にしたいと
言った）。サイドバーの「いま何をしているか」の区画と、「セッション情報」の3つの `<select>`
（仕事 / 雑談・モデル・許可モード。仕事 / 雑談は門）が帯へ移る。**帯の高さは 52px**（ユーザーの
選択。見本は `docs/history/mockup/sidebar-tasks-2026-09-23.html` の `<header>` で、いちど見本
どおりの 60px にしたあと「少しだけ狭く」と言われて下げた。30px・60px との比較は下の「帯が奪う
面積（実測）」）。

```
 (顔⌄) 空色の間 - FA  仕事 雑談 │ キャラ トークン 成果  ( ● 作業中 │ Bash: git add … )  Opus ⌄ 自動判定 ⌄ (⚙)
 └── 名乗る ──┘ └──────────── 行き先（仕事・雑談は会話の画面への門）────────────┘ └──────── いまの作業 ────────┘   └── 動き方 ──┘ └設定┘
─────────────────────────────────────────────────────────────────────────────────────────────────────
 ┌──────────────────────────┬──────────────┐
 │        メインビュー       │  サイドバー   │   サイドバーは タスク一覧 と下端の使用量の帯
 └──────────────────────────┴──────────────┘
 ┌──────────────┬──────────────────────────┐
 │  キャラビュー  │          入力欄           │
 └──────────────┴──────────────────────────┘
```

帯の要素を左から:

| 並び | 要素                                          | 押すと                                                                                    | 読む値                                                                | 節                                                       |
| ---: | --------------------------------------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------- | -------------------------------------------------------- |
|    1 | 顔                                            | キャラクターの選び口が開く                                                                | パックの `face`                                                       | 下の「顔」・「キャラクターの選び口」                     |
|    2 | プロジェクト名・部屋の名前と短縮ID            | 切り替え画面が開く                                                                        | `repository.projectName`・ページの URL のポート・`state.session` のID | 下の「部屋の名前」・「セッションの札」・「切り替え画面」 |
|    3 | 5つの門（仕事・雑談・キャラ・トークン・成果） | その画面へ移る（`<a href>`）。違うモードの仕事・雑談は起こし直す（`session.setChatMode`） | `location.hash`・`state.chatMode`                                     | 下の「帯に何を置くか」・「動き方の操作子」               |
|    4 | いまの作業                                    | 依頼の手順の一覧が開く                                                                    | `state.turn` / `state.pending` / `records` / `backgroundTasks`        | 下の「いまの作業」・「バックグラウンドタスク」           |
|    5 | モデル                                        | 選ぶ（`session.setModel`）                                                                | `state.model`                                                         | 下の「動き方の操作子」                                   |
|    6 | effort                                        | 選ぶ（`session.setEffort`）                                                               | `state.effort`（`effort-changed`・`setting-confirmed`）               | 下の「動き方の操作子」                                   |
|    7 | 許可モード                                    | 選ぶ（`session.setPermissionMode`）                                                       | `state.session` の `permissionMode`                                   | 下の「動き方の操作子」                                   |
|    8 | 設定の歯車                                    | 設定のダイアログが開く                                                                    | `localStorage`（13.6 の表）                                           | 下の「設定の歯車」                                       |

- **1〜3 は左から詰め、5・6・7 は右端に寄せる**（`margin-left: auto`）。4 は 3 の右に置き、
  **幅が足りないときに最初に縮む**（要約の末尾が「…」になる）。4 の字が伸び縮みしても 5・6・7 は
  動かない
- **8（歯車）はいちばん右端**（ユーザーがモック
  `docs/history/mockup/settings-2026-09-23.png` を示した）。
  **設定は「画面」ではなくこの帯の歯車で開くダイアログ**にする（ポップオーバーにはしない。
  下の「設定の歯車」）——どの画面からでも触れて、開いてもいま読んでいるものが画面ごと入れ替わらない
- **帯の形**（値は見本の `<header>` から写し、色はトークンに宛てる）:
  - **画面の端から端まで出す。** 帯は body の padding の外へ負の margin ではみ出す（padding の値は
    `--page-padding` の1箇所）。外寸は**帯の地 52px（`--screen-nav-height`）＋下の罫線 1px
    （`--screen-nav-rule`）** で、会話の画面の grid も同じ変数から高さを引く。帯の下の隙間
    （`--screen-nav-gap`）は画面の縁と同じ `--page-padding`
  - **帯の地は `--ground` と `--surface` を半々に混ぜた色**（画面の地より一段明るく、領域の地より
    暗い）。下の罫線と仕事・雑談の門とほかの門の間の縦の仕切り（高さ 24px・幅 1px）は `--rule`。どれも導出
    なので、歯車から地・字の色を変えても追従する（新しいトークンは足さない）。**上端に差し色の
    線は引かない**（印象が強すぎるため。この線と切り替えの置き場の経緯は `docs/history/decision.md`「screen-design.md 13.x 画面設計の本文から日付を消した経緯6件」）
  - 左右の padding 24px・要素の間 20px・すべて縦に中央揃え。顔と部屋の名前の札は1つの塊で、間は 12px
  - **口は枠も地も無い文字のタブ**（14px。13.3 の「区画の見出し」の段）。帯の高さいっぱいに
    伸ばし、左右 12px・口どうしの間 2px。**いまの口は字の濃さ（`--ink`）・太さ（500）・差し色の
    2px の下線**で示し（色だけで伝えない。13.1 原則1）、下線は下の罫線に重ねる。ほかの口は
    `--ink-quiet` と透明の下線（選ばれても字の位置が動かない）

#### 帯に何を置くか

- 出すのは **「仕事・雑談・キャラ・トークン・成果」の5つの門**（見本は
  `docs/history/mockup/screen-nav-mode-gates-2026-10-11.svg`）。**仕事と雑談はどちらも会話の画面
  `#`** へのリンクで、残りはキャラクター `#character` / トークン消費 `#token-usage` / 成果 `#achievement`
  （成果の口は 13.10）。**口の字は短く**（帯が窮屈なので画面の名前より縮める）。
  **新しく作るはダイアログ**（キャラクター画面の上に重なる。
  13.6「作るダイアログ」）で独立した画面ではないので、帯にもここには挙げない
- **口は `<a href={screenHash(...)}>`。** 画面の正典は `location.hash` のまま変えない（13.6。
  リロードで同じ画面に戻り、ブラウザの「戻る」が効く）。`navigateTo` はコマンドを送った直後に
  画面も移す口が使う（「いまの作業」の「お伺いへ」〔`features/current-work/hooks/use-current-work.ts`〕など）
- **いま出している画面の口は、字の濃さ・太さ・差し色の下線で示す**（上の「帯の形」。**色だけで
  伝えない**。13.1 原則1）。狭い画面ではキャラ・トークン・成果の口は帯ではなく引き出しの歯車の面の行になり、
  仕事・雑談の門は動き方の段に並ぶ（13.9「狭い画面（760px 以下）」）
- **仕事・雑談の門のいまの印（`aria-current="page"`）は、会話の画面にいて、かつサーバから届いた
  `chatMode` がその門のモードと一致するときだけ。** 押した側へ先に倒さない（「動き方の操作子」）
- **会話以外の画面にいるあいだは、戻り先のモード（裏で生きているセッションが仕事か雑談か）の門に
  差し色（`--accent`）の 5px の点を、字の右上に添える。** 戻る先の印なので、いまの印（下線と字）とは
  別の形にして取り違えないようにし、色だけに頼らず点という形でも伝える。会話の画面では付けない
  （いまの印がその役を持つ）

**資格の規則は「どの画面に居ても要り、4つの役目のどれかを持つもの」**。
帯は**どの画面にも出る唯一の要素**なので、1つの画面でしか意味の無いものは置かない。役目は
**名乗る**（この窓は誰の・どの部屋か）・**行き先**（ほかの画面へ）・**動き方**（次のターンの
結果を変える、セッション限りの設定と、端末に覚える見た目の設定）・**いまの作業**（ターンが進んでいるか、何を待っているか）の4つ:

| 置く                   | 役目       | 理由                                                                                                       |
| ---------------------- | ---------- | ---------------------------------------------------------------------------------------------------------- |
| 顔・部屋の名前と短縮ID | 名乗る     | 部屋を並べて動かすと、画面の中身だけではどの窓か見分けにくい。押すとキャラクター・セッションを選べる       |
| 5つの門                | 行き先     | 画面が4枚になり、1枚だけ入口が無かった。成果の画面（13.10）も入口はここだけ。仕事・雑談は会話の画面への門  |
| モデル・許可モード     | 動き方     | **返ってくるもの・勝手に走るかどうか・返る形**が変わる。キャラクター画面やトークン消費の画面からも変えたい |
| いまの作業             | いまの作業 | 会話の画面の外に居ても、ターンが進んでいるか・答えを待っているかに気づける                                 |
| 設定の歯車             | 動き方     | 地・領域・字の色と新しいセッションの既定を、どの画面からでも変えたい（下の「設定の歯車」）                 |

| 置かない   | 理由                                                                                 |
| ---------- | ------------------------------------------------------------------------------------ |
| タスク一覧 | 読む量が多い。サイドバーの区画とモーダルが持つ（`docs/architecture/display.md` 4.2） |

**キャラクターとセッションの切り替えは、名乗りの顔と札を押して開く口として置く**。
名乗っているもの（誰と・どのセッションか）をその場で押して選び直せるほうが
迷わず、サイドバーも空く。帯には口だけを置き、選ぶ面（選び口・切り替え画面）は押したときだけ出す。

**資格の軸は「読ませたいか」ではなく「どの画面からでも変えたいか」。**
「画面を見ても分からず、かつターンの結果を変えるもの」は帯に読みの字だけを置く前提の規則で、
雑談モードを「画面ごと入れ替わるので見れば分かる」として外していたが、
帯に操作子を置くので雑談モードも入る。

#### 採らなかった案

**口の置き場所**:

- **区画の見出しの右に置く**（サイドバーの「タスク一覧 … 一覧を見る」の横展開。トークン消費は
  「セッション情報」の右へ）。奪う面積はゼロだが、**画面と区画が1対1のときしか成立しない** —
  サイドバーの区画の数は画面の数と関係なく決まる（`docs/architecture/display.md` 4.2）ので、どの区画にも
  属さない画面が出た時点で置き場が尽きる
- **右下の常設ボタン（「領域の比率を既定に戻す」）にまとめる**。`position: fixed` なので面積は
  奪わないが、**狭い画面では `display: none`**（layout.module.css）なので入口が丸ごと消え、
  別の手当てが要る
- **狭い画面でも帯を2段目に出す**。見え方は幅によらず同じになるが、メインビューが 378.9px
  （-11.2%）まで減る
- **入力欄のコマンド（`/token-usage`）だけにする**。面積は奪わないが、補完を知らないと届かない

**帯の中身**:

- **「帯は名乗り、サイドバーは触らせる」を続ける**。キャラクター画面と
  トークン消費の画面から動き方を変えられず、同じ値の読みと操作子が2箇所に出続ける
- **ドロップダウンを独自の開閉にする**（モックの見た目に寄せる）。キーボード（矢印・先頭の字で
  飛ぶ・Esc・フォーカスの戻り）と読み上げ（listbox の役割と選択の伝え方）を自前で持つことになり、
  いまの作業の一覧と開閉を取り合う。見た目の差は `appearance: none` で埋まる
- **モードの門を押したら確かめの一言を挟む**。前のセッションへは切り替え画面から戻れるので、失うのは画面の初期化だけ
  （`docs/architecture/chat-mode.md` 4.9 で受け入れ済み）。確かめは押すたびの手間にしかならない
- **答え待ちの印を札と並べる**。「作業中」と「答え待ち」が同時に出て、どちらがいまかを読む側が
  決めることになる
- **手順の範囲を `finishedTools`（直近50件）のままにする**。依頼をまたいで混ざり、「この依頼で」
  何をしたかが読めない。記録（`records`）がすでに依頼ごとに持っているので、新しい入れ物も要らない
- **顔を `mini` から丸く切り抜く**。`mini` は筆を抱えた全身の絵で、顔の位置も大きさも絵ごとに
  違う。切り抜く位置をコードに書くと原則4 に触れる
- **顔の切り抜き位置を定義の欄にする**（立ち絵のどこを丸く抜くかの座標）。書く側が座標を測る
  ことになり、顔を1枚切り出して置くより手間が多い
- **顔の無いパックで頭文字の丸を出す**。パックに無いものを tsukumo がこしらえることになる。
  部屋の名前だけで名乗りは足りる

**帯の主の字**:

- **部屋の名前を消してプロジェクト名だけにする**。同じディレクトリで2つ起こしたとき、見分けが
  短縮IDだけになる。部屋の名前を補足に残せば、ポートの違いが目に入る
- **プロジェクト名を `SessionState` に乗せて配る**。cwd は起動から変わらず、畳み込みに入れる理由が
  無い。`repository.listFiles` と同じく、手続きで一度だけ引く

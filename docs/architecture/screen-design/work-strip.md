# 画面のデザイン: 進み具合のプログレスバー

ステータス: **正典**。入口は `docs/architecture/screen-design.md`（画面のデザインの全体）。

責務: 会話の画面のメインビューのカードの頭に固定する進み具合のプログレスバー（状態のチップ・フェーズの丸・手順のボタンと開く一覧）と、走っている手順を出す流れの末尾の「いま」の行。
読む時: 進み具合のプログレスバーに触るとき。
直す時: プログレスバーの行・状態の色・フェーズの丸の押したとき・手順のボタンと一覧・プログレスバーの外寸を変えたとき。局面の出し分けは `docs/architecture/screen-design/conversation-phase.md`。

## 13. 画面のデザイン

### 13.13 会話の画面の局面

#### 進み具合のプログレスバー

**働くあいだとレポートを読むあいだ、メインビューのカードの右の側（やり取りの列の右）の上端に、フェーズを
その場で書き換える横のプログレスバーを固定する**（`WorkStrip`。見本は
`docs/history/mockup/work-strip-2026-10-02.html`。作業の地図と浮かぶカードとレポートの「進み具合」を置き換えた。
旧い形は `docs/history/decision.md`「screen-design.md 13.13 作業の地図・会話の画面の浮かぶ札・レポートの進み具合
（2026-10-02 に覆した記録）」）。本文ではなく、ワークプランと依頼の手順と状態から導くだけのもの。
プログレスバーはカードの頭としてスクロールしても上に残る（`position: sticky`。カードの中の並びは `docs/architecture/display.md` 4.2「各表示物」のメインビュー）。
プログレスバーの上に題の行は置かない。
会話の流れ（メインビューの本文）にも段の札が出るが、これはワークプランの記録が届いた位置を残す履歴の1行で、いまの状態はプログレスバーだけが持つ（同じ情報を2か所に出さない）。

```
 ┌ 進み具合のプログレスバー（カードの頭） ─────────────────────────────────────────────┐
 │ ●作業中 ✓─✓─✓─(4◜) 集計の関数…  (5)─(6)─(7)  経過 6分12秒 [手順 12 ▾]   │
 │            Bash  pnpm exec vitest run …  · 12秒  · 再試行中 2/10           │
 └─────────────────────────────────────────────────────────────────────┘
```

- **状態のチップ**: 1行目の左端に、いまの状態を色の点と字で出す
  （見本は `docs/history/mockup/report-verdict-quiet-2026-10-08.html` の「案A 静か」）。
  状態は6つ: 作業中・背景で作業中・答え待ち・完了・止めた・失敗。枠・地・太字は無く、直径 8px の状態の色の丸い点と、
  字（13px・`--ink-soft`・普通の太さ）を 7px 空けて並べる。作業中も点だけで、回さない。
  **背景で作業中はプログレスバーのチップだけの状態**（やり取りの列の印には無い）で、ターンが動いておらず、答え待ちも無く、
  バックグラウンドタスクが残っているときに出す（モデルはもう手を止めていて、背景のコマンドだけが生きている）。
  背景で作業中の点は `--accent`。答え待ちが来ていれば答え待ちが先。
  **字と導き方はやり取りの列の結果の印と同じ表**（`docs/architecture/display.md` 4.2。列の印は変えない。背景で作業中を除く）で、
  導き方も同じ（`turnResultsOf`）。点の色は作業中 `--accent`・背景で作業中 `--accent`・答え待ち `--state-warn`・完了 `--state-ok`・
  止めた `--ink-quiet`・失敗 `--state-ng`。チップは縮めない（縮むのは今のフェーズの名前だけ）。
  失敗の理由と次の手は失敗の表示が持ち、プログレスバーは状態の名前だけを言う
- **1行目**: フェーズの丸を1本の線でつなぐ。済んだフェーズは「✓」の印の丸だけ（飛ばしたフェーズは同じ位置に、地なし・`--rule` の破線の枠・`--ink-quiet` の「/」の丸。数え方は済んだフェーズと同じ。`docs/architecture/display.md`「ワークプラン」）、残りのフェーズは番号の丸だけで、
  委譲先のフェーズの数が未定のあいだ（`pending`）は、範囲の要素だけが番号の無い「…」の丸で、後ろのフェーズは群の中の序数（1から）を持つ。
  **名前を出すのは今のフェーズだけ**（7フェーズでも1行に収める。今のフェーズの名前は末尾を「…」にする）。
  どの丸も名前を `title` と読み上げに持ち、押せる（`button`。Tab で届く）。押すと手順の一覧が開いてそのフェーズの行へ着地する（下の「フェーズの丸を押したとき」）。
  範囲があれば、群（前・本・後）の先頭の丸の前に群の名を小さく置き、前の群の丸とは線でつながず間を空ける（今いる群の名は差し色）。
  右端に「経過 6分12秒」（等幅）と「手順 n ▾」のボタン。位置の字は出さない（丸の並びと今のフェーズの名前が言うので、言い直しになる）。
  **760px 以下ではプログレスバーを出さず、同じもの（状態・フェーズの丸・今のフェーズの名前・経過・「手順 n」）を頭の2行が持つ**
  （13.9「狭い画面（760px 以下）」。プログレスバーを2行にはしない）
- **「いま: <セクション>」**（見本は `docs/history/mockup/report-reading-tool-2026-10-18/after-norail-w1400.png`）:
  読んでいる `##` の字を、1行目の状態のチップの右に出す。出すのはやり取りの列を畳んだときだけで（開いていれば列の
  見出しの強調が同じことを言う）、新しい行は足さない。字は `--ink-quiet`・普通の太さで、縮むのはこの字（末尾を「…」にする）。
  セクションは読む面の上端を通り過ぎた最後の `##` で、`###` の途中にいても親の `##` を出す。スクロールし切ったときは最後の `##`
  （最後の見出しが上端に届かないため）。見出しの無いレポートと、最初の見出しより前では出さない。
  **760px 以下は頭の1行目の状態の語・経過の右に同じ字を出す**（列もプログレスバーも無いので畳みは見ない。読む面の上端は本文のスクロールする器の上端）
- **並列のフェーズ**（`docs/architecture/display.md`「ワークプラン」の「同時に走るフェーズは、並列のフェーズで受ける」）: 中のフェーズの丸を1つの囲みの中に横に並べ、
  囲みを前後のフェーズと線でつなぐ（囲みの中の丸どうしは線でつながない）。済んだ・今・残りは丸ごとに付け、どの順で済んでも済んだ丸は戻らない。
  今のフェーズが2つ以上なら、頭の字は今のフェーズの名前を「・」でつなぎ（末尾を「…」で縮めるのは同じ）。今のフェーズの丸はどれも今の丸の枠で強調する。お伺いが届いたら今のフェーズの丸をどれも「?」にする。済んだ姿の「7フェーズのうち3フェーズ済み」は並びを平らにしたフェーズで数える

```
 │ ●作業中 ✓─[(2◜) (3◜)]─(4)  B・C…  経過 2分05秒 [手順 9 ▾]          │
```

- **フェーズの丸を押したとき**（吹き出しは出さない）: 依頼の手順の一覧を開き（開いていれば開いたまま）、一覧の中だけをスクロールして
  そのフェーズの行を一覧の上端に置く。そのフェーズの手順が1つも無い・まだ始まっていないフェーズも行があるので、同じに着地する。
  フェーズのまとめは一覧に出さず、流れの済んだフェーズの札が持つ（同じ情報を2か所に出さない）。
  - 丸の押す的は 24px 四方で、見える丸の寸法・丸の並びの幅・プログレスバーの高さは押せなかったころのまま（はみ出すぶんは負の margin で打ち消す）
  - 答え待ちの今のフェーズの丸も、並列のフェーズの中の丸も同じに押せる。並列のフェーズの囲みそのものは押せない。
    760px 以下の頭の2行の丸は押せない
  - 丸の hover は枠を `--accent` に（答え待ちの丸は `--state-warn` の枠のまま）

- **流れの末尾の「いま」の行**（`NowLine`。プログレスバーの外）: 最新のやり取りの流れの末尾（最後の行の下、入力欄の上）に、
  左寄せの小さな札（縁・全周の角丸・不透明の面。列の幅いっぱいにしない）に、回る印・動詞・対象・経過・添え書きを1行で置く。
  「いま」の字は出さない。回る印は会話の画面でこの1個だけで、札の中に置く。
  作業中のあいだだけ出し、答え待ち・レポートに入れ替わったあと・過去のやり取りでは出さない。
  プログレスバーの「2行目」にあった走っている手順の置き場を、ここへ移した（ADR 0059）。
  面は不透明で、ぼかしの面（進行の帯は高さ 40px のカプセルで `--panel-glass`・`--panel-filter`・縁・影の透ける面）の外に置く。
  狭い画面は「いまの段」の下の1行が持ち、文は今のまま（`workActivityOf`。広い画面の文は `nowLineStatementOf`）。
  文は動詞（太字）・対象（要約は等幅。`summarizeToolInput`）・手順が始まってからの秒（`formatElapsed`）で、動詞の表は
  ADR 0062 論点 3 が正（ここへ書き写さない）。道具の名前から機械的に引き、文を作る処理は持たない。
  同じ状態が 120 秒を超えると回る印を遅くして「長く掛かっている」を添える（`LONG_RUNNING_SECONDS`。委譲先に任せている状態には付けない）。
  API の再試行中は動詞「もう一度試している」に「API の応答待ち · n回目」を添える（理由と待ち時間は `title`）。
  以下は、何を行の対象に選ぶかの決まり。手順を持つバックグラウンドタスク
  （ワークフロースクリプト・サブエージェント）は、手順を持たないバックグラウンドタスク（Bash・Monitor）の説明より先に出す。
  手順を持つものが複数なら、いちばん新しく手順が始まったものを出す（同時刻なら顔ぶれの後ろの方。
  サブエージェントの手順はタスクに結ばれないので、サブエージェント全体で1つと数える）。
  選んだものがサブエージェントなら「背景で 委譲先に任せている」に、依頼の `Agent` の手順の役と説明（無ければバックグラウンドタスクの説明）を添える。
  選んだものがワークフロースクリプトなら、その中で
  手順が始まっていれば、始まりだけでなく終わりも見る。走っている手順は動詞の前に「背景で」を添えて言い、
  手順が終わって次がまだで、ワークフロースクリプトの agent に走っているもの（start・progress）があれば
  「背景で 委譲先に任せている」に agent の段の題（`phaseTitle`。役は運ばれないので作らない）を添え、
  走っている agent が無ければ（段の間）ワークフロースクリプトの説明（「背景で <説明>」）に戻す
  （SDK はワークフロースクリプトの中の手順をメインの流れに流さないので、
  `PreToolUse` のフックから `workflow-step-started` に、`PostToolUse`・`PostToolUseFailure` のフックから
  `workflow-step-finished` にして運び、`tool_use_id` で始まりと突き合わせる（新しい手順に替わったあとに届く古い終わりは捨てる）。
  `task_progress` の `workflow_progress` で agent の `state` が done・error になっても、その agent の手順は終わりになる。
  `task_progress` の `workflow_progress` が名指す agent の id と
  フックの `agent_id` を突き合わせ、その agent を持つワークフロースクリプトに当てる（どのワークフロースクリプトの agent でもない呼び出しは捨てる）。
  ワークフロースクリプトが顔ぶれから外れると手順も消える。
  目視は疑似セッションの場面 `workflow-steps`）。
  **常に1行**（要約の改行は空白に畳み、長ければ末尾を「…」にする。複数行のコマンドで行が伸びるため）
- **お伺い**: 答え待ちが届いたら（`pending` が空でない）、今のフェーズの丸を `--state-warn` の系統と「?」にし、
  流れの末尾の「いま」の行は出さない（チップと丸が答え待ちを言い、お伺いのカードが末尾に出る）。
  狭い画面の「いまの段」の下の1行は、何を待っているか（「お伺いが届いた · 許可: Bash rm -rf … · 答え待ち 8秒」、質問なら
  「質問: <1問目の header>（ほか n問）」）を出す。待った秒は、答え待ちが届いた時刻（状態の `pending` の
  `askedAt`）から数える。答えるカードそのものはプログレスバーの下の本文に出る
- **手順のボタン**: 「手順 n」を押すと、依頼の手順の一覧をプログレスバーの真下に本文を押し下げて開く。もう一度押すと閉じる
  （外を押しても閉じない）。高さはビューポートの 40% を超えたら内側でスクロールする。やり取りが替わると閉じる。
  先頭は「背景で動いているもの」の区画（バックグラウンドタスク）。ワークプランがあれば、全フェーズを上から1行ずつ（印・名前・所要。印と数え方はフェーズの丸と同じで、
  並列のフェーズと範囲の群の名も同じ）並べ、行の下にそのフェーズの手順（13.9「いまの作業」の一覧の手順の行。失敗の行は
  引数と出力を開いて読める）を置く。済んだフェーズの手順は「手順 n」に畳み（押すと開く。失敗した手順を持つ済んだフェーズは開く）、
  今のフェーズの手順は開いておき、これからのフェーズは名前だけを出す。実行中の手順の行の印は回さない。
  所要は済んだフェーズが「1分40秒」、今のフェーズが「20秒〜」で、測れないフェーズ・飛ばしたフェーズ・これからのフェーズは出さない
  （求め方は `docs/architecture/display.md`「ワークプラン」のフェーズごとの所要時間と同じ）。
  済んだ姿（最終レポートに入れ替わったあと）では、一覧の末尾に「計 …」と「n フェーズ」、フェーズごとの所要時間の帯を置く
  （帯と計だけで、一覧の行は行が持つので出さない。割合は帯の区間の `title`。作業中は出さない。帯の求め方と形は `report-head.md` の所要時間の帯と同じ）。
  ワークプランの無い依頼は、フェーズの行を持たない手順の一覧。フェーズの丸からも開く（上の「フェーズの丸を押したとき」）
- **レポートに入れ替わったら**、流れの末尾の「いま」の行が消え、プログレスバーは「7フェーズすべて済み · 所要 21分49秒」の
  済んだ姿で残る（途中で止めたなら「7フェーズのうち3フェーズ済み」）。手順のボタンも残り、開くと一覧の末尾に所要時間の計と帯が出る。閉じたあとの続きのターンでも
  1行のまま（読んでいるあいだに伸ばさない）。続きのターンが走っているあいだは、1行目の字を済み具合でなく今のフェーズの名前にする
- **プログレスバーは送った直後から必ず出す**（ワークプランが届くまでプログレスバーが無いと、動いているのか分からないため）。
  ワークプランが届く前（答えるだけのときも）はフェーズの丸を出さず、1行目をチップと「経過 12秒」だけにし（チップが「作業中」を言うので、
  見出しの字に「作業中」を重ねない）、流れの末尾の「いま」の行は上と同じ
- **会話の画面で回る印は、流れの末尾の「いま」の行の頭の1個だけ**（形と速さは `--spinner-animation`、1秒で1周。
  `prefers-reduced-motion: reduce` では止まる）。チップは点だけで回さず、今のフェーズの丸も回さない
  （今のフェーズであることは今の丸の枠の強調〔`data-phase-state="current"`〕で示す。並列のフェーズで今のフェーズが複数ならその丸すべてを強調する）。
  開いた「手順」の一覧の実行中の行と背景の区画の「…」は止まった印にする（回る印が1画面に2か所以上動かないように）。
  ほかの画面のいまの作業の一覧（`CurrentWorkList`）と、狭い画面の引き出しのやり取りの列のいまの回は今のまま回す。
  「いま」の行が出ない答え待ち・レポートに入れ替わったあとは、回る印がどこにも無い
- **ワークフロースクリプトの流れでは、今のフェーズを段の id でワークフロースクリプトの段に結ぶ。**
  段の id は `tw plan-phases` の1か所だけで生まれ（`impl-1`…`impl-n`・`accept`・`retrospect`）、メインは同じ値を `work_plan` の `phases` の `{ id, name }` と Workflow の args `phaseIds` の両方へ渡す。
  ワークフロースクリプトは `phase()` の題を args の id からしか作らない。
  tsukumo はワークフロースクリプトの写し（`task_progress` の `workflow_progress`）の `workflow_agent` の `phaseTitle` を id として引き、`phaseIds` に一致する agent（`state` を問わない）のうち並びでいちばん後ろの段の要素を今の要素にして、前の段を済ませる。
  `workflow_phase` の並びは段の題が起動時に先に振られるので使わない。
  源が重なったら（写し・`phase_result`・`work_plan`）並びの上で進んだ方を採り、写しでは戻さない。
  `phase_result` は id のあるワークプランでは順を外れる申告（済んだフェーズへの戻り・先のフェーズへの飛ばし）を差し戻す。
  `phaseTitle` が `phaseIds` のどれにも一致しないワークフロースクリプトは照合せず、従来の `phase_result` と `work_plan` の道で進む
- **ワークプランの無いまま閉じたターンも、プログレスバーを残して状態と所要だけの1行にする**（フェーズの丸は無く、1行目はチップと
  「所要 …」〔失敗でも「所要」。チップが状態を言うので語を重ねない〕。失敗がプログレスバーに出ず、閉じるとプログレスバーが消えて終わり方が読めなくなるのを避ける）。
  閉じたのに本文が1つも無いやり取り（`no-report`）は5つのどれでもないので、ワークプランがあればフェーズの進みから
  決め（途中で閉じていれば止めた、全部済んでいれば完了）、ワークプランも無ければプログレスバーごと出さない
- **過去のやり取りを見ているあいだは出さない**。プログレスバーは最新のやり取りの上端に固定するもので、過去のやり取りの
  結果はやり取りの列の同じ印が持つので、2か所に出さない
- **経過と所要の置き場はプログレスバーの1か所**で、仕事のときは入力欄の行に経過も再試行も出さない
  （雑談モードはプログレスバーが無いので、入力欄の行に残す。`docs/architecture/display.md` 4.2「各表示物」の入力欄）
- **会話の画面には、いまの作業のカードを置かない。** プログレスバーがカードの役（今のフェーズ・手順の一覧を開くボタン・お伺いの知らせ）を
  持つので、並べると同じことが2か所に出る（`docs/requirements.md` 4.7）。ほかの画面のプログレスバーのカードと一覧（13.9）は変えない
- 色は 13.2 のトークン（済んだフェーズと今のフェーズは `--accent`、残りは `--rule` と `--ink-quiet`、お伺いは `--state-warn`、状態のチップは上の「状態のチップ」の色、

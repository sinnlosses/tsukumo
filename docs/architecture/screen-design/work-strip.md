# 画面のデザイン: 進み具合のプログレスバー

ステータス: **正典**。入口は `docs/architecture/screen-design.md`（画面のデザインの全体）。

責務: 会話の画面のメインビューのカードの頭に固定する進み具合のプログレスバー（状態の印と見出し・下線の区間と位置・手順のボタンと開く一覧）と、その1行の縦線の右に出すいまの手順の一文。
読む時: 進み具合のプログレスバーに触るとき。
直す時: プログレスバーの行・状態の色・下線の区間の押したとき・手順のボタンと一覧・プログレスバーの外寸を変えたとき。局面の出し分けは `docs/architecture/screen-design/conversation-phase.md`。

## 13. 画面のデザイン

### 13.13 会話の画面の局面

#### 進み具合のプログレスバー

**働くあいだとレポートを読むあいだ、メインビューのカードの右の側（やり取りの列の右）の上端に、フェーズを
その場で書き換える横のプログレスバーを固定する**（`WorkStrip`。見本は
`docs/history/mockup/work-strip-2026-10-02.html`。作業の地図と浮かぶカードとレポートの「進み具合」を置き換えた。
旧い形は `docs/history/decision.md`「screen-design.md 13.13 作業の地図・会話の画面の浮かぶ札・レポートの進み具合
（2026-10-02 に覆した記録）」）。本文ではなく、ワークプランと依頼の手順と状態から導くだけのもの。
プログレスバーはカードの頭としてスクロールしても上に残る（`position: sticky`。カードの中の並びは `docs/architecture/display.md` 4.2「各表示物」のメインビュー）。
プログレスバーの上に題の行は置かない。
会話の流れ（メインビューの本文）にも段の札が出るが、これはワークプランの記録が届いた位置を残す履歴の1行で、いまの状態はプログレスバーだけが持つ（同じ情報を2か所に出さない）。

```
 ┌ 進み具合のプログレスバー（カードの頭） ─────────────────────────────────────────────┐
 │ ● 集計の関数… │ Bash pnpm exec vitest run … 12秒                  4/7  [手順 ⌄] │
 │ ▬▬▬ ▬▬▬ ▬▬▬ ▬▬▬(伸びる線) ▭▭▭ ▭▭▭ ▭▭▭   ← 下線: 7等分の区間          │
 └─────────────────────────────────────────────────────────────────────┘
```

- **状態の印と見出し**: 1行目の左端に、いまの状態を印と見出しの語で出す
  （形は ADR 0070 論点 3）。
  状態は6つ: 作業中・バックグラウンドで作業中・答え待ち・止めた・失敗・完了。印は 16px の箱に収め、状態が替わっても見出しの左端を動かさない。印は回さず脈打たせない。
  見出しは手順のボタンと同じ字の大きさ（`--font-secondary`）の太字で、縮めず「…」にもしない（幅が足りないときは右の一文が縮む）。

  | 状態                     | 状態の印                | 見出し                         | 一文                         |
  | ------------------------ | ----------------------- | ------------------------------ | ---------------------------- |
  | 作業中                   | `--accent` の点         | 今のフェーズの名前             | 無し（いまの手順は別の決め） |
  | バックグラウンドで作業中 | `--accent` の点         | 今のフェーズの名前             | 無し（いまの手順は別の決め） |
  | 答え待ち                 | `--state-warn` の点     | 「返事を待っています」（琥珀） | 「質問 n件」「許可 n件」     |
  | 止めた                   | `--ink-soft` の四角     | 「止めました」                 | 「〈今のフェーズ〉の途中」   |
  | 失敗                     | `--state-ng` の ✕       | 「失敗しました」               | 失敗の理由の語               |
  | 完了                     | `--state-ok` のチェック | 「できました」                 | 無し                         |

  ワークプランの無いターンの見出しは「作業中」。緑はチェックの印だけに使う。
  一文は見出しの右に縦線で区切って置き、無いときは縦線も出さない。件数の質問は問いに含まれる質問の数、許可は許可のお伺いの数で、両方あれば「質問 1件・許可 1件」。
  失敗の理由の語は失敗の表示の理由と同じ関数（`turnFailureLabel`）から引き、引けなければ一文を出さない。
  **バックグラウンドで作業中はプログレスバーだけの状態**（やり取りの列の印には無い）で、ターンが動いておらず、答え待ちも無く、
  バックグラウンドタスクが残っているときに出す（モデルはもう手を止めていて、背景のコマンドだけが生きている）。答え待ちが来ていれば答え待ちが先。
  状態の導き方はやり取りの列の結果の印と同じ（`turnResultsOf`。列の印の字は変えない）。
  答えるボタンと「続きを頼む」はプログレスバーに置かない（質問の札と流れの止めた表示が持つ。失敗の理由の詳しい説明と次の手は失敗の表示が持つ）

- **下線の区間**: 帯の下端に、ワークプランの要素の数で等分した区間を隙間なく並べる（ADR 0070 論点 4・5）。
  区間の数は要素1つにつき1つで、並列のフェーズの配列は1つ、委譲の範囲が未定のあいだ（`pending`）も範囲で1つ、ワークプランの無いターンは今の区間1つ。
  済んだ区間は差し色、今の区間は太く、まだの区間は白の薄塗り。飛ばしたフェーズも済んだ区間と同じに数える（`docs/architecture/display.md`「ワークプラン」）。
  ページが隠れていたあいだに済んだ区間は、見えるようになっても次にフェーズが進むまで濃い差し色で残す（タブのメモリだけで保存しない）。
  完了は全部の区間が済んだ色で、緑にしない。答え待ちの今の区間は `--state-warn` で止まり、止めた・失敗の今の区間は縁だけを残す。
  働くあいだ（バックグラウンドで作業中も含む）、今の区間の中を線が始端から終端まで伸びて消え、また始端から伸びる（2.4 秒で 1 周。`transform` だけを `linear` で滑らかに動かし、`steps()` で間引かない。動きを減らす設定では半分まで伸びた形で止める）。
  フェーズが済むと、その区間が一瞬白く光ってから済んだ色に落ち着く（描画のあいだに済んだときだけで、付け直し・再読み込みでは光らない。動きを減らす設定では光らせない）。
  どの区間も `button`（Tab で届く）で、読み上げの名前は「フェーズ 2/4 名前（いま）」（済み・いま・これから）。今のフェーズが並列で2つ以上なら名前は「・」でつなぐ。
  押せる高さは線の上下に広げ、隣の区間と隙間なく並べる。押すとそのフェーズの詳細が区間の下に重なって出る（下の「区間を押したとき」）。
  名前を出すのは見出し（今のフェーズ）だけで、群の名（前・本・後）・番号つきの丸・済んだ数のまとめは帯に置かない（手順の一覧の中は残す）。
  右端の手順のボタンの左に、区間で数えた位置「今/全体」（「4/7」。等幅）を出す。完了とワークプランの無いターンでは出さず、中央の列の幅が 720px 未満では位置から譲って隠す。
  位置の右に、目安の残り「あと3〜5分」（等幅の数字。`remainingEstimateOf`）を出す（ADR 0070 論点 6）。
  残りの区間の数（今の区間を含む）を n、同じ依頼の中で済んだ区間の所要の最短を a・最長を b、今の区間の経過を t として、下の端は n×a−t、上の端は n×b−t を分に切り上げる。
  下の端は 1 分を下回らず、上の端は下の端より 1 分以上大きい。n は位置と同じ区間（ワークプランの要素1つ）で数え、区間の所要は並列なら中の和ではなく壁時計を使う。
  所要が測れない済んだ区間と飛ばしたフェーズは a・b から外し、セッションをまたいだ記録は使わない。
  t は分に切り捨てて式に入れ、値は分が替わるときとフェーズが替わるときだけ書き直す（秒ごとには揺らさない）。
  済んだ区間が無い・範囲の数が未定・答え待ち・止めた・失敗・完了・ワークプランの無いターン・狭い画面（760px 以下）では出さず、バックグラウンドで作業中は出す。
  中央の列の幅が 560px 未満では、位置の次に目安の残りを隠す。
  帯は広い画面で頭の左右の余白（`--gutter-region`）の内側に置き、左右の端を入力欄にそろえる（頭は縁を含めて 976px までで、中央の列の中で左右の中央に置く。`layout.md` 13.4、ADR 0072）。
  右端に「手順」のボタン（字の右に開閉の山形の印を置き、閉じていれば下向き、開くと上向き）。経過は1行に出さず、手順のボタンが開く全体の詳細の下端に置く。
  位置・手順のボタンは帯の右端に寄せ、左の一文の長さが変わっても横に動かさない。
  **760px 以下ではプログレスバーを出さず、同じもの（状態・フェーズの丸・今のフェーズの名前・経過・「手順 n」）を頭の2行が持つ**
  （13.9「狭い画面（760px 以下）」。プログレスバーを2行にはしない）
- **「いま: <セクション>」**（見本は `docs/history/mockup/report-reading-tool-2026-10-18/after-norail-w1400.png`）:
  読んでいる `##` の字を、1行目の一文の右（位置の左）に出す。出すのはやり取りの列を畳んだときだけで（開いていれば列の
  見出しの強調が同じことを言う）、新しい行は足さない。字は `--ink-quiet`・普通の太さで、縮むのはこの字（末尾を「…」にする）。
  セクションは読む面の上端を通り過ぎた最後の `##` で、`###` の途中にいても親の `##` を出す。スクロールし切ったときは最後の `##`
  （最後の見出しが上端に届かないため）。見出しの無いレポートと、最初の見出しより前では出さない。
  **760px 以下は頭の1行目の状態の語・経過の右に同じ字を出す**（列もプログレスバーも無いので畳みは見ない。読む面の上端は本文のスクロールする器の上端）
- **並列のフェーズ**（`docs/architecture/display.md`「ワークプラン」の「同時に走るフェーズは、並列のフェーズで受ける」）: 配列全体で下線の区間1つ。配列の中のフェーズがすべて済むと済んだ区間になり、どの順で済んでも済んだ区間は戻らない。
  今のフェーズが2つ以上なら、頭の字は今のフェーズの名前を「・」でつなぎ（末尾を「…」で縮めるのは同じ）、位置は区間で数えるので1つのまま（「2/4」）。区間の読み上げの名前も済んでいない今のフェーズを「・」でつなぐ。お伺いが届いたら今の区間を琥珀で止める。済んだ姿の「7フェーズのうち3フェーズ済み」は並びを平らにしたフェーズで数える

```
 │ ● B・C…  2/3  [手順 ⌄]（下線は3等分、2つ目が今の区間）               │
```

- **区間を押したとき**: 押した区間の下に、そのフェーズの詳細が重なって出る（ネイティブの Popover API は使わず、`usePopover` と同じ `useDismissSignal` と `acquireOverlay` に載せる）。
  - 中身は、済んだフェーズならまとめと手順、今のフェーズなら走っている手順と直前の手順、まだのフェーズなら名前と一言（次のフェーズは「今のフェーズが済んだら始めます。」、その先は「まだ始めていません。」）
  - 見出しは、状態の印・名前・「2/4 · 済み · 48秒」（まだのフェーズは所要を付けない）。委譲の範囲の中のフェーズは群の番号（「本 2」）を添える
  - 外を押す・Esc・同じ区間をもう一度押すと閉じる。Esc では押した区間へフォーカスを戻す。開いているあいだもピルの1行は替えない
  - 開く詳細は1つだけ。フェーズの詳細を開くと「手順」の一覧は閉じ、一覧を開くとフェーズの詳細は閉じる
  - 面は押した区間の下 8px に重ね、幅は 340px（帯の幅を超えない）、左右はピルの端とビューポートの端 8px の内に収める。位置は押したときに測って置き、流れを押し下げない。頭（sticky）と一緒に動く
  - 区間の押す的は線の上下に広げ、隣の区間と隙間なく並べる（見える線の太さ・プログレスバーの高さは変えない）
  - 答え待ちの今の区間も同じに押せる。並列のフェーズの配列は1つの区間なので、名前を「・」でつないだ1つの詳細が開く。
    760px 以下の頭の2行の丸は押せない
  - 区間の hover は線の周りだけを薄く縁取る（押せる高さは1行目に重なるので、地は敷かない）

- **いまの手順の一文**（広い画面のプログレスバーの1行。見出しの右の縦線の右）: 対象・つなぎと動詞・手順の秒・添え書きを1行で置く。
  「いま」の字と回る印は出さない。ターンが走っているあいだはいつも出し、最終レポートに入れ替わったあとの続きのターンでも出す。
  答え待ち・過去のやり取りでは出さない（答え待ちは状態の表の一文が持つ）。流れの末尾には行を置かない（ADR 0070 論点 1・2）。
  対象は頭から「…」で縮め、最後の語（ファイル名・コマンドの最後の語）を残す。見出しは縮めない。幅が足りないときは添え書きから先に譲る。
  手順が替わると、古い文が上へ抜けて新しい文が下から入る（0.32 秒。`transform` と `opacity` だけ。動きを減らす設定では止める）。
  プログレスバーの「2行目」にあった走っている手順の置き場は、この一文へ移した（ADR 0059・ADR 0070）。
  狭い画面は「いまの段」の下の1行が持ち、文は今のまま（`workActivityOf`。広い画面の文は `nowStepStatementOf`）。
  道具の手順は対象だけを出し、つなぎと動詞を付けない（「sort-order.ts」。対象は要約で等幅〔`summarizeToolInput`〕、表に無い道具は道具の名前。
  対象が引けない手順だけは動詞を太字で言う）。道具でない状態は動詞だけ（「考えています」）、委譲は役に「任せています」、
  バックグラウンドタスクは対象の前に「バックグラウンドで」。これに、手順が始まってからの秒（`formatElapsed`）と、
  幅が足りないとき先に譲る添え書き（委譲の説明・再試行の回数）を添える。動詞の表は ADR 0062 論点 3 と ADR 0070 論点 2 が正（ここへ書き写さない）。
  道具の手順で動詞を外したのは、等幅の対象（パス・コマンド）だけで何をしているかが読め、「を読んでいます」「を走らせています」が冗長だったため（利用者の決定）。
  道具の名前から機械的に引き、文を作る処理は持たない。時間が掛かっても添え書きや回る印の遅さは付けず、秒がそのまま長さを言う。
  API の再試行中は「API の応答 を待っています」に添え書き「n回目の再試行」を付ける（理由と待ち時間は `title`）。
  以下は、何を行の対象に選ぶかの決まり。手順を持つバックグラウンドタスク
  （ワークフロースクリプト・サブエージェント）は、手順を持たないバックグラウンドタスク（Bash・Monitor）の説明より先に出す。
  手順を持つものが複数なら、いちばん新しく手順が始まったものを出す（同時刻なら顔ぶれの後ろの方。
  サブエージェントの手順はタスクに結ばれないので、サブエージェント全体で1つと数える）。
  選んだものがサブエージェントなら「バックグラウンドで <役> に任せています」に、依頼の `Agent` の手順の説明（無ければバックグラウンドタスクの説明）を添え書きで付ける。
  選んだものがワークフロースクリプトなら、その中で
  手順が始まっていれば、始まりだけでなく終わりも見る。走っている手順は動詞の前に「バックグラウンドで」を添えて言い、
  手順が終わって次がまだで、ワークフロースクリプトの agent に走っているもの（start・progress）があれば
  「バックグラウンドで <段の題> を進めています」と言い（段の題は agent の `phaseTitle`。役は運ばれないので作らない）、
  走っている agent が無ければ（段の間）ワークフロースクリプトの説明（「バックグラウンドで <説明>」）に戻す
  （SDK はワークフロースクリプトの中の手順をメインの流れに流さないので、
  `PreToolUse` のフックから `workflow-step-started` に、`PostToolUse`・`PostToolUseFailure` のフックから
  `workflow-step-finished` にして運び、`tool_use_id` で始まりと突き合わせる（新しい手順に替わったあとに届く古い終わりは捨てる）。
  `task_progress` の `workflow_progress` で agent の `state` が done・error になっても、その agent の手順は終わりになる。
  `task_progress` の `workflow_progress` が名指す agent の id と
  フックの `agent_id` を突き合わせ、その agent を持つワークフロースクリプトに当てる（どのワークフロースクリプトの agent でもない呼び出しは捨てる）。
  ワークフロースクリプトが顔ぶれから外れると手順も消える。
  目視は疑似セッションの場面 `workflow-steps`）。
  **常に1行**（要約の改行は空白に畳み、長ければ末尾を「…」にする。複数行のコマンドで行が伸びるため）
- **お伺い**: 答え待ちが届いたら（`pending` が空でない）、今の区間を `--state-warn` で止め、
  いまの手順の一文は出さない（見出しと区間が答え待ちを言い、お伺いのカードが末尾に出る）。
  狭い画面の「いまの段」の下の1行は、何を待っているか（「お伺いが届いた · 許可: Bash rm -rf … · 答え待ち 8秒」、質問なら
  「質問: <1問目の header>（ほか n問）」）を出す。待った秒は、答え待ちが届いた時刻（状態の `pending` の
  `askedAt`）から数える。答えるカードそのものはプログレスバーの下の本文に出る
- **手順のボタン**: 「手順」を押すと、依頼全体の詳細を帯の右端にそろえて帯の下に重ねて開く（本文は押し下げない。頭の高さは開閉で変わらない）。
  外を押す・Esc・「手順」をもう一度押すと閉じ、Esc ではフォーカスを「手順」へ戻す。開く詳細は1つだけで、区間のフェーズの詳細とは同時に開かない。
  幅は 30rem（帯の幅を超えない）、高さはビューポートの 70%（35rem まで）を超えたら面の中でスクロールする。やり取りが替わると閉じる。
  先頭は見出し「依頼の手順」と「n フェーズ」、次に「バックグラウンドタスク」の区画。ワークプランがあれば、フェーズを上から1行ずつ（印・名前・所要。印と数え方は区間と同じで、
  並列のフェーズと範囲の群の名も同じ）並べ、行の下にそのフェーズの手順（13.9「いまの作業」の一覧の手順の行。失敗の行は

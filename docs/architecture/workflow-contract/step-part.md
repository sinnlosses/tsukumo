# ワークフローの契約: 部品

ステータス: **正典**。入口は `docs/architecture/workflow-contract.md`（ワークフローの契約の全体）。

責務: ワークフローの並びに差し込めるスキル（部品）の作り手が守る印・受け取るもの・返すもの・置ける位置・しないことを、このファイルだけで読める形で持つ。
読む時: 並びに差し込む段のスキルを書く・直すとき。
直す時: 印の名前・部品が受け取るもの・返す結果の語・置ける位置を変えたとき。判断の経緯は `docs/architecture/adr/0079-workflow-part-contract.md`。

## 部品の契約

**部品は、ワークフローの並びに差し込めるスキル。** 作り手が守るのは印・受け取るもの・返すものの3つだけ。

1. **印**: SKILL.md の frontmatter の `metadata` に `workflow-step: "true"` を置く。段の名前を日本語で出したければ `workflow-step-title: "<名前>"` も置く（無ければ `name`）。
   置き場は作業ツリーの `.claude/skills/`・利用者の `~/.claude/skills/`（リンクでよい）・ワークフローの plugin の `skills/` のどれか。ほかの plugin のスキルは拾わない。
   印のあるスキルが `tw config --schema` の `steps` の候補に出て、歯車の設定の「並び」から選べる
2. **受け取るもの**: 呼び出しの引数のタスクの ID 1つ。それ以外を会話の文脈から受け取らない。前の段の結果とタスクの中身は `tw show <ID>`（Beads）から読み、自分の結果の中身（したこと・分かったこと）も Beads に書く
3. **返すもの**: 手順の最後に、結果の語を1つと1〜2文を返す。
   - `finished`: 済ませた。1〜2文はプログレスバーの中間レポートに出る
   - `skipped`: この回は要らなかった（近道・条件に当たらない）。1〜2文は飛ばしたわけ
   - `stopped`: 途中で止めた。1〜2文は止めた理由。並びはここで止まり、同じタスクを呼び直すとこの段から再開する

## 置ける位置

実装（`implement`）より後ろならどこでもよい。`implement` より前には置けず、`tw config set` が終了コード2で断る。

- 受け入れ（`accept`）より前に置いた部品が変えた作業ツリーは、受け入れの対象の差分に入る。差し戻しで部品は走り直さない
- 受け入れより後ろに置いた部品は、作業ツリーを変えない。変えると送り出し（`tw finish`）が `CHANGED_AFTER_ACCEPT` で止まる

## 呼ばないもの・しないこと

- プログレスバー・委譲・ワークプランのツール（`work_plan`・`phase_result`・`report`）を呼ばない。部品を走らせるのはワークフローの agent で、結果の語をプログレスバーへ写すのもその agent
- コミット・送り出しをしない（`tw` の関門が拒む）
- 設定コマンドと Beads の欄の形は `docs/architecture/workflow-contract/config-and-beads.md` が持つ。部品の作り手はこのファイルのほかを読まなくてよい

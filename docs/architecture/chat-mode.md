### 4.9 雑談モード

**入れる**（2026-09-20 決定）。レポートを読むための画面とは別に、**キャラクターと短い往復を
するだけの場**を持つ。「1. 概要・目的」の2つの成分のうち**「キャラクターと一緒にいる感じが
すること」の側だけを取り出した場**で、仕事の側（レポート）は止める。

**モードとして分ける**（モードが無いと「今回は雑談かどうか」をモデルの推測に委ねることになり、
**雑談のつもりが技術文で返る揺れ**が残る）。

#### 雑談モードで変わるもの

| 変わるもの                             | 仕事のとき                       | 雑談のとき                                                          |
| -------------------------------------- | -------------------------------- | ------------------------------------------------------------------- |
| レポートの記法（`report-notation.ts`） | `systemPrompt` に載る            | **載せない**                                                        |
| ターンの本文                           | メインビューにレポートとして出る | **出さない**（答えはすべてセリフ）                                  |
| メインビュー                           | レポートを縦に積む               | **立ち絵と会話のログ**（`docs/architecture/screen-design.md` 13.7） |
| キャラビュー                           | 立ち絵と吹き出し                 | **畳む**（立ち絵がメインへ移る）                                    |
| サイドバー                             | タスク一覧と下端の帯             | **4段に差し替わる**（`docs/architecture/screen-design.md` 13.7）    |
| セリフの間合い（`speech-cadence.ts`）  | ツールの前後に1回                | **往復そのもの**になるので別の文面が要る                            |

**「レポートは出さない」はユーザーの決定**（2026-09-20）。**雑談中に調べ物を頼んだときも本文は
出さず、セリフで返す**（本文が出たターンだけ画面を入れ替えると、モードに入っている意味が薄れる）。

**`speak` で終えたターンに本体が差し込む催促は、仕組み（環境変数）で塞ぐ**（2026-09-24 に
「仕組みと条の両方」と決め、2026-09-25 に条を外した。どちらもユーザーの決定）。雑談のターンは
`speak` のツール呼び出しで終わるので、本体が `[Your previous response had no visible output. ...]`
を利用者の発言として差し込み、1往復増える。

- **仕組み**: 子プロセスに `CLAUDE_CODE_TERMINAL_MCP_TOOLS=mcp__tsukumo__speak` を渡す
  （`src/server/session-driver/core/visible-output-nudge.ts`。仕事・雑談の両方で渡す）。直前の
  ツールの往復にこの変数に載ったツールの成功した呼び出しがあれば、本体は催促を出さない
  （同梱の `claude` 2.1.280 と 2.1.281 のバイナリで確かめた判定。判定は `Stop` フックより前に
  走るので、フックからは止められない）。**公式の文書には載っていない**
  （2026-09-24 に `env-vars.md`・`settings.md`・`llms-full.txt` の全文を当たった。催促そのものは
  2.1.183 の変更履歴にだけある）ので、本体の更新で黙って効かなくなりうる。**催促が届いたら
  気づける見張りを一緒に置く**（`src/server/session-driver/adapter/sdk-driver.ts`。催促の固定文で始まる
  利用者側のメッセージを見たら、届いた事実だけを stderr に1行出す。中身は写さない）
- **条は置かない**: 最後の `speak` のあとに「完了」の1行を書かせる条を保険として重ねていたが、
  `report` を呼ばないターン（仕事のセッションで一言だけ返すとき）ではその1行が最終レポートとして
  画面に出た（`docs/architecture/display.md` 4.2 の、`report` が呼ばれなかったターンの扱い）。環境変数が
  効くことを実機で確かめたうえで、2026-09-25 に外した。
  変数が効かなくなったら見張りの1行で気づき、そのとき改めて手を考える

**雑談のときだけ、キャラクターから話しかけてもらえる**（2026-09-21 決定）。利用者がボタンを
押すと tsukumo が合図を1つ送り、キャラクターが**自分で選んだ話題**で話し始める。

- **送った合図は画面のログにも記録にも、下の「雑談の会話のアーカイブ」にも残さない**
  （2026-09-21、ユーザーの選択）。利用者が打っていない一言をログに並べない、という点で下の
  「依頼として流す案は採らない」（直近の逐語の読み戻し）と同じ立場
- **話題そのものを tsukumo は持たない**（原則4「キャラクターの中身をコードに書かない」）。
  渡すのは「話題はあなたが選ぶ」という合図だけ
- **時間では起こさない**（2026-10-05 利用者決定。黙って立つだけの場面を埋める見直しで、誰もつつかない
  間が一定時間続いたら合図を送る案と比べ、この決定を保った。見直しの結論は `docs/requirements.md` 4.3
  「黙って立つだけの場面の埋め方」）
- **仕事のときは押す場所そのものが無い**（メインビューが雑談のログではないため）。
  ボタンの置き場所・見え方・ターン進行中の扱いは `docs/architecture/screen-design.md` 13.7

#### 切り替え方

**セッションを起こし直す**（`session.switchCharacter` と同じ道）。`systemPrompt` はセッションを起こす
ときに固定されるので、載せる文面を変えるには起こし直すしかない。**切り替えるたびに画面が
初期化される**のはキャラクターの切り替えと同じ挙動で、そこは受け入れる（2026-09-20）。

**雑談と仕事は、画面だけでなく claude 側の文脈ごと分ける**（2026-09-20 決定。分けないと仕事中の
依頼とセリフが雑談のログに並び、画面だけ仕切っても口調と話題が仕事へ引かれる）。**セッションの
印をモードごとに分け**（`tsukumo:<パック名>` と `tsukumo:<パック名>:chat`。4.8「鍵」）、
起こし直すときは**これから入る側の印を持つセッションを `resume` する**。雑談⇄仕事を往復しても、
それぞれが自分の側の続きに戻る。**両側で分ける** — 仕事へ戻したメインビューにも雑談は出ない。
**仕事の側の印の文字列は変えない**（変えると、いま続いている仕事のセッションが次の起動で
見つからなくなる）。

**代わりに、そのパックで一度も雑談のターンを終えていないうちは、雑談のログが空から始まる。**
印が付くのはターンが終わって数秒あとなので（4.8「鍵」）、最初の雑談には続きにするものが無い。
**これは受け入れる**（4.8「復元できなかったときどうするか」の範囲）。

**切り替える口は画面の最上部の帯の「仕事｜雑談」のトグル**（2026-09-23 決定）。モードは
セッション限りの**動き方**で、どの画面からでも変えられる帯に置く（`docs/architecture/screen-design.md` 13.6 の表）。

- **トグルを1回押すと起こし直す**（確かめの一言は挟まない）。失うのは画面の初期化だけで、それは
  上で受け入れてある。戻せばそれぞれの続きから始まる
- **ターン進行中は切り替えられない**（キャラクターの切り替えと同じ条件。画面は押せなくし、
  サーバも断る）。理由の文面はモードの語で言う（「ターン進行中は仕事と雑談を切り替えられない
  （中断すると切り替えられる）」）
- 形・押せないときの見せ方は `docs/architecture/screen-design.md` 13.9「動き方の操作子」、雑談中の帯は 13.7

#### どこまで遡れるか

**雑談だけ記録の上限を上げる**（2026-09-20 決定）。`src/shared/session/session-state.ts` の
`MAX_SESSION_STATE_TURNS = 20` は仕事のときの値として据え置き、**雑談のときは 100 ターン**を
持つ。雑談の1ターンはセリフ1〜2件で軽く、20往復は会話としては短いため。上限そのものは消さない
（**常駐プロセスが持つ記録を無限に増やさない**という `trimToRecentTurns` の前提）。

**仕事のメインビューとは揃えない。** 仕事は依頼ごとの札に区切って `‹` `›` で遡り
（`MAX_MAIN_VIEW_TURNS`）、雑談は素直な時系列をスクロールで遡る。並びの規則が違うので、遡り方も
別のままにする（`docs/architecture/screen-design.md` 13.7）。

#### 記憶の圧縮と忘却

**入れる**（2026-09-21 決定。2026-09-25 に形を組み替えた）。狙いは**記憶を引き継ぎつつ忘却を
再現する**こと。**人のように大量に覚えていて、トークンを際限なく使わず、索引で局所的に記憶を
引ける**形にする（2026-09-25 のユーザーの指示。比べた案と見積もりは
`docs/research/chat-memory-index.md`）。

**記憶は4つの層で持ち、うち2つは引いたときだけ載る**（2026-09-25 決定）:

| 層               | 何が渡るか                           | どこから来るか                                            | いつ載るか                       | 書くのは                   |
| ---------------- | ------------------------------------ | --------------------------------------------------------- | -------------------------------- | -------------------------- |
| 作業記憶         | **直近の会話の文面そのもの**（逐語） | `~/.tsukumo/chat-archive/`（下のアーカイブ）              | 起こすとき                       | —（アーカイブを読むだけ）  |
| あらすじ         | 作業記憶より前の話の筋（要約1つ）    | `~/.tsukumo/chat-summary/<パック名>.md`                   | 起こすとき                       | **定着の `query()`**       |
| 覚えたこと       | キャラクター自身の属性               | `persona.md`（下の「プロフィールの書き戻し」）            | 起こすとき                       | キャラクター（`remember`） |
| エピソード索引   | 見出し・要旨・手がかり語             | `episode.jsonl`（下の「古い雑談は索引を引いて思い出す」） | キャラクターが `recall` したとき | **定着の `query()`**       |
| エピソードの逐語 | 開いた1件の会話の文面                | アーカイブ                                                | `recall_episode` で開いたとき    | —（アーカイブを読むだけ）  |

**記憶は雑談と仕事で1つ**（2026-09-26 決定）。同じアーカイブ・同じエピソード索引・同じあらすじを
両方のモードが書き、両方のセッションが読む。**分かれているのは claude 側の文脈（セッション）だけ**
（上の「切り替え方」）で、雑談中に仕事の話を、仕事中に雑談の話を思い出せる。例外は覚えたこと
（`remember` / `forget`）で、雑談だけのまま（下の「プロフィールの書き戻し」）。

| 層         | 雑談のセッション                               | 仕事のセッション                                            |
| ---------- | ---------------------------------------------- | ----------------------------------------------------------- |
| 作業記憶   | 新しいほうから 64 KiB                          | **新しいほうから 16 KiB**                                   |
| あらすじ   | 載る（下の「載せる条件」）                     | **起こすたびに載る**                                        |
| 覚えたこと | 載る（`persona.md` の一部）                    | 載る（`persona.md` の一部。書き足す・消すツールは載らない） |
| 索引・逐語 | `recall` / `recall_episode` で引く             | **同じく引ける**                                            |
| 書くもの   | 依頼とセリフ（下の「雑談の会話のアーカイブ」） | **依頼の冒頭・`conclusion`・セリフ**（同じ節）              |

**起こすときに載る量は、アーカイブが何年ぶん増えても容量の表の合計で頭打ちになる。** それより
前の会話は、キャラクターが引いたときにだけ、引いた1件ぶんが文脈に入る。

**容量は1つの表に集め、値を書き換えるだけで上げ下げできるようにする**（2026-09-25 のユーザーの
指示）。**設定ファイル・環境変数から上書きする口は作らない** — 利用者は作者本人だけで、表を直して
上げ直せば足りる（要るようになったら `docs/research/configuration-and-state.md` の置き場に足す）。
表は `src/shared/chat/chat-memory-budget.ts` の `CHAT_MEMORY_BUDGET` 1つ。**値の根拠はこの節だけに
書く**（コードの doc コメントには書かず、ここを指す）:

| 何                    | 表の鍵                  | 既定値           | 根拠                                                                                                                       |
| --------------------- | ----------------------- | ---------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 作業記憶（雑談）      | `recentBytes`           | **64 KiB**       | ユーザーの指示（2026-09-21。2026-09-25 にも据え置き）。下の「直近の会話は逐語のまま読み戻す」                              |
| 作業記憶（仕事）      | `workRecentBytes`       | **16 KiB**       | ユーザーの選択（2026-09-26）。仕事の文脈を記憶で押し広げない。定着が畳む境目もこれ（下の「窓から溢れた会話は定着で畳む」） |
| 仕事の行の文面        | `workExcerptChars`      | **300 文字**     | 依頼の冒頭と `conclusion` を切る長さ（コードポイント）。仕事の1ターンが 1〜2 KiB に収まり、16 KiB で 8〜10 ターンぶん      |
| あらすじ              | `synopsisBytes`         | **8 KiB**        | 要約が**会話の写しに育つ経路を塞ぐ**上限。作業記憶の 1/8 で、要約がここへ近づいたら畳まれていない（下の縛りの表）          |
| `recall` の一覧       | `recallListBytes`       | **2 KiB**        | 候補の `id`・見出し・要旨で 10 件前後。一覧は目次で、逐語を渡さない                                                        |
| `recall` を引ける回数 | `recallListsPerTurn`    | **1ターンに2回** | 1回目の言葉が外れたときに、言い換えて引き直せる                                                                            |
| エピソードの逐語      | `recallEpisodeBytes`    | **8 KiB**        | 1件の話を頭から追える量。定着の1回の入力（契機の2倍）の半分                                                                |
| 開けるエピソードの数  | `recallEpisodesPerTurn` | **1ターンに2件** | 候補が2つに割れたときに両方を見比べられる                                                                                  |
| 定着の契機            | `consolidateEveryBytes` | **8 KiB**        | 雑談の1ターン（130〜195 バイト）で 40〜60 ターンぶん。日に20往復なら2〜3日に1回走る                                        |

- **常に載るのは作業記憶とあらすじの、雑談 72 KiB・仕事 24 KiB**（それに覚えたこと）。組み替える前の比較は
  `docs/history/decision.md`「chat-mode.md 4.9 雑談モード（容量の比較・やめた keep の旗・recall の戻り値を広げた理由）」
- **1ターンで増える文脈は 20 KiB で頭打ち**（一覧 2 KiB × 2 回＋エピソード 8 KiB × 2 件）。
  ふだんは引かないので 0
- 値を上げたくなったら表の値だけを直す。**ほかの値は表から導き、別の定数として持たない**
  （定着の1回の入力の上限は `consolidateEveryBytes` の2倍）

**`/compact` はやめる**（2026-09-25 決定）。**要約を作るのは背景の使い捨て `query()`**（下の
「窓から溢れた会話は定着で畳む」）で、いま動いている claude の文脈の中ではない。

- **これは 2.2 の「会話を外部のモデルへ送る」に当たらない。** 受けるのは同じマシンの claude の
  子プロセスで、送り先は動いている雑談と同じ Anthropic の API（`docs/requirements.md` 2.2）。
  **使い捨ての `query()` にアーカイブの逐語（2026-09-26 から仕事の行も）を渡すことは、規約の例外として
  2026-09-25 にユーザーが認めた**（`docs/coding-standards.md`「会話内容の扱い」）。tsukumo が別の事業者・別のサービスへ
  送る案は 2.2 のまま対象外
- **tsukumo は `/compact` を投げず、`PostCompact` の写しも取らない。** 組み込みの `/compact` を
  利用者が手で叩くことは止めない（入力欄の `/` 補完にも出る）が、tsukumo の記憶には関わらない

**雑談は起こすたびに `resume` し、tsukumo は自分から新しいセッションに切り替えない**
（2026-09-25 のユーザー判断）。

- **新しいセッションにするのは利用者の責任**（`/clear`・`TSUKUMO_NEW_SESSION=1`）。そのときに
  作業記憶・あらすじを載せる条件は下の「載せる条件は2つあり、どちらかに当たれば載せる」
- **新しいセッションで画面のログが空になるのは受け入れる。** 画面が空でもキャラクターが覚えて
  いるのは、人がひと晩寝ても記憶が残るのと同じで自然（ユーザーの見方）。**アーカイブから画面を
  復元する口は作らない**
- **`resume` を続けるあいだ claude 側の文脈は伸び続ける**（1ターンの読み出しが積もった会話の
  分だけ増える）。これも利用者が新しいセッションにする判断に任せ、**受け皿は claude 自身の自動の
  圧縮だけ**になる。tsukumo は容量を数えて畳む役を持たない

**忘却は2つの縁で起きる:**

1. **新しいセッションへ渡るのは作業記憶・あらすじ・覚えたことだけ。** 作業記憶より前は、
   言葉は残らず筋だけがあらすじに残る
2. **索引の中では「消える」ではなく「引きにくくなる」。** 古くて一度も思い出していない
   エピソードは `recall` の一覧の下へ沈むが、はっきりした言葉を渡せばまた届く（下の
   「古い雑談は索引を引いて思い出す」の採点）

**忘却は画面に1本の区切りとして出す。** claude 自身の自動の圧縮が起きた位置へ、**文言を添えない
細い線を1本だけ**入れる（2026-09-21 決定。忘却は頭の中で起きるもの、という想定）。**セリフでも
知らせない** — セリフの文面を決めるのは claude だけで、tsukumo がキャラクターの言葉を作らない。
起こし直したあとはこの区切りがログのいちばん上に来る。

**画面のログは圧縮では消えない。** 記録（`SessionState`）の上限（雑談 100 ターン）はそのまま効く。
**変わるのは起こし直したあと**で、復元されるログは圧縮点から始まる（`resume` も
`getSessionMessages` も区切りから先だけを見る）。それより前の会話は下の「雑談の会話の
アーカイブ」に残る。**ただし「キャラクターが覚えている範囲」は画面とは別**で、作業記憶は
アーカイブから読むので**圧縮の区切りにも画面の上限にも縛られない**。

**100 ターンは画面の上限であって、残す量の上限ではない**（ユーザーが 2026-09-21 に
tsukumo 側のディスクへの複製を認めた。覆った記録は `docs/history/decision.md`）。
あらすじは記憶を渡すためのもので、会話そのものを残す役は持たない。

**あらすじを1つだけディスクに持つ**（2026-09-21 決定。2026-09-25 に書き手を替えた）。狙いは
**「セッションをリセットしても記憶を持つ」**こと——`/clear`・`TSUKUMO_NEW_SESSION=1`・印を
見失ったとき・`cwd` が変わったときは transcript が別になり、claude 側の文脈ごと落ちるため。
**ユーザーはそれを承知のうえで「新しいセッションでも持つ」を選び、要約を `~/.tsukumo/` の下に
置く例外を認めた**（`docs/coding-standards.md`「会話内容の扱い」の「別の場所に複製しない」に
対する、範囲を限った例外）。

- **書き直すのは定着のたび。** 定着の `query()` に**前のあらすじと、いま畳んだエピソード**から
  あらすじを書き直させる（同じ出力に含める）。上限は `synopsisBytes`
- **置き場は組み替える前の要約の写しと同じ1ファイル**（`~/.tsukumo/chat-summary/<パック名>.md`）。
  **はじめの定着が読む「前のあらすじ」は `/compact` が作った写しそのもの**なので、写しを種に
  使うのは構造上1回だけになる（別の移し替えを持たない）
- 日・週・月の段を別のファイルに持つ木にするかは、あらすじ1つで足りないと分かってから決める
- **中身は1行目が印、2行目からあらすじの本文**（見出しも日時も付けない）。印は「次に起こす
  セッションへ渡す必要があるか」の1ビット（下の「載せる条件」が使う）。**同じファイルに持つ**のは、
  あらすじと印が1回の書き込みで揃うから（別ファイルにすると片方だけ残った状態が生まれる）。
  ファイルを消せば印も一緒に消える
- **書くのは定着が返したあらすじと話題の見出しを tsukumo が1つの本文に組んだもの**で、上書きする。
  書いた文字列は**ログにも画面にも出さない**（出してよいのは長さまで）

雑談のセッションでは、次のように載せ分ける（仕事は下の箇条）:

| セッションが別になる場面                                                    | claude 側の文脈        | あらすじと作業記憶を載せるか                         |
| --------------------------------------------------------------------------- | ---------------------- | ---------------------------------------------------- |
| 起こし直し（モード切替・キャラ切替・上げ直し）                              | `resume` が読む        | **載せない**（載せると2度載る）                      |
| `/clear`                                                                    | 落ちる見込み（未実測） | その場では載せない。**次に起こしたときに必ず載せる** |
| 新しいセッション（`TSUKUMO_NEW_SESSION=1`・印を見失った・`cwd` が変わった） | 落ちる                 | **載せる**                                           |

**載せる条件は2つあり、どちらかに当たれば載せる**（どちらでもなければ載せない）:
(1) **続きから始めない**（新規に起こす） (2) **続きから始めるが、前に `/clear` を見ている**。

- **「続きから始めたか」だけでは足りない。** 印はターンが終わるたびに**そのときのセッションID**へ
  付け直されるので、**`/clear` のあと1ターンでも回すと、空になったほうのセッションが印を持つ**。
  条件が1つだけだと**そのパックの記憶が二度と戻らない**
- **印が無い・読めないときは未渡し扱い** — **黙って記憶が消えるほうへ倒さない**。載せたら
  「渡し済み」に戻す（`resume` した文脈に同じものが既にあるときに重ねない）。**定着があらすじを
  書き直しても印は変えない** — 定着はどのプロセスのどちらのモードのターンからも走るので、畳んだ
  会話を文脈に持っているセッションが決まらない。倒れる方向は「同じものが2度載る」側
- **仕事のセッションは印を読みも書きもせず、起こすたびに（新規でも続きからでも）載せる。**
  `systemPrompt` は transcript に残らず、続きから起こした仕事の文脈に雑談の行は無い。量は小さい
  窓（16 KiB）で抑える
- **`/clear` は印で受ける。** `conversation-cleared` が流れたら印を「未渡し」に戻す
- **判断と印の書き換えは1回で済ませ、あらすじと直近の逐語を同じ機会に組んで返す**（口を2つに
  分けると、先に呼ばれたほうが印を「渡し済み」に戻して、あとの1つが黙って載らない）。並びは
  あらすじ → 直近の逐語で、**印の行は載せない**。前置きには**あらすじであって会話ではないこと**と
  **引用しないこと**を短く添える

**あらすじに会話の文面がそのまま入らないよう、定着の指示に線を添える。** 引く線は
「プロフィールの書き戻し」の3条件と「書かないもの」をそのまま使う（**自分の言葉で書き直す・
発言を引用しない・利用者について知ったことは書かない**）。

**同じ出力で、最近の話題の見出しを書かせる**（2026-09-23 決定。ユーザーの選択。2026-09-25 に
書き手を定着へ移した）。雑談中のサイドバーの「最近の話題」（`docs/architecture/screen-design.md` 13.7）に
出すためで、**話題の一覧という別のデータは持たない**。

- **形**: tsukumo があらすじの**いちばん最後**に `<topics>` と `</topics>` の行で挟んで置く
  （新しい順で3件まで）。見出しにも上の3条件が掛かる。**最後に置く**のは、あらすじが上限を
  超えたときに先頭側から落ちるので、見出しの節が先に消えないようにするため。1行1件で `- ` で
  始める。**組むのはモデルではなく tsukumo**（定着の出力の `topics` から組む）
- **取り出し方**: **最後の `<topics>` から次の `</topics>` まで**を読み、箇条の印を落とし、空行を
  飛ばし、3件で切る。**印が無い・閉じが無いときは空**（推し量って出さない）。組み替える前の写しも
  同じ取り出し方で読める
- **更新されるのは定着のときだけ**（それまでは前回の話題のまま）
- **画面へ流す契機は2つ**（`chat-topics-changed`）: 雑談で起こしたとき、定着があらすじを書いたあと。
  後者は**書いた直後のファイルを読み直して**流す（上限で行が落ちたあとの形から取るので、次に
  起こしたときと同じ見出しになる）
- **一度も定着していないパックは空**で、サイドバーは「まだ話題が無い（話が積もると、ここに
  並ぶ）」を出す。組み替える前の写しに見出しの節があれば、次の定着まではそれが出る
- **画面へ運ぶのは見出しだけ**で、あらすじの本文は運ばない（`SessionState` に載るのは `chatTopics` だけ）

**ただし、それだけでは守らせきれない。** あらすじを書くのはモデルで、**tsukumo は書く中身を読んで
判定しない**（読んで判定する経路を作るほうが規約とぶつかる）。だから**中身に立ち入らない縛り**を
重ねて、あらすじが会話のログに育つ経路のほうを塞ぐ:

| 縛り                                                                                              | 何を塞ぐか                                                                 |
| ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 書くのは定着の `query()` が返したあらすじ1つだけ                                                  | 生のログ・transcript・ツールの入出力は今までどおり書かない                 |
| 1パック1ファイルを上書きする（世代バックアップも取らない）                                        | 履歴が積み上がらない（前のあらすじは残らない）                             |
| `synopsisBytes`（印の行を含む）を上限にし、溢れたら古いほうの行から落とす（行の途中では切らない） | 要約の形をした会話の写しが際限なく太らない                                 |
| 本文を画面にも 手続きの応答にも stderr にも出さない（画面に出すのは話題の見出しだけ）             | あらすじが別の経路から外へ出ない                                           |
| 仕事の会話は、アーカイブに書いた3つ（依頼の冒頭・`conclusion`・セリフ）からだけ畳む               | レポートの本文・ツールの入出力・パスが、あらすじを通って入る経路を作らない |

**元に戻す手はファイルを消すこと。** `~/.tsukumo/chat-summary/` を消せば、そのぶんを忘れる
（次の定着は空のあらすじから書き直す）。

**あらすじは世代を重ねるほど薄くなる。** 書き直すたびに古い話の筋は短く畳まれ、**全部は
残らない**。**これは受け入れる** — 倒れる方向が忘却の側で、この機能が再現したいものと同じ向き
だから。**薄くなるのは筋だけ**で、畳んだ会話はエピソード索引から引ける。

**`/clear` の直後の文脈には記憶が無く、戻るのは次にセッションを起こしたとき**（`persona.md` への
書き戻しと同じ粒度）。**その場で起こし直さない** — 画面の初期化とセッションの起こし直しという
大きな動きを、利用者が打った組み込みコマンド1つの副作用にしないため。**その代わり、「次に
起こしたとき」では確実に戻す**（上の条件2）。`/clear` は利用者がいちばん素直に「セッションを
リセット」と呼ぶ操作なので、ここが抜けるとこの機能の狙いそのものを外す。

**直近の会話は逐語のまま読み戻す**（2026-09-21 決定。上の表の作業記憶）。

**出どころは下の「雑談の会話のアーカイブ」だけ**（`~/.tsukumo/chat-archive/<パック名>/`）。
transcript は読まない（`docs/coding-standards.md`「会話内容の扱い」の「広げていないこと」）。

**量は容量（バイト）で決め、件数では測らない。**

| 何         | 値                                                                                                        |
| ---------- | --------------------------------------------------------------------------------------------------------- |
| 規定の容量 | 雑談 **64 KiB**（65,536 バイト。表の `recentBytes`）・仕事 **16 KiB**（16,384 バイト。`workRecentBytes`） |
| 数えるもの | アーカイブの各行の**文面だけ**の UTF-8 バイト数（時刻・話者・表情は数えない）                             |
| 数える向き | **新しいほうから遡る**（新しい日のファイルから順に、届いたところで止める）                                |
| 切り方     | **1件（1行）を単位にし、途中では切らない**。溢れる1件は載せない                                           |

**64 KiB はユーザーの指示**（2026-09-21。2026-09-25 に 16 KiB へ縮める案を比べて据え置いた）。
**336〜504 ターン**に当たり、画面の上限（100 ターン）の3.4〜5倍あるので、**3つが入れ子**になる:

| 範囲                 | どこまで                                         | 読み方                                                             |
| -------------------- | ------------------------------------------------ | ------------------------------------------------------------------ |
| 画面のログ           | 100 ターン                                       | **いま読める**                                                     |
| 逐語で覚えている     | 336〜504 ターン（64 KiB）                        | **画面から消えても、言葉のまま覚えている**                         |
| あらすじと索引が持つ | 新しいほうの 16 KiB より前（逐語の範囲と重なる） | **話の筋は残っていて、引けば言葉も戻る**（引かなければ出てこない） |

**物差しは日数。** 日に20往復なら 64 KiB は **17〜25 日**ぶんで、**「ここ3週間ほどの雑談は
そのまま覚えていて、それより前は筋と目次になっている」**と読める。画面は窓の 1/3 にも満たないので
**必ず内側に収まり**、「さっき画面で見た話を忘れている」は起きない。

**`systemPrompt` が抱える量が増えることは受け入れる。** 64 KiB は日本語で約 22,000 文字で、
**1文字＝1トークンと最も悪く見積もっても** claude の窓の 2.2% 程度。加えて:

- **前置きは伸びない。** `systemPrompt` は起こすときに固定され、**上限が決まっている側**に入る
- **載る機会が限られる。** 載せるのは「新規に起こしたとき」と「`/clear` のあと」だけ
- **払っているものが、そのまま「覚えている距離」。** この機能が決めるのは忘却の距離なので、
  対価が文脈の数%なら目的と釣り合う

**仕事のセッションには新しいほうから 16 KiB を載せる**（2026-09-26 決定）。数えるのは雑談と
仕事の行を区別しないアーカイブの新しいほうで、並びは人格 → セリフの間合い → 段取り → レポートの記法 →
あらすじ → 直近の会話。**雑談の作法（`chat-manner.ts`）は載せない**。載せる条件は置かず、起こす
たびに載せる（上の「載せる条件」の箇条）。前置きの文面は両方のモードで同じ1つで、「雑談の」とは
言わない。仕事では作法の条が載らないので、思い出せないときに `recall` で引けることも前置きに一言
添える。

**載せる口は `systemPrompt` の append で、雑談の載せる条件はあらすじと同じ**（上の「載せる条件は2つ
あり、どちらかに当たれば載せる」）。どちらでもなければ載せない——**`resume` した文脈には同じ
会話が既にある**。

- **あらすじがまだ無いときも逐語は載せる**（条件を決めるのは「続きから始めたか」と印だけ）
- **依頼として流す案は採らない**（雑談のログに利用者が打っていない一言が並び、次の transcript にも
  依頼として残る）
- **画面には出さない。** 画面のログは今までどおり transcript からの復元で作る（4.8）。**新しい
  セッションでは画面が空でもキャラクターは直近を覚えている**
- **あらすじと範囲が重なるのは許す**（組み替える前の写しを種にしたあらすじは、窓の中の話を
  含むことがある）。**倒れる方向を「忘れる」側にしない**
- **載せるのは文面と話者の別だけ。** 仕事の行にはその印とプロジェクトの名前を添え、`conclusion` の
  行は「したこと」として話者の印を分ける。表情も画像の枚数も載せない（表情はそのときのセリフに付いて
  いた印で、次のセリフを縛る材料にしない）。いつごろの話かは**日付が変わるところに見出しを
  1つ挟む**ことで足りる（並べ替えたり落としたりしない）

**逐語の読み戻しはユーザーが 2026-09-21 に認めた規約の例外**（`docs/coding-standards.md`
「会話内容の扱い」の「読み戻してよいもの」の表）。**逐語の会話が新しいセッションの transcript
（`~/.claude/projects/`）へ毎回書かれることも、その承認に含まれる。** 2026-09-26 に仕事の
セッションへ広げた（16 KiB）。広げたのはここまで。

#### 窓から溢れた会話は定着で畳む

**入れる**（2026-09-25 決定）。作業記憶は**古い順に落ちるだけ**なので、溢れた会話を
背景の使い捨て `query()` に**エピソード**（話題のまとまり）へ畳ませ、索引に積む。これを
**定着**と呼ぶ。

**「残す」旗（`keep`）はやめる**（2026-09-25。経緯は
`docs/history/decision.md`「chat-mode.md 4.9 雑談モード（容量の比較・やめた keep の旗・recall の戻り値を広げた理由）」）。窓から
溢れた会話は**すべて**エピソードに畳まれて索引から引けるので、大事な一言だけを別に残す口は
要らない。大事さはエピソードの `weight` が持つ（下）。**`kept.jsonl` は読まなくなる**（消さずに
残す）。

**索引を書くのはキャラクターではなく定着の `query()`**（2026-09-25 のユーザー判断）。キャラクター
自身に書かせる `index` は、書き忘れに左右され、区切りも見出しの粒度もそろわなかった。

| 論点             | 決め                                                                                                                                                                                                                                                           |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 何を畳むか       | **仕事の作業記憶の窓（16 KiB。小さいほう）から溢れていて**、**まだどのエピソードにも入っていない行**（雑談と仕事を区別しない）                                                                                                                                 |
| いつ走るか       | **雑談・仕事のターンの終わり**に、畳む行が `consolidateEveryBytes` 以上あるとき。**`consolidateEveryBytes` の2倍（下の「1回に畳む量」の上限）で打ち切ったときは、届いていなくても走る**（2026-09-26 決定。待つと、上限で弾かれ続けている行が永久に畳まれない） |
| 同時に走る数     | **プロセスをまたいで1本だけ**（下の錠）。走っているあいだの契機は捨てる（次のターンの終わりにまた数える）                                                                                                                                                      |
| 1回に畳む量      | 畳む行の**古いほうから** `consolidateEveryBytes` の**2倍**まで（1件を単位にし、溢れる1件は次に回す）。**先頭の1件だけで2倍を超えるときは、切らずにその1件だけを単独で畳む**（2026-09-26 決定。行の途中では切らない決めを保ったまま、その回で必ず前へ進める）   |
| 渡すもの         | 畳む行の文面と話者の別（日付が変わるところに見出しを1つ挟む）・前のあらすじ・直前のエピソードの見出し（話題が続いているかを見分けるため）                                                                                                                      |
| 返させるもの     | 話題の切れ目で区切ったエピソードの並び・書き直したあらすじ・最近の話題の見出し（形は下の「受け取る形」）                                                                                                                                                       |
| どこまで畳んだか | **最後のエピソードの終わりの時刻**から分かる（別の印を持たない）                                                                                                                                                                                               |
| 失敗したら       | **その回を諦める**（常駐プロセスは落ちない）。行は畳まれないまま残り、次の契機で拾い直す                                                                                                                                                                       |
| 走らないとき     | 疑似セッション（`TSUKUMO_DRIVER=fake`。本物の claude を起こさない）                                                                                                                                                                                            |

**畳む境目は小さいほうの窓（16 KiB）の外**。64 KiB の外にすると、16〜64 KiB の行が仕事の
セッションからは `systemPrompt` にも `recall` にも届かない。雑談の窓（64 KiB）の中の話があらすじと
索引にも入る重なりは許す（倒れる方向を「忘れる」側にしない）。

**プロセスをまたいで1本にするのは錠のファイル**（`consolidation.lock`。パックのアーカイブの
ディレクトリに置く）。仕事の tsukumo は作業ツリーごとに並行して動き、2本が同じ未定着の行を読むと
エピソードが重なって積まれ、あらすじが後勝ちで上書きされる。

- **排他で作れた（`wx`）プロセスだけが走らせ**、書き終えたか諦めたら消す。作れなければその契機を
  捨てる（走っているあいだの契機と同じ）
- **書いてから定着の時間切れ（120 秒）の2倍を過ぎた錠は、落ちたプロセスの残りとして消して取り直す**
- プロセスの中の1ビット（`session-manager`。起こし直しをまたいで同じ行を2本で畳まない）もそのまま持つ

**量は文面のバイト数で数え、件数では測らない**（作業記憶と同じ物差し）。**数え落としは許す** —
添えた画像は数えない（残るのは枚数だけで、文面ではない）。

**溜まったぶんは、1ターンに1回ずつ畳む。** 定着を入れた時点では、窓の外のアーカイブがまるごと
「まだどのエピソードにも入っていない行」になる。**はじめの定着はアーカイブの最初の行から順に
畳む**（`index.jsonl` の見出しは種にしない。書かれ方がそろっていないため）が、1回に畳むのは契機の
2倍までで、次が走るのは**次のターンの終わり**なので、`query()` が続けて走ることはない
（1回に畳むのは 16 KiB までなので、溜まった 64 KiB なら畳み終えるのに4ターンほど）。

**大事さ（`weight`、1〜3）は定着の `query()` が中身で決める。** 目安は指示に書く: **3** は約束・
頼まれた覚えごと・キャラクター自身に関わる決め事、**2** は中身のある話題、**1** は挨拶と相槌。
**機械の手がかりは「思い出した回数」**（下の「古い雑談は索引を引いて思い出す」の `recalled.jsonl`）が
受け持ち、`weight` には混ぜない — 引かれたことは索引の行を書き換えずに別に積むので、追記だけの
性質が崩れない。

**見出し・要旨・手がかり語に書いてよいものの線は、あらすじと同じ**（自分の言葉で書く・発言を
引用しない・利用者について知ったことは書かない）。**索引は会話ではなく目次**で、開く先が
アーカイブの行の範囲になる。

**定着に渡したものも受け取ったものも、ログ・stderr・手続きの応答・画面に出さない**（出して
よいのは件数・長さまで）。

**起こし方は訪問の台本と同じ使い捨ての `query()`**: 軽いモデル（`CHAT_CONSOLIDATION_MODEL`。
はじめは `haiku`）・ツールなし・MCP サーバなし・設定もフックも読まない（`settingSources: []`）・
1ターン・transcript を書かない（`persistSession: false`）・考える段なし・出力は JSON Schema の
構造化出力。指示文は `systemPrompt` をそのまま置き換える（Claude Code の既定の指示文も CLAUDE.md も
載らない）。**時間切れは 120 秒**（背景で走り、利用者を待たせない）。

**渡すもの**（依頼の文面は tsukumo が組む）:

- **畳む行**: 行番号（1始まり）・話者の別・文面の並び。仕事の行にはその印とプロジェクトの名前を
  添え、`conclusion` の行は「したこと」として分ける。日付が変わるところに見出しを1つ挟む。
  **表情・画像の枚数・時刻は渡さない**（作業記憶と同じ線）
- **前のあらすじ**（無ければ空）。本文だけで、印の行と `<topics>` の組は渡さない
- **直前のエピソードの見出し**（無ければ無し）

**受け取る形**（構造化出力。`episodes`・`synopsis`・`topics` の3つ）:

| 鍵         | 決め                                                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------------------------- |
| `episodes` | 1件以上。**`end` はそのエピソードの最後の行番号**で、前のものより大きく、**最後のものは入力の最後の行**（切れ目なく覆う） |
| `title`    | 空でない 20 文字まで・改行を含まない                                                                                      |
| `gist`     | 空でない 120 文字まで（`remember` の1行と同じ値）                                                                         |
| `cues`     | 1〜10 個・各 20 文字まで。言い換え・上位の語を含める                                                                      |
| `weight`   | 1・2・3 の整数（目安は上）                                                                                                |
| `synopsis` | 空でもよい（`<topics>` の組は含めない。tsukumo が組む）                                                                   |
| `topics`   | 0〜3 個・各 40 文字まで                                                                                                   |

- **区切りを行番号で返させる**のは、モデルに時刻を写させないため。行番号を各エピソードの始まりと
  終わりの**アーカイブの行の時刻**（`from` / `to`）に直すのは tsukumo
- **検査は丸ごと**。1か所でも崩れていたらその回は何も書かず、行は未定着のまま残る。長すぎる
  あらすじは落とさず、書くときに上限で古い行から落とす
- **書く順はエピソード → あらすじ**。途中で止まったときに「エピソードはあるがあらすじが古い」側に
  倒す（行は二重に畳まれない）
- **話題が前の回から続いていても、前のエピソードは書き換えない**（追記だけ）。続きは新しい
  エピソードになり、見出しが似るのは許す

**走っているあいだの契機は捨て、待たない。** 数えるのは1ターンに1回（ターンの終わり）で、走り
終えても次のターンの終わりまで次を起こさない。**次のターン・パックの切り替え・プロセスの終わりと
重なっても待たない** — 書きかけで止まれば、追記済みのエピソードまでが定着したことになり、残りは
次の契機で拾い直す。起こし直しのあとで結果が届いても**書くのは起こした時点のパックのファイル**で、
話題の見出しを流すのは、そのときの状態が雑談で同じパックのときだけ。プロセスを終えるときは
走っている1本を中断し、中断のあとに届いた結果は書かない。

#### 古い雑談は索引を引いて思い出す

**入れる**（2026-09-21 決定。2026-09-25 に2段階の引き方へ組み替えた）。作業記憶とあらすじは
**起こすときに渡しきり**なので、窓から溢れた話の言葉は、引かない限り戻らない。足りないのは探す
手段ではなく、**探しに行く契機と、言葉のずれを吸収する索引**のほう（全文検索の仕組みは要らない）。

**`recall` / `recall_episode` は仕事のセッションにも載る**（2026-09-26 決定。記憶が1つなので、
仕事中に雑談の話を、雑談中に仕事の話を引ける）。1ターンの回数の縛りも同じ。

**引き方は2段階**（2026-09-25 決定）:

1. **`recall(言葉)`**: エピソード索引を採点して、上位の候補の `id`・見出し・要旨を
   **`recallListBytes` まで**返す。**逐語は渡さない**。1ターンに `recallListsPerTurn` 回まで
2. **`recall_episode(id)`**: その1件の範囲の逐語を、**古いほうから `recallEpisodeBytes` まで**
   返す（話の頭から追えるように。溢れたら続きがあることだけを一言添える）。1ターンに
   `recallEpisodesPerTurn` 件まで

| 論点             | 決め                                                                                                |
| ---------------- | --------------------------------------------------------------------------------------------------- |
| 索引を誰が書くか | **定着の `query()`**（上の「窓から溢れた会話は定着で畳む」。**`index` ツールはやめる**）            |
| 探しに行く契機   | **キャラクター自身が引く**（`recall` に引く言葉を渡す）                                             |
| 一覧の並び       | 採点の高い順（下）                                                                                  |
| 読む量           | 一覧 2 KiB・1件 8 KiB。**作業記憶ともあらすじとも別に数える**（値の根拠は上の「記憶の圧縮と忘却」） |

**採点に使うのは4つ**（`node:fs` で索引を読み、TypeScript だけで計算する。`grep` などの外部
コマンドも、埋め込みの API も使わない）:

| 要素           | 効き方                                                                      |
| -------------- | --------------------------------------------------------------------------- |
| 一致           | 手がかり語・見出し・要旨との部分一致。**日本語は2文字ずつの重なりでも拾う** |
| 重み           | `weight` をそのまま掛ける                                                   |
| 新しさ         | エピソードの終わりから日が経つほど下がる（下限があり、0 にはならない）      |
| 思い出した回数 | `recall_episode` で開かれた回数が多いほど、新しさによる下がり方を緩める     |

**忘却は「消える」ではなく「引きにくくなる」で表す。** 古くて一度も思い出していないものは一覧の
下へ沈むが、はっきりした言葉を渡せばまた届く。**言葉のずれを吸収するのは手がかり語**（定着が
言い換え・上位の語を含めて書く）。

**採点の式**（引く言葉は空白で分けた語の並び。比べる前に小文字にする）。係数は
`src/shared/chat/chat-memory-budget.ts` の `CHAT_RECALL_SCORE` の表に置き、**初期値は目安**（使って
みて表の値だけを直す。式を直すのはそれで足りないと分かってから）:

| 段     | 式                                                                                                                                                                        |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 一致   | 語ごとに、手がかり語・見出し・要旨それぞれへの当たり（含まれれば 1、でなければ**語の2文字ずつの組のうち相手に含まれる割合**）に欄の重みを掛けた最大をとり、語について足す |
| 足切り | 一致が `minMatch` 未満のエピソードは候補にしない                                                                                                                          |
| 新しさ | `max(recencyFloor, 0.5 ^ (to からの日数 / (halfLifeDays × (1 + halfLifeGainPerRecall × 思い出した回数))))`                                                                |
| 点     | 一致 × `weight` × 新しさ。高い順に並べ、同点は新しい順                                                                                                                    |

- **1文字の語**は2文字の組が作れないので、含まれるかどうかだけで見る
- **一覧に返すのは `id`・`title`・`gist` だけ**。`recallListBytes` に収まるところで止める
  （1件を単位にし、溢れる1件は載せない）
- **開いた1件の返す形は作業記憶と同じ**（話者の別・文面・その行の日付だけ）。逐語の並べ方も
  `systemPrompt` に載せるときと同じ1つ

**索引は `episode.jsonl`（1行1件の追記。書くのは tsukumo で、中身は定着の出力）**:

| 鍵            | 中身                                                                                              |
| ------------- | ------------------------------------------------------------------------------------------------- |
| `v`           | 行の形の版。**`2`**（アーカイブの行の `1` と見分ける。`index.jsonl` の `1` とも）                 |
| `id`          | `to` のローカル日付＋その日の通し番号（`-1` から）。tsukumo が振る                                |
| `from` / `to` | そのエピソードの最初と最後の**アーカイブの行の `at`**。**逐語はアーカイブにしか無く、索引は目次** |
| `title`       | 見出し（20 文字まで）                                                                             |
| `gist`        | 要旨（120 文字まで）                                                                              |
| `cues`        | 手がかり語（10 個まで）                                                                           |
| `weight`      | 大事さ 1〜3                                                                                       |

- **日ごとに割らない。** エピソードは定着1回に数件で、太り方は日数で読める
- **どこまで定着したかは、最後の行の `to` から分かる**（別の印を持たない）。未定着の行は
  「`to` より後の `at` を持ち、作業記憶の窓の外にある行」。**同じ秒に書かれた行は区別しない**
  （落ちるのは索引から引けないことだけで、会話はアーカイブに残る）
- **読めない行は飛ばす**（壊れた JSON・知らない版）。例外は投げない（索引が無い・壊れていても
  作業記憶の読み戻しはそのまま動き、次の定着がアーカイブの最初から畳む）
- **思い出した記録は `recalled.jsonl`**（`recall_episode` で1件開くたびに `id` と時刻を1行追記）。
  **索引の行を書き換えないために別に持つ**（追記だけなら途中で止まっても被害が1行）。文面を
  持たないので、会話の複製に数えない
- 索引の上限は**持たない**（読むのは採点のためだけで、返す量は `recallListBytes` と
  `recallEpisodeBytes` で頭打ち）

**引く契機を tsukumo は作らない。** **作法の条（`chat-manner.ts`）と
ツールの説明で足りる** — 引くかどうかはキャラクターが自分で決める。仕事では作法の条が載らないので、
ツールの説明と記憶の前置きの一言が受け持つ。tsukumo が隠しの依頼を
送ったり、利用者の依頼の文面で引いたりはしない（採らなかった案は `docs/history/decision.md`）。
**呼ばなければ古い話は出てこない**のは組み替える前と同じ弱さで、受け入れる。

**`recall` と `recall_episode` は、戻り値が `"ok"` だけではないツール**（4.2 の線をここで広げる。
2026-09-21 に `recall` 1つで広げ、2026-09-25 に2段階へ分けた。仕事の `report` が規約違反を返すのは
別の例外。`docs/architecture/display.md` 4.2）。広げてよいと判断した理由は
`docs/history/decision.md`「chat-mode.md 4.9 雑談モード（容量の比較・やめた keep の旗・recall の戻り値を広げた理由）」

**広げるのはこの2つだけ**（仕事でも同じ2つ）。 `speak` / `remember` / `forget` の戻り値は `"ok"` のままで、
**ほかに足すにはユーザーの決定が要る**。

- **当たらなかったときは正直に言う**（作り話で埋めない）。tsukumo が返すのは短い一言だけで、
  **会話の文面は1バイトも入らない**。知らない `id`・回数を超えた呼び出しも同じ短い一言
- **定着を入れる前の会話も、いずれ届く。** はじめの定着はアーカイブの最初の行から畳むので、
  溜まったぶんを畳み終えれば、アーカイブにある雑談はすべて索引から引ける（`index.jsonl` の
  見出しは読まなくなる）
- **引いた逐語を読み上げない・引用しない**（踏まえてよい、は作業記憶と同じ）
- **画面には出さない。** 引いた結果はモデルの文脈に入るだけで、雑談のログには並ばない
- **消す手はファイルを消すこと。** 忘れさせたい会話は**アーカイブの日のファイル**を消す。
  `episode.jsonl` だけを消すと、次の定着がアーカイブの最初から畳み直す（**会話が残っていれば
  索引も戻る**）。`recalled.jsonl` を消すと、思い出した回数だけが落ちる
- **規約の例外**は `docs/coding-standards.md`「会話内容の扱い」の表（書き出してよいものの
  エピソード索引の行と、読み戻して渡してよいものの `recall_episode` の行）

#### 雑談の会話のアーカイブ

**入れる**（2026-09-21 決定）。狙いは**あとで活用できること・設計変更に耐えること**。**tsukumo が
自分で、雑談の会話を受け取ったその場でディスクへ書く。**

**claude の transcript には任せない。** **鎖を無視して全部読む口が無い**うえ、保持期間も形式も
Claude Code の都合で古いものから消えていく（確かめた内容と採らなかった案は
`docs/history/decision.md`）。

**画面の上限とアーカイブは別物。** 混ぜない:

| 何               | 画面のログ                                   | アーカイブ                                                             |
| ---------------- | -------------------------------------------- | ---------------------------------------------------------------------- |
| 何のためにある   | **いま読むため**                             | **直近を逐語で読み戻すため・あとで活用するため・設計変更に耐えるため** |
| 持ち場           | 動いているプロセスのメモリ（`SessionState`） | `~/.tsukumo/` の下のファイル                                           |
| 上限             | 雑談 100 ターン（`trimToRecentTurns`）       | **持たない**                                                           |
| 圧縮・起こし直し | 圧縮点から先だけが復元される                 | **影響されない**（続きに書き足す）                                     |
| 消える契機       | プロセスが終わる・窓から溢れる               | **利用者がファイルを消したときだけ**                                   |

**雑談と仕事の両方を残す**（2026-09-26 決定。上の「記憶の圧縮と忘却」の「記憶は雑談と仕事で1つ」）。

| モード | 残すもの                                                                                                                                               |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 雑談   | 雑談のログに乗る2種類（利用者の依頼とキャラクターのセリフ）と、セリフの表情                                                                            |
| 仕事   | **依頼の冒頭**（`workExcerptChars`＝300 文字で切る）・**そのターンで最後に届いた `report` の `conclusion`**（同じく 300 文字）・**セリフ**（表情つき） |

- **本文（レポートの `sections`）・`checks`・`favor`・中間レポートの `conclusion`・ツールの入力と結果・
  許可プロンプト・質問は、どちらのモードでも書かない**（雑談では画面の雑談のログが拾っていないものは
  アーカイブにも入らない。`src/shared/chat/chat-log.ts`）。**添えた画像そのものも書かない** —
  残すのは枚数だけ（4.10）
- **仕事の「何をしたか」は `conclusion` で足りる。** ターンごとに要約の `query()` を足すことはしない
- **依頼は冒頭で切る**（貼り付けたログやコードで行が太り、16 KiB の窓が1〜2ターンで埋まるのを防ぐ）。
  切ったら末尾に `…` を付ける

**書くのは届いたその場で1件ずつ。** ターンの終わりにまとめない（溜めている間にプロセスが終わると
そのターンが丸ごと落ちる）。**例外は仕事の `conclusion` だけ**で、`turn-finished` が届いたときに
1行書く（`at` はターンの終わりで、並びではそのターンのセリフのあと）。`report` は1ターンに何度も届き、
最後のものが最終レポートなので、ターンが終わるまでどれを書くかが決まらない。途中の `report` は駆動の
代の勘定に預けて上書きするだけで、`report` 無しで終わったターンは何も足さない（預けたままプロセスが
終わればその1行が落ちる。受け入れる）。**`SessionState` の 100 ターンに影響されない経路で書き**（切り詰めた
あとの記録から拾うと、窓から溢れたターンが永久に落ちる。書く材料は届いたイベントそのもの）、
**復元で流し直されたぶんは、どちらのモードでも書かない**（書くと起こし直すたびに同じ会話がもう一度積まれる。
`conclusion` を預けるのも駆動から届いた `report` だけ）。
**書けなくても例外を投げない** — 落ちるのはその1行だけ。経路は `docs/architecture/character-pack.md`「雑談の記憶の
置き場」。

**ファイルはパックごと・日ごとに割る**（`<パック名>/<YYYY-MM-DD>.jsonl`）。日の境目は**その
マシンのローカル時刻**（利用者が「その日」と読む単位）。**形は JSONL（1行1件、追記）**:

```jsonl
{"v":2,"at":"2026-09-21T14:03:12+09:00","pack":"tsukumo","mode":"chat","kind":"request","speaker":"user","text":"ただいま"}
{"v":2,"at":"2026-09-21T14:03:20+09:00","pack":"tsukumo","mode":"chat","kind":"speech","speaker":"character","text":"おかえり","expression":"smile"}
```

| 鍵           | 中身                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------- |
| `v`          | 行の形の版（いまは `2`）。形を変えたら上げ、古い行と見分ける                                       |
| `at`         | ISO 8601（**オフセット付き**）。行だけで時刻が決まる                                               |
| `pack`       | キャラクターパックの名前                                                                           |
| `mode`       | `"chat"` か `"work"`（書いたときのモード）                                                         |
| `project`    | **`"work"` の行だけ**が持つ。リポジトリの名前だけ（下）                                            |
| `kind`       | `"request"`（依頼）・`"speech"`（セリフ）・`"conclusion"`（仕事のターンの最終レポートの結論）の3つ |
| `speaker`    | `"user"` か `"character"` の2つだけ（`request` は `user`、ほかは `character`）                     |
| `text`       | 文面（依頼・セリフ・`conclusion`。仕事の依頼と `conclusion` は 300 文字まで）                      |
| `expression` | 表情の名前。**`"speech"` の行だけ**が持つ                                                          |
| `images`     | 添えた画像の**枚数**。**`"request"` の行が、1枚以上あるときだけ**持つ                              |

- **`v:1` の行も読む。** `mode`・`kind`・`project` を持たない雑談の行として、`speaker` から依頼か
  セリフかを決める
- **`project` はリポジトリの名前だけで、パスは書かない**（ホームの名前と作業ツリーの置き場が入り、
  話の在りかには名前で足りる）。名前は共有の `.git` の親ディレクトリの名前（作業ツリーが違っても
  同じ名前になる。日記の `<リポジトリ>` と同じ取り方）で、`git` で取れなければ `cwd` の最後の名前
- **tsukumo の内部の型をそのまま書き出さない。** 上の鍵に決め打った形へ変換して書く。内部の
  型が変わってもファイルの形は変わらない — これが「設計変更に耐える」の中身で、**`v` はその形が
  変わった日のための逃げ道**
- **行だけで意味が決まるようにする。** 時刻もパックも各行が持つので、別の場所へ移しても、何本かを
  結合しても読める（パスとの重複は承知のうえ）
- **JSON の配列1つにしない**（追記で閉じ括弧を書き換えることになり、途中で止まるとファイル全体が
  読めなくなる。JSONL は壊れても被害が1行）。**Markdown にもしない**（機械で読むために置く）
- セッションIDは持たない（起こし直すたびに変わる。ターンの境目は時刻の並びで足りる）
- 1行の上限は別に足さない（雑談の依頼は zod の 20,000 文字が既に効き、仕事の依頼と `conclusion` は 300 文字で切る）

**書くプロセスは1つとは限らない**（仕事の tsukumo は作業ツリーごとに並行して動き、雑談も同じ
ファイルへ書く）。**追記に錠は置かない** — 1行を1回の追記（`O_APPEND`）で書き、混ざって壊れた行が
出ても読む側が1行ずつ飛ばす（落ちるのはその1行）。錠を置くのは定着だけ（上の「窓から溢れた会話は
定着で畳む」）。

**読み戻すときは新しい日のファイルから遡る。** 各ファイルは末尾の行から遡り、文面のバイト数の
合計が上限に届いたら止める（全部は読まないので、ファイルが何年ぶん増えても読む量は変わらない）。
返すのは**古い→新しいの順**で、**話者の別・文面・その行の日付だけ**（表情も画像の枚数も最初から
渡さない）。**読めない行は1行ずつ飛ばし**（壊れた JSON・知らない版・鍵が足りない行）、読めなければ
空を返してそのセッションは逐語なしで始まる。**文面を読んで載せる・載せないを決めない**。窓から
溢れた会話はこの読み戻しでは返さない（定着で畳まれ、索引から引く）。

**保持期間も総量の上限も持たない。** tsukumo は自分で消さない — 「あとで活用できる」が狙いなので、
勝手に消すとその狙いを外す。歯止めは**日ごとにファイルを割ること**で、見積もりは **1日20往復で
10 KiB 前後**。

**消す手はファイルを消すこと。** `~/.tsukumo/chat-archive/` を消せば全部、`<パック名>/` を消せば
そのキャラクターぶん、日付のファイルを消せばその日ぶんを忘れる。**画面から消す口は作らない**
（対象利用者は作者本人だけで、ファイルを直接開ける）。**ただし画面からキャラクターそのものを
消したときは、そのキャラクターぶん（`<パック名>/`。エピソード索引を含む）とあらすじも一緒に消える**（利用者が
id を打って確かめたうえでの操作で、勝手には消さない。残すと同じ id で作り直したキャラクターが
消したキャラクターとの会話を思い出してしまう。同梱のパックに戻すだけのときは残す。
`docs/requirements.md` 4.4 の「消す」）。

**既に claude の transcript にあるぶんを遡って取り込むことはしない**（**「すべて残す」には最初から
届かない**うえ、**いま広げた例外より広い口**を常駐プロセスに残す）。失われるのは**この機能が
動き出す前の会話**だけ。

**規約との関係**はあらすじと同じ（例外は「別の場所に複製しない」だけ。`docs/coding-standards.md`
「会話内容の扱い」）。**アーカイブは逐語を claude へ戻す唯一の出どころ**でもあり、**渡す先は3つ
だけ**: セッションの `systemPrompt`（新しいほうから雑談 64 KiB・仕事 16 KiB）、`recall_episode` の
戻り値（1件 8 KiB）、定着の使い捨て `query()`（1回に契機の2倍まで）。

#### プロフィールの書き戻し

**雑談でキャラクター自身の設定に関わることが決まったら、`persona.md` に1行だけ書き足す**
（2026-09-21 決定）。**書き換えは自動で、事前の承認も事後の通知もしない**（同日のユーザーの判断）。

**`docs/coding-standards.md`「会話内容の扱い」が最優先なので、書き戻してよい範囲を先に狭める。**
書いてよいのは、次の3つを**すべて**満たすものだけ:

1. **主語がキャラクター自身**（「ボクは〜」）。利用者・第三者・プロジェクト・コードの話ではない
2. **次のセッションでも同じく成り立つ属性**（好み・口調・呼び方・来歴）。その場の出来事・
   今日やったこと・進行中の作業ではない
3. **会話の文面を写していない。** キャラクターが自分の言葉で書き直した1行で、発言の引用でも
   その要約でもない

**書かないもの**（1つでも当たれば書かない）:

- **利用者について知ったこと**（名前・所属・家族・健康・予定・好み・感情・評価）。
  これは**会話から抜き出した内容をディスクに残す行為そのもの**で、規約と正面からぶつかる
- 会話の引用・要約・日時・出来事のログ
- ファイルのパス・コードの断片・プロジェクトの事情・認証情報

**この線引きなら規約と衝突しない**理由は2つ。(1) 書く先の `persona.md` は 2.2 が
**キャラクター素材**に数えた文書で、同梱パックにも「好きなもの」節が最初からある —
その欄に入る種類の情報は、もともと会話ではなく素材である。(2) 残るのは**キャラクターの属性
1行だけ**で、誰が何を言ったか・利用者が何を抱えているかは残らない。**会話そのものは複製されない**。

**裏返しとして、利用者のプロフィールは覚えない。**

**遅れて効くことは説明しない。** 書き足した内容が効くのは**次にセッションを起こしてから**
（`systemPrompt` の append のため）。通知しないと決めた以上、遅れて効くことも画面には出ない。

**覚えた1行は、キャラクター自身が1行だけ忘れられる**（2026-09-21 決定）。**消すのも自動で、事前の
承認も事後の通知もしない**。**消す手がファイルを開くことしか無い**と、取り違えて覚えた1行が
残り続ける。

**消せるのは「覚えたこと」の節に自分で書き足した行だけ。** もともと `persona.md` にあった文面
（見出し・地の文・表）は消せない。**節の境目がそのまま「自分で書いたもの」の線**になる。

**消してよいのは、次のどれかに当たるときだけ:**

1. **もう成り立たなくなった**（好みが変わった・呼び方を変えた）
2. **取り違えて覚えた**（そもそも自分の属性ではなかった。上の3条件のどれかを満たしていなかった）
3. **利用者から消すよう言われた**

**消す口ができても、触れる範囲は広がらない。** 触るのは「覚えたこと」の節だけで、**会話を
読み直して判定する経路はここにも作らない** — どれを消すかを決めるのはキャラクター（モデル）で、
tsukumo 側は受け取った1行と一致する行を落とすだけ。**消すために会話を保持することもしない**。

**画面からも1行ずつ消せる**（2026-09-23 決定。雑談中のサイドバー「覚えていること」の
「編集」。`docs/architecture/screen-design.md` 13.7）。消せる範囲はキャラクター自身の `forget` と同じで、
**触れる範囲は広がらない**（会話を読み直しはしない）。**画面から消すときだけ1ターン1行の上限は
掛からない**——その上限はモデルの暴走を防ぐためのもの。**消す前に確認を出す**（消した行は戻せない）。

**書く口も消す口もキャラクター自身が呼ぶツール**（`remember` / `forget`。`speak` と同じプロセス内の
MCP サーバに出す）。**雑談モードのときだけ載る**（仕事のときに出すと、作業の文脈が人格に入り込む
経路になる）。記憶を仕事と1つにしても変えない — 何を書いてよいかの条は雑談の作法にしか無く、
書く先の `persona.md` はパックの素材。引数は**1行の文字列1つ**だけ、戻り値は `"ok"` だけ（tsukumo からモデルへ情報が
戻る経路を作らない）。何を書き・何を消すかの判断は雑談の作法の条（`chat-manner.ts`）が上の線引きを
写して持ち、**tsukumo 側は受け取った1行をどこにどう書くかだけ**を持つ。

**書き方は末尾の追記専用の節。** `persona.md` の**いちばん最後**に `## 覚えたこと` を置き、`- ` の
箇条書きを1行ずつ足す。節が無ければ見出しごと作る。**節より前は1バイトも触らない**（人が書いた
文面と機械が書いた領域の境目が、ファイルの中で1本に決まる）。

**上限**（承認も通知も無いので、積み上がって人格が崩れる経路はここで塞ぐ）:

| 何                | 上限                                                               |
| ----------------- | ------------------------------------------------------------------ |
| 1ターンに書ける数 | 1行（2回目以降は書かずに `"ok"` を返す）                           |
| 1ターンに消せる数 | 1行（**`remember` とは別に数える**。画面から消すときは掛からない） |
| 1行の長さ         | 120 文字（超えたら書かない。改行を含む行も弾く）                   |
| 節が持てる行数    | 20 行（超えたら**いちばん古い行を落とす**）                        |
| 触るファイル      | そのパックの `persona.md` 1つだけ                                  |

**消し方**:

- **指し方は完全一致**（`- ` の印と前後の空白だけ吸収する）。**番号では指さない**（同じ
  セッションで `remember` が走ったり上限で古い行が落ちたりすると番号がズレ、ズレたまま別の行を
  消す）。前方一致も採らない（書き出しの似た行を巻き込む）
- **一致する行が無いときは何もしない。** 見つからなかったこともモデルへ戻さない（消えたかどうかは
  次に起こしたときの `systemPrompt` で分かる）
- **同じ文面の行が2つあるときは、いちばん古い1つだけを消す**（行数の上限で落ちるのと同じ向き）
- **`remember` と `forget` は同じターンに1回ずつ呼べる**（覚え違いをその場で言い直せる）
- **節が空になったら見出しごと消す**（全部忘れた状態は「書き足す前の人格」と同じであるべき）
- **画面から消すときも同じ突き合わせで消す**（冪等なので、同じ行をキャラクター自身が同時に
  消していても壊れない）。画面へは節の行を `SessionState.rememberedLines` で渡し、雑談で起こした
  とき・`remember` / `forget` で節が変わったとき・画面から消したときに流し直す。消す依頼は
  **雑談モードでなければサーバも断る**。チップ・「編集」・確認の形は `docs/architecture/screen-design.md` 13.7

**元に戻す手は3つ**: キャラクター自身に `forget` で1行ずつ消させる（ファイルを開かない唯一の
手）、`## 覚えたこと` の節を手で消す（節より前は写した時点の文面のまま）、ホームのパックを消す
（同梱を直したパックなら画面の「同梱に戻す」）。**世代バックアップは取らない**（会話をきっかけに
書いたものの残る場所を増やさない）。

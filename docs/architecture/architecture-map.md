# アーキテクチャの地図の契約

ステータス: **正典**。

責務: tsukumo が地図のファイル（`.architecture-map.json`）に対して定める契約 — 置き場・欄と必須か・箱の ID とパス・版・作り手の義務・読まないものと読めないとき・箱を指す語 — を1か所に持つ。
読む時: 地図の作り手を書く・直すとき、tsukumo で地図を読む・描く・指すコードを書くとき、利用者独自の作り手を tsukumo に当てるとき。
直す時: 地図のファイルの欄・版・箱の ID とパスの決まり・作り手の義務・読まないもの・箱を指す語を変えたとき。判断の経緯は `docs/architecture/adr/0082-architecture-map-contract.md`。

## 契約とは何か

**地図は、リポジトリを大・中・小の3段の箱の木と、箱どうしのエッジで表したもの。契約は、作り手が書いて tsukumo が読む地図のファイル1つの形。**
tsukumo が定めるのはこのファイルの形と、箱を指す語だけで、地図の作り方（抽出の道具・人が直す定義の書式・照合の手順）は定めない。

契約を満たす作り手は、`tsukumo-plugins` のもの（プラグイン `tsukumo-architecture-map`）も利用者独自のものも同じ立場で当てられる。
`tsukumo-plugins` のものは契約に型の合う1つの例で、tsukumo の一部ではない。tsukumo は作り手を起こさず、ファイルだけを読む。

## 置き場と書式

- 置き場は、tsukumo を起こした作業ディレクトリの根の `.architecture-map.json` の1か所だけ。tsukumo はほかの場所を探さない
- 書式は UTF-8 の JSON の値1つ（オブジェクト）。大きさの上限は 5 MiB で、超えたら壊れている扱い
- コミットするかはリポジトリが決める。tsukumo の開発では検証（`pnpm run check`）が毎回書き直すので、git の外に置く
- 作り手は一時ファイルに書いてから名前を替えて置く。tsukumo が書きかけを読まないため

## 欄

### 頭の欄

| 欄                | 必須             | 意味                                                                                                                                                                               |
| ----------------- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `version`         | 必須             | 契約の版。整数で、今は `1`（下の「版」）                                                                                                                                           |
| `source.producer` | 必須             | 作り手の名前と版の文字列（例 `tsukumo-architecture-map 0.1.0`）。表示にだけ使う                                                                                                    |
| `source.commit`   | 必須             | 抽出した時点の `HEAD` のコミットの SHA                                                                                                                                             |
| `source.tree`     | 任意             | 抽出した時点の作業ツリーの木の SHA（未コミットの変更を含む。検証の控えの `tree` と同じ求め方）。tsukumo は、これがレポートの時点の木と一致したときだけ `findings` をレポートに出す |
| `overview`        | 任意             | リポジトリの概要。3文までの地の文で、何のリポジトリで、どんな部分からできていて、外と何をやり取りするかを言う。全体の図で出す                                                      |
| `boxes`           | 必須             | 大の段の箱の配列（1件以上）。中の段は大の箱の `children`、小の段は中の箱の `children`                                                                                              |
| `edges.intended`  | 必須（空でよい） | 意図したエッジの配列                                                                                                                                                               |
| `edges.actual`    | 必須（空でよい） | 実際のエッジの配列                                                                                                                                                                 |
| `findings`        | 必須（空でよい） | ずれの配列                                                                                                                                                                         |

### 箱

| 欄            | 必須                                         | 意味                                                                                                                                                                                             |
| ------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `id`          | 必須                                         | 箱の ID（下の「箱の ID」）                                                                                                                                                                       |
| `title`       | 任意                                         | 表示名。無ければ `id` を出す                                                                                                                                                                     |
| `summary`     | 大・中は必須、小は任意                       | 役割の1行。ファイルの中身を写さず、決定の記録・要件・用語への導線にする                                                                                                                          |
| `purpose`     | 任意（大・中だけ）                           | 目的の1行。この箱がなぜほかと分かれているか（何を守る・何を外から隔てるか）                                                                                                                      |
| `overview`    | 任意（大・中だけ）                           | 概要。3文までの地の文で、箱の中の主な流れと子の箱の分け方を言う。ファイルの中身を写さない                                                                                                        |
| `paths`       | 必須（外の世界の箱は空の配列）               | 箱に属するファイルの glob の配列（下の「パスの書き方」）。大の箱は子の `paths` の和、小の箱は `<ディレクトリ>/*` と、直下に `.` で始まる名前のファイルを抽出したときだけ足す `<ディレクトリ>/.*` |
| `links.adr`   | 任意                                         | 決定の記録のファイルのパス（リポジトリの根からの相対）の配列                                                                                                                                     |
| `links.terms` | 任意                                         | 用語の配列。tsukumo は字のまま出す                                                                                                                                                               |
| `aliases`     | 任意（大・中だけ）                           | 改名する前の ID の配列                                                                                                                                                                           |
| `external`    | 任意（大だけ）                               | `true` なら外の世界の箱（リポジトリの外の相手）。`paths` を空にし、`children` を持たない                                                                                                         |
| `place`       | 任意（大・中だけ）                           | `{ "column": <整数>, "row": <整数> }`（0 始まり）。親の図（大の箱は全体の図）の中の格子の位置。描き方は下の「tsukumo が読む意味」                                                                |
| `children`    | 大・中は必須（外の世界の箱を除く）、小は無い | 1つ下の段の箱の配列（1件以上）                                                                                                                                                                   |

`summary`・`purpose`・`overview` は、読み手がアーキテクチャを理解する助けになるよう、段ごとに答える問いに合わせて書く（書き方は `docs/architecture/adr/0082-architecture-map-contract.md` の論点 10）。

木はちょうど3段で、外の世界の箱を除く大の箱はどれも中の箱を、中の箱はどれも小の箱を1つ以上持つ。

### エッジ

| 欄                    | 必須 | 意味                                                                                                           |
| --------------------- | ---- | -------------------------------------------------------------------------------------------------------------- |
| 意図した `from`・`to` | 必須 | どの段の箱の ID でもよい（段がそろわなくてよい）。`from` と `to` は違う箱                                      |
| 意図した `label`      | 任意 | エッジに添える短い語（`import`・`WebSocket` など）                                                             |
| 意図した `origin`     | 任意 | 作り手がこのエッジをどこから読んだか（定義か、依存の規則の名前か）。tsukumo は字のまま出すだけで意味を解かない |
| 実際の `from`・`to`   | 必須 | 小の箱の ID。`from` と `to` は違う箱                                                                           |
| 実際の `count`        | 必須 | 1以上の整数。`from` の箱のファイルから `to` の箱のファイルへの import の本数（ファイルの組ごとに1本）          |

- 実際のエッジは同じ `from`・`to` の組を1件にまとめる。同じ小の箱の中で閉じる import と、どの箱にも属さないファイルにつながる import は書かない
- エッジの端はどれも今の ID で書き、別名で書かない

### ずれ

どのずれも `kind`（種類）と `severity`（`error` か `warn`）を持ち、種類ごとに次の欄を足す。

| `kind`                 | 足す欄                                                                                 | 意味                                                                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `undeclared-edge`      | `from`・`to`（宣言が要る段の箱）・`count`・`sample`（`{ from, to }` のファイルのパス） | 実際の import のうち、どの意図したエッジにも覆われないもの（覆い方は下の「tsukumo が読む意味」）。`count` はその組の本数 |
| `unmapped-file`        | `path`                                                                                 | 作り手が抽出したファイルのうち、どの箱にも属さないもの                                                                   |
| `overlapping-file`     | `path`・`boxes`                                                                        | 同じ段の2つ以上の箱に属するファイル                                                                                      |
| `split-directory`      | `path`（ディレクトリ）・`boxes`                                                        | 直下のファイルが2つ以上の中の箱に分かれたディレクトリ（小の箱をディレクトリ1つに決められない）                           |
| `empty-box`            | `box`                                                                                  | `paths` がどのファイルにも当たらない箱（外の世界の箱を除く）                                                             |
| `missing-link`         | `box`・`path`                                                                          | `links.adr` に書いたパスのファイルが無い                                                                                 |
| `unused-intended-edge` | `from`・`to`                                                                           | 覆う実際の import が1本も無い意図したエッジ                                                                              |

`severity` は `unused-intended-edge` だけ `warn`、ほかは `error`。作り手は、上の種類のほかを足してもよい（版は上げない）。

## 箱の ID

- `/` でつないだ区切りの並びで、区切りは `\.?[A-Za-z0-9_][A-Za-z0-9._-]*`（頭の `.` は1つまで。`.`・`..` だけの区切りは書けない）、全体で100字以内。空白・`{`・`}` を含まない
- ファイルの中の ID と別名の全部で重ならない
- 大・中の箱の ID は人が付ける名前（`server`・`server/report` など）。親の ID を頭に付ける決まりは無い
- 小の箱の ID は、そのディレクトリのリポジトリの根からのパス（`src/server/report/core` など）
- 大・中の箱を改名したら、古い ID を新しい箱の `aliases` に残す。小の箱は別名を持たない（ディレクトリを移すと古い ID は知らない ID になる）

## パスの書き方

- リポジトリの根からの相対で `/` で区切る。頭に `./`・`/` を付けない
- 区切り1つは、`**`（0個以上の区切り）か、字と `*`（`/` を除く0字以上）の並び。`?`・`[...]`・`{a,b}`・`!` は使わない
- **ワイルドカード（`*`・`**`）は `.` で始まる区切りに当たらない。** `src/x/*` は `src/x/.eslintrc.cjs` に、`plugin/**` は `plugin/.claude-plugin/plugin.json` に当たらない
- `.` で始まるファイルやディレクトリを箱に入れるときは、その区切りを `.` から字のまま書く（`src/x/.*`・`src/x/.eslintrc.cjs`・`plugin/.claude-plugin/*`）
- 箱に属するかは、作り手も tsukumo もこの決まりで照らす。Node の `path.matchesGlob` と、Python 3.13 以降の `re.fullmatch(glob.translate(<glob>, recursive=True, include_hidden=False, seps="/"), <パス>)` はこの決まりどおりに当たる
- Python の `PurePosixPath.full_match` と git の pathspec `:(glob)` は、ワイルドカードが `.` で始まる区切りにも当たるので、箱に属するかの判定に使わない。git に渡すときは、git の当たり（契約の当たりをいつも含む）を候補の絞り込みにだけ使い、出たファイルをこの決まりで照らし直す

## 版

- tsukumo は知っている版（今は `1`）だけを読む。それより大きい版は「知らない版」として読まない
- 版を上げないもの: 任意の欄を足す、ずれの種類を足す。tsukumo は知らない欄を読み捨て、知らない種類のずれを種類の名前だけ一覧に出して描かない
- 版を上げるもの: 欄を消す・名前を替える・意味を変える、任意の欄を必須にする、箱の ID やパスの決まりを変える、木の段の数を変える
- 作り手は、書く中身を表せるいちばん小さい版を書く

## 作り手の義務

1. 地図のファイル（と自分の入力・一時ファイル）だけを書く。tsukumo の口（`mcp__tsukumo__*`）を呼ばない
2. 一時ファイルに書いてから名前を替えて置く
3. 上の欄・箱の ID・パスの書き方の決まりを全部満たす。とくに、ID と別名が重ならない、エッジの端が今の ID の箱にある、実際のエッジは小の箱どうしで組ごとに1件、大の箱の `paths` は子の和、小の箱の `paths` は `<ディレクトリ>/*` で（直下に `.` で始まる名前のファイルを抽出したときは `<ディレクトリ>/.*` も足す）、そのディレクトリ直下の抽出したファイルは全部その中の箱に属する
4. `findings` は、同じファイルのほかの欄と同じ抽出から作る。`source.commit` を書き、求められるなら `source.tree` も書く
5. 同じ入力からは同じバイト列を書く（箱は定義の順、エッジと `findings` は欄の値の順に並べる）。コミットするリポジトリの差分を小さく保つため
6. ファイルの中身・差分・会話の中身を書かない。書くのはパス・ID・表示名・役割の1行・用語・数だけ

## tsukumo が読まないもの・しないこと

- 作り手の入力（人が直す地図の定義、依存の抽出の出力と設定）、作り手のスクリプトとスキルを読まない
- 作り手も依存の抽出の道具も起こさない。地図のファイルを書かない
- `origin`・`source.producer` の中身を解かない（字のまま出すだけ）

## 読めないときの振る舞い

| 状態                                                      | tsukumo の振る舞い                                                                   |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 無い                                                      | 地図の入口を出さない。箱を指す語は字のまま残す                                       |
| 壊れている（JSON でない・欄が契約に沿わない・大きすぎる） | 入口は出し、開くと読めない理由の1行だけを出す。箱を指す語は字のまま残す              |
| 知らない版                                                | 壊れているときと同じで、理由は「tsukumo より新しい版」                               |
| 読める                                                    | 描く。開くたびに読み直す（ファイルの更新時刻が同じなら前に読んだ値を使い回してよい） |

## tsukumo が読む意味

- **束ね方**: 実際のエッジは小の段だけにある。粗い段で描くときは、両端をその段の祖先の箱に置き換えて `count` を足し合わせる。両端が同じ箱になった本数は、その箱の中で閉じた本数に数える（束ねた本数と閉じた本数の和は、いつも `edges.actual` の `count` の和に等しい）
- **覆い方**: 意図したエッジ `P → Q` は、ファイル `a → b` の import のうち、`a` が `P` か `P` の子孫の箱に属し、`b` が `Q` か `Q` の子孫の箱に属するものを覆う。両端が同じ中の箱に属する import は宣言を要らない。宣言が要る段は、両端の祖先が分かれるいちばん上の段（共通の祖先のすぐ下。共通の祖先が無ければ大の段）
- **描く範囲**: 全体の図は大の箱とそのあいだのエッジ。箱にフォーカスした図は、その箱の子と、子とエッジでつながる外の箱（フォーカスした箱と同じ段の祖先に置き換える）と、そのあいだのエッジ。外の箱どうしのエッジは描かない。意図したエッジも、両端を図の段の祖先に置き換えて描く
- **配置**: 図の中の箱が全部 `place` を持つときは、その格子に置く。1つでも欠けたら、tsukumo がエッジの向きで列を決め、定義の順で行を決める（毎回同じ結果になる配置）。フォーカスした図の外の箱は `place` を使わない
- **ずれの描き方**: `undeclared-edge` は、図の段に置き換えた両端の箱とエッジを赤で描く。`empty-box`・`missing-link` は箱を赤で描く。ほかの種類は一覧にだけ出す

## 箱を指す語

- 箱は `{{map: <ID>}}` で指す（ID は1つ）。レポートの本文の行内の印（`src/shared/report/inline-mark.ts` の `parseInlineMarks` が読む `{{…}}` の仲間）、`speak` のセリフ、入力欄で箱のバッジを付けて送った依頼の文で、同じ形を使う
- 入力欄の箱のバッジを付けて送った依頼は、文面の頭に1行 `{{map: <ID>}} <表示名>（<縮尺>の箱）: <役割>` を足す（役割が無い箱は `: …` を付けない。文面が slash コマンドで始まるときはコマンドの行の次の行に入れる）。表示名と縮尺を1行に入れるのは、吹き出しが地図を引かずにバッジを描くため
- tsukumo は ID か別名に当たる箱を探し、当たれば箱のバッジ（表示名と縮尺）で描く。当たらない・地図が読めないときは字のまま残す。インラインコードの中は読まない
- 字だけの場所（タブの題・要約など）では、箱の表示名に畳む
- エージェントは MCP の道具 `map_box` で箱の定義を引く。ID を渡すとその箱の欄とつながる箱を、渡さなければ大・中の箱の ID・表示名・役割の一覧を返す。道具が読むのも地図のファイルだけ

# アーキテクチャの地図の契約

ステータス: **正典**。

責務: tsukumo が地図のファイル（`.architecture-map.json`）に対して定める契約 — 置き場・欄と必須か・モジュールの ID とパス・版・作り手の義務・読まないものと読めないとき・モジュールを指す語 — を1か所に持つ。
読む時: 地図の作り手を書く・直すとき、tsukumo で地図を読む・描く・指すコードを書くとき、利用者独自の作り手を tsukumo に当てるとき。
直す時: 地図のファイルの欄・版・モジュールの ID とパスの決まり・作り手の義務・読まないもの・モジュールを指す語を変えたとき。判断の経緯は `docs/architecture/adr/0082-architecture-map-contract.md`（区画は `docs/architecture/adr/0085-architecture-map-lanes.md`）。

## 契約とは何か

**地図は、リポジトリを大・中・小の3段のモジュールの木と、モジュールどうしのエッジで表したもの。契約は、作り手が書いて tsukumo が読む地図のファイル1つの形。**
ここで言うモジュールはファイルの glob で束ねたディレクトリの束で、ES モジュール（1ファイル）ではない（`docs/glossary/architecture-map.md`「モジュール」）。
tsukumo が定めるのはこのファイルの形と、モジュールを指す語だけで、地図の作り方（抽出の道具・人が直す定義の書式・照合の手順）は定めない。

契約を満たす作り手は、`tsukumo-plugins` のもの（プラグイン `tsukumo-architecture-map`）も利用者独自のものも同じ立場で当てられる。
`tsukumo-plugins` のものは契約に型の合う1つの例で、tsukumo の一部ではない。tsukumo は作り手を起こさず、ファイルだけを読む。

## 置き場と書式

- 置き場は、tsukumo を起こした作業ディレクトリの根の `.architecture-map.json` の1か所だけ。tsukumo はほかの場所を探さない
- 書式は UTF-8 の JSON の値1つ（オブジェクト）。大きさの上限は 5 MiB で、超えたら壊れている扱い
- コミットするかはリポジトリが決める。tsukumo の開発では検証（`pnpm run check`）が毎回書き直すので、git の外に置く
- 作り手は一時ファイルに書いてから名前を替えて置く。tsukumo が書きかけを読まないため

## 欄

### 頭の欄

| 欄                | 必須             | 意味                                                                                                                                                                               |
| ----------------- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `version`         | 必須             | 契約の版。整数で、今は `1`（下の「版」）                                                                                                                                           |
| `source.producer` | 必須             | 作り手の名前と版の文字列（例 `tsukumo-architecture-map 0.1.0`）。表示にだけ使う                                                                                                    |
| `source.commit`   | 必須             | 抽出した時点の `HEAD` のコミットの SHA                                                                                                                                             |
| `source.tree`     | 任意             | 抽出した時点の作業ツリーの木の SHA（未コミットの変更を含む。検証の控えの `tree` と同じ求め方）。tsukumo は、これがレポートの時点の木と一致したときだけ `findings` をレポートに出す |
| `overview`        | 任意             | リポジトリの概要。3文までの地の文で、何のリポジトリで、どんな部分からできていて、外と何をやり取りするかを言う。全体の図で出す                                                      |
| `lanes`           | 任意             | 区画の配列（1件以上。下の「区画」）。全体の図を実行の境界の列と横断の帯で組むときに書く                                                                                            |
| `boxes`           | 必須             | 大の段のモジュールの配列（1件以上）。中の段は大のモジュールの `children`、小の段は中のモジュールの `children`                                                                      |
| `edges.intended`  | 必須（空でよい） | 意図したエッジの配列                                                                                                                                                               |
| `edges.actual`    | 必須（空でよい） | 実際のエッジの配列                                                                                                                                                                 |
| `findings`        | 必須（空でよい） | ずれの配列                                                                                                                                                                         |

### モジュール

| 欄            | 必須                                                 | 意味                                                                                                                                                                                                                     |
| ------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `id`          | 必須                                                 | モジュールの ID（下の「モジュールの ID」）                                                                                                                                                                               |
| `title`       | 任意                                                 | 表示名。無ければ `id` を出す                                                                                                                                                                                             |
| `summary`     | 大・中は必須、小は任意                               | 役割の1行。ファイルの中身を写さず、決定の記録・要件・用語への導線にする                                                                                                                                                  |
| `purpose`     | 任意（大・中だけ）                                   | 目的の1行。このモジュールがなぜほかと分かれているか（何を守る・何を外から隔てるか）                                                                                                                                      |
| `overview`    | 任意（大・中だけ）                                   | 概要。3文までの地の文で、モジュールの中の主な流れと子モジュールの分け方を言う。ファイルの中身を写さない                                                                                                                  |
| `paths`       | 必須（外の世界のモジュールは空の配列）               | モジュールに属するファイルの glob の配列（下の「パスの書き方」）。大のモジュールは子の `paths` の和、小のモジュールは `<ディレクトリ>/*` と、直下に `.` で始まる名前のファイルを抽出したときだけ足す `<ディレクトリ>/.*` |
| `links.adr`   | 任意                                                 | 決定の記録のファイルのパス（リポジトリの根からの相対）の配列                                                                                                                                                             |
| `links.terms` | 任意                                                 | 用語の配列。tsukumo は字のまま出す                                                                                                                                                                                       |
| `aliases`     | 任意（大・中だけ）                                   | 改名する前の ID の配列                                                                                                                                                                                                   |
| `external`    | 任意（大だけ）                                       | `true` なら外の世界のモジュール（リポジトリの外の相手）。`paths` を空にし、`children` を持たない                                                                                                                         |
| `lane`        | 任意（大だけ。`lanes` があれば大は全部必須）         | 属する区画の `id`。`lanes` が無い地図では書かない                                                                                                                                                                        |
| `place`       | 任意（大・中だけ）                                   | `{ "column": <整数>, "row": <整数> }`（0 始まり）。親の図（大のモジュールは全体の図）の中の格子の位置。描き方は下の「tsukumo が読む意味」                                                                                |
| `children`    | 大・中は必須（外の世界のモジュールを除く）、小は無い | 1つ下の段のモジュールの配列（1件以上）                                                                                                                                                                                   |

`summary`・`purpose`・`overview` は、読み手がアーキテクチャを理解する助けになるよう、段ごとに答える問いに合わせて書く（書き方は `docs/architecture/adr/0082-architecture-map-contract.md` の論点 10）。

木はちょうど3段で、外の世界のモジュールを除く大のモジュールはどれも中のモジュールを、中のモジュールはどれも小のモジュールを1つ以上持つ。

### 区画

区画は、全体の図で大のモジュールを実行の境界（ブラウザ・サーバなど）の列と、それらを横断する帯に組むための並び。モジュールではなく、`{{map: …}}` で指せない。

| 欄      | 必須 | 意味                                                                                                                         |
| ------- | ---- | ---------------------------------------------------------------------------------------------------------------------------- |
| `id`    | 必須 | 区画の ID。モジュールの ID の区切り1つの形で、区画どうしで重ならない。モジュールの ID とは別の名前の空間で、同じ字にしてよい |
| `title` | 任意 | 表示名。無ければ `id` を出す                                                                                                 |
| `kind`  | 必須 | `runtime`（実行の境界の列）・`crosscut`（実行の境界を横断する帯）・`external`（外の世界のモジュールを集める列）              |

- `lanes` を書く地図では、大のモジュールが全部 `lane` を持ち、`lane` はどれも `lanes` のどれかの `id` を指す。`lanes` を書かない地図では、どのモジュールも `lane` を持たない
- 外の世界のモジュール（`external: true`）は `kind` が `external` の区画にだけ属し、`kind` が `external` の区画には外の世界のモジュールだけが属する
- どの区画にも大のモジュールが1つ以上属する

### エッジ

| 欄                    | 必須 | 意味                                                                                                                  |
| --------------------- | ---- | --------------------------------------------------------------------------------------------------------------------- |
| 意図した `from`・`to` | 必須 | どの段のモジュールの ID でもよい（段がそろわなくてよい）。`from` と `to` は違うモジュール                             |
| 意図した `label`      | 任意 | エッジに添える短い語（`import`・`WebSocket` など）                                                                    |
| 意図した `origin`     | 任意 | 作り手がこのエッジをどこから読んだか（定義か、依存の規則の名前か）。tsukumo は字のまま出すだけで意味を解かない        |
| 実際の `from`・`to`   | 必須 | 小のモジュールの ID。`from` と `to` は違うモジュール                                                                  |
| 実際の `count`        | 必須 | 1以上の整数。`from` のモジュールのファイルから `to` のモジュールのファイルへの import の本数（ファイルの組ごとに1本） |

- 実際のエッジは同じ `from`・`to` の組を1件にまとめる。同じ小のモジュールの中で閉じる import と、どのモジュールにも属さないファイルにつながる import は書かない
- エッジの端はどれも今の ID で書き、別名で書かない

### ずれ

どのずれも `kind`（種類）と `severity`（`error` か `warn`）を持ち、種類ごとに次の欄を足す。

| `kind`                 | 足す欄                                                                                         | 意味                                                                                                                     |
| ---------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `undeclared-edge`      | `from`・`to`（宣言が要る段のモジュール）・`count`・`sample`（`{ from, to }` のファイルのパス） | 実際の import のうち、どの意図したエッジにも覆われないもの（覆い方は下の「tsukumo が読む意味」）。`count` はその組の本数 |
| `unmapped-file`        | `path`                                                                                         | 作り手が抽出したファイルのうち、どのモジュールにも属さないもの                                                           |
| `overlapping-file`     | `path`・`boxes`                                                                                | 同じ段の2つ以上のモジュールに属するファイル                                                                              |
| `split-directory`      | `path`（ディレクトリ）・`boxes`                                                                | 直下のファイルが2つ以上の中のモジュールに分かれたディレクトリ（小のモジュールをディレクトリ1つに決められない）           |
| `empty-box`            | `box`                                                                                          | `paths` がどのファイルにも当たらないモジュール（外の世界のモジュールを除く）                                             |
| `missing-link`         | `box`・`path`                                                                                  | `links.adr` に書いたパスのファイルが無い                                                                                 |
| `unused-intended-edge` | `from`・`to`                                                                                   | 覆う実際の import が1本も無い意図したエッジ                                                                              |

`severity` は `unused-intended-edge` だけ `warn`、ほかは `error`。作り手は、上の種類のほかを足してもよい（版は上げない）。

## モジュールの ID

- `/` でつないだ区切りの並びで、区切りは `\.?[A-Za-z0-9_][A-Za-z0-9._-]*`（頭の `.` は1つまで。`.`・`..` だけの区切りは書けない）、全体で100字以内。空白・`{`・`}` を含まない
- ファイルの中の ID と別名の全部で重ならない
- 大・中のモジュールの ID は人が付ける名前（`server`・`server/report` など）。親の ID を頭に付ける決まりは無い
- 小のモジュールの ID は、そのディレクトリのリポジトリの根からのパス（`src/server/report/core` など）
- 大・中のモジュールを改名したら、古い ID を新しいモジュールの `aliases` に残す。小のモジュールは別名を持たない（ディレクトリを移すと古い ID は知らない ID になる）

## パスの書き方

- リポジトリの根からの相対で `/` で区切る。頭に `./`・`/` を付けない
- 区切り1つは、`**`（0個以上の区切り）か、字と `*`（`/` を除く0字以上）の並び。`?`・`[...]`・`{a,b}`・`!` は使わない
- **ワイルドカード（`*`・`**`）は `.` で始まる区切りに当たらない。** `src/x/*` は `src/x/.eslintrc.cjs` に、`plugin/**` は `plugin/.claude-plugin/plugin.json` に当たらない
- `.` で始まるファイルやディレクトリをモジュールに入れるときは、その区切りを `.` から字のまま書く（`src/x/.*`・`src/x/.eslintrc.cjs`・`plugin/.claude-plugin/*`）
- モジュールに属するかは、作り手も tsukumo もこの決まりで照らす。Node の `path.matchesGlob` と、Python 3.13 以降の `re.fullmatch(glob.translate(<glob>, recursive=True, include_hidden=False, seps="/"), <パス>)` はこの決まりどおりに当たる
- Python の `PurePosixPath.full_match` と git の pathspec `:(glob)` は、ワイルドカードが `.` で始まる区切りにも当たるので、モジュールに属するかの判定に使わない。git に渡すときは、git の当たり（契約の当たりをいつも含む）を候補の絞り込みにだけ使い、出たファイルをこの決まりで照らし直す

## 版

- tsukumo は知っている版（今は `1`）だけを読む。それより大きい版は「知らない版」として読まない
- 版を上げないもの: 任意の欄を足す、ずれの種類を足す。区画の欄（`lanes`・`lane`）も任意の欄として版 `1` に足した。tsukumo は知らない欄を読み捨て、知らない種類のずれを種類の名前だけ一覧に出して描かない
- 版を上げるもの: 欄を消す・名前を替える・意味を変える、任意の欄を必須にする、モジュールの ID やパスの決まりを変える、木の段の数を変える
- 作り手は、書く中身を表せるいちばん小さい版を書く

## 作り手の義務

1. 地図のファイル（と自分の入力・一時ファイル）だけを書く。tsukumo の口（`mcp__tsukumo__*`）を呼ばない
2. 一時ファイルに書いてから名前を替えて置く
3. 上の欄・モジュールの ID・パスの書き方の決まりを全部満たす。とくに、ID と別名が重ならない、エッジの端が今の ID のモジュールにある、実際のエッジは小のモジュールどうしで組ごとに1件、大のモジュールの `paths` は子の和、小のモジュールの `paths` は `<ディレクトリ>/*` で（直下に `.` で始まる名前のファイルを抽出したときは `<ディレクトリ>/.*` も足す）、そのディレクトリ直下の抽出したファイルは全部その中のモジュールに属する
4. `findings` は、同じファイルのほかの欄と同じ抽出から作る。`source.commit` を書き、求められるなら `source.tree` も書く
5. 同じ入力からは同じバイト列を書く（モジュールは定義の順、エッジと `findings` は欄の値の順に並べる）。コミットするリポジトリの差分を小さく保つため
6. ファイルの中身・差分・会話の中身を書かない。書くのはパス・ID・表示名・役割の1行・用語・数だけ

## tsukumo が読まないもの・しないこと

- 作り手の入力（人が直す地図の定義、依存の抽出の出力と設定）、作り手のスクリプトとスキルを読まない
- 作り手も依存の抽出の道具も起こさない。地図のファイルを書かない
- `origin`・`source.producer` の中身を解かない（字のまま出すだけ）

## 読めないときの振る舞い

| 状態                                                      | tsukumo の振る舞い                                                                   |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 無い                                                      | 地図の入口を出さない。モジュールを指す語は字のまま残す                               |
| 壊れている（JSON でない・欄が契約に沿わない・大きすぎる） | 入口は出し、開くと読めない理由の1行だけを出す。モジュールを指す語は字のまま残す      |
| 知らない版                                                | 壊れているときと同じで、理由は「tsukumo より新しい版」                               |
| 読める                                                    | 描く。開くたびに読み直す（ファイルの更新時刻が同じなら前に読んだ値を使い回してよい） |

## tsukumo が読む意味

- **束ね方**: 実際のエッジは小の段だけにある。粗い段で描くときは、両端をその段の祖先のモジュールに置き換えて `count` を足し合わせる。両端が同じモジュールになった本数は、そのモジュールの中で閉じた本数に数える（束ねた本数と閉じた本数の和は、いつも `edges.actual` の `count` の和に等しい）
- **覆い方**: 意図したエッジ `P → Q` は、ファイル `a → b` の import のうち、`a` が `P` か `P` の子孫のモジュールに属し、`b` が `Q` か `Q` の子孫のモジュールに属するものを覆う。両端が同じ中のモジュールに属する import は宣言を要らない。宣言が要る段は、両端の祖先が分かれるいちばん上の段（共通の祖先のすぐ下。共通の祖先が無ければ大の段）
- **描く範囲**: 全体の図は大のモジュールとそのあいだのエッジ。モジュールにフォーカスした図は、そのモジュールの子と、子とエッジでつながる外のモジュール（フォーカスしたモジュールと同じ段の祖先に置き換える）と、そのあいだのエッジ。外のモジュールどうしのエッジは描かない。意図したエッジも、両端を図の段の祖先に置き換えて描く
- **配置**: 図の中のモジュールが全部 `place` を持つときは、その格子に置く。1つでも欠けたら、tsukumo がエッジの向きで列を決め、定義の順で行を決める（毎回同じ結果になる配置）。フォーカスした図の外のモジュールは `place` を使わない。`lanes` のある地図の全体の図は、下の「区画の組み方」で置き、大のモジュールの `place` を使わない
- **区画の組み方**: `lanes` のある地図の全体の図は、`kind` が `runtime`・`external` の区画を `lanes` の順に左から列に並べ、`crosscut` の区画を列の下に `lanes` の順に上から帯として重ねる。帯は、いちばん左の `runtime` の列からいちばん右の `runtime` の列までにまたがる（`runtime` の区画が無ければ全部の列）。`external` の列は、帯のまたがる範囲の外なら列の行と帯の行を縦に通して占め、範囲の内なら列の行だけを占める。大のモジュールがちょうど1つの `runtime`・`crosscut` の区画は区画そのものをそのモジュールとして描き、`external` の区画とモジュールが2つ以上の区画は、枠の中に大のモジュールを定義の順に上から並べる。サイドバー・広げた地図・レポートの「変えたファイル」のミニマップは、どれもこの組み方で描く
- **区画のある地図のフォーカスした図**: 区画を組まず、フォーカスしたモジュールの区画（中のモジュールなら親の大のモジュールの区画）の色の枠「〈フォーカスしたモジュールの表示名〉の中」で子を囲む。子とつながる外のモジュールは枠の外の右に1列で、属する区画の色で縁取って並べる（区画の順、同じ区画の中は定義の順）
- **区画の無い地図**: `lanes` の無い地図（区画を書かない作り手・古い作り手の地図）は、上の「配置」の格子で描く。tsukumo の古い版は `lanes`・`lane` を読み捨て、同じく格子で描く
- **ずれの描き方**: `undeclared-edge` は、図の段に置き換えた両端のモジュールとエッジを赤で描く。`empty-box`・`missing-link` はモジュールを赤で描く。ほかの種類は一覧にだけ出す

## モジュールを指す語

- モジュールは `{{map: <ID>}}` で指す（ID は1つ）。レポートの本文の行内の印（`src/shared/report/inline-mark.ts` の `parseInlineMarks` が読む `{{…}}` の仲間）、`speak` のセリフ、入力欄でモジュールのバッジを付けて送った依頼の文で、同じ形を使う
- 入力欄のモジュールのバッジを付けて送った依頼は、文面の頭に1行 `{{map: <ID>}} <表示名>（<縮尺>の箱）: <役割>` を足す（役割が無いモジュールは `: …` を付けない。1行の `の箱` は送る文と読み戻しが照らす字の並びで、語の改名と別に据え置く。文面が slash コマンドで始まるときはコマンドの行の次の行に入れる）。表示名と縮尺を1行に入れるのは、吹き出しが地図を引かずにバッジを描くため
- tsukumo は ID か別名に当たるモジュールを探し、当たればモジュールのバッジ（表示名と縮尺）で描く。当たらない・地図が読めないときは字のまま残す。インラインコードの中は読まない
- 字だけの場所（タブの題・要約など）では、モジュールの表示名に畳む
- エージェントは MCP の道具 `map_box` でモジュールの定義を引く。ID を渡すとそのモジュールの欄とつながるモジュールを、渡さなければ大・中のモジュールの ID・表示名・役割の一覧を返す。道具が読むのも地図のファイルだけ

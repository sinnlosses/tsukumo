# 雑談モード: 定着

戻り: `docs/architecture/chat-mode.md`

窓から溢れた会話を背景の使い捨て `query()` であらすじに畳む定着の、契機・排他・渡すもの・受け取る形。

責務: 定着がいつ走り、何を渡し、何を受け取り、どう排他するかを持つ。書けなかったあとの扱いは `docs/architecture/chat-mode/consolidation-failure.md`、写しの形は `docs/architecture/chat-mode/synopsis-file.md`。
読む時: 定着の契機・入出力・錠に触るとき。
直す時: 定着の走らせ方、渡すもの、受け取る形を変えたとき。

## 窓から溢れた会話は定着で畳む

**入れる**（決定）。作業記憶は**古い順に落ちるだけ**なので、溢れた会話を
背景の使い捨て `query()` にあらすじへ畳ませる。これを**定着**と呼ぶ。

**「残す」旗（`keep`）はやめる**（経緯は
`docs/history/decision.md`「chat-mode.md 4.9 雑談モード（容量の比較・やめた keep の旗・recall の戻り値を広げた理由）」）。
**`kept.jsonl` は読まない**（残ったファイルは移行スクリプトの `--prune` で消す）。

| 論点             | 決め                                                                                                                                                                                                                                                |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 何を畳むか       | **仕事の作業記憶の窓（16 KiB。小さいほう）から溢れていて**、**まだ畳んでいない行**（雑談と仕事を区別しない）                                                                                                                                        |
| いつ走るか       | **雑談・仕事のターンの終わり**に、畳む行が `consolidateEveryBytes` 以上あるとき。**`consolidateEveryBytes` の2倍（下の「1回に畳む量」の上限）で打ち切ったときは、届いていなくても走る**（決定。待つと、上限で弾かれ続けている行が永久に畳まれない） |
| 同時に走る数     | **プロセスをまたいで1本だけ**（下の錠）。走っているあいだの契機は捨てる（次のターンの終わりにまた数える）                                                                                                                                           |
| 1回に畳む量      | 畳む行の**古いほうから** `consolidateEveryBytes` の**2倍**まで（1件を単位にし、溢れる1件は次に回す）。**先頭の1件だけで2倍を超えるときは、切らずにその1件だけを単独で畳む**（決定。行の途中では切らない決めを保ったまま、その回で必ず前へ進める）   |
| 渡すもの         | 畳む行の文面と話者の別（日付が変わるところに見出しを1つ挟む）・前のあらすじ                                                                                                                                                                         |
| 返させるもの     | 書き直したあらすじ・最近の話題の見出し（形は下の「受け取る形」）                                                                                                                                                                                    |
| どこまで畳んだか | **あらすじの写しの `fold` が決める**（取り込んだ最後の行の時刻。`docs/architecture/chat-mode/synopsis-file.md`）                                                                                                                                    |
| 失敗したら       | **その回を諦める**（常駐プロセスは落ちない）。行は畳まれないまま残り、次の契機で拾い直す。続けて落ちたら契機を間引く（`docs/architecture/chat-mode/consolidation-failure.md`）                                                                      |
| 走らないとき     | 疑似セッション（`TSUKUMO_DRIVER=fake`。本物の claude を起こさない）                                                                                                                                                                                 |

**畳む境目は小さいほうの窓（16 KiB）の外**。64 KiB の外にすると、16〜64 KiB の行が仕事の
セッションからは `systemPrompt` に届かない。雑談の窓（64 KiB）の中の話があらすじにも
入る重なりは許す（倒れる方向を「忘れる」側にしない）。

**プロセスをまたいで1本にするのは錠のファイル**（`consolidation.lock`。パックのアーカイブの
ディレクトリに置く）。仕事の tsukumo は作業ツリーごとに並行して動き、2本が同じ未定着の行を読むと
あらすじが後勝ちで上書きされる。

- **排他で作れた（`wx`）プロセスだけが走らせ**、書き終えたか諦めたら消す。作れなければその契機を
  捨てる（走っているあいだの契機と同じ）
- **書いてから定着の時間切れ（120 秒）の2倍を過ぎた錠は、落ちたプロセスの残りとして消して取り直す**
- プロセスの中の1ビット（`session-manager`。起こし直しをまたいで同じ行を2本で畳まない）もそのまま持つ

**量は文面のバイト数で数え、件数では測らない**（作業記憶と同じ物差し）。**数え落としは許す** —
添えた画像は数えない（残るのは枚数だけで、文面ではない）。

**溜まったぶんは、1ターンに1回ずつ畳む。** 定着を入れた時点では、窓の外のアーカイブがまるごと
「まだ畳んでいない行」になる。**はじめの定着はアーカイブの最初の行から順に
畳む**（`index.jsonl` の見出しは種にしない。書かれ方がそろっていないため）が、1回に畳むのは契機の
2倍までで、次が走るのは**次のターンの終わり**なので、`query()` が続けて走ることはない
（1回に畳むのは 16 KiB までなので、溜まった 64 KiB なら畳み終えるのに4ターンほど）。

**定着に渡したものも受け取ったものも、ログ・stderr・手続きの応答・画面に出さない**（出して
よいのは件数・長さまで）。

**起こし方は使い捨ての `query()`**: 軽いモデル（`CHAT_CONSOLIDATION_MODEL`。
はじめは `haiku`）・ツールなし・MCP サーバなし・設定もフックも読まない（`settingSources: []`）・
1ターン・transcript を書かない（`persistSession: false`）・考える段なし・出力は JSON Schema の
構造化出力。指示文は `systemPrompt` をそのまま置き換える（Claude Code の既定の指示文も CLAUDE.md も
載らない）。**時間切れは 120 秒**（背景で走り、利用者を待たせない）。

**渡すもの**（依頼の文面は tsukumo が組む）:

- **畳む行**: 行番号（1始まり）・話者の別・文面の並び。仕事の行にはその印とプロジェクトの名前を
  添え、`conclusion` の行は「したこと」として分ける。日付が変わるところに見出しを1つ挟む。
  **表情・画像の枚数・時刻は渡さない**（作業記憶と同じ線）
- **前のあらすじ**（無ければ空）。本文だけで、印の行と話題の見出しは渡さない

**受け取る形**（構造化出力。`synopsis`・`topics` の2つ）:

| 鍵         | 決め                                                                                                                                                                                              |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `synopsis` | 空でない・`synopsisBytes` まで・予約タグ（注入の印の全件。下）を含まない・前のあらすじ（120 文字以上のとき）の半分未満に縮まない（縮みは書く口が見る）。話題の見出しは含めない（`topics` に書く） |
| `topics`   | 0〜3 個・各 40 文字まで                                                                                                                                                                           |

- **検査は丸ごと**。1か所でも崩れていたらその回は何も書かず、行は未定着のまま残る。長すぎる
  あらすじも検査で落とし（`failed`）、書くときの古い行の切り詰めは検査をすり抜けた分の最後の防波堤
- **予約タグは、tsukumo と Claude Code が依頼に差し込む印の全件**（`CHAT_SYNOPSIS_RESERVED_TAGS`）。
  tsukumo の脇の話の包み（`<tsukumo-aside>`）・委譲の引き継ぎの頭（`<agent-message`）・SDK が展開した
  スラッシュコマンドの3タグ（`<command-name>` など）・話題を本文に埋め込んでいた古い形（`<topics>`）に、
  Claude Code が差し込む `<system-reminder>`・`<task-notification>`・`<local-command-stdout>` を加える。
  印の形を正規表現で広く拒むことはしない — 地の文の `<` まで拒み、逃がし口の無い止まりを作る
- **縮みの検査の逃がし口・続けて落ちたときの間引き・落ちた理由の足跡**は
  `docs/architecture/chat-mode/consolidation-failure.md`

**走っているあいだの契機は捨て、待たない。** 数えるのは1ターンに1回（ターンの終わり）で、走り
終えても次のターンの終わりまで次を起こさない。**次のターン・パックの切り替え・プロセスの終わりと
重なっても待たない** — 書きかけで止まれば、その回は畳まれず、次の契機で拾い直す。起こし直しのあとで結果が届いても**書くのは起こした時点のパックのファイル**で、
話題の見出しを流すのは、そのときの状態が雑談で同じパックのときだけ。プロセスを終えるときは
走っている1本を中断し、中断のあとに届いた結果は書かない。

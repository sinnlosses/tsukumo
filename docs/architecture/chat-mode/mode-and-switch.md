# 雑談モード: モードと切り替え

戻り: `docs/architecture/chat-mode.md`

雑談モードを入れる理由、仕事のときとの違い、切り替え方、画面で遡れる幅。

責務: 雑談モードの入口の仕様（モードとして分けること、仕事のときから変わるもの、切り替えの道、遡れる幅）を持つ。記憶の層と忘却は `docs/architecture/chat-mode/memory-layers.md`。
読む時: 雑談モードの画面・切り替え・記録の上限に触るとき。
直す時: 雑談と仕事の違い、切り替え方、遡れる幅を変えたとき。

## 雑談モード

**入れる**（決定）。レポートを読むための画面とは別に、**キャラクターと短い往復を
するだけの場**を持つ。「1. 概要・目的」の2つの成分のうち **「キャラクターと一緒にいる感じが
すること」の側だけを取り出した場**で、仕事の側（レポート）は止める。

**モードとして分ける**（モードが無いと「今回は雑談かどうか」をモデルの推測に委ねることになり、
**雑談のつもりが技術文で返る揺れ**が残る）。

## 雑談モードで変わるもの

| 変わるもの                             | 仕事のとき                       | 雑談のとき                                                          |
| -------------------------------------- | -------------------------------- | ------------------------------------------------------------------- |
| レポートの記法（`report-notation.ts`） | `systemPrompt` に載る            | **載せない**                                                        |
| ターンの本文                           | メインビューにレポートとして出る | **出さない**（答えはすべてセリフ）                                  |
| メインビュー                           | レポートを縦に積む               | **立ち絵と会話のログ**（`docs/architecture/screen-design.md` 13.7） |
| キャラビュー                           | 立ち絵と吹き出し                 | **畳む**（立ち絵がメインへ移る）                                    |
| サイドバー                             | タスク一覧と下端の帯             | **4段に差し替わる**（`docs/architecture/screen-design.md` 13.7）    |
| セリフの間合い（`speech-cadence.ts`）  | ツールの前後に1回                | **往復そのもの**になるので別の文面が要る                            |

**「レポートは出さない」はユーザーの決定**。**雑談中に調べ物を頼んだときも本文は
出さず、セリフで返す**（本文が出たターンだけ画面を入れ替えると、モードに入っている意味が薄れる）。

**`speak` で終えたターンに Claude Code が差し込む催促は、仕組み（環境変数）で塞ぐ**（はじめ
「仕組みと条の両方」と決め、のちに条を外した。どちらもユーザーの決定）。雑談のターンは
`speak` のツール呼び出しで終わるので、Claude Code が `[Your previous response had no visible output. ...]`
を利用者の発言として差し込み、1往復増える。

- **仕組み**: 子プロセスに `CLAUDE_CODE_TERMINAL_MCP_TOOLS=mcp__tsukumo__speak` を渡す
  （`src/server/session-driver/core/visible-output-nudge.ts`。仕事・雑談の両方で渡す）。直前の
  ツールの往復にこの変数に載ったツールの成功した呼び出しがあれば、Claude Code は催促を出さない
  （同梱の `claude` 2.1.280 と 2.1.281 のバイナリで確かめた判定。判定は `Stop` フックより前に
  走るので、フックからは止められない）。**公式の文書には載っていない**
  （`env-vars.md`・`settings.md`・`llms-full.txt` の全文を当たった。催促そのものは
  2.1.183 の変更履歴にだけある）ので、Claude Code の更新で黙って効かなくなりうる。**催促が届いたら
  気づける見張りを一緒に置く**（`src/server/session-driver/adapter/sdk-driver.ts`。催促の固定文で始まる
  利用者側のメッセージを見たら、届いた事実だけを stderr に1行出す。中身は写さない）
- **条は置かない**: 最後の `speak` のあとに「完了」の1行を書かせる条を保険として重ねていたが、
  `report` を呼ばないターン（仕事のセッションで一言だけ返すとき）ではその1行が最終レポートとして
  画面に出た（`docs/architecture/display.md` 4.2 の、`report` が呼ばれなかったターンの扱い）。環境変数が
  効くことを実機で確かめたうえで外した。
  変数が効かなくなったら見張りの1行で気づき、そのとき改めて手を考える

**雑談のときだけ、キャラクターから話しかけてもらえる**（決定）。利用者がボタンを
押すと tsukumo が合図を1つ送り、キャラクターが**自分で選んだ話題**で話し始める。

- **送った合図は画面のログにも記録にも、下の「会話のアーカイブ」にも残さない**
  （ユーザーの選択）。利用者が打っていない一言をログに並べない、という点で下の
  「依頼として流す案は採らない」（直近の逐語の読み戻し）と同じ立場
- **話題そのものを tsukumo は持たない**（原則4「キャラクターの中身をコードに書かない」）。
  渡すのは「話題はあなたが選ぶ」という合図だけ
- **時間では起こさない**（利用者決定。黙って立つだけの場面を埋める見直しで、誰もつつかない
  間が一定時間続いたら合図を送る案と比べ、この決定を保った。見直しの結論は `docs/requirements/expression.md` 4.3
  「黙って立つだけの場面の埋め方」）
- **仕事のときは押す場所そのものが無い**（メインビューが雑談のログではないため）。
  ボタンの置き場所・見え方・ターン進行中の扱いは `docs/architecture/screen-design.md` 13.7

## 切り替え方

**セッションを起こし直す**（`session.switchCharacter` と同じ道）。`systemPrompt` はセッションを起こす
ときに固定されるので、載せる文面を変えるには起こし直すしかない。**切り替えるたびに画面が
初期化される**のはキャラクターの切り替えと同じ挙動で、そこは受け入れる。

**雑談と仕事は、画面だけでなく claude 側の文脈ごと分ける**（決定。分けないと仕事中の
依頼とセリフが雑談のログに並び、画面だけ仕切っても口調と話題が仕事へ引かれる）。**セッションの
印をモードごとに分け**（`tsukumo:<パック名>` と `tsukumo:<パック名>:chat`。4.8「鍵」）、
起こし直すときは**戻す先のモードの直前のセッション（このプロセスが覚えているもの）の続きから起こす**
（決定。覚えていない・他の窓が使用中なら新規。4.8「いつ復元するか」）。
**パックが変われば覚えを捨てる**（印がパックごとなので、別のパックの仕事を今のキャラクターで続けないため）。
それ以前のセッションへは切り替え画面で行を選んで戻る（切り替え先の一覧は印で絞るので、モードごとに別の一覧になる）。
**両側で分ける** — 仕事へ戻したメインビューにも雑談は出ない。
**仕事の側の印の文字列は変えない**（変えると、いま続いている仕事のセッションが切り替え先の一覧に
出なくなる）。

**直前の雑談が無い（覚えていない・使用中）ときは、雑談のログは空から始まる。** 前の雑談のやり取りは画面に出ないが、
あらすじと作業記憶は新規のセッションに載る（下の「載せる条件は2つあり、どちらかに当たれば載せる」）。

**行き来で仕事の側の迎えの挨拶と反応の行を書き直さない。** このプロセスで書けたものをセッションごとに覚えておき、
同じセッションへ戻る代では書かせずにそのまま出し直す（`src/server/welcome-greeting/core/kept-welcome.ts`）。
覚えるのはプロセスの中だけで、ディスクには書かない。`/clear`・新しく始める代・tsukumo を起こし直したあとの続きは今までどおり書く。

**切り替える口は画面の最上部の帯の「仕事」「雑談」の門**（決定。以前は「仕事｜雑談」のトグル）。どちらも会話の画面への門で、押すと会話の画面へ移り、
いまと違うモードの門ならモードも決まる。雑談モードが効くのは会話の画面だけで、入力欄も会話の画面
にしか無いので、会話以外の画面（キャラ・トークン・成果）はモードと無関係に保つ
（`docs/architecture/screen-design.md` 13.6 の表）。

- **違うモードの門を1回押すと起こし直す**（確かめの一言は挟まない）。失うのは画面の初期化だけで、
  それは上で受け入れてある。直前のセッションの続きに戻り、それ以前のものへは切り替え画面から戻る。同じモードの門は移動だけ
- **ターン進行中か、委譲先が動いている間は切り替えられない**（キャラクターの切り替えと同じ条件。画面は押せなくし、
  サーバも断る）。理由の文面はモードの語で言う（「ターン進行中か委譲中は仕事と雑談を切り替えられない
  （中断するか委譲を止めると切り替えられる）」）
- 形・押せないときの見せ方は `docs/architecture/screen-design.md` 13.9「動き方の操作子」、雑談中の帯は 13.7

## どこまで遡れるか

**雑談だけ記録の上限を上げる**（決定）。`src/shared/session/session-record.ts` の
`MAX_SESSION_STATE_TURNS = 20` は仕事のときの値として据え置き、**雑談のときは 100 ターン**を
持つ。雑談の1ターンはセリフ1〜2件で軽く、20往復は会話としては短いため。上限そのものは消さない
（**常駐プロセスが持つ記録を無限に増やさない**という `trimToRecentTurns` の前提）。

**仕事のメインビューとは揃えない。** 仕事は依頼ごとの札に区切って `‹` `›` で遡り
（`MAX_MAIN_VIEW_TURNS`）、雑談は素直な時系列をスクロールで遡る。並びの規則が違うので、遡り方も
別のままにする（`docs/architecture/screen-design.md` 13.7）。

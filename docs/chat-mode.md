### 4.9 雑談モード

**入れる**（2026-09-20 決定）。レポートを読むための画面とは別に、**キャラクターと短い往復を
するだけの場**を持つ。「1. 概要・目的」の2つの成分のうち**「キャラクターと一緒にいる感じが
すること」の側だけを取り出した場**で、仕事の側（レポート）は止める。

**モードとして分ける**（モードが無いと「今回は雑談かどうか」をモデルの推測に委ねることになり、
**雑談のつもりが技術文で返る揺れ**が残る）。

#### 雑談モードで変わるもの

| 変わるもの                             | 仕事のとき                       | 雑談のとき                                             |
| -------------------------------------- | -------------------------------- | ------------------------------------------------------ |
| レポートの記法（`report-notation.ts`） | `systemPrompt` に載る            | **載せない**                                           |
| ターンの本文                           | メインビューにレポートとして出る | **出さない**（答えはすべてセリフ）                     |
| メインビュー                           | レポートを縦に積む               | **立ち絵と会話のログ**（`docs/screen-design.md` 13.7） |
| キャラビュー                           | 立ち絵と吹き出し                 | **畳む**（立ち絵がメインへ移る）                       |
| サイドバー                             | タスク一覧と下端の帯             | **4段に差し替わる**（`docs/screen-design.md` 13.7）    |
| セリフの間合い（`speech-cadence.ts`）  | ツールの前後に1回                | **往復そのもの**になるので別の文面が要る               |

**「レポートは出さない」はユーザーの決定**（2026-09-20）。**雑談中に調べ物を頼んだときも本文は
出さず、セリフで返す**（本文が出たターンだけ画面を入れ替えると、モードに入っている意味が薄れる）。

**`speak` で終えたターンに本体が差し込む催促は、仕組みと条の両方で塞ぐ**（2026-09-24、ユーザーの
決定）。雑談のターンは `speak` のツール呼び出しで終わるので、本体が
`[Your previous response had no visible output. ...]` を利用者の発言として差し込み、1往復増える。

- **仕組み**: 子プロセスに `CLAUDE_CODE_TERMINAL_MCP_TOOLS=mcp__tsukumo__speak` を渡す。直前の
  ツールの往復にこの変数に載ったツールの成功した呼び出しがあれば、本体は催促を出さない
  （同梱の `claude` 2.1.280 のバイナリで確かめた判定）。**公式の文書には載っていない**
  （2026-09-24 に `env-vars.md`・`settings.md`・`llms-full.txt` の全文を当たった。催促そのものは
  2.1.183 の変更履歴にだけある）ので、本体の更新で黙って効かなくなりうる。**催促が届いたら
  気づける見張りを一緒に置く**
- **条**: 仕事の「完了」の1行（`report-notation.ts`）と同じく、雑談でも最後の `speak` のあとに
  「完了」の1行を書かせる。変数が効かなくなったときの保険で、本文は画面に出ないので
  「本文を書かない」の例外はこの1行だけ
- **両方にするのは、どちらも片方だけでは確かでないため**。条はモデルが書き忘れれば効かず、
  変数は文書にない内部の仕様に頼っている

**雑談のときだけ、キャラクターから話しかけてもらえる**（2026-09-21 決定）。利用者がボタンを
押すと tsukumo が合図を1つ送り、キャラクターが**自分で選んだ話題**で話し始める。

- **送った合図は画面のログにも記録にも、下の「雑談の会話のアーカイブ」にも残さない**
  （2026-09-21、ユーザーの選択）。利用者が打っていない一言をログに並べない、という点で下の
  「依頼として流す案は採らない」（直近の逐語の読み戻し）と同じ立場
- **話題そのものを tsukumo は持たない**（原則4「キャラクターの中身をコードに書かない」）。
  渡すのは「話題はあなたが選ぶ」という合図だけ
- **仕事のときは押す場所そのものが無い**（メインビューが雑談のログではないため）。
  ボタンの置き場所・見え方・ターン進行中の扱いは `docs/screen-design.md` 13.7

#### 切り替え方

**セッションを起こし直す**（`switch-character` と同じ道）。`systemPrompt` はセッションを起こす
ときに固定されるので、載せる文面を変えるには起こし直すしかない。**切り替えるたびに画面が
初期化される**のはキャラクターの切り替えと同じ挙動で、そこは受け入れる（2026-09-20）。

**雑談と仕事は、画面だけでなく claude 側の文脈ごと分ける**（2026-09-20 決定。分けないと仕事中の
依頼とセリフが雑談のログに並び、画面だけ仕切っても口調と話題が仕事へ引かれる）。**セッションの
印をモードごとに分け**（`tsukumo:<パック名>` と `tsukumo:<パック名>:chat`。4.8「鍵」）、
起こし直すときは**これから入る側の印を持つセッションを `resume` する**。雑談⇄仕事を往復しても、
それぞれが自分の側の続きに戻る。**両側で分ける** — 仕事へ戻したメインビューにも雑談は出ない。
**仕事の側の印の文字列は変えない**（変えると、いま続いている仕事のセッションが次の起動で
見つからなくなる）。

**代わりに、そのパックで一度も雑談のターンを終えていないうちは、雑談のログが空から始まる。**
印が付くのはターンが終わって数秒あとなので（4.8「鍵」）、最初の雑談には続きにするものが無い。
**これは受け入れる**（4.8「復元できなかったときどうするか」の範囲）。

**切り替える口は画面の最上部の帯の「仕事｜雑談」のトグル**（2026-09-23 決定）。モードは
セッション限りの**動き方**で、どの画面からでも変えられる帯に置く（`docs/screen-design.md` 13.6 の表）。

- **トグルを1回押すと起こし直す**（確かめの一言は挟まない）。失うのは画面の初期化だけで、それは
  上で受け入れてある。戻せばそれぞれの続きから始まる
- **ターン進行中は切り替えられない**（キャラクターの切り替えと同じ条件。画面は押せなくし、
  サーバも断る）。理由の文面はモードの語で言う（「ターン進行中は仕事と雑談を切り替えられない
  （中断すると切り替えられる）」）
- 形・押せないときの見せ方は `docs/screen-design.md` 13.9「動き方の操作子」、雑談中の帯は 13.7

#### どこまで遡れるか

**雑談だけ記録の上限を上げる**（2026-09-20 決定）。`src/shared/session-state.ts` の
`MAX_SESSION_STATE_TURNS = 20` は仕事のときの値として据え置き、**雑談のときは 100 ターン**を
持つ。雑談の1ターンはセリフ1〜2件で軽く、20往復は会話としては短いため。上限そのものは消さない
（**常駐プロセスが持つ記録を無限に増やさない**という `trimToRecentTurns` の前提）。

**仕事のメインビューとは揃えない。** 仕事は依頼ごとの札に区切って `‹` `›` で遡り
（`MAX_MAIN_VIEW_TURNS`）、雑談は素直な時系列をスクロールで遡る。並びの規則が違うので、遡り方も
別のままにする（`docs/screen-design.md` 13.7）。

#### 記憶の圧縮と忘却

**入れる**（2026-09-21 決定）。狙いは**記憶を引き継ぎつつ忘却を再現する**こと。雑談は起こし直す
たびに前の雑談セッションへ戻るので（上の「切り替え方」）、**放っておくと claude 側の文脈だけが
際限なく伸びる**。

**記憶は2層で持つ**（2026-09-21 決定）。**直近は要約せず逐語のまま読み戻し、それより前だけを
要約が受け持つ。**

| 層         | 何が渡るか                             | どこから来るか                               | 量を決めるのは |
| ---------- | -------------------------------------- | -------------------------------------------- | -------------- |
| 直近       | **会話の文面そのもの**（逐語）         | `~/.tsukumo/chat-archive/`（下のアーカイブ） | **tsukumo**    |
| それより前 | claude が自分の言葉で書き直した要約1つ | `~/.tsukumo/chat-summary/`（下の要約の写し） | claude         |

**2つは別の口で、渡す先だけが同じ**（雑談のセッションの `systemPrompt`）。直近の側の正典は下の
「直近の会話は逐語のまま読み戻す」。

**要約を作るのは claude 自身で、口は Claude Code 組み込みの `/compact`。** tsukumo がするのは
容量を数えて、閾値を超えたターンの終わりに `/compact` を依頼として1回投げることだけ。

- **これは 2.2 の「会話を外部のモデルへ送る」に当たらない。** 会話はもともとその claude の
  文脈にあり、要約も同じプロセスの中で作られる。**tsukumo が自前で API を叩いて要約する案は
  2.2 のまま対象外**
- `/compact` は組み込みのスラッシュコマンドで、**引数に要約の指示を添えられる**ので、雑談では
  「覚えておくことだけを短く」に当たる一文を添える。入力欄の `/` 補完にも出るので、**利用者が
  手で叩く道も最初からある**
- **送る文面は画面のログにも記録にも、下の「雑談の会話のアーカイブ」にも残さない**（2026-09-21
  決定。上の「話しかけてもらう」の合図を残さないのと同じ立場）。流れるのは `request` ではなく
  `turn-started` なので、圧縮が起きたこと自体は下の「忘却は画面に1本の区切りとして出す」が伝える

**閾値は容量（バイト）で持ち、件数では測らない。**

| 何         | 値                                                                      |
| ---------- | ----------------------------------------------------------------------- |
| 規定の容量 | **128 KiB**（131,072 バイト）                                           |
| 数えるもの | 雑談のログの文面（利用者の依頼とキャラクターのセリフ）の UTF-8 バイト数 |
| 数える範囲 | **前の圧縮点から先だけ**（それより前は claude 側にもう無い）            |
| 数える契機 | ターンの終わりに1回。**1ターンで2度は投げない**                         |

**128 KiB の根拠**: 雑談の1ターンは 130〜195 バイトなので、128 KiB は **672〜1,008 ターン**に
当たり、**「画面からは消えたけれど、まだ覚えている」が普通の状態**になる（測り方は
`docs/history/decision.md`「chat-mode.md 4.9 記憶の圧縮と忘却（実測）」）。

**この値を決めているのは逐語の窓（下の 64 KiB）で、閾値はその2倍**（2026-09-21 にユーザーが
選んだ）:

- **1倍（＝逐語の窓と同じ）では忘却が起きない。** **畳むそばから同じ量を戻す**。**2倍なら、畳んだ
  128 KiB のうち逐語で戻るのは新しい半分（64 KiB）だけ**で、古い半分は要約しか持たない
- **3倍・4倍にはしない。** 新しいセッションへ渡るのは「要約（前の圧縮点まで）＋新しいほうから
  64 KiB」なので、**その間に挟まってどちらにも入らない範囲**が最大で「閾値 − 64 KiB」できる。
  2倍なら1窓ぶんで収まるが、4倍では3窓ぶんが**要約にも逐語にも無い**時間帯になる

**圧縮の間隔が延びることは受け入れる**（日に20往復なら 34〜50 日に1度）。**忘却が起きる縁は
2つあって、間隔が効くのは片方だけ**だから釣り合う: 続きから始めるとき（`resume`）は圧縮点より前が
要約だけになり、新規に起こすときは**逐語の窓より前**が要約だけになる（後者は圧縮を待たない）。
**閾値が受け持つのは「claude 側の文脈を際限なく伸ばさない」というこの節の最初の役**で、128 KiB は
claude の窓から見ればまだ十分に小さい。

**claude 自身の自動の圧縮には任せない**（自動の閾値には雑談では永久に届かず、窓を小さくする設定も
効かなかった。実測は `docs/history/decision.md`）。**忘却の距離は tsukumo が決め、claude 側の
自動の圧縮は最後の受け皿として残る。**

**数え落としは許す。** 添えた画像とツールの入出力は数えない（雑談では稀で、正しく数えるには
毎ターン claude へ問い合わせる必要がある）。数え落ちて起きるのは「圧縮が少し遅れる」ことだけで、
その先は claude 側の自動の圧縮が受ける。

**「その時点より過去の記録は読み込まない」に、tsukumo 側の実装は要らない。** 圧縮は transcript に
区切りを1つ書き、**そこで親子の鎖が切れる**ので、`resume` も `getSessionMessages` も**自動的に区切りから先だけを
見る**（範囲を指定する口はどれも**「指定した点より前を残す」**向きなので使わない）。

**1回でどれだけ空くかも tsukumo は決めない**（残す範囲を選ぶのは Claude Code 側で、**圧縮の直後に
また閾値を超える心配が無い**）。決めないのは**いま動いている claude の文脈に残る量**までで、
**新しいセッションへ渡す直近の量は tsukumo が決める**（下の「直近の会話は逐語のまま読み戻す」）。

**圧縮には時間がかかる**（数十秒）。だから**ターンが終わった直後に投げる** — 利用者が次の一言を
打つ前に済ませる。

**画面のログは圧縮では消えない。** 記録（`SessionState`）の上限（雑談 100 ターン）はそのまま効く。
**変わるのは起こし直したあと**で、復元されるログは圧縮点から始まる。それより前の会話は下の
「雑談の会話のアーカイブ」に残る。

**ただし「キャラクターが覚えている範囲」は画面とは別で、圧縮点より前にも届く。** 逐語の読み戻しは
アーカイブから読むので、**圧縮の区切りにも画面の上限にも縛られない**。画面は「いま読むため」、
記憶は claude の文脈、と持ち場が違う。

**100 ターンは画面の上限であって、残す量の上限ではない**（ユーザーが 2026-09-21 に
tsukumo 側のディスクへの複製を認めた。覆った記録は `docs/history/decision.md`）。
要約の写し（下の表）は記憶を渡すためのもので、会話そのものを残す役は持たない。

**忘却は画面に1本の区切りとして出す。** 雑談のログの圧縮点に当たる位置へ、**文言を添えない
細い線を1本だけ**入れる（2026-09-21 決定。忘却は頭の中で起きるもの、という想定）。**セリフでも
知らせない** — セリフの文面を決めるのは claude だけで、tsukumo がキャラクターの言葉を作らない。
起こし直したあとはこの区切りがログのいちばん上に来る。

**要約の写しを1つだけディスクに持つ**（2026-09-21 決定）。狙いは**「セッションをリセットしても
記憶を持つ」**こと——`/clear`・`TSUKUMO_NEW_SESSION=1`・印を見失ったとき・`cwd` が変わったときは
transcript が別になり、claude 側の要約ごと落ちるため。**ユーザーはそれを承知のうえで
「新しいセッションでも持つ」を選び、要約を `~/.tsukumo/` の下に置く例外を認めた**
（`docs/coding-standards.md`「会話内容の扱い」の「別の場所に複製しない」に対する、範囲を
限った例外）。

| セッションが別になる場面                                                    | claude 側の要約        | tsukumo の写しを載せるか                             |
| --------------------------------------------------------------------------- | ---------------------- | ---------------------------------------------------- |
| 起こし直し（モード切替・キャラ切替・上げ直し）                              | `resume` が読む        | **載せない**（載せると2度載る）                      |
| `/clear`                                                                    | 落ちる見込み（未実測） | その場では載せない。**次に起こしたときに必ず載せる** |
| 新しいセッション（`TSUKUMO_NEW_SESSION=1`・印を見失った・`cwd` が変わった） | 落ちる                 | **載せる**                                           |

**載せる条件は2つあり、どちらかに当たれば載せる**（どちらでもなければ載せない）:
(1) **続きから始めない**（新規に起こす） (2) **続きから始めるが、前に `/clear` を見ている**。

- **「続きから始めたか」だけでは足りない。** 印はターンが終わるたびに**そのときのセッションID**へ
  付け直されるので、**`/clear` のあと1ターンでも回すと、空になったほうのセッションが印を持つ**。
  条件が1つだけだと**そのパックの記憶が二度と戻らない**
- **印が無い・読めないときは未渡し扱い** — **黙って記憶が消えるほうへ倒さない**。載せたら
  「渡し済み」に戻す（`resume` した文脈に要約が既にあるときに重ねない）
- **雑談のときだけ**。仕事の側の文脈に写しを載せることはしない
- 印の置き場と形・捕まえ方・渡し方・上限は `docs/design.md` 7章「雑談の記憶の要約はどこに置くか」

**写しに会話の文面がそのまま入らないよう、`/compact` の引数に指示を添える。** 引く線は
「プロフィールの書き戻し」の3条件と「書かないもの」をそのまま使う（**自分の言葉で書き直す・
発言を引用しない・利用者について知ったことは書かない**）。

**同じ依頼で、要約のいちばん最後に最近の話題の見出しを書かせる**（2026-09-23 決定。ユーザーの
選択）。雑談中のサイドバーの「最近の話題」（`docs/screen-design.md` 13.7）に出すためで、**話題の
一覧という別のデータは持たない**。

- **形**: `<topics>` と `</topics>` の行の間に、新しい順で3件まで。見出しにも上の3条件が掛かる。
  **要約の最後に置かせる**のは、写しが上限を超えたときに先頭側から落ちるので、見出しの節が先に
  消えないようにするため。取り出し方は `docs/design.md` 7章（**推し量って出さない**）
- **更新されるのは圧縮のときだけ**（それまでは前回の話題のまま）
- **一度も圧縮していないパックは空**で、サイドバーは「まだ話題が無い（話が積もると、ここに
  並ぶ）」を出す。見出しの節が無い古い写しも同じ空になり、次の圧縮で埋まる
- **画面へ運ぶのは見出しだけ**で、要約の本文は運ばない（`SessionState` に載るのは `chatTopics` だけ）

**ただし、それだけでは守らせきれない。** 要約を書くのはモデルで、**tsukumo は写す中身を読んで
判定しない**（読んで判定する経路を作るほうが規約とぶつかる）。だから**中身に立ち入らない縛り**を
重ねて、写しが会話のログに育つ経路のほうを塞ぐ:

| 縛り                                                                                      | 何を塞ぐか                                                         |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 写すのは claude が作った要約1つだけ                                                       | 生のログ・transcript・ツールの入出力は今までどおり書かない         |
| 1パック1ファイルを上書きする                                                              | 履歴が積み上がらない（前の要約は残らない）                         |
| 8 KiB を上限にし、溢れたら古いほうの行を落とす                                            | 要約の形をした会話の写しが際限なく太らない                         |
| 本文を画面にも `error` フレームにも stderr にも出さない（画面に出すのは話題の見出しだけ） | 写しが別の経路から外へ出ない                                       |
| 雑談のときだけ書き、仕事のときは触らない                                                  | 作業の文脈（プロジェクトの事情・利用者の都合）が入る経路を作らない |

**「会話内容の扱い」の4つの条のうち、例外を使うのは「別の場所に複製しない」の1つだけ**（残る
3条の満たし方は `docs/coding-standards.md`「会話内容の扱い」の「広げていないこと」）。

**元に戻す手はファイルを消すこと。** `~/.tsukumo/chat-summary/` を消せば、そのぶんを忘れる。

**写しは世代を重ねるほど薄くなる。** 写しを渡す `systemPrompt` は会話ではないので、**次の圧縮が
作る要約に写しの中身が全部は残らないことがある**。**これは受け入れる** — 倒れる方向が忘却の側で、
この機能が再現したいものと同じ向きだから。**薄くなるのは古い側だけ**（直近は逐語のまま別の口で渡る）。

**`/clear` の直後の文脈には記憶が無く、戻るのは次にセッションを起こしたとき**（`persona.md` への
書き戻しと同じ粒度）。**その場で起こし直さない** — 画面の初期化とセッションの起こし直しという
大きな動きを、利用者が打った組み込みコマンド1つの副作用にしないため。**その代わり、「次に
起こしたとき」では確実に戻す**（上の条件2）。`/clear` は利用者がいちばん素直に「セッションを
リセット」と呼ぶ操作なので、ここが抜けるとこの機能の狙いそのものを外す。

**`/clear` で要約が落ちるかは実測していない。** 落ちる前提で組んでいるが、もし残っていたとしても
起きるのは**同じ要約が2度載ること**だけで、記憶が消えることはない。**実測を決定の前提にしない。**

**直近の会話は逐語のまま読み戻す**（2026-09-21 決定。上の「記憶は2層で持つ」の直近の側）。

**出どころは下の「雑談の会話のアーカイブ」だけ**（`~/.tsukumo/chat-archive/<パック名>/`）。
transcript は読まない（`docs/coding-standards.md`「会話内容の扱い」の「広げていないこと」）。

**量は容量（バイト）で決め、件数では測らない**（上の閾値と同じ物差しを引き継ぐ）。

| 何         | 値                                                                            |
| ---------- | ----------------------------------------------------------------------------- |
| 規定の容量 | **64 KiB**（65,536 バイト）                                                   |
| 数えるもの | アーカイブの各行の**文面だけ**の UTF-8 バイト数（時刻・話者・表情は数えない） |
| 数える向き | **新しいほうから遡る**（新しい日のファイルから順に、届いたところで止める）    |
| 切り方     | **1件（1行）を単位にし、途中では切らない**。溢れる1件は載せない               |

**64 KiB はユーザーの指示**（2026-09-21）。**336〜504 ターン**に当たり、画面の上限（100 ターン）の
3.4〜5倍あるので、**3つが入れ子**になる:

| 範囲             | どこまで                  | 読み方                                       |
| ---------------- | ------------------------- | -------------------------------------------- |
| 画面のログ       | 100 ターン                | **いま読める**                               |
| 逐語で覚えている | 336〜504 ターン（64 KiB） | **画面から消えても、言葉のまま覚えている**   |
| 要約だけが持つ   | それより前                | **話の筋は残っているが、言葉は残っていない** |

**物差しは日数。** 日に20往復なら 64 KiB は **17〜25 日**ぶんで、**「ここ3週間ほどの雑談は
そのまま覚えていて、それより前は要約になっている」**と読める。画面は窓の 1/3 にも満たないので
**必ず内側に収まり**、「さっき画面で見た話を忘れている」は起きない。

- **圧縮の閾値（128 KiB）と読み戻す量（64 KiB）は別の値で、閾値のほうが大きい。** 前者は
  「いつ畳むか」、後者は「新しいセッションへ逐語で何を渡すか」（揃えないわけは上の「128 KiB の
  根拠」の下）。**表が2つに割れているのはそのため**

**`systemPrompt` が毎ターン抱える量が増えることは受け入れる。** 64 KiB は日本語で約 22,000 文字で、
**1文字＝1トークンと最も悪く見積もっても** claude の窓の 2.2% 程度、自動の圧縮の閾値には桁が
2つ足りない。加えて:

- **前置きは伸びない。** `systemPrompt` は起こすときに固定され、**上限が決まっている側**に入る
- **載る機会が限られる。** 載せるのは「新規に起こしたとき」と「`/clear` のあと」だけ
- **払っているものが、そのまま「覚えている距離」。** この機能が決めるのは忘却の距離なので、
  対価が文脈の数%なら目的と釣り合う

**要約の写しの上限（8 KiB）は動かさない。** あちらは「要約が会話の写しに育つ経路を塞ぐ」ための
上限で、**逐語でどれだけ戻すか**とは目的が違う（上の「中身に立ち入らない縛り」の表）。

**載せる口は `systemPrompt` の append で、載せる条件は要約の写しと同じ**（上の「載せる条件は2つ
あり、どちらかに当たれば載せる」）。どちらでもなければ載せない——**`resume` した文脈には同じ
会話が既にある**。

- **写しがまだ無いときも逐語は載せる**（条件を決めるのは「続きから始めたか」と印だけ）
- **依頼として流す案は採らない**（雑談のログに利用者が打っていない一言が並び、次の transcript にも
  依頼として残る）
- **画面には出さない。** 画面のログは今までどおり transcript からの復元で作る（4.8）。**新しい
  セッションでは画面が空でもキャラクターは直近を覚えている**
- **要約と範囲が重なるのは許す**（窓が最後の圧縮点より前まで届くことがある）。**倒れる方向を
  「忘れる」側にしない**
- **載せるのは文面と話者の別だけ。** 表情も画像の枚数も載せない（表情はそのときのセリフに付いて
  いた印で、次のセリフを縛る材料にしない）。いつごろの話かは**日付が変わるところに見出しを
  1つ挟む**ことで足りる（並べ替えたり落としたりしない）

**窓から溢れた1往復でも、旗が立っていれば落ちない**（下の「残すと決めた1往復は窓から落とさない」）。
**この 64 KiB の外側に、別の 8 KiB として足す**ので、上の見積もりの前提（窓の大きさ）は動かない。

**`/compact` はやめない。** 直近を逐語で渡すようになっても、**古い側の要約を作る口**として残る。
外すと claude 側の文脈が際限なく伸び、受けるのは雑談では永久に届かない claude 自身の自動の圧縮
だけになる。

**逐語の読み戻しはユーザーが 2026-09-21 に認めた規約の例外**（`docs/coding-standards.md`
「会話内容の扱い」の「読み戻してよいもの」の表）。**逐語の会話が新しいセッションの transcript
（`~/.claude/projects/`）へ毎回書かれることも、その承認に含まれる。** 広げたのはここまでで、
**仕事の側の文脈には載せない**（雑談のときだけ）。

#### 残すと決めた1往復は窓から落とさない

**入れる**（2026-09-21 決定。ユーザー承認済みのドラフト）。上の窓（64 KiB）は**古い順に落ちる
だけ**で、大事な一言と相槌が同じ重さで落ちる。

**旗を立てるのはキャラクター自身**（2026-09-21、ユーザーの選択）。`remember` / `forget` と同じく
**プロセス内の MCP ツールを1つ足す**（`keep`）。**利用者が画面から指す UI は作らない。**

| 論点              | 決め                                                                          |
| ----------------- | ----------------------------------------------------------------------------- |
| どの1件に立てるか | **そのターンの1往復**（依頼とセリフをまとめて）。ツールは**引数を取らない**   |
| いつ書くか        | **ターンの終わり**（旗はターンの途中のどこで呼んでも、その1往復ぜんぶに付く） |
| どう残すか        | **アーカイブの行を指す印だけ**を別に積む（**文面は複製しない**）              |
| 読み戻しでの扱い  | **窓の外に足す**（窓の中で優先しない）。**上限は別に 8 KiB**                  |
| 旗が増え続けたら  | 8 KiB に収まらないぶんは**古い旗から落ちる**（窓と同じ向き）                  |
| 消す口            | **作らない**（`forget` に当たるものは置かない）                               |

**ツールに引数を持たせない。** 文面をモデルに渡させると、会話の文面がツールの引数を通って戻って
くる経路になり、**アーカイブの行と一致しない写し**が生まれる。指せるのがそのターンだけなら、
指し先は tsukumo 側で確定する。

**1件ではなく1往復に付ける。** 大事なのは「何を言われて、何と答えたか」なので、片側だけを残すと
読み戻したときに意味が立たない。

**窓の中で優先しない。** 64 KiB の中で先に詰めると、旗が増えるほど直近が押し出され、**「いまの話が
通じなくなる」**ほうへ倒れる。外に足せば、読み戻し全体の上限は **64 KiB + 8 KiB** で決まったまま。

**8 KiB は要約の写しと同じ大きさ**（約 21〜31 往復）。旗は「たまに立てるもの」で、これで足りなければ
立てすぎだと読む。

**窓に入っている件は旗のぶんに重ねない。** **同じ会話が2度載らない。**

**形は「印だけ」。** 積むのは行を指す時刻だけなので、旗そのものは `docs/coding-standards.md`
「会話内容の扱い」の**書き出してよいものの表に数えずに済む**。**版（`v`）も上げない**。置き場と形は
`docs/design.md` 7章「「残す」旗はどこに置くか」。

**時系列が飛ぶことは、節を分けて伝える。** 旗のぶんは直近より前で、間に残っていない会話がある。
`systemPrompt` には**別の見出しの節**として要約と直近の間に置き、**続きとして読まないこと**を
前置きで断る（混ぜて1つの並びにすると、その断絶が読む側に見えない）。

**消す口は作らない。** `forget` に当たるものを置くと、**消したい行の文面をツールの引数で指す**ことに
なり、上の「引数を持たせない」と逆を向く。**消す手はファイルを消すこと**（索引のファイルを消せば
旗が全部落ち、会話そのものは残る）。

#### 古い雑談は索引を引いて思い出す

**入れる**（2026-09-21 決定。ユーザー承認済みのドラフト）。上の窓（64 KiB）と旗（8 KiB）は
**起こすときに渡しきり**なので、そこから溢れた話は要約にしか残らない。足りないのは探す手段では
なく、**探しに行く契機と、言葉のずれを吸収する索引**のほう（全文検索の仕組みは要らない）。

| 論点                  | 決め                                                                                                                     |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 索引の1行を誰が書くか | **キャラクター自身**（`index` ツール。**文面の判断はモデル側**）                                                         |
| いつ書くか            | **その日のうち**（付くのは書いた日で、前の日には付け直せない）                                                           |
| 何を書くか            | **その日の見出し**（120文字まで・**1ターンに1行**。区切りがつくたびに書くので**1日に何行でもある**）。会話の写しではない |
| 探しに行く契機        | **キャラクター自身が引く**（`recall` ツール。引く言葉を渡す）                                                            |
| 読む量                | **1回 8 KiB**・**1ターンに1回**（窓とも旗とも別に数える）                                                                |

置き場（**パックごと**。またがない）・形・どう引くか（**`node:fs` で索引を読んで絞る**。`grep` などの
外部コマンドを起こさない）は `docs/design.md` 7章「日ごとの索引はどこに置くか」。

**書く契機も引く契機も tsukumo は作らない。** **作法の条（`docs/design.md` 5章の `chat-manner.ts`）と
ツールの説明で足りる** — 索引を書くのも引くのも、キャラクターが自分で決める。tsukumo が隠しの
依頼を送ったり、利用者の依頼の文面で引いたりはしない（採らなかった案は `docs/history/decision.md`）。

**`recall` は戻り値が `"ok"` だけではない最初のツールになる**（4.2 の線をここで1つだけ広げる。
2026-09-23 に仕事の `report` が規約違反を返す2つ目になった。`docs/display.md` 4.2）。
**広げてよいと判断した理由は3つ:**

1. **返すのは tsukumo の状態ではなく、その会話自身の過去。** 4.2 が塞いでいるのは
   「tsukumo からモデルへの逆流路」（画面の事情・セッションの状態が文脈へ戻ること）で、
   アーカイブの逐語はそこに当たらない
2. **逐語を claude へ戻すこと自体は 2026-09-21 に認められている**（上の「直近の会話は逐語のまま
   読み戻す」）。ここで増えるのは**渡す扉**であって、渡すものではない
3. **扉を増やさないと「当たった日だけ」が成り立たない**（引く言葉を受け取れるのはツールだけ）

**雑談で広げるのはこの1つだけ。** `speak` / `remember` / `forget` / `keep` の戻り値は `"ok"` のままで、
**ほかに足すにはユーザーの決定が要る**。

**見出しに書いてよいものの線は `remember` と同じ**（下の「プロフィールの書き戻し」の3条件のうち、
**自分の言葉で書く**・**会話の文面を写さない**・**利用者について知ったことは書かない**の3つ）。
**見出しは会話ではなく、その日の目次**で、当たったときに開く先がアーカイブの1つの行になる。

- **当たらなかったときは正直に言う**（作り話で埋めない）。tsukumo が返すのは短い一言だけで、
  **会話の文面は1バイトも入らない**
- **索引の無い日（索引を入れる前の日）は `recall` から届かない。** 見出しが無ければ引きようが
  無いので、既知の制約として受け入れる（本文そのものを照合する・日付を引数で渡す手段は
  用意しない。2026-09-23 決定）
- **引いた逐語を読み上げない・引用しない**（踏まえてよい、は窓と同じ）
- **画面には出さない。** 引いた結果はモデルの文脈に入るだけで、雑談のログには並ばない
- **消す手はファイルを消すこと**（`index.jsonl` を消せば索引が全部落ち、**会話そのものは残る**）
- **規約の例外を2つ広げた**（`docs/coding-standards.md`「会話内容の扱い」の表の、書き出してよい
  ものの3つ目と、読み戻して渡してよいものの2つ目）

#### 雑談の会話のアーカイブ

**入れる**（2026-09-21 決定）。狙いは**あとで活用できること・設計変更に耐えること**。**tsukumo が
自分で、雑談の会話を受け取ったその場でディスクへ書く。**

**claude の transcript には任せない。** **鎖を無視して全部読む口が無い**うえ、保持期間も形式も
Claude Code の都合で古いものから消えていく（確かめた内容と採らなかった案は
`docs/history/decision.md`）。

**画面の上限とアーカイブは別物。** 混ぜない:

| 何               | 画面のログ                                   | アーカイブ                                                             |
| ---------------- | -------------------------------------------- | ---------------------------------------------------------------------- |
| 何のためにある   | **いま読むため**                             | **直近を逐語で読み戻すため・あとで活用するため・設計変更に耐えるため** |
| 持ち場           | 動いているプロセスのメモリ（`SessionState`） | `~/.tsukumo/` の下のファイル                                           |
| 上限             | 雑談 100 ターン（`trimToRecentTurns`）       | **持たない**                                                           |
| 圧縮・起こし直し | 圧縮点から先だけが復元される                 | **影響されない**（続きに書き足す）                                     |
| 消える契機       | プロセスが終わる・窓から溢れる               | **利用者がファイルを消したときだけ**                                   |

**残すのは雑談だけ**（仕事の会話は残さない）。仕事の側は今までどおり**ディスクに書かない**。
広げたくなったら、まず `docs/coding-standards.md`「会話内容の扱い」の例外を1つ増やす判断からになる。

**残すのは雑談のログに乗る2種類（利用者の依頼とキャラクターのセリフ）と、セリフの表情だけ。**
**本文（レポート）・ツールの入力と結果・許可プロンプト・質問は書かない**（画面の雑談のログが
拾っていないものは、アーカイブにも入らない。`src/shared/chat-log.ts`）。**添えた画像そのものも
書かない** — 残すのは枚数だけ（4.10）。

**書くのは届いたその場で1件ずつ。** ターンの終わりにまとめない。**`SessionState` の 100 ターンに
影響されない経路で書き**、**復元で流し直されたぶんは書かない**（理由と経路は `docs/design.md` 7章
「雑談の会話のアーカイブはどこに置くか」の「誰がいつ書くか」）。

**保持期間も総量の上限も持たない。** tsukumo は自分で消さない — 「あとで活用できる」が狙いなので、
勝手に消すとその狙いを外す。歯止めは**日ごとにファイルを割ること**で、見積もりは **1日20往復で
10 KiB 前後**。

**消す手はファイルを消すこと。** `~/.tsukumo/chat-archive/` を消せば全部、`<パック名>/` を消せば
そのキャラクターぶん、日付のファイルを消せばその日ぶんを忘れる。**画面から消す口は作らない**
（対象利用者は作者本人だけで、ファイルを直接開ける）。**ただし画面からキャラクターそのものを
消したときは、そのキャラクターぶん（`<パック名>/`）と雑談の要約の写しも一緒に消える**（利用者が
id を打って確かめたうえでの操作で、勝手には消さない。残すと同じ id で作り直したキャラクターが
消したキャラクターとの会話を思い出してしまう。同梱のパックに戻すだけのときは残す。
`docs/design.md` 7.1「消すときの細部」）。

**既に claude の transcript にあるぶんを遡って取り込むことはしない**（**「すべて残す」には最初から
届かない**うえ、**いま広げた例外より広い口**を常駐プロセスに残す）。失われるのは**この機能が
動き出す前の会話**だけ。

**規約との関係**は要約の写しと同じ（例外は「別の場所に複製しない」だけ。`docs/coding-standards.md`
「会話内容の扱い」）。**アーカイブは直近を逐語で読み戻す唯一の出どころ**でもあり、**読み戻して
よいのは新しいほうから 64 KiB までで、渡す先は雑談のセッションの `systemPrompt` だけ。**

#### プロフィールの書き戻し

**雑談でキャラクター自身の設定に関わることが決まったら、`persona.md` に1行だけ書き足す**
（2026-09-21 決定）。**書き換えは自動で、事前の承認も事後の通知もしない**（同日のユーザーの判断）。

**`docs/coding-standards.md`「会話内容の扱い」が最優先なので、書き戻してよい範囲を先に狭める。**
書いてよいのは、次の3つを**すべて**満たすものだけ:

1. **主語がキャラクター自身**（「ボクは〜」）。利用者・第三者・プロジェクト・コードの話ではない
2. **次のセッションでも同じく成り立つ属性**（好み・口調・呼び方・来歴）。その場の出来事・
   今日やったこと・進行中の作業ではない
3. **会話の文面を写していない。** キャラクターが自分の言葉で書き直した1行で、発言の引用でも
   その要約でもない

**書かないもの**（1つでも当たれば書かない）:

- **利用者について知ったこと**（名前・所属・家族・健康・予定・好み・感情・評価）。
  これは**会話から抜き出した内容をディスクに残す行為そのもの**で、規約と正面からぶつかる
- 会話の引用・要約・日時・出来事のログ
- ファイルのパス・コードの断片・プロジェクトの事情・認証情報

**この線引きなら規約と衝突しない**理由は2つ。(1) 書く先の `persona.md` は 2.2 が
**キャラクター素材**に数えた文書で、同梱パックにも「好きなもの」節が最初からある —
その欄に入る種類の情報は、もともと会話ではなく素材である。(2) 残るのは**キャラクターの属性
1行だけ**で、誰が何を言ったか・利用者が何を抱えているかは残らない。**会話そのものは複製されない**。

**裏返しとして、利用者のプロフィールは覚えない。**

**遅れて効くことは説明しない。** 書き足した内容が効くのは**次にセッションを起こしてから**
（`systemPrompt` の append のため）。通知しないと決めた以上、遅れて効くことも画面には出ない。

**覚えた1行は、キャラクター自身が1行だけ忘れられる**（2026-09-21 決定）。**消すのも自動で、事前の
承認も事後の通知もしない**。**消す手がファイルを開くことしか無い**と、取り違えて覚えた1行が
残り続ける。

**消せるのは「覚えたこと」の節に自分で書き足した行だけ。** もともと `persona.md` にあった文面
（見出し・地の文・表）は消せない。**節の境目がそのまま「自分で書いたもの」の線**になる。

**消してよいのは、次のどれかに当たるときだけ:**

1. **もう成り立たなくなった**（好みが変わった・呼び方を変えた）
2. **取り違えて覚えた**（そもそも自分の属性ではなかった。上の3条件のどれかを満たしていなかった）
3. **利用者から消すよう言われた**

**消す口ができても、触れる範囲は広がらない。** 触るのは「覚えたこと」の節だけで、**会話を
読み直して判定する経路はここにも作らない** — どれを消すかを決めるのはキャラクター（モデル）で、
tsukumo 側は受け取った1行と一致する行を落とすだけ。**消すために会話を保持することもしない**。

**画面からも1行ずつ消せる**（2026-09-23 決定。雑談中のサイドバー「覚えていること」の
「編集」。`docs/screen-design.md` 13.7）。消せる範囲はキャラクター自身の `forget` と同じで、
**触れる範囲は広がらない**（会話を読み直しはしない）。**画面から消すときだけ1ターン1行の上限は
掛からない**——その上限はモデルの暴走を防ぐためのもの。**消す前に確認を出す**（消した行は戻せない）。

書き込み先・書き手・書き方・上限・消し方（指し方・一致しなかったとき・節が空になったとき）・
元に戻す手・画面から消すときの契約は `docs/design.md` 7.1。

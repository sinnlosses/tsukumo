## 13. 画面のデザイン

見た目の正典。**ここに書いてあるのは計画であって、CSS はこれを写したもの**（写す先は
各機能の `*.module.css`。トークンは `src/browser/styles/theme.css` に置く。6.6）。

### 13.1 Principles

**色はキャラクターの持ち物、静けさは画面の持ち物。** これが他の4つの根拠になる。

1. **読む面はキャラクターの色を受け取らない。** レポートの本文・サイドバーの文字・入力欄の
   文字は、誰が来ても同じ濃さで読める。色が現れるのは**キャラクターが居る場所**（立ち絵・
   吹き出し）と、**機械が指し示す場所**（フォーカスの輪・`:hover` の縁・選ばれたタブ・
   選んだ選択肢・送信・依頼の見出しの縦罫）と、**読む面を仕切る罫線**（レポートの見出しの
   罫線・表の見出し行の下罫。2026-09-21 に広げた。13.2「レポートの見出しと表に」）と、
   **チェックリストの済みの印**（枠・✓・地。2026-09-23 に利用者の注文で足した。✓ の文字が
   必ず添うので色だけで済みを伝えない。原則5）だけ。
   **見出しやツール名も「文字」の側**なので `ink` で、色を持つのは隣の縦罫・枠のほう
   （2026-09-13、当ててみたうえで確定）。**仕切る罫線に出すのは弱めた色**で、素の `accent` は
   キャラクターが居る場所と機械が指し示す場所に残す。
   **リンクだけは例外の扱いが要る**: 色を取り上げるかわりに**下線**で区別する。色だけに
   頼らないので、どのパックの `accent` が来てもリンクだと分かる
2. **枠を持たないのはキャラクターだけ。** 付喪神は器物に宿るのであって、ウィジェットの中に
   座っているのではない。**大胆さはこの1箇所に使い**、他の3領域は静かな枠のまま保つ
3. **機械が付けた名前は等幅、人が書いた言葉は本文書体。** タスクのID・ツール名・キー・モデル名・
   経過時間は等幅。レポートとセリフは本文書体。**装飾ではなく区別**で、等幅は「これは機械の側の
   名前だ」という情報を運ぶ
4. **読む面の幅は領域に任せる。** 本文の行長に上限は置かず、**1400px の窓で約 67 全角になる
   ことを承知のうえで選んでいる**（一度は上限 42 全角を置いていた。撤回の理由は
   `docs/history/decision.md`「design.md 13.1 Principles（原則4。行長の上限を撤回した経緯）」）
5. **意味を固定した色は誰が来ても変わらず、文字と対でだけ増やす。** ok / warn / ng / ask の
   意味がキャラクターごとに動くと、色が情報を運べなくなる。**色を1つ足してよいのは、その色が
   指すものに tsukumo が文字のラベルを必ず添えるときだけ** — モデルの書き忘れで消えない文字が
   付いていれば、色は読みやすさのための重ねがけになり、色だけで意味を伝えることにならない
   （2026-09-22 にレポートの `note` を6種に割り、6種すべてにラベルを出したうえで `state-ask` を
   足した）。ラベルを添えられないところでは色を足さず、**既にある色・地の段・枠・文字の印**で
   区別する

### 13.2 Color

**差せるつまみは4つだけ**にする。残りは導出するか固定する。つまみが少ないほど、
どのパック・どの設定でも壊れない。

| トークン     | 既定値（つくもの精霊） | 役割                 | 誰が差すか                     |
| ------------ | ---------------------- | -------------------- | ------------------------------ |
| `ground`     | `#191720`              | 画面の地             | **使う人**                     |
| `surface`    | `#221f2b`              | 領域の地             | **使う人**                     |
| `ink`        | `#e8e3ea`              | 本文の字             | **使う人**                     |
| `accent`     | `#f2b0a0`              | キャラクターの色     | **パック**（`character.json`） |
| `ink-quiet`  | —                      | 補助の字・弱い見出し | 固定（`ink` から導出）         |
| `rule`       | —                      | 罫線・領域の境目     | 固定（`surface` から導出）     |
| `rule-quiet` | —                      | 読む面の静かな罫線   | 固定（`surface` から導出）     |
| `state-ok`   | `#7ee081`              | 成功・完了           | **固定**                       |
| `state-warn` | `#e3c766`              | 注意・答え待ち       | **固定**                       |
| `state-ng`   | `#e88b8b`              | 失敗・エラー         | **固定**                       |
| `state-ask`  | `#8ab4e8`              | 疑問・未確認         | **固定**                       |

**罫線は2段ある。** `rule` は**線そのものが輪郭を担う**場所（押せる部品の縁・領域の境目）、
`rule-quiet` は**「ここで切れている」とだけ言えばよい**場所（カードの枠・表の行・凡例の行）。
どちらも `surface` に `ink` を混ぜた導出値で、混ぜる割合だけが違う（32% と 6%）。

**この表に無い固定の色**が3組ある。**コンテキストの内訳の分類**（`context-*`。分類ごとに違う色で、
凡例に分類名が必ず並ぶ）と、**量の棒**（`usage-bar*`。期間の札の縦棒とモデル別／ツール別の
横棒。分類の色ではなく「その列の最大に対する長さ」を言うだけ）と、**トークン消費の画面の中身の
地・罫・字**（`usage-*`。この画面の中でだけ使う）。どれも**誰が来ても変わらない**ので、
つまみにも導出にもしない（値は `src/browser/styles/theme.css`。この節の末尾に値の表がある）。

**既定値の選び方。** `accent` の `#f2b0a0` は**立ち絵の頬と耳から採った色**で、原則1を文字どおりに
した結果。地も中性の黒ではなく紫に寄せた暖色の黒で、淡いピンクの立ち絵と喧嘩しないように
してある。

**パックが差すのは `accent` 1つだけ**で、地と字は差さない。キャラクターごとに世界の色が変わる
案も検討したが、**読めるかどうかがパック次第になる**ので採らなかった（衣装ごとの差し色
`outfitAccents` は既にあり、そちらは立ち絵の中だけに効く）。

**雑談中は、パックが持てば `chatAccent` の値に差し替わる**（2026-09-23 決定。
`character.json` の任意の欄、検証は `src/shared/character-definition.ts`）。**新しいつまみを
足すのではなく、`accent` という1つの枠がモードに応じて別の値を取るだけ**（`--surface-accent` /
`--surface-raised` などの導出も、値の由来を意識せず `--accent` を読むだけなので自動で追随する）。
`chatAccent` を持たないパックは雑談中も `accent` のまま（仕事と同じ差し色）。仕事へ戻すと
`accent` に戻る（`src/shared/character.ts` の `effectiveAccent`。`docs/screen-design.md` 13.7）。

**コントラストの下限を守る。** `ground` と `ink` の組は、使う人が何を入れても本文が読める比を
下回らないところで止める。下回る値が来たら、受け取らずに既定へ落とす。

**この検算は画像には効かない。** キャラビューに敷く背景画像は、**覆い（`ground` 一色）の
不透明度の下限**で同じ保証を作る（13.8）。

**色付けが薄いのは色相ではなく地の段差。** 「機械の名前に地を敷いて区別する」仕組みは既にあり、
`ground` と `surface` の差が段差として見えていないだけだった。だから足すのは色相ではなく
**地の段**にする（測り方と数字は `docs/history/decision.md`「design.md 13.2 Color（色付けが
薄い原因の実測）」）。

**足すのは導出を1つだけ。差せるつまみは4つのまま。** 上の表に1行だけ加える:

| トークン         | 役割                                                   | 誰が差すか                                   |
| ---------------- | ------------------------------------------------------ | -------------------------------------------- |
| `surface-raised` | 本文の地の上に**浮く**小さな塊（機械の名前・結論の塊） | 固定（敷いた地に `ink` を1割**重ねて**導出） |

`surface-accent` と同じく**計算するだけの値**で、新しいつまみではない。割合は1割
（`surface` の上では比 1.31:1、その上の `ink` は 9.77:1）。

**混ぜるのではなく重ねる**（`color-mix(in srgb, var(--ink) 10%, transparent)`）。`surface` と
混ぜた不透明な色にすると、**浮く塊が浮く塊の中に入ったとき**に親と同じ色になって消える
（実測済み。やり取りの最後の本文は必ず最終レポートなので、その中のインラインコード・
表の見出し行・カードが全部沈む）。重ねる形なら `surface` の上での色は不透明に混ぜたときと
変わらず、どの段の上でも必ず1段上がる。

読む面の地はこれで3段になり、段がそのまま意味を持つ:

- **沈む（`ground`）** = 途中のもの・畳んだもの（中間レポート・`details`・コードブロック）
- **基準（`surface`）** = 本文
- **浮く（`surface-raised`）** = 機械の名前（インラインコード・`kbd` / `samp`）、表の見出し行、
  カード

**「Slack のような1行への色付け」に印は足さない。** **行を塗る記法は既に1つある**
（` ```diff ` の地を塗る色付け）。`report-notation.ts` に行を塗る印を足すと `badge` と意味が二重になり、色だけで意味を伝える入口に
なる（13.1 原則5）。代わりに、**意味を持つ塊の地を、既にある色で1割だけ染める**
（`color-mix(in srgb, var(--surface), var(--state-warn) 10%)` の形）。染めてよいのは
`state-*`（ok / warn / ng / ask）と `accent` だけで、**塊に文字のラベルが出ないなら色は足さない**
（13.1 原則5。1割の染めは地との比 1.19〜1.26:1、その上の `ink` は 10:1 以上を保つ）。

**`note` は6種（情報・注意・異常・疑問・メモ・お願い）に割り、種別のラベルを tsukumo が文字で
描く**（`markdown/notation.tsx`。2026-09-22）。色は 情報＝`ink` / 注意＝`state-warn` /
異常＝`state-ng` / 疑問＝`state-ask` / メモ＝`ink-quiet` / お願い＝`accent` で、**足したのは
`state-ask` の1つだけ**。情報とメモは同じ灰でも地の段で割れる（情報は浮く地、メモは地なし）。

**素の `note`（結論）は引用と見分けが付いていない。** どちらも灰色の 3px の縦罫で、地の差も無い
（`note` の縦罫は `ink-quiet`、引用の縦罫は `rule`）。**いちばん読ませたい印がいちばん弱い**
ので、`note` は縦罫を `ink` に上げ、地を `surface-raised` にする。引用は今のまま
（目立たせないための印）。

**コードの色付けは同梱のテーマのまま残す**（`highlight.js` の `github-dark`）。実測でページの中で
いちばん情報量が多く、読めている。ただし **Chart.js の軸と格子の色だけは16進が `theme.css` の外に
書かれている**（`markdown/chart-block.tsx`）ので、`--ink-quiet` / `--rule` の実効値を読んで渡す形に
直す。**色を足す話ではなく、外から来た色を減らす話**。mermaid は `theme: "dark"` のままにする。

**最終レポートに印を付ける。** 最終レポートの地は中間レポートと同じ `ground` にする
（ユーザー指摘 2026-09-21。地の段差では「途中 / 結論」を表さない）。中間レポートとの差は
枠（中間だけ破線）とラベルの2つで、**枠は既に他の情報（中間かどうか）を運んでいる**ので、
最終レポートだと分かるのは実質ラベル1つが支えている。最終レポートには次の1つを当てる:

- **ラベル「最終レポート」**。中間レポートのラベルと同じ段・同じ色（`--font-label`・`ink-quiet`）に
  置く。**同じやり取りに中間レポートが1つ以上あるときだけ出す** — 本文が1つしか無いやり取りでは
  「最終」が何も区別せず、内容を持たない行になる

**レポートの見出しと表に、キャラクターの色の線を1本ずつ通す。** 色が付くのは**罫線の側だけ**で、
文字は `ink`・地は `surface` / `surface-raised` のまま（13.1 原則1 は変えない）:

- `##`（`h4`）の**下の1本**（領域の幅いっぱい）
- `###`（`h5`）の**文字の幅だけの1本**（`width: fit-content`）。**段の深さを運ぶのは罫線の長さ**で、
  色は段の違いを運ばない（色だけに頼らない。13.1 原則5 と同じ構え）
- 表の**見出し行の下の1本**（2px。`border-collapse` で下の行の 1px に勝たせる太さ。同じ太さだと
  どちらの色が残るかが文書順まかせになる）

**素の `accent` ではなく `rule` に6割混ぜる**（`color-mix(in srgb, var(--rule), var(--accent) 60%)`。
`surface-accent` / `surface-raised` と同じく**計算するだけの値**で、新しいつまみでもトークンでも
ない）。レポートの中で何度も出る線なので、素のまま出すと**差し色が地の色になって何も指さなく
なる** — 素の `accent` は縦罫の2つ（依頼の見出し・お願い）に残し、仕切りの線はその一段下に置く。
**入れるのはこの3本だけ**で、`hr`・`details` の枠・カードの枠・引用の縦罫・`report-stat` の枠は
`rule` のまま（全部に入れると上と同じことが起きる）。

**使うのは `accent`（パックの色）で、`outfitAccents`（衣装ごとの差し色）ではない。**
衣装の差し色は `<Portrait>` が立ち絵の要素に置く CSS 変数（`--outfit-accent`）で、**レポートの
側には届かない**。届かせる配線を足しても、衣装を変えるたびにレポートの線の色が動く。
**パックが差すのは `accent` 1つ、`outfitAccents` は立ち絵の中だけ**というこの節の決定をそのまま
使う。

**採らなかった案**（つまみを足す・行を塗る印を記法に足す・`highlight.js` のテーマを作り直す・
見出しの文字に色を当てる・最終レポートの枠を `accent` の縦罫にする）の理由は
`docs/history/decision.md`「design.md 13.2 Color（採らなかった案）」。

**コンテキストの内訳の分類には、固定の色を7つ置く**（`context-system-prompt` /
`context-system-tools` / `context-mcp-tools` / `context-memory-files` / `context-skills` /
`context-messages` / `context-other`。トークン消費の画面の札で、横棒の区間と凡例の四角が同じ
1つを読む）。**差せるつまみは4つのまま**で、これも `state-*` と同じ「意味を固定した色」の側
（誰が来ても変わらない）。**増やしてよい根拠は 13.1 原則5** — 凡例に分類名が必ず並ぶので、色は
読みやすさの重ねがけになり、色だけで意味を伝えることにならない。**知らない分類は
`context-other` に落ちる**ので、SDK 側に分類が増えても色を足さずに出せる。**空きと自動圧縮
バッファには色を割り当てない**（無地と斜線で分ける。柄のほうが「中身ではない」ことを運ぶ）。

**トークン消費の画面の中身は、ユーザーの見本の色に寄せる**（2026-09-23、ユーザーの指示
「見本の色をできる限り再現してほしい」。範囲は画面の中身だけで、`ground` / `surface` / `ink` /
`accent` の既定値・帯・ほかの画面は変えない。書体と寸法も変えない）。見本の灰の段は
`surface-raised` / `rule` / `ink-quiet` の導出では作れない（字だけで6段ある）ので、見本の16進を
そのまま固定の値として置く。**足すのは固定の値で、つまみは4つのまま**（パックからは差せない）:

| 塗るもの                                            | トークン                                                                        | 値                                                                    |
| --------------------------------------------------- | ------------------------------------------------------------------------------- | --------------------------------------------------------------------- |

- **直近のセリフの出どころ**: 吹き出しと同じ `SessionState.speeches` の最後の1件
  （まだ無ければ何も出さない）
- **狭い幅での段の並び**: 760px 以下で2列→1列（他の区画と同じ境目。`token-usage.module.css`
  末尾の `@media`）

  から引く。**`usageReview.days` が選べる日数（1/7/30）でなければ数を出さない**——それ以外の
  値で引くと `readTokenUsageDays` が既定の7日に落ち、見た目の期間と違う数を出してしまうため
  （コンテキスト・見直し案の2段は数える元が無いので常に出さない）
- **終わりの知らせ（ヘッダーの「いまの作業」の札）**: 実機での確認は該当タスクの `evidence` を

  に戻るだけ
- **「前回の提案」リンク**: 押しても現時点では何も起きない（`use-usage-review.ts` の
  `previousReviewView` にその旨のコメントがある）。結果の札を描く後続タスクが、押すと同じ札の

（`{ url, alt }`）は帯（`screen-nav`）と同じ導き方なので、`browser/domain/character-face.ts`

**結果の場面**（`usage-review-card.tsx` の `ResultReviewCard`。見本

（`usageReview.kind === "result"`）と「前回の提案」を開いたとき（`previousUsageReview`）の
両方で同じ部品を使う**（`use-usage-review.ts` の `resultView`。「解くべき論点」への回答）。
「前回の提案」は画面を移さず、区画がその場で同じ札の形に差し替わり、右上に「閉じる」が出て
「ふだん」へ戻れる（今回の結果には「閉じる」を出さない——戻る先の「ふだん」が無いため）。

「解くべき論点」（もとのタスク本文）への回答:

- **依頼を送ったあと画面をどうするか**: **留まる**。「機能の側は `useScreen` を読まない」
  （13.9）のとおり、`navigateTo` は「作る画面」だけの例外で、この区画も「減らし方を見てもらう」
  （ふだん）の `onStart` と同じく送るだけに留める。会話へ移りたければ帯の「いまの作業」の札
  （13.9）が既にその役目を持つ
- **全部見送ったときの区画の一言**: 「いま出せる提案は無い。」（見送りきった・スキルがそもそも
  挙げなかったの両方に使う——`UsageReviewFindings.proposals` にはどちらだったかの区別が無い）
- **ターンが進んでいるあいだの主ボタン・「もう一度見てもらう」の扱い**: どちらも会話へ依頼を
  送る点は同じなので、ふだんの「減らし方を見てもらう」と同じ理由（`startAvailability`）を
  1つだけ出し、主ボタンの数だけ繰り返さない。**「見送る」はコマンドで会話へは送らないので、
  ターンが進行中でも押せる**

見た目の決定:

- **区画の地は「ふだん」と同じ染め**（`.usage-review-invite` と同じ `color-mix`）。「見直し中」の
  ような全力の `accent` 枠にはしない——結果は「押せて動いている」状態ではなく「見終わった」
  静かな状態なので、ふだんと同じ強さでよい
- **効きめの札（大/中/小）は新しい固定色を増やさない**（13.1 原則5）。大は `--accent`
  （キャラクターの色。押せる区画そのものの強調の色を再利用）、中は `--state-warn`
  （すでにある「意味を固定した色」——大小関係を運ぶのも状態の一種として相乗り）、小は色を
  足さず `--usage-rule` の無地にする。見本の3色（`#66d1be` / `#e3b95c` / `#3a3946`）を固定値と
  しては置かない——この区画は13.2「トークン消費の画面の中身は…見本の色に寄せる」が指す
  「読むだけの数字」の表ではなく、押せる・キャラクターが動いている区画の続きだから
- **主ボタンの文言は `delegate` → 「tsukumo に頼む」、`task` → 「タスクにする」の2つに固定**
  （`docs/design.md`「見直しのツールと状態」）。見本にある「設定を開く」は置かない
  （2026-09-23 ユーザー決定。行き先が無いため）
- **主ボタンの枠と字は `--usage-rule` / `--usage-ink` に `--accent` を `color-mix` で重ねる**
  だけ（見本の `#2c4744` / `#bfeee4` は固定値として置かない。13.2「染める」と同じ扱い）
- **「もう一度見てもらう」は中立の枠**（`.usage-review-stop` と同じ地味さ）。区画全体の染めが
  すでに「押せる区画」だと言っているので、ボタンにまで `accent` を足すと強すぎる
- **頭の吹き出しは三角を描かず、左上の角だけ立てる**（`border-radius: 0.25rem 0.875rem …`。
  見本と同じ手）。新しい部品（`<Balloon>`）は増やさない——`features/character-view/` に
  閉じた部品で、2機能目のこの区画から読むには `browser/domain/` へ上げる手間が要り、この
  区画だけの単純な吹き出しにその手間は見合わない
- **日時は見本の `[MM-DD HH:MM]` の角括弧を付けない**（他の画面に角括弧で時刻を囲む言い回しが
  無いため）。期間は「直近 N 日」（1日だけは「今日」——`presentational-token-usage-screen.tsx`
  の期間の切り替えと同じ言い換え）

### 13.3 Type

**書体は `system-ui` と等幅の2本のまま**にする。外部フォントは足さない。ネットワークへ出るのは
`127.0.0.1` に閉じる方針に触れるうえ、この画面が抱える問題は書体の選択ではなく**寸法と行長**の
ほうにあるため。仕事はそちらにさせる。

| 役割                                 | 寸法                                                      | 書体     |
| ------------------------------------ | --------------------------------------------------------- | -------- |
| 印・小さなラベル                     | 0.6875rem（11px）                                         | 本文書体 |
| 枠なしの入口（リンク風の操作）       | 0.75rem（12px）                                           | 本文書体 |
| 補助・サイドバーの本文               | 0.8125rem（13px）                                         | 本文書体 |
| 区画の見出し・強調した要約           | 0.875rem（14px）                                          | 本文書体 |
| 本文（レポート・セリフ）             | 0.9375rem（15px）                                         | 本文書体 |
| 大きな見出し（画面・ダイアログの題） | 1.125rem（18px）                                          | 本文書体 |
| ID・ツール名・キー                   | 0.8125rem（13px）。サイドバーのタスクのIDは印の段（11px） | 等幅     |

- 段は**この6つだけ**（2026-09-23 に2つ足した——サイドバーの
  区画の見出しと「一覧を見る」の入口が、既存の4段のどれにも収まらなかったため。見出しは
  13px だと「補助」に沈み、18px の「大きな見出し」ほど重くもしたくない。入口は 13px だと
  本文と同じ重さになって押せる字が埋もれ、11px だと小さすぎて読みにくい）。これ以外の寸法を
  足さない。**同じ mock で 14px が出ても、機械のラベルに近い字（`dispatch` の送信ボタン）は
  新しい段を使わず既存の 13px に寄せた**（採らなかった理由は
  `src/browser/features/dispatch/dispatch.module.css` の該当コメント）——段を増やすのは
  「差をはっきり見せたい」という要求があるときだけで、寄せられるところは寄せる
- **札の頭のタイトル（`turn-header.tsx` の `.turn-title-text`）は「区画の見出し・強調した要約」
  の段（14px）**（2026-09-23）。18px の段は札の頭を高くする主因だったので使わない——タイトルは
  窓の中の1件のやり取りの見出しで、意味のうえでもこの段に近い。18px の段は他の画面の見出し
  （雑談ログ・タスク一覧・確認ダイアログ・トークン消費・キャラクター画面のラベル）が使うので
  残し、行の名前を依頼に限らない「大きな見出し（画面・ダイアログの題）」にした。
  **タイトルの行の高さは本文の 1.75 を継がず、この1行だけ 1.3 に詰める**
  （`.detail-block .report-stat b` と同じ値。1.75 は長文を読むための余白で、1行の見出しには
  縦に余りすぎる）。前後の口（`.turn-nav-button`）は 13.9 の「帯の高さの床」と同じ 24px で、
  字はタイトルと同じ 14px
- **例外は日記の本文だけで、端末の明朝体に寄せる**（2026-09-25。成果の画面の吹き出しと見開きの
  右ページ。13.10）。書体の指定は `theme.css` の `--font-serif`（端末に入っている明朝体の名前を
  並べ、最後を `serif` にする）。**外から取らず、書体ファイルも同梱しない**（上の「外部フォントは
  足さない」と同じ理由）。明朝体の無い端末では `serif` に落ちるだけで、読めなくはならない。
  寸法は上の段のまま（本文の 15px）で、新しい段は足さない
- **本文の行間は 1.75**（日本語で長時間読むため、欧文の既定より広く取る）
- **本文の行長に上限は置かない**（13.1 原則4）。レポートは段落も表も `.main-step` の内幅を
  そのまま使い、
  1400px の窓では約 67 全角になる
- **領域の内幅に入りきらない表は、その表だけ横スクロールさせる**（`.table-scroll`。
  ページ全体は横スクロールさせない）。**表のセルは最低4全角を1行で出す**（`min-width: 4em`）。
  この下限が無いと `width: 100%` の表は列の数だけ詰まってセルが1〜2字ずつの折り返しになり、
  表が器に収まってしまうので横スクロールも働かない
- **フォーム部品（`button` / `input` / `select` / `textarea`）の書体は `theme.css` が継がせる。**
  ブラウザの既定では親の書体を継がないので、`theme.css` の `body` 直後の1か所だけが継がせる
  （大きさ・行の高さ・太さも一緒に継ぐ）。機能の CSS には書かない——書くのは大きさなど、既定から
  変える値だけ

### 13.4 Layout

構想を1文で。**上の2枠は読む場所、下は居る場所。キャラクターだけが枠を持たない。**

```
┌─────────────────────────────────┬──────────────────┐
│ メインビュー                      │ サイドバー         │
│ レポート（幅は領域に任せる）        │ タスク一覧         │
│ 左揃え・本文書体・行間 1.75        │ セッション情報      │
│                                 │ （名前は等幅）      │
│                                 │                  │
└─────────────────────────────────┴──────────────────┘

   ◯  ╭───────────────────╮         ┌──────────────────┐
  立ち絵 │ 吹き出し（最新が下）│         │ 入力欄            │
       ╰───────────────────╯         │                  │
   ↑ 枠も地も持たない。ground の上に直接立つ  │ [送信]  経過: –   │
                                     └──────────────────┘
```

- **揃えは全面左揃え。** 日本語の読み物なので、中央揃えも両端揃えも使わない
- **キャラビューだけが枠と地を持たない**（原則2）。他の3領域は `surface` の地に `rule` の枠
- 領域の比率は使う人が動かせる（既存の仕組みを変えない）

### 13.5 差せるものの受け渡し

- **パック**: `character.json` に `accent` を1つ足す（`outfitAccents` と同じ階層）。無ければ既定値に落ちる
- **パック（背景）**: `character.json` の `background`（素材のファイル名と覆いの不透明度）。
  **効くのはキャラビューだけ**で、無ければ背景画像は出ない（13.8）
- **使う人**: `ground` / `surface` / `ink` の3つ。**キャラクター画面から変え、
  `localStorage` に持つ**（13.6）
- どちらも、届いた値は**境界で検証してから CSS 変数に流す**（外部由来の値の扱いは
  `docs/coding-standards.md`）

### 13.6 設定の置き場所

**今回のことは帯とサイドバーに、それ以外はキャラクター画面に**（2026-09-17 決定。2026-09-23 に

**色は「利用者が決める部分」と「キャラクターが決める部分」に割る**（2026-09-23 決定。ユーザーが
設定のポップオーバーのモック `docs/history/mockup/settings-2026-09-23.png` を示した）。
**地・領域・字の色は歯車へ移し、差し色（パックの持ち物）はキャラクター画面に残す。** 同じ
`<input type="color">` が並んでいても、**一方は「どの端末でも自分が読みやすい画面」、もう一方は
「このキャラクターの見た目」**で、変えたくなる時機も持ち先（`localStorage` と
`~/.tsukumo/characters/<name>/`）も違う。**保存の仕方は変えていない**（`localStorage` の鍵も
検証も `src/browser/domain/appearance-color.ts` のまま。機能をまたいで読まれるようになったので
`browser/domain/` へ上げただけ。2章）。

**歯車に置くのは上の4群だけ**（モックのうち 送信キー・通知・吹き出しで話しかける・発話を
読み上げる・文字の大きさ は置かない。通知は Orca の機能に任せる）。**領域の比率を戻すボタンも
歯車に入れない**——狭い画面では仕切りごと `display: none` になるので、ボタンだけが歯車に残ると
行き先の無い操作になる。**訪問のオン・オフは帯には置かない**——モデル・許可モードのように
毎ターン切り替える値ではなく、腰を据えて整える側の操作なので歯車へ（下の「訪問のオン・オフだけは」
で持ち先の理由を述べる）。

**新しいセッションの既定（モデル・許可モード）は `~/.tsukumo/state.json` に覚える**（覚えた
キャラクターと同じファイル・同じ扱い。5章「`remembered-default.ts`」）。**`localStorage` には
置けない** — セッションはブラウザが繋がる前にサーバ側で起こすので、起こすときに読める場所に無いと
意味がない。効き方は5つ:

- **起こすたびに効く**（起動も起こし直しも、復元でも新規でも同じ）。読むのは `session-launch` の
  1回だけで、同じ値が `query()` のモデル・許可モードにも、画面へ流す `session-default-changed`
  にも渡る（画面に出る既定と、実際に起こした既定がずれない）
- **帯で変えた値は既定を書き換えない**（帯はセッション限り）。逆に、歯車で既定を変えても
  **いま動いているセッションは変わらない**（効くのは次に起こすときから）
- **既定に「全部許す」（`bypassPermissions`）は選べない。** `<select>` に出さないだけでなく、
  コマンドの検証でも落とす（`SESSION_DEFAULT_PERMISSION_MODES`。`src/shared/session-default.ts`）。
  全部許すのは起こしたあと帯からその都度選ぶもので、次に起こすたびに黙って全部許す状態から
  始まる形にはしない
- **読めない・欠けている・知らない値は同梱の既定**（Opus・`auto`）。壊れた `state.json` で
  起動が止まらない（キャラクターの覚え方と同じ扱い）
- **`TSUKUMO_HOME` を分ければ既定も分かれる**（ホームごと差し替わるため。5章）

**書き上げる演出の速さは `localStorage` に持つ**（色と同じ並び。保存と読み取りは
`src/browser/domain/reveal-speed.ts` に集める——歯車（`features/screen-nav/`）とレポートの演出
（`domain/reveal/use-report-reveal.ts`）の両方が読むので、機能どうしの import を増やさず
`browser/domain/` へ置く。2章）。選択肢は3つ（既定は**標準**）:

| 選択肢 | 文字1つあたり  | 塊の下限 | 塊の上限 |
| ------ | -------------- | -------- | -------- |
| 標準   | 40ms           | 2400ms   | 8000ms   |
| 速い   | 20ms           | 1200ms   | 4000ms   |
| 切る   | （演出しない） | —        | —        |

- **速いは3つとも標準の半分**。下限・上限を一緒に半分にしないと、短い塊が下限に張り付いた
  まま「速い」を選んでも速さが変わって見えない（`domain/reveal/plan.ts` の `topicDurationMs` が
  塊の大きさをこの3値で時間に直す）
- **切ると演出そのものを走らせない**。`domain/reveal/use-report-reveal.ts` の `useReportReveal` が
  `revealSpeed === "off"` を見て `startReveal` を呼ばずに済ませるので、本文はマウントした時点で
  すぐ全部出て、筆先に付くミニ立ち絵（13.6 冒頭の表・`docs/requirements.md` 4.3）も出ない
- **選び直しても、書いている最中の演出には効かない。** `useReportReveal` は速さも `reveal`
  （書き上げる相手かどうか）と同じく**マウントした時点の値だけ**を読む（`useState` の初期値
  として1回読むだけで、あとから歯車を触っても読み直さない）。次に書き始めたレポートから
  新しい速さになる

**訪問のオン・オフは「覚え方」は新しいセッションの既定と同じだが、「効き方」だけ違う。** サーバの
`src/server/core/visit-timing.ts` が読む値なので `localStorage`（色・演出の速さ）には置けない。
**覚え先は新しいセッションの既定と同じ `~/.tsukumo/state.json`**（`remembered-default.ts` の
3つ目の欄。うまく動かないときに画面から止めたら、起こし直しても止めたままでいてほしいため）
——ここまでは新しいセッションの既定と同じ「次に起こすときから効く」で足りるはずだが、**「訪問中に
オフにしたらその場で帰る」だけは、いま動いているセッションにも即座に効くことを求める**。だから
`set-visit-enabled` は書いて覚えるところまでは `set-session-default` と同じ道を通り、**そのあと
画面へ流す `visit-enabled-changed` だけがほかの駆動由来のイベントと同じ経路で訪問の見張りにも
届く**（`SessionState.visitEnabled`。起こすたびに覚えた値へ揃え直す。5章「訪問の契機と状態」）。

**動き方は、読む場所と変える場所が同じ1つ**（2026-09-23 に改めた）。2026-09-22 には「帯は
名乗り、サイドバーは触らせる」として、モデルと許可モードの**読みだけ**を帯に置き、`<select>` は
サイドバーに残していた。帯の操作子がその読みを兼ねるので、**読みだけの字とサイドバーの
`<select>` は両方外す**（13.9「何を外すか」）。サイドバーは会話の画面にしか無いので、
キャラクター画面とトークン消費の画面からも変えられるようになる。

**キャラクターの切り替えは「セッション限り」から「ずっと」へ移したわけではない。** 選ぶ操作自体は
今回どおりセッション限り（起こし直すと戻る）だが、**次に起こしたときの初期値としては覚える**
（2026-09-14 決定。ユーザーの指摘「終了直前のキャラクターで起動時にもそうであってほしい」）。
持ち先は `localStorage` ではなく `~/.tsukumo/state.json`（`adapter/remembered-default.ts`、5章）。
**cwd には依存させない**（キャラクターの好みはプロジェクトごとではないため）。置き場所（サイドバー
「セッション情報」）は変えない。

**覚えるのは「画面から名前が選ばれた」ときだけ**（2026-09-21 決定。2026-09-14 の決定は覆していない
— 覚える範囲を、当時からそのつもりだった「画面から選んだとき」に絞り直しただけ）。**起こし方は
3つあり、どれで来たかで覚えるかが決まる**:

| 起こし方           | これから起こすパック                 | 覚えるか   |
| ------------------ | ------------------------------------ | ---------- |
| 起動               | 初期パック（指定 > 覚えた値 > 既定） | 覚えない   |
| `switch-character` | 画面から選ばれた名前                 | **覚える** |
| `set-chat-mode`    | いま出しているパックのまま           | 覚えない   |

**`set-chat-mode` は覚えない**（2026-09-21 に直した）。それまでは「起こし直しに使うパック」を
「画面から選ばれた名前」と同じ欄で渡していたので、**モードを切り替えただけで
`~/.tsukumo/state.json` の覚えたキャラクターが書き換わっていた**（`TSUKUMO_CHARACTER` の使い捨ての
パックも、同梱の既定も、雑談へ入った瞬間に「前回のキャラクター」になっていた）。`core` の
コメントは当時から「覚えるのは画面から選んだときだけ」と書いてあり、**実装と食い違っていた。**
直し方は**2つの意味を型で分ける**こと（`CharacterSelection`。初期パック／画面から選ばれた名前／
いま出しているパックのまま の3つ。`src/server/core/character-selection.ts`）。「いま出しているまま」は
名前を運ばないので、画面から選ばれたのと取り違えようがない。

- **同じパックを画面から選び直したときは覚える**（変えない）。画面から選ぶのは明示の操作なので、
  値が同じかどうかで扱いを分けない
- **`TSUKUMO_CHARACTER` を指定していても、画面から選べば覚える**（変えない）。環境変数が
  勝つのは**起動時にどのパックで起こすかを読むとき**だけで（指定 > 覚えた値）、画面からの明示の
  選択に負ける理由にはしない。その回だけ試したいなら、切り替えずに起こしたまま使う

**割るのは保存先ではなく「読んでいる最中に触るか（セッション限り）／腰を据えて整えるか
（それ以外）」**（**歯車はこの割りの外**——どの画面からでも触れる場所に、腰を据えて整えるものの
うち**キャラクターに紐づかない**ものだけを集めた）（そうした理由は `docs/history/decision.md`「design.md 13.6 設定の置き場所
（保存先ではなく寿命で割る理由）」）。キャラクター画面に並ぶのはパックの持ち物
（立ち絵・差し色・背景）だけになった。添え書き（「この端末だけ」のような）は出さない。

**キャラクター画面は会話の画面と入れ替わる**（重ねない。2026-09-17 決定。ユーザー「SPA のような
ものを想定していたよ」）:

- **切り替えは `location.hash`**（`#character`。無ければ会話の画面。キャラクター画面で選んでいる
  パックも `#character?pack=<名前>` として同じ hash に乗る。下の「キャラクター画面の中身」）。
  `stores/screen.tsx` の `useScreen()` が `hashchange` を読む（`useSyncExternalStore`）。
  リロードしても同じ画面に戻り、ブラウザの「戻る」が効き、`bun run dev` の再読み込み
  （`lib/refresh.ts`）でもキャラクター画面に留まれる。サーバの経路は増えない（`?token` はそのまま）。
  **ルーターのライブラリは入れない**（画面は3つで、分岐は hook 1つで足りる）
- **会話の画面は外さず `hidden` で隠す**（6.1「部品を外すのではなく隠す」と同じ）。
  `<SessionProvider>` はその上に居るので会話は進み続け、入力欄の下書き・選んでいるターン・
  スクロール位置も残る。戻ったときにセリフとレポートが追いついているかは目視で確かめる
  （吹き出しの追従は領域の高さに依存するため）
- **答え待ちが来たら帯の「いまの作業」が「答え待ち」に変わる**（`state.pending` が空でないとき、
  字を `state-warn` で。色だけにしない。2026-09-22 に戻る口の横から帯の右端の印へ移し、
  2026-09-23 に「いまの作業」へまとめた。13.9）。タブのタイトルの印は隠れていても効いている
- **入る口はヘッダーの帯**（13.9。2026-09-22 に置き換えた。それまではサイドバーのキャラクターの
  行の「整える」で、「ページ最上部のナビは置かない（画面が3枚以上になったら検討し直す）」と
  書いてあった。4枚目が入ったので検討し直した）。**サイドバーの「整える」は外す**
- **戻る口も帯が兼ねる**（帯の「会話」。2026-09-24 に「作る画面だけは左上の
  「← キャラクターへ戻る」を残す」を外した——作る口が独立した画面からダイアログに変わり、
  帯に出ない画面が無くなったため。下の「作るダイアログ」）
- **右下は「領域の比率を既定に戻す」だけのまま**（引き出しを作る前の形）。増える常設の要素は
  帯の1つで、サイドバーのリンクは1つ減る
- **読んでいる間に見えている必要がないものは会話の画面に置かない。** 主な仕事は長く読み続ける
  ことなので（13章のブリーフ）、整える口は別の画面に出す。**帯はこの原則の唯一の例外**
  （13.9。どの画面からも他の画面へ行けることを、面積と引き換えに採った）

**キャラクター画面の中身**（2026-09-17 決定。2026-09-24 に見本

作り直した）。**左に一覧、右に選んでいるパックの詳しい設定の2段組。** 色は 13.2 の4つから増やさず
（見本の灰の段は `surface` / `ground` / `rule` / `rule-quiet` / `ink-quiet`、仕事の差し色は `accent`、
消す口の赤は `state-ng` に当てた。**16進は1つも足していない**）、書体も 13.3 の2本のまま（見本の

  カードは 立ち絵（`<Portrait>`。衣装は `default`、動きは無し。カードの地の上に直接置き、立ち絵
  自体は枠も地も持たない。13.1 原則2）と表情のラベル（パックの `expressions` から。原則4）。
  `default` のカードには「いつもの顔」の札を添える。見出しには添え書きを付けない（枚数は空欄の
  カードで分かり、口の出し方は乗せれば分かる。2026-09-24 決定）
- **「差し替える」「消す」はカードの右上のアイコン**で、**乗せたとき（`:hover`）とカードの中に

  ので、キーボードでは Tab で口に入った時点で出る（`display: none` だと入れない）。乗せる操作の

  枠そのものが選ぶ口で、9つそろえば空欄は出ない。汎用の「表情を足す」カードは置かない
- **表情を消す前の確かめ**: 「消す」は押しただけでは送らない。押すとカードに添う幅 300px の吹き出し
  （`components/portrait-clear-confirm.tsx`。見本
  `docs/history/mockup/character-delete-expression-2026-09-23.html` / `.png`）が開き、
  見出し「「<表情>」を消しますか？」・本文「この表情を使う場面では「<`default` のラベル>」が
  出ます。」（どちらもパックのラベル。原則4）・「やめる」「消す」を出す。**画面全体は覆わない**
  ——`<dialog>` の `showModal()` で top layer には出すが、UA既定の中央寄せは外して押した位置から
  自前で置き、`::backdrop` も透明にする。「やめる」・Esc・外側のクリックはどれも何も送らずに閉じる
- **どのカードにも画像を落とせる**（落とすと差し替え・足す。受け付ける種類の検証はサーバ側）
- **差し色は横に並べる**（2 : 4）。左が画面の差し色（仕事・雑談。`chatAccent` を持つときだけ
  見出しの右に「雑談も仕事と同じにする」、無ければ同じ場所に「雑談も仕事と同じ」の字）、右が
  立ち絵の差し色（既定・軽装 haiku・通常装備 sonnet・戦闘配置 opus）。色見本は札全体が
  `<label>` で、左の四角が `<input type="color">` そのもの、右端に今の値の16進（色だけにしない）。
  狭くなると上下に積む。**呼び名がかぶる**ので、衣装ごとの行は「立ち絵の差し色」と呼ぶ
- **背景は縮図（220×124。敷いたときと同じ cover・下端合わせ）と「差し替える」「消す」の2つだけ**。
  **覆いの濃さは画面から変えない**（定義ファイルを手で直す。13.8）
- **760px 以下では一覧を詳しい設定の上に積む**（格子と差し色の列数は詳しい設定の幅を見る
  `@container` が決めるので、狭い画面用に別の規則は足していない）
- **`<Portrait>` は `components/portrait.tsx`**（2つ目の読み手。2章）。並びでの大きさは
  `character-screen.module.css` が決め、`className` で渡す（キャラビュー側の割合指定は
  `.character-region` の変数が無いので効かない。6.6）
- **「このキャラクターを消す」帯は、詳しい設定の最下部・背景の節の下**（見本
  `character-screen-2026-09-23.png` の最下部）。`removal`（7.1「消すときの細部」の
  `characterPackRemoval`）が `"none"` のパック（同梱だけ・`characters/local`・一覧の外）では
  出さない。**`"delete"` と `"revert-to-bundled"` で見出し・本文・ボタンの動詞を出し分ける**
  （消せるパックは「このキャラクターを消す」/「<名前> を消す」、同梱を直したパックは
  「同梱に戻す」/「<名前> を同梱に戻す」。7.1 の文言をそのまま画面の字にする）。**使用中は
  帯のボタンを押せなくする**（`inUse`。理由は帯の本文にすでに書いてあるので `title` は
  短い言い換えにとどめる）
- **帯のボタンは即座に送らず、確かめのダイアログ（`components/character-delete-confirm.tsx`。
  見本 `character-delete-2026-09-23.png`）を開く。** 作るダイアログと同じ UA 既定の中央寄せで
  画面全体を覆い、押した位置には寄らない（表情の確かめ〔`portrait-clear-confirm.tsx`〕は
  カードの位置に添うが、こちらは帯のどこから開いても同じ場所でよい）。中身は顔（無ければ
  点線の丸）・見出し「<名前> を消しますか？」／「<名前> を同梱に戻しますか？」・本文
  （消す: 表情の枚数と「元に戻せません」。同梱に戻す: 「覚えたことが消え、雑談の記録は残る」）・
  id の確かめの入力欄・「やめる」「消す」／「同梱に戻す」
- **打った id がパックの id と完全に一致するまで実行ボタンは押せない**（決まっていること。
  一致の判定は表示のたびに引き直す軽い比較で、`components/character-delete-confirm.tsx` が

  使用中の姿に落ちる」という既存のフォールバックがそのまま担う**——消したパックの hash は
  残るが、一覧から消えたその名前はもう見つからないので、次の描画で使用中のパックが自動的に
  選ばれた状態になる（新しく作るときの `selectPack` のような明示の呼び出しは要らない）

**画面の差し色を編集する口の形**（2026-09-23 決定）:

- **雑談の差し色が無いときの色見本は、いまの仕事の差し色（引きずり中の値も含む）をそのまま出す。**
  仕事の色をドラッグしている最中も雑談側が一緒に動く。**「仕事と同じ」であることは色だけで

- **送信の debounce は衣装の差し色と同じ定数（`ACCENT_DEBOUNCE_MS`）を使う。** 衣装の差し色も画面の差し色も「ドラッグ中の色を
  離れてから1回にまとめる」という同じ操作なので、間隔を2つに分ける理由が無い

### 13.7 雑談モードの画面

**雑談中はメインビューが「立ち絵と会話のログ」になる**（2026-09-20 決定）。モードそのものの
決定（入れる理由・何が変わるか・切り替えに起こし直しが要る理由）は `docs/chat-mode.md` 4.9 が
持ち、ここは**見え方と置き場所だけ**を書く。

```
（帯。［仕事｜雑談］は「雑談」が押された形。ほかは仕事のときと同じ。13.9）
┌──────────────────────────────────┬──────────────────┐
│ メインビュー（雑談）                 │ サイドバー         │
│                                  │ プロフィールの札    │
│    ◯     ╭──────────────╮        │ 最近の話題         │
│   立ち絵   │ セリフ        │        │ 覚えていること      │
│   （大）   ╰──────────────╯        │ セッション         │
│           ╭──────────────╮        │                  │
│           │ 利用者の発言   │        │                  │
│           ╰──────────────╯        │                  │
│           （古い→新しいが縦に積む）   │                  │
└──────────────────────────────────┴──────────────────┘

   キャラビューは畳む（立ち絵が上へ移る） ┌──────────────────┐
                                     │ 入力欄            │
                                     └──────────────────┘
```

- **立ち絵は左、会話のログは右**（2026-09-20、ユーザーの選択）。ログは LINE / Discord と同じく
  **古い→新しいの順に縦へ積み**、利用者の発言とキャラクターのセリフが交互に並ぶ。
  仕事のときのメインビュー（依頼ごとの札に区切り、`‹` `›` で遡る）とは並びの規則が違う
- **サイドバーはタスク一覧を出さず、4段に差し替わる**（下の「雑談のときのサイドバー」）
- **キャラビューの領域は雑談中は畳む。** 立ち絵がメインへ移るので、残しても空の帯になる。
  吹き出しもメインのログが引き受ける。**4領域が3領域になるのは雑談の間だけ**で、
  仕事へ戻せば 13.4 の形に戻る
- **メインビューの領域は雑談中だけ枠と角丸を外し、背景（13.8）もそこへ移る**（2026-09-21 決定。
  ユーザーの指示「雑談モードで、メイン画面に背景を設定したい。設定する背景は仕事モードの背景と
  同じでかまわない」）。立ち絵と会話が移ってきたこの領域は**畳んだキャラビューと同じ立場**になり、
  ウィジェットの中ではなく `ground`（絵があればその絵）の上に直接立つ。**仕事へ戻せば枠も角丸も
  戻り**、背景はキャラビューへ帰る
- **立ち絵はメインでも枠と地を持たない**（13.1 原則2。居る場所が変わっても原則は変わらない）
- **会話のログは `speak` のセリフから作る。** `shared/main-view.ts` の `mainViewEntries` は
  セリフの記録を落とし続け、**雑談のログは `shared/chat-log.ts` の `chatLogEntries` が
  別に組む**（2026-09-20、プロトタイプで確かめて決めた）。`mainViewEntries` は依頼を境目に
  やり取りへまとめて札で遡る形を作っており、**素直な時系列で積む雑談とは並びの規則が違う**
- **ログに並ぶのは雑談のセッションのぶんだけ**（2026-09-20 決定。`docs/chat-mode.md` 4.9）。
  雑談と仕事は**セッションの印から分かれていて**（`tsukumo:<パック名>:chat`）、雑談へ入る
  起こし直しが `resume` するのは前の雑談。**仕事の会話はログに混ざらず**、仕事へ戻した
  メインビューにも雑談は出ない。**ログの組み立てで仕切っているのではない** — 組む前の段階で
  別の履歴になっている。**そのパックで初めて雑談へ入るときはログが空から始まる**（印が付くのは
  ターンが終わって数秒あとなので、続きにするものが無い。理由と受け入れた判断は 4.9）
- **利用者の発言に添えた画像の控えは、吹き出しの中に並ぶ**（`docs/requirements.md` 4.10。
  LINE / Discord と同じ見え方になるのはここ）。控えは押すと拡大して見られる（同上）
- **圧縮の区切りは、線の見た目だけで吹き出しと見分ける**（`docs/glossary.md`「圧縮の区切り」。
  2026-09-23、辛口レビュー「文言なしの1px 線が吹き出しの縁と同じ色で見分けが付かない」を受けて
  直した）。**文言を添えない決定**（`docs/chat-mode.md` 4.9）は変えず、**色は `rule` のまま
  据え置く**（13.2「入れるのはこの3本だけ」——差し色を薄めた仕切り線はレポートの見出しと表の
  3本に絞ってあり、ここを4本目にすると仕切りの合図が薄まる）。**破線にし、幅を縮めて中央へ置き、
  上下の余白を広げる**の3つを組み合わせ、吹き出しの実線・全幅の箱と見分ける
- **読む面の原則（13.1 原則1）はログにも効く。** 話者を分ける縁や印には `accent` を使ってよいが、
  **セリフの文字そのものは `ink`**。長い往復でも濃さが変わらない
- 寸法は 13.3 の段のまま（セリフは本文の 0.9375rem）。**立ち絵とログの比率はプロトタイプで
  目視して決めた**（2026-09-20、1400x900 で実測）: 立ち絵は領域の高さの 80%・幅の上限 32%、
  ログが残りで、**下端から積む**（件数が少ないうちに上へ貼り付くと立ち絵の高さと話が合わない）。
  狭い画面（760px 以下）は高さ 76%・幅の上限 28%
- **雑談中も上下の仕切りを出し、入力欄の高さを掴んで変えられるようにする**（2026-09-20 決定）。
  **既定は仕事のときの比率（`split.rowTop`）をそのまま使い**、雑談で動かした比率は
  `Split` の `collapsedRowTop` に別で覚える。どちらのモードで動かしても相手の比率は動かない。
  **`collapsedRowTop` は「まだ動かしていない」を `undefined` で表す** — 初期値として
  `rowTop` をコピーすると、あとから仕事の比率を変えたときに雑談側が追随しなくなる
- **立ち絵をつつくと話しかけてくれる**（2026-09-22 決定。ユーザーの指示「立ち絵をつつく形に
  置き換える」。**もとはログの末尾に「話しかけてもらう」という字の操作子を置いていた**のを
  置き換えた。当時の形は `docs/history/decision.md`「design.md 13.7 雑談モードの画面（ログの
  末尾に置いていた「話しかけてもらう」ボタン）」）。押すと tsukumo が合図を1つ送り、**返ってきた
  セリフだけがログに並ぶ**
  - **送った文面はログにも記録にも残さない**（2026-09-21、ユーザーの選択）。**落とすのは組み立ての
    側ではない** — 駆動が `request` の代わりに**文面を持たないイベント**（`turn-started`）を流すので、
    雑談のログ（`shared/chat-log.ts`）にも仕事のメインビュー（`shared/main-view.ts`）にも雑談の
    会話のアーカイブにも**初めから流れようが無い**。上の「ログの組み立てで仕切っているのでは
    ない」と同じ立場で、組む前の段階で決まっている。**アーカイブが書くのは `request` と `speech`
    の2種類だけ**なので、ここも別に除外を足す必要が無い
  - **話題は tsukumo が持たない**（原則4）。送る一言は「話題はあなたが選ぶ」という合図だけで、
    候補も例も傾向も並べない（`src/server/core/chat-nudge.ts`。雑談の作法を持つ
    `chat-manner.ts`・`/compact` の文面を持つ `chat-compact.ts` と同じ切り分けで、**core が持つ**）
  - **置き場所は立ち絵そのもの**（ログの末尾でも、立ち絵の下でも、ログの外の帯でもない）。
    **操作子は増えるどころか1つ減る** — 字の操作子が消え、**この画面で唯一ずっと同じ場所に
    居るもの**が受けるようになる。妖をつつくという動作自体が説明を要らなくするので、常設の字も
    要らない（13.1 原則2）
  - **押せることを持たせるのは雑談の側で、`components/portrait.tsx` ではない。** 立ち絵は
    キャラビューとキャラクター画面も使う共有部品なので、**仕事のときの立ち絵は押せないまま**に
    する。**包むのは `<button>`** — セリフの行と違って立ち絵には選ぶ文字が無いので、
    `role="button"` ＋ 自前のキーの受けが要らず、**キーボードで押せる道はブラウザが最初から
    持っている**
  - **載せたときの合図は3つ**: **ひと揺らしする**・**指の形にする**・**短い案内をポップさせる**
    （案内の字は「話しかけてもらう」。2026-09-22 ユーザーの指示）。**立ち絵に載せても表情は
    変わらない** — 遡る先を持たないので、変える材料が無い
  - **揺らすのは包んだボタンのほうで、立ち絵そのものではない。** 立ち絵は呼吸や歩行
    （`data-motion`）を自分で持っているので、同じ要素に当てると上書きして息が止まる。入れ子に
    すれば transform が掛け合わさり、呼吸したまま揺れる。**一度きり**なので、載せ続けても
    揺れ続けない
  - **案内は常設の枠を増やさない** — 載せている間とフォーカスの間だけ見える。**隠すのは
    透明にするだけ**（`display: none` / `visibility: hidden` にすると支援技術の木からも消え、
    ボタンの `aria-describedby` が指す先が無くなる）。**ボタンの名前は立ち絵の alt のまま**に
    し、何が起きるかは説明の側に置く
  - **`ground` 一色を1枚だけ地に敷く**（2026-09-21。載せたときの案内も、空のときの案内も同じ）。
    背景がメインへ移ったので、地を持たないままだと**絵が字の背後へ回り込む**（13.8「読めることを
    どう守るか」の2）。敷く色が領域の地と同じなので、**背景の無いパックでは見え方が変わらない**
  - **ログが空のときは、空のときの案内の文面が促す**（「立ち絵をつつくと話しかけてくれます」）。
    促す操作子がログの中から消えたので、**最初の一言を促す場所はこの1件だけ**になった
    （雑談を始める場面がいちばん要る場面）
  - **ターン進行中は押せない**（帯の仕事/雑談のトグルと同じ立場）。**ただし `disabled` には
    しない** — ブラウザは `disabled` の要素にホバーもフォーカスも通さず、キーボードで辿り着ける
    道ごと消える。`aria-disabled` で伝える。**その間は案内そのものを出さない**（2026-09-22
    ユーザーの指示。それまでは押せない理由の定型文に差し替えていた）ので、`aria-describedby` も
    指す先を持たない。**立ち絵そのものは薄めない**（要素の `opacity` は地ごと透かす。13.8）ので、
    押せないことは**応えないこと**で見せる: 指の形にならず、揺れず、字も出ない。
    **雑談のときだけ**で、仕事のメインビューには出ない
    （`<ChatView>` 自体が雑談の間しか出ない）うえ、**サーバも雑談でなければ断る**（画面を経ない
    依頼の取りこぼし対策）

#### 切り替えのときの立ち絵

**仕事 / 雑談を切り替えたら、最初に出る立ち絵は切り替えた先のもの**（2026-09-23 決定。ユーザーの
報告「切り替えた瞬間、一瞬だけ切り替える前のモードの立ち絵が出てチカッとする」）。移り変わりの
動き（位置と大きさを移す）は付けない — ユーザーが望んだのは「すぐに正しい姿」で、動きではない。
前の姿が出ていたのは、駆動が起き上がるまでの数秒に新しい代のイベント（`chat-mode-changed` など）が
`events` で先に配られ、ブラウザが**前のセッションの姿のままモードだけ**を切り替えていたため。そこで
**起こし直しの代は新しい `hello` を配るまで束を配らず**（`server/core/session-manager.ts`。その間の
姿は `hello` に入る）、**`hello` は続きの履歴を流し終えてから配る**（`server/core/session-launch.ts`。
表情が既定から続きの表情へもう一度飛ばない）。移った先の立ち絵が読み込み待ちで空かないよう、
**表情の数だけ先に読んでおく**（`components/portrait.tsx` の `usePortraitPreload`）。新しくマウント
された立ち絵の入り（`portrait-fade-in`）はほかの場面と同じに残す。

#### 雑談のときのサイドバー

**雑談中はタスク一覧を出さず、上から4段に差し替える**（2026-09-23 決定。ユーザーが示したモック
`docs/history/mockup/chat-sidebar-2026-09-23.png`。辛口レビューの指摘「雑談していても画面の一部が
仕事の話を続けている」）。仕事へ戻すと元の形（タスクの区画＋下端の帯）に戻る。

```
┌────────────────────────────────┐
│ ◯ 名前                [変える ⌄] │ 1. プロフィールの札（伸び縮みしない）
│   ひとことプロフィール            │
├────────────────────────────────┤
│ 最近の話題                       │ 2. ┐ まとめて1つの入れ物に入り、
│ 覚えていること            （編集） │ 3. ┘ 残りの高さを取ってその中で転がる
├────────────────────────────────┤
│ セッション [<select>           ] │ 4. 下端の帯（セッションだけ。伸び縮みしない）
└────────────────────────────────┘
```

1. **プロフィールの札**（`features/sidebar/profile-card.tsx`）: 顔（13.9「顔」と同じ素材・丸・
   差し色の輪で、大きさだけ 64px）・名前（パックの `name`）・**ひとことプロフィール**
   （`character.json` の新しい欄 `tagline`。検証は `src/shared/character-definition.ts`。
   **無いパックは名前だけ**で、空の行を置かない）・右端の「変える ⌄」。領域の左右と上の縁まで
   広げ、地は `surface` を `accent` で**5%だけ**染める（名前という文字のラベルがある塊なので
   13.2「意味を持つ塊の地」の範囲。選ばれたものの地の `surface-accent` とは分ける）。下の罫線は
   `rule` のまま（差し色の仕切り線はレポートの3本に絞ってある。13.2）。**名前とひとことは読む面の
   文字**なので `ink` / `ink-quiet`（13.1 原則1）
2. **最近の話題** / 3. **覚えていること**: 区画の枠（`SidebarSection`）で見出しを出す。
   **最近の話題は雑談の要約の写しから取り出した見出し**（`state.chatTopics`。出どころと取り出し方は
   7章「雑談の記憶の要約はどこに置くか」）を**新しい順に3件まで**、届いた順のまま並べる
   （各行の上に `rule` の細い線。印は付けない）。**更新されるのは圧縮のときだけ**で、それまでは
   前回の話題のまま。**空のとき**（一度も圧縮していない・見出しを取り出せなかった）は
   「まだ話題が無い（話が積もると、ここに並ぶ）」を出す。**覚えていることは `persona.md` の
   `## 覚えたこと`**（`state.rememberedLines`。出どころと消し方は7.1「1行だけ忘れる」）を
   **1行＝チップ1つ**で並べる（各行の上に `rule` の細い線）。チップは先頭20文字で
   切り、押すとその場で全文に開く。空のときは「まだ覚えていることが無い」を出す。**「編集」は
   消せる行があるときだけ置く**（空のときに押せても何もできない）——押すと各チップに × が付き、
   × を押すと消す前の確認を挟んで `forget-remembered-line` を送る
3. **セッション**: 仕事のときと同じ下端の帯（`SessionInfo`）から、キャラクターの対を外したもの
   （キャラクターの切り替えは札の「変える」へ移る）。**切り替え先が1つも無いときは帯ごと出さない**
   （罫線と沈んだ地だけの空の帯が残らないように）

**誰が組むか: `<Sidebar>` が `chatMode` を見て自分で差し替える**（`<Root>` から別の部品を渡さない）。
下端の帯は両方のモードで同じ部品で、差し替わるのはその上だけ——`<Root>` が2つのサイドバーを
渡す形にすると、帯を2つの組み立てで重ねて持つことになる。2章「区画ひとまとまりは領域の側に
置く」と同じ理由でもある。`<Root>` がメインビューを差し替えるのは `<MainView>` と `<ChatView>` が
**別の領域の機能**だからで、サイドバーは1つの領域の中で段の並びが変わるだけ。`<Layout>` に渡す
旗も増えない。

**どの機能に置くか: `features/sidebar/` の中**（`profile-card.tsx` / `recent-topic-section.tsx` /
`persona-memory-section.tsx`）。雑談の側（`features/chat-view/`）に置くと、下端の帯を読むために
領域の機能どうしの import が要る（2章）。中身を入れたあと、話題や覚えたことがタスクの
`task-board` のようにサイドバーの外でも使う語彙になったら、そのとき「置かれる機能」に切り出す。

**「変える ⌄」は、見た目のボタンの上に本物の `<select>` を透明にして同じ大きさで重ねる**
（`features/sidebar/character-switch.tsx`。**下端の帯のキャラクターの `<select>` と同じ部品**で、
選択肢・塞ぐ条件・送る `switch-character` を1箇所に持ち、見た目と名前だけを置く側が渡す）。押すと
ブラウザの選択肢の一覧が開き、キーボードも読み上げもブラウザが持つ。名前（`aria-label`）は
「キャラクターを変える」で、見える字「変える」を含む。**フォーカスの輪は透明な `<select>` では
なく外枠に描く**（`:has(:focus-visible)`）。ターン中は `<select>` を `disabled` にして理由を
`title` に出し、外枠を薄める（振る舞いは帯の `<select>` と同じ）。**⌄ は共有の `<Select>` の枠が描く矢印**で、枠ごと口いっぱいに広げるので
`<select>` を透明にしても矢印は見えたまま残る（手描きの矢印を別に持たない）。

**狭い画面（760px 以下）でも配分は変えない。** 札と帯は伸び縮みせず、2段目と3段目をまとめた
入れ物だけが残りの高さを取り、入りきらないぶんはその中で転がる。雑談中は下段のキャラビューが
畳まれるので、390x844 でもサイドバーは高さ 587px あり、札（101px）と帯（84px）を固定しても
中段に 400px 残る（2026-09-23 実測。疑似セッション）。

**採らなかった案**:

- **`<Root>` が `chatMode ? <ChatSidebar /> : <Sidebar />` を渡す。** 下端の帯が2つの組み立てに
  またがる
- **雑談のサイドバーを `features/chat-view/` に置く。** 1つの機能が2つの領域を持ち、`chat-view`
  から `sidebar` の帯を読む機能どうしの import が要る
- **「変える」を今の `<select>` のまま札に置く。** `<select>` は選んでいる選択肢の名前を見せるので、
  札の名前と同じ字が2度並び、「変える」という操作の名前が見えない
- **「変える」をボタン＋独自の選択肢の一覧にする。** 13.9「採らなかった案」の「ドロップダウンを
  独自の開閉にする」と同じ理由（キーボードと読み上げを自前で持つことになる）。選択肢を CSS で
  組める `<select>`（`appearance: base-select`）はまだ新しく、Orca の中のブラウザで使えるかを
  確かめていない
- **2段目と3段目をそれぞれの区画で転がす**（仕事のときのタスクの区画と同じ形）。どちらも短い
  一覧で、区画ごとに転がすと小さな窓が2つ並ぶ
- **見本の色と書体をそのまま写す**（橙の地・淡い橙の字・橙寄りの枠・明朝）。16進を `theme.css`
  の外に書かない・読む面は差し色を受け取らない（13.1 原則1）・書体は2本（13.3）の決定と当たる。
  見本の橙は雑談中の `--accent`（パックの `chatAccent`）にあたるので、札の地の染めと顔の輪・
  `:hover` の縁・フォーカスの輪に写し、字と枠は `ink` / `ink-quiet` / `rule` に写した

#### セリフは全文で現れ、吹き出しは2秒空ける

**届いたセリフは、ログの末尾に全文でそのまま出て、現れる瞬間だけ短く弾む**（2026-09-23
決定。同日のうちに「1文字ずつ育てる」形からここへ変えた——育てる形は「キャラクターと一緒に
居る感じ」を足す狙いで入れたが、**吹き出しどうしが間を置かず続けて現れるとびっくりする**
という指摘を受け、**「ポンと現れる・吹き出しどうしは最低2秒空ける」**に差し替えた）。

- **サーバの契約は変えない**（`SessionEvent` も `SessionState` もそのまま）。セリフは `speech`
  で1件まるごと届く（`speak` の戻りが `"ok"` になる時点で全文がある）ので、**出すタイミングを
  ブラウザ側で持たせるだけ**で足りる（`features/chat-view/hooks/use-speech-reveal.ts`）
- **現れる瞬間、0.2秒ほど小さく拡大して落ち着く**（`chat-view.module.css` の
  `.chat-entry-pop`。CSS のアニメーションなので、`prefers-reduced-motion` は
  `styles/theme.css` の全体規則がそのまま止める——`.chat-typing-dot` と同じ扱いで、ここに
  個別の対応は要らない）
- **キャラクターの吹き出しどうしは、前の吹き出しを出してから最低2秒空けて次を出す。**
  すでに2秒以上空いていれば待たずに出す。**待たせるのは吹き出しどうしの間だけ**——利用者の
  発言・日の区切り・圧縮の区切りは、順番が回ってくれば待たせずそのまま出す。ただし実装は
  「`entries` の先頭から出せるところまで」という前置きを絞る形なので、**待っている吹き出しの
  手前に積まれた行は一緒に足止めされる**。雑談は返事を待っている間、入力欄が塞がる
  （`turnInProgress`）ので、待っている吹き出しの手前に利用者の発言が割り込むことは無い——
  そのため実際に足止めされるのは、1ターンに `speak` を複数回呼んだときのキャラクターの
  吹き出しどうしだけになる
- **画面を開いた時点で並んでいた記録は待たせず全部出す**（マウント時点の件数が起点。前の
  雑談の続きが、開くたびに端から出し直されることにならないように）。**弾む動きも同じ境目**
  ——マウントより後に現れた行だけが弾み、開いた時点の記録は弾まない
- **待たせている間、末尾に「...」を出す**（次の節「返事を待つ間の「...」」）。**立ち絵の表情は
  届いたセリフではなく、すでに出した吹き出しのものにする**——待っている間に表情だけ先に
  進むと、まだ出ていない吹き出しの中身が表情から漏れる。ただし新しいターンの始まり
  （まだ何も話していない）は、待っている吹き出しがあっても構わず既定の表情へ戻す
  （キャラビューと同じ扱い）
- **キャラビューの `<Balloon>` は再利用せず、`components/` へも上げない。** 雑談の行はすでに
  吹き出しの見た目を持っており（`chat-view.module.css` の `.chat-entry`）、`<Balloon>` のほうは
  `.balloon-track` の並び（`column-reverse`・押し上げ・薄める）と一体になっている。上げると
  **両方の事情を知る部品**になり、どちらを直しても相手が動く。`features/chat-view/` に閉じた
  ままなので、機能どうしの import も増えない（`test/architecture.test.ts`）

**採らなかった案**:

- **1文字ずつ育てる**（2026-09-23 に採用したが同日中に差し替えた元の案）。吹き出しの中身の
  ぶんだけ育つので「いま話している」時間は生まれるが、**1ターンに `speak` を複数回呼ぶと
  吹き出しが間を置かず次々に現れ、びっくりする**という指摘のほうを優先した
- **サーバから書きかけを流す**（`speech` を刻んで押す・雑談でも `partialUtterance` を使う）。
  **`speak` は1件まるごと届く**ので、刻むのはサーバ側の作り事になり、`SessionEvent` と
  `SessionState` が1つずつ増える。**同じ絵がブラウザ側だけで出せる以上、契約を増やす理由が無い**
  （13.1 原則2 の「枠を増やさない」と同じ判断を、プロトコルに当てたもの）

#### 時刻と日の区切り

**発言ごとに時刻（`HH:MM`）を添え、日が変わるところに日付の区切りを1本入れる**（2026-09-23 決定。
LINE / Discord と同じ形で、日の区切りだけの案・ホバーしたときだけ出す案は採っていない）。
雑談は日をまたいで戻ってくる場所なのに、昨日の一言と三十秒前の一言が見分けられなかったのを埋める。
記録の側の形は 4.2「記録の時刻」。

- **時刻は吹き出しの外、下端の内側**（キャラクターの行は右脇、利用者の行は左脇）。**吹き出しの
  中には入れない** — セリフをドラッグで選んでコピーしたときに時刻が混ざらない。DOM の順は
  話者によらず「発言 → 時刻」で、左右は並べる向きだけで返す
- **秒は出さない**（`HH:MM`）。会話の時刻としては分で足り、秒まで出すと行ごとに数字が動いて
  読む面が騒がしくなる
- **時刻と日付は `ink-quiet`**（13.1 原則1）、**時刻は等幅**（13.1 原則3。機械が付けた値）。
  背景（13.8）の上に字が直に乗らないよう、どちらも `ground` 一色の地を1枚敷く（`.chat-empty` と同じ）
- **区切りは日付の字だけ**（`9月23日（水）`。線は引かない）。圧縮の区切り（破線1本・文言なし）と
  **字の有無で見分ける**。年は出さない（ログが持つのは 100 ターンぶんで、年をまたいでも並びの順で
  読める）。「今日」「昨日」とも書かない —— 呼び名は時計に依るので、日付が変わったあとに描き直す
  まで古い呼び名が残る
- **区切りは日が変わった発言の手前にだけ入り、ログの先頭には入れない**。日を比べる相手は1つ前の
  発言で、圧縮の区切りは飛ばす。日の境目は画面を見ている人のタイムゾーン
  （`utils/clock.ts` の `localTimeZoneId`）で決め、並びを組むのは `shared/chat-log.ts` の
  `chatLogRows`（タイムゾーンは引数で受け取る）
- **前のセッションを組み直した発言（時刻が分からない）には時刻を出さない**。そこから
  いまの発言へ移るところに、いまの発言の日付の区切りを入れる。**「時刻の無い行 = 前のセッション
  から引き継いだ行」**として読め、起こし直した直後のログが全部「今日」に見えることはない。
  雑談⇄仕事の切り替えは起こし直しなので、切り替えるたびに、それまでの行は時刻の無い側へ移る
  （受け入れた判断。本当の時刻を運べない理由は 4.2「記録の時刻」）

#### 返事を待つ間の「...」

**返事を待っている間、ログの末尾にキャラクター側の吹き出しとして「...」を animation させる**
（2026-09-23 決定。Discord と同じ、「まだ喋ってくれる」合図）。**セリフの吹き出しの
初期状態ではなく、別の行**——控えている吹き出しの文字は `hooks/use-speech-reveal.ts` が持って
いて、ここには渡さない。控えていた吹き出しが出ると「...」の行は消え、入れ替わりにその行が
現れる（`features/chat-view/` の `components/chat-typing.tsx` と `components/chat-speech.tsx`）。

- **出す条件は2つ**: 今のターンでまだ `speak` が呼ばれていない（`turnInProgress &&
!speechCalledInTurn`。`SessionState.speechCalledInTurn` に既にある値で判定できる）、
  **または**まだ出していない吹き出しが控えている（`hooks/use-speech-reveal.ts` の
  `pending`）。**後者はターンが終わったあとも効く**——1ターンに `speak` を複数回呼んで、
  最後の1件がまだ2秒のゲートで控えたままターンが終わっても、「...」は出続ける。
  サーバの契約は増やさない
- **押せる行にしない**（遡る先の表情を持たない利用者の発言の行と同じ立場）。ドット3つは装飾
  なので、待っていること自体を文字で伝える `<TurnStatus>` の経過表示と役割が重ならないよう
  `aria-hidden` で支援技術の木から外す
- 色は accent（13.1 原則1「色を持ってよいのはキャラクターが居る場所」——現れる吹き出しの弾みと
  同じ立場）。`prefers-reduced-motion` は `styles/theme.css` の全体規則がアニメーションの
  duration を潰すので、CSS の animation を使うここは個別の対応が要らない

#### 会話を遡る

**ふつうのスクロールだけで遡る**（2026-09-20 決定）。持っているぶんは最初から全部ログに並べ、
上へスクロールすれば古い方が出る。**枠も操作子も増やさない**（13.1 原則2）。
「もっと見る」を置く案・上へ着いたら継ぎ足す案は、どちらも操作子か仕掛けが1つ増えるので
採らなかった。持つ幅（雑談は 100 ターン）は `docs/chat-mode.md` 4.9 が決める。

**セリフの行を押すと、そのときの表情へ立ち絵が遡る**（2026-09-21。キャラビューが過去のターンの
札でやっていることの、雑談での対応物。遡る先が「ターン」ではなく「1件のセリフ」なのは、
雑談のログが依頼で区切られていないため）。**立ち絵の動きは遡らない**（キャラビューと同じ扱い）。

- **押せるのはキャラクターのセリフの行だけ。** 利用者の発言は遡る先の表情を持たないので、
  押せる要素にしない（押しても何も起きない）
- **セリフはドラッグで選んでコピーできる**（2026-09-21 ユーザーの指示）。そのため**押せる行は
  `<button>` ではなく `role="button"` の `<div>`** — ブラウザは `<button>` の中の文字を
  `user-select` を何にしても掴ませない（2026-09-21、実機の Chromium で確認）。
  **選び終えて手を離した瞬間にも click は飛ぶ**ので、押し始めからの距離で「押した」と
  「選んだ」を見分ける（いま選ばれている文字は見ない。選択が消えるのは手を離したあとなので、
  見ると押せない回ができる）。キーボード（Tab → Enter / Space）で遡る道は自前で開ける
- **印が付くのは「立ち絵がいま従っている行」**（2026-09-22 決定。それまでは押した行だけに印が
  付き、**何も押していなければ印はどこにも無かった** — 行が押せること自体に気づけない）。
  **何も押していないときは最新のセリフに印が付き**、新しいセリフが来ればそこへ移る。
  増えるのは要素ではなく**既定値**のほうなので、枠も操作子も増えない（13.1 原則2）
- **印は、いまある地と縁を強めて示す**（地を差し色の側へ寄せ、内側の影で縁を1px 重ねる）。
  **印も操作子も増やさない**（13.1 原則2）し、縁を太らせない（行の高さが動いて並びがずれる）
- **印が指すのは行であって、その行の表情が常に出ているという意味ではない。** 何も留めていない
  間の表情の源は `speak` の1つだけ（`SessionState.speechExpression`）なので、**次のターンが
  始まれば立ち絵は既定へ戻る**（キャラビューと同じ扱い。`docs/requirements.md` 4.3）。印はその間も
  最新のセリフの行に残り、次のセリフが来ればそこへ移る
- **利用者が解くなら、留めた行をもう一度押す**の1つだけ。最新へ戻る専用のボタンは置かない。
  **既定で印の付いている最新の行を押したときは、解くものが無いので「留める」側に倒す**
  （印の位置は変わらないが、次のターンが始まっても表情がその行に留まる）
- **新しいセリフが来たら留めた選択は解け、印は最新のセリフへ移り、立ち絵もその表情へ戻る**
  （2026-09-21 決定）。
  **下端付近に居るかどうかでは分けない** — 自動スクロールの規則とは揃えず、立ち絵は常に
  「いまのセリフ」を表す側へ倒す。解けないままにすると、印の付いた行はログが伸びるうちに画面の
  外へ流れるので、**なぜ表情が古いのかが画面から分からなくなる**（一度押すと以後の新着に
  追従しなくなっていた。2026-09-21 に直した）。窓から古い記録が落ちて並びが前へ詰まったときも
  同じく解ける（番号で持った選択が別の行を指さない）

**行に載せても立ち絵は動かない**（2026-09-22 ユーザーの指示で戻した）。同日にいちど
「0.2 秒 載せると立ち絵がその行の表情へ先に応える」を入れたが、**遡るのは押したときだけ**に
戻してある。

- **ホバーが示すのは「押せること」まで**（地が差し色へ寄る・指の形）。**表情を動かす道は
  押す1つだけ**なので、ポインタの有無で振る舞いが割れない（キーボードとタッチも同じ道）
- **立ち絵の `alt` は押して遡ったときに書き換わる**（出ている絵をそのまま説明する）。
  **支援技術への手当ては足さない** — 立ち絵は `aria-live` の中に居ないので alt が変わっても
  読み上げに割り込まない

**`justify-content: flex-end` で「下端から積む」を作らない。** column flex で
`justify-content: flex-end` にすると溢れた分が block-start（上）側へ出るが、**CSS の
scrollable overflow は end 方向にしか伸びない**ので、上へ出た分はクリップされて掴めなくなる。
`.chat-log > * { flex-shrink: 0 }` は
この手当てにならない（原因は縮みではなく overflow の向き）。**「下端から積む」は別の手段で
作る**（先頭の子に `margin-top: auto` を当てる、など）。

**自動スクロールは下端付近に居たときだけ寄せる。** 件数が変わるたび無条件に
`scrollTop = scrollHeight` を当てると、**読み返している最中に下へ攫う**（実測と、直す前の
`ChatLog` の姿は `docs/history/decision.md`「design.md 13.7 会話を遡る（下端から積む・
自動スクロールの実測）」）。

#### モードの操作子はどこに置くか

**帯の左寄り、部屋の名前の右の「仕事｜雑談」のトグル**（2026-09-23 決定。それまではサイドバーの
「セッション情報」の `<select>`）。雑談モードは**セッション限り**の**動き方**で、どの画面からでも
触れる帯に置く（13.6 の表）。形・押したときの扱い・ターン進行中の扱いは 13.9「動き方の操作子」が
正典で、ここには二重に書かない。要点だけ:

- **1回押すと起こし直す**（確かめの一言は挟まない）。起こし直すと画面は初期化されるが、
  モードごとに印が分かれているので、戻せばそれぞれの続きから始まる（`docs/chat-mode.md` 4.9）
- **ターン進行中は押せない**（キャラクターの切り替えと同じ条件。理由の文面はモードの語に直す）

**雑談中の帯は、仕事のときと同じ要素を同じ位置に出す**（2026-09-23 決定）。変わるのはトグルの
押された側だけ。**「いまの作業」も残す** — 雑談中でも調べ物を頼めばツールが走り、レポートを
出さない雑談では、走っている手順を読める場所がそこしか無い。モデル・許可モードも同じ理由で残す。
帯の要素を雑談のときだけ減らすと、モードを切り替えるたびに口の位置がずれる。

**雑談中は `--accent` がパックの `chatAccent`（無ければ仕事と同じ `accent`）に切り替わる**
（2026-09-23 決定。13.2「雑談中は」）。すでに `--accent` / `--surface-accent` を読んでいる場所
（仕事/雑談のトグルのいまの側・いま出している画面の口・「いまの作業」の札の
`running` 状態・顔の丸の地）はコードを足さずに追随する。**立ち絵には枠を足さない**
（13.1 原則2「枠を持たないのはキャラクターだけ」は変えない）。

**「いまの作業」の札は、雑談中の依頼待ちだけ字と色が変わる**（2026-09-23 決定。13.9「いまの
作業」の直後の注記も参照）。答え待ち・作業中・止まっているはすでに意味を持つ語と色なので
雑談中でも変えないが、**依頼待ちの「依頼」は雑談の語彙ではない**ので、字を
「<パックの `name`> とおしゃべり中」に、印と枠を `--accent` に変える（無ければ「キャラクター
とおしゃべり中」。`docs/screen-design.md` 13.9 が決めた「札の頭にキャラクターの名前は置かない」の
例外がここだけ生まれる——名を出さないと「誰と」おしゃべり中なのかが札だけで読めないため）。

### 13.8 背景

**枠を持たない領域にだけ背景画像を敷ける**（2026-09-21 決定。ユーザーの問い「メイン画面、キャラ画面は
背景をカスタマイズできたほうが楽しいと思ったけどどうかな?」）。いまそれに当たるのは
**キャラビューと、雑談中のメインビュー**の2つ。**背景はキャラクターパックの
持ち物**で、キャラクターを切り替えると背景も入れ替わる。

**置き場所と効く範囲はユーザーが先に決めた**:

- **パックの持ち物にする**（`character.json`。`localStorage` の「利用者の設定」には持たない）。
  精霊なら森、というようにキャラクターと背景は一緒に決まるもので、置き場所を2つに割ると
  「森の精霊にサーバルームの写真」という組み合わせが作れてしまう。切り替えで丸ごと入れ替わる
  ほうが、パック＝1つの世界という7章の形にも合う
- **効かせるのは読む面以外だけ。** はじめは**キャラビューだけ**に絞った。主な仕事は長く
  読み続けることなので（13章）、**読む面の地は誰が来ても同じ**にする（13.1 原則1 の延長。
  元の問いは「メイン画面とキャラ画面」だったが、長く読み続ける面の可読性を優先して絞った）
- **雑談中のメインビューはあとから足した**（2026-09-21 決定。ユーザーの指示「雑談モードで、
  メイン画面に背景を設定したい。設定する背景は仕事モードの背景と同じでかまわない」）。
  **絞った理由と衝突しない** — 雑談の間そこは読む面ではなく**立ち絵の居る面**で、畳んだ
  キャラビューの行き先そのものだから。**サイドバー・入力欄・仕事モードのメインビューには
  敷かない**（読む面の地は変えない、は変えない）

#### 何を持つか

`character.json` に `background` を1つ足す（`outfitAccents` と同じ階層）:

```json
{
  "background": {
    "image": "background.png",
    "veil": 0.75
  }
}
```

| キー    | 中身                                                                        | 省略したとき         |
| ------- | --------------------------------------------------------------------------- | -------------------- |
| `image` | 素材のファイル名（`portraits` と同じ書き方。`/character/<pack>/<file>` へ） | **背景画像は出ない** |
| `veil`  | 覆い（`ground` 一色）の不透明度。0.7〜1                                     | `0.75`               |

- **`background` ごと無ければ、いまと同じ見え方**（`ground` の上に立ち絵が直接立つ）。省略は
  「背景なし」であって既定の絵に落ちるのではない（**素材はリポジトリに同梱しない**。
  `docs/requirements.md` 2.2）
- **`veil` が下限を下回る値なら下限へ引き上げる**（受け取らずに既定へ落とす `accent` と違い、
  背景は「出さない」より「薄く出す」ほうが書いた人の意図に近い）。`veil: 1` は画像が見えない
  安全側の端で、実用の帯は 0.7〜0.9

#### 読めることをどう守るか（覆いの下限）

**画像の上に文字を乗せない**ようにし、そのうえで**地そのものの明るさに下限**を置く。どちらも
数で決める:

1. **覆いの不透明度 `veil` は 0.7 以上。** 画像は `ground` 一色の覆いの下に敷き、**見えるのは
   最大でも 30%**。加えて、**画像が真っ白（`#ffffff`）・真っ黒（`#000000`）だと仮定して合成した
   地**が `ink` との比 `MIN_CONTRAST`（4.5。`src/browser/domain/appearance-color.ts`）を
   下回らないところまで `veil` を引き上げる。**画像の中身を1ピクセルも読まずに検算できる**のは、
   合成した色が必ず `ground` と画像の色を結ぶ線分の上に来て、その線分の端がいちばん危ない色
   （真っ白・真っ黒）だからである。`ground` と `ink` の比は 13.2 の境界がすでに 4.5 以上に
   保っているので、`veil: 1` まで上げれば必ず満たせる（＝引き上げが行き止まらない）。
   **雑談中のメインビューでも同じ論法がそのまま成り立つ**（地と字の色は領域で変わらないので、
   下限も 1つで足りる。2026-09-21 に確かめた）
2. **文字が乗る要素の地は不透明を保つ。** キャラビューで文字が乗るのは吹き出しの中だけなので
   （空のときの案内も吹き出し1件。`src/browser/features/character-view/balloon-track.tsx`）、
   地が不透明であれば画像は文字の背後に回り込まない。**雑談のログでも吹き出しは同じ**
   （`.chat-entry` の地は `surface` / `surface-accent` / それに `ink` を混ぜた色で、どれも不透明）
   だが、**吹き出しの外に出る字が2つある** — 立ち絵に載せたときの案内（13.7）と空のときの案内。
   この2つには **`ground` 一色を1枚だけ敷いた**（2026-09-21。雑談用に `veil` の下限を別に持つ
   のではなく、字の側を守る。敷く色が領域の地と同じなので、背景の無いパックでは見え方が
   変わらない）

下限が 0.7 なのは、既定の3色で**境目が 0.66 だから**。既定を 0.75 にするのは、下限ちょうどに
置くと `ink` を少し変えただけで引き上げが起きて、書いた `veil` と見え方がずれるため。
**見直すのは既定の3色を変えたとき**で、そのときの測り方と数字は `docs/history/decision.md`
「design.md 13.8 読めることをどう守るか（覆いの下限の実測）」にある。

**過去の吹き出しは要素の `opacity` で薄めない。** 要素ごと半透明にすると**吹き出しの地ごと
透ける**ので、背景画像が文字の裏へ回って上の2が崩れる（`veil` をいくら上げても届かない）。
**地は不透明な `surface` のまま、文字の色だけを地へ混ぜて薄める**ことにし、**混ぜる量の
上限は 45%**（50% では下限を割る）。

#### どう敷くか

- **敷く先は枠を持たない領域そのもの**（`.layout-ground`。キャラビューと、雑談中のメインビュー。
  **2つの領域が同じ class を共有する**ので、覆いの式はここ1箇所にしか無い）。**枠も角丸も付けない**
  （13.1 原則2 の「枠を持たないのはキャラクターだけ」は変えない — 背景は**ウィジェットの地**では
  なく、`ground` がその領域だけ絵に替わったものとして扱う）
- CSS は**覆いを1枚重ねた形で書く**（`linear-gradient()` に `ground` を `veil` の不透明度で
  2回並べ、その下に `url(...)` を重ねる）。`background-size: cover`、
  `background-position: center bottom`。
  **下端を合わせる**のは、立ち絵が床に立つ見え方（`--portrait-drop`）と地面の位置をそろえるため
- **セリフのログ（`docs/display.md` 4.2）は領域の背景をそのまま上へ伸ばす**（2026-09-23。
  ユーザーの指摘「背景が映ってない」）。絵の位置決めを領域の矩形に重ねて `cover` /
  `center bottom` を解くので、領域の中は開く前と同じ絵になり、領域の上には `cover` が切り落として
  いた上の部分が続く。領域の上端から上 6rem で地（`ground`）へ溶かす。領域の高さはキャラビューの
  領域をコンテナにして `cqh` で読む（`<dialog>` は top layer に出るが、DOM の祖先はそのまま）。
  **領域が絵より縦長のとき**（`cover` が高さで決まるとき）は絵の上端が領域の上端と一致し、
  溶かす前に絵が尽きるので、そこに薄い境目が見える
- 画像の URL は立ち絵と同じ `/character/<pack>/<file>` で、**取り直しの印（`?v=`）も同じ**（7.1）。
  配る側に足す経路は無い
- **雑談モードでは背景がメインビューへ移る**（2026-09-21 決定。ユーザーの指示「雑談モードで、
  メイン画面に背景を設定したい」。**もとは持ち込まない決定だったのを撤回した**）。
  キャラビューの領域は畳む（13.7）が、立ち絵と会話がメインへ移るので背景も一緒に移り、
  その間だけメインの枠と角丸が外れる。**素材は仕事モードと同じ**（パックの `background` 1つ。
  雑談用の別のキーは持たず、時刻や天気で切り替えもしない）。**`background-size` /
  `background-position` も同じ値**（`cover` / `center bottom`。メインは横長なぶん cover が左右を
  削るだけで、立ち絵が床に立つ位置と地面は合ったまま）。どちらの領域を地にするかを決めるのは
  入口（`src/browser/main.tsx` が `<Layout>` に `mainAsGround` を渡す）で、**`<Layout>` は
  「なぜ地になるのか」を知らない**（13.7 の `collapseCharacter` と同じ立場）
- **キャラクター画面（`#character`）にも敷かない。** 立ち絵が最大6体並ぶ面で、どれも枠と地を
  持たない（13.6）ため、背後に絵があると輪郭が混ざる数がキャラビューの6倍になる。整える面は
  静かなままにする

#### 画面からの差し替え

**キャラクター画面のパックの持ち物の並びに「背景」の行を1つ足す**（13.6）。口は「差し替える」と
「消す」の2つだけで、**覆いの濃さは画面から変えない**（濃くしたい人は定義ファイルを手で直す。
表示名を日本語にしたいときと同じ扱い。7.1）。常設の操作子は増えない（13.1 原則2）。
受け取り方・上限・書き込み先は 7.1 のままで、`ClientCommand` に `set-background` /
`clear-background` を足す。

#### 採らなかった案

色の延長で済ませる・`localStorage` に持つ・4領域すべてに効かせる・画像の明るさを測って覆いを
自動で決める・別の経路（POST）で受け取る・枚数の上限を増やす、の6つは採らない。理由は
`docs/history/decision.md`「design.md 13.8 背景（採らなかった案）」。

### 13.9 画面のナビゲーション

**会話・キャラクター・トークン消費の3枚を、全画面の最上部に置いた帯から行き来する**
（2026-09-22 決定。案を3つ出し、面積を実測して比べたうえでユーザーが帯を選んだ）。13.6 は
「ページ最上部のナビは置かない（**画面が3枚以上になったら検討し直す**）」としていたが、
トークン消費の画面（`#token-usage`）が入って4枚になり、**その1枚だけ UI からの入口が無い**
（`location.hash` を手で打つしかない）状態になったので、書いてあったとおり検討し直した。

**2026-09-23 に、帯を「名乗る場所」から「名乗り、動き方を触らせ、いまの作業を見せる場所」へ
広げた**（ユーザーがモック `docs/history/mockup/header-2026-09-23.png` を示し、この形にしたいと
言った）。サイドバーの「いま何をしているか」の区画と、「セッション情報」の3つの `<select>`
（仕事 / 雑談・モデル・許可モード）が帯へ移る。**帯の高さは 52px**（2026-09-23 のユーザーの
選択。見本は `docs/history/mockup/sidebar-tasks-2026-09-23.html` の `<header>` で、いちど見本
どおりの 60px にしたあと「少しだけ狭く」と言われて下げた。30px・60px との比較は下の「帯が奪う
面積（実測）」）。

```
 (顔) 空色の間 [仕事|雑談] │ 会話 キャラクター トークン消費 成果 │ ( ● 作業中 │ Bash: git add … )  Opus ⌄ 自動判定 ⌄ (⚙)

  **幅が足りないときに最初に縮む**（要約の末尾が「…」になる）。5 の字が伸び縮みしても 6・7・8 は
  動かない
- **8（歯車）はいちばん右端**（2026-09-23 決定。ユーザーがモック

  **設定は「画面」ではなくこの帯のポップオーバー**にする——どの画面からでも触れて、開いても
  いま読んでいるものが画面ごと入れ替わらない
- **帯の形**（2026-09-23 決定。値は見本の `<header>` から写し、色はトークンに宛てる）:
  - **画面の端から端まで出す。** 帯は body の padding の外へ負の margin ではみ出す（padding の値は
    `--page-padding` の1箇所）。外寸は**帯の地 52px（`--screen-nav-height`）＋下の罫線 1px
    （`--screen-nav-rule`）**で、会話の画面の grid も同じ変数から高さを引く。帯の下の隙間
    （`--screen-nav-gap`）は画面の縁と同じ `--page-padding`
  - **帯の地は `--ground` と `--surface` を半々に混ぜた色**（画面の地より一段明るく、領域の地より
    暗い）。下の罫線とトグル・口の間の縦の仕切り（高さ 24px・幅 1px）は `--rule`。どれも導出

    3px の線（`border-top`）があったが、2026-09-23 に印象が強すぎるという指示でなくした**
    （専用のトークンごと削除）
  - 左右の padding 24px・要素の間 20px・すべて縦に中央揃え。顔と部屋の名前は1つの塊で、間は 10px
  - **口は枠も地も無い文字のタブ**（14px。13.3 の「区画の見出し」の段）。帯の高さいっぱいに

    2px の下線**で示し（色だけで伝えない。13.1 原則1）、下線は下の罫線に重ねる。ほかの口は
    `--ink-quiet` と透明の下線（選ばれても字の位置が動かない）

#### 帯に何を置くか

- 出すのは **`Screen` の4つすべて**（会話 `#` / キャラクター `#character` /
  トークン消費 `#token-usage` / 成果 `#achievement`。成果の口は 2026-09-24 に足した。13.10）。**新しく作るはダイアログ**（キャラクター画面の上に重なる。
  13.6「作るダイアログ」）で独立した画面ではないので、帯にもここには挙げない
- **口は `<a href={screenHash(...)}>`。** 画面の正典は `location.hash` のまま変えない（13.6。
  リロードで同じ画面に戻り、ブラウザの「戻る」が効く）。`navigateTo` はコマンドを送った直後に
  画面も移す口が使う（「いまの作業」の「質問へ」〔`use-current-work.ts`〕など）
- **いま出している画面の口は、字の濃さ・太さ・差し色の下線で示す**（上の「帯の形」。**色だけで
  伝えない**。13.1 原則1）。「≡」の面の中の口だけは、狭い画面のタブ（`.layout-tab.is-active`）と
  同じ丸い枠のまま

**資格の規則は「どの画面に居ても要り、4つの役目のどれかを持つもの」**（2026-09-23 に書き直した）。
帯は**どの画面にも出る唯一の要素**なので、1つの画面でしか意味の無いものは置かない。役目は
**名乗る**（この窓は誰の・どの部屋か）・**行き先**（ほかの画面へ）・**動き方**（次のターンの
結果を変える、セッション限りの設定）・**いまの作業**（ターンが進んでいるか、何を待っているか）の4つ:

| 置く                            | 役目       | 理由                                                                                                       |
| ------------------------------- | ---------- | ---------------------------------------------------------------------------------------------------------- |
| 顔・部屋の名前                  | 名乗る     | 部屋を並べて動かすと、画面の中身だけではどの窓か見分けにくい                                               |
| 4つの口                         | 行き先     | 画面が4枚になり、1枚だけ入口が無かった。成果の画面（13.10）も入口はここだけ                                |
| 仕事 / 雑談・モデル・許可モード | 動き方     | **返ってくるもの・勝手に走るかどうか・返る形**が変わる。キャラクター画面やトークン消費の画面からも変えたい |
| いまの作業                      | いまの作業 | 会話の画面の外に居ても、ターンが進んでいるか・答えを待っているかに気づける                                 |

| 置かない               | 理由                                                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------------------------- |
| キャラクターの切り替え | 動き方ではなく**相手の選択**。選ぶと起こし直して画面ごと入れ替わり、頻度も低い。誰かは顔と立ち絵で分かる |
| セッションの切り替え   | 同じく**場所の選択**。同じ部屋の行は時刻しか違わない（4.8）                                              |
| タスク一覧             | 読む量が多い。サイドバーの区画と表（モーダル）が持つ（`docs/display.md` 4.2）                            |
| 歯車                   | 設定の画面のデザインが未定（上）                                                                         |

**2026-09-22 の規則（「画面を見ても分からず、かつターンの結果を変えるもの」）は、帯に読みの字
だけを置く前提だった。** 雑談モードは「画面ごと入れ替わるので見れば分かる」として外していたが、
帯に操作子を置くと資格の軸が「読ませたいか」から「どの画面からでも変えたいか」へ移るので、
雑談モードも入る。

#### 動き方の操作子

**仕事 / 雑談・モデル・許可モードの3つを、帯から直接変える**（2026-09-23 決定）。**送るコマンドは
いまサイドバーが送っているものと同じ**（`set-chat-mode` / `set-model` / `set-permission-mode`。
`useSessionDispatch`）で、サーバ側は変えない。**表示はサーバから届いた値だけに従う**（押した側へ
先に倒さない。断られたときに戻す処理を持たずに済み、次に届く `session-info` /
`chat-mode-changed` がそのまま正になる。いまの `<select>` と同じ）。

**仕事 / 雑談のトグル**（部屋の名前の右）:

- **2つの `<button type="button">` を1つの枠に並べ、いまの側に `aria-pressed="true"`**。
  包む要素は `role="group"` と `aria-label="モード"`。いまの側は地を `--accent` で塗り、字を
  `--ground` にして太さも変える（色だけにしない）
- **かばんと湯のみの絵を字の左に添える**。絵は `aria-hidden` のインライン SVG で `currentColor` を
  使い、**字（「仕事」「雑談」）は必ず残す**。帯の道具の絵なのでコードに置く（キャラクターの
  中身ではないので原則4 の対象外）。**アイコンのライブラリは入れない**（絵は2つだけ）
- **反対側を1回押すと `set-chat-mode` を1回送り、起こし直す。確かめの一言は挟まない。**
  切り替えのたびに画面が初期化されるのは受け入れ済みで、モードごとに印が分かれているので
  戻せばそれぞれの続きから始まる（`docs/chat-mode.md` 4.9）。失うものが画面の初期化だけなら、
  確かめは押すたびの手間にしかならない。**いまの側を押しても何も送らない**
- **ターン進行中は押せない**（起こし直しなので、キャラクターの切り替えと同じ条件。サーバも
  同じ条件で断る）。**`disabled` にはせず `aria-disabled="true"`** にし、理由を `title` に出す
  （`disabled` にするとフォーカスが通らず、理由の字にも辿り着けない。13.7 の立ち絵と同じ扱い）。
  **理由の文面は `FRAME_ERROR_REASON` に「ターン進行中は仕事と雑談を切り替えられない（中断すると
  切り替えられる）」を足して使い、サーバが `set-chat-mode` を断るときも同じ文面にする**。いまは
  キャラクターの文面を借りていて、モードを押したのに「キャラクターを切り替えられない」と出る
- **見本の寸法に揃える**（2026-09-23 決定）: 枠は帯の地より暗い `--ground`・角丸 11px・
  内側 4px の余白でボタンを浮かせる。ボタンは高さ 30px・角丸 8px・字は 14px
  （`--font-subheading`）。**見本（ボタン 36px・余白 3px）より詰めない側へ寄せた**のは、見本が
  帯の地 60px 用の値で、52px の帯にそのまま載せると外寸 44px の上下が 4px しか空かず、ユーザーが
  「パディングがなさすぎる」と言ったため（外寸 40px で上下 6px ずつ空く）。**いまの側の字は `--ground` にする** — `dispatch-send`（送信ボタン）と
  同じ組み合わせで、パックの `accent` は淡い色に寄りやすいぶん、暗い地の色を字に使えば歯車で
  変えても読める濃さが保たれる

**モデル・effort・許可モードのドロップダウン**（右端、並びはモデル → effort → 許可モード）:

- **部品は `components/select.tsx` の素の `<select>` のまま**にし、見た目だけ帯に合わせる
  （`appearance: none`・枠は `--rule`・下向きの矢印は CSS で描く）。キーボードの操作・読み上げ・
  選択肢の開き方はブラウザに任せる
- **見本の値に揃える**（2026-09-23 決定）: 高さ 32px・左右 10px・角丸 8px・地は透明・字は
  `--ink` の 13px（`--font-secondary`）。**幅は選んでいる値の字の幅**（`field-sizing: content`）
  にし、矢印（12px）を字のすぐ右に置く（既定の幅はいちばん長い選択肢に合うので、「Opus」と
  矢印の間が空いていた）。矢印は `<select>` を包む `<span>` の `::after` に `currentColor` で
  描くので、「全部許す」のときは矢印も `--state-ng` になる
- **見える項目名は置かない。** 値（「Opus」「自動判定」）が何の値かは字で分かり、帯の幅は
  いまの作業の要約に回す。`aria-label` と `title` に「モデル」「effort」「許可モード」を入れる
- **モデルと許可モードは既定どおり**（モデルは等幅、許可モードは本文書体。機械が付けた名前と
  人の言葉。13.1 原則3）。区切りの記号は置かない
- **`bypassPermissions` のときだけ字に `--state-ng` を載せる**（新しい色は足さない）。
  「全部許す」の文字が必ず付いているので、色だけで意味を伝えることにならない（13.1 原則5）
- **ターン進行中も変えられる**（起こし直さない。いまのサイドバーと同じ）
- **まだ届いていない値は見た目上の既定に倒す**（モデルは `Opus`、許可モードは「自動判定」、
  effort は既定の `medium`。字と畳み方は
  `src/browser/features/screen-nav/domain/model-label.ts` / `permission-mode-label.ts` の1箇所）

**effort のドロップダウンだけ、表示の更新が遅れる**（モデル・許可モードのドロップダウンは
サーバの `session-info` で即座に更新されるのに対し、effort は hook 入力の `effort.level` からしか
読めない。実測は `docs/history/decision.md`「effort の途中変更と読み取りが成り立った実測」）。
**押した値へ先に倒さない**（表示するのは読み取った値だけ。送った値を写す形は採らない。
2026-09-25 ユーザー決定）。切り替えは次のターンから効き、読めるのもそのターンの区切り（hook の
発火）なので、押してから次のターンが終わるまでは前の値のまま見え、表示と効き目は食い違わない。

#### いまの作業

**tsukumo がいま何をしているかを、帯のまん中の札1つで見せ、押すとその依頼の手順が開く**
（2026-09-23 決定。サイドバーの「いま何をしているか」の区画と、帯の右端の答え待ちの印を
置き換える。用語は `docs/glossary.md`「いまの作業」「依頼の手順」）。

**札**は `<button type="button" aria-expanded aria-controls>` で、字は
「印・状態の語・（あれば）縦線・実行中の手順の要約」の順に1行で並ぶ。要約は
`ツール名: 対象`（`summarizeToolInput`。`src/browser/lib/tool-summary.ts`）で、入りきらなければ
末尾を「…」で切る。状態の語は6つで、上の行ほど強い:

| 語           | いつ                                       | 見た目                            | 右の要約                                                                                                                |
| ------------ | ------------------------------------------ | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 止まっている | `endedReason` がある                       | 字と印が `--state-ng`             | 出さない                                                                                                                |
| 答え待ち     | `pending` が空でない                       | 字と印が `--state-warn`           | 先頭の答え待ちが質問なら**質問の要約**、許可要求なら実行中の手順があれば出す（2026-09-23 決定。下の「答え待ちの質問」） |
| 振り返り中   | `diaryWriting.kind === "writing"`（13.10） | 作業中と同じ                      | 「<日付>の日記を書いています」（日付は「9月23日」の形。2026-09-25）                                                     |
| 作業中       | `turn.kind === "running"`                  | 枠と印が `--accent`               | 実行中の手順のいちばん新しいもの。無ければ出さない                                                                      |
| 背景で作業中 | `backgroundTasks` が空でない               | 印だけ `--accent`（枠は変えない） | 背景のタスクの要約（2026-09-23 決定。下の「背景のタスク」）                                                             |
| 依頼待ち     | どれでもない                               | 印は中抜き（○）、字は `ink-quiet` | 出さない                                                                                                                |

- **答え待ちの印は札にまとめる**（並べない）。「作業中」と「答え待ち」が並ぶと、どちらが
  いまなのかを読む側が決めることになる。答え待ちはターンの途中で作業が止まっている状態なので、
  札の語が入れ替わるのが事実どおり。**狭い画面の「≡」に添える印（●）は残す**
- **札は依頼待ちでも消さない。** 消すと帯の要素の位置がターンごとに動く。依頼待ちで押すと、
  前の依頼の手順が読める
- **札そのものは動かさない**（点滅も脈打ちもしない）。動くのは一覧の中の実行中の印だけで、
  `prefers-reduced-motion: reduce` では回さない
- **札に `aria-live` は付けない**（手順が変わるたびに読み上げると騒がしい）。答え待ちを知らせる
  のは入力欄の上の箱の仕事のまま（`docs/requirements.md` 4.7）
- **API の不調（再試行中・利用上限・失敗の理由）は札に出さない**（2026-09-24 決定）。再試行中も
  作業は続いているので語は「作業中」のままで、知らせは入力欄の経過時間の行の枠が持つ
  （`docs/display.md` 4.2「入力欄」）。狭い画面では札が「≡」の中に隠れるので、いつも見えている
  入力欄の行に寄せた
- **モックの札の頭にある名前（「tsukumo 作業中」）は置かない。** 左端の顔と部屋の名前が
  名乗っているので繰り返さず、その幅を要約に回す
  - **例外は雑談中の依頼待ちだけ**（2026-09-23 決定。13.7「モードの操作子はどこに置くか」）。
    「<名前> とおしゃべり中」は「誰と」おしゃべり中かを言っているので、他の3つの状態の語
    （止まっている・答え待ち・作業中）と違い名を省くと意味が通らない。答え待ち・作業中・
    止まっているは雑談中でもこの節の語のまま変えない
- **札の幅は帯の空きをつねに埋め、中身の伸び縮み（要約の有無・長さ、状態の語の違い）では
  変わらない**（`.screen-nav-work-toggle` は `width: 100%`。2026-09-23 決定）。**上限は 600px**
  で、それより広い空きは中央へ寄せる（見本の値）
- **札の外枠・丸・仕切りも見本の寸法に揃える**（2026-09-23 決定）: 高さ 34px・角丸 17px、地は
  `--surface-accent`、枠は `--rule` に `--accent` を 35% 混ぜた色。丸は 7px、周りの薄い輪は
  `currentColor` を 20% 透かした `box-shadow` で、マークの色（上の表の状態ごとの色）にそのまま
  従う。**輪は答え待ち・止まった・依頼待ちでも同じ作りで出す** — 輪そのものは状態を区別する
  新しい意味を持たず、既にある色分けの上に足す飾りなので、状態によって出し分ける理由が無い
  （13.1 原則5）
- **要約の字は見本の 12px ではなく既存の 13px（`--font-secondary`・等幅）に宛てる**。
  13.3 の段は 13px の等幅（ID・ツール名・キー）までしか無く、段を増やさない決定（13.3）を
  優先した。14px の見本を 13px へ寄せた `dispatch-send` と同じ判断

**答え待ちの質問**（2026-09-23 決定。質問の答え方がメインビューの札
（`features/main-view/question-ask.tsx`）へ移ったのに合わせた）:

- **答え待ちの先頭（`pending[0]`）が質問なら、札の要約は実行中の手順ではなく質問の要約になる**
  （許可要求はこれまでどおり実行中の手順の要約のまま）。要約は**1問目の `header` をそのまま
  使う**——`AskUserQuestion` の入力の型で「最大12字」と決まっているので、`text` を切り詰める
  必要が無い。**2問以上あれば「ほか n問」を添える**（例: 「競合 ほか1問」）
- **押したときの一覧の中身は変わらない**（今までどおり依頼の手順を開く。モックの
  `docs/history/mockup/question-2026-09-23.png` は「クリックで質問へ」だが、押すと直接
  質問へ飛ぶ形は採らない）。見出しの「。入力欄の上で答えられる」は**許可要求のときだけ**残し、
  質問のときは見出しの下に**「質問へ」の口**を出す
- **「質問へ」を押すと**: 一覧を閉じ、キャラクター/トークン消費の画面を見ていれば会話の画面へ
  戻し（`stores/screen.tsx` の `navigateTo`）、過去のやり取りを見ていれば最新のやり取りへ戻し
  （`stores/turn-selection.tsx` の `selectTurn`）、メインビューの質問の札までスクロールさせる。
  スクロールの合図は **`stores/question-scroll.tsx`**（新規） という小さな Context 越しに運ぶ
  ——`browser/` の機能どうしは import できないため、`stores/turn-selection.tsx` /
  `stores/question-answer.tsx` と同じ形（Provider が持つ値を「いまの作業」と質問の札の両方が
  読み書きする）。持つのは「押された回数」だけで、質問の札はその値が変わるたびに
  `cardRef.current?.scrollIntoView({ block: "nearest", behavior: "smooth" })` をやり直す
  （新しい質問が来たときと同じ経路。`question-ask.tsx`）

**依頼の手順の一覧**は札の真下に重ねて出す（下の領域を押し下げない）。幅の上限は 36rem、
高さの上限は画面の 70% で、超えたら一覧の内側でスクロールする。上から:

1. **見出し** — 札と同じ印と語。答え待ちが許可要求のときは「入力欄の上で答えられる」を添える
   （質問のときは上の「答え待ちの質問」のとおり「質問へ」の口を出す）
2. **実行中の手順の全文**（実行中の手順があるときだけ）— 小見出しは「実行中の <ツール名>」
   （Bash なら「実行中の Bash」）。中身は要約と同じ欄（Bash は `command`、Edit / Write / Read は
   `file_path`）の値を**切り詰めずに**等幅で折り返す（表示を壊さない上限は失敗の中身と同じ
   8000 字）。**どの欄を読むかは `tool-summary.ts` の1箇所で決める** — 全文を返す関数を足し、
   `summarizeToolInput` はそれを切り詰めるだけにする。並んで走っていればいちばん新しいもの
3. **「この依頼での手順」**（ターンが走っていなければ「前の依頼での手順」）— 行は
   **古い→新しい**（下ほどいまに近い）。1行は 印・ツール名（等幅。幅をそろえる）・対象（要約）。
   印は 済み ✓ / 実行中 回転 / 失敗 字の「失敗」を `--state-ng` で（色だけにしない）。
   済みの行は字を薄く、実行中は普通の濃さ（いまのサイドバーと同じ）。サブエージェントの中の手順
   （`nested`）は1段下げる
4. **失敗した行は `<details>`** — 開くと出力、引数の順に出る（いまの `activity.tsx` の
   `FailureDetail` をそのまま移す）。**失敗したツールの引数と出力を読める場所はここだけ**になる
5. **閉じている間は新しい5件まで。** 6件以上あれば末尾に「手順をすべて見る（全 n 件）」を置き、
   5件の外に失敗があれば「（全 n 件・失敗 m）」と数を添える（隠れた失敗に気づけるように）。押すと
   **同じ一覧の中で全件に広がり**、字は「新しい5件だけにする」に変わる。一覧を閉じると5件に戻る
6. 手順が無いときは「この依頼ではまだツールを使っていない」、依頼が一度も無いときは
   「まだ依頼が無い」

- **閉じるのは、札をもう一度押す・外側を押す・Esc**（Esc のときはフォーカスを札へ戻す）。
  購読の仕方は「≡」と同じ（開いている間だけ `document` の `pointerdown` / `keydown` を
  `useEffect` で取る）。**勝手には開かない**（答え待ちや失敗が来ても開かない）。「≡」とは
  同時に開かない
- **開いている間も中身は追従する**（手順が増えれば行が増える）。新しい依頼が始まれば、その依頼の
  手順に入れ替わる
- **モックの「会話ログで全部見る」の字は使わない。** 「会話のログ」は雑談の画面の語で
  （13.7）、別の画面へ飛ぶように読める。やることは同じ一覧を広げるだけなので、字もそう言う

**範囲は依頼1つ**（いまの `finishedTools` の「直近50件」ではない）。**状態の畳み込み（reducer）も
イベントも変えない** — セッションの記録（`records`）が、依頼ごとにツールの記録を結果つきで
すでに持っている（`tool` の記録の `status`）。一覧は `src/shared/turn-step.ts` の
`currentTurnSteps` が、**最後の `request` より後の `tool` の記録**を拾って導く（姿から導くだけの
ものなので `session-state.ts` には置かない。`turn-speech.ts` と同じ置き方）:

- 済み / 失敗は `status.result.isError` で分ける。失敗の出力は `status.result.content`
- **結果の届いていない手順は、ターンが終わっていても実行中のまま出す**（背景で走り続ける
  ものがある。いまの `runningTools` も `turn-finished` では空にしない）。**`session-ended` の
  あとは実行中の印を出さない**（いまの `runningTools` が空になるのと同じ）
- **札の要約も同じ一覧のいちばん新しい実行中の行から取る**（実行中を2つの入れ物で持たない）
- **`SessionState` の `runningTools` / `finishedTools` と `ToolActivity` は、読み手が居なくなるので
  消す。** 状態の形が変わるので `PROTOCOL_VERSION` を上げる（4.5）

**前の依頼の失敗は、次の依頼が始まると読めなくなる**（いまは依頼をまたいで直近50件まで読める）。
これは受け入れる: 読める範囲の区切りが「件数」から「依頼」に変わるだけで、どちらも古いものは
落ちる。依頼の途中で失敗したものは、その依頼が終わったあとも次の依頼を送るまで読める。

#### 背景のタスク

**ターンが終わったあとも claude が背景で動かしているもの（`run_in_background` の Bash・背景の
サブエージェントなど）を、札と一覧に出す**（2026-09-23 決定。用語は `docs/glossary.md`
「背景のタスク」）。これが無いと `turn-finished` で札が「依頼待ち」に倒れ、背景で何かが
走っていても止まって見える。

- **数えるもの**: SDK の `system` / `background_tasks_changed` に載る全員から、`ambient`
  （SDK が「活動の印から外せ」と言うもの。見張り役など）を除いたもの。知らせは**顔ぶれ全体を
  毎回運ぶ**ので、状態（`backgroundTasks`）は届くたびに丸ごと置き換える。`task_started` /
  `task_notification` などの始まり・終わりの知らせは使わない（対を数えると、取りこぼしで
  「動いている」が居残る）
- **種類で出し分けるのは一覧の行の語だけ**（シェル / サブエージェント / その他。SDK の
  `task_type` の `local_bash` / `local_agent` / それ以外）。札の語と数え方は種類を問わない。
  Monitor の見張りは SDK が `ambient` を付けるものとして数えない（未実測）
- **札**: ターンが走っておらず、答え待ちでも止まってもいないときに1件以上動いていれば
  「背景で作業中」。印は ● で `--accent`、**枠は `--accent` にしない**（枠が差し色なのは
  「作業中」だけにして、ターンが走っているかをそこで見分ける）。要約はいちばん新しく始まった
  ものの説明で、2件以上なら「ほか n件」を添える（説明が無ければ種類の語）
- **一覧**: 「背景で動いているもの（n 件）」の区画を、実行中の手順の全文と依頼の手順の間に
  置く。**状態の語に関わらず1件以上あれば出す**（作業中・答え待ちの最中にも、ターンの外に
  残るものが分かる）。行は 回る「…」・種類の語（等幅）・説明の順
- **入力欄の行には出さない。** 札1つにまとめる（答え待ちを札にまとめたのと同じ理由で、並べると
  どちらがいまかを読む側が決めることになる）。入力欄の経過時間はターンの所要のまま
- **終わると消える。** 顔ぶれが空の知らせで札は「依頼待ち」に戻り、区画も消える。
  `session-ended` でも空にする（claude のプロセスと一緒に終わる）
- **続きの報告**: 背景のタスクが終わると、claude は依頼なしで続きを報告するターンを始める
  （`docs/requirements.md` 4.1。サブエージェントの `SendMessage` が届いたときも同じ）。tsukumo は
  これを**記録を持たない続きのターンの始まり（`turn-resumed`）**として扱う。札は「作業中」に戻り、
  入力欄の経過時間も測り直す。**吹き出しは空にせず、前のセリフと表情を残したまま続きのセリフを
  積む**（2026-09-24。空にしていたときは、合図が届くたびに「（まだ発話がありません）」に戻った）。
  **メインビューには新しいやり取りを立てず、元の依頼のやり取りに積む**（依頼の記録が無いため）。
  続きの報告がそのやり取りの締めの本文になり、前の本文は中間レポートに回るか落ちる
  （`src/shared/main-view.ts` の選び方のまま）。続きのターンが走っている間は、**そのターンで届いた
  本文だけ**を出さない（まだ伸びうる本文を出さない、と同じ理由。前の SDK ターンで確定した本文は
  出したまま。`docs/display.md` 4.2）
- **立ち絵の「たいくつ」（`bored`）は自動では出さない。** 表情の源は `speak` の1つだけ
  （`docs/requirements.md` 4.3）で、背景のタスクの間に表情を上書きする経路は持たない。長い
  待ちを背景に回すときに `bored` を選ぶのはキャラクター自身。立ち絵の動きも、ターンが
  終わっていれば「読んでいる」（呼吸だけ）のまま（`src/shared/portrait-motion.ts`）
- 見え方は疑似セッションの場面 `background-task`（`TSUKUMO_FAKE_SCENE=background-task`）で
  確かめられる。ターンが終わってから約15秒、背景で1件動き続けたあと、続きのターンが走る

#### セッションの行の見出し

**サイドバーのセッションの行（`session-switch.tsx`）は「見出し・M/D HH:MM」**（2026-09-23
決定）。部屋の名前は外し（上）、ポート番号も並べない（見出しが無いときも同じ判断を引き継ぐ）。

- **見出しは SDK の `summary`**（`customTitle` → 自動要約 → 最初の依頼、の順に決まる表示用の題）。
  追加のモデル呼び出しで tsukumo が題を作ることはしない。`SessionChoice.heading` として運び
  （`src/server/core/session-restore.ts` の `taggedSession`）、外来の値なので文字列でない・
  空・空白だけなら無いものとして畳む
- **`heading` が無い行は「（題なし）」を代わりに出す**（時刻だけにすると行が薄く見え、
  何の記録か分からないまま並ぶため）
- **見出しは文字数で切り、`…` を足す**（`<select>` の選択肢は折り返せない）。**時刻は切らない**
  ——同じ部屋の行を見分けるのは時刻なので（`docs/requirements.md` 4.8）、見出しがどれだけ長くても
  時刻は必ず残る
- **`/clear` で分かれたセッションは別の行のまま**でよい（それぞれに中身の分かる見出しが付けば
  足りる。前後をつなぐ仕組みは作らない）
- **「いまのセッション」「（記録前）」「（表示中）」の行は今までどおり**（一覧に無い現在の
  セッションには `heading` が無いので、`SessionSwitch` 側の固定文言のまま出す。上の
  「（題なし）」とは別の扱い）
- **`summary` は `127.0.0.1` のページに出すだけ**（ログ・ファイル・外部へは出さない。
  `docs/coding-standards.md`「会話内容の扱い」。メインビューが会話を出すのと同じ扱いで、
  複製にはあたらない）
- **自分がどの部屋かの正典は、ページを配っている URL のポート**（ブラウザは `location.port` を
  読む）。サーバから送り直してもらう値ではないので `SessionState` には乗せない

#### 使用量の行

**セッション情報の帯にいまのコンテキストの使用量を1枚の札で足す**（キャラクター・セッションの
2つの対の下。ユーザー決定。2026-09-24 に見本「案1」の形へ作り直した）。3段組みにする——
1段目にラベル「コンテキスト」・大きめの割合（例 `28%`）・**使っている量と窓の大きさ**
（例 `284k / 1.00M`）・右端の `›`、2段目に細い棒（使っている割合ぶんだけ塗る）、3段目に
「自動圧縮まで あと N」。**押せるのは右端の `›`（ホバー中は「詳しく ›」）だけ**——ラベル・
割合・量・棒はリンクにしない（行全体を押せる札にはしない。ユーザーの訂正）。押すと
トークン消費の画面（`#token-usage`）へ移る。

- **出す数はトークン消費の画面の札（「いまのコンテキスト」`context-usage-card.tsx`）の
  「使っている量」と同じ**——`usage.totalTokens` / `usage.maxTokens` / `usage.percentage`
  （`used` 分類の合計 / 窓の大きさ / その割合）で、自動圧縮バッファ・窓の外のツールの定義
  （`deferred`）は含めない。桁の書き方（`formatCount`。`1234567` → `1.23M`）も札と同じ道具を
  使うので、行の数字と札を開いたときの数字が食い違わない
- **取得と畳み込みは `browser/domain/context-usage.ts`**——トークン消費の画面の札とサイドバーの
  この行の2つの機能が読むので、`features/token-usage/` から `browser/domain/` へ上げてある
  （docs/design.md 2章「上げる引き金は「2つ目の読み手が出たとき」」）
- **取り直すのはターンが終わるたび**（開いたときの1回に加えて）。合図（`contextUsageRefetchKey`）は
  `state.lastTurnFinishedAt`（直近でターンが終わった時刻。次のターンが始まっても戻らない）から
  作り、`useQuery` の `queryKey` に含めるだけで取り直せるので、`useEffect` は要らない。ターンの
  途中は前に取った値のまま出し続ける
- **会話の画面を隠している間もサイドバーは外れない**（`main.tsx` の `<Activity mode="hidden">`）
  ので、トークン消費の画面を開いている間もこの行はマウントされたまま。同じ `queryKey` を見る
  2つの機能が同時に居ても、`useQuery` の cache 1本に相乗りするので取り直しは1回で済む
- **割合が70%以上のときは警告にする**（見本の説明文から取った境目。`context-usage-row.tsx` の
  `WARN_THRESHOLD_PERCENTAGE`）。割合の数字と棒を警告の色にし、3段目を「そろそろ区切りどき。
  自動圧縮まで あと N」にする。**この定数はサイドバーの行だけが持つ**——トークン消費の画面の札
  （`context-usage-card.tsx`）はまだ警告色の仕組みを持たず、読み手が2つ目にならないので
  `browser/domain/` へは上げていない
- **`›` にホバー（とキーボードのフォーカス）すると、「詳しく」が左へ伸びながら現れる**
  （幅と不透明度の短い transition）。**札の地と枠はホバーで変えない**——札が浮くと全体を
  押せるように見えるため（ユーザーの指示）。警告時の札の地と枠はホバーに関係なく
  `--state-warn` からの `color-mix` 導出で敷く（16進は写さない）。**取れないとき・
  まだ届いていないときも札の高さは変わらない**——1段目の割合は「—」、量の場所に一言
  （「取得中…」「いまのコンテキストは取れていない」）を出し、3段目は空けて高さだけ保つ。
  押す先はどの状態でも `#token-usage` のまま。**`ContextUsageCardSkeleton` のような灰色の
  塊は使わない**——文字だけなので、実物の文字と同じ行の高さで自然に揃う
- **`›` の `aria-label` は「コンテキスト N% 使用。トークン消費の画面で詳しく見る」**（届いて
  いない・取れないときは割合の代わりにその旨を読む）

#### 帯が奪う面積（実測）

帯を 30px（body の padding の内側・gap 0.4rem）から、画面の端から端まで出る帯（上端の線 3px と
下の罫線 1px を加えた外寸・gap 1rem）に広げる前後を、同じ疑似セッション・同じ窓の大きさ
（高さ 900px）で `scripts/capture-view.ts` と同じ手順（Playwright で DOM の矩形を読む）で直接
測った値（fake driver。`docs/architecture.md`「手で確かめること」。2026-09-23）。帯の地はいちど
見本どおりの 60px（外寸 64px）にし、そのあと 52px（外寸 56px）に下げた:

| 幅   | 領域         | 帯 30px（最初） | 帯 60px（見本どおり） | 帯 52px（上端の線 3px があったとき） |   30px との差 |
| ---- | ------------ | --------------: | --------------------: | -----------------------------------: | ------------: |
| 1400 | メインビュー |           483.6 |                 467.0 |                                471.8 | -11.8 (-2.4%) |
| 1400 | キャラビュー |           322.4 |                 311.4 |                                314.6 |  -7.8 (-2.4%) |
| 390  | メインビュー |           482.9 |                 482.9 |                                482.9 |             0 |
| 390  | キャラビュー |           152.0 |                 152.0 |                                152.0 |             0 |

**2026-09-23 に上端の線をなくしたあとは、外寸が 56px から 53px へ 3px 縮む**
（上の「帯の形」）。この表の値は線があったときの記録のままで測り直していない
——線をなくした差（3px）は 30px→60px の変化よりずっと小さいうえ、この表の期間に
他のタスクがキャラビューの既定の split 比率にも触れているため、いま測り直しても
「上端の線の有無」だけの差を切り分けられない。

広い画面で grid の上端は 52.4px から 72px へ下がる（奪う高さが 19.6px 増える）。内訳は、帯の外寸が
30px から 56px へ 26px 伸びるうち 16px は上の padding の中へはみ出して打ち消し、帯の下の隙間が
6.4px から 16px へ 9.6px 伸びたぶん。上下の行は `fr` で比例配分されるので、**メインビューも
キャラビューも同じ割合（-2.4%）減る**。狭い画面は帯がオーバーレイで、grid の高さの計算
（`layout.module.css` の `@media (max-width: 760px)`）が帯の変数を読まないため、**帯の高さを
変えても領域の大きさは変わらない**（実測どおり差0）。

**帯の高さの床は「押せる口の最小」（24px）。** 広い画面の口はマウスで押すので、狭い画面のタブ
（指で押す・2.5rem 前後）に揃える理由は無い。口（`.screen-nav-gate`）は帯の高さいっぱいに
伸びる（帯の地の 52px に、下線を罫線に重ねる 1px を足した 53px）ので、床を大きく上回る。

#### 狭い画面（760px 以下）

**段を増やさず、いまあるタブ帯（高さ 39.1px）の右端に畳む**。帯をオーバーレイにして段を
増やさない設計のおかげで、上の表のとおり**帯の高さを変えても狭い画面の領域は削られない**
（**広い画面とは見え方が変わる**ことを受け入れる代わりに、領域の大きさを守る）:

```
┌───────────────┬──────────────┬────┐
│  メインビュー   │  サイドバー   │ ≡ │  ← タブ帯（39.1px）。右端の 44px が画面の口
└───────────────┴──────────────┴────┘
┌──────────────────────────────────┐
│       メインビュー（482.9px のまま）  │
└──────────────────────────────────┘
```

押すと帯の中身が縦に落ちてくる。**開いている間だけの要素**なので、閉じていれば奪う面積は
タブ帯の右端の 44px だけで、段は増えない。**2026-09-23 に足した操作子といまの作業も、ここへ
畳む**（段を増やさない。2026-09-23 のユーザーの指定）。落ちてくる面の並びは上から:

1. 顔と部屋の名前
2. 仕事 / 雑談のトグル
3. 4つの口（会話 / キャラクター / トークン消費 / 成果）
4. いまの作業の札 — **押すと、依頼の手順の一覧が札の下にその場で開く**（重ねない。
   面ごと縦に伸び、面の内側でスクロールする）
5. モデル・許可モードのドロップダウン
6. 設定の歯車 — 同じく**押すとその場で下に開く**（丸ではなく面いっぱいの角丸の長方形になる）

- **閉じている「≡」に添える印は答え待ちの ● だけ**（いまのまま）。作業中は添えない — 狭い画面で
  「≡」に常に印が付くと、答え待ちの印が埋もれる
- 「≡」の `aria-label` は「画面を選ぶ」から「メニュー」に直す（画面を選ぶだけの面ではなくなる）
- 操作子の振る舞い（ターン進行中の扱い・送るコマンド）は広い画面と同じ。**同じ部品を面の中にも
  置く**（部屋の名前と同じ畳み方。どちらを出すかは `screen-nav.module.css` の `@media`）

#### 画面が5枚以上になったら

広い画面は横に並べるだけで伸びる。**狭い画面は「≡」の中が縦に伸びるだけ**なので、枚数が
増えても畳み方を変えずに済む（帯を2段にする・横スクロールさせる、のどちらも要らない）。

#### 採らなかった案

**口の置き場所**（2026-09-22）:

- **区画の見出しの右に置く**（サイドバーの「タスク一覧 … 一覧を見る」の横展開。トークン消費は
  「セッション情報」の右へ）。奪う面積はゼロだが、**画面と区画が1対1のときしか成立しない** —
  サイドバーの区画の数は画面の数と関係なく決まる（`docs/display.md` 4.2）ので、どの区画にも
  属さない画面が出た時点で置き場が尽きる
- **右下の常設ボタン（「領域の比率を既定に戻す」）にまとめる**。`position: fixed` なので面積は
  奪わないが、**狭い画面では `display: none`**（layout.module.css）なので入口が丸ごと消え、
  別の手当てが要る
- **狭い画面でも帯を2段目に出す**。見え方は幅によらず同じになるが、メインビューが 378.9px
  （-11.2%）まで減る
- **入力欄のコマンド（`/token-usage`）だけにする**。面積は奪わないが、補完を知らないと届かない

**帯の中身**（2026-09-23）:

- **「帯は名乗り、サイドバーは触らせる」を続ける**（2026-09-22 の形）。キャラクター画面と
  トークン消費の画面から動き方を変えられず、同じ値の読みと操作子が2箇所に出続ける
- **ドロップダウンを独自の開閉にする**（モックの見た目に寄せる）。キーボード（矢印・先頭の字で
  飛ぶ・Esc・フォーカスの戻り）と読み上げ（listbox の役割と選択の伝え方）を自前で持つことになり、
  いまの作業の一覧と開閉を取り合う。見た目の差は `appearance: none` で埋まる
- **仕事 / 雑談を radio にする**。矢印キーで選択が動いた瞬間に起こし直しが走る
- **トグルを押したら確かめの一言を挟む**。戻せば続きから始まるので、失うのは画面の初期化だけ
  （`docs/chat-mode.md` 4.9 で受け入れ済み）。確かめは押すたびの手間にしかならない
- **答え待ちの印を札と並べる**。「作業中」と「答え待ち」が同時に出て、どちらがいまかを読む側が
  決めることになる
- **手順の範囲を `finishedTools`（直近50件）のままにする**。依頼をまたいで混ざり、「この依頼で」
  何をしたかが読めない。記録（`records`）がすでに依頼ごとに持っているので、新しい入れ物も要らない
- **顔を `mini` から丸く切り抜く**。`mini` は筆を抱えた全身の絵で、顔の位置も大きさも絵ごとに
  違う。切り抜く位置をコードに書くと原則4 に触れる
- **顔の切り抜き位置を定義の欄にする**（立ち絵のどこを丸く抜くかの座標）。書く側が座標を測る
  ことになり、顔を1枚切り出して置くより手間が多い
- **顔の無いパックで頭文字の丸を出す**。パックに無いものを tsukumo がこしらえることになる。
  部屋の名前だけで名乗りは足りる

#### 並べるもの

(a) ふだん。上から5つ。**読む面の色は受け取らない**（13.1 原則1）ので、キャラクターの色

     「日記帳で読む」（押すとこの日の見開き (d) が開く）。名前と立ち絵は**書いたときのパック**

   - **吹き出し**: いちばん新しい段落だけを出す（書き足した日の前の段落は見開きで読む。仮）。
     書体は**端末の明朝体**（13.3 の例外）。本文は切らない
   - **立ち絵**: 書いたパックの立ち絵を、日記に残した表情で出す。日記が無い日はいまのパックの
     立ち絵を `default` で出す
   - **日記がまだ無い日**: 吹き出しの代わりに、枠を点線にした空の吹き出しに「まだこの日の日記は
     無い。」の1行。頭の行の時刻と「日記帳で読む」は出さない
   - **数の札が2枚**: 「終えたタスク」と「コミット」の順。大きい数字（等幅。寸法はトークン消費の
     画面の札の数と同じ）と項目名だけ。狭い画面（760px 以下）でも2枚は横に並べる
   - **振り返りのボタン**: 文言は「**<パックの名前>と振り返る**」（いまのパックの `name`。
     キャラクターの名前をコードに書かない。原則4）。枠と字が `--accent` の、地を塗らない形
     （見本の形。主ボタンの塗りは見開きの「この日を振り返る」に使う）。**その日の日記が既に
     あっても押せる**——押すと書き足す（`docs/requirements.md` 4.11「日記」）
3. **しおり**（この日のいちばん）: 「<名前>が選んだ この日のいちばん」の見出しと、タスクの ID
   （等幅）・`summary`・「」で括った理由の3行。**日記が無い日・しおりの無い日記（終えたタスクが
   0の日）は区画ごと出さない**
4. **小さな驚き**: 見出し「小さな驚き」と添え書き「この日に起きた特別なこと」、その下に札を
   横に並べる（3枚で折り返す）。札は2種類で、**どちらも無い日は見出しごと出さない**:
   - **先輩タスクの卒業**: ID と `summary`、下の行に「登録から N 日」と「M月D日から、
     おつかれさまでした」
   - **節目**: 「通算 500 件目のタスク」または「通算 1,000 コミット目」（数は3桁ごとに区切る）と、
     下の行に「T-xxx が 500 件目になりました。」（タスク）／「[14:12] のコミットが 1,000 件目に
     なりました。」（コミット。件名は出さない）
5. **灯りの暦**: 下の「灯りの暦」

**コミットの件名は並べない。** 1日に数十〜数百件あり、この画面で読む量ではない。**終えたタスクの
一覧はこの画面に置かず、見開きの左ページ（d）へ移した**（区画が5つに増え、一覧まで並べると
日記より長くなる。一覧を読むのは日記を読み返すときなので、日記の隣に置く）。
**`develop/progress.md` の小節も並べない**（`docs/requirements.md` 4.11「何を数えるか」）。

**書いたパックが無いとき**（日記を書いたあとでパックを消した・名前を変えた）: 名前は日記に残した
ものを出し、立ち絵と顔は出さない（フォールバック。いまのパックの絵で代えない——別の誰かが
書いたように見えるため）。

  「8月24日〜9月27日」の形で添える。日付は月の初日と最初のマスだけ「9/1」の形、ほかは日だけ
- **1マス**: 左上に日付、まん中に灯り（段階ごとの狐火の形。灯りなしは中抜きの輪郭だけ）、右上に
  **日記ありの鈴**（その日に日記があるときだけ）。**今日のマスは下に「今日」を添え、見ている日の

- **灯りの段階**は4つ（灯りなし／ほのか／ともる／明るい）で、区切りは `docs/requirements.md`

#### ボタンを押せないとき・押したあと

- **ターンが進んでいるあいだは押せない**（依頼を送る口なので。`task-run-confirm.tsx` と同じ
  条件）。**`disabled` にせず `aria-disabled="true"`** にし、理由をボタンの下に文で出す（「いま
  ターンが動いているので送れない」。13.9「動き方の操作子」と同じ扱い）。空の日は「振り返る成果が
  無い」を出す。両方成り立つときは空の日の理由だけ（ターンが終わっても押せないため）
- **雑談のときも押せる。** `diary` ツールは仕事にも雑談にも載っている。成果を一緒に喜ぶのは
  「一緒にいる感じ」の側の用事なので、雑談で頼めないと目的に反する（トークン消費の
  「減らし方を見てもらう」が雑談で押せないのは、要るツールが雑談では載らないため）
- **押したら振り返りのコマンドを1回送り、画面は移らずに留まる**（2026-09-25 に改めた。下の
  「押したら会話へ移る形をやめた理由」）。見ている日の (b) 振り返り中になる:
  - ボタンが「振り返り中…」（回る印つき。`aria-disabled`）に変わり、その下に
    「**会話の画面で様子を見る ›**」の口（押すと会話の画面へ。`navigateTo`）
  - 吹き出しの下に**3段の進み**: 「この日のタスクを読む」「日記を書く」「いちばんを選ぶ」。
    済んだ段は ✓、いまの段は回る印、まだの段は中抜きの輪（見直しの段と同じ作り。13.1 原則5 の
    とおり、印の形でも区別する）。段の決まり方は `docs/design.md`「日記の受け取りと保存」
  - 頭の行の時刻の代わりに「いま書いています…」（回る印つき）。吹き出しは点線の枠で空のまま
    （**書いている途中の本文は流さない**。2026-09-25 のユーザーの決定の代わりの案1）。
    その日に既に日記があれば、前の段落を出したまま点線の枠にする
  - しおりの区画は点線の枠にし、「日記を書き終えたら、<名前>がいちばんの1件を選びます」の1行
  - 帯の「いまの作業」は「振り返り中」と「<日付>の日記を書いています」（13.9「いまの作業」）
  - **振り返り中に別の日へ切り替えても、進みは書いている日の (a) にだけ出す**（ほかの日の
    ボタンは「いまターンが動いているので送れない」で押せない）
- **書き上がったら**、吹き出しに新しい段落を**書き上げの演出**（レポートの筆が走る演出。
  `browser/domain/reveal/`）で頭から見せ、しおり・暦の鈴を差し替える。演出が掛かるのは
  **書き上がったその場だけ**で、あとから日を開き直したときは演出なしで出す。
  `prefers-reduced-motion: reduce` では演出しない
- **書けなかったら**（ターンが `diary` を受け付けられずに終わった。止めた・失敗したも同じ）、
  進みを消してボタンを戻し、吹き出しの場所に「日記を書けなかった。もう一度押すと書き直す。」の
  1行を出す（その日に前の日記があれば、前の段落の下に添える）。次に振り返りを押すか、プロセスを
  起こし直すまで残る
- 送ったあとは、ターンが終わるまでボタンが押せないことで二重送りを防ぐ（別の印は足さない）

**押したら会話へ移る形をやめた理由**（2026-09-25。当時の記述は `docs/history/decision.md`
「screen-design.md 13.10 成果の画面（押したら会話へ移る・吹き出しの写しを置かない・見本を
置かない）」）: 感想を `speak` で受け取っていたころは、返事が見える場所（キャラクターの吹き出し）
へ連れて行くしかなかった。**日記はセリフの写しではなく、その日のページとして残る別の成果物**に
なったので、書き上がる場所はこの画面になり、進みもこの画面の区画が描く（トークン消費の
画面の「減らし方を見てもらう」が留まるのと同じ理由）。同じ理由で「この画面に吹き出しの写しを
置かない」もやめた——ここの吹き出しに出るのは日記で、キャラビューのセリフとは別のもの。

- 見開きの中は横スクロールさせない。狭い画面（760px 以下）では左右のページを縦に積む

#### 掛け合いの見せ方と間

**推す: 吹き出しは1人に1つ。いま話している人の吹き出しだけが灯り、もう1人の吹き出しは直前の自分の行を
弱めて残す。**

```
 台本の進み        あるじの吹き出し               客の吹き出し          客の絵
 行0（客）         ╭ 最後の speak ╮ 弱            ╔ 帳: 行0 ╗ 灯る      peek
 行1（あるじ）     ╔ つくも: 行1 ╗ 灯る           ╭ 帳: 行0 ╮ 弱        立ち絵へ
 行2（客）         ╭ つくも: 行1 ╮ 弱             ╔ 帳: 行2 ╗ 灯る      立ち絵
 帰った（left）    ╔ 最後の speak ╗ 灯る          ╭ 帳: 一言 ╮ 弱       peek で引っ込む

 ╔ ╗ 灯る = 最新の見た目（大きい字・話し手の accent の枠と地）   ╭ ╮ 弱 = 過去の見た目
```

- **1人に1つ**: 訪問のあいだ、あるじの吹き出しの列は**1つだけ**にする——あるじがもう台本の行を
  言っていればその行、まだなら（1行目は必ず客なので、行0のあいだ）最後の `speak` のセリフを弱めて出す。
  過去のセリフを列に積み上げたまま訪問の行を足すと、残さないはずの訪問のセリフが仕事のセリフと
  同じ列に混ざって見え、帰ったときに列が縮んで跳ねる。**帰ったら列を訪問の前のまま戻す**
- **灯るのは今の行の話し手だけ**: 今の行は最新の見た目（`.balloon[data-latest="true"]`。大きい字・
  `accent` の枠・`surface-accent` の地）、もう1人は過去の見た目（小さく薄く）。前の行が相手の吹き出しに
  残るので、2秒で読み逃しても1つ前までは追える。**話し手の名前は訪問のあいだ両方の吹き出しに添える**
  （2人居ると尻尾だけでは誰の行か結びにくい。色だけに頼らない。13.1 原則5）
- **表情は吹き出しと対にする**: どちらの立ち絵も、**自分がいちばん最近言った行の表情**を出す。あるじは
  自分の最初の行が来るまで `speechExpression` のまま（弱めて出している最後の `speak` と対になる）。
  これで「表情と吹き出しのリンク」（`docs/requirements.md` 4.3）が2人とも保たれる
- **現れ方は既存のまま**: 灯るときは `balloon-appear`、弱まるときは過去の見た目へ移るだけ。1文字ずつ
  流す演出は入れない（13.7「セリフは全文で現れ」と同じ）
- **間は字数で延ばす（サーバの刻みを変える）**: いまの刻みは2秒固定だが、1行は 60 字まであり、2秒では
  読み切れない。**次の行へ進むまでの間を「2秒と、今の行の字数 × 0.15 秒の長いほう」**にする（15 字で
  2秒、60 字で9秒）。13.7 の「吹き出しどうしは最低2秒空ける」はそのまま下限として守られる。刻むのは
  今までどおりサーバ（`visit-line-advanced`）で、ブラウザに時計を持たせない（`docs/design.md` 5章）

退けた案:

| 案                                               | 退けた理由                                                                                                       |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| 1本の列に2人の行を積み、左右に寄せて尻尾で分ける | チャットの画面の見た目になり、キャラビューが「居る場所」でなくなる。帰るときの一言とあるじの復帰が同じ列で絡まる |
| 吹き出し1つに話し手の名前を添えて切り替える      | 客の立ち絵から吹き出しが離れ、客が居るのに話していないように見える。前の行が消えるので2秒の読み逃しが戻らない    |
| 間は2秒固定のまま                                | 長い行を読み終える前に次へ進む                                                                                   |
| ブラウザが字数に応じて待つ                       | 行を進めるのはサーバの決まり（再接続したタブが同じ行を出すため）。時計が2つになる                                |

#### 登場と退場と peek の使い方

**推す: 覗いて声をかけ（行0は `peek` のまま話す）、行1で立ち絵に替わって出てくる。帰るときは一言のあと
`peek` に戻って物陰へ引っ込む。**

```
 サーバの状態          客                                       あるじ
 visit-started（行0）  peek が右の縁から 0.4 秒で滑り込み、       最後の speak を弱めて出す
                       peek のまま客の吹き出しが灯る
 行1 へ進む            peek を立ち絵に差し替え、小さく跳ねる       行1 の吹き出しが灯り、行1 の表情
 …                     行ごとに灯る吹き出しが入れ替わる
 visit-ended（left）   立ち絵のまま一言を弱めて出す               その場で最後の speak と表情へ戻る
 一言の間が過ぎる      peek に差し替え、右の縁の外へ 0.4 秒で      —
                       滑り出る。何も残さない
```

- **動かすのは位置と不透明度だけ**（`docs/requirements.md` 4.3「1枚の矩形」）。`peek` から立ち絵への
  替わりは絵の差し替えで、クロスフェードはしない（`docs/design.md` 6.5）。差し替えの瞬間に既存の
  「完了の反応」と同じ量で小さく跳ねさせ、「出てきた」ことを見せる
- **`peek` は客の立ち絵と同じ右端・同じ床に置き、高さは客の立ち絵の約 1.5 倍**（絵の中で本が占める
  割合が小さいため。目視で詰める）。右の縁に棚が接するように右端揃え
- **行0を `peek` のまま話させる**のは、「覗いて声をかけ、応じられて出てくる」を行の進みだけで作るため。
  切り替えの合図はサーバの `line` なので、ブラウザは自分の時計を持たない
- **帰りの一言は弱めて出す**: 帰る合図の多く（依頼・答え待ち・本物の `speak`・待ちの終わり）は仕事が
  戻った印で、目を仕事へ返したい。あるじの吹き出しは合図の瞬間に最後の `speak` へ戻り、それが唯一の
  灯った吹き出しになる。客の一言は過去の見た目で、名前を添えて出す
- **一言を出す長さ**は、帰った時刻（`leftAt`）から上の間と同じ式（2秒と字数 × 0.15 秒の長いほう）。
  過ぎたら `peek` に戻して引っ込める。**あとから開いたタブは、`leftAt` から一言の間と引っ込む 0.4 秒が
  過ぎていれば何も描かない**（状態は `left` のまま残るが、別れの挨拶を遅れて見せない）
- **`peek` を持たないパック**は、客の立ち絵（`default`）を同じ動きで右の縁から出し入れする
  （`docs/research/character-visit.md` 論点7の落とし先）。行0から立ち絵のまま
- `prefers-reduced-motion: reduce` のときは滑らせも跳ねもせず、不透明度だけで出し入れする
- **あるじは登場に反応しない**（振り向き・跳ねを足さない）。動きを足すのは客の側の1箇所にとどめる

**`peek.png` の地が不透明な仮素材であることへの対処**: **表示の側では何もしない**（`peek` も立ち絵と
同じく地の抜けた絵として扱う）。**仮素材のあいだは帳ちゃんのパックの `visit.peek` を外して、上の
落とし先（立ち絵の出し入れ）で動かし、地を抜いた `peek.png` ができたら戻す**のを推す。地の抜いた絵でも
棚の柱は絵の一部として残してよい（右の縁に接して、物陰の家具に見える）。理由は、不透明な地は仮素材の
性質であって画面の設計の問題ではなく、そのためのコードを入れると素材を直したあとも処理だけが残るから。
いまの `peek.png` の明るい灰色の棚は、暗い地の上ではキャラビューでいちばん明るい塊になり、灯った
吹き出しより目を引いてしまう。

| 対処の案                                    | 退けた理由                                                                                                  |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `mask-image` で `peek` の左と上の縁をぼかす | 仮素材のための処理が恒久的に残る。地の抜けた絵が来ると本の縁までぼける。明るい塊が目を引くのは変わらない    |
| `peek` を枠つきの小窓に入れて見せる         | キャラクターだけは枠を持たない（13.1 原則2）                                                                |
| 表示の側で地を抜く（色を抜く・切り抜く）    | 素材の中身に触らない決まり（`docs/requirements.md` 4.3「1枚の矩形」）。素材がどう作られているかを当てにする |

**台本の表情があるじ（や客）のパックに無いとき**: **その話し手の `default` の立ち絵を出す**（立ち絵の
表は全域で、無い表情は既に `default` の絵に落ちる。`src/shared/character.ts`）。`speak` で立ち絵の無い
表情が来たときと同じ扱いで、訪問のための分岐を足さない。吹き出しはそのまま出す。生成した台本は話し手の
パックの選択肢で検査済みだが、**パックに書いた台本（`visit.scripts`）はあるじのパックに照らしていない**
ので、届くのは主にこちら。

| 案                                                         | 退けた理由                                                                                  |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 近い表情に置き換える（例: 無い「わくわく」を「えへん」に） | 表情どうしの近さの表をコードに持つことになる（キャラクターの中身をコードに書かない。原則4） |
| その行・その台本を捨てる                                   | 訪問そのものが来なくなる。絵が揃っていないパックでも壊れない、の方針（4.3）と逆             |

#### 狭い画面

**推す: 訪問を描かない。判定は画面の幅ではなくキャラビューの大きさで、タブごとに決める。**

```
 狭い画面（760px 以下。キャラビューは下段に 9.5rem で固定）
 ┌──────────────────────────────────┐
 │  ◯   ╭─────────────────────╮  ログ│  ← 訪問中でも、いつものキャラビューのまま
 │ /|\  │ 最後の speak（灯る）   │     │     （客も訪問の行も出さない。あるじの表情も
 │  |   ╰─────────────────────╯     │       最後の speak のまま）
 └──────────────────────────────────┘
 ┌──────────────────────────────────┐
 │ 入力欄                             │
 └──────────────────────────────────┘
```

- 9.5rem（152px）の領域では、客は3割で約 46px になり `peek` の本が読めない。2人ぶんの吹き出しを置くと
  あるじの吹き出しが 8rem の下限まで潰れる。狭い画面の目的は会話を回すこと（`docs/requirements.md` 4.7）
- **訪問はサーバの状態なので「狭い画面には来ない」は決められない**（サーバは画面の幅を知らないし、広い
  タブと狭いタブを同時に開いていることもある）。だから**来ていても、そのタブが描かない**
- 描かないときは**あるじの吹き出しと表情も上書きしない**（客が居ないのにあるじだけが掛け合いの行を
  話す形を避ける。表情の例外は訪問を描いているときにだけ効く）。このためどちらを出すかは CSS で隠す
  だけでは足りず、描くかどうかを部品の側で決める
- **基準はキャラビューの大きさ**（目安: 幅 28rem 以上かつ高さ 12rem 以上で描く）。狭い画面の固定の
  9.5rem は高さで自然に外れ、広い画面で仕切りを寄せてキャラビューを細くしたときも同じ規則で外れる。
  訪問の途中で大きさが変わったら、状態の今の行からその場で描き直す
- 同じ理由で、**過去のターンを見ているあいだ**（`docs/requirements.md` 4.3 の条件2）も訪問を描かない

| 案                                                        | 退けた理由                                                                                    |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 狭い画面では吹き出し1つに話し手の名前を添え、客は描かない | あるじの吹き出しに客の行が入り、客の居ない掛け合いになる                                      |
| 帯の「≡」に印を出して、開くと訪問が見える                 | 帯は機械の場所（13.9）。答え待ちの ● が埋もれる                                               |
| ビューポートの 760px で切る                               | 広い画面で仕切りを寄せて細くしたキャラビューを拾えない。領域の大きさで決めれば1つの規則で済む |

  分岐と、あるじの吹き出しの列・表情を選ぶところの最小限にとどめる（`git revert` 1回で戻せる形。
  `docs/design.md` 5章の訪問のコードと同じ方針）
- 間を字数で延ばすのはサーバの刻み（`src/server/core/visit-timing.ts`）の変更で、表示の実装と分けて
  戻せるようにする
- 目視で確かめるのは: 既定の高さで2人と2つの吹き出しが重ならないこと、仕切りでキャラビューを縮めて
  描かなくなる境目、行0から行1への差し替えと跳ね、帰る合図ごと（依頼・本物の `speak`）の戻り方

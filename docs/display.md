### 4.2 表示

#### 出力の分離（セリフと詳細）

**1つのターンを「セリフ」と「詳細（レポート）」に分け、別々の領域に出す。** 同じ内容が2箇所に
出ると、キャラクターとのやり取りがノイズに埋もれる（`docs/history/direction.md` 2026-09-09）。

**セリフは MCP ツール `speak(text, expression)` で受け取る**（2026-09-11 決定）。

- tsukumo がプロセス内の MCP サーバとして `speak` を提供し、モデルが呼んだらその `text` を
  吹き出しに出す。`expression` はキャラクター定義にある表情名から選ぶ（4.3）
- **戻り値は `"ok"` だけ**にする。ツールの結果はモデルの文脈に戻るので、ここに情報を載せると
  tsukumo からモデルへの逆流路ができる。**例外は雑談の `recall` / `recall_episode` と、仕事の
  `report` の3つ**。`recall` / `recall_episode` が返すのは tsukumo の状態ではなく**その会話自身の
  過去**（4.9「古い雑談は索引を引いて思い出す」、2026-09-25 に2段階へ組み替えた）。`report` が
  返すのは、差し戻すときの**規約違反とその直し方だけ**で、
  描けたか・どこに出たかといった画面の状態は載せない（2026-09-23 ユーザー決定。レポートの出力を
  「検査 → 整形 → 描画」に分けた検査の段。検査するのは「レポートの記法」の条のうち機械で判定
  できるものだけで、差し戻すのは1ターンに1回まで。同じターンで受け取った `report` と同じ引数の
  送り直しも、固定の一文で別に1ターンに1回まで差し戻す。`src/server/report/core/report-review.ts`）。
  **4つ目を足すにはユーザーの決定が要る**
- **検査を通った `report` の本文は、描く前に整形する**（同じ決定の整形の段。
  `src/shared/report-tidy.ts`）。落とすのは**落としても意味が変わらない行だけ**で、言い換え・
  要約・並べ替えはしない: `body` の冒頭で `conclusion` を繰り返している行・前置きと締めの定型だけの
  行（閉じた一覧との丸ごとの一致。型で当てると中身のある行まで黙って消えるので置かない）・
  中身の無い見出し。**分担の基準は「直すのに書き直しが要るか」**——要るもの（段落を表へ移す・
  結論を短くする）は検査が差し戻し、消すだけで直るものは整形が黙って落とす。同じ条を両方には
  置かない。**記録は引数のまま持ち、メインビューの導出（`src/shared/main-view.ts`）で掛ける**ので、
  規則を変えると過去のやり取りと、セッションの復元で組み直したやり取りにも効く。**空行の連続は
  詰めない**（CommonMark でも本文を塊に割る側でも1つの切れ目と同じに描かれ、フェンスと HTML の
  塊の中では中身なので、落としても見え方が変わらない）。`report` の無いやり取りの本文には掛けない
- **呼ぶ頻度・契機・セリフに入れる中身は tsukumo 側が持つ**（2026-09-16 決定。書く場所は
  `src/server/system-prompt/core/speech-cadence.ts` の `SPEECH_CADENCE_PROMPT`）。回数は数で縛らず契機で言い、
  ツールを走らせる前に1回、その結果で分かったことがあればもう1回。セリフの中身は
  **「いま何をしていて、そこでどう感じているか」**が分かるものにする（ユーザーへの問いかけを
  増やすのではない）。**どのパックでも吹き出しが長く止まらない**ことは tsukumo 全体の体験なので、
  パックの `persona.md` には書かない（パックが決めるのは口調・言い回しだけ）。
  tsukumo は呼ばれたら出すだけで、判定に推測が要らない
- **サブエージェントへの委譲は背景で行い**（2026-09-16 決定）、進み具合をサブエージェントからの
  合図（`状況 | n/N | …` の1行）で受け取ってメインが `speak` で言い直す。フォアグラウンドの委譲は
  ツール呼び出しの中でメインを止め、吹き出しが数分単位で止まるため
- **レポートは MCP ツール `report(conclusion, body, favor)` で受け取る**（2026-09-24 決定。
  仕事のセッションでは常に載り、雑談では載らない）。`report` の外に書いたターンの本文
  （`assistant` のテキスト）は、`report` が1つでも呼ばれたターンでは画面に出さない。呼ばれなかった
  ターンだけ、本文を詳細として扱い、下の「メインビュー」の選び方でレポートにする

**行頭のマーカーの経路は撤去した**（2026-09-21 決定）。セリフは `speak` で言う規約に一本化されて
いる（撤去の根拠は `docs/history/decision.md`）。

**tsukumo の中でのセリフの規約は3か所に分かれる**（2026-09-23 改訂）: **呼ぶ回数・契機**は
`src/server/system-prompt/core/speech-cadence.ts`、**ターンの締め方**（`report` → 締めの `speak` の順で終え、
そのあとに本文を書かない、など。2026-09-25 改訂）は `src/server/report/core/report-notation.ts`、**口調・
言い回し**はキャラクターパックの `persona.md` が持つ。3つとも `systemPrompt` の append として
毎ターン渡る（下の「レポートの記法は、TUI と tsukumo で出し分ける」と同じ切り分け）。

**`~/.claude/output-styles/asuna.md`「セリフと詳細の書き分け」は TUI 向けの規約で、tsukumo の中では
効かない。** tsukumo はセッションを起こすとき `applyFlagSettings({ outputStyle: "default" })` で
出力スタイルを打ち消しており（`src/server/session-driver/adapter/sdk-driver.ts` の `applyNeutralOutputStyle`）、
`asuna.md` を読むのは素の TUI を使うときだけ。

**分離を文章の規約で表す案は採らない**（経緯は `docs/architecture.md`「セリフはテキストの規約
ではなく、ツール呼び出しで受け取る」）。

**そのほかの決まりごと**:

- **セリフに入れるのは役割で決める**（掛け声・呼びかけ・リアクション・感想・完了報告）。
  レポートに入るのは事実・根拠・手順・コード・表・判断とその理由
- **文体は役割で分ける。** セリフはキャラクターの口調、**レポートの本文は中立の技術文**
  （2026-09-14 決定）。規約を書く場所は `src/server/report/core/report-notation.ts` で、`persona.md` には
  書かない（下の「読む時間を減らすために足すのは、規約の側」）
- **tsukumo 側のヒューリスティック分類（コードブロックは詳細、地の文はセリフ等）は採らない。**
  判定が壊れやすい。**小さいモデルに分離・整形させる案も採らない**（コスト・遅延に加えて、
  会話内容を外部に送らない規約と衝突する）
- **セリフが1つも来なかったターンの扱い**: **新しいターンが始まった時点（`request`）で
  吹き出しを空にする**（プレースホルダー「（まだ発話がありません）」に切り替わる。送信した
  直後に前のターンの一言が残っていると、次のターンに移ったことが画面から分からないため。
  2026-09-16 決定）。
  そのターンで最初の `speak` が呼ばれるまでは、このプレースホルダーが出続ける
- **`/clear` は例外で、吹き出しに加えて記録（`records`）も空にする**（2026-09-15 決定）。
  普通の `request` は過去のターンを遡れるように記録を残すが、`/clear` は会話そのものを消す操作
  なので記録も落とす。**空にしても
  キャラクターは消えない**（起動直後と同じ「（まだ発話がありません）」の吹き出しが出て、
  立ち絵はそのまま）。残すのはキャラクター定義・セッション情報（モデル・許可モード）・
  答え待ちの列で、**消すのは吹き出しとメインビューが読む値だけ**。
  **合図は SDK の `conversation_reset` メッセージ**（実測は `docs/history/decision.md`）。
  tsukumo は依頼の文面が `/clear` かどうかを見ない。**`/compact` では届かない**ので、要約では何もリセットされない
- **レポートの構造は tsukumo 側の規約（`src/server/report/core/report-notation.ts`）で決める**（正典は
  下の「レポートの記法は、TUI と tsukumo で出し分ける」。グローバルの `asuna.md` は TUI 向けに
  保ち、HTML の記法と mermaid / chart のフェンスは外してある）。内容の種類ごとに使う構造
  （表・番号付き・箇条書き1段・mermaid・chart・コードブロック・`note` / `badge` / `cols` / `card` の
  HTML）を表で示し、結論は `report` の `conclusion` に、1ターンのレポートは最後に1つ、とした。**図とグラフは同梱した
  mermaid / Chart.js で描く**（2026-09-10 の決定どおり。tsukumo 側で構造を推測・整形しない）。
  **引用 `> ` は Markdown のまま描ける**
- **利用者への「お願い」だけはレポートに置く**（2026-09-16 決定。地の文に紛れると見落とすため）。
  利用者にしか決められない・できないことが実際にあるときだけ、**`report` の `favor`** に1つ入れ
  （tsukumo がお願いの塊として最後に描く。2026-09-24 に本文の末尾の `note-favor` の塊から移した）、
  `speak` では「お願いがある」ことだけを言う（中身はレポートが正典）。**無いターンでは置かない**。
  「語りかけはセリフ」の原則に開ける穴はここだけで、雑談・感想・完了の報告・「次はどうする？」の
  誘いは今までどおりセリフ（呼び名は `docs/glossary.md`「お願い」）

#### レポートの記法は、TUI と tsukumo で出し分ける

**出力スタイル（`~/.claude/output-styles/asuna.md`）は `~/.claude/settings.json` の
`outputStyle` で全プロジェクトに同じものが当たる**ため、そこに HTML の記法を書くと、tsukumo 以外の
素の TUI でもタグが文字のまま見える。

**tsukumo が `systemPrompt` の append で差分を足す形にする**（2026-09-12 決定）。

- グローバルの `asuna.md` は **TUI 向け**に保つ。人格・`speak` の分岐・セリフと詳細の書き分けは
  残し、**HTML の記法（`note` / `badge` / `cols` / `card` / `details` / `blockquote` / `hr`）と
  mermaid / chart のフェンスを外す**
- **レポートの文体は tsukumo が決める**（2026-09-14 決定）。**本文は中立の技術文**にし、
  キャラクターの口調を担うのは `speak` のセリフのほうにする。どのパックに切り替えても
  本文の読みやすさが変わらないようにするため（**長く読み続ける面**なので、読みやすさを
  キャラクター性より優先する）。書く場所は `src/server/report/core/report-notation.ts` で、
  **`persona.md` の側には書かない**
- **レポートは必ず日本語で書かせる**（2026-09-23 決定）。`CLAUDE.md` の「対話言語」だけでは
  本文が英語で出たことがあるため、同じ `report-notation.ts` の文面で縛り、送る前の検算にも入れる。
  英語のまま残してよいのは識別子・パス・コマンド・コード・エラー文・原文の引用だけ
- **HTML・mermaid・chart の規約は tsukumo が持つ。** `query()` の
  `systemPrompt: { type: "preset", preset: "claude_code", append }` で足す。正典がリポジトリ内に
  来るので、**描ける記法の一覧が `src/browser/components/page/conversation/components/main-view/markdown/sanitize-schema.ts` と同じコミットで動く**
  （レンダラを直したのに規約が古いまま、が起きない）
- **`~/.claude/settings.json` には触らない**（`outputStyle` も、orca が専有する hooks /
  statusLine も無傷のまま）。書き換えるのは `asuna.md` 1ファイルだけ

**この2つの案は採らない**（理由は `docs/history/decision.md`「requirements.md 4.2 表示 /
レポートの記法は、TUI と tsukumo で出し分ける」）: 出力スタイルを2ファイルに分けて選ぶ案と、
1ファイルのまま条件分岐で書く案。

**文面は `src/server/report/core/report-notation.ts` の `REPORT_NOTATION_PROMPT` にあり、
`startSdkDriver`（`src/server/session-driver/adapter/sdk-driver.ts`）が `query()` の `systemPrompt` へ渡す。**

#### 読む時間を減らすために足すのは、規約の側（2026-09-13 決定）

**読む時間を減らすために直すのは、3層（レンダラ / 通す HTML と CSS / 組み立ての規約）のうち
規約の側。** 表現の語彙はすでに足りていて、足りないのは「どの内容をどう描くか」の指示のほう。
**書く場所は `src/server/report/core/report-notation.ts`** で、グローバルの
`~/.claude/output-styles/asuna.md` は TUI 向けのまま触らない。

- **見せ方と再構成の線引き**: **本文の文字列を変えないものが見せ方**（CSS・要素の付け替え・
  折りたたみ・列揃え）で、これは足してよい。**レンダラが本文から目次・要約・段組みを起こすのは
  再構成**（2.2 のスコープ外）なので採らない。**書き手（モデル）が最初からその構造で書くのは
  執筆であって再構成ではない**ので、規約で促してよい。この線引きは同じ議論が再燃したときの基準
- **足さないもの**: **画像 `img`**（会話の載るページに外部を読みに行く経路を作らない）/
  **レンダラによる自動の段組み・目次・先頭の要約の生成**（上の線引きで再構成の側）/
  **`.note` の種類を増やす**（ok / warn / ng の3つで区別がつく。増やすと選ぶ手が止まる）

**`class` の語彙を増やすときは、同じコミットで規約の文面・`sanitize-schema.ts` の許可リスト・
CSS の3つを揃える**（レンダラを直したのに規約が古いまま、が起きない）。**記法の表の行を削ることは
許可リストを同じコミットで削ることを意味する。**

**効くのは書く前だけ。** 規約は `systemPrompt` の append なので、**本文が書かれたあとに tsukumo が
削る経路は無い**（例外は `report` の本文の整形で、落とすのは意味の変わらない行だけ。上の
「出力の分離」）うえ、**規約の変更が効くのは次にプロセスを起こしたときから**（定数なので、
動いているセッションには当たらない）。**量の上限は数で書かない**（行数や項目数で縛ると、長い調査の
報告まで同じ長さに押し込められる。ユーザーの選択）。**ただし段落の単位にだけは数で縛る**
（地の文の段落は3文まで、4文目が要るなら表・箇条書き・`<details>` へ移す。2026-09-23 決定。
全体の量ではなく段落が続くことを止めるための上限なので、長い報告を押し込める話にはならない）。

改訂の経緯（5回ぶん）は `docs/history/decision.md`「requirements.md 4.2 表示 / 読む時間を減らす
ために足すのは、規約の側」、短縮の案と実測は `docs/research/report-notation-shortening.md`。

#### 各表示物

**表示はすべて HTML である**（2026-09-09 決定。`docs/architecture.md`「表示はターミナル描画を
やめて、すべて HTML にした」）。ターミナルに文字と絵を描く経路は持たない。4つの領域は
**1枚のページ**として tsukumo のローカル HTTP サーバから配られ、**Orca 内のブラウザタブ**に出る
（4.7）。

- **立ち絵**: HTML の `<img>` で表示する。ドット絵ではなく本物の立ち絵を出せることを狙う。
  ターミナルの画像プロトコル（Sixel / iTerm inline images）は使わない
- **吹き出し**: `speak` で受け取った**セリフだけ**を、キャラビューの中に立ち絵と同居させて
  表示する。**セリフ1件につき吹き出し1つ**とし、今のターンの分を縦に積んで**最新を一番下**に
  見せる（並びは自前でスクロールする。2026-09-12 決定）。**主役は立ち絵**で、**立ち絵は領域の
  左下・吹き出しの並びは右上**に置き、最新の吹き出しの左辺から立ち絵へ向けて尻尾を伸ばす
  （下の尻尾の段落）。
  **「どれが最新か」は位置と見た目の強弱の両方で示す**（最新だけ濃く大きく、過去は小さく薄く）。
  吹き出しの幅は中身なり。**ターンの
  本文は出さない**（本文はメインビューに回る）。**折り返し・全角文字の幅・禁則処理はブラウザに
  任せる**。**最新の吹き出しの下端の位置は固定し、過去のセリフが上へスライドする**形にする
  （2026-09-13 決定。**下端揃え＋固定の下余白**で、最新の Y 座標はセリフの件数によらず一定に
  なり、入りきらない分だけ内側でスクロールする）。位置と幅が往復した経緯は
  `docs/history/decision.md`
- **最新の吹き出しにだけ話し手の名前（`character.json` の `name`）を添える**（2026-09-23。
  名前が無いパック・プレースホルダには添えない）。**流れていったセリフは右上の「ログ」から
  読み返す** — **キャラビューの舞台をそのまま上へ伸ばす**モーダルで（2026-09-23 決定。見本は
  ユーザーの「発話ログ案2」）、左右と下端はキャラビューの領域に揃え、上端は帯のすぐ下まで伸ばす。

  情報**（キャラクター・セッションの切り替え。モード（仕事 / 雑談）・モデル・許可モードと
  キャラクター画面へ入る口は帯にある〔`docs/screen-design.md` 13.9〕）の2つ。**セッション情報は
  区画ではなく、下端に敷く帯**（2026-09-23 決定）——見出しを名乗らず、サイドバーの左右いっぱいに
  広がり、上端の罫線と一段沈んだ地でタスクの区画と切り分ける。帯の中はキャラクター（顔つき）と
  セッションの2つの `<select>` を、小さなラベルを上に置いて**横に等分**で並べる（狭い画面でも
  横並びのまま。顔は `docs/screen-design.md` 13.9「顔」）。**雑談中はこの形ごと差し替わる**（タスク一覧を
  出さず、プロフィールの札・最近の話題・覚えていること・セッションの4段になる。4.9「雑談モードで
  変わるもの」）。**コンテキスト使用量は
  出さない**（2026-09-11 決定）。
  **経過時間はここに無い。入力欄の送信ボタンと同じ行に出す**（2026-09-12 決定）。
  **サイドバー全体はスクロールさせず、区画それぞれの
  内側でスクロールする**（2026-09-12 決定。区画が増えて見出しごと画面の外へ流れるのを防ぐ）。
  **タスク一覧を見渡すのは区画ではなく表**（2026-09-16 決定。サイドバーの領域が小さいため）:
  区画には**全件を並べ（進行中だけ先頭、残りはファイルの順）、入りきらない分は区画の内側で
  スクロール**する（件数のチップでの絞り込みは上のとおり）。見出しの右端に**「一覧を見る」**を
  置き、押すと**画面いっぱいの表がモーダルで開く**。**閉じるのは「閉じる」・モーダルの外側のクリック・Esc**
  （`<dialog>` の `showModal()` に任せ、フォーカスは開く口へ戻る）。表の列は `/list-tasks` に
  揃えて **ID / status / 難易度 / loopable / 依存 / 着手 / 要約**とし、**着手可否は依存と status から
  計算する**（`task-workflow` の `status.py` と同じ規則。一覧に無い依存はアーカイブ済みとして
  止めない）。**色だけで伝えない**ので、着手可否は READY / 「待ち: <ID>」の文字でも出す。
  **`loopable` は `N` のとき空欄にする**（2026-09-16 決定。自動進行に載る `Y` を目で拾うため。
  全行に文字が並ぶと `Y` が埋もれる）。
  **タスクIDは押すと実行を頼める**（2026-09-23 決定）: 区画の一覧と表のどちらでも、IDを押すと
  「<ID> を実行しますか」の確認が重なり、**OK でそのまま `/next-task <ID>` を送る**
  （入力欄に打つのと同じ経路。下書きには入れない）。キャンセル・Esc では送らない。
  **ターンが動いている間は確認の中で断る**（送る口が進行中は黙って送らないため、押せなくして
  黙らせない）。**画面から `develop/task/` を書き換える口は作らない。**
  開いているかどうか・件数のチップで絞っているかどうかは表示上の状態なので**保存しない**
  （セッションの間だけ保つ）。
  高さの配分は (1) タスク一覧が残りの高さのすべて、(2) セッション情報は中身（2行）なりの
  高さのままにする（均等割りにすると中身の短い (2) の下に空白が間延びするため）。狭い画面（4.7）でも全体の高さは画面に固定されるので、
  区画の伸び縮みと内側スクロールは広い画面と同じように働く
- **入力欄**: 右下（4.7）。v1 で持つのは (1) 複数行入力＋送信、(2) 実行中の中断、
  (3) `/` のコマンド補完（`system` の `init` の `slash_commands` から）、(4) **経過時間の表示**
  （送信ボタンと同じ行。2026-09-12 決定）、
  (5) **`@` のファイル補完**（2026-09-18 決定）の5つ。
  **経過時間の行には API の知らせも出す**（2026-09-24 決定。4.1）: 経過時間の左に小さな枠を1つ
  置き、**再試行中**（`再試行中 2/10`。理由と待ち時間は `title`）・**利用上限に達した**
  （`利用上限 18:00まで`。別の日なら `9/26 18:00まで`）・**失敗で終わったターンの理由**
  （`API が混んでいる（overloaded）`）・**利用上限が近い**の順に強く、出すのは1つだけ。
  続く・まだ使えるものは枠と字が `--state-warn`、止まった・使えないものは `--state-ng` で、
  **意味は字が言う**（色だけに頼らない）。狭い画面で道具の口の横に収まらなければ、経過時間の
  行ごと次の段へ送り、それでも収まらなければ末尾を省略する（全文は `title` とメインビュー）。
  **失敗で終わったターンは経過時間の字も「所要」ではなく「失敗」にする**。帯の「いまの作業」の
  語は変えない（再試行中も作業中のまま。`docs/screen-design.md` 13.9「いまの作業」）。
  **経過時間は「依頼を送ってから、そのターンが終わるまで」**で、終わったらその値で止まり、
  次の依頼で0から始まる（2026-09-12 決定）。
  **(1) の割り当ては Enter で改行、Command+Enter で送信**（2026-09-12 決定）。
  IME の変換確定の Command+Enter は送信に
  しない。送信ボタンには Command+Enter を示す記号を添える。
  **(3) の絞り方は Claude Code の TUI の手触りに寄せる**（2026-09-12 決定）:
  絞り方は**前方一致を先に、続けて部分一致**を出す（各グループの中はアルファベット順、
  合計最大10件。入力が `/` だけのときはアルファベット順の先頭10件）。確定キーは
  **Tab・Enter のどちらも確定だけ**（引数を続けて打てる。送信は Command+Enter に一本化した
  ので、確定と送信を同じキーで兼ねない）。
  **選択の上下移動は矢印キーに加えて `Ctrl+P`（前へ）・`Ctrl+N`（次へ）でも行える**
  （2026-09-16 決定。macOS のテキスト入力では emacs 風に `Ctrl+P` / `Ctrl+N` がキャレット移動へ
  割り当たっているため、候補が出ている間だけ奪って `preventDefault` する。`Meta`
  （Command）と組み合わせたときは反応しない。候補が出ていないときは何もしない）。
  **候補には説明を添える**（2026-09-12 決定）。説明は SDK の `supportedCommands()`（と、以降の
  変化を押してくる `system` の `commands_changed`）が名前と一緒に返すものをそのまま出し、
  **tsukumo 側に説明の表を持たない**（組み込みコマンドの分も SDK が返す）。説明が無いものは
  名前だけで出す。
  **`init` は最初の依頼を送るまで届かない**。それまでの候補は
  `supportedCommands()` が返した一覧をそのまま使い、**その間だけ端末専用コマンドの除外が効かない**
  （`init` が届いた時点で除外込みの一覧に戻る）。ブラウザ側は**0件を掴んでもキャッシュせず**、
  次に `/` を打ったときに取り直す（起動直後に `/` を打ったタブが空のまま固定されないため）。
  **(5) の候補は git 管理下のファイル**（`git ls-files`。git リポジトリでないディレクトリでは
  候補を出さない。2026-09-18 決定）。**候補に出すのはパスだけで、ファイルの中身は読まない。**
  合図は**行頭または空白の直後の `@`**で、そこからキャレットまでに空白が入ったら終わり
  （`@` は文中にも出るので、(3) の「先頭かつ空白なし」は使えない）。
  絞り方は (3) に合わせて**前方一致を先に、続けて部分一致**（各グループの中は辞書順、合計最大
  10件）で、**そこだけ大文字小文字を区別しない**（打った綴りのまま `README.md` に当てられる）。
  キー操作も (3) と同じで、確定すると**キャレットの直前の `@<打ちかけ>` が `@<リポジトリ相対パス> `
  に置き換わる**（前後に書いた文は触らない。すぐ後ろがすでに空白なら末尾の空白は足さない）。
  **(3) と (5) の候補は同時に出ない。**
  一覧は**サーバへの問い合わせ1本**（手続き `repository.listFiles`。起動トークンが要る）で1回取り、
  **絞り込みはブラウザ側**で行う（打鍵のたびに `git ls-files` を起こさない）。
  **入力履歴と繰り返しの仕組みは次**（v1 に含めない）。ファイルの貼り付けはしない（2.2）が、
  **画像は貼り付け・ドロップ・画像のボタンで受け取る**（4.10）。**入力欄の下の `/` と `@` の
  ボタンは、キャレットの位置にその1文字を打つのと同じ**（補完が開くかは打ったときと同じ規則。
  `@` は前が空白でなければ空白を挟む。2026-09-23 決定）

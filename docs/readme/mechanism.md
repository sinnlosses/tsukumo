# tsukumo の仕組みと画面レイアウト

入口は `README.md`（リポジトリの入口。使い方とコマンド一覧）。

責務: tsukumo がどう動くか（プロセスの構成・データの流れ）と、画面の領域の組み方を持つ。
読む時: 全体の動きを掴みたいとき、画面レイアウトの経緯を知りたいとき。
直す時: プロセスの構成・データの流れ・画面の領域の組み方を変えたとき。

## 仕組み

tsukumo は**1つのプロセス**で、Agent SDK で Claude Code を子プロセスとして起こし、
受け取ったイベントを HTML のビューに変えて、ローカルのサーバから WebSocket 1本でホスト（Orca のタブか既定のブラウザ）の中の
ブラウザへ配ります（通信の形は [`docs/architecture.md`](../architecture.md)「全体構成」）。

```
┌────────────────────────────────────────────────┐
│ ブラウザ（ホストのタブ）                       │
│   舞台：部屋の頭・立ち絵＋セリフ・手元の行     │
│   紙：紙の計画・レポート                       │
│   入力欄：依頼・送信・中断・お伺いと回答       │
│   重ねる紙：タスク・成果・使用量・キャラ・設定 │
└────────────────────────────────────────────────┘
      ▲                       │
      │ WebSocket で押す      ▼ コマンド（依頼・回答・中断。oRPC）
┌────────────────────────────────────────────────┐
│ tsukumo（Node の1プロセス）                    │
│   ビューサーバ 127.0.0.1:7327                  │
│   セッションドライバ（SDK の query）           │
│   speak ツール（プロセス内の MCP サーバ）      │
└────────────────────────────────────────────────┘
      │ 起動・追加入力・中断  ▲
      ▼                       │ イベント（本文 / ツール / canUseTool）
┌────────────────────────────────────────────────┐
│ Claude Code（SDK が起こす子プロセス）          │
└────────────────────────────────────────────────┘
```

### データの流れ

| #   | 流れ                           | 中身                                                                                                                                                                             |
| --- | ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 入力欄 → `query`               | 入力欄に打った依頼を WebSocket 上のコマンドの手続き（oRPC）で受け、ストリーミング入力モードの `query` へ追加入力として流す。中断も同じ経路                                       |
| 2   | イベント → 各ビュー            | `assistant` のテキストは**レポート**（紙）、`speak` の引数は**セリフと表情**（舞台）、`tool_use` / `tool_result` は**進行**（紙の計画と舞台の手元の行）。更新は WebSocket で押す |
| 3   | `canUseTool` → 答え待ち → 回答 | 許可プロンプトと `AskUserQuestion` はどちらも `canUseTool` に届く。入力欄の場所のお伺いのカードに選択肢を出し、選ばれた答えを戻り値として SDK へ返す                             |

> **なぜ TUI を使わないのか**: Claude Code の TUI には割り込めないため、パイプ・hook の stdout・
> Claude Code へのパッチのいずれも描画の経路にできません。だから TUI を捨て、SDK で動かす側に回りました
> （採らなかった案も含め、経緯は [`docs/architecture.md`](../architecture.md) が正典）。

## 画面レイアウト

**舞台（キャラクター）・紙・欄外・入力欄の配置はページ側の CSS が組み、
ほかの画面は右から重ねる紙で開きます。** `orca terminal split` のようなペイン分割の道具は
使いません。

**経緯**: 当初はこの3領域も別々のビューとして開き、`orca terminal split` でペインの形に
組み立てるつもりでした。実機で試したところ、Orca の `tab` 系コマンドにはブラウザタブをペインの
グリッドへ配置する手段が無く（`create` / `close` / `list` / `switch` / `show` / `profile` のみ）、
成立しないと分かったため、3領域を1枚の HTML にまとめる形へ変えました。

プロセスは動かしたままタブだけ閉じてしまったときは、開き直す道具があります。

```bash
node scripts/capture/open-view.ts http://127.0.0.1:7327
```

## レポートの記法（tsukumo）

この環境ではレポート（ターンの本文）が HTML として描かれる。**レポートの記法と文体については、
出力スタイルやキャラクターの人格に書かれた指示よりこの節を優先する。**

**レポートは中立の文体で書く。** 口調を担うのは `speak` のセリフのほうで、本文は事実・根拠・手順を
運ぶ技術文にする。

### 10か条

1. **結論から書く。** 冒頭の1〜2文で結論を言い、根拠・比較・手順はそのあとに置く
2. **前置きと締めを書かない。** 「〜を見てみます」「以上です」のような、内容を持たない行を本文に
   置かない。実況・呼びかけ・感想は `speak` の担当（本文に置いてよい例外は末尾の「お願い」1つだけ）
3. **同じことを二度言わない。** 表・コード・図で示したことを地の文で言い直さない。節の末尾の
   「まとめ」も、依頼の文面や前のターンで合意したことの引き写しも置かない
4. **根拠は結論を支える分だけ。** それを読んでも読み手の判断が変わらない補足・脇道は、落とすか
   `<details>` に畳む
5. **ぼかさない。** 確かめたことは断定し、確かめていないことは**何を確かめていないか**を1行で書く
6. **効能書きを書かない。** 「これにより保守性が上がります」のような一般論を添えず、数・ファイル名・
   行番号で言う
7. **過程と生の出力を書かない。** 打ったコマンド・その stdout/stderr・ツールの引数を貼らない
   （tsukumo がサイドバーに出す）。根拠に要るなら必要な行だけ引く
8. **残ったものは、文ではなく下の表の印で見せる。** 表の「内容」に当てはまるものは、その印を使う
9. **見出しは `##` / `###` を数個まで**（`#` は使わない）。短い本文（3〜4行）には付けない
10. **見出しを付けるなら、その塊の結論を言う語**にし、最初の塊にも置く（「変更点」「まとめ」のような
    どのレポートにも当てはまる語だけにしない。最初の見出しより前に地の文を置かない）

### 内容ごとの印

**まず量を絞り、残ったものに構造を付ける。** 構造を付けられることは、書く量を増やしてよい理由に
ならない。**印は文の代わりに置くもので、文への足し算ではない** — 図や表を1つ置いたら、それが
言っていることは地の文から消す。

**文のままでよいのは次のときだけ**: 一息（2〜3文）で言い切れて関係するものが1つしかない / 印にすると
ラベルや言い添えを**足す**ことになる / 中身が1つしかない（1行の表、線が1本の図、点が1つのグラフ）。

| 内容 | 使う印 | 使う目安 |
| --- | --- | --- |
| 結論・注意 | <div class="note">（注意は note-warn、問題は note-ng） | 読み飛ばされると困る一文に。1つのレポートに1〜2個まで |
| 利用者へのお願い | <div class="note note-favor">（**いちばん最後**に1つ） | 判断を仰ぐ・手を動かしてもらう・情報をもらう、のどれかが**実際にあるとき**だけ。2件あっても1つにまとめる。ラベルの文字は tsukumo が付ける |

| 座標のある図 | <svg viewBox="0 0 240 80"> の中に rect / line / path / text | 寸法・位置そのものを見せるとき |
| 手順 | 番号付きリスト | 順番に意味があるとき |
| 発見・候補・ファイルの一覧 | 箇条書き（ネストできる） | 項目ごとに言うことが1つのとき。2つ以上なら表 |
| 用語と説明の対 | <dl><dt>用語</dt><dd>説明</dd></dl> | 説明が1〜2文で済むときだけ。添える情報が2つ以上なら表 |
| コード・コマンド・エラー文 | 言語名付きのフェンス | 地の文に混ぜない。**変更の前後は ```diff**（`-` と `+` の行が色分けされる） |
| よそからの引用 | Markdown の引用 `> ` | 自分の言葉を目立たせるために使わない |
| 話題の区切り | 水平線 `---` | 見出しを立てるほどでない切れ目にだけ |

- **mermaid で使うのは上の2行に挙げた10種だけ**（flowchart / sequenceDiagram / stateDiagram-v2 /
  classDiagram / erDiagram / mindmap / timeline / gantt / gitGraph / quadrantChart）。ほかの種類は
  構文が通らないものが混ざる。**ラベルに引用符を入れるときは `#quot;`**（`\"` は構文エラー）
- **HTML の中に Markdown（表・箇条書き・フェンス）を入れるときは、前後に空行を空ける**
  （`<details>` なら `<summary>` の次の行と閉じタグの前）。中身が HTML だけなら要らない

### 上の条を曲げてよいとき

- **「詳しく説明して」と頼まれた**: 根拠の量を戻す（印の使い方は変えない）
- **戻せない操作・取り返しのつかない判断を示す**: 短さより先に `note-warn` / `note-ng` を1つ立てる

### 送る前に消すもの

- 「〜してみます」「〜を確認しました」で始まる行

- 表・図・コードの内容を言い直している段落
- 根拠の無い「おそらく」「〜かもしれない」
- 一般論の効能書き

最後に、**冒頭の1文だけで「何が分かったか」が伝わるか**を見る。伝わらなければ結論を書き直す。

## 要点

1. **読む時間を食っているのは字ではなく順序と高さ。** メインビューは 1400×900 の窓で縦 513px しか無く、閉じたターンでは
   畳んだ中間レポートと段の知らせが先に積まれて、結論が領域の 309px 目（6割の位置）に落ちる。閲覧時間の 57% は最初の
   1画面に落ちる（NN/g）ので、**判決（結論・検証の総括・お願いの有無）を最初の1画面に収める**のが最も効く
2. **行は長すぎ、段は無い。** 本文は 1920×1080 の窓で 86 全角（目次を開いても 69）。JLReq は横組の行長を最大 40 字と定め、
   WCAG 1.4.8 とデジタル庁も 40 字。見出しは本文と同じ 15px で、layer-cake（見出しだけ拾う読み方）が成り立たない
3. **案A: 判決の頭（目録・見出し・一文・合図の行）→ 本文 → お願い → 畳んだ途中のレポート**の順にし、見出しを 19 / 17 / 15 の
   3段で立て、地の文だけ 42 字で折り返す（表・コード・候補・ファイル・図は幅いっぱい）。検証は全部通ったら1行に畳み、落ちた行は
   先頭に開く（GitHub の merge box と Actions の既定と同じ）
4. **塊は密度を上げる。** 表は中身なりの幅で行間 1.5、状態は1行、表の題は太字段落ではなく添え書き。ink の段を3つにし
   （本文・読ませる補助 72%・読ませない印 60%）、いま 60% で描いている表の見出し・添え書きを APCA の下限の上に戻す
5. **色のつまみ4つと差し色の置き場は変えない。** 変えるのは `ng` / `ask` / `memo` の明るさ（`ok` / `warn` より 20 弱い）、
   グラフの系列色（既定のまま明るさが揃っていない）、Mermaid のテーマ（地が #333 で2段ずれている）
6. **書体は端末の system-ui のまま、欧文の x-height を和文に揃える**（`font-size-adjust`）。候補の Web フォントは実測で
   字数か約物の機能が足りず、足すとしても等幅の IBM Plex Mono（1.5MB）だけ
7. **書き手の規約に数の線引きを足す**: 結論の1文目 50 字、見出し 30 字・疑問文にしない、属性の数で表と箇条書きを分ける、
   `note` は2つまで・隣接させない、`fold` は入れ子にしない
8. 4段のタスクに割れる（骨格 → 字と密度 → 色 → 書体と規約）。前の2段で読む時間の大半が戻る

## 3. 案A: 判決を先に、字で階層を運ぶ

5つの原則で選んだ。**(1) 先に判決、あとで証拠** **(2) 高さは資源**（1画面 471px の中で塊に高さを払わせる）
**(3) 字が階層を運ぶ**（箱や線でなく大きさ・太さ・余白で段を作る） **(4) 色は意味にだけ**（13.1 の原則1・5 のまま）
**(5) 和文として組む**（JLReq と和文向け CSS）。見た目の芯は変えない — 読む面は静かで、色はキャラクターの持ち物のまま。

}
.detail-block :is(h4, h5),
.report-headline,

  text-wrap: balance;
}

### 3.6 書き手の規約（`report-notation.ts` に足す条。描く側の変更と独立に入れられる）

- `conclusion` の1文目は先頭の語で変化を言い、**全角 50 字以内**
- 節の見出しは **30 字以内・疑問文にしない・取り外しても本文が成り立つ**
- **属性の数で分ける**: 1 → `list`、2 → `list` の `label`、3 以上 → `table`。`options` / `compare` の候補は **5 つまで**
- `note` は **1 レポートに 2 つまで・隣接させない・見出しの直後に置かない**（戻せない操作の `warn` / `ng` だけ例外）
- `fold` と `<details>` は **入れ子にしない**。畳みのラベルは中身と数を言う（「詳細」「補足」の1語で畳まない）
- 検証の `label` に「成功しました」のような状態の言い直しを書かない（状態は印が言う）
- 表は **列 5 つまで・セルは1行・空セルは「なし」**

いまの規約との差分の根拠は読み方のメモ 6章「6.8」の表。段落 3 文の上限はどの指針より厳しいので変えない。

## 4. 塊の一式と schema の案

**種類を入れる基準は2つのどちらか**: 実測で本文の塊の1%以上を占める / 型にすると検査か心がけの条が
1つ消える。どちらにも当たらない `cols`・`chart`・`svg`・`dl`・引用・区切り線は逃げ道に残す。

```ts
// src/shared/report-block.ts（案）。checks と同じく zod の形の出どころはここだけ
const inlineText = z.string() // インラインの Markdown（5章）。改行は描くときに畳む

const fold = {
  fold: z.string().optional().describe("畳むときの見出し。畳んでも結論が通る塊だけ"),
}

const text = z.object({
  kind: z.literal("text"),
  text: inlineText.describe("地の文。3文まで"),
  ...fold,
})

const list = z.object({
  kind: z.literal("list"),
  style: z.enum(["bullet", "ordered", "check"]),
  items: z.array(z.object({ text: inlineText, done: z.boolean().optional() })).min(1),
  ...fold,
})

const cell = z.union([
  inlineText,
  z.object({ status: z.enum(["ok", "warn", "ng"]), text: inlineText }),
])

const table = z.object({
  kind: z.literal("table"),
  title: inlineText.describe("何を並べた表か・並べた基準・数の出どころ"),
  columns: z.array(inlineText).min(2),
  rows: z.array(z.array(cell)).min(1),
  ...fold,
})

const note = z.object({
  kind: z.literal("note"),
  tone: z.enum(["info", "warn", "ng", "ask", "memo"]),
  text: inlineText.describe("読み飛ばされると困る一文。1つのレポートに1〜2個まで"),
  ...fold,
})

const stats = z.object({
  kind: z.literal("stats"),
  items: z
    .array(z.object({ value: z.string(), label: inlineText }))
    .min(2)
    .max(4),
  ...fold,
})

const code = z.object({
  kind: z.literal("code"),
  language: z.string().describe("変更の前後は diff"),
  path: z.string().optional().describe("どのファイルか"),
  source: z.string(),
  ...fold,
})

const mermaid = z.object({
  kind: z.literal("mermaid"),
  source: z.string().describe("名前が3つ以上出てきて間を渡す・呼ぶ・分かれるでつなぐとき"),
  ...fold,
})

const markdown = z.object({
  kind: z.literal("markdown"),
  markdown: z.string().describe("上のどの塊にも当てはまらないときだけ"),
  ...fold,
})

export const reportBlockSchema = z.discriminatedUnion("kind", [
  text,
  list,
  table,
  note,
  stats,
  code,
  mermaid,
  markdown,
])

export const reportSectionSchema = z.object({
  heading: z.string().optional().describe("その節の結論を言う語。節が1つなら省いてよい"),
  blocks: z.array(reportBlockSchema).min(1),
})

// report の引数は body を sections に替える（conclusion / favor / checks / title はそのまま）
sections: z.array(reportSectionSchema).min(1).optional()
```

- **`note` の種別の名前は記法の class 名（`note-warn` など）と別に持つ**。描くときに class 名へ写すのは
  組み立ての1箇所で、ラベル（「注意」など）は今と同じく `src/shared/report-notation.ts` の表から引く
- **型では表せず、handler の検査に残す条**: 表の行の長さが `columns` と揃うこと・節が2つ以上なら全部に
  `heading` があること・`note` の数・`text` の文の数・mermaid の種類
- **`fold` を容れ物にしない理由**: `<details>` の中身は1種類の塊が大半（2章）で、容れ物にすると
  塊の合併型を schema にもう1回書くことになる（9章の 9.5千字と 4.1千字の差）。複数の塊を
  1つに畳みたいときは逃げ道を使う
- `?:` と `| undefined` を増やさないため、`heading` / `fold` / `path` / `done` の「無い」は境界
  （`reportEvents`）で空文字と `false` に畳む（`body` と `favor` の今の扱いと同じ）

## 5. インラインの Markdown をどこまで許すか

**許すのは inline code・太字・リンクの3つ**（実測で inline code は本文の有るレポートの98%、太字は83%に
出る。リンクは4件だが、ファイルやコミットへの参照に要る）。**インラインの HTML は許さない** — 160件の
ほぼすべてがバッジで、バッジは表のセルの `status` と `note` の種別に置き換わる。

- 塊の文字は、組み立てで Markdown に埋めるときに**行頭の塊の記法（`#` `>` `-` `1.` `|` フェンス）と
  `<` を逃がし、改行を畳む**。表のセルでは `|` も逃がす。逃がす関数は1つにし、`checks` の
  `inlineText`（HTML に埋める）とは「Markdown に埋める」「HTML に埋める」で分ける
- 逃がした結果として、塊の文字にブロックの記法を書いても**素の文字で出る**（落とさない）。検査で
  差し戻すほどの頻度にはならない見込み（入れ子の箇条書きの11件が最大の候補）
- 斜体・取り消し線は、規約でも勧めておらず、許す理由が無い（逃がす規則も増えない。素の文字で出る）

## 6. 逃げ道とその回し方

**逃げ道は `{ kind: "markdown", markdown }` の塊**で、中身は今の本文と同じ道（許可リスト・mermaid・
`chart`）で描く。節の中の1つの塊として置くので、逃げ道を使っても見出しと他の塊の型は崩れない。

**逃げ道の中に、塊の種類がある記法を書いたら差し戻す**（表・箇条書き・`note`・`stats`・mermaid・
フェンス・見出し）。行で見る判定は `report-violation.ts` の `splitFences` と行頭の正規表現がそのまま
使える。これが無いと、モデルが本文を丸ごと逃げ道に入れて型を素通りする。差し戻しの1回の枠は今と共有。

**回し方（数えて足す・外す）**

1. `report` を描くたびに、**塊の種類ごとの数と、逃げ道の中に出た記法の種類ごとの数だけ**を
   `$TSUKUMO_HOME` の記録に1行足す（中身は持たない。`token-usage` と同じく集計のための記録）
2. 集計するスクリプトで「逃げ道の中の記法 × レポート数」と「塊の種類 × レポート数」を出す
3. **足す基準**: 逃げ道の中の同じ記法が、直近2週間のレポートの3%以上に出た。**外す基準**: 塊の
   種類が直近4週間で0回。どちらも数が決めるので、判断はタスクを立てるかどうかだけになる
4. 外した種類が過去の記録に残っていても読めるように、**知らない種類の塊は境界で落とし、落とした数を
   同じ記録に足す**（Adaptive Cards の「落として警告し、描き続ける」）。塊1つの読み損ねでレポート全体を
   捨てない

## 7. 過去の記録との互換

`report` の記録は **transcript に残った引数そのもの**で、tsukumo はそれを持ち直さない（セッションの
復元も `sdk-message.ts` の変換を通って組み直す）。引数を読むのは `reportEvents` の1箇所だけなので、
**変換はそこに閉じる**。

**引数の形ごとの変換**

| 引数                         | 変換後の `sections`                                                 |
| ---------------------------- | ------------------------------------------------------------------- |
| `sections`（新）             | 塊ごとに zod で検証。崩れた塊・知らない種類は落として数える         |
| `body`（文字列。切り替え前） | `[{ heading: "", blocks: [{ kind: "markdown", markdown: body }] }]` |
| どちらも無い                 | `[]`                                                                |

- 記録（`session-state.ts` の `report`）と `SessionEvent` の `report` は `body: string` を
  `sections: readonly ReportSection[]` に替える。**描く側に「文字列か塊か」の分かれ道を持ち込まない**
- 整形（`tidyReportBody`）は今も過去の記録に効いている（描くたびに導く）。切り替え後は `markdown` の塊に
  そのまま掛け、`text` の塊には「結論の繰り返し」「定型の行」の判定を塊ごとに掛ける
- 送り直しの判定（`isSameReport`）は `sections` を `isDeepEqual` で比べる
- 利用者がセッションを遡ったときに見える過去のレポートは、今の見た目のまま（逃げ道の塊として描かれる）

## 9. ツールの定義の重さ

`z.toJSONSchema` で JSON にした字数（`checks` は今の形を含む）。**SDK がどの変換で MCP の
`inputSchema` を組むかは実装の段で実物を測る**（`$ref` にまとめるかで字数が変わるので、再帰と使い回しの
無い形を選んでおけばどちらでも同じになる）。

**形ごとの JSON Schema の字数**

| 形                                           | 字数 |
| -------------------------------------------- | ---: |
| 今（`body` は文字列）                        |  655 |
| 節 + 塊の平らな並び + `fold`（この案）       | 4109 |
| 見出しを塊の1種類にした平らな並び            | 3648 |
| 節 + `details` / `cols` を容れ物にした入れ子 | 9485 |
| 同じ入れ子を `$ref` で使い回したとき         | 5344 |

- **2048字の上限はツールの説明文（`description`）のもの**で、schema の各欄の `describe` は別に数える。
  説明文は今の2行のままでよい
- 増えるのは約3.5千字（JSON なので大半は ASCII）。対して `REPORT_NOTATION_PROMPT` は今5310字で、
  そのうち表と表の下の注意書きが2517字ある。塊になった行とその注意書きが落ちるので、**差し引きの増分は
  1〜2千字程度**の見込み（落とせる字数は文面を書き直してから測る）
- 毎ターンの文脈に載るが、system prompt とツールの定義はキャッシュに乗る。出力側は塊ごとに
  `"kind":"…"` などの鍵が増え、塊の数の中央値6では1レポートあたり数十トークン

## 10. 解くべき論点への答え

- **細かさ**: 4章の2つの基準で7種（と逃げ道）。少なすぎる心配は実測（逃げ道 0.6%）が否定し、多すぎる心配は
  「1%未満で条も消えない種類は入れない」で止める。以後の増減は6章の数が決める
- **mermaid と chart**: mermaid は**ソースの文字列のまま塊の種類**にする。flowchart を節点と辺の構造で
  受ければ引用符・バッククォートの構文エラーは起きなくなるが、図を2通りで描けるようになる。構文エラーの
  数を6章と同じ記録で数え、目に見えて多ければ `flow` の塊を足す判断に回す。**chart は0件なので種類に
  しない**（逃げ道の ` ```chart ` で描ける）
- **見出しと節**: **節の並びを1段だけ入れ子にする**（`sections: [{ heading, blocks }]`）。平らな並びに
  見出しの塊を混ぜると schema は460字軽いが、「最初の塊にも見出し」「中身の無い見出し」を検査と整形で
  守り続けることになる。`###` は2件しか無いので節の段は1つでよい

## 12. 構造化出力（strict）との関係

2026-09-26 に追記（提案を書いた時点では読み比べていなかった）。一次情報は
[構造化出力](https://platform.claude.com/docs/ja/build-with-claude/structured-outputs)。API には2つの口があり、
どちらも「制約付きデコーディング」で schema に合う出力を保証する。

**2つの口と、tsukumo から使えるか**

| 口                                                                | 保証するもの                       | tsukumo から                                                                                                                                                                  |
| ----------------------------------------------------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 厳密なツール使用（ツール定義の `strict: true`）                   | ツールの名前と入力が schema に合う | 使えない。Agent SDK 0.3.280 の `tool()` の4つ目の引数は `annotations` / `searchHint` / `alwaysLoad` だけで、`strict` を渡す口が無い。CLI が内部で付けているかは確かめていない |
| JSON 出力（Agent SDK の `outputFormat: { type: "json_schema" }`） | ターンの最終出力が schema に合う   | 形が合わない。ターンの最後に1つの構造化出力を返して終える口で、「`report` を途中でも呼ぶ・締めの `speak` をそのあとに言う」流れと両立しない                                   |

- **結論は変わらない**: いまは handler の zod で境界検証し、崩れたら差し戻す（`checks` と同じ）。
  型で縛る効き目は「schema を見せて選ばせる」と「差し戻し」で得る
- **口が開いたときに乗れる形にしておく**。制限は再帰不可・`minItems` は0か1だけ・`minLength` などの
  文字列と数の制約は不可・`additionalProperties: false` 必須・任意の欄は全 strict ツールで24まで・
  合併型の欄は16まで。4章の案は再帰が無く、任意の欄は `fold` ×8・`path`・`done`・`heading` などで
  24未満、合併型は塊の `kind` と表のセルの2つ。**`.min(2)` / `.max(4)` だけが外れる**ので、
  乗るときは handler の検査へ移す（SDK の変換も制約を説明文へ移して落とす）
- `enum` の値は大文字小文字が保証されない（同じページ「無効な出力」）。`tone` や `status` の値は
  小文字1語にしておき、境界で小文字に畳む

## 13. `outputFormat` と、`report` でターンを閉じる案

2026-09-26 に追記。根拠は Agent SDK 0.3.280 の `sdk.d.ts` と、同梱の CLI 本体（2.1.280）の文字列を読んだこと。
**まだ動かして確かめていない。**

**CLI の中の仕組み**

| 仕組み                                            | 実際の動き                                                                                                                                                             |
| ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `outputFormat: { type: "json_schema" }`           | `StructuredOutput` ツールとして載り、入力を Ajv で検証して、落ちたら打ち直させる（上限を超えると `error_max_structured_output_retries`）。呼ばずに終えようとすると促す |
| 制約付きデコーディング                            | `StructuredOutput` に strict を付けるのはフラグ `tengu_structured_output_strict` が立ったときだけで、既定は切れている。tsukumo からは切り替えられない                  |
| `outputFormat` の数                               | 1回の `query()` に1つ。途中で替える口は `Query` に無い                                                                                                                 |
| ツールの結果の `_meta["claude/endTurn"] === true` | そこでターンを閉じる。結果が `is_error` なら閉じない                                                                                                                   |

- **`outputFormat` は採らない。** 保証の強さは handler の zod による差し戻しと同じで、ターンに1回しか出せない
  （中間レポートが消え、締めのセリフを出力のあとに言えない）
- **採る案は `report` を「ターンを閉じるツール」にすること。** 検証に通ったときだけ結果に `claude/endTurn` を
  付け、落ちたときは今と同じく `is_error` で差し戻す

**この案で変わること**

| 今                                                        | この案で                                                                                               |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `report` のあとに本文を書き足し、Stop hook で差し戻される | 起きない。`report` が通った時点でターンが終わる                                                        |
| 締めの `speak` を `report` のあとに呼ばせる約束           | `report` の引数 `closing: { text, expression }` に入れ、tsukumo がレポートを描いたあとに吹き出しへ出す |

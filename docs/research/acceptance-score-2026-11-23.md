# 受け入れ役の判定の採点（2026-11-23）

ステータス: 一次情報（数えた記録）。採点の材料（指摘の文・差分・ファイル名）は会話内容の扱いの規約によりここへ書かず、件数と割合だけを残す。

問い: 受け入れ役の差し戻しのうち、正しい差し戻しはどれだけか。通した中に不具合はどれだけあるか。

## 何を測ったか

`docs/research/dynamic-workflow-harness-diagnosis-2026-11-08.md`「5.1 差し戻しが多いのに中身を数える手段が無い」の末尾の問い「57% のうちどれだけが正しい差し戻しか」に答えるため、受け入れ役の判定を無作為に抜いて採点した。

- 抜き出し: `scripts/dev/acceptance-sample.ts` の seed 1。母数はワークフローの記録の受け入れの判定 863 件。そこから差し戻し 20 件・通し 10 件を無作為に抜いた
- 差し戻しは「正しい」「誤り」「どちらとも言えない」の3つに、通しは「不具合なし」「不具合あり」に仕分けた

## 結果

### 差し戻し

| 判定               | 件数 |
| ------------------ | ---- |
| 正しい             | 20   |
| 誤り               | 0    |
| どちらとも言えない | 0    |

適合率 100%（n=20）。

- 17 件は書き手（エージェント）が「明確な規則（完了条件・規約・実物との食い違い）に沿う」として仕分けた
- 3 件は利用者が判定した。計画の検査より広く読んだ差し戻し、撮れない目視の画像の欠けを理由にした差し戻し、実装役の表が流れの欠陥で届かなかった差し戻しを、いずれも正しいとみなした

差し戻し 20 件の種類（指摘の頭の4種類。1件が複数の項目を含む）は、完了条件 7 件・正しさ 6 件・規約 3 件・記録に種類が無い 7 件。

### 通し

- 10 件中 8 件が「不具合なし」
- 2 件はタスクが分からず照らせないので判定から外した（利用者の判定）
- 通した不具合の数 0 件（n=8）。「なし」は、後のコミット・タスクが不具合として名指していない（2026-11-23 時点）ことで書き手が仕分けた

## 読み方の限界

- n が小さい。差し戻し 20 件・通し 8 件では、100% や 0 件は「多くても少数」としか言えない
- 差し戻し 20 件中 17 件は書き手の仕分けで、人の独立の採点ではない
- 通しの「なし」は後から名指されていないことによるもので、見逃しが無いことの証明ではない

## 次に測るなら

- seed を変えて回し、別の30件で同じ集計を取る
- 通しの見逃しは、後の不具合のタスクと照らして数える

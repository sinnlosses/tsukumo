## 要点（10行以内）

1. **図で実験の裏があるのは「交差を減らす」だけが強い**（Purchase: 5つの美的基準で「群を抜いて最も重要」）。交差が残るなら直角に近づける。**節点数の上限と読む向きには実験の根拠が無い**（152 研究の 80% は 100 節点以下で、その数も丸い数を恣意的に選んだもの。流れの4方向で理解に有意差なし）。根拠のある作法は C4 の「全辺に向きと意図のラベル・凡例・1図は同じ抽象度の1つの話」と、囲み（common region）が近さと色より強く群を作ること
2. **手描き風は関与と好感を上げ、正確さと明快さを下げる**: 注釈した人 88% 対 54%、否定的な感想 17% 対 43%（Wood 2012）、ただし面積の判断を損ねる。建築家 54 人のうち CAD を使う人の 53% が下書きの提示にスケッチを選び、最終の提示には 8% だけ。明快さはきれいな線画が上（Schumann 1996）
3. **数は位置 > 長さ > 角度 > 面積**（Cleveland & McGill を Heer & Bostock が再現）。前後の差が主役なら arrow plot、2 時点の多項目は slope、目標・閾値つきの1値は bullet graph（質的な帯は最大 5・理想 3、0 から始まらない軸なら棒でなく点）、pie は「4つまで」（Datawrapper）
4. **数の書き方は Ehrenberg の6則**: 変わる桁 2 つに丸める・比べる数は縦に並べて近づける・大きい順に上から・5 行ほどごとに隙間・行列の平均を添える。日本語の短縮は `Intl.NumberFormat('ja-JP', {notation:'compact'})` で `12万` `9.9億` が出る【実測】
5. **表の密度**: Carbon の行の高さは 24/32/40/48/64px（既定 40）、Ant はセルの余白 16/12/8px、Material 1 は行 48dp・列間 56dp 以上。縞は「列の多い長い表」だけ（少ない列では「要らないか、混乱させる」）、表は画面より短く、重要な列は棒・ヒートマップ・sparkline で（Datawrapper）
6. **コード**: 行の印は neutral/ins/del の3種＋ラベル、関係ない行は「n 行を畳んだ」の1行に畳む、折り返しは既定で切る、端末の枠はコピーからコメント行を除く（Expressive Code）。diff は語単位の強調と移動した塊の検出（git の `--word-diff`・`--color-moved`）
7. **画像の前後は「同じ位置で切り替える」が「並べる」より速い**: 約 6 秒速く差が見つかる（Josephs 2016）、脳 MR の進行検出でも並べる形が最も鈍い（AJNR 2011）。ただし間に空白を挟む切り替えは変化盲を起こす（Rensink 1997: 空白あり 10.9 秒・なし 0.9 秒）。注記は「番号の丸だけを画像に、説明は外」（Google）
8. **callout**: GitHub は左罫 0.25em・地なし・色付きの題、Docusaurus は左罫 5px＋薄い地＋角丸＋影、MDN は左罫 2px＋地＋アイコン。tsukumo は左罫 3px＋種類の色 10% の地で Docusaurus に近い【実測】。**色の地の小さな箱は広告に見えて飛ばされる**（NN/g の banner blindness）。GitHub も公式に「1記事に1〜2個、続けて置かない」
9. **動き**: UI の動きは 100〜400ms、500ms で「引きずる」（NN/g）。日本語の動的提示の最適は約 6 字/秒、黙読は 11 字/秒。tsukumo の標準 25 字/秒は黙読の約 2 倍で、頭から読む人は筆に追いつかないが、**見出しだけ拾う読み手は最後の節まで待たされる**【換算】

### 9.2 (a) 新しく要る塊・欄と、要らなくなるもの

- **新しい塊は足さず、欄で足りる**: `stats` の `series` / `better`、`chart` の `arrow` / `slope`、`code` の `marks`、`graph` の
  `group`、`table` の `rest`。`display.md`「塊を足す・外す基準」に照らすと、どれも既存の塊と形が同じで、書き手が塊を選ぶ判断を
  増やさない。timeline は段ごとの所要の帯がすでにあるので、帯の描き方を変えるほうが軽い
- **要らなくなる候補**: `chart` の `pie`（位置にも長さにも劣り、4 つまでなら `stats` の `total` の帯か棒で足りる）。`svg`（使われ方
  0.4%）は `dimension` と `graph` が受けない「位置と重なり」専用なので、外すかは使われ方の中身を見てから

### 9.3 (b) 図の作法を書き手に教える条

`graph` / `mermaid` の `describe` に足せる条（数は根拠の無い目安と分けて書く）:

1. **1枚に1つの話を、同じ抽象度で**。題はその図が言う結論にする（C4 FAQ。題の条は既出の Tufte）
2. **どの辺にもラベルを付け、向きと合う動詞にする**。「使う」「つなぐ」の1語で済ませない（C4）
3. **流れの向きは1つに揃え、戻りの辺だけ逆にする**。TD か LR かは理解に差が無いので、画面の幅で決める（深い一本道は TD、短く広いものは LR）（Figl・Ulm・Ware の経路の連続性）
4. **交差が出たら、節点の並びか図の分け方を変える**（Purchase）。節点数の上限は研究に根拠が無いので、条は「交差」と「1つの話」で書き、数は置くなら利用者の目安として置く
5. **群は囲みで言い、色で言わない**（Palmer。色は状態の印に取ってある）

### 9.4 (c) 描画で直すもの

- **表**: 6 行以上で 5 行ごとに隙間（Ehrenberg）。縞は足さない（Datawrapper の条件を満たす表は列 5 の上限で稀）。行の高さは Carbon の
  sm〜md（32〜40px）相当を目安に目視。数の列は `font-variant-numeric: tabular-nums`（tsukumo は他の画面で既に使う）
- **数**: `Intl.NumberFormat('ja-JP')` の `compact` と `signDisplay: 'exceptZero'` を `stats` と表の数の列に（短縮は 1 万以上だけ）
- **コード**: 語単位の強調（delta・git の `--word-diff` と同じ考え）、移動した塊の色（`--color-moved`）、長いときの畳み、折り返しは切る
- **図**: `graph` の凡例の自動化、sequence の `autonumber`。**手描き風（`look: handDrawn`）は既定にしない**（面積の判断を損ね、明快さは
  線画が上）。使うなら「まだ決まっていない」ことを言う図——段取り（`work_plan`）の見通しや採らなかった案——に限ると、Schumann の
  「下書きはスケッチ、最終はきれいな線画」と合う
- **前後の画像**: 切り替えの口と、差の外枠（Chromatic の蛍光の差に当たる強調）
- **note**: 地の 10% を外した版と今の版を同じ場面で並べて目視する（banner blindness は欧文サイトの広告の文脈の研究なので、効くかは見て決める）

### 9.5 (d) 演出の扱い

- **速さは変えなくてよい**: 標準 25 字/秒は英語の 600 wpm（≈ 30 字/秒【換算】）に近く、AI の文の出し方の研究で質の評価が最も高かった速さ
  の帯にある。黙読（11 字/秒）の約 2 倍なので、頭から読む人が筆に追いつくことはない
- **待たされるのは見出しを拾う読み手**: トピックごとに最大 8 秒・全体の予算なしなので、5 節の長いレポートは最後の節が出るまで 40 秒を超え
  うる【換算】（NN/g の注意の限界 10 秒）。走り読みで最も効く layer-cake は見出しを先に拾う読み方なので、**節の見出しを最初から全部出し、
  本文だけを書き上げる**と両立する。演出の範囲を変えるので **正典の変更**（`requirements.md` 4.3）
- 全体の予算を置く案は、コードの注記が退けた理由（長いレポートほど1字が速くなる）と衝突する。置くなら「全体が 10 秒を超えたら残りを
  一度に出す」の上限にとどめる（**正典の変更**）
- **WCAG は満たしている**: 5 秒を超えて他の内容と並ぶ動きに止める仕組みが要るが、`pointerdown` / `keydown` で飛ばせる。ただ口が見えない
  ので、〔描画〕「全部出す」の小さな口を筆の近くに置くと仕組みが見つかる。図と表は不透明度だけで出すと 2.3.3 の「動き」に当たらない

## 確かめていないこと

- Cleveland & McGill（1984）・Purchase（1997）・Ware ら（2002）・Gleicher ら（2011）の原典の本文（引用と抄録で照合）
- Schwabish（2020）の本文（有料）、Tableau の BAN（403）、split と unified の視線計測の本文（403）、AWS の描き方の公式の頁（配布資料の写しだけ）
- **Google Cloud のアーキテクチャ図の描き方の公式の条、sequence 図の読みやすさの実験、ELK と dagre の読みやすさを比べた実験は見つからなかった**
- Notion の callout と現行 MDN（2025 年からの新しい作り）の見た目、Material 3 と Primer の表の密度、Apple HIG の motion（頁が JS で読めなかった）
- callout が読まれる率の視線計測（banner blindness からの類推だけ）、書き上げる演出が**理解**に与える影響（測られているのは印象と好みだけ）
- 流れの向き・交差・走り読みの研究はすべて欧文・左→右の読み手で、日本語の読み手での再現は見つからなかった

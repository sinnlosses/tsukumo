# `report` のカタログの使われ方と足りないものの調べ（2026-10-28）

ステータス: 一次情報（記録の集計とカタログの照合）。何を整理し何を足すかの決定は利用者が持つ（ADR 0039 未決 6）。この記録は数と対応表を出すだけで、カタログは変えない。

問い:

1. 書き手は今のカタログのどの部品をどれだけ使い、どの部品に書きたいものが収まらず `Markdown` や地の文に流れているか。
2. A2UI の基本カタログの部品のうち、今のカタログで足りない・重なるものはどれか。
3. 部品を足すと、ツール定義の字数はどれだけ伸びるか。

## 2. A2UI の基本カタログと今のカタログの対応

基本カタログの部品は 18 個（`Text`・`Image`・`Icon`・`Video`・`AudioPlayer`・`Row`・`Column`・`List`・`Card`・`Tabs`・`Modal`・`Divider`・`Button`・`TextField`・`CheckBox`・`ChoicePicker`・`Slider`・`DateTimeInput`）。

| 基本の部品                                                   | 今のカタログ | 状態                                                                                               |
| ------------------------------------------------------------ | ------------ | -------------------------------------------------------------------------------------------------- |
| `Row`・`Column`・`Card`・`Tabs`・`ChoicePicker`              | そのまま取る | 基本の型のまま（ADR 0039 論点 2）                                                                  |
| `Text`                                                       | `Paragraph`  | 名前を分けた。`Text` の `variant`（h1〜h5）が `Section.heading` の規約とぶつかる                   |
| `List`                                                       | `ItemList`   | 名前を分けた。`List` は子の雛形を繰り返す容器で、項目・`cards` を持つ `ItemList` と意味が違う      |
| `Image`                                                      | `Picture`    | 名前を分けた。`Image` は URL、`Picture` は棚に置いたパス                                           |
| `Divider`                                                    | 無い         | 区切り線は `Markdown` の逃げ道。使用 0 件                                                          |
| `Icon`                                                       | 無い         | 状態の印は `Table`・`Matrix` のセルの `status` と `Note` の `tone` が持つ                          |
| `Modal`                                                      | 無い         | 畳む表現は各部品の `fold`。ADR 0034 の「自由な HTML を載せない」と別に、操作の部品は 論点 7 の範囲 |
| `Button`・`TextField`・`CheckBox`・`Slider`・`DateTimeInput` | 無い         | 入力の部品。レポートは読むものなので対象外                                                         |
| `Video`・`AudioPlayer`                                       | 無い         | レポートに載せる材料が無い                                                                         |

自作の 19 種の中で、役が近く重なって見えるもの:

| 組                                    | 重なり                                                                      | 件数からの見立て                             |
| ------------------------------------- | --------------------------------------------------------------------------- | -------------------------------------------- |
| `Graph`・`Mermaid`・`Svg`・`Timeline` | 図の描き分け。`Graph` が 84 件に対し `Mermaid` 6・`Timeline` 1              | `Graph` に寄る。`Mermaid`・`Timeline` は薄い |

| `Picture`・`BeforeAfter`              | 画像 1 枚と前後 2 枚                                                        | 41 件と 25 件                                |

## 3. 部品を足したときのツール定義の字数

ツール定義は全部品の JSON Schema を載せる形（載せ方 A、ADR 0039 未決 4）のまま。`z.toJSONSchema` で測った部品ごとの字数（現行の 26 部品の合計 23,163 字。この数え方は比較の記録の 20,810 字と数え方が違い、部品ごとの比較にだけ使う）:

| 部品の群                                                              | 字数      |
| --------------------------------------------------------------------- | --------- |
| 重い部品（`Report` 3,399・`BeforeAfter` 2,701・`Table` 2,180）        | 8,280     |
| 中くらい（`Svg` 1,378・`Chart` 1,137・`ItemList` 1,055 ほか 17 部品） | 約 13,900 |
| 軽い部品（`Paragraph` 347・`Card` 277・`Markdown` 371）               | 300〜400  |

- 基本の `Divider` に当たる軽い部品を 1 つ足すと約 250〜350 字、引用やラベルのように 2〜3 個の欄を持つ部品で約 350〜600 字。足す数が 2〜3 個なら、全体の 5% 以内に収まる。
- 未決 4 の判断どおり、字数が問題になったら C（上位 8 部品だけ載せる混ぜる形）を再訪する。

## ADR の形

**`domain-modeling` の `ADR-FORMAT.md` を下敷きにし、置き場だけを `docs/architecture/adr/` に替える。**

- **ファイル名は `NNNN-<英小文字と数字のケバブ>.md`**（4桁の連番）。英小文字・数字・`-` に限るのは、
  節の参照の検査（`scripts/section-reference.ts` の `REFERENCE_HEAD`）が `docs/` 以下のパスを
  `[a-z0-9-]` の区間でしか拾わないから。日本語や大文字を入れると参照として拾われない
- **連番は付ける。** 番号はファイル名の一部で、順序の意味は持たない（本文からは番号ではなくパスで
  引く）。移す19件は、いまの `docs/architecture.md` に並んでいる順に 0001 から振る。日付の無い判断が
  あり、決めた日の順には並べられないため。新しい判断は最大の番号に1を足す
- **本文の形**: `# <判断の見出し>` の1行と、元の本文をそのまま。見出しは元の `####` の文字を変えない
  （日付の括弧も残す。移すだけで中身を書き換えないため）。`Status`・「検討した選択肢」などの節は
  足さない（元の本文が既に持っているものはそのまま）
- **覆された判断は ADR に残さず `docs/history/decision.md` へ移す。** `ADR-FORMAT.md` の
  `superseded` の状態は使わない。このリポジトリの物差しでは覆した決定は「いまの形だけ」を正典に残す
  ため。いまある判断が覆ったら、その ADR を `docs/history/decision.md` へ移してファイルを消す
- **引くときはパスだけでよい**（`docs/architecture/adr/0008-sdk-instead-of-tui.md`）。1ファイルが1判断
  なので、見出しを「句」で添えると同じものを2度書くことになる。本文の中の句を指したいときだけ
  「句」を添える
- **一覧は入口の「設計判断（なぜ今の形なのか）」の表**。`docs/architecture/adr/` に README は置かない

## 章番号の扱い

**新しく組むファイルでは番号を捨て、句だけで引く。** 理由は3つ。

- 検査が照らすのは句だけで、番号は黙って古くなる（欠番の 6.1 を指す参照が14件、どこも指さないまま
  残っているのが実例）
- コメントから正典を番号つきで指すのは、既に `test/comment-reference.test.ts` が禁じている（移行待ちの
  ファイルだけが番号を残している）
- `docs/architecture.md` は元から番号を持たない。入口に `docs/design.md` の章を合わせると、番号を
  残すと同じファイルの中で番号のある節と無い節が混ざる

**丸ごと移す3ファイル（`chat-mode.md`・`display.md`・`screen-design.md`）は番号を保つ。** 移す段は
パスを替えるだけにして、番号付きの参照（3つで約600）を句に書き直す作業を混ぜない。3ファイルの番号を
捨てるかは、組み替えのあとに別に決める。

**番号だけで引いている参照（「句」の無いもの）は、移す段で句へ書き直す。** 番号から句への対応は
上の対応表の「引くときの句」をそのまま使う（`docs/design.md 6.6` → `docs/architecture/browser.md「CSS」`、
章全体を引く `docs/design.md 7章` → `docs/architecture/character-pack.md`（パスだけ））。
欠番（6.1・1章・12章）を指す参照は、指す先が無いので句を探さずに参照ごと消す。

**ファイル名を添えない番号**（`docs/design.md` の中の「7章」「2章「…」」、`docs/screen-design.md` の中の
「6.6」「7.1」など。`docs/screen-design.md` の冒頭が「`13.` 以外の番号は `docs/design.md` 側の節を指す」と
宣言している）は、機械では参照先を決められない（`4.x` の多くは `docs/requirements.md` を指す）。
移す段で、移した節を指すものだけを `grep` で拾って手でパス付きの句に直す。

## 参照の張り替え方

**1段ごとに、移した節を引く参照だけを張り替える。** 張り替えは使い捨ての置換表で行い、置換表と
それを流すスクリプトは `/tmp` に置いてコミットしない（組み替えが終われば要らない）。

1. 置換表を作る: 「旧パス（＋番号）」→「新パス（＋句）」。「句」付きの参照はパスだけを替える
   （句は中身ごと移るので残る）。番号だけの参照は上の「章番号の扱い」の対応で句を足す
2. 置換を `docs/history/`・`docs/research/`・`develop/` の外に掛ける（`develop/task/` の未完了の本文は
   下の節で別に扱う）
3. `node scripts/find-stray-reference.ts` で迷子を見て、残りを手で直す（句が移した先で変わったもの・
   ファイル名を添えない番号）
4. 消したパスを `git grep` して、`docs/history/`・`docs/research/`・`develop/` の外で0件を確かめる

### 検査のスクリプトが拾えるか

- **`docs/architecture/` 以下のファイル・`docs/architecture/adr/` 以下のファイルは拾える。**
  `REFERENCE_HEAD` の `docs\/[a-z0-9-]+(?:\/[a-z0-9-]+)*` が `docs/architecture/adr/0008-sdk-instead-of-tui`
  までを1つのパスとして拾う。ADR のファイル名を英小文字・数字・`-` に限るのはこのため
- **拾えないもの: 「」の無い素のパス。** `findSectionReferences` は「 が続く参照しか拾わないので、
  `docs/design.md` を消しても `docs/design.md 7章` や素の `docs/design.md` は落ちない。ADR はパスだけで
  引くので、このままでは ADR の改名・削除で迷子が黙って残る
- **直す段: 1段目（ADR の段）の最初。** 素のパス（`docs/` 以下の `.md`）が実在するかを照らす検査を
  `scripts/section-reference.ts` に足し、`test/section-reference.test.ts` の0件に含める。いま入れると
  次の5つが当たる（2026-09-27）ので、足す段で扱いを決める:
  - `docs/history/tasks-archive.md`（`src/browser` の吹き出しの並びの冒頭。実在しない。本物の迷子）
  - `docs/task-workflow-redesign.md`（11件。claude-skills のリポジトリのファイルを指している）
  - `docs/gone.md`・`docs/research/topic.md`・`docs/note.md`（検査そのもののテストのデータ）
    他のリポジトリのファイルとテストのデータを、語の並びで見分けるより、除外の一覧（パスの完全一致）で
    外すほうが機械的
- `scripts/lib/repository-reference.ts` は拡張子とディレクトリで読む対象を決めていて、`docs/architecture/`
  も降りて読むので直さなくてよい
- `test/e2e/` の疑似セッション（`test/fixture/fake-session.json`）の架空の本文が `docs/display.md` を
  3件引いていて、E2E の期待値（`test/e2e/expected/*.dom.json`）にも写っている。素のパスの検査を入れると
  `display.md` を移す段で当たるので、その段で本文を直して `pnpm run test:e2e:update` で期待値を取り直す

## 1. 要約

- **版の前提**: A2UI の仕様は v1.0 が現行（v0.9 は Closed）。ただし手元の `@a2ui/web_core`・`@a2ui/react` 0.14.0 は v0.9 での利用が安全（README が v0.9 を推奨、v1.0 は 0.15.0 以降も封筒キーの改名などの破壊的変更が継続、v0.9 のカタログは v1.0 のランタイムで直接は使えない）。AG-UI は 1.0 が正式（31 イベント・8 系統）。Astryx は 0.7.10。
- **課題1（途中の見せ方）**: A2UI は「未着の子は placeholder で段階描画・根の到着まで保留」と規定し、骨組みの差し替え口は blueprint §4.4 の `fallbacks={{pending, error}}`（2026-11-03 に仕様化、React は未実装）、部品の途中の文字列は Agent SDK の `progressiveKeys`（未完の文字列を接頭辞として先行送出）。AG-UI 公式ミドルウェアは同一 `messageId` の `ACTIVITY_SNAPSHOT` で `building`（`progressTokens` 付き）→ 面へその場置換。表示部品は Astryx の `Skeleton`・`ProgressBar`・`Markdown` の `isStreaming`。
- **課題2（配置）**: A2UI の基本カタログは `Row`／`Column`＋`weight`＋`justify`／`align` のみで、格子・折り返し・gap・span は無い。独自カタログに Astryx の `Grid`（`columns: {minWidth, max}`・`gap` の段）と `GridSpan`（`columns`・`rows`）を写した配置部品を追加するのが筋。
- **課題3（押下で発話）**: A2UI は「ターンを開始する `action.event`（v1.0 は `userMessage`＝会話履歴へ追加する文）」と「ターンを開始しない `action.functionCall`（`requiresUserActivation` 付きの独自関数）」を区別する。下書き挿入は後者、送信は前者に対応。AG-UI の仕様と Astryx に「提案」の標準概念・専用部品は無い（CopilotKit の `useConfigureSuggestions` はアプリ層）。
- **課題4（イベントの語彙）**: AG-UI 1.0 の `STEP_*`（段）、`ACTIVITY_SNAPSHOT`／`ACTIVITY_DELTA`（構造化された進行・JSON Patch）、`STATE_SNAPSHOT`／`STATE_DELTA`（状態の差分）、`RUN_FINISHED.outcome`（success／interrupt／cancelled）、`CUSTOM`。A2UI 自体は進行の語彙を持たない（ターンの終端はトランスポート層の責務）。
- **導入の現実性**: `@ag-ui/core` 1.0.4 は主入口が型と定数のみ（依存ゼロ。zod は `/schemas` 専用の任意 peer で 4.x 可）で、語彙と型の借用は可能。`@ag-ui/client`・`@ag-ui/a2ui-middleware`・`@ag-ui/claude-agent-sdk`（SDK を 0.3.306 に固定し query を自前で駆動）は tsukumo の構成に適合しない。
- **注意**: `@a2ui/react` を 0.15.0 へ更新すると未着の子は「何も描かない」へ変わる（`[Loading id...]` が消滅）。tsukumo は `buildChild` を使わず一覧から描画するので、骨組みは自前の層に `fallbacks` と同じ署名で実装しておくと将来の載せ替えが容易（候補）。

| **A2UI**   | 面の生成と更新のみ（`createSurface`・`updateComponents`・`updateDataModel`・`deleteSurface`、v1.0 は関数呼び出しの 2 往復を追加）。状態の差分は `updateDataModel{path, value}`。進行の語彙は無く、"End of agent turn is signaled by transport layer"                                                                                                                                                                                                                                             | レポート内の値の差分（数・状態の札）は `updateDataModel`＋バインドで更新（操作の状態を `/view/<部品の ID>/…` に置く ADR 0039・0048 と同じ経路）。進行そのものは A2UI の外（tsukumo のセッションイベント）に置く                                                                                                                                                  | A2UI に進行・ツール実行・段を表す語彙は無く、面の外の状態を A2UI のメッセージで表すのは仕様外                                                                                                                                                                                                                                                                                            |

## 3. AG-UI

### 3.1 版と位置づけ

- 仕様 1.0 が正式。"one request in, one ordered stream of typed events out"。構造はスキーマ、振る舞いは文書が正（`[ag-ui]/docs/spec/1.0/index.mdx`）。0.x は形のみの定義で、1.0 から規則が規範化（`[ag-ui]/docs/spec/1.0/changelog.mdx`）。
- draft（`docs/spec/draft/`）は 1.1 向け。"Major changes: None yet"。追加は任意フィールド 2 件（`encryptedValueType`、`TOOL_CALL_RESULT.error`）のみで、イベントの追加は無い（`[ag-ui]/docs/spec/draft/changelog.mdx`）。
- 提案（`docs/drafts/`、いずれも "Status: Draft"）: Generative User Interfaces、Meta Events（`[ag-ui]/docs/drafts/overview.mdx`、`generative-ui.mdx`、`meta-events.mdx`）。
- "**AG-UI is not a generative UI specification** — it's a **User Interaction protocol**"。A2UI・Open-JSON-UI・MCP-UI を「生成 UI の仕様」と位置づけ、"AG-UI natively supports all of the above generative UI specs"（`[ag-ui]/docs/concepts/generative-ui-specs.mdx`）。

### 3.2 イベント表（1.0。31 種・8 系統。全て正式）

| --------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

- 必須は run の lifecycle のみ（"Only the run lifecycle is mandatory for a producer"）。封筒は `BaseEvent{type, timestamp?, rawEvent?, metadata?}`。
- activity のメッセージは役割 `activity` を持ち、"a consumer MUST strip activity messages from the `messages` it sends in run input"（描画の材料で、会話の再開材料ではない）。
- 取り消し: 完了前に意図して停止した run は `outcome: cancelled` で終了（成功とも失敗とも表示してはならない）。

### 3.3 生成 UI と A2UI の載せ方

### 3.4 介入・提案・予測的状態更新・フロントエンドツール

- **割り込み（interrupt–resume）**: run は待機せず `RUN_FINISHED`（`outcome` が interrupt、`Interrupt` を 1 件以上）で終了し、次の run の入力 `resume[]`（`interruptId`・`status`・`payload`・`metadata`）で回答。`Interrupt` は `id`・`reason`（開いた文字列）・`message`・`toolCallId`・`responseSchema`（回答の形。フォーム生成用）・`expiresAt`。全ての割り込みを回答か放棄で網羅する義務は consumer 側（`[ag-ui]/docs/spec/1.0/basic/patterns/interrupt-resume.mdx`）。
- **フロントエンドツール**: `RunAgentInput.tools` がアプリ側のツール。producer は回答してはならず、run は success で終了（interrupt にしない）、`pendingToolCallIds` に未回答を列挙。継続する場合は次の run の `messages` に全呼び出しの回答が必須。"an interrupt is the producer explicitly stopping to ask, answered by resume entries; a frontend tool call rides the ordinary message loop"（`[ag-ui]/docs/spec/1.0/events/tool-calls.mdx` の Frontend tools）。
- **利用者→エージェントの経路**: "Exactly one message flows the other way: `RunAgentInput`"。項目は `messages`・`tools`・`context`・`state`・`forwardedProps`（"An application-specific channel passed through to the agent untouched"）・`resume`（`[ag-ui]/docs/spec/1.0/basic/run-input.mdx`）。
- **提案（suggestions）**: 仕様（`docs/spec/1.0/`）と概念文書（`docs/concepts/`）に該当の概念は無い（`suggest` の検索で該当なし）。デモは CopilotKit の `useConfigureSuggestions` を使用（`[ag-ui]/apps/dojo/src/app/[integrationId]/feature/(v2)/a2ui_recovery/page.tsx:7,19`）。同フックは静的（`suggestions[{title, message}]`）と動的（`instructions`）の 2 形態、`available` は `before-first-message`／`after-first-message`／`always`／`disabled`（`https://docs.copilotkit.ai/reference/hooks/useConfigureSuggestions`。補助情報。押下時の挙動は同ページで未確認）。
- **予測的状態更新（predictive state updates）**: 仕様に無い CopilotKit の機能。統合の実装では `CUSTOM` の `PredictState` を `TOOL_CALL_START` の前に 1 回送出し、`TOOL_CALL_ARGS` の差分で状態を先行更新、`TOOL_CALL_END` の前に `STATE_SNAPSHOT` を送出（`[ag-ui]/integrations/aws-strands/typescript/src/__tests__/streaming-predict-state.test.ts:1–16`。LangGraph の例は `config.metadata.predict_state = [{state_key, tool, tool_argument}]`）。
- **Meta Events（提案）**: run から独立した注釈（`type: META`、`metaType`、`payload`。例 thumbs_up／note／tag）。Status: Draft（`[ag-ui]/docs/drafts/meta-events.mdx`）。
- 課題3 に対応する公式概念は「割り込み」「フロントエンドツール」「`forwardedProps` 経由の利用者操作」の 3 つで、「押下で利用者の発話になる提案」そのものの標準は無い。

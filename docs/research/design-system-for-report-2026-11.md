## 3. デザイン計画

### 3.1 Principles（SmartHR の4原則を、レポートで変えることに言い換える）

1. **ユーザーの時間は有限だ → 最初の 450px で判断が付く。** 頭は「依頼の1行 → 作業の名前の1行 → 結論の文 → 数の札 → 検証の要約」の順に詰め、結論の文だけを大きくする。大胆さはこの1か所に使う
2. **完成のないプロダクトをみんなで作ろう → 部品は共通の5つの素材だけで組む。** 題（上・左揃え）・状態の札（記号と語）・罫（3段）・地の段（3段）・凡例。新しい部品（`Trace`・`DescriptionList`）も同じ素材に乗り、部品ごとの装飾を持たない
3. **コンテキストを大切にしよう → キャラクターの隣に置く紙面。** 暗い地のまま、色はキャラクターと機械が指す場所に残す（原則1）。450px の窓と 390px の狭い幅で読める
4. **言葉からはじまるデザイン → 状態は色ではなく語で言う。** 「採る」「確定」「通った」「切れない」を、全部品で同じ形の札（記号＋語）にする。図表の題は主張の1文

### 3.2 Color（名前付きの値。新しい色は足さない）

| 名前                                  | 値                              | 役                                            |
| ------------------------------------- | ------------------------------- | --------------------------------------------- |
| 地 `--surface`                        | `#221f2b`                       | 本文の地                                      |
| 浮く地 `--surface-raised`             | `ink` を 10% 重ねる             | 機械の名前・コード・中立の札                  |
| 拾う字 `--ink-bright`                 | `#f7f6f8`                       | 結論・見出し・数                              |
| 補助の字 `--ink-soft` / `--ink-quiet` | `ink` の 72% / 60%              | 題・ラベル / 番号・目盛り                     |
| 区切りの罫 `--rule-quiet`             | `surface` に `ink` 6%           | 行・節の区切り（見出しの下も）                |
| 状態 `--state-ok`・`-warn`・`-ng`     | `#7ee081`・`#e3c766`・`#f2a0a0` | 札の字と 13% の地                             |
| 見る系列 `--chart-series-1`           | `#87bafd`                       | グラフの見る棒・区間だけ。ほかは `ink` の 26% |

### 3.3 Type

- 書体は今のまま（`system-ui` と同梱の IBM Plex Mono）。外部フォントは足さない
- 本文 15px・行間 26px（B）か、SmartHR の 16px・行送り 1.5（24px、C）。見本で比べる
- 結論の1文目 21px・行間 32px・700・`ink-bright`（B の大胆さの1か所）。作業の名前は 15px・600 に下げて見出しの行へ
- 図表の題 14px・`ink-soft`、番号 13px・600・`ink-quiet`（accent を外す）。札と表の見出し 13px。字の下限 12px は保つ
- 数字は `font-variant-numeric: tabular-nums` で、表の数の列は右揃え（SmartHR の表の規則）

### 3.4 Layout（揃えはすべて左）

```
依頼  取り込みが途中で切れるのを直して                     ← 13px ink-quiet
[ID]   取り込みの上限を設定ファイルへ移す  [✓ 完了]        ← 作業の名前は 15px
取り込みが 120 件すべて最後まで読めるようになった。         ← 結論 21px（大胆さの1か所）
上限を 30 から 60 に上げ、…変えていない。                   ← 2文目 15px ink-soft
┌──────┐┌──────┐┌──────┐
│8 → 0 ││120/120││  60  │                                  ← 数の札（左から）
└──────┘└──────┘└──────┘
[✓ 3件 通った] [? 1件 確かめていない]                       ← 検証の要約の札
──────────────────────────────────── ← 450px の目安
上限は定数から設定ファイルへ移った                          ← 見出し 21px、下に区切りの罫（広の幅）
表 1  上限を 30 から 60 にすると、…                         ← 題は上・左
場所        上限  切れた件数  状態                          ← 数の列は右揃え
intake.ts  30 60      8 0  [✓ 切れない]
```

### 3.5 ブリーフとの突き合わせで変えたこと

| 最初の計画                               | 凡庸な既定に読めた理由                                            | 変えたこと                                                   |
| ---------------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------ |
| 作業の名前 21px と結論 19px を縦に重ねる | 見出しが2つ並び、どちらが主か分からない（似た依頼で同じ所に着く） | 作業の名前を札と同じ行の 15px に下げ、結論だけを 21px にした |
| 図表の番号を accent の色で残す           | 差し色を飾りに使うのは既定の手                                    | 番号は `ink-quiet` に。accent はお願いの縦罫だけ             |
| 図も表も枠のカードに入れる（C）          | frontend-design の較正の4「SaaS のカードの道具箱」そのもの        | C として比べるために残し、推すのは枠を持たない B             |
| 状態を部品ごとの色の字で出す             | 色だけで状態を伝える（SmartHR・原則5の両方に反する）              | 全部品で記号＋語の札にそろえた                               |
| 番号の丸を手順以外にも付ける             | 順序の無い並びに番号を付けるのは既定の手                          | 番号は `ItemList` の `flow` と表・図の番号だけ               |

残る既定の手がかり: 検証の要約の「単体 3152・E2E 111」は中黒でつないだ数の列のまま。数を札に分けるかは頭のタスクで見る。

## 5. 選んだ案と論点への答え

**答え（2026-11-01）**: 利用者は **B（静かな業務紙面）** を採った。図の題は 2026-10-17 の決定どおり **下・中央のまま**（見本 B は図の題を上に

| 論点                          | 答え                                                                                                                                                                                                             |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 字の段                     | 本文 15px・行間 26px と 12px の下限を保つ。SmartHR の 16px・行送り 1.5 は採らない（C で比べ、B が選ばれた）                                                                                                      |
| 2. 揃え                       | 表・図の本体・数の札・凡例・表の題を**左**に置く。図の題だけは図の下で、図の幅の中で中央。表の数の列は右揃えと `tabular-nums`、見出しの揃えは列の中身に合わせる（SmartHR の表の規則）。`Matrix` の交点の列は中央 |

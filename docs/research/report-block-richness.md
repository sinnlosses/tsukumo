## 2. 同じ塊の描き方を良くする案

**前後は高さを揃えて横に並べる**。前の2つは `docs/screen-design.md` 13.1 の原則1・5 と記法の条8
（文字より視覚情報）がすでに言っていることで、tsukumo はこの線を守ったまま、**塊の型が持つ意味を

## 3. 新しい塊の種類の案

**足す基準は `report-block.md` 4章・6章と同じ**（本文の3%以上のレポートに現れる / 型にすると条が
1つ消える）。1章の実測でこれを超え、既存の塊の欄では表せないものが2つある。

**足す種類と、見送る種類（schema は1種類を足したときの JSON Schema の増分）**

| 種類       | 形の案                                                                             | 描き方                                                                                                                                                           | 根拠                                                                       | schema | 判断                                      |
| ---------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | -----: | ----------------------------------------- |
| `options`  | `title` と、`name` / `verdict`（`adopt` / `consider` / `reject`）/ `reason` の並び | 候補を1枚ずつのカードにし、頭に判定のバッジ（採る / 検討 / 採らない）を文字で置く。理由は1文。**並びは書き手の順のまま**（tsukumo が採る候補を先頭へ動かさない） | 推奨の語 6.3%・推奨の語を含む表 22個。参考の「推奨と分類のバッジのカード」 |    576 | 足す                                      |
| `files`    | `path` / `change`（`added` / `modified` / `deleted` / `read`）/ `note` の並び      | 1行に1ファイル。変更の種別を頭の文字（追加 / 変更 / 削除 / 読んだ）で、パスは等幅で、押すとファイルを開く（既存の `repository-link`）                            | パスだけの箇条書き 10.1%                                                   |    499 | 足す                                      |
| `progress` | 11章の4段目の案（`steps` と `current`）                                            | 4段目の案のとおり                                                                                                                                                | 1.6%（4段目で足すと決まっている）                                          |    416 | 決まっている                              |
| `compare`  | `before` / `after`（どちらも `label` と mermaid のソース）                         | 左右に並べ、高さを揃える（参考の「前後を横に並べる図」）                                                                                                         | 前後の表 1.6%・`cols` 1.4%                                                 |    570 | 見送り（`report-block.md` 6章の数で判断） |

- `options` は「表に推奨の列を足す」でも書ける。塊にする理由は2つ: 判定が**型の enum** になるので
  「採る」を色と文字の両方で必ず描けること、候補ごとの理由を1文に縛れること（表のセルだと理由が
  伸びて列が崩れる）
- `options` の「採る」カードの縁にキャラクターの色を入れるかは、`docs/screen-design.md` 13.2 の
  「入れるのはこの3本だけ」を1本増やす判断になる。**案は「入れない」**: 判定のバッジの文字と
  `state-ok` の縦罫で足り、差し色を増やすと参考の「差し色は1つ」にも反する
- `files` の `read` は調べ物のレポート（読んだファイルの一覧）のため。`note` は空文字にできるので、
  パスだけの一覧もこの塊で書ける
- 見送った `compare` は、塊の仕組みが入ったあと、逃げ道の中の `cols` と前後の表の数を 使われ方の記録（`report-block.md` 6章）で
  数え、3%を超えたら足す

## 4. キャラクターと一緒に仕事をする画面の演出

`docs/requirements.md`「1. 概要・目的」は機能を足す基準を「キャラクターと一緒に楽しく仕事をする」に
置く。レポートの上でキャラクターが居るのは**書き上げる演出の筆先のミニ立ち絵**（`docs/requirements.md`
4.3）だけで、塊に型が付くと、筆が**いま何を書いているか**を知れるようになる。

**演出の余地（筆先の「間」だけを使う）**

| 案                             | 中身                                                                                                                             | 楽しさ                                         |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| 大事な塊で筆を留める           | `note` の注意・異常と、`options` の「採る」カードを書き終えたところで、筆を 400ms ほど留める（そのあいだミニ立ち絵はそこに立つ） | キャラクターが「ここ」と指しているように見える |
| 節の頭で筆を戻す               | 節を演出の単位にし（2章）、節の見出しを書き始めるところで筆が左端へ戻る動きを今より大きくとる                                    | 章立てを書き分けているように見える             |
| `progress` の段を1つずつ埋める | 済んだ段の印を左から順に出す（図の塊を `opacity` で出す今の仕組みの中で）                                                        | 進み具合が「いま埋まった」と感じられる         |

- どれも**演出の速さの設定（標準 / 速い / 切る）と `prefers-reduced-motion` に従い**、クリック・
  キー入力で即座に全部出す今の打ち切りをそのまま使う。「切る」なら何も起きない
- 留める時間は塊の時間の外に足す（今の「塊の大きさで按分」を崩さない）。1つのレポートで留めるのは
  `note` の上限（1〜2個）と「採る」カードの数までなので、全体は数秒しか伸びない

**やりすぎの線（ここを越える案は採らない）**

- **表情とセリフを塊の中身から決めない。** 異常の `note` で困った顔にする・検証が全部 OK なら喜ぶ、の
  ような自動の切り替えは、`docs/requirements.md` 4.3 の「表情の源は `speak` の1つだけ」を壊す
  （2026-09-17 に同じ形の自動の上書きを撤去している）。反応は締めの `speak` が言う
- **本文から要約・目次・並べ替え・差の計算を起こさない**（`docs/requirements.md` 2.2 の「レポートの
  中身の要約・再構成」）。`options` を並べ替えない・diff の行数や `stats` の差を出さないのはこのため
- **読む面にキャラクターの色を広げない**（`docs/screen-design.md` 13.1 原則1）。差し色の仕切りは
  13.2 の3本のまま
- **書き上げたあとまで動くものを置かない。** 揺れ続ける・光り続ける印は、読む面の静けさ
  （13.1「静けさは画面の持ち物」）に反する。演出は書き上げるあいだだけ
- **絵文字やマスコットの飾りを本文に足さない。** キャラクターは立ち絵と吹き出しに居て、本文は
  中立の文体（`REPORT_NOTATION_PROMPT`）のまま

## 5. ツールの定義の重さと、選び損ねの危険

**案ごとの JSON Schema の増分（`report-block.md` 4章の `sections` だけの形 3272字が起点）**

| 案                                                  | 増分 | 選び損ねの危険                                           |
| --------------------------------------------------- | ---: | -------------------------------------------------------- |
| 描き方だけ（数の列・状態の列・節の単位）            |    0 | 無い（書き手は何も選ばない）                             |
| 欄の4つ（`from` / `to`・`before`・`label`・`flow`） |  287 | 小さい。使い忘れても同じ塊の素の形で描かれ、崩れない     |
| `options`                                           |  576 | 表と取り違える。取り違えても表で描かれるだけ             |
| `files`                                             |  499 | 箇条書きと取り違える。取り違えても箇条書きで描かれるだけ |
| `progress`（11章の4段目）                           |  416 | チェックリストと取り違える                               |
| `compare`（見送り）                                 |  570 | 逃げ道の `cols`・表と取り違える                          |

- 足すと決めたもの（欄の4つ・`options`・`files`・`progress`）を全部載せると、`sections` の schema は
  **3272字 → 5050字（+1778字）**。毎ターンの文脈に載るが、ツールの定義はキャッシュに乗り
  （`report-block.md` 9章）、`REPORT_NOTATION_PROMPT` の表から塊になった行が落ちる分と一部が相殺される
- **選び損ねは描けなくなる事故ではなく、貧しく描かれる事故**にとどまる。新しい種類はどれも
  既存の塊（表・箇条書き）で代わりが利く形にしてあり、取り違えても逃げ道には落ちない
- **塊の種類は逃げ道を含めて11までを目安にする**（今の案の8種 + `progress` / `options` / `files`）。
  足すたびに塊の説明を1つ読ませることになるので、使われ方の記録の「外す基準」（直近4週間で0回）に当たった
  ものは外す
- 選び損ねの程度は、使われ方の記録の「塊の種類 × レポート数」で `options` / `files` と表 / 箇条書きの比を
  見れば分かる。「パスだけの箇条書きは `files` へ」のような差し戻しは足さない — 判定がヒューリスティックで、
  取り違えの害が小さい

## 6. 解くべき論点への答え

- **種類を増やすか、描き方を良くするか**: **描き方を先にし、種類は実測の3%を超えた2つだけ足す。**
  描き方の工夫と欄の追加で、1章の上位の形のうち4つ（名前と説明の対・変化したセル・流れ・数の列）に
  届き、schema は +287字で済む。種類を増やすのは、欄では表せない判定（`options`）とファイルの一覧
  （`files`）だけ
- **見た目を tsukumo だけで決めるか、書き手に強調を選ばせるか**: **汎用の重要度（`emphasis: "high"` の
  ような欄）は持たせない。** 理由は3つ: 書き手が全部を「高」にしていく（`note` に数の上限を置いたのと
  同じ理由）・重要度は色か大きさでしか描けず文字のラベルを添えられない（`docs/screen-design.md` 13.1
  原則5）・書き手の主観なので同じ内容の見た目が揃わない。代わりに**事実か判定を言う欄**（`status`・
  `verdict`・`from` / `to`・`before`・`change`・`tone`）を持たせ、強弱は tsukumo がその意味から決める。
  どれも文字のラベルで描けるので原則5 を満たす

## 7. 移す順番

`report-block.md` 11章の1〜3段のあとに載せる。4段目の `progress` とは
独立に進められる。

1. **描き方だけ**（schema を変えない）: 表の数の列の右揃え・状態の列の揃え・節を演出の単位にする
2. **欄の4つ**: `from` / `to`・`before`・`label`・`flow`。塊の説明と記法の文面を合わせる

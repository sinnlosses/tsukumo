## 要点

1. 見本は**「読み物」ではなく「見渡す板」**の型。互いに独立した区画を2次元に並べ、各区画が見出しと右肩の状態の札を持つ。tsukumo のレポートは
   読者の問いの順に1列で読ませる型（提案書 2章、`docs/architecture/display/rich-rendering.md` の「横に並べて Z 字に読ませない」）で、
   **欠けの大半は塊の種類ではなく配置と区画の枠**にある
2. 見本の要素 13 のうち、いまの塊で**書けるのは 5**（題と説明・表・定義の積み・棒グラフ・パンくず相当の目録）、**近いが欠けがあるのは 3**
   （KPI の補足の行と値の状態色、区画の見出し、分類の札と進捗の棒を持つ小カード）、**書けないのは 5**（2列の区画の格子、区画の枠、右肩の札、タブ、
   右上の操作ボタン。最後の1つは足さない）【実測】
3. 製品の語彙は驚くほど揃っている: **数の札**（Grafana stat・Linear metric block・Datadog Query Value・Observable `.big`）、**区画**（Observable `card`・
   shadcn `Card`・Carbon tile・Grafana panel・Datadog Group）、**札**（Geist Badge・Stripe Badge・Atlassian Lozenge・Primer Label）、**タブ**の4つが核 [3]〜[18]
4. 配置の文法も揃っている: **大事なものを上・左に**（Carbon・Apple・Grafana）、**格子は器の幅で「全部か約数か1列」**（Observable）、**区画は格子の升目だけ・
   入れ子は1段**（Observable、`report-page-geometry.md` 5章）、**札は1行に1つ・1〜2語・色は意味だけ**（Geist・Atlassian）、**タブは同時に比べないものだけ**（Atlassian）
5. 板の型は「読む順」ではなく「見渡す」ので、F 字・左上からの走査を前提に2列にする（Carbon [11]）。これは「Z 字に読ませない」決定と**目的が違う**が、
   決定の文面とは衝突するので**正典の変更**になる。提案書5章の「2段組で幅を使う」を採らなかった理由（読む列は1本）は読み物の型の理由で、板の型には当たらない
6. 優先度の上位3つは **(1) レポート全体の配置の欄 `layout: "board"`**（節を区画にして2列の格子に置き、幅の要る塊を含む節は tsukumo が自動で2列ぶち抜きにする）、
   **(2) 節の右肩の札 `badge`**（語1〜2つと状態の種類）、**(3) `stats` の項目に補足の1行と値の状態**。どれも新しい塊ではなく欄で、書き手の判断はレポートに1回・節に1回・数に1回増えるだけ
7. タブは**保留**を推す。読み手が全部を見るレポートで中身を隠すことになり、畳み（`fold`）は 0.4% しか使われていない（提案書 1.2）。入れ子の塊も 10-01 に採らなかった形
8. 塊を増やす・別の口（`board` のツール）・逃げ道の HTML（描く側に残っている `cols`・`card`・`badge`）・外のファイルの4つの道と比べると、**レイアウトの欄が判断負荷と
   スキーマの増え方の両方で最も軽い**。ただし見本の見た目（明るい地・数の札の横並び・同じ形のカード）はテンプレっぽさの手がかりそのもの（`ai-report-surfaces-2026.md` 6章）で、
   **形を真似るより「区画の独立・状態の札・重要度の順」という文法だけを採る**のがよい【推測】

## 1. 見本の分解と、いまの塊での書け方

見本の画は 1180px 幅・明るい地。上から、頭の帯 → KPI の札 4枚 → 2列×2段の区画 4つ。記事の筆者は「下書き候補は、Claude、Codex、Slack のように
テーマで切り替えられると読みやすい」とし、狭い画面ではメタ情報と下書きの一覧を先に出す並びにしている [1]。artifact は1枚の自己完結した HTML で、
Claude は**組み込みのデザインのスキルを当てて配色・書体・配置を決める**（プロジェクトにデザインシステムがあればそちらを優先）[2]。つまり見本の見た目は
「固定の部品」ではなく「モデルが毎回 HTML と CSS を書く」方式の産物で、tsukumo の固定の部品の方式とは作り方が違う。なお artifact は
**Agent SDK では既定で無効**で、tsukumo からそのまま使う道は無い [2]。

### 1.1 対応表

| 見本の要素                                                                                 | いまの塊での書き方                                                                  | 判定             | 欠け（部品／配置／見た目）                                                                                                            |
| ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 頭の上付き（`MIY-158 / PUBLIC SAMPLE / 2026-06-19`）                                       | レポートの頭の目録の行（ID・状態・所要。tsukumo が `task` から組む）                | 書ける           | 書き手が自由な語を置く口は無い（無くてよい）                                                                                          |
| 題と説明文                                                                                 | `conclusion` の1文目と2文目                                                         | 書ける           | なし                                                                                                                                  |
| 右上の操作ボタン（外へ・更新・格子）                                                       | 無し                                                                                | 書けない         | 部品。ただし更新や外部への遷移はレポートの役目の外で、足さない                                                                        |
| KPI の札 4枚（ラベル・大きな値・補足の1行）                                                | `stats`（3〜4項目、`label`・`value`・`before`・`total`・`series`・`better`）        | 近いが欠けがある | 部品の欄: **補足の1行**（「local CLI check」）が無い。`blocked` のような**語の値に状態の色**を付けられない（`better` は数の増減だけ） |
| 2列×2段の区画の格子                                                                        | 節は縦に1本で積む                                                                   | 書けない         | **配置**。`cols` は描く側に残るがモデルに教えていない（10-01 決定）                                                                   |
| 区画の枠（地・罫・角丸・内側の余白）                                                       | 節は見出しと見出しの罫だけ。最終レポートは箱を持たない（2026-10-03）                | 書けない         | **配置と見た目**。`card` の印は描く側に残るが教えていない                                                                             |
| 区画の見出し                                                                               | 節の `heading`                                                                      | 近いが欠けがある | 見出しの右肩に何も置けない                                                                                                            |
| 区画の右肩の状態の札（「鮮度メモあり」「source checked」「do not overclaim」「5 drafts」） | 無し。状態の印は表のセル・`options` の判定・`claims` の確度・`files` の変更の中だけ | 書けない         | **部品**（札）。`badge-ok/warn/ng` の印は描く側に残るが教えていない                                                                   |
| 区画の中の表（項目・取得経路・記事での扱い）                                               | `table`                                                                             | 書ける           | 見た目: 区画の中では表の左右の余白を 0 にしたい（Observable [3]）                                                                     |
| 定義の積み（太字の名前の下に説明）                                                         | `list` の `label` 付き（名前と説明の2列。器が狭いと上下に積む）                     | 書ける           | なし（区画が狭ければ今の畳み方で上下に積まれる）                                                                                      |
| タブ（Claude・Codex・Slack・発信）と、その横の札「source required」                        | 無し。近いのは塊の `fold`（1つずつ畳む）                                            | 書けない         | **部品**（タブ）。中身を隠す形                                                                                                        |
| 小カードの格子（分類の札・題・説明・進捗の棒）                                             | 近いのは `options`（番号と判定の札つきのカード）と `stats` の `total` の帯          | 近いが欠けがある | 部品: 自由な分類の札と、項目ごとの割合の棒を1枚に持つ形が無い。配置: 2列の小格子                                                      |
| 棒グラフ（5本、軸と目盛り）                                                                | `chart` の `bar`                                                                    | 書ける           | 見た目: tsukumo は系列1色・格子線なし・直接ラベル（`section-and-block.md`）。見本の棒ごとの色はデータの意味を持たない装飾で、真似ない |

数え方: 13 行のうち書ける 5・近いが欠けがある 3・書けない 5（うち右上の操作ボタンは足さないので、埋める欠けは 4）。

### 1.2 欠けを3つに分ける

| 種類       | 欠け                                                                                                                                                      | いまの描く側の残り物                                                            |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| **部品**   | (a) 区画の右肩の札 (b) 数の札の補足の1行と語の値の状態 (c) タブ (d) 分類の札と割合の棒を持つ小カード                                                      | `badge`・`badge-ok/warn/ng`（`src/shared/report/report-notation.ts`）           |
| **配置**   | (e) 区画を2列の格子に並べる (f) 幅の要る区画だけ2列ぶち抜き (g) 区画の中の塊の入れ子（区画 → 表・小カード格子）                                           | `cols`・`cols-of-2/3/4`・`card`（同じファイル。過去の記録を同じに描くため残す） |
| **見た目** | (h) 区画の枠と地 (i) 密度（見本は本文 13〜14px・区画の内側の余白 16px 前後で、tsukumo の本文 15px・行 26px・節の上 52px より詰まる） (j) 明るい地と色の札 | —                                                                               |

(j) の明るい地は「暗い面は常時」の正典（`screen-design.md` 13.2）と食い違い、利用者の目的（キャラクターと一緒に仕事をする画面）にも関わらないので候補にしない。
いまの紙面は 42em の1列で、図と表は列の中央に小さく置かれ、1400 幅では左右に大きな空きが残る（`report-chart.png`）【実測】。見本の「整って見える」印象の
多くは、この空きを区画で埋めて**面が均等に使われていること**から来ている【推測】。

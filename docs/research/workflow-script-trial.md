## 設計に効くこと

- 関門は台本の agent にも掛かる。ただし `lap-hook` は `agent_type` の末尾が `no-delegate`・`general-purpose` のときだけ `delegate` を書くので、台本の `agent()` が既定の型のままだと計測が書かれない。台本で `agentType` を指す必要がある。
- `isolation: 'worktree'` は未送信のコミットを持たない。送り出し前の枝の上で並列に直させる設計には使えず、`main`（`origin/main`）に載った内容を前提にする。
- 台本はこのセッションの途中で足した保存済みのファイルを読まなかった。`/reload-skills` か次のセッションで読まれるかは未確認。
- 台本の agent は tsukumo の MCP の道具を最初から持たず、`ToolSearch` で引いてから呼ぶ。台本の依頼文に「`ToolSearch` で引く」1行を入れる。
- 台本の agent が `phase_result` を呼べるので、帯は台本の完了を待たず段ごとに進む。台本が schema で返してメインが `work_plan` に写す形は要らない。
- 台本の agent の `speak` は、メインや別の agent の直前の `speak` からあいだに新しい事実が無いと差し戻される。台本の中でセリフを言わせるなら、段ごとに事実（`phase_result` の戻りなど）を挟む。
- 台本の完了通知は委譲ゲートを立てない。メインは通知を受けたあと、`work_plan` を呼ばずに作業の道具を使える。ただし帯は台本の agent の `phase_result` で先に進んでいるので、メインの `work_plan` は進んだ位置のまま渡す。
- 計測の確かめには `tw metrics --stages` が使えない（送り出したタスクだけを数える）。`.git/task-workflow/flow/` の台帳を直接読んだ。

## 要点

1. **10-17 で紙面の字と段は先例の帯に入った。残る差は4つ。** 幅の段が2つしかなく広い段に上限が無い（1920 で図とコードが本文の 1.75〜2.1 倍）／

   居場所を言う口が無い
2. **4本の調査は「意味の無い印は読む時間を食う」に収斂した。** 構文色は問いの構造と一致したときだけ効き（Asenov 2016。390 名の研究では
   証拠なし）、並列に拾える色相は 5 まで（Healey 1996）、概観＋詳細は線形より理解で勝ち（Hornbæk 2001）、終わった文書は確定の版を入口に置く
   （Guardian・Linear・Buildkite・Slack）、広い段は本文の 1.25〜1.5 倍で止める（Distill・Observable）、カードの左の色罫は AI っぽさの最も
   確かな印（Krebs、1,590 ページ）
3. **戦略の芯は「色相は意味に、幅は中身に、入口は確定した版に」。** 10-17 の「読み手の問いに位置で答える」を保ったまま、紙面の幾何・色・
   並びをその問いに揃える
4. 原則は5つ: **(1) 幅は中身が選ぶ（本文・広・全の3段） (2) 色相は意味に、構造は明度・太さ・地の段に (3) 印は状態を運ぶ所だけ
   (4) 閉じたら確定の版が入口、経過は畳む (5) 居場所と照らし合わせは1手で**
5. 最大の3手は **幅の段を3つにして横並びを器の幅で落とす**（3.1）、**コードと差分の色を紙面の体系に畳む**（箱を1段に・構文色を 5 値 2 色相に・

7. 読む補助は5つ: 列を畳んだときの「いま: <節>」、`{` `}` で節を移る、読み位置を覚える、前回から変わった節の印、`path:line` の抜き書き（3.3）

## 2. 戦略: 色相は意味に、幅は中身に、入口は確定した版に

### 2.1 4つの差と、それぞれを埋める根拠

| 差                              | 読む時間を食う形                                                 | 根拠（メモ）                                                                                                                                              |
| ------------------------------- | ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 幅の段が2つ、広い段に上限が無い | 1920 で表と図が本文の2倍に伸び、題と本文の軸がずれ、目が往復する | 先例は3〜4段で広は本文の 1.25〜1.5 倍、左端を揃えて右へ伸ばす（`report-page-geometry.md` 1章）                                                            |
| コードが色相を4つ持ち込む       | 状態色と見分けがつかず、1画面の色相が7つで並列に拾えない         | 5色まで並列（Healey）、色は問いの構造に合うときだけ効く（Asenov）、控えめな系は keyword に色相を使わない（`code-and-color-in-dark-reports.md` 1・2・5章） |
| 閉じた札で最終が中間の下        | 中間が多いほど判決の頭が1画面目から落ちる                        | 終わったら確定の版を入口に、経過は畳むか別の口（`report-reading-interface.md` 4章）                                                                       |
| 列を畳むと居場所を言う口が無い  | スクロールで位置を見失い、作業記憶の低い読み手で理解が落ちる     | 概観＋詳細 2.47 対 2.00（Hornbæk）、sticky の題（GitHub）、scroll-spy（docs 8つ中6つ）（同 1章）                                                          |

### 2.2 原則

1. **幅は中身が選ぶ。** 本文（42em）・広（本文の 1.5 倍＝63em で止める）・全（内幅）の3段。どの段に入るかは塊の種類で決め、書き手は名指さない。
   横に並べるかは窓ではなく器の幅で決め、3＋1 の孤児の段を作らない
2. **色相は意味に、構造は明度・太さ・地の段に。** 意味の色相は `state-*` 5 つと `accent` の6つで打ち止め。コードの色は彩度 C ≤ 0.06 の淡い
   2 色相にとどめ、名前は太さで拾わせる。差分は帯の明度で向きを言う（追加が明るい）。13.1 の原則1・5 は変えない
3. **印は状態を運ぶ所だけ。** 左の色罫・札・番号・太字は、それが無いと読み違える所にだけ置く。同じことを言う印が2つあれば1つにする（採る案の罫は
   「採る」の札が言う）
4. **閉じたら確定の版が入口、経過は畳む。** 働くあいだは今のまま。閉じた瞬間だけ「依頼 → 最終 → 経過 n 件」に並べ替える。
   「入れ替わるのは送ったときと閉じたときだけ」の約束の内側
5. **居場所と照らし合わせは1手で。** いまの節・前後の節・読んでいた位置・参照先の中身が、転がしたり開いたりせずに分かる

### 3.5 書き手の規約（足す条の案文）

1. `stats` は数が3つ以上で、前後か推移を見せるときだけ。2つ以下の数は結論か本文の文に入れる
2. 表は 10 行、一覧は 10 件を超えたら上位を残して `rest`（か「ほか n 件」）に書く
3. `marks` の無い `code` は 45 行を超えない。超えるなら要る範囲だけを引く
4. 調べもののレポートの外部の出典は `[ドメイン](URL)` の形で文の直後に書く
5. `path:line` は押すと開き、重ねると前後が見えるので、本文で行の中身を写し直さない

〔規約〕。条1・2・3 は 10-17 の条4・6 の続き。既存の条（段落3文・note は2つ・`**` は1段落に1か所）は変えない。

## 8. 確かめていないこと

- 見本は静的な HTML で、実物の React の木・書き上げる演出・やり取りの列の実測の幅と合わせていない。`@container` の閾値（600px・724px）と
  図の高さの `cqh` は見本の器では効いておらず、実装で確かめる
- 構文色と差分の候補の値は計算だけで、C 0.055 の2色が「色」に見えるか「くすんだ字」に見えるかは目視が要る。作者の色覚も確かめていない
- 1依頼あたりの中間レポートの件数の分布。最終を入口に置く案の効き目（判決の頭が1画面目から落ちる割合）はこれで決まる
- 読む面より高い図の割合（70% の上限の要否）。`{` `}` が JIS 配列と IME の変換中にどう届くか
- Scroll Anchoring が貼り付いた帯と畳みの開け閉めでどう効くか（Orca の Chromium で未確認）
- 研究はすべて欧文の読み手で、和文の長い報告を暗い面で読む条件の実験は見つかっていない
- 読む面の高さ（1440×900 で 458px）は器（領域の比率）の話で、この提案の外。段0の仕切りの記録で材料を集めてから別に議論する

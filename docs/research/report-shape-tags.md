# レポートの節に「形の札」を付け、札ごとに使える塊を決める（2026-10-18）

状態: 参考

実装は ADR 0038 に置き換わった。

**この文書は調査の記録であって正典ではない。** 正典は `docs/architecture/display.md`「各表示物」「塊を足す・外す基準」と `src/shared/report/report-block.ts`
（塊の欄と `describe`）・`src/server/report/core/report-notation.ts`（記法の条8）で、**採用が決まるまでコードは1行も変わらない**。

**主題**: レポートが図で描ける内容を表と文字列で書いてしまう癖を、仕組みで減らす。節ごとに「その節が表す内容の形」
（札）を書き手に言わせ、札ごとに「第一候補・許す代替・許さない」塊を決めておき、許さない塊を機械で照合する。
この文書は、その札の一覧と割り当てを、内部の経緯・実物のレポート・外部の分類体系から組み立てた記録。

**出典の印**: 無印は一次情報に当たったもの。**【二次】** は要約・引用でしか読めなかったもの。**【実測】** は手元の記録を数えた値。
**【推測】** は私の判断で、文献にも記録にも根拠が無いもの。

## 要点（10行以内）

1. **札は「内容の型」ではなく「形」で切る。** ADR 0028 が内容の型5つの表をやめたのは、型に当たらない内容の「その他」が箇条と文に落ちたから。形（要素の数・向きのある関係・数・候補）はどの内容にも問えるので、最後を「一言」「並列」で必ず受けられる
2. **札は14の形と3つの添え物。** 関係を描く6（因果・つながり・位置・状態・時間・順序）と、並べる8（量・選択・属性の並び・対応・見比べ・境界・並列・一言）。前後・確度・所在はどの形にも掛かる添え物で、札にすると形との掛け算で数が増える
3. **表は「値を引く・行を比べる」作業にだけ当てる。** 記号を読む作業には表、形を見る作業には図が速い（Vessey の認知適合）。Few も個々の値と正確さが要るときだけ表を推す。セルが文になったら表の外へ出す
4. **因果と推論は箇条にしない。** Tufte と Nygard が共通して言う。社内の調べの「因果は文で」とは鎖の段数で両立させる（1〜2段は文、3段以上か要因の合流は graph）
5. **実物のレポート 100件・166節【実測】は16の型に分かれ、すべて札に乗る。** 合わなかった17件の最多は文の詰まった表（7件）で、graph・chart・mermaid は節の中では0回（図の欄にだけ出ていた）
6. **札で受けても描き切れない穴が5つある。** 確度つきの主張・時間の区間と内訳・位置の模式図の書き込み代・複数基準の判断・（分布・相関・地図は採らない）
7. **照合で拾えるのは、合わなかった17件中およそ14件【推測】。** 拾えないのは並びや数を地の文に詰めたものと、見た目の案を code に罫線で描いたもの

## 2. 内部の経緯

- **内容の型の表は一度やめている。** 2026-10-12 まで条8は内容の型5つ（経路・流れ・層の構造／画面の見た目／時間順のやり取り・状態／
  前後の数／候補の比較）に第一候補を挙げる表だった。型に当たらない内容の落ち先が無く、`list`・`text` に落ちた。
  そこで形の梯子5段（図 → 数の図 → 揃えた並び → 並び → 文）に替えた（`docs/architecture/adr/0028-report-block-priority.md`「何が困っていたか」「梯子」）
- **ADR 0028 は「上の段の乱用は数えない・差し戻さない」と決めている。** 図を避けさせる向きに働くため。札の照合も
  「許さない」は下の段だけを塞ぎ、図の使い過ぎは見ない（この線に合わせる）
- **性質ごとのテンプレート案は却下されている**（`docs/research/report-architecture.md` 2〜3章）。112件で塊の組み合わせが33通りあり、
  1ターンに性質が混ざり、選び違えるとレポート全体の形が崩れるため。札はレポート単位ではなく**節単位**なので、この理由には当たらない
- **図の欄（`figure`）を必須にしても、節の中は縛られていない。** 図の欄が埋まれば、節は何で書いても通る（ADR 0028「追記: 図を欄で必須にした」）
- **差し戻しは字数と書式が大半。** 実セッションの差し戻し535件の上位は `long-first-sentence` 266・`long-conclusion` 53・`crowded-notes` 43【実測】。
  塊と内容の合い方を見るのは `arrow-in-prose` と `figure-contradiction` くらいしか無い

### 4.2 表と箇条が最適になる条件

- **表**: 記号を読む作業（特定の値を引く）には表、空間的な作業（傾向や形を見る）にはグラフが速く正確になる（Vessey 1991 の認知適合
  [is.theorizeit.org](https://is.theorizeit.org/wiki/Cognitive_fit_theory)【二次】）。Few は個々の値を引く・正確な値が要る・観測が少ないときに表を推す
  [perceptualedge.com](https://www.perceptualedge.com/blog/?p=2080)。Microsoft は「似た項目を並べるだけなら表でなく箇条」と書く
  [learn.microsoft.com](https://learn.microsoft.com/en-us/style-guide/scannable-content/tables)
- **箇条**: 番号つきは並べ替えると意味が変わるもの、番号なしは順番も相互の関係も無いもの
  [developers.google.com](https://developers.google.com/tech-writing/one/lists-and-tables)
- **箇条に向かないもの**: 因果・判断の理由・推論。Tufte は箇条が因果の前提と分析の構造を隠すと書き
  [rightattitudes.com](https://www.rightattitudes.com/2016/06/10/the-cognitive-style-of-powerpoint/amp/)【二次】、Nygard は箇条を文の断片の言い訳にしないと書く
  [cognitect.com](https://www.cognitect.com/blog/2011/11/15/documenting-architecture-decisions)
- **不確かさ**: 言葉だけの確率は人によって解釈が割れる（Kent の "serious possibility" は 20〜80%）
  [nature.com](https://www.nature.com/articles/467883a)。主張ごとに確度の印と根拠を付ける形が要る【推測】

### 4.3 選び方の手順

Zelazny は「要点を1文で書き、要点の語から比較の型を見分け、型に対応する図を選ぶ」
[qimacros.com](https://www.qimacros.com/free-excel-tips/say-it-with-charts/)【二次】。FT は「データの中の最も大事な関係を1つ選び、その列から図を選ぶ」。
Abela の4分類（比較・分布・構成・関係）は Few に「概念の階層が揃っていない」と批判されている
[perceptualedge.com](https://www.perceptualedge.com/blog/?p=2080)。札の決め方（5.3）は Zelazny の「要点を先に1文」と FT の「最も大事な関係を1つ」を借りた。

## 5. 札の設計

### 5.1 関係を描く札（要素の間に向きのある関係がある）

### 5.3 札の決め方

節の要点を1文で書き、上から問いを当てる。最後は「並列」で必ず受けるので、どの札にも当たらない内容は出ない。

1. 要素は1つか → 一言
2. 要素の間に向きのある関係（因果・つながり・位置・遷移・時間・順番）があるか → 5.1 の札
3. 数が主役か → 量
4. 候補を採否するか、2つの側を比べるか → 選択・見比べ・境界
5. 項目が2つ以上の属性を持つか → 属性の並び・対応
6. どれでもない → 並列

### 5.4 添え物（どの札にも掛かる）

| 添え物 | 使う塊・欄                                                                                               |
| ------ | -------------------------------------------------------------------------------------------------------- |
| 前後   | 第一候補の塊を `beforeAfter` の側に入れる・`graph` の `+` `-` `~`・`table` の from/to・`stats` の before |
| 確度   | 6章の新しい塊。それまでは `note`（ask）を1つ                                                             |
| 所在   | `path:line`・`files`・`code` の `path`                                                                   |

前後と確度を札にしなかったのは、形との掛け算で札が倍になるため。前後は ADR 0028 でも「段ではなく容れ物」として扱っている。

### 5.5 「許さない」の向き

「許さない」は下の段（表・箇条・文）だけを塞ぎ、上の段（図）の使い過ぎは数えない。ADR 0028 の「上の段の乱用を差し戻さない」と同じ向き。
札を弱く申告して下の段へ逃げる抜け道（因果の内容に「並列」の札を付ける）は、札と無関係な検査（セルが文の表を差し戻す）で塞ぐ。
許す範囲の中でより良い選択肢を避けること（chart で見せられる数を table にする）は止められない。目的は明らかに悪い選択を消すことで、最適は保証しない。

## 6. 札で受けても描き切れない穴

札ごとに、実物で合わなかった17件と4章の型を今の塊で描いてみて、描けない・描くと崩れるものを拾った。

| 穴                       | 何が描けないか                                                                              | 提案                                                                         | 判定     |
| ------------------------ | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | -------- |
| 確度つきの主張           | 主張・確度（確定・推測・未確認）・根拠・確かめ方の1組。note（ask）と状態のセルに散る        | 新しい塊（主張ごとの行に確度の印・根拠・確かめ方）                           | 採る     |
| 時間の区間と内訳         | 段の所要と重なり（trace の waterfall）、全体に占める割合                                    | `chart` に区間（`arrow` の浮き棒を流用）と内訳（100% の積み上げ棒1本）を足す | 採る     |
| 位置の模式図の書き込み代 | `svg` は座標書きが重く、実セッションで全期間2回。見た目の案を code の罫線で描いた例がある   | 格子に箱を置き、重なりに印を付ける配置の塊                                   | 検討     |
| 複数の基準での判断       | 判断の報告28件中27件に `options` が無く、基準が2つ以上だと table に流れて採否と基準が割れる | `options` に基準ごとの判定を足す                                             | 検討     |
| 分布・相関・地図         | 箱ひげ・散布図・地図                                                                        | 札にしない（166節に0件。出たら `chart` の種類として足す）                    | 採らない |

## 7. 照合で拾える見込み【推測】

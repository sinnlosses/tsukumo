# 委譲先の歩の内訳（2026-09-28 〜 2026-10-04）

`plugin/skills/token-usage-diet/scripts/summarize_subagent_steps.py` で、
Claude Code の transcript（`subagents/agent-*.jsonl`）の歩を種類ごとに数えた結果。
数と分類名だけを載せ、transcript の抜き書きは載せない。

## 数え方

- 歩 = assistant メッセージ1つ（id で束ねる）。種類は、その歩の先頭のツール呼び出しの名前と、
  Read は引数のパスの形、Bash は先頭の語・`git`・`tw verify`/`pnpm` の有無だけで決めた
- キャッシュ読みと文脈の大きさはその歩の usage（文脈 = 入力 + キャッシュ読み + キャッシュ作成）。
  結果のバイト数は、その歩の呼び出しに返ったツールの結果の大きさ
- 対象は `~/.claude/projects/` のうちディレクトリ名に `tsukumo` を含むすべて（本体と各作業ツリー）。
  tsukumo の記録の集計（委譲 122 回・12,776 歩）より範囲が広く、同じ数にはならない

## 削ると効く歩の上位

1. **Bash の探索（`ls`・`find`・`grep`・`cat`・`sed` など）**: 歩数 8,676（33%）・キャッシュ読み 29.5%。
   結果も 31.7MB で Bash の中で最大。探索を1歩ずつ重ねるほど、後続の歩ごとに文脈が持ち越される。
   依頼文に読む場所を書いて探索の歩を減らすのが最も効く
2. **Bash のその他**: 5,030 歩・20.7%。先頭の語で探索・検証・git・tw に入らなかった呼び出しで、
   分類の粗さが残る。歩あたりの文脈は 163,175 と探索より大きく、作業の後半に偏る
3. **Edit・Write**: 4,267 歩・19.1%。歩あたりの文脈は 176,490 で、検証を除く種類の中で2番目に大きい。
   文脈が育ち切った後半に書く歩が集まるので、1歩の単価が高い。小さな編集を束ねる余地がある
4. **検証（`tw verify`・`pnpm`）**: 2,635 歩・10.7%。1歩あたり 160,340 読む。落ちて打ち直す回数がそのまま乗る
5. 結果のバイト数だけで見ると **Read: その他** が 99.2MB で突出する（586 歩、2.7%）。
   歩数は少ないが1歩の結果が大きく、後続の文脈を押し上げる

委譲1回の歩数は中央値 45 に対して 90パーセンタイル 141・最大 1,302 と裾が長い。
長い委譲ほど後半の文脈が大きい歩を多く含むので、委譲を小さく分けるほうが、種類を削るより効く可能性が高い。

## 限界

- 分類は歩の先頭のツール呼び出しだけで決めている。1歩に複数の呼び出しがあっても先頭の種類に寄る
- Bash の種類は先頭の語（と `git`・`tw verify`・`pnpm` の有無）で決めた粗い分類で、`cat` や `sed` でファイルを読む歩は探索に入る
- 結果のバイト数はトークン数ではない（日本語が多いとトークンは多くなる）

# 用語集

tsukumo で使う固有の用語を、**日本語表記・コード上で使う英語識別子・定義**の3点でまとめたもの。
表記ゆれを防ぐことが目的なので、迷ったらここに合わせる。

**方針**:

- ここに載せるのは**このプロジェクト固有の概念だけ**。タイムアウト・リトライ・エラー型のような
  一般的なプログラミング概念は載せない
- **英語識別子はまだコードが無いため「予定」**。実装時にこの表を正典として命名し、
  変えたくなったら**先にここを直してからコードを直す**
- 同じものを指す言い方が複数あるときは1つに決め、他は「避ける言い方」に書く

## このファイルの読み方

現時点では小さいので通読してよい。**25KBを超えたら**、下の索引で用語を1つ特定して
その見出しだけを読む運用に切り替える:

```bash
sed -n '/^### 立ち絵/,/^#\{2,4\} /p' docs/glossary.md
```

## 実行構成

### サイドカー

- **英語識別子（予定）**: `sidecar`
- **定義**: 本体とは別のペインで常駐し、transcript と状態ファイルを読んで3つのビューを
  組み立てて配るプロセス。tsukumo の本体そのもの
- **避ける言い方**: ウォッチャー、ビューアー、デーモン。**「サイドカー」で統一する**
  （本体に寄り添うが割り込まない、という位置づけを名前に残したいため）

### ペイン

- **英語識別子（予定）**: `pane`
- **定義**: ターミナルの分割された1区画。実測環境では Orca の split terminal
  （`orca terminal split`）で作る
- **注記**: tmux は未導入で、前提にもしない。以前は VS Code の split terminal を前提に
  していた（`docs/architecture.md`「ペイン分割は Orca を前提にした」に経緯がある）

### サイドバー

- **英語識別子（予定）**: `sidebar`
- **定義**: 画面レイアウトの右上に置く、幅の狭いビュー。会話ではなく「その他情報」を出す
  （`docs/requirements.md` 4.7）
- **注記**: **何を出すかはまだ決まっていない**（`docs/requirements.md`「7. 未決事項」）。
  **会話の内容はここに出さない**（吹き出しとメインビューの役割で、同じものを2箇所に出さないため）
- **避ける言い方**: 情報パネル、ステータスペイン、HUD

### ホスト

- **英語識別子（予定）**: `host`
- **定義**: tsukumo が載っているターミナル環境そのもの。実測環境では Orca。ペインを開くことと
  ビューを見せることを頼む相手
- **注記**: ホストに依存する操作は1つのポート（`src/host.ts`）の裏に置き、実装は
  アダプタ（`src/orca-host.ts`）に閉じ込める（`docs/architecture.md`
  「ホスト依存の操作は1つのポートにまとめる」）
- **注記**: **「本体」とは別のもの**。本体は Claude Code の CLI を指す
- **避ける言い方**: 端末環境、プラットフォーム、シェル

### 本体

- **英語識別子（予定）**: 使わない（コード上に本体を指す識別子は現れない）
- **定義**: Claude Code の CLI そのもの。tsukumo から見て、transcript と状態ファイルを
  書き出す側
- **避ける言い方**: 親、ホスト、メイン

## 発話の取得

### transcript

- **英語識別子（予定）**: `transcript`
- **定義**: Claude Code がセッションごとに書き出す JSONL ファイル。1行1イベントで、
  `~/.claude/projects/<セッションスラッグ>/<session-id>.jsonl` にある
- **注記**: **ユーザーの生の会話ログである**。扱いの制約は
  `docs/coding-standards.md`「会話内容の扱い」が正典
- **避ける言い方**: ログ、履歴、JSONL（ファイル形式を指したいときだけ「JSONL」と言う）

### セッションスラッグ

- **英語識別子（予定）**: `projectSlug`
- **定義**: transcript の置き場所を決めるために、cwd をスラッグ化したディレクトリ名
- **注記**: **スラッグ化の規則は Claude Code の内部仕様**なので、tsukumo 側で再実装しない。
  hook が渡す `transcript_path` を使う（`docs/architecture.md`「追従先は自前でスラッグ化せず、
  hookが書いたパスを読む」）

### 発話

- **英語識別子（予定）**: `utterance`
- **定義**: Claude の応答1回分のまとまったテキスト。transcript の `type: "assistant"` の行から
  取り出した `content[].text` にあたる。**「セリフ」と「詳細」を両方含んだ全体**を指す
- **注記**: `user` の入力や `attachment` などは発話として扱わない
- **注記**: 発話をそのまま吹き出しに出すことはしない。セリフだけを切り出して出す
  （`docs/requirements.md` 4.2）
- **避ける言い方**: メッセージ、レスポンス

## 表示

### ビュー

- **英語識別子（予定）**: `view`（識別子は `ViewName` = `main` / `character` / `sidebar`）
- **定義**: サイドカーが HTML で組み立て、ホストの中のブラウザタブに出す表示単位。
  メインビュー・キャラビュー・サイドバーの3つがある
- **注記**: **表示はすべてビューである**（2026-09-09 に全 HTML 化した。
  `docs/architecture.md`「表示はターミナル描画をやめて、すべて HTML にした」）
- **避ける言い方**: 画面、ウィンドウ、パネル

### メインビュー

- **英語識別子（予定）**: `main`
- **定義**: レイアウトの左上に置く、いちばん広いビュー。作業の進行と、発話の**詳細**を出す
- **注記**: 以前は「詳細ビュー」と呼んでいたが、完成したレポートだけでなく**作業そのものが
  進む場所**であることが決まったため改めた（`docs/history/direction.md` 2026-09-09）
- **避ける言い方**: 詳細ビュー、詳細ペイン、プレビュー

### キャラビュー

- **英語識別子（予定）**: `character`
- **定義**: レイアウトの左下に置くビュー。**立ち絵と吹き出しが同じ領域に同居する**
- **注記**: ターミナルのペインではなく HTML のビュー。**これが決まったことで、端末の画像
  プロトコルが通らない問題は関係なくなった**
- **避ける言い方**: キャラペイン、立ち絵ペイン

### ビューサーバ

- **英語識別子（予定）**: `viewServer`
- **定義**: ビューをブラウザに配るローカルの HTTP サーバ。`127.0.0.1` にだけバインドし、
  本文をメモリに持ち、更新を Server-Sent Events で push する
- **注記**: **本文をファイルに書き出さない。** 会話の一部を含むため
  （`docs/coding-standards.md`「会話内容の扱い」）
- **避ける言い方**: プレビューサーバ、開発サーバ

### 立ち絵

- **英語識別子（予定）**: `portrait`
- **定義**: キャラビューに表示するキャラクターの画像。HTML の `<img>` で出す
- **注記**: 素材はリポジトリに同梱せず、キャラクター定義からパスで参照する
- **避ける言い方**: スプライト、アバター、アイコン、マスコット（「マスコット」は
  statusline 側の小さい絵を指す語として空けておく）

### 吹き出し

- **英語識別子（予定）**: `balloon`
- **定義**: 最新の**セリフ**を囲って見せる表示。キャラビューの中で立ち絵と同居する。
  折り返し・全角文字の幅・禁則処理はブラウザに任せる
- **注記**: **発話の全文は入れない**。全文が Claude Code の TUI と2箇所に出ることが、
  分離を決めた理由そのものだった（`docs/requirements.md` 4.2）
- **避ける言い方**: バブル、コメント欄、メッセージボックス

### セリフ

- **英語識別子（予定）**: `speech`
- **定義**: 発話のうち、**会話のための部分**。吹き出しに出す
- **注記**: 発話をセリフと詳細に分けるのは**モデル側**で、出力スタイルの規約で書き分けさせる。
  tsukumo はその規約に従って切り出すだけ（`docs/requirements.md` 4.2）
- **注記**: 以前この語は「キャラクター定義側の固定文言」を指すために空けてあったが、
  出力の分離が決まったことで**発話の会話部分**を指す語に確定した。固定文言を指したくなったら
  別の語を立てる
- **避ける言い方**: 台詞（表記は「セリフ」に統一）、メッセージ、一言

### 詳細

- **英語識別子（予定）**: `detail`
- **定義**: 発話のうち、**技術的な情報の部分**（手順・コード・表・パスなど）。メインビューに出す
- **注記**: **中身は変えない。** 読みづらさの主因は見た目なので、整形は見た目の範囲に留める
  （`docs/requirements.md` 2.2）
- **避ける言い方**: 本文、ログ、詳細情報

### 表情

- **英語識別子（予定）**: `expression`
- **定義**: 立ち絵の差分。hook イベントで切り替わる（作業中 / どや顔 / あわあわ など）
- **避ける言い方**: 感情、ステート、ムード

### 衣装

- **英語識別子（予定）**: `outfit`
- **定義**: 実行中のモデルに対応する立ち絵の見た目。`haiku` = 軽装 / `sonnet` = 通常装備 /
  `opus` = 戦闘配置
- **注記**: 「装備の重さ＝モデルの重さ」というメタファーで、Asuna output style の
  「出撃時の掛け声」のモデル分岐と対応する
- **避ける言い方**: コスチューム、スキン、テーマ

### キャラクター定義

- **英語識別子（予定）**: `characterPack`
- **定義**: 立ち絵の素材パスと、表情・衣装の対応を宣言的に書いた差し替え可能な定義ファイル
- **注記**: **コードにキャラクターの中身を書かない**ための置き場所
  （`docs/architecture.md` 原則4）
- **避ける言い方**: 設定ファイル（`config` は別の意味に使いたくなるため）、テーマ

### フォールバック

- **英語識別子（予定）**: 使わない（動作の呼び名であって、対応する識別子は置かない）
- **定義**: 表示物が1つ欠けても、残りを表示して動作を続けること。立ち絵の素材が無ければ
  セリフだけを出し、`orca` が無ければビューを開かずに配信だけ続ける
- **注記**: **表示物が1つ欠けたことを起動失敗にしない**（`docs/requirements.md` 4.2）
- **注記**: 端末の画像プロトコルが使えるかどうかは、立ち絵が `<img>` になったことで
  関係なくなった（2026-09-09）

## Claude Code 側の仕組み

### hook

- **英語識別子（予定）**: `hook`
- **定義**: Claude Code が特定のイベント（`SessionStart` / `PreToolUse` / `Stop` など）で
  実行する外部コマンド。tsukumo では**状態ファイルを書くためだけ**に使う
- **注記**: hook の stdout はエスケープされてテキスト扱いになるため、そこから描画はできない
  （`docs/requirements.md`「3. 技術制約」）。登録先の `~/.claude/settings.json` は
  **orca が専有しているので上書きしない**

### 状態ファイル

- **英語識別子（予定）**: `stateFile`
- **定義**: hook が書き、サイドカーが読む小さなファイル。表情の元になるイベント種別と、
  実行中のモデルを持つ
- **注記**: statusline 併走（案B）を作るときも**同じファイルを共有する**。状態の発生源を
  hook 1つに保つため

### statusline

- **英語識別子（予定）**: `statusline`
- **定義**: Claude Code の入力欄下に出る1行の表示。ここに小さいマスコットを出すのが案B
- **注記**: 現状 orca が専有している。優先度は低く、MVPには含めない

### output style

- **英語識別子（予定）**: 使わない
- **定義**: Claude Code の応答の人格・口調を定義する設定。実測環境では `Asuna` が有効
- **注記**: 衣装のモデル分岐は、この output style の「出撃時の掛け声」と対応させる

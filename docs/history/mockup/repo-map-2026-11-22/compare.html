置き場: 小さく右・広げて中央

  • 右の列の「地図」タブは縮図と選んだ箱の説明だけ。296px では箱の名前が読めないので、描き込む場は中央の列に広げる（場面1）。
  • 広げた地図は会話の流れの上に重なり、⎋ で流れに戻る。入力欄と声の帯は隠さないので、地図を見たまま頼める。
  • レポートの中の地図は同じ描き方の縮小版で、別の図を作らない（場面4）。

指す語は「箱の ID」1種類

  • 利用者が箱から始めると、入力欄の頭に箱の札が付く（場面2）。エージェントにはその ID と縮尺が届き、MCP で同じ箱の定義（置き場・ADR・つながり）を引ける。
  • エージェントも本文とセリフに同じ札を書き、札に触れると地図の箱が光る（場面3）。指す道具が入力欄・本文・セリフで同じ形になる。
  • 札の ID は図の定義の ID。改名したら古い ID を別名として残す。

情報の置き場は重ねない

  • 地図は「どこか」だけを持つ。ファイルと差分は今までどおり「変更」タブとレポートの「変えたファイル」にあり、箱を押すとその一覧を絞る（場面4）。
  • 箱の説明はファイルの中身を写さず、ADR・要件・用語への導線にする。
  • ずれの検査の結果は「検証」の行に出し、地図の上では箱と矢印の赤だけで示す（場面5）。

まだ決めていないこと

  • 図の定義の形式（LikeC4 の DSL を正典にするか、tsukumo の JSON にするか）。見本は前者の想定で docs/map/tsukumo.c4 と書いた。
  • 配置を手で置くか自動にするか。見本は手で置いた座標。
  • 動きの図（依頼1件が通る順）を同じ地図の上の経路で出すか、別の図にするか。

キャラクターの側

  • エージェントが箱を指すとき、セリフの札と地図の箱が同時に光る。つくもが「ここ」と指さしている形を、立ち絵ではなく狐火の色（青緑）で出す。
  • 箱を指す色は狐火の青緑に固定し、変更の黄・追加の緑・ずれの赤と混ぜない。

メンテナンスの経路

  • 箱の置き場（パス）が消えた・地図に無い依存が生えた、を pnpm run check が落とす。直すのは図の定義の数行で、画は描き直さない。
  • 落ちたときは次の一手のカードに「地図を直す」が出る（場面5）。

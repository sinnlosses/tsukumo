レポートの出典の番号（Citation）と用語の注（InfoTip）— 見本

同じ架空の調べもののレポートを、今の書き方と案で描き分けた。案は astryx 0.7.10 の Citation（number 型）と HoverCard を写した見た目で、書き手は部品ではなく Report の欄（出典の一覧・用語の注）と本文の番号の印だけを書く。紙の幅 730px・本文 14px・補足 12px は今のアプリに合わせた。

案では番号と点線の語に触れるか Tab で焦点を当てると札が出る。狭い幅では札が画面の下に出る。

架空の結論: 再試行の上限は 3 回のままでよく、待ち時間だけを指数で延ばす。

上限を増やしても成功率はほぼ変わらない

再試行の4回目以降に成功する要求は全体の 0.2% に満たないと報告されている example.com（架空）。待ち時間を一定にすると、失敗した要求が同じ瞬間に戻ってきて相手の負荷が跳ねる（いわゆるサンダリングハード。多数の待ち手が同時に起きて同じ資源へ殺到すること）www.example.org（架空）。

指数バックオフ（待ち時間を失敗のたびに倍にしていく再試行の間隔の決め方）に揺らぎを足すと、戻りがばらけて負荷の山が消える www.example.org（架空）。

Paragraph.text:
  "…満たないと報告されている[^s1]。…"

番号は描く側が初出の順に振り、同じ出典は同じ番号にする。用語の注は本文で最初に出た1か所にだけ付く（書き手は本文に印を書かない）。

見比べるところ

  • 本文の長さ: 今は用語の説明と出典の札が文の流れに入る。案は番号と点線だけになる
  • 同じ出典の二度書き: 今は www.example.org が2回。案は同じ「2」
  • 書き出し: 浮く札は出せないので、用語は「注n」と末尾の一覧に開く
  • 狭い幅: 札が語の上でなく画面の下に出て、指で隠れない

まだ決めていないこと

  • 本文の番号の印の書き方（[^s1] か、主張ごとの欄か）
  • Claims の basis や表のセルにも番号を許すか
  • 用語の注を、同じセッションの次のレポートでも付け直すか

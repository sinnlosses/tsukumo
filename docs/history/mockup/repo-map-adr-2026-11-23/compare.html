入口はサイドバーの区画（論点7）

  • タスクの区画と使用量の帯のあいだに「地図」を足す。中身はミニマップと選んだ箱の詳細で、区画はミニマップの高さで止まり、詳細だけが中でスクロールする。
  • 「広げる」かミニマップを押すと、中央の列の流れの上に重なる。入力欄と声の帯は隠さない。⎋ で流れに戻る。
  • 左右の列のタブが採られたら、同じ部品 ArchitectureMapPanel を「地図」タブへ移す。

3段の縮尺と数（論点4・8）

  • 大は browser・server・shared と外の世界。server は箱1つで、前の見本の adapter・core・wiring の3つは小の段のディレクトリに出る。
  • 矢印の数は小の段の import の本数を祖先の箱で束ねた和。箱の中で閉じた本数は箱の下に「中で n」と出す。
  • 潜った図は、子の箱と、子とつながる外の箱（点線）だけを描く。並びは定義の place の格子、無ければ自前の配置。

指す語は {{map: ID}}（論点3）

  • 本文・セリフ・入力欄で同じバッジに描く。触れると地図の同じ箱が光る。
  • 大・中の ID は人が付けた名前、小の ID はディレクトリのパス。
  • 知らない ID・地図が読めないときの印は、字のまま残す（場面6）。

最近のタスク（論点9）

  • 箱を選ぶと、作業ディレクトリの HEAD の直近200コミットから、箱のファイルを触った件名の ID を新しい順に5件。題と状態はタスク一覧から引く。
  • 「最近7日に触った箱」は、箱ごとの ID の数を角のバッジに出す。

読めないとき（論点5）

  • 地図のファイルが無いときと雑談のあいだは、区画ごと出さない。
  • 壊れている・知らない版のときは区画を出し、理由の1行と次の手だけを置く（黙って消えない）。

  • 地図の上のずれの赤。ずれは pnpm run check の段 architecture-map が落とし、レポートの「確かめたこと」の1行に出す。

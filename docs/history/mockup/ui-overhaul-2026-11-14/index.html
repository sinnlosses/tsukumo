入力欄の骨格（Astryx の ChatComposer に合わせた点）: 本体は角丸 28px・内側 12px・間 8px。上に添付の引き出し、中に入力、下の行の左に添付・コマンド・参照とモデルの札、右に新規と円形の送信（作業中は中断）。コマンドやタスクの ID は入力の中で札になる。入力欄の頭に使用量を出す枠は、使用量をサイドバーへ置いたので使っていない。

提案者の所見（決定の前に書いたもの）

案B を土台にして、案A の右パネルを開閉式（⌘B）で足す形を推す。

理由は3つ。tsukumo の目的はキャラクターと一緒に仕事をすることで、舞台を最も広く取れるのは案B。入力欄が常にフォーカスを持つ使い方に、オムニバーと ⌘ の体系が最も合う。そして案B の弱点である「タスクが呼び出すまで見えない」は、案A のパネルを必要なときだけ開けば埋まる。

案C からは、顔の棚（常時見える1操作の交代）と、完了の場面の「次の候補」を部品として採れる。タブ列とボードは、セッションとタスクの対応づけが裏側に入ってから検討するのが安全。

前提と制約

  • セッションの切替・新規・キャラクターの交代・タスクの依頼は、ターンの最中は受け付けない。今の裏側の制約で、試作でも知らせを出して再現してある（作業の場面で押すと分かる）。
  • 書体は端末にあるものだけを使い、外部のフォントは読み込まない。色はキャラクターの差し色を、居る場所と指し示す場所にだけ使う。
  • 幅 760 以下の配置、雑談モード、尋ねる（お伺い）の場面は今回の試作に含めていない。
  • キャラクターを選んだときの一言（案C のボード）は、相づちの札の応用を想定した演出で、今の実装には無い。

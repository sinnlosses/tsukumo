## 背景

## 背景

**当初は「引数も結果も全部出す」と決めていたが、実際に使ったユーザーが撤回した**（2026-09-10）。

> 打ったBashコマンドはさすがにメイン画面に出さなくてよかった。私が見るべき情報のみに絞ってほしい。

`src/transcript.ts` の `extractMainViewEntries` が `tool_use`（`name` / `input`）と `tool_result` をすべて拾い、`src/view.ts` の `buildMainBody` がそれを全部描いている。**実測では本物の transcript で63個のツール実行ブロックが並び、その大半が `Bash` のコマンドと出力だった。**

## **決定事項（2026-09-10、ユーザーと合意済み。再検討しない）**

| 種類                       | 扱い                                                  |
| -------------------------- | ----------------------------------------------------- |
| **ファイルを変えた操作**   | **出す。** ツール名とパス（`Edit: src/view.ts` など） |
| **サブエージェントの起動** | **出す。** タスク名（`meta.json` の `description`）   |
| **失敗したツール**         | **出す。** エラーの内容。利用者が見るべき情報だから   |
| コマンドとその出力         | **出さない**                                          |
| 読み取り・検索             | **出さない**（作業者側の調べ物であって成果ではない）  |

**判断の根拠**: 利用者が見たいのは「**何をしたか**」であって「どう調べたか」ではない。テストの件数やエラーといった重要な結果は、**発話の詳細（レポート）側に必ず書かれる**ので、ツールの実行として重複して出す必要がない。あわせて、`Bash` の引数に秘密が入りうるという露出も消える。

## 解くべき論点

1. **「ファイルを変えた操作」をどう判定するか。** ツール名（`Edit` / `Write` / `NotebookEdit` など）で決め打ちにするか、他の手がかりがあるか。**未知のツール名が来たときにどちらへ倒すか**（出さない側へ倒すのが安全）
2. **失敗の判定。** `tool_result` に `is_error` があることは確認済み（`docs/requirements.md` 4.1 / 実装済みの `extractMainViewEntries`）。それで足りるか
3. **サブエージェントの起動をどう見せるか。** サイドバーに既に同じ情報がある（`T-012` で実装済み）。**二重に出すのか、メインビューでは別の見せ方にするのか**

## やること

1. `src/transcript.ts` の `extractMainViewEntries`（読む層）か `src/view.ts` の `buildMainBody`（決める層）のどちらで絞るかを決める。**「決める」層で絞るほうが素直**（読む層は事実をそのまま返し、何を見せるかは決める層の責務）
2. 上の表のとおりに絞る
3. `docs/requirements.md` 4.2 の「各表示物」のメインビューの記述を、この決定に合わせて直す

### 当時のタスク本文

ビューの更新のたびに画面がチカチカするのを直す。

## 背景

**ユーザーが実際に使って報告した**（2026-09-10）: 「描画のたびにチカチカする」。

現在の実装は、SSE で新しい本文を受け取るたびに **`innerHTML` を丸ごと差し替えている**（`src/view.ts` の各ビューの購読スクリプト）。差し替えのたびに要素が作り直されるため、画像の再読み込み・スクロール位置の巻き戻り・一瞬の空白が起きる。

キャラビューの立ち絵にはフェードインの CSS アニメーションが付いており、**更新のたびに再生される**のもチカチカの一因になっている可能性がある。

## 解くべき論点

1. **どこまで作り直しを減らすか。** 変わった部分だけを差し替えるには、サーバが「何が変わったか」を知っている必要がある。**全体を送って、クライアント側で前回と比べて変わったところだけ当てる**（差し替え前に文字列比較する）だけでも大半は消えるはず
2. **立ち絵のフェードを、表情が変わったときだけにする方法。** 今は要素が作り直されるたびに再生される
3. **メインビューのスクロール位置。** 作業の進行が積まれる場所なので、更新で位置が飛ぶと読めない

## やること

1. **まず原因を切り分ける。** 実際に更新を繰り返して、何がチカチカの主因かを確かめる
   （毎回の `innerHTML` 差し替えか、画像の再読み込みか、アニメーションの再生か）
2. 主因から順に潰す。**「本文が前回と同じなら差し替えない」だけで直るなら、それで止める**
3. 直したことを目視で確かめられる形にする（何を見れば直ったと言えるか）

## 完了条件

- チェックコマンドが通る
- **本文が変わっていないときに DOM を差し替えないこと**をテストで固定する
- ユーザーが実機で見て、チカチカが解消していることを確認する。結果を `evidence` に書く

## 背景

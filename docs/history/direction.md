## 2026-09-09 「二重表示の何が厳しいか」への回答（本質）

大まかな問題点は2つ。

1. asuna が出力するものは詳細な情報+会話のためのセリフ。実現したいのは、詳細な情報と会話の
   ためのセリフを分離して別々のペインに表示することでノイズを減らしてキャラクターとのやり取りを
   楽しみつつ仕事したいというものだよ。
2. 詳細な情報の部分が結構理解しづらいことも多いよ。ここを人間にとってわかりやすくフォーマット
   したうえで会話と分けて出せると仕事が捗る気がする。

### 補足（メインセッションの読み。タスク化のときに確かめること）

**これは `docs/requirements.md` 1章の目的そのものの書き換えになる。** 現在の要件は
「最新の assistant 発話を吹き出しに出す」だが、本当の目的は**出力を「セリフ」と「詳細」に
分離して別ペインに出し、詳細は人間に読みやすく整形すること**。吹き出しはその手段の一部。

分離の手段が最大の論点。少なくとも3案ある:

- **(a) 出力スタイル側に規約を入れて、モデルが構造的に書き分ける**（例: セリフは決まった位置に置く）。
  決定的で安上がりだが、`~/.claude/output-styles/asuna.md` の変更が要り、TUI の見え方にも影響する
- **(b) tsukumo 側がヒューリスティックで分類する**（コードブロック・表・パスは詳細、地の文はセリフ）。
  変更は tsukumo 内で閉じるが、判定が壊れやすい
- **(c) 小さいモデルに分離・整形させる**。2つ目の「読みやすく整形」にも同時に効くが、
  コストと遅延が乗り、`docs/requirements.md`「会話内容の扱い」（外部に送らない）と衝突しうる

**2つ目の「理解しづらい」の正体を先に切り分けること。** 見た目の問題（Markdown が素のまま出る）なら
レンダラを作れば済み、中身の問題（情報が多い・順序が悪い）なら要約や再構成が要る。前者なら (c) は不要。

## 2026-09-09 前提の訂正と Q1〜Q3 への回答

**前提**: tsukumo とは「キャラクターと一緒に楽しく仕事をするためのターミナル環境」。
この目的に沿うなら要件に入れてよい。詳細な情報とセリフの分離は**その手段の1つ**。

- **Q1（分離をどこでやるか）→ (a) 出力スタイル側に規約を入れて、モデルが構造的に書き分ける**
- **Q2（「理解しづらい」の正体）→ 見た目が主、で合っている。**
  実例として挙がったのは、メインセッションが書いた「目視確認の手順」の応答
  （見出し＋箇条書き＋コードブロック＋注意書き2件が一度に並ぶもの）。
  「いろんな情報があってすぐに頭に入らなかった」「見やすく HTML で描画できたりするといいけどねぇ」
- **Q3（TUI ペインに何を残すか）→ 正直不要まである。**
  入力専用・表示専用・キャラクターとのやり取り専用、と完全分離できると biim っぽくなる

### 補足（メインセッションの観察）

**ユーザーが実例として貼り返した応答は、貼られた時点で表示が途中で欠けていた**
（「衣装は当面「不明」のま の payloadにしか載らなくて」のように、行の途中が飛んでいる）。

## 2026-09-09 Orca 依存と画面レイアウトの決定

**まずは Orca 前提でよい。**

- **左下**: 立ち絵＋セリフ
- **右下**: 入力（claude の TUI）
- **右サイドバー**: その他情報

**比率の指定**: 上段と下段で縦の仕切り位置が違う。

- **上段**: ブラウザ（広い） ＋ サイドバー（狭い）
- **下段**: 立ち絵＋セリフ（半分） ＋ 入力（半分）

サイドバーは入力の上に乗る位置関係だが、**サイドバーだけは狭い**ので、上段の仕切りは
下段より右寄りになる。

```
┌────────────────────────────────────────┬────────┐
│ ブラウザ                                │サイドバー│
│  詳細をHTMLで描画（広い）                │ （狭い） │
│                                        │        │
├─────────────────────┬──────────────────┴────────┤
│ 立ち絵＋セリフ（半分） │ 入力 claude TUI（半分）      │
└─────────────────────┴───────────────────────────┘
```

先に上下で割り、**上段と下段をそれぞれ別々に左右分割**すれば組める
（`orca terminal split` の呼び順がそのまま対応する）。

# chara-terminal — ターミナルにキャラクター立ち絵＋吹き出しを出す

作成: 2026-09-08 / 決定: **案C（サイドカー pane）で行く**

## ゴール

Claude Code との会話を、立ち絵付きの吹き出しでターミナルに表示する。

## 調査結果（2026-09-08 時点）

### 既存でやれること

- **`/buddy`** — Claude Code 本体の companion 機能。バイナリ v2.1.263 に
  `companion_intro` という内部リマインダ種別が実在するのを確認済み。
  入力欄の横に ASCII ペットが住み、10秒おきに吹き出しで喋る。18種、ユーザーID から決定論的生成。
- **claude-code-mascot-statusline** (TeXmeijin) — statusline に半角ブロックのピクセル絵マスコット。
  11個の hook イベントで表情9状態、context 消費で毛色が赤くなる。
  **キャラパックが YAML/JSON で差し替え可能**。
  https://github.com/TeXmeijin/claude-code-mascot-statusline
- **VOICEVOX / ずんだもん hooks** — Stop hook で応答を読み上げ。音声のみ、絵は出ない。

### 空いている穴

「**Claude の発話そのものを、立ち絵＋吹き出しで見せる**」ものは存在しない。

## 技術制約（設計の勘所）

Claude Code の TUI は自分で全画面を描画する。したがって:

- `claude | cowsay` のようなパイプ噛ませは**不可**
- hook の stdout はエスケープされてテキスト扱いになるため、
  そこから ANSI や画像プロトコルを流し込むのは**不可**
- → **本体の描画には割り込まない**設計にする。これが案Cを選ぶ理由。

## 採用アーキテクチャ（案C: サイドカー pane）

別ペインで常駐するプロセスが、セッションの JSONL を tail して立ち絵＋吹き出しを描く。
本体と描画が競合しないので何でもできる。

```
┌─────────────────┬──────────────────┐
│ claude (本体TUI) │ サイドカー        │
│                 │  ┌────────────┐  │
│  通常の会話      │  │  立ち絵     │  │
│                 │  └────────────┘  │
│                 │  ╭────────────╮  │
│                 │  │ 最新の発話  │  │
│                 │  ╰────────────╯  │
└─────────────────┴──────────────────┘
       │                    ▲
       │ 書く                │ tail
       ▼                    │
  ~/.claude/projects/<slug>/<session-id>.jsonl
       ＋ hook が書く状態ファイル（表情・モデル）
```

### データ源（実証済み）

最新の assistant 発話を抜くワンライナー。動作確認済み:

```bash
jq -r 'select(.type=="assistant") | .message.content[]? | select(.type=="text") | .text' \
  ~/.claude/projects/<slug>/<session-id>.jsonl | tail -1
```

- transcript は `~/.claude/projects/<cwd をスラッグ化>/<session-id>.jsonl`
- hook には `transcript_path` が渡るので、SessionStart hook で既知の場所に書いておけば
  サイドカーが追従先を知れる
- JSONL の type 分布（実測）: `assistant` / `user` / `attachment` / `mode` /
  `permission-mode` / `last-prompt` / `ai-title` ほか

### 機能

- **立ち絵**: VS Code ターミナルは `terminal.integrated.enableImages: true` +
  `gpuAcceleration` で Sixel / iTerm inline 画像が通る → ドット絵でなく本物の立ち絵が出せる
- **表情差分**: hook イベントで切替（PreToolUse=作業中 / Stop=どや顔 / エラー=あわあわ）
- **モデル別の衣装**: haiku=軽装 / sonnet=通常装備 / opus=戦闘配置。
  既存の Asuna output style の掛け声分岐と対応させる
- **タイプライター表示** ＋ VOICEVOX の口パク同期（後回しでよい）
- 副産物: ただのログ tailer なので Codex / Gemini CLI にも流用可能

### 併走させるもの（案B）

statusline 側にも小さいマスコットを出す。mascot-statusline をフォークし、
**hook が書く状態ファイルをサイドカーと共有**すれば二重実装にならない。

## 環境メモ（2026-09-08 実測）

- macOS (Darwin 25.6.0), zsh
- ターミナル: **VS Code 統合ターミナル** (`TERM_PROGRAM=vscode`, `TERM=xterm-256color`)
- あり: `node` (nodebrew), `jq`
- なし: `tmux`, `chafa`, `viu`, `timg`, `img2sixel`, `cowsay`, `deno`, `bun`

  **設定を足すときは既存の orca エントリを壊さないこと**

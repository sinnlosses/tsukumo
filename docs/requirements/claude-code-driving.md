## 4. 機能要件

### 4.1 Claude Code の駆動

**Agent SDK の `query` を、ストリーミング入力モードで1つ動かす**
（`@anthropic-ai/claude-agent-sdk`）。**セッションは tsukumo 1プロセスにつき1つ**（起こし直した
ときは新規のセッションから始める。4.8）。入力欄から送られたテキストは同じ `query` への追加入力として流し込み、
実行中の中断も SDK の経路で行う。

受け取るイベントと、その行き先:

| イベント                               | 行き先                                                                                                  |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `assistant` のテキスト                 | **ターンの本文**。レポートとしてメインビューへ（4.2）                                                   |
| `speak` ツールの呼び出し               | **セリフ**と**表情**。キャラビューの吹き出しへ（4.2 / 4.3）                                             |
| `tool_use` / `tool_result`             | 作業の進行。帯の「いまの作業」へ（4.2）                                                                 |
| `canUseTool`                           | 許可プロンプトと、キャラクターからの質問。答え待ちにする（4.2）                                         |
| `system` の `init`                     | 使えるスラッシュコマンド（`slash_commands`）・モデル・許可モード                                        |
| `system` の `background_tasks_changed` | **バックグラウンドタスク**（ターンのあとも動くもの）。帯の「いまの作業」へ（4.2）                       |
| `system` の `task_notification`        | 背景で走らせた Bash の**終わりの時刻**（`tool_use_id` で結ぶ）。検証の行と依頼の手順の所要時間へ（4.2） |
| `system` の `api_retry`                | **再試行中**（何回目か・待ち時間・理由）。入力欄の経過時間の行へ（4.2）                                 |
| `rate_limit_event`                     | **利用上限**（上限に達した、枠と戻る時刻）。同じ行へ（4.2）                                             |
| `assistant` の `error`                 | API のエラーの種類。**失敗で終わったときの理由**になる                                                  |
| `result`                               | ターンの終わり方（完了・中断・失敗）。失敗はメインビューと同じ行へ                                      |

- **モデルと許可モードは SDK のオプションで渡す**（`/model` を入力文字列として送らない）。
  どちらも画面から切り替えられるようにする。**既定の許可モードは `auto`**（`default` だと
  読み取り専用以外が逐一 `canUseTool` に届く。実測は `docs/history/decision.md`）
- **既定のモデルは Opus、既定の effort は medium**（2026-09-12 のユーザーの指示では high。Opus 5.5 で API の既定が medium に下がり、同じ段でも前の Opus より多く考えるため、2026-09-24 に見直した）。
  **effort は帯から切り替えられる**（`applyFlagSettings({ effortLevel })` でセッションの途中から
  変えられ、変えた値は次のターンから hook 入力の `effort` に載って外から読める。実測は
  `docs/history/decision.md`）。**画面に表示するのは読み取った値**で、帯から送った値をそのまま
  出す形は採らない（読めない場合にだけ出さない、という判断はここから来る）
- **モデルと許可モードの既定は、画面（帯の右端の歯車）から変えて覚えさせられる**
  （`~/.tsukumo/state.json`。`docs/architecture/screen-design.md` 13.6）。上の Opus・`auto` は**覚えた値が無い・
  読めないときの同梱の既定**で、覚えた値があればそちらで起こす（効くのは起こすたび）。
  **帯から変えた値はそのセッション限り**で、既定を書き換えない。**既定に「全部許す」
  （`bypassPermissions`）は選べない**（全部許すのは起こしたあと帯からその都度選ぶ）
- **`thinking` は表示しない。** モデルの内部の思考なので、出すと事故になる
- **未知のイベント種別が来ても落ちないこと。** 種別は Claude Code の更新で増える（旧方針で
  transcript の `type` が実際に増えたのを観測している）
- **出力スタイル（`~/.claude/output-styles/asuna.md`）は SDK でもそのまま効く**（実測は
  `docs/history/decision.md`）。`init` はプロンプトを送るたびに届くので、「新しいセッション」の
  合図にしない
- **バックグラウンドタスクが終わると、claude は依頼なしで続きのターンを始める**（実測は
  `docs/history/decision.md`）。依頼に当たるメッセージは流れないので、**ターンの外で届いた
  `init` を合図に、記録を持たない続きのターンの始まり（`turn-resumed`）を補う**（`src/server/session-driver/core/self-started-turn.ts`。
  見え方は `docs/architecture/screen-design.md` 13.9「バックグラウンドタスク」）
- **中断は SDK の `interrupt()` で効く。** 中断されたターンの `result` は `error_during_execution`
  で終わり、同じセッションに続けて入力を送れる（中断前の文脈を保っている）
- **API がうまくいかなかったことを黙って捨てない**（2026-09-24 決定）。再試行中（まだ続く）・
  失敗で終わった（もう続かない）・利用上限に達した（いつ戻るか）の3つを、**入力欄の経過時間の行の
  1つの枠**に出す（強いほうを1つ。見え方は `docs/architecture/display/input-box.md`「入力欄」。仕事のときは
  再試行中を進み具合の帯、失敗の理由を失敗の塊が持ち、行に残すのは利用上限に達しただけ）。**利用上限が近い
  （`allowed_warning`）は出さない**（2026-09-27 ユーザー決定）。失敗で終わった
  ターンは、加えてメインビューのそのやり取りの頭の失敗の塊に、理由と次の手（同じ依頼を入力欄に戻す など）を
  残す（過去のターンを遡っても成功と見分けられるように）。**中断は失敗にしない**
- **出すのは型の決まった理由だけ**（エラーの列挙値・HTTP の状態コード・回数と待ち時間・利用上限の
  枠と戻る時刻）。`result` の `errors` の自由文は画面にもログにも流さない（会話の断片が混ざりうる。
  `docs/coding-standards.md`「会話内容の扱い」）。`rate_limit_event` の使用率は出さない（効いている
  枠1つぶんしか運ばない。枠ごとの使用率は下のプラン使用量が持つ）。`error` の付いた `assistant` の本文は今までどおり本文として扱う（出力の上限で切れた
  本物の本文のこともあり、Claude Code が作ったエラーの文面と見分ける印が無い）
- **5時間枠と7日間枠の使用状況（プラン使用量）は、知らせを待たずに SDK へ取りに行く**（2026-09-27
  決定）。口は `Query` の `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET({ skipBehaviors: true })`
  で、Claude Code が自分のログインで `/usage` と同じ値を取ってくる（60秒以内の取り直しは Claude Code の控えで
  答える）。**tsukumo は認証情報を読まない**。`skipBehaviors` は必ず `true`（手元の transcript の
  走査を起こさない）。名前のとおり実験中の口なので、呼ぶのは `sdk-` のアダプタ1本に閉じ、読めない形・
  失敗は「取れない」に畳む。運ぶのは2つの枠の使用率・戻る時刻・取った時刻だけ（出し方は
  `docs/architecture/display.md` 4.2「各表示物」のサイドバー。調べた結果は `docs/research/plan-usage.md`）
- **SDK も transcript（JSONL）を書くが、tsukumo はそれを読まない**

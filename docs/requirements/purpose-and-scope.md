## 1. 概要・目的

**tsukumo は、キャラクターと一緒に楽しく仕事をするためのターミナル環境である。**

立ち絵・吹き出し・セリフと詳細の分離・詳細ビュー・画面レイアウトは、**すべてこの目的のための
手段**であって目的ではない。**機能を足すかどうかは「この目的に沿うか」で決める**（手段の側から
「立ち絵ツールだからこれも要る」と発想しない）。

目的は2つの成分に分かれ、**どちらか一方だけでは足りない**:

- **キャラクターと一緒にいる感じがすること。** 応答が無機質なテキストの塊ではなく、
  キャラクターのセリフとして届く
- **仕事が捗ること。** 楽しさのために効率を落とさない。技術的な詳細は、セリフとは別の場所に
  人間が読みやすい形で出す

### 合格シーン（v1）

**プロジェクトのディレクトリで `tsukumo` と打つと1つの画面が開く。そこで依頼を打つと、左下の
キャラが話し、左上にレポートが出て、キャラが質問したら画面上のボタンで答えられる。Claude Code
の TUI は一度も見ない**（2026-09-11 のユーザーの言葉）。

これが v1 の合格ラインである。**機能を足すかどうかは、このシーンに近づくかで決める。**

### 「ターミナル環境」とは何を指すか

**道具立てはターミナルが中心**である。作業の中心はターミナル（Orca）の中にあり、tsukumo は
そこで1コマンドで起動する。ただしこれは**すべてをターミナルの文字で描く**という意味ではない。
**入力も表示も HTML** で、**Orca のブラウザタブ、または macOS の既定のブラウザ**に出す（4.2 / 4.7）。
**Claude Code の TUI は使わない**ので、利用者が見るのは tsukumo の画面だけになる
（2026-09-11 の方針転換。3章）。

境界はここに引く: **画面は1枚のページで完結し、視線と操作が別のアプリケーションへ
散らないこと。** 一体感が壊れるのは「ターミナルの文字でないこと」ではなく「別のアプリケーションへ視線と操作が
移ること」だと確認済み。Orca の中で起こせば Orca のタブに、外で起こせば既定のブラウザの1タブに出す
（2026-10-24 ユーザー決定。「Orca のウィンドウの中で完結する」境界を、Orca と既定のブラウザが並ぶ形へ改めた）。

**Orca と既定のブラウザは並ぶ「ページを表示するホスト」** であって、中身はホストを差し替えても動く Web アプリとして作る
（`docs/architecture/adr/0011-separate-shell-and-app.md`）。

### 実現の手段

**tsukumo が Claude Code を動かす。** Agent SDK（`@anthropic-ai/claude-agent-sdk`）で claude を
子プロセスとして起こし、会話・ツール実行・許可プロンプト・質問を構造化イベントで受け取って、
入力欄・レポート・吹き出し・ボタンを tsukumo が描く。**Claude Code の TUI は使わない。**
この形を採る理由は「3. 技術制約」、**2026-09-11 に TUI を使う形から転換した経緯**と採らなかった案は
`docs/architecture/adr/0008-sdk-instead-of-tui.md` が正典。

**tsukumo が磨くのは、レポートを分かりやすく表示することと、キャラクターが魅力的に話すこと**（2026-10-07
ユーザー決定）。作業を段に分けて測り、帯とレポートに描くのも tsukumo の機能で、段は tsukumo が定めた口
（`work_plan`・`report`）で受ける。**特定のスキルの約束事には依存しない**（口と Beads の欄は
`docs/architecture/workflow-contract.md`、境界の判断は `docs/architecture/adr/0024-no-skill-dependency.md`）。

名前は付喪神から。長く使った道具に魂が宿るように、ターミナルという道具に姿と声を与える。

## 2. スコープ

### 2.1 対象とすること

- **Agent SDK で Claude Code を動かす**（4.1）。セッションは tsukumo 1プロセスに1つで、
  起こし直したら新規のセッションから始める（前のセッションへは切り替え画面から戻る。4.8）
- 画面の入力欄から依頼を送り、実行中は中断する。`/` でスラッシュコマンドを補完する
- セリフを MCP ツール `speak(text, expression)` で受け取り、吹き出しに出す（4.2）
- **ターンの本文**をレポートとして HTML に整形し、メインビューに**リアルタイムで**出す
- 許可プロンプトとキャラクターからの質問を、メインビューのお伺いの札で（数字キーでも）答えられるようにする（4.7）
- 作業の進行（実行中のツールと、その依頼での手順）を画面の最上部の帯に、タスク一覧・
  セッション情報をサイドバーに出す
- メインビュー・キャラビュー・サイドバー・入力欄を1枚のページに組み立てる（4.7）
- 終えたタスク（Beads の閉じた課題）を日ごとに数えて画面に並べ、押したときだけ
  キャラクターに振り返ってもらう（4.11）
- `speak` の引数から表情を切り替える（4.3）
- キャラクターの素材と、表情の対応を差し替え可能にする
- ページを「どのホストでも動く Web アプリ」として保ち、ホスト（Orca のタブか既定のブラウザ）に依存する操作を
  1箇所に閉じる
- **どのプロジェクトのディレクトリでも `tsukumo` で起動でき、そのプロジェクト（cwd）を
  作業対象にする**（`claude` を打つのと同じ感覚。ユーザーの言葉「絶対条件」）

### 2.2 対象外とすること（スコープ外）

- **Claude Code のTUIへの描画割り込み**。割り込む経路が無く（「3. 技術制約」）、
  そもそも**TUI を使わない**
- Claude Code のフォーク・パッチ適用
- **端末（PTY）を自前で持つこと**（2026-09-11）。画面の中でシェルや TUI を動かすことはやらない。
  **設計上の余地も残さない**（2026-09-13。tsukumo 自身が Orca のタブの中にいて隣にターミナルが
  あるので、画面の中に端末を持つ用途が無いことを確認した。実験の経緯は
  `docs/architecture/adr/0008-sdk-instead-of-tui.md`）
- **起動時に選ばせる画面**（2026-09-13）。起動は**常に新規のセッションから**始めるので（2026-10-10。4.8）、
  起動のたびにどれを続けるかを選ばせる画面は作らない。**続けるセッションは起動後に帯のセッションの札から開く
  切り替え画面で切り替えられる**（2026-09-22。4.8）
- **ファイルの貼り付け**（2026-09-11。2026-09-21 に**画像だけを覆した**）。入力欄が
  ファイルの中身を受け取ることはしない — **`@` のファイル補完がパスを渡す道を既に持っている**
  （4.2 (5)）。パスのほうが素直に強く、大きさの上限が要らず、どんな種類でも通り、Claude Code が
  自分の `Read` で必要なだけ読む。**画像だけが例外**で、**クリップボードの画像にはパスが無い** —
  `@` で埋められない穴はそこ1つしかないので、貼り付けとドロップで受け取る（4.10）
- **Orca と macOS の既定のブラウザ以外のホストを作り込むこと。** ホストは Orca のブラウザタブ
  （`orca tab create --url`）と、既定のブラウザ（`open <URL>`）が並ぶ（2026-10-24 に既定のブラウザを足した）。
  どのホストで開くかは起動のしかたに属するので環境変数で選び、既定は自動で選ぶ
  （`docs/architecture/adr/0025-no-project-settings.md`）。VS Code 用・Linux の `xdg-open` などは作らない。
  手で確かめるのは Orca と macOS の既定のブラウザで、ほかは落ちずに開ければよい
  （`docs/architecture/adr/0015-single-host-port.md`）
- `orca` コマンドが無い環境で orca のホストを選んでいるときと、`open` が失敗したときは、**ビューを開くことを諦めて動作を
  続ける**（起動失敗にしない。URL は表示するので、手で開けば同じページが見える）
- **レポートの中身の要約・再構成。** 読みづらさの主因は見た目だと確認済みなので、整形は**見た目の範囲**に留める。
  中身を削る・並べ替える・言い換えることはしない。**`report` の本文から落とすのは、落としても
  意味が変わらない行だけ**（`conclusion` の繰り返し・定型だけの行・中身の無い見出し。
  2026-09-23 ユーザー決定の「検査 → 整形 → 描画」の整形の段。`docs/architecture/display.md` 4.2）
- **音声・口パク**（2026-09-13。2026-09-21 に**当面やらない**へ緩めた）。
  **いまの立ち絵は動くが話さない**。VOICEVOX の口パク同期は後回しで、MVP には含めない（4.2）
- 会話内容の外部送信・クラウドへの保存（「5. 実行環境・非機能要件」の会話内容の扱い）。
  **同じマシンのディスクに残すことはこれに当たらない** — 2026-09-21 に雑談の会話を、2026-09-26 に
  仕事の会話の一部（依頼の冒頭・最終レポートの結論・セリフ）を `~/.tsukumo/` の下へ残すと決めた
  （4.9「会話のアーカイブ」）。**外へ出さないことは
  変わらない。**
  **分離や整形のために会話を外部のモデルへ送ることも含めて対象外**（2026-09-21 補足、
  2026-09-25 に置き換え: **雑談の記憶を畳む定着の使い捨て `query()`（同じ claude）に雑談の逐語を
  渡して、あらすじを書かせるのはこれに当たらない** — 受けるのは同じマシンの claude の
  子プロセスで、送り先は動いている雑談と同じ Anthropic の API。「分離や整形のために外部のモデルへ
  送ること」は**別の事業者・別のサービスへ送ること**を指す、と読む。
  4.9「記憶の圧縮と忘却」）。
- キャラクター素材そのものの同梱・配布。**素材は利用者が自分で用意する**。権利の扱いを
  このリポジトリに持ち込まないため。**`persona.md` に書く人格の記述もここに数える**
  （2026-09-14。画像でなくても、既存の作品のキャラクターを書けば同じ問題になる）
- **複数セッション・常駐（client–daemon）へ広げること**（2026-09-21 に未決から落とした）。
  1つの画面で相手にするセッションは1つ。`SessionManager` はセッションを1つだけ持ち、鍵を
  持たない（切り替えは中で起こし直す。`docs/architecture.md`「セッションの復元と複数化」）。**格子のページ
  （`scripts/capture/open-room-grid.ts`）はこれに当たらない** — tsukumo の外で手で打つスクリプトが
  配る1枚の HTML で、各マスは動いている部屋（1画面＝1セッション）を iframe で覗くだけ。
  スクリプトは格子のタブがあるあいだだけ常駐し、読み込みのたびに部屋を並べ直す（タブを
  閉じると終わる）。tsukumo 自身は常駐のダッシュボードを持たない。**成果の日記書きで日記を書かせる
  使い捨ての問い合わせで claude の子プロセスが一時的に2つになることもこれに当たらない**
  （2026-09-25 決定。`SessionManager` は今までどおりセッションを1つだけ持つ。日記を1つ書いたら
  終わり、transcript を書かず、利用者の入力を受けない。4.11「振り返りの依頼」）。**雑談の定着の使い捨て `query()` も同じ扱い**（2026-09-25
  決定。1回ぶんのあらすじを返したら終わり、同時に1本だけ。4.9「記憶の圧縮と忘却」）
- **Electron などのスタンドアロンのアプリに包むこと**（2026-09-21 に未決から落とした）。
  ホストは Orca のタブと既定のブラウザのままにする。ただし**載せ替えられる形は保つ** — ホスト依存の操作は
  `showView` 1つに閉じてあり、包みたくなったらそこを差し替える
  （`docs/architecture/adr/0015-single-host-port.md`。候補は `docs/research/app-shell.md`）
- **statusline 側にも小さいマスコットを出すこと**（案B。2026-09-21 に節ごと落とした。
  経緯は `docs/history/decision.md`）
- Windows / Linux での動作保証。動けばよいが、確認するのは macOS のみ
- **日本語以外での応答・画面**（2026-10-03 ユーザー決定）。応答の言語は設定にせず、
  システムプロンプト・UI も日本語のまま
- **待ち時間にほかのキャラクターが訪ねてくる仕組み（訪問）**（2026-10-07 に取りやめた）

### 2.3 想定利用者

個人利用（作者本人）。**macOS の Orca と、macOS の既定のブラウザを並ぶ環境とする**（2026-10-24 に Orca ファーストをやめた）。
対応ブラウザは `Temporal` を持つもの（Chromium 系と Firefox 139 以降）。持たないブラウザ（Safari など）では描き始めずに案内だけを出す（2026-10-26 決定。polyfill は入れない）。

**作者の運用が揃っていない環境でも、落ちず、黙って機能を欠かさない**（2026-10-03 ユーザー決定）。
作者の運用とは Beads・`main` という名の主ブランチ・orca を指す。Beads には依存してよく、それを制約とする
（2026-10-07 ユーザー決定）。特定のスキルには依存せず、ワークフローの契約だけを見る
（`docs/architecture/workflow-contract.md`。判断は `docs/architecture/adr/0024-no-skill-dependency.md`）。
前提が無いときは、その前提に頼る機能を出さないか、何が無いかを画面で言う。「不明」へ倒して
空の欄を見せるだけにしない。値を変えられるようにするときの置き場は
`docs/architecture/adr/0025-no-project-settings.md`（環境変数・歯車の設定の2つ）。ワークフローが持つ値（スキルの並び）は
`.tw/config.toml` に置いたまま、ワークフローの設定コマンド（`docs/architecture/workflow-contract.md`「設定コマンド」）で歯車から見せて書き、
`tw` が無い・口を持たないときは欄を出さずに何が無いかを言う。

Orca と既定のブラウザは「ページを表示するホスト」として並び、VS Code 統合ターミナルは対象にしない。
ただし**ホストに頼む仕事はページを開くことと、レポートのパスを開くことだけ**になったので、ホストの差し替えは
現実的な選択肢として残っているが、**包むのは当面やらない**（2026-09-21 に 2.2 へ移した）。

## 6. 既存のものとの関係（なぜ作るのか）

**空いている穴**: 「**キャラクターと一緒に仕事をする環境**」として、セリフと詳細を分けて
別々の場所に出すものは存在しない。先行の3件（`/buddy`・claude-code-mascot-statusline・
VOICEVOX hooks）はいずれも**Claude Code の出力に絵か音を添える**もので、出力そのものの見せ方を
組み替えてはいない。tsukumo が埋めるのはここ。

それぞれが何をするものかは `docs/research/prior-art.md`（2026-09-08 の調査。2026-09-21 に移した）。

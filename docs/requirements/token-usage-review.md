## 4. 機能要件

### 4.12 トークン消費の見直し

**トークン消費の画面の「減らし方を見てもらう」は、仕事の会話へ依頼を送らず、押すたびに会話とは別の
使い捨ての問い合わせを起こしてスキル `token-usage-diet` を流し、結果を tsukumo の MCP ツールで構造のまま受け取る**
（2026-09-24。別の問い合わせにしたのは 2026-10-12、`docs/architecture/adr/0029-usage-review-own-query.md`。
語は `docs/glossary.md`「見直し」「見直しの段」「提案」、画面は `docs/architecture/screen-design.md` 13.2）。
tsukumo 本体は分析しない。**スキルと集計スクリプトは tsukumo に同梱する**（`plugin/` を SDK の
プラグインとして載せ、`tsukumo:token-usage-diet` の名で呼ばれる。2026-10-04）ので、利用者のホームに
スキルが無くても見直しが流れる。タスク運用のスキルは tsukumo-plugins を git submodule（`vendor/tsukumo-plugins`）で
コミット固定して取り込み、同じく SDK のプラグインとして載せる（2026-10-08）。
ただし利用者が同じスキルとエージェントを設定ディレクトリにリンクで入れていれば、二重に並ばないよう載せない（2026-10-10）。集計は python3 で走る（5. の実行時の依存）。

- **ツールは2つ**: 段の進みを渡す `usage_review_stage` と、結果を1回で渡す `usage_review_result`。
  段は**いまの段だけ**を運び、並びより前を済と読む。載るのは**見直しの問い合わせだけ**で、仕事の会話・
  雑談には載らない（入力欄から見直しを頼むと、スキルは本文のレポートで返す）
- **段の右の数（モデル・キャッシュ・ツール）はスキルから受け取らない。** tsukumo の集計
  （見直しの期間で引いたトークン消費の集計）から出す。スキルの書き間違いが画面に出ない
- **見直しの寿命は仕事の会話のターンと関係しない。** 問い合わせを起こしたときに見直し中になり、経過は
  そこから数える。問い合わせが終わったら（結果を渡したかどうか・止めた・失敗・時間切れのどれでも）終わり、
  結果を渡さずに終わればふだんへ戻る。仕事のターンの終わり・会話の終わり・起こし直しでは動かない。
  結果は次の見直しまで残り、プロセスを起こし直すとふだんから始まる
- **押せないのは、見直しか提案の実行が1つ走っている間だけ。** 仕事のターンの進行中も雑談中も押せる。
  見直し中のセリフは見直しの区画にだけ出し、会話の吹き出しには出さない
- **提案の識別子は種類 + 対象**。種類はスキルの候補に揃えた固定の列挙で、列挙の外は断る
  （言い回しの揺れで見送りが黙って効かなくなるため）。種類を足すときはスキルと一緒に直す。
  提案の数には上限がある（`MAX_USAGE_PROPOSALS`）
- **押す口は「tsukumo に頼む」と「タスクにする」の2つ**。押したときの依頼文は提案に持たせず、
  tsukumo が見出し・やること・根拠から組む（スキルが書く欄を増やさない）。**起動先の `.beads` が
  読めない（タスク運用なし）なら「タスクにする」の提案を受け付けない**。
  段の戻り値でそれを伝え、呼ぶたびに `.beads` を読み直す
- **提案の実行**: 押す口は、仕事の会話へ送らず、提案ごとに会話とは別の使い捨ての問い合わせを起こす。
  画面は提案を識別子で指すだけで、依頼文はサーバが結果から引いた提案で組む。トークンの画面には許可を尋ねる
  場所が無いので、**押したことを同意とみなし**、許す道具を押す口ごとに絞る。実行の様子（頼んでいる・済んだ・
  できなかった・止めた、経過、直近のセリフ）はその提案の札に出す
- **受け付けない結果**: 空の見出し・空の欄・上限を超える件数・識別子の重なり・見送った提案・
  タスク運用なしでの「タスクにする」。
  理由と直し方を返して呼び直させ、状態は変えない（`report` と同じ線）
- **見送り**: 画面から見送った提案の識別子をホームに残し、以後の見直しから外す。見送った一覧は
  `usage_review_stage` の戻り値で渡す。**取り消す口は画面に
  無い**（ホームのファイルから手で消す）。見送りは会話へ送らないので、ターン中でも押せる
- **前回の結果**: ホームに**直前の1回だけ**を上書きで残し、「前回の提案」として出す（履歴を並べて
  選ぶ画面は作らない）。プロセスの起こし直しをまたいで残り、見送った提案はそこからも除いて出す
- 残すのは結果と識別子だけで、会話の文面は残さない。見直しと提案の実行の問い合わせは transcript を作らない
  （`docs/coding-standards.md`「会話内容の扱い」）

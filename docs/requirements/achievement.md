## 4. 機能要件

### 4.11 成果の振り返り

**終えたタスク（Beads の閉じた課題）を日ごとに数えて画面に並べ、ボタンを押したときだけキャラクターにその日の
日記を書いてもらい、日記を後から読み返せるように残す**（2026-09-24 に数えて感想を言ってもらう形で
決め、2026-09-25 に日記を書いて残す形へ広げた。2026-10-08 に、コミットの数をやめて閉じた課題だけで数えると決めた）。1章の2つの成分のうち「一緒にいる感じ」を、仕事の結果の側から足すもの。目的は
「キャラクターが自分の仕事をちゃんと見ていてくれて、それが後から読み返せる形で積もっていく」
こと。画面の形は `docs/architecture/screen-design.md` 13.10、状態に入れず取りに行く決まりは `docs/architecture.md`
「成果は `SessionState` に入れない」、日記の保存の形は `src/server/diary/adapter/diary.ts` の冒頭。

**決まっていること**（蒸し返さない）:

- 見せ方は**区切りでまとめて振り返る**だけ。その場で反応するもの（`done` になった瞬間・節目の
  数に届いた瞬間）は作らない
- **キャラクターが自分から成果に触れる経路は足さない**（2026-10-05 利用者決定）。区切りの迎えの
  挨拶に前日・今日の成果を混ぜる案と、`done`・節目の瞬間に一言触れる案を比べ、成果の画面と日記だけの
  今の形を保つと決めた。タスクを終えたことは Claude Code がそのターンの締めの `speak` で話しており、
  瞬間に触れる案はそれと二重になり、終える件数が多い日や並行する作業ツリーの分でうるさくなる
- **数えるのは Beads の閉じた課題だけ**（2026-10-08 利用者決定）。git の枝もコミットも読まない。
  閉じた課題は作業ツリーに依らないので、並行する作業ツリーで終えた分も二重にならずに入る。
  どの枝へ送るか・PR に留めるかはワークフローの持ち物で、tsukumo は主ブランチを知らない
- 区切りは**ローカル時刻の日**（0時で切る。日の境目は OS のタイムゾーンで、
  `src/server/adapter/local-time.ts` の1箇所が決める）。前の日へ遡れる
- 置き場は帯の口に足す1枚の画面（「成果」）
- キャラクターは、画面のボタン（「<キャラクターの名前>と振り返る」）を押したときに、**会話の
  セッションとは別の使い捨ての問い合わせ**で**専用のツール `diary` で日記を書く**（下の「日記」
  「振り返りの依頼」。2026-09-25 に、会話へ1ターンの依頼を送る形から改めた）。**会話のメインビュー・
  キャラビュー・会話の文脈には何も残らない**。**画面を開いただけでは書かせない**。押しても画面は
  会話へ移らない
- **会話のターン中でも振り返れる**。同時に書かせるのは1日ぶんだけ（書いているあいだは次の
  振り返りを断る）
- **卒業と節目は tsukumo が数える**（モデルに選ばせない。下の「卒業と節目」）。依頼にも載せる
- **前日比と連続日数は数えない**（数を競わせる画面にしない）
- **見る日が読めない・今日より先なら今日に倒す**（断らない）。「今日」はサーバのローカル時刻で
  決め、ブラウザは時計を読まない
- **取り直す契機**: 画面を開いたとき・日を切り替えたとき・窓にフォーカスが戻ったとき、今日を
  見ているあいだは 60 秒ごと（暦も同じ）、日記が書き上がったときはその日と暦。タスク板の
  `tasks-changed` には繋がない（着手の印の出入りでも飛ぶため）。振り返りの画面なので1分の遅れは
  問題にしない
- **数えられない・読めないときの出し方**は、下の「数えられない・読めないとき」の表

#### 数えられない・読めないとき

どの読みが欠けたら何を出すかの正典（2026-10-05 利用者決定を含む）。数える途中の `bd` の
失敗・時間切れは部分的な数を出さず「取れなかった」にする。読むのは Beads だけなので、Beads が読めなければ
成果のどの部分も出さない（終えたタスクだけ「数えられない」にする場面は無い）。

| 場面                                                                              | 数の札   | 暦                                                   | 日記・しおり・節目                                                                                                  | 1行の注記                                                            |
| --------------------------------------------------------------------------------- | -------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `.beads` が無い・`bd` が無い                                                      | 出さない | 出さない                                             | 出さない。日の切り替え・ボタンも出さない                                                                            | 「このディレクトリでは成果を数えられない（Beads の課題が読めない）」 |
| 取りに行って失敗した（`.beads` があるのに `bd` が落ちた・時間切れ、応答が落ちた） | 出さない | 別に取るので、取れていれば出す。取れなければ出さない | 出さない。日の切り替えは使える                                                                                      | 成果は「成果を取れなかった。」、暦は「灯りの暦を取れなかった。」     |
| 日記のファイルが読めない                                                          | 出す     | 出す                                                 | 日記が無い日と同じに出す（数・卒業・節目は出る）。ボタンで書き直すと、読めなかったファイルは新しい1段落で置き換わる | 無し                                                                 |

#### 何を数えるか

| 数えるもの   | 規則                                                                                                                   |
| ------------ | ---------------------------------------------------------------------------------------------------------------------- |
| 終えたタスク | Beads の課題のうち、閉じた時刻（`closed_at`）がその日のうちにあるもの（下の「`done` になった日」）。閉じ方は見分けない |

**進めたことは、タスクの題で足りる。**

- 完了したことの本文（何を・なぜ・どう検証したか）は課題ごとに別の場所にあり、並べても題とほぼ同じ行が
  2度出るだけで、振り返りの画面で読む量ではない
- タスクを通さずに済ませた仕事（会話で頼まれた作業）は数に出ない。コミットの数で拾っていたが、
  数える枝を決めるのに主ブランチを知る必要があり、それはワークフローの持ち物なのでやめた（2026-10-08）

**取り下げた課題も終えたタスクに数える**のは、取り下げの印が Beads の組み込みの欄に無く、スキルが足したラベルでしか
見分けられないため（`docs/architecture/adr/0024-no-skill-dependency.md`）。

#### `done` になった日

**Beads の閉じた課題の、閉じた時刻（`closed_at`）のローカルの日で決める**（2026-10-05 利用者決定）。
その日の始まりから終わりまでに閉じた課題を、その日に終えたと
数える。`bd list` を1回読み、閉じた時刻で振り分ける。

- **読むのは Beads だけ。** git の履歴にあるタスクの置き場のファイルは読まないので、
  Beads へ移す前の日の終えたタスクは数に出ない
- 画面と依頼に出すのは、課題の題（`title`）
- **`.beads` が無い**（`bd where` が見つけない・`bd` が無い）リポジトリ（tsukumo をほかのプロジェクトで
  起こしたとき）の出し方は「数えられない・読めないとき」。
  **`.beads` があるのに `bd` が落ちた・時間切れ**のときは「取れなかった」にする（黙って少なく数えない）
- **リポジトリごとの設定ファイルは無い**（2026-10-08。`docs/architecture/adr/0025-no-project-settings.md`）。Beads だけを読む

#### 卒業と節目

画面の「小さな驚き」に出し、振り返りの依頼にも載せる、その日に起きた特別なこと
（2026-09-25 決定）。**どちらも tsukumo が数え、モデルには選ばせない**（数え間違いが日記に
書かれない。見るたびに同じものが出る）。区切りの値は**プロトタイプとしての仮の値**で、使い
ながら直す。

**先輩タスクの卒業**: その日に終えたタスク（上の「`done` になった日」）のうち、**登録から7日以上
経っていたもの**（仮）。

- **登録日は、Beads の課題を作った日**（`created_at` のローカルの日）。登録から N 日は
  「終えた日 − 登録日」の日数
- git のタスクファイルから Beads へ移した課題は、移した日が登録日になる（タスクファイルの履歴を
  読まないため。2026-10-05 の利用者決定の帰結として受ける）
- 並びは登録の古い順（長く待っていたものほど先）。数に上限は置かない（仮）

**節目**: **通算 N 件目のタスク**。その日の終わりまでに閉じた Beads の課題の数（上の「`done` になった日」と
同じ規則）が、刻み（仮に 250 件ごと）の倍数をその日にまたいだとき。2026-10-08 にコミットの節目（通算 N コミット目）を外した。

- **何件目になったのがどれか**: 前の日の終わりまでの数に、その日に終えたタスクを閉じた
  時刻の順に足していって N に届いたもの
- 1日に節目を2つまたいだら（刻みより多く進んだ日）、大きいほう1つだけ出す

#### 灯りの段階

灯りの暦（`docs/architecture/screen-design.md` 13.10）の1日ぶんの明るさ。**その日に閉じた Beads の課題の数で決める**
（2026-10-08。見開きの灯りも同じ。区切りは仮）:

| 段階     | 閉じた課題の数 |
| -------- | -------------- |
| 灯りなし | 0              |
| ほのか   | 1〜9           |
| ともる   | 10〜39         |
| 明るい   | 40 以上        |

- 閉じた時刻は、暦のために読む `bd list` 1回の結果から日ごとに数える
- 暦の応答は、マスの数が何の数かを運ぶ欄を持たない（数えるのは閉じた課題の1種類だけ。2026-10-08 に、コミットの数と閉じた課題の数を見分ける欄を消した）
- 区切りは 2026-09-25 にコミットの数に合わせて、ふつうの日が「ともる」〜「明るい」に入るように置いたもの。
  閉じた課題の数に替えても区切りは変えない。このリポジトリの閉じた課題は 2026-09-27〜10-08 に
  1日 8〜63 件・中央値 41 件（同じ期間のコミットは 27〜176 件・中央値 57 件前後）で、ふつうの日が
  「ともる」〜「明るい」に入る狙いがそのまま成り立つ（2026-10-08 の実測）。**別のリポジトリでは
  明るくなりにくい**（見直すのは、使ってみて段階が偏ったとき）
- **空の日**（その日に閉じた課題が0）は灯りなしで、振り返りも押せない（`docs/architecture/screen-design.md` 13.10
  「空の日・数えられないとき」）。タスクを通さずに済ませた仕事だけの日も空の日になる

#### 日記

**振り返りの問い合わせでキャラクターが `diary` ツールで渡す、その日の1ページ**（2026-09-25 決定。
語は `docs/glossary.md`「日記」、保存の形は `src/server/diary/adapter/diary.ts` の冒頭）。

- **渡すもの**: 本文（キャラクターの口調で、その日の仕事について書く短い文）・しおり（その日に
  終えたタスクの ID と、それを選んだ理由）・表情（`speak` と同じ表情の一覧から）。しおりは
  終えたタスクが無い日だけ省ける
- **tsukumo が足すもの**: 書いた時刻、書いた時点のパックの名前と顔（パックのディレクトリ名と
  表示名。あとでキャラクターを替えても、誰が書いたかが残る）
- **置き場はホームの下に、リポジトリごと・日付ごと**。日付は振り返った日ではなく**振り返りの
  対象の日**。リポジトリは作業ツリーではなく共有の `.git` で見分ける（同じリポジトリの別の
  作業ツリーから書いても、同じ日記帳に入る）
- **同じ日に2回振り返ったら書き足す**: 本文は新しい段落として後ろに足し、しおりは新しいほうに
  差し替える。書き直し（前の段落を消す）はしない
- **問い合わせが `diary` を受け付けられずに終わったら「書けなかった」**を画面に出し、ボタンを戻す
  （時間切れ・失敗・起こし直しで中断したも同じ）。受け付けられない呼び出し（しおりの ID がその日に
  終えたタスクに無い・本文が空など）は理由を返して呼び直させる（`report` と同じ線）
- **受け付けない呼び出し**（仮の上限）: 同じ問い合わせで2回目・本文が空か 600 文字を超える・
  終えたタスクがあるのにしおりが無い・しおりの ID がその日に終えたタスクに無い・理由が空か
  120 文字を超える・保存に失敗した
- **書いたパックの顔は画像を写さず、ディレクトリ名で指す**（仮）。パックを消すと名前だけになる
- **しおりにはそのときのタスクの題を写して残す**（あとで課題が消えても読める）
- **仕事でも雑談でも、同じ形で書ける**（会話のモードに関わらない）。会話に入らないので、会話の
  アーカイブにも残らない（4.9「会話のアーカイブ」）
- 日記は会話の写しではない（キャラクターがツールで渡す成果物）。ただし文面はログに出さず、
  ホームの外へ出さない（`docs/coding-standards.md`「会話内容の扱い」。`docs/architecture.md`「会話内容と安全」）

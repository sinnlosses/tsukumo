# tsukumo 要件定義: セッションの復元の条件

ステータス: **ドラフト**。入口は `docs/requirements.md`（要件定義の全体）。

責務: 4.8 セッションの復元の後半。別の窓で使用中のセッション、いつ復元するか、復元できなかったときどうするか。
読む時: 別の窓との取り合い・起動やモードの切り替えで続きから起こすか・復元の失敗に触るとき。
直す時: 復元する契機・使用中の扱い・失敗の扱いを変えたとき。

## 4. 機能要件

### 4.8 セッションの復元

#### 別の窓で使用中のセッション

**別の窓で動いている tsukumo がいま開いているセッションは、切り替え画面で選べない**。
一覧を部屋（ポート）の縛りから外すと別の窓のセッションも並ぶので、上の混線をこれで塞ぐ。経路と採らなかった案は
`docs/architecture/adr/0026-session-claim-file.md`。

- **使用中は、生きているほかの tsukumo が占有ファイルに書いたセッションIDだけで決める。** 各 tsukumo は
  いま持っているセッションのIDを `$TSUKUMO_HOME/session-claim/<pid>.json` に書き、読む側は
  そのプロセスが生きているものだけを数える。**ポートの塞がりと印の目印は見ない**
- **占有ファイルに書くIDは「いま持っているもの」。** 続きから起こしたらそのID、新規なら最初の依頼で ID が届いてから、
  `/clear` で ID が変われば新しいほう。セッションが終わった・プロセスを閉じたら消す。
  **占有ファイルにはセッションIDしか書かない**（会話・見出し・要約は書かない。`docs/coding-standards.md`「会話内容の扱い」）
- **落ちた tsukumo の占有ファイルでは使用中にならない。** プロセスがもういない占有ファイルは、読んだ側が捨てて消す
- **行は隠さず、選べなくして「別の窓で使用中」と出す。** 自分の窓のいまのセッションは「いま」の行のままで、
  使用中にはしない。見え方は `docs/architecture/screen-design.md`「切り替え画面」
- **聞くのは切り替え画面を開くたび**（手続き `sessionClaim.occupied`）。画面は待たせず、答えが届くまでは
  全行を選べるまま描く。起こすたびに流す一覧には載せない（別の窓があとで開いたものを知らずに古くなるため）
- **起こす直前にもう一度確かめて断る。** `session.switchSession` は起こし直す前に、選んだIDを自分の占有ファイルに
  足してから他の占有ファイルを読み、同じIDがあれば足したIDを外して断る（いまの駆動は閉じない）。
  2つの窓が同時に同じIDを選んだときは両方が断る側に倒れ、2重の `resume` にはならない。
  断られた画面は切り替え画面を開き直し、その行が「別の窓で使用中」で出る

#### いつ復元するか

**起動・キャラクターの切り替えは、常に新規のセッションから始める**。
続きから起こしても `/clear` することが多く手間だったため、「常に自動で続きから始める」を覆した。
**モードの切り替えは、戻す先のモードの直前のセッション（このプロセスが覚えているもの）の続きから起こす**
（雑談を挟むと仕事の続きが失われるため、モードの切り替えに限って「新規から始める」を覆した）。
覚えていない（tsukumo を起こし直したあと・そのモードに入るのが初めて）・他の窓が使用中なら新規で起こす。
キャラクターを切り替えたら覚えを捨てる（セッションの印はパックごとなので、別のパックでは続きにできない）。
起動のたびに選ばせる画面は作らない（手数が増えるうえ、「1コマンドで起動」という 4.6 の狙いと衝突する）。
新規で起こす環境変数は、起動が常に新規なので持たない。
前のセッションへ戻る口は、始め方の一覧の「前回の続き」の札と、切り替え画面で行を選ぶことの2つ。
おかえりの一言は、切り替え画面から前のセッションを選んで再開したときだけ出る。

#### 復元できなかったときどうするか

**新しいセッションとして起動し、プロセスは落とさない。** セッションIDが古い・transcript が
消えている・`listSessions` が読めない、のいずれも「前提不足」ではなく「動作中の一時的な失敗」
として扱う（`docs/coding-standards.md`「エラーハンドリング」。起動時の即時終了は前提不足だけ）。
**画面の履歴の組み直しに失敗したときも同じ**で、会話（`resume`）だけ生きていれば続行する。

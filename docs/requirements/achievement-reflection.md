## 4. 機能要件

### 4.11 成果の振り返り

#### 振り返りの依頼

ボタン（または見開きの「この日を振り返る」）を押すと、振り返りのコマンドが見ている日付を
tsukumo へ送り、**tsukumo がその日の成果を数え直して依頼文を組み立て**、**会話のセッションとは
別の使い捨ての問い合わせ**に1回渡す（下の「会話から切り離す」）。**依頼文は tsukumo が数えたもの
だけから組み立てる**（キャラクターにファイルやログを読みに行かせない。数え直しで画面と話が
食い違わないように、そして1回の問い合わせで済むように）:

```
9月23日の成果を一緒に振り返って、この日の日記を書いてほしい。終えたタスクは 31 件。
終えたタスク:
- <課題の ID> 帯のトグルといまの作業の札を見本の値に揃える
- …
小さな驚き:
- 先輩タスクの卒業: <課題の ID>（登録から 12 日）
- 節目: 通算 500 件目のタスク
日記は diary ツールで1回書いて。本文はこの日の仕事の感想とねぎらいを短く。しおりには終えたタスクから1件を選び、選んだ理由を添える。ファイルやログは読みに行かず、この一覧だけで書いてほしい。次にやることの提案はいらない。
```

- **日の言い方**は「今日」「昨日」、それより前は「9月21日」の形
- **並べるタスクは20件まで**。超えたら「ほか n 件」の1行に畳む（1日に数十件終える日があり、
  依頼が長いと問い合わせが重くなる）。終えたタスクが0件の日（空の日）は振り返りを断るので、
  依頼文は常に終えたタスクの一覧としおりの頼みを持つ
- **小さな驚きは、あるときだけ**「小さな驚き:」の行を出す（卒業は ID と登録からの日数、節目は
  数）。**本文で触れるかはキャラクターに任せる**
- **その日に既に日記があれば**、「この日の日記は既にあるので、続きとして書き足す」の1行を足す
  （前の本文は載せない。書き足す段落だけを書いてもらう）
- **モードで文面を変えない**（`report` の1行は足さない。問い合わせには `report` ツールが無い）
- **キャラクターに書いてほしいのは感想とねぎらい**で、評価や指摘ではない。表情は指定しない
  （`diary` の `expression` はキャラクターが選ぶ）。口調は `persona.md` に任せ、依頼文には
  書かない（原則4。キャラクターの中身をコードに書かない）
- 依頼文に入るのは数とタスクの ID・`summary` だけで、会話の文面は入らない
  （`docs/coding-standards.md`「会話内容の扱い」）。会話に入らないので、画面のどこにも依頼文は
  出ず、会話のアーカイブにも残らない

**会話から切り離す**（2026-09-25 決定。元の指示は同日のユーザーのフィードバック「振り返りを会話から
独立させたい」。起こし方の形は `docs/architecture/core-and-adapter.md`「使い捨ての `query()`」）:

- **書かせるのは使い捨ての問い合わせ**（会話とは別の claude の子プロセス）。
  持たせるのは `diary` ツールだけで、ファイルを読む道具も `speak` も `report` も持たせない。
  **人格（`persona.md` の全文。雑談で覚えたことの節も含む）は効かせる**。日記を1つ書き終えたら
  終わり、transcript を残さない（続きから始めるセッションの一覧にも出ない）
- **会話のセッションには何も残らない**: メインビューに依頼文・レポート・ターンが増えず、
  キャラビューにセリフが出ず、会話の claude の文脈にも入らない（次のターンのキャラクターは
  日記を書いたことを知らない。受け入れる）
- **会話のターン中・答え待ちの最中でも押せる**。押せないのは、別の日（または同じ日）の日記を
  いま書いているあいだだけ。書いているあいだにキャラクター・モード・セッションを切り替えると、
  書くのをやめて「書けなかった」と同じに扱う（起こし直すと画面は初期状態に戻るので、ボタンは
  戻る）
- **トークン消費の記録（`~/.tsukumo/token-usage/`）には数えない**。記録の
  1行は会話のセッションの1ターンで、押したときだけの短い問い合わせを混ぜる軸が無い。消費が
  目立ってきたら、そのとき数え方を足す
- **書き手のモデルは会話のいまのモデル**（日記は後から読み返す物なので、会話と同じ声で書かせる。
  軽いモデルは使わない）。考える段は切る。呼び直しの余地は4ターン、**120 秒で
  諦める**（どちらも仮）
- **疑似セッション（`TSUKUMO_DRIVER=fake`）では書かせない**（押すとすぐ「書けなかった」になる）
- **進みは3段で見せる**（段のツールは足さない。1回の `diary` の呼び出しで済む短い問い合わせで、
  段ごとにツールを呼ばせると往復が増えるため）:

| 段                   | 入る合図                                                             |
| -------------------- | -------------------------------------------------------------------- |
| この日のタスクを読む | 振り返りを受けて書き手に渡した                                       |
| 日記を書く           | `diary` の呼び出しが書かれ始めた                                     |
| いちばんを選ぶ       | 書かれている引数に `bookmark` が現れた（本文の途中は画面に流さない） |

欄の順を守らずしおりを先に書くと2段目をすぐ抜け、しおりの無い日は3段目に入らない。どちらも
見え方が飛ぶだけで、書き上がりは `diary` を受け付けたことで決まる

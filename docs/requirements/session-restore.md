## 4. 機能要件

### 4.8 セッションの復元

**起動・キャラクターの切り替えは常に新規のセッションから始め、雑談と仕事のモードの切り替えは戻す先のモードの
直前のセッションの続きから起こす**（2026-10-10・2026-10-11 決定。2026-09-13 の「常に自動で続きから始める」を
覆した。経緯は `docs/history/decision.md`）。前のセッションへ戻る口は2つ — 始め方の一覧の「前回の続き」の札（前の
セッションの残り〔`report` の `sessionRemaining`〕を新しいセッションへ送る。`docs/architecture/screen-design.md`）と、切り替え画面で行を選ぶこと
（その ID で `resume` する）。戻すものと戻さないものは、切り替え画面から選んで `resume` したときの話。

#### 何を戻し、何を戻さないか

| もの                                       | 戻す     | どうやって                                                |
| ------------------------------------------ | -------- | --------------------------------------------------------- |
| claude 側の会話（文脈）                    | 戻す     | `query({ options: { resume: sessionId } })`               |
| メインビューのやり取り（レポート・ツール） | 戻す     | `getSessionMessages(sessionId, { dir })` を読み直して組む |
| 吹き出しのセリフ                           | 戻す     | 同上（`speak` の呼び出しは transcript に残っている）      |
| 答え待ち（許可・質問）                     | 戻さない | 前のプロセスの `canUseTool` は既に解決されている          |
| 書きかけの本文（`partial-utterance`）      | 戻さない | 仮の表示なので、完成した本文だけを組み直せば足りる        |

#### tsukumo 側に会話を保存しない

**復元のために会話を保存しない。** claude 自身が `~/.claude/projects/` に transcript を
書いている（SDK の `Options.persistSession`。既定 `true`）ので、**そこを正典として読み直す**。
tsukumo 側のキャッシュ・スナップショットは作らない。

これは `docs/coding-standards.md`「会話内容の扱い」の**「別の場所に複製しない」を満たす**。
複製にあたるのは「transcript の内容を tsukumo が別の場所へ書き出すこと」であって、正典を
読んでメモリ上のビューを組み直すのは複製ではない（組み上がったビューは今までどおりプロセスの
メモリにしかなく、`127.0.0.1` にだけ配られる）。**規約を曲げる必要は無い。**

**2026-09-21 に足した会話のアーカイブ（4.9）は、ここを変えない。** あちらは**あとで
活用するため・記憶の材料にするため**に会話の一部を残すもので、**復元の材料にはしない** — 起こし直したときに画面を
組み直すのは今までどおり transcript からで、アーカイブを読み戻す経路は作らない。

#### 鍵（切り替え先の一覧に何を出すか）

**起動した作業ディレクトリ（`cwd`）＋ tsukumo が付けた印**の2つで絞る。**印はキャラクター
パックごとに違い**（`tsukumo:<パック名>`。2026-09-14 決定）、**雑談のときだけ後ろに `:chat` が
付く**（2026-09-20 決定。4.9）ので、実質は「ディレクトリ×キャラクター×モード」で1つの
セッションになる。

1. セッションIDが届いたら（`session-info`）覚えておき、**ターンが終わるたびに**
   `tagSession(sessionId, <そのパックの印>, { dir: cwd })` で印を付け直す。付けるのは `result` の直後で、
   待たない。**`init` の直後には付けない**（transcript がまだ無く、`tagSession` が投げる）。
   印は transcript の末尾に足す1行で、SDK も Claude Code も**末尾 64 KiB の中の最後の tag 行**しか読まない。
   Claude Code は書き足した量が 32 KiB を超えるたびに末尾を読み直して印を書き写すが、その前に 64 KiB を
   超えて書き足されると印は押し出されて消える。**消えても次のターンの終わりに付け直すので戻る**
   （実測は `docs/history/decision.md`）
2. **起動時に** `listSessions({ dir: cwd })` を読んで印の付いた一覧をメモリに持ち、起こすたびに
   その一覧のうち**これから起こすパックの印を持つもの**を切り替え先として画面へ流す（2026-09-28 決定。
   読むのに 0.2〜0.3 秒かかるので、起こすときはメモリの一覧を使う）。**1. で印が付いたら、持っている
   一覧にもその時刻で写す**。一覧は起こすたびに駆動を起こしたあとで読み直し、読めたら切り替え先の
   一覧を画面へもう一度流す（見出しと、外で増えた・消えたセッションはここで追いつく）。
   起こすセッションは一覧から探して選ぶことはしない（新規で起こす。続きになるのは画面で選ばれた ID だけ）。
   外で消された transcript を選んだときは、そのIDで `resume` して新規として起き上がる

**`cwd` は「起こしたリポジトリ」の意味で読む**（2026-09-22）。同じリポジトリでも worktree が
分かれていれば起こすたびに違うディレクトリになり、ディレクトリの文字列だけで絞ると
**前のセッションが切り替え先の一覧に一度も出ない**ので、`listSessions` には
`includeWorktrees: true` を渡して**同じリポジトリの worktree を全部見てから印で絞る**。
履歴を読み直す `getSessionMessages` はディレクトリで絞らない（セッションIDが一意なので、
絞らなくても別のものには当たらない）。**鍵の考え方（ディレクトリ×キャラクター×モード）は
変わっていない** — 「ディレクトリ」の粒度がリポジトリになっただけ。

`cwd` だけで絞らないのは、`tsukumo` がグローバルに入っていて**どのプロジェクト
からも起こせる**（4.6）ため。同じディレクトリで素の `claude` を使っていると、印が無ければ
そちらのセッションを拾ってしまう。**印は会話の内容ではない**ので、transcript に付けても
「会話内容の扱い」には触れない。

**パックごとに分けるのは、キャラクターごとに別の部屋を持たせるため**（`docs/architecture/character-pack.md`）。
切り替えて戻ってくると、そのキャラクターとの会話と口調が戻る（実測は
`docs/history/decision.md`）。ただし**印はターンが終わったときに
付く**ので、ターンを1つも終えずに離れたパックのセッションは切り替え先の一覧に出ない。

**同じ `sessionId` を2つの `query` から重ねて `resume` すると、別ファイルへ fork するのではなく
同じ transcript へ混線する**（2026-09-22 実測。測り方は `docs/history/decision.md`）。
**印だけでは「その目印がいま使われているか」は分からない**ので、下の目印はその前提に立つ。

**2026-09-22 決定: 印の末尾に「目印」を足し、同じディレクトリで何個 tsukumo を起こしても
セッションを取り合わないようにする**（`tsukumo:<パック名>@7327` /
`tsukumo:<パック名>:chat@7327`）。鍵は「ディレクトリ×キャラクター×モード×目印」の4つになる。
組み立ても読み取りも `src/server/session-driver/core/session-mark.ts`（`sessionTag` / `readSessionMark`）だけで、
文字列を他所で作らない。

- **区切りは `@`。** `:` を使わないのは、後置きの `chat` と読み違えないため。**目印は
  いちばん後ろの `@` から先**で、読み取りもそこだけを見る
- **目印はビューのポート番号そのもの**（同日決定。**セッションを指す ID は「キャラクターパック
  × ポート番号」**にする、という決めごとの後半がここに出る）。ポートを使うのは、**「その目印が
  いま使われているか」を知っているものが他に無い**ため — 印は transcript に残るだけなので、
  落ちた tsukumo の印と動いている tsukumo の印は見分けられない（上の混線）。ポートは OS が
  握っていて、**既定なら塞がっているぶんだけずれ**（4.6）、**プロセスが落ちれば空く**ので、
  生きている tsukumo の起動順がそのまま出る
- **落ちた側を起こし直すと、空いたポートへ戻る**。切り替え先の一覧はポートで絞らないので、落ちた側も
  動いている側のセッションも並ぶ（動いている側は「別の窓で使用中」で選べない。下）。起動そのものは新規から始まる（下の「いつ復元するか」）
- **畳まない。** 既定から遠い番号（`TSUKUMO_VIEW_PORT` で指したとき）も `0`（OS まかせ）も、
  そのまま名乗る（**ポート番号なら上限が無い**）
- **昔の印は読むときにポートへ戻す**（`readSessionMark` だけの仕事。transcript を書き換える
  手当てはしない）。**目印の無い印**（`tsukumo:<パック名>`）は既定の 7327、**1文字だった目印**
  （`@A` / `@B` …）は並び順から元のポート（`A` が 7327、+1 ごとに次の番号）。いま続いている
  仕事はそのまま見つかり、次にターンが終われば新しい形の印に置き換わる
- **印の一覧がそのままセッションの一覧**（`listMarkedSessions` が目印・`sessionId`・
  `lastModified`・始まった時刻（`startedAt`。SDK の `createdAt`）・見出し（`heading`。下）を新しい順に返す）。
  別の保存先は作らない。依頼の数・要約・最後のセリフは一覧に載せず、切り替え画面で選んだ1件ぶんだけ
  transcript から読む（`docs/glossary.md`「セッションの要約」）
- **切り替え先の一覧は、リポジトリの全作業ツリー × キャラクターパック × モードのセッション**
  （2026-10-10 決定。2026-09-23 の「いまの部屋の印を持つものだけ」を覆した。理由は
  `docs/history/decision.md`）。絞る鍵は目印を除いた印（`SessionMark.family`）で、**ポート（目印）では絞らない**。
  **行は作業ツリーの名前**（SDK の `cwd` の末尾のディレクトリ名。取れなければ `gitBranch`。どちらも無い
  セッションは載せない）**で見分け**、**作業ツリーを問わず新しい順**に並べて上限（`MAX_SESSION_CHOICES`）で
  切る（2026-10-11 決定。いまの作業ツリー〔`cwd` が起動した作業ディレクトリと同じ〕の行を先に数える
  取り決めを覆した）。新しい10件にいまの作業ツリーの行が無いときは、始め方の一覧の「前回の続き」の札と
  挨拶は出ない（同日、利用者が許した）。
  別の作業ツリーの行を選んでも、いまの作業ツリーで `resume` する。印の書き込み（`@<ポート>` の目印）は
  残す。**部屋の名前は一覧の行には出さない**（`docs/architecture/screen-design.md` 13.9「部屋の名前」）
- **切り替え画面の行の見出しは SDK の `summary` にする**（2026-09-23 決定。`customTitle` →
  自動要約 → 最初の依頼、の順に決まる表示用の題。`getSessionInfo` / `listSessions` が返す
  `SDKSessionInfo.summary`）。追加のモデル呼び出しで tsukumo が題を作ることはしない。
  `SessionChoice.heading` として運び、読めない・空なら無いものとして畳む
  （`src/shared/session/session-choice.ts`）。**`/clear` で分かれたセッションは別の行のまま**でよく
  （それぞれに中身の分かる見出しが付けば足りる）、前後をつなぐ仕組みは作らない。行の形
  （短縮ID・見出し・時刻・見出しが無いときの見え方）は `docs/architecture/screen-design.md`「切り替え画面」
  が正典。**画面から新しいセッションを起こす口**（切り替え画面の「＋ 新しいセッション」。
  `session.startNewSession`）は新規で起こす（2026-09-27 ユーザー決定。2026-10-10 からは起動・切り替えも同じ）

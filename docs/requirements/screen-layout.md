# tsukumo 要件定義: 画面レイアウト

ステータス: **ドラフト**。入口は `docs/requirements.md`（要件定義の全体）。

責務: 4.7 画面レイアウト（舞台と紙、1枚の HTML にまとめた形、狭い画面での見せ方）。
読む時: 舞台・紙・欄外・入力欄の役割・お伺いの置き場・重ねる紙・狭い画面の並びに触るとき。
直す時: 画面レイアウトの要件を変えたとき。

## 4. 機能要件

### 4.7 画面レイアウト

**キャラクターの舞台と、読む紙を並べる**（「舞台と紙」。ADR 0057）。biim システムの「ゲーム画面と立ち絵を同じ画面に置く」をリスペクトし、
**場所ごとに役割を1つだけ持たせ、同じ情報が2箇所に出ないようにする**ことが狙い。**狭い画面（760px 以下）では並べない**（下の「狭い画面」の段落）。

```
┌ 舞台 ───────────────┬ 紙の場所 ──────────────────────────┬ 欄外 ────────┐
│ 部屋の頭             │ 紙（始め方／紙の計画／レポート）       │ この部屋の    │  全部で1枚のHTML
│                      │                                      │ やり取り      │  ＝ブラウザタブ1つ
│ 吹き出し             │                                      │              │
│ 立ち絵               │ ┌ 入力欄（紙の下端に浮く）──────────┐ │              │
└─────────────────────┴──────────────────────────────────────┴──────────────┘
```

| 場所   | 中身                                                           | 対応する biim の要素 |
| ------ | -------------------------------------------------------------- | -------------------- |
| 舞台   | 部屋の頭・立ち絵・最新のセリフの吹き出し・手元の行             | 立ち絵・テロップ     |
| 紙     | 局面ごとの中身（始め方・紙の計画・レポート）                   | ゲーム画面           |
| 欄外   | この部屋のやり取りの一覧（雑談中は覚えていること・最近の話題） | タイム表・チャート   |
| 入力欄 | 依頼とお伺いの自由入力                                         | 実況者の手元         |

**許可と質問は、同じ形のカード「お伺い」にし、答え待ちのあいだは紙の下端の入力欄の場所に出す**（
形は `docs/architecture/screen-design/inquiry.md`「お伺い」）。キャラは吹き出しで「これいい？」と言うだけで、
tsukumo は吹き出しの文言を作らない。**入力欄はそのまま出したままにし**、質問の間だけ**選択肢にない答えを
書く場所**になる（打ちかけの文字はそのまま残る）。許可の間は、ふつうの下書きのまま。
それまでの「許可は入力欄の上の箱、質問はメインビューのカード」と覆した理由は
`docs/history/decision.md`「requirements.md 4.7 画面レイアウト（答え待ちの箱。2026-10-02 に覆した記録）」。

**紙の中身は、ターンの局面（迎える・働く・尋ねる・渡す・つまずく）で入れ替わり、器の形は姿勢（迎える・働く・渡す）で変わる**
（`docs/architecture/screen-design/conversation-phase.md`、`docs/architecture/screen-design/layout.md`）。

**舞台と紙は1枚の HTML にまとめ、CSS で場所を分ける。** ブラウザタブは1つだけで、
**ターミナルのペインは1つも要らない**（Claude Code の TUI を開かないため）。

**ほかの画面（タスク・成果・使用量・キャラクター・設定）は、会話の画面の上に右から重ねる紙で開く**（ADR 0057 論点 3）。
キャラクターの紙には立ち絵・差し色の差し替え・新しいパックを作るボタンを、設定の紙には画面の色3つ
（`ground` / `surface` / `ink`）などを置く。
**開閉は URL の hash**（`#tasks`・`#achievement`・`#token-usage`・`#character`・`#settings`）で、リロードしても同じ紙に
戻り、ブラウザの「戻る」が効く。**入口はサイドバーの入口の行と、探す（⌘K）の「移る」の群**（狭い画面は頭の「≡」から開く探す）。
会話の画面は紙を開いているあいだも出したままなので、会話は進み、入力欄の打ちかけも
残る。**答え待ちが来たら部屋の頭の状態の行が「答えを待っている」に変わる**（狭い画面は頭の状態の語）。部屋の頭と紙の入口は
`docs/architecture/screen-design/room-head-and-search.md` が正典。

**場所そのものは縦にだけスクロールし、横にはスクロールしない**。
**横に長いものは、中身の側が自前のスクロール容器を持つ**
（レポートの表は `.table-scroll` の中でスクロール、コードは折り返し、図は紙の幅に収め、
長い語は途中で折り返す）。

**狭い画面（760px 以下＝スマホ）では、舞台・欄外・部屋の頭を出さず、上から「頭・紙・顔と吹き出し・入力欄」の
縦の1列にする**（ユーザー決定。基準は 390x844。ADR 0057 論点 5）。スマホでやる「様子を見る」「聞かれたら答える」「止める」を親指の届く下半分に集めるのが狙い。

- **頭**: 顔・状態・やり取りの題・右端の「≡」。「≡」は探すの一覧を開き、「移る」の群からタスク・成果・使用量・キャラ・設定・仕事と雑談の切り替え・セッションの一覧へ移る
- **紙**: 広い画面と同じ中身
- **顔と吹き出し**: 舞台の立ち絵は出さず、入力欄の上に顔と**最新のセリフ1件**を出す。
  **作業中も常に出す**（答え待ちのときだけにしない）
- **答え待ちのカード**: お伺い（許可と質問）は入力欄の場所に出し、答えを押しやすいボタンで選ぶ
- **重ねる紙**: 画面の全面に重ね、閉じたら会話の画面へ戻る

全体の高さは **`100dvh`** に固定し（`vh` だとソフトウェアキーボードが出たときにページごと押し上がる）、
**スクロールするのは紙だけで、ページ全体はスクロールしない**。切れ目は `@media (max-width: 760px)` の
1つだけで、規則は各機能の CSS に分かれている（`docs/architecture/browser.md`「CSS」）。寸法・部品の行き先・見本に無い場面は
`docs/architecture/screen-design/narrow-screen.md` が正典。

**タスクのモーダル（レポートのタスク ID から開く、左に一覧・右に詳細のモーダル）とタスクの紙は、狭い画面では2列を
縦に積む**（「1タスク＝1枚のカード」は、表をやめたので置き換えた）。
一覧が上で高さを区切って内側でスクロールし、詳細が残りの高さで内側でスクロールし、下の操作の帯は箱の下端に
残す。組み替えるのは CSS だけで、部品の側は広い画面のまま書く（一覧と詳細を行き来する画面の
切り替えは持たない。セッションの一覧〔`docs/architecture/screen-design/room-head-and-search.md`「セッションの切り替え」〕の積み方と同じ）。
値は `docs/architecture/display/task-modal.md` 13.12。**レポートの中の表はこの対象ではない**（`docs/architecture/screen-design.md`
13.3「領域の内幅に入りきらない表は、その表だけ横スクロールさせる」）。

- **代償**: 舞台と紙を別々のウィンドウ（別モニタなど）に分けることはできない。今の構想では不要

# tsukumo 要件定義: 起動と設定

ステータス: **ドラフト**。入口は `docs/requirements.md`（要件定義の全体）。

責務: 4.6 起動と設定（1コマンドでの起動と、既存設定を壊さない制約）。
読む時: 起動のしかた・ポート・グローバルへの導入・ホストの選び方・`~/.claude/settings.json` に触るとき。
直す時: 起動と設定の要件を変えたとき。

## 4. 機能要件

### 4.6 起動と設定

- **プロジェクトのディレクトリで `tsukumo` と打つ**（開発中はリポジトリ直下の `pnpm run start`
  でも同じ）。tsukumo はローカルの HTTP サーバを立て、Agent SDK で Claude Code を起こし、
  ページをホスト（Orca のタブか既定のブラウザ）に開く。**利用者が並べる手間はゼロ**（1枚のページで完結する。4.7）
- **ビューを配るポートは既定 7327**（`TSUKUMO_VIEW_PORT` で変更可）。**既定のまま塞がっていたら**
  EADDRINUSE のあいだ +1 して20個先（7346）まで順に試し、空いた番号で待つ（複数のプロジェクトで
  同時に起こしても2つ目以降が起動できるように）。**`TSUKUMO_VIEW_PORT` を
  明示的に渡したとき（`0` を含む）はずらさず、そのポートで一度だけ試してそのまま失敗する**
  （指定したポートで待てないことに気づけなくなるため）。EADDRINUSE 以外の失敗（`EACCES` など）も
  ずらさない。20個全部塞がっていたら、試した範囲（7327〜7346）を伝えて終了コード1で終わる
  （黙って0番＝空きポート自動割り当てへは逃げない。どのポートで待っているか分からない状態を
  作らないため）。実際に待っているポートは起動時に stdout へ出る URL（`layoutUrl`）で分かる
- **グローバルへの導入は `pnpm add --global "link:<リポジトリ>"`**（`bun link` から `pnpm link` へ移したあと、pnpm 12 の `pnpm link` が `--global` を受け付けないのでこの形へ移した）。リポジトリの直下で
  `mise run setup` を打つと `~/Library/pnpm/bin/tsukumo` ができ、どのディレクトリからでも打てる。
  **リポジトリの `bin/tsukumo` へのリンク**なので、開発中の変更がそのまま次の起動に反映される。
  **tsukumo のリポジトリの作業ツリーの中で打ったときは、その作業ツリーの `bin/tsukumo` が起きる**
  （link 元でなく打った場所の版になる）。**消すときは `pnpm remove --global tsukumo`**。
  リポジトリの外に置かれるのは `~/Library/pnpm/bin/tsukumo` と `~/Library/pnpm/global/` 配下（pnpm の
  登録簿）の2つだけ。シェルの設定ファイルは、`~/Library/pnpm/bin` が `PATH` に無いときだけ
  `pnpm setup --force` が pnpm の区画を書き直す。**打つのは本体の作業ツリーの直下で、`tsukumo-N` の作業ツリーでは
  打たない**（打つとグローバルの `tsukumo` がその作業ツリーのコードに付け替わる）
- **cwd に依存してよいのは起動先プロジェクトのもの**（作業ディレクトリ・
  相対指定の素材）**だけ**で、**自分で持ち歩くもの（既定の立ち絵・`node_modules` の外部
  ライブラリ）は自分の場所から読む**（`tsukumo` 自身が置かれている場所からの相対。
  どのディレクトリで起こしても立ち絵が出る）
- **どのホストで開くかは `TSUKUMO_HOST` で選ぶ**（未設定・知らない値は自動で選ぶ。
  環境変数 `TERM_PROGRAM` が `Orca` なら `orca`、そうでなければ `browser`。
  `docs/architecture/adr/0022-three-setting-homes.md`）。起動時の URL はどれでも
  stdout に出る。`TSUKUMO_OPEN_VIEW=0` はどれでも起動時のタブを開くことだけを止める
  - `orca`: 起動時に Orca のタブを開く（同じページのタブが既にあれば貼り直す）。レポートのパスを
    押すと Orca のエディタで開く。**`orca` が無ければタブを開くのを諦め、URL を表示して動作を続ける**
    （起動失敗にしない）。そのときパスは押しても開かず、「ファイルを開けなかった」で断られる
  - `browser`: 起動時に macOS の `open` で既定のブラウザにページを開く（呼ぶたびに新しいタブになるが、
    呼ぶのは起動時の1回だけ）。レポートのパスを押すと、git 管理下のパスだけ `open` で OS の既定のアプリに開く。
    ブラウザのタブは tsukumo から閉じられない。**`open` が失敗したら開くのを諦め、URL を表示して動作を続ける**
  - `none`: 何も開かない（外部コマンドを起こさない）。起動時のタブは開かず、開かない理由を
    stderr に1行出すので、表示された URL を手でブラウザに開く。レポートのパスは押しても開かず、
    「ファイルを開けなかった」で断られる
- **`~/.claude/settings.json` に tsukumo のエントリを残さない。** 旧方針で足した hook は外す。
  ただし**このファイルの hooks と statusLine は orca（`~/.orca/agent-hooks/`）が専有している**
  ので、触るときは既存エントリを壊さないこと。上書きすると orca 側が黙って動かなくなる
- **入力は画面の入力欄から SDK へ直接渡す。** Orca 経由でターミナルへ文字やキーを送る経路は
  使わない（**Orca はエージェント端末への合成入力を弾く**。実測は `docs/architecture.md`
  「core と adapter」）

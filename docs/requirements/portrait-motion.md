# tsukumo 要件定義: 立ち絵の動き

ステータス: **ドラフト**。入口は `docs/requirements.md`（要件定義の全体）。

責務: 4.3 状態連動の後半。立ち絵を1枚の矩形として動かす範囲、レポートの書き上げの演出とミニ立ち絵、動いてよいとき。
読む時: 立ち絵の動き・書き上げの演出・ミニ立ち絵に触るとき。
直す時: 立ち絵の動きか、書き上げの演出の要件を変えたとき。

## 4. 機能要件

### 4.3 状態連動

- **立ち絵は動くが話さない**。演出はブラウザ側の `Portrait` 部品の中に閉じる
  （`docs/architecture/browser.md`「立ち絵の動き」）
- **立ち絵は「1枚の矩形」として扱う**。tsukumo が動かすのは**位置・大きさ・
  傾き・上下・不透明度**だけで、**素材の中身（目・口・腕）には触らない**。理由は 2.2 の
  「素材は利用者が自分で用意する」で、**素材がどう作られているかを当てにできない**から
  この割り切りにより、**SVG でも PNG でも GIF でも同じだけ動く**（パック作者に何も要求しない）
- **まばたきと表情のクロスフェードは作らない**（同上の帰結。素材の構造に依存するため）。
  表情は引き続き立ち絵そのものの差し替えで表す
- **`<Portrait>` が動ける範囲はキャラビューの領域の中だけ**（読書を妨げないため）。
  **ただし「レポートの上に被らせない」の線は、ミニ立ち絵に限って見直した**（元の指示と、それまでの線は `docs/history/decision.md`）。**認めるのは、いま書かれている本文の
  筆先に添う1体だけ**で、次を条件にする:
  - **書き上げる様子は、届いた順に部品をポンと出して見せる**（筆で行をなぞる形をやめた経緯は
    `docs/history/decision.md`「requirements.md 4.3 レポートの書き上げの演出（Z字の筆をやめた記録）」）。
    書いている途中のレポート（草稿）は、届いた部品をその場でポンと出し、ミニ立ち絵は次の部品を待つ欄の
    右の余白で揺れて書く仕草をする。部品が届くたびに小さく跳ねる
  - **草稿を描かずに確定版が一度に届いたレポート**（古い transcript の読み戻し・草稿の運びが切れたとき）は、
    **節ごとに上から順に、草稿と同じポンで出す**。塊は節の欄（`data-report-section`）1つで、節の後ろの欄
    （振り返り・お願い）は直前の節と一緒に出す。間隔は標準で 240ms・速いで 120ms、**全体は3秒に収める**
    （節が多いときは間隔を詰める）。出しているあいだ、ミニ立ち絵は次に出す節の頭の行の右で揺れる
  - **結論（`conclusion`）と検証結果（`checks`）は、ターンの確定と同時に最初から出す**（境目は頭の欄の入れ物
    `data-report-region="head"`）。**セクションが短いレポートは演出せずに出す**——頭の欄の外の
    文字数（図は1つにつき100字相当）の合計が 200 に満たないとき（速さの設定に依らない）
  - **文字を足していく実装にしない。** Markdown のソースを1文字ずつ増やして変換し直すと、表・
    mermaid・Chart.js が未完成のソースで作り直され、非同期に描く mermaid は途中の形で失敗する
    （塊ごとの `memo` も全部無効になる）。**DOM は完成品を一度に作り、出す前の節は場所を取ったまま隠す**
  - クリック・キー入力のどちらかで**即座に全部出す**。**ホイールと指では打ち切らない**。
    **過去のターンを見返すときは演出しない**（確定済みの本文は一度も「書かれない」）
  - **速さは歯車で開く設定のダイアログの「演出」の面から選べる**（標準／速い／切る の3つ）。
    **利用者の設定**（`localStorage`）なので、選び直しても出している最中の演出には効かない。
    値と置き場所は `docs/architecture/screen-design/setting-place.md` が正典
  - **やり取りの列は出た節から見出しを並べる**。列そのものは最初から確保する（出入りで本文が横へずれるため）
  - **素材は「あれば使う」。** `character.json` に任意の `mini` を置き、**無いパックは
    `portraits.default` の縮小に落ちる**（4.4「あるものだけでよい」に例外を作らない）。
    ミニ用の画像はリポジトリに同梱しない（2.2）
  - **2体見えることは「分身」として受け入れる**。キャラビューの立ち絵は
    消さず、ミニ立ち絵を明確に小さくして式神として見せる（**不透明**）。**書いている間だけ
    キャラビューを空ける案は採らない**（吹き出しの持ち主が居なくなる）
  - **書き上げたあとも消えず、本文の末尾に残る**。残った立ち絵は**本文に
    貼り付いて一緒にスクロールする**（筆先の座標をビューポートではなく本文の入れ物の原点で持つ。
    画面に固定する案は採らない）。**残る場所は本文の右下**——縦は末尾の行の下（そこに立ち絵の
    高さぶんの床を敷く）、**横は筆が止まったところではなく本文の右端**（経緯は `docs/history/decision.md`）。**見切れるところまでは寄せない**（隅に置くが姿は全部
    見える）。**消えるのは次に書き始めたときだけ**で、過去のターンへ切り替えたときにも依頼を
    送った時点でも消さない。**演出を途中で飛ばしたときも、筆が止まった場所ではなく同じ末尾に
    置く**——飛ばすと本文は全部出るので、途中に残るとまだ書いている途中に見える
  - `prefers-reduced-motion: reduce` では**演出ごと無効**にし、ミニ立ち絵も出さない
    （**演出が走らない場面で新たに出すことはしない**——過去のターンも同じ）
- **動くのは利用者の注意が空いているときだけ。** 判定の材料は `SessionState` に既にある
  （`turn` / `lastToolFailureAt`）。**どの動きを作るかは `docs/architecture/browser.md`「立ち絵の動き」が正典**。
  **長いアイドルのふるまい（座る・うとうと）は作らない**（席を外している時間で誰も見ていない）。
  **例外は依頼を待つ間の待ちの一言1回だけ**（利用者決定。上の「黙って立つだけの場面の埋め方」）で、
  動きは足さず、繰り返さない
- `prefers-reduced-motion: reduce` を尊重する（規則は `src/browser/styles/theme.css` にある）

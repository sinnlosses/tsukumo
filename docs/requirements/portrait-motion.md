# tsukumo 要件定義: 立ち絵の動き

ステータス: **ドラフト**。入口は `docs/requirements.md`（要件定義の全体）。

責務: 4.3 状態連動の後半。立ち絵を1枚の矩形として動かす範囲、レポートの書き上げの演出とミニ立ち絵、動いてよいとき。
読む時: 立ち絵の動き・書き上げの演出・ミニ立ち絵に触るとき。
直す時: 立ち絵の動きか、書き上げの演出の要件を変えたとき。

## 4. 機能要件

### 4.3 状態連動

- **立ち絵は動くが話さない**（2026-09-13）。演出はブラウザ側の `Portrait` 部品の中に閉じる
  （`docs/architecture/browser.md`「立ち絵の動き」）
- **立ち絵は「1枚の矩形」として扱う**（2026-09-13 決定）。tsukumo が動かすのは**位置・大きさ・
  傾き・上下・不透明度**だけで、**素材の中身（目・口・腕）には触らない**。理由は 2.2 の
  「素材は利用者が自分で用意する」で、**素材がどう作られているかを当てにできない**から
  この割り切りにより、**SVG でも PNG でも GIF でも同じだけ動く**（パック作者に何も要求しない）
- **まばたきと表情のクロスフェードは作らない**（同上の帰結。素材の構造に依存するため）。
  表情は引き続き立ち絵そのものの差し替えで表す
- **`<Portrait>` が動ける範囲はキャラビューの領域の中だけ**（読書を妨げないため）。
  **ただし「レポートの上に被らせない」の線は、ミニ立ち絵に限って見直した**（2026-09-20 決定。
  元の指示と、それまでの線は `docs/history/decision.md`）。**認めるのは、いま書かれている本文の
  筆先に添う1体だけ**で、次を条件にする:
  - **書き上げる様子は演出で作る。** レポートは確定するまで出ない（`docs/architecture/display/main-view.md` の
    「リアルタイムに流す」）ので、**流れている本文に添える筆先はどこにも無い**——
    出た時点で本文は全部そろっている。演出は**出そろった本文を「書き上げていくように見せる」**
    ものとし、ミニ立ち絵はその筆先に添う
  - **筆で書くのは節（`sections`）だけ**（2026-10-02 決定。覆した旧い決定と戻し方は
    `docs/history/decision.md`「requirements.md 4.3 レポートの書き上げの演出」）。**結論（`conclusion`）と
    検証結果（`checks`）は、ターンの確定と同時に最初から出す**（結論が筆で書かれて待たされないように。
    境目は頭の欄の入れ物 `data-report-region="head"`）。**節が短いレポートは演出せずに出す**——筆の対象の
    文字数（図は100字相当）の合計が 200 に満たないとき（速さの設定に依らない）
  - **文字を足していく実装にしない。** Markdown のソースを1文字ずつ増やして変換し直すと、表・
    mermaid・Chart.js が未完成のソースで作り直され、非同期に描く mermaid は途中の形で失敗する
    （塊ごとの `memo` も全部無効になる）。**DOM は完成品を一度に作り、見せる範囲だけを進める**。
    **文字を持たない図・グラフの塊は塊ごと出し**、ミニ立ち絵はその脇に立つ
  - **筆は1行ずつ追わず、塊1つをZ字で書く**（2026-09-20 決定）。塊の行を上下2つの帯に割り、
    帯ごとに左から右へなぞって、あいだを斜めに戻る——Z字の3画。**帯の切れ目は実際の行の box に
    合わせる**ので文字が上下に切れず、1行しかない塊は1画で書く
  - **なぞる右端は帯ごとに、その帯にある行のいちばん右**（2026-09-21 決定。枠でなぞっていた頃の
    数字は `docs/history/decision.md`）。**左端はどの帯も塊の左端で揃える**（行頭は揃っているので
    帯ごとに変えない）。**横画の時間は帯の幅で按分する**（等分すると、筆の速さが同じ塊の中で
    変わる）
  - **塊は「トピック」**（同日のユーザーの判断。**段落や表の1つ1つではない**）。見出しと
    水平線を境に、そこから次の境目までの要素をひとまとめにする。**帯は要素をまたいで1本に
    伸びる**ので、見出しと段落と表が同じ画で書かれ、図・グラフは筆が通り過ぎた割合が
    そのまま `opacity` になる。細かく割ると筆が何度も折り返して目で追えなくなる
  - **節の見出し（`##`・`###`）と図表の題は演出の対象から外し、最初から出す**（2026-10-17 決定。
    走り読みは見出しを先に拾うので、見出しが本文と一緒に書き上げられるのを待たせない。本文・表・図だけを書き上げる）
  - **演出の全体は10秒で終わる**（2026-10-17 決定。上の「塊ごとの速さ」を変えずに、全体にだけ10秒の
    上限を掛ける。注意が切れる目安の10秒を超えた分は、その時刻に残りを一度に出す。上限をまたぐ塊は
    そこまでに書き切る）。レポートの領域の右上に**「全部出す」の小さな口**を演出中だけ置き、
    押すと残りが一度に出る（クリック・キー入力で飛ばす仕組みは残す）
  - **速さは塊ごとに決める**（2026-09-20 決定。全体の上限は上の10秒だけ）。**塊の大きさ
    （中の文字数の合計）で按分し、1つあたり 2.4〜8秒**——文字1つあたり 40ms で、下限 2400ms・
    上限 8000ms に収める（図・グラフは文字数を持たないので、段落1つぶん＝100文字に相当させる）。
    **下限が大きいのは、1回のZ字をゆっくり書くため**——短い塊を文字数に素直に比例させると筆が
    飛んで見える。**塊の数で全体が伸びるのは10秒までで受け入れる。全体に予算を置いて按分する案は採らない（超えた分は按分せず、一度に出す）**
    （どちらの理由と実測も `docs/history/decision.md`）。読み始めが遅れるぶんは、クリック・
    キー入力のどちらかで**即座に全部出す**ことで引き受ける。**ホイールと指では打ち切らない**
    （2026-09-22 決定）。**過去のターンを見返すときは演出しない**（確定済みの本文は一度も
    「書かれない」）
  - **速さは歯車で開く設定のダイアログの「演出」の面から選べる**（2026-09-23 決定。2026-10-14 にポップオーバーからダイアログへ替えた。標準／速い／切る の3つで、
    **標準は上の値のまま**）。**利用者の設定**（`localStorage`）なので、選び直しても書いている
    最中の演出には効かない。値と置き場所は `docs/architecture/screen-design.md` 13.6 が正典
  - **塊の中は出だしと締めをゆっくり、真ん中を速く**（2026-09-22 決定。3次のイーズインアウトで、
    真ん中の速さは等速の3倍）。ミニ立ち絵が「そこで書いている」ように見えるのは筆が遅いところ
    だけなので、**見せたい両端に時間を寄せて、読み手が待つだけの真ん中を速く抜ける**。
    **塊の持ち時間そのものは変えない**ので、レポート全体の長さは変わらない
  - **`note` の注意・異常と、`options` の「採る」の行は、書き終えたところで筆を 400ms 留める**
    （2026-09-28 決定。`docs/research/report-block-richness.md` 4章。キャラクターが「ここ」と
    指しているように見える）。**留める長さは速さの設定（標準／速い）に関わらず一定**——読む
    速さのつまみではなく、大事な塊を指す強調の間なので連動させない。**留める時間は塊の
    「大きさで按分」した持ち時間の外に足す**（上のバケットに時間を含めない）ので、留めがあっても
    文字数に比例した書く速さそのものは変わらない。留める位置は DOM の実測ではなく文字数の重みの
    比例で決める（`src/browser/domain/reveal/plan.ts` の `pausesOf`）。対象の印
    （`report-pause-point`）は記法の語彙に無い class 名で、`NotationBlock` の置き換えを受けない
    （`src/shared/report/report-pause-point.ts`）
  - **書いているあいだは画面が筆先に付いていく**（2026-09-20 決定）。**追うのは帯ぜんたいでは
    なくミニ立ち絵の立つ位置**（帯の下端から立ち絵の高さぶん上まで。2026-09-23）。そこが器の
    上下の縁から 96px 以内に入ったら、その差だけ器を送る。**器がその範囲と上下の余白を両方とも
    収められないほど狭いときは、下端を優先する**。**器は根から上へたどって見つける**——転がる
    祖先は広い画面も狭い画面も `main[data-region="main"]` で、ページ自身は転がらない（`docs/architecture/screen-design.md` 13.9「狭い画面（760px 以下）」）。
    呼ぶ側が器を決め打ちにしないためである。**利用者が手で転がしたら、その演出のあいだ自動送りは降りる**（2026-09-22 決定。読む
    位置を選んだのは利用者のほうなので、筆が譲る）。**自動送りには上限がある**（2026-10-02 決定）——
    結論の上端が器の上の余白（96px）に入るところまでしか送らず、書き終えても結論が画面から流れない。
    筆先が器の下へ出たまま書き進むのは受け入れる
  - **やり取りの列は筆が届いた節から見出しを並べる**（2026-10-02 決定）。列そのものは最初から確保する（出入りで本文が
    横へずれ、筆の座標が狂うため）
  - **素材は「あれば使う」。** `character.json` に任意の `mini` を置き、**無いパックは
    `portraits.default` の縮小に落ちる**（4.4「あるものだけでよい」に例外を作らない）。
    ミニ用の画像はリポジトリに同梱しない（2.2）
  - **2体見えることは「分身」として受け入れる**（2026-09-20 決定）。キャラビューの立ち絵は
    消さず、ミニ立ち絵を明確に小さくして式神として見せる（**不透明**）。**書いている間だけ
    キャラビューを空ける案は採らない**（吹き出しの持ち主が居なくなる）
  - **書き上げたあとも消えず、本文の末尾に残る**（2026-09-21 決定）。残った立ち絵は**本文に
    貼り付いて一緒に転がる**（筆先の座標をビューポートではなく本文の入れ物の原点で持つ。
    画面に固定する案は採らない）。**残る場所は本文の右下**——縦は末尾の行の下（そこに立ち絵の
    高さぶんの床を敷く）、**横は筆が止まったところではなく本文の右端**（2026-09-23 決定。
    経緯は `docs/history/decision.md`）。**見切れるところまでは寄せない**（隅に置くが姿は全部
    見える）。**消えるのは次に書き始めたときだけ**で、過去のターンへ切り替えたときにも依頼を
    送った時点でも消さない。**演出を途中で飛ばしたときも、筆が止まった場所ではなく同じ末尾に
    置く**——飛ばすと本文は全部出るので、途中に残るとまだ書いている途中に見える
  - `prefers-reduced-motion: reduce` では**演出ごと無効**にし、ミニ立ち絵も出さない
    （**演出が走らない場面で新たに出すことはしない**——過去のターンも同じ）
- **動くのは利用者の注意が空いているときだけ。** 判定の材料は `SessionState` に既にある
  （`turn` / `lastToolFailureAt`）。**どの動きを作るかは `docs/architecture/browser.md`「立ち絵の動き」が正典**。
  **長いアイドルのふるまい（座る・うとうと）は作らない**（席を外している時間で誰も見ていない）。
  **例外は依頼を待つ間の待ちの一言1回だけ**（2026-10-05 利用者決定。上の「黙って立つだけの場面の埋め方」）で、
  動きは足さず、繰り返さない
- `prefers-reduced-motion: reduce` を尊重する（規則は `src/browser/styles/theme.css` にある）

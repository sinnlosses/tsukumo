## 1. 概要・目的

**tsukumo は、キャラクターと一緒に楽しく仕事をするためのターミナル環境である。**

立ち絵・吹き出し・セリフと詳細の分離・詳細ビュー・画面レイアウトは、**すべてこの目的のための
手段**であって目的ではない。**機能を足すかどうかは「この目的に沿うか」で決める**（手段の側から
「立ち絵ツールだからこれも要る」と発想しない）。

目的は2つの成分に分かれ、**どちらか一方だけでは足りない**:

- **キャラクターと一緒にいる感じがすること。** 応答が無機質なテキストの塊ではなく、
  キャラクターのセリフとして届く
- **仕事が捗ること。** 楽しさのために効率を落とさない。技術的な詳細は、セリフとは別の場所に
  人間が読みやすい形で出す

### 合格シーン（v1）

**プロジェクトのディレクトリで `tsukumo` と打つと1つの画面が開く。そこで依頼を打つと、左下の
キャラが話し、左上にレポートが出て、キャラが質問したら画面上のボタンで答えられる。Claude Code
の TUI は一度も見ない**（2026-09-11 のユーザーの言葉）。

これが v1 の合格ラインである。**機能を足すかどうかは、このシーンに近づくかで決める。**

### 「ターミナル環境」とは何を指すか

**道具立てはターミナルが中心**である。作業の中心はターミナル（Orca）の中にあり、tsukumo は
そこで1コマンドで起動する。ただしこれは**すべてをターミナルの文字で描く**という意味ではない。
**入力も表示も HTML** で、**Orca 自身のブラウザタブ**に出す（4.2 / 4.7）。**Claude Code の TUI は
使わない**ので、利用者が見るのは tsukumo の画面だけになる（2026-09-11 の方針転換。3章）。

境界はここに引く: **Orca のウィンドウの中で完結し、外部ブラウザ（Chrome など）へ飛ばないこと。**
一体感が壊れるのは「ターミナルの文字でないこと」ではなく「別のアプリケーションへ視線と操作が
移ること」だと確認済み。

**Orca は「ページを表示する箱」**であって、中身は箱を差し替えても動く Web アプリとして作る
（`docs/architecture/adr/0011-separate-shell-and-app.md`）。

### 実現の手段

**tsukumo が Claude Code を動かす。** Agent SDK（`@anthropic-ai/claude-agent-sdk`）で claude を
子プロセスとして起こし、会話・ツール実行・許可プロンプト・質問を構造化イベントで受け取って、
入力欄・レポート・吹き出し・ボタンを tsukumo が描く。**Claude Code の TUI は使わない。**
この形を採る理由は「3. 技術制約」、**2026-09-11 に TUI を使う形から転換した経緯**と採らなかった案は
`docs/architecture/adr/0008-sdk-instead-of-tui.md` が正典。

**tsukumo が磨くのは、レポートを分かりやすく表示することと、キャラクターが魅力的に話すこと**（2026-10-07
ユーザー決定）。作業を段に分けて測り、帯とレポートに描くのも tsukumo の機能で、段は tsukumo が定めた口
（`work_plan`・`report`）で受ける。**特定のスキルの約束事には依存しない**（境界は
`docs/architecture/adr/0024-no-skill-dependency.md`）。

名前は付喪神から。長く使った道具に魂が宿るように、ターミナルという道具に姿と声を与える。

## 2. スコープ

### 2.1 対象とすること

- **Agent SDK で Claude Code を動かす**（4.1）。セッションは tsukumo 1プロセスに1つで、
  起こし直したら前の続きから始める（4.8）
- 画面の入力欄から依頼を送り、実行中は中断する。`/` でスラッシュコマンドを補完する
- セリフを MCP ツール `speak(text, expression)` で受け取り、吹き出しに出す（4.2）
- **ターンの本文**をレポートとして HTML に整形し、メインビューに**リアルタイムで**出す
- 許可プロンプトとキャラクターからの質問を、メインビューのお伺いの札で（数字キーでも）答えられるようにする（4.7）
- 作業の進行（実行中のツールと、その依頼での手順）を画面の最上部の帯に、タスク一覧・
  セッション情報をサイドバーに出す
- メインビュー・キャラビュー・サイドバー・入力欄を1枚のページに組み立てる（4.7）
- 終えたタスク（Beads の閉じた課題）を日ごとに数えて画面に並べ、押したときだけ
  キャラクターに振り返ってもらう（4.11）
- `speak` の引数から表情を、モデルから衣装を切り替える（4.3）
- キャラクターの素材と、表情・衣装の対応を差し替え可能にする
- ページを「どの箱でも動く Web アプリ」として保ち、箱（いまは Orca のタブ）に依存する操作を
  1箇所に閉じる
- **どのプロジェクトのディレクトリでも `tsukumo` で起動でき、そのプロジェクト（cwd）を
  作業対象にする**（`claude` を打つのと同じ感覚。ユーザーの言葉「絶対条件」）

### 2.2 対象外とすること（スコープ外）

- **Claude Code 本体のTUIへの描画割り込み**。割り込む経路が無く（「3. 技術制約」）、
  そもそも**TUI を使わない**
- Claude Code 本体のフォーク・パッチ適用
- **端末（PTY）を自前で持つこと**（2026-09-11）。画面の中でシェルや TUI を動かすことはやらない。
  **設計上の余地も残さない**（2026-09-13。tsukumo 自身が Orca のタブの中にいて隣にターミナルが
  あるので、画面の中に端末を持つ用途が無いことを確認した。実験の経緯は
  `docs/architecture/adr/0008-sdk-instead-of-tui.md`）
- **起動時に選ばせる画面**（2026-09-13）。復元は**常に自動で続きから**なので、起動のたびに
  どれを続けるかを選ばせる画面は作らない。**続けるセッションは起動後に帯のセッションの札から開く
  切り替え画面で切り替えられる**（2026-09-22。4.8）
- **ファイルの貼り付け**（2026-09-11。2026-09-21 に**画像だけを覆した**）。入力欄が
  ファイルの中身を受け取ることはしない — **`@` のファイル補完がパスを渡す道を既に持っている**
  （4.2 (5)）。パスのほうが素直に強く、大きさの上限が要らず、どんな種類でも通り、Claude Code が
  自分の `Read` で必要なだけ読む。**画像だけが例外**で、**クリップボードの画像にはパスが無い** —
  `@` で埋められない穴はそこ1つしかないので、貼り付けとドロップで受け取る（4.10）
- **Orca 以外の箱を第一級に作り込むこと。** いまの箱は Orca のブラウザタブで、開くのに
  `orca tab create --url` を使う。2026-10-03 に「いま2つ目の実装は作らない」を外し、
  **Orca 以外で開くホストの実装も持つ**（どのホストで開くかは起動のしかたに属するので環境変数で
  選ぶ。`docs/architecture/adr/0022-three-setting-homes.md`）。ただし手で確かめるのは Orca だけで、
  ほかのホストは落ちずに開ければよい（`docs/architecture/adr/0015-single-host-port.md`）
- `orca` コマンドが無い環境で orca のホストを選んでいるときは、**ビューを開くことを諦めて動作を
  続ける**（起動失敗にしない。URL は表示するので、手で開けば同じページが見える）
- **レポートの中身の要約・再構成。** 読みづらさの主因は見た目だと確認済みなので、整形は**見た目の範囲**に留める。
  中身を削る・並べ替える・言い換えることはしない。**`report` の本文から落とすのは、落としても
  意味が変わらない行だけ**（`conclusion` の繰り返し・定型だけの行・中身の無い見出し。
  2026-09-23 ユーザー決定の「検査 → 整形 → 描画」の整形の段。`docs/architecture/display.md` 4.2）
- **音声・口パク**（2026-09-13。2026-09-21 に**当面やらない**へ緩めた）。
  **いまの立ち絵は動くが話さない**。VOICEVOX の口パク同期は後回しで、MVP には含めない（4.2）
- 会話内容の外部送信・クラウドへの保存（「5. 実行環境・非機能要件」の会話内容の扱い）。
  **同じマシンのディスクに残すことはこれに当たらない** — 2026-09-21 に雑談の会話を、2026-09-26 に
  仕事の会話の一部（依頼の冒頭・最終レポートの結論・セリフ）を `~/.tsukumo/` の下へ残すと決めた
  （4.9「雑談の会話のアーカイブ」）。**外へ出さないことは
  変わらない。**
  **分離や整形のために会話を外部のモデルへ送ることも含めて対象外**（2026-09-21 補足、
  2026-09-25 に置き換え: **雑談の記憶を畳む定着の使い捨て `query()`（同じ claude）に雑談の逐語を
  渡して、エピソードとあらすじを書かせるのはこれに当たらない** — 受けるのは同じマシンの claude の
  子プロセスで、送り先は動いている雑談と同じ Anthropic の API。「分離や整形のために外部のモデルへ
  送ること」は**別の事業者・別のサービスへ送ること**を指す、と読む。
  4.9「記憶の圧縮と忘却」）。
- キャラクター素材そのものの同梱・配布。**素材は利用者が自分で用意する**。権利の扱いを
  このリポジトリに持ち込まないため。**`persona.md` に書く人格の記述もここに数える**
  （2026-09-14。画像でなくても、既存の作品のキャラクターを書けば同じ問題になる）
- **複数セッション・常駐（client–daemon）へ広げること**（2026-09-21 に未決から落とした）。
  1つの画面で相手にするセッションは1つ。`SessionManager` はセッションを1つだけ持ち、鍵を
  持たない（切り替えは中で起こし直す。`docs/architecture.md`「セッションの復元と複数化」）。**格子のページ
  （`scripts/open-room-grid.ts`）はこれに当たらない** — tsukumo の外で手で打つスクリプトが
  配る1枚の HTML で、各マスは動いている部屋（1画面＝1セッション）を iframe で覗くだけ。
  スクリプトは格子のタブがあるあいだだけ常駐し、読み込みのたびに部屋を並べ直す（タブを
  閉じると終わる）。tsukumo 自身は常駐のダッシュボードを持たない。**成果の振り返りで日記を書かせる
  使い捨ての問い合わせで claude の子プロセスが一時的に2つになることもこれに当たらない**
  （2026-09-25 決定。`SessionManager` は今までどおりセッションを1つだけ持つ。日記を1つ書いたら
  終わり、transcript を書かず、利用者の入力を受けない。4.11「振り返りの依頼」）。**雑談の定着の使い捨て `query()` も同じ扱い**（2026-09-25
  決定。1回ぶんのエピソードとあらすじを返したら終わり、同時に1本だけ。4.9「記憶の圧縮と忘却」）
- **Electron などのスタンドアロンのアプリに包むこと**（2026-09-21 に未決から落とした）。
  箱は Orca のタブのままにする。ただし**載せ替えられる形は保つ** — ホスト依存の操作は
  `showView` 1つに閉じてあり、包みたくなったらそこを差し替える
  （`docs/architecture/adr/0015-single-host-port.md`。候補は `docs/research/app-shell.md`）
- **statusline 側にも小さいマスコットを出すこと**（案B。2026-09-21 に節ごと落とした。
  経緯は `docs/history/decision.md`）
- Windows / Linux での動作保証。動けばよいが、確認するのは macOS のみ
- **日本語以外での応答・画面**（2026-10-03 ユーザー決定）。応答の言語は設定にせず、
  システムプロンプト・UI も日本語のまま
- **待ち時間にほかのキャラクターが訪ねてくる仕組み（訪問）**（2026-10-07 に取りやめた）

### 2.3 想定利用者

個人利用（作者本人）。**macOS の Orca を第一級の環境とする**。

**作者の運用が揃っていない環境でも、落ちず、黙って機能を欠かさない**（2026-10-03 ユーザー決定）。
作者の運用とは Beads・`main` という名の主ブランチ・orca を指す。Beads には依存してよく、それを制約とする
（2026-10-07 ユーザー決定）。特定のスキルには依存しない — スキルの道具・課題の本文の書式・委譲の返却の書式・
課題のラベル・ファイルの置き場を読まず、Beads の課題は組み込みの欄だけを読む
（`docs/architecture/adr/0024-no-skill-dependency.md`）。
前提が無いときは、その前提に頼る機能を出さないか、何が無いかを画面で言う。「不明」へ倒して
空の欄を見せるだけにしない。値を変えられるようにするときの置き場は
`docs/architecture/adr/0025-no-project-settings.md`（環境変数・歯車の設定の2つ）。

Orca は「ページを表示する箱」として第一級であり、VS Code 統合ターミナルは第一級ではない。
ただし**Orca に頼む仕事はページを箱の中に開くこと1つだけ**になったので、箱の差し替えは
現実的な選択肢として残っているが、**包むのは当面やらない**（2026-09-21 に 2.2 へ移した）。

## 3. 技術制約

**事実**: Claude Code のTUIは自分で全画面を描画する。ここから次が決まる。

- `claude | cowsay` のようにパイプを噛ませる方式は**不可**
- hook の stdout はエスケープされてテキスト扱いになるため、そこから ANSI エスケープや
  画像プロトコルを流し込む方式も**不可**
- **TUI の中にキャラクターを出す方法は無い**

**だから TUI を使わない。** Agent SDK（`@anthropic-ai/claude-agent-sdk`）で Claude Code を動かし、
会話・ツール実行・許可・質問を構造化イベントとして受け取る。描くべきものは全部こちらに届くので、
**割り込む必要がそもそも無くなる**（TUI をそのまま使っていた頃の形と、そこから転換した経緯は
`docs/architecture/adr/0008-sdk-instead-of-tui.md`）。

**SDK で使えることは一次情報で確認済み**（2026-09-11、code.claude.com/docs の agent-sdk 各ページ）:
構造化イベント、`canUseTool`（許可と `AskUserQuestion` の両方が届く）、ストリーミング入力モードでの
追加入力と中断、スキルと `.claude/commands`、hook、MCP、Bun サポート。**スラッシュコマンドは
`/<name>` を入力文字列に書けば送れ**、使えるものは `system` の `init` イベントの `slash_commands` に
並ぶ（対話端末が要る `/theme` `/terminal-setup` などは使えない）。

**headless CLI（`claude -p --input-format stream-json`）は採らない。採るなら SDK 一択**
（理由と、PTY で TUI を包む案は `docs/architecture/adr/0008-sdk-instead-of-tui.md` が正典）。

## 4. 機能要件

### 4.1 Claude Code の駆動

**Agent SDK の `query` を、ストリーミング入力モードで1つ動かす**
（`@anthropic-ai/claude-agent-sdk`）。**セッションは tsukumo 1プロセスにつき1つ**（起こし直した
ときは前の続きから始める。4.8）。入力欄から送られたテキストは同じ `query` への追加入力として流し込み、
実行中の中断も SDK の経路で行う。

受け取るイベントと、その行き先:

| イベント                               | 行き先                                                                                                  |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `assistant` のテキスト                 | **ターンの本文**。レポートとしてメインビューへ（4.2）                                                   |
| `speak` ツールの呼び出し               | **セリフ**と**表情**。キャラビューの吹き出しへ（4.2 / 4.3）                                             |
| `tool_use` / `tool_result`             | 作業の進行。帯の「いまの作業」へ（4.2）                                                                 |
| `canUseTool`                           | 許可プロンプトと、キャラクターからの質問。答え待ちにする（4.2）                                         |
| `system` の `init`                     | 使えるスラッシュコマンド（`slash_commands`）・モデル・許可モード                                        |
| `system` の `background_tasks_changed` | **背景のタスク**（ターンのあとも動くもの）。帯の「いまの作業」へ（4.2）                                 |
| `system` の `task_notification`        | 背景で走らせた Bash の**終わりの時刻**（`tool_use_id` で結ぶ）。検証の行と依頼の手順の所要時間へ（4.2） |
| `system` の `api_retry`                | **再試行中**（何回目か・待ち時間・理由）。入力欄の経過時間の行へ（4.2）                                 |
| `rate_limit_event`                     | **利用上限**（上限に達した、枠と戻る時刻）。同じ行へ（4.2）                                             |
| `assistant` の `error`                 | API のエラーの種類。**失敗で終わったときの理由**になる                                                  |
| `result`                               | ターンの終わり方（完了・中断・失敗）。失敗はメインビューと同じ行へ                                      |

- **モデルと許可モードは SDK のオプションで渡す**（`/model` を入力文字列として送らない）。
  どちらも画面から切り替えられるようにする。**既定の許可モードは `auto`**（`default` だと
  読み取り専用以外が逐一 `canUseTool` に届く。実測は `docs/history/decision.md`）
- **既定のモデルは Opus、既定の effort は medium**（2026-09-12 のユーザーの指示では high。Opus 5.5 で API の既定が medium に下がり、同じ段でも前の Opus より多く考えるため、2026-09-24 に見直した）。
  **effort は帯から切り替えられる**（`applyFlagSettings({ effortLevel })` でセッションの途中から
  変えられ、変えた値は次のターンから hook 入力の `effort` に載って外から読める。実測は
  `docs/history/decision.md`）。**画面に表示するのは読み取った値**で、帯から送った値をそのまま
  出す形は採らない（読めない場合にだけ出さない、という判断はここから来る）
- **モデルと許可モードの既定は、画面（帯の右端の歯車）から変えて覚えさせられる**
  （`~/.tsukumo/state.json`。`docs/architecture/screen-design.md` 13.6）。上の Opus・`auto` は**覚えた値が無い・
  読めないときの同梱の既定**で、覚えた値があればそちらで起こす（効くのは起こすたび）。
  **帯から変えた値はそのセッション限り**で、既定を書き換えない。**既定に「全部許す」
  （`bypassPermissions`）は選べない**（全部許すのは起こしたあと帯からその都度選ぶ）
- **`thinking` は表示しない。** モデルの内部の思考なので、出すと事故になる
- **未知のイベント種別が来ても落ちないこと。** 種別は本体の更新で増える（旧方針で
  transcript の `type` が実際に増えたのを観測している）
- **出力スタイル（`~/.claude/output-styles/asuna.md`）は SDK でもそのまま効く**（実測は
  `docs/history/decision.md`）。`init` はプロンプトを送るたびに届くので、「新しいセッション」の
  合図にしない
- **背景のタスクが終わると、claude は依頼なしで続きのターンを始める**（実測は
  `docs/history/decision.md`）。依頼に当たるメッセージは流れないので、**ターンの外で届いた
  `init` を合図に、記録を持たない続きのターンの始まり（`turn-resumed`）を補う**（`src/server/session-driver/core/self-started-turn.ts`。
  見え方は `docs/architecture/screen-design.md` 13.9「背景のタスク」）
- **中断は SDK の `interrupt()` で効く。** 中断されたターンの `result` は `error_during_execution`
  で終わり、同じセッションに続けて入力を送れる（中断前の文脈を保っている）
- **API がうまくいかなかったことを黙って捨てない**（2026-09-24 決定）。再試行中（まだ続く）・
  失敗で終わった（もう続かない）・利用上限に達した（いつ戻るか）の3つを、**入力欄の経過時間の行の
  1つの枠**に出す（強いほうを1つ。見え方は `docs/architecture/display.md` 4.2「入力欄」。仕事のときは
  再試行中を進み具合の帯、失敗の理由を失敗の塊が持ち、行に残すのは利用上限に達しただけ）。**利用上限が近い
  （`allowed_warning`）は出さない**（2026-09-27 ユーザー決定）。失敗で終わった
  ターンは、加えてメインビューのそのやり取りの頭の失敗の塊に、理由と次の手（同じ依頼を入力欄に戻す など）を
  残す（過去のターンを遡っても成功と見分けられるように）。**中断は失敗にしない**
- **出すのは型の決まった理由だけ**（エラーの列挙値・HTTP の状態コード・回数と待ち時間・利用上限の
  枠と戻る時刻）。`result` の `errors` の自由文は画面にもログにも流さない（会話の断片が混ざりうる。
  `docs/coding-standards.md`「会話内容の扱い」）。`rate_limit_event` の使用率は出さない（効いている
  枠1つぶんしか運ばない。枠ごとの使用率は下の利用枠が持つ）。`error` の付いた `assistant` の本文は今までどおり本文として扱う（出力の上限で切れた
  本物の本文のこともあり、本体が作ったエラーの文面と見分ける印が無い）
- **5時間枠と7日間枠の使用状況（利用枠）は、知らせを待たずに SDK へ取りに行く**（2026-09-27
  決定）。口は `Query` の `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET({ skipBehaviors: true })`
  で、Claude Code が自分のログインで `/usage` と同じ値を取ってくる（60秒以内の取り直しは本体の控えで
  答える）。**tsukumo は認証情報を読まない**。`skipBehaviors` は必ず `true`（手元の transcript の
  走査を起こさない）。名前のとおり実験中の口なので、呼ぶのは `sdk-` のアダプタ1本に閉じ、読めない形・
  失敗は「取れない」に畳む。運ぶのは2つの枠の使用率・戻る時刻・取った時刻だけ（出し方は
  `docs/architecture/display.md` 4.2「各表示物」のサイドバー。調べた結果は `docs/research/plan-usage.md`）
- **SDK も transcript（JSONL）を書くが、tsukumo はそれを読まない**

### 4.3 状態連動

- **表情差分**: **`speak` の `expression` 引数を主にする**（2026-09-11 決定）。キャラクター
  定義にある表情名から選ばせる
- **表情は9つ**（2026-09-22 決定）。**`default` が先頭**で、足すものは**末尾に積む**（既存の
  並びを動かさず、パック作者から見える順を変えないため。足した順は `docs/history/decision.md`）:

  | 識別子      | ラベル（`characters/tsukumo`） | 出す場面                                                                                                                               |
  | ----------- | ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
  | `default`   | にっと                         | 下のどれにも当たらないとき。**表情の指定が無いときの落とし先**でもある                                                                 |
  | `thinking`  | ふむ                           | 調べる前・結果を突き合わせるとき・判断に迷うとき                                                                                       |
  | `proud`     | えへん                         | うまくいったとき・完了を報告するとき                                                                                                   |
  | `flustered` | あわわ                         | 外したとき・失敗したとき                                                                                                               |
  | `serious`   | きりっ                         | **危険な操作を確認するとき**（はしゃぐのをやめて止める）                                                                               |
  | `curious`   | きょとん                       | **予想外のものに出くわして目を丸くするとき**                                                                                           |
  | `sad`       | しょんぼり                     | **思ったように行かず凹むとき・断られたとき・自分の見立てが外れたと認めるとき**（`flustered` は外した瞬間、`sad` はそのあと凹んでいる） |
  | `excited`   | わくわく                       | **面白そうなものを見つけたとき・これから始めるとき**                                                                                   |
  | `bored`     | たいくつ                       | **長いテストやビルドを待っているあいだ**（眠っている顔ではない。つくもは眠らない）。**話しかけられているあいだは出さない**             |
  - **表の「出す場面」は `speak` で選ぶときの目安で、反応の行は別に表情を当ててよい**
    （2026-10-05 利用者決定。反応の行は迎えの挨拶と同じ問い合わせが行ごとに表情の選択肢から選び、
    `speak` を通らずに出る）
  - `curious` は**質問を出すときに必ず出すものではない**（2026-09-20 決定）。他の表情と同じく、
    **キャラクター自身が場面に合わせて `speak` の引数で選ぶ**
  - **ラベルはパックごとに違う**（語の系統が違うパックは別の言い回しを持つ。実物は各パックの
    `character.json`）
  - **選択肢に出るのは、立ち絵かラベルのどちらかが定義にある表情**
    （`src/shared/character-pack/expression-choice.ts`）。**`default` は定義に無くても必ず出る**（未知の表情の
    落とし先なので、これが無いと受け付けられる名前が1つも無くなる）
  - つまり**ラベルだけ足したパックでも、その表情を選べる**（立ち絵は `default` に落ちる）。
    **絵が揃っていないパックでも壊れない**のはこのため。選択肢から外れるのは、立ち絵もラベルも
    定義に無い表情だけ
  - **`persona.md` にも 4.3 にも場面が書かれていないものは足さない**（見送った例は
    `docs/history/decision.md`）

- **表情の源は `speak` の1つだけ**（2026-09-17 決定）。**ツールを実行している間に自動で
  「作業中」へ上書きする経路は持たない**（同じ案をまた出さないための理由と実測は
  `docs/history/decision.md`「requirements.md 4.3 状態連動」）。**原則は「表情と吹き出しは
  リンクしていること」**で、自動の上書きはこの原則を壊す唯一の経路だった
  - **例外: 機械の出来事への反応**（2026-10-02 決定）。反応の行を吹き出しに出すとき、立ち絵もその行の
    表情にする。セリフと表情が1行で対になっているので、リンクの原則は破らない。**条件は3つ**
    （守らないと 2026-09-17 に退けた経路と同じ壊れ方をする）:
    反応は `speechExpression`・`speeches`・`records` に書かず姿から導くだけにする（「戻す」処理を
    要らなくする）／過去のターンを見ているあいだは出さない／本物の `speak` が届けば消える。どの出来事で何の行を出すかは
    `docs/architecture/display.md` 4.2「出力の分離（セリフと詳細）」
  - **例外: 迎えの挨拶**（2026-10-04 決定。4.3 に書き足したのは 2026-10-05 利用者決定）。立ち絵は
    挨拶を書いた問い合わせが選んだ表情にする。挨拶の文と表情が1つの答えで対になっているので、
    リンクの原則は破らない。縛りは反応と同じ3条件。出し方は上と同じ節
- **黙って立つだけの場面の埋め方**（2026-10-05 利用者決定。場面ごとのいまの振る舞いは
  `docs/architecture/screen-design.md` 13.13「場面ごとのキャラクターの振る舞い」）。黙って立つだけの
  場面は、依頼を待つ間・続きから起こした直後・雑談で誰もつつかない間の3つ:
  - **線引き: 言葉は、なるべく本体のセッションのモデルが書く。** 「いつ・何回・いつ消すか」は
    機械（tsukumo）が決める。実装の手間・揺れ・プロトコルの変更が重すぎる場面は、機械が決めたうえで
    使い捨ての問い合わせ（`haiku`）で妥協してよい（パックの定型文には頼らない。2026-10-05 利用者決定）
  - **依頼を待つ間は、待ちの一言を1回だけ出す。** 本体がターンの終わりに `report` の引数で待ちの一言
    （`closing` と同じ文と表情の組）を前もって書き、ターンが閉じて依頼を待つ間が一定時間続いたら、
    吹き出しに1回だけ出す。依頼を送れば消え、次のターンが閉じるまで繰り返さない。本体が書いて
    いない（`report` を呼ばなかった・引数を省いた）ときは、迎えの挨拶と同じ問い合わせが書いた反応の行
    （待ち `idle`）を1回出す。それも書けていなければ何も出さない。下の「長いアイドルのふるまいは作らない」は、この1回だけの
    一言のために狭める
  - **続きから起こしたときは、おかえりの一言を出す。** 前回の最後のターンで本体が書いた待ちの一言
    （transcript の `report` の引数に残る）があれば、それを出す。無ければ迎えの挨拶と同じ使い捨ての
    問い合わせ（`haiku`）が書いた、中身に触れないおかえりを出す（この問い合わせは反応の行のために、
    待ちの一言があっても毎回打つ）。材料は迎えの挨拶の材料に、続きからの
    印と前回からの経過の帯（transcript の最後の時刻から tsukumo が決める）を足すだけで（どちらも数と決まった語で、
    会話の文面を含まないので「会話から導いた材料」に当たらない）、会話の中身を
    新しい渡し先に渡さない（`docs/coding-standards.md`「会話内容の扱い」は変えない）。依頼を送れば消える
  - **雑談の自発の話しかけは、立ち絵をつついたときだけのまま**（2026-09-21 決定を保つ。
    `docs/architecture/chat-mode.md` 4.9）
- **モデル別の衣装**: `haiku` = 軽装 / `sonnet` = 通常装備 / `opus` = 戦闘配置 / `fable` = 戦闘配置
  （`opus` と同じ。2026-09-17 決定。衣装は「装備の重さ」の3段のままにし、`OUTFITS` を増やさない）。
  Asuna output style の「出撃時の掛け声」のモデル分岐と対応させる。モデルは**SDK に渡した値と
  `system` の `init` から分かる**。値の形式（短い別名か解決済みの完全なモデルIDか）は場合に
  よるので、衣装の判定は部分一致で行う
- 表情の日本語ラベルはキャラクター定義の `character.json` の `expressions` が持つ。`src/shared/character-pack/expression.ts` に
  置くのは、表情名の全体と、モデルから衣装を決める規則だけ（`docs/architecture/character-pack.md`）
- **立ち絵は動くが話さない**（2026-09-13）。演出はブラウザ側の `Portrait` 部品の中に閉じる
  （`docs/architecture/browser.md`「立ち絵の動き」）
- **立ち絵は「1枚の矩形」として扱う**（2026-09-13 決定）。tsukumo が動かすのは**位置・大きさ・
  傾き・上下・不透明度**だけで、**素材の中身（目・口・腕）には触らない**。理由は 2.2 の
  「素材は利用者が自分で用意する」で、**素材がどう作られているかを当てにできない**から
  この割り切りにより、**SVG でも PNG でも GIF でも同じだけ動く**（パック作者に何も要求しない）
- **まばたきと表情のクロスフェードは作らない**（同上の帰結。素材の構造に依存するため）。
  表情は引き続き立ち絵そのものの差し替えで表す
- **`<Portrait>` が動ける範囲はキャラビューの領域の中だけ**（読書を妨げないため）。
  **ただし「レポートの上に被らせない」の線は、ミニ立ち絵に限って見直した**（2026-09-20 決定。
  元の指示と、それまでの線は `docs/history/decision.md`）。**認めるのは、いま書かれている本文の
  筆先に添う1体だけ**で、次を条件にする:
  - **書き上げる様子は演出で作る。** レポートは確定するまで出ない（`docs/architecture/display.md` 4.2 の
    「リアルタイムに流す」）ので、**流れている本文に添える筆先はどこにも無い**——
    出た時点で本文は全部そろっている。演出は**出そろった本文を「書き上げていくように見せる」**
    ものとし、ミニ立ち絵はその筆先に添う
  - **筆で書くのは節（`sections`）だけ**（2026-10-02 決定。覆した旧い決定と戻し方は
    `docs/history/decision.md`「requirements.md 4.3 レポートの書き上げの演出」）。**結論（`conclusion`）と
    検証結果（`checks`）は、ターンの確定と同時に最初から出す**（結論が筆で書かれて待たされないように。
    境目は節の始まりの印 `.report-sections-start`）。**節が短いレポートは演出せずに出す**——筆の対象の
    文字数（図は100字相当）の合計が 200 に満たないとき（速さの設定に依らない）
  - **文字を足していく実装にしない。** Markdown のソースを1文字ずつ増やして変換し直すと、表・
    mermaid・Chart.js が未完成のソースで作り直され、非同期に描く mermaid は途中の形で失敗する
    （塊ごとの `memo` も全部無効になる）。**DOM は完成品を一度に作り、見せる範囲だけを進める**。
    **文字を持たない図・グラフの塊は塊ごと出し**、ミニ立ち絵はその脇に立つ
  - **筆は1行ずつ追わず、塊1つをZ字で書く**（2026-09-20 決定）。塊の行を上下2つの帯に割り、
    帯ごとに左から右へなぞって、あいだを斜めに戻る——Z字の3画。**帯の切れ目は実際の行の box に
    合わせる**ので文字が上下に切れず、1行しかない塊は1画で書く
  - **なぞる右端は帯ごとに、その帯にある行のいちばん右**（2026-09-21 決定。枠でなぞっていた頃の
    数字は `docs/history/decision.md`）。**左端はどの帯も塊の左端で揃える**（行頭は揃っているので
    帯ごとに変えない）。**横画の時間は帯の幅で按分する**（等分すると、筆の速さが同じ塊の中で
    変わる）
  - **塊は「トピック」**（同日のユーザーの判断。**段落や表の1つ1つではない**）。見出しと
    水平線を境に、そこから次の境目までの要素をひとまとめにする。**帯は要素をまたいで1本に
    伸びる**ので、見出しと段落と表が同じ画で書かれ、図・グラフは筆が通り過ぎた割合が
    そのまま `opacity` になる。細かく割ると筆が何度も折り返して目で追えなくなる
  - **速さは塊ごとに決め、レポート全体には上限を掛けない**（2026-09-20 決定）。**塊の大きさ
    （中の文字数の合計）で按分し、1つあたり 2.4〜8秒**——文字1つあたり 40ms で、下限 2400ms・
    上限 8000ms に収める（図・グラフは文字数を持たないので、段落1つぶん＝100文字に相当させる）。
    **下限が大きいのは、1回のZ字をゆっくり書くため**——短い塊を文字数に素直に比例させると筆が
    飛んで見える。**塊の数で全体が伸びるのは受け入れる。全体に予算を置いて按分する案は採らない**
    （どちらの理由と実測も `docs/history/decision.md`）。読み始めが遅れるぶんは、クリック・
    キー入力のどちらかで**即座に全部出す**ことで引き受ける。**ホイールと指では打ち切らない**
    （2026-09-22 決定）。**過去のターンを見返すときは演出しない**（確定済みの本文は一度も
    「書かれない」）
  - **速さは歯車のポップオーバーから選べる**（2026-09-23 決定。標準／速い／切る の3つで、
    **標準は上の値のまま**）。**利用者の設定**（`localStorage`）なので、選び直しても書いている
    最中の演出には効かない。値と置き場所は `docs/architecture/screen-design.md` 13.6 が正典
  - **塊の中は出だしと締めをゆっくり、真ん中を速く**（2026-09-22 決定。3次のイーズインアウトで、
    真ん中の速さは等速の3倍）。ミニ立ち絵が「そこで書いている」ように見えるのは筆が遅いところ
    だけなので、**見せたい両端に時間を寄せて、読み手が待つだけの真ん中を速く抜ける**。
    **塊の持ち時間そのものは変えない**ので、レポート全体の長さは変わらない
  - **`note` の注意・異常と、`options` の「採る」カードは、書き終えたところで筆を 400ms 留める**
    （2026-09-28 決定。`docs/research/report-block-richness.md` 4章。キャラクターが「ここ」と
    指しているように見える）。**留める長さは速さの設定（標準／速い）に関わらず一定**——読む
    速さのつまみではなく、大事な塊を指す強調の間なので連動させない。**留める時間は塊の
    「大きさで按分」した持ち時間の外に足す**（上のバケットに時間を含めない）ので、留めがあっても
    文字数に比例した書く速さそのものは変わらない。留める位置は DOM の実測ではなく文字数の重みの
    比例で決める（`src/browser/domain/reveal/plan.ts` の `pausesOf`）。対象の印
    （`report-pause-point`）は記法の語彙に無い class 名で、`NotationBlock` の置き換えを受けない
    （`report-section-break` と同じやり方。`src/shared/report/report-markdown.ts`）
  - **書いているあいだは画面が筆先に付いていく**（2026-09-20 決定）。**追うのは帯ぜんたいでは
    なくミニ立ち絵の立つ位置**（帯の下端から立ち絵の高さぶん上まで。2026-09-23）。そこが器の
    上下の縁から 96px 以内に入ったら、その差だけ器を送る。**器がその範囲と上下の余白を両方とも
    収められないほど狭いときは、下端を優先する**。**器は根から上へたどって見つける**——転がる
    祖先は画面幅で入れ替わる（広い画面は `section[data-region="main"]`、狭い画面はページ自身）
    ため。**利用者が手で転がしたら、その演出のあいだ自動送りは降りる**（2026-09-22 決定。読む
    位置を選んだのは利用者のほうなので、筆が譲る）。**自動送りには上限がある**（2026-10-02 決定）——
    結論の上端が器の上の余白（96px）に入るところまでしか送らず、書き終えても結論が画面から流れない。
    筆先が器の下へ出たまま書き進むのは受け入れる
  - **やり取りの列は筆が届いた節から見出しを並べる**（2026-10-02 決定）。列そのものは最初から確保する（出入りで本文が
    横へずれ、筆の座標が狂うため）
  - **素材は「あれば使う」。** `character.json` に任意の `mini` を置き、**無いパックは
    `portraits.default` の縮小に落ちる**（4.4「あるものだけでよい」に例外を作らない）。
    ミニ用の画像はリポジトリに同梱しない（2.2）
  - **2体見えることは「分身」として受け入れる**（2026-09-20 決定）。キャラビューの立ち絵は
    消さず、ミニ立ち絵を明確に小さくして式神として見せる（**不透明**）。**書いている間だけ
    キャラビューを空ける案は採らない**（吹き出しの持ち主が居なくなる）
  - **書き上げたあとも消えず、本文の末尾に残る**（2026-09-21 決定）。残った立ち絵は**本文に
    貼り付いて一緒に転がる**（筆先の座標をビューポートではなく本文の入れ物の原点で持つ。
    画面に固定する案は採らない）。**残る場所は本文の右下**——縦は末尾の行の下（そこに立ち絵の
    高さぶんの床を敷く）、**横は筆が止まったところではなく本文の右端**（2026-09-23 決定。
    経緯は `docs/history/decision.md`）。**見切れるところまでは寄せない**（隅に置くが姿は全部
    見える）。**消えるのは次に書き始めたときだけ**で、過去のターンへ切り替えたときにも依頼を
    送った時点でも消さない。**演出を途中で飛ばしたときも、筆が止まった場所ではなく同じ末尾に
    置く**——飛ばすと本文は全部出るので、途中に残るとまだ書いている途中に見える
  - `prefers-reduced-motion: reduce` では**演出ごと無効**にし、ミニ立ち絵も出さない
    （**演出が走らない場面で新たに出すことはしない**——過去のターンも同じ）
- **動くのは利用者の注意が空いているときだけ。** 判定の材料は `SessionState` に既にある
  （`turn` / `lastToolFailureAt`）。**どの動きを作るかは `docs/architecture/browser.md`「立ち絵の動き」が正典**。
  **長いアイドルのふるまい（座る・うとうと）は作らない**（席を外している時間で誰も見ていない）。
  **例外は依頼を待つ間の待ちの一言1回だけ**（2026-10-05 利用者決定。上の「黙って立つだけの場面の埋め方」）で、
  動きは足さず、繰り返さない
- `prefers-reduced-motion: reduce` を尊重する（規則は `src/browser/styles/theme.css` にある）

### 4.4 キャラクター定義

素材（立ち絵の画像）と、表情・衣装の対応は**宣言的な定義ファイル**で差し替え可能にする。
ハードコードしない（`docs/architecture.md` 原則4）。

**置き場所**（`characters/README.md` が使い方の正典）:

| 場所                            | 中身                                                       |
| ------------------------------- | ---------------------------------------------------------- |
| `characters/tsukumo/`           | 既定のキャラクター。**このリポジトリのために自作**したもの |
| `characters/tsukumo-spirit/`    | もう1体。同じく**このリポジトリのために自作**したもの      |
| `characters/local/`             | 利用者が自分で用意した素材。**`.gitignore` 済み**          |
| `~/.tsukumo/characters/<name>/` | **画面から作ったパック**（2026-09-15 決定）                |

**画面から作ったパックはリポジトリの外（`~/.tsukumo/`）に書く**（2026-09-15 決定）。
探索先の優先順位・画像の受け取り方（data URL を WebSocket のコマンドに載せる）・大きさの上限は
`docs/architecture/character-pack.md`（「画面から作るときの置き場と受け取り方」を含む）が正典。**cwd には依存させない**ので、どのプロジェクトから起こしても同じ
パックが選べる。**作る口も、立ち絵・差し色を変える口も、会話の画面とは別のキャラクター画面にある**
（2026-09-17 決定。4.7、`docs/architecture/screen-design.md` 13.6）。

**このリポジトリは公開されている。** 権利のある画像（公式絵・ファンアート等）を
コミットしないため、利用者の素材は `characters/local/` に置く
（`docs/architecture/adr/0014-no-bundled-character-asset.md`）。

**定義ファイル**（`character.json`）は次を持つ:

- `portraits`: 表情（4.3 の一覧）→ 画像ファイル。
  **「あるものだけ」でよく、見つからない表情は `default` に落ちる。** 1枚から始められる
- `outfitAccents`: 衣装（`default` / `light` / `normal` / `heavy`）→ 差し色。
  表情×衣装の全組み合わせぶんの画像を要求しないための仕組み

**移行後（2026-09-13 決定）は「パック」になる**: `character.json` に `expressions`（表情名 → ラベル）と
`speechMarker` が加わり、同じディレクトリの `persona.md`（tsukumo 向けの人格）と素材を1単位として
読む。切り替えは別のパックでセッションを起こし直し、**そのパックのセッションの続きから始まる**
（`docs/architecture/character-pack.md`・4.8）。

**同梱するパックは自作のものだけ**（2026-09-14 決定。理由は 2.2 の「キャラクター素材そのものの
同梱・配布」で、**`persona.md` に書く人格の記述も「素材」に数える**）。既存の作品のキャラクターを
演じさせたいときは、`characters/local/` に自分で置く（`.gitignore` 済み）。

**人格の二重適用は `applyFlagSettings({ outputStyle: "default" })` で避ける**。
`~/.claude/settings.json` の `outputStyle` は全プロジェクトに効くので、そのまま `persona.md` を
足すと人格が2つ重なる。**セッションを起こしたあとに呼ぶと `init` の `output_style` が `default`
になり、グローバルの人格が消えて `persona.md` だけが残る**。**これはセッション限りの層にしか
触らず、設定ファイルを書き換えない**（実測は `docs/history/decision.md`）。
`settingSources` からユーザー設定を外す案は、**orca の hooks まで外れる**ので採らない。

**差し色が効くのはインラインで埋め込んだ SVG だけ**（実測）。`<img>` で読み込んだ画像は
独立した文書として扱われ、ページ側の CSS 変数が届かない。ラスタ画像（PNG / GIF）を使う場合、
衣装の出し分けは表情と同じくファイルを分けることになる。

**日記の書体（`diaryFont`）はパックが持つ**（2026-09-25）。効くのは成果の画面の吹き出しと
日記帳の見開きの本文だけ（`docs/architecture/screen-design.md` 13.3「例外は日記の本文だけ」）。パックに同梱した
書体ファイルだけを指せ、外部フォントは足さない。無いパックは端末の明朝体のまま。**キャラクター
編集の画面から差し替える口は無い**（手で `character.json` と書体ファイルをパックに置く）。

**切り替えたときに画面から消すのは吹き出し・立ち絵・メインビューの3つ。** 素材が1体しか無くても
サイドバーの `<select>` は出す（選択肢1つ。無いように見えるほうが分かりにくい）。

**画面から変える**（口の並びは `docs/architecture/screen-design.md` 13.6）:

- **使用中以外のパックも変えられる**（キャラクター画面の一覧で選んだパック）。起動先の
  `characters/local` と同じ名前のパックだけは変えられない（ホームに書いても探索の順で負け、次の
  起動で消えたように見えるため）
- **反映はセッションを起こし直さない**（会話も履歴も消えない）。使用中のパックを変えたときだけ、
  使用中の姿と素材がホームの版に替わる。**立ち絵を足した表情を `speak` で選べるのは次の起動から**
  （`speak` の enum は起こしたときの定義から作る）
- **受け付ける素材**: 立ち絵と顔は `.svg` / `.png` / `.gif`、背景は `.png` / `.jpg` / `.webp`
  （写真が主な素材で、透過も差し色のインライン埋め込みも要らない。`.gif` は入れない — 動く背景は
  読む面の隣で気が散る）。大きさと枚数の上限は `docs/architecture/character-pack.md`「画面から作るときの置き場と受け取り方」
- **名前とひとことプロフィールは1つのボタンから2つの欄をまとめて変える**（`characterPack.setProfile`）。
  どちらも空文字を通し、名前が空なら id へ折り返し、ひとことは空白だけなら「無い」に畳む

**新しく作る**:

- **id と表示名を分けて受け取る。** 保存するフォルダの名前になるのは id だけ（半角の英数字と
  `.` `_` `-`。`.` では始められない）。表示名は空文字を許し、文字種も縛らない（長さの上限だけ）。
  空なら id と同じ名前で出る（同じ文字列を2回打たせない）
- **既にある id は弾く**（作れてしまうと既存のパックが黙って隠れる）。変えたいなら選んで編集の口で変える
- **最低限そろえさせるのは `default` の立ち絵1枚と画面の差し色2つ**（仕事・雑談）。衣装ごとの差し色と
  ほかの表情は作ったあとに足す（**作る口は最低限にする**）
- **作った直後に自動では切り替えない**（切り替えは会話の画面の初期化なので、作る操作の副作用に
  しない）。作れたら一覧で作ったパックを選んだ状態にするだけ

**消す**（id を打って確かめるのは画面の側）:

- **消すのはいつもホームの版だけ。** 使用中のパックは断る（切り替えてから消す）
- **消すと何が起きるかはパックごとに決まり、一覧の1件が持つ**（`removal`。使用中かどうかは混ぜない）:

  | `removal`             | どのパック                                      | 消したあと                                       |
  | --------------------- | ----------------------------------------------- | ------------------------------------------------ |
  | `"delete"`            | ホームにしか無い（画面から作ったもの）          | 一覧から消える。雑談の要約とアーカイブも消える   |
  | `"revert-to-bundled"` | 同梱のパックを画面で直したホームの版            | **同梱の版が一覧に戻る**。雑談の記録は残る       |
  | `"none"`              | 同梱だけ・起動先の `characters/local`・一覧の外 | 画面から消す口を出さない（届いてもサーバが断る） |

- **同梱を直したものは「同梱に戻す」と見せる**（「消す」と見せると押したあとも同じ名前が一覧に
  残り、消えなかったように見える）。戻すと、画面で直した見た目とキャラクター自身が書き足した
  「覚えたこと」も消える（どちらもホームの版の中にある）ので、画面はそれを文言で伝える
- **雑談の記録（あらすじ・アーカイブ・エピソード索引）は、一覧から名前ごと消えるとき（`"delete"`）だけ
  一緒に消す。** 記録の鍵がパックの名前だけなので、残すと同じ id で作り直したパックが消したパックの
  会話を思い出す。同梱に戻すときは同じキャラクターが続くので残す
- **消せないもの（既知の制約）**: claude 側の transcript（`~/.claude/`）は触らない。同じ id で作り直し、
  同じ起動先・同じポートで起こすと、印が同じなので消したパックのセッションを続きから拾いうる。
  別の tsukumo のプロセスがそのパックを使用中でも止めない（そのプロセスでは素材が 404 になり、次に
  起こすと既定のパックへ落ちる）

### 4.6 起動と設定

- **プロジェクトのディレクトリで `tsukumo` と打つ**（開発中はリポジトリ直下の `pnpm run start`
  でも同じ）。tsukumo はローカルの HTTP サーバを立て、Agent SDK で Claude Code を起こし、
  ページのタブを箱（Orca）の中に開く。**利用者が並べる手間はゼロ**（1枚のページで完結する。4.7）
- **ビューを配るポートは既定 7327**（`TSUKUMO_VIEW_PORT` で変更可）。**既定のまま塞がっていたら**
  EADDRINUSE のあいだ +1 して20個先（7346）まで順に試し、空いた番号で待つ（複数のプロジェクトで
  同時に起こしても2つ目以降が起動できるように。2026-09-12 決定）。**`TSUKUMO_VIEW_PORT` を
  明示的に渡したとき（`0` を含む）はずらさず、そのポートで一度だけ試してそのまま失敗する**
  （指定したポートで待てないことに気づけなくなるため）。EADDRINUSE 以外の失敗（`EACCES` など）も
  ずらさない。20個全部塞がっていたら、試した範囲（7327〜7346）を伝えて終了コード1で終わる
  （黙って0番＝空きポート自動割り当てへは逃げない。どのポートで待っているか分からない状態を
  作らないため）。実際に待っているポートは起動時に stdout へ出る URL（`layoutUrl`）で分かる
- **グローバルへの導入は `pnpm add --global "link:<リポジトリ>"`**（2026-09-12 決定・実施。2026-09-27 に `bun link`
  から移し、2026-10-02 に pnpm 12 の `pnpm link` が `--global` を受け付けないので移した）。リポジトリの直下で
  `mise run setup` を打つと `~/Library/pnpm/bin/tsukumo` ができ、どのディレクトリからでも打てる。
  **リポジトリの `bin/tsukumo` へのリンク**なので、開発中の変更がそのまま次の起動に反映される。
  **tsukumo のリポジトリの作業ツリーの中で打ったときは、その作業ツリーの `bin/tsukumo` が起きる**
  （link 元でなく打った場所の版になる）。**消すときは `pnpm remove --global tsukumo`**。
  リポジトリの外に置かれるのは `~/Library/pnpm/bin/tsukumo` と `~/Library/pnpm/global/` 配下（pnpm の
  登録簿）の2つだけ。シェルの設定ファイルは、`~/Library/pnpm/bin` が `PATH` に無いときだけ
  `pnpm setup --force` が pnpm の区画を書き直す。**打つのは本体の作業ツリーの直下で、`tsukumo-N` の作業ツリーでは
  打たない**（打つとグローバルの `tsukumo` がその作業ツリーのコードに付け替わる）
- **cwd に依存してよいのは起動先プロジェクトのもの**（作業ディレクトリ・
  相対指定の素材）**だけ**で、**自分で持ち歩くもの（既定の立ち絵・`node_modules` の外部
  ライブラリ）は自分の場所から読む**（`tsukumo` 自身が置かれている場所からの相対。
  どのディレクトリで起こしても立ち絵が出る）
- **どのホストで開くかは `TSUKUMO_HOST` で選ぶ**（既定は `orca`。知らない値も `orca` に倒す。
  2026-10-03 決定。`docs/architecture/adr/0022-three-setting-homes.md`）。起動時の URL はどちらでも
  stdout に出る。`TSUKUMO_OPEN_VIEW=0` はどちらでも起動時のタブを開くことだけを止める
  - `orca`: 起動時に Orca のタブを開く（同じページのタブが既にあれば貼り直す）。レポートのパスを
    押すと Orca のエディタで開く。**`orca` が無ければタブを開くのを諦め、URL を表示して動作を続ける**
    （起動失敗にしない）。そのときパスは押しても開かず、「ファイルを開けなかった」で断られる
  - `none`: 何も開かない（外部コマンドを起こさない）。起動時のタブは開かず、開かない理由を
    stderr に1行出すので、表示された URL を手でブラウザに開く。レポートのパスは押しても開かず、
    「ファイルを開けなかった」で断られる
- **`~/.claude/settings.json` に tsukumo のエントリを残さない。** 旧方針で足した hook は外す。
  ただし**このファイルの hooks と statusLine は orca（`~/.orca/agent-hooks/`）が専有している**
  ので、触るときは既存エントリを壊さないこと。上書きすると orca 側が黙って動かなくなる
- **入力は画面の入力欄から SDK へ直接渡す。** Orca 経由でターミナルへ文字やキーを送る経路は
  使わない（**Orca はエージェント端末への合成入力を弾く**。実測は `docs/architecture.md`
  「core と adapter」）

### 4.7 画面レイアウト

biim システムをリスペクトした4領域にする。**領域ごとに役割を1つだけ持たせ、同じ情報が
2箇所に出ないようにする**ことが狙い。

```
┌────────────────────────────────────────┬────────┐
│ メインビュー                            │サイドバー│
│  迎える口／進み具合の帯／レポート（広い）│ （狭い） │  全部で1枚のHTML
├─────────────────────┬──────────────────┴────────┤  ＝ブラウザタブ1つ
│ キャラビュー（半分）   │ 入力欄（半分）              │
│  立ち絵＋セリフ        │  依頼・お伺いの自由入力     │
│                        │  ・送信・中断／のコマンド補完│
└─────────────────────┴───────────────────────────┘
```

| 位置         | 中身                                         | 対応する biim の要素 |
| ------------ | -------------------------------------------- | -------------------- |
| 左上（広い） | メインビュー。局面ごとの中身（お伺いを含む） | ゲーム画面           |
| 右上（狭い） | サイドバー。タスク一覧・セッション情報       | タイム表・チャート   |
| 左下（半分） | キャラビュー。立ち絵＋セリフ                 | 立ち絵・テロップ     |
| 右下（半分） | 入力欄。依頼とお伺いの自由入力               | 実況者の手元         |

**許可と質問は、同じ形の札「お伺い」にしてメインビューに出す**（進み具合の帯の下の本文。2026-10-02 決定。
形は `docs/architecture/screen-design.md` 13.13「お伺い」）。キャラは吹き出しで「これいい？」と言うだけで、
tsukumo は吹き出しの文言を作らない。**入力欄はそのまま出したままにし**、質問の間だけ**選択肢にない答えを
書く場所**になる（打ちかけの文字はそのまま残る）。許可の間は、ふつうの下書きのまま。
それまでの「許可は入力欄の上の箱、質問はメインビューの札」（2026-09-11・2026-09-23）と覆した理由は
`docs/history/decision.md`「requirements.md 4.7 画面レイアウト（答え待ちの箱。2026-10-02 に覆した記録）」。

**メインビューの中身は、ターンの局面（迎える・働く・尋ねる・渡す・つまずく）で入れ替わる**（2026-10-02 決定。
4領域の位置と比率は依頼のあいだ動かさない。`docs/architecture/screen-design.md` 13.13）。

**4領域は1枚の HTML にまとめ、CSS で領域を分ける。** ブラウザタブは1つだけで、
**ターミナルのペインは1つも要らない**（Claude Code の TUI を開かないため）。

**同じページの中に、4領域の会話の画面と入れ替わる「キャラクター画面」が1つある**
（2026-09-17 決定）。立ち絵・差し色の差し替え、新しいパックを作る口、画面の色3つ
（`ground` / `surface` / `ink`）はここに置く。
**切り替えは URL の `#character`（作る画面は `#character/new`）**で、リロードしても同じ画面に
戻り、ブラウザの「戻る」が効く。**入る口も戻る口も、全画面の最上部の帯**（2026-09-22 決定）。
会話の画面は隠すだけで外さないので、キャラクター画面に居る間も会話は進み、入力欄の打ちかけも
残る。**答え待ちが来たら帯のいまの作業が「答え待ち」に変わる。** 中身の並びと採らなかった案は
`docs/architecture/screen-design.md` 13.6、帯は 13.9 が正典。

**領域そのものは縦にだけスクロールし、横には転がらない**（2026-09-15 決定）。
`.layout-region` に `overflow-y: auto` だけを書くと、CSS では片方の軸が `visible` でなくなった
ときにもう片方の `visible` も `auto` に計算されるため、書いていない `overflow-x` が `auto` に
なって4領域すべてが横に転がっていた。**横に長いものは、中身の側が自前のスクロール容器を持つ**
（レポートの表は `.table-scroll` の中で転がり、コードは折り返し、図は領域の幅に収め、
長い語は途中で折り返す）。

**狭い画面（760px 以下＝スマホ）では、画面の高さに固定して上段をタブで切り替える**
（2026-09-20 決定。基準は 390x844）。
全体の高さは **`100dvh`** に固定する（`vh` だとソフトウェアキーボードが出たときにページごと
押し上がる）。**上段はメインビューとサイドバーをタブで1つずつ出し**（同時には出さない）、
**下段のキャラビューと入力欄は常に見えたまま**にする。スクロールするのは上段の中だけで、
**ページ全体はスクロールしない**。**タブは「どちらを見せるか」の切り替えであって、領域を
統合するものではない**（4領域はそのまま4つある）。**仕切りのドラッグと「比率を既定に戻す」は
狭い画面では出さない**（動かせる比率が無い）。切れ目は `@media (max-width: 760px)` の1つだけで、
規則は各機能の CSS に分かれている（`docs/architecture/browser.md`「CSS」）。

**タスクのモーダル（「一覧を見る」で開く、左に一覧・右に詳細のモーダル）は、狭い画面では2列を
縦に積む**（2026-09-28 決定。2026-09-20 の「1タスク＝1枚のカード」は、表をやめたので置き換えた）。
一覧が上で高さを区切って内側で転がし、詳細が残りの高さで内側で転がし、下の操作の帯は箱の下端に
残す。組み替えるのは CSS だけで、部品の側は広い画面のまま書く（一覧と詳細を行き来する画面の
切り替えは持たない。切り替え画面〔`docs/architecture/screen-design.md` 13.9「切り替え画面」〕の積み方と同じ）。
値は `docs/architecture/screen-design.md` 13.12。**レポートの中の表はこの対象ではない**（`docs/architecture/screen-design.md`
13.3「領域の内幅に入りきらない表は、その表だけ横スクロールさせる」）。

**右下は入力欄**で、比率は CSS だけで決まる（1枚にまとめた理由と、そこが空いていた頃の経緯は
`docs/history/decision.md`「requirements.md 4.7 画面レイアウト」）。

- **上段と下段で縦の仕切り位置が違う。** 上段はメインが広くサイドバーが狭い、下段は半々。
  これは CSS の grid で表す
- **代償**: 領域を別々のウィンドウ（別モニタなど）に分けることはできない。今の構想では不要

### 4.8 セッションの復元

**tsukumo を起こし直したら、前の続きから始める**（2026-09-13 決定。元の指示は
`docs/history/decision.md`）。

#### 何を戻し、何を戻さないか

| もの                                       | 戻す     | どうやって                                                |
| ------------------------------------------ | -------- | --------------------------------------------------------- |
| claude 側の会話（文脈）                    | 戻す     | `query({ options: { resume: sessionId } })`               |
| メインビューのやり取り（レポート・ツール） | 戻す     | `getSessionMessages(sessionId, { dir })` を読み直して組む |
| 吹き出しのセリフ                           | 戻す     | 同上（`speak` の呼び出しは transcript に残っている）      |
| 答え待ち（許可・質問）                     | 戻さない | 前のプロセスの `canUseTool` は既に解決されている          |
| 書きかけの本文（`partial-utterance`）      | 戻さない | 仮の表示なので、完成した本文だけを組み直せば足りる        |

#### tsukumo 側に会話を保存しない

**復元のために会話を保存しない。** claude 自身が `~/.claude/projects/` に transcript を
書いている（SDK の `Options.persistSession`。既定 `true`）ので、**そこを正典として読み直す**。
tsukumo 側のキャッシュ・スナップショットは作らない。

これは `docs/coding-standards.md`「会話内容の扱い」の**「別の場所に複製しない」を満たす**。
複製にあたるのは「transcript の内容を tsukumo が別の場所へ書き出すこと」であって、正典を
読んでメモリ上のビューを組み直すのは複製ではない（組み上がったビューは今までどおりプロセスの
メモリにしかなく、`127.0.0.1` にだけ配られる）。**規約を曲げる必要は無い。**

**2026-09-21 に足した雑談の会話のアーカイブ（4.9）は、ここを変えない。** あちらは**あとで
活用するため・記憶の材料にするため**に会話の一部を残すもので、**復元の材料にはしない** — 起こし直したときに画面を
組み直すのは今までどおり transcript からで、アーカイブを読み戻す経路は作らない。

#### 鍵（どれを「前のセッション」とみなすか）

**起動した作業ディレクトリ（`cwd`）＋ tsukumo が付けた印**の2つで絞る。**印はキャラクター
パックごとに違い**（`tsukumo:<パック名>`。2026-09-14 決定）、**雑談のときだけ後ろに `:chat` が
付く**（2026-09-20 決定。4.9）ので、実質は「ディレクトリ×キャラクター×モード」で1つの
セッションになる。

1. セッションIDが届いたら（`session-info`）覚えておき、**ターンが終わるたびに**
   `tagSession(sessionId, <そのパックの印>, { dir: cwd })` で印を付け直す。**受け取った直後に
   付けても残らない**（本体もターンの終わりにセッションの要約を書いていて、その書き込みに印が
   含まれないため上書きで消える。実測は `docs/history/decision.md`）
2. **起動時に** `listSessions({ dir: cwd })` を読んで印の付いた一覧をメモリに持ち、起動時も
   切り替え（キャラクター・モード）のたびも、その一覧のうち**これから起こすパックの印を持つもの**
   から `lastModified` が最新のものを選ぶ（2026-09-28 決定。読むのに 0.2〜0.3 秒かかり、切り替えの
   待ちになっていた）。**1. で印が付いたら、持っている一覧にもその時刻で写す**。一覧は起こす
   たびに駆動を起こしたあとで読み直し、読めたら切り替え先の一覧を画面へもう一度流す（見出しと、
   外で増えた・消えたセッションはここで追いつく）。外で消された transcript を選んだときは、
   そのIDで `resume` して新規として起き上がる

**`cwd` は「起こしたリポジトリ」の意味で読む**（2026-09-22）。同じリポジトリでも worktree が
分かれていれば起こすたびに違うディレクトリになり、ディレクトリの文字列だけで絞ると
**前の続きが一度も見つからず、起動のたびに新規になる**ので、`listSessions` には
`includeWorktrees: true` を渡して**同じリポジトリの worktree を全部見てから印で絞る**。
履歴を読み直す `getSessionMessages` はディレクトリで絞らない（セッションIDが一意なので、
絞らなくても別のものには当たらない）。**鍵の考え方（ディレクトリ×キャラクター×モード）は
変わっていない** — 「ディレクトリ」の粒度がリポジトリになっただけ。

`cwd` だけで絞らないのは、`tsukumo` がグローバルに入っていて**どのプロジェクト
からも起こせる**（4.6）ため。同じディレクトリで素の `claude` を使っていると、印が無ければ
そちらのセッションを拾ってしまう。**印は会話の内容ではない**ので、transcript に付けても
「会話内容の扱い」には触れない。

**パックごとに分けるのは、キャラクターごとに別の部屋を持たせるため**（`docs/architecture/character-pack.md`）。
切り替えて戻ってくると、そのキャラクターとの会話と口調が戻る（実測は
`docs/history/decision.md`）。ただし**印はターンが終わって
3秒後に付く**ので、ターンを1つも終えずに離れたパックのセッションは次に来たときに見つからず、
下の「復元できなかったとき」と同じく新規から始まる。

**同じ `sessionId` を2つの `query` から重ねて `resume` すると、別ファイルへ fork するのではなく
同じ transcript へ混線する**（2026-09-22 実測。測り方は `docs/history/decision.md`）。
**印だけでは「その目印がいま使われているか」は分からない**ので、下の目印はその前提に立つ。

**2026-09-22 決定: 印の末尾に「目印」を足し、同じディレクトリで何個 tsukumo を起こしても
セッションを取り合わないようにする**（`tsukumo:<パック名>@7327` /
`tsukumo:<パック名>:chat@7327`）。鍵は「ディレクトリ×キャラクター×モード×目印」の4つになる。
組み立ても読み取りも `src/server/session-driver/core/session-mark.ts`（`sessionTag` / `readSessionMark`）だけで、
文字列を他所で作らない。

- **区切りは `@`。** `:` を使わないのは、後置きの `chat` と読み違えないため。**目印は
  いちばん後ろの `@` から先**で、読み取りもそこだけを見る
- **目印はビューのポート番号そのもの**（同日決定。**セッションを指す ID は「キャラクターパック
  × ポート番号」**にする、という決めごとの後半がここに出る）。ポートを使うのは、**「その目印が
  いま使われているか」を知っているものが他に無い**ため — 印は transcript に残るだけなので、
  落ちた tsukumo の印と動いている tsukumo の印は見分けられない（上の混線）。ポートは OS が
  握っていて、**既定なら塞がっているぶんだけずれ**（4.6）、**プロセスが落ちれば空く**ので、
  生きている tsukumo の起動順がそのまま出る
- **落ちた側を起こし直すと、空いたポートへ戻るので落ちた側の続きから始まる**（動いている側の
  印は目印が違うので拾わない）。起動のたびに自動で続きから始まるのは変えない（下の「いつ復元するか」）
- **畳まない。** 既定から遠い番号（`TSUKUMO_VIEW_PORT` で指したとき）も `0`（OS まかせ）も、
  そのまま名乗る（**ポート番号なら上限が無い**）
- **昔の印は読むときにポートへ戻す**（`readSessionMark` だけの仕事。transcript を書き換える
  手当てはしない）。**目印の無い印**（`tsukumo:<パック名>`）は既定の 7327、**1文字だった目印**
  （`@A` / `@B` …）は並び順から元のポート（`A` が 7327、+1 ごとに次の番号）。いま続いている
  仕事はそのまま見つかり、次にターンが終われば新しい形の印に置き換わる
- **印の一覧がそのままセッションの一覧**（`listMarkedSessions` が目印・`sessionId`・
  `lastModified`・始まった時刻（`startedAt`。SDK の `createdAt`）・見出し（`heading`。下）を新しい順に返す）。
  別の保存先は作らない。依頼の数・要約・最後のセリフは一覧に載せず、切り替え画面で選んだ1件ぶんだけ
  transcript から読む（`docs/glossary.md`「セッションの要約」）
- **切り替え先の一覧は、いまの部屋（起きている tsukumo のビューのポート）の印を持つものだけ**
  （2026-09-23 決定）。渡す鍵は続きから始めるときと同じ、目印まで揃えた印なので、別の部屋の
  セッションへは画面から行けない。**部屋の名前の表示は `docs/architecture/screen-design.md` 13.9「部屋の名前」が
  正典**（人が読む名前・目印との対応）。**一覧の行はいまの部屋のものだけになるので部屋の名前は
  全行で同じになり、切り替え画面の行では見分けの役に立たない**（下）
- **切り替え画面の行の見出しは SDK の `summary` にする**（2026-09-23 決定。`customTitle` →
  自動要約 → 最初の依頼、の順に決まる表示用の題。`getSessionInfo` / `listSessions` が返す
  `SDKSessionInfo.summary`）。追加のモデル呼び出しで tsukumo が題を作ることはしない。
  `SessionChoice.heading` として運び、読めない・空なら無いものとして畳む
  （`src/shared/session/session-choice.ts`）。**`/clear` で分かれたセッションは別の行のまま**でよく
  （それぞれに中身の分かる見出しが付けば足りる）、前後をつなぐ仕組みは作らない。行の形
  （短縮ID・見出し・時刻・見出しが無いときの見え方）は `docs/architecture/screen-design.md`「切り替え画面」
  が正典。**画面から新しいセッションを起こす口**（切り替え画面の「＋ 新しいセッション」。
  `session.startNewSession`）は続きを探さずに新規で起こす（2026-09-27 ユーザー決定）

#### いつ復元するか

**常に自動で続きから始める。** 起動のたびに選ばせる画面は作らない（手数が増えるうえ、
「1コマンドで起動」という 4.6 の狙いと衝突する）。**新しい会話を始めたいときの逃げ道**
（新規で起こす指定）は併せて用意する。

#### 復元できなかったときどうするか

**新しいセッションとして起動し、プロセスは落とさない。** セッションIDが古い・transcript が
消えている・`listSessions` が読めない、のいずれも「前提不足」ではなく「動作中の一時的な失敗」
として扱う（`docs/coding-standards.md`「エラーハンドリング」。起動時の即時終了は前提不足だけ）。
**画面の履歴の組み直しに失敗したときも同じ**で、会話（`resume`）だけ生きていれば続行する。

### 4.10 画像の添付

**入れる**（2026-09-21 決定。元の指示は `docs/history/decision.md`）。2.2 の「画像やファイルの
貼り付け」（2026-09-11）のうち、**画像だけを覆した**。

#### 渡せることの裏取り

**Agent SDK には画像を渡す道がある**（2026-09-21 に型定義と公式ドキュメントで確認。出典の一覧は
`docs/history/decision.md`「requirements.md 4.10 画像の添付 / 渡せることの裏取り」）。
`SDKUserMessage.message` の `content` に `image` ブロックを混ぜれば渡り、
**`Base64ImageSource`（`{ data, media_type, type: "base64" }`）で渡せ、形式は `image/jpeg` /
`image/png` / `image/gif` / `image/webp` の4つだけ。** **単発入力（Single Message Input）は画像を
受け付けない**ので、ストリーミング入力の側にいることが条件になる。

**tsukumo は最初からストリーミング入力の側にいる**（`createPromptStream` が `query` に「まだ
終わらない」非同期イテレータを渡している。4.1）。**渡し方を変えずに、`content` を文字列から
配列にするだけで済む。**

#### 受け取り方

**貼り付け（`paste`）・ドロップ（`drop`）・入力欄の下の画像のボタン（ファイルを選ぶ窓）の3つ。**
**クリップボードの画像を貼るのが主な道**で、これは `@` の補完では埋められない穴そのもの
（下の「ファイルは覆さない理由」）。操作の案内は入力欄の下の道具の行に1行で出す
（「画像は貼り付けかドロップでも」）。**ボタンは 2026-09-23 に足した**（それまでの形は
`docs/history/decision.md`）。選ぶ窓で選べるのは受け付ける4種だけで、ほかの種類は貼り付けと
同じく黙って落ちる。

#### 上限

**`docs/architecture/character-pack.md`「画面から作るときの置き場と受け取り方」（キャラクターパックの素材）の上限はそのままは使えない。** 向きが違い
（あちらは1つのパックが持てる総数、こちらは1件の依頼に添えられる数）、**受け付ける形式は
API 側で決まっている**。

| 何                        | 上限                                                                            |
| ------------------------- | ------------------------------------------------------------------------------- |
| 画像1枚（デコード後）     | 5 MiB（API の天井「base64 で1枚 10 MB」の内側で、スクリーンショットが収まる幅） |
| 1件の依頼に添えられる枚数 | 2 枚                                                                            |
| 控え1枚（デコード後）     | 128 KiB（長辺 320px の webp。下の「記録の大きさが有界になる」を数にしたもの）   |
| 形式                      | `.png` / `.jpg` / `.gif` / `.webp` の4つ                                        |
| WebSocket の `maxPayload` | 16 MiB（2 枚 × 5 MiB の base64 ≒ 13.33 MiB ＋ 控え2枚 ≒ 0.34 MiB ＋ 文面）      |

- **形式は tsukumo の都合ではなく API の天井。** `Base64ImageSource.media_type` が上の4つしか
  取らないので、**`.svg` は渡せない**（立ち絵は `.svg` を受け付けるが、あちらは画面に描くだけで
  モデルへは渡らない。同じ「画像の上限」に見えて別の制約）
- **枚数を 2 枚に絞ったのはリクエスト全体の天井のため。** 1枚あたりを 5 MiB まで緩めたので、
  枚数まで広いと base64 が API の 32 MB に届きうる（2 枚なら ≒ 13.3 MiB で当たらない）。
  「スクリーンショットを1〜2枚貼る」という主な使い方は 2 枚で足りる
- **`maxPayload` を上げても依頼の文面は緩まない**（`MAX_PROMPT_TEXT_LENGTH` の 20,000 文字が
  別に効いている）

#### 画面での見え方

**送る前は入力欄の中の小さな札、送ったあとは依頼に付く控え。**

- **送る前**: 添えた画像が `<textarea>` の上に**小さな札**（縮めた絵と外す `×`）で並ぶ。
  **1枚も無いときは何も出ない**ので、常設の枠にならない
- **送ったあと**: 依頼の記録（`request`）に**縮めた控え**が付き、仕事のときはメインビューの
  依頼の見出しの下に、雑談のときは利用者の発言の吹き出しの中に並ぶ（`docs/architecture/screen-design.md` 13.7。
  LINE / Discord と同じ見え方になるのはここ）
- **札も控えも押すと原寸を拡大して見られる**（2026-09-23 決定。ホバー・フォーカスで虫眼鏡を
  重ね、押すと画面の内側に収めた拡大の面が開く。閉じ方は Esc・背景のクリック・閉じるボタンの
  3つ）。控えは押した瞬間に id で下の「棚」から原寸を取りに行き、**残っていれば原寸を、棚から
  落ちていれば控えを代わりに拡大して「原寸はもう手放したので、控えを拡大しています」と1行
  添える**

#### 会話内容の扱い（この機能の形そのもの）

**画像も会話の内容**（`docs/coding-standards.md`「会話内容の扱い」）。**この制約は注意書きではなく、
上の形の決め方そのものになっている。**

- **ディスクに書かない。** 原寸はブラウザのメモリ → WebSocket の1フレーム → サーバのメモリ →
  SDK の子プロセス、と流れるだけで、**どこにも書き出さない。一時ファイルに落とす案は採らない**
  （`src/server/adapter/` に新しい書き込み先が増え、「どこに置きいつ消すか」という問いが
  生まれる。`Base64ImageSource` で直接渡せるので、そもそも要らない）
- **原寸はサーバのメモリの「棚」に直近ぶんだけ残る**（2026-09-23 決定。
  `src/server/session-driver/core/prompt-image-shelf.ts`）。記録（`SessionState`）と `hello` に載るのは
  控えと id の組だけで、原寸は棚にしか無い。**捨てる契機は2つ**——記録の窓（4.9のターン数。
  仕事20・雑談100）から依頼が落ちたときと、棚が持つ原寸の合計の大きさが
  `MAX_SHELVED_PROMPT_IMAGE_BYTES`（128 MiB。枚数の上限から変えた経緯は
  `docs/history/decision.md`）を超えたとき（古いほうから）。**どちらの契機でも、棚はディスクに
  書かない**（プロセスのメモリにだけ置く。上の1つめの約束のまま）。**上の「控えも押せる」は、
  棚に原寸が残っている間だけ効く**
- **控えだけを記録に残すので、記録の大きさが上限を持つ。** 原寸を `SessionState` に積むと
  雑談の 100 ターン（4.9）で数百 MiB に届きうるが、控えなら1枚あたり数十 KiB で収まる。
  **縮めるのはブラウザ側**で、サーバは受け取った控えをそのまま `request` に載せるだけ
  （**サーバは画像を加工しない**）
- **経路は既にあるものをそのまま使う。** 起動トークンと `Origin` の照合・zod の検証・定型文の
  `error` が効く WebSocket の `prompt` コマンドに足すだけで、新しい書き込み口（POST）を作らない
  （`docs/architecture/character-pack.md`「画面から作るときの置き場と受け取り方」と同じ判断）
- **Claude Code 本体が自分の transcript に何を書くかは変わらない**（`~/.claude/`。文面と同じ
  扱いで、4.8 の復元はそこを読む）。**tsukumo が新しく残す場所を作らない**、というのがここでの約束

#### ファイルは覆さない理由

**2.2 のうち覆したのは画像だけで、ファイルの貼り付けは対象外のまま**（理由は 2.2 の
「ファイルの貼り付け」。**画像だけが例外なのは、クリップボードの画像にパスが無いから** —
`@` で埋められない穴はそこ1つしかない）。

### 4.11 成果の振り返り

**終えたタスク（Beads の閉じた課題）を日ごとに数えて画面に並べ、ボタンを押したときだけキャラクターにその日の
日記を書いてもらい、日記を後から読み返せるように残す**（2026-09-24 に数えて感想を言ってもらう形で
決め、2026-09-25 に日記を書いて残す形へ広げた。2026-10-08 に、コミットの数をやめて閉じた課題だけで数えると決めた）。1章の2つの成分のうち「一緒にいる感じ」を、仕事の結果の側から足すもの。目的は
「キャラクターが自分の仕事をちゃんと見ていてくれて、それが後から読み返せる形で積もっていく」
こと。画面の形は `docs/architecture/screen-design.md` 13.10、状態に入れず取りに行く決まりは `docs/architecture.md`
「成果は `SessionState` に入れない」、日記の保存の形は `src/server/diary/adapter/diary.ts` の冒頭。

**決まっていること**（蒸し返さない）:

- 見せ方は**区切りでまとめて振り返る**だけ。その場で反応するもの（`done` になった瞬間・節目の
  数に届いた瞬間）は作らない
- **キャラクターが自分から成果に触れる経路は足さない**（2026-10-05 利用者決定）。区切りの迎えの
  挨拶に前日・今日の成果を混ぜる案と、`done`・節目の瞬間に一言触れる案を比べ、成果の画面と日記だけの
  今の形を保つと決めた。タスクを終えたことは本体がそのターンの締めの `speak` で話しており、
  瞬間に触れる案はそれと二重になり、終える件数が多い日や並行する作業ツリーの分でうるさくなる
- **数えるのは Beads の閉じた課題だけ**（2026-10-08 利用者決定）。git の枝もコミットも読まない。
  閉じた課題は作業ツリーに依らないので、並行する作業ツリーで終えた分も二重にならずに入る。
  どの枝へ送るか・PR に留めるかはワークフローの持ち物で、tsukumo は主ブランチを知らない
- 区切りは**ローカル時刻の日**（0時で切る。日の境目は OS のタイムゾーンで、
  `src/server/adapter/local-time.ts` の1箇所が決める）。前の日へ遡れる
- 置き場は帯の口に足す1枚の画面（「成果」）
- キャラクターは、画面のボタン（「<キャラクターの名前>と振り返る」）を押したときに、**会話の
  セッションとは別の使い捨ての問い合わせ**で**専用のツール `diary` で日記を書く**（下の「日記」
  「振り返りの依頼」。2026-09-25 に、会話へ1ターンの依頼を送る形から改めた）。**会話のメインビュー・
  キャラビュー・会話の文脈には何も残らない**。**画面を開いただけでは書かせない**。押しても画面は
  会話へ移らない
- **会話のターン中でも振り返れる**。同時に書かせるのは1日ぶんだけ（書いているあいだは次の
  振り返りを断る）
- **卒業と節目は tsukumo が数える**（モデルに選ばせない。下の「卒業と節目」）。依頼にも載せる
- **前日比と連続日数は数えない**（数を競わせる画面にしない）
- **見る日が読めない・今日より先なら今日に倒す**（断らない）。「今日」はサーバのローカル時刻で
  決め、ブラウザは時計を読まない
- **取り直す契機**: 画面を開いたとき・日を切り替えたとき・窓にフォーカスが戻ったとき、今日を
  見ているあいだは 60 秒ごと（暦も同じ）、日記が書き上がったときはその日と暦。タスク板の
  `tasks-changed` には繋がない（着手の印の出入りでも飛ぶため）。振り返りの画面なので1分の遅れは
  問題にしない
- **数えられない・読めないときの出し方**は、下の「数えられない・読めないとき」の表

#### 数えられない・読めないとき

どの読みが欠けたら何を出すかの正典（2026-10-05 利用者決定を含む）。数える途中の `bd` の
失敗・時間切れは部分的な数を出さず「取れなかった」にする。読むのは Beads だけなので、Beads が読めなければ
成果のどの部分も出さない（終えたタスクだけ「数えられない」にする場面は無い）。

| 場面                                                                              | 数の札   | 暦                                                   | 日記・しおり・節目                                                                                                  | 1行の注記                                                            |
| --------------------------------------------------------------------------------- | -------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `.beads` が無い・`bd` が無い                                                      | 出さない | 出さない                                             | 出さない。日の切り替え・ボタンも出さない                                                                            | 「このディレクトリでは成果を数えられない（Beads の課題が読めない）」 |
| 取りに行って失敗した（`.beads` があるのに `bd` が落ちた・時間切れ、応答が落ちた） | 出さない | 別に取るので、取れていれば出す。取れなければ出さない | 出さない。日の切り替えは使える                                                                                      | 成果は「成果を取れなかった。」、暦は「灯りの暦を取れなかった。」     |
| 日記のファイルが読めない                                                          | 出す     | 出す                                                 | 日記が無い日と同じに出す（数・卒業・節目は出る）。ボタンで書き直すと、読めなかったファイルは新しい1段落で置き換わる | 無し                                                                 |

#### 何を数えるか

| 数えるもの   | 規則                                                                                                                   |
| ------------ | ---------------------------------------------------------------------------------------------------------------------- |
| 終えたタスク | Beads の課題のうち、閉じた時刻（`closed_at`）がその日のうちにあるもの（下の「`done` になった日」）。閉じ方は見分けない |

**進めたことは、タスクの題で足りる。**

- 完了したことの本文（何を・なぜ・どう検証したか）は課題ごとに別の場所にあり、並べても題とほぼ同じ行が
  2度出るだけで、振り返りの画面で読む量ではない
- タスクを通さずに済ませた仕事（会話で頼まれた作業）は数に出ない。コミットの数で拾っていたが、
  数える枝を決めるのに主ブランチを知る必要があり、それはワークフローの持ち物なのでやめた（2026-10-08）

**取り下げた課題も終えたタスクに数える**のは、取り下げの印が Beads の組み込みの欄に無く、スキルが足したラベルでしか
見分けられないため（`docs/architecture/adr/0024-no-skill-dependency.md`）。

#### `done` になった日

**Beads の閉じた課題の、閉じた時刻（`closed_at`）のローカルの日で決める**（2026-10-05 利用者決定）。
その日の始まりから終わりまでに閉じた課題を、その日に終えたと
数える。`bd list` を1回読み、閉じた時刻で振り分ける。

- **読むのは Beads だけ。** git の履歴にあるタスクの置き場のファイルは読まないので、
  Beads へ移す前の日の終えたタスクは数に出ない
- 画面と依頼に出すのは、課題の題（`title`）
- **`.beads` が無い**（`bd where` が見つけない・`bd` が無い）リポジトリ（tsukumo をほかのプロジェクトで
  起こしたとき）の出し方は「数えられない・読めないとき」。
  **`.beads` があるのに `bd` が落ちた・時間切れ**のときは「取れなかった」にする（黙って少なく数えない）
- **リポジトリごとの設定ファイルは無い**（2026-10-08。`docs/architecture/adr/0025-no-project-settings.md`）。Beads だけを読む

#### 卒業と節目

画面の「小さな驚き」に出し、振り返りの依頼にも載せる、その日に起きた特別なこと
（2026-09-25 決定）。**どちらも tsukumo が数え、モデルには選ばせない**（数え間違いが日記に
書かれない。見るたびに同じものが出る）。区切りの値は**プロトタイプとしての仮の値**で、使い
ながら直す。

**先輩タスクの卒業**: その日に終えたタスク（上の「`done` になった日」）のうち、**登録から7日以上
経っていたもの**（仮）。

- **登録日は、Beads の課題を作った日**（`created_at` のローカルの日）。登録から N 日は
  「終えた日 − 登録日」の日数
- git のタスクファイルから Beads へ移した課題は、移した日が登録日になる（タスクファイルの履歴を
  読まないため。2026-10-05 の利用者決定の帰結として受ける）
- 並びは登録の古い順（長く待っていたものほど先）。数に上限は置かない（仮）

**節目**: **通算 N 件目のタスク**。その日の終わりまでに閉じた Beads の課題の数（上の「`done` になった日」と
同じ規則）が、刻み（仮に 250 件ごと）の倍数をその日にまたいだとき。2026-10-08 にコミットの節目（通算 N コミット目）を外した。

- **何件目になったのがどれか**: 前の日の終わりまでの数に、その日に終えたタスクを閉じた
  時刻の順に足していって N に届いたもの
- 1日に節目を2つまたいだら（刻みより多く進んだ日）、大きいほう1つだけ出す

#### 灯りの段階

灯りの暦（`docs/architecture/screen-design.md` 13.10）の1日ぶんの明るさ。**その日に閉じた Beads の課題の数で決める**
（2026-10-08。見開きの灯りも同じ。区切りは仮）:

| 段階     | 閉じた課題の数 |
| -------- | -------------- |
| 灯りなし | 0              |
| ほのか   | 1〜9           |
| ともる   | 10〜39         |
| 明るい   | 40 以上        |

- 閉じた時刻は、暦のために読む `bd list` 1回の結果から日ごとに数える
- 暦の応答は、マスの数が何の数かを運ぶ欄を持たない（数えるのは閉じた課題の1種類だけ。2026-10-08 に、コミットの数と閉じた課題の数を見分ける欄を消した）
- 区切りは 2026-09-25 にコミットの数に合わせて、ふつうの日が「ともる」〜「明るい」に入るように置いたもの。
  閉じた課題の数に替えても区切りは変えない。このリポジトリの閉じた課題は 2026-09-27〜10-08 に
  1日 8〜63 件・中央値 41 件（同じ期間のコミットは 27〜176 件・中央値 57 件前後）で、ふつうの日が
  「ともる」〜「明るい」に入る狙いがそのまま成り立つ（2026-10-08 の実測）。**別のリポジトリでは
  明るくなりにくい**（見直すのは、使ってみて段階が偏ったとき）
- **空の日**（その日に閉じた課題が0）は灯りなしで、振り返りも押せない（`docs/architecture/screen-design.md` 13.10
  「空の日・数えられないとき」）。タスクを通さずに済ませた仕事だけの日も空の日になる

#### 日記

**振り返りの問い合わせでキャラクターが `diary` ツールで渡す、その日の1ページ**（2026-09-25 決定。
語は `docs/glossary.md`「日記」、保存の形は `src/server/diary/adapter/diary.ts` の冒頭）。

- **渡すもの**: 本文（キャラクターの口調で、その日の仕事について書く短い文）・しおり（その日に
  終えたタスクの ID と、それを選んだ理由）・表情（`speak` と同じ表情の一覧から）。しおりは
  終えたタスクが無い日だけ省ける
- **tsukumo が足すもの**: 書いた時刻、書いた時点のパックの名前と顔（パックのディレクトリ名と
  表示名。あとでキャラクターを替えても、誰が書いたかが残る）
- **置き場はホームの下に、リポジトリごと・日付ごと**。日付は振り返った日ではなく**振り返りの
  対象の日**。リポジトリは作業ツリーではなく共有の `.git` で見分ける（同じリポジトリの別の
  作業ツリーから書いても、同じ日記帳に入る）
- **同じ日に2回振り返ったら書き足す**: 本文は新しい段落として後ろに足し、しおりは新しいほうに
  差し替える。書き直し（前の段落を消す）はしない
- **問い合わせが `diary` を受け付けられずに終わったら「書けなかった」**を画面に出し、ボタンを戻す
  （時間切れ・失敗・起こし直しで中断したも同じ）。受け付けられない呼び出し（しおりの ID がその日に
  終えたタスクに無い・本文が空など）は理由を返して呼び直させる（`report` と同じ線）
- **受け付けない呼び出し**（仮の上限）: 同じ問い合わせで2回目・本文が空か 600 文字を超える・
  終えたタスクがあるのにしおりが無い・しおりの ID がその日に終えたタスクに無い・理由が空か
  120 文字を超える・保存に失敗した
- **書いたパックの顔は画像を写さず、ディレクトリ名で指す**（仮）。パックを消すと名前だけになる
- **しおりにはそのときのタスクの題を写して残す**（あとで課題が消えても読める）
- **仕事でも雑談でも、同じ形で書ける**（会話のモードに関わらない）。会話に入らないので、雑談の
  アーカイブにも残らない（4.9「雑談の会話のアーカイブ」）
- 日記は会話の写しではない（キャラクターがツールで渡す成果物）。ただし文面はログに出さず、
  ホームの外へ出さない（`docs/coding-standards.md`「会話内容の扱い」。`docs/architecture.md`「会話内容と安全」）

#### 振り返りの依頼

ボタン（または見開きの「この日を振り返る」）を押すと、振り返りのコマンドが見ている日付を
tsukumo へ送り、**tsukumo がその日の成果を数え直して依頼文を組み立て**、**会話のセッションとは
別の使い捨ての問い合わせ**に1回渡す（下の「会話から切り離す」）。**依頼文は tsukumo が数えたもの
だけから組み立てる**（キャラクターにファイルやログを読みに行かせない。数え直しで画面と話が
食い違わないように、そして1回の問い合わせで済むように）:

```
9月23日の成果を一緒に振り返って、この日の日記を書いてほしい。終えたタスクは 31 件。
終えたタスク:
- <課題の ID> 帯のトグルといまの作業の札を見本の値に揃える
- …
小さな驚き:
- 先輩タスクの卒業: <課題の ID>（登録から 12 日）
- 節目: 通算 500 件目のタスク
日記は diary ツールで1回書いて。本文はこの日の仕事の感想とねぎらいを短く。しおりには終えたタスクから1件を選び、選んだ理由を添える。ファイルやログは読みに行かず、この一覧だけで書いてほしい。次にやることの提案はいらない。
```

- **日の言い方**は「今日」「昨日」、それより前は「9月21日」の形
- **並べるタスクは20件まで**。超えたら「ほか n 件」の1行に畳む（1日に数十件終える日があり、
  依頼が長いと問い合わせが重くなる）。終えたタスクが0件の日（空の日）は振り返りを断るので、
  依頼文は常に終えたタスクの一覧としおりの頼みを持つ
- **小さな驚きは、あるときだけ**「小さな驚き:」の行を出す（卒業は ID と登録からの日数、節目は
  数）。**本文で触れるかはキャラクターに任せる**
- **その日に既に日記があれば**、「この日の日記は既にあるので、続きとして書き足す」の1行を足す
  （前の本文は載せない。書き足す段落だけを書いてもらう）
- **モードで文面を変えない**（`report` の1行は足さない。問い合わせには `report` ツールが無い）
- **キャラクターに書いてほしいのは感想とねぎらい**で、評価や指摘ではない。表情は指定しない
  （`diary` の `expression` はキャラクターが選ぶ）。口調は `persona.md` に任せ、依頼文には
  書かない（原則4。キャラクターの中身をコードに書かない）
- 依頼文に入るのは数とタスクの ID・`summary` だけで、会話の文面は入らない
  （`docs/coding-standards.md`「会話内容の扱い」）。会話に入らないので、画面のどこにも依頼文は
  出ず、雑談のアーカイブにも残らない

**会話から切り離す**（2026-09-25 決定。元の指示は同日のユーザーのフィードバック「振り返りを会話から
独立させたい」。起こし方の形は `docs/architecture.md`「使い捨ての `query()`」）:

- **書かせるのは使い捨ての問い合わせ**（会話とは別の claude の子プロセス）。
  持たせるのは `diary` ツールだけで、ファイルを読む道具も `speak` も `report` も持たせない。
  **人格（`persona.md` の全文。雑談で覚えたことの節も含む）は効かせる**。日記を1つ書き終えたら
  終わり、transcript を残さない（続きから始めるセッションの一覧にも出ない）
- **会話のセッションには何も残らない**: メインビューに依頼文・レポート・ターンが増えず、
  キャラビューにセリフが出ず、会話の claude の文脈にも入らない（次のターンのキャラクターは
  日記を書いたことを知らない。受け入れる）
- **会話のターン中・答え待ちの最中でも押せる**。押せないのは、別の日（または同じ日）の日記を
  いま書いているあいだだけ。書いているあいだにキャラクター・モード・セッションを切り替えると、
  書くのをやめて「書けなかった」と同じに扱う（起こし直すと画面は初期状態に戻るので、ボタンは
  戻る）
- **トークン消費の記録（`~/.tsukumo/token-usage/`）には数えない**。記録の
  1行は会話のセッションの1ターンで、押したときだけの短い問い合わせを混ぜる軸が無い。消費が
  目立ってきたら、そのとき数え方を足す
- **書き手のモデルは会話のいまのモデル**（日記は後から読み返す物なので、会話と同じ声で書かせる。
  軽いモデルは使わない）。考える段は切る。呼び直しの余地は4ターン、**120 秒で
  諦める**（どちらも仮）
- **疑似セッション（`TSUKUMO_DRIVER=fake`）では書かせない**（押すとすぐ「書けなかった」になる）
- **進みは3段で見せる**（段のツールは足さない。1回の `diary` の呼び出しで済む短い問い合わせで、
  段ごとにツールを呼ばせると往復が増えるため）:

| 段                   | 入る合図                                                             |
| -------------------- | -------------------------------------------------------------------- |
| この日のタスクを読む | 振り返りを受けて書き手に渡した                                       |
| 日記を書く           | `diary` の呼び出しが書かれ始めた                                     |
| いちばんを選ぶ       | 書かれている引数に `bookmark` が現れた（本文の途中は画面に流さない） |

欄の順を守らずしおりを先に書くと2段目をすぐ抜け、しおりの無い日は3段目に入らない。どちらも
見え方が飛ぶだけで、書き上がりは `diary` を受け付けたことで決まる

### 4.12 トークン消費の見直し

**トークン消費の画面の「減らし方を見てもらう」は、いまの会話の1ターンとしてスキル
`token-usage-diet` を流し、結果を tsukumo の MCP ツールで構造のまま受け取る**（2026-09-24。
語は `docs/glossary.md`「見直し」「見直しの段」「提案」、画面は `docs/architecture/screen-design.md` 13.2）。
tsukumo 本体は分析しない。**スキルと集計スクリプトは tsukumo に同梱する**（`plugin/` を SDK の
プラグインとして載せ、`tsukumo:token-usage-diet` の名で呼ばれる。2026-10-04）ので、利用者のホームに
スキルが無くても見直しが流れる。集計は python3 で走る（5. の実行時の依存）。

- **ツールは2つ**: 段の進みを渡す `usage_review_stage` と、結果を1回で渡す `usage_review_result`。
  段は**いまの段だけ**を運び、並びより前を済と読む。載るのは**仕事のときだけ**（`report` と同じ）
- **段の右の数（モデル・キャッシュ・ツール）はスキルから受け取らない。** tsukumo の集計
  （見直しの期間で引いたトークン消費の集計）から出す。スキルの書き間違いが画面に出ない
- **見直し中の契機は「そのターンで `usage_review_stage` が届いた」こと**（画面のボタンか入力欄かは
  見ない。依頼の文面を読まない）。経過はそのターンの始まりから数える。**見直し中のままターンが
  終わったら（成功・止めた・失敗のどれでも）、セッションが終わったら、ふだんへ戻す。** 結果は
  次の見直しまで残る。起こし直すとふだんから始まる
- **提案の識別子は種類 + 対象**。種類はスキルの候補に揃えた固定の列挙で、列挙の外は断る
  （言い回しの揺れで見送りが黙って効かなくなるため）。種類を足すときはスキルと一緒に直す。
  提案の数には上限がある（`MAX_USAGE_PROPOSALS`）
- **押す口は「tsukumo に頼む」と「タスクにする」の2つ**。押したときの依頼文は提案に持たせず、
  tsukumo が見出し・やること・根拠から組む（スキルが書く欄を増やさない）。**起動先の `.beads` が
  読めない（タスク運用なし）なら「タスクにする」の提案を受け付けない**。
  段の戻り値でそれを伝え、呼ぶたびに `.beads` を読み直す
- **受け付けない結果**: 空の見出し・空の欄・上限を超える件数・識別子の重なり・見送った提案・
  タスク運用なしでの「タスクにする」。
  理由と直し方を返して呼び直させ、状態は変えない（`report` と同じ線）
- **見送り**: 画面から見送った提案の識別子をホームに残し、以後の見直しから外す。見送った一覧は
  `usage_review_stage` の戻り値で渡す（入力欄から呼んだときにも渡るように）。**取り消す口は画面に
  無い**（ホームのファイルから手で消す）。見送りは会話へ送らないので、ターン中でも押せる
- **前回の結果**: ホームに**直前の1回だけ**を上書きで残し、「前回の提案」として出す（履歴を並べて
  選ぶ画面は作らない）。起こし直しをまたいで残り、見送った提案はそこからも除いて出す
- 残すのは結果と識別子だけで、会話の文面は残さない（`docs/coding-standards.md`「会話内容の扱い」）

## 5. 実行環境・非機能要件

実装スタック: **Node + TypeScript**（2026-09-26 に Bun から移すと決め、2026-09-27 に完了した。
理由は `docs/architecture/adr/0002-render-migration-tech-choice.md`）。チェックコマンドは
`pnpm run check`。

実行時の依存は次のとおり:

- **`@anthropic-ai/claude-agent-sdk`**（npm パッケージ）— Claude Code を動かす。2026-09-11 に
  追加。これが唯一の本質的な実行時依存で、`claude` 本体は SDK が子プロセスとして起こす
- **`orca` コマンド**— 使うのは **`orca tab list` / `orca goto` / `orca tab create --url`（ページを箱の中に開く・開いているタブを貼り直す）だけ**。
  1つのアダプタに閉じ込め、**無ければその機能を諦めて動作を続ける**（`orca` に何ができるかの
  一覧は `docs/history/decision.md`「requirements.md 5. 実行環境・非機能要件 / Orca の使える機能」）
- **`python3` コマンド**— 同梱した見直しのスキルが使用量の記録を集計するのに使う（4.12。2026-10-04
  承認）。tsukumo 本体からは起こさず、会話の中でスキルが走らせる。無ければ見直しが集計できないと
  断るだけで、ほかの機能は動く
- **本体（立ち絵・吹き出し・レポートの整形）は外部コマンドに依存しない**
- **2026-09-13 の移行で足す npm の依存（React・`ws`・unified 一式）は承認済み**（一覧は
  `docs/architecture/build.md`）。外部**コマンド**は増えない
- これ以外の実行時依存を増やすときは、ユーザーの承認を得る

開発する環境は **macOS + Orca**（第一級の環境は 2.3）。**バージョンや導入済みコマンドの一覧は
正典に持たない**（2026-09-21 決定。時間が経つと変わるので、前提にする前に**その場で確認する**。
2026-09-09 時点の実測は `docs/history/environment-2026-09-09.md`）。

**ただし「入っていないもの」は残す** — 外部コマンドを増やす提案を止める材料になるため。
2026-09-09 時点で**未導入**だったのは `tmux`, `chafa`, `viu`, `timg`, `img2sixel`, `cowsay`,
`deno`, `cargo`。これらに依存する案は、入れてよいかの承認から始まる。

Node の下限は `package.json` の `engines.node`（`>=26`）。`engines` は宣言で、`pnpm install`・
`pnpm run` は止めない。止めるのは `bin/tsukumo` で、古い node ならメッセージを出して 1 で終える
（起動時の前提不足に当たる）。`node src/cli.ts` や `pnpm run start` を直に打つ開発用の入口は覆わない。
`.ts` を直に実行するので、古い node ではファイルの中に案内を書く場所が無い。

非機能要件:

- **常駐プロセスは、描画1回の失敗で落ちない。** 未知のイベントが来ても、画像が読めなくても、
  `orca` コマンドが失敗しても、次の更新で復帰する。**SDK のセッションが終わったり落ちたりしても
  プロセスは生き、画面はその事実を出す**（黙って止まらない）
- **会話は tsukumo のプロセスの外へ出さない。** SDK のイベント（本文・ツールの入出力・`speak` の
  引数）にはユーザーの生の会話が入る。外部へ送らない、別の場所に複製しない、ログに丸ごと
  出さない（`docs/coding-standards.md`「会話内容の扱い」が正典）。**ビューの HTML は
  ファイルに書き出さない。** 本文はプロセスのメモリにだけ持ち、`127.0.0.1` にだけバインドした
  サーバから配る（4.2）
- 画面への反映は体感で気にならない程度（目安1秒以内）。厳密な数値目標は置かない

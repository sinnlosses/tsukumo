## 1. 概要・目的

**tsukumo** は、Claude Code との会話を、キャラクターの立ち絵と吹き出しでターミナルに
表示するサイドカーである。Claude Code 本体のTUIには**一切割り込まず**、別ペインで常駐する
プロセスがセッションの transcript（JSONL）を追従して描画する。

名前は付喪神から。長く使った道具に魂が宿るように、ターミナルという道具に姿と声を与える。
（検討時の作業名は `chara-terminal` だった。正式な名前は `tsukumo`）

## 2. スコープ

### 2.1 対象とすること

- Claude Code の transcript（JSONL）を追従し、最新の assistant 発話を取り出す
- 別ペインに常駐し、立ち絵＋吹き出しを描画するプロセスを提供する
- hook が書き出す状態ファイルを読み、表情・衣装を切り替える
- キャラクターの素材と、表情・衣装の対応を差し替え可能にする
- 他のCLIエージェント（Codex / Gemini CLI 等）のログにも流用できる形に保つ
  （本体はただのログ tailer であり、**流用を妨げない**ことまでが対象。個別対応は対象外）

### 2.2 対象外とすること（スコープ外）

- **Claude Code 本体のTUIへの描画割り込み**。技術的に不可能（「3. 技術制約」）
- Claude Code 本体のフォーク・パッチ適用
- 音声合成そのものの実装。VOICEVOX 連携は口パク同期の入力としてのみ検討し、後回しにする
- 会話内容の外部送信・クラウドへの保存（「5. 実行環境・非機能要件」の会話内容の扱い）
- キャラクター素材そのものの同梱・配布。**素材は利用者が自分で用意する**。権利の扱いを
  このリポジトリに持ち込まないため
- Windows / Linux での動作保証。動けばよいが、確認するのは macOS のみ

### 2.3 想定利用者

個人利用（作者本人）。macOS の VS Code 統合ターミナルと Orca を第一級の環境とする。

## 3. 技術制約

**Claude Code のTUIは自分で全画面を描画する。** ここから次が決まる:

- `claude | cowsay` のようにパイプを噛ませる方式は**不可**
- hook の stdout はエスケープされてテキスト扱いになるため、そこから ANSI エスケープや
  画像プロトコルを流し込む方式も**不可**

したがって tsukumo は**本体の描画に割り込まない**。サイドカー方式（別ペイン常駐）を採る
理由はこれ1つであり、他の方式に作り直そうとする前に必ずここを読む。採用アーキテクチャと
採らなかった案は `docs/architecture.md` が正典。

## 4. 機能要件

### 4.1 発話の取得

- transcript の場所は `~/.claude/projects/<cwd をスラッグ化したもの>/<session-id>.jsonl`
- 最新の assistant 発話は次で取り出せる（2026-09-08 に動作確認済み）:

  ```bash
  jq -r 'select(.type=="assistant") | .message.content[]? | select(.type=="text") | .text' \
    ~/.claude/projects/<slug>/<session-id>.jsonl | tail -1
  ```

- hook には `transcript_path` が渡る。SessionStart hook で既知の場所に書き出しておけば、
  サイドカーは**スラッグ化の規則を自前で再実装せずに**追従先を知れる
- 行の `type` 分布（2026-09-09 に907行で実測）: `attachment` / `assistant` / `user` /
  `permission-mode` / `mode` / `last-prompt` / `bridge-session` / `atis-latch` / `ai-title` /
  `system` / `file-history-snapshot` / `file-history-delta`。**assistant 以外は無視してよい**が、
  **未知の `type` が来ても落ちないこと**。後半の5つは 2026-09-08 の実測時には無かったもので、
  **この集合は増える**と実際に確かめられている
- **assistant 行の `content[]` にも複数の `type` がある**（同じ実測で `tool_use` 84 /
  `thinking` 58 / `text` 30）。**吹き出しに出してよいのは `type: "text"` だけ。**
  `thinking` はモデルの内部の思考なので、表示すると事故になる
- 同じディレクトリには `<session-id>.jsonl` のほかに `<session-id>/` という**サブディレクトリ**が
  でき、その下にサブエージェントの transcript（`subagents/*.jsonl`）が入る。
  **`*.jsonl` を再帰的に拾うとサブエージェントの発話まで混ざる**ので、追従先は1ファイルに絞ること

### 4.2 表示

- **立ち絵**: ターミナルの画像プロトコル（Sixel / iTerm inline images）で表示する。
  ドット絵ではなく本物の立ち絵を出せることを狙う
- **吹き出し**: 最新の発話をペイン幅に合わせて折り返し、枠で囲って表示する
- **フォールバック**: 画像プロトコルが使えない環境では、**吹き出しだけを表示して動作を続ける**。
  立ち絵が出ないことを理由に起動失敗にしない
- **タイプライター表示**と、VOICEVOX の口パク同期は後回しでよい（MVPに含めない）

### 4.3 状態連動

- **表情差分**: hook イベントで切り替える。対応の初期案は
  `PreToolUse` = 作業中 / `Stop` = どや顔 / エラー = あわあわ
- **モデル別の衣装**: `haiku` = 軽装 / `sonnet` = 通常装備 / `opus` = 戦闘配置。
  Asuna output style の「出撃時の掛け声」のモデル分岐と対応させる。
  **`model` は `SessionStart` の payload にしか載らない**（他のイベントのスキーマには無い。
  Claude Code v2.1.263 のバイナリに埋め込まれたスキーマ定義で確認）。したがって hook は
  SessionStart でだけ `model` を拾い、以降のイベントは状態ファイルの前回値を引き継ぐ。
  値の形式（短い別名か解決済みの完全なモデルIDか）は未確認なので、衣装の判定は部分一致で行う
- 表情・衣装の対応は、キャラクター定義ファイルの形式が決まるまで `src/expression.ts` に置く
  （決まったら定義ファイル側へ移す。「7. 未決事項」）
- **hook は状態ファイルを書くだけ**にし、描画はサイドカーが行う。hook の stdout からは
  何も描画できない（「3. 技術制約」）ので、状態の受け渡しはファイル経由になる

### 4.4 キャラクター定義

- 素材（立ち絵の画像）と、表情・衣装の対応は**宣言的な定義ファイル**で差し替え可能にする。
  ハードコードしない
- 先行事例の claude-code-mascot-statusline がキャラパックを YAML/JSON で差し替え可能に
  している。同じ考え方を採る（形式そのものは実装スタックの決定と合わせて決める）

### 4.5 statusline 併走（案B・優先度低）

statusline 側にも小さいマスコットを出す。mascot-statusline をフォークし、
**hook が書く状態ファイルをサイドカーと共有**すれば二重実装にならない。

サイドカーが動いたあとの追加機能であり、MVPには含めない。

### 4.6 起動と設定

- 別ペインで常駐プロセスとして起動する。ペイン分割は **VS Code の split terminal** で
  代用できるため、tmux の導入は前提にしない
- hook の登録先である `~/.claude/settings.json` は、**既存の hooks / statusLine 設定を
  壊さないよう追記する**（現状 orca が専有している。`develop/progress.md`「注意」参照）

## 5. 実行環境・非機能要件

実装スタック: **Bun + TypeScript**。チェックコマンドは `bun run check`。
**実行時の外部コマンド依存は無し**（`docs/architecture.md`「画像処理に外部コマンドを
使わない（当面）」）。

環境の実測値（2026-09-09 時点。**時間が経つと変わるので、前提にする前にその場で確認する**）:

- macOS (Darwin 25.6.0), zsh
- ターミナル: **Orca**（`TERM_PROGRAM=Orca`, `TERM=xterm-256color`）と VS Code 統合ターミナル
- 導入済み: `bun` 1.3.8, `node` v22.13.1, `npm`, `pnpm`, `go` 1.26.5, `python3` 3.9.6,
  `jq`, ImageMagick（`magick`。**SIXEL の読み書きに対応**）, `ffmpeg`
- 未導入: `tmux`, `chafa`, `viu`, `timg`, `img2sixel`, `cowsay`, `deno`, `cargo`
- Claude Code v2.1.263 / outputStyle: `Asuna`

**2026-09-08 の記録からの差分**: `bun` は「未導入」だったが導入済みになった。ターミナルも
`TERM_PROGRAM=vscode` から `Orca` に変わっている。

非機能要件:

- **常駐プロセスは、描画1回の失敗で落ちない。** transcript の行が壊れていても、画像が
  読めなくても、次の更新で復帰する
- **transcript にはユーザーの生の会話が入る。** 外部へ送らない、別の場所に複製しない、
  ログに丸ごと出さない（`docs/coding-standards.md`「会話内容の扱い」が正典）
- 追従の遅延は体感で気にならない程度（目安1秒以内）。厳密な数値目標は置かない

## 6. 既存のものとの関係（なぜ作るのか）

2026-09-08 時点の調査結果。**同じものを作らないため**にここを残す。

- **`/buddy`** — Claude Code 本体の companion 機能。バイナリ v2.1.263 に `companion_intro`
  という内部リマインダ種別が実在するのを確認済み。入力欄の横に ASCII ペットが住み、
  10秒おきに吹き出しで喋る。18種、ユーザーIDから決定論的に生成される
- **claude-code-mascot-statusline**（TeXmeijin） — statusline に半角ブロックのピクセル絵
  マスコットを出す。11個の hook イベントで表情9状態、context 消費で毛色が赤くなる。
  **キャラパックが YAML/JSON で差し替え可能**。
  <https://github.com/TeXmeijin/claude-code-mascot-statusline>
- **VOICEVOX / ずんだもん hooks** — Stop hook で応答を読み上げる。音声のみで、絵は出ない

**空いている穴**: 「**Claude の発話そのものを、立ち絵＋吹き出しで見せる**」ものは存在しない。
tsukumo が埋めるのはここ。

| 未決事項                                                  | 対応タスク |

| 立ち絵の素材をどう用意するか（ドット絵 / 画像）           | T-002      |

| キャラクター定義ファイルの形式                            | T-002 の後 |

**画像プロトコルの実測（2026-09-09）**: 赤い四角を iTerm2 inline images と Sixel の両方で
流すプローブを、VS Code 統合ターミナルと Orca で実行したが、**どちらの端末でも何も表示
されなかった**。VS Code 側は `terminal.integrated.enableImages` が未設定（既定 `false`）
だったことで説明が付くので、有効化して再確認するのが T-004 の最初の一歩になる。
**ここが通らないと「立ち絵付き」という企画の前提が変わる**（吹き出しだけのツールになる）。

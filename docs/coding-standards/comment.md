# コーディング規約: コメント（基準と種類）

ステータス: **正典**。入口は `docs/coding-standards.md`（規約の理由と例外の入口と、子のファイルの一覧）。

責務: コメントの前半。書く基準（無いと明らかに不都合を招くことだけ）、判定の1問、種類別の判断表を持つ（後半は `docs/coding-standards/comment-reference-and-style.md`）。
読む時: コメントを書くか・消すか・正典へ移すかを決めるとき。
直す時: コメントの基準・種類別の扱いを変えたとき、コメントを検査する規則を変えたとき。

## 節の索引

| 節          | 中身                                                                                                                                                                                                                                                                                                                                                                            |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ## コメント | 基準は**無いと明らかに不都合を招くことだけ**。判定の1問と、書く/書かない/正典へ移すの**種類別**判断表、正典の対応表。同じ前提を経路上の複数の関数に書かない基準。別の場所を指すときの指し方（シンボル・節の句。パス・節番号・使い手の一覧を書かない）。Markdown の記法を使わない・意味の切れ目で改行する書き方（後半は `docs/coding-standards/comment-reference-and-style.md`） |

## コメント

**無いと明らかに不都合を招くことだけ**を書く。不都合とは、次にこのコードを読む・直す人（エージェントを
含む）が、コード・型・名前だけを見て**壊す・誤って使う・同じ調べ物をやり直す**ことを指す。
あれば分かりやすい、という程度の説明は書かない。

書くか迷ったら1問だけ問う: **「このコメントを消したとき、コードだけを見て直した人が壊す・誤って使う
場面を、具体的に1つ挙げられるか」。** 挙げられなければ書かない（あれば消す）。挙げた場面が、
リポジトリ全体の規約や設計判断を読めば防げるもの（正典に従っているだけのもの）なら、それも書かない。
規約と設計判断は正典と `AGENTS.md` が持ち、従う箇所ごとに書き直さない・指さない。

残すかどうかは**長さではなく種類**で決める。行数の目安は置かない（数字を置くと、種類の基準の
代わりにその数字が基準として使われるため）。

| 種類                                                                                                                                                              | 扱い                                                                                                                                                                                                                                                                                                  |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ファイル・モジュールの責務（何を持ち、何を持たないか）                                                                                                            | 書く。ファイルの冒頭に置く                                                                                                                                                                                                                                                                            |
| 今の挙動の制約・前提で、素直に書き直すと壊れるもの（この順序でなければならない理由。空の `catch` やわざと待たない呼び出しのような、誤りに見えて意図どおりのもの） | 書く。必要なだけ長くてよい。何が壊れるかを添える                                                                                                                                                                                                                                                      |
| 外部との対応関係（transcript のどの `type` 由来か、SDK・端末・ブラウザの実測した挙動）                                                                            | 書く。必要なだけ長くてよい                                                                                                                                                                                                                                                                            |
| 外から使う型・関数の契約のうち、名前と型から読めないもの（単位・値の出どころ・呼ぶ側に求める条件）                                                                | 書く。正典が「doc コメントを正典とする」と委ねている型では、その doc コメントが契約の置き場になる                                                                                                                                                                                                     |
| 一緒に直さないと壊れる相手（揃えておく義務があるもの）                                                                                                            | 書く。相手をシンボルの名前で1つ指し、何を揃えるかを書く                                                                                                                                                                                                                                               |
| 規約の例外にあたる箇所（規約に反して見えるが、正典が例外として認めているもの）と、規則を機械で検査するコードが検査している規則                                    | 書く。規約に合わせて直されないよう、どの例外・どの規則かを正典の節の句で指す                                                                                                                                                                                                                          |
| コード・型名・フィールド名・関数名の言い直し                                                                                                                      | 書かない                                                                                                                                                                                                                                                                                              |
| 規約・方針・設計判断に従っていること（「〜の方針でこうした」「〜の規約どおり」）と、その正典への参照                                                              | 書かない。上の問いで挙げた場面が、その規約・判断を読めば防げるもの                                                                                                                                                                                                                                    |
| 正典に書いてあることの要約                                                                                                                                        | 書かない。要約の代わりの節への参照も置かない                                                                                                                                                                                                                                                          |
| 用語の出典（`docs/glossary.md` の語を指すだけのもの）                                                                                                             | 書かない                                                                                                                                                                                                                                                                                              |
| 昔はこうだった（過去の実装・過去の設計の経緯）                                                                                                                    | 長短にかかわらず正典へ移し、コードから消す                                                                                                                                                                                                                                                            |
| 採らなかった案の比較（どの案をなぜ捨てたか）                                                                                                                      | 正典（`docs/architecture.md`）へ移し、コードから消す。素直に書き直すと壊れることを防ぐ一言（Why not）は、上の「制約」として残す                                                                                                                                                                       |
| ほかの箇所との照らし合わせ（「〜と同じ割り切り」「〜と同じ形」）                                                                                                  | 書かない。この箇所の制約はこの箇所の言葉で書く。揃えておく義務があるときは上の「一緒に直さないと壊れる相手」                                                                                                                                                                                          |
| このファイルを呼ぶ側・使う側                                                                                                                                      | 書かない。呼ぶ側に求める条件は上の「契約」として書く                                                                                                                                                                                                                                                  |
| いつ決まったか・誰が言ったか（特定の日付・「〜の指摘」「ユーザーの決定」）                                                                                        | 書かない（禁止）。日付つきの記録は `docs/architecture.md` と `docs/history/` が持つ。**`src` `test` `scripts` の `.ts` `.tsx` `.css` は `test/architecture/lint-rule.test.ts`「コメント中の日付」が機械で検査する**（`pnpm run check` から走る。見本のパス `docs/history/mockup/…` の中の日付は除く） |

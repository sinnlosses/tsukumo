# コーディング規約: 会話内容の扱い（書き出す例外）

ステータス: **正典**。入口は `docs/coding-standards.md`（規約の理由と例外の入口と、子のファイルの一覧）。

責務: 会話内容の扱いの前半。最優先の規約の4条（外部に送らない・別の場所に複製しない・ログに全文を出さない・フィクスチャに実物を使わない）と診断ログの線、書き出してよい3つの例外の表、スクリーンショットの別枠を持つ（後半は `docs/coding-standards/conversation-content-read-back-and-boundary.md`）。
読む時: 会話（SDK のイベント・transcript）をディスク・ログ・テストに触れさせるとき、書き出しの例外に当たるかを確かめるとき。
直す時: 会話内容の扱いの条・書き出しの例外の表を変えたとき（例外を足すにはユーザーの決定が要る）。

## 会話内容の扱い

**このリポジトリ固有の規約で、優先度が最も高い。** transcript には利用者と Claude の
生の会話が入っている。**SDK のイベント（ターンの本文・ツールの入力と結果・`speak` の引数）も
transcript と同じ扱いにする。**

- **外部に送らない。** 解析サービス・テレメトリ・クラッシュレポートを含め、ネットワークに
  出す経路を作らない
- **別の場所に複製しない。** キャッシュ・一時ファイル・バックアップとして transcript の
  内容を書き出さない。**禁じているのは「書き出す」ほうで、正典（claude 自身が
  `~/.claude/projects/` に書く transcript）を読んでメモリ上のビューを組み直すのは複製に
  あたらない**（セッションの復元。`docs/requirements.md` 4.8。仕事の依頼に添えた画像も、tsukumo は書かずに
  復元でここから読み戻す）。読んだものはプロセスの
  メモリに留め、`127.0.0.1` のビュー以外へ出さない。**例外は下の2つの表だけ** —
  **書き出してよいもの**が3つ、**会話を claude へ渡してよいもの**が2つ。
  そのどれにも当たらない書き出し・読み戻しは今までどおり禁止
- **ログに全文を出さない。** デバッグ時も、出すのは長さ・行数・`type` のような**中身を
  含まない情報**にとどめる。文面そのものを出す必要があるときは、その場限りにして
  コミットしない
- **診断ログ（`~/.tsukumo/diagnostic/`）に入れてよいのは、数・真偽・決まった語だけ。** 不具合の
  経緯を追う足跡で、会話の複製ではない。エラーの `name`・code も決まった語（リテラルの合併）に
  写してから入れ、`error.message`・イベントの中身・パスは入れない（SDK 由来の文字列には会話が
  混じりうる）。任意の文字列を受ける欄を型に作らないことで締め出し、無いことは
  `test/shared/diagnostic/diagnostic-record.test.ts` が守る（線の正典は `src/shared/diagnostic/diagnostic-record.ts`）
- **テストのフィクスチャに実物を使わない。** SDK のイベントや JSONL のフィクスチャは、
  手で書いた架空の会話にする

**「別の場所に複製しない」に認められた例外は3つだけ**（ユーザーが決め、
のちにあらすじの書き手を定着の `query()` へ移すことを認め、仕事の会話へ
広げ、雑談で貼った画像を足し、エピソード索引を外した。広げたのは**この1条だけ**で、広げた先も次の3つに限る）。どれも `~/.tsukumo/` の下へ書き、
**記憶は雑談と仕事で1つ**（同じアーカイブ・同じあらすじ）。**仕事で書いてよい会話は
雑談より狭い**（アーカイブの行。画像も雑談だけ）:

| 何を                                                                                                                                            | どこへ                                                                                                                     | なぜ書いてよいか                                                                                                                                            | 形と上限                                                                                                                         |
| ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 定着の `query()` が書いた**あらすじ1つ**                                                                                                        | `~/.tsukumo/chat-summary/<パック名>.summary.json`（話題の見出しと渡し済みの印も同じ1つの JSON）                            | 新しいセッションへ記憶を渡すため。中身は会話そのものではなく、claude が自分の言葉で書き直した話の筋                                                         | 最新の1つを上書き。8 KiB                                                                                                         |
| **会話**（雑談: 利用者の依頼とセリフ。仕事: **依頼の冒頭**・**そのターンの最後の `report` の `conclusion`**・セリフ。セリフはどちらも表情つき） | `~/.tsukumo/chat-archive/<パック名>/<日付>.jsonl`                                                                          | あとで活用するため・設計が変わっても残すため・雑談と仕事で同じ記憶を引くため。**画面の 100 ターンは画面の上限であって、残す量の上限ではない**               | 1行1件の JSONL。日ごとに1ファイル。仕事の依頼の冒頭と `conclusion` は 300 文字まで                                               |
| **雑談で貼った画像**（原寸。仕事の依頼に添えた画像は書かず、復元では claude の transcript から読み戻す）                                        | `~/.tsukumo/chat-archive/<パック名>/images/<日付>-<id>.<拡張子>`（アーカイブの依頼の行が `imageFiles` でファイル名を指す） | 雑談で見せた画像を、メモリの棚から落ちたあとも残すため。**使い道は保存だけ** — 画面で見返す口も claude へ渡し直す口も持たず、下の「渡してよい」表に入らない | 貼った1枚を1ファイル（同じ画像も貼るたびに別のファイル）。**7日で消す**（`CHAT_IMAGE_RETENTION_DAYS`。起動時と日付が変わるとき） |

範囲・理由・形・上限の正典は `docs/architecture/chat-mode.md` 4.9、置き場は `docs/architecture/character-pack.md`「会話の記録の置き場」。
**ここに4つ目を足すにはユーザーの決定が要る。** この節を根拠に、「似ているから」で別の複製を
足さない。

**利用者が参考に示した tsukumo の画面のスクリーンショットをリポジトリに写すのは、上の表とは
別枠で許されている**（ユーザーが決めた）。tsukumo が会話を書き出すのではなく、
利用者が手元に保存したファイルを指示で写すもの。**入力欄に貼った画像（棚の原寸）は含まない。**
置き方は `docs/workflow.md`「参考に示された画像・ディレクトリを残す」。

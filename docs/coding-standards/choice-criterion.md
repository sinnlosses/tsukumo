# コーディング規約: 案を選ぶ物差し

ステータス: **正典**。入口は `docs/coding-standards.md`（規約の理由と例外の入口と、子のファイルの一覧）。

責務: 複数の案から1つを選ぶときの物差し（コードの把握のしやすさ）と、仕組みをヒューリスティックより優先する順を持つ。
読む時: 案を並べる・選ぶ・提案するとき。
直す時: 物差し・優先の順・仕組みの実例を変えたとき。

## 案を選ぶときの指標（コードの把握のしやすさ）

案が2つ以上あるときは、書いたあとのコードを**読む人が把握しやすいほう**を選ぶ。物差しは次の3つ。

- **1. 開くファイルの数。** その変更を理解するのに何ファイル開く必要があるか。1ファイルで
  完結する案を、2ファイル以上に散る案より上に置く
- **2. 呼ぶ側が知らずに済むか。** 呼ぶ側が、自分のファイルの外の事情（親の DOM の構造・
  別ファイルの CSS・他の層の都合）を知らないと正しく書けない案は下げる。
  `layout.module.css` の「部品は自分の subtree の外の DOM を直接いじらない」と同じ考え方
- **3. 黙って効かなくならないか。** 暗黙の前提（画面幅・件数・並び順）に乗っていて、前提が
  変わると**エラーも出さずに何もしなくなる**案は採らない。読んだ人の理解が裏切られるため

**同点のときだけ**、既存の書き方との一貫性・実行の速さで決める。**工数と行数は指標にしない**
（コードを書く時間は一度きりだが、読む回数はそれより多い）。

**提案で案を並べるときは、この3つでの優劣と理由を必ず添える**（並べただけで終わらせない）。

**例: メインビューのスクロール位置を親へ戻す3案では、`scrollIntoView` を使う案が勝った。**
呼ぶ側が「どの祖先の要素が実際に転がっているか」を知らずに済み、開くファイルも1つで済み、
画面幅が変わって祖先の構造が変わっても黙って効かなくなることがなかったため。

## 仕組みをヒューリスティックより優先する

解決策を提案・選択するときは、**機械的に判定・強制できる仕組み**（検査・テスト・型・hook・lint・
ツールの戻り値での差し戻し）を、**ヒューリスティック**（文面の条・モデルへの指示・覚え書き・
閾値の当て推量）より優先する。仕組みは前提が変わっても自動で効き続けるが、文面の条は読まれない・
忘れられる・モデルが解釈を誤る形で黙って効かなくなる。

**優先の順**: 機械的な仕組み ＞ 仕組みで塞げない部分だけを文面の条で補う。このリポジトリにある
「仕組み」の実例:

- `test/architecture/layer.test.ts`: 層をまたぐ `import` を構文木（`vite` の `parseSync`）で検査し、許した辺以外を落とす。静的 import・`export … from`・動的 `import()`・`require()` を拾う
- `src/server/report/core/report-review.ts`: 規約違反のある `report` 呼び出しを handler が差し戻す。
  差し戻しの枠を足すときは、`REPORT_PROCEDURE_REJECTIONS` と `ReportReview.judge` の JSDoc（順と脇の話の扱い）を直し、
  `docs/architecture/display/work-plan-closing.md` の「枠の数え方」と脇の話の節の列挙を同じ順・同じ枠に合わせる
- `src/server/report/core/report-tool.ts` の `Stop` フックの関所: ターンの最後に `report` を
  通さない本文で止まろうとしたら差し戻す
- `.oxlintrc.json` の `no-restricted-globals`: `Date` の使用を lint で落とす
- `test/scripts/document/section-reference-repository.test.ts`: 正典の節への参照が切れていないかを検査する

**キャラクターのセリフ・振る舞い**（頻度・間合い・言い回し）はこの優先の対象外で、ヒューリスティックでよい。
仕組みで縛るのは、表示・ログ・契約・台帳などキャラクターの外側。

**ヒューリスティックを採るしかないとき**は、その理由（機械で判定できない点）を提案に1行添える。

**案を並べるとき**は、各案が「仕組み」か「ヒューリスティック」かを明示する（「案を選ぶときの
指標」の3つの物差しとは別の軸で、両方を併記してよい）。

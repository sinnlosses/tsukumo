# コーディング規約: 会話内容の扱い（読み戻しと境界）

ステータス: **正典**。入口は `docs/coding-standards.md`（規約の理由と例外の入口と、子のファイルの一覧）。

責務: 会話内容の扱いの後半。会話を claude へ渡してよい2つの例外の表、広げていないことの線、会話をプロセスの外へ出さない境界、ブラウザ側で会話の状態を持つことの扱いを持つ（前半は `docs/coding-standards/conversation-content.md`）。
読む時: アーカイブの会話を `systemPrompt`・ツールの戻り値・定着の `query()` へ渡すとき、例外の線を確かめるとき。
直す時: 読み戻して渡す例外の表・広げていないことの線を変えたとき（渡す先を増やすにはユーザーの決定が要る）。

## 会話内容の扱い

**会話を claude へ渡してよいのは、次の2つだけ**（ユーザーが 2026-09-21 に決め、2026-09-25 に
定着の行を足し、2026-09-26 に仕事のセッションへ広げ、2026-10-25 に `recall_episode` の行を外した。**2026-09-21 にここにあった「書き出したものは claude へ戻さない」
という前提を覆している**）。
**表を分けているのは、「書き出す」と「読み戻して渡す」が別の動きだから** — 1つの表に混ぜると
どちらの例外なのかが読めなくなり、読み戻しにだけ要る「どこへ渡すか」「いつ」「どれだけ」も
書けない:

| 何を                                                                   | どこから               | どこへ                                                                                  | いつ                                                                                                                     | どれだけ                                                      |
| ---------------------------------------------------------------------- | ---------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| **アーカイブの会話**（上の表に書いた行の文面。雑談と仕事を区別しない） | 上の表のアーカイブだけ | **雑談と仕事のセッションの `systemPrompt`** だけ                                        | 起こすとき1回。雑談は**新規に起こしたとき**と **`/clear` のあと**、仕事は**起こすたび**                                  | **新しいほうから 雑談 64 KiB・仕事 16 KiB**（文面のバイト数） |
| **窓から溢れた会話**（同じく文面）                                     | 上の表のアーカイブだけ | **定着の使い捨て `query()`**（同じマシンの claude の子プロセス。transcript を書かない） | 雑談・仕事のターンの終わりに、仕事の窓（16 KiB）から溢れた未定着の行が 8 KiB 溜まったとき（プロセスをまたいで同時に1本） | **1回 16 KiB まで**（同じ物差し）                             |

- **渡すのは文面と話者の別、行の種類（依頼・セリフ・`conclusion`）と、仕事の行ならその印とプロジェクトの名前だけ**
  （表情・画像の枚数・画像のファイル名・時刻の各行は渡さない。日付は窓の両端だけ）
- **定着の `query()` に渡すのは文面と話者の別・前のあらすじだけ**（2026-09-25 に
  ユーザーが認めた）。その子プロセスは transcript を書かず（`persistSession: false`）、ツールも
  設定も持たない。返ったもののうち書いてよいのは上の表のあらすじの行だけ
- **渡す先を増やすにもユーザーの決定が要る。** 量は `docs/architecture/chat-mode.md` 4.9 の容量の表の値で、
  表を直すのは値の調整にあたる（先と物差しは変えない）。この2行を根拠に、
  「似ているから」で別の読み戻しを足さない
- **逐語の会話が新しいセッションの transcript へ書かれることは、この決定に含まれる**

**広げていないこと**（この例外を持ち出してよいのはここまで、という線）:

- **仕事で書くのは、依頼の冒頭・そのターンの最後の `report` の `conclusion`・セリフ（表情つき）の
  3つだけ。** 依頼の残り・中間レポートの `conclusion`・`report` の本文（`sections`）・`checks`・`favor` は
  書かない。**読み戻して渡すのも書いたものだけ**で、作業ツリーのパスは書かない（プロジェクトの
  名前だけ）
- **transcript を読んで書き出さない。** 残すのは tsukumo が画面のために受け取ったものだけで、
  `~/.claude/projects/` の過去のぶんを取り込む経路は作らない（読んで組み直すのは今までどおり
  複製にあたらない、のまま）。**読み戻しの出どころにもしない**（出どころはアーカイブだけ）
- **読み戻したものを他所へ出さない。** 渡してよいのは `systemPrompt` だけで、画面にも
  手続きの応答にも stderr にも出さない（**読んだ中身で判定する経路も作らない**）
- **本文（レポートの `sections`）・ツールの入力と結果・許可プロンプト・質問は、雑談でも仕事でも
  書かない。** 雑談で残すのは雑談のログに乗る2種類（依頼とセリフ）と、セリフの表情だけ
- **添えた画像そのものは、雑談で貼った画像を上の表の3行目のとおり7日だけ書くほかは書かない**（仕事の
  画像は枚数まで）。書いた画像も保存だけで、読み戻して claude へ渡さず、画面にも手続きの応答にも出さない。
  ファイル名の指す画像が消えていたら、その行は期限切れとして画像を無いものと扱う
- **ブラウザ側の永続化には置かない**（`localStorage` などに会話を置かないことは変わらない）
- **残る3条は1文字も緩まない。** 外部に送らない（書く先は同じマシンのファイルで、渡す先も
  同じマシンで動いている claude と、それが起こす使い捨ての子プロセスだけ。`docs/requirements.md`
  2.2 の読みで外部送信に当たらない。tsukumo 自身がネットワークへ出る経路を足さない）、ログに全文を出さない（画面にも 手続きの応答にも stderr にも出さず、
  出してよいのは長さ・件数まで）、テストのフィクスチャに実物を使わない（アーカイブのフィクスチャも
  手で書いた架空の会話）
- 組み替える前の「残す」旗（`kept.jsonl`）、キャラクターが書いていた見出し（`index.jsonl`）、
  定着が書いていたエピソード索引（`episode.jsonl`）と思い出した記録（`recalled.jsonl`）はもう書かず読まない（残ったファイルは `scripts/runtime/migrate-chat-summary.ts --prune` で消す。`docs/architecture/chat-mode.md` 4.9
  「窓から溢れた会話は定着で畳む」）
- **おすすめの札の問い合わせには会話を渡さない**（`docs/architecture/screen-design.md` 13.13
  「おすすめの札の中身」）。前のセッションの `sessionSummary` と残り（`sessionRemaining`）は会話から書いた要約なので、
  定着と同じ形の使い捨て `query()` でも上の2行に当たらず、**渡さない・キャッシュに書かない**。
  「前回の続き」は中身を持たない固定の候補として渡し、前のセッションや残りが有るかもサーバは
  見ない（有無を見ればそれも会話から導いた値になる）。渡すのはタスク一覧（ID・要約・依存。
  進捗管理のデータで会話ではない）だけで、`~/.tsukumo/recommendation.json` に書くのもその候補と、
  候補だけから書かれた理由の1行なので、**書き出しの表に数えない**。残りを渡したくなったら
  渡す先を増やすことになるので、ユーザーの決定が要る
- **迎えの挨拶の問い合わせにも会話を渡さない**（`docs/architecture/display.md` 4.2「出力の分離（セリフと詳細）」）。
  渡すのはパックの `persona.md`（キャラクターの属性。日記と同じ）・表情の選択肢・月と曜日と
  時刻の帯・直近に書いた挨拶と、続きから起こしたときの続きからの印と前回からの経過の帯（決まった語）だけで、
  前のセッションの要約もタスク一覧も渡さない。挨拶はこの
  材料だけから書かれるので、`~/.tsukumo/welcome-greeting/<キャラ名>.json`（直近の挨拶5件）は**書き出しの表に数えない**
- **キャラクターパックへ書く1行はこの表に数えない**（`persona.md` の「覚えたこと」）。あれは
  会話ではなく**キャラクター自身の属性**で、複製にあたらないという整理のまま
  （`docs/architecture/chat-mode.md` 4.9「プロフィールの書き戻し」）

**会話は tsukumo のプロセスの外へ出さない。** SDK は claude を子プロセスとして起こすだけ、
`speak` はプロセス内の MCP ツール（戻り値は `"ok"` だけ）、ビューは `127.0.0.1` にだけ配る。
ここに外へ出る経路を足さない。**読み戻した逐語を `systemPrompt` に載せることも、定着の
使い捨て `query()` に渡すことも、この線の内側**——渡す相手は同じプロセスが起こした子プロセスで、
tsukumo から外へは出ない。

**ブラウザ側で会話の状態を持つこと（移行後の `SessionState`）は、外へ出すことにあたらない。**
同じマシンの同じオリジン（`127.0.0.1`）のタブのメモリに閉じるためで、いまも DOM として同じものを
持っている。**`localStorage` などブラウザ側の永続化に会話を置かない**（置いてよいのは領域の比率の
ような画面の都合だけ。`docs/architecture.md`「会話内容と安全」）。
